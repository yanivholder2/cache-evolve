# H01

Removing the ghost set and referenced-bit from cycle/0006/v001 and layering IRR timestamps as a secondary tie-breaker for equal-frequency candidates raises hit rate by combining the long-term warmth signal of frequency counters with IRR's burst-detection capability while eliminating two exhausted mechanisms.

## Parent

cycle/0006/v001

## Changes

Start from the cycle/0006/v001 overlay (SLRU + frequency + ghost set + referenced-bit + MAX_FREQ cap).

**Remove ghost admission entirely:**
- Delete the `ghost: VecDeque<K>`, `ghost_set: HashSet<K>`, and `ghost_cap: usize` fields from `LruCache`.
- Delete the `add_to_ghost()` helper.
- Remove all ghost-set reads/writes from `put()`: the ghost-hit branch in step 2 (where a ghost match routes a new key directly into protected) is removed; all new keys always land in probationary via the normal path.
- Remove the `ghost_set.remove()` defensive cleanup in `get()`.
- Remove the `HashSet` import if no longer needed.

**Remove the referenced-bit tie-breaker:**
- Delete the `referenced: bool` field from `Node`.
- In `get()`, remove the `self.nodes[idx].referenced = true` assignment on protected hits.
- In `demote_prot_head()`, replace the old `(freq, referenced as u32)` victim score with the new composite described below.

**Add IRR timestamps:**
- Add `op_clock: u64` to `LruCache`, initialized to `1`.
- Add `last_access: u64` and `prev_access: u64` fields to `Node`. On new insertion in `put()`, set `last_access = op_clock` and `prev_access = 0`. Increment `op_clock` after the assignment.
- In `get()`, before the segment dispatch: `self.nodes[idx].prev_access = self.nodes[idx].last_access; self.nodes[idx].last_access = self.op_clock; self.op_clock += 1;`
- On demotion in `demote_prot_head()`, do NOT reset timestamps. They are preserved just as in cycle/0007/v003, so a warm demoted entry retains its competitive IRR.
- On slot reuse in `put()` (the arena-full path), reset `prev_access = 0` and `last_access = op_clock` for the recycled slot, same as a fresh insertion.
- Add `fn irr(&self, idx: usize) -> u64` returning `u64::MAX` if `self.nodes[idx].prev_access == 0`, else `self.nodes[idx].last_access - self.nodes[idx].prev_access`.

**Update victim selection in both scan functions:**

In `demote_prot_head()` (LRU-quarter scan of protected), use composite `(freq, irr)` ascending to select the coldest victim: a candidate beats the current victim if `cur_freq < victim_freq`, or `cur_freq == victim_freq && cur_irr > victim_irr`. Lower frequency is colder; at equal frequency, higher IRR (larger gap between last two accesses) is colder.

In the probationary eviction scan (LRU-half scan), apply the same composite: candidate beats current victim if `cur_freq < victim_freq || (cur_freq == victim_freq && cur_irr > victim_irr)`.

**Keep unchanged:**
- MAX_FREQ=8 cap on `freq` counter (incremented on every `get` hit, capped with `.min(MAX_FREQ)`).
- Halving of `freq` on demotion: `self.nodes[v].freq /= 2`.
- 80/20 protected/probationary split (`prot_cap = capacity * 4 / 5`).
- LRU-quarter scan in protected, LRU-half scan in probationary.
- Single-hit promotion from probationary to protected.
- All linked-list helpers and the arena slot-reuse mechanism.

## Rationale

Ghost admission and the referenced bit have been exhausted as productive directions across cycles 2-8. Removing them simplifies the design and frees up the guard logic for a genuinely informative signal: IRR. The frequency counter preserves long-term access history that pure IRR discards (the key reason cycle/0006/v001 outscores cycle/0007/v003 at 0.7343 vs 0.726), while IRR adds burst-detection precision as a tie-breaker when frequency scores are degenerate. Preserving timestamps across demotion — a principle validated in cycle 7 — keeps demoted warm entries competitive in probationary without any extra adjustment logic.
