# H02

Expanding the ghost window from probationary capacity (~20% of total) to half of total capacity will raise hit rate by capturing reuse events at intermediate reuse distances that currently bypass ghost admission entirely.

## Parent

cycle/0005/v002

## Changes

The only change is in `try_new()`: replace the `ghost_cap = prob_cap` assignment with `ghost_cap = capacity / 2`.

Before:
```rust
let ghost_cap = prob_cap;
```

After:
```rust
let ghost_cap = capacity / 2;
```

Also update the two allocation sites that depend on `ghost_cap` so they do not under-allocate:
```rust
ghost: VecDeque::with_capacity(ghost_cap + 1),
ghost_set: HashSet::with_capacity(ghost_cap + 1),
```
These lines already reference `ghost_cap`, so they require no textual change beyond the value of `ghost_cap` itself changing.

At `capacity = 2048` this raises `ghost_cap` from 410 to 1024. All ghost logic (`add_to_ghost`, `ghost_set.contains`, `ghost.retain`) is unchanged; only the window size grows.

**Invariants to preserve**: the 80/20 segment split (`prot_cap = capacity * 4 / 5`, `prob_cap = capacity - prot_cap`) is unchanged; eviction and demotion paths are untouched; the `ghost_cap == 0` guard in `add_to_ghost` remains correct.

## Rationale

Cycle 4 tested a ghost window equal to full capacity and saw regression: reuse events at distances greater than total capacity are unreliable locality signals. The current window at `prob_cap` (~20% of capacity) is confirmed to contribute negligibly on workload-a — it is too narrow to intercept most cross-residency reuse. The 50%-of-capacity point is the only untested intermediate: it is narrow enough to exclude the long-distance cold traffic that hurt cycle 4 but wide enough to cover reuse patterns that currently fall in the dead zone between probationary capacity and total capacity.
