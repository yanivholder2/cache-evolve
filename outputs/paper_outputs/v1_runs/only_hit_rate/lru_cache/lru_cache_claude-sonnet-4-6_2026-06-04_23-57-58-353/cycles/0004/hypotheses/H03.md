# H03

Applying a minimum-frequency scan to the LRU half of the probationary segment when evicting protects demoted-from-protected entries over cold newcomers and raises hit rate by giving recently-warm keys a second residency window.

## Parent

cycle/0003/v002

## Changes

In `put()`, inside the arena-full branch where `prob_count > 0` (lines
that currently do `let h = self.prob_head.expect(...)` and then unlink
and ghost-record that head unconditionally), replace the direct head eviction
with a minimum-frequency scan of the LRU half of probationary:

```
let scan_len = (self.prob_count / 2).max(1);
let mut victim_idx: Option<usize> = None;
let mut victim_freq = u32::MAX;
let mut current = self.prob_head;
let mut scanned = 0usize;
while scanned < scan_len {
    let Some(idx) = current else { break };
    let freq = self.nodes[idx].freq;
    if freq < victim_freq {
        victim_freq = freq;
        victim_idx = Some(idx);
    }
    current = self.nodes[idx].next;
    scanned += 1;
}
let evict_idx = victim_idx.expect("prob_count > 0 guarantees a victim");
let evicted_key = self.nodes[evict_idx].key.clone();
self.map.remove(&evicted_key);
self.unlink_prob(evict_idx);
self.prob_count -= 1;
self.add_to_ghost(evicted_key);
```

Use `evict_idx` in the slot-reuse path that immediately follows (replacing
`h`). The ghost recording, arena slot reuse, and subsequent step-2 segment
placement logic are unchanged.

The protected-segment demotion path (`demote_prot_head`) is untouched; this
change applies only to the probationary eviction path triggered when the
arena is full and probationary has entries.

## Rationale

In cycle/0003/v002, entries demoted from protected land in probationary
with a halved but non-zero `freq` counter. Cold new insertions enter with
`freq = 0`. Under strict probationary LRU, a demoted entry that happens to
sit near the probationary head can be evicted immediately by the next
insertion, discarding the residency history it accumulated in the protected
segment. A minimum-frequency scan of the first half naturally prefers
`freq = 0` new entries over `freq > 0` demoted ones, giving recently-warm
keys a second window without freezing list positions or disabling recency
ordering — the flaw that killed cycle-3 v003's second-chance bit. The scan
is bounded to half of probationary to keep per-operation work proportional
and avoid degrading the fast path for cold traffic.
