# H03

Reinsert demoted protected keys at the probationary LRU (front) instead of the MRU (back) to reserve the scarce probationary window for fresh arrivals and raise hit-rate.

## Parent

cycle/0004/v001

## Changes

A pure eviction-ordering tweak to the incumbent, isolating one question
the cohort has never tested: when a key ages out of the 95% protected
tier, should it get a fresh full pass through the ~100-slot probationary
segment, or should it yield immediately to genuinely new keys?

In `src/lru_cache/mod.rs`:

1. Add a helper `push_front_probationary(&mut self, idx: usize)` that
   links a node at the LRU (head) end of the probationary segment: set
   `protected = false`, `prev = None`, `next = self.prob_head`; if
   `prob_head` is `Some(h)` set `nodes[h].prev = Some(idx)` else set
   `prob_tail = Some(idx)`; then `prob_head = Some(idx)` and increment
   `prob_len`. It is the head-end mirror of the existing
   `push_back_probationary`.
2. In `enforce_protected_budget`, replace the
   `self.push_back_probationary(lru)` call with
   `self.push_front_probationary(lru)`. Leave the rest of the function
   (the `prot_len > protected_cap` guard and the `unlink`) unchanged.

Everything else is untouched: new keys still enter at probationary MRU via
`push_back_probationary`, eviction in `put` still takes `prob_head`
first, the budgets still sum to `capacity`, and net resident count is
unchanged by a demotion. Because the eviction victim is `prob_head`, a
demoted node placed at the front becomes the next probationary victim,
so cold demoted keys die before fresh keys spend their reuse window. Do
not touch `lru_cache_jni.rs`.

## Rationale (optional)

Cycle 0004 found the probationary floor — not protected appetite — is now
the binding constraint, because the ~100-slot probationary segment is
where fresh keys must land their second touch. This change stops
once-hot-now-cold demoted keys from crowding that segment, costing
nothing and testing the eviction-ordering lever the narrative says is the
only one that has ever paid.
