# H01

Pushing the SLRU protected split from 90/10 to 95/5 keeps converting protected residency into hits and raises hit-rate before the probationary floor breaks the eviction path.

## Parent

cycle/0003/v001

## Changes

In `try_new`, change the protected-budget constant from
`let protected_cap = (capacity * 9) / 10;` to
`let protected_cap = (capacity * 19) / 20;` (floor of 95% of capacity).
Leave every other line of the variant untouched: the probationary budget
stays `capacity - protected_cap`, so the two segment budgets still sum to
exactly `capacity` and the P1 capacity bound is unchanged.

This is a pure ratio probe to find where the live lever stops paying. For
the evaluated `capacity == 2048` it leaves `protected_cap == 1945` and a
`103`-slot probationary segment — still non-empty, so the
probationary-first victim selection in `put` keeps draining one-hit
wonders and `enforce_protected_budget` keeps demoting the protected LRU
on overflow exactly as before.

Preserve these invariants: `prob_len + prot_len == map.len()`,
`map.len() <= capacity`, and the `capacity == 1` edge case (the `19/20`
floor still yields `protected_cap == 0`, leaving one usable probationary
slot, identical to the parent's behaviour at that capacity). Do not touch
`get`, `put`, `enforce_protected_budget`, or the segment link helpers —
the only diff is the budget constant.

## Rationale (optional)

Cycles 0001→0003 won three times in a row by enlarging the protected
tier (segmentation, then 80/20, then 90/10). 90/10 is the current
incumbent; the cross-cycle open question is explicitly whether 95/5 still
pays or whether the shrinking probationary segment starts starving the
eviction path. This isolates that single variable.
