# H02

Letting the protected/probationary boundary float at runtime via ghost-hit feedback (adaptive geometry) beats the static 95/5 split on hit-rate.

## Parent

cycle/0005/v003

## Changes

The parent fixes `protected_cap` at floor(0.95 * capacity) for the cache's
lifetime; prior cycles proved *static* ratios are exhausted at 95/5 but never
tried an *adaptive* boundary. Replace the constant `protected_cap` with a
mutable target `prot_target`, initialized to floor(0.95 * capacity) and clamped
to a band of roughly [floor(0.90 * capacity), floor(0.98 * capacity)] so the
probationary floor can neither vanish nor dominate.

Add one bounded ghost structure that records the **keys** (no values, so
residency and the P1 capacity bound are untouched) of nodes evicted from the
probationary LRU (`prob_head`) in `put`. Implement it as a `HashSet<K>` plus a
FIFO index list bounded to about `capacity` entries; evict the oldest ghost
when full. In `put`, before allocating for a brand-new key, check the ghost
set: a hit there means a probationary one-hitter we already discarded has
returned — its reuse distance just exceeded the probationary window — so a
larger probationary would have caught it. On such a ghost hit, decrement
`prot_target` by a small step (e.g. 1) within the clamp, then remove the key
from the ghost set. Symmetrically, when a key that was demoted out of protected
is subsequently evicted and later returns, nudge `prot_target` upward by the
same step (track demoted-then-evicted keys with a tier/flag bit reusing the
same ghost machinery). Have `enforce_protected_budget` compare against
`prot_target` instead of the old constant. Keep `prob_len + prot_len ==
map.len()` and the demote-to-front behavior of the parent intact.

## Rationale (optional)

Static geometry is closed, but the binding constraint (probationary floor size)
may differ from 95/5 in phases of the trace. Ghosts are used here only as a
*resize signal*, not for re-admission (the redundant mechanism prior cycles
ruled out), so this is a genuinely untested axis: the cache discovers its own
split from observed reuse distances.
