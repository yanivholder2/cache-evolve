# H01

Split the single LRU list into a probationary and a protected segment (SLRU) so frequently-reused keys resist eviction, raising hit-rate on the LIRS trace.

## Parent

baseline

## Changes

Replace the single head/tail list in `LruCache` with a two-segment
structure (Segmented LRU). Partition `capacity` into a protected segment
(~80% of capacity, rounded down, minimum 1) and a probationary segment
(the remainder, minimum 1); the two segment sizes must sum to exactly
`capacity` so the P1 capacity bound is unchanged.

Behaviour:
- Each node carries a `segment` flag (probationary vs protected). Keep
  separate head/tail pointers per segment, still in the shared arena.
- On `put`-after-miss: insert the new node at the MRU end of the
  **probationary** segment. If the cache is full, evict the LRU (head) of
  the probationary segment first; only if probationary is empty, evict
  the LRU of protected. Reuse the evicted slot in place, exactly as the
  baseline does.
- On `get` hit: promote the node to the MRU end of the **protected**
  segment. If protected is now over its size budget, demote its LRU node
  to the MRU end of probationary. Net resident count is unchanged, so
  P1 still holds.

Preserve `unlink`/`push_back` mechanics (adapt them to take a segment
target) and keep the map as key -> arena index. Do not store values for
demoted/evicted keys (P2/P3). Eviction must still free exactly one slot
when at capacity.

## Rationale (optional)

Pure LRU evicts a reused key as readily as a one-hit-wonder. SLRU gives
a node that earns a second access a protected tier, directly targeting
hit-rate, and is the canonical first improvement over LRU.
