# H02

Gate promotion into v003's protected tier on estimated frequency so the protected segment holds frequency-hot keys rather than merely recently-hit ones, raising hit-rate.

## Parent

cycle/0004/v003

## Changes

In `promote(idx)`, v003 unconditionally moves the hit node into the protected
tail and, on overflow, demotes the protected LRU head (`prot_head`). Change the
overflow case into a frequency contest: when promoting would push
`protected_len` past `protected_cap`, compare `sketch.estimate(promotee_key)`
against `sketch.estimate(prot_head_key)`. Only demote the protected head and
admit the promotee into the protected tail when the promotee's estimate is
strictly greater; otherwise leave the protected segment untouched and instead
re-insert the hit node at the probationary tail via `push_back_prob` (refreshing
its recency without displacing a hotter protected key). Preserve these
invariants: a node already in the protected segment that is re-hit always stays
protected (move it to `prot_tail`, no contest); when `protected_len <
protected_cap` promote unconditionally as today; keep `protected_len` and the
`protected` flags consistent with the segment each node actually lands in; never
exceed `protected_cap`.

## Rationale (optional)

v003's protected tier is recency-selected — any single hit promotes a node,
letting one-touch keys evict proven-hot ones. The workload's signature is that
a mechanism only matters when the head hides a much-hotter key; gating
promotion on the sketch targets exactly that case.
