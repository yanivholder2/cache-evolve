# H03

Choosing the eviction victim as the lowest-frequency item among several LRU-tail candidates, rather than the single LRU head, evicts truly cold items and raises hit-rate.

## Parent

baseline

## Changes

The baseline always fixes the eviction victim as `self.head` (the strict LRU
node) and only then compares its frequency to the incoming key. This means a
recently-touched-but-rarely-used key can be protected while a genuinely cold
key two slots away survives. Replace single-victim selection with
small-sample frequency-aware selection:

- In `put`, in the full-cache branch (currently lines ~89-100), instead of
  taking `self.head` directly, walk forward from `self.head` along `next`
  pointers collecting up to `SAMPLE` candidate indices (introduce `const
  SAMPLE: usize = 5;`, clamped to the number of resident nodes).
- Compute `sketch.estimate` for each candidate's key and pick the candidate
  with the minimum estimate as `victim_idx` (break ties by preferring the one
  closest to the LRU head, i.e. oldest).
- Keep the existing admission rule unchanged otherwise: admit the incoming key
  only if `incoming_freq > victim_freq` for the *selected* victim; on
  admission, reuse the chosen `victim_idx` slot exactly as today (remove victim
  key from map, unlink, overwrite key/value, push_back, reinsert into map).

This changes only which resident slot is moved out, never how many reside, so
capacity_bound (P1) holds; the slot still carries a real put key/value so
value_fidelity (P2) and no_phantom_items (P3) hold. Target dimension:
hit-rate.
