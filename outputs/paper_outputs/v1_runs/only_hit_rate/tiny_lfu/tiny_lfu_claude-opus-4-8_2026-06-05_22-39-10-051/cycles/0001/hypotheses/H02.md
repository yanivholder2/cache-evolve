# H02

Adding a small LRU admission window in front of the main set (W-TinyLFU) protects bursty newcomers from immediate sketch rejection and raises hit-rate.

## Parent

baseline

## Changes

The baseline admits a newcomer into a full cache only if its sketch estimate
already beats the LRU victim — a brand-new key with frequency 1 is almost
always dropped, so short bursts and recency are punished. Introduce a
W-TinyLFU-style admission window:

- Partition `capacity` into a window region of size `window =
  max(1, capacity / 100)` and a main region of size `capacity - window`. Store
  both as fields on `TinyLfuCache`.
- Tag each `Node` with which segment it lives in (add a `segment` field, or
  keep two separate head/tail linked-list pairs reusing the existing
  `unlink`/`push_back` machinery parameterised by segment).
- In `put` for a never-seen key: always insert into the window's MRU position
  first (no sketch gate). When the window exceeds `window`, take the window's
  LRU node as the *candidate* and the main region's LRU node as the *victim*,
  and apply the existing frequency comparison
  (`sketch.estimate(candidate) > sketch.estimate(victim)`): if the candidate
  wins it moves into the main region and the victim is evicted; otherwise the
  candidate itself is evicted. When the main region is not yet full, the window
  node simply migrates into main with no eviction.
- `get` still increments the sketch and does LRU-promotes within whichever
  segment the key currently occupies.

Critically preserve capacity_bound (P1): total residents across window + main
must never exceed `capacity`. P2/P3 are unaffected since keys and values move
together. Target dimension: hit-rate.
