# H02

Switching the count-min sketch to conservative-update increments (raise only the minimum counters) cuts overestimation bias and raises hit-rate without spending extra memory.

## Parent

cycle/0002/v003

## Changes

In `src/tiny_lfu/mod.rs`, replace the body of `CountMinSketch::increment` with
a conservative-update (CU sketch) rule. Today it unconditionally bumps the
counter in every row:
```
for row in 0..self.depth { ... *counter += 1 ... }
```
Instead: first compute the current minimum estimate across the rows (the same
value `estimate` returns), then for each row only increment that row's counter
if its current value is equal to that minimum — i.e. set each row's counter to
`max(counter, min_estimate + 1)`, which raises only the cells that are at the
minimum and leaves already-higher cells alone. Keep the `MAX_COUNT` saturation
guard so no counter exceeds `u32::MAX`. Do not change `estimate`, `position`,
the width/depth constants, or any policy mechanic. This is a pure
estimator-accuracy change: CU increments are monotonic and never reset or
withhold signal, but they sharply reduce the count-min's systematic
overestimation of cold keys, which is exactly the noise the victim-admission
comparison (`incoming_freq > victim_freq`) is sensitive to.

## Rationale (optional)

The dominant lever is estimator fidelity, and v003 bought it with raw width.
Conservative update buys accuracy algorithmically at zero extra memory and is
orthogonal to width, so it can stack with the parent's wider sketch rather than
compete with it.
