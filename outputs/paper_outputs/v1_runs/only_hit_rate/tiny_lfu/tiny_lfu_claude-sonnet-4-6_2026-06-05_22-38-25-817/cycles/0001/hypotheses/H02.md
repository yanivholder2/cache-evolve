# H02

Reserving a small admission window (⌈capacity / 100⌉, minimum 1 slot) that admits newcomers unconditionally before they face the frequency gate will raise hit rate by giving new items time to accumulate sketch frequency before eviction pressure hits.

## Parent

baseline

## Changes

Modify `TinyLfuCache` in `src/tiny_lfu/mod.rs`:

### New fields on `TinyLfuCache`

```rust
window_capacity: usize,   // = (capacity / 100).max(1)
window_len: usize,        // current occupancy of the window segment
window_head: Option<usize>,
window_tail: Option<usize>,
```

Add a boolean field to `Node`:
```rust
in_window: bool,
```

Initialize `in_window: false` for every node constructed in the existing path.

### Capacity split in `try_new`

```rust
let window_capacity = (capacity / 100).max(1);
// main LRU holds the remaining slots; total node arena is still `capacity`
```

### Modified `put()` for new keys (not already in `map`)

**When the arena is not yet full** (`self.nodes.len() < self.capacity`):
- Unconditionally insert the new node into the window (set `in_window: true`,
  link into `window_head`/`window_tail`, increment `window_len`).

**When the arena is full and window is not full** (`window_len < window_capacity`):
- Impossible once the arena is full, since window slots are part of the total
  arena. However if `window_len < window_capacity`, admit the new item into the
  window unconditionally: evict the main LRU head (`self.head`) from the main
  list, recycle its node, set `in_window: true`, link into window tail.

**When the arena is full and window is also full**:
1. Eject the window LRU head (`window_head`) from the window list
   (`in_window = false`, `window_len -= 1`). Call this the "window evictee."
2. Compare the window evictee's sketch frequency against the main LRU head's
   frequency (exactly as the baseline admission gate).
3. If `window_evictee_freq > main_victim_freq`: recycle the main victim's node
   slot for the window evictee (insert it into main LRU tail). The incoming new
   key then takes the recycled window slot (insert into window tail).
4. Otherwise (window evictee loses): drop the window evictee. The new key still
   enters the window tail using that same recycled slot.

### Modified `get()` for window-resident keys

When `get()` finds a key with `in_window == true`:
- Promote it immediately to the main LRU MRU tail (`in_window = false`,
  `window_len -= 1`, unlink from window list, push onto main LRU tail).
- If the main LRU is now over `capacity - window_capacity` items, evict its
  LRU head into the recycled slot (no frequency comparison needed here since
  the promotion itself counts as a "hit").

For main-LRU-resident keys, `get()` behaves exactly as the baseline (unlink +
push_back in main list).

### Helper methods to add

- `window_unlink(idx)` — mirrors `unlink()` but updates `window_head`/`window_tail`.
- `window_push_back(idx)` — mirrors `push_back()` but for window list.

All invariants P1–P3 are preserved: total resident count never exceeds
`capacity`, values are never corrupted, and phantom keys are never returned.
