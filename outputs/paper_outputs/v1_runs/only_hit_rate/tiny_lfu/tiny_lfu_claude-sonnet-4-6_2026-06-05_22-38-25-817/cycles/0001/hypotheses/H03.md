# H03

Replacing the flat LRU resident set with a 2-segment SLRU (20 % probationary + 80 % protected) will raise hit rate by shielding frequently-re-accessed resident items from one-hit-wonder eviction pressure.

## Parent

baseline

## Changes

Modify `TinyLfuCache` in `src/tiny_lfu/mod.rs`:

### New fields on `TinyLfuCache`

```rust
protected_capacity: usize,    // = (capacity * 4) / 5  (80 %)
probationary_capacity: usize, // = capacity - protected_capacity  (20 %)
protected_len: usize,
probationary_len: usize,
// Separate list pointers for each segment
prot_head: Option<usize>,
prot_tail: Option<usize>,
prob_head: Option<usize>,
prob_tail: Option<usize>,
```

Remove the existing `head` and `tail` fields (they are replaced by the four
segment pointers above).

Add a field to `Node`:
```rust
in_protected: bool,  // false → probationary, true → protected
```

### Capacity split in `try_new`

```rust
let protected_capacity = (capacity * 4) / 5;
let probationary_capacity = capacity - protected_capacity;
```

### Modified `get()` — promotion logic

1. Look up `idx` in `map` as before, increment sketch.
2. **Key is in probationary** (`in_protected == false`):
   - Unlink from probationary list (`prob_unlink(idx)`), decrement
     `probationary_len`.
   - Push onto protected MRU tail (`prot_push_back(idx)`), set
     `in_protected = true`, increment `protected_len`.
   - If `protected_len > protected_capacity`:
     - Take `prot_head` (protected LRU head), unlink it from protected list,
       decrement `protected_len`, set its `in_protected = false`.
     - Push it onto probationary MRU tail (`prob_push_back`), increment
       `probationary_len`.
3. **Key is in protected** (`in_protected == true`):
   - Unlink from protected, push to protected MRU tail (standard LRU-within-segment move).

### Modified `put()` — admission and eviction

**Arena not yet full** (`nodes.len() < capacity`):
- Allocate new node with `in_protected = false`, link into probationary tail.
  Increment `probationary_len`.

**Arena full** (eviction needed):
- Victim is always `prob_head` (probationary LRU head). If `probationary_len ==
  0` (edge case: entire cache somehow in protected), fall back to `prot_head`.
- Compute `victim_freq = sketch.estimate(&nodes[victim_idx].key)`.
- Compute `incoming_freq = sketch.estimate(&key)`.
- If `incoming_freq > victim_freq`:
  - Remove victim from map, unlink from probationary (`prob_unlink(victim_idx)`),
    decrement `probationary_len`.
  - Recycle victim slot for the new key (`in_protected = false`), push onto
    probationary MRU tail, increment `probationary_len`, insert into map.
- Otherwise: drop the newcomer (same as baseline).

### Helper methods to add/rename

Replace the existing single-list `unlink` and `push_back` with four helpers:

- `prob_unlink(idx)` — updates `prob_head`/`prob_tail`.
- `prob_push_back(idx)` — updates `prob_head`/`prob_tail`.
- `prot_unlink(idx)` — updates `prot_head`/`prot_tail`.
- `prot_push_back(idx)` — updates `prot_head`/`prot_tail`.

The `Node.prev` / `Node.next` fields are reused as-is; only the segment head/tail
pointers differ between segments.

### Invariant preservation

- **P1 (capacity_bound)**: `probationary_len + protected_len <= capacity` is an
  invariant maintained by all paths — eviction always frees exactly one slot
  before a new node is inserted.
- **P2 (value_fidelity)** and **P3 (no_phantom_items)**: unaffected — no changes
  to how values are stored or the map lookup path.
