# H02

Widening the probationary victim scan from k=4 to k=6 will find lower-frequency eviction candidates more reliably under the now-accurate sketch estimates, raising hit rate.

## Parent

cycle/0008/v001

## Changes

In `src/tiny_lfu/mod.rs`, change the constant declaration from:

```
const EVICTION_SCAN_K: usize = 4;
```

to:

```
const EVICTION_SCAN_K: usize = 6;
```

No other code changes. The victim selection loop in `put()` already iterates `for _ in 1..EVICTION_SCAN_K`, so changing the constant is the complete implementation. The scan still starts from `prob_head` (LRU end of probationary), selects the minimum-frequency candidate among the first k items, and falls back to `prot_head` if probationary is empty.

### Rationale

k=8 was tested in cycle 0005/v002 against the cycle 0004/v003 baseline (4× sketch width, no conservative update, no PROMO_THRESHOLD) and found flat — the insight concluded that "the coldest reachable candidate already appears within the first four LRU-tail positions." That closure was reached with substantially higher collision noise in the sketch.

Under the cycle/0008/v001 baseline (8× width + conservative update), frequency estimates are accurate enough that candidate ranks 5–6 in the LRU tail may correctly show lower true frequencies that were previously masked by collision inflation. A k=6 scan has not been tested at any prior point in the evolution history. If even one additional position in ten correctly identifies a colder victim, the scan overrides an otherwise suboptimal eviction decision. k=6 (rather than k=8) is tested as the minimal extension that opens the new window without jumping to a value already confirmed flat.

## Preservation invariants

- The scan still originates from `prob_head` and traverses toward `prob_tail` (LRU to MRU order).
- Tie-breaking remains first-found (LRU-biased): `victim_idx` updates only on strict `f < victim_freq`.
- The admission gate (`incoming_freq > victim_freq`) and all promotion/demotion logic are unchanged.
