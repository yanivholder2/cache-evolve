# H03

Scanning k=4 protected-LRU candidates at demotion time and demoting the minimum-frequency one (instead of always the LRU head) will preserve higher-value protected residents under the sharper sketch estimates, raising hit rate.

## Parent

cycle/0008/v001

## Changes

In `src/tiny_lfu/mod.rs`, add a new constant after `EVICTION_SCAN_K`:

```rust
/// Number of LRU-end protected candidates to scan when selecting the demotion
/// victim during protected-segment overflow.
const PROT_DEMOTION_SCAN_K: usize = 4;
```

Then replace the body of `maybe_demote_from_protected()`:

**Before:**

```rust
fn maybe_demote_from_protected(&mut self) {
    while self.protected_len > self.protected_capacity {
        if let Some(h) = self.prot_head {
            self.prot_unlink(h);
            self.protected_len -= 1;
            self.nodes[h].was_protected = true;
            self.prob_push_back(h);
            self.probationary_len += 1;
        } else {
            break;
        }
    }
}
```

**After:**

```rust
fn maybe_demote_from_protected(&mut self) {
    while self.protected_len > self.protected_capacity {
        // Scan up to PROT_DEMOTION_SCAN_K items from the LRU end of protected
        // and demote the one with the lowest estimated access frequency.
        let Some(head) = self.prot_head else { break };

        let mut victim_idx = head;
        let mut victim_freq = self.sketch.estimate(&self.nodes[head].key);

        let mut cursor = self.nodes[head].next;
        for _ in 1..PROT_DEMOTION_SCAN_K {
            let Some(c) = cursor else { break };
            let f = self.sketch.estimate(&self.nodes[c].key);
            if f < victim_freq {
                victim_freq = f;
                victim_idx = c;
            }
            cursor = self.nodes[c].next;
        }

        self.prot_unlink(victim_idx);
        self.protected_len -= 1;
        self.nodes[victim_idx].was_protected = true;
        self.prob_push_back(victim_idx);
        self.probationary_len += 1;
    }
}
```

No other code changes. The `was_protected` flag is set on the demoted item as before, preserving the bypass on re-access. The probationary and protected list helpers are unchanged.

### Rationale

Frequency-ordered demotion from protected was explored once in cycle 0006/v001, against the cycle 0005/v001 baseline — before conservative update and before 8× sketch width. The cycle 0006 insight found it flat and concluded that PROMO_THRESHOLD pre-filters entrants, leaving the protected LRU tail frequency-homogeneous (all items have freq ≥ 8 at promotion time, so no colder candidate stands out). That argument was valid under a noisy 4× sketch: collision inflation blurred the frequency differences among protected-LRU residents.

Under cycle/0008/v001's 8× width + conservative update, protected residents' frequencies are estimated accurately. The protected LRU tail contains the oldest-resident items — items promoted earliest that have not been recently accessed. Among those, genuine frequency differences now surface correctly: some promoted at freq=8–10 (borderline at the gate, subsequently cold) vs. others at freq=50+ (durably hot). A k=4 scan within the protected LRU candidates at demotion time can now identify and demote the genuinely colder resident, preserving higher-value items in protected. The cross-cycle open question explicitly calls this out as untested under the sharper sketch.

## Preservation invariants

- The demoted item still receives `was_protected = true` and re-enters probationary at the MRU end (`prob_push_back`), preserving the re-promotion bypass on next access.
- The scan is bounded to the protected list only and does not touch probationary nodes.
- The outer `while self.protected_len > self.protected_capacity` loop is preserved; each iteration demotes exactly one item.
