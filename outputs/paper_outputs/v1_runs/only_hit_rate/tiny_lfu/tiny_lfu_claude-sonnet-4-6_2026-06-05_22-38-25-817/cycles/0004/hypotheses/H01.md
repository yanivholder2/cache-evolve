# H01

Adding a ghost ring-buffer (capacity/4 slots) on top of v003's promotion gate will improve hit rate by fast-tracking re-admitted evicted keys into protected, bypassing the PROMO_THRESHOLD for items the cache already knows are hot.

## Parent

cycle/0003/v003

## Changes

Layer a ghost ring-buffer on top of v003's existing code. Every other aspect of v003 — 90/10 SLRU split, `PROMO_THRESHOLD=8`, `was_protected` bypass — must be preserved exactly.

**New fields on `TinyLfuCache`:**
```rust
ghost: Vec<u64>,   // ring-buffer of evicted key hashes
ghost_head: usize, // next write position
```

**Initialise in `try_new`:**
```rust
let ghost_size = (capacity / 4).max(4);
// ...
ghost: vec![u64::MAX; ghost_size],
ghost_head: 0,
```

**Add three private helpers (same signatures as v002 used):**
```rust
fn hash_key(&self, key: &K) -> u64 { ... }      // DefaultHasher, no seed
fn ghost_insert(&mut self, key: &K) { ... }     // write hash at ghost_head; advance mod len
fn ghost_contains(&self, key: &K) -> bool { ... } // linear scan for hash match
```

**Modify `put()` — eviction branch (`incoming_freq > victim_freq`):**
Before calling `self.map.remove(&victim_key)`, record the victim in the ghost:
```rust
self.ghost_insert(&victim_key);
```
After recycling the victim slot for the incoming key, check for a ghost hit:
```rust
if self.ghost_contains(&key) {
    self.nodes[victim_idx].in_protected = false; // prot_push_back sets it to true
    self.prot_push_back(victim_idx);
    self.protected_len += 1;
    // overflow: same demotion block as in get()
    if self.protected_len > self.protected_capacity {
        let d = self.prot_head.expect("prot non-empty");
        self.prot_unlink(d);
        self.protected_len -= 1;
        self.nodes[d].in_protected = false;
        self.nodes[d].was_protected = true;
        self.prob_push_back(d);
        self.probationary_len += 1;
    }
} else {
    self.prob_push_back(victim_idx);
    self.probationary_len += 1;
}
```

**Modify `put()` — pre-full arena branch (`nodes.len() < capacity`):**
Apply the same ghost check after `self.map.insert(key, idx)`:
```rust
if self.ghost_contains(&key) {
    self.prot_push_back(idx);
    self.nodes[idx].in_protected = true;
    self.protected_len += 1;
    if self.protected_len > self.protected_capacity { /* same demotion block */ }
} else {
    self.prob_push_back(idx);
    self.probationary_len += 1;
}
```
(Remove the unconditional `self.prob_push_back(idx); self.probationary_len += 1;` that v003 currently has in this branch.)

**Modify `get()` — `should_promote` computation:**
Add a ghost-hit as an additional bypass alongside `was_protected`:
```rust
let should_promote = self.nodes[idx].was_protected
    || self.ghost_contains(key)
    || self.sketch.estimate(key) > PROMO_THRESHOLD;
```

**Invariant to preserve:** The `was_protected` flag must still be cleared on promotion and set on demotion exactly as v003 does. Ghost insertion only occurs in `put()` when a victim is evicted out of the cache entirely (not on demotion from protected to probationary).

## Rationale

The cycle-0003 insight explicitly identified the ghost-set mechanism as the highest-priority experiment for cycle 0004, noting that v002's ghost buffer (capacity/8) fired too rarely because evicted items cycled out before re-request. Doubling to capacity/4 provides longer memory of evictions. This hypothesis isolates the ghost mechanism from the SLRU restructuring that accompanied it in v002, layering it cleanly on v003's proven promotion gate.
