# H01

Restrict victim eviction to items in the lowest-frequency cohort to improve hit-rate by ensuring only genuinely cold items are replaced before touching warmer cache residents.

## Parent

cycle/0007/v001

## Changes

In the victim-selection loop within the `put()` method (where capacity is full and a victim must be chosen), implement frequency-cohort filtering before scoring:

1. Compute the 25th percentile of frequency estimates across all cached items.
2. Scan through cached items twice:
   - **First pass** (cold cohort): Consider only items with `estimated_freq <= 25th_percentile` for eviction. Use the existing score formula `(age as f64) / (victim_freq + 2.0)` within this subset to find the best victim.
   - **Fallback pass** (if cold cohort is empty): Revert to the current full-cache scan if no cold items are found.

Keep all other logic unchanged: the admission gate threshold (`incoming_freq > victim_freq`), the burstiness tracking from c0007/v001, the sketch parameters, and the LRU ordering.

## Rationale

The incumbent policy (c0007/v001) uses a single continuous score across all items, which can occasionally evict moderately-warm items if they are very old. This hypothesis tests whether explicitly partitioning candidates into a cold cohort first—similar in intent to H02 from Cycle 0007 (frequency tiering), but applied to victim selection only rather than all decision logic—can improve hit-rate by guaranteeing that eviction targets the coldest items first. Unlike H02 (which regressed on tiering), this approach is more conservative: it only filters the victim pool, not the entire scoring surface, reducing the risk of losing fine-grained discrimination. The threshold value (25th percentile) is chosen to align with typical cache working-set models where a small tail of infrequently-used items should be evicted before touching the active set.
