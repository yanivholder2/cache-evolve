# H01

Inserting stash-promoted items at the MRU end of the target bucket (Back) instead of the LRU end (Front) raises hit rate by letting recently-reactivated cold items earn probing-tier status on their next access rather than having to crawl from the coldest position.

## Parent

baseline

## Changes

In `src/dash/segments/dash_segment.rs`, change the single call-site in the `Segment::get` implementation from:

```rust
fn get(&mut self, key: &K) -> Option<&Item<K, V>> {
    promotion_get(&mut self.core, key, InsertPosition::Front)
}
```

to:

```rust
fn get(&mut self, key: &K) -> Option<&Item<K, V>> {
    promotion_get(&mut self.core, key, InsertPosition::Back)
}
```

`InsertPosition::Back` is already wired through every downstream function (`promote_to_target`, `promote_to_probing`, `demote_from_normal_bucket`) via the `insert_pos` parameter — no other changes are required. The invariant that every key occupies exactly one slot is unaffected because the promotion logic removes before reinserting regardless of position. The effect is that a stash hit lands an item at the MRU end of its target bucket immediately, making it the `promotion_candidate_index()` on its very next access rather than the eviction candidate.
