# H03

Incrementing lfu_counter by 1 on the stash-hit item before promoting it to its target bucket lets proven-accessed items arrive already protected from eviction by cold newcomers, raising hit rate by closing the one-access gap between stash exit and target protection.

## Parent

cycle/0008/v001

## Changes

Keep all overlay files from cycle/0008/v001 unchanged (`geometry.rs`, `eviction_policy.rs`, `dash_bucket.rs`) **except** `src/dash/segments/dash_segment.rs`.

In `dash_segment.rs`, in `promotion_get()`, locate the stash-hit branch. After `remove_at` and before the call to `promote_to_target`, add one line to credit the stash access:

```rust
if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key) {
    debug!("promotion_get: key={key:?} found in stash -> target={target_idx} ...");
    let mut data = core.stash_buckets[stash_idx].remove_at(item_idx);
    data.lfu_counter += 1;  // credit the stash-hit access before entering target
    promote_to_target(core, data, insert_pos);
    ...
}
```

The `mut` binding on `data` is required; the rest of the stash-hit branch is unchanged.

Do **not** modify the second-chance path in `put()` — items evicted from a full stash without ever being accessed have `lfu_counter == 0` (set during demotion), and they should enter the target at counter 0 as cold probationers. Do not touch the `lfu_counter` reset on demotion in `demote_from_normal_bucket`, the geometry, or the `ClassicLRUFreqProtect` policy.

## Rationale

Under `ClassicLRUFreqProtect`, an item in the target tier is protected from eviction by cold newcomers only when its `lfu_counter > 0`. Currently, stash-hit promotion uses `get_position` (which locates the item without calling the eviction-policy hook) and `remove_at`, so the item enters target with whatever counter it carried in the stash — almost always 0, since counters are reset on demotion and the stash-hit is typically the first post-insertion access. The net effect is a window of one full target access during which a genuinely hot item is as vulnerable to eviction as a freshly inserted cold item.

The stash hit itself is unambiguous evidence of post-insertion access. Crediting it directly closes this protection gap without weakening the zero-access eviction guard for truly cold items, and without affecting the proven second-chance or geometry configuration.
