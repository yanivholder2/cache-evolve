# H01

Promote target keys on a per-key touch count rather than bucket rank, sidestepping the sparse-target occupancy ceiling that caps every rank gate, to raise hit-rate.

## Parent

cycle/0005/v003

## Changes

The root bottleneck identified across cycles 0004–0005 is that target buckets
skew to len-1/len-2, so the rank-based promotion gate (`is_in_top_quarter`) has
no daylight — a genuinely warm key sitting in a len-2 bucket but not at the
hottest slot never promotes. This hypothesis replaces the density-dependent rank
signal with a density-independent per-key touch counter, attacking that ceiling
directly instead of trying to widen the gate fraction (now saturated).

Modify only `src/dash/segments/dash_segment.rs` (do not touch the
contract-protected files). Concretely:

- Add a field `target_touches: std::collections::HashMap<K, u8>` to the
  `DashSegment` struct and initialise it empty in both `try_new` and `new`.
  Keep the existing `core: SegmentCore<K, V>` field.
- Change the `get` method so it passes `&mut self.target_touches` alongside
  `&mut self.core` into `promotion_get` (widen `promotion_get`'s signature to
  take the map).
- In `promotion_get`, in the **target-hit branch** (where `is_in_top_quarter`
  is consulted): increment `target_touches[key]` on every target hit. Compute
  `is_promotable = is_in_top_quarter(...) || target_touches[key] >= 2`. When the
  key promotes to probing, remove its entry from `target_touches`. When a key is
  first landed into target from a stash hit (the `promote_to_target` path),
  ensure its counter starts at 0 (so the slow first hop of v003's two-speed
  promotion is preserved — a freshly-admitted key still needs two demonstrated
  target accesses before the counter fires).

Preserve all existing invariants: the two-speed landing positions
(stash→target at `Front`, target→probing at `Back`, demotions at `Back`) stay
exactly as in v003; the unreachable-after-insert guarantees still hold; and the
stash admission step is untouched. The map only adds a promotion trigger that
works on len-1/len-2 buckets where the rank rule degenerates. Stale entries for
evicted keys are tolerable (the key population is small); optionally remove a
key's entry whenever it is observed missing from both normal buckets.

## Rationale (optional)

Every prior promotion lever (quarter gate, half gate, two-speed) was throttled
by the same small-bucket occupancy ceiling. A touch counter is the one signal
that does not need bucket density to discriminate warm from cold, so it tests
whether the ceiling is truly structural or merely an artifact of using *rank*
as the warmth proxy. It composes with — rather than re-runs — v003's winning
two-speed structure.
