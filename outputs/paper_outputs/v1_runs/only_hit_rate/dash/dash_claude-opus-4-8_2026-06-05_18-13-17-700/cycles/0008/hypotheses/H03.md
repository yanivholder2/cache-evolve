# H03

Giving each stash key a third salted home so overflow relocation tries two alternates before dropping attacks the "alternate is usually full too" cause and lifts hit-rate.

## Parent

cycle/0007/v001

## Changes

The winner's single-hop relocation rescues a stash overflow victim only when
its one `stash_alt_index` bucket happens to be non-full — and cycle 0006/0007
diagnosed that this lone alternate is usually full too, which is *why* the hop
left dwell-time headroom on the table. v003 attacked that by adding cascade
depth; this hypothesis attacks the same structural cause by widening *breadth*
of the home-set, with no cascade machinery, so the two levers can be compared
cleanly. It stays reactive (primary insert is still always primary-first), so
it does not repeat the regressed power-of-two-choices admission balancing.

In `src/shared/utils.rs`, add a second independent salt and a third-home index
helper alongside the existing `stash_alt_index`:

- `pub const STASH_ALT_SALT2: u64 = 0xC2B2_AE3D_27D4_EB4F;` (a distinct mixing
  constant).
- `pub fn stash_alt_index2<K>(key, size)` mirroring `stash_alt_index` but using
  `STASH_ALT_SALT2` via `get_index_with_salt`; collapse to `get_index` when
  `size < 2`.

In `src/dash/segments/dash_segment.rs`:

- In `stash_insert`, when the overflow `victim`'s primary `stash_alt_index`
  bucket is full or non-distinct, try `stash_alt_index2` next: if it is distinct
  from both primary and the first alternate and non-full, `put_at` the victim
  there (`InsertPosition::Back`); only drop the victim when *both* alternates are
  unavailable. This remains at most one extra seat per `put` (no eviction, no
  cascade), preserving occupancy conservation.
- In `promotion_get`, extend the stash-hit search to check `stash_alt_index2` as
  a third home after the primary and first alternate, so a victim relocated into
  the third home is still found and promoted.

Keep the two-speed promotion, touch counter, top-quarter gate, and 3:1 geometry
exactly as in v001. The invariant: every placement still lands in one of the
key's (now three) legal homes, and at most one new seat is added per `put`.

## Rationale (optional)

This isolates breadth-of-homes from depth-of-cascade: if a second non-full
alternate exists more often than the first, breadth captures dwell-time the
single hop missed without paying the per-op cost of an eviction cascade.
