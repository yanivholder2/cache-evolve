# H03

Cap the protected segment at a fixed fraction of the bucket and demote its LRU member on overflow, so a fully-proven working set cannot crowd out all probation, lifting hit-rate.

## Parent

cycle/0002/v003

## Changes

Modify v003's segmented bucket in `src/associative_cache/associative_cache_bucket.rs`. Today protection is unbounded: every key that earns a second hit is promoted to `lfu_counter == 1` and never demoted, so the protected region can grow to fill the entire bucket, leaving no probationary slots and collapsing the bucket back toward plain LRU on a churning workload.

Introduce a bounded protected segment with demotion:

1. Define a protected cap as a fraction of `get_max_size()` — implement `protected_cap = (max_size * 4) / 5` (rounded down, minimum 1), giving an ~80/20 protected/probationary split. Keep this as a small helper so the ratio is easy to tune.
2. In `get_from_position`, when promoting a probationary item (`lfu_counter` 0 → 1): first count current protected residents (`items.iter().filter(|i| i.lfu_counter >= 1).count()`). If that count is already at `protected_cap`, **demote the protected LRU item back to probation** by setting its `lfu_counter = 0` before performing the promotion. The protected LRU item is the lowest-index resident with `lfu_counter >= 1` (protected items are moved to the back on hit, so the frontmost protected item is least-recently-used). Then promote the current item (set its counter to 1) and move it to the back as v003 already does.
3. Leave admission (`put` front insert), the eviction rule (`eviction_candidate_index` prefers `lfu_counter == 0`, falls back to index 0), and all capacity invariants unchanged.

Net effect: the protected set is held to a fixed size; a newly proven key displaces the stalest protected key into probation rather than enlarging protection forever. This preserves "no aging of survivors that stay hot" (they keep getting re-promoted) while preventing protected saturation. Keep the policy enum / JNI ordinal mapping pristine.

## Rationale (optional)

The standing open question from cycle 0002 is whether an explicit protected/probationary ratio beats v003's implicit, unbounded split. Capacity-collision pressure means an unbounded protected region eventually starves probation; a capped SLRU with demotion directly tests the canonical fix.
