# H03

Collapse the full-bucket admission path's two O(n) memmoves (evict-remove plus insert-at-front) into a single in-place rotate-and-replace, lowering per-op-time on `put`.

## Parent

cycle/0007/v002

## Changes

In `src/associative_cache/associative_cache_bucket.rs`, optimize the
full-bucket branch of `put`. Today a full admission does
`let evicted = self.evict_item();` (an `items.remove(idx)`) followed by
`self.items.insert(0, item);` (a full-length right shift) — two O(bucket_size)
memmoves plus a length-down-then-length-up churn.

Add a fast path for the common case where the eviction candidate is the oldest
*probationary* item (i.e. `protected_count < len`, so
`idx = len - protected_count - 1`, the boundary slot — not the all-protected
fallback). In that case the desired post-state is: new probationary item at
index 0, former prefix items `[0, idx)` shifted to `[1, idx]`, the evicted
oldest-probationary at `idx` removed, protected suffix untouched. Achieve it
without changing the vector length: rotate the prefix `self.items[..=idx]`
right by one with `rotate_right(1)` (moving the oldest-probationary element to
index 0), then `let evicted = std::mem::replace(&mut self.items[0], item);`.
Return `(&self.items[0], Some(evicted))`. `protected_count` is unchanged
because both the dropped victim and the new item are probationary.

Keep the all-protected fallback (`protected_count == len`, victim at index 0)
on the existing remove+insert path. Preserve `put`'s existing in-place update
branch for keys already present (the `get_position` hit), and do not touch
`get_from_position`, `eviction_candidate_index`, or the geometry overlay.

## Rationale (optional)

The boundary-eviction case is the dominant steady-state admission once buckets
fill, and it currently pays two full memmoves and a `Vec` length round-trip.
Folding them into one prefix rotate plus an in-place `mem::replace` keeps the
result byte-identical (same ordering, same evicted item, same counts) while
roughly halving the per-`put` data movement — a behavior-neutral per-op-time
win on the `put` p50 (143ns baseline).
