# H01

Repartitioning the same total capacity into fewer, wider buckets (one halving of the bucket count) raises hit-rate by giving each collision set more associativity to retain hot keys.

## Parent

cycle/0005/v003

## Changes

Edit only `src/shared/geometry.rs`; leave the bucket logic (the FIFO-probation
segmented-LRU plus the v003 no-op-reorder fast path) untouched so this is a pure
associativity test.

In `BaselineGeometry::layout`, instead of returning the stored
`(self.num_of_buckets, self.bucket_size)` unchanged, derive a *coarser* split
that conserves total capacity exactly:

- Start with `nb = self.num_of_buckets`, `bs = self.bucket_size`.
- Apply **one** widening step: if `nb` is even and `nb > 1`, set
  `nb = nb / 2` and `bs = bs * 2`. Otherwise (odd or already 1) leave both
  unchanged — fall back to the identity split so the capacity invariant
  `nb * bs == self.num_of_buckets * self.bucket_size` always holds.
- Return `(nb, bs)`.

Keep the `BaselineGeometry` type name and the `for_settings` constructor signature
intact — the construction glue and the invariant gate both build the geometry
through them, so the entry point must not change. Do not touch
`num_of_buckets`/`bucket_size` validation in settings.

Rationale: prior geometry coarsening gave only a small early gain, but it was
never layered on top of the current best segmented logic. A single controlled
halving (not a collapse toward one fully-associative bucket, which would forfeit
routing) probes whether modestly larger collision sets let the promote-on-first
segmented scheme hold a larger hot working set without eroding any earned
protection.
