# H01

Repartitioning the fixed capacity into fewer, wider buckets raises hit rate by lowering per-bucket collision pressure.

## Parent

baseline

## Changes

Overlay `src/shared/geometry.rs`. Keep the public type name `BaselineGeometry`
and its `for_settings` constructor (the factory and invariant gate both build
the geometry through that entry point), but change `BucketGeometry::layout` so
it returns a *coarser* split of the same total capacity instead of echoing the
harness-provided `(num_of_buckets, bucket_size)`.

Concretely, inside `layout(&self, total_capacity)`:

1. Compute `total = self.num_of_buckets * self.bucket_size` (this equals
   `total_capacity` on the eval path; prefer the stored fields so the result is
   self-consistent).
2. Choose a new bucket count that is *half* the original where that stays
   capacity-exact: if `self.num_of_buckets` is even and `>= 2`, return
   `(self.num_of_buckets / 2, self.bucket_size * 2)`; otherwise fall back to the
   original `(self.num_of_buckets, self.bucket_size)` unchanged.

This doubles associativity (e.g. 128×16 → 64×32 at the swept budget) so hot
keys that previously collided in a 16-way bucket now share a 32-way bucket and
evict each other less often.

Invariants to preserve: the returned `num * size` MUST equal the original total
(P4 capacity_conservation runs `factory::resolve_geometry` across many budgets,
including odd `num_of_buckets` from the proptest range, so the even-only guard
above is required to stay exact). Routing in `AssociativeCache` already derives
the bucket index from `buckets.len()`, so P2 slot_legality is unaffected. Do not
touch any file other than `geometry.rs`.
