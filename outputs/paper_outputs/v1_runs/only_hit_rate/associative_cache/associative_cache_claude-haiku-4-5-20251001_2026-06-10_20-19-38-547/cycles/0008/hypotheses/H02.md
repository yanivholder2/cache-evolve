# H02

Implement a three-tier stash with frequency-based promotion where newly evicted items enter a warm tier, and only after a second re-access are promoted to hot, reducing pollution from transient items while preserving recovery capacity.

## Parent

cycle/0006/v002

## Changes

Extend the two-tier structure to three tiers: cold, warm, and hot. In `AssociativeCache<K, V>`, add a warm_stash field and warm_stash_capacity alongside the existing cold and hot stash fields.

**Partition allocation**: Distribute the 25% total stash as cold 8%, warm 9%, hot 8% (100 * 8/9/8 split).

**Eviction logic** (in `put`): When an item is evicted from the bucket, add it to the cold stash (unchanged).

**Lookup and promotion logic** (in `get_and_update_item`):
- On primary bucket hit: return value (unchanged).
- On hot stash hit: return value (unchanged).
- On warm stash hit: return value directly without promotion (warm items need one more re-access to be promoted to hot).
- On cold stash hit: promote the item from cold to warm tier (instead of directly to hot). If warm is at capacity, evict the oldest item from warm tier using FIFO.

Add a `promote_cold_to_warm()` helper method analogous to `promote_cold_to_hot()` in the parent design.

This organizational change filters out transient evictions (those that don't re-access a second time) before committing them to the hot tier, where protection is most expensive. The workload's re-access pattern will determine whether this two-step promotion reduces hot-tier pollution or loses valuable items prematurely.

## Rationale

The cross-cycle insights explicitly mention "frequency-based tiering" and "multi-level hierarchies" as untested organizational strategies. This hypothesis tests a simple frequency signal (re-access count) coupled with hierarchical promotion. Unlike prior filtering attempts (which tried to suppress insertion or promotion), this mechanism promotes eagerly but stages promotion across tiers, allowing the cache to observe re-access behavior before allocating premium hot-tier space. The distinction from prior filtering is that it doesn't discard items; it observes them longer before committing resources.
