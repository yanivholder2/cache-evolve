# H01

Add a bounded overflow stash buffer to capture evicted items and provide a second-chance lookup on cache misses, raising hit rate by reducing loss of evicted data.

## Parent

baseline

## Changes

Introduce a stash field to the AssociativeCache struct: a bounded Vec<Item<K, V>> with a fixed capacity of approximately 10% of total cache capacity (e.g., 128 items for a 2048-item cache). When a bucket evicts an item via evict_item(), capture that item and insert it into the stash instead of discarding. Use FIFO logic: if the stash reaches capacity, discard the oldest item to make room for new evictions.

Modify AssociativeCache::get_and_update_item() to perform a secondary lookup in the stash on primary bucket miss. On stash hit, attempt to re-insert the item back into its primary bucket if space is available; otherwise, leave it in the stash and return a reference to the stashed copy. This preserves access patterns for items that would otherwise be permanently lost to eviction, improving hit rate especially on workloads with temporal working-set re-use.

## Rationale

The baseline offers no recovery for evicted items. A stash trades modest metadata overhead for a second-chance window that captures useful data that hash collisions would otherwise discard entirely.
