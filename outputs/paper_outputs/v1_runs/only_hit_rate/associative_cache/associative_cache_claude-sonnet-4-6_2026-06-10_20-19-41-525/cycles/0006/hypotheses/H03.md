# H03

Applying wide-bucket geometry with pure minimum-counter LFU eviction — no cold-first positional bias, no decay pass, no mid-point insertion — will match or exceed the best-known hit-rate by letting frequency signal alone drive eviction from a large-enough candidate pool.

## Changes

Two overlay files must be created; `src/associative_cache/associative_cache_bucket.rs` is NOT overlaid (use the trait default `evict_item()` and `put()`).

**1. `src/shared/geometry.rs` — factor-4 wide-bucket repartition (identical to cycle/0005/v003):**

Apply the same factor-4 repartition as the cross-cycle winners: divide `num_of_buckets` by 4, multiply `bucket_size` by 4, preserving total capacity exactly. At the standard harness sweep point (128 × 16 = 2048), this yields 32 × 64. Copy the `BaselineGeometry::for_settings()` implementation from `cycle/0005/v003/src/shared/geometry.rs` verbatim — the capacity-conservation guard (`total % target_num_buckets == 0`) must be preserved.

**2. `src/shared/eviction_policy.rs` — rework `ClassicLRU` to implement pure min-counter LFU:**

Change `ClassicLRU::get_from_position` to increment `lfu_counter` (capped at 4) and keep the item in place — do not move it to the back of the bucket:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    // Increment frequency counter, capped at 4 so no item can accumulate
    // unbounded protection tenure.
    items[position].lfu_counter = items[position].lfu_counter.saturating_add(1).min(4);
    position  // item stays in place; no positional promotion
}
```

Change `ClassicLRU::eviction_candidate_index` to select the item with the minimum `lfu_counter`, with the lowest index as a tiebreaker (oldest insertion wins among equals):

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    items
        .iter()
        .enumerate()
        .min_by_key(|(i, item)| (item.lfu_counter, *i))
        .map(|(i, _)| i)
        .unwrap_or(0)
}
```

Leave `promotion_candidate_index` and all other policy structs (`TimestampLRU`, `Lifo`, `Lfu`, `Fifo`, `Swap`) completely unchanged. The rest of the `eviction_policy.rs` file — `EvictionPolicyKind` enum, `build()`, `all()`, tests — must be preserved byte-for-byte.

**No `associative_cache_bucket.rs` overlay.** The trait default `put()` appends new items to the back (index `len`) and calls `evict_item()` which delegates to `eviction_candidate_index` from the modified `ClassicLRU`. No mid-point insertion, no decay, no cold-first scan.

**Summary of the resulting configuration:**
- Geometry: 32 × 64 (wide-bucket, factor-4, total capacity preserved)
- On GET hit: counter++ (capped at 4), item stays at its current index
- On eviction: remove item at min(lfu_counter), ties broken by lowest index
- On insertion: append to back (standard `Vec::push`)
- No decay, no cold-first bias, no mid-point insertion

## Rationale

The accumulated mechanism stack in the current best-known config (cold-first + mid-point + decay + cap) represents two cycles of refinements that have converged to a local optimum at 0.7289. Each added mechanism introduced new interactions (mid-point disrupts LFU recency structure; decay compresses counter differentiation), raising implementation complexity without further gain. Pure min-counter LFU with a wide candidate pool tests whether frequency-only eviction — the simplest possible signal that distinguishes scan items (counter == 0) from recurrent items (counter ≥ 1) — can match the accumulated stack when given 64-slot buckets where cold-pool exhaustion is rare. The counter cap at 4 eliminates the warm-lock problem without a decay pass: items accessed fewer than 4 times stay at lower counts and are evicted before items accessed 5+ times, restoring cold supply passively. This is an independent baseline probe, not an incremental refinement, and its result will determine whether the local optimum is a property of the eviction mechanism family or of the specific mechanism stack.
