# H02

Tightening cycle/0002/v002's eviction cold threshold from `lfu_counter == 0` to `lfu_counter <= 1` will improve hit-rate by also evicting single-hit items that currently survive as warm despite being likely scan traffic.

## Parent

cycle/0002/v002

## Changes

Overlay `src/shared/eviction_policy.rs`. In `ClassicLRU::eviction_candidate_index`, change the scan predicate from `item.lfu_counter == 0` to `item.lfu_counter <= 1`:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    items
        .iter()
        .position(|item| item.lfu_counter <= 1)
        .unwrap_or(0)
}
```

All other logic in `ClassicLRU` is unchanged:
- `get_from_position` still increments `items[position].lfu_counter` and moves the item to the back.
- The `.unwrap_or(0)` fallback to the plain LRU front when every item has `lfu_counter >= 2` is preserved.

Do **not** overlay `src/shared/geometry.rs` or `src/associative_cache/associative_cache_bucket.rs` — both are inherited unchanged from cycle/0002/v002.

## Rationale

In cycle/0002/v002 a single GET hit is sufficient for an item to escape cold eviction forever (counter goes 0 → 1, and the scan only targets counter == 0). On scan-heavy LIRS workload-a, each new item typically receives one access when it is inserted (the initial miss-then-fill), which is enough to increment its counter to 1 and shield it from cold eviction on subsequent scan passes. Raising the threshold to `lfu_counter <= 1` means an item must have been accessed at least twice to be considered warm, providing tighter separation between genuine hot-set entries and single-pass scan items.
