# H03

Replacing the O(n) `remove + push` sequence in `ClassicLRU::get_from_position` with an O(1) swap-to-back reduces per-get latency by eliminating element-shifting across the bucket's items vector.

## Parent

baseline

## Changes

Only `src/shared/eviction_policy.rs` changes; no other file is touched.

In `ClassicLRU::get_from_position`, replace the current body:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    let item = items.remove(position);   // O(n): shifts every element after position
    items.push(item);                    // appends to back
    items.len() - 1
}
```

with a single swap:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    let last = items.len() - 1;
    items.swap(position, last);          // O(1): exchanges two elements in place
    last
}
```

**Invariants preserved:**
- The accessed item still lands at index `items.len() - 1` (the MRU position),
  so `ClassicLRU::promotion_candidate_index` (which returns `items.len() - 1`)
  continues to identify the correct item.
- The eviction candidate remains at index 0; `ClassicLRU::eviction_candidate_index`
  returns 0 and is unchanged.
- No item is lost or duplicated; `items.len()` is unchanged.

**Semantics trade-off:** the item that was previously at the back (most-recently-used)
gets displaced to `position` rather than staying adjacent to other recent items. The
strict LRU ordering of intermediate slots is no longer maintained, making this an
approximate LRU. The approximation is acceptable because the two boundary slots
(index 0 = eviction victim, index len-1 = most-recently-used) remain correct; only
the middle ordering is disturbed.

The per-op-time improvement targets the `get` path directly. The `put` path calls
`evict_item` (via `eviction_candidate_index` + `remove_at`), which is unaffected.
