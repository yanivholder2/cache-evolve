# H02

Removing the `timestamp: Instant` field from `Item` reduces per-item metadata from 40 bytes to 24 bytes by eliminating a 16-byte field the ClassicLRU baseline never reads.

## Parent

baseline

## Changes

Two files change together; they must be applied as a unit.

### `src/shared/item.rs`

Remove the `timestamp` field and all infrastructure that supports it:

- Delete `use std::time::Instant;` from the imports (keep `use std::fmt` and `use std::hash::Hash`).
- Remove the `timestamp: Instant` field from the `Item<K, V>` struct, leaving:
  ```rust
  pub struct Item<K, V> { pub key: K, pub value: V, pub lfu_counter: usize }
  ```
- In `Item::new`, remove the `timestamp: Instant::now()` line from the struct
  initialiser.
- In the `Display` impl, remove `timestamp` from the `write!` format string and
  its argument.
- The `PartialEq`, `Eq`, and `Clone` impls need no changes (they do not reference
  `timestamp`).

After this change `std::mem::size_of::<Item<u64,u64>>()` drops from 40 to 24 bytes.

### `src/shared/eviction_policy.rs`

`TimestampLRU` currently uses `item.timestamp` which no longer exists. Replace its
implementation with one that uses `lfu_counter` as a monotonically increasing
recency sequence number:

- Remove `use std::time::Instant;` from the imports.
- In `TimestampLRU::get_from_position`: instead of writing `items[position].timestamp`,
  compute `let next_seq = items.iter().map(|i| i.lfu_counter).max().unwrap_or(0) + 1;`
  then set `items[position].lfu_counter = next_seq;`. Return `position` unchanged
  (items stay in place, as before).
- In `TimestampLRU::eviction_candidate_index`: change from `min_by_key(item.timestamp)`
  to `min_by_key(item.lfu_counter)` — the item with the smallest sequence number is the
  least recently used.
- In `TimestampLRU::promotion_candidate_index`: change from `max_by_key(item.timestamp)`
  to `max_by_key(item.lfu_counter)`.

All other policy structs (`ClassicLRU`, `Lifo`, `Lfu`, `Fifo`, `Swap`) do not reference
`timestamp` and need no changes.
