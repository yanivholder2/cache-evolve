# H01

Replacing uniform magnitude-2 decay with value-split decay (magnitude 2 for counter ≤ 2, magnitude 1 for counter ≥ 3) in the warm-lock path will raise hit-rate by concentrating cold-pool replenishment on the lukewarm tier while preserving the hot tier's frequency signal.

## Parent

cycle/0008/v003

## Changes

In `evict_item()` in `src/associative_cache/associative_cache_bucket.rs`, replace the uniform
warm-lock decay loop with a value-split version:

Current code (Step 2):
```rust
for item in self.items.iter_mut() {
    item.lfu_counter = item.lfu_counter.saturating_sub(2);
}
Some(self.remove_at(0))
```

New code (Step 2):
```rust
for item in self.items.iter_mut() {
    if item.lfu_counter <= 2 {
        // Lukewarm tier (counter 1 or 2): decay aggressively — both become cold (0)
        item.lfu_counter = item.lfu_counter.saturating_sub(2);
    } else {
        // Hot tier (counter 3 or 4): decay conservatively — preserve most of the signal
        // counter 3 → 2 (warm), counter 4 → 3 (warm)
        item.lfu_counter = item.lfu_counter.saturating_sub(1);
    }
}
Some(self.remove_at(0))
```

The rationale: cycle 0009 confirmed that position is not a reliable proxy for "genuinely hot"
under cap-4, but counter value is. This change honors that finding by decaying the lukewarm
tier (counter 1–2) at full magnitude-2 (collapsing it to cold in one pass) while reducing the
decay cost on the hot tier (counter 3–4), leaving hot items at counter 2–3 rather than 1–2.
The net effect is a larger cold pool after each warm-lock event alongside a better-preserved
frequency gradient above it.

All other logic is unchanged: `eviction_policy.rs` keeps the counter cap at 4 and
`get_from_position` promotion logic; `geometry.rs` keeps the factor-4 wide-bucket layout;
the pre-decay cold-first scan (Step 1) and the post-decay `remove_at(0)` fallback remain as-is.

## Rationale

Cycle 0009 v001 demonstrated that position-split decay is inert because upper-half items span
the full counter range 1–4, making position an unreliable discriminator. The cycle 0009 insight
explicitly flags value-split decay as the next logical axis: "a value-split may preserve the hot
tier without compressing its frequency signal." This hypothesis directly tests that conjecture.
Under the current uniform magnitude-2 decay, a counter-3 item (accessed three times since the
last decay) is treated identically to a counter-1 item (accessed once), collapsing both to 0
and 1 respectively — but the counter-3 item is meaningfully hotter. The value-split keeps
counter-3 → 2 and counter-4 → 3, making these items harder to evict immediately after a
warm-lock recovery, which should reduce spurious hot-item evictions on the next eviction call.
