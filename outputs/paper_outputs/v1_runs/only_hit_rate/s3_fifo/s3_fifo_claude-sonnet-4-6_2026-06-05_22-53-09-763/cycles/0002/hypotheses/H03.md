# H03

Combining v001's enlarged main queue (small = 10%) with a half-size ghost queue raises hit rate beyond v001 alone by layering sharper ghost signal precision on top of the increased resident capacity.

## Parent

cycle/0001/v001

## Changes

Starting from v001's overlay (which already sets `small_size = capacity / 10`), make three additions to `src/s3_fifo/mod.rs`:

1. Add a `ghost_size` field to the `S3Fifo` struct:

```rust
pub struct S3Fifo<K: PartialEq + Clone, V> {
    small: VecDeque<Entry<K, V>>,
    main: VecDeque<Entry<K, V>>,
    ghost: VecDeque<K>,
    small_size: usize,
    main_size: usize,
    ghost_size: usize,   // new field
}
```

2. In `try_new()`, after computing `main_size` (which in v001 is `capacity - capacity/10`), compute `ghost_size` and wire it in:

```rust
let ghost_size = (main_size / 2).max(1);
Some(Self {
    small: VecDeque::with_capacity(small_size),
    main: VecDeque::with_capacity(main_size),
    ghost: VecDeque::with_capacity(ghost_size),
    small_size,
    main_size,
    ghost_size,
})
```

3. In `evict_small()`, update the ghost overflow guard from `self.main_size` to `self.ghost_size`:

```rust
if self.ghost.len() >= self.ghost_size {
    self.ghost.pop_back();
}
```

The 10% small queue sizing from v001 (`capacity / 10`) is preserved. Only the ghost capacity changes: for a 2048-slot cache, the ghost shrinks from 1844 (v001's `main_size`) to ~922 keys. The promotion threshold (`freq > 1`), `MAX_FREQ`, and all eviction logic remain as in v001.

## Rationale

v001 grew main to 1844 slots. With more capacity in main, items cycle through main more slowly on average, meaning each eviction from main is of a slightly colder item than in the baseline. A full-main_size ghost window (1844 keys) may therefore capture more noise than before: items evicted from the now-larger main include items that were genuinely cold by the time they left, and their ghost entries inflate the tracking history with keys unlikely to benefit from direct promotion. Halving the ghost to 922 keys keeps only the most recently evicted items tracked — precisely where re-use signal is densest — while shedding the long tail of the window that v003's failure showed carries noise. The two changes are expected to be complementary: v001 maximises the value of a cache slot; the ghost shrinkage maximises the value of a ghost entry.
