# H03

Inserting ghost-hit items into the main queue with an initial freq of 1 instead of 0 will improve hit rate by giving recently re-requested items one free second-chance credit, reflecting the strong re-use signal that a ghost hit represents.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, locate the `put()` function's ghost-hit branch — the code path that executes when the incoming key is found in the ghost queue. In that branch, after ensuring main has capacity and removing the key from ghost, a new `Entry` is constructed and pushed into main. Change its initial `freq` from `0` to `1`:

Find the ghost-hit insertion statement, which will resemble:

```rust
self.main.push_back(Entry { key, value, freq: 0 });
```

and change it to:

```rust
self.main.push_back(Entry { key, value, freq: 1 });
```

This is the only change. Keep all baseline parameters intact:
- `small_size = (capacity / 10).max(1).min(capacity - 1)`
- Ghost capacity = `main_size` (no `ghost_size` field; ghost is allocated with `main_size`)
- Small-queue promotion threshold: `tail.freq > 1`
- `MAX_FREQ = 3`
- All paths that insert NEW keys (non-ghost) into small or main continue to use `freq: 0`

## Rationale

A ghost hit is the strongest re-use signal the cache observes: the key was recently displaced from main and is already being requested again within the ghost's retention window. Despite this signal, the current policy re-inserts the item at `freq: 0`, placing it immediately at risk of eviction if main is under pressure — the same vulnerability as a brand-new, never-seen key. Setting `freq: 1` on ghost re-entry gives the item one free second-chance cycle in main, matching the resilience earned by a small-queue item that was accessed twice before graduation. The change is confined to a single insertion site and preserves all eviction invariants: the item will still be evicted once its freq reaches 0 through the normal second-chance loop.
