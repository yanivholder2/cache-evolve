# H03

Moving main-queue items to the front of the queue on every cache hit combines recency and frequency signals in the resident population, improving hit rate by keeping actively re-accessed items away from the eviction frontier.

## Parent

cycle/0007/v001

## Changes

In `get()`, replace the in-place main-queue frequency increment with a position-based extract-and-reinsert pattern that moves the accessed item to the front of `main`. The existing iterator-mutation approach (`iter_mut().find()`) cannot extract entries; replace the main-queue branch with:

```rust
// main queue: freq increment + move-to-front
if let Some(pos) = self.main.iter().position(|e| &e.key == key) {
    self.main[pos].freq = (self.main[pos].freq.saturating_add(1)).min(MAX_FREQ);
    let entry = self.main.remove(pos).unwrap();
    self.main.push_front(entry);
    return self.main.front().map(|e| &e.value);
}
```

The small-queue eager-promotion branch (lines 82–98 of the parent) is unchanged: small-queue items with freq >= 2 are still extracted and pushed to the front of main. The `put()`, `evict_main()`, `evict_small()`, and `try_new()` functions are all unchanged.

Note that `VecDeque::remove(pos)` is O(n) — the same asymptotic cost as the existing `iter_mut().find()` scan — so this change does not alter the algorithmic complexity of `get()`.

## Rationale

The current main queue is a pure frequency-weighted FIFO: hits only increment the frequency counter in place, so an item can drift arbitrarily close to the eviction tail between accesses. The second-chance mechanism in `evict_main()` recycles high-frequency items back to the front, but only at eviction time — items must survive to the tail before recency is reasserted. Adding an unconditional move-to-front on every main-queue hit prevents this drift entirely, continuously refreshing the recency position of any item that receives a cache hit. Prior cycles tested conditional repositioning (saturation-triggered in cycle/0006/v002, midpoint insertion in cycle/0003); unconditional repositioning on every access has not been evaluated.
