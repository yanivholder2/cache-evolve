# H03

Normalising the frequency counter to 1 when an item is promoted from the small queue into main (instead of carrying over its accumulated count) will improve hit rate by preventing small-queue residents from monopolising main-queue eviction reprieves through inflated pre-earned credits.

## Parent

cycle/0004/v001

## Changes

In `src/s3_fifo/mod.rs`, modify the promotion branch inside `evict_small()`. Currently the tail Entry — which may carry a freq as high as MAX_FREQ (4) accumulated during small-queue residency — is pushed directly into main, giving it up to 4 eviction-pass reprieves immediately. Change the branch to normalise freq to 1 before insertion:

Find this block in `evict_small()`:

```rust
if tail.freq > 1 {
    if self.main.len() >= self.main_size {
        self.evict_main();
    }
    self.main.push_front(tail);
```

Add a single line to cap the carried-over frequency:

```rust
if tail.freq > 1 {
    if self.main.len() >= self.main_size {
        self.evict_main();
    }
    tail.freq = 1;
    self.main.push_front(tail);
```

No other changes. Ghost re-admission continues to use `Entry::new(key, value)` (freq = 0). `MAX_FREQ = 4`, `small_size = capacity / 10`, `ghost_size = main_size / 2`, and promotion threshold `freq > 1` are all inherited unchanged from cycle/0004/v001.

## Rationale

Items promoted from small enter main at the head position regardless of their accumulated freq; the carried-over count can reach 4, giving them the same protection as the most-accessed main residents. This may displace genuinely hot main incumbents that earned their position through main-queue accesses. Setting the initial main freq to 1 lets promoted items prove their main-queue worth from a level footing — one guaranteed reprieve — while still distinguishing them from ghost-re-admitted items (freq = 0). If the workload's hot set is stable, this change should have minimal impact; if small-queue residents frequently over-count due to scan patterns, it should improve eviction quality.
