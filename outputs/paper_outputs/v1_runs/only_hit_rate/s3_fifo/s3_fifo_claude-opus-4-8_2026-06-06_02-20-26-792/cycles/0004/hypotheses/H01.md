# H01

Decoupling the ghost window from main capacity and enlarging it (without any re-admission gate) raises hit-rate by capturing longer-gap reuse that the current main-sized ghost forgets too soon.

## Parent

cycle/0003/v001

## Changes

This isolates the one lever the cross-cycle insights flag as untried-on-its-own:
ghost *sizing* with the validated direct-to-main re-admission path left fully
intact. The prior ghost-depth probe (cycle/0002 and cycle/0003 v002) is
confounded — it bundled deeper ghost with a freshness/recency gate AND a
different partition ratio, and the gate is the known regressor. Here we change
ghost depth alone, on the winning ~4/96 (`capacity / 24`) parent.

Concretely, in `S3Fifo`:

- Add a `ghost_size: usize` field to the struct (mirroring the existing
  `small_size` / `main_size` fields).
- In `try_new()`, after computing `main_size`, set
  `ghost_size = main_size.saturating_mul(2).max(1)` and allocate the ghost
  `VecDeque::with_capacity(ghost_size)`. Keep `small_size = (capacity / 24).max(1).min(capacity - 1)` exactly as in the parent.
- In `evict_small()`, replace the ghost-trim bound `self.ghost.len() >= self.main_size`
  with `self.ghost.len() >= self.ghost_size`.

Do NOT add any freshness, recency, or routing gate: every ghost hit must still
go straight to `main` via the existing `in_ghost` branch in `put()` (push_front
into main after an `evict_main()` if full). The only behavioural change is that
the ghost queue now remembers ~2× as many recently-evicted keys before
discarding the oldest. Preserve the capacity-bound, value-fidelity, and
no-phantom invariants (ghost holds keys only, never counts as resident).

## Rationale (optional)

The partition ratio is converged; the open question is whether a deeper memory
of evicted keys surfaces more confirmed-reuse re-admissions. Testing depth
without the contaminating gate cleanly answers whether ghost sizing is a live
lever or, like the gate, inert/harmful.
