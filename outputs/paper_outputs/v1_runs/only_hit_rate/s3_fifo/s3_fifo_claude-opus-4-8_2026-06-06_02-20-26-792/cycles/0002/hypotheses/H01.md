# H01

Pushing the small/main split further past 10/90 toward roughly 6/94 raises hit-rate by handing the admission queue's freed slots to the main resident queue.

## Parent

cycle/0001/v002

## Changes

In `try_new`, change the `small_size` computation for the `capacity > 1`
branch from `(capacity / 10).max(1).min(capacity - 1)` to
`(capacity / 16).max(1).min(capacity - 1)`. This shrinks the admission
queue to ~6% of capacity and enlarges `main_size = capacity - small_size`
correspondingly. Leave the `capacity == 1` special case (`small_size = 1`)
untouched, and keep every other field initialization, the ghost sizing
(`with_capacity(main_size)`), and all promotion/eviction logic exactly as
in v002. This is a pure partition-ratio sweep one step past v002's winning
10/90 point to probe whether the optimum is sharper than ~10/90 before the
shrinking filter starts leaking one-hit-wonders.

## Rationale (optional)

v002 won by moving 25/75 → 10/90 but the gain was modest, and the cycle
insight explicitly asks how far the ratio can be pushed before the
admission filter starts leaking. This isolates that single knob.
