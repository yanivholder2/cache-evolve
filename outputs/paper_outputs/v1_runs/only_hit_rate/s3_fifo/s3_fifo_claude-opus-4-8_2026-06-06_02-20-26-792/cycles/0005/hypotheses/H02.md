# H02

Select the main-queue eviction victim as the lowest-frequency entry within a bounded tail window, sharpening which cold resident the scan reaches and raising hit-rate.

## Parent

cycle/0004/v003

## Changes

Replace the strict tail second-chance rotation in `evict_main()` with a
recency-aware tail-window victim selection. Define a small window depth
`W = (main.len() / 16).max(1)` measured from the tail (the least-recently
used end, since v003's `get()` keeps hot keys at the front). Among the last
`W` entries (the `W` oldest residents), pick the victim as the entry with
the **lowest `freq`**, breaking ties toward the entry nearest the tail
(oldest). Remove exactly that entry. For every other entry inspected in the
window that had `freq > 0`, decrement its `freq` by 1 in place (preserve the
second-chance aging) but leave its position unchanged.

This differs from H01: rather than evicting the first `freq == 0` from the
tail, it actively chooses the coldest among the oldest few, so a `freq == 0`
key buried just inside the window is preferred over a `freq == 1` key exactly
at the tail.

Preserve invariants: exactly one removal per call, capacity never exceeded,
and the saturating-`freq` semantics retained. When `main.len() <= 1`, fall
back to `pop_back()`.

## Rationale (optional)

The open question from cycle 0004 names "recency-aware tail selection"
explicitly. This sharpens which resident the eviction scan reaches — the
class of change the cross-cycle narrative says pays — without re-admitting
or warm-starting weak-signal keys.
