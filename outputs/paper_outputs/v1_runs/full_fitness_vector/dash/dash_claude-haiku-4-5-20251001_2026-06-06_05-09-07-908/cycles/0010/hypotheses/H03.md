# H03

Implement frequency-aware demotion cascade gating where demoted items only receive the "one-more-chance" to re-land in an intermediate tier if their frequency counter exceeds a threshold, else bypass to stash directly, thereby reducing cascading evictions and improving latency on baseline geometry.

## Parent

baseline

## Changes

Modify the demotion logic in `src/dash/segments/dash_segment.rs`, specifically in the `demote_from_normal_bucket` function. Add a frequency-aware gate before attempting demotion to the target tier: if an item being demoted from probing has `lfu_counter < 2`, skip the "one-more-chance" logic and place it directly into stash, bypassing target. If `lfu_counter >= 2`, follow the current demotion cascade (attempt target first, then stash if needed).

Additionally, modify `src/dash/segments/mod.rs` to ensure the SegmentCore initializes with a frequency-aware eviction policy (change to `FrequencyAwareLRU` in the DashSettings) so that `lfu_counter` is reliably maintained across get operations on all items, not just in the promotion-path items.

The change gates the "second chance" demotion based on observed frequency: items that have proven hot (recent access) retain the safety net; items that are cold get evicted more aggressively, reducing stash occupancy and lowering the probability of cascading evictions when the probing tier is under pressure. This introduces a new optimization axis—demotion selectivity—orthogonal to both promotion threshold tuning (which gates *entry* to probing) and geometry allocation (which sizes the tiers).

## Rationale

Cycles 0001–0009 have extensively optimized promotion gating (what enters probing) and geometry allocation (tier sizes). The cycle insights explicitly identify unexplored axes: "tier-crossing heuristics, promotion cascading policies." This hypothesis targets cascading demotion policy directly. The current "one-more-chance" logic unconditionally grants a retry in target for any item evicted from probing, incurring cost when that item lands in target, also evicts (cascade), and then finally reaches stash. By gating the second chance on frequency—allowing only truly-hot items to retry—this hypothesis reduces cascade depth without sacrificing hot-item retention. The baseline geometry provides a stable comparison point without confounding geometry changes. If successful, the approach demonstrates a new independent axis; if unsuccessful, it confirms that the current unconditional cascade is already near-optimal for this workload.
