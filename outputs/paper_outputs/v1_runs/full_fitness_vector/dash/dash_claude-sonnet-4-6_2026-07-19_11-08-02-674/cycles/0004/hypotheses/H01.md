# H01

Raising the vacancy-gate frequency threshold from ≥ 2 to ≥ 3 in `promotion_get` will improve hit rate by promoting only items with stronger reuse evidence while preserving the cascade-free guarantee that v003's vacancy check already provides.

## Parent

cycle/0003/v003

## Changes

In `src/dash/segments/dash_segment.rs`, inside `promotion_get`, locate the non-hottest target branch (the `else` arm where `is_hottest` is `false`). The current condition for the vacancy-gated frequency promotion is:

```rust
if counter >= 2 && probing_has_space {
```

Change it to:

```rust
if counter >= 3 && probing_has_space {
```

That is the only logic change. The `probing_has_space` vacancy guard remains in place exactly as in v003, preserving the structural guarantee that gate-fires never trigger cascade evictions. The `lfu_counter` increment immediately before (`core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter += 1`) is unchanged.

Update the module-level doc comment and `promotion_get`'s inline comment to reflect the new threshold value (replace "2" with "3" wherever the threshold is described). Update the `vacancy_gated_frequency_promote_fires_when_probing_has_space` test to pre-set `lfu_counter = 2` (so the next hit reaches 3) and adjust the `vacancy_gated_promote_does_not_fire_when_probing_full` test's pre-set to `lfu_counter = 2` as well. Add a new test `vacancy_gated_frequency_promote_requires_three_hits` that verifies a non-hottest item with `lfu_counter = 2` is NOT yet promoted (gate stays silent at threshold 2) but IS promoted after one more hit brings the counter to 3.

No changes to `src/shared/item.rs`, `src/shared/eviction_policy.rs`, or any other file.

## Rationale

cycle/0003/v002 demonstrated that threshold ≥ 3 (without the vacancy guard) produces the highest raw hit-rate (0.6796) seen across all cycles, but at the cost of a p99 latency regression. cycle/0003/v003 showed that the vacancy guard is sufficient to eliminate cascade latency entirely, even at the lower threshold of ≥ 2. Combining the guard from v003 with the higher threshold from v002 should preserve the zero-cascade cost while matching or exceeding v002's hit-rate selectivity, since the gate now fires on a stricter subset of items with genuinely repeated reuse.
