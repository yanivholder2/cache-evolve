# H01

Restricting CLOCK_BIT in `promotion_get` to fire only when the non-hottest item's raw frequency reaches 3 (rather than on every hit) will give the two-chance clock genuine discriminating power over the LFU-minimum scan and improve hit rate on the cycle/0008/v001 base.

## Parent

cycle/0008/v001

## Changes

In `src/dash/segments/dash_segment.rs`, modify the non-hottest target branch inside `promotion_get`. The current code unconditionally ORs CLOCK_BIT on every non-hottest hit:

```rust
let items_mut = core.buckets[target_idx].get_items_mut();
items_mut[item_idx].lfu_counter = (items_mut[item_idx].lfu_counter + 1) | CLOCK_BIT;
let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
let freq = counter & !CLOCK_BIT;
```

Replace with logic that sets CLOCK_BIT only when the new raw frequency first crosses 3:

```rust
let items_mut = core.buckets[target_idx].get_items_mut();
let old_freq = items_mut[item_idx].lfu_counter & !CLOCK_BIT;
let new_freq = old_freq + 1;
items_mut[item_idx].lfu_counter = if new_freq >= 3 {
    new_freq | CLOCK_BIT
} else {
    new_freq
};
let freq = new_freq;
```

The frequency gate (`if freq >= 2 && probing_has_space`) is unchanged — items still promote early to probing at freq 2. CLOCK_BIT is now set only when an item accumulates its third access, giving it clock-protection precisely when it has proven high reuse likelihood.

Also adjust the arriving-item pre-marking in `promote_to_target`. Change the guard from `if item.lfu_counter & !CLOCK_BIT > 0` to `if item.lfu_counter & !CLOCK_BIT >= 3` so that only items carrying freq≥3 are marked warm on arrival into a target bucket.

Keep `clock_evict_prepare`, all other promotion paths, and `ClassicLRU::eviction_candidate_index` (LFU-minimum scan) exactly as in the parent.

This overlay must include all three files from cycle/0008/v001's overlay — `src/shared/item.rs`, `src/shared/eviction_policy.rs`, and `src/dash/segments/dash_segment.rs` — carried forward unchanged except for the two modifications described above, to avoid the struct-footprint regression that has occurred when overlay files were omitted.

## Rationale

In cycle/0008/v001, CLOCK_BIT inflates `lfu_counter` to ~2^63, making any marked item immune to LFU-minimum eviction. With CLOCK_BIT set on every hit, nearly all bucket items become immune simultaneously; `clock_evict_prepare` then cycles through the whole bucket to find a cold victim, and after clearing one CLOCK_BIT the LFU-min has only that one newly-unprotected item to pick (since everything else is still warm). The clock's effect degenerates to round-robin eviction with no frequency awareness. By raising the CLOCK_BIT threshold to freq≥3, items with freq 0–2 remain unprotected and compete directly by raw frequency under LFU-min, while items with freq≥3 receive one protected round per eviction event. This restores the two-tier discrimination the clock was designed to provide.
