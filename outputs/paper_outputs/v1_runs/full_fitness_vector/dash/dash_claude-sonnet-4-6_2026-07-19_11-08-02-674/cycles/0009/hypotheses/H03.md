# H03

Replacing the O(n) LFU-minimum scan in `ClassicLRU::eviction_candidate_index` with O(1) position-0 eviction — combined with CLOCK_BIT set only at freq≥3 — will reduce per-op latency while preserving frequency-aware eviction through the two-chance clock on the cycle/0008/v001 base.

## Parent

cycle/0008/v001

## Changes

Two coordinated changes are required:

**1. `src/shared/eviction_policy.rs` — switch `ClassicLRU::eviction_candidate_index` to position 0.**

Replace the current LFU-minimum scan:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    let mut min_counter = items[0].lfu_counter;
    let mut min_idx = 0usize;
    for (idx, item) in items.iter().enumerate().skip(1) {
        if item.lfu_counter < min_counter {
            min_counter = item.lfu_counter;
            min_idx = idx;
        }
    }
    min_idx
}
```

with:

```rust
fn eviction_candidate_index(&self, _items: &[Item<K, V>]) -> usize {
    0
}
```

Position 0 is the victim selected by the clock: after `clock_evict_prepare` rotates all warm items (CLOCK_BIT set) to the back, the first cold item (CLOCK_BIT clear) sits at position 0 and is evicted. `promotion_candidate_index` stays `items.len() - 1` (unchanged).

**2. `src/dash/segments/dash_segment.rs` — apply CLOCK_BIT sparsification (same as H01).**

In `promotion_get`'s non-hottest target branch, change the CLOCK_BIT setting so it fires only when the new raw frequency crosses 3. Replace:

```rust
let items_mut = core.buckets[target_idx].get_items_mut();
items_mut[item_idx].lfu_counter = (items_mut[item_idx].lfu_counter + 1) | CLOCK_BIT;
let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
let freq = counter & !CLOCK_BIT;
```

with:

```rust
let items_mut = core.buckets[target_idx].get_items_mut();
let old_freq = items_mut[item_idx].lfu_counter & !CLOCK_BIT;
let new_freq = old_freq + 1;
items_mut[item_idx].lfu_counter = if new_freq >= 3 {
    new_freq | CLOCK_BIT
} else {
    new_freq
};
let freq = new_freq;
```

Also change the arriving-item pre-marking guard in `promote_to_target` from `> 0` to `>= 3`:

```rust
if item.lfu_counter & !CLOCK_BIT >= 3 {
    item.lfu_counter |= CLOCK_BIT;
}
```

Keep `clock_evict_prepare`, the frequency promotion gate (`freq >= 2`), all demotion paths, and `ClassicLRU::promotion_candidate_index` exactly as in the parent.

This overlay must include all three parent overlay files: `src/shared/item.rs` (unchanged), `src/shared/eviction_policy.rs` (modified as in change 1), and `src/dash/segments/dash_segment.rs` (modified as in change 2). Carry all of cycle/0008/v001's accumulated changes forward to prevent struct-footprint regression.

## Rationale

In the parent (cycle/0008/v001), `clock_evict_prepare` reorganises bucket positions but the LFU-minimum scan ignores positions, making the clock rotation irrelevant to which item is evicted. By switching to position-0 eviction, the clock rotation becomes the sole eviction decision mechanism: warm items (CLOCK_BIT set, freq≥3) get rotated to the back and spared; the cold item that settles at position 0 is evicted. With sparse CLOCK_BIT (freq≥3 threshold), items with freq 0–2 are cold immediately — the clock does not protect them — while items with freq≥3 receive one round of protection before becoming eviction candidates. This restores the true two-chance clock semantics lost in cycle/0008/v001 and eliminates the O(n) min-scan that has inflated put p99 in multiple prior cycles.
