# H02

Extending the two-chance clock eviction pre-pass to the probing tier will protect warm probing residents from premature demotion and improve hit rate.

## Parent

cycle/0009/v001

## Changes

In `src/dash/segments/dash_segment.rs`, make two coordinated changes so probing items participate in the clock scheme symmetrically with target items:

**1. Add `clock_evict_prepare` to `promote_to_probing`** — mirror the guard already present in `promote_to_target`:

```rust
fn promote_to_probing<K, V>(core: &mut SegmentCore<K, V>, item: Item<K, V>, insert_pos: InsertPosition)
where ...
{
    let target_idx = get_index(&item.key, core.segment_size);
    let probing_idx = (target_idx + 1) % core.segment_size;
    if core.buckets[probing_idx].is_full() {
        clock_evict_prepare(core.buckets[probing_idx].get_items_mut());
    }
    let Some(evicted) = core.put_at(Slot::Probing, insert_pos, item) else {
        return;
    };
    demote_from_normal_bucket(core, evicted, probing_idx, insert_pos);
}
```

**2. Track CLOCK_BIT for probing items in `promotion_get`'s probing hit path** — replace the raw `+= 1` increment with the same frequency-masking pattern used in the target path, using the same freq≥3 threshold:

```rust
if let Some(item_idx) = core.buckets[probing_idx].get_position(key) {
    let items_mut = core.buckets[probing_idx].get_items_mut();
    let old_freq = items_mut[item_idx].lfu_counter & !CLOCK_BIT;
    let new_freq = old_freq + 1;
    items_mut[item_idx].lfu_counter = if new_freq >= 3 {
        new_freq | CLOCK_BIT
    } else {
        new_freq
    };
    let counter = new_freq;
    let target_has_space = !core.buckets[target_idx].is_full();
    if counter >= 2 && target_has_space {
        // ... existing re-entry path unchanged
    }
    // ...
}
```

Do NOT change the CLOCK_BIT threshold for target items (keep freq≥3 throughout, matching v001). Do NOT change `promote_to_target`, `demote_from_normal_bucket`, the vacancy-gated frequency promotion gate, or the probing re-entry threshold. No changes to `eviction_policy.rs` or `item.rs`.

Add tests for the probing clock: `probing_clock_bit_set_at_freq3`, verifying that a probing item's CLOCK_BIT is set when its raw freq reaches 3; and `clock_evict_prepare_fires_on_probing_eviction`, verifying that a warm probing item (CLOCK_BIT set) survives one eviction event and is rotated to the back.

## Rationale

In cycle/0009/v001 the two-chance clock is applied only in `promote_to_target` and the `demote_from_normal_bucket` target-retry path; `promote_to_probing` has no clock pre-pass. Items frequently accessed in probing (raw freq≥3) are now cold from the probing clock's perspective even though they are genuinely hot. Extending the clock to probing gives those items a protected round before demotion, independent of the threshold-tuning explored in H01.
