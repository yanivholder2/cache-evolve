# H03

Adding cold-preferring stash eviction — scanning the stash bucket for lfu_counter == 0 items and swapping one to the eviction position before each full-stash insert — will improve hit-rate on cycle/0005/v001 by retaining warm stash items that are likely to be re-accessed.

## Parent

cycle/0005/v001

## Changes

In `src/dash/segments/dash_segment.rs`, starting from cycle/0005/v001's code (MRU-end insertion, timestamp-free item struct, vacancy-gated frequency promotion ≥ 2, LFU-minimum eviction scan for target buckets, no probing re-entry):

1. **Add `stash_cold_evict_prepare`** function that repositions a cold item (lfu_counter == 0) to the eviction slot (position 0) before a stash insert displaces the existing LRU victim:
   ```rust
   fn stash_cold_evict_prepare<K, V>(stash_bucket: &mut impl BucketOps<K, V>)
   where K: Hash + Eq + Clone, V: Eq + Clone,
   {
       // Find the first cold item (lfu_counter == 0) and swap it to position 0
       // so ClassicLRU's constant-0 eviction discards it instead of a warm item.
       // If all items are warm, fall through to normal LRU eviction — no change.
       if let Some(cold_pos) = stash_bucket
           .get_items()
           .iter()
           .position(|it| it.lfu_counter == 0)
       {
           if cold_pos != 0 {
               stash_bucket.get_items_mut().swap(0, cold_pos);
           }
       }
   }
   ```
   Use whatever trait bound or concrete type `stash_buckets[i]` exposes that provides `get_items()` / `get_items_mut()` — the same API used by `clock_evict_prepare` and the LFU-min scan in other overlays.

2. **Modify `demote_from_normal_bucket`** to call `stash_cold_evict_prepare` before every stash insert when the target stash bucket is full. There are two stash insert sites in this function:

   **Site A** — item goes directly to stash (true_target == source_idx):
   ```rust
   // Before:
   core.put_at(Slot::Stash, insert_pos, item);

   // After:
   let stash_idx_for_item = get_index(&item.key, core.stash_size);
   if core.stash_buckets[stash_idx_for_item].is_full() {
       stash_cold_evict_prepare(&mut core.stash_buckets[stash_idx_for_item]);
   }
   core.put_at(Slot::Stash, insert_pos, item);
   ```

   **Site B** — cascade eviction from the target-retry also lands in stash:
   ```rust
   // Before:
   core.put_at(Slot::Stash, insert_pos, cascade);

   // After:
   let stash_idx_for_cascade = get_index(&cascade.key, core.stash_size);
   if core.stash_buckets[stash_idx_for_cascade].is_full() {
       stash_cold_evict_prepare(&mut core.stash_buckets[stash_idx_for_cascade]);
   }
   core.put_at(Slot::Stash, insert_pos, cascade);
   ```

3. **Keep `item.rs` unchanged** from cycle/0005/v001 (key + value + lfu_counter, no timestamp; metadata-size stays at 24).

4. **Keep all other code from cycle/0005/v001 unchanged**: MRU-end insertion (`InsertPosition::Back`), LFU-minimum eviction scan in `promote_to_target`, vacancy-gated frequency promotion (≥ 2) in `promotion_get`. Do NOT add probing re-entry (this variant isolates the stash-eviction change).

**Overhead**: `stash_cold_evict_prepare` runs only when a stash bucket is full, which is rarer than target evictions. The scan cost is O(stash_bucket_size), which is bounded and small. On most accesses (stash hit, target hit, probing hit) no scan occurs at all.

**Invariant preserved**: ClassicLRU's eviction policy selects position 0 as the victim. The pre-scan moves a cold item to position 0 before `put_at` is called, so the overall eviction still goes through the configured policy — no policy-layer changes are needed.

## Rationale

All frequency-aware eviction work to date (LFU-minimum scan in cycle 5, two-chance clock in cycle 6) has focused on the *target* tier. The *stash* tier has always used ClassicLRU, which evicts the positional LRU item regardless of whether it is warm (lfu_counter > 0, likely to be re-accessed) or cold (lfu_counter == 0, likely dead). On a Zipfian workload, warm items cycle through stash during periods of contention; cold-preferring stash eviction ensures those warm items survive longer while genuinely cold items are discarded first. The scan fires only at stash eviction time, which is much less frequent than target evictions, so the latency impact is small and amortized. This axis is orthogonal to H01 (clock on target) and H02 (stash bypass to probing) and has not been explored in any prior cycle.
