# H02

Adding a vacancy-gated frequency promotion path in `DashSegment::get`'s probing-hit branch that moves items with `lfu_counter >= 2` back into the target tier when target has space will improve hit-rate by recognizing demoted items that continue to demonstrate reuse as candidates for re-entry into the hot tier.

## Parent

cycle/0003/v003

## Changes

This variant inherits all three overlay files from cycle/0003/v003 and modifies only `dash_segment.rs`. All three files must be present in the overlay to avoid the coverage-gap regression seen in cycle/0004.

**`src/shared/item.rs`** — Carry forward unchanged from cycle/0003/v003.

**`src/shared/eviction_policy.rs`** — Carry forward unchanged from cycle/0003/v003.

**`src/dash/segments/dash_segment.rs`** — Carry forward the MRU-end insertion (`InsertPosition::Back`) and the vacancy-gated frequency promotion in the target-tier non-hottest branch exactly as in cycle/0003/v003. Make the following addition in the probing-hit branch of `get` (the branch that executes after the key is found in the probing bucket):

1. After the existing intra-probing MRU update (`get_from_position` on the probing bucket), increment the accessed item's `lfu_counter` by 1.
2. Immediately after the increment, evaluate the promotion condition: if `data.lfu_counter >= 2` AND `!core.buckets[target_idx].is_full()`, remove the item from its current probing slot (`remove_at(pos)` on the probing bucket) and insert it into the target bucket at `InsertPosition::Back` (MRU end). This mirrors the vacancy-gate pattern already used in the target non-hottest branch, applied symmetrically to items found in probing.
3. If the condition is not met (counter below threshold or target full), leave the item in probing with its position updated by step 1's `get_from_position` call and return normally.

Add two unit tests: `probing_item_with_counter_ge2_promotes_to_target_when_target_has_space` (verifies the promotion fires and the item is in target afterward) and `probing_item_stays_in_probing_when_target_is_full` (verifies the vacancy gate blocks promotion). All existing tests from the parent must continue to pass.

## Rationale

Items reach probing primarily by being evicted from a full target tier during insertion pressure. An item that was evicted from target but continues to receive cache hits in probing is demonstrating persistent reuse — exactly the evidence the frequency gate was designed to capture. Currently these items remain in probing indefinitely, missing the opportunity to reclaim a target slot when one opens up. The proposed path is cascade-free by construction (the vacancy gate ensures target has room before the move) and reuses the same threshold already validated in the target promotion path, so it introduces no new parameters.
