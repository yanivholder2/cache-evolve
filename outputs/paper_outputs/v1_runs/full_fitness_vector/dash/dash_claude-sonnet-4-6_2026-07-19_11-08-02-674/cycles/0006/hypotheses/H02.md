# H02

Halving each surviving item's `lfu_counter` after every target-bucket eviction event introduces temporal decay that prevents stale high-frequency items from permanently dominating the LFU ordering, improving hit rate on the Zipfian workload.

## Parent

cycle/0005/v001

## Changes

Start from the full cycle/0005/v001 three-file overlay. Carry `src/shared/item.rs` and `src/shared/eviction_policy.rs` forward unchanged. Modify only `src/dash/segments/dash_segment.rs`.

In `promote_to_target`, add a decay pass immediately after `core.put_at(Slot::Target, ...)` returns `Some(evicted)` — that is, immediately after an eviction has occurred and before `demote_from_normal_bucket` is called:

```rust
fn promote_to_target<K, V>(core: &mut SegmentCore<K, V>, item: Item<K, V>, insert_pos: InsertPosition) {
    let target_idx = get_index(&item.key, core.segment_size);
    let Some(evicted) = core.put_at(Slot::Target, insert_pos, item) else {
        return;
    };
    // Decay: halve lfu_counter for every item remaining in the target bucket
    // so that stale frequency counts age out after each eviction cycle.
    for remaining in core.buckets[target_idx].get_items_mut().iter_mut() {
        remaining.lfu_counter >>= 1;
    }
    demote_from_normal_bucket(core, evicted, target_idx, insert_pos);
}
```

Apply the same decay pattern in `demote_from_normal_bucket` at the point where the cascade calls `core.put_at(Slot::Target, insert_pos, item)` and it returns `Some(cascade)`:

```rust
// inside demote_from_normal_bucket, in the else-branch:
if let Some(cascade) = core.put_at(Slot::Target, insert_pos, item) {
    // decay the target bucket that just evicted
    let cascade_target_idx = true_target; // already in scope
    for remaining in core.buckets[cascade_target_idx].get_items_mut().iter_mut() {
        remaining.lfu_counter >>= 1;
    }
    core.put_at(Slot::Stash, insert_pos, cascade);
}
```

The right-shift (`>>= 1`) is an integer halving with floor at 0; for `usize` this is safe and requires no additional imports. No changes to the LFU-minimum scan in `ClassicLRU::eviction_candidate_index`, no changes to the vacancy-gated promotion logic, and no changes to insertion position — all v001 mechanisms remain intact. Only the post-eviction decay lines are new.

## Rationale

The LFU-minimum scan in v001 evicts whichever item has accumulated the lowest hit count across the bucket's entire history. On a stationary Zipfian workload this works well, but any item that was transiently popular early in the trace retains a high counter forever and becomes effectively immune to eviction even after it cools. Halving all surviving counters after each eviction is an O(slots) operation (≤16 items) that fires only at eviction time — far less frequently than gets — so it should not materially affect p50 latency. The decay makes the LFU ordering reflect recent frequency rather than lifetime frequency, giving newly-hot items a chance to displace those whose popularity has faded.
