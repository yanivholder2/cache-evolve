# H03

Shrinking `Item` by dropping the 16-byte `Instant` timestamp and narrowing the LFU counter cuts per-item metadata from 40 to 24 bytes.

## Parent

baseline

## Changes

Target the metadata-size dimension (baseline `Item<u64,u64>` = 40 bytes:
key 8 + value 8 + `lfu_counter: usize` 8 + `timestamp: Instant` 16). Two
coordinated edits to overlayable files:

1. `src/shared/item.rs`: remove the `timestamp: Instant` field and change
   `lfu_counter` from `usize` to `u8`. Keep `key` and `value` as the first two
   fields and keep `Item::new(key, value)` constructible (initialise
   `lfu_counter: 0`). Drop the `use std::time::Instant` import and remove the
   `timestamp` reference from the `Display` impl so it still compiles. New
   layout for `<u64,u64>`: 8 + 8 + 1 = 17 bytes, aligned to 24.

2. `src/shared/eviction_policy.rs`: the `TimestampLRU` and `Lfu` impls read the
   removed/narrowed fields, so adjust them. Reimplement `TimestampLRU` to use
   positional recency identical to `ClassicLRU` (`get_from_position` moves the
   item to the back; `eviction_candidate_index` = 0; `promotion_candidate_index`
   = `len()-1`), removing all `item.timestamp` access. In `Lfu`, make the
   counter increment saturating on `u8` (`lfu_counter = lfu_counter.saturating_add(1)`)
   so it cannot overflow-panic; `min_by_key`/`max_by_key` over `u8` are
   unchanged.

Do **not** change `DashSegment` movement logic — the configured eval policy is
`ClassicLRU`, which never reads `timestamp` or `lfu_counter`, so hit-rate on the
eval trace should be unchanged while metadata-size drops. Keep
`EvictionPolicyKind` and all six variants present so the JNI ordinal/name
contract and the policy round-trip tests still hold.

The hypothesis is confirmed if the metadata binary reports
`sizeof(Item<u64,u64>) == 24` (down from 40) with hit-rate unchanged at 0.6634
and all P1–P6 invariants passing. Removing `Instant::now()` calls from the get
path may also nudge per-op-time down.

## Rationale (optional)

The baseline carries a 16-byte `Instant` and an 8-byte `usize` counter on every
item even though the active policy (`ClassicLRU`) uses neither — pure overhead
on the metadata-size axis. Collapsing these to a single byte is a low-risk,
directly-measurable win that leaves the eviction behaviour the baseline actually
exercises untouched.
