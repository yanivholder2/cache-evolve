# H02

Storing buckets as a concrete `Vec<DashBucket>` instead of `Vec<Box<dyn Bucket>>` removes the outer Bucket-trait vtable indirection and per-access heap deref on every get/put, lowering per-op-time below v002's 78ns.

## Parent

cycle/0004/v002

## Changes

v002 devirtualized the *inner* `EvictionPolicy` trait object but every bucket is
still reached through a `Box<dyn Bucket<K, V>>` in `SegmentCore`, so each
`get_position`, `get_items`, `put_at`, and `get_from_position` call pays a Bucket
vtable dispatch plus a pointer chase into a separately-heap-allocated bucket.
Monomorphize that outer layer:

- In `src/dash/segments/mod.rs`: change `SegmentCore::buckets` and
  `stash_buckets` from `Vec<Box<dyn Bucket<K, V>>>` to `Vec<DashBucket<K, V>>`.
  In `try_new`, construct `DashBucket::new(settings.bucket_size,
  settings.eviction_policy.build())` directly instead of calling `new_bucket`
  (drop the boxing). Update the manual `Debug` impl and the `put_at` slot match
  (the `&mut self.buckets[idx]` borrows now yield `&mut DashBucket`, whose
  `Bucket` methods resolve via static dispatch).
- Keep the `Bucket` trait and `DashBucket`'s `impl Bucket` exactly as-is so all
  method bodies and the v002 `is_classic_lru` inner devirtualization are reused
  unchanged — only the storage type and dispatch change.
- Leave `new_bucket` in `src/dash/dash_bucket.rs` in place if other callers need
  it; just stop using it inside `SegmentCore`.

Preserve all behaviour: hit-rate, metadata-size, and slot/cascade logic must be
bit-for-bit identical; only get/put latency should move. This is the same class
of structural, harness-resolvable win as v002's policy devirtualization, applied
one layer out, and targets both p50 and p99 by removing a heap indirection per
bucket touch.

## Rationale (optional)

The cycle-0004 insight asks for "further structural latency wins of v002's
magnitude (allocation strategy, bucket layout)". Collapsing the Bucket trait
object is exactly such a structural change and is independent of the policy-level
devirtualization already banked.
