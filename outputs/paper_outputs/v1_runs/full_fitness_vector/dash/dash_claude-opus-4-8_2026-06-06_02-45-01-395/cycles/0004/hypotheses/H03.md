# H03

Widen the probing neighborhood from one bucket to two so a key can reside in `target`, `target+1`, or `target+2`, raising set-associativity to cut conflict-eviction misses and lift hit-rate.

## Parent

cycle/0003/v002

## Changes

Every prior hit-rate attempt tuned the *promotion gate* or *MRU
placement* — and the cross-cycle insights conclude those two are
saturated substitutes. This hypothesis attacks a different miss class
entirely: **conflict misses**. Today a key maps to exactly one target
bucket `h` with a single probing bucket `h+1`; once both fill, warm keys
that collide on `h` evict each other regardless of recency. Increasing
the neighborhood from 2 to 3 buckets raises effective associativity, so
colliding warm keys coexist instead of thrashing — a structural lever
MRU placement cannot touch.

Concretely, in `src/dash/segments/dash_segment.rs`:

1. Introduce `probing2_idx = (target_idx + 2) % core.segment_size`
   alongside the existing `target_idx` and `probing_idx = (target_idx +
   1) % core.segment_size` in `promotion_get`.

2. Extend `promotion_get`'s lookup chain to also check
   `core.buckets[probing2_idx]` after `probing_idx`, returning an
   in-place hit there (same as the current probing-bucket branch).

3. In `promote_to_probing`, when the primary probing bucket
   (`probing_idx`) is full, prefer placing the promoted item into
   `probing2_idx` if it has room before triggering the demotion cascade;
   only cascade when both probing buckets are full.

4. Update `demote_from_normal_bucket`'s one-more-chance logic so an item
   evicted from any of the three neighborhood buckets is recognized
   against its `true_target = get_index(key, segment_size)`: if the
   source was a foreign probing slot (`probing_idx` or `probing2_idx`),
   retry into the true target before stash; if it was the true target,
   go to stash — preserving today's cascade shape, just over a 3-wide
   window.

Preserve invariants: the ADR-0004 uniqueness guarantee (a key resident
in at most one of the three buckets) must hold — before inserting into
any neighborhood bucket, ensure the key is not already resident in
another. Keep `InsertPosition::Back` placement, the `PROMOTE_AT`
frequency gate, and the wraparound modulo math intact. Expect a
hit-rate gain on conflict-heavy regions of the trace; watch per-op-time,
since each get now scans up to one additional bucket.

## Rationale (optional)

cycle/0003/v002 is the best-so-far hit-rate (0.6794) but reached it
purely through placement/gate tuning, which the narrative declares
exhausted. Associativity is an untried, structurally distinct axis: if
conflict misses are a real component of the remaining miss mass, this is
the only lever left that could move hit-rate above the noise floor; if
not, it cleanly falsifies the "conflict misses remain" hypothesis.
