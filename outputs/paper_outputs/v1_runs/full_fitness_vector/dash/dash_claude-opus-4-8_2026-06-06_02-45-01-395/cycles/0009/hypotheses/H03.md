# H03

Extend the one-more-chance rescue to the cascade victim — giving a foreign-resident target overflow its own retry instead of dropping it straight to stash — to push hit-rate above the standing 0.6794 cap.

## Parent

cycle/0007/v001

## Changes

Modify `demote_from_normal_bucket` in `src/dash/segments/dash_segment.rs`. In the
parent's `true_target != source_idx` branch, when the retry insert into the true
target overflows, the cascade victim is sent unconditionally to the stash:

```
if let Some(cascade) = core.put_at(Slot::Target, insert_pos, item) {
    core.put_at(Slot::Stash, insert_pos, cascade);
}
```

Replace that terminal stash insert with one additional rescue level: if the
cascade victim is itself a *foreign* resident in this target (i.e.
`get_index(&cascade.key, core.segment_size) != true_target`), retry it once into
*its own* true target via `core.put_at(Slot::Target, insert_pos, cascade)`, and
only if **that** retry overflows, send the resulting victim to the stash. If the
cascade victim's own true target equals `true_target` (it is home), keep the
existing direct-to-stash behaviour. Bound the rescue to this single extra level —
do not loop — so the worst case is three normal-bucket inserts plus one stash
insert per demotion.

Preserve: `insert_pos` honored on every insert; every demotion path still
terminates in the stash; the `true_target == source_idx` branch is unchanged.

## Rationale (optional)

Cycle 0008/v003 proved the cascade is a genuine latency-vs-hit-rate trade
(collapsing it cost 0.0008 hit-rate), cracking the "hit-rate fully capped"
framing. This pushes the trade the *opposite* direction: spend more put-side work
to rescue additional conflict victims and measure whether hit-rate can exceed
0.6794 at all. It directly tests the open question "how much hit-rate does the
cascade actually buy," with the expected cost surfacing as a wider put-p99.
