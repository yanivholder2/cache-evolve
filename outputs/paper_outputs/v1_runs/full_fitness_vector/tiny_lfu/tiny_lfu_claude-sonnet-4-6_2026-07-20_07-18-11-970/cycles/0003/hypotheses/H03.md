# H03

Selecting the eviction victim as the lower-frequency of the two least-recently-used entries will improve hit rate by avoiding incorrect evictions when a recently-loaded hot item temporarily occupies the LRU head.

## Parent

baseline

## Changes

In `TinyLfuCache::put()`, replace the single-victim selection:

```rust
let victim_idx = decode(self.head.expect("TinyLfuCache: full cache has no victim"));
```

with a best-of-2 candidate check one step deeper in the LRU list:

```rust
let head_idx = decode(self.head.expect("TinyLfuCache: full cache has no victim"));
let victim_idx = match self.nodes[head_idx].next {
    None => head_idx,
    Some(second_nz) => {
        let second_idx = decode(second_nz);
        let head_freq   = self.sketch.estimate(&self.nodes[head_idx].key);
        let second_freq = self.sketch.estimate(&self.nodes[second_idx].key);
        if second_freq < head_freq { second_idx } else { head_idx }
    }
};
```

Everything that follows uses `victim_idx` unchanged: the admission gate `if incoming_freq > victim_freq`, the `map.remove`, `unlink`, node-slot reuse, `push_back`, and `map.insert`. The `unlink()` method already handles arbitrary node positions, so evicting the second-oldest entry rather than the head is structurally correct.

Do not touch the `get()` path, the sketch, or the node layout. The `decode` helper from the baseline (`Option<usize>` in the baseline) is used directly — no new types needed.

## Rationale

The LRU head is the oldest entry by last-access time but not necessarily the lowest-frequency one. When a cold newcomer is admitted and immediately unlinked-and-pushed-back by `push_back`, it sits at the LRU tail. Meanwhile, the head may be a recently-cold item whose estimated frequency is still higher than the entry just behind it because of historical access bursts. Inspecting the two oldest entries and evicting the lower-frequency one adds one extra `sketch.estimate()` call per eviction event — a code path that fires only when the cache is full, not on every `get()` — and targets a class of admission error that pure LRU ordering cannot avoid. This axis (eviction candidate selection) is entirely unexplored in prior cycles, which focused exclusively on sketch geometry and node encoding.
