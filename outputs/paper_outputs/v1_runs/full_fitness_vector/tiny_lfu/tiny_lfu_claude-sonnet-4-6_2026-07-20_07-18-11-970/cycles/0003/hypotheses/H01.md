# H01

Adding periodic sketch half-decay every `capacity × 10` operations will improve hit rate by aging stale frequency accumulations so recent access patterns dominate admission decisions on the LIRS trace.

## Parent

baseline

## Changes

Add a field `ops_since_decay: usize` to `TinyLfuCache<K, V>` (initialize to 0 in `try_new`).

In both `get()` and `put()`, after calling `self.sketch.increment(key)`, increment `self.ops_since_decay`. When it reaches `self.capacity * 10`, call `self.sketch.decay()` and reset `self.ops_since_decay = 0`.

Add a `decay()` method to `CountMinSketch`:

```rust
fn decay(&mut self) {
    for row in self.counts.iter_mut() {
        for c in row.iter_mut() {
            *c >>= 1;
        }
    }
}
```

No other changes. Preserve `SKETCH_DEPTH = 4`, `SKETCH_WIDTH_FACTOR = 4`, `Vec<Vec<u32>>` row layout, and all existing sketch geometry. The trigger interval `capacity * 10` is ~5× longer than the `width / 2` cadence that destroyed hit rate in cycle/0001/v001; the half-decay (`>>= 1`) preserves relative frequency ordering among hot items while shrinking counts for keys that have stopped being accessed.

## Rationale

The baseline accumulates sketch counts without bound. A key that was heavily accessed in the distant past but is now cold retains a high count that can block admission of currently-hot items. The half-decay scales all counters proportionally so the relative ordering of the live working set is preserved, while dormant keys lose influence over time. The LIRS trace's 500 000 accesses at `capacity = 2048` yield roughly 24 decay events — enough aging to matter without erasing the frequency signal the way a reset or shorter interval would.
