# H03

Replacing the dual-chain SLRU with a single-list CLOCK second-chance policy will deliver equivalent hit-rate protection with lower per-operation bookkeeping cost.

## Parent

cycle/0009/v002

## Changes

Collapse the two doubly-linked lists (probationary head/tail + protected head/tail) into a
single LRU list, reusing the existing `prot_flags` bitset as the CLOCK "referenced" bit.

### Fields to remove from `TinyLfuCache`

Delete `prot_head: Option<usize>`, `prot_tail: Option<usize>`, and `prot_count: usize`.
Keep `prot_capacity: usize` (repurposed as the maximum clock-scan bound per eviction, set to
`(capacity / 5).max(1)` as before) and `prot_flags: Vec<u64>` (the CLOCK reference bits).

### Functions to delete

Remove `prot_unlink()`, `prot_push_back()`, and `promote_to_protected()` entirely.

### `get` path (single list)

Replace the current dual-chain dispatch with a single-list move + bit-set:

```rust
pub fn get(&mut self, key: &K) -> Option<&V> {
    self.sketch.increment(key);
    let &idx = self.map.get(key)?;
    self.unlink(idx);
    self.push_back(idx);           // move to MRU end of the single list
    self.set_protected_flag(idx);  // mark as "referenced" for CLOCK
    Some(&self.nodes[idx].value)
}
```

### `put` existing-key path (single list)

Same single-list refresh + bit-set:

```rust
if let Some(&idx) = self.map.get(&key) {
    self.nodes[idx].value = value;
    self.unlink(idx);
    self.push_back(idx);
    self.set_protected_flag(idx);
    return;
}
```

### `put` new-key path — CLOCK eviction loop

When the cache is full, replace the current "force-demote from prot_head" guard and the
single victim comparison with a bounded CLOCK scan before the admission gate:

```rust
// Bounded CLOCK scan: give referenced nodes a second chance.
let mut scanned = 0usize;
loop {
    let candidate = self.head.expect("full cache has no LRU head");
    if self.is_protected(candidate) && scanned < self.prot_capacity {
        // Second chance: clear the reference bit and move to MRU tail.
        self.clear_protected_flag(candidate);
        self.unlink(candidate);
        self.push_back(candidate);
        scanned += 1;
    } else {
        // Either unreferenced or scan limit reached — this is the victim.
        break;
    }
}
let victim_idx = self.head.expect("full cache has no victim after clock scan");
```

Then run the existing admission gate unchanged (both the 7-in-8 standard comparison and the
1-in-8 stricter `> victim_freq + 1` threshold via `evict_counter`).

### Invariants to preserve

- `prot_flags` bits are set only by `get` and the existing-key `put` path; cleared only by
  the CLOCK scan during eviction. This mirrors the SLRU rule that protection is conferred by
  reads/writes and revoked under eviction pressure.
- The scan bound `prot_capacity` (≈ 20% of capacity) caps the worst-case CLOCK work per
  eviction to the same fraction as the previous protected-segment size.
- The 8× sketch width, bijective remix hash (`seeded_hash` + `remix`), and amortised gate
  (`evict_counter`, 1-in-8 threshold) are unchanged from v002.

### Rationale

Cycle 0009 identified dual-list bookkeeping as the primary put-path latency cost: every
full-cache `put` for a new key conditionally walks and relinks two chains. The CLOCK design
eliminates the second chain entirely; the CLOCK scan is amortised across evictions and
bounded at the same 20% fraction as the old protected segment. A referenced node that
survives the scan (bit cleared, moved to MRU) effectively gets the same second-chance
as a node in the SLRU protected zone, but without maintaining separate head/tail pointers
or a live count.
