# H02

Doubling the sketch width factor from 8× to 16× will further reduce collision noise and raise hit rate on the Zipfian trace.

## Parent

cycle/0007/v003

## Changes

In `src/tiny_lfu/mod.rs`, change the single constant:

```rust
// Before
const SKETCH_WIDTH_FACTOR: usize = 8;

// After
const SKETCH_WIDTH_FACTOR: usize = 16;
```

No other code changes. All functions (`increment`, `estimate`, `seeded_hash`, `remix`) are
identical to v003. The `try_new` path already computes sketch width as:

```rust
let width = (capacity * SKETCH_WIDTH_FACTOR)
    .max(MIN_SKETCH_WIDTH)
    .next_power_of_two();
```

At the evaluation capacity of 1024, this produces a sketch width of 16384 (instead of 8192),
giving a heap footprint of 4 rows × 16384 × 4 bytes = 262144 bytes. At the benchmark capacity
of 2048 it becomes 32768 per row = 524288 bytes total.

### Rationale

The 4× → 8× jump (cycle 0007 v003) delivered a confirmed hit-rate gain of ~0.004 (0.737 → 0.741)
by halving the expected bucket collision rate. The 8× → 16× step is the natural continuation of
the same hypothesis: if the 4× baseline was collision-limited on this Zipfian trace, the 8×
sketch may still exhibit residual collision noise that 16× can suppress. The sketch heap grows
2× (from ~128 KB to ~256 KB at cap=1024), which stays within typical L2 cache boundaries and
should not materially regress the per-op latency that cycle 0007 v003 already achieved (p50=100ns).
The bijective remix hash and amortised admission gate are preserved unchanged.
