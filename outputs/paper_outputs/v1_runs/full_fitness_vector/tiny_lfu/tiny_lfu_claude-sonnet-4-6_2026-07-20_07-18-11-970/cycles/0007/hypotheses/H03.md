# H03

Doubling the sketch width factor from 4× to 8× reduces count-min sketch collision probability, producing more accurate frequency estimates for the admission gate and raising hit rate.

## Parent

cycle/0006/v002

## Changes

Change exactly one constant in `mod.rs`:

```rust
// Before:
const SKETCH_WIDTH_FACTOR: usize = 4;

// After:
const SKETCH_WIDTH_FACTOR: usize = 8;
```

No other code changes are needed. All downstream logic — `try_new()`, `CountMinSketch::new()`, `increment()`, `estimate()`, the admission gate — derives the sketch width from this constant and adapts automatically.

**Effect on sketch geometry:**
- Capacity 1 024: width = 1 024 × 8 = 8 192 (was 4 096); heap = 4 × 8 192 × 4 = 131 072 bytes (was 65 536).
- Capacity 2 048 (benchmark trace size): width = 16 384; heap = 262 144 bytes.
- `MIN_SKETCH_WIDTH` (16) is unaffected and only guards very small capacities; leave it unchanged.

**Invariants to preserve:**
- The `TinyLfuCache` struct layout (including `evict_counter: u32`) is unchanged; only heap allocation by the sketch grows.
- The bijective-remix hash path (`seeded_hash` + `remix`), the per-row position derivation, the 1-in-8 strict admission gate, and all unit tests are untouched.
- The `next_power_of_two()` call in `try_new()` ensures width remains a power of two for the bitmask to work correctly.

## Rationale

Six cycles of evolution have substantially refined the hash computation, node layout, victim-selection policy, and admission-gate threshold. Sketch width — the primary lever controlling per-key collision noise in the count-min structure — has never been tested as an independent variable. The global best-ever hit rate (0.738, cycle/0003/v003) used the same 4× width; if some of those missed hits are due to frequency over-estimation from collisions, a wider sketch would correct them. Doubling from 4× to 8× halves the expected collision rate at any given bucket (Zipfian skew means hot items share buckets with many cold items, so the expected count noise is proportional to working-set size divided by width). The trade-off is a larger sketch heap (128 KB–256 KB at the benchmark sizes), which may increase L2/L3 pressure and raise per-op-time; but hit-rate gains compound across every operation while the latency delta is bounded by the sketch access portion of each op.
