# H01

Increasing the best-of-2 victim-comparison rate from 1-in-8 to 1-in-4 will raise hit rate on Zipfian traces without breaking per-op-time parity.

## Parent

cycle/0004/v002

## Changes

In `TinyLfuCache::put`, the amortised best-of-2 eviction branch is gated by
`self.evict_counter & 7 == 0` (fires every 8th full-cache eviction). Change
the mask constant from `7` to `3` so the branch fires every 4th eviction
instead:

```rust
let victim_idx = if self.evict_counter & 3 == 0 {
    // Every 4th eviction: compare LRU head vs second-oldest ...
```

No other logic changes: the second-oldest candidate fetch, the frequency
comparison (`second_freq < head_freq`), and the fallback plain-LRU branch for
the remaining 3-in-4 evictions all stay exactly as in v002. The `evict_counter`
field, its wrapping increment, and all sketch and admission logic are
unchanged.

The key question is whether doubling the probe rate from 12.5 % to 25 % of
evictions captures a proportionally larger fraction of the frequency-aware
selection benefit while keeping per-op-time at the same level cycle/0004/v002
achieved — or whether the extra sketch lookups start pushing p50 latency above
100 ns.

## Rationale

cycle/0004/v002 proved the signal is strong enough to survive 1-in-8 sampling
(hit-rate improved, latency stayed neutral). The cycle insight explicitly flags
1-in-4 as the natural next step. If latency remains flat at this rate, the
optimal probe frequency lies at or above 25 % and a further step to 1-in-2 is
worth testing; if latency breaks, the sweet spot has been bracketed.
