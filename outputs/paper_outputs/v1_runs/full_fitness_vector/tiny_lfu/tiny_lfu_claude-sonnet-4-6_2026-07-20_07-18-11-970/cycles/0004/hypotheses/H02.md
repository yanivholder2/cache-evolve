# H02

Performing best-of-2 victim selection on only every eighth eviction rather than on every eviction will capture most of the hit-rate benefit found in cycle/0003/v003 while keeping per-op-time close to cycle/0003/v002.

## Parent

cycle/0003/v002

## Changes

In `src/tiny_lfu/mod.rs`, add one field to `TinyLfuCache`:

```rust
evict_counter: u32,
```

Initialise it to `0` in `TinyLfuCache::try_new` (add `evict_counter: 0` to the `Self { ... }` struct literal).

In `TinyLfuCache::put`, at the start of the eviction branch (immediately after the `if self.nodes.len() < self.capacity { ... return; }` early-return block, where `self.head` is the victim candidate), increment the counter and apply best-of-2 selection conditionally:

```rust
self.evict_counter = self.evict_counter.wrapping_add(1);
let victim_idx = if self.evict_counter & 7 == 0 {
    // Every 8th eviction: compare LRU head vs second-oldest,
    // evict whichever has lower estimated frequency.
    let head_idx = self.head.expect("TinyLfuCache: full cache has no victim");
    match self.nodes[head_idx].next {
        None => head_idx,
        Some(second_idx) => {
            let head_freq = self.sketch.estimate(&self.nodes[head_idx].key);
            let second_freq = self.sketch.estimate(&self.nodes[second_idx].key);
            if second_freq < head_freq { second_idx } else { head_idx }
        }
    }
} else {
    // Remaining 7 out of 8 evictions: plain LRU-head selection (no extra probe).
    self.head.expect("TinyLfuCache: full cache has no victim")
};
```

Then continue with the existing admission-check + replacement code using `victim_idx` (clone the victim key, estimate frequencies, replace if `incoming_freq > victim_freq`). No other changes: the sketch, hash logic, struct fields beyond `evict_counter`, LRU link helpers, and tests remain as in v002.

The `& 7` mask is equivalent to `% 8` and uses only a bitwise AND, adding no branch prediction pressure beyond the one conditional select. The wrapping add avoids overflow on long-running caches.

## Rationale

cycle/0003/v003 demonstrated that best-of-2 victim selection has a real positive hit-rate signal (+0.0017 over baseline), but the mandatory two extra sketch probes on every full-cache `put` doubled the median eviction latency. Amortising those probes over 8 evictions reduces the average extra-probe overhead to one-eighth of v003's cost. On a stable LIRS working set where eviction frequency (rather than rate) drives hit-rate corrections, even occasional best-of-2 decisions should rescue the most egregious frequency-blind evictions while keeping the common-case path as cheap as v002.
