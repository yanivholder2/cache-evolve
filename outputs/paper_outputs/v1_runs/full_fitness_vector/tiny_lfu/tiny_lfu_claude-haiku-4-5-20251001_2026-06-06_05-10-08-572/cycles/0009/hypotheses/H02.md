# H02

Add an absolute frequency floor to the admission gate to filter out very-low-frequency items that may represent estimate noise or hash collisions, improving hit-rate through more selective entry control.

## Parent

baseline

## Changes

In `src/tiny_lfu/mod.rs`, in the `put()` method where the admission check occurs (around line 122 in prior cycles), modify the condition that gates admission on frequency comparison:

```rust
// Old:
if incoming_freq > victim_freq {
    // admit and evict
}

// New:
if incoming_freq > 1 && incoming_freq > victim_freq {
    // admit and evict
}
```

This requires incoming items to have an estimated frequency of at least 2 (i.e., `incoming_freq >= 2`) before they are considered for admission, in addition to the existing relative comparison against the victim's frequency. Keep the sketch geometry (depth=3, width=4 from baseline), eviction strategy (LRU-only, N=1 from baseline), and all other logic unchanged.

## Rationale

The cross-cycle insights document identifies sketch collision sensitivity as a root cause of pathology, particularly in cycle 0008 v002 where depth-2 produced a 141% p99 tail-latency spike. Frequency estimates below 2 are likely to be dominated by noise or single-hit coincidences rather than true access patterns. By filtering out items with `freq < 2`, we reduce cache pollution from items that are statistically unlikely to have high future value. This is an orthogonal admission-tuning approach that does not modify victim selection or sketch geometry. It targets hit-rate by ensuring only items with meaningful frequency signals enter the cache. The baseline's strict `incoming_freq > victim_freq` is proven necessary; this hypothesis adds a secondary absolute gate without relaxing the relative comparison, providing additional selectivity.
