# H01

Replace LRU-only victim selection with frequency-aware candidate selection to improve hit-rate on the latency-optimized depth-3 baseline.

## Parent

cycle/0002/v002

## Changes

In the `put()` method (around line 98), modify the victim selection strategy. Instead of always evicting `self.head` (the LRU item), scan a fixed window of N=5 items starting from the head of the linked list, compute their estimated frequencies using the sketch, and select the one with the minimum estimated frequency for eviction.

Pseudocode:
```
let victim_idx = self.head;
let mut min_freq = self.sketch.estimate(&self.nodes[victim_idx].key);
let mut candidate = victim_idx;
let mut current = self.nodes[victim_idx].next;

// Scan up to 5 items from head, find minimum frequency
for _ in 0..4 {
    if let Some(idx) = current {
        let freq = self.sketch.estimate(&self.nodes[idx].key);
        if freq < min_freq {
            min_freq = freq;
            candidate = idx;
        }
        current = self.nodes[idx].next;
    } else {
        break;
    }
}

// Evict the candidate with minimum frequency
let victim_idx = candidate;
```

This targets hit-rate by ensuring we evict truly cold items rather than purely LRU-ordered items. Keep the depth-3 sketch geometry and strict admission condition `incoming_freq > victim_freq` unchanged.

## Rationale

The cycle 0004 insight identifies eviction policy variations as an unexplored lever. The current implementation evicts the LRU head regardless of actual frequency, potentially displacing hot items that happen to be older. A small candidate pool (N=5) introduces frequency awareness without O(n) per-operation overhead, aligning eviction decisions with the LFU principle while preserving the latency gains of the depth-3 baseline.
