# H03

Replacing the per-row compare-and-bump in the sketch with a branchless saturating add trims per-op-time on the get/put hot path at bit-identical hit-rate.

## Parent

cycle/0005/v001

## Changes

In `CountMinSketch::increment` in `src/tiny_lfu/mod.rs`, replace the
conditional increment

```
let counter = &mut self.counts[row][pos];
if *counter < MAX_COUNT {
    *counter += 1;
}
```

with a single branchless statement using `u8::saturating_add`:

```
let counter = &mut self.counts[row][pos];
*counter = counter.saturating_add(1);
```

Because `MAX_COUNT == u8::MAX`, `saturating_add(1)` caps at exactly the
same ceiling, so the stored counts — and therefore every `estimate` and
every admission/eviction decision — are bit-identical to the parent. The
only difference is removing one data-dependent branch per row from the
single hottest inner loop (`increment` runs on every get and every put,
`SKETCH_DEPTH` times each). Leave `estimate`, `position_for`, and the
sketch geometry untouched.

Rationale: this is a pure micro-architectural cost edit on a different
surface than sketch depth or victim sampling — it removes a branch the
predictor must resolve under the high-frequency, saturating counter
distribution of this hot set. The experiment confirms the claim if
hit-rate is unchanged at 0.7425 while get p50 falls below the incumbent.
It also composes cleanly with H01's depth reduction since both touch only
the increment loop body versus the loop count.
