# H01

Stacking v002's 4x-wider count-min sketch onto v001's compact u32-sentinel node layout raises hit-rate to v002's level while holding metadata-size at 24.

## Parent

cycle/0004/v001

## Changes

In `src/tiny_lfu/mod.rs`, change the constant `SKETCH_WIDTH_FACTOR` from
`4` to `16`, matching the width that won the hit-rate dimension in
cycle/0004/v002. Leave everything else in v001 intact: the `u32`/`NIL`
intrusive-link node layout, the `FastHasher` double-hash sketch
addressing in `position_for`, the sampled-coldest victim walk in `put`,
and `SKETCH_DEPTH = 4`. The `width` computation in `try_new`
(`(capacity * SKETCH_WIDTH_FACTOR).max(MIN_SKETCH_WIDTH).next_power_of_two()`)
already consumes the constant, so no other edit is needed. This is the
additivity check the cycle-0004 insight asked for: v002 proved 16x width
lifts hit-rate from 0.7369 to 0.7425 by quartering sketch collisions,
and v001 proved the compact node layout holds metadata-size at 24 with
bit-identical hit-rate; combining them should yield ~0.7425 hit-rate at
metadata-size 24 with per-op-time unchanged, since the extra sketch
columns enlarge only the heap table the hot path already strides with one
cached double-hash.

## Rationale (optional)

The two cycle-0004 winners modify disjoint structures (node encoding vs.
sketch geometry) and neither touches admission semantics, so the
cross-cycle "composition is additive" pattern predicts a clean stack that
strictly dominates both parents on the composite score.
