# H01

Periodically halving all sketch counters (frequency aging) raises hit-rate by keeping admission estimates adaptive to workload shifts instead of locking in stale-hot keys.

## Parent

baseline

## Changes

In `src/tiny_lfu/mod.rs`, give `CountMinSketch` a frequency-aging reset
modeled on real TinyLFU's sample-based decay. Add two fields: a running
`size: u64` counter and a `sample_size: usize` threshold computed at
construction in `CountMinSketch::new` as roughly `10 * width / SKETCH_WIDTH_FACTOR`
(i.e. ~10× the cache capacity; pick a concrete multiple and document it).

Modify `increment()` so that after bumping the `depth` counters for a key it
also does `self.size += 1`, and when `self.size >= sample_size as u64` it calls
a new private `reset()` method. `reset()` halves every counter in `self.counts`
(`*c >>= 1`) and sets `self.size` to a value reflecting the surviving mass —
either `self.size >> 1` or recompute, but keep it bounded so resets recur
periodically rather than once.

Leave `estimate()`, the LRU list, and the `put()` admission test
(`incoming_freq > victim_freq`) structurally unchanged — only the counter
values they read are now periodically decayed. Preserve all three invariants
(capacity_bound, value_fidelity, no_phantom_items): this change touches only
frequency bookkeeping, never which keys are resident or what values they map to.

## Rationale (optional)

The baseline sketch counters only ever saturate upward (capped at `MAX_COUNT`),
so an early-hot key can permanently out-rank later-arriving hot keys and block
admission. Aging is the canonical TinyLFU fix and targets the hit-rate dimension
(baseline 0.7362) without changing per-entry metadata size.
