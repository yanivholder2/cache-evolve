# H02

Requiring an incoming key to beat the sampled victim's frequency by a margin of 1 (admission hysteresis) raises hit-rate by protecting the stable hot set from churn, at near-zero per-op and metadata cost.

## Parent

cycle/0005/v001

## Changes

Modify only the admission test at the end of `TinyLfuCache::put`. The parent
admits the incoming key when `incoming_freq > victim_freq`. With
monotonically inflating counters and the confirmed stable, low-true-frequency
hot set of this trace, a transient mid-frequency newcomer that just edges out
the sampled-coldest victim still evicts a settled incumbent, causing churn.

Introduce a compile-time constant `const ADMISSION_MARGIN: u32 = 1;` near the
other sketch constants, and change the admission branch from
`if incoming_freq > victim_freq` to
`if incoming_freq > victim_freq + ADMISSION_MARGIN`.

Keep everything else identical: the sampled victim walk (SAMPLE_VICTIMS = 5),
the strictly-`<` victim comparison, node layout, sketch geometry, and the
get/put frequency recording. No new fields, no metadata growth, and only one
extra integer add on the eviction path (which already runs only when the cache
is full), so per-op time should be unchanged within noise.

The testable claim: demanding a clear frequency advantage before displacing an
incumbent reduces eviction churn on a stable hot set and lifts hit-rate. If it
instead rejects genuinely-rising keys and lowers hit-rate, the margin lever is
refuted for this trace.

## Rationale (optional)

This probes the admission *decision* rather than the estimate or geometry —
a strategy orthogonal to H01 and H03 — and is the cheapest possible hit-rate
lever (one constant, one comparison) so a positive result is immediately
adoptable on the incumbent base.
