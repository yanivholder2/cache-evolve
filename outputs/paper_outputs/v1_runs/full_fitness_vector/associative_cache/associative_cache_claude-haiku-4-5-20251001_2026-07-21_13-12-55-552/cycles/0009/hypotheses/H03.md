# H03

Improve hit-rate by fixing insertion-position bias based on workload characterization during an initial phase, eliminating per-operation overhead while capturing temporal access-pattern insights.

## Parent

cycle/0004/v003

## Changes

Add a `characterization_phase: bool` and `hot_phase_count: u32` field to the `AssociativeCache` struct in `src/associative_cache/mod.rs`. During the first 512 insertion operations (tracked in put()), sample access patterns by recording the ratio of get hits that occur on recently-inserted items (tracked per-item via insertion order in `src/shared/item.rs` insert timestamp). Once 512 insertions are complete, compute a fixed `insertion_bias` value (0.0–1.0) based on whether the workload exhibits high temporal reuse (bias toward head positioning) or temporal spreading (bias toward mid-bucket positioning), then lock this bias for all subsequent operations. Modify the insertion path in `src/associative_cache/associative_cache_bucket.rs` to use this fixed bias when placing new items in the bucket's eviction order. Maintain the 32×64 geometry and early-exit optimization from the parent; only the insertion position changes. This trades a one-time characterization cost (512 operations) for zero per-operation overhead during normal execution, potentially recovering hit-rate improvements similar to cycle 0008 v003's +0.43% without the 40–50% latency penalty.
