# H01

Reduce per-put latency overhead in characterization-based insertion bias by replacing floating-point arithmetic with integer-only operations to improve hit-rate gains achieved at acceptable latency.

## Parent

cycle/0009/v003

## Changes

Replace the `insertion_bias: f64` field in `AssociativeCache` and `AssociativeCacheBucket` with `insertion_bias: u8` (representing scale 0–15). In `compute_insertion_position()`, replace the float multiplication `(self.insertion_bias * len as f64) as usize` with integer arithmetic: `(insertion_bias as usize * len) >> 4`, which uses a bit-shift instead of float multiplication. Update the bias calculation at the end of characterization phase to output u8: `self.insertion_bias = ((self.recent_hits_count as f64 / self.total_gets_count as f64) * 15.0) as u8` (computed once per characterization phase, not per-operation). This eliminates the per-put floating-point arithmetic overhead that contributes to cycle 0009 v003's 2–3× latency degradation, while preserving the insertion-position biasing mechanism that achieved +8.1% hit-rate.

## Rationale

Cycle 0009 v003 proved that insertion-bias characterization works algorithmically (+8.1% hit-rate improvement), but latency overhead (2–3×) makes the gain infeasible. Root-cause analysis identifies the per-put `compute_insertion_position()` call, which performs floating-point multiplication on every insertion. Modern CPUs heavily penalize float operations in the hot path (stall pipeline, disable optimizations). Replacing with integer bit-shift (a single-cycle operation) directly targets this bottleneck without changing the algorithmic strategy. If latency penalty is primarily from arithmetic type, this variant should recover hit-rate gain at reduced cost.
