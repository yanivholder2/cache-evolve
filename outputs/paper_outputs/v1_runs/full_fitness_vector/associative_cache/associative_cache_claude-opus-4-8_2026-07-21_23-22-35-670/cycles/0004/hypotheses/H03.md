# H03

Admit miss items at the bucket midpoint instead of the immediate front slot so genuinely-hot-but-not-yet-rehit items get a longer proving window, testing whether midpoint probation lifts hit-rate over v003's pure front admission — with no per-item state.

## Parent

cycle/0003/v003

## Changes

In the overlaid `src/associative_cache/associative_cache_bucket.rs`, change only
the admission position in `put`. v003 currently does `self.items.insert(0, item)`
(the immediate eviction slot). Replace the insert index with a midpoint:
`let mid = self.items.len() / 2; self.items.insert(mid, item);` computed *after*
any eviction, so `mid` reflects post-evict length.

Rationale for the geometry: under `ClassicLRU`, eviction removes index 0 and a
re-hit promotes to the back. Pure front admission (v003) places a fresh miss at
the very next-to-evict slot, so a hot item that is not re-hit before the next
conflicting insert dies immediately. Midpoint admission instead seats new items
in a probationary middle band: unpromoted items sink toward index 0 across
subsequent evict-and-insert rounds and are eventually evicted (scan resistance
preserved — scan items still never reach the protected back), while items re-hit
within a slightly longer window are promoted to the back. This is the classic
midpoint-insertion / SLRU probation heuristic realised purely by insertion index.

Keep everything else identical to v003: `Item` remains key+value (metadata-size
16), the update-in-place branch still routes through `get_from_position`, and
eviction still removes the `ClassicLRU` front (index 0). No new struct fields, no
per-item state — a single changed insert index versus the parent.

## Rationale (optional)

An open question is whether stateless front admission leaves hit-rate on the
table. Midpoint insertion is a distinct, stateless point on the
admission-geometry axis: if a longer probation window retains more true hot items
without admitting scan items into the protected back, it closes v003's 0.0085 gap
to 0.7267 at zero metadata and latency cost; if it instead lets scan items
linger, the negative result sharpens where the front-admission win comes from.
