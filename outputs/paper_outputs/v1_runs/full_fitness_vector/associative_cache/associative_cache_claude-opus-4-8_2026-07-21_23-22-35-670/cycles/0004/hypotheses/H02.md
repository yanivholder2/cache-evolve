# H02

Stack explicit reuse protection onto v003's stateless front-admission base to test whether front admission plus one-hit-wonder protection beats 0.7267 hit-rate at the 16-byte metadata floor with clean tails.

## Parent

cycle/0003/v003

## Changes

Extend the overlaid `src/associative_cache/associative_cache_bucket.rs` so v003's
probationary-front admission is combined with a bucket-side reuse set — but
built cheaply from the start (avoiding v001's quadratic rebuild).

1. Add a field `reuse: Vec<bool>` to `AssociativeCacheBucket`, kept
   index-aligned with `items` (`reuse.len() == items.len()` at all exits).
   Initialise `Vec::with_capacity(settings.bucket_size)` in `new`. It lives on
   the bucket struct, which the metadata-size metric does not weigh, so `Item`
   stays key+value = 16 bytes.
2. In `put`, keep v003's front admission: on a miss into a full bucket, evict
   first, then `self.items.insert(0, item)` and `self.reuse.insert(0, false)`
   (fresh miss items are unprotected). On an update-in-place of an existing key,
   route through `get_from_position` as today.
3. In `get_from_position`, after the policy relocates the accessed item from
   `position` to the returned `index`, move the bit with the same shape of
   operation — `let bit = self.reuse.remove(position); self.reuse.insert(index, bit);`
   then `self.reuse[index] = true`. O(n), not the O(n²) key search.
4. Override `eviction_candidate_index` to return the first slot in index order
   whose `reuse == false` (the frontmost probationary one-hit-wonder), falling
   back to index 0 if every resident is protected. Override `remove_at` to
   `self.reuse.remove(index)` alongside `self.items.remove(index)`.

The distinction from H01/v001: new items land at the *front* (probation) rather
than the *back* (MRU), so scan items are both positionally exposed and
reuse-unprotected — the two scan-resistance signals compound.

## Rationale (optional)

v003 (0.7182, front admission, no state) and v001 (0.7267, back admission,
protection) each hit only one of the two levers. This isolates whether admission
position matters once protection exists, and whether compounding both pushes
hit-rate past 0.7267 while keeping v003's clean p99 tails and the 16-byte floor.
