# H01

Replace the SipHash `DefaultHasher` in `get_index`/`hash` with a cheap integer finalizer to cut the per-op hashing cost paid on every get and put, lowering per-op-time.

## Parent

cycle/0008/v002

## Changes

Target `src/shared/utils.rs`. Today `get_index` calls `hash`, which builds a
`std::collections::hash_map::DefaultHasher` (SipHash), feeds the key through
`Hash`, and calls `finish()` — a keyed-permutation hash that runs on *every*
`AssociativeCache::put` and `get_and_update_item` (both route through
`get_index`). SipHash over an 8-byte key is tens of nanoseconds and is a fixed
cost the incumbent pays on the hot path independent of bucket work; it is the
largest single per-op cost not addressed by the reuse-vector fix in v002.

Replace the `DefaultHasher` path with a cheap integer avalanche/finalizer. Keep
the public signatures of `hash<K>` and `get_index<K>` and their `K: Hash + Debug`
bounds unchanged so the rest of the crate (and the gate's `find_keys_for_bucket`
helper, which reuses this same `get_index`) stays self-consistent. Implement the
mix by hashing the key into a `u64` seed once with a lightweight `Hasher` and
then running a Fibonacci-style multiply-xorshift finalizer
(`h = h.wrapping_mul(0x9E3779B97F4A7C15); h ^= h >> 29; ...`) before `% size` —
or, simpler, keep a single `DefaultHasher` write but that is exactly what we are
removing, so prefer folding the key bytes with a wrapping-multiply mixer that
avoids the SipHash setup entirely. The result must remain deterministic
(`hash(k)==hash(k)`) and total across the key space, and stay `< size` after the
modulo (the existing `get_index_within_bounds` / `get_index_deterministic`
tests must still pass).

Preserve everything else: the bucket policy, the reuse-scan eviction, and the
16-byte `Item`. Distribution should stay approximately uniform so hit-rate holds
near 0.7267; the primary claim is the per-op-time reduction from removing the
SipHash setup on every access.

## Rationale (optional)

Every measured op calls `get_index`; the incumbent's p50 sits at 100 while
baseline reads 69, and the SipHash construction is a fixed hot-path tax that
neither the metadata nor the reuse-vector work touches. A one-multiply mixer is
~1ns versus SipHash's tens of ns, so this is the largest untried latency lever
and is orthogonal to the bucket-side changes explored so far.
