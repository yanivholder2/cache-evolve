# H02

Admitting a re-referenced (recently-evicted) key as already-protected via a per-bucket ghost history lifts hit-rate above the reuse-bit incumbent's 0.7267 ceiling.

## Parent

cycle/0003/v001

## Changes

Build on `cycle/0003/v001`'s reuse-bit bucket (the top incumbent:
per-bucket `reuse: Vec<bool>`, scan-resistant `eviction_candidate_index`
picking the first LRU-front slot whose reuse bit is `false`, 16-byte
`Item`). Inherit that overlay wholesale — `Item`, eviction_policy, and
the reuse machinery — then add a 2Q-style ghost history.

Add a second bucket-side field, `ghost: Vec<K>` (a small fixed-capacity
ring, e.g. `max_size` keys), that records the keys of items **evicted
from this bucket**. Wire it in:
- In `remove_at` / `evict_item`, push the evicted item's key onto
  `ghost`, evicting the oldest ghost key when the ring is full. Ghost
  stores keys only, never values — it stays off `Item`, so the
  metadata-size metric (which weighs only `Item` and the top-level
  cache) is unchanged at 16 bytes.
- In `put`, on a genuine miss (key not resident), check whether the
  incoming key is present in `ghost`. If it is, this key was seen and
  evicted before — a proven reuse candidate — so admit it as protected:
  set its `reuse` bit to `true` at insertion instead of the default
  `false`, and remove it from `ghost`. A miss on a never-before-seen key
  keeps the parent's behaviour (inserted unprotected, `reuse = false`).

Preserve every existing invariant: `reuse.len() == items.len()` at all
times, the index-alignment that `realign_reuse` maintains on hits, and
the LRU-front fallback when all bits are set. Only the *initial* reuse
bit of an admitted item and the eviction-time ghost bookkeeping change.

The bet: the reuse-bit incumbent only protects an item after a hit while
it is still resident; a key with a reuse distance longer than its bucket
lifetime is evicted and then re-admitted cold every time, never earning
protection. A ghost list gives the bucket memory across eviction so
returning keys survive the next scan burst — the classic 2Q lever,
achieved with off-`Item` state so the 16-byte floor holds. Watch that
the ghost scan in `put` is only `O(ghost_len)` on misses and does not
reintroduce a quadratic per-op cost.
