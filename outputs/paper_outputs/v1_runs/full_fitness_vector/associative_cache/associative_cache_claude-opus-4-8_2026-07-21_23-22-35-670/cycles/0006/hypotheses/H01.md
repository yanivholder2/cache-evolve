# H01

Restore the 16-byte `Item` layout to the segmented (SLRU) bucket so its ceiling-breaking hit-rate is delivered at the metadata-size floor instead of the 40-byte regression it currently carries.

## Parent

cycle/0005/v003

## Changes

The parent's `AssociativeCacheBucket` (segmented SLRU with a `protected_len`
boundary and single-element rotations) is kept **exactly as-is** — same
`put`, same `get_from_position` promotion/demotion logic, same `protected_cap`.
The only defect this hypothesis fixes is the overlay-hygiene regression: the
cycle-5 overlay carried *only* the bucket file, so `Item` silently reverted to
the 40-byte baseline (`lfu_counter: usize` + `timestamp: Instant`), scoring
metadata-size 40 instead of the 16-byte floor.

Add to this variant's overlay the trimmed layout already proven at 16 bytes by
`cycle/0003/v001` and `cycle/0003/v003`:

- `src/shared/item.rs`: drop the `lfu_counter` and `timestamp` fields so
  `Item<K,V>` is just `{ key: K, value: V }` (16 bytes for `u64,u64`). Update
  `Item::new`, the `Display` impl, and the in-file unit tests to stop
  referencing the removed fields.
- `src/shared/eviction_policy.rs`: remove the policies that read the deleted
  fields (`Lfu` reads `lfu_counter`; `TimestampLRU` reads/writes `timestamp`)
  and their `EvictionPolicyKind` entries, matching exactly the trimmed
  eviction-policy file `cycle/0003/v001` shipped — do not invent a new trim,
  copy the known-gate-passing one so `EvictionPolicyKind::all()`, the index
  round-trips, and the contract/invariant gates still pass.

Invariant to preserve: the SLRU bucket never reads `lfu_counter` or `timestamp`
(it uses `protected_len` + rotations), so removing those fields is behaviourally
inert for hit-rate — the trace-measured hit-rate must be identical to the
parent's while metadata-size drops from 40 to 16.

## Rationale (optional)

Segmentation is the one lever that has moved hit-rate, but the parent forfeited
the metadata win by omission. This is the cheap, monotonic "trim dead metadata
off the eval path" move applied to the segmented incumbent — no logic risk, a
full 40→16 metadata reclaim.
