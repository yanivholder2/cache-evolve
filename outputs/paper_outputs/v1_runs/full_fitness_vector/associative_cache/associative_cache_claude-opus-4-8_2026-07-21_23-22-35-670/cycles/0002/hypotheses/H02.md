# H02

Replacing v002's permanent binary protection with a self-clearing second-chance (CLOCK-style) reference bit lets long-resident-but-cold entries become evictable again, pushing hit rate above v002's 0.727.

## Parent

cycle/0001/v002

## Changes

v002's `ClassicLRU` marks any reused item as permanently protected
(`lfu_counter` becomes and stays nonzero), so once every resident item
has been touched at least once the eviction scan finds no
`lfu_counter == 0` entry and degrades to plain LRU-front — and an item
that was hot long ago but is now cold stays protected forever. Fix that
by giving protection a second chance instead of permanent immunity.

In `src/shared/eviction_policy.rs`, `ClassicLRU`:
- Keep `get_from_position` as remove(position)+push, and on reuse set the
  reference bit by saturating `lfu_counter` at 1 (i.e.
  `items.last_mut().unwrap().lfu_counter = 1`), not an unbounded
  increment.
- Rewrite `eviction_candidate_index` as a CLOCK sweep from the front: walk
  items front-to-back; the first item with `lfu_counter == 0` is the
  victim; for each item with `lfu_counter == 1` that you pass, clear it to
  0 (give it its second chance) as a side effect. Because
  `eviction_candidate_index` takes `&[Item]` it cannot mutate — so move
  this logic into the bucket's eviction path: override
  `eviction_candidate_index`/`evict_item` in
  `src/associative_cache/associative_cache_bucket.rs` (editable) to
  perform the clearing sweep over `get_items_mut()` and return/remove the
  first slot whose bit is already 0, wrapping to slot 0 if a full sweep
  clears everything.

Preserve all `EvictionPolicyKind` ordinals/names and the
`Item` layout (still uses the existing `lfu_counter` field, no new
metadata). Target dimension: hit-rate. Invariant to keep: eviction still
removes exactly one resident item and never touches an empty bucket.

## Rationale (optional)

The cycle insight's first open question asks whether scan resistance can
be improved without new metadata. Second-chance aging is the classic
answer: it keeps v002's zero-metadata reuse signal but stops cold-but-
once-hot items from squatting, which is exactly the failure mode that
caps v002's hit rate on the LIRS-style trace.
