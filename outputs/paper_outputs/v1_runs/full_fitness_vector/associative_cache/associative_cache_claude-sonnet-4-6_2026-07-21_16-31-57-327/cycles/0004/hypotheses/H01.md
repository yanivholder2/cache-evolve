# H01

Extending the promotion cap in ClassicLRU::get_from_position from one swap to three will raise hit rate on Zipfian traces by allowing warm mid-bucket items to converge to position 0 in fewer accesses.

## Parent

cycle/0003/v003

## Changes

In `eviction_policy.rs`, replace the single conditional swap in `ClassicLRU::get_from_position` with a loop that runs at most 3 iterations. The position-0 early-return guard is preserved unchanged. After the guard, enter a loop capped at 3:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;
    }
    let mut pos = position;
    for _ in 0..3 {
        items[pos].lfu_counter += 1;
        if items[pos].lfu_counter > items[pos - 1].lfu_counter {
            items.swap(pos, pos - 1);
            pos -= 1;
            if pos == 0 {
                break;
            }
        } else {
            break;  // no swap: left neighbour is still hotter, stop early
        }
    }
    pos
}
```

The early break on a failed swap keeps the common-case (already near the front) fast. No changes to `eviction_candidate_index` (stays `items.len() - 1`), `promotion_candidate_index` (stays `0`), or `item.rs` — the 32-byte aligned struct from v003 (`key: K`, `value: V`, `lfu_counter: usize`, `_pad: u64`) is preserved exactly.

## Rationale

v003's single swap cap means a warm item at distance k from the head requires k accesses to reach position 0, while v001's data showed that on a Zipfian trace single-swap convergence is too slow to protect mid-bucket items from eviction before they can reach the front. Capping at 3 rather than unbounded avoids reinstating the O(n) latency risk on long-distance promotions (rare on Zipfian) while allowing the 2–3 most common cases — items already adjacent to or one slot behind their natural resting position — to settle in a single access.
