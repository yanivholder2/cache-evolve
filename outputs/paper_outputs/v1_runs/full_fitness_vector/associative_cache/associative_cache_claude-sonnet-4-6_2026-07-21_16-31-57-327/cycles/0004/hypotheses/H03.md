# H03

Scanning the last two items in the bucket and evicting the one with the lower lfu_counter rather than always evicting the tail will improve hit rate by ensuring the chosen victim is the genuinely colder of the two tail candidates.

## Parent

cycle/0003/v003

## Changes

In `eviction_policy.rs`, modify `ClassicLRU::eviction_candidate_index` to compare the last two items and return the index with the lower `lfu_counter`:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    let len = items.len();
    if len < 2 {
        return 0;
    }
    // Pick the colder of the two tail candidates — O(1), one comparison.
    if items[len - 2].lfu_counter < items[len - 1].lfu_counter {
        len - 2
    } else {
        len - 1
    }
}
```

No changes to `get_from_position` (position-0 guard + single-swap LFU from v003 is preserved unchanged), `promotion_candidate_index` (stays `0`), or `item.rs` (32-byte aligned struct with `_pad: u64` is preserved).

The implementation is O(1): one integer comparison between two adjacent tail entries. Because v003's single-swap LFU ordering converges toward descending counter order, the penultimate item (index `len-2`) should only be chosen over the tail when the usual soft-ordering invariant was violated by a recent insertion — in practice the tail will still win most comparisons, so the change is low-cost and low-risk.

## Rationale

v003's eviction logic unconditionally targets position `len-1`. Under the soft LFU ordering the tail is usually the coldest item, but after a fresh insertion (which always appends at the tail with `lfu_counter = 0`) the new item IS the correct eviction candidate — but if the previous tail item also had a very low counter, the ordering guarantee does not distinguish them. A two-item minimum scan costs one comparison and zero extra swaps, targeting hit-rate on the eviction path rather than the promotion path (which H01 already addresses). The strategies are orthogonal and could be composed in a later cycle.
