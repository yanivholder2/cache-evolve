# H03

Restricting the write-once flag to items that are promoted all the way to position 0 — rather than any item on first touch — will concentrate second-chance protection on truly hot items (accessed multiple times) and allow once-accessed warm items to be reclaimed by the eviction scan, improving hit rate on Zipfian workloads where one-time accesses dominate cold keys.

## Parent

cycle/0006/v003

## Changes

Modify `ClassicLRU::get_from_position` in `src/shared/eviction_policy.rs`.

Starting from v003's overlay, move the flag write from its current location (before the swap loop, unconditional on position) to two specific sites where position 0 is reached: the early-return branch and the post-loop landing when `pos == 0`. Remove the pre-loop write entirely.

Before (v003):
```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;
    }
    // Write-once flag: 0 → 1 on first access only.
    if items[position].lfu_counter == 0 {
        items[position].lfu_counter = 1;
    }
    let mut pos = position;
    for _ in 0..3 {
        items.swap(pos, pos - 1);
        pos -= 1;
        if pos == 0 {
            break;
        }
    }
    pos
}
```

After (H03):
```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        // Already at head: flag on first arrival at position 0.
        if items[0].lfu_counter == 0 {
            items[0].lfu_counter = 1;
        }
        return 0;
    }
    // Promote up to 3 positions toward index 0. No flag write during transit.
    let mut pos = position;
    for _ in 0..3 {
        items.swap(pos, pos - 1);
        pos -= 1;
        if pos == 0 {
            break;
        }
    }
    // Flag only if this access landed the item at the head.
    if pos == 0 && items[0].lfu_counter == 0 {
        items[0].lfu_counter = 1;
    }
    pos
}
```

Leave `eviction_candidate_index` and `item.rs` unchanged from v003 (second-chance scan up to 8 items from the cold tail, 32-byte `#[repr(C)]` layout).

Invariants to preserve: the flag write is still guarded (`counter == 0` check), so it is written at most once per item lifetime. The 3-swap loop is identical to v003. Items that never reach position 0 retain `lfu_counter == 0` and remain eviction candidates; items that reach position 0 receive `lfu_counter = 1` and are thereafter protected by the second-chance scan. The `eviction_candidate_index` scan logic is unchanged.

## Rationale

In v003, the flag is set on the very first access regardless of how far the item travels (an item accessed once from position 7 reaches position 4 and earns counter==1 protection). Under 3-swap promotion with 8-slot buckets, an item must be accessed approximately three times to converge from position 7 to position 0. Items accessed only once or twice remain in the mid-to-cold zone (positions 1–6) with counter==1, consuming protection capacity that could be reserved for hotter keys. Gating the flag on reaching position 0 introduces a natural frequency threshold — items that recur often enough to reach the head earn eviction immunity; items that are accessed once or twice remain eligible. The second-chance scan then becomes a frequency filter rather than a recency filter, which may align better with the Zipfian access distribution where a small set of keys accounts for most hits.
