# H01

Replacing ClassicLRU's position-based eviction with frequency-counting (LFU) semantics raises hit rate on the LIRS workload-a trace by protecting heavily-reused items from displacement by cold one-time accesses.

## Parent

baseline

## Changes

Edit `src/shared/eviction_policy.rs`. Keep the `ClassicLRU` struct name unchanged (the JNI ordinal 0 dispatches to it via `EvictionPolicyKind::ClassicLRU.build()`); change only its `EvictionPolicy` implementation:

1. `get_from_position`: Replace the `Vec::remove`/`push` shuffle with an in-place frequency bump —
   `items[position].lfu_counter += 1;` — and return `position` unchanged. No vector reordering.

2. `eviction_candidate_index`: Replace the hard-coded `0` with a linear scan that finds the item
   with the minimum `lfu_counter`:
   ```rust
   items.iter().enumerate()
       .min_by_key(|(_, item)| item.lfu_counter)
       .expect("eviction_candidate_index precondition: non-empty")
       .0
   ```

3. `promotion_candidate_index`: Mirror the above with `max_by_key` on `lfu_counter`:
   ```rust
   items.iter().enumerate()
       .max_by_key(|(_, item)| item.lfu_counter)
       .expect("promotion_candidate_index precondition: non-empty")
       .0
   ```

The `lfu_counter` field already exists on `Item` (initialised to 0 in `Item::new`), so no changes
are needed outside `eviction_policy.rs`. All other eviction policy variants (`TimestampLRU`,
`Lifo`, `Lfu`, `Fifo`, `Swap`) stay untouched. Preserve the `EvictionPolicyKind` enum, its
`all()` array, ordinal assignments, and the `build()` match — only the `ClassicLRU` struct's
`impl EvictionPolicy` body changes.

## Rationale

The baseline uses position-order to track recency: the head of the Vec is LRU, the tail is MRU.
On LIRS workload-a — a trace designed to stress recency-only policies — a burst of distinct cold
accesses can push 16 different items through a narrow bucket and displace items that were
accessed many times before the burst. LFU's frequency counter is immune to such cold bursts: an
item needs zero prior accesses to be evicted, not one unlucky position in a short queue. The
`Item.lfu_counter` field is already allocated in every item (contributing to the 40-byte baseline
metadata cost) but unused by ClassicLRU, so this change adds benefit with zero additional memory
cost.
