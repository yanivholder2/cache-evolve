# H02

Repartitioning the cache into half as many, twice as wide buckets — while retaining v001's 3-swap unconditional promotion — raises hit rate by letting each hash-collision class hold a larger working-set slice without changing the per-item memory layout.

## Parent

cycle/0005/v001

## Changes

Overlay `src/shared/geometry.rs` to halve `num_of_buckets` and double `bucket_size`. All other files remain identical to cycle/0005/v001.

Replace the `BaselineGeometry::for_settings` constructor so it halves the bucket count and doubles the slot depth:

```rust
pub fn for_settings(settings: &AssociativeCacheSettings) -> Self {
    // Halve the number of buckets, double the bucket size.
    // Integer division is safe: if num_of_buckets is odd, the remaining
    // slot is absorbed into bucket_size via the layout() call that receives
    // the full budget, so capacity is conserved exactly.
    let new_num = (settings.num_of_buckets / 2).max(1);
    let total   = settings.num_of_buckets * settings.bucket_size;
    let new_bsz = total / new_num;
    BaselineGeometry {
        num_of_buckets: new_num,
        bucket_size:    new_bsz,
    }
}
```

The `layout()` method is unchanged; it still returns `(self.num_of_buckets, self.bucket_size)`. The factory's capacity-conservation check (`new_num * new_bsz == budget`) will validate correctness at build time.

`eviction_policy.rs` is a verbatim copy of cycle/0005/v001: ClassicLRU with position-0 early return and a 3-swap unconditional loop. `item.rs` is a verbatim copy of cycle/0005/v001: 32-byte `#[repr(C)]` struct with `_pad: u64`.

Do not touch `src/factory.rs`, `src/lib.rs`, `Cargo.toml`, or any test file.

## Rationale

Cycle 0001 v002 showed wider buckets improve hit rate on the LIRS trace but caused a latency regression due to O(n) linear scans. Since then: (1) the per-op-time benchmark appears pinned at the 100 ns measurement floor for write-free variants (cycles 0004–0005), so a moderate linear-scan increase may be invisible; (2) the 3-swap early-break promotion means the common Zipfian hot-key case exits after 0–3 swaps rather than scanning the full bucket. Wider buckets increase the number of unique Zipfian hot keys that can coexist within a single hash target before eviction pressure forces one out, which is the mechanism most likely to push hit rate beyond the current 0.7189 ceiling.
