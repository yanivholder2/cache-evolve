# H01

Applying LRU ordering to the warm-all fallback case in `eviction_candidate_index` — returning `len - scan_depth` instead of `len - 1` — improves hit rate by evicting the oldest warm item rather than the newest when no unaccessed cold candidate exists.

## Parent

cycle/0008/v003

## Changes

In `src/shared/eviction_policy.rs`, `ClassicLRU::eviction_candidate_index`, change only the final fallback return value.

Current code (after the forward scan finds no `lfu_counter == 0` item):
```rust
// All scanned items have been accessed: fall back to the LRU tail.
len - 1
```

Change to:
```rust
// All scanned items have been accessed: fall back to the oldest item in the
// cold window (inner edge), applying LRU-among-warm ordering.
len - scan_depth
```

The scan loop itself (`for i in len - scan_depth..len { if items[i].lfu_counter == 0 { return i; } }`) is unchanged. `scan_depth` is already computed as `len.min(8)` before the loop — reuse it for the fallback index.

**Rationale**: The primary scan already uses LRU-among-cold semantics confirmed in cycle 0008: it scans inner-edge-first (`len-8..len`) and returns the oldest (inner-most) never-accessed item. When all scanned items are warm (the fallback path), the current code selects `len - 1` — the *newest* item in the cold zone (LIFO-among-warm). Changing to `len - scan_depth` selects the *oldest* item in the cold zone (LRU-among-warm), applying the same LRU principle uniformly to both paths. An item at the inner edge of the cold window (`len - scan_depth`) has survived in the cold zone longer without receiving a hit; it is a better eviction candidate than the most recently inserted item at `len - 1`.

No other changes. `get_from_position`, the flag write logic, scan depth, and scan direction are unmodified. `item.rs` is unchanged.
