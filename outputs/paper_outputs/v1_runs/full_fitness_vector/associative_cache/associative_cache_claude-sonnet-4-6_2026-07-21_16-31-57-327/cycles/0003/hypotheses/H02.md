# H02

Splitting each bucket into a cold zone and a hot zone so that re-hits on already-hot items require no memory movement will improve hit rate over pure LRU while making the hot-item get path O(1).

## Parent

baseline

## Changes

In `src/shared/eviction_policy.rs`, replace the body of `ClassicLRU::get_from_position` with a two-zone promotion rule:

```
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    let hot_threshold = items.len() / 2;
    if position >= hot_threshold {
        // Already in hot zone (tail half): no move, O(1)
        position
    } else {
        // In cold zone (head half): promote to MRU tail
        let item = items.remove(position);
        items.push(item);
        items.len() - 1
    }
}
```

Leave `eviction_candidate_index` returning `0` (head, the coldest item) and `promotion_candidate_index` returning `items.len() - 1` unchanged.

No changes to `item.rs` — `lfu_counter` and `timestamp` fields are untouched (the counter is simply not written).

The semantics: the bucket tail half is the "protected" hot zone; the head half is the "probation" cold zone. A cold-zone hit triggers a `Vec::remove + Vec::push` (same cost as baseline LRU). A hot-zone hit is a no-op (O(1)). Eviction always removes from the head (coldest probation item), so probation items are naturally evicted before any protected item. An item must be hit while in the cold zone to reach the hot zone, approximating the 2Q requirement that an item be accessed at least once after initial insertion before it earns protection.

## Rationale

Baseline ClassicLRU's `Vec::remove + Vec::push` on every hit achieves 69 ns get-p50 because hot items sit at the tail: `remove(len-1)` = O(1), `push` = O(1). But every hit — even a re-hit of the hottest item — does two memory operations. The hot-zone bypass eliminates those two operations for already-protected items entirely. Meanwhile, 2Q semantics improve hit-rate over pure LRU on Zipfian traces by shielding frequently-accessed items from one-time scan eviction. This is a completely new eviction policy not tried in prior cycles.
