# H01

Replacing strict LRU with a two-queue policy (probationary FIFO + protected LRU) will improve hit-rate on workload-a by shielding confirmed-hot items from one-time-access evictions.

## Parent

baseline

## Changes

Restructure `LruCache<K, V>` in `src/lru_cache/mod.rs` to maintain two independent doubly-linked chains through the same node arena:

**Node changes:**
Add a `protected: bool` field to `Node<K, V>` to record which queue each node belongs to (false = probationary, true = protected).

**LruCache fields:** Replace the single `head`/`tail` pair with:
- `prob_head: Option<usize>`, `prob_tail: Option<usize>`, `prob_len: usize` — the probationary FIFO queue
- `prot_head: Option<usize>`, `prot_tail: Option<usize>`, `prot_len: usize` — the protected LRU queue
- `prob_cap: usize` — computed in `try_new` as `(capacity / 4).max(1)`; the protected queue fills the remaining `capacity - prob_cap` slots

**`put` (new key):**
1. Evict if needed (see eviction order below) to make room.
2. Insert the new node at the probationary tail with `protected = false`.
3. Increment `prob_len`.

**Eviction order:** When a slot must be freed, evict from the probationary head first (FIFO). If `prob_len == 0`, fall back to the protected head (LRU of protected). Remove the evicted key from `map` and decrement the corresponding `*_len`.

**`get` (hit in probationary):**
Unlink from the probationary chain, decrement `prob_len`. Attach to the protected tail, set `protected = true`, increment `prot_len`. If `prot_len` now exceeds `capacity - prob_cap`, demote the protected head back to the probationary tail (set `protected = false`, adjust `prot_len`/`prob_len`) — this keeps the two queues within their budgets.

**`get` (hit in protected):**
Standard LRU promotion: unlink and push to protected tail (no queue change, no len change).

**`put` (existing key):**
Behave as a get-then-update: promote according to the existing node's queue, then overwrite the value in place.

Keep `try_new`/`new`, the `Cache<K, V>` trait impl, and the `unlink`/`push_back` helpers; extract `push_back_prob` and `push_back_prot` variants that append to the respective queue tail, or re-use a single helper parameterised by which head/tail pair to update.

Preserve all three invariants: capacity_bound (total nodes ≤ capacity), value_fidelity, no_phantom_items.
