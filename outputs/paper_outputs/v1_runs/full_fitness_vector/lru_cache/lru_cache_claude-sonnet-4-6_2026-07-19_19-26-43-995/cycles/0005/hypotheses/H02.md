# H02

Moving the `prev` and `next` link fields out of `Node<K, V>` into a dedicated `Vec<Link>` shrinks `Node<u64,u64>` from 24 to 16 bytes and raises link-array density from ~2.67 nodes per 64-byte cache line to 8 link pairs per cache line, targeting a metadata-size win and reduced cache-miss cost on the linked-list traversal paths without adding any per-op branch.

## Parent

cycle/0002/v001

## Changes

Start from the exact `src/lru_cache/mod.rs` of cycle/0002/v001 and apply the following structural changes; all sentinel constants, policy logic, and public API remain identical.

**1. Add a plain `Link` struct to hold per-slot link metadata.**

Add before `Node<K, V>`:
```rust
/// Per-slot doubly-linked-list pointers, stored separately from key/value data.
/// 8 bytes each; 8 entries fit in a 64-byte cache line.
#[derive(Debug)]
struct Link {
    /// bit 31 = PROT_BIT; bits 0-30 = prev index (or NULL = 0x7FFF_FFFF)
    prev: u32,
    next: u32,
}
```

**2. Remove `prev` and `next` from `Node<K, V>`.**

Change:
```rust
pub struct Node<K, V> {
    key: K,
    value: V,
    prev: u32,
    next: u32,
}
```
To:
```rust
pub struct Node<K, V> {
    key: K,
    value: V,
}
```
`size_of::<Node<u64, u64>>()` becomes 16 bytes (two 8-byte fields).

**3. Add `links: Vec<Link>` to `LruCache<K, V>`.**

In the `LruCache<K, V>` struct, add one new field:
```rust
links: Vec<Link>,   // parallel to nodes; links[i] holds prev/next for nodes[i]
```
Place it directly after `nodes: Vec<Node<K, V>>` for readability.

**4. Initialize `links` in `try_new`.**

In the `Some(Self { ... })` block, add:
```rust
links: Vec::with_capacity(capacity),
```
alongside the existing `nodes: Vec::with_capacity(capacity)`.

**5. Grow `links` in lockstep with `nodes` in `put()`.**

In the "Arena has room" branch of `put()`, change:
```rust
self.nodes.push(Node {
    key: key.clone(),
    value,
    prev: NULL,
    next: NULL,
});
```
To:
```rust
self.nodes.push(Node {
    key: key.clone(),
    value,
});
self.links.push(Link { prev: NULL, next: NULL });
```
`evict_one()` reuses an existing slot; `unlink()` (step 6) already resets `links[slot]` to NULL/NULL, so no additional reset is needed there.

**6. Replace all `self.nodes[idx].prev` / `self.nodes[idx].next` with `self.links[idx].prev` / `self.links[idx].next` in every internal method.**

The affected methods and the substitution pattern:

- **`promote()`**: `let raw_prev = self.nodes[idx].prev;` → `let raw_prev = self.links[idx].prev;`
- **`unlink()`**:
  - `let raw_prev = self.nodes[idx].prev;` → `self.links[idx].prev`
  - `let next = self.nodes[idx].next;` → `self.links[idx].next`
  - `self.nodes[prev_idx as usize].next = next;` → `self.links[prev_idx as usize].next = next;`
  - `self.nodes[next as usize].prev = ...` → `self.links[next as usize].prev = ...`
  - `self.nodes[idx].prev = NULL;` → `self.links[idx].prev = NULL;`
  - `self.nodes[idx].next = NULL;` → `self.links[idx].next = NULL;`
- **`push_back_prob()`**:
  - `self.nodes[idx].prev = self.prob_tail;` → `self.links[idx].prev = self.prob_tail;`
  - `self.nodes[idx].next = NULL;` → `self.links[idx].next = NULL;`
  - `self.nodes[self.prob_tail as usize].next = idx32;` → `self.links[self.prob_tail as usize].next = idx32;`
- **`push_back_prot()`**: same substitution pattern as `push_back_prob`.

**7. Leave all key/value access unchanged.** References to `self.nodes[h].key` (in `evict_one` and `put`), `self.nodes[idx].value` (in `get`), and `self.nodes[slot].key = key.clone(); self.nodes[slot].value = value;` (slot reuse in `put`) remain exactly as they are — they now address only the key and value fields of the 16-byte `Node<K, V>`.

**Invariants to preserve:**
- `links.len() == nodes.len()` at all times.
- `links[i].prev` and `links[i].next` carry the same PROT_BIT and IDX_MASK semantics as `nodes[i].prev` and `nodes[i].next` did before the split.
- The NULL sentinel (0x7FFF_FFFF), PROT_BIT (0x8000_0000), and IDX_MASK (0x7FFF_FFFF) constants are unchanged.

## Rationale

The 24-byte `Node<K, V>` means ~2.67 nodes share a 64-byte cache line; node `i` where `i mod 3 == 2` has its `prev` and `next` fields straddling a cache-line boundary, requiring a second cache-line load for the link traversal in `unlink`. The 8-byte `Link` struct packs 8 entries per cache line with perfect alignment; no link pair ever crosses a boundary. For a 2048-entry cache, the link array occupies 16 KB — within L1 cache — while the key/value `nodes` array occupies 32 KB. This replaces one 48 KB hot-path structure with a 16 KB structure that fits in L1, and a separate 32 KB structure that is only accessed when the actual value is needed. No policy logic changes, no extra branches.
