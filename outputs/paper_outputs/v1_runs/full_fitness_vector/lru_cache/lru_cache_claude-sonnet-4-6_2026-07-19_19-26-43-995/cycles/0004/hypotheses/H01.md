# H01

Dynamically adjusting the protected-queue quota in response to observed demotion pressure will capture the hit-rate benefit of a larger protected budget without permanently inflating the per-op-time cost seen in cycle/0003/v002.

## Parent

cycle/0002/v001

## Changes

Add two counter fields to `LruCache` (no change to `Node<K,V>`):

```rust
demotion_count: u32,  // demotions from protected → probationary since last adaptation
op_count: u32,        // get + put calls since last adaptation
```

Initialise both to `0` in `try_new`.

Add a new `#[inline] fn maybe_adapt(&mut self)` method called at the **top** of both `get()` and `put()` (before any other logic). The method increments `self.op_count` and, when `op_count` reaches `self.capacity.max(512) as u32`, evaluates the adaptation:

- If `demotion_count > (self.capacity / 16).max(1) as u32`:
  protected is under-provisioned → shrink `prob_cap` by 1, clamped to a floor of `(self.capacity / 8).max(1)`.
- Else if `demotion_count == 0`:
  no demotion pressure → grow `prob_cap` by 1, clamped to a ceiling of `(self.capacity / 4).max(1)`.
- Reset `self.op_count = 0; self.demotion_count = 0`.

In `promote()`, in the probationary-graduation branch, **after** the demotion block fires (`prot_len > prot_cap`), increment `self.demotion_count`.

All invariants, list structure, and the `Node<K,V>` layout (24 bytes, unchanged) must be preserved. The adaptation logic should be a pure side effect on the two counter fields and `prob_cap`; it must not touch `nodes`, the linked lists, or `map`.

## Rationale

cycle/0003/v002 achieved the highest hit-rate ever recorded (0.729) by fixing `prob_cap` at `capacity / 8`, but this permanently enlarged the protected path, raising per-op-time. The global winner cycle/0002/v001 uses `prob_cap = capacity / 4` and sits exactly at per-op-time = 0. Adaptive sizing should track the working-set size and drift the quota toward the most favourable point for the current phase, recovering hit-rate when demotion pressure is high without paying the steady-state cost of a permanently small `prob_cap`.
