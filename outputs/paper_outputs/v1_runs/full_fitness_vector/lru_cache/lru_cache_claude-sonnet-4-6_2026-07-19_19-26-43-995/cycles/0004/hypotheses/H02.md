# H02

Replacing the unconditional unlink-and-relink on every protected hit with a lazy referenced-bit and a bounded CLOCK-style sweep during demotion will reduce per-op-time on protected-heavy paths while preserving or improving hit-rate through second-chance semantics.

## Parent

cycle/0002/v001

## Changes

**Step 1 — add a compact referenced bitmap to `LruCache`** (does not affect `Node<K,V>`):

```rust
ref_bits: Vec<u8>,  // bit i covers arena slot i; bit = 1 means "referenced since last sweep"
```

Initialise to `Vec::new()` in `try_new`. Grow in sync with the arena: in the `put()` path that allocates a new node (the `else` branch at `let new_idx = self.nodes.len()`), after `self.nodes.push(...)`, extend `ref_bits` to cover the new slot:

```rust
if self.nodes.len() > self.ref_bits.len() * 8 {
    self.ref_bits.push(0u8);
}
```

Add three private helpers:

```rust
#[inline] fn set_ref(&mut self, idx: usize)   { self.ref_bits[idx >> 3] |= 1 << (idx & 7); }
#[inline] fn clear_ref(&mut self, idx: usize) { self.ref_bits[idx >> 3] &= !(1u8 << (idx & 7)); }
#[inline] fn test_ref(&self,  idx: usize) -> bool {
    (self.ref_bits[idx >> 3] >> (idx & 7)) & 1 != 0
}
```

**Step 2 — lazy promotion on protected hits.**

In `promote()`, in the `if protected { … }` branch, replace:

```rust
self.unlink(idx);
self.push_back_prot(idx);
```

with:

```rust
self.set_ref(idx);
return;
```

The node stays at its current position in the protected queue; only a bit flip is written.

**Step 3 — bounded CLOCK sweep during demotion.**

In `promote()`, in the probationary-graduation branch, replace the single-step demotion of `prot_head` with a bounded scan (limit = 8 iterations). Replace:

```rust
let h = (self.prot_head & IDX_MASK) as usize;
self.unlink(h);
self.prot_len -= 1;
self.push_back_prob(h);
self.prob_len += 1;
```

with:

```rust
let mut scan = 8usize;
loop {
    let h = (self.prot_head & IDX_MASK) as usize;
    if scan == 0 || !self.test_ref(h) {
        // First unreferenced node (or scan budget exhausted): demote it.
        self.clear_ref(h);
        self.unlink(h);
        self.prot_len -= 1;
        self.push_back_prob(h);
        self.prob_len += 1;
        break;
    }
    // Referenced: give it a second chance by moving to the MRU end of protected.
    self.clear_ref(h);
    self.unlink(h);
    self.push_back_prot(h);
    scan -= 1;
}
```

**Step 4 — clear referenced bits on eviction.**

In `evict_one()`, after computing `h` in each branch, call `self.clear_ref(h)` before `self.unlink(h)` (defensive; the bit should already be clear for probationary nodes, but protected nodes evicted via the fallback path may still have it set).

No changes to `Node<K,V>`, `IDX_MASK`, `NULL`, `PROT_BIT`, or the probationary-path logic.

## Rationale

The cycle-0003 cycle insight identified that the MRU-tail guard fails because it fires only for the exact tail node. This variant avoids the same trap: by recording "was accessed" with a single bit-or (no pointer chasing) and only doing physical relinking during the rare demotion event, the per-operation cost on protected hits drops from two pointer writes to one bit-or. The bounded CLOCK sweep (max 8 iterations, each moving a referenced node to MRU) additionally grants a second eviction chance to recently accessed protected items, which can lift hit-rate on Zipfian traces where a small hot set is accessed far more often than the tail. The scan cost is amortised: it only runs when a probationary hit forces a demotion, not on every get.
