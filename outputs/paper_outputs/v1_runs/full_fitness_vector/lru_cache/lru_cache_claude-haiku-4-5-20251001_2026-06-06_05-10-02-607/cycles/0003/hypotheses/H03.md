# H03

Adaptive frequency bucketing: activate V002's bucket mechanism only under high cache saturation to avoid paying normal-case overhead during underutilized phases.

## Parent

cycle/0002/v002

## Changes

V002 always maintains frequency buckets, paying the pointer-chasing overhead (get p99 +120%, put p50 +11%) even on underutilized caches where simpler V001-style eviction would suffice. Implement adaptive bucketing that transitions between two modes based on cache saturation and hit-rate health: (1) Default mode (saturation < 75%): Use bounded-window eviction like V001 (scan min(capacity/4, 256) nodes, prefer low frequency) to avoid bucket overhead when cache has breathing room. (2) High-saturation mode (saturation ≥ 75% or observed hit rate < 0.65): Activate full frequency bucket indexing to improve hit rate when the cache is under pressure. Add saturation monitoring (nodes.len() / capacity) and a hit-rate tracker (recent-window rolling average). When transitioning into high-saturation mode, rebuild frequency buckets from the current node set; when dropping below threshold, simplify bucket state. This strategy preserves V001's latency efficiency on underutilized workloads while leveraging V002's hit-rate strength when most needed.

Modify LruCache to add a `saturation_threshold` field (default 0.75), a `hit_rate_threshold` field (default 0.65), a `recent_hits` and `recent_accesses` counter for hit-rate estimation, and a `bucketing_enabled` flag. In put() and get(), check saturation and conditionally route through bucket-aware or bounded-search code paths. Implement mode-transition logic to rebuild/simplify bucket structures when crossing thresholds.
