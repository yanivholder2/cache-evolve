# H01

Optimize frequency bucket structure cache locality to reduce pointer-chasing overhead during hot-path bucket scans, lowering per-op latency while preserving O(1) eviction indexing.

## Parent

cycle/0003/v003

## Changes

Restructure the frequency bucket representation to pack bucket-node pointers and metadata into cache-line-aligned clusters. Instead of separate per-node bucket pointers scattered across the node arena, organize bucket chains using a dedicated compact bucket-header array where each bucket entry stores the first 2-3 node indices inline before spilling to overflow pointers. This reduces memory indirection during the bounded-window bucket scan at eviction time: the common case (first few candidates per bucket) hits in a compact structure with no additional pointer dereference, while overflow chains remain available for rare high-frequency nodes. The invariant: eviction candidate selection remains O(1) within the bounded window; only the cache locality of bucket traversal improves.

## Rationale

Cycle 0009 V002 demonstrated that removing frequency bucketing entirely yields a 53% get p99 improvement by eliminating pointer-chasing, but causes a catastrophic 215% put p99 regression due to loss of O(1) eviction indexing. This indicates the bottleneck is memory indirection on the hot path, not the bucketing algorithm. Packing bucket structures to reduce cache misses during the eviction scan addresses this without sacrificing the critical O(1) property that Cycles 0002–0009 show is non-eliminable.
