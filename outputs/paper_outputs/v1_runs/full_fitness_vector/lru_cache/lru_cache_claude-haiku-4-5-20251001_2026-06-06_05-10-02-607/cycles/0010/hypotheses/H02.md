# H02

Replace per-operation frequency counters with reduced-precision (2-4 bit) quantized frequency representation, lowering per-node metadata overhead and memory pressure while maintaining sufficient selectivity for hit rate.

## Parent

cycle/0004/v002

## Changes

Modify the Node structure to store frequency as a 2-bit or 3-bit quantized level instead of a full u64 counter. Map actual access counts to coarse buckets: 0 (never accessed), 1-2 (cold), 3-15 (warm), 16+ (hot). Update bucket indexing to compute bucket position from the quantized level (2-4 possible levels instead of 64), reducing per-node metadata from 8 bytes to 1-2 bits. On hot-path operations, increment a local counter in the Node without atomic operations; only quantize and update the bucket pointer during eviction or when the counter saturates. This preserves the O(1) eviction structure while reducing cache-line footprint, allowing more nodes to fit in L1/L2 during candidate scanning.

## Rationale

Cycles 0003–0009 confirm that hit rate plateaus at 0.66–0.69 regardless of frequency precision, indicating that fine-grained frequency (64 levels) provides no selectivity advantage over coarse quantization. Reducing precision from 64 to 4 levels cuts per-node frequency metadata by 75%, directly reducing arena memory pressure and cache misses during eviction scans. The bounded-window baseline already limits selectivity to within a small window; coarser quantization within that window preserves the bounded-window hit-rate property while improving memory efficiency.
