# H01

Reduce adaptive bucketing metadata overhead via lazy bucket allocation to improve metadata-size without sacrificing latency gains.

## Parent

cycle/0003/v003

## Changes

Cycle 0003's adaptive bucketing currently maintains both bucket pointers and simple-mode state simultaneously, carrying a permanent 72-byte metadata tax even on underutilized caches that never transition to high-saturation mode. Implement lazy bucket initialization to eliminate this overhead:

1. Remove pre-allocated bucket vectors (bucket_lists, min_freq, etc.) from the LruCache struct initialization.
2. Store bucket-related pointers as Option<Box<BucketState>> initialized to None.
3. When saturation ≥ 75% or hit-rate drops below threshold, allocate the BucketState struct on demand (containing all bucket vectors and their management fields).
4. When transitioning out of high-saturation mode (saturation < 60%), deallocate the BucketState and drop it back to None.
5. Keep all mode-detection logic, saturation tracking, and bucketing algorithms identical to v003; only defer the allocation of bucket infrastructure until needed.

This trades a one-time allocation overhead (when transitioning into high saturation) for eliminating the per-cache memory tax of 40-50 bytes (removing unused bucket vector allocations), reducing metadata footprint on underutilized caches while preserving v003's latency improvements on saturation-prone workloads.

## Rationale

The cross-cycle insights identify that "Metadata overhead taxes all caches, utilized or not." V003's 72-byte LruCache overhead applies uniformly, even though the tested workload never saturates enough to activate bucketing. Lazy allocation preserves the latency benefits for workloads that DO saturate while eliminating the memory cost for those that don't, improving the fitness trade-off without sacrificing existing wins.
