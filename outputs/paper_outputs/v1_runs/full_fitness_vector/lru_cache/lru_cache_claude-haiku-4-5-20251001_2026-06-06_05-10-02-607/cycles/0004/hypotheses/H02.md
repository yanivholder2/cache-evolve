# H02

Defer frequency bucket promotion operations from the get fast path to eviction time to reduce get p99 pointer-chasing overhead.

## Parent

cycle/0002/v002

## Changes

Modify the get() fast path to queue frequency updates instead of executing them immediately:

1. Replace the immediate `update_node_frequency()` call in `get()` with a queue operation: append the node index and key to a `pending_promotions` vector.
2. Execute the queued frequency bucket updates (unlinking, relinking, min_freq tracking) immediately before `find_evictable_node()` is called in `put()`, ensuring that eviction decisions see accurate frequency information without adding pointer-chasing overhead to the hot get path.
3. Flush any remaining pending promotions at the start of `put()` when the arena is full (before eviction), ensuring correctness.
4. Keep the frequency bucket index structure, eviction selection logic, and frequency decay mechanism unchanged.

This defers the expensive node unlinking/relinking work from the frequent get() calls to the less-frequent put() calls at eviction boundaries, reducing get p99 latency while preserving frequency-aware eviction accuracy.
