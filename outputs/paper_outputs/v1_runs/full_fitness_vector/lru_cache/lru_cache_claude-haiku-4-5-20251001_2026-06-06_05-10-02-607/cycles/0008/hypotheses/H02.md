# H02

Eliminate frequency-tracking overhead while achieving balanced tail-latency improvements by combining FIFO eviction with a larger window and deferred-promotion batched queue-flush, testing whether batching benefits generalize independent of frequency tracking.

## Parent

baseline

## Changes

Implement a baseline variant using pure FIFO eviction with an adaptive window size (min(capacity/2, 512) from cycle/0007/v002) to maintain hit rate without frequency metadata overhead. Incorporate the deferred-promotion queue-flush mechanism with two-batch swap strategy from cycle/0007/v001, including 16-item batch processing and swap-on-full logic, but operating on FIFO candidates instead of frequency-bucketed candidates. This isolates the batching and queue-flush algorithmic improvements from frequency tracking, testing whether cycle/0007/v001's p99 gains (42-50%) hold in a simpler eviction context. Measure whether removing per-item frequency counters and bucketing infrastructure while retaining batched queue-flush achieves comparable latency improvements with reduced metadata overhead (48 bytes vs. 56 bytes).

## Rationale

Cycle/0007/v001 demonstrated that batched queue-flush can achieve simultaneous p99 improvements for both get and put operations, breaking the operation-shifting trade-off. However, this breakthrough was achieved within a frequency-tracked context (cycle/0003/v003's bucketing baseline). Cycle/0007/v002 separately validated that FIFO with a larger window maintains hit rate (0.6904) while eliminating frequency metadata, but showed only marginal latency improvements. This hypothesis tests whether the algorithmic improvement (batched queue-flush) transfers to simpler eviction strategies, decoupling batching benefits from frequency-tracking infrastructure. If successful, this would indicate that the bottleneck V001 optimized (queue-flush overhead) is orthogonal to the eviction-selection mechanism.
