## Changes

All cycles have maintained near-constant hit rate (0.6904, 0.6652) regardless of eviction selection strategy sophistication (frequency bucketing, operation-count tracking, etc.), while selective eviction consistently adds latency overhead via per-operation counter increments, search operations, or tracking fields. Test the hypothesis that workload's Zipfian skew is captured sufficiently by a larger window size, eliminating the need for frequency awareness:

1. Remove all per-item frequency/counter tracking logic and fields from Node<K,V>.
2. Implement a larger bounded-window FIFO eviction: instead of scanning min(capacity/4, 256) items, scan min(capacity/2, 512) items using strict FIFO order (oldest first within the window).
3. Preserve the bounded-window sequential scan structure and latency predictability from Cycle 0002 v001, but eliminate the eviction-selection logic entirely—simply evict the first item in the expanded window without any frequency/recency comparison.
4. Measure hit rate and per-op-time on the standard workload. If hit rate matches baseline's 0.6652 or baseline-era results (0.6904), the complexity of frequency tracking is unjustified.
5. If hit rate degrades significantly, incrementally increase window size (capacity/2 → capacity/3 → capacity) until hit rate stabilizes.

This removes per-operation frequency-tracking overhead (counter increments) and reduces metadata overhead by eliminating frequency/count fields, targeting a latency baseline against which more sophisticated strategies can be measured.

## Rationale

Cross-cycle analysis shows that every selective-eviction strategy adds latency without proportional hit-rate gain (Cycles 0002–0006: hit rate stable despite frequency bucketing, operation-count tracking, saturation-aware activation). The cross-cycle open question asks: "Does hit rate actually plateau on this workload, or is selective eviction already near-optimal?" and "Should fundamentally different eviction families be explored?" This hypothesis answers by testing whether FIFO with a larger window—the simplest possible strategy—is sufficient. If hit rate is window-size-dependent rather than eviction-strategy-dependent, selective logic is overhead. If hit rate remains constant, the Zipfian hot-set is already captured by window size alone, and frequency tracking is unjustified complexity. This directly tests the claim that "hit-rate improvement ceiling has been reached by bounded-window baseline."
