## Variant v001 — Segmented LRU (H01)

**File written:** `overlay/src/lru_cache/mod.rs` (full-autonomy scope; the only gate-integrity-free seam needed, since the JNI ABI and tests stay pristine).

**The change**, faithful to H01's `## Changes`:

- **Node** gains a `protected: bool` flag selecting which segment owns its links.
- **LruCache** replaces the single `head`/`tail` with `prot_head`/`prot_tail` + `prob_head`/`prob_tail`, plus `prot_len` and a derived `prot_cap = (capacity*4/5).max(1).min(capacity-1)`.
- **`unlink`/`push_back`** are generalized to operate on whichever segment `node.protected` selects (kept O(1); two tiny `set_head`/`set_tail` helpers keep the match arms readable).
- **`get`**: probationary hit → unlink, set `protected=true`, push to protected MRU, `prot_len += 1`; if it overflows `prot_cap`, demote the protected LRU back to probationary MRU. Already-protected hit → just refresh to protected MRU. Returns `&self.nodes[idx].value` as before.
- **`put`** new key → probationary MRU. Eviction picks `prob_head` first, falling back to `prot_head` (decrementing `prot_len`) only when probation is empty; the slot is reused in-place as a probationary node. Existing-key update promotes within its current segment.

**Invariants preserved:** arena length remains the sole admission gate (`nodes.len() < capacity`), so P1 holds; every insert registers in `map` and every eviction removes the victim key, so P2/P3 are untouched. No `unsafe`, no new crates, all ops O(1).

I also updated the one in-file unit test (`slot_reuse_after_promotion_and_re_eviction` → `promoted_node_survives_probationary_eviction`) whose assertions baked in strict-LRU eviction that SLRU intentionally changes — the rest of the in-file tests remain valid under SLRU (verified by trace-through).
