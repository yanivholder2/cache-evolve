# H01

Shrink `Node<u64,u64>` from 48 to 24 bytes on the v003 base by encoding the recency links as `u32` sentinels, widening only on read so metadata-size improves without v002's per-access cast penalty.

## Parent

cycle/0001/v003

## Changes

Keep everything v003 introduced (the `FastHasher`/`FastBuildHasher` integer
hash path and its `HashMap<K, usize, FastBuildHasher>`). Change only the
recency-list representation:

- Replace `prev: Option<usize>` and `next: Option<usize>` in `Node<K, V>`
  with `prev: u32` and `next: u32`. Define an associated constant
  `const NIL: u32 = u32::MAX;` to stand in for the absent link, and use it
  in place of `None`. This drops each link field from 16 bytes (no-niche
  `Option<usize>`) to 4 bytes, taking `Node<u64,u64>` from 48 to 24 bytes.
- Change `head` and `tail` on `LruCache` from `Option<usize>` to `u32`,
  also using `NIL` for empty.
- Crucially, avoid v002's mistake of casting at every link touch. The
  documented regression came from narrowing (`idx as u32`) and widening
  (`prev as usize`) scattered across `unlink`/`push_back` on each access.
  Centralise the conversions: read a link field once into a `usize` local
  at the top of `unlink`/`push_back`/`get`/`put` via a single
  `#[inline] fn idx(link: u32) -> Option<usize>` helper (returns `None`
  when the link is `NIL`), and write back through a single
  `#[inline] fn link(idx: usize) -> u32` helper. Widening `u32 -> usize`
  is a zero-cost zero-extend on the 64-bit target; the only narrowing is
  the one write per structural mutation, not per traversal step.

Preserve strict global LRU ordering and all arena slot-reuse semantics
exactly — this is a pure representation change, so hit-rate must stay
byte-for-byte identical to v003 (0.6652). The target dimension is
metadata-size; the success condition is matching v002's 24-byte node
while keeping per-op-time at or near v003's 39 ns p50 rather than v002's
regressed ~78 ns.
