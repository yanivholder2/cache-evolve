# H01

Replacing per-hit link surgery in the protected segment with a single CLOCK reference-bit set, reconciled by a bounded sweep only on overflow demotion, lowers get per-op-time while preserving the champion's hit-rate and 24-byte node.

## Parent

cycle/0006/v003

## Changes

Target the one named, never-directly-attacked hot-path cost from the
cross-cycle insights: link surgery and cache-line traversal during
promote/demote. Today every *protected but non-MRU* hit in `get()` pays a
full `unlink(idx)` + `push_back(idx)` (writes across three nodes); only
the exact-MRU case is short-circuited. Generalize that short-circuit into
a CLOCK reference bit so *all* protected hits become a single in-place
write.

Concrete diff against the parent's `src/lru_cache/mod.rs`:

- Steal a reference bit from the high bit of `next` (the `next` word
  never carries a flag today). Mirror the existing `PROT_MASK`/`prev`
  machinery: add `REF_MASK: u32 = 1 << 31`, add `referenced()`,
  `set_referenced(bool)`, and make `next_link()`/`set_next_link()` mask
  `REF_MASK` off exactly as `prev_link()`/`set_prev_link()` mask
  `PROT_MASK`. `Node<u64,u64>` stays 24 bytes — the bit lives in an
  existing link word, no new per-entry storage.
- In `get()`, replace the whole protected branch (the `prot_tail ==
  link(idx)` fast path plus the unlink/push_back refresh) with: set the
  node's reference bit and return. No list mutation on any protected hit.
- On a probationary hit that promotes into protected, after
  `set_protected(true)` and `push_back(idx)`, also `set_referenced(true)`
  so a freshly promoted node survives the next sweep.
- Rewrite `demote_protected_lru()` as a bounded CLOCK sweep over the
  protected list starting at `prot_head`: while the head node's reference
  bit is set, clear it and rotate that node to `prot_tail`
  (`unlink`+`push_back`); the first node found with a clear reference bit
  is the demotion victim — `unlink` it, `set_protected(false)`,
  `set_referenced(false)`, `push_back` into probation, decrement
  `prot_len`. This moves the surgery off the hot read path and onto the
  rarer overflow path.

Preserve all existing invariants: probation-first victim selection in
`put()` (and the protected-LRU fallback via `prot_head`), the `prot_cap`
soft bound and `prot_len` accounting, the 7/8 geometry, and `FastHasher`.
The put-update fast path is unchanged. The sweep must terminate in one
pass (every node's bit is cleared as the hand passes), so the protected
segment can never be left without a demotable victim when over cap.

## Rationale (optional)

The parent's protected-MRU fast path already proved that skipping surgery
on hot protected nodes is free; CLOCK extends that from "only when
already MRU" to "every protected hit," which is exactly the dominant
get-path cost the insights flagged as still holding room. Hit-rate should
hold because CLOCK approximates LRU within the protected set and eviction
order is otherwise unchanged.
