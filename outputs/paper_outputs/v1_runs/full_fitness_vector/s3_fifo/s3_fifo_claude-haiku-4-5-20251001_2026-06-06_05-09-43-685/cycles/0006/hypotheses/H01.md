# H01

Restore occupancy-responsive promotion thresholds with finer granularity to recover hit-rate while maintaining latency efficiency.

## Parent

cycle/0005/v002

## Changes

In `src/s3_fifo/mod.rs`, restore occupancy-responsive threshold logic to `evict_small()` with refined occupancy breakpoints:

1. In `evict_small()`, compute `occupancy_ratio = self.main.len() as f64 / self.main_size as f64` before the promotion decision.

2. Replace the fixed `if tail.freq > 2` check with adaptive thresholds based on occupancy:
   - If `occupancy_ratio < 0.4`: use `threshold = 1` (loose: freq > 1 promotes)
   - If `occupancy_ratio >= 0.4 && occupancy_ratio < 0.7`: use `threshold = 2` (medium: freq > 2 promotes)
   - If `occupancy_ratio >= 0.7`: use `threshold = 3` (strict: freq > 3 promotes)

3. Use the dynamically computed `threshold` in the promotion decision: `if tail.freq > threshold`.

4. Keep v002's sizing parameters intact: `small_size_min = 15%`, `small_size_max = 20%`, no growth adjustment at 0.5 occupancy.

This targets the open question from cycle 0005: whether fine-grained occupancy-threshold parameters (0.4, 0.7 vs the baseline 0.5, 0.8) can achieve better hit-rate balance without structural overhead.

## Rationale

Cycle 0005/v002 achieved excellent latency (131 ns) but sacrificed hit-rate (0.7222) compared to cycle 0003/v003 (0.716, 140 ns). The hypothesis is that v003's original occupancy thresholds (0.5, 0.8) are suboptimal. By tightening the breakpoints to 0.4 and 0.7, we test whether earlier threshold transitions (engaging stricter filtering sooner) recover hit-rate during moderate-load phases while maintaining latency protection under high load. The finer granularity targets items that fall through the 0.5-0.7 occupancy band where neither parent performs ideally. Expected outcome: hit-rate recovery toward 0.715+ with per-op-time staying near or under 140 ns.
