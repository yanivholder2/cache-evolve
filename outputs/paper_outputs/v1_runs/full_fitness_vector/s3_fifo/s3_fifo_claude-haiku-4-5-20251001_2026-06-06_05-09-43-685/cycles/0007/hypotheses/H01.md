# H01

Add ghost-queue frequency decay with lenient retention (-3 depth) to v005/v002's proven lean strategy to recover hit-rate without sacrificing latency.

## Parent

cycle/0005/v002

## Changes

In `src/s3_fifo/mod.rs`, enhance the ghost queue with frequency decay tracking while preserving v005/v002's overhead-free threshold approach:

1. Change the `ghost` field type from `VecDeque<K>` to `VecDeque<(K, i8)>` to track frequency decay states.

2. In `evict_main()`, when an entry reaches freq=0 and is selected for eviction:
   - Compute `ghost_freq = (tail.freq as i8).saturating_sub(1)` (0 - 1 = -1)
   - Push to ghost only if `ghost_freq >= -3` (allow decay through -3 levels before discard)
   - Store both key and frequency: `self.ghost.push_front((tail.key, ghost_freq))`

3. In `evict_small()`, when the promotion decision fails (item does not meet freq threshold):
   - Compute `ghost_freq = (tail.freq as i8).saturating_sub(1)`
   - Push to ghost only if `ghost_freq >= -3`
   - Keep the same promotion threshold logic as v005/v002 (freq > 2 for main promotion)

4. In `put()`, when a ghost hit occurs:
   - Extract both key and preserved frequency from the ghost entry
   - Re-admit to main queue with boosted frequency: `boost_freq = (ghost_freq + 3).max(0) as u8`
   - Clamp to MAX_FREQ: `freq = boost_freq.min(MAX_FREQ)`
   - Create entry with boosted frequency before pushing to main

5. Keep v005/v002's threshold logic intact: no occupancy-responsive thresholds, no dynamic sizing, just the lean threshold-based promotion.

This tests whether more lenient ghost retention (-3 vs v006/v002's -2) preserves more re-access opportunities without incurring the per-operation overhead of occupancy-aware mechanics, achieving hit-rate recovery closer to v005/v002's baseline 0.7222 while maintaining its latency profile.

## Rationale

v005/v002 achieved the best latency (131 ns) with strong hit-rate (0.7222) through a lean, overhead-free approach. The hypothesis tests whether ghost frequency decay—without dynamic sizing or occupancy tracking—can push hit-rate higher by preserving warm-but-evicted candidates. The -3 decay depth (more lenient than v006/v002's -2) targets items with 1–2 accesses that were evicted from small queue, giving them a second chance on re-access while keeping per-operation overhead minimal.
