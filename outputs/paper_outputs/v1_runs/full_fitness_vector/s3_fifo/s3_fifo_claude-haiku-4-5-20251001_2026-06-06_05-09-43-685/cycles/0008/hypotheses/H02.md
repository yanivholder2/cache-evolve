# H02

Implement dual-signal ghost re-admission combining frequency depth and recency position to improve re-access prediction accuracy beyond single-signal approaches.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, implement a novel ghost re-admission strategy that synthesizes two independent signals:

1. Change the `ghost` field type from `VecDeque<K>` to `VecDeque<(K, i8)>` to track frequency decay states.

2. In `evict_main()`, when an entry reaches freq=0:
   - Compute `ghost_freq = (tail.freq as i8).saturating_sub(1)` (decay from current frequency)
   - Push to ghost only if `ghost_freq >= -2` (allow two levels of decay before discard)
   - Store entry as `self.ghost.push_front((tail.key, ghost_freq))`

3. In `evict_small()`, when the promotion decision fails (item does not meet freq > 2 threshold):
   - Compute `ghost_freq = (tail.freq as i8).saturating_sub(1)`
   - Push to ghost only if `ghost_freq >= -2`
   - Keep fixed promotion threshold (freq > 2 in small queue)

4. In `put()`, when a ghost hit occurs:
   - Find the position of the ghost entry: `let pos = self.ghost.iter().position(|(ghost_key, _)| ghost_key == &key)`
   - Extract the key and frequency: `let Some((_, ghost_freq)) = self.ghost.remove(pos)`
   - Compute two independent signals:
     - **Recency signal**: `recency_ratio = 1.0 - (pos as f64 / self.ghost.len() as f64)`
       - Recently evicted items (pos near 0, at front) have recency_ratio near 1.0
       - Aged items (pos near back) have recency_ratio near 0.0
     - **Frequency signal**: `freq_signal = ((ghost_freq + 2) as f64 / 4.0).max(0.0).min(1.0)`
       - Items with higher ghost_freq (were hotter) score higher
   - Compute combined boost: `combined_score = (recency_ratio + freq_signal) / 2.0`
   - Apply boost formula: `boost = 2 + (combined_score * 2.0).floor() as i8`
   - Compute final frequency: `boosted_freq = (ghost_freq + boost).max(0) as u8`
   - Clamp to MAX_FREQ: `freq = boosted_freq.min(MAX_FREQ)`
   - Create entry with boosted frequency and push to main queue

5. Use fixed promotion threshold `freq > 2` in `evict_small()` (no occupancy-responsive variation).

6. Keep main-queue eviction logic as-is (second-chance pass with frequency decrement).

This tests the hypothesis that single-signal re-admission (frequency alone, recency alone, or occupancy alone) misses important dimensions of re-access likelihood. By combining a **hotness signal** (frequency decay) with a **temporal signal** (recency position), we capture both "was this item genuinely hot?" and "was this item recently displaced?" These signals are complementary—an item that was rarely accessed but just got evicted is less valuable than an item that was hot and was just evicted. The dual-signal approach normalizes both to [0,1], averages them, and scales to a boost magnitude that balances confidence from both perspectives. Expected outcome: hit-rate improvement toward 0.720+ by better fidelity of re-admission decisions, potentially with acceptable latency since re-admission computation occurs only on ghost hits (rare operations compared to main-queue traffic).

## Rationale

Cycles 0006–0007 tested individual signals in isolation: frequency decay (v006/v002), occupancy ratio (v007/v002), and recency alone (v007/v003). Each succeeded in some metric but failed in others, suggesting that no single observable signal fully predicts re-access patterns. This hypothesis combines two mechanically independent signals—one intrinsic to the item (how hot was it originally, captured by ghost_freq) and one contextual to eviction timing (how recently was it evicted, captured by ghost position)—with equal weighting. This avoids overfitting to workload-specific patterns while capturing orthogonal dimensions of information. The approach differs from v007/v002's occupancy-responsive boost (which conflates queue state with item properties) and v007/v003's pure recency (which ignores hotness). Expected to unlock hit-rate improvement by fusing complementary signals.
