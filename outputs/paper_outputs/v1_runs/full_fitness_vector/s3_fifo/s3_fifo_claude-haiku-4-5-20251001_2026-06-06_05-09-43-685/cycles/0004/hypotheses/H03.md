# H03

Dynamically adjust small-queue size based on main-queue occupancy to reduce eviction churn during high load while improving hit-rate during low-load phases.

## Parent

cycle/0001/v001

## Changes

In `src/s3_fifo/mod.rs`, implement occupancy-aware small-queue sizing to adapt queue proportions dynamically:

1. Replace the static `small_size` field with `small_size_min` and `small_size_max` to establish a tuning range:
   - `small_size_min`: 10% of total capacity
   - `small_size_max`: 25% of total capacity
   - `current_small_size`: tracks the dynamic size, initialized to (capacity / 4) as before

2. In `put()`, before potentially calling `evict_small()`:
   - Compute `occupancy_ratio = self.main.len() as f64 / self.main_size as f64`
   - If `occupancy_ratio >= 0.75`: shrink small_size toward `small_size_min` (reduce by 1 if current > min) to lower eviction churn when main queue is congested
   - If `occupancy_ratio <= 0.5`: grow small_size toward `small_size_max` (increase by 1 if current < max) to accept more items and improve hit-rate during underutilization
   - Resize `small` queue capacity immediately after adjustment

3. When resizing the small queue:
   - If shrinking, let the VecDeque naturally drop excess items or evict them explicitly to maintain size invariant
   - If growing, allocate additional capacity

4. Keep the fixed promotion threshold of `freq > 2` (as in the parent v001) or allow it to be orthogonal to this sizing change.

This targets the small-queue eviction bottleneck identified in cross-cycle analysis: small-queue evictions are a primary source of latency, and adjusting the small-queue size based on main-queue load reduces unnecessary evictions during peak contention. Unlike v003's threshold adaptation, this mechanism adjusts the queue structure itself, providing a complementary lever for load-response.

## Rationale

Cross-cycle analysis shows small-queue eviction is a major latency contributor, but queue sizing has not been deeply explored with occupancy awareness. Cycles 1-2 tested static sizing adjustments; this hypothesis makes the sizing dynamic based on live queue state, similar to v003's threshold adaptation but applied to queue structure. Expected outcome: improved hit-rate during low-load phases (when small queue is larger and more items can graduate) combined with reduced eviction latency during peak load (when small queue is smaller and evictions are less frequent), achieving better latency stability without sacrificing hit-rate.
