# H01

Give the resident set an O(1) hash index so `get` resolves in constant time instead of a linear queue walk, lowering get-p50 (per-op-time) below v002's 38ns floor.

## Parent

cycle/0006/v002

## Changes

v002's `get`/`find_entry_mut` walk `main.iter().chain(small)` linearly, so the
scored get-p50 is the median scan-to-hit distance. Restructure the resident
store so lookups are O(1) while keeping every S3-FIFO eviction decision
bit-identical (hit-rate must stay 0.7312):

- Change `small` and `main` from `VecDeque<Entry<K,V>>` to `VecDeque<K>` — they
  now hold only keys and continue to encode FIFO/eviction order exactly as
  today.
- Add `entries: HashMap<K, Entry<K,V>>` storing the authoritative
  `value`/`freq` for every resident key. Keep the `Entry<K,V>` struct defined
  with its current `{ key, value, freq }` fields so `size_of::<Entry<u64,u64>>()`
  stays 24 bytes (metadata-size summary must not change).
- `get`: replace the chained linear scan with `self.entries.get_mut(key)`,
  bump `freq` there (same saturating `.min(MAX_FREQ)` logic), return `&value`.
  This is the get-p50 win — one hash probe instead of a queue walk.
- `find_entry_mut` (the put update-in-place path): also resolve via
  `entries.get_mut`.
- `put`/`evict_small`/`evict_main`: wherever an entry is pushed onto a queue,
  also `entries.insert`; wherever one is popped/evicted, `entries.remove`. The
  second-chance loop in `evict_main` reads `freq` from `entries` for the key at
  the queue tail and decrements it there; promotion moves the key between
  `small` and `main` queues and leaves the `entries` record in place. Ghost
  handling is unchanged.
- To make sure the hash probe actually beats the current 38ns linear median,
  parameterise `entries` with an inline fast hasher (a small multiplicative /
  FNV-style `Hasher` + `BuildHasherDefault` defined in this module) rather than
  the default SipHash — no new crate dependency, no edit outside
  `src/s3_fifo/mod.rs`.

Preserve all existing capacity invariants (`small.len() + main.len() <=
capacity`) and update the in-module `#[cfg(test)]` tests that currently index
`main`/`small` entries by `.key` to go through the new key-queue + `entries`
layout.

## Rationale (optional)

get-p50 is the sole per-op scoring lever and is currently a median linear scan;
making the lookup structurally O(1) is the direct attack. Container growth is
unscored, and Entry stays 24B, so the only scored risks are get-p50 (the target)
and hit-rate (held exactly by mirroring v002's decisions).
