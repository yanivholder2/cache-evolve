# H02

Drop the redundant key field from v003's folded-tombstone design to reach Entry=16 with O(1) put while keeping the smaller single-map container that avoids v001's duplicate ghost set.

## Parent

cycle/0008/v003

## Changes

v003 gets its O(1) put from folding ghosts into the existing `entries` map as
value-less `Slot::Ghost` tombstones (no separate `ghost_set`), so its unscored
`S3Fifo` container is 152 bytes versus v001's 176 — it pays for the O(1) ghost
probe without duplicating every ghost key into a second hash table. But like
v001 its per-entry `Entry<K, V>` still stores `key`, leaving scored
metadata-size stuck at 24.

Shrink the per-entry record the same way v002 did, adapted to the `Slot` enum:

- Redefine `Entry<K, V>` as `{ value: V, freq: u8, _k: PhantomData<K> }`,
  removing the `key: K` field; keep `K` as a parameter via `PhantomData<K>`.
- Change `Entry::new` to take only `value`.
- Update every `Slot::Resident(Entry::new(key.clone(), value))` /
  `Entry::new(key, value)` construction in `put` and the test literals so they
  no longer pass a key into the entry.
- Leave the `Slot::{Resident, Ghost}` enum, `ghost_count`, the `entries`-map
  ghost probe in `put`, `demote_to_ghost`, `evict_main`, and `evict_small`
  exactly as they are.

This tests whether the folded-tombstone family can match H01's scored
metadata-size (16) and O(1) put while carrying a smaller container than the
separate-`ghost_set` family — directly probing the container-memory frontier the
cross-cycle notes flag as the next binding constraint. Eviction/promotion logic
is untouched, so hit-rate must stay 0.7312.
