# H01

Pushing the small/main split further (small = capacity/16) hands even more capacity to the main resident queue and raises hit-rate on workload-a.

## Parent

cycle/0001/v003

## Changes

In `S3Fifo::try_new` (src/s3_fifo/mod.rs), v003 sets the admission-queue
size to roughly `capacity / 10`. Shrink it further: replace that formula
with `(capacity / 16).max(1).min(capacity - 1)` for the `capacity > 1`
branch, and recompute `main_size = capacity - small_size` as before. Keep
the `capacity == 1` special case (`small_size = 1`) untouched, and keep
the `with_capacity` allocations consistent with the new sizes. Do not
change any eviction or promotion logic — only the split ratio. This
directly tests the cycle's open question of how narrow the small queue
can get before it stops screening one-hit-wonders at capacity 2048.

## Rationale (optional)

v003 proved that moving capacity from the admission filter to main lifts
hit-rate. This is the next step on that monotone sweep, isolating the
split ratio while preserving v003's strict thresholds.
