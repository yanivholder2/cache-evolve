# H03

Tightening the ghost re-admission window to only the most-recently-evicted keys (a quarter of `main_size`) raises hit-rate by restricting promotion-to-main to genuine near reuse.

## Parent

cycle/0002/v001

## Changes

In `evict_small`, the ghost queue is currently bounded by `self.main_size`
(the `if self.ghost.len() >= self.main_size { self.ghost.pop_back(); }` guard).
Replace that bound with an inline tighter expression `(self.main_size / 4).max(1)`
so the ghost retains only the freshest ~25% of evicted keys. Compute the bound
inline from the existing `main_size` field — do NOT add a `ghost_size` struct
field (that grew metadata to 120 in v002; keep metadata-size at 24). Leave the
`small`/`main` split, the `freq > 1` promotion test, and the `put` ghost-hit
promotion branch unchanged. A `put` whose key is no longer in the (now shorter)
ghost queue simply falls through to the normal small-queue admission path.

## Rationale (optional)

The cross-cycle narrative establishes this trace rewards near reuse, not far
reuse — widening the ghost (v002) readmitted stale long-distance keys that
displaced recently-reused entries and regressed hit-rate. Shrinking the ghost
is the unexplored opposite direction: it fires re-admission only for keys
evicted very recently, which should sharpen rather than dilute the main queue.
