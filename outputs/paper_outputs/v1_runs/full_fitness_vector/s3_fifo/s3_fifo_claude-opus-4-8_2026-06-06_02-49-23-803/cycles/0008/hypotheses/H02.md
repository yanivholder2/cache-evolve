# H02

Remove the redundant `key` field from the scored `Entry` struct to drop metadata-size from 24 to 16 bytes.

## Parent

cycle/0007/v001

## Changes

The metadata-size fitness summary is exactly `size_of::<Entry<u64,u64>>()`
(see `src/bin/evolve_metadata_size.rs`). It has been frozen at 24 bytes across
all seven cycles and is currently held by baseline. In the v001 incumbent the
`Entry { key: K, value: V, freq: u8 }` layout costs 24 bytes for `Entry<u64,u64>`
(8 + 8 + 1, padded to 24). The `key` field is now dead weight: since v001 indexes
the resident set by an `entries: HashMap<K, Entry<K,V>>` keyed on `K`, the key is
already stored as the map key, and the `small`/`main` queues store keys too. A
grep over the overlay confirms `Entry.key` is written by `Entry::new` and the
inline `#[cfg(test)]` constructors but is **never read** by `get`,
`find_entry_mut`, `evict_main`, or `evict_small`. No non-editable surface (the
JNI shim, `tests/`, `test_utils/`, or `evolve_metadata_size.rs`) references
`Entry.key`.

Make these edits in `src/s3_fifo/mod.rs`:
- Change the struct to `struct Entry<V> { value: V, freq: u8 }` (dropping the `K`
  type parameter, since `key` was its only use) — or, if keeping the generic
  signature is simpler, `struct Entry<K, V> { value: V, freq: u8, _k: PhantomData<K> }`
  is **not** acceptable because PhantomData-free is the goal; prefer dropping `K`.
- Update `Entry::new(value: V)` to no longer take or store a key.
- Update every `entries.insert(k.clone(), Entry::new(...))` call site and the
  inline test constructors `Entry { key: .., value: .., freq: .. }` to the new
  field set.

Invariants to preserve: `get` still returns `&entry.value`; `freq` saturation at
`MAX_FREQ`, two-touch promotion, and all eviction/ghost logic stay byte-identical
in behaviour. Only the per-entry layout shrinks. Expected result: metadata-size
24 → 16, with hit-rate and per-op-time held identical — a pure metadata win on a
dimension that has not moved in seven cycles.

## Rationale (optional)

The emerging cost frontier flagged in the cross-cycle notes is container memory;
this attacks the *scored* per-entry cost directly and cheaply by deleting a field
the hash index made redundant.
