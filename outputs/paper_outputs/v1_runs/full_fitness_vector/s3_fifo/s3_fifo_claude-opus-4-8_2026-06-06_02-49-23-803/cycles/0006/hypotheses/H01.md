# H01

Replace the linear ghost membership scan with an O(1) container-level hash index to cut put per-op-time without changing hit-rate or scored metadata-size.

## Parent

cycle/0005/v003

## Changes

In `src/s3_fifo/mod.rs`, the put hot path currently performs a linear
`self.ghost.iter().any(|ghost_key| ghost_key == &key)` scan on every put
miss, and `evict_main`/`evict_small` also `retain`/`iter` over the ghost
deque. This O(ghost_len) walk is the documented driver of put p50/p99
(380/994 ns at a 50%-of-main ghost). Add a container-level membership
index to make the lookup O(1):

- Add a field `ghost_set: std::collections::HashSet<K>` to the `S3Fifo`
  struct (add `use std::collections::HashSet;`). Initialize it empty in
  `try_new` with capacity `main_size`.
- Widen the impl/struct generic bounds from `K: PartialEq + Clone` to
  `K: PartialEq + Eq + std::hash::Hash + Clone` so the set is usable.
  The concrete cache type is `u64` and the tests use `i64`, both of which
  already satisfy `Eq + Hash`, so this is a no-op at the call sites.
- Keep the existing `ghost: VecDeque<K>` as the ordering/eviction
  structure. On every `ghost.push_front(k)` also `ghost_set.insert(k.clone())`;
  on every `ghost.pop_back()` of key `k` also `ghost_set.remove(&k)`; on the
  re-admission `ghost.retain(... != key)` also `ghost_set.remove(&key)`.
- Replace the membership test in `put` with `self.ghost_set.contains(&key)`.

**Invariants to preserve:** `ghost_set` must stay exactly in sync with the
contents of `ghost` (same keys, same cardinality) so hit-rate is bit-for-bit
identical to the parent — this is purely a latency optimization. Do NOT add
any field to `Entry<K,V>`; the scored metadata-size summary is the
`Entry<u64,u64>` size (24 bytes) and must remain 24. The `S3Fifo` container
may grow (it is not the scored summary). Keep the 50%-of-main ghost cap, the
dual-source (small-demotion + main-victim) ghost population, and freq=0
re-admission exactly as in the parent.

## Rationale (optional)

v003 keeps the ghost fuller than any prior incumbent (it adds main victims),
so its put path pays the most for the linear membership scan — making it the
parent that benefits most from an O(1) index, and the change cannot regress
hit-rate because membership semantics are unchanged.
