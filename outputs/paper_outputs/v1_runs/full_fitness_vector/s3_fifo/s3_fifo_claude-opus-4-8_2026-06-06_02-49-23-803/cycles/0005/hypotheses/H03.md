# H03

Recording main-queue eviction victims in the ghost queue (not just small-queue demotions) lets proven-but-aged keys be re-admitted on reaccess and raises hit-rate.

## Parent

cycle/0004/v001

## Changes

Currently only `evict_small()` populates the ghost queue; `evict_main()`
drops its zero-frequency victim without trace, so a key that graduated to
main, was reused, then aged out can never be fast-re-admitted on a later
reaccess. In `evict_main()`, when the loop drops the final
zero-frequency tail (the `else { break; }` arm), push that victim's key
into the ghost queue using the SAME bounded insertion already used in
`evict_small()`: if `self.ghost.len() >= (self.main_size / 2).max(1)`
then `self.ghost.pop_back()`, then `self.ghost.push_front(tail.key)`.
Reuse the existing `ghost: VecDeque<K>` — add no new struct field, so
metadata-size stays at 24. Keep the ghost cap at 50% of main so
main-victim keys compete with small-demotion keys for the same fixed
window rather than enlarging it. Leave the admission filter, split,
`MAX_FREQ`, and graduation/demotion thresholds unchanged.

## Rationale (optional)

Prior ghost experiments only resized the window; none changed what
populates it. Main victims are the highest-value re-admission candidates
(proven main residents), unlike the far one-hit-wonders that ghost
*widening* readmitted and hurt. This tests whether the workload rewards
re-admitting aged proven keys, while keeping the ghost length (and its
scan cost) fixed.
