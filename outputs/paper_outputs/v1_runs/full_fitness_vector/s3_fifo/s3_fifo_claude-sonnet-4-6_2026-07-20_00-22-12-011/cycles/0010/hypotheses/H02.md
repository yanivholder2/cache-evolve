# H02

Adding a compact 512-entry byte-counter admission sketch that rejects first-time-seen keys from entering the small queue reduces `evict_small()` invocation rate and lowers put p50 on Zipfian workloads where one-hit-wonder entries constitute the bulk of cold traffic.

## Parent

cycle/0007/v003

## Changes

Starting from cycle/0007/v003 (which has O(1) lookups, `small_size = capacity/40`, `MAX_FREQ = 5`, and the ghost HashSet):

1. **Add two fields to `S3Fifo<K,V>`**:
   ```rust
   admit_sketch: Box<[u8; 512]>,
   evict_count: usize,
   ```
   `admit_sketch` is a heap-allocated 512-byte counter array. `evict_count` tracks total evictions from small for periodic sketch reset.

2. **`try_new()`**: Initialise `admit_sketch: vec![0u8; 512].into_boxed_slice().try_into().unwrap()` (or `Box::new([0u8; 512])`), and `evict_count: 0`.

3. **Add a sketch-index helper** (private):
   ```rust
   fn sketch_idx(key: &K) -> usize {
       use std::hash::{Hash, Hasher, BuildHasher};
       let mut h = std::collections::hash_map::RandomState::new().build_hasher();
       // Use a stable per-instance seed instead: store a u64 seed at construction.
       key.hash(&mut h);
       (h.finish() as usize) % 512
   }
   ```
   Since `RandomState` is per-instance non-deterministic, instead store a `sketch_seed: u64` field initialised once in `try_new()` using a cheap inline mix, and implement a minimal finaliser inline:
   ```rust
   fn sketch_idx(&self, key: &K) -> usize {
       use std::hash::{Hash, Hasher};
       struct MixHasher(u64);
       impl Hasher for MixHasher {
           fn write(&mut self, bytes: &[u8]) {
               for &b in bytes { self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(b as u64 ^ 1442695040888963407); }
           }
           fn finish(&self) -> u64 { self.0 }
       }
       let mut h = MixHasher(self.sketch_seed);
       key.hash(&mut h);
       (h.finish() as usize) % 512
   }
   ```
   Add `sketch_seed: u64` field, initialised in `try_new()` as `capacity as u64 ^ 0xdeadbeefcafe1234`.

4. **`put()` cold-admission path** (the `Vacant`/new-key branch only, after the resident-update check and ghost-hit check pass through unchanged):
   ```rust
   // Cold admission gate
   let idx = self.sketch_idx(&key);
   let count = self.admit_sketch[idx];
   if count == 0 {
       // First time seen: record in sketch, skip admission entirely.
       self.admit_sketch[idx] = 1;
       return;
   }
   // Seen before: saturating-increment sketch, proceed with normal admission.
   if count < 255 { self.admit_sketch[idx] = count + 1; }
   // ... normal small-queue admission follows
   ```

5. **Sketch reset in `evict_small()`**: After each call to `evict_small()` increments `evict_count`, reset the sketch when `evict_count` reaches `self.main_size`:
   ```rust
   self.evict_count += 1;
   if self.evict_count >= self.main_size {
       self.evict_count = 0;
       self.admit_sketch.iter_mut().for_each(|c| *c = 0);
   }
   ```
   This prevents counter saturation over time and adapts to workload shifts.

6. **No changes to `get()`, `evict_main()`, or ghost logic.** The ghost hit path (key found in `ghost_set`) bypasses the admission gate and always admits to main — ghost hits represent re-access confirmation and must not be filtered.

7. **`Entry<K,V>`, `MAX_FREQ`, `small_size`**: All unchanged from v003.

8. **Tests**: Existing tests remain valid. Add a unit test confirming that a key inserted once is rejected (`put` returns without adding to `small`), and that the same key on a second `put` is admitted.

**Invariants to preserve**: The ghost-hit path must remain unaffected by the sketch (no gate on ghost promotion). The capacity bounds on `small` and `main` are unchanged. The sketch is a best-effort hint; false positives (hash collisions causing a first-time key to look seen) are acceptable — they do not corrupt state, they only slightly over-admit.

## Rationale

Every cold `put()` currently results in a `small.push_front` and a future `evict_small()` call. On Zipfian workloads, the vast majority of cold keys are never re-accessed (one-hit-wonders), so their admission into small causes churn — they get evicted to ghost immediately and never return. The admission sketch lets them fall off the cold path without touching small at all. This directly reduces `evict_small()` invocation rate, which the cross-cycle insight identified as the per-put bottleneck when `small_size` is small. The sketch adds only one array lookup and one conditional on the cold path, which is always a cache miss anyway, so its marginal cost is low.
