# H01

Capping `evict_main()`'s second-chance loop at 16 iterations before forcing eviction will reduce get p99 latency while preserving most of the hit-rate quality that full O(n) second-chance provides.

## Parent

cycle/0003/v002

## Changes

Replace the unbounded `while let Some(tail) = self.main.pop_back()` loop in `evict_main()` with a bounded variant that introduces a `SCAN_CAP: usize = 16` constant and a `scanned: usize` counter.

Each iteration proceeds exactly as before: pop the tail entry and its freq. If `freq == 0`, evict it (drop the entry, break). If `freq > 0` **and** `scanned < SCAN_CAP`, decrement freq, push_front to re-admit, increment `scanned`, and continue. If `freq > 0` **and** `scanned >= SCAN_CAP`, the budget is exhausted — drop the entry (evict it without re-admission) and break.

```rust
fn evict_main(&mut self) {
    const SCAN_CAP: usize = 16;
    let mut scanned = 0;
    while let Some(tail) = self.main.pop_back() {
        let freq = self.main_freq.pop_back().unwrap_or(0);
        if freq == 0 || scanned >= SCAN_CAP {
            // Evict: either zero-freq natural victim or scan budget exhausted.
            break;
        }
        // Re-admit with second-chance decrement.
        self.main.push_front(tail);
        self.main_freq.push_front(freq - 1);
        scanned += 1;
    }
}
```

All other functions (`evict_small`, `put`, `get`, `try_new`) remain identical to `cycle/0003/v002`. The `entry` and `S3Fifo` struct layouts are unchanged. The existing unit test `main_eviction_uses_frequency_second_chance` remains valid; update its assertion comments to note the cap exists but the test's queue (4 entries, mixed freq) will still find a zero-freq entry before hitting the cap.

**Invariant to preserve**: `evict_main()` must always remove exactly one entry from `self.main` (and one from `self.main_freq`) per call. The bounded loop preserves this: either the `freq == 0` branch breaks (removing that entry) or the `scanned >= SCAN_CAP` branch breaks (removing the entry popped in that iteration). An early-exit when `main.is_empty()` is not needed here since `evict_main` is only called when `main.len() >= main_size > 0`.

## Rationale

cycle/0003/v001 demonstrated that the deque-churn inside `evict_main()` (not scan length per se) dominates get latency, but pure two-random-choices sacrificed hit-rate materially. A bounded scan of 16 candidates limits worst-case churn to 16 `pop_back`/`push_front` pairs while still draining frequency from the back of the queue — preserving demand-confirmation quality for all entries that make it through the first 16 slots. The cap value 16 is chosen to be a small constant (cache-line friendly) large enough to encounter zero-freq entries on most eviction calls under Zipfian workloads where the majority of entries are cold.
