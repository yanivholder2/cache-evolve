# H02

Reducing the small-queue fraction from 1/20 to 1/40 will further improve hit rate on Zipfian traces by expanding main-queue residency to approximately 97.5% of total capacity.

## Parent

cycle/0003/v002

## Changes

In `try_new()`, change the small-queue sizing formula from `capacity / 20` to `capacity / 40`. The `.max(1).min(capacity - 1)` guards must remain in place to protect against edge cases at small capacities. No other code changes.

Before:
```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 20).max(1).min(capacity - 1)
};
```

After:
```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 40).max(1).min(capacity - 1)
};
```

All other functions, struct fields, and constants remain identical to `cycle/0003/v002`.

The `S3Fifo<u64,u64>` control struct size may change slightly (the `ghost` and `ghost_set` fields are pre-allocated to `main_size`, which grows from `capacity * 19/20` to `capacity * 39/40`). The `Entry<u64,u64>` size remains 16 bytes.

Update the inline comment above the formula from "H02 change: use 1/20 instead of 1/10" to "H02 change: use 1/40 instead of 1/20".

## Rationale

The small-queue fraction has been halved in every prior cycle (1/4 → 1/10 → 1/20) and each reduction improved hit rate and get latency with no observed penalty on the Zipfian workload-a trace. The trend has not yet shown a floor. At 1/40, main receives approximately 39 out of every 40 capacity slots, further reducing the admission-filtering overhead. The risk is that an overly thin small queue may fail to absorb cold-start bursts, but the ghost channel's demand-confirmation mechanism compensates: keys that re-surface quickly are still promoted to main regardless of small queue depth.
