# H01

Composing v001's 1/10 small-queue split, v003's parallel-freq-deque entry layout, and v002's HashSet ghost oracle into a single variant while eliminating the remaining O(n) `ghost.retain()` call via lazy deletion will improve hit-rate, metadata-size, and per-op-time simultaneously.

## Parent

cycle/0001/v001

## Changes

Start from v001's `mod.rs` (small_size = capacity/10, no HashSet, freq inside Entry).

Apply the following three orthogonal changes on top:

1. **Entry layout (from v003)**: Remove `freq: u8` from `Entry<K, V>`, leaving only `key` and `value`. Add two parallel sibling deques `small_freq: VecDeque<u8>` and `main_freq: VecDeque<u8>` to `S3Fifo`. Every `push_front`/`pop_back` on `small` or `main` must mirror a corresponding `push_front`/`pop_back` on the matching freq deque. Update `get()` to use index-based position lookup (`iter().position(...)`) and index into the freq deque instead of `entry.freq`. Update `evict_main()` and `evict_small()` to pop and push freq values in tandem with their entry deques. This shrinks `Entry<u64,u64>` from 24 to 16 bytes.

2. **O(1) ghost membership (from v002)**: Add `ghost_set: HashSet<K>` to `S3Fifo` (capacity hint: `main_size`). In `evict_small()`, after pushing a key into the ghost deque, also insert it into `ghost_set`; when evicting the oldest ghost entry (capacity guard), also remove it from `ghost_set`. In `put()`, replace `self.ghost.iter().any(...)` with `self.ghost_set.contains(&key)`.

3. **Lazy ghost deletion (fixes v002's remaining O(n) path)**: When a ghost hit is detected in `put()`, call only `self.ghost_set.remove(&key)` — do NOT call `self.ghost.retain(...)`. The stale key remains in the `ghost` deque. In the capacity-guard section of `evict_small()` (the loop that pops from the back of `ghost` when `ghost.len() >= main_size`), after popping an entry, check whether it is still in `ghost_set`; if yes, remove it from `ghost_set` (normal aged eviction); if no, the key was already lazily deleted — loop again without decrementing the effective ghost count. This ensures the deque stays bounded and ghost hit removes zero entries from the deque, making ghost-hit `put()` fully O(1) end-to-end.

Preserve all existing unit tests. Add one test that verifies `ghost_set.len() <= ghost.len()` after a ghost-hit scenario to confirm lazy deletion does not desync the set and deque capacities beyond bounds.

## Rationale

All three cycle-1 improvements are confirmed orthogonal by the cycle-insight; composing them is expected to be additive. The lazy-deletion fix closes the last known O(n) path (ghost.retain on ghost hits), which was explicitly flagged as the remaining hotspot in the cycle-1 continuation note.
