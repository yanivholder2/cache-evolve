# H03

Applying v001's 1/10 small-queue fraction to v003's parallel-freq-deque layout will combine the hit-rate and per-op-time gains of v001 with the metadata-size reduction of v003, without altering the ghost path.

## Parent

cycle/0001/v003

## Changes

In v003's `mod.rs`, make exactly one change in `try_new()`:

Replace the existing small-queue sizing expression:
```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 4).max(1).min(capacity - 1)
};
```
with:
```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 10).max(1).min(capacity - 1)
};
```

No other code changes. The parallel `small_freq` and `main_freq` deques, the index-based `get()` implementation, and the tandem push/pop in `evict_small()` and `evict_main()` all remain exactly as in v003. The ghost deque retains v003's original O(n) scan (no HashSet).

The `VecDeque::with_capacity` calls in `try_new()` must also be updated to use the new `small_size` and the derived `main_size` for pre-allocation consistency:
```rust
small:      VecDeque::with_capacity(small_size),
small_freq: VecDeque::with_capacity(small_size),
main:       VecDeque::with_capacity(main_size),
main_freq:  VecDeque::with_capacity(main_size),
ghost:      VecDeque::with_capacity(main_size),
```
(v003 already does this; verify the capacity arguments are consistent with the new `small_size`.)

Preserve all existing v003 unit tests unchanged. The `small_eviction_promotes_to_main_after_multiple_hits` test uses a capacity-4 cache: with `capacity/10 = 0`, `small_size` clamps to `max(1) = 1`, so small holds 1 entry and main holds 3 — the promotion scenario still triggers correctly.

## Rationale

v001 showed that shrinking the small queue from 1/4 to 1/10 improved both hit rate and get latency on the Zipfian workload-a trace, because a smaller small queue means a shorter linear scan before reaching the hot entries in the larger main queue. v003 showed that moving `freq` into parallel deques reduces per-entry size from 24 to 16 bytes and further improves scan latency by fitting more entries per cache line. These two changes touch disjoint parts of the code (sizing formula vs. entry layout and scan indexing), so combining them is expected to stack their individual benefits. This hypothesis isolates the combination from the ghost-path changes in v002/H01 and H02, providing a clean measurement of how sizing and layout interact.
