# H02

Replacing v002's O(n) `ghost.retain()` call on ghost hits with lazy deletion that removes only from the HashSet and lets stale deque entries be skipped during capacity enforcement will reduce p99 put latency without changing hit rate or entry metadata size.

## Parent

cycle/0001/v002

## Changes

In v002's `mod.rs`, make exactly two modifications:

1. **In `put()`, remove the `ghost.retain()` call on ghost hit**: The current code on a ghost hit is:
   ```rust
   self.ghost.retain(|ghost_key| ghost_key != &key);
   self.ghost_set.remove(&key);
   ```
   Change it to:
   ```rust
   self.ghost_set.remove(&key);
   // ghost deque intentionally not modified — lazy deletion
   ```
   The stale copy of `key` remains in `self.ghost` but is no longer in `self.ghost_set`, so it will never be treated as a live ghost entry again.

2. **In `evict_small()`, update the ghost capacity guard to skip lazily-deleted entries**: The current code pops one entry from the back of `ghost` when `ghost.len() >= main_size`:
   ```rust
   if self.ghost.len() >= self.main_size {
       if let Some(evicted) = self.ghost.pop_back() {
           self.ghost_set.remove(&evicted);
       }
   }
   ```
   Replace with a loop that pops until it either evicts one live ghost entry or drains stale tombstones:
   ```rust
   while self.ghost.len() >= self.main_size {
       match self.ghost.pop_back() {
           Some(k) if self.ghost_set.contains(&k) => {
               self.ghost_set.remove(&k);
               break; // evicted one live entry, deque is now within bounds
           }
           Some(_) => { /* stale tombstone — keep looping */ }
           None => break,
       }
   }
   ```
   This ensures the ghost deque stays bounded at `main_size` live entries even when stale keys accumulate, while keeping the hot-path (no ghost hit) at zero deque mutations.

Preserve all existing v002 unit tests including `ghost_set_stays_in_sync_with_ghost_deque`. Update that test: after a ghost-hit scenario, `ghost_set.len()` must be strictly less than or equal to `ghost.len()` (not necessarily equal, since stale tombstones may remain). Add a new test confirming that after repeated ghost hits, `ghost.len()` never exceeds `main_size + number_of_ghost_hits_not_yet_evicted`.

## Rationale

v002's cycle-insight explicitly identified `ghost.retain()` as an O(n) residual hotspot in the ghost-hit path. The `ghost_set` already provides O(1) membership; lazy deletion extends that O(1) guarantee to the deletion path without any new data structure. The ghost deque may temporarily exceed live-entry count by the number of pending tombstones, but the capacity guard loop ensures it stays bounded in deque length at `main_size`.
