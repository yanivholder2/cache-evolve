# H03

Lower the small-queue promotion threshold from `freq > 1` to `freq > 0` in `evict_small()` so that any re-accessed small-queue entry is promoted to main, targeting improved hit-rate for once-warm keys on Zipfian traces.

## Parent

cycle/0002/v001

## Changes

In `evict_small()`, change the single branch guard from:

```rust
if freq > 1 {
```

to:

```rust
if freq > 0 {
```

This is the only change. All other code — queue sizing (1/10 fraction), parallel-freq-deque layout, ghost_set membership oracle, lazy-deletion tombstone guard, `evict_main()` second-chance loop, `MAX_FREQ = 3` cap — remains identical to `cycle/0002/v001`.

Under the new rule an entry with `freq = 1` (accessed exactly once after admission) is promoted to main instead of being ghosted. It enters main carrying `freq = 1` via the unchanged `self.main_freq.push_front(freq)` line, giving it one second chance before it is vulnerable to eviction in main. Entries with `freq = 0` (never accessed after admission) still go to ghost, so the ghost channel remains active for the coldest keys.

The direct consequence on the eviction path: `evict_main()` will be called more often because main fills faster, but `evict_small()` itself stays O(1) — the only change is which branch is taken.

## Rationale

The current threshold (`freq > 1`, i.e. ≥ 2 accesses in small) follows the original S3-FIFO paper. However on a Zipfian workload the "once-warm" tier — keys accessed exactly twice total (once on put, once on get before eviction from small) — may belong to the recurring mid-frequency population rather than the cold-only stratum. Ghosting these keys rather than promoting them forces a round-trip through the ghost window before they re-enter main; if the ghost window is shorter than the inter-arrival time for these keys, they miss the ghost hit and are re-admitted from cold. Promoting them directly on first re-access should capture this mid-frequency population earlier, at the cost of slightly faster main-queue fill and marginally more `evict_main()` work. The hypothesis is that the additional hit-rate gain from retaining once-warm keys in main outweighs the extra eviction pressure on that queue for this workload.
