# H03

Shrink the small queue to about 3% of capacity on the baseline while keeping the shortened ghost, to test whether the sizing gain keeps going and raise hit rate.

## Parent

baseline

## Changes

In the cache constructor, set the small queue capacity to max(1, capacity * 3 / 100), where the existing sizing uses ~5% in the winning variants. Set the ghost capacity to the same shortened value the earlier winners used, which is roughly the main capacity multiplied by a factor below baseline's. Do not change promotion, main eviction or freq handling. Make the small and ghost ratios named constants at the top of the file.

## Rationale (optional)

Small-queue shrinking was the clearest single gain with diminishing returns. A 3% point checks whether 5% is the optimum or only a stop along the way. Starting from baseline also keeps the result independent of the hit-path changes.
