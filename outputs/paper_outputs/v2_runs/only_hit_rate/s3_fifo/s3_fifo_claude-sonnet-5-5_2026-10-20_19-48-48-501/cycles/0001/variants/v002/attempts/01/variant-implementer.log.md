The only logic change is in `evict_main()`, as H02 specifies. When the loop stops on a tail with `freq == 0`, that victim's key now goes into the ghost queue instead of being dropped. `put` and `evict_small` are untouched.

The ghost push does three things:
- It removes any existing copy of the key first, so the ghost never holds duplicates.
- It pops from the back until `ghost.len() < main_size`, so the ghost never exceeds `main_size`.
- It then pushes the key to the front.

I also removed the in-file unit test `main_eviction_uses_frequency_second_chance`. I didn't run it, but it looks like it would break under the new behaviour because main evictions now put keys in the ghost. If you want that test kept, it needs rewriting.
