# H01

Promoting small-queue tail entries to main after a single reuse (freq >= 1 instead of > 1) will raise hit-rate on the LIRS workload.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, `evict_small()`: change the promotion condition `tail.freq > 1` to `tail.freq >= 1`. Reset the promoted entry's `freq` to 0 before `main.push_front(tail)` so it does not get extra second chances in main. Leave `get`, `put`, `evict_main`, and ghost handling unchanged. Preserve the capacity invariant (small+main <= capacity). Note the existing unit test `small_eviction_promotes_to_main_after_multiple_hits` still passes (2 hits).

## Rationale (optional)

With a small queue of 25% capacity, one-hit-wonder filtering may be too strict for a loop/recency-mixed LIRS trace; testing a looser gate.
