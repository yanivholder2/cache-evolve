# H01

Make main-queue eviction scan-resistant by evicting the lowest-frequency entry among the first K tail entries, to raise hit-rate.

## Parent

cycle/0004/v001

## Changes

In the main-queue eviction routine (the loop that pops the tail, and if freq>0 decrements and reinserts at head, else evicts), replace the pure FIFO-reinsertion loop with a bounded lookahead: inspect up to K=4 entries from the tail, evict the first one with freq==0; if none has freq==0, evict the entry with the minimum freq among the K, and decrement the freq of the others skipped (leave them in place, do not reinsert). Keep small-queue, ghost, and promotion logic unchanged. Invariants: total resident count never exceeds capacity; ghost insertion of main victims (already present in the parent) still occurs for the evicted key. Verify the diff actually changes eviction order (the code path must be reachable when tail freq>0).

## Rationale (optional)

Earlier cycles tuned sizing and admission to saturation; main-eviction scanning is an untested lever listed in cross-cycle insights.
