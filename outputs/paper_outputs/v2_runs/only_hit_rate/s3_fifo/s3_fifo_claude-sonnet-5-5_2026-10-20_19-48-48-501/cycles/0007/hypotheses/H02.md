# H02

Ghosting only main evictees that had freq>0 during their main residency will raise hit-rate by keeping the shortened ghost populated with keys likely to be reused.

## Parent

cycle/0004/v001

## Changes

In the main-queue eviction path, when a victim is finally evicted (freq reaches 0 after the second-chance scan), the incumbent currently ghosts every evictee. Track whether the entry was ever reinserted/decremented in the scan (i.e. it had freq>0 at any point this scan, or had been promoted via a ghost hit with a hit afterward) using a local boolean in the eviction loop, not per-key state. Insert into the ghost only if that flag is true; otherwise drop the evictee silently. Small-queue evictees that fail promotion continue to be ghosted. Leave sizes, ghost length, promotion rule and ghost-hit admission unchanged. Add no struct fields to the entries.

## Rationale (optional)

Ghost capacity is limited; filtering never-reused main evictees tests whether they pollute it, without adding per-key flags.
