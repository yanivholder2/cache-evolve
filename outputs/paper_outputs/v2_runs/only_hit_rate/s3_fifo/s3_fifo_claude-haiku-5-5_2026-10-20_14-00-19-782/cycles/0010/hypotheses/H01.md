# H01

Partitioning main-fed ghost entries into their own bounded ring will raise hit-rate on lirs workload-a at capacity 2048 by keeping small-queue ghost history from being displaced by main-queue evictions.

## Parent

cycle/0009/v002

## Changes

Keep the zero-frequency push in `evict_main` from cycle/0009/v002, but stop writing those keys into the shared ghost queue. Add a second, separate ghost ring `main_ghost` with a fixed capacity of one quarter of the main capacity (capacity / 4), FIFO-evicted on overflow. In `evict_main`, a zero-frequency victim is pushed onto `main_ghost` only. In the ghost-hit check (the path that currently uses the shared ghost `retain` and `iter().any` scans), look up both the shared ghost queue and `main_ghost`; a hit in either takes the existing ghost-hit path and re-enters `main` directly. A hit in `main_ghost` removes that entry from `main_ghost`. Small-queue evictions keep pushing only to the shared ghost queue, unchanged. Do not change the small-queue promotion bar, the frequency logic, or the sizing of the shared ghost window. Keep the eviction order for all non-ghost paths identical to the parent.

## Rationale (optional)

v002 showed that main-evicted keys re-entering through the ghost path helps, and its own takeaway flags that these entries add to the shared ghost history. Earlier cycles found that widening the shared ghost window lost hits, which suggests main-fed entries may be displacing small-queue ghost history. A separate bounded ring tests that directly.
