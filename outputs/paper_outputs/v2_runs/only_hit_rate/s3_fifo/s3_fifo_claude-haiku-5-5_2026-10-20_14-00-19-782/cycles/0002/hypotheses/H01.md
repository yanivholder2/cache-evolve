# H01

Mirror the ghost queue in a `HashSet` so the ghost-membership check on every miss in `put()` stops scanning, lowering per-op-time while leaving hit-rate at 0.7164 on lirs workload-a at size 2048.

## Parent

baseline

## Changes

In `src/s3_fifo/s3_fifo.rs`, add a field `ghost_set: HashSet<K>` to `S3Fifo` that always holds exactly the keys currently in `ghost`. Import `std::collections::HashSet` and `std::hash::Hash`.

- Change the inherent impl bound from `impl<K: PartialEq + Clone, V> S3Fifo<K, V>` to `impl<K: PartialEq + Eq + Hash + Clone, V> S3Fifo<K, V>`. The `Cache` trait impl already requires `Eq + Hash`, so trait callers are unaffected. Check that any direct `S3Fifo::new` caller in `s3_fifo_jni.rs` uses a key type that satisfies the new bound; if one does not, leave the bound alone and do not edit that file.
- In `try_new()`, initialise `ghost_set: HashSet::with_capacity(main_size)`.
- In `put()`, replace `let in_ghost = self.ghost.iter().any(|ghost_key| ghost_key == &key);` with `let in_ghost = self.ghost_set.contains(&key);`. On the ghost-hit branch, keep `self.ghost.retain(...)` for ordering and add `self.ghost_set.remove(&key);`.
- In `evict_small()`, ghost branch: when `self.ghost.len() >= self.main_size`, do `if let Some(old) = self.ghost.pop_back() { self.ghost_set.remove(&old); }`. Then `let key = tail.key; self.ghost_set.insert(key.clone()); self.ghost.push_front(key);`.

Do not change `get()`, `find_entry_mut()`, `evict_main()`, `MAX_FREQ`, the partition in `try_new()` (keep `capacity / 4`), or the promotion predicate `tail.freq > 1`. Eviction order and ghost contents must be exactly as in the baseline, so hit-rate must match the parent's 0.7164 exactly. Add a unit test in the existing `tests` module that runs a short mixed put/get sequence and asserts `ghost_set` equals the set of keys in `ghost` after each step. Report per-op-time and metadata-size; metadata-size is expected to rise because of the set, and that is an acceptable trade if per-op-time drops.

## Rationale (optional)

Every miss in `put()` currently runs two linear scans: `find_entry_mut()` over small and main, then the ghost scan. The ghost scan is O(main_size) and is the one scan that can be replaced without changing which keys are resident or ghosted. Cycle 0001 found hit-rate insensitive to ghost routing, and asked for cost metrics to be reported; this hypothesis tests a pure cost change with a hit-rate control.
