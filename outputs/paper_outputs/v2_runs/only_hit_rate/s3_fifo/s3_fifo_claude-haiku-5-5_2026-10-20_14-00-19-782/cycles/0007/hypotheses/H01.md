# H01

Replacing the linear resident scans with a keyed index makes `get` and `put` O(1) per operation and lowers per-op-time, with hit-rate unchanged because eviction order is preserved.

## Parent

baseline

## Changes

Restructure `S3Fifo` in `src/s3_fifo/mod.rs` so that residency and per-key state live in a hash index rather than being found by scanning the queues.

- Add `use std::collections::HashMap;` and a private `struct Slot<V> { value: V, freq: u8 }`.
- Add a field `resident: HashMap<K, Slot<V>>` to `S3Fifo`. Change the `small` and `main` fields from `VecDeque<Entry<K, V>>` to `VecDeque<K>`. Keep `ghost: VecDeque<K>` as in baseline, and keep baseline's linear `ghost.iter().any(...)` membership check in `put`. Do not add a `ghost_set`, so ghost behaviour is unchanged and this hypothesis stays separate from H02.
- Tighten the impl bound to `K: PartialEq + Eq + Hash + Clone` and the struct bound to match.
- `get(&mut self, key)`: look up `self.resident.get_mut(key)`, bump `freq` with `saturating_add(1).min(MAX_FREQ)`, and return `Some(&slot.value)`. No queue scan.
- `put(&mut self, key, value)`: if `resident` contains `key`, overwrite `value` and return. Otherwise, if the key is in the ghost queue, remove it from `ghost`, call `evict_main()` when `main.len() >= main_size`, then `main.push_front(key)` and insert `Slot { value, freq: 0 }` into `resident`. Otherwise call `evict_small()` when `small.len() >= small_size`, then `small.push_front(key)` and insert the slot.
- `evict_main()`: pop the back key from `main`. Look up its freq in `resident`. If freq > 0, decrement it in the map and `push_front` the key again, then continue. If freq == 0, `resident.remove(&key)` and stop. The pass order and the stop condition are identical to baseline.
- `evict_small()`: pop the back key from `small` and read its freq from `resident`. If freq > 1, call `evict_main()` when `main.len() >= main_size` and `push_front` the key onto `main` (the slot stays in `resident`). Otherwise remove the slot from `resident`, push the key onto the ghost queue with the same ghost-capacity rule as baseline (`ghost.len() >= main_size` pops the back).
- Keep `MAX_FREQ`, `try_new` sizing, and the `framework::Cache` impl unchanged apart from the bounds.
- Invariants to preserve: the same key is never in both `resident` and `ghost`; `small.len() + main.len() == resident.len()`; capacity bound `small.len() + main.len() <= capacity`; the eviction sequence for any trace is identical to baseline.
- Update the inline tests that push raw `Entry` values onto `small`/`main` so they use keys plus `resident` entries. Assertions about which key survives in `main` must stay the same.

Report per-op-time and metadata-size alongside hit-rate. Metadata-size is expected to rise because of the map, so the claim is a per-op-time claim with a metadata cost to be measured.

## Rationale (optional)

Every cycle so far has been measured on hit-rate only, and no cost-side change has been ranked. Baseline's `get` and `put` both scan up to the full capacity (2048 slots on the reference run). A keyed index changes the cost profile without touching the eviction decisions that drive hit-rate.
