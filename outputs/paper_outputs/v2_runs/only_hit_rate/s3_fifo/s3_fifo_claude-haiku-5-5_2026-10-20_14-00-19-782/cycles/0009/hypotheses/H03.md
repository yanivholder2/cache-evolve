# H03

Using the `HashMap` entry API for the miss path in `put` will cut per-op-time by removing the second hash of the key on every miss, with hit-rate unchanged on lirs workload-a at capacity 2048.

## Parent

cycle/0008/v001

## Changes

In `src/s3_fifo/mod.rs`, rewrite the residency step at the top of `S3Fifo::put` so the key is hashed once. Currently `put` calls `self.resident.get_mut(&key)` (hash 1) and, on a miss, `self.resident.insert(key, ...)` (hash 2), on both the ghost-hit and small-insert branches.

- Add `use std::collections::hash_map::Entry;`.
- Replace the leading `if let Some(slot) = self.resident.get_mut(&key)` block with `match self.resident.entry(key.clone())`. On `Entry::Occupied(mut o)`, set `o.get_mut().value = value` and return. On `Entry::Vacant(v)`, do the ghost check as today and, in place of the later `self.resident.insert(key, Slot { value, freq: 0 })` calls, use `v.insert(Slot { value, freq: 0 })`.
- Because the entry must be held while `evict_main` and `evict_small` mutate `self.resident`, do not hold the `Vacant` entry across those calls. Instead, record the decision (ghost-hit or small-insert) first, call the evictions, then insert with `self.resident.insert(key, Slot { value, freq: 0 })`. If that ordering makes the single-hash goal impossible under borrow rules, stop and report the conflict rather than reintroducing a second lookup silently.
- Leave `get`, `evict_main`, `evict_small`, the ghost linear scan, `MulHasher`, and `Entry<K, V>` unchanged.

Eviction order, queue contents, and `freq` values must match the parent exactly, so hit-rate should be identical on the trace.

## Rationale (optional)

Every cache miss in `put` currently pays two hash computations and two probes of `resident`. Cycle 0008 swapped the hasher, but the number of hash operations on the miss path did not change. Cutting one probe per miss is a constant-factor change to per-op-time that does not touch eviction. It is a cost candidate only; the rerun must report per-op-time to confirm it.
