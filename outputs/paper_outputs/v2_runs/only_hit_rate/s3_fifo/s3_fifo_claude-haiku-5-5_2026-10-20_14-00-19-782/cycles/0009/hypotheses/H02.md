# H02

Recording keys evicted from the main queue in the ghost queue, not only keys evicted from the small queue, will raise hit-rate on lirs workload-a at capacity 2048 by letting recently-main-evicted keys re-enter main directly on their next access.

## Changes

In `src/s3_fifo/mod.rs`, change where ghost entries come from. Currently only `evict_small` pushes into `ghost`. Add the same bounded ghost push to `evict_main`:

- In `evict_main`, in the `else` branch where the key is removed with `self.resident.remove(&key)` and the loop breaks, also do `if self.ghost.len() >= self.main_size { self.ghost.pop_back(); }` followed by `self.ghost.push_front(key.clone())` before the key is dropped. Clone the key before `remove` if the ownership requires it.
- Leave `evict_small`'s ghost push for keys with `freq <= 1` as is.
- Leave the `put` ghost-hit branch unchanged. A ghost hit still removes the key from `ghost` with `retain`, and still inserts it at the front of `main` with `freq: 0`.
- Do not change `MAX_FREQ`, the `freq > 1` promotion bar in `evict_small`, `main_size`, or `small_size`.

The `main_eviction_uses_frequency_second_chance` test and the other tests in the module must still pass. In `put`'s ghost-hit branch the re-admitted key is removed from `ghost` with `retain` before `evict_main` runs, so `evict_main` may push a different key into ghost but never the key being admitted. Confirm that no key is ever in `ghost` and `resident` at the same time.

## Rationale (optional)

Earlier ghost experiments changed the window size, the re-admission route, or the re-admission frequency. None changed which keys enter the ghost queue. A key that leaves main with positive frequency history and is then re-referenced currently misses and restarts in small. Feeding main evictions into ghost gives those keys the ghost-hit path on return. This is a source change to the ghost queue rather than an admission-rule tweak, so it is a distinct axis from the flat and negative cycles.
