# H01

Removing the second hash probe on the miss path of cycle/0004/v001 should lower per-op-time without changing hit-rate, because eviction order is unchanged.

## Parent

cycle/0004/v001

## Changes

Start from the parent's resident-key probe (the set-membership check that v001 added with early return on hits). Make the miss path perform one probe, not two: the probe result computed during the lookup is carried forward and reused by the admission step that inserts the new key into the small queue, so the admission code does not rehash or re-query the resident-key set.

Specifically:
- In the lookup path, keep v001's early return on hits unchanged.
- On a miss, store the computed key hash (or the probe outcome) in a local and pass it to the admission/insert routine, replacing any second hash-and-lookup there.
- Do not change queue order, promotion decisions, ghost handling, or the eviction victim choice. The only permitted behavioural difference is the removed redundant lookup.
- Keep the resident-key set consistent on eviction: when a key leaves the cache, it must be removed from the set in the same place as before.

Verify by inspecting the built code that the reuse is present before measuring.

## Rationale (optional)

v001 was hit-rate neutral (0.7164), consistent with unchanged eviction order, but reported no cost metrics, so its speedup claim is unverified. This hypothesis isolates the one cost change most likely to matter (a duplicated probe on misses) and makes the experiment's claim measurable: per-op-time should drop, hit-rate should stay at 0.7164, and metadata-size should not grow. The run must report per-op-time and metadata-size, which earlier cycles never did.
