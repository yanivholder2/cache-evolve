# H03

Enlarging the ghost queue to twice the main-queue size should raise hit-rate by letting re-references with longer reuse distances be caught as ghost hits and re-admitted to main, targeting hit-rate.

## Parent

baseline

## Changes

Add a `ghost_size` field to `S3Fifo`, set to `2 * main_size` in `try_new()`. Allocate `ghost` with `VecDeque::with_capacity(ghost_size)`.

In `evict_small()`, change the ghost-capacity check from `if self.ghost.len() >= self.main_size` to `if self.ghost.len() >= self.ghost_size`, so the oldest ghost key is dropped only when the ghost is full.

Leave everything else as in the baseline: `small_size = capacity / 10`, `MAX_FREQ = 3`, the two-hit promotion bar (`freq > 1`), ghost hits re-admitted directly to `main`, and `evict_main()` unchanged.

Ghost entries store keys only, so the metadata cost is the extra key storage. Report metadata-size and per-op-time along with hit-rate. Hit-rate above 0.7164 on lirs workload-a at 2048 is the signal to watch. The main cost risk is the linear `ghost.iter().any()` check in `put()`, which doubles in length, so per-op-time may rise.
