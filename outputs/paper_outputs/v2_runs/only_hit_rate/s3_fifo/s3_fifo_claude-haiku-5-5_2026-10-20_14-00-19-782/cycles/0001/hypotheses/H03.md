# H03

Shrink the small admission queue to roughly ten percent of capacity, as in the original S3-FIFO design, so more of the cache holds the main resident set and raises hit-rate on the lirs workload-a trace at size 2048.

## Parent

baseline

## Changes

In `src/s3_fifo/s3_fifo.rs`, change the partition computation in `S3Fifo::try_new()` from `(capacity / 4).max(1).min(capacity - 1)` to `(capacity / 10).max(1).min(capacity - 1)` for the non-unit-capacity branch. Keep the `capacity == 1` branch returning `small_size = 1`, and keep `main_size = capacity - small_size`. Leave the ghost queue capacity as `main_size`, the `VecDeque::with_capacity` hints as they are, and the logic in `put()`, `get()`, `evict_small()`, and `evict_main()` unchanged. At size 2048 this yields `small_size = 204` and `main_size = 1844`, down from 512 and 1536. The invariant `small_size + main_size == capacity` must hold, and `capacity == 0` must still return `None`. No new fields, so metadata-size is unchanged.

## Rationale (optional)

The baseline's quarter-of-capacity small queue is much larger than the roughly ten-percent split the S3-FIFO paper recommends. A smaller admission queue leaves more slots for the main queue, which holds the frequency-tracked resident set, but it also gives new keys less time to earn a second hit. This hypothesis tests whether the baseline's partition is over-weighted toward admission, and it changes only a single arithmetic constant so its effect is easy to attribute.
