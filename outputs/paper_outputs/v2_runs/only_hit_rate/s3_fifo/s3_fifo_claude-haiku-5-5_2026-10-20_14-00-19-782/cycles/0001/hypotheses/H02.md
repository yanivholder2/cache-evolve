# H02

Re-admit ghost-hit keys into the small admission queue instead of straight into the main queue, so a re-referenced ghost key must earn promotion again and raises hit-rate on the lirs workload-a trace at size 2048 by filtering bursty re-references.

## Parent

baseline

## Changes

In `src/s3_fifo/s3_fifo.rs`, in the ghost-hit branch of `put()`, replace the current re-admission block

    if self.main.len() >= self.main_size { self.evict_main(); }
    self.main.push_front(Entry::new(key, value));

with a re-admission into `small`:

    if self.small.len() >= self.small_size { self.evict_small(); }
    self.small.push_front(Entry::new(key, value));

Keep the preceding `self.ghost.retain(|ghost_key| ghost_key != &key);` so the key still leaves the ghost queue on a ghost hit. Leave `evict_small()` and `evict_main()` unchanged; `evict_small()` already handles the case where the tail is promoted to `main` or sent to ghost. The fresh entry starts with `freq = 0` via `Entry::new`, so it needs a `get()` hit before it can be promoted under the existing rule. Do not change `try_new()`, `get()`, `MAX_FREQ`, or the non-ghost insertion path. No new fields; metadata-size is unchanged.

## Rationale (optional)

The baseline's ghost-hit path bypasses the admission queue entirely, which means a key that was evicted once and returns is trusted as hot. Routing it back through `small` tests the opposite assumption: that ghost hits are sometimes short-term bursts that should be re-filtered. This is a deliberate break from the S3-FIFO paper's design, included to cover the ghost-admission axis of the cohort.
