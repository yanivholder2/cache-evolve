# H03

Packing each entry's queue membership and frequency counter into a single byte should reduce metadata-size below baseline's 24 while leaving hit-rate at 0.7164.

## Parent

baseline

## Changes

Change only how per-entry metadata is stored. Eviction order, admission, and promotion logic must stay identical to baseline.

- Identify the per-entry fields that hold queue membership (small, main, or ghost) and the frequency counter. Replace them with a single `u8` bitfield: two bits for queue membership and two bits for a saturating frequency capped at the value the baseline already uses.
- Provide accessor helpers (for example `queue_of(entry)`, `freq_of(entry)`, `bump_freq(entry)`) so that all existing `freq > 2` checks, the promotion bar in `evict_one()`, and the ghost-hit branch in `put()` read the same values as before.
- Remove any padding or separate `bool` fields that the bitfield makes redundant. Do not change the key or value storage.
- Do not change the sizes of the small, main, or ghost queues, or the ghost window.
- Behavior must be bit-for-bit identical in eviction decisions. If the frequency cap in baseline is above what two bits can hold, keep the cap and use a wider field instead, and say so in the variant's notes.

Report hit-rate, metadata-size, and per-op-time. Confirm each edit lands in the built code. This variant's main purpose is to produce the first measured metadata-size number for an S3-FIFO variant.
