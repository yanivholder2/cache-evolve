# H02

Re-admitting ghost hits through the small queue instead of directly into main should recover the hit-rate that widening the ghost window lost in cycle 0003.

## Parent

cycle/0002/v001

## Changes

Keep v001's ghost-membership lookup refactor unchanged. Change only the branch that handles a ghost hit on insertion.

- In the ghost-hit branch of `put()` (the path that currently pushes the key straight into the main queue), instead insert the key into the small queue, using the normal small-queue admission path.
- Leave the ghost queue size at its v001 value. Do not double it; cycle 0003 showed that a larger ghost window alone loses hit-rate.
- Keep the two-hit promotion bar in `evict_one()` and the main-queue frequency cap as they are in v001.
- A key re-admitted from ghost now has to earn promotion from the small queue, so it should no longer displace main-queue residents on arrival. Do not add any new counters or new state for this.
- The main-queue eviction path `evict_main()` should be unchanged.

Report hit-rate, metadata-size, and per-op-time. Confirm that the ghost-hit branch edit is present in the built code before reading the hit-rate result, since an unlanded edit cannot be attributed.
