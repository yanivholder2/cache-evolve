# H03

Gating the ghost linear scan in `put` behind a 64-bucket counting filter over the ghost queue lowers per-op-time on misses in cycle/0007/v002, with hit-rate unchanged because the filter only skips scans that cannot match.

## Parent

cycle/0007/v002

## Changes

Keep the ghost-mirror removal from cycle/0007/v002. Add a counting filter in front of its ghost membership scan, in `src/s3_fifo/mod.rs`.

- Add a field `ghost_filter: [u8; 64]` to `S3Fifo`, initialised to all zeros in `try_new`. Add a private helper `fn ghost_bucket(key: &K) -> usize` that hashes `key` with `std::collections::hash_map::DefaultHasher` and returns `(hash & 63) as usize`. Add `use std::collections::hash_map::DefaultHasher;` and `use std::hash::Hasher;` as needed.
- Every push onto `ghost` increments `ghost_filter[ghost_bucket(&key)]`. This happens in `evict_small`, where the key is pushed with `self.ghost.push_front(tail.key)`.
- Every removal from `ghost` decrements its bucket:
  - In `evict_small`, the `if self.ghost.len() >= self.main_size` branch becomes `if let Some(old) = self.ghost.pop_back() { self.ghost_filter[ghost_bucket(&old)] -= 1; }`.
  - In `put`, the `self.ghost.retain(...)` on re-admission becomes a removal of the matching key, followed by a decrement of `ghost_filter[ghost_bucket(&key)]`. A key is in `ghost` at most once, so the decrement runs exactly once.
- In `put`, replace the ghost membership check with `let in_ghost = self.ghost_filter[ghost_bucket(&key)] != 0 && self.ghost.iter().any(|ghost_key| ghost_key == &key);`. A zero bucket means the key cannot be in `ghost`, so the scan is skipped.
- Keep the `last_miss` probe reuse and the resident-bit logic from cycle/0007/v002 unchanged.
- Invariants to preserve: `ghost_filter.iter().map(|&c| c as usize).sum::<usize>() == ghost.len()` at every step; the ghost queue holds the same keys in the same order as the parent; the eviction sequence on any trace is identical to cycle/0007/v002.
- Add one unit test that runs a short trace with repeated evictions and re-admissions and asserts the filter sum equals `ghost.len()` after each `put`.

Report per-op-time, metadata-size, and hit-rate. Expected direction: per-op-time goes down on misses whose key is absent from `ghost`, which is the common case for a scan-heavy trace. Metadata-size rises by 64 bytes.

## Rationale (optional)

cycle/0007/v002 removed `ghost_set` and made ghost membership a linear scan of up to `main_size` keys on every miss. Its insight flags that scan as the likely per-op-time regression, and the cycle 0007 insight said to hold v002 until that cost is measured. This hypothesis addresses that cost directly, instead of restoring the mirror set that v002 removed. It keeps the metadata footprint small compared with a full hash set.
