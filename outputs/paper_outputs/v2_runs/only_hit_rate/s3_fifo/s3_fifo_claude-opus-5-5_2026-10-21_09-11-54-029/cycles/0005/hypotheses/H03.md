# H03

Recording main-queue eviction victims in the ghost, so that a returning main victim re-enters main directly instead of re-running small-queue probation, will raise hit-rate on workload-a.

## Parent

cycle/0004/v001

## Changes

In `src/s3_fifo/mod.rs`, change `S3Fifo::evict_main`'s eviction branch. Today, when the popped tail has `freq == 0`, it calls `self.release(idx)` and drops the key. Change it to `let entry = self.release(idx); self.ghost_insert(entry.key);` and then `break`. A key that has lived in main and aged out is then remembered the same way a small-queue reject is. When it comes back, the existing `put` ghost branch (`ghost_set.remove` → evict_main if full → `push_front` at freq 0) re-admits it straight to main.

Keep everything else unchanged:
- The re-admission rule itself (front of main, freq 0).
- `MAX_FREQ = 7`.
- The 5% split.
- `evict_small`'s `freq > 1` graduation.
- The ghost live-entry cap of `main_size`, enforced in `ghost_insert`, so metadata stays bounded.
- The lazy compaction threshold `2 * main_size + 16`.

Watch out for re-entrancy. `evict_main` is called from inside `evict_small` and from `put`'s ghost branch, both before the new key is allocated. Calling `ghost_insert` there is safe, because the key being inserted was just removed from `index` by `release` and cannot equal the key being admitted. The `put` ghost branch has already removed its own key from `ghost_set` before calling `evict_main`.

Make these test changes:
- Update the reference `RefS3Fifo::evict_main` so the popped freq-0 tail is pushed into its ghost with the same `main_size` cap (`pop_back` when full, then `push_front`). The step-by-step equivalence test must keep passing.
- Add a unit test: fill main, force a main eviction of key K, then `put(K)`, and assert that K is in main, not in small.

## Rationale (optional)

Today, a main victim that comes back is treated as brand new. It goes to the 5% small queue, where (as cycle 0004's v003 showed) the window is much shorter than its reuse horizon, so it usually gets ghosted once more before it can return to main. That costs at least one extra miss per return. This change keeps the settled re-admission point and does not make re-admission more generous for small-queue rejects. It only widens what counts as ghost evidence to include keys that already proved reuse in main. It is a different axis from H01 (credit decay) and H02 (graduation threshold). The risk to test is ghost dilution: main victims share the `main_size` ghost budget and may push small-queue rejects out sooner. If hit-rate drops below v001's 0.7289, that dilution outweighs the faster return.
