# H02

Giving ghost-readmitted keys one second-chance credit (freq = 1 on insertion into main) will raise hit-rate on workload-a by keeping proven-reuse keys through their first main eviction pass.

## Parent

cycle/0001/v001

## Changes

In `src/s3_fifo/mod.rs`, in `put`, in the `in_ghost` branch: after removing the key from `ghost` and calling `evict_main()` if main is full, insert the entry with `freq = 1` instead of `Entry::new(key, value)`'s default 0. For example, build the entry with `let mut e = Entry::new(key, value); e.freq = 1; self.main.push_front(e);`.

Change nothing else relative to v001: 10% small split, ghost sized to `main_size`, graduation from small at `freq > 1` (promoted entries keep their small-queue freq), `evict_main` decrement-and-reinsert logic, and `MAX_FREQ = 3`. Fresh inserts into small still start at freq 0.

Invariants: the capacity bound `small.len() + main.len() <= capacity` holds because only the initial freq changes. Existing tests must still pass. Add an inline test: fill a capacity-10 cache so that key 1 is ghosted, re-put key 1, and assert that key 1 is in `main` with `freq == 1`.

## Rationale (optional)

A ghost hit is evidence of reuse at a distance longer than the small window. Under v001 these keys enter main at freq 0 and are the first to go on the next `evict_main` pass unless they are hit again. That treats them worse than keys graduated from small with freq 2–3. This variant tests whether one protective pass converts ghost re-admissions into hits. Unlike v002, it does not loosen small-queue graduation.
