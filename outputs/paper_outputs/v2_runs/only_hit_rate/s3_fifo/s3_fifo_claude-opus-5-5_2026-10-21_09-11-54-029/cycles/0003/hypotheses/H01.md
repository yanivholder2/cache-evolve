# H01

Insert ghost-readmitted keys at the eviction end of the main queue instead of the front, so they must be reused before the next main eviction to stay, raising hit-rate on workload-a.

## Parent

cycle/0002/v003

## Changes

Change only the ghost-hit branch of `S3Fifo::put` in `src/s3_fifo/mod.rs`. The other branches stay as they are.

Current behaviour: when `in_ghost` is true, the key is removed from `ghost`, `evict_main()` runs if main is full, and the new `Entry` (freq 0) is placed with `self.main.push_front(...)`. That gives it a full lap of main (about 1946 insertions) before it is first checked for eviction.

New behaviour:
- Keep removing the key from the ghost and keep calling `evict_main()` when `self.main.len() >= self.main_size`, as now.
- Insert the re-admitted entry with `self.main.push_back(Entry::new(key, value))` (the tail, which `evict_main` pops from) instead of `push_front`, still with `freq = 0`.
- As a result, the next `evict_main()` call looks at this entry first. If it was hit at least once since re-admission (`get` raised freq to 1 or more), the existing second-chance loop decrements freq and moves it to the front for a full lap. If it was not hit, it is evicted right away. That eviction is the "require a second reuse signal" rule.
- Do not change `evict_main`, `evict_small`, `MAX_FREQ`, the 5% partition, or ghost sizing (`main_size`).

Edge case: when `evict_main()` runs inside the ghost branch it runs before the push, so the newly re-admitted entry is never its own victim on the same `put`. Keep that order.

Tests: the existing `ghost_hit_promotes_back_to_main` test must still pass, since the key is still in `main`. Add a unit test showing that a ghost-readmitted key with freq 0 is the first victim on the next main eviction, and that one with freq ≥ 1 survives it.

## Rationale (optional)

Both cycles found that lenient re-admission loses (the ghost freq credit and the larger ghost both lost), and cycle 0002's open question asks directly whether stricter re-admission, such as tail insertion, pays off. This is the most targeted form of that change. One ghost hit only buys a probationary slot in main, so main capacity stays with keys that have proven reuse.
