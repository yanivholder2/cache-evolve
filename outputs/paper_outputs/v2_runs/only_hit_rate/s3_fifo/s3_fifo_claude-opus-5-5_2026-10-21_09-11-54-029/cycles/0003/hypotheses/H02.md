# H02

Replace the linear small/main/ghost scans with hash-indexed lookups while keeping the eviction decisions identical, which cuts per-op-time and leaves hit-rate exactly at the incumbent's 0.7275.

## Parent

cycle/0002/v003

## Changes

This is a behaviour-neutral data-structure port of v003's policy in `src/s3_fifo/mod.rs`. It is the indexed-structure port that the Continuations of cycles 0001 and 0002 asked for and that has not been done yet.

1. **Resident index.** Add `index: HashMap<K, (Queue, u64)>` (or a slab of entries keyed by a stable slot id) so that `get`, `find_entry_mut`, and the "already resident" check in `put` are O(1) instead of `small.iter_mut().chain(main.iter_mut()).find(..)`. A simple design is to store the entries in a `Vec<Option<Entry<K,V>>>` slab with a free list. `small` and `main` then become `VecDeque<usize>` FIFOs of slot ids, and `index: HashMap<K, usize>` maps each key to its slot. `freq` lives in the slab entry, so `get` updates it in place.
2. **Ghost index.** Keep `ghost: VecDeque<K>` for FIFO order. Add `ghost_set: HashMap<K, u64>` that maps each key to the sequence number of its newest ghost insertion, and keep a sequence number alongside each `ghost` element (`VecDeque<(K, u64)>`). Removing a key on a ghost hit becomes `ghost_set.remove(&key)`, and the stale deque element is skipped lazily. When popping the ghost tail for capacity, remove from `ghost_set` only if the sequence numbers match. Ghost capacity must count only live entries (track `ghost_live: usize`) so that the effective ghost size stays exactly `main_size` as in v003. Pop stale elements from the back until a live one is evicted. Alternatively, compact the deque whenever it grows beyond 2× `main_size`.
3. **Policy preserved exactly.** The 5% split (`(capacity/20).max(1).min(capacity-1)`), `MAX_FREQ = 3`, the `freq > 1` graduation in `evict_small`, ghost-hit insertion at main front with freq 0, the second-chance decrement loop in `evict_main`, and the order of `push_front`/`pop_back` all stay unchanged. The sequence of evictions must match v003 for the same trace.
4. **Bounds.** Keep the public API (`try_new`, `new`, `get`, `put`) and the `framework::Cache` impl with the same signatures. If adding `Eq + Hash` bounds is needed, add them to the struct/impl in a way that still compiles with the unmodified `s3_fifo_jni.rs` (it uses concrete integer keys). Check this by building, and do not touch the JNI file.
5. **Tests.** Update the in-module unit tests that poke at `cache.main`/`cache.small` directly, such as `main_eviction_uses_frequency_second_chance`, to use small helper accessors (for example a `#[cfg(test)] fn main_keys(&self) -> Vec<K>`) so that they assert the same behaviour. Add a test that replays a pseudo-random key stream through both a reference copy of the v003 logic and the new structure, and asserts identical hit/miss sequences.

## Rationale (optional)

Every winning change has lengthened the linear ghost scan, which is O(main_size) on every `put` miss, plus an O(capacity) resident scan on every `get`. That cost has never been measured. The port makes per-op-time sub-linear without trading any hit-rate, and it lets later policy tweaks build on a faster structure.
