# H03

Replacing the linear queue and ghost scans with a hash index over slab-allocated entries, so lookups and queue-to-queue moves cost O(1), cuts get p50 per-op time well below the baseline's 248 ns without changing hit rate.

## Parent

baseline

## Changes

Rewrite the storage in src/s3_fifo/mod.rs. Policy behaviour must stay exactly
the same as the baseline. Only data structures change.

- **Slab of entries.** Add `slots: Vec<Entry<K, V>>` (preallocated to
  `capacity`) and a `free: Vec<u32>` list. `Entry` keeps `key`, `value`, and
  `freq: u8`, plus `queue: u8` (0 = small, 1 = main) if needed. Change
  `small` and `main` to `VecDeque<u32>`, which hold slot indices instead of
  entries.
- **Resident index.** Add `index: HashMap<K, u32>` that maps a key to its slot.
  `get` becomes `index.get(key)` → `slots[i].freq = min(freq+1, MAX_FREQ)` →
  return `&slots[i].value`, with no scan. `put` on an existing key updates the
  value in place through the index. Use a fast hasher for this map and for the
  ghost map: an FxHash-style multiply hasher implemented locally in mod.rs,
  because Cargo.toml cannot be edited.
- **Ghost membership.** Add `ghost_set: HashMap<K, u64>` that maps a key to a
  monotonically increasing insertion sequence number. Keep the ghost FIFO as
  `VecDeque<(K, u64)>`. Lookup on `put` becomes `ghost_set.remove(&key)`. When
  the ghost FIFO is full, pop the back and remove it from `ghost_set` only if
  the stored sequence number matches. That replaces the O(n) `retain` with lazy
  deletion. Count `ghost_set.len()` (not the deque length) against
  `main_size`. Drain stale deque entries while popping, so capacity matches the
  baseline's.
- **Movement.** `evict_small` pops a slot index from `small`. On graduation
  (`freq > 1`, same as the baseline), push the index to the front of `main`
  without moving the entry. On demotion, remove the key from `index`, push the
  key into the ghost structures, and return the slot to `free`. In
  `evict_main`, the second-chance loop works on indices. The final victim's key
  is removed from `index` and its slot is freed.
- Add `K: Eq + Hash` to the inherent `impl` bounds; the trait impl already
  requires them. Keep the public signatures `try_new`, `new`, `get`, and `put`
  unchanged so that `s3_fifo_jni.rs` still compiles untouched.

Invariants to preserve: `small.len() <= small_size`,
`main.len() <= main_size`, `index.len() == small.len() + main.len()`, number of
live ghost keys ≤ `main_size`, and the same graduation, demotion, and eviction
order as the baseline. Update the unit tests that poke `cache.main` or
`cache.small` directly so they go through the slab, or add small test-only
helpers. Their assertions must stay the same.

## Rationale (optional)

At capacity 2048, every get scans up to 2048 entries, and every miss-put also
scans the ghost queue (up to 1536 keys), plus a `retain` on ghost hits. That
explains the 248 ns get p50 and the 4150 ns put p99. The hit-rate dimension
should stay at exactly 0.7164, so the change isolates the per-op-time
trade-off. It may cost some metadata bytes per entry and is a candidate base
for later hit-rate variants.
