# H02

Inserting new main entries just behind the SIEVE hand, instead of at the main head, will raise hit-rate on workload-a because every freq-0 newcomer is guaranteed a full lap before the hand examines it.

## Parent

cycle/0007/v002

## Changes

In `src/s3_fifo/mod.rs`, add `main_insert_behind_hand(idx)` and use it in place of `main_push_head(idx)` at both main insertion sites. Those are the ghost-hit re-admission in `put()` and graduation in `evict_small()`. In both places the call comes after any `evict_main()`, so the hand position is already updated.

"Behind the hand" means the slot the hand will reach last. The hand moves from tail toward head (following `prev`). So the new entry should be linked as the hand's `next` neighbour, between `hand` and `hand.next`. The hand must not move: it should next examine `hand` itself, and examine the new entry only after a full wrap.

Edge cases:
- If `self.hand == NIL`, the next sweep starts at `main_tail`. "Examined last" then means the head, so fall back to `main_push_head`.
- If `hand.next == NIL` (the hand is at the tail), link the new entry as the new tail: set `main_tail = idx`, `hand.next = idx`, `idx.prev = hand`, `idx.next = NIL`.
- In every case, increment `main_len` and keep `prev`/`next` consistent. Write a general `main_link_after(anchor, idx)` helper.

Keep the following unchanged: the decrement-by-one sweep, `MAX_FREQ = 7`, freq 0 on re-admission, the 5% split, ghosting main victims, and the ring ghost.

Update the tests:
- In `RefS3Fifo`, replace `main_push_front` with the same rule. Insert at `hand_pos + 1` in the VecDeque (front = head, so a larger index is closer to the tail). The hand index does not change. When the hand is `None`, push to the front and keep the hand `None`.
- Keep the full-state comparison in `matches_ring_reference_on_pseudo_random_streams`.
- Update the expected orders in `main_eviction_uses_frequency_second_chance` and `main_victim_is_ghosted_and_returns_to_main`.
- Add a test with the hand in mid-list. A newly inserted freq-0 key must survive at least `main_len - 1` further `evict_main` calls while older freq-0 keys are evicted first.

## Rationale

Cycle 7's inferred mechanism is that freq-0 ghost re-entries now get a full sweep to prove reuse. That only holds when the hand is far from the head. With head insertion, a newcomer placed while the hand is near the head is examined almost immediately (SIEVE's known quick demotion). Inserting behind the hand makes the full-lap guarantee hold every time, which tests the mechanism directly. A gain confirms it. A loss means quick demotion of some newcomers was itself useful filtering.
