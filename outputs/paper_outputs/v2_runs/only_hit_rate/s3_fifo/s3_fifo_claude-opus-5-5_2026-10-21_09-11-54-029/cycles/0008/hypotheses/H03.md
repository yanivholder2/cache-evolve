# H03

Combining the identity-hashed ghost map with 32-bit fingerprints on top of the SIEVE winner will cut per-op-time and metadata-size, with hit-rate staying within ±0.0005 of cycle/0007/v002.

## Parent

cycle/0007/v002

## Changes

This change is representation-only. Do not change the policy in `src/s3_fifo/mod.rs`. Port the two proven policy-neutral changes from cycle 7 (v001 and v003) onto v002's SIEVE code:

1. **32-bit fingerprints** (from cycle/0007/v003). `fingerprint()` returns `u32`, computed by folding the 64-bit `DefaultHasher` output as `(h ^ (h >> 32)) as u32` and mapping 0 to 1. `ghost_ring` becomes `Vec<u32>`. `ghost_map` becomes a map from `u32` to `u32`. `ghost_insert` and the ghost-hit path in `put()` use `u32` throughout. In `try_new`, add a guard that `main_size.max(1)` fits in `u32`.
2. **Identity hasher on `ghost_map`** (from cycle/0007/v001). Add the `IdentityHasher` and `BuildHasherDefault` type. Because the keys are now `u32`, implement `write_u32` (`self.0 = x as u64`). Without it, `u32` keys fall through to the byte-folding fallback. Spread the bits in `finish()`, for example by returning `self.0 | (self.0 << 32)` or by multiplying by a 64-bit odd constant. hashbrown takes control bits from the top 7 bits of the hash, so a plain zero-extended `u32` would put every key in the same control-byte group and perform badly. Declare `ghost_map: HashMap<u32, u32, IdentityBuild>` and build it with `HashMap::with_capacity_and_hasher(main_size + 1, IdentityBuild::default())`.

Leave the following unchanged: the SIEVE `evict_main`, the intrusive `prev`/`next` links, the hand, `MAX_FREQ = 7`, the 5% split, and ghosting of main victims.

Update the tests:
- In `matches_ring_reference_on_pseudo_random_streams`, build `ref_ring` as `Vec<u32>` from the new `fingerprint`. Keep the full small, main, hand and ghost-state comparison.
- `fingerprint_never_zero_and_deterministic` keeps working with `u32`.
- Add a test that inserts about 10k distinct fingerprints into `ghost_map` and checks the round-trip lookups, so the identity-hasher path is exercised for `u32`.

## Rationale

Cycle 7's continuation asked for both changes to be folded into the winner as one cost-only change. Each was verified independently: v001 was bit-for-bit identical, and v003 was within noise at about main_size/2^32 false-hit odds. This variant gives the lineage a lean ghost (4-byte ring slots and no SipHash rehash on ghost lookups) while the policy experiments in H01 and H02 run. Hit-rate outside ±0.0005 of the parent would point to a porting bug, not a policy effect.
