# H01

Capping SIEVE main-queue retention at two laps, so keys with at least two main hits survive two hand passes and keys with one hit survive one, will raise hit-rate on workload-a over the single clear-on-pass visited bit.

## Parent

cycle/0008/v001

## Changes

Keep the policy the same everywhere except for how the hand spends credit in `evict_main()`.

- In the survivor branch of `evict_main()` (currently `if e.freq > 0 { e.freq = 0; ... }`), replace `e.freq = 0` with a two-level main retention step: `e.freq = if e.freq >= 2 { 1 } else { 0 };`. So a main entry with freq ≥ 2 survives this pass with one lap of credit left, and an entry with freq 1 is cleared as it is today. A survivor still keeps its position, and the hand still moves to `prev` (wrapping to `main_tail`).
- Leave `get()` alone: it still saturates at `MAX_FREQ = 7`. Leave the small-queue graduation test (`freq > 1` in `evict_small`) alone too. Small graduation keeps the full counter. The cap of 2 applies only to how the hand spends main credit, so a key with more than 2 hits keeps at most 2 laps in main.
- Leave the rest unchanged: ghost re-admission at the head with freq 0, ghosting main victims, the fingerprint ring and the 5% split.
- Update the in-file reference `RefS3Fifo::evict_main` in the same way (`freq >= 2 → 1`, otherwise `→ 0`), so that `matches_ring_reference_on_pseudo_random_streams` still checks main order, freq and hand exactly.
- Update the unit tests that pin clear-on-pass semantics:
  - `sieve_pass_clears_credit_fully`: freq 5 should now become 1 after one pass, not 0.
  - `max_freq_key_survives_one_main_pass_then_evicted_on_second`: rewrite it as "MAX_FREQ key survives two passes, evicted on third" (freq 7→1 on the first pass, 1→0 on the second, victim on the third). Add cold freq-0 newcomers at the head between sweeps so that each sweep has a victim.
- Update the header comment to describe the cycle-9 rule.

## Rationale

Cycle 8 showed that cap 7 with decrement-by-one under SIEVE gives too much retention, and that one visited lap is better. It left open whether the optimum is exactly one lap or a small number. Being able to retain a second lap separates keys that were hit repeatedly in main from keys that were hit once by chance, which is S3-FIFO's 2-bit counter idea. Worst-case sweep length stays bounded at about two laps. If hit-rate does not rise, or regresses, the single visited bit is confirmed as optimal under SIEVE.
