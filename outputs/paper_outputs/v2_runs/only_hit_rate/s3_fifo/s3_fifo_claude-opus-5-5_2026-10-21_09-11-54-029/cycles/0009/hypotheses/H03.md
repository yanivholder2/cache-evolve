# H03

Rebasing the SIEVE clear-on-pass winner onto a 32-bit fingerprint ring with an identity-hashed ghost map and a cheaper non-SipHash fingerprint mixer will lower per-op-time and metadata-size, with hit-rate unchanged.

## Parent

cycle/0008/v001

## Changes

This is a cost-only change. Policy must stay exactly the same apart from fingerprint collisions, which are negligible at this size. Cycle 8's continuation asked for this rebase. The cycle-8 v003 representation was verified policy-neutral, but on the cycle-7 lineage, not on v001.

- **Fingerprint.** Replace `fingerprint()` (currently a `DefaultHasher`/SipHash over the key, returning `u64`) with a function that returns `u32`:
  - Hash the key once through a small fixed-seed FxHash-style `Hasher` defined in the overlay. Use multiply-rotate per `write_u64`/`write` chunk, with a fixed seed, and make it deterministic.
  - Finish with a 64-bit avalanche mix, e.g. the splitmix64 finalizer.
  - Fold to 32 bits as `(h ^ (h >> 32)) as u32`.
  - Keep 0 reserved: map 0 to 1.
- **Ghost ring.** Change `ghost_ring` to `Vec<u32>` and `ghost_map` to `HashMap<u32, u32, BuildHasherDefault<IdentityU32Hasher>>`. `IdentityU32Hasher` is a tiny hasher defined in the overlay. Its `write_u32` stores the value, its `finish` returns it widened (or multiplied by an odd constant for bucket spread), and its `write` panics or falls back to a byte fold. Keep `with_capacity(main_size + 1)`.
- **Call sites.** Update `put()` (ghost lookup) and `ghost_insert()` to the `u32` types. Everything else stays the same: `evict_main` clear-on-pass SIEVE, `evict_small` with graduation at `freq > 1`, head/freq-0 re-admission, ghosting main victims, the 5% split and `MAX_FREQ = 7`.
- **Tests.** In `matches_ring_reference_on_pseudo_random_streams`, map `ref_ring` with the new `u32` fingerprint (`unwrap_or(0)` as `u32`). Keep all order, freq and hand assertions as they are. Update `fingerprint_never_zero_and_deterministic` for the `u32` return type. Add a test that the ghost map uses the identity hasher (a construction smoke test is enough).
- **Header comment.** Note the cycle-9 representation change.

## Rationale

The incumbent hashes each missed key with SipHash twice: once in `put()` and once more in `ghost_insert()` when that key is later evicted. It then hashes the 64-bit fingerprint again with SipHash inside `ghost_map`. Switching to a cheap mixer and identity bucketing removes most of that work. Halving the ring entries cuts ghost metadata from about 8 B to about 4 B per main slot, plus smaller map keys. Hit-rate should match cycle/0008/v001 within ±0.0005. per-op-time and metadata-size should both improve if they are evaluated. This also gives the cycles 9+ policy variants a cheaper base.
