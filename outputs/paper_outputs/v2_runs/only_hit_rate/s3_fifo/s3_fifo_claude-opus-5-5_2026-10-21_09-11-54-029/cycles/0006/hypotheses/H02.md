# H02

Replacing v003's key-cloning lazy ghost (a VecDeque plus a HashMap of cloned keys, with periodic `retain` compaction) by a fixed-size ring buffer of 64-bit key fingerprints will cut per-op-time and metadata-size while keeping hit-rate within ±0.001 of 0.7295.

## Parent

cycle/0005/v003

## Changes

All edits are in `src/s3_fifo/mod.rs`. Do not change policy: small 5%, `MAX_FREQ = 7`, graduation at freq > 1, front-of-main re-admission at freq 0, main victims ghosted, ghost live cap `main_size`.

1. Add `fn fingerprint(key: &K) -> u64`. Hash the key with a fixed-seed hasher, for example `std::collections::hash_map::DefaultHasher::new()` (it is deterministic), and write `key.hash(&mut h)`. Map a result of 0 to 1, because 0 is reserved as the "empty" marker.
2. Replace `ghost: VecDeque<(K, u64)>`, `ghost_set: HashMap<K, u64>` and `ghost_seq` with:
   - `ghost_ring: Vec<u64>` of length `main_size.max(1)`, initialised to 0, and `ghost_head: usize`.
   - `ghost_map: HashMap<u64, u32>`, which maps each fingerprint to its ring slot. Pre-allocate it with capacity `main_size + 1`.
3. `ghost_insert(key)`:
   - Compute `fp`.
   - Let `slot = ghost_head`. If `ghost_ring[slot] != 0` and `ghost_map.get(&ghost_ring[slot]) == Some(&slot)`, remove that fingerprint from `ghost_map`. This evicts the oldest entry and gives FIFO order with a capacity of `main_size`.
   - Write `ghost_ring[slot] = fp` and `ghost_map.insert(fp, slot)`. If `fp` was already present at another slot, the insert overwrites the map entry and the old slot goes stale, which the slot check above handles.
   - Advance `ghost_head = (ghost_head + 1) % len`.
4. Ghost hit in `put`: replace it with `if let Some(slot) = self.ghost_map.remove(&fp) { self.ghost_ring[slot] = 0; ... }` and keep the existing front-of-main path.
5. Delete the `retain` compaction branch. The ring is fixed-size, so there are no compaction spikes and no cloned `K` in the ghost.
6. Note one behavioural difference. Removing an entry on a ghost hit leaves a hole in the ring and does not shift entries. The old structure also kept stale holes but bounded live count rather than position, so the effective ghost window can be slightly *larger* in the new structure. Fingerprint collisions (probability about 2^-64 per pair) are accepted. Document both in a comment.
7. Tests: update the test-only `ghost_keys()` helper. Fingerprints cannot be reversed, so change the reference-equivalence test to compare `small` and `main` queues exactly and to check ghost membership by fingerprint (`ghost_map.contains_key(&fingerprint(&k))`) for keys in the reference ghost. Bound the comparison to the steps before the first divergence caused by the hole semantics, or make the reference ring-based too. The simplest option is to rewrite `RefS3Fifo::ghost_push` and its ghost-hit removal to mimic ring-with-holes semantics over `Vec<Option<i64>>`. Keep `capacity_bound_never_exceeded` and add `ghost_map.len() <= main_size`.

## Rationale

The incumbent lineage has accumulated ghost work that has never been costed: a doubled ghost source, a `K` clone per ghost insert, and periodic O(n) `retain` compaction. Five cycles of Continuations have asked for cost-side progress. This variant holds policy fixed and targets per-op-time and metadata-size directly. Ghost metadata drops from (`K` + u64 in the deque, plus `K` + u64 in the map, at up to 2x length) to (u64 in the ring, plus u64 + u32 in the map). Hit-rate should stay within noise.
