# H03

Making the small-queue size adaptive (ARC-style), growing it on ghost hits from small rejects and shrinking it on ghost hits from main victims within [1%, 10%] of capacity, will raise hit-rate on workload-a above v003's 0.7295 by tracking phase changes that the fixed 5% split cannot.

## Parent

cycle/0005/v003

## Changes

All edits are in `src/s3_fifo/mod.rs`. Keep `MAX_FREQ = 7`, graduation at freq > 1, front-of-main re-admission at freq 0, and the shared ghost with live cap fixed at the *initial* `main_size`. The ghost cap must not move as the split adapts.

1. Add fields `capacity: usize`, `small_min = (capacity / 100).max(1)`, `small_max = (capacity / 10).max(1)` (both clamped to `<= capacity - 1` when capacity > 1), and `ghost_cap` (the initial `main_size`). `small_size` starts at 5% as today. `main_size` becomes the derived value `capacity - small_size`. Update it whenever `small_size` changes.
2. Tag ghost entries by source. Change `ghost_set` to `HashMap<K, (u64, bool /*from_main*/)>` and the deque to `(K, u64)` as now. Liveness compares the seq only. `evict_small` inserts with `from_main = false`, and `evict_main` inserts with `from_main = true`.
3. In `put`, on a ghost hit `(seq, from_main)`:
   - `from_main == false`: the small queue was too short to catch this reuse, so set `small_size = (small_size + 1).min(small_max)`.
   - `from_main == true`: main was too short, so set `small_size = small_size.saturating_sub(1).max(small_min)`.
   - Recompute `main_size`, then take the existing front-of-main path.
4. Capacity safety. Queue lengths may temporarily exceed their new targets after an adaptation, so make eviction decisions against the total:
   - Ghost-hit path: `while small.len() + main.len() >= capacity { if main.len() >= main_size || small.is_empty() { evict_main() } else { evict_small() } }`, then push to the front of main.
   - New-key path: `while small.len() + main.len() >= capacity || small.len() >= small_size { if small.len() >= small_size || main.is_empty() { evict_small() } else { evict_main() } }`, then push to the front of small.
   - `evict_small`'s graduation branch: make room in main only when `small.len() + main.len() >= capacity`. After `pop_back` the total has already dropped by 1, so in practice the check is `main.len() >= main_size` *and* the total stays bounded. Keep the invariant `small.len() + main.len() <= capacity` after every public call.
   - Guard `evict_main` against an empty main, where it is already a no-op loop.
5. `ghost_insert` uses `ghost_cap` in place of `main_size` for the live bound and for the compaction threshold `2 * ghost_cap + 16`.
6. Tests: the exact-equivalence reference test no longer applies. Replace it with an invariant fuzz test over the same pseudo-random streams that checks:
   - `index.len() == resident_len() <= capacity`
   - `small_min <= small_size <= small_max`
   - `ghost_set.len() <= ghost_cap`
   - no key is both resident and ghosted
   - every `get` hit returns the last value `put`

   Update `small_queue_is_five_percent_of_capacity` so it only asserts the *initial* size.

## Rationale

The static partition sweep is settled: 10%→5% helped, and below 5% was flat. But a single static point can be optimal on average while wrong in each phase. Ghost hits tagged by source, which v003 makes possible by ghosting main victims, are exactly ARC's adaptation signal. This tests a different axis from every prior cycle: *when* to use which split, not how large it is. Bounds of [1%, 10%] keep it inside the region already shown to be reasonable.
