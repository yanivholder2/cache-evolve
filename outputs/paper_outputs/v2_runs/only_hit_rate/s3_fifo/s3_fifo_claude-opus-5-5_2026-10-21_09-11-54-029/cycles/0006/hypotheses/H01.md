# H01

Giving main-queue eviction victims their own ghost budget, separate from small-queue rejects, will raise hit-rate on workload-a above v003's 0.7295 by removing the shared-budget dilution of small-queue ghost evidence.

## Parent

cycle/0005/v003

## Changes

All edits are in `src/s3_fifo/mod.rs`. Re-admission semantics stay exactly as in v003: on any ghost hit, the key goes to the front of main with freq 0.

1. Split the ghost into two independent lazy-deleted FIFOs that share one lookup map:
   - `ghost_small: VecDeque<(K, u64)>`, which records small-queue rejects from `evict_small`. Cap it at `main_size` live entries, the same budget small rejects had before cycle 0005.
   - `ghost_main: VecDeque<(K, u64)>`, which records freq-0 victims from `evict_main`. Cap it at `main_victim_ghost_size = (main_size / 2).max(1)` live entries. Make that a named constant-derived field so it can be swept later.
   - Keep one `ghost_set: HashMap<K, (u64, GhostSrc)>` where `GhostSrc` is a `Small | Main` enum. A deque element is live only if `ghost_set.get(k) == Some(&(seq, src))` and `src` matches that deque. One shared `ghost_seq` counter is fine.
2. Replace `ghost_insert(key)` with `ghost_insert(key, src: GhostSrc)`:
   - Choose the target deque from `src`.
   - Count live entries per source by keeping two counters, `ghost_small_live` and `ghost_main_live`. Increment the counter on insert. Decrement it when an entry is removed by a ghost hit in `put` (use the stored `src`) or by eviction from the back of its own deque.
   - Evict from the back of that deque only, skipping stale elements, until that source's live count is below its cap.
   - Compaction: when a deque's length exceeds `2 * cap + 16`, `retain` only that deque's live elements.
3. In `put`, `self.ghost_set.remove(&key)` now returns `(seq, src)`. Decrement the matching live counter and then follow the unchanged front-of-main path.
4. In `evict_main`, call `ghost_insert(entry.key, GhostSrc::Main)`. In `evict_small`, call `ghost_insert(entry.key, GhostSrc::Small)`.
5. Preserve these invariants: `index.len() == small.len() + main.len() <= capacity`; `ghost_small_live <= main_size`; `ghost_main_live <= main_victim_ghost_size`; and no key is both resident and in `ghost_set`. A small reject of key K that is already in `ghost_main` cannot happen, because K would have been a ghost hit and not entered small. Still, `insert` must overwrite the map entry, and the old deque element becomes stale.
6. Update the in-file reference model (`RefS3Fifo`) to use two `VecDeque<i64>` ghosts with the same caps. Keep `matches_v003_reference_on_pseudo_random_streams` (rename it as appropriate) and `ghost_stays_bounded_with_lazy_deletion` passing, with bounds updated per deque.

## Rationale

v003's insight says the hit-rate gain from ghosting main victims comes with an unmeasured dilution cost: small rejects now leave the shared `main_size` ghost sooner. This variant isolates that lever. It restores the full ghost window for small rejects and adds main-victim evidence on top. If hit-rate rises, dilution was hiding part of the gain. If it is flat, the main-victim signal is simply small on this trace. This is the only policy lever the cycle 0005 Continuation still recommends.
