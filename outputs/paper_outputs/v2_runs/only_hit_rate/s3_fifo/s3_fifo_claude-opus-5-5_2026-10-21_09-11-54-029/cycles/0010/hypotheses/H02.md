# H02

Shrinking the small queue from 5% to 2.5% of capacity will raise hit-rate under clear-on-pass SIEVE, because SIEVE's main queue is scan-resistant enough to use the extra space better than the admission filter does.

## Parent

cycle/0009/v003

## Changes

1. In `S3Fifo::try_new()`, change the small-queue size from `(capacity / 20).max(1).min(capacity - 1)` to `(capacity / 40).max(1).min(capacity - 1)`. Keep the `capacity == 1` special case.
   - At capacity 2048 this gives `small_size = 51` and `main_size = 1997`.
   - `main_size` is still `capacity - small_size`. The ghost ring length still follows `main_size.max(1)`, so the ghost grows only as main grows; it gets no separate budget.
2. Update the matching size formula in `RefS3Fifo::new` in the test module so the lockstep reference test still passes.
3. Rename or update `small_queue_is_five_percent_of_capacity`: assert `small_size == 51`, `main_size == 1997` and `ghost_ring.len() == 1997` at capacity 2048.
4. Leave the rest unchanged: clear-on-pass SIEVE eviction, graduation at `freq > 1`, ghost re-admission at the head with freq 0, ghosting of main victims, and the cheap fingerprint representation.

## Rationale (optional)

The 5% split was tuned in cycles 0001–0002 under FIFO-reinsertion main. Main-queue size was the lever there, and the gain curve was flattening but still positive. SIEVE (0007–0008) changed how main ranks residents, and the split has not been re-checked since. Cross-cycle insights list this as an open question. If the result is flat or negative, that confirms the split is settled under SIEVE.
