# H01

Inserting ghost re-admissions just ahead of the SIEVE hand, not at the main head, will raise hit-rate on workload-a because a re-admitted key gets only a short window to prove reuse before it is examined.

## Parent

cycle/0009/v003

## Changes

Only the ghost-hit branch of `S3Fifo::put()` changes. Small-queue graduation in `evict_small()` keeps using `main_push_head`.

1. Add a helper `main_insert_before_hand(&mut self, idx: usize)`. It links slot `idx` on the head side of the hand: it becomes the `prev` neighbour of `self.hand`, sitting between `hand` and the hand's old `prev`. Because the hand sweeps toward the head (along `prev`), the new entry is the next thing examined after the hand's current entry. Fix up `main_head` when the hand's old `prev` was NIL, and increment `main_len`. Do not move `self.hand`.
   - If `self.hand == NIL` (the next sweep restarts at the tail), or main is empty, fall back to `main_push_head(idx)`.
2. In the ghost-hit branch of `put()`, run `evict_main()` first as today when `main_len >= main_size`. The hand may move during that call, so read `self.hand` only after it. Then `alloc` and call `main_insert_before_hand(idx)` instead of `main_push_head(idx)`. The entry is still re-admitted with `freq = 0`.
3. Leave the rest unchanged: clear-on-pass SIEVE, graduation at `freq > 1`, `MAX_FREQ = 7`, the 5% split, ghosting of main victims, and the 32-bit fingerprint ring with its identity-hashed map.
4. Tests in `src/s3_fifo/mod.rs`:
   - Update `RefS3Fifo::put` the same way. On a ghost hit, insert at index `hand` when `hand` is `Some(h)`, so the entry sits head-ward of the hand entry; then add 1 to `hand` so it still points at the same entry. When `hand` is `None`, push front.
   - Keep the lockstep test passing.
   - Add a unit test checking that a ghost-hit re-admission lands next to the hand, not at the head.

## Rationale (optional)

Earlier cycles showed that more generous re-admission (extra credit, behind-hand insertion) loses, while freq 0 at the head already performs well. Ghost hits bypass the small filter and force a main eviction, so they are the least-proven residents of main. This probes the untested opposite direction, less protection for re-admits, which both cycle-0009 open questions flagged. Cheap representation from v003 is kept.
