# H03

Halving the shared ghost ring to `main_size / 2` fingerprints will raise hit-rate on workload-a by reserving the small-filter bypass for keys that return quickly, so fewer stale returns force out main residents.

## Parent

cycle/0009/v003

## Changes

1. In `S3Fifo::try_new()`, change the ghost ring length from `main_size.max(1)` to `(main_size / 2).max(1)`.
   - At capacity 2048 this gives 973 entries instead of 1946.
   - Size `ghost_map`'s initial capacity to match: ring length + 1.
2. `ghost_insert()` already wraps at `ghost_ring.len()`, so it needs no logic change. Its eviction of the oldest live slot (the map still points at the slot) and its hole handling stay as they are.
3. Ghost hits are unchanged: they re-admit at the main head with freq 0 and run `evict_main()` first when main is full. Main victims and small rejects still share the one ring.
4. Tests in `src/s3_fifo/mod.rs`:
   - Update `RefS3Fifo::new` so `ring` has `(main_size / 2).max(1)` slots, keeping the lockstep test exact.
   - In `capacity_bound_never_exceeded`, `ghost_ring_is_fixed_size_and_bounded` and the lockstep test, change the bounds on `ghost_map.len()` to compare against `ghost_ring.len()`.
   - Update `small_queue_is_five_percent_of_capacity` to expect `ghost_ring.len() == 973`.
   - Check `main_victim_is_ghosted_and_returns_to_main` still holds; capacity 20 gives a ring of 9, which is enough for that scenario.
5. Leave the rest unchanged: clear-on-pass SIEVE, graduation at `freq > 1`, the 5% split, `MAX_FREQ = 7`, and the 32-bit identity-hashed fingerprints.

## Rationale (optional)

Every attempt to add ghost capacity lost (cycle 0002 larger or decoupled ghost, cycle 0006 separate main-victim budget). The stated reason is that each ghost hit bypasses the small filter and forces a main eviction. The opposite direction, a smaller ghost, has never been tested. If that mechanism is right, cutting the oldest half of ghost history should drop mostly low-value re-admissions. As a side effect it also halves ghost metadata.
