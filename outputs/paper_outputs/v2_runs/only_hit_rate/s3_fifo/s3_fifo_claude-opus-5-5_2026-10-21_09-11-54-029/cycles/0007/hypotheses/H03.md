# H03

Narrowing ghost fingerprints from u64 to u32, with a `u32 → u32` ghost map, will roughly halve ghost metadata-size and leave hit-rate within ±0.0005 of v002.

## Parent

cycle/0006/v002

## Changes

In `src/s3_fifo/mod.rs`, change `fingerprint<K: Hash>(key) -> u64` to return `u32`. Compute the `DefaultHasher` 64-bit result and fold it as `(h ^ (h >> 32)) as u32`, then keep the existing rule that maps 0 to 1 (0 is still the empty-slot sentinel). Change `ghost_ring: Vec<u64>` to `Vec<u32>` and `ghost_map: HashMap<u64, u32>` to `HashMap<u32, u32>`. Make the matching type changes in `try_new`, in `ghost_insert` (the `old` and `fp` locals), and in the ghost-hit branch of `put`. Keep the std default hasher on `ghost_map`; do not add an identity hasher here, so that this change stays separately attributable from H01.

Leave everything else unchanged: ring length (`main_size.max(1)`), hole-leaving removal, `ghost_head` advance, stale-slot check in `ghost_insert`, and all policy (5% split, cap 7, `freq > 1` graduation, front-of-main freq-0 re-admission, main victims ghosted).

Tests: update `fingerprint_never_zero_and_deterministic` and the ring comparison in `matches_ring_reference_on_pseudo_random_streams` (`ref_ring: Vec<u32>`) to the new width. Every other assertion stays as it is. With at most 1946 live fingerprints, the chance of a false ghost hit per miss is about 1946/2³² ≈ 4.5e-7. The reference test's small key spaces will still match exactly.

## Rationale (optional)

Each ghost entry costs a `u64` ring slot plus a `(u64, u32)` map bucket, about 8 + 16 bytes after padding. With `u32` it costs 4 + 8 bytes. That is roughly a 50% cut in the largest non-resident structure, which scales with `main_size`. A collision only causes a spurious front-of-main re-admission, so it is a policy error and never a correctness error, and at this rate it should not show up in hit-rate. A hit-rate change beyond ±0.0005 would refute the "collisions are negligible" assumption.
