# H01

Probing the fingerprint-keyed ghost map through an identity hasher, so each miss hashes the key once, will cut per-op-time and leave hit-rate exactly at v002's 0.7299.

## Parent

cycle/0006/v002

## Changes

In `src/s3_fifo/mod.rs`, add a private `IdentityHasher` (a `std::hash::Hasher` that stores one `u64`. `write_u64(x)` sets `self.0 = x`, `finish()` returns it, and `write(&[u8])` folds the bytes in little-endian order as a fallback that is never hit). Also add `type IdentityBuild = std::hash::BuildHasherDefault<IdentityHasher>;`. Change the field `ghost_map: HashMap<u64, u32>` to `ghost_map: HashMap<u64, u32, IdentityBuild>`. In `try_new`, build it with `HashMap::with_capacity_and_hasher(main_size + 1, IdentityBuild::default())`.

The fingerprints are already SipHash outputs (`fingerprint()` via `DefaultHasher`), so they are uniformly distributed. hashbrown takes the top 7 bits as its control byte and the low bits as the bucket index, and both are well-mixed. Re-hashing adds nothing.

Do not change `fingerprint()`, the ring layout, `ghost_head`, `ghost_insert`, the ghost-hit path in `put`, `evict_main`, `evict_small`, or any policy constant. Policy behaviour must be bit-for-bit identical to v002. `matches_ring_reference_on_pseudo_random_streams` and every other existing test must pass unchanged. Add one unit test that checks `IdentityHasher` returns its `write_u64` input from `finish()`.

## Rationale (optional)

The cycle 6 insight and the cross-cycle insights both named this as the cheap cost-side follow-up. v002's main new cost is two hashes per resident miss: SipHash for the fingerprint, then SipHash again inside `HashMap<u64,_>`. This change removes the second one. It is a pure representation change, so a hit-rate delta of exactly 0 confirms it is safe. Any per-op-time gain is attributable to this change alone.
