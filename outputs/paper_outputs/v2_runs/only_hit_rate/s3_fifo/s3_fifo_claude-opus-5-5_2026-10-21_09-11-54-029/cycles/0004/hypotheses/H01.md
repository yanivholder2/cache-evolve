# H01

Porting cycle/0003/v003's policy (5% small queue, MAX_FREQ = 7) onto the verified slab/index/lazy-ghost structure from cycle/0003/v002 will lower per-op-time while keeping hit-rate exactly at 0.7289.

## Parent

cycle/0003/v003

## Changes

Replace the linear-scan data structures in `src/s3_fifo/mod.rs` with the indexed structures from `cycle/0003/v002` (attempt 01 overlay, `src/s3_fifo/mod.rs`). Do not change the policy at all.

- Struct: `slab: Vec<Option<Entry<K,V>>>`, `free: Vec<usize>`, `index: HashMap<K, usize>`, `small: VecDeque<usize>`, `main: VecDeque<usize>`, and a ghost made of `ghost: VecDeque<(K, u64)>`, `ghost_set: HashMap<K, u64>` and `ghost_seq: u64`, with lazy deletion. The generic bound changes to `K: Eq + Hash + Clone`.
- `get`: O(1) lookup through `index`, then `freq = (freq + 1).min(MAX_FREQ)`.
- `put`: if `index` hits, update the value. Else, if `ghost_set.remove(&key)` succeeds, evict from main if full, then `alloc` and `main.push_front` at freq 0. Else, evict from small if full, then `alloc` and `small.push_front`.
- `evict_main`: the same CLOCK-style rotation as v003 (decrement freq and `push_front` slot ids until a freq-0 tail is found, then `release` it).
- `evict_small`: promote to main if `freq > 1`, otherwise `release` and `ghost_insert`.
- `ghost_insert`: copy it from v002. Cap live ghost entries at `main_size` by popping stale or oldest elements from the back, and compact once the deque exceeds `2*main_size + 16`.

Keep `MAX_FREQ: u8 = 7`, the `capacity / 20` small split, front-of-main freq-0 ghost re-admission and the `freq > 1` graduation threshold exactly as in v003.

Tests:
- Port v003's unit tests, including `main_resident_frequency_saturates_at_seven` and `max_freq_key_survives_seven_main_passes_then_evicted_on_eighth`, to use v002's test helpers (`test_push_main_back`, `test_push_small_front`, `main_keys`).
- Update v002's `matches_v003_reference_on_pseudo_random_streams` so that its embedded reference implementation is cycle/0003/v003's linear code with `MAX_FREQ = 7`. Hit/miss sequences and the small, main and ghost key orders must match exactly.

## Rationale (optional)

The last three cycle insights all asked for this combination, and it has never been done. The cap of 7 makes the linear lookups in `get`/`put` and the O(main_size) `ghost.iter().any` + `retain` even more expensive relative to the incumbent's policy work. This variant isolates the structural gain from any policy change, so later policy probes can be costed fairly. The expected outcome is the same hit-rate, a large per-op-time reduction, and a modest metadata-size increase from the HashMap index and the duplicated ghost keys.
