# H03

Replacing the per-item `Instant` timestamp and `usize` LFU counter with two `u32` logical fields will cut `Item<u64,u64>` from 40 to 24 bytes, reducing metadata size. Because position-based movement makes wall-clock time redundant, hit rate stays the same.

## Parent

baseline

## Changes

ClassicLRU orders items purely by their position in the bucket, so the 16-byte `Instant` adds nothing on the eval path. Shrink the item record and swap in a logical clock.

1. `src/shared/item.rs`:
   - Change the fields to `pub key: K, pub value: V, pub lfu_counter: u32, pub stamp: u32`.
     Remove `timestamp: Instant` and the `std::time::Instant` import.
   - Add `pub static LOGICAL_CLOCK: std::sync::atomic::AtomicU32 = AtomicU32::new(0);`
     and `pub fn next_stamp() -> u32 { LOGICAL_CLOCK.fetch_add(1, Ordering::Relaxed) }`.
   - `Item::new` sets `lfu_counter: 0, stamp: next_stamp()`.
   - Update `Display` to print `stamp` instead of `timestamp`. Keep the existing unit tests.
     `lfu_counter == 0` still holds, because integer literals infer `u32`.
2. `src/shared/eviction_policy.rs`:
   - `TimestampLRU::get_from_position`: replace `Instant::now()` with
     `items[position].stamp = crate::shared::item::next_stamp();`.
   - `TimestampLRU` eviction and promotion: `min_by_key` / `max_by_key` on `item.stamp`.
     Wrap-around is acceptable because about 4.29e9 ops is far beyond the eval trace.
   - `Lfu::get_from_position`: use `lfu_counter = lfu_counter.saturating_add(1)` so the
     narrower counter cannot overflow.
   - Remove the now-unused `std::time::Instant` import.
3. Grep the overlayable source (outside the protected surface) for any other `.timestamp`
   or `lfu_counter` uses and adapt them. The tests in `src/shared/traits/bucket.rs`
   compare `lfu_counter` with integer literals, so they keep compiling.

Leave the generic signature `Item<K, V>` unchanged, so the protected metadata-size binary still compiles. Do not change ClassicLRU's movement logic or the bucket. Hit rate should be unchanged.

## Rationale (optional)

Metadata-size summary is 40 bytes = 8 (key) + 8 (value) + 8 (usize counter) + 16 (Instant). Two u32 fields give 8 + 8 + 4 + 4 = 24 bytes with no padding, a 40% cut. As a side effect, `Item::new` no longer calls `Instant::now()` on every put, and each ClassicLRU `remove`/`push` shift moves 24-byte instead of 40-byte elements. Put p50 (143 ns) and get p50 (69 ns) should therefore not regress. To confirm or refute, check that the metadata-size report shows 24 bytes and that hit rate stays exactly 0.6611.
