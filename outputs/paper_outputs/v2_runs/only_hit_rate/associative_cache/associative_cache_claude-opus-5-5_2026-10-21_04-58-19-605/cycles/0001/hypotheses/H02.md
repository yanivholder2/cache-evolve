# H02

Swapping ClassicLRU's move-to-tail-on-hit for an in-place CLOCK reference bit with a per-bucket hand will lower get latency by removing all Vec shifting on hits, at near-LRU hit rate.

## Parent

baseline

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. The bucket's `Vec` becomes a circular CLOCK ring when the policy is ClassicLRU. Other policies keep the exact baseline behaviour.

1. Add fields to `AssociativeCacheBucket`: `clock_mode: bool` (set in `new()` to
   `settings.eviction_policy == EvictionPolicyKind::ClassicLRU`) and `hand: usize`
   (initialised to 0). Store the reference bit in the existing `Item::lfu_counter`
   (0 = unreferenced, 1 = referenced), so per-item metadata does not grow.
2. Override `get_from_position` in the `Bucket` impl. If `clock_mode`, set
   `self.items[position].lfu_counter = 1` and return `&self.items[position]`. Do not
   move anything. Otherwise delegate to the policy as today.
3. Override `put`:
   - Existing key: update the value and call `get_from_position(position)`. This sets
     the bit in clock mode. Return `(ref, None)`.
   - Not full (or `!clock_mode`): baseline path, push to the tail with `lfu_counter = 0`.
   - Full and `clock_mode`: run the CLOCK sweep. Loop: if `items[hand].lfu_counter == 1`,
     clear it to 0 and set `hand = (hand + 1) % len`. Otherwise this slot is the victim.
     Swap the new item into that slot with `std::mem::replace(&mut self.items[hand], item)`
     so the Vec is never shifted. Remember `idx = hand`, advance
     `hand = (hand + 1) % len`, and return `(&self.items[idx], Some(evicted))`. The loop
     ends within `len + 1` steps because each pass clears bits.
4. Override `evict_item` the same way, as a standalone sweep that ends in
   `remove_at(hand)`. When `clock_mode`, clamp `hand` with `hand % len.max(1)` after
   removal. Nothing on the hot path calls it, but it keeps the trait contract coherent.

Invariants: the victim slot is replaced in place, so size never exceeds `max_size` (P1). Only routed keys enter (P2). Lookup is still `get_position`'s linear scan, so a resident key is always found (P3). Geometry is untouched (P4). The trait-default tests in `src/shared/traits/bucket.rs` use `TestBucket` and are unaffected. The Fifo-based tests in `src/associative_cache/mod.rs` do not use clock mode.

## Rationale (optional)

Baseline get p50 is 69 ns, and every hit does `Vec::remove` + `push` over 40-byte items, shifting up to 15 elements. CLOCK makes a hit a single store. Its cost moves to misses, as a short bit sweep that replaces the miss path's existing `remove(0)` shift. To confirm or refute, measure get p50/p99 against 69/101 ns and check that hit rate stays within about 1 point of 0.6611.
