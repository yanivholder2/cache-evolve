# H02

Recording a ghost fingerprint only for keys evicted without ever being hit while resident will raise hit rate on workload-a above 0.731, because the 4-entry ring stops being diluted by aged-out residents with long reuse distances.

## Parent

cycle/0007/v001

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Keep everything else from
cycle/0007/v001 as it is: the `clock_mode` gate, `CLOCK_MAX = 3`, `GHOST_LEN = 4`, the
`ghost_fp` fingerprint (top 16 bits, 0 = empty), `admission_counter` (consumes the match and
returns 1), `clock_find_victim`, the hand resting on the newcomer, and the saturating increment.

1. Per-item "ever hit" flag, kept inside `Item::lfu_counter` so that no parallel vector has to
   follow `remove_at`/`push`: add `const HIT_FLAG: usize = 1 << 8;` and
   `const COUNT_MASK: usize = 0xFF;`. In clock mode the counter value is
   `lfu_counter & COUNT_MASK`, and the flag is `lfu_counter & HIT_FLAG`.
2. `get_from_position` (clock branch): read `c = lfu_counter & COUNT_MASK`, compute the new
   count exactly as now (saturating +1 up to `CLOCK_MAX`), and write back
   `new_count | HIT_FLAG`. This sets the flag on every hit, including the update-existing path
   in `put`.
3. `clock_find_victim`: test and decrement only the masked count. Keep the flag bit when
   decrementing: `lfu_counter -= 1` is still correct when the count is greater than 0, because
   the flag sits above bit 7. The victim condition becomes `(lfu_counter & COUNT_MASK) == 0`.
4. Admission: newcomers get `lfu_counter = admission_counter(..)`, with the flag clear, as now.
   A ghost-admitted newcomer has not been hit yet, so its flag is also clear.
5. Ghost recording, at both eviction sites (the in-place replace in `put` and `evict_item`):
   call `record_ghost(evicted.key)` only when `evicted.lfu_counter & HIT_FLAG == 0`. Evicted
   items that were hit at some point are not recorded in the ring.
6. Invariants: the count stays in `0..=CLOCK_MAX`. The sweep still terminates within
   `CLOCK_MAX * len + 1` steps. The bucket never holds more than `max_size` items. `get` still
   never reads the ring. Non-ClassicLRU policies keep the baseline behaviour exactly. Their
   `lfu_counter` is never touched by this code.

## Rationale (optional)

On GCLOCK, a resident that was hit and later evicted has had at least one full counter-decay
cycle. Its reuse distance is well beyond the bucket, which is the long-reuse population that
diluted the 16-entry ring in cycle 5. A never-hit newcomer evicted by the hand-on-newcomer
filter is exactly the key that the one-miss filter might have rejected too early, and a return
of that key is the signal ghost admission rewards. Cycle 6 found that the opposite filter
(exclude hit keys) hurt on the LRU line. Cycle 6 also noted that ghost lessons do not carry
over between lines, because each line's ring selects a different population. A ring-admission
filter has never been tried on CLOCK. The reward and the ring size stay unchanged, so only the
trigger gets more selective, as cycle 7 recommended. Refutation: a hit rate at or below 0.731
means aged-out residents' returns are as valuable as rejected newcomers' returns on CLOCK, and
the unfiltered ring is already complete.
