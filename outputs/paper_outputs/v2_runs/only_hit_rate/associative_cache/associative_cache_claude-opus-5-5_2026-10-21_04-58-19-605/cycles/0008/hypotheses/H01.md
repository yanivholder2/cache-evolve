# H01

Making a resident's first hit lift its GCLOCK counter from 0 straight to 2 (instead of 1) will raise hit rate on workload-a above 0.731, because keys that proved reuse while resident get more protection than ghost-admitted newcomers, which keep counter 1.

## Parent

cycle/0007/v001

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Keep everything else from
cycle/0007/v001 as it is: the `clock_mode` gate (ClassicLRU only), `CLOCK_MAX = 3`,
`GHOST_LEN = 4`, the 16-bit fingerprint ring (`ghost_fp`, `record_ghost`,
`admission_counter`, consumed on match, reward = counter 1), `clock_find_victim`, the in-place
`std::mem::replace` with `self.hand = idx` resting on the newcomer, and the `evict_item` path.

1. Edit the `clock_mode` branch of `get_from_position`. Today it does
   `if c < CLOCK_MAX { c + 1 }`. Change it to:
   - `c == 0` → set `lfu_counter = 2` (a `const FIRST_HIT_COUNTER: usize = 2;`).
   - `0 < c < CLOCK_MAX` → `c + 1`, as now.
   - `c == CLOCK_MAX` → unchanged.
2. The update-existing branch of `put` already goes through `get_from_position`, so it picks
   up the same rule. Do not add a separate path.
3. Do not change admission. Plain newcomers still enter at counter 0, and ghost-hit newcomers
   at counter 1. After this change, a newcomer hit while the hand rests on it survives two
   extra sweep passes, while a ghost-admitted newcomer that is never hit survives one.
4. Invariants: counters stay in `0..=CLOCK_MAX`. The sweep still terminates within
   `CLOCK_MAX * len + 1` steps. The bucket never holds more than `max_size` items. Non-ClassicLRU
   policies keep the baseline behaviour exactly.

## Rationale (optional)

Today a newcomer that is hit (real proof of reuse) and a newcomer admitted only because its
fingerprint was in the ghost ring (a weaker, indirect signal) both have counter 1. On the
1/8-depth LRU line, a hit sends the key all the way to MRU. On GCLOCK it buys only one pass, the
same as a ghost return. This change separates the two signals. Ghost admission keeps its small
reward and its selective trigger, which is the shape cycles 2, 4 and 7 found necessary. It is
also not frequency victim choice at the eviction end, which failed in cycle 3. It changes only
the size of the first hit's promotion. The magnitude of the hit-side reward has never been
probed on the CLOCK line. Refutation: a hit rate at or below 0.731 means one pass of protection
after a first hit is already enough on workload-a, and extra protection only shields stale keys.
