# H02

Adding a small per-bucket ghost list of recently evicted keys to v001 will raise hit rate. A missed key found in the ghost list goes straight to the MRU tail; all other new keys still go to the midpoint.

## Parent

cycle/0001/v001

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Do not modify `Item`; the ghost list is per-bucket state.

1. Add the constant `GHOST_SIZE: usize = 16`, so the ghost list has one entry per bucket slot at
   the eval geometry. Add these fields to `AssociativeCacheBucket`:
   `ghost: Vec<u64>` (created with capacity `GHOST_SIZE`) and `ghost_head: usize` (initialised
   to 0). Use them only when `midpoint_insert` is true. The entries are 64-bit key fingerprints.
   Compute each fingerprint by hashing the key with `std::collections::hash_map::DefaultHasher`,
   or any fixed-seed `Hasher`, to a `u64`. Use a hash function that differs from the bucket
   router's, or mix the bits, so that fingerprints within one bucket stay distinct.
2. In `put`, in the `midpoint_insert` miss path:
   - Before evicting, compute `fp = fingerprint(&item.key)` and check
     `let in_ghost = self.ghost.iter().position(|&g| g == fp)`.
   - Evict exactly as now (`self.evict_item()`, index 0 under ClassicLRU). If an item was
     evicted, write its fingerprint into the ring: push it while `ghost.len() < GHOST_SIZE`,
     otherwise overwrite `ghost[ghost_head]` and advance `ghost_head = (ghost_head + 1) % GHOST_SIZE`.
   - If `in_ghost` is `Some(g)`, remove that fingerprint so one ghost hit cannot promote twice.
     The cheap way is to overwrite it with a sentinel such as `0`, since the scan never matches
     the sentinel. If a real key ever hashes to 0, map it to 1. Then `self.items.push(item)` to the
     MRU tail and return a reference to the last element.
   - Otherwise, insert at `len * INSERT_DEPTH_NUM / INSERT_DEPTH_DEN` (the midpoint), as v001 does.
3. Leave the hit path (`get_from_position` → ClassicLRU move-to-tail) and the update-existing-key
   branch unchanged. Non-ClassicLRU policies never touch the ghost list.

Invariants: the capacity check still runs before the insert, so size never exceeds `max_size`.
The ghost list holds only fingerprints, never resident items, so lookups (`get_position`) and the
P2/P3 properties are unaffected. Geometry is unchanged.

## Rationale (optional)

Midpoint insertion protects reused keys from one-off keys. Its cost is that a key with a
re-reference distance slightly longer than half a bucket's lifetime gets evicted early again and
again, and it never earns MRU protection. A ghost list (the ARC/2Q "B1" idea, scaled down to one
bucket) detects these keys and inserts them at the tail on their next miss. One-off keys never
appear in the ghost list, so the midpoint filter still holds back scans. To confirm, check that
hit rate beats 0.695. `Item` size is unchanged, so metadata-size per item is unaffected. The ghost
list adds 128 B per bucket. The miss path gets one 16-entry u64 scan, which should be small next
to the existing Vec shifts.
