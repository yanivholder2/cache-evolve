# H01

Inserting new keys at index 0 (pure LIP) instead of v001's 1/8 depth will raise hit rate on workload-a above 0.7206 by giving keys used only once exactly one miss of probation in every bucket state.

## Parent

cycle/0003/v001

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Everything else stays exactly as in cycle/0003/v001.

1. In `put`'s depth-insertion branch (the `midpoint_insert` path after the capacity check),
   replace the computed index `self.items.len() * INSERT_DEPTH_NUM / INSERT_DEPTH_DEN` with a
   fixed index of `0`. Remove `INSERT_DEPTH_NUM` and `INSERT_DEPTH_DEN`, or set them to
   `0` / `1` and keep the formula, whichever is cleaner. Update the doc comment and the inline
   comment to say "pure LIP: newcomers enter at the eviction end".
2. Keep the hit path unchanged: `get_from_position` still delegates to
   `ClassicLRU::get_from_position`, which moves the item to the MRU tail. A newcomer therefore
   reaches protection only through a hit before the bucket's next miss.
3. Keep the update-existing-key branch, the `midpoint_insert` gate (ClassicLRU only), and the
   rule that the capacity check (`evict_item`, which removes index 0) runs before the insert.
   The new key is inserted after the old index-0 victim has been removed, so the newcomer
   never evicts itself. Bucket size never exceeds `max_size`, and geometry is unchanged.

## Rationale (optional)

This closes the depth bracket: midpoint 0.695 → 1/4 0.714 → 1/8 0.7206, with smaller gains at each step.
v003, a CLOCK filter with about one miss of grace, scored 0.716, which suggests the curve may
be flat or turning down near index 0. If index 0 beats 0.7206, the optimum is pure LIP. If it is
at or below 0.7206, then 1/8, which still keeps about one key of buffer behind the newcomer, is
the peak, and this line of depth tuning can be retired. Index 0 also shifts the whole bucket on
every miss (15 moves), so per-op-time should be recorded if it is available.
