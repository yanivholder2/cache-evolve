# H03

Adding a per-bucket 8-bit tag array to cycle/0009/v002, so that key lookup filters slots by tag before comparing full keys and one hash per op feeds both the tag and the ghost fingerprint, will lower per-op-time on workload-a while keeping hit rate exactly at 0.731.

## Parent

cycle/0009/v002

## Changes

This is a cost-only change (per-op-time) on the ClassicLRU/GCLOCK path. Today every get and put on the winner does a linear scan of up to 16 full keys through `get_position`. Every miss on a full bucket then also re-hashes the key in `ghost_fp`. This change replaces both with one cheap hash plus a SWAR tag probe.

1. **One hash per op.** In `associative_cache_bucket.rs`, add `#[inline] fn key_hash<K: Hash>(key: &K) -> u64`, which is the existing `FpHasher` + 64-bit mix that `ghost_fp` already computes. Derive two values from it:
   - `tag = (x >> 40) as u8 | 1`, which is non-zero. 0 marks an empty slot.
   - `fp`, the existing top-16-bit ghost fingerprint.
   Refactor `ghost_fp` and `admission_counter` to accept a precomputed `x` so the miss path hashes only once.
2. **Tag array.** Add `tags: [u8; 16]` to `AssociativeCacheBucket`, used only when `clock_mode` and `max_size <= 16`. Otherwise keep the default path. Keep it in lockstep with `items`:
   - push: write the tag at `items.len()`.
   - in-place replace in `put`: overwrite `tags[idx]`.
   - `evict_item`/`remove_at(idx)`: `copy_within(idx+1..len, idx)` and zero the last slot.
3. **Override `get_position`** in the `Bucket` impl for `AssociativeCacheBucket`. Implementing a trait default method in the impl is allowed, and `src/shared/traits/bucket.rs` may also be adjusted if it is not overridable. In clock mode:
   - Compute `x`, then the tag.
   - Load `tags` as two `u64` words and find matching bytes with the SWAR has-zero-byte trick on `word ^ (tag * 0x0101_0101_0101_0101)`.
   - For each candidate bit, in index order, compare `items[i].key == *key` and return the first match.
   - Tag collisions only cost an extra key compare, never correctness. Non-clock policies keep the default linear scan.
4. **Reuse the hash on a miss.** `put` already calls `get_position` and then, on a full bucket, `admission_counter`. Cache the `x` computed for the last lookup in a local variable: add a `get_position_hashed(&self, key) -> (Option<usize>, u64)` inner helper that `put` uses. Do not store `x` as bucket state.
5. **Unchanged:** GCLOCK +1 step, `CLOCK_MAX = 3`, hand on newcomer, the 4-entry ring with consume-on-match, the 24-byte `Item`. Metadata grows by 16 bytes per bucket, which is under 1 byte per entry.
6. **Invariants:** `get_position` returns exactly the same index as the linear scan for every key, so the hit/miss sequence and the victim sequence are identical to the parent. Add a `debug_assert!` in debug builds that compares the result against a plain scan.

## Rationale (optional)

Cycles 3, 7, 8 and 9 all showed that cost-only changes keep hit rate exactly. The open cost questions are whether fingerprint hashing on the miss path costs more than it saves, and whether hits are cheap enough. This variant attacks both. The hash is shared between lookup and ghost check, so the fingerprint becomes free on misses. Most non-matching slots are rejected with byte compares instead of 8-byte key loads spread over 24-byte items, as in Swiss tables and F14. Confirmation: per-op-time below the parent's (and below baseline's 69) with hit rate 0.731. Refutation: no per-op-time gain, which would mean `u64` key compares over 16 slots are already cheaper than one FNV hash per op, and the tag array should be dropped.
