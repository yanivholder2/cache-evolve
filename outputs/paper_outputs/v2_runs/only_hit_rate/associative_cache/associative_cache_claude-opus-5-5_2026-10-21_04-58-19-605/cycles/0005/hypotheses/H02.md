# H02

On the 1/8-depth LRU line, inserting a key at 1/4 depth instead of 1/8 when it is found in a 4-entry per-bucket ghost ring will raise hit rate on workload-a above 0.721, by moving v003's capped ghost admission onto the shift-based LRU line.

## Parent

cycle/0003/v001

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Keep cycle/0003/v001's
`midpoint_insert` gate (ClassicLRU only), the 1/8 insert depth for ordinary newcomers, the
eviction at index 0 through the existing `evict_item` / `ClassicLRU` path, and the hit path
(delegate to `self.eviction_policy.get_from_position`, which promotes to MRU) all unchanged.

1. Ghost ring: add `ghosts: [Option<K>; GHOST_LEN]` and `ghost_pos: u8` to
   `AssociativeCacheBucket`, with `const GHOST_LEN: usize = 4;`. Initialise them to
   `[None; GHOST_LEN]` and `0` in `new`. Add the same helpers as cycle/0004/v003:
   - `record_ghost(&mut self, key: K)` writes at `ghost_pos`, overwriting the oldest entry, and
     advances `ghost_pos` modulo `GHOST_LEN`.
   - `in_ghosts(&mut self, key: &K) -> bool` scans the ring linearly. On a match it sets that
     entry to `None` and returns `true`.
2. Recording: in `put`, when `self.midpoint_insert` is true and `self.is_full()`, call
   `self.evict_item()` as now. If it returns `Some(ev)`, call `self.record_ghost(ev.key)`.
   Record only on this miss path. Do not record on explicit removals.
3. Admission: in `put`'s `midpoint_insert` branch, call `in_ghosts(&item.key)` before the
   eviction, so a key cannot match the key it is about to displace. Then:
   - Ghost hit: `idx = self.items.len() * 1 / 4`, computed after the eviction (len 15 gives
     idx 3).
   - Otherwise: keep `idx = self.items.len() * 1 / 8` (len 15 gives idx 1).
   Then call `self.items.insert(idx, item)`. Add constants `GHOST_DEPTH_NUM = 1` and
   `GHOST_DEPTH_DEN = 4` next to the existing `INSERT_DEPTH_*` constants.
4. Invariants: the bucket never holds more than `max_size` items, because eviction still runs
   before the insert. The ring is bounded at 4 keys. `get` never consults the ring. When
   `midpoint_insert` is false, the baseline push-to-tail path stays unchanged.

## Rationale (optional)

The cycle 0004 open questions ask directly whether capped ghost admission carries over to the
1/8 LRU line. On CLOCK, the capped reward was one extra sweep pass. Here the matching capped
reward is a modestly deeper slot, two places above the normal newcomer and still well below the
midpoint. The uncapped version (MRU on a ghost hit, cycle 0002) hurt. A result above 0.721 would
show the ghost signal is independent of the policy line. A result at or below 0.721 would mean
LRU's one-slot buffer behind the newcomer already captures most of what the ghost ring gave CLOCK.
