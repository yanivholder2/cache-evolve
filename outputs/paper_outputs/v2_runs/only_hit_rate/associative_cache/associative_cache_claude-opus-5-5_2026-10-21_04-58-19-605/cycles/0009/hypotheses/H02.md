# H02

Shrinking the item record on cycle/0007/v001 by dropping the per-item `Instant` and narrowing `lfu_counter` from `usize` to `u32` will cut metadata-size from 40 bytes toward 24 bytes per `Item<u64,u64>`, while keeping hit rate on workload-a exactly at 0.731.

## Parent

cycle/0007/v001

## Changes

This is a cost-only change. The GCLOCK path never reads wall-clock time, and its counter never exceeds 3.

1. `src/shared/item.rs`:
   - Change the fields to `pub key: K, pub value: V, pub lfu_counter: u32, pub stamp: u32`. Remove `timestamp: Instant` and the `std::time::Instant` import.
   - Add a logical clock: `pub static LOGICAL_CLOCK: AtomicU32 = AtomicU32::new(0);` and `pub fn next_stamp() -> u32 { LOGICAL_CLOCK.fetch_add(1, Ordering::Relaxed) }`.
   - `Item::new` sets `lfu_counter: 0, stamp: next_stamp()`. Update `Display` to print `stamp`.
   - Keep the generic signature `Item<K, V>`, so the protected metadata-size binary in `src/bin/` still compiles unchanged.
2. `src/shared/eviction_policy.rs`:
   - In the timestamp-based LRU policy, replace `Instant::now()` with `crate::shared::item::next_stamp()`, and order eviction/promotion by `stamp` (`min_by_key` / `max_by_key`).
   - In the LFU policy, use `saturating_add(1)` on the now-`u32` counter.
   - Remove the unused `Instant` import.
3. `src/associative_cache/associative_cache_bucket.rs`:
   - Change `const CLOCK_MAX: usize = 3;` to `const CLOCK_MAX: u32 = 3;`.
   - Make `admission_counter` return `u32`.
   - Adjust the comparisons in `get_from_position` and `clock_find_victim` so they type-check.
   - Change no logic: same increment, same ceiling, same sweep, same hand placement, same 4-entry fingerprint ring.
4. Find any other `.timestamp` or `lfu_counter` uses in overlayable files (for example the default methods in `src/shared/traits/bucket.rs`) and adapt their types. Integer-literal comparisons infer `u32` without changes. Do not touch `tests/`, `src/test_utils/` or `src/bin/`. If a protected file names the `Instant` field or requires `usize`, keep that field's type and shrink only what compiles.
5. **Invariants:** the GCLOCK victim sequence is bit-for-bit identical to cycle/0007/v001, so the eviction trace on workload-a is unchanged. Non-ClassicLRU policies keep their ordering semantics, with a logical stamp in place of wall-clock time.

## Rationale (optional)

The hit-rate axis on workload-a has been flat at 0.731 for four cycles. Every continuation since cycle 5 says the next decisions depend on metadata-size and per-op-time. The leaderboard shows metadata-size 40 for the baseline: 8 key + 8 value + 8 `usize` counter + 16 `Instant`. Cycle 1 v003 tested this shrink on the baseline line and kept hit rate exactly, but it was never carried onto the winning CLOCK line. On the winning line, the `Instant` is pure dead weight, and the `Instant::now()` call in `Item::new` runs on every miss. Confirmation: metadata-size reports 24 and hit rate stays 0.7310. Refutation: any change in hit rate means some path still depends on the timestamp or the counter width. No change in metadata-size means the metric does not measure `Item`.
