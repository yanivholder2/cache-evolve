# H02

Replacing v003's self-referential grace duel with DIP-style set dueling (fixed strict and lenient leader buckets voting through a global miss counter) will raise hit rate on workload-a above 0.731 by letting follower buckets adopt the lenient one-sweep newcomer grace only when it measurably lowers misses.

## Parent

cycle/0004/v003

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Start from cycle/0004/v003 (not
cycle/0005/v003; drop that variant's `grace`/`rest` state entirely). Keep `GHOST_LEN = 4`,
`CLOCK_MAX = 3`, `admission_counter` (counter 1 on ghost hit, entry consumed), `record_ghost` at
both eviction sites, `clock_find_victim`, and saturating increments on hit.

1. Leader assignment: add a module-level `static BUCKET_SEQ: AtomicUsize = AtomicUsize::new(0);`
   and a per-bucket field `role: u8` set in `new` from `BUCKET_SEQ.fetch_add(1, Relaxed) % 32`:
   value 0 → `ROLE_STRICT_LEADER`, value 1 → `ROLE_LENIENT_LEADER`, anything else →
   `ROLE_FOLLOWER`. (1/16 of buckets are leaders.)
2. Global selector: add `static PSEL: AtomicI32 = AtomicI32::new(0);` with
   `const PSEL_MAX: i32 = 1023;`. On every ClassicLRU (`clock_mode`) miss that inserts a new item
   in `put` (both full and non-full branches): a strict leader increments PSEL (saturating at
   `PSEL_MAX`), a lenient leader decrements it (saturating at `-PSEL_MAX`). Use relaxed
   `fetch_update`/compare-exchange with clamping. Followers never touch PSEL. This is the
   unbiased negative signal: raw misses under each fixed policy, not outcomes of the bucket's own
   choice.
3. Policy choice in the full-bucket `clock_mode` branch of `put`, after
   `let idx = self.clock_find_victim();` and `std::mem::replace`:
   - lenient if `role == ROLE_LENIENT_LEADER`, or `role == ROLE_FOLLOWER && PSEL.load(Relaxed) > 0`;
     then set `self.hand = (idx + 1) % self.items.len()` so the newcomer is examined last in the
     next sweep.
   - strict otherwise; keep v003's `self.hand = idx`.
   Ghost admission stays identical under both policies.
4. Invariants: bucket never exceeds `max_size`; sweep terminates within `CLOCK_MAX * len + 1`
   steps; PSEL bounded in `[-PSEL_MAX, PSEL_MAX]`; strict leaders behave exactly like
   cycle/0004/v003; non-ClassicLRU policies keep baseline behaviour and never touch PSEL or
   BUCKET_SEQ. Note in a comment that the statics are process-global (shared across cache
   instances), which is acceptable for the single-cache simulator run.

## Rationale (optional)

Cycle 0005's duel could not leave strict mode because strict mode generated its own negative
evidence. The insights call for one retry with leader buckets and an unbiased signal before
declaring "strict + capped ghosts" the right shape. Fixed leaders running each policy permanently
give a clean A/B miss comparison; followers (15/16 of buckets) follow the winner. Refutation: hit
rate at or below 0.731 (with PSEL observed to settle negative, or lenient followers losing) closes
the leniency question on workload-a.
