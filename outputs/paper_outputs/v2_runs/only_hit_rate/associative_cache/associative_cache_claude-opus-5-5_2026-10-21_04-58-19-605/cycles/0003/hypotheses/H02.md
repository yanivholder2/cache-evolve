# H02

Making v001's eviction frequency-aware will raise hit rate on workload-a above 0.7139: the bucket counts hits per item and, on eviction, picks the lowest-count item among the 4 slots nearest the eviction end, instead of always picking index 0.

## Parent

cycle/0002/v001

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Insertion depth stays at 1/4 (`INSERT_DEPTH_NUM = 1, INSERT_DEPTH_DEN = 4`). All of the new behaviour applies only when `midpoint_insert` is true (ClassicLRU). Other policies keep the baseline behaviour exactly.

1. Add constants `VICTIM_WINDOW: usize = 4` and `HIT_COUNT_MAX: usize = 15`.
2. Hit counting: in `get_from_position`, when `midpoint_insert` is set, saturating-increment
   `self.items[position].lfu_counter` (cap at `HIT_COUNT_MAX`, cast to the field's type if it
   is not `usize`) *before* delegating to `self.eviction_policy.get_from_position`. The
   promotion to the MRU tail is unchanged. On the miss path in `put`, set
   `item.lfu_counter = 0` before inserting, so every newcomer starts at zero.
3. Victim selection: override `evict_item` in `impl Bucket for AssociativeCacheBucket`. If
   `!midpoint_insert` or the bucket is empty, use the trait-default path
   (`eviction_candidate_index()` then `remove_at`). Otherwise scan indices
   `0..min(VICTIM_WINDOW, len)` and pick the index with the smallest `lfu_counter`. Break ties
   toward the lowest index, so recency is the tie-break. Then `remove_at(idx)` and return
   `Some(evicted)`. `put` already calls `self.evict_item()` before inserting, so the
   capacity-before-insert invariant still holds.
4. Aging, to stop old frequent items from pinning the window: whenever the item evicted from
   the window had `lfu_counter == 0` and some other window item had a counter above 0, halve
   (`>>= 1`) the counters of the other items in the window. This is a single pass over at
   most 4 slots.
5. Keep the update-existing-key branch as it is. It calls `get_from_position`, which now also
   increments the counter.

Invariants: size never exceeds `max_size`. Lookup is a linear scan. Geometry is unchanged.
Do not edit `src/shared/traits/bucket.rs`.

## Rationale (optional)

Deep insertion filters keys used once, but its eviction rule is still pure recency at index 0.
A hot key that drifts to the bottom between bursts is evicted just like a cold one. GCLOCK
(cycle/0002/v003) showed that hit frequency carries signal on workload-a that recency throws
away. This hypothesis adds that signal to the winning line without touching the newcomer
filter: a newcomer at index 3 with count 0 is still the cheapest victim in the window. To
confirm, hit rate must be above 0.7139. If it is at or below that, frequency adds nothing once
deep insertion is in place. The extra miss cost is a scan of up to 4 slots.
