# H03

Leaving v003's GCLOCK hand on the newly inserted slot, instead of moving it past that slot, will raise hit rate above v003's 0.6831 toward v001's 0.7139, because a newcomer that has not been hit becomes the next eviction candidate.

## Parent

cycle/0002/v003

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Keep everything else from cycle/0002/v003: the `clock_mode` gate (ClassicLRU only), `CLOCK_MAX = 3`, saturating increments on hit, the in-place `std::mem::replace` on misses, and newcomers entering with `lfu_counter = 0`.

1. In `put`, in the `clock_mode && self.is_full()` branch, after
   `std::mem::replace(&mut self.items[idx], item)`, set `self.hand = idx` instead of
   `self.hand = if idx + 1 == len { 0 } else { idx + 1 }`. The hand now rests on the
   newcomer.
2. Effect: on the next miss in this bucket, `clock_find_victim` starts at the newcomer. If it
   has not been hit (counter 0), it is evicted at once in O(1). If it has been hit (counter ≥ 1),
   it is decremented and the sweep continues into the rest of the ring as before. So a newcomer
   has to be hit before the bucket's next miss, or it leaves. This is a LIP-style filter for
   CLOCK.
3. Leave `clock_find_victim`, `get_from_position`, the non-full push path and `evict_item`
   unchanged. In `evict_item`, keep the `self.hand %= len.max(1)` clamp after `remove_at`.

Invariants: in-place replacement means size never exceeds `max_size`. The sweep still
terminates within `CLOCK_MAX * len + 1` steps. Lookup is a linear scan. Geometry is unchanged.
Non-ClassicLRU policies behave exactly as in the baseline.

## Rationale (optional)

In v003, a newcomer is placed just behind the hand, so it gets a full revolution of grace
before it is examined. That gives the CLOCK line a weak filter for keys used once, and the
filter is exactly the lever that won both previous cycles. This change tests the open
question of whether the CLOCK/GCLOCK line can match deep insertion on hit rate once its
newcomer filter is strengthened, while keeping in-place hits and making the common miss
case cheaper. It is deliberately aggressive: the grace window is about 1 miss, compared with
about 4 for v001. Refutation: if hit rate falls below 0.6831, a grace window of one miss is
too short on workload-a, and keys with short reuse distances are being lost.
