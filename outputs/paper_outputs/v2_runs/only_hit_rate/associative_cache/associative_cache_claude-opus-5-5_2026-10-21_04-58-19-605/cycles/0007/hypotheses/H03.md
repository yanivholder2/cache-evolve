# H03

Adding a small per-bucket frequency sketch of missed keys to v003, and admitting a newcomer with counter 1 when the sketch shows at least two recent misses on its key, will raise hit rate on workload-a above 0.731 by catching repeat returners that have already fallen out of the 4-entry ghost ring.

## Parent

cycle/0004/v003

## Changes

Only `src/associative_cache/associative_cache_bucket.rs` changes. Keep everything else from
cycle/0004/v003 as it is: the `clock_mode` gate, `CLOCK_MAX = 3`, the 4-entry `[Option<K>; 4]`
ghost ring with `record_ghost` at both eviction sites, `clock_find_victim`, the hand resting on
the newcomer, and the saturating increments in `get_from_position`. The admission reward stays
capped at counter 1. This hypothesis widens only the signal that grants it, never the size of
the reward.

1. New per-bucket state: add `sketch: [u8; SKETCH_LEN]` with `const SKETCH_LEN: usize = 32;`
   (saturating counters capped at `SKETCH_MAX: u8 = 15`) and `sketch_misses: u16`. Initialise
   them to zeros in `new`.
2. Hashing: add a private `fn sketch_idx(key: &K) -> (usize, usize)`. Hash the key with a cheap
   local `std::hash::Hasher`, for example FNV-1a with a 64-bit finaliser mix (`x ^= x >> 33;
   x = x.wrapping_mul(0xff51afd7ed558ccd); x ^= x >> 33;`). Return two indices from different
   **high** bit ranges of the mixed value, each `% SKETCH_LEN` (e.g. `(x >> 40) as usize % 32`
   and `(x >> 52) as usize % 32`), so they do not reuse the bucket-index bits.
3. Recording, on every clock-mode miss: in `put`, in both clock-mode miss branches (full-bucket
   in-place and non-full push), and before the admission decision:
   - Compute `(a, b) = sketch_idx(&item.key)`.
   - Read `est = min(sketch[a], sketch[b])` as the value **before** incrementing.
   - Saturating-increment `sketch[a]` and `sketch[b]` up to `SKETCH_MAX`.
   - Increment `sketch_misses`. When it reaches `SKETCH_RESET: u16 = 8 * max_size` (computed
     from `self.max_size`), halve every sketch counter (`c >>= 1`) and set `sketch_misses = 0`.
     This ageing keeps the window bounded and recent.
4. Admission rule, replacing the direct `admission_counter` call:
   `item.lfu_counter = if self.admission_counter(&item.key) == 1 || est >= 2 { 1 } else { 0 };`.
   Always call `admission_counter` first so a matching ghost entry is still consumed exactly as
   in v003.
5. Hits do not touch the sketch. It counts only misses, so it measures "keeps coming back after
   eviction" and not "is hot while resident".
6. Invariants: the bucket never holds more than `max_size` items. The sweep still terminates
   within `CLOCK_MAX * len + 1` steps. Sketch counters stay in `0..=15`. The ring is unchanged.
   Non-ClassicLRU policies keep the baseline behaviour. The added memory is 34 bytes per bucket.

## Rationale (optional)

Every exact-key change to the ghost ring (sizes 2 and 16, admission filtering) has lost. Size 16
lost because it rewarded keys seen once at a long reuse distance, which dilutes the signal. A
miss-frequency sketch is a different selector. It rewards keys that missed at least twice
within the ageing window, whatever their distance from the ring. On LIRS-style traces with
looping access, that is the population that keeps being thrown out by the strict one-miss
filter. Because the reward is still counter 1, this does not repeat cycle 0002's generous
promotion. It is also not frequency protection at the eviction end, which failed three times.
It applies only at admission. Refutation: a hit rate at or below 0.731 means repeat returners
beyond ring distance are not worth even one extra sweep pass, and v003's admission signal is
complete for workload-a.
