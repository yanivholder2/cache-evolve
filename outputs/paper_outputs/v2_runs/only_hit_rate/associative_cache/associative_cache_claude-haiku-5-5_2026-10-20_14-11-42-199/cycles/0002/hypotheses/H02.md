# H02

Encoding ClassicLRU recency as a saturating 8-bit per-slot age counter instead of a wide timestamp reduces metadata-size below the baseline's 40 while keeping hit-rate within 0.001 of baseline.

## Parent

baseline

## Changes

In the baseline ClassicLRU policy, replace the per-entry recency field (currently a wide counter or timestamp, whichever the policy stores per slot) with a `u8` age counter. On every hit or insert, set the touched slot's age to 0 and increment the ages of other occupied slots in the same bucket, saturating at 255. On eviction, `evict_one()` (or the equivalent victim-selection function in the LRU path) picks the slot with the highest age; ties break by lowest slot index so the result is deterministic. Remove any global clock or per-policy counter that becomes unused. Keep the public policy trait signatures unchanged so the bucket code needs no edits. Do not touch test or harness files.

## Rationale (optional)

Cycle 0001 showed hit-rate-only changes were hard to separate from noise, and metadata-size was never measured. This hypothesis trades a small, bounded loss of recency precision (ages saturate only after 255 intra-bucket accesses, and a 64-slot bucket rarely needs more) for a smaller per-slot footprint. The claim is refuted if metadata-size is not reduced or if hit-rate drops more than 0.001.
