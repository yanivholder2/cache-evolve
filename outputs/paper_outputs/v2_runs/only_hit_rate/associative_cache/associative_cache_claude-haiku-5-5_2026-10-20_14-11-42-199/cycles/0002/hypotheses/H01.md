# H01

Adding a per-bucket tag fingerprint array to the 64-slot wide buckets lowers per-op-time versus v001 while keeping hit-rate at or above 0.664.

## Parent

cycle/0001/v001

## Changes

Keep v001's `BucketGeometry::layout` override (fixed 64-slot buckets, harness-split fallback for budgets not divisible by 64) unchanged. Inside the bucket lookup path (the function that scans slots for a key, e.g. `find_slot` or the get/put probe loop in the bucket module), store a parallel fixed-size array of 8-bit fingerprints (low byte of the key hash) for each bucket. On lookup, compare fingerprints first and only compare full keys where the fingerprint matches; on insert, write the fingerprint alongside the key. On removal or slot reuse, clear or overwrite the fingerprint. Eviction order and the victim-selection logic must not change, so hit-rate should be identical in principle to v001; any difference indicates a bug. Preserve the fallback path for non-64-divisible budgets. Do not touch test or harness files.

## Rationale (optional)

v001's insight predicted the cost of scanning up to 64 entries per bucket but did not measure it. Fingerprint filtering targets exactly that scan cost, so the claim is testable on the per-op-time dimension that cycle 0001 left unmeasured. Hit-rate is held fixed by design, which isolates the latency effect.
