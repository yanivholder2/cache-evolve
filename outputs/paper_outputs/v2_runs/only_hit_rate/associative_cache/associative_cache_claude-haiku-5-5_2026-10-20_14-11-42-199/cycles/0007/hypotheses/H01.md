# H01

Placing admitted misses at the probationary victim end, on top of the shared-frequency admission gate, raises workload-a hit-rate above the incumbent's 0.7427.

## Parent

cycle/0005/v001

## Changes

Keep the shared-frequency admission gate in the miss path exactly as the parent implements it: an incoming key displaces the probationary-first victim only when its shared counter exceeds the victim's. Change only the insert position of an admitted key. In the parent's probationary slice, insert the admitted key at the position that the probationary-first victim scan will select next (the victim end), not at the MRU/back end and not at index 0 of the slice. State the chosen index in a code comment so the position is unambiguous.

Do not change the counter type, the counter update rule, the admission predicate, the protected-region sizing, or the demotion rule. Preserve the existing hit path. The experiment isolates the insert-position effect that cycle 0005's eviction-next variant reported alone, now stacked on the gate.

Note for the implementer: cycle 0006 v002 showed that placing admitted keys at index 0 of probation lowered hit-rate. This hypothesis is a different position (victim end). If the position is ambiguous in the code, prefer the victim end and document it.
