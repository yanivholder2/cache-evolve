# H02

A second-miss ghost list admission filter, using exact keys and no frequency counter, raises workload-a hit-rate over baseline by rejecting one-shot inserts.

## Parent

baseline

## Changes

Add a ghost list of recently missed keys, stored exactly as keys (no hashing, no aliasing, no saturating counters) in a bounded FIFO whose capacity equals the total number of cache slots. On a miss, if the incoming key is not in the ghost list, record it there and do not insert it into the cache. If the key is already in the ghost list (its second miss within the window), remove it from the ghost list and insert it through the baseline insertion path unchanged.

Eviction in the baseline stays as it is. Only the admission decision on a miss changes. Keep the ghost list out of the hit path, and do not touch the baseline's existing frequency or ranking metadata.

Measure and record the ghost list's memory overhead in the variant notes, because metadata size is a fitness dimension and this variant is expected to cost more metadata than the baseline. The strategy differs from the frequency-counter gate in cycles 0004 to 0006: it admits on recurrence, not on an estimated frequency comparison against the victim.
