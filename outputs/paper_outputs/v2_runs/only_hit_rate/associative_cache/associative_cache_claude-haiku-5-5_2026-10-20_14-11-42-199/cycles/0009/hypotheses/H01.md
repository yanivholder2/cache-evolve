# H01

Adding a one-capacity recurrence (ghost-list) gate in front of the shared-frequency admission gate raises workload-a hit-rate by refusing first-time misses that the frequency comparison would otherwise have to judge.

## Parent

cycle/0005/v001

## Changes

Start from the cycle 0005 v001 incumbent in `src/associative_cache/mod.rs`. Keep the shared `freq` counter, the probationary-first eviction, and the admission comparison in `put()` exactly as they are.

Add a second-miss ghost list to `AssociativeCache`:

- New fields: a `HashSet<K>` named `ghost` and a `VecDeque<K>` named `ghost_order`, both holding keys that missed once and were not admitted. Capacity is fixed at `num_of_buckets * bucket_size` (one cache capacity). When inserting into a full ghost list, pop the oldest key from `ghost_order` and remove it from `ghost`.
- In `put()`, handle only the case where the key is not resident and its bucket is full. Before the existing admission comparison:
  - If the key is not in `ghost`, record it (push to `ghost_order`, insert into `ghost`, apply the capacity bound) and return without inserting. This is the first-miss refusal.
  - If the key is in `ghost`, remove it from `ghost` and `ghost_order`, then fall through to the existing admission comparison unchanged.
- Do not change `get_and_update_item()`, the `freq` bump on every access, or the `bucket.put` call path. Keys inserted into a non-full bucket bypass the ghost check so cold start is not penalised.

Preserve the invariant that a key is either resident or in the ghost list, never both at the time of the check. Do not add counters or aging to the ghost list. Do not widen the window beyond one capacity; cycle 0008 showed a longer window regressed.

## Rationale (optional)

Cycle 0007 v002 showed a recurrence gate with a one-capacity window gained hit-rate on its own. Cycle 0005 v001 is the only incumbent gain, and it filters one-shot inserts by comparing counters at miss time. The two mechanisms filter the same population at different points: the ghost list refuses a key's first appearance outright, while the admission gate compares counts after the first appearance. Stacking them tests whether the recurrence signal adds information the counter comparison lacks.
