# H02

Stacking the eviction-next miss-insertion position from cycle/0005/v003 onto the admission-gated incumbent will raise workload-a hit-rate above 0.7427 by letting admitted one-shot entries leave first.

## Parent

cycle/0005/v001

## Changes

In `src/associative_cache/associative_cache_bucket.rs`, change how `put` places a new entry after the miss path has been admitted.

- Add a boolean flag to `AssociativeCacheBucket`, `insert_at_eviction_next: bool`, set from a new constant `INSERT_EVICTION_NEXT = true` in the same file. Set the flag to `true` in `new`.
- In `put`, on the new-key path (after `evict_victim()` has run, where the code currently does `self.items.insert(self.prob_len, item); self.prob_len += 1;`), when the flag is set insert at index 0 instead: `self.items.insert(0, item); self.prob_len += 1;`. Index 0 is the front of the probationary slice, which is the position the eviction policy treats as the next candidate, the same position cycle/0005/v003 used.
- Return value: keep `(&self.items[self.prob_len - 1], evicted)`. Once the item is at index 0, use `(&self.items[0], evicted)` instead, so the returned reference points at the inserted item.
- Keep probationary-first eviction, promotion on probation hit, the protected region and its demotion, and `get_from_position` unchanged.
- Keep the admission gate in `mod.rs` unchanged. The gate runs before `bucket.put`, so only admitted keys reach this path.
- Keep the `insert_new` helper from v003 out of this change. Do not add any per-entry metadata.

Expected check: a hit on the entry moves it through `touch`, so a re-referenced entry is promoted out of the front slot as before. An entry that is never reused reaches eviction first.
