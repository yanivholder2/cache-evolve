# H01

Replacing the unbounded shared frequency HashMap with a fixed-size saturating counter table cuts the admission gate's metadata-size while keeping workload-a hit-rate within 0.5 points of the incumbent.

## Parent

cycle/0005/v001

## Changes

In `src/associative_cache/mod.rs`, replace the field `freq: HashMap<K, usize>` with a fixed-size direct-mapped table `freq: Vec<u8>` of length `FREQ_SLOTS = 4096`, allocated once in `try_new`. Index it with a deterministic hash of the key: build a `std::collections::hash_map::DefaultHasher::new()`, feed it the key with `Hash::hash`, and take `finish() as usize % FREQ_SLOTS`.

- In `get_and_update_item`, replace `*self.freq.entry(*key).or_insert(0) += 1` with a saturating increment of the key's slot (`saturating_add(1)` capped at `u8::MAX`). Keep the rest of the function unchanged.
- Add a `accesses_since_halving: usize` counter. Each access increments it. When it reaches `10 * FREQ_SLOTS`, halve every slot (`*slot >>= 1`) and reset the counter to 0. This keeps stale frequencies from dominating the gate.
- In `put`, the admission comparison stays as it is: `incoming = slot(key).max(1)` and `victim = slot(victim_key)` as `u32`, with the same strict `incoming <= victim` bypass. Read the slot through the same hash function.
- Do not change the bypass logic, the probationary-first bucket, or `bucket.put`.
- Keep the `get_mut_bucket` helper and the `Display` and `framework::Cache` impls unchanged.
- Update the doc comment on the `freq` field to describe the fixed table and the periodic halving.

The unit tests in `mod.rs` must still pass. Do not edit `tests/` or `src/test_utils/`.
