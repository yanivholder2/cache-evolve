# H03

Inserting most new misses at the eviction-next position, with a 1-in-32 MRU exception, raises workload-a hit-rate over baseline by stopping one-shot entries from displacing the working set.

## Parent

baseline

## Changes

Change only the insert path of the baseline bucket policy. Victim selection stays exact-minimum, and hit handling stays as in baseline.

- On a miss that inserts a new entry, place the entry at the eviction-next (lowest-rank) position within its bucket, not at the normal MRU position.
- Use a per-cache miss counter. On every 32nd miss, insert at the normal MRU position, as baseline does. Use the counter instead of a random number so runs are deterministic.
- On the first hit to an entry inserted at the eviction-next position, move it to the normal MRU position, so repeated use still protects it.
- Do not add any new per-entry metadata beyond a single insert-position flag or reuse of an existing rank field. Keep the miss counter as a single integer per cache.

## Rationale (optional)

This is a different lever from the incumbent. The incumbent changes which region is evicted first. This hypothesis changes where new entries start in the ranking, which is the insertion-position idea behind LIP/BIP-style policies. It targets scan-heavy misses without the admission-compare step. The 1-in-32 MRU exception keeps the policy from freezing the cache when the working set changes.
