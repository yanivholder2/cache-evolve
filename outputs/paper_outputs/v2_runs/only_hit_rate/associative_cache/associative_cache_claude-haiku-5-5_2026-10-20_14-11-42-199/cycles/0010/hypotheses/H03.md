# H03

Admitting a full-bucket miss when its key appears in a one-capacity second-miss ghost list, after the counter comparison has rejected it, will raise hit-rate on workload-a over cycle/0005/v001.

## Parent

cycle/0005/v001

## Changes

Add a ghost list to `AssociativeCache` (`src/associative_cache/mod.rs`): a bounded FIFO of keys with capacity equal to the total slot count (`buckets.len() * bucket_size`), plus a `HashSet` for O(1) membership.

Change the admission check in `put()`. When the target bucket is full and the key is not resident, keep the existing order: first test `incoming > victim` with the existing `freq` values. If that test passes, admit as before. If it fails, check the ghost list. If the key is in the ghost list, admit it. Otherwise record the key in the ghost list (evicting the oldest ghost entry if at capacity) and bypass the insert.

Ghost entries are written only on a bypass. A key that is admitted is not added to the ghost list. Do not touch the get path, the bucket code, the victim choice, or the frequency counting in `get_and_update_item()`.

Invariants to preserve: the ghost list never exceeds its capacity, a key is never both resident and in the ghost list after admission (remove it from the ghost set on admit), and a bypassed insert leaves the bucket untouched.

## Rationale (optional)

Cycle 0009 stacked a first-miss refusal in front of the counter gate and lost, because the counter already bypasses one-shot keys. This variant tests the recurrence signal in the other direction: it only adds admissions for keys the counter refused but which have recurred, so it cannot delay keys the counter would have admitted. The one-capacity window matches the setting that gained in Cycle 0007.
