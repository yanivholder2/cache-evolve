# H03

Splitting each bucket into a probationary and a protected region, with promotion on hit, raises hit-rate on workload-a over the baseline's single-pool eviction.

## Parent

baseline

## Changes

Modify the bucket structure in the baseline so each bucket holds two logical regions: a probationary region and a protected region. Use a fixed split of 25% probationary and 75% protected slots, rounded so each region has at least one slot. A new entry from a miss is placed in the probationary region. On a hit in the probationary region, move the entry to the protected region. If the protected region is full, demote its least-recently-used entry back to probationary. Modify `evict_one()` so that a victim is taken from the probationary region first, using the baseline's existing recency ordering within that region. Only fall back to the protected region if the probationary region is empty. Preserve the baseline's key comparison, bucket indexing, and public get/put signatures. Do not change the aging logic or the bucket geometry.

## Rationale (optional)

Every variant so far has changed how eviction ranks entries, and none has isolated the scan-resistance question directly. A segmented policy protects entries that were reused from being displaced by single-use inserts, which is distinct from both the sampled victim scan in H01 and the insert gate in H02. The baseline parent keeps this hypothesis independent of the 0001 and 0002 Winners, so it measures the segmentation effect on its own.
