# H02

Adding an aged-frequency eviction policy that halves per-item hit counters periodically will raise hit rate on workload-a over ClassicLRU by keeping stale-but-once-hot items from crowding out current working-set items.

## Parent

baseline

## Changes

Overlay `src/shared/eviction_policy.rs` only. Add a new zero-sized-or-minimal policy struct `AgedLfu` that implements `EvictionPolicy<K, V>` for the same `K: Hash + Eq + Copy + Debug, V: Eq + Copy + Debug` bounds as the existing impls.

Behaviour:
- `get_from_position`: increment `items[position].lfu_counter` and return `position` (same as `Lfu`). Keep a per-bucket hit counter in a `Cell<u32>` field on `AgedLfu`, incremented on each call. When it reaches the constant `AGED_LFU_DECAY_PERIOD: u32 = 64`, halve every `lfu_counter` in `items` (`>>= 1`) and reset the counter to 0. The constant is fixed rather than derived from bucket size because the policy is built without access to the bucket geometry.
- `eviction_candidate_index`: return the index of the minimum `lfu_counter`, breaking ties by lowest index (oldest insertion position), using the same `min_by_key` shape as `Lfu`.
- `promotion_candidate_index`: return the index of the maximum `lfu_counter`, ties to the highest index, matching `Lfu`.

Wiring:
- Add a variant `AgedLfu` to `EvictionPolicyKind`, assign it index 6, name `"AgedLfu"`, update `all()` to return a 7-element array, `all_names()` to a 7-element array, the exhaustive match in `all()`/`name()`/`index()`/`build()`, and `from_usize`/`from_name` (these derive from `all()` and need no other change).
- Update the inline test `from_usize_out_of_range`: it currently asserts index 6 is `None`; change that case to index 7. Update the `from_usize_valid_indices` test to assert index 6 maps to `AgedLfu`.

Invariants: `ClassicLRU`, `TimestampLRU`, `Lifo`, `Lfu`, `Fifo`, and `Swap` behaviour must be unchanged, and existing indices 0-5 must keep their meaning because JNI crosses policy ordinals. Do not modify the bucket or geometry files.
