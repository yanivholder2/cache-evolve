# H01

Repartitioning the fixed 2048-slot capacity into 32 wider buckets of 64 slots raises hit rate on workload-a by removing conflict misses from the 16-slot baseline layout.

## Parent

baseline

## Changes

Overlay `src/shared/geometry.rs` only. Keep the `BaselineGeometry` type name and the `for_settings(settings)` constructor unchanged, since the construction glue and invariant gate build the geometry through it. Change the `BucketGeometry::layout(&self, total_capacity)` implementation so it ignores the harness-provided `num_of_buckets`/`bucket_size` split and instead fixes `bucket_size = 64` and returns `(total_capacity / 64, 64)`. For the swept capacity of 2048 this yields 32 buckets of 64 slots.

Invariant to preserve: `num_of_buckets * bucket_size == total_capacity`. Add a `debug_assert!` that `total_capacity % 64 == 0`. Do not touch `eviction_policy.rs` or `associative_cache_bucket.rs`; the ClassicLRU policy and bucket container stay as in the baseline.

Expected trade-off: fewer, wider buckets reduce the chance that a hot key's bucket is overloaded while others sit empty, which should lift hit rate. The cost is that ClassicLRU's `get_from_position` (remove-and-push on a Vec) and the per-bucket linear scan now touch up to 64 entries instead of 16, so per-op time may regress. Report both dimensions.
