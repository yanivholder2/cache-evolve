# H03

Widening the cycle-0007 ghost-list recurrence window to four times the cache capacity raises workload-a hit-rate above the 0.7164 that the cycle-0007 v002 ghost list reached.

## Parent

cycle/0007/v002

## Changes

Change only the window size of the second-miss ghost list. In `AssociativeCache::try_new()` (`src/associative_cache/mod.rs`), the parent builds `GhostList::new(settings.capacity())`. Change that to `GhostList::new(4 * settings.capacity())`, so a key's first miss stays recorded for about four times as many subsequent distinct misses before it ages out. Leave `GhostList::admit()`, `GhostList::record()`, the lazy-deletion FIFO, and the stale-entry compaction unchanged. Leave `put()` unchanged: it still admits only on a second miss of a key that is currently displacing, and it still never filters updates or inserts into a bucket with free slots.

The claim is that reuse distances longer than the current window are being missed, so a longer memory admits recurring keys that the current window forgets. Report `hit-rate` and `metadata-size` for this variant. The metadata-size measurement is the test of the cost concern raised in cycle 0007, since the ghost list's `live` and `order` structures scale with the window. A hit-rate gain that comes with a metadata increase is a trade-off, not a Winner by itself. A flat or lower hit-rate means the cycle-0007 window was not the limit.
