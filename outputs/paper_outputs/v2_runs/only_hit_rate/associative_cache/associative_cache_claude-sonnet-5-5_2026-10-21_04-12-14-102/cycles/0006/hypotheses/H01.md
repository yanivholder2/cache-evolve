# H01

Placing the entry demoted from the protected segment at the probation LRU end (next to be evicted) instead of the probation MRU end will raise hit-rate by keeping fresh one-touch inserts alive longer.

## Parent

cycle/0004/v003

## Changes

In the hit path of the bucket logic in the associative-cache overlay file (the code that, on a probation hit, promotes the entry to the protected MRU and demotes the protected LRU entry across the segment boundary), change where the demoted entry lands. Currently it sits at the probation segment's most-recent position. Instead, place it at the probation segment's least-recent position (the first slot to be evicted under probation-first eviction), shifting the other probation entries one step toward the MRU side. Do not add any per-entry state or counters. Preserve: the probation size of slots/16, first-hit promotion, probation-first eviction, and that all keys stay in their hashed bucket. If the current code has no explicit demotion (a pure positional swap), implement this by swapping the promoted entry with the boundary entry and then rotating that demoted entry to the probation LRU end.

## Rationale (optional)

Demoted protected entries have already shown reuse once, but they have gone cold. Putting them at probation MRU makes them outlive new inserts that may be about to be re-hit. Cycle 5 says the eviction side is exhausted, but the demotion placement hasn't been tested.
