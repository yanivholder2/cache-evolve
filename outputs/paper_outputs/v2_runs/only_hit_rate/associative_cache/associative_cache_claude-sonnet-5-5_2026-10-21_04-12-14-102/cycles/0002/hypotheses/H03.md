# H03

Pick the insertion bucket as the less-loaded of two hash choices (power-of-two-choices placement) in the baseline geometry to raise hit-rate by cutting conflict misses.

## Parent

baseline

## Changes

In the baseline overlay, compute two bucket indices for each key from two different mixes of the key hash (for example the low bits and a multiplicatively rehashed value). On `get`, check the first bucket and then the second. On insert, if the key is not present, place it in whichever of the two buckets currently holds fewer entries, and evict the LRU of that bucket only if both are full (choose the one with the older front entry). Remove must also check both buckets. Keep the baseline bucket count, ways and move-to-back hit policy. Total capacity is unchanged.

## Rationale (optional)

v001 showed that wider sets gave only a small gain. This tests whether balancing load across buckets reaches the same effect without 64-way scans.
