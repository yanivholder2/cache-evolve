# H02

Picking the eviction victim from the probation LRU only when its last-seen tick is older than the protected LRU's, otherwise from the protected LRU, in cycle/0004/v001 raises hit-rate by letting stale protected entries leave instead of fresh probation arrivals.

## Parent

cycle/0004/v001

## Changes

In v001's victim-selection path (the eviction branch of the insert/put function), keep the 4-slot probation segment and first-hit promotion unchanged. Add one compare: if the probation segment is non-empty and the protected segment is full, compare a per-bucket monotonic access counter stamped on the probation-LRU entry versus the protected-LRU entry (reuse an existing recency field if present; otherwise add a u32 stamp per slot, set on insert and on hit). Evict the entry with the older stamp. If either stamp is unavailable, fall back to evicting the probation LRU. Do not change insertion or promotion. All placement stays within the hashed bucket.

## Rationale (optional)

Always evicting probation first can discard a new entry while a long-dead protected entry stays.
