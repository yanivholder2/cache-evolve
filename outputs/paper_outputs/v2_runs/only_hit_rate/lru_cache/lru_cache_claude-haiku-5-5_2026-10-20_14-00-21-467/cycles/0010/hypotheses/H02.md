# H02

Doubling the ghost-set retention bound from capacity to twice capacity raises hit-rate on workload-a at size 2048 by admitting keys that re-appear after a longer gap.

## Parent

cycle/0007/v003

## Changes

Change only the ghost-set retention bound; leave the admission rule, victim selection, and recency handling as in the parent.

- Add a module constant `GHOST_FACTOR: usize = 2` next to `VICTIM_WINDOW`, with a doc comment stating the ghost set retains at most `GHOST_FACTOR * capacity` keys.
- In `ghost_record()`, change the trim condition `while self.ghost_order.len() > self.capacity` to `while self.ghost_order.len() > GHOST_FACTOR * self.capacity`. Keep the generation-tagged FIFO and the stale-entry skipping exactly as they are.
- In `try_new()`, pre-size `ghost` and `ghost_order` for `GHOST_FACTOR * capacity` entries (use `saturating_mul` to avoid overflow).
- Update the module header comment that says "The ghost set holds at most `capacity` keys" to say `GHOST_FACTOR * capacity`.
- The admission check in `put()` (`self.nodes.len() >= self.capacity && self.ghost.remove(&key).is_none()`) is unchanged: a key is still admitted only when it is currently in the ghost set, which is now a larger set.

Invariants to preserve: ghost size never exceeds `GHOST_FACTOR * capacity`; ghost entries are removed on admission as before; the filter stays inactive while the arena has free slots. Existing unit tests must still pass.

## Rationale (optional)

The ghost filter has been in the lineage since cycle 0007, but the cross-cycle notes say its engagement has never been confirmed. With a retention bound equal to capacity, a key evicted and re-requested after roughly one cache-worth of other misses is rejected as a one-hit wonder. Doubling the bound tests whether the filter is too short-memoried on this trace. If the result is flat, the ghost bound is not the limiting factor and the filter is either not engaging or not the source of the gain.
