# H01

Shrinking per-entry node metadata on top of the v001 hit-rate gain will cut metadata-size below the baseline's 48 bytes per node without moving hit-rate off 0.7241.

## Parent

cycle/0001/v001

## Changes

Keep v001's eviction decision logic exactly as it is. Apply only the representation change that cycle 0001's v003 used: in the node struct and the arena link fields, replace each `Option<usize>` (prev/next links and the head/tail indices) with a `u32` where `u32::MAX` is the "none" sentinel. Convert at the boundary only: every read of a link goes through a single helper (for example `fn link(&self) -> Option<usize>`) so that eviction and promotion branches compare the same values they did in v001. Do not change capacity accounting, insertion order, or the order in which victims are chosen. Before editing, confirm against v001's overlay the exact names of the node struct, link fields, and head/tail indices, because the implementer should not assume they match baseline. Add a size check so the node layout is asserted to be 24 bytes or less where the overlay permits it.

## Rationale (optional)

Cycle 0001 credited v003 with a size win it never measured (its fitness vector reports hit-rate only). This hypothesis composes that representation change with the strongest measured hit-rate so far, so one evaluation both confirms the size effect and checks that the sentinel conversion leaves v001's hit-rate unchanged. If hit-rate moves, the sentinel conversion changed behaviour and the hypothesis is refuted.
