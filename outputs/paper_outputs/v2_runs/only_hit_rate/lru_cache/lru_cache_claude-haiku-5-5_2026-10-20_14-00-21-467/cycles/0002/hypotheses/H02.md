# H02

Adding a ghost-list admission filter to v001 will raise hit-rate on scan-heavy traces by keeping one-hit-wonder keys out of the cache.

## Parent

cycle/0001/v001

## Changes

Keep v001's eviction order for admitted entries. Add a bounded ghost set of recently evicted keys, capped at the cache capacity (in entries) and kept in FIFO order so it is O(1) to update. On the insert path, when the cache is full and the incoming key is absent from the cache, admit the key only if it is present in the ghost set; otherwise record it in the ghost set and do not insert it, returning the miss as usual. When a key is evicted from the cache, push it into the ghost set and drop the oldest ghost if the set exceeds capacity. Do not apply the filter while the cache has free slots, so warm-up behaviour is unchanged. Do not alter the get/hit path or the promotion logic. Confirm the insert and evict function names against v001's overlay before editing.

## Rationale (optional)

v001's gain over baseline (0.7241 vs 0.665) came from changing what stays resident. A ghost-based admission filter is a different lever on the same metric: it targets scan pollution, where one-shot keys push out reused ones. It changes eviction behaviour on purpose, so unlike H01 it must be judged on hit-rate and the per-op cost of the ghost bookkeeping must be measured too.
