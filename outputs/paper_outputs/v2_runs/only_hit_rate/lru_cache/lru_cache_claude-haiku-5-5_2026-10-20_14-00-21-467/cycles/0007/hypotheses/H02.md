# H02

Inserting new keys at the LRU tail with no other change should raise hit-rate on workload-a at size 2048 by resisting one-pass scan pollution.

## Parent

baseline

## Changes

Change only the insert path of the baseline LRU: a key that misses and is inserted is placed at the tail (LRU end) of the recency list instead of the head (MRU end). Keep the hit path unchanged: a hit on any resident key still moves it to the MRU head, so a key earns MRU position on its first re-reference. Keep the eviction routine unchanged, so the victim is still taken from the tail. Do not add a sparse MRU insert, a second list, a counter, or any stacked change. The only intended behavioural difference is the position of newly inserted keys relative to existing residents.

## Rationale (optional)

Cycle 0005 v003 was the only hit-rate gain from changing insertion position, but cycle 0006 stacked the same mechanism on a lookup collapse with a sparse MRU insert and lost hit-rate. This is the clean ablation the cycle 0006 insight asks for: tail insertion alone, against the permanent baseline, with no other moving part.
