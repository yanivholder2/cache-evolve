# H01

Gating new-key admission on ghost-set membership should raise hit-rate on workload-a at size 2048 by keeping one-hit keys out of the cache.

## Parent

cycle/0003/v002

## Changes

Keep the existing ghost-based admission filter from the parent, but make its decision path verifiable and tighter. In the miss path that decides whether a new key is admitted, size the ghost set to exactly the cache's entry count (not the current capacity), and admit a key only when it is already present in the ghost set; otherwise record the key in the ghost set and skip caching it. Keep eviction order, the hit path, and the recency list untouched. Add a counter for admissions and rejections so the run reports whether the filter engaged on workload-a. Preserve the existing hit-path and eviction invariants; do not touch the key index.

## Rationale (optional)

Cycles 0002 and 0003 reported ghost-filter variants with hit-rate equal to their parent, and no cycle showed the filter engaged on the trace. This hypothesis tests whether a tighter, observable admission rule moves hit-rate at all, rather than assuming the earlier null was real.
