# H01

Skipping the relink on a hit whose node is already the MRU head will cut per-op-time on the incumbent without changing hit-rate from 0.7348.

## Parent

cycle/0002/v002

## Changes

Keep v002's eviction order, admission, and capacity accounting exactly as they are. In the get/hit path, before performing the move-to-front (unlink and relink at head) on the hit node, check whether that node is already the head of the recency list; if it is, return the value immediately without touching any link or head/tail fields. All other hit cases run the existing promotion code unchanged. Do not modify the insert or evict paths, the node layout, or the key index. Before editing, confirm the exact names of the get/promote function, the head index field, and the node link fields against v002's overlay, since the implementer should not assume they match baseline.

## Rationale (optional)

Per-op-time has never been measured on any lineage, and the incumbent's hit-rate is the reference to hold. Because this change only elides writes that would leave the list unchanged, the eviction sequence is identical, so hit-rate should match 0.7348 exactly. Any hit-rate movement refutes the claim. The per-op-time effect is the thing being tested, and it is expected to be small on traces where the head is rarely re-hit, so the measurement should report the per-op delta explicitly.
