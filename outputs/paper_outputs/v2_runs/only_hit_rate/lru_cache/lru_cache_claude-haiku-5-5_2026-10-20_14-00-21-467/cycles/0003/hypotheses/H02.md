# H02

Adding a ghost-list admission filter to the incumbent will raise hit-rate above 0.7348 on scan-heavy traces by keeping one-hit-wonder keys out of the cache.

## Parent

cycle/0002/v002

## Changes

Keep v002's eviction order for admitted entries. Add a bounded ghost set of recently evicted keys, capped at the cache capacity (in entries) and kept in FIFO order so updates are O(1). On the insert path, when the cache is full and the incoming key is absent from the cache, admit the key only if it is present in the ghost set; otherwise record it in the ghost set, do not insert it, and return the miss as usual. When a key is evicted from the cache, push it into the ghost set and drop the oldest ghost if the set exceeds capacity. Do not apply the filter while the cache has free slots, so warm-up behaviour is unchanged. Do not alter the get/hit path or the promotion logic. Confirm the insert and evict function names against v002's overlay before editing. Record the ghost-set bookkeeping as a separate per-op-time figure so its cost is visible alongside hit-rate.

## Rationale (optional)

This is the only hypothesis in the cohort that deliberately changes what stays resident, so it is the one hit-rate bet. It targets scan pollution, where one-shot keys displace reused ones. Cycle 0002's H02 proposed the same filter on v001 and was never evaluated, so this is a re-attempt on the current best lineage. It must clear the incumbent's 0.7348 on hit-rate and must not cost so much per-op time that the gain is a net loss.
