# H01

Combining tail insertion of new keys with periodic MRU insertion onto the cycle/0004/v001 hit-path lineage raises workload-a hit-rate at size 2048 above the 0.7348 incumbent by keeping one-touch keys from displacing re-referenced entries.

## Parent

cycle/0004/v001

## Changes

Start from cycle/0004/v001, which already collapses the hit-path lookup. Port the insertion-position change from cycle/0005/v003 into the insertion routine, the code path that links a newly admitted node into the recency list on a miss. New nodes are linked at the LRU tail by default. Only every 32nd insert is linked at the MRU head, using a simple insert counter held in the cache struct. Leave the hit path unchanged: a re-referenced node still moves to MRU on hit, which is what makes tail insertion pay off. Keep the eviction routine's victim selection (LRU end of the list) unchanged, so the only behavioural difference is where new nodes start. Preserve the lookup collapse and all existing invariants on list links and the key index. Do not add a second list or a ghost set.

## Rationale (optional)

Tail insertion with 1-in-32 MRU insertion is the only hit-rate gain in the ledger so far. Cycle 0004's lookup collapse preserved hit-rate exactly, so stacking the two should keep the gain and inherit the hit-path savings. The per-op effect of the lookup collapse is still unmeasured, so the fitness vector should include per-op time.
