# H03

Replacing the default SipHash key index with an inline non-cryptographic hasher on the baseline lowers per-op time on workload-a at size 2048 without changing hit-rate from the baseline's 0.665.

## Parent

baseline

## Changes

Keep the baseline's eviction and recency logic byte-for-byte unchanged. In the key index used for lookup, insert, and remove, swap the default hasher for a small hasher implemented inline in the overlay (an FxHash-style multiply-and-rotate over the key bytes, with no new dependency, since Cargo.toml is out of scope). Implement it as a `std::hash::Hasher` and build the index with a `BuildHasherDefault` of that type, so the map's call sites do not change. Do not change key equality, capacity, or the index's pre-sizing if present. Because the hasher only affects bucket placement, every lookup must return the same result as before; hit-rate should match the baseline exactly. Record per-op time in the fitness vector so the claim is measurable.

## Rationale (optional)

Per-op time has never been measured on any lineage, and this is the one hypothesis in the cohort that targets it directly with an eviction-neutral change. Hit-rate equality is a built-in check that the index behaviour was not altered. It is a constant-factor change, so the expected effect is small, and a null result is still informative for the per-op dimension.
