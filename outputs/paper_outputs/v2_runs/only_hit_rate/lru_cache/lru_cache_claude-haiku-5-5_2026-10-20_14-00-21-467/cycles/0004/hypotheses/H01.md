# H01

Collapsing the hit path's separate key-index lookup and recency-list touch into a single probe lowers per-op time while hit-rate on workload-a at size 2048 stays at 0.7348.

## Parent

cycle/0003/v001

## Changes

Keep the head-hit relink skip from v001 intact. In the `get`-style hit path of the LRU cache, the key index is currently probed once to find the node and again to validate or re-fetch it before the recency update. Replace those two probes with one entry-style lookup that returns a mutable handle to the node, then perform the recency update through that handle. Do not change which node is evicted, the order of the recency list after a hit, or the miss path. Preserve the existing return value and the behaviour on absent keys.

## Rationale (optional)

v001 showed that eliding list writes leaves hit-rate unchanged, but its per-op time was never measured, so the hit path is the place where a per-op gain is most plausible. A single probe removes one hash computation per hit without touching eviction order, so hit-rate should match the parent exactly. Judge this on per-op time against the parent.
