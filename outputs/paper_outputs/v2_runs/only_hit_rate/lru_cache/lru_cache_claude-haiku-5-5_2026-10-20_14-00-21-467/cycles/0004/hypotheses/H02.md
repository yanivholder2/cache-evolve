# H02

Gating the ghost-based admission filter on cache-full misses, with the ghost set sized to the resident entry count, makes it engage on workload-a and raises hit-rate above 0.7348 by rejecting one-touch scan keys.

## Parent

cycle/0003/v002

## Changes

Keep the ghost-list admission filter from v002. Change its trigger so that the admission check runs only when a miss would force an eviction, that is, when the cache is at capacity, and skip it while there is free space. Set the ghost set's capacity to equal the number of resident entries, evicting the oldest ghost when full. On a miss for a key not present in the ghost set, reject insertion and record the key as a ghost instead of evicting a resident entry; on a miss for a key present in the ghost set, admit normally and remove it from the ghost set. Add a counter for admission rejections and a counter for admission-path entries, and expose both through the existing stats output so the run shows whether the path was reached. Do not change the recency order of resident entries on hit.

## Rationale (optional)

v002 left hit-rate exactly at its parent's value, and its insight flags that the filter may never have engaged on this trace. Counting admission-path entries answers that question directly. If the counters show the path was reached and hit-rate is still flat, the idea is refuted; if the path was reached and hit-rate rises, the scan-pollution bet is confirmed.
