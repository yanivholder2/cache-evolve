# H01

Replacing the single recency list with a segmented LRU (80% protected, 20% probation) will raise hit rate on the lirs workload-a trace at size 2048 by keeping one-hit-wonder keys from displacing the reused working set.

## Parent

baseline

## Changes

Keep the arena (`nodes: Vec<Node<K, V>>`) and `map: HashMap<K, usize>` unchanged in role, but split the recency order into two intrusive lists sharing the arena:

- Add `prot_head`, `prot_tail`, `prot_len` and `prot_cap` to `LruCache`, and a `protected: bool` field to `Node`. Set `prot_cap = capacity * 4 / 5`, clamped to at least 1. Keep the existing `head`/`tail` pair as the probation list.
- `put()` new-key path: allocate or reuse an arena slot exactly as today. On the full-arena path, evict the probation head if the probation list is non-empty, otherwise the protected head; remove its map entry before reusing the slot. Link the new node at the probation tail with `protected = false`.
- `get()` hit on a probation node: unlink it from probation, set `protected = true`, and append to the protected tail. If `prot_len > prot_cap`, demote the protected head to the probation tail with `protected = false`.
- `get()` hit on a protected node: unlink from protected and append to the protected tail.
- `put()` existing-key path: update the value in place, then apply the same promotion rule as `get()`.
- Update `unlink`/`push_back` to take the list selector (or to operate on a list-id parameter) so one helper serves both lists.
- For `capacity < 2` the code must reduce to baseline behaviour.
- Preserve `try_new`, `new`, the `get`/`put` signatures, the `framework::Cache` impl, and the capacity-zero rejection. Inline unit tests that assert strict global LRU order (for example `eviction_removes_lru`, `access_updates_lru_order`) will need their expectations updated for segmented semantics; keep `capacity_zero_panics` intact.

## Rationale (optional)

The baseline inserts every new key at MRU, so a single pass of cold keys evicts the hot set. Segmenting gives new keys a probationary lane that is evicted first, which is the scan-resistance property the lirs trace should reward.
