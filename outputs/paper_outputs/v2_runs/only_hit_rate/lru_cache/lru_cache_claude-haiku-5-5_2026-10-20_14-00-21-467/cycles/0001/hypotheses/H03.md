# H03

Storing arena links and head/tail indices as `u32` with a `u32::MAX` sentinel, instead of `Option<usize>`, will shrink `Node<u64,u64>` from 48 bytes to 24 bytes and reduce metadata-size without changing eviction order.

## Parent

baseline

## Changes

Change the link representation so the node arena is more compact, while keeping the list algorithm identical.

- In `Node<K, V>`, change `prev` and `next` from `Option<usize>` to `u32`, using `const NIL: u32 = u32::MAX` as the "no neighbour" value.
- In `LruCache`, change `head` and `tail` from `Option<usize>` to `u32` (`NIL` when empty), and change `map` to `HashMap<K, u32>`.
- Rewrite `unlink()` and `push_back()` to compare against `NIL` instead of matching on `Option`, casting with `as usize` only at arena indexing sites (`self.nodes[...]`).
- In `put()`, the full-arena branch uses `self.head` as a `u32`, and the map insert/remove use the `u32` index.
- In `try_new()`, reject capacities that cannot be represented as a non-sentinel `u32` (`capacity >= u32::MAX as usize`) by logging an error and returning `None`, matching the existing capacity-zero rejection.
- Keep `get`/`put` signatures, the `framework::Cache` impl, and the `new()` panic behaviour unchanged.
- Expected result: `Node<u64,u64>` is 8 (key) + 8 (value) + 4 (prev) + 4 (next) = 24 bytes, and the `LruCache` struct shrinks correspondingly.

Invariant to preserve: the recency order and eviction decisions are unchanged, so the hit-rate summary must remain exactly 0.6652 on the lirs trace. Per-op time should be checked for regression against the baseline get p50 of 41 ns, though smaller nodes may improve cache locality.

## Rationale (optional)

The baseline pays 48 bytes per entry, of which 32 are two `Option<usize>` links. Node indices never exceed the capacity, so a 32-bit index with a sentinel is sufficient. This hypothesis isolates the metadata-size dimension.
