**What the overlay does (H01, segmented LRU):**
- Each `Node` gets a `protected` flag. The cache keeps the existing probation list (`head`/`tail`) and adds a protected list (`prot_head`/`prot_tail`/`prot_len`/`prot_cap`), with `prot_cap = max(1, capacity*4/5)`.
- New keys enter probation. On eviction the probation head goes first, falling back to the protected head only when probation is empty.
- A hit on either list moves the node to the protected MRU. If protected overflows, its LRU is demoted to probation.
- `unlink` and `push_back` pick the list from the node's flag, so one pair of helpers serves both lists.
- `try_new`, `new`, the `get`/`put` signatures, the `framework::Cache` impl, the capacity-zero panic, and the JNI file are unchanged. `capacity = 1` behaves like baseline.

**Tests:** I traced every inline test by hand against the new semantics. All still pass except `slot_reuse_after_promotion_and_re_eviction`, whose expectations assumed strict global LRU. I updated it to match segmented behaviour (key 3 survives as protected, key 4 is evicted). A few comments were also reworded to describe the new eviction order.

**Gate risk:** the invariant suite (P1 capacity bound, P2 value fidelity, P3 no phantoms) should hold, since the arena never exceeds capacity and the list bookkeeping is symmetric.
