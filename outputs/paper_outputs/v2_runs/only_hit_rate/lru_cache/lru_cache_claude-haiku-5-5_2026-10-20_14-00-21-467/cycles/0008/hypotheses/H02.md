# H02

Narrowing the v003 per-entry hit counter from `u32` to a 2-bit saturating counter will cut node metadata while keeping hit-rate at or near cycle/0007/v003's 0.7351 on workload-a at size 2048.

## Parent

cycle/0007/v003

## Changes

Keep the v003 overlay structure intact: segmented lists, ghost admission filter, `VICTIM_WINDOW = 4`, and the least-hit-in-window victim rule in `select_victim()`. Recency order in `get()` and `touch()` is unchanged.

Change the `hits` field on `Node` from `u32` to `u8`, with a constant `HIT_CAP: u8 = 3` so the counter saturates at 3 instead of growing without bound. Update the two increments (`get()` and the existing-key branch of `put()`) to `self.nodes[idx].hits = self.nodes[idx].hits.saturating_add(1).min(HIT_CAP)`. Reset to 0 on slot reuse as before.

Leave `select_victim()` logic unchanged, so ties and window scanning behave the same; the only difference is that counts above 3 are indistinguishable. Do not add fields or collections.

Expected effect: each `Node` loses three bytes of counter width per entry, which should show up in the metadata-size dimension. Hit-rate should stay within noise of 0.7351, since the window rarely needs counts above 3 to separate candidates.

Report the metadata-size change against baseline (48) and against cycle/0007/v003. If hit-rate drops below 0.7351, the saturation cap is too low for this trace.
