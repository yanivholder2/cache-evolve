# H03

A TinyLFU-style frequency gate on admission from baseline will raise hit-rate on workload-a at size 2048 by refusing new keys whose recent access frequency is lower than the eviction victim's.

## Parent

baseline

## Changes

Start from the baseline LRU as it stands: strict move-to-front recency on hit, insert at MRU, evict the LRU tail when full. Keep recency handling unchanged; do not add segmentation or a ghost set.

Add a small frequency sketch to the cache struct: a count-min sketch with 4 rows of `u8` counters, width `capacity.next_power_of_two()`, and a fixed hash seed per row. Increment the estimate for a key on every `get()` and every `put()` (both hit and miss paths). Halve all counters every `10 * capacity` total increments to age the sketch. Use `std::collections::hash_map::DefaultHasher` (already in std) or a simple multiplicative hash on a `Hash`-derived value; no external crates.

In `put()`, when the cache is full and the key is new, compare `estimate(new_key)` with `estimate(victim_key)`, where the victim is the LRU tail. Admit the new key and evict the victim only if `estimate(new_key) > estimate(victim_key)`. Otherwise drop the new key without inserting it and leave the victim in place. Strict ties reject the new key.

Add `admitted` and `rejected` counters on the cache, exposed through a `pub fn admission_counts(&self) -> (u64, u64)` in the style of the existing v001 lineage, and log them on `Drop` so the engagement of the gate can be confirmed from the run.

Invariants: map and arena stay consistent, and no unsafe code. The hit path must still move the node to the MRU position.

Measure hit-rate on workload-a at size 2048 against baseline (0.665). Report the admission counts to show the gate engaged. Note the sketch's memory cost in metadata-size.
