# H02

Replacing move-to-front on hit with a per-node referenced bit and a second-chance sweep at eviction lowers hit-path per-op time on cycle/0004/v001 while holding workload-a hit-rate at size 2048 within 0.01 of 0.7348.

## Parent

cycle/0004/v001

## Changes

Keep v001's collapsed single-probe hit-path lookup and its head-hit handling. Change only how recency is recorded on hit and how the victim is chosen.

- Hit path: instead of unlinking the hit node and relinking it at the head, set the node's referenced flag and return the value. If the layout has a spare bit, use it. Otherwise add one byte per node, and report that metadata cost explicitly.
- Insert path: a newly inserted node is linked at the head with its referenced flag clear, as the current insert code does.
- Eviction path (`evict_one()` or the equivalent): starting from the tail, walk toward the head. If the candidate's referenced flag is set, clear it and move the node to the head, then continue. Evict the first node whose flag is clear. Bound the walk to one full pass; if every node was referenced, evict the original tail node.

Keep the key index, the node layout apart from the flag, and the return values on hit, miss, and absent keys unchanged. Confirm the get/promote, insert, and evict function names and the head/tail field names against v001's overlay before editing. Report the per-op time delta on the hit path, the hit-rate delta against 0.7348, and the metadata-size delta.

## Rationale (optional)

v001's hit-path collapse is eviction-neutral, so its per-op target is still unmeasured. Move-to-front is the one list write every hit performs. Second chance keeps the recency signal while removing that write from the hit path. Eviction order does change, so hit-rate is the risk. The bounded sweep limits the cost of that change to the miss path, where it is paid once per eviction.
