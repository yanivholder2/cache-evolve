# H03

Inserting most misses at the LRU end of the recency list, and only every 32nd miss at the MRU end, raises hit-rate on workload-a at size 2048 above the baseline's 0.665 by keeping one-touch keys from displacing re-referenced entries.

## Parent

baseline

## Changes

Keep the baseline's key index, node layout, hit-path promotion, and return values unchanged. Change only where a newly inserted node is placed in the recency list.

- Add a deterministic miss counter to the cache struct, incremented on each insertion of a new key. Do not use a random number generator, so runs stay reproducible.
- If the counter is a multiple of 32, link the new node at the MRU head, as the baseline does.
- Otherwise link the new node at the LRU tail, so it becomes the next eviction victim unless it is hit first.
- A hit on such a node moves it to the MRU head through the baseline's existing promotion code, so a key that is re-referenced is kept.

Do not change the eviction call, the victim selection, the key index, or the public return values. Confirm the constructor, insert, and recency-list field names against the baseline before editing. Report the hit-rate delta against 0.665, and the per-op time delta, since per-op time has not been measured on the insert path.

## Rationale (optional)

This is a different mechanism from segmentation and from the ghost-based admission filter. It changes insertion position, not the number of segments or what is admitted. It is the bimodal-insertion idea, and it is the one scan-resistance mechanism from baseline that does not add a second list or a ghost set, so its metadata cost should stay near zero.
