# H02

Demote overflowed protected entries to the probation LRU end instead of the MRU end to raise hit-rate by evicting stale demoted keys first.

## Parent

cycle/0004/v001

## Changes

In `touch` of the overlay `src/lru_cache/mod.rs`, the demotion loop currently calls `push_back(demote, PROBATION)` (MRU end). Add a `push_front(idx, seg)` helper that inserts at the list head (LRU end, updating `head`, `prev`/`next`, `segment`, `len`) and use it for demoted nodes so they are the next eviction victims, ahead of newly inserted probation keys. Newly inserted keys still use `push_back(PROBATION)`. Leave protected_cap at 95%, eviction, and put logic unchanged.

## Rationale (optional)

Demoted nodes have not been touched recently, whereas fresh probation keys are the ones that might get a first hit; this changes promotion/probation ordering rather than the share.
