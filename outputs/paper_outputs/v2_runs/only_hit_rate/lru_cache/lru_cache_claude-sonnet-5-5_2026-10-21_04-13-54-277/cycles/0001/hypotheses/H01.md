# H01

Shrink Node by replacing `Option<usize>` links with `u32` indices and a sentinel, cutting metadata-size from 48 to 24 bytes for Node<u64,u64>.

## Parent

baseline

## Changes

In `src/lru_cache/mod.rs` (not the JNI file), change `Node.prev` and `Node.next` from `Option<usize>` (16 bytes each) to `u32`, with a `const NIL: u32 = u32::MAX`. Change `LruCache.head`/`tail` likewise to `u32`. Rewrite `unlink` and `push_back` to compare against `NIL` instead of matching on `Option`. In `try_new`, reject (return None) capacity >= u32::MAX. Convert `u32 as usize` only at the `nodes[...]` index sites; `HashMap<K, usize>` may become `HashMap<K, u32>` to also shrink map values. Keep strict LRU semantics, eviction order, slot reuse and the public API unchanged so existing tests and the invariant gate still pass. Expected Node<u64,u64> size is 8+8+4+4 = 24 bytes.
