# H03

Admitting a candidate on ties and requiring a strictly warmer estimate only against protected-segment victims, with sketch recording on every access removed from the hit path for already-resident keys, should cut per-op time without losing hit-rate.

## Parent

baseline

## Changes

Start from the baseline source. Convert it to a segmented LRU (probation + protected, 95% protected share, new keys into probation, hit promotes to protected with demotion of protected LRU when over cap, evict from probation head, fallback protected head) with a single count-min sketch (4 rows, u8 counters, width = next_power_of_two(capacity), halve every 10*capacity additions) and no doorkeeper. Increment the sketch only in `put()` for non-resident keys and in `get()` only on a miss (rejected misses count toward frequency); resident hits skip the sketch update. Gate: drop the candidate if `est(cand) < est(victim)`. Keep the public API and `framework::Cache` impl identical. Targets lower per-op time and metadata size (no door bitset) at roughly equal hit-rate to v002.
