# H01

Halving the ghost window from capacity/8 to capacity/16, so it is smaller than the probation queue, raises hit-rate on workload-a at size 2048 because the ghost-into-`main` fast path then admits only keys with the shortest reuse gaps.

## Parent

cycle/0005/v001

## Changes

In `src/lru_cache/mod.rs`, `LruCache::try_new`: change
`let ghost_cap = std::cmp::max(1, capacity / 8);` to
`let ghost_cap = std::cmp::max(1, capacity / 16);` and update the
adjacent comment and the `log::info!` text to say `capacity / 16`.
At size 2048 that gives `ghost_cap = 128`, below `small_target = 204`.

Change nothing else. `small_target` stays `capacity / 10`, `MAX_FREQ`
stays 3, and `put`, `evict_one`, and `push_ghost` stay as they are. The
`with_capacity(ghost_cap + 1)` reservations follow `ghost_cap`
automatically.

Update the in-file tests that assume `ghost_cap == 2`
(`ghost_hit_admitted_into_main` and
`ghost_window_expires_after_ghost_cap_plus_one_evictions`). Build those
caches with capacity 32 instead of 16 so that `ghost_cap` is still 2.
The fill loops become `1..=32`, and the first evicting put uses key 33
instead of 17. `small_target` becomes `max(1, 32/10) = 3`, so the
eviction sequence changes:
- Fill 1..=32. All entries are in `small` with freq 0.
- The next put evicts key 1 into the ghost, because `small.len() >= small_target`.
- After that, each new key evicts the next-oldest key from `small`.

Adjust the asserts on `small_target` to 3. Make the expiry test loop run
`ghost_cap + 1` evictions starting at key 33. Keep the meaning of each
test the same.

## Rationale (optional)

This is the probe that cycle 5 asked for. The ghost-size curve has not
turned over yet, and each of the last three halvings gained less than
the one before. If hit rate goes down here, the ghost size is settled at
`/8`. If it goes up or stays flat, that is evidence the ghost fast path
is close to dispensable on this trace.
