# H02

Requiring two hits during probation (`freq >= 2`) before a key is promoted from `small` to `main` will raise hit-rate on workload-a by tightening S3-FIFO's admission filter further.

## Parent

cycle/0001/v001

## Changes

Change only the small-queue branch of `evict_one()` in `src/lru_cache/mod.rs`.

- Add a constant `const PROMOTE_FREQ: u8 = 2;` next to `MAX_FREQ`.
- In the `small` branch of `evict_one`, change the promotion test from `if node.freq > 0` to `if node.freq >= PROMOTE_FREQ`. A promoted node still gets `freq = 0`, `in_main = true`, and is pushed to the back of `main`.
- A node popped from `small` with `freq < PROMOTE_FREQ` (that is, 0 or 1) is evicted exactly as a freq-0 node is today: remove it from `map`, call `push_ghost(key)`, and return its slot. This means a single-hit key leaves the cache but stays in the ghost. If it comes back while still ghosted, it reaches `main` through the existing ghost-hit path in `put`, which is unchanged.
- Leave all of the following unchanged:
  - `get`, the update path in `put`, and their saturating `freq` increment
  - the `main` branch of `evict_one`, including the decrement-and-reinsert behaviour
  - `small_target = capacity / 10`
  - `ghost_cap = capacity - small_target`
  - `MAX_FREQ = 3`
- Termination: each loop iteration still either frees a slot or moves a `small` node into `main` with freq reset to 0, or lowers a `main` node's freq. So the loop still terminates.
- Tests: update `accessed_small_entry_promoted_to_main` so key 2 is accessed twice before the promoting eviction. Add a test where a key accessed once in `small` is evicted to the ghost rather than promoted, and is then admitted into `main` when it is put again.

## Rationale (optional)

Across two cycles, every change that loosened admission into `main` lost hit rate. This hypothesis moves the other way and makes a key show stronger evidence of reuse while resident before it takes a protected `main` slot. On loop phases, a key re-referenced once inside the short probation window is weak evidence. Requiring two references filters such keys more aggressively. The ghost still gives single-hit keys a second chance, so genuinely hot keys are only delayed, not blocked.
