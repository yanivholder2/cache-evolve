# H03

Raising LIRS's resident-HIR fraction from 1% to 5% of capacity will raise hit-rate on workload-a, because newly arriving keys stay resident long enough to show a short inter-reference recency and earn LIR status.

## Parent

cycle/0002/v003

## Changes

Change only the HIR sizing in `LruCache::try_new` in `src/lru_cache/mod.rs`.

- Replace `let hir_cap = std::cmp::max(1, capacity / 100);` with `let hir_cap = std::cmp::max(1, capacity / 20);`. `lir_cap = capacity - hir_cap` stays as it is. At size 2048, this moves HIR from 20 to 102 slots and LIR from 2028 to 1946.
- Guard small capacities: if `capacity == 1`, `lir_cap` becomes 0. Keep the existing behaviour, where warm-up admits as LIR only while `lir_count < lir_cap`, and confirm that `capacity_one` still passes. If it fails, use `hir_cap = min(hir_cap, capacity - 1)` when `capacity > 1`, and keep `hir_cap = 1, lir_cap = 0` for capacity 1, as the parent does.
- Leave all of the following unchanged:
  - `access`
  - `demote_bottom_lir`
  - `prune_stack`
  - `evict_q_front`
  - `nonres_cap = 2 * capacity`
  - `enforce_nonres_bound`. Its linear walk is a per-op-time issue, not a hit-rate one, and changing which non-resident gets dropped would confound the result.
- Update the doc comment at the top of the file (`hir_cap = max(1, capacity / 20)`) and the `capacity 10` comment in `scan_does_not_evict_lir_entries`. With capacity 10, `hir_cap` is still 1, so that test's expectations hold. Existing invariant tests (`residency_and_nonresident_bound_hold_under_random_workload`) must still pass.

## Rationale (optional)

LIRS (0.7145) beat LRU but trailed S3-FIFO (0.7269), whose probation queue is 10% of capacity. With only 20 resident-HIR slots at size 2048, a new key gets about 20 misses' worth of residency before it is evicted. If it is re-referenced after that, it can only be promoted through the non-resident path, which costs a miss each time. A 5% HIR queue sits between LIRS's default and S3-FIFO's split. That makes this a single-knob test of whether a larger probation buffer is why S3-FIFO is ahead. Cycle 2's insight explicitly called for this experiment. It also gives the cohort an independent lineage alongside the S3-FIFO tweaks in H01 and H02.
