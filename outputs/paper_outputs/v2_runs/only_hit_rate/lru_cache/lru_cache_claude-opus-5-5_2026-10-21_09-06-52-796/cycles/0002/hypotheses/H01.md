# H01

Replace v001's key-cloning ghost queue with a compact fingerprint ring sized at 2× capacity, so loop reuse distances longer than the cache still earn main-queue admission, raising hit rate on workload-a.

## Parent

cycle/0001/v001

## Changes

In `src/lru_cache/mod.rs` (v001's S3-FIFO), replace `ghost_q: VecDeque<K>` and `ghost_set: HashMap<K, ()>` with a fingerprint ghost:

- Add `ghost_ring: Vec<u64>` (fixed length `ghost_cap`, initialised to 0), `ghost_head: usize`, and `ghost_count: HashMap<u64, u8>`, a multiset of fingerprints currently in the ring. Set `ghost_cap = 2 * capacity`, up from `capacity - small_target`.
- Compute the fingerprint with `std::hash::BuildHasher::hash_one` on a fixed `std::collections::hash_map::DefaultHasher`-based builder (`BuildHasherDefault<DefaultHasher>`, deterministic). Map a hash of 0 to 1 so that 0 can mean an empty slot.
- `push_ghost(key)`: compute fp. If `ghost_ring[ghost_head] != 0`, decrement that old fp's count and remove it when the count reaches 0. Write fp at `ghost_head`, increment its count, and advance `ghost_head = (ghost_head + 1) % ghost_cap`. The key no longer has to be cloned into the ghost.
- In `put`, replace `ghost_set.remove(&key)` with a lookup: if `ghost_count` contains fp, treat it as a ghost hit. Decrement the count, or remove it when it reaches 0. Leave the stale ring slot in place; the count bookkeeping makes that harmless. Fingerprint collisions only cause a spurious main admission, which is acceptable.
- Keep `small_target = max(1, capacity/10)`, `MAX_FREQ`, the main-queue reinsertion, and the rule that main evictions are not ghosted.
- Update the tests that reference `ghost_set` (`ghost_hit_admitted_into_main`, `main_evictions_not_ghosted`) so they use a helper `fn in_ghost(&self, key:&K)->bool` that checks `ghost_count` for the fingerprint. All other invariants must hold: `small.len()+main.len()==map.len()` and `map.len() <= capacity`.

## Rationale (optional)

workload-a is a LIRS trace with loops. Loops longer than the cache are re-referenced at distances above `capacity`, and v001's ghost is shorter than `capacity`, so it forgets them before they return. A 2× ghost catches those returns. Storing 8-byte fingerprints instead of cloned keys plus a key-hash set keeps the per-entry metadata cost roughly unchanged, even though the ghost covers twice as many keys.
