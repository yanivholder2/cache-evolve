# H01

Shrinking the S3-FIFO ghost window from capacity/2 to capacity/4 raises hit-rate on workload-a by only fast-tracking keys into `main` when they come back soon after leaving `small`.

## Parent

cycle/0003/v001

## Changes

Single-knob change in `src/lru_cache/mod.rs`, `LruCache::try_new`:

- Replace `let ghost_cap = std::cmp::max(1, capacity / 2);` with
  `let ghost_cap = std::cmp::max(1, capacity / 4);` (at size 2048 this
  gives 512 remembered keys instead of 1024). Update the comment to say
  this is the H01 capacity/4 ghost window.
- Leave everything else as it is: `small_target = max(1, capacity / 10)`,
  `MAX_FREQ = 3`, ghost hits still go straight into `main`, and
  `evict_one`/`push_ghost` keep their current logic. The
  `with_capacity(ghost_cap + 1)` reservations follow the new `ghost_cap`
  automatically.
- Update the in-module unit tests that hard-code `ghost_cap == 5` for
  capacity 10. With capacity/4, capacity 10 now gives `ghost_cap == 2`.
  In `ghost_hit_admitted_into_main` and
  `ghost_window_expires_after_ghost_cap_plus_one_evictions`, change the
  asserted value to 2. The rest of the expiry test is already written in
  terms of `ghost_cap`, so it should pass unchanged. Keep every invariant
  assertion (`map.len() <= capacity`,
  `small.len() + main.len() == map.len()`,
  `ghost_q.len() <= ghost_cap`).

## Rationale (optional)

Cycle 2 lengthened the ghost and lost hit rate. Cycle 3 cut it to
capacity/2 and gained (0.727 → 0.7306). This is the next point on the
same axis, and it shows whether the optimum is lower still or whether
capacity/4 starts dropping genuine re-references. Nothing else changes,
so any hit-rate difference comes from the ghost size alone.
