# H03

Gating the ghost-hit fast path with a TinyLFU-style count-min frequency sketch, so a ghost-hit key enters `main` only if it is used more often than the `main` entry it would displace, raises hit-rate on workload-a.

## Parent

cycle/0003/v001

## Changes

All edits are in `src/lru_cache/mod.rs`. Use only std, no new crates (Cargo.toml must not change). Keep `ghost_cap = max(1, capacity / 2)`, `small_target = max(1, capacity / 10)` and `MAX_FREQ = 3`.

1. **Add a private `FreqSketch` struct.** It is a count-min sketch with
   4 rows of saturating `u8` counters capped at 15. Each row has width
   `w = next_power_of_two(max(16, capacity))`, stored as one `Vec<u8>`
   of length `4 * w`. Add an `additions: usize` counter and
   `sample = 10 * capacity`.
   - Hash keys with `std::collections::hash_map::DefaultHasher`, built
     with fixed (non-random) state so results are deterministic. Derive
     the 4 row indices from one 64-bit hash, using a different 16-bit
     slice per row (or a multiply-mix by distinct odd constants), masked
     by `w - 1`.
   - `increment(&K)` bumps each of the 4 counters if it is below 15.
     After each increment, add one to `additions`. When
     `additions >= sample`, halve every counter (`c >>= 1`) and halve
     `additions`. This is the aging/reset step.
   - `estimate(&K) -> u8` returns the minimum of the 4 counters.
2. **Add a `sketch: FreqSketch` field to `LruCache`** and build it in
   `try_new`.
3. **Record accesses.** Call `sketch.increment(key)` at the top of
   `get`, for hits and misses alike, before the map lookup. In `put`,
   call it only on the new-key path, after the existing-key early
   return. That way the usual `get`-miss → `put` sequence counts as a
   single access.
4. **Gate the ghost-hit path in `put`.** Keep
   `let ghost_hit = self.ghost_set.remove(&key).is_some();`. Then work
   out whether the key goes to `main`:
   - It goes to `main` only if `ghost_hit` is true, the cache is full
     (`map.len() >= capacity`), `main` is non-empty, and
     `sketch.estimate(&key) > sketch.estimate(&nodes[*main.front()].key)`.
   - If the cache is not full, a ghost hit goes to `main` without the
     comparison, as today.
   - Otherwise the key goes to `small` as a cold miss, with
     `in_main = false`.
   - Set `in_main` from this decision. Push onto `main` or `small` to
     match.
   - The decision must be made before `evict_one()` runs, because that
     call may change `main.front()`.
5. **Leave the rest alone.** `evict_one` and `push_ghost` are unchanged.
6. **Update the unit tests.**
   - Adjust `ghost_hit_admitted_into_main` so the ghosted key has a
     higher sketch frequency than the `main` front. For example, `get`
     it several times while it is resident before it is evicted.
   - Add a test where a ghost-hit key with low frequency lands in
     `small` because it lost to a frequent `main` front.
   - Add a sketch unit test: estimates never go below the true count
     before aging, and halving runs once `additions` reaches `sample`.
   - Keep all capacity and queue invariants.

## Rationale (optional)

Ghost hits are a misleading reuse signal on loops longer than the cache.
The project has so far handled this only by changing the window size.
This hypothesis keeps the window and adds a long-horizon frequency check
instead: a ghost-hit key may displace `main` content only if it is used
more often. If this beats the plain ghost, it explains part of the gap
between S3-FIFO and LIRS through the quality of re-admission decisions,
which the insights point to as the likely cause.
