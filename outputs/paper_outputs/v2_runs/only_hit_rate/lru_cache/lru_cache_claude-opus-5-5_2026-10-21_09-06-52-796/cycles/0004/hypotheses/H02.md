# H02

Routing ghost hits into `small` with a head-start frequency, while requiring two hits for ordinary probation keys to reach `main`, raises hit-rate on workload-a by making every path into `main` depend on reuse while the key is resident.

## Parent

cycle/0003/v001

## Changes

All edits are in `src/lru_cache/mod.rs`. Keep `ghost_cap = max(1, capacity / 2)` and `small_target = max(1, capacity / 10)` as they are.

1. Add `const PROMOTE_FREQ: u8 = 2;`, next to `MAX_FREQ`.
2. Add a `ghosted: bool` field to `Node`. It records that the key was
   re-admitted after a ghost hit. `in_main` stays and keeps its meaning.
3. In `put`, on the new-key path: when `ghost_hit` is true, do **not**
   push the slot onto `main`. Push it onto `small`, the same as a cold
   miss. Initialise the node with `freq = 0`, `in_main = false` and
   `ghosted = ghost_hit`, both when reusing an evicted slot and when
   pushing a new node. Delete the `if ghost_hit { main.push_back }`
   branch, so every new key enters `small`.
4. In `evict_one`, small-queue branch: compute the promotion bar
   `let bar = if node.ghosted { 1 } else { PROMOTE_FREQ };`.
   - If `node.freq >= bar`, promote: set `freq = 0`, `in_main = true`,
     `ghosted = false`, `main.push_back(idx)`, then `continue`.
   - Otherwise evict as today: remove from `map` and call
     `push_ghost(evicted)`. A non-promoted key with `freq` of 1 is still
     ghosted, so it can come back with the lower bar. Return `idx`.
   - The main-queue branch is unchanged.
   - Termination still holds. Every loop iteration either moves a node
     from `small` to `main` (which only happens to nodes that met the
     bar, with their freq reset) or decrements a `main` freq or frees a
     slot.
5. Fix the ghost bookkeeping bug while you are in `push_ghost`. When a
   key is ghosted twice, a stale earlier copy in `ghost_q` can remove the
   newer `ghost_set` entry when it expires. Change `ghost_set` to
   `HashMap<K, u64>`, storing a monotonically increasing insertion
   sequence number. Store `(K, u64)` pairs in `ghost_q`. On pop, remove
   from `ghost_set` only if the stored sequence number matches.
6. Update the unit tests:
   - `ghost_hit_admitted_into_main` should now assert that the ghost-hit
     key lands in `small` (`!in_main`) with `ghosted == true`.
   - Add a test that a ghosted key accessed once is promoted to `main`
     at its next small eviction.
   - Add a test that a non-ghosted key accessed once is evicted
     (ghosted) rather than promoted.
   - Update `main_evictions_not_ghosted` and
     `accessed_small_entry_promoted_to_main` to the new semantics (the
     latter needs two `get`s before the promoting eviction).
   - Keep all capacity and queue-length invariant assertions.

## Rationale (optional)

Cycle 3 v002 raised `PROMOTE_FREQ` alone and stayed flat, because
rejected keys came straight back into `main` through the ghost. Here
both admission paths change together:

- A ghost hit is only a hint. It lowers the bar to one resident hit,
  which matches a normal key under the parent's rules.
- A cold key needs two resident hits.

So `main` is reached only with reuse proven while resident. That is the
lever that has helped in every cycle so far, and it also closes the
long-loop false-positive route through the ghost.
