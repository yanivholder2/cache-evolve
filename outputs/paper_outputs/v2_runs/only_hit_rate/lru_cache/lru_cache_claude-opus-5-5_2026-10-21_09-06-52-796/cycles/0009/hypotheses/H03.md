# H03

Replacing cycle 8 v003's key-cloning ghost (`VecDeque<K>` + `HashMap<K, ()>`) with a `u64` fingerprint ring will lower metadata-size and leave hit rate unchanged.

## Parent

cycle/0008/v003

## Changes

This is a representation-only port. It has been pending since cycle 5, where the fingerprint ring left hit rate unchanged on an ancestor. Do not change the policy at all.

In `src/lru_cache/mod.rs` (v003):

1. Replace `ghost_q: VecDeque<K>` and `ghost_set: HashMap<K, ()>` with:
   - `ghost_ring: Vec<u64>`, a fixed-length ring of size `ghost_cap` with `0` meaning empty, plus a `ghost_head: usize` write cursor.
   - `ghost_count: HashMap<u64, u32>`, mapping fingerprint to its number of live occurrences in the ring.

   Compute the fingerprint from one `std::hash::BuildHasher` stored on the struct, using `RandomState` built once in `try_new`. Hash with `hash_one(&key)`. Remap a result of `0` to `1`.
2. `push_ghost(key)`:
   - Compute `fp`.
   - If `ghost_ring[ghost_head] != 0`, decrement or remove the count of the fingerprint being overwritten.
   - Write `fp`, increment its count, and advance `ghost_head = (ghost_head + 1) % ghost_cap`.

   This preserves the FIFO window of exactly `ghost_cap` `small` evictions and needs no key clone.
3. Ghost check in `put()`:
   - Compute `fp` once.
   - `ghost_hit` is true when `ghost_count` has `fp` with count `> 0`. On a hit, decrement the count and leave the ring slot in place. When that slot is later overwritten, guard the decrement so it saturates at zero, i.e. remove the entry only if it is present.

   This matches v003's "remove from set on hit" semantics up to fingerprint collisions, which are negligible at 64 bits.
4. In `evict_one()`, the `small` branch no longer needs `node.key.clone()` for the ghost. Pass the fingerprint, computed from `&node.key` before `self.map.remove`. The `map.remove` itself still needs the key, so borrow it rather than clone it. Use `let key = std::mem::replace` only if needed. Otherwise compute `fp` from the borrow, then `self.map.remove(&self.nodes[idx].key)`.
5. Keep `small_target`, `ghost_cap`, `MAX_FREQ = 3`, `get()` and the `main` branch unchanged.

Tests:
- Update the ghost tests to query through a helper `fn in_ghost(&self, k: &K) -> bool`.
- Assert that the number of non-zero ring slots stays `<= ghost_cap` under churn.
- Keep `split_ratios_at_2048`.

## Rationale (optional)

Both incumbents are tied at 0.7381, and hit-rate gains have flattened. `metadata-size` (best is 48, held by the baseline) is a fitness dimension no S3-FIFO variant has competed on. The ring stores 8 bytes per ghost slot plus a small count map, instead of two owned key copies plus the overhead of `HashMap` and `VecDeque`. That makes v003's 332-entry ghost cheaper. The claim is refuted if hit rate moves or metadata-size does not fall.
