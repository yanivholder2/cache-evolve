# H02

Adding a separate small ghost of keys evicted from `main`, so that a quickly re-requested `main` victim goes straight back into `main` and skips `small`, will raise hit rate on workload-a.

## Parent

cycle/0008/v003

## Changes

This changes what feeds the ghost, which is a new lever. The existing `small` ghost is left unchanged.

In `src/lru_cache/mod.rs` (v003):

1. Add three fields to `LruCache`:
   - `main_ghost_q: VecDeque<K>`
   - `main_ghost_set: HashMap<K, ()>`
   - `main_ghost_cap: usize`

   In `try_new`, set `main_ghost_cap = max(1, capacity / 32)` (64 at size 2048). Pre-size both containers to `main_ghost_cap + 1`. Add it to the `log::info!` line.
2. In `evict_one()`, `main` branch: when a node with `freq == 0` is evicted, call a new `push_main_ghost(evicted)` instead of dropping the key. It mirrors `push_ghost` and enforces `main_ghost_cap` FIFO-wise.
3. In `put()`, on a new key:
   - Compute `ghost_hit = self.ghost_set.remove(&key).is_some() || self.main_ghost_set.remove(&key).is_some()`, using short-circuit order: `small` ghost first.
   - If the key was found in the `small` ghost, also remove it from `main_ghost_set` if present, so a key never sits in both sets with live membership. Stale `VecDeque` entries are tolerated, the same way `push_ghost` already tolerates them.
   - A main-ghost hit takes the existing ghost-hit route: `in_main = true`, `freq = 0`, `main.push_back`. Give it no starting credit.
4. Keep `ghost_cap`, `small_target`, `MAX_FREQ = 3` and the `small` branch of `evict_one()` exactly as in v003.

Tests:
- Rewrite `main_evictions_not_ghosted` as `main_evictions_enter_main_ghost`. After eviction from `main`, the key must be in `main_ghost_set`, and re-putting it must land in `main`.
- Add `main_ghost_q.len() <= main_ghost_cap` checks to the churn tests.

## Rationale (optional)

Every cycle so far has tuned only the `small`-eviction ghost. Today a `main` victim that is re-requested a little later must pass through the 25-slot `small` again and is usually lost. The cycle 8 SIEVE result showed that zero-credit keys in `main` are often reused "later, just not right away". A short window keeps the new path strict, in line with the history that loose admission hurts.

How to read the result:
- A gain means the reuse that `main` evicts too early is recoverable.
- A loss means `main` eviction already rejects keys correctly. It also closes the "feed the ghost" question.
