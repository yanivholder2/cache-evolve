## Parent

cycle/0008/v003

## Changes

Start from v003's `src/lru_cache/mod.rs` and change only these two things:

1. Change `const MAX_FREQ: u8 = 3;` to `const MAX_FREQ: u8 = 7;`.
2. In `evict_one()`, in the `small` branch (`if self.small.len() >= self.small_target || self.main.is_empty()`), replace `node.freq = 0;` with `node.freq -= 1;` inside the `if node.freq > 0` promotion block. A key hit k times in `small` then enters `main` with `k - 1` credits, where it used to get 0. Keep `node.in_main = true; self.main.push_back(idx); continue;` unchanged.

Leave these exactly as they are in v003: the split (`small_target = max(1, capacity / 80)`, `ghost_cap = max(1, 13 * capacity / 80)`), the ghost-hit path in `put()` (it still inserts with `freq = 0`; do not add a starting credit on the ghost path), the `main` branch of `evict_one()`, and `push_ghost()`.

Termination still holds: each loop iteration either lowers some node's `freq` or frees a slot.

Tests in `mod.rs`:
- Add one in-file test. Fill a cache of capacity 160, so `small_target = 2`. `get` one key in `small` three times, force its promotion, and assert that it lands in `main` with `freq == 2`.
- Add a second test asserting that a key hit once in `small` arrives in `main` with `freq == 0`.
- Keep all of v003's existing tests and update any that hard-code `MAX_FREQ`-dependent behaviour.

## Rationale (optional)

The cycle 8 insight asks for exactly this combined check as the cheap stacking test. Read the result this way:
- If hit rate does not beat 0.7381, carryover and the smaller `small` overlap as predicted. Credit work on the `small` path is then closed.
- If it gains, the two levers are independent and the line can continue.
