# H02

Shrinking `small` to `capacity/40` and growing the ghost to `3*capacity/20`, which keeps `small + ghost` about constant, will raise hit-rate above cycle/0006/v003's 0.7364 by moving more resident slots into `main`.

## Changes

In `src/lru_cache/mod.rs`, `LruCache::try_new`:
- Change `small_target` from `max(1, capacity / 20)` to `max(1, capacity / 40)`. At capacity 2048 that is 51, down from 102.
- Change `ghost_cap` from `max(1, capacity / 8)` to `max(1, capacity * 3 / 20)`. At capacity 2048 that is 307, up from 256. Write it as `max(1, capacity.saturating_mul(3) / 20)` so it can't overflow and gives exactly 307 at 2048. Don't use `(capacity / 20) * 3`, which gives 306.
- Update the `log::info!` line to report the new ratios.

At 2048, `small + ghost` goes from 358 to 358 (51 + 307): the combined admission window is unchanged, and 51 resident slots move from probation to `main`. Keep `MAX_FREQ = 3` and leave `get`, `put`, `evict_one` and `push_ghost` unchanged, so the split is the only variable.

Tests: at capacity 16 the new formula still gives `ghost_cap = 48 / 20 = 2` and `small_target = 1`, so the existing assertions in `ghost_hit_admitted_into_main` and `ghost_window_expires_after_ghost_cap_plus_one_evictions` should still hold. Check them anyway. Add a test at capacity 2048 that asserts `small_target == 51` and `ghost_cap == 307`. Add a churn test at capacity 400 (small 10, ghost 60) that checks `small.len() + main.len() == map.len()` and `ghost_q.len() <= ghost_cap`.

## Rationale (optional)

This tests the "constant combined window" rule that cycle 6 proposed. If hit-rate rises, the ghost is the cheaper form of probation and the shift can go further. If it falls, `small` has hit its floor: too many keys reach `main` through the ghost with `freq = 0`, or `small`'s in-queue reuse window is now too short to catch reuse gaps that the ghost doesn't cover.
