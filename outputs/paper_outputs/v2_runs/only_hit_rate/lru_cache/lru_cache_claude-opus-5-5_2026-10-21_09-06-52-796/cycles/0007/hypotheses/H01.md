# H01

Raising `MAX_FREQ` from 3 to 7 on top of cycle/0006/v003's `small = capacity/20` split will raise hit-rate above 0.7364, because main-retention depth and admission-window split are independent levers.

## Parent

cycle/0006/v003

## Changes

In `src/lru_cache/mod.rs`, change `const MAX_FREQ: u8 = 3;` to `const MAX_FREQ: u8 = 7;`. Leave everything else exactly as in v003: `small_target = max(1, capacity / 20)`, `ghost_cap = max(1, capacity / 8)`, the saturating increment in `get` and in the update branch of `put`, the `evict_one` logic (a `small` pop with `freq > 0` resets freq to 0 and moves to `main`; a `main` pop with `freq > 0` decrements by 1 and reinserts), and ghost-hit admission straight into `main`. `Node.freq` stays `u8`.

Add an in-file test `freq_saturates_at_max_freq`: put a key, call `get` 20 times, and assert the node's `freq == MAX_FREQ` (7). Add a test at capacity 2048 that asserts `small_target == 102` and `ghost_cap == 256`, so the v003 ratio is actually exercised. The existing `capacity_bound_under_churn` invariants must still hold.

## Rationale (optional)

Cycle 6's v002 got a small gain from MAX_FREQ=7 when `small` was capacity/10, and v003 won by shrinking `small`. The two changes touch different code (retention credits in `main` vs. probation size) and were never combined. This variant changes one thing, so it directly tests whether they stack. If hit-rate lands near v003's 0.7364, the two overlap: v003's bigger `main` already absorbed the retention benefit.
