# H02

Replace the S3-FIFO ghost's `VecDeque<K>` plus `HashMap<K, ()>` with a fixed-size ring of 64-bit key fingerprints at the same capacity / 4 window to lower metadata-size and per-op-time while holding hit rate.

## Parent

cycle/0004/v001

## Changes

This is a representation-only change in `src/lru_cache/mod.rs`. The ghost-admission
policy stays exactly as it is in the parent: `ghost_cap = max(1, capacity / 4)`, only
evictions from `small` are ghosted, and a ghost hit goes straight into `main`.

1. Remove the fields `ghost_q: VecDeque<K>` and `ghost_set: HashMap<K, ()>`. Replace them with:
   - `ghost_ring: Vec<u64>`, length `ghost_cap`, filled with 0. It stores fingerprints in FIFO order.
   - `ghost_head: usize`, the next write position.
   - `ghost_map: HashMap<u64, u32>`, which maps a fingerprint to the ring slot that currently holds it.
2. Add `fn fingerprint(key: &K) -> u64`. It hashes the key with
   `std::collections::hash_map::DefaultHasher` (no external crates), then applies `| 1`
   so the value is never 0. That keeps 0 free as the "empty slot" marker.
3. `push_ghost(key)`: compute `fp`. If `ghost_ring[ghost_head] != 0`, take the old
   fingerprint and remove it from `ghost_map`, but **only if**
   `ghost_map[old] == ghost_head`. This is the stale-entry fix: an older slot can no
   longer erase a newer insertion of the same fingerprint. Then write `fp` into the
   slot, set `ghost_map.insert(fp, ghost_head as u32)`, and advance `ghost_head` modulo `ghost_cap`.
   The evicted key no longer has to be cloned into the ghost.
4. Ghost lookup in `put`: replace `ghost_set.remove(&key)` with: compute `fp`. If
   `ghost_map.remove(&fp)` returns `Some(slot)`, set `ghost_ring[slot] = 0` and treat
   it as a ghost hit.
5. In `try_new`, pre-size `ghost_map` with `with_capacity(ghost_cap)`.
6. Update the unit tests that touch `ghost_q` or `ghost_set`. Use a small
   `#[cfg(test)] fn ghost_contains(&self, k: &K) -> bool` helper, and assert that
   `ghost_map.len() <= ghost_cap` wherever the tests currently check `ghost_q.len()`.

Invariants: `ghost_map.len() <= ghost_cap`. Every value in `ghost_map` points to a
ring slot that holds that same fingerprint. The resident structures (`map`, `nodes`,
`small`, `main`) and `evict_one`'s logic are unchanged.

## Rationale (optional)

Since cycle 2, every cycle insight has recommended running this experiment with the ghost window held fixed, and it has never
been run. The ghost no longer stores `K` (no key clones, no `K`-sized hash entries). Fingerprint collisions
are rare at 2^64, so hit rate should stay within noise of 0.7329. Any gain should appear in
`metadata-size` and `per-op-time`. It also carries the sequence-style stale-erase fix forward.
