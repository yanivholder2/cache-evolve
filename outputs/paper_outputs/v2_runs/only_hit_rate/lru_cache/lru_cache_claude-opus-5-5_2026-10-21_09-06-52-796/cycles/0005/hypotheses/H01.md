# H01

Shrink the S3-FIFO ghost window from capacity / 4 to capacity / 8 to raise hit rate on workload-a by finding where the ghost-size curve turns over.

## Parent

cycle/0004/v001

## Changes

Change one knob in `src/lru_cache/mod.rs`, `LruCache::try_new`: replace
`let ghost_cap = std::cmp::max(1, capacity / 4);` with
`let ghost_cap = std::cmp::max(1, capacity / 8);`. At size 2048 that takes the
ghost from 512 to 256 remembered keys. Update the comment and the `log::info!`
line to match. Leave everything else as it is in the parent: `small_target = max(1, capacity / 10)`,
`MAX_FREQ = 3`, ghost hits go straight into `main`, the `evict_one` loop and
`push_ghost`.

The in-file unit tests assume `ghost_cap == 2` at capacity 10
(`ghost_hit_admitted_into_main` and
`ghost_window_expires_after_ghost_cap_plus_one_evictions`). With `/8`, capacity 10 gives
`ghost_cap == 1`. Change those tests to use capacity 16 (`ghost_cap == 2`,
`small_target == 1`) and adjust their key ranges, for example `1..=16` to fill and
then 17 onward to evict. Keep the meaning of each test the same. Do not touch
anything under `tests/`.

## Rationale (optional)

The ghost has been halved twice and both times hit rate went up (0.727 → 0.731 →
0.733), but the gains are getting smaller. This is the probe that cycle 4 asked
for. If hit rate drops, capacity / 4 is the optimum and the ghost size gets frozen.
If it rises, the next probe is capacity / 16. Only the ghost size changes, so the
result can be read cleanly.
