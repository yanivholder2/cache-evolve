# H03

Gate every entry into `main` with a TinyLFU count-min sketch that compares the candidate against the real CLOCK eviction victim of `main`, to raise hit rate on workload-a.

## Parent

cycle/0004/v001

## Changes

All changes are in `src/lru_cache/mod.rs`. Keep `ghost_cap = capacity / 4`,
`small_target = capacity / 10` and `MAX_FREQ = 3`.

1. **Sketch.** Add a `FreqSketch` struct with:
   - 4 rows of `u8` counters. Width `w = next_power_of_two(max(16, capacity * 2))`. Store them in one flat `Vec<u8>` of length `4 * w`.
   - Per-row seeds. Index row `i` with `(h ^ seed_i).wrapping_mul(0x9E3779B97F4A7C15) >> shift`, masked to `w - 1`, where `h` is one `DefaultHasher` hash of the key per operation.
   - `increment` saturates at 15. `estimate` returns the minimum across the rows.
   - An `additions` counter. When it reaches `10 * capacity`, halve every counter (`c >>= 1`) and halve `additions`. This is the aging step.

   Call `sketch.increment(key)` once at the top of `get` (on hit or miss) and once at
   the top of `put`, for every access.
2. **`fn main_victim(&mut self) -> Option<u32>`.** Run `main`'s existing CLOCK sweep:
   pop from the front; if `freq > 0`, decrement and push to the back; repeat until the
   front node has `freq == 0`. Leave that node at `main.front()` and return its index.
   This is the node that `evict_one` would actually evict next. Doing the sweep here is
   safe because `evict_one` would perform the same decrements later.
3. **Gate on both routes into `main`.** The gate is active only when
   `main.len() + 1 > capacity - small_target`, meaning admitting the candidate would
   displace a main resident. When it is active, call `main_victim()` and admit only if
   `estimate(candidate) > estimate(victim_key)`.
   - **Ghost-hit insert in `put`:** if the gate rejects, push the new node into `small`
     instead of `main` (`in_main = false`).
   - **Promotion from `small` in `evict_one`** (the `node.freq > 0` branch): if the gate
     rejects, treat the node as cold. Remove it from `map`, ghost it with `push_ghost`, and
     return its slot as the eviction, just like the existing freq-0 path.
4. Termination: `main_victim` always finds a freq-0 node within at most
   `MAX_FREQ * main.len()` steps. `evict_one` still frees exactly one slot per call.
   Preserve `small.len() + main.len() == map.len()` and `map.len() <= capacity`.
5. Unit tests: the existing tests use capacities of 10 or less, where the gate seldom
   triggers. Fix any test whose expectation changes, keeping what it checks. Add a test
   that, with `main` full, a ghost-hit key with a lower sketch count than the victim
   lands in `small`.

## Rationale (optional)

Cycle 4's v003 gated only the ghost path and compared against `main.front()`. It
leaked through the `small` promotion route and compared against the wrong entry, and
still gained slightly (0.7314 against a 0.731 parent). This version fixes both of
the flaws that cycles 3 and 4 identified, covering every route into `main` and comparing against the true victim. It tests whether
frequency-based admission adds hit rate beyond what the short ghost already gives.
Cycle 4 also advised waiting for cost measurements before bringing the sketch back.
This variant goes ahead anyway, on the hit-rate dimension only, and its sketch cost
should be judged once `per-op-time` is reported.
