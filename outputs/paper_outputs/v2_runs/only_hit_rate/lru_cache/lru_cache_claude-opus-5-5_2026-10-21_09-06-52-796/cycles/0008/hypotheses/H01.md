# H01

Carry surplus resident-hit credits from `small` into `main` on promotion, together with `MAX_FREQ = 7`, to raise hit rate by letting multi-hit keys in `main` outlast keys that showed reuse only once.

## Parent

cycle/0007/v002

## Changes

All edits are in `src/lru_cache/mod.rs`.

1. Change `const MAX_FREQ: u8 = 3;` to `const MAX_FREQ: u8 = 7;`.
2. In `evict_one()`, `small` branch: when the popped node has `node.freq > 0`, it is currently reset with `node.freq = 0` before `self.main.push_back(idx)`. Replace that reset with `node.freq -= 1;`. The first resident hit pays for admission to `main`, as it does now. Every extra hit seen while in `small` becomes a carried credit, so a key hit once in `small` still arrives with `freq = 0` and keeps today's behaviour. Keep `node.in_main = true` and the `continue`.
3. Leave the ghost-hit path in `put()` unchanged. Ghost arrivals still start at `freq = 0`. This keeps one rule for both admission paths: a key's starting credit in `main` is the number of resident hits it had beyond the first, and a ghost arrival had none. Unlike cycle 7's v003, ghost arrivals get no free credit.
4. Leave `get`, the existing-key branch of `put`, the `main` branch of `evict_one` (decrement and reinsert), `push_ghost`, `small_target = capacity / 40` and `ghost_cap = 3 * capacity / 20` unchanged.
5. Termination still holds: each loop iteration either lowers some node's `freq` by at least 1 or frees a slot.
6. Tests: add an in-file test. Put a key in `small`, `get` it three times, then force it out of `small`. Assert it is now `in_main` and its node has `freq == 2`. Also check that a key with a single hit arrives with `freq == 0`. The existing tests must still pass.

## Rationale

Cycle 7 found that a higher `MAX_FREQ` barely helps because both admission paths reset credits to zero. Credits then only build up during `main` residency, which with lazy reinsertion is slow. Carrying credits over is the evidence-respecting way to make the higher cap matter. The credit comes only from hits actually observed while resident, which is exactly the stronger evidence that v003's ghost credit lacked. If hit rate rises over v002 by more than `MAX_FREQ = 7` alone gave (cycle 7 v001), carryover is the lever. If it is flat, credit work in `main` is exhausted.
