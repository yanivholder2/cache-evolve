# H03

Halve `small` again to `capacity / 80` and grow the ghost to `13 * capacity / 80` so the combined admission window stays the same, to test whether shifting more resident probation into the ghost still raises hit rate or whether `capacity / 40` is the floor.

## Parent

cycle/0007/v002

## Changes

All edits are in `src/lru_cache/mod.rs`, in `try_new()`. This is a single-knob change.

1. Change `let small_target = std::cmp::max(1, capacity / 40);` to `std::cmp::max(1, capacity / 80);`. At size 2048 this gives 25, down from 51.
2. Change `let ghost_cap = std::cmp::max(1, capacity.saturating_mul(3) / 20);` to `std::cmp::max(1, capacity.saturating_mul(13) / 80);`. At size 2048 this gives 332, up from 307. `small + ghost` becomes 357, against v002's 358, so the combined window stays essentially the same.
3. Update the `log::info!` line and the comments to say `capacity / 80` and `13 * capacity / 80`.
4. Do not change `MAX_FREQ` (it stays 3), `get`, `put`, `evict_one` or `push_ghost`. The split is the only variable, so the result can be compared directly with the cycle 6 → 7 step.
5. Update the in-file tests that pin ratios. In `split_ratios_at_2048`, expect `small_target == 25`, `ghost_cap == 332` and a sum of 357. In `capacity_bound_under_churn_400`, expect `small_target == 5` and `ghost_cap == 65`. In `ghost_hit_admitted_into_main` and `ghost_window_expires_after_ghost_cap_plus_one_evictions` at capacity 16, `ghost_cap` becomes `208 / 80 = 2`, unchanged, and `small_target` stays 1, so their asserts still hold. Re-check every hard-coded constant anyway. Add a churn test at capacity 1600 (`small_target = 20`) so the new ratio is exercised with a non-trivial `small`.

## Rationale

The halving steps from `/10` to `/20` to `/40` each helped, by less each time. That is the same shrinking-gains curve the ghost-only halvings followed before they went flat at `/16`. This probe finds where the curve turns. If hit rate rises, the ghost is still cheaper probation than resident slots. If it falls, the two forces cycle 7 named have taken over: less reuse caught in `small`, and more ghost arrivals with no credit. Either way the result settles the `small`/ghost split and frees later cycles for other levers. Compare against H01: if carrying credits over helps, a smaller `small` may need it, and the next cycle could combine the two.
