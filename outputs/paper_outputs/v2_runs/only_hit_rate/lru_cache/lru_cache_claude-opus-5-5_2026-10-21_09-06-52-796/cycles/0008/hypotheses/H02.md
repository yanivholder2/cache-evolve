# H02

Replace `main`'s FIFO-with-reinsertion with a SIEVE-style in-place hand, so survivors keep their position and new arrivals are examined first, to raise hit rate through quicker demotion of keys that entered `main` and were never reused.

## Parent

cycle/0007/v002

## Changes

All edits are in `src/lru_cache/mod.rs`. `small`, the ghost, the split constants (`capacity / 40`, `3 * capacity / 20`), `MAX_FREQ = 3`, `get` and both admission routes into `main` stay exactly as in v002. Only how `main` picks its victim changes.

1. Make `main` an intrusive doubly linked list over the arena. Add `prev: u32` and `next: u32` to `Node` (sentinel `NIL = u32::MAX`). Replace `main: VecDeque<u32>` with `main_head: u32` (newest), `main_tail: u32` (oldest), `main_len: usize` and `hand: u32` (`NIL` = start at the tail). Add the helpers `main_push_head(idx)` and `main_unlink(idx)`. If the unlinked node is the one under `hand`, `main_unlink` must first move `hand` to that node's `prev`.
2. Every place that did `self.main.push_back(idx)` for a new arrival must call `main_push_head(idx)` instead. That covers promotion from `small` in `evict_one()` and a ghost hit in `put()`.
3. Rewrite the `main` branch of `evict_one()` as a SIEVE sweep. Start at `hand`, or at `main_tail` if `hand == NIL`. While the current node has `freq > 0`, decrement its `freq` and leave it **in place**. Do not unlink or reinsert it. Then step `hand` to `node.prev` (toward the head), wrapping to `main_tail` when it reaches `NIL`. When a node with `freq == 0` is found, set `hand = node.prev`, unlink the node, remove its key from `map` and return its slot. Main evictions still do not go into the ghost.
4. Replace `self.main.is_empty()` / `self.main.len()` with `main_len == 0` / `main_len`. Update the in-file tests that assert `small.len() + main.len() == map.len()` to use `main_len`. Keep that invariant, and add a debug check that walking from `main_head` reaches exactly `main_len` nodes.
5. Termination: every step of the sweep either decrements a positive `freq` or evicts a node, so the loop is bounded by `main_len * MAX_FREQ + 1` steps.
6. Tests: add a test in which an old `main` survivor (freq > 0) is retained, and a newly promoted key with `freq == 0` that sits between the hand and the head is evicted on a later sweep before the survivor is visited again. Also run the existing churn tests with the new invariant.

## Rationale

Every win so far has come from admission filtering, and retention tuning in the form of credit caps has stalled. This is a different retention lever: the order in which `main` is scanned. In FIFO with reinsertion, a surviving key moves behind every new arrival, so a new arrival that is never reused sits in `main` for a full rotation. In SIEVE, survivors stay where they are and the hand reaches recent arrivals sooner relative to proven keys. With `small` now only a fortieth of capacity, more keys arrive in `main` with weak evidence (ghost hits with `freq = 0`), so demoting them quickly should matter more than it did before. If this does not beat v002's 0.7377, scan order is not a limiting factor.
