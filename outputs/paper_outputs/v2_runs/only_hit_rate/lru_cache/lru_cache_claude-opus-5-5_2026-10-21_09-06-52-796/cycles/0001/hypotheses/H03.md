# H03

Keeping exact LRU semantics but replacing SipHash with an in-crate Fx-style hasher and shrinking the recency links to `u32` with a sentinel will lower get p50 below the baseline's 41 ns.

## Parent

baseline

## Changes

Edit only `src/lru_cache/mod.rs`, or add a new sibling module such as `src/lru_cache/fx_hash.rs` declared from `mod.rs`. Do not edit `Cargo.toml`, so no external crates. Do not touch `lru_cache_jni.rs`. Keep the public API unchanged: `LruCache<K, V>`, `Node<K, V>`, `try_new`, `new`, `get`, `put`, and the `framework::Cache` impl. Eviction order must stay exactly LRU, and all existing unit tests in `mod.rs` must still pass unmodified.

1. Hasher: implement `FxHasher`, a `std::hash::Hasher` with a `u64` state. `write_u64(x)` does `state = (state.rotate_left(5) ^ x).wrapping_mul(0x51_7c_c1_b7_27_22_0a_95)`. `write` folds bytes in 8-byte chunks the same way, with `write_u8`/`write_u32`/`write_usize` handled similarly, and `finish()` returns `state`. Add `type FxBuild = BuildHasherDefault<FxHasher>;` and change `map` to `HashMap<K, u32, FxBuild>`, built with `HashMap::with_capacity_and_hasher(capacity, FxBuild::default())`.
2. Links: in `Node`, replace `prev: Option<usize>` and `next: Option<usize>` with `prev: u32` and `next: u32`, using `const NIL: u32 = u32::MAX;`. Do the same for `head`/`tail` in `LruCache`. In `try_new`, reject `capacity >= u32::MAX as usize` by returning None with a log error. Update `unlink` and `push_back` to compare against `NIL` instead of matching on `Option`.
3. Fast path in `get` and the existing-key branch of `put`: if `idx == self.tail`, the node is already MRU, so skip `unlink`/`push_back` entirely.
4. Eviction branch in `put`: replace `map.remove(&evicted_key)` after `key.clone()` with a swap. Write the new key into the node using `std::mem::replace(&mut self.nodes[head_idx].key, key.clone())`, then remove the old key it returns from `map`. This avoids cloning the evicted key.

Invariants P1–P3 and strict LRU order are preserved because only the representation changes, not the policy.

## Rationale (optional)

At 41 ns per get, SipHash-1-3 over a `u64` key accounts for a large part of the cost. An Fx-style multiply-rotate hash takes a few cycles. Narrower `u32` links make `Node<u64,u64>` 24 bytes, so more nodes fit per cache line during splices. The tail fast path avoids pointless splices on repeated hits. This hypothesis is the control arm: it leaves hit rate unchanged and isolates the speed gain.
