# H01

Replacing move-to-MRU promotion with an S3-FIFO admission scheme (small probation FIFO, main FIFO with lazy reinsertion, and a ghost queue) will raise hit rate above the baseline's 0.6652 on the scan- and loop-heavy LIRS workload-a at capacity 2048.

## Parent

baseline

## Changes

Rewrite the policy in `src/lru_cache/mod.rs` and leave the public surface the JNI and bins depend on unchanged: `pub struct LruCache<K, V>`, `pub struct Node<K, V>`, `try_new`, `new`, `get(&mut self, &K) -> Option<&V>`, `put(&mut self, K, V)`, and the `framework::Cache` impl. Do not touch `lru_cache_jni.rs`.

Data layout:
- `Node<K, V>` becomes `{ key: K, value: V, freq: u8, in_main: bool }`. Remove `prev`/`next`. Nodes still live in the `nodes: Vec<Node>` arena, and evicted slots are reused in place.
- `LruCache` keeps `map: HashMap<K, u32>` (key → arena index) and adds `small: VecDeque<u32>` and `main: VecDeque<u32>` (arena indices in FIFO order), `small_target = max(1, capacity / 10)`, and a ghost structure: `ghost_q: VecDeque<K>` bounded to `capacity - small_target` entries (minimum 1), plus `ghost_set: HashMap<K, ()>`. On every push, pop the front of `ghost_q` once it is over the bound and remove that key from `ghost_set`. Remove `head`/`tail`.

Behaviour:
- `get`: on a hit, set `freq = min(freq + 1, 3)`. No queue movement. On a miss, return None.
- `put` with an existing key: overwrite the value and bump `freq` as in `get`. Do not move the node.
- `put` with a new key: if `map.len() == capacity`, call `evict_one()` first and reuse the freed slot; otherwise push a new arena node. If the key is in `ghost_set`, remove it from the ghost, set `in_main = true` and push the index onto `main`. Otherwise push it onto `small`. New nodes start with `freq = 0`.
- `evict_one()`: if `small.len() >= small_target` or `main` is empty, pop from the front of `small`. If that node has `freq > 0`, clear its freq, set `in_main = true`, push it onto `main`, and loop. Otherwise remove it from `map`, push its key onto the ghost, and return its slot. If instead we evict from `main`: pop the front. If `freq > 0`, decrement freq and push the node back onto `main`, then loop. Otherwise remove it from `map` and return the slot. Main evictions are not added to the ghost. The loop must stop: each pass lowers a freq or frees a slot.
- Invariants to keep: `map.len() <= capacity` at all times (gate P1), the value stored on put is the value read back (P2), and only keys that were put can be resident (P3). Capacity 1 must work: `small_target = 1` and main stays empty, so evictions come from small.

Tests: the strict-LRU unit tests in `mod.rs` (`eviction_removes_lru`, `access_updates_lru_order`, `put_updates_lru_order`, `repeated_get_preserves_eviction_order`, `get_middle_node_promotes_correctly`, `overwrite_mru_at_capacity`, `slot_reuse_after_promotion_and_re_eviction`) assert exact LRU victims. Replace them with S3-FIFO-specific tests: one-hit wonders are evicted from small first, an accessed small entry is promoted to main, and a ghost hit is admitted straight into main. Keep the capacity, overwrite and miss tests.

## Rationale (optional)

LIRS traces contain loops and scans larger than the cache, and strict LRU handles these badly: each scanned block flushes the reusable working set. S3-FIFO's small probation queue filters one-hit wonders. The ghost lets keys with real reuse re-enter main directly. As a side effect, `get` becomes a byte increment instead of two list splices.
