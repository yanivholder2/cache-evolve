# H02

Splitting the main LRU into a probation and a protected segment should raise hit-rate on workload-a by retaining re-referenced entries that a single LRU evicts too early.

## Parent

baseline

## Changes

Leave the TinyLFU frequency sketch, its increment/estimate logic, and the admission comparison exactly as in baseline. Replace the single main-region LRU list with two LRU lists: a probation segment and a protected segment, with the protected segment capped at roughly 80% of the main region's capacity (e.g. `protected_cap = main_cap * 4 / 5`, minimum 1). New entries that pass admission are inserted at the MRU end of probation. On a hit to an entry in probation, move it to the MRU end of protected; if protected is over its cap, demote protected's LRU entry to the MRU end of probation (not out of the cache). On a hit to an entry already in protected, move it to protected's MRU end. Victim selection when the main region is full evicts from the LRU end of probation; fall back to the LRU end of protected only if probation is empty. Keep the window/admission entry point and the sketch update call sites unchanged, so that the only behavioural difference is the ordering inside the main region. Preserve the per-entry key/value bookkeeping and the existing index map; add only the segment tag and the second pair of list head/tail pointers.

## Rationale (optional)

Cycle 0002 recorded that a recency window in front of the LRU lost hit-rate, but did not test the main region's own recency policy. Segmenting the main region changes which entries are evicted, not when admission sees a key, so it is a distinct claim from the window experiment. Falsified if hit-rate on workload-a at size 2048 does not exceed 0.7362.
