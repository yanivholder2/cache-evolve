# H02

Applying conservative update to the count-min sketch, so each access raises only the minimum counters across rows, should raise hit-rate on workload-a at size 2048 by lowering over-counting from colliding keys without adding any sketch memory.

## Parent

baseline

## Changes

Edit `CountMinSketch::increment` in `src/tiny_lfu/mod.rs`. Replace the current per-row unconditional increment loop with a conservative update:

1. Compute the row positions once: `let mut pos = [0usize; SKETCH_DEPTH];` and fill `pos[row] = self.position(key, row as u64)` for each row. A fixed-size array avoids a per-call allocation.
2. Compute `min = min over rows of self.counts[row][pos[row]]`.
3. For each row where `self.counts[row][pos[row]] == min` and `min < MAX_COUNT`, increment that counter. Leave counters above the minimum untouched.

Leave `estimate`, `position`, `heap_bytes`, `new`, `TinyLfuCache::get`, `TinyLfuCache::put`, and `try_new` unchanged. The counter table shape is unchanged, so `sketch_heap_bytes()` matches baseline exactly.

Invariant to preserve: `estimate()` must remain an upper bound on the true access count for each key (conservative update keeps this property, because the minimum counter always reaches at least the true count). Keep the `MAX_COUNT` saturation behaviour.

Expected direction: `estimate()` for the victim and incoming keys in `put()` should be closer to true frequencies, so the admission comparison `incoming_freq > victim_freq` is decided on less collision noise. Report hit-rate on workload-a at size 2048 and `sketch_heap_bytes()` at that capacity.
