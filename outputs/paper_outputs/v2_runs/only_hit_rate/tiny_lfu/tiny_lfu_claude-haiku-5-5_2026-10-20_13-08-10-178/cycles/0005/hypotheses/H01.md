# H01

Holding sketch memory at baseline size by halving the sketch depth to 2 while keeping the width factor at 8 should raise hit-rate above 0.741 on workload-a at size 2048, because wider rows keep the collision-error gain while the extra counters are paid for by removing rows.

## Parent

cycle/0004/v002

## Changes

Edit `src/tiny_lfu/mod.rs`, keeping `SKETCH_WIDTH_FACTOR = 8` as in the parent. Change `SKETCH_DEPTH` from `4` to `2`.

Because `CountMinSketch::new`, `increment`, `estimate`, `position`, and `heap_bytes` all loop over `self.depth` (not the constant), no other code needs to change; the row seed in `position()` already works for any row index.

Memory check at capacity 2048: the parent's width is `next_power_of_two(2048 * 8) = 16384`, so its counter table is `4 * 16384 * 4 = 262144` bytes. The depth-2 variant has the same width, so its table is `2 * 16384 * 4 = 131072` bytes, half the parent's and equal to baseline's `4 * 8192 * 4 = 131072` bytes (baseline width is `2048 * 4 = 8192`). Keep `try_new` and `sketch_heap_bytes` unchanged so the metadata-size reading is directly comparable to baseline.

Invariants to preserve: `put`/`get` logic, the admission comparison `incoming_freq > victim_freq`, the `MAX_COUNT` saturation check, and the probation/protected ordering (this subject has no separate segments at the parent; do not add any). Report hit-rate on workload-a at size 2048 and `sketch_heap_bytes()` at the same capacity.
