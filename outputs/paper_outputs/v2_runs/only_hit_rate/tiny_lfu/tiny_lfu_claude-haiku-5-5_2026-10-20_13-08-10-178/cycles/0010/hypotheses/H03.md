# H03

Counting only `put()` accesses in the frequency sketch, and not `get()` accesses, should raise hit-rate by keeping read probes from inflating admission estimates for keys that are only read.

## Parent

baseline

## Changes

In src/tiny_lfu/mod.rs, delete the `self.sketch.increment(key);` line at the top of `TinyLfuCache::get()` so that reads no longer touch the sketch, hit or miss. Keep `self.sketch.increment(&key);` in `put()` as it is, so only writes feed the frequency estimate. Leave `promote()`, `estimate()`, `position()`, `select_victim()`, and the admission comparison `incoming_freq > victim_freq` in `put()` unchanged. Add a one-line comment on `get()` saying reads do not update the sketch. The tests in `mod tests` only use public behaviour and should still compile; if `eviction_prefers_hot_items` or `low_frequency_new_item_is_rejected` no longer hold because they relied on `get()` counting, adjust only their setup calls to use `put()`.

## Rationale (optional)

The admission comparison uses sketch estimates of the newcomer and the victim, and `get()` currently adds frequency on every read, including misses for keys that are never inserted. Cycle 0006 found that filtering first touches out of the update path loses hit-rate, so this is a real risk. It differs from that family in that it removes read-side counting entirely rather than gating writes, and its outcome is not predictable from the cycle 0006 result alone.
