# H01

Stacking the conservative-update rule onto the width-8 sketch of cycle/0004/v002 raises hit-rate above 0.741 on workload-a at size 2048 by removing the over-counts that the wider rows still leave behind.

## Parent

cycle/0004/v002

## Changes

Start from cycle/0004/v002, which keeps `SKETCH_WIDTH_FACTOR` at 8 and `SKETCH_DEPTH` at 4. Change `CountMinSketch::increment` so that, for each key, it first computes the minimum counter value across the rows and then raises only the counters that equal that minimum. Counters above the row minimum stay untouched. Leave `estimate()` as the min-across-rows read, and leave the counter table shape, `put()`, `get()`, and `evict_one()` unchanged. Do not add any halving, decay, or aging to `record()`. This variant tests whether the Cycle 0005 conservative-update gain and the Cycle 0004 width gain stack, or whether they overlap and cancel.

## Rationale (optional)

Cycle 0005 v002 showed conservative update gaining on the baseline sketch, and cycle/0004/v002 showed width gaining on the same trace, but nothing has tested them together. Both target collision over-counting, so they may overlap. Measuring the combination on the incumbent answers that directly.
