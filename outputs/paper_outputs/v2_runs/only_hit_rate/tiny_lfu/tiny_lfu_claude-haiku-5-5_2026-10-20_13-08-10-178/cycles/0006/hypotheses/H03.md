# H03

Gating first-time keys through a doorkeeper bit set before they reach the frequency sketch raises hit-rate on workload-a at size 2048 by keeping one-touch keys from inflating sketch counters that admission reads.

## Parent

baseline

## Changes

Add a doorkeeper, a small bit vector with two hash functions sized to roughly the cache capacity, to the TinyLFU struct alongside the sketch. In `record()`, which currently calls `CountMinSketch::increment`, first check whether the key's doorkeeper bits are all set. If they are not, set them and return without incrementing the sketch. If they are, increment the sketch as today. In `estimate()`, or in the admission path that reads frequency, add one to the sketch's estimate when the doorkeeper contains the key, so that a key seen once still reads as frequency 1. Clear the doorkeeper bits when the existing sample counter reaches its reset point, but leave `CountMinSketch` counters untouched at that point, with no halving. Leave `put()`, `get()`, `evict_one()`, and the probation/protected split unchanged.

## Rationale (optional)

Earlier cycles showed that the admission comparison is sensitive to the sketch's frequency history, and the window-in-front-of-LRU variant lost hit-rate by delaying admission. The doorkeeper differs because it filters only the sketch's update input and does not delay admission, and it leaves the sketch's accumulated counts intact. No cohort so far has tested this family.
