# H03

Halving every sketch counter whenever one would reach a saturation threshold, rather than on an access count, keeps the admission comparison intact and does not lose hit-rate on workload-a at size 2048.

## Parent

baseline

## Changes

Add a saturation-triggered aging rule inside `CountMinSketch::increment()` (src/tiny_lfu/mod.rs). It must not use a global access count as the trigger.

- Add `const SAT_THRESHOLD: u32 = 255;` next to the existing constants.
- In `increment(&mut self, key)`, first compute the `depth` positions for the key. If any of the current counters at those positions is already `>= SAT_THRESHOLD`, halve every counter in every row (`c >>= 1` across `self.counts`) before incrementing. Then increment the key's counters as today, still respecting `MAX_COUNT`.
- Halving only happens when a key's own counter is about to saturate, so it is triggered by frequency, not by elapsed accesses.
- Leave `estimate()`, the victim rule, `put()`, `get()`, the protected/probation split, and the sketch width and depth unchanged.

Expected behaviour: the rule fires only on hot keys, so it reshapes counter magnitudes without zeroing one-touch counts as often as the earlier fixed-schedule halving did. The admission comparison in `put()` should keep its ordering among hot and cold keys.

## Rationale (optional)

Cycles 0001 and 0005 showed that fixed access-count halving discards admission history and lost hit-rate, and the cross-cycle notes ask whether an aging trigger that is not an access count can shed stale frequency without that loss. This tests the saturation-triggered form directly against baseline, so the result is attributable to the aging rule alone, not to the victim change in v002.
