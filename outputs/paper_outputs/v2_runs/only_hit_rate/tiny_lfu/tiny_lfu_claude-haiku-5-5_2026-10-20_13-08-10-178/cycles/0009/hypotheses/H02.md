# H02

Narrowing the frequency sketch counters from `u32` to `u16` halves the sketch's measured metadata footprint while leaving workload-a hit-rate at size 2048 unchanged.

## Parent

cycle/0008/v002

## Changes

Change the counter storage of `CountMinSketch` (src/tiny_lfu/mod.rs) from 32-bit to 16-bit, keeping the logical counter mapping identical:

- `CountMinSketch::counts`: `Vec<Vec<u32>>` becomes `Vec<Vec<u16>>`. Update the initialiser in `CountMinSketch::new` to `vec![vec![0u16; width]; depth]`.
- `MAX_COUNT`: retype to `u16` with value `u16::MAX`. The saturation check in `increment()` (`if *counter < MAX_COUNT { *counter += 1; }`) stays as is.
- `estimate()`: keep its `u32` return type by converting the minimum with `as u32`, so the call sites in `put()` (`victim_freq`, `incoming_freq`) and the comparison are unchanged.
- `heap_bytes()`: use `std::mem::size_of::<u16>()` instead of `size_of::<u32>()`, so `sketch_heap_bytes()` reports the real halved footprint that the metadata-size dimension reads.

Do not change the hash in `position()`, the sketch depth or width, the victim rule in `select_victim()`, or the protected share. Hit-rate should be bit-identical to the parent on the current trace, because no counter reaches 65535 at this size. If any counter could exceed `u16::MAX` on a longer trace, saturation is the intended behaviour and must not wrap.

## Rationale (optional)

Earlier narrower-counter variants (cycles 0002 and 0003) were layout-only and could not show a payoff because metadata-size was not measured then. The fitness vector now carries a metadata-size dimension (baseline 48), so this is the first counter-width change that can register a gain. Keeping the hash mapping fixed avoids the hit-rate noise that earlier key-hashing rewrites introduced.
