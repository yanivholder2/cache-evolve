# H03

Hashing each key once with `DefaultHasher` and deriving all four sketch row positions from that single 64-bit value via a cheap multiplicative mix cuts the per-op cost of `get` and `put` on the sketch path, targeting the per-op-time dimension while holding hit rate roughly flat.

## Changes

In `src/tiny_lfu/mod.rs`, restructure `CountMinSketch` so the expensive hash runs once per key rather than once per row:

- Add `fn base_hash<K: Hash>(key: &K) -> u64` that creates one `DefaultHasher`, calls `key.hash(&mut hasher)`, and returns `hasher.finish()`.
- Replace `position(&self, key, seed)` with `fn position_from(&self, h: u64, row: usize) -> usize`. Compute `let x = (h ^ (row as u64).wrapping_mul(0x9E37_79B9_7F4A_7C15)).wrapping_mul(0xBF58_476D_1CE4_E5B9); (x >> 32) as usize & (self.width - 1)`. Keep the width mask so it stays a power of two.
- `increment<K: Hash>(&mut self, key: &K)` and `estimate<K: Hash>(&self, key: &K)` each call `base_hash` exactly once, then loop over rows using `position_from`. Keep the `MAX_COUNT` saturation in `increment` and the `min()` reduction in `estimate`.

Leave `TinyLfuCache::get`/`put`, the LRU list, the admission comparison `incoming_freq > victim_freq`, `try_new` sizing, and `sketch_heap_bytes()` unchanged. Expected effect: roughly four SipHash invocations per sketch access collapse to one, which should reduce `get` p50 (currently 132 ns) and `put` p50 (currently 166 ns). Hit rate on workload-a at size 2048 (baseline 0.7362) may shift slightly because row positions change; the variant should be judged as acceptable if hit rate stays within noise of baseline.
