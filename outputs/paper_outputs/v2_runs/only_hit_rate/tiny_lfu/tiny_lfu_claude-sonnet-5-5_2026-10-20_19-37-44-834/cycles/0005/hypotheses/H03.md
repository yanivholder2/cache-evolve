# H03

Deriving the sketch row indices once per access and reusing them for both estimate and increment will lower per-op-time without changing hit-rate.

## Parent

cycle/0004/v003

## Changes

In the sketch implementation (parent already derives all row indices from a single 64-bit hash), add a small `Indices([usize; DEPTH])` helper computed once per key via one hash call. Change the access path so that the admission duel's `estimate(candidate)`/`estimate(victim)` and the subsequent `increment(key)` take precomputed indices rather than rehashing the key; cache the indices for the current accessed key in the cache struct for the duration of one `get`/`put` call. Replace any `%` by mask where width is a power of two. Do not alter counter semantics, aging, or admission rules, so hit-rate must be identical to the parent. Invariant: output of estimate/increment is bit-identical to the parent for every key.

## Rationale (optional)

Hash-sharing was hit-rate neutral but unmeasured on speed; removing redundant hashing targets per-op-time directly.
