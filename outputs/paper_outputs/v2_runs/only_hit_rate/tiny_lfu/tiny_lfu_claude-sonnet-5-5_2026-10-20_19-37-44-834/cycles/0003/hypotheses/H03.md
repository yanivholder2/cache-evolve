# H03

Pack the baseline sketch into 4-bit counters with a power-of-two width and a single 64-bit hash split into rows to cut metadata-size without losing hit-rate.

## Parent

baseline

## Changes

In the frequency sketch, replace the per-counter wide storage with 4-bit saturating counters (max 15) packed 16 per `u64`, with 4 rows. Size the table to the next power of two >= capacity so indexing uses a mask. Derive the 4 row indices from one 64-bit mix hash of the key (different bit slices of the same hash, each re-mixed with an odd multiplier) instead of 4 independent hash calls. Use conservative update (increment only counters equal to the current minimum). Keep the estimate = min over rows interface and admission logic untouched. No aging/reset.

## Rationale (optional)

Cycle 1 showed a compact sketch costs no accuracy; this targets metadata-size and per-op-time, which remain unmeasured.
