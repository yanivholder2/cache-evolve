# H01

Lay out the count-min sketch as cache-line-blocked rows (all rows for a key in one 64-byte block) on top of the incumbent to cut per-op-time without changing hit-rate.

## Parent

cycle/0003/v002

## Changes

In the sketch implementation, keep u8 counters, the same total counter count and the same conservative-update rule, but change indexing: derive one block index from the key hash (`block = h % num_blocks`, each block 64 bytes), and derive each row's slot within the block from distinct bit ranges of the same 64-bit hash. `estimate()` and `increment()` then touch a single cache line. Keep the tie-admit duel and all segment logic unchanged. Total sketch memory must not grow. Invariant: hit-rate stays within noise of 0.7377; if collisions rise because blocks are shared, round num_blocks up to a power of two so total counters are not reduced.

## Rationale (optional)

Prior cycles showed width cuts hurt hit-rate, so this keeps width and targets per-op-time only.
