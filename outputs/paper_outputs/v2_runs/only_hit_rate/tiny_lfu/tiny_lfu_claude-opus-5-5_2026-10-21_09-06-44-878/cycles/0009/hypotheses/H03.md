# H03

Gating promotion so that a probation hit enters protected only when its estimate is at least that of the protected entry it would displace will raise hit-rate on workload-a, because low-count keys stay in probation where the admission contest can reach them.

## Parent

cycle/0007/v001

## Changes

In `src/tiny_lfu/mod.rs`, change only the probation-hit branch of `on_hit(idx)`:

- Protected hits are unchanged: unlink and push to protected MRU.
- On a probation hit when `self.prot_len < self.protected_cap`, promote exactly as today.
- On a probation hit when protected is full (`self.prot_len >= self.protected_cap`), first call `select_demotion()` to find the protected entry that would be demoted (`demote_idx`, with estimate `demote_freq`; you may extend `select_demotion` to also return the estimate). Compute `hit_freq = self.sketch.estimate(&self.nodes[idx].key)`.
  - If `hit_freq >= demote_freq`, promote `idx` to protected MRU and demote `demote_idx` to probation MRU. This is the same swap as today, done in the same order, and `prot_len` stays at the cap.
  - Otherwise, do not promote. Unlink `idx`, keep `segment = SEG_PROBATION`, and push it to probation MRU (a second chance within probation). Leave protected untouched.
- Run `select_demotion` *before* `idx` is pushed into protected, so the sample covers only existing protected entries and never the hit node itself.
- Leave `put`, `select_victim` (`VICTIM_SAMPLE = 8`), the admission predicate, the ghost ring, dedup and the sketch unchanged. Keep the invariants checked by `check_structure` (`prot_len <= protected_cap`, list lengths match `prot_len`, `map.len() == nodes.len()`).
- Tests: `protected_overflow_demotes_to_probation` uses equal estimates, so `>=` promotes and demotes key 0 as before. `protected_overflow_spares_hot_head_and_demotes_colder_entry` must still pass. Add a test where protected is full of entries with estimate 5, a probation key with estimate 2 is hit, and assert that it stays in probation at the MRU end while `prot_len` is unchanged.

## Rationale (optional)

Earlier SLRU work changed *which* protected entry gets demoted (by LRU, by frequency, by idle time) and the split ratio. It never changed *whether* a probation hit is allowed to displace anyone. Today any single hit promotes, so a key hit once at count 2 can push a count-5 key down to probation, where it faces the contest. The incumbent's insights found that the contest never reaches protected, so protected's contents set the cache's long-term frequency mass. The gate makes protected membership a frequency-ranked set, like the main region in Caffeine, without decaying any counts. Every earlier recency lever lost, and this one adds no recency. It only applies the same lifetime-frequency signal one level up.
