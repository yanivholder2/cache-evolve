# H01

Capping count-min sketch counters at 31 (saturating, no aging) will raise hit-rate on workload-a by keeping demoted stale-high keys from blocking newcomers in probation, while still keeping the lifetime ordering of cold and warm keys.

## Parent

cycle/0006/v003

## Changes

In `src/tiny_lfu/mod.rs`, change only the counter ceiling of `CountMinSketch`:

- Replace `const MAX_COUNT: u32 = u32::MAX;` with `const COUNT_CAP: u32 = 31;`. In `increment_hashed`, increment a counter only when `*counter < COUNT_CAP`, so counters saturate at 31.
- `estimate_hashed` still starts its minimum at a sentinel above the cap. Use `u32::MAX` as the start value, not the cap, so the result is unchanged for counts ≤ 31.
- Do not add any halving, reset or decay. Keep strict `>` with keep-victim-on-tie in `put`, `select_victim` (`VICTIM_SAMPLE = 8`), `select_demotion` (`DEMOTE_SAMPLE = 4`), the 80/20 SLRU split, dedup via `pending_miss_hash`, and the 16× sketch width exactly as they are.
- Counter storage stays `Vec<u32>`, so metadata-size does not change. This isolates the policy effect.
- Add a unit test: increment one key 100 times, then assert `sketch.estimate(&key) == 31`. Then assert that a newcomer with estimate 31 still loses to a victim with estimate 31 (tie keeps the victim), and that a newcomer with estimate 5 beats a victim with estimate 4. Existing tests use estimates ≤ 6 and must still pass.

## Rationale (optional)

Every earlier attempt to weaken lifetime counts decayed them (halving, idle discount), which removes information from cold and warm keys too. That hurt. A saturating cap is a different lever and has never been tested in eight cycles. It leaves every comparison below 31 exactly as it is, and only flattens the top of the distribution. This matters when a protected key is demoted with a very large lifetime count and then sits in probation. The min-estimate sample skips it as a victim, so it stays in a probation slot indefinitely even though it may never come back. With the cap, a very-hot key is still never chosen ahead of a cold one. Among capped keys, ties fall back to probation LRU order through the strict `<` in `select_victim`, which gives recency a role only at the top of the range. If hit-rate drops, that means very high counts above 31 were carrying real ordering information on this trace. If it stays the same, a later variant can use 5-bit counters to save memory.
