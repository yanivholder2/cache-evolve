# H02

Switch the count-min sketch to conservative update, with no aging, to raise hit-rate by removing the remaining collision overcount without widening the sketch.

## Parent

cycle/0003/v003

## Changes

All edits are in `CountMinSketch` in `src/tiny_lfu/mod.rs`. Change nothing else: no aging or reset, no geometry change (width factor 16, depth 4), no change to `select_victim`, `VICTIM_SAMPLE`, or the strict-`>` contest.

Rewrite `CountMinSketch::increment_hashed(h)` as a conservative update:
1. Compute `let pos = self.positions(h);` once.
2. Find `min` = the smallest of `self.counts[idx]` over `pos`.
3. If `min < MAX_COUNT`, then for each `idx` in `pos` where `self.counts[idx] == min`, set `self.counts[idx] = min + 1`. Leave counters above `min` untouched.

This keeps `estimate_hashed` semantics: the min across rows rises by exactly 1 per increment, the same as today, while counters shared with hotter keys stop being inflated further. `increment`, `estimate`, and `estimate_hashed` stay unchanged. `positions` is computed once per increment, so the extra cost is a single compare pass over 4 counters already in cache.

The in-file unit tests should pass without changes. At the test capacities, a 16×-capacity sketch has effectively no collisions, so plain and conservative update produce the same estimates. Add one small unit test: two keys forced to share a counter, verified at the `CountMinSketch` level by incrementing key A many times and key B once, should give B an estimate ≤ its true count plus the overcount in its least-shared row. A simpler acceptable check is that `estimate` after k increments of a fresh key equals k.

## Rationale (optional)

Cycle 0003 showed that collision noise is the strongest hit-rate lever found so far (16× width beat 4×). Conservative update has only been tested together with aggressive aging (cycle 1), so its effect is unresolved. Testing it alone isolates it as a pure estimate-quality improvement at zero memory cost. Comparing it with v003 shows whether there is accuracy left to gain beyond width; v003 still has some collisions, because its counters never age and keep growing.
