# H03

Add very-long-period halving aging (every 256×capacity sketch increments) to the de-noised wide sketch to raise hit-rate by letting stale residents lose the admission contest to keys that are currently hot.

## Parent

cycle/0003/v003

## Changes

All edits are in `src/tiny_lfu/mod.rs`. Keep `SKETCH_WIDTH_FACTOR = 16`, `SKETCH_DEPTH = 4`, plain (non-conservative) increments, `select_victim` with `VICTIM_SAMPLE = 8`, and the strict-`>` contest unchanged.

1. Add a constant `AGING_PERIOD_FACTOR: u64 = 256`.
2. Add two fields to `CountMinSketch`: `additions: u64` and `sample_size: u64`. Change `CountMinSketch::new(width)` to `new(width, sample_size)`. In `TinyLfuCache::try_new`, pass `sample_size = (capacity as u64) * AGING_PERIOD_FACTOR`, which is 524 288 increments at capacity 2048. Log it next to `sketch_width`.
3. In `increment_hashed`, after the existing per-row increment, do `self.additions += 1;`. If `self.additions >= self.sample_size`, call a new `fn reset(&mut self)`. `reset` halves every counter in place (`for c in self.counts.iter_mut() { *c >>= 1; }`) and sets `self.additions /= 2`, following Caffeine's reset convention so the next period starts half full.
4. `heap_bytes()` stays `depth * width * size_of::<u32>()`; the two new u64 fields are not heap. The in-file tests use capacities ≤ 4 (sample_size ≤ 1024) and far fewer increments, so they never trigger a reset and should pass unchanged. Add one unit test: a `CountMinSketch::new(16, 8)` incremented 8 times on one key has estimate 4 afterwards.

## Rationale (optional)

Aging has lost twice, but both tests ran on the noisy 4×-width sketch, and cycle 0003 showed that some of the "stale-high" inflation was actually collision overcount, so both results are confounded. The cross-cycle open question asks for a re-test against the wide-sketch baseline at a very long period. 256×capacity is far longer than the 10×capacity that failed in cycle 1. It keeps nearly all long-run frequency information, which workload-a rewards, while still capping how far ancient counts can block newcomers. If this loses again on the clean sketch, aging can be dropped for workload-a with confidence.
