# H01

Add periodic sketch halving (reset every 10×capacity counted accesses) to the SLRU+dedup design so stale lifetime counts decay, raising hit-rate on workload-a.

## Parent

cycle/0006/v003

## Changes

This is the single decisive re-test of aging on the current design (wide 16× u32 sketch, get-miss/put dedup, SLRU 80/20 with probation-only min-of-8 victim sampling, frequency-based demotion). It is not a stack of tweaks.

1. In `CountMinSketch`, add `additions: u32` and `sample_size: u32` fields. Set `sample_size = (capacity * 10)` (pass capacity into `CountMinSketch::new`, or set it from `try_new`). Use saturating arithmetic.
2. In `increment_hashed(h)`, after the counters are bumped, do `self.additions += 1`. When `additions >= sample_size`, call a new `reset()`. `reset()` halves every counter in place (`*c >>= 1`) and sets `additions /= 2`, which is the standard Caffeine/TinyLFU reset. Only counted increments advance `additions`. The deduped put that skips the sketch must not advance it either, so each access counts once.
3. Remove every shortcut that assumes counts never decrease. For example, an early return in `select_victim`/`select_demotion` when an estimate is ≤ 1, or early rejection of newcomers whose estimate is ≤ 1, must go if present in this lineage. Victim and demotion scans must always evaluate all sampled entries.
4. Keep the admission rule exactly as it is: strict `incoming_freq > victim_freq`, victim kept on ties. Keep SLRU, `VICTIM_SAMPLE = 8`, `DEMOTE_SAMPLE = 4`, sketch width/depth, and dedup unchanged.
5. Keep `sketch_heap_bytes()` correct (the counter table size does not change). Update or add a unit test: after `sample_size` increments, the estimate of a key incremented k times becomes ⌊k/2⌋ (assuming no collisions on a wide sketch). Also make sure the existing structure tests still pass.

## Rationale (optional)

The anti-aging verdict came from cycles 1–4, before SLRU and dedup, and with collision noise or conservative update confounding it. Cycles 5–7 showed that neither the contest nor the victim sample can reach stale-high keys while counts are lifetime totals. Halving is the cleanest way to test whether recency now pays. If it loses again, the plateau can be treated as workload-a's ceiling for this family.
