# H03

Demote idle protected entries (untouched for more than 2×capacity accesses) to the probation LRU head, with their estimate discounted by idle time in the victim contest, so stale-high residents become evictable and hit-rate on workload-a rises.

## Parent

cycle/0005/v001

## Changes

This targets the gap found in cycles 6–7: protected keys never meet the contest or the victim sample, so stale-high residents can never be evicted. It works per entry using last-access recency. The global sketch is not aged.

1. Add a `tick: u64` counter to `TinyLfuCache`, incremented once per `get` and once per non-deduped `put`. Add `last_access: u64` to `Node`, set on insert and in `on_hit`.
2. In `put()`, before calling `select_victim()` on a full cache, check the protected LRU head (`prot_head`). If `tick - last_access > STALE_IDLE` with `STALE_IDLE = 2 * capacity`, unlink it, set its segment to probation, push it to the probation **head** (the LRU end, so it is inside the 8-entry victim sample), and decrement `prot_len`. Do at most one such demotion per put. Add a `push_front` helper that mirrors `push_back` for the probation list.
3. In `select_victim()`, rank each sampled entry by an effective frequency, `est >> min(idle / capacity, 8)`, where `idle = tick - last_access`. Return that effective value as `victim_freq`. Recently touched entries (idle < capacity) keep their full estimate. A key idle for k×capacity accesses has its estimate halved k times.
4. Keep the admission rule strict: `incoming_freq > victim_freq`, victim kept on ties. Use the newcomer's raw sketch estimate. Leave the sketch, dedup, `VICTIM_SAMPLE = 8`, and the 80/20 split unchanged.
5. Add unit tests:
   - A protected key that was hot early and then left idle past `STALE_IDLE` gets demoted, and a warm newcomer evicts it.
   - A protected key with recent hits is never demoted by this path.
   - The SLRU structure invariants (`prot_len`, list membership, map/nodes sizes) hold under a mixed random workload.

## Rationale (optional)

Global halving (H01) decays every key, including the hot set that lifetime counts protect well. This variant applies recency only to keys that have actually gone idle, at the point where cycle 0007's analysis says stale-high keys live. It tests the open question "can recency act through protected-segment demotion?" independently of the aging re-test. Its parent is the plain SLRU winner, which carries no ghost ring and no demotion-by-frequency.
