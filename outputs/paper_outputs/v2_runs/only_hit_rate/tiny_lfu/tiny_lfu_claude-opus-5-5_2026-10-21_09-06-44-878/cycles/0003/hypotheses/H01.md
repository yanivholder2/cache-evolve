# H01

Admitting a newcomer on an exact frequency tie with the sampled victim, but only when the tied estimate is at least 2, will raise hit-rate on workload-a by letting warm newcomers displace equally-warm but older residents.

## Parent

cycle/0002/v001

## Changes

Single lever: the admission contest in `TinyLfuCache::put` (file `src/tiny_lfu/mod.rs`), in the full-cache branch after `select_victim()`.

Today the code is `if incoming_freq > victim_freq { ...replace victim... }`, so on a tie the victim always stays. Replace that condition with:

```rust
let admit = incoming_freq > victim_freq
    || (incoming_freq == victim_freq && incoming_freq >= TIE_ADMIT_MIN_FREQ);
if admit { ...existing replace-victim body unchanged... }
```

Add `const TIE_ADMIT_MIN_FREQ: u32 = 2;` next to `VICTIM_SAMPLE`, with a doc comment explaining it. The threshold keeps one-hit wonders (estimate 1, which is the common tie case) out, so pure scan traffic is still rejected. Ties at higher counts go to the newcomer, because it is the more recently active key of two equally frequent ones.

Keep everything else unchanged: `select_victim` (8-entry oldest-LRU sample with strict `<`), the sketch (no aging, no conservative update), hashing, and the get path. Keep the `map.len() == nodes.len() <= capacity` invariant. The inline test `low_frequency_new_item_is_rejected` must still pass unmodified. In that test the tie is at estimate 1, so it is still rejected, which is why the threshold is 2 and not plain `>=`. Add one inline test where the newcomer and the sampled victim both have estimate 2 and the newcomer is admitted.

## Rationale (optional)

Cycles 0001 and 0002 both named strict-`>` keep-victim-on-tie as the bottleneck, but no variant has tested it directly. Plain `>=` would also admit estimate-1 ties, which hurts scan resistance and breaks an inline test. The threshold isolates the warm-tie case. This hypothesis would be refuted if hit-rate stays at or below 0.7379.
