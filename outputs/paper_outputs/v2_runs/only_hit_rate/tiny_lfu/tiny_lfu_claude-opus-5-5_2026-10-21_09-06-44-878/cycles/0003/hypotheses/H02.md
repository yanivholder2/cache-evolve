# H02

Widening the frequency-sampled victim search from the 8 oldest LRU entries to the 64 oldest will raise hit-rate on workload-a by finding genuinely cold victims that the 8-entry window misses.

## Parent

cycle/0002/v001

## Changes

Single lever: the victim sample width in `src/tiny_lfu/mod.rs`.

- Change `const VICTIM_SAMPLE: usize = 8;` to `const VICTIM_SAMPLE: usize = 64;`. Update its doc comment.
- Keep `select_victim()` as written: walk from `self.head` along `next`, track the minimum `sketch.estimate`, and break ties with strict `<` so the entry closest to the head wins. Add one early exit: if `best_freq` reaches 0 or 1, stop scanning, because no entry can be colder than a one-hit key (the minimum possible estimate for a resident is 1). This caps the extra per-miss-put cost when the head region is already cold.
- Do not change the admission contest (`incoming_freq > victim_freq`), the sketch, the hashing, or the get path.
- Keep the invariants: `map.len() == nodes.len() <= capacity`, and the list stays consistent after `unlink`/`push_back` of the chosen victim, even when the victim is in the middle of the list. The existing inline test `victim_is_min_frequency_among_oldest_not_lru_head` must still pass.

## Rationale (optional)

v001's insight says an 8-node window is a tiny slice of 2048 entries and the gain was marginal. This tests the open question "is victim sampling capped by sample width?" directly. If 64 gives no further gain over 0.7379, the head region is uniformly cold and sampling is exhausted as a lever. This change adds sketch estimates on miss-puts, so per-op-time should be watched.
