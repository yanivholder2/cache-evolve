# H01

Letting a newcomer win a tie when it was evicted recently (a small ghost set of evicted key hashes) will raise hit-rate on workload-a by re-admitting keys whose reuse distance is just above the cache size.

## Parent

cycle/0006/v003

## Changes

Add a non-resident "ghost" history to `TinyLfuCache` in `src/tiny_lfu/mod.rs`. It records the 64-bit hashes of keys that were recently evicted, using the same `hash_key` value already computed in `put`.

- New fields: `ghost_ring: Vec<u64>` (fixed length `GHOST_CAP = capacity`, starting at 0), `ghost_pos: usize`, and `ghost_set: HashSet<u64, FastBuildHasher>` (pre-sized to `capacity`). Allocate them in `try_new`.
- On eviction in `put`, inside the `incoming_freq > victim_freq` branch and before the victim's key is overwritten, compute `hash_key(&victim_key)` and insert it into the ring at `ghost_pos`. If the ring slot already held a non-zero hash, first remove that old hash from `ghost_set`. Insert the new hash into `ghost_set` and advance `ghost_pos` modulo `GHOST_CAP`. Map a hash of 0 to 1 so that 0 can stay the "empty" sentinel.
- Change the admission contest only for ghost hits. Let `is_ghost = ghost_set.contains(&key_hash)`. Admit if `incoming_freq > victim_freq || (is_ghost && incoming_freq == victim_freq && incoming_freq >= 2)`. When a ghost key is admitted, remove its hash from `ghost_set` but leave the ring slot alone, because a stale ring entry is harmless: it only triggers a removal that does nothing. Everything else stays the same. Non-ghost ties still keep the victim (strict `>`), victim sampling (`select_victim`, `VICTIM_SAMPLE = 8`) is unchanged, demotion (`select_demotion`) is unchanged, and dedup and the 16× sketch are unchanged.
- Rejected newcomers are not added to the ghost set. Only keys that actually lived in the cache are added.
- Invariants: `check_structure` must still hold, and `map.len() == nodes.len() <= capacity`. Ghost memory is bounded at `capacity` u64 values plus the set. Add a unit test showing that an evicted key which comes back and ties the victim's estimate gets admitted, while a never-seen key with the same estimate is rejected.

## Rationale

Every earlier attempt to loosen the contest applied tie-admission to all newcomers and swapped one cold key for another. A ghost hit is evidence the earlier tests never used: the key was resident recently, so it has a real reuse pattern of roughly the cache size. LIRS-style traces are built around exactly this case. The `>= 2` guard keeps one-hit wonders out.
