# H02

Shrinking the cycle/0004/v001 sketch to u16 saturating counters at 8× capacity width with conservative update will cut metadata-size by 4× while holding hit-rate within noise of 0.7439.

## Parent

cycle/0004/v001

## Changes

Edit `src/tiny_lfu/mod.rs` only.

- Change `CountMinSketch.counts` from `Vec<u32>` to `Vec<u16>`, and `MAX_COUNT` to `u16::MAX`. `estimate_hashed` / `estimate` / `select_victim` may keep returning `u32` (widen with `as u32`) so the contest code in `put` is unchanged. `heap_bytes()` must use `size_of::<u16>()` so the metadata-size bin sees the reduction.
- Change `SKETCH_WIDTH_FACTOR` from 16 to 8 (width for capacity 2048 becomes 16384 per row; depth stays 4). Total sketch bytes: 4 × 16384 × 2 = 131072, down from 524288.
- Replace `increment_hashed` with conservative update: compute the four positions, find the current minimum `m`, and increment only counters equal to `m` (saturating at `MAX_COUNT`). This offsets the extra collision overcount at half width.
- Keep the `pending_miss_hash` dedup, `VICTIM_SAMPLE = 8`, the strict `>` keep-victim-on-tie contest and no aging exactly as in v001.
- Update the inline test `sketch_width_is_sixteen_times_capacity` (rename to `sketch_width_is_eight_times_capacity`) to assert `4 * 16384 * 2` bytes.

## Rationale (optional)

c4 showed conservative update is redundant at 16× width because both fix collision overcount. That suggests the two are substitutes, so CU should let width drop without losing hit-rate. Lifetime counts on this trace sit far below 65535, so u16 saturation will not change any contest. metadata-size has been unscored for four cycles. This is the first variant built specifically to move it, and a hit-rate tie with v001 would confirm the trade.
