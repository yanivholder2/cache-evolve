# H03

Caching each resident key's 64-bit hash in its node and stopping the victim scan early at estimate 1 will lower per-op-time of cycle/0004/v001 with bit-identical hit-rate.

## Parent

cycle/0004/v001

## Changes

Edit `src/tiny_lfu/mod.rs` only. Make no policy changes; every admission and eviction decision must match v001 exactly.

- Add `hash: u64` to `Node`. Set it from the already-computed `key_hash` in `put`, both on the fill path and when an admitted newcomer overwrites the victim slot.
- In `select_victim()`, replace `self.sketch.estimate(&self.nodes[idx].key)` with `self.sketch.estimate_hashed(self.nodes[idx].hash)`. This removes up to 8 key rehashes per eviction-path `put`.
- Add an early exit to the `select_victim()` scan: once `best_freq <= 1`, stop walking. Residents always have estimate ≥ 1 (no aging, and every resident was counted at least once by its `get` miss or by its `put`), and ties keep the earliest candidate under strict `<`. So the selected victim is unchanged.
- Hoist the contest: in `put`, compute `incoming_freq = estimate_hashed(key_hash)` before `select_victim()`. If `incoming_freq <= 1`, reject immediately without scanning, because no resident can be below 1, so `incoming_freq > victim_freq` can never hold. Otherwise call `select_victim()` as before. This skips the whole scan for one-hit-wonder newcomers, which are the common rejection case.
- In the eviction branch, avoid the double hash of the victim key in `self.map.remove(&victim_key)`: use `std::mem::replace` to take `nodes[victim_idx].key` out and remove it from the map, instead of cloning it first.
- Keep the inline tests passing unchanged. Add one inline test that asserts the `hash` stored in a node equals `hash_key(&node.key)` after a few puts and evictions.

## Rationale (optional)

Per-op-time has been unmeasured across four cycles, and v001's eviction path rehashes up to 9 keys per miss-put. Because this is semantics-preserving, any per-op-time movement can be attributed cleanly. Hit-rate must stay exactly 0.7439, which serves as a built-in correctness check.
