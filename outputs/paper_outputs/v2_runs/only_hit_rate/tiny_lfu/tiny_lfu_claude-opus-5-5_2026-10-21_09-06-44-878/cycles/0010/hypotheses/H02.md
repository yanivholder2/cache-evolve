# H02

Adding the protected-segment LRU head as one extra eviction candidate lets the admission contest reach stale-high protected residents, which raises hit-rate on workload-a.

## Parent

cycle/0009/v003

## Changes

In `src/tiny_lfu/mod.rs`, change `TinyLfuCache::select_victim`. Keep the existing scan over the `VICTIM_SAMPLE = 8` oldest probation entries (min estimate, strict `<`, head-most wins ties). Then, if `self.prot_head` is `Some(p)` and probation is non-empty, compute `self.sketch.estimate(&self.nodes[p].key)`. Replace the current best with `p` only if that estimate is **strictly less** than the probation minimum. Ties keep the probation candidate, so the protected entry is chosen only when it is clearly colder. When probation is empty, keep the existing fallback to `prot_head` as it is.

No other code changes are needed. `put` already handles a protected victim: it decrements `prot_len` when `segment == SEG_PROTECTED`, then re-tags the slot as `SEG_PROBATION`. Confirm that this path still runs, and that the newcomer is pushed to probation MRU. Keep strict `>` admission plus the ghost tie, the dedup, the promotion gate and `select_demotion` unchanged. Add a unit test. Set up a full cache whose protected head has estimate 1 and whose probation entries all have estimate ≥ 3. A newcomer with estimate 2 should then evict the protected head, and `check_structure` should pass with `prot_len` reduced by one.

## Rationale (optional)

Cycle 0007 observed that neither the contest nor the victim sample ever reaches protected keys, which leave only through demotion. Cycles 0006, 0008 and 0009 changed how keys move between segments, but every one of those tests still sent the evicted key through probation. This change makes one protected entry directly evictable on frequency alone, with no recency discount. It is not aging, because estimates stay lifetime counts. It only widens the *set* of comparators by one key that was previously unreachable.
