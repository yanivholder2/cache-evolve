# H01

Put a small 1%-of-capacity LRU admission window in front of the SLRU main region, so newcomers are admitted unconditionally and only window victims face the TinyLFU contest, to raise hit-rate on workload-a.

## Parent

cycle/0005/v001

## Changes

Edit `src/tiny_lfu/mod.rs` only. Turn the SLRU winner into a full W-TinyLFU layout. Keep the sketch, the dedup, the strict `>` contest and the `select_victim` probation sampling unchanged.

- Add a third segment tag, `SEG_WINDOW: u8 = 2`, with its own `win_head`, `win_tail` and `win_len` fields, plus `window_cap = (capacity / 100).max(1)`. Size the main region as `main_cap = capacity - window_cap`, and recompute `protected_cap = (main_cap * 8 / 10).max(1)` from `main_cap` instead of `capacity`. When `capacity < 2`, set `window_cap = 0` and keep the current behaviour.
- `unlink` and `push_back` have to dispatch over three lists. Replace the `protected: bool` logic with a match on `segment`.
- In `put`, take this path for a brand-new key:
  1. While `nodes.len() < capacity`, push the new node to the window MRU end (`SEG_WINDOW`).
  2. Once the cache is full, insert the newcomer into the window unconditionally. If `win_len > window_cap`, take the window LRU node (`win_head`) as the *candidate*. If main has free room, move it into probation MRU. Otherwise run the existing contest: `select_victim()` over probation, then `candidate_freq = sketch.estimate(candidate.key)`. If `candidate_freq > victim_freq`, evict the victim (remove it from the map, unlink it, adjust `prot_len` if it was protected) and relink the candidate into probation MRU. Otherwise evict the candidate. The node slot is reused for the incoming key, so `nodes.len()` never exceeds `capacity`. Use the freed slot (victim's or candidate's) for the new window entry, which means you allocate the slot after the contest is resolved.
- In `on_hit`, a hit on a `SEG_WINDOW` node just moves it to window MRU and does not promote it. Probation and protected hits behave as they do now.
- Add an in-file unit test that drives a mixed workload and checks `win_len <= window_cap`, `prot_len <= protected_cap`, that the three list lengths sum to `nodes.len()`, and `map.len() == nodes.len()`. Update `check_structure` to cover the window list.

## Rationale (optional)

The window was tested only in cycles 1–2, on the noisy, double-counted sketch, and it was never placed in front of SLRU. Today a first-time newcomer (estimate 1) always loses its tie against a once-seen probation resident, so the trace's short-reuse keys never get a single residency. The cross-cycle open question asks for "a cheap fix that doesn't reintroduce tie-admission noise". A 20-slot window gives every newcomer a short recency trial, and the contest decides only once the newcomer leaves the window. That makes this a direct test of whether any hit-rate is left past the 0.745 plateau.
