# H02

Making the frequency sketch decay over time (halving all counters every 10×capacity conservative-update increments) will let stale formerly-hot keys lose admission contests to newly hot keys, raising hit-rate on workload-a above the baseline's 0.7362.

## Parent

baseline

## Changes

All edits are in `src/tiny_lfu/mod.rs`, inside `CountMinSketch` and the place that builds it in `TinyLfuCache::try_new`. The recency list, `get`/`put` control flow and the admission contest (strict `>`) do not change.

1. **Sample counter.** Add `additions: usize` and `sample_size: usize` fields to `CountMinSketch`. Change `CountMinSketch::new(width)` to `CountMinSketch::new(width, sample_size)`. In `try_new`, pass `sample_size = 10 * capacity` (saturating multiply, minimum 16).
2. **Conservative update in `increment`:**
   - First compute the 4 row positions once.
   - Read the current minimum `m` across those cells.
   - Only increment the cells whose value equals `m`, and keep the `MAX_COUNT` saturation guard.
   - If at least one cell was incremented, do `additions += 1`.
   
   This cuts count-min over-estimation from collisions. Over-estimation currently lets cold keys tie or beat warm victims.
3. **Aging (reset).** After an increment, if `additions >= sample_size`, call a new `fn reset(&mut self)`. It does `*c >>= 1` on every counter in every row and sets `additions /= 2`. This is the standard TinyLFU "halving" freshness mechanism. Frequency history then decays, so keys that were hot long ago can be displaced by newly hot keys.
4. **No other changes.** `heap_bytes()` stays `depth * width * 4`, so the metadata-size dimension is unchanged. `estimate` stays a count-min over rows, but it should reuse the positions helper so the hashing work isn't duplicated.
5. **Tests.** The existing in-module unit tests use tiny capacities and very few operations. `sample_size` is at least 16 and those tests never reach it, so they must still pass without edits.

## Rationale (optional)

The baseline sketch only ever grows: u32 counters with no reset. After a long warm-up, early hot keys hold huge estimates forever. On a phase-changing LIRS trace they can't be displaced, and newly hot keys get rejected again and again. Aging restores adaptivity, and conservative update makes the strict-greater contest more accurate. This hypothesis changes only *when the admission contest lets items move into the resident set*. It leaves the segment structure alone, so it stays orthogonal to H01.
