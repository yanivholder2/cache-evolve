# H03

Replacing the per-row SipHash (`DefaultHasher` rebuilt four times per increment and four more per estimate) with one fast 64-bit hash per key, split into four row indices over a flat counter array, will cut per-op-time get p50 below the baseline's 132 ns without changing hit-rate.

## Parent

baseline

## Changes

All edits are in `src/tiny_lfu/mod.rs`. Cache semantics stay bit-for-bit equivalent at the policy level: same LRU movement, same strict-greater admission contest, same depth 4 and same width, so `sketch_heap_bytes()` is unchanged. Only the hashing and memory layout of `CountMinSketch` change.

1. **Single hash per key.** Add `fn hash_key<K: Hash>(key: &K) -> u64`. It feeds the key into a cheap non-cryptographic hasher implemented locally, with no new crates since `Cargo.toml` is protected. For example:
   - a small `FxHasher`-style `Hasher` struct whose `write_u64` does `h = (h.rotate_left(5) ^ x).wrapping_mul(0x51_7c_c1_b7_27_22_0a_95)`, with a byte-loop fallback in `write`;
   - then a final avalanche, e.g. the splitmix64 finalizer.
2. **Row indices from one hash.** Derive the 4 row indices with `h1 = h as u32`, `h2 = (h >> 32) as u32 | 1`, and `pos_i = (h1.wrapping_add(i * h2)) & (width-1)` (Kirsch–Mitzenmacher double hashing). Return them as `[usize; 4]` from `fn positions(&self, h: u64)`.
3. **Flat layout.** Replace `counts: Vec<Vec<u32>>` with `counts: Vec<u32>` of length `depth * width`, where row `i` lives at offset `i * width`. This removes the double indirection and the per-row bounds checks. `heap_bytes()` keeps returning `depth * width * 4`.
4. **Shared hash on the put/contest path.** In `put`, compute the incoming key's hash once and reuse it for both `increment` and the contest `estimate`. Add `increment_hashed(h)` and `estimate_hashed(h)` variants, and have `increment<K>` and `estimate<K>` wrap them.
5. **Cheaper `HashMap` hashing.** Change the `map` field's hasher to `BuildHasherDefault<LocalFastHasher>`, reusing the same local hasher type, so key→slot lookups also skip SipHash. The struct's generic parameters stay `TinyLfuCache<K, V>`, with the hasher as a concrete type in the field. `try_new` uses `HashMap::with_capacity_and_hasher`.
6. **Invariant.** The existing in-module unit tests must still pass. They depend only on relative counts for a handful of distinct small keys, which collide with negligible probability at width ≥ 16. If a collision makes one fail, change the finalizer constant, not the test.

## Rationale (optional)

Each baseline `get` builds 4 SipHash-1-3 states for the increment, plus another SipHash for the `HashMap` lookup. Each miss-`put` adds about 8 more for the two estimates. Hashing probably dominates the 132 ns get p50 and the 400 ns put p99. This hypothesis targets the per-op-time dimension specifically, leaving hit-rate unchanged (up to differences in hash-collision patterns) and metadata unchanged.
