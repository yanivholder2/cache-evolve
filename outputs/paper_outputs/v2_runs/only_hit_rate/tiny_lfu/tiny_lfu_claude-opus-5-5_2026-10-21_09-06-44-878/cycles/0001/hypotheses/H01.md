# H01

Splitting the single recency list into a W-TinyLFU layout (a 1% admission window LRU feeding a segmented main region with probation and protected segments, where the admission contest runs only when a window evictee meets the probation LRU) will raise hit-rate on workload-a at size 2048 above the baseline's 0.7362.

## Parent

baseline

## Changes

All edits are in `src/tiny_lfu/mod.rs`; the JNI file, `Cargo.toml`, `src/lib.rs`, `tests/` and `src/test_utils/` stay as they are. The public API (`try_new`, `new`, `get`, `put`, `sketch_heap_bytes`, the `framework::Cache` impl) keeps its signatures.

1. **Segments.** Add a `seg: u8` tag to `Node`, with the values `WINDOW=0`, `PROBATION=1` and `PROTECTED=2`. Swap the single `head`/`tail` pair for three intrusive lists in the same arena. Each list gets its own head, tail and length (`win_*`, `prob_*`, `prot_*`). Generalise `unlink(idx)` and `push_back(idx)` into `unlink(list, idx)` and `push_back(list, idx)`, where `list` picks which head/tail/len triple to update.
2. **Sizing** in `try_new`:
   - `window_cap = max(1, capacity / 100)`
   - `main_cap = capacity - window_cap`
   - `protected_cap = main_cap * 80 / 100`
   - If `capacity == 1`, use `window_cap = 1` and `main_cap = 0`, and the window evictee is simply dropped.
   
   Leave the sketch width formula alone.
3. **`get` on a hit** (after `sketch.increment`):
   - WINDOW: move the node to the window MRU.
   - PROBATION: unlink it and push it to the protected MRU with `seg=PROTECTED`. If `prot_len > protected_cap`, demote the protected LRU to the probation MRU.
   - PROTECTED: move it to the protected MRU.
4. **`put` of an existing key**: update the value, then do the same movement as `get`.
5. **`put` of a new key**: always insert it at the window MRU. While `nodes.len() < capacity`, push a new arena slot. When the window goes over `window_cap`, take the window LRU node as the *candidate*:
   - If `prob_len + prot_len < main_cap`, move the candidate to the probation MRU unconditionally.
   - Otherwise, run the admission contest between `estimate(candidate)` and `estimate(probation LRU victim)`. If probation is empty, use the protected LRU as the victim. A strictly greater estimate wins:
     - If the candidate wins, evict the victim (remove it from `map`) and move the candidate to the probation MRU.
     - If the candidate loses, evict the candidate.
   - Slot reuse: once the cache is full, the incoming key's arena slot is the evicted node's slot. Do the contest *before* writing the new key, then write the new key and value into whichever slot was freed and push it to the window MRU. The arena then never grows past `capacity`, and no free list is needed.
6. **Invariant to preserve:** `map.len() == nodes.len() <= capacity` after every operation, and every resident key lives in exactly one list.
7. **In-module unit tests.** Update the `#[cfg(test)]` tests in this file whose expectations encode the old "newcomer dropped without residency" behaviour (`low_frequency_new_item_is_rejected` and `eviction_prefers_hot_items` at capacity 2). They should assert the new window semantics: a new key is always resident right after `put`, and the contest happens at window overflow.

## Rationale (optional)

The baseline admits nothing whose sketch count isn't strictly above the LRU victim's. So a new burst of recency (a key re-referenced shortly after first sight) is always rejected, and the LRU gives scanned-once entries in the main region no protection. The window gives recency a foothold, and the probation→protected promotion keeps frequently hit items away from the victim position. This is the canonical Caffeine design, and it usually beats plain TinyLFU+LRU by several points on LIRS-style traces.
