# H02

Apply v002's admission filter only when the victim is a recently hit entry, so one-hit-wonders are admitted over cold victims, to raise hit-rate by avoiding needless rejection of useful new keys.

## Parent

cycle/0003/v002

## Changes

In v002's DashSegment insert path, keep the second-sighting filter, but make it conditional on the victim candidate. Before rejecting a first-sighting key, inspect the entry that would be evicted (the cold-end entry in the target bucket per the existing MRU ordering). If that entry has never been promoted (never hit since insertion, i.e. it sits at its original insert position or has no hit mark), admit the new key immediately and evict that entry. Only when the candidate victim has been hit at least once do we require the second sighting. Record the first sighting in the filter in both cases. Use existing per-slot ordering as the hit signal; if no hit bit exists, add a one-bit-per-slot flag set in the promote-on-hit code and cleared on insert. Preserve the hit path and the stash logic.
