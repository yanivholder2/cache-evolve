# H01

Replace v002's binary second-sighting admission filter with a two-bit saturating frequency counter per fingerprint slot, admitting only at count >= 2, to raise hit-rate by filtering one-hit-wonders more precisely.

## Parent

cycle/0003/v002

## Changes

In the DashSegment insert path that v002 modified (the admission filter consulted when the segment is full enough to need eviction), change the filter state from a one-bit "seen once" marker to a 2-bit saturating counter per hashed slot (packed into the existing filter byte array, up to 256 bytes per segment, so no growth in memory is needed if it is repacked 4 per byte and the slot count is halved). On a miss that would require eviction: increment the counter for the key's fingerprint slot; admit only if the counter was already >= 1 before the increment (the same behaviour as v002 on the second sighting), but additionally, on every admission, decrement the counters of colliding slots by aging: halve all counters when a segment-wide sighting counter reaches 4x the slot count. Keep the existing "full enough" threshold and the hit path unchanged. Invariants: lookups must never miss resident keys, and the filter must never block inserts when the segment has free space.
