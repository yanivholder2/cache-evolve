# H03

Widen the probing neighbourhood to two adjacent buckets and delay stash use, to raise hit-rate by cutting premature evictions from full buckets.

## Parent

baseline

## Changes

In the baseline DashSegment insert path, find where the target bucket and its single probing neighbour are tried before the stash is used. Extend the probe so that insert tries, in order: the target bucket, the next bucket, the previous bucket, and only then the stash. Apply the same order to the lookup path (`get` and `promotion_get`), so every key stored in the extra bucket can be found. Evict only if all of those and the stash are full. Preserve fingerprint matching and the stash overflow bookkeeping. Do not change the promotion logic. The implementer must check that lookup, delete and update all use the same probe order.

## Rationale (optional)

This changes the bucket and probing structure, which cycle 2 named as untested. Branching from baseline keeps the result independent of the MRU lineage. The source could not be inspected while writing this hypothesis, so the implementer should confirm the real probe order and adapt the names.
