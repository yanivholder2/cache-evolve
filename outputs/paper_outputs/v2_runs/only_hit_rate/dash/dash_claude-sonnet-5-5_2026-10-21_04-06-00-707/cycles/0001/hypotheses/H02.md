# H02

Promote target-bucket hits to the probing bucket on any hit when the probing bucket is not full, to raise hit rate by using probing-slot spare capacity.

## Parent

baseline

## Changes

In `src/dash/segments/dash_segment.rs`, modify the target-hit branch of `promotion_get`. Currently an item moves to probing only if `item_idx == promotion_candidate_index()`. New rule: if `core.buckets[probing_idx].is_full()` is false, move the item (via `remove_at` + `promote_to_probing`) regardless of hotness; otherwise keep the existing hottest-only rule and in-bucket touch via `get_from_position`. Keep the post-insert lookup in probing (the `unreachable!` invariant must still hold: key must be resident in probing after promote). Keep `InsertPosition::Front` for the stash path. No changes to other files.

## Rationale (optional)

Probing buckets may sit partly empty early; filling them eagerly avoids evictions from target buckets, increasing effective capacity use.
