# H03

Give probing-bucket hits a promotion back to the target bucket's MRU end (swap with target's coldest) to improve hit rate by keeping hot items in the primary tier.

## Parent

baseline

## Changes

In `src/dash/segments/dash_segment.rs`, modify the probing-hit branch of `promotion_get` (currently a plain in-place touch). New behaviour: on a probing hit, if the item is NOT the probing bucket's `promotion_candidate_index()` (i.e. not already hottest), just touch in place as now. If it IS the hottest, remove it from probing with `remove_at`, then `core.put_at(Slot::Target, InsertPosition::Back, item)`; any evicted target item is demoted into the probing bucket via `core.put_at(Slot::Probing, InsertPosition::Front, evicted)`, and any item evicted from there goes to `core.put_at(Slot::Stash, InsertPosition::Front, ..)`. Note `Slot::Target` is computed from the item's key, so this applies only to items whose true target is `target_idx` (always the case for the probing lookup in `promotion_get`, as `probing_idx` is derived from the key). Return a reference found via `get_position` in `core.buckets[target_idx]`; preserve the invariant that the key remains resident in target after the move. The stash path and target-hit path remain as in baseline.

## Rationale (optional)

Baseline promotion is one-way up to probing; items demoted/evicted never return. A bidirectional swap lets hot probing items re-occupy their home bucket.
