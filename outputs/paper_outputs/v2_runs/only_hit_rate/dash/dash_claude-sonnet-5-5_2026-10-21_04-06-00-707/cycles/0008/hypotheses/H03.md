# H03

Adding a probationary segment where newly admitted keys are evicted first (scan-resistance) on top of the single reuse-bit eviction will raise hit-rate on workload-a.

## Parent

cycle/0006/v001

## Changes

Starting from the cycle 6 reuse-bit eviction, add a second per-entry bit "protected" in the spare bits next to the referenced flag. New entries are inserted with referenced=0, protected=0 (probation). A hit on a probation entry sets protected=1 and referenced=1. The victim scan first looks for a slot with protected=0 and referenced=0; then protected=0 with referenced=1 (clearing referenced); only if the whole scanned window is protected does it demote: clear protected on the first slot and evict the first slot with referenced=0. Cap protected entries implicitly by this demotion rule, no extra counter. Admission filter stays the unconditional one-bit second-sighting filter. Invariants: no allocation, no change to public API or the insert placement.

## Rationale (optional)

Distinguishes once-reused from never-reused entries via a segmented (SLRU-like) structure rather than a counter, as an alternative to the cycle 7 counter that is cheaper in metadata.
