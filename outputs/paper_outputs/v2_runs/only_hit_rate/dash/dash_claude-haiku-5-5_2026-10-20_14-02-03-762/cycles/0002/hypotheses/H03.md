# H03

Keeping the direct-to-stash foreign eviction only while the stash has free capacity recovers the hit-rate that v003 lost, without giving up the shorter demotion path.

## Parent

cycle/0001/v003

## Changes

In `demote_from_normal_bucket`, keep v003's change that sends a foreign probing eviction straight to `Slot::Stash` with `insert_pos` honoured. Add a guard before that branch: if the stash has at least one free slot, take the direct path. If the stash is full, restore the original one-more-chance retry in the item's true target bucket and only fall through to the stash if that retry also fails. Leave the stash eviction order, `promotion_get`, and the probing-tier code unchanged. Add a short comment at the guard naming the free-capacity condition so the two paths are easy to tell apart in review.

## Rationale (optional)

v003 lost hit-rate because items that used to stay in a normal bucket now depend on the stash and get lost under stash pressure. Cycle 0001's open question asks whether the removed retry would pay for itself if paired with better stash capacity handling. This hypothesis tests the simplest version of that pairing: the shortcut is only taken when the stash can absorb the item, so the retry is only given up when it costs nothing in stash pressure. The per-op-time benefit v003 predicted is not yet measured, so the variant should record per-op-time as well as hit-rate.
