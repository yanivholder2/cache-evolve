# H02

Promoting a stash item only on its second stash hit raises hit-rate by keeping one-off stash hits from displacing resident items.

## Parent

baseline

## Changes

In `DashSegment::get`, add a one-bit "seen in stash" marker to each stash entry (reuse an existing flag or spare bit in the entry metadata if one exists, so metadata-size does not grow). On the first stash hit, set the marker and return the value without calling `promotion_get`, leaving the item in the stash. On a later stash hit where the marker is already set, call `promotion_get` as the baseline does, with the default `InsertPosition::Front`. Clear the marker when the item is evicted or demoted out of the stash. Do not change the probing-tier logic, `promotion_get`'s signature, or the demotion path. Keep the existing behaviour for probing-tier hits unchanged.

## Rationale (optional)

This is a different lever from v002. v002 changes where a promoted item lands. This hypothesis changes whether a stash hit promotes at all, which is an admission-style filter. It is aimed at workloads where stash hits are often one-off, which the single LIRS trace used in cycle 0001 may or may not exhibit. The change should be measured on hit-rate and metadata-size, because the marker is the one place metadata could grow.
