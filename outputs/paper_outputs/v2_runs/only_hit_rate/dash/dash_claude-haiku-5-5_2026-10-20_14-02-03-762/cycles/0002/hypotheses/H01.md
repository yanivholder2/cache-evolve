# H01

Choosing the stash-hit landing slot by target-bucket occupancy raises hit-rate over the uniform MRU landing of v002 on the LIRS workload-a trace.

## Parent

cycle/0001/v002

## Changes

Keep v002's change in `DashSegment::get`, where a stash-promoted item is passed to `promotion_get(..., InsertPosition::Back)`, but make the insert position conditional. Before calling `promotion_get`, inspect the target bucket: if it has at least one empty slot, or if its current LRU-end resident is itself a stash-origin item, use `InsertPosition::Back` as v002 does. Otherwise (the target bucket is full and its LRU-end resident is a normal-tier item) use `InsertPosition::Front`, so a stash hit does not displace a normal-tier resident that has its own recency. Do not change the probing-tier touch in `promotion_get`, the demotion path, or any eviction logic. Preserve v002's fallback behaviour for the case where the stash item has no target bucket. Update the `get` docstring so it no longer calls LRU-end promotion "the baseline design", and make the `promotion_get` comment state the new default.

## Rationale (optional)

v002 showed that landing re-referenced stash items at MRU helps, but it applies that landing unconditionally, which may evict a normal-tier resident that is still warm. Cycle 0001's continuation asks for the landing slot to be varied further, and this hypothesis tests whether occupancy is the variable that decides when MRU landing pays off.
