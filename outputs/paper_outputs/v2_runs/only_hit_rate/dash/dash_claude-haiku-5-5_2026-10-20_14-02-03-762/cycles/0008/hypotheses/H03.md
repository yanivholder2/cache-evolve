# H03

Shrinking the probing-tier share of capacity and giving the freed slots to the stash should raise hit-rate by relieving stash pressure.

## Parent

baseline

## Changes

Start from the baseline and change only the capacity split between the probing tier and the stash. Locate the constant or constructor argument that sets the probing-tier share of the 2048-slot cache, and reduce the probing-tier slot count by 128 (one-sixteenth of 2048), giving those 128 slots to the stash. Keep the total cache capacity at 2048 so the trace and size stay comparable.

Invariants to preserve:

- Admission, promotion, landing, and eviction rules stay exactly as in the baseline; only the sizes of the two tiers change.
- The seen-in-stash marker and the reuse counter are not added, removed, or changed.
- The size of each tier must still satisfy whatever minimum the code enforces; if the smaller probing size violates an existing assertion, the implementer should choose the largest step that keeps the assertion and report the chosen value.

Expected result: a measurable change in hit-rate on LIRS workload-a at size 2048 relative to baseline (0.663). A gain would support the view that stash pressure is the limiting factor; a loss or no change would argue the probing tier is already sized correctly.

## Rationale (optional)

Cycle 2 found that restoring the foreign-eviction retry helped only when the stash was full, which points to stash pressure as the constraint. Earlier cycles changed what moves between tiers but never changed how much room each tier has, so this tests a capacity lever rather than a movement or gating rule.
