# H02

Lower per-op-time below the baseline's 183 by replacing the bucket slot scan in victim search with a per-bucket occupancy counter, leaving hit-rate identical to baseline.

## Parent

baseline

## Changes

Add an equivalence-preserving per-bucket occupancy count and use it to skip slot scans that cannot find a free slot.

- Add a per-bucket occupancy count to the bucket structure, initialised to zero and kept equal to the number of occupied slots in that bucket.
- Update the count at every site that inserts, removes, or moves an entry between buckets. Cover the normal-tier insert and evict, the probing-tier insert and exit, stash landing and stash-hit promotion (including the MRU landing), normal-tier demotion, and foreign eviction. Do not miss any path that changes occupancy.
- In victim search (`evict_one()` or the equivalent victim-selection routine), check the count first. When the count equals the bucket's capacity, go straight to victim selection. When it is below capacity, run the existing slot scan unchanged, so the same slot is chosen as before.
- Do not change which entry is chosen as victim in any case, and do not change promotion, demotion, or foreign-eviction logic.
- Keep the baseline's promotion rule, probing tier, stash, and capacities exactly as they are.

The claim is confirmed if hit-rate on lirs workload-a at size 2048 equals the baseline value exactly (0.663) and per-op-time drops below 183. Any hit-rate difference means the change is not equivalence-preserving and the variant fails.

## Rationale (optional)

Per-op-time has never been measured in any cycle, so every cost claim in the history is unverified. The occupancy-counter idea has appeared twice (cycle 5 v002, cycle 6 v003), and both matched parent hit-rate exactly, so the behaviour-preserving part is already shown to be safe. What was missing was a per-op-time reading, which the prior continuation notes asked for. Parent is the baseline so that the cost effect is measured in isolation from the hit-rate lineage.
