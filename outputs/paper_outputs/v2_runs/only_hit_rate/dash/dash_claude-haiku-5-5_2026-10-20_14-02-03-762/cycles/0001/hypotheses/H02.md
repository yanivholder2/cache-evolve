# H02

Land stash-hit promotions at the MRU end of the target bucket so a re-referenced stash item survives the next eviction round and raises hit rate on the LIRS workload-a trace.

## Parent

baseline

## Changes

In `src/dash/segments/dash_segment.rs`, change the insert position used when an
item is promoted out of the stash. The `Segment::get` implementation for
`DashSegment` currently calls `promotion_get(&mut self.core, key, InsertPosition::Front)`.
Change that call to `InsertPosition::Back`.

This single argument flows into the stash-hit branch of `promotion_get()`,
which calls `promote_to_target(core, data, insert_pos)`, and from there into
`put_at(Slot::Target, insert_pos, ...)`. The `demote_from_normal_bucket`
cascade and the target-hottest / probing branches keep their current
behaviour; they only receive the same `insert_pos` value as before for the
hits they already handle.

Update the in-file tests that pin the old placement:
`stash_hit_inserts_at_front_of_target` (should now expect the newer key at
the back of the bucket, with the earlier key at index 0) and any assertions
that rely on `insert_pos = Front` for stash-origin promotions. Do not change
`InsertPosition` itself, `ClassicLRU`, or the geometry/bucket code.
