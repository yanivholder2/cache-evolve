# H03

Inserting items demoted from the probing tier at the LRU end of their normal-tier target bucket should raise hit-rate by evicting one-shot items before proven residents.

## Parent

baseline

## Changes

Change only the landing position for items demoted from the probing tier into the normal tier. Stash-hit landing and the stash promotion path stay as in baseline.

- Locate the code path where an item leaving the probing tier is inserted into the normal tier's target bucket. This is the insertion that happens when a probing-tier item is displaced; do not touch the probing-hit path or stash-hit landing.
- In the baseline, that insertion places the item at the MRU end of the target bucket. Change it to place the item at the LRU end, so it is the first candidate for eviction in its bucket.
- Keep the existing eviction loop in `evict_one()` unchanged. The LRU-end placement only changes which slot is ranked first, so no new branch or marker is needed.
- If the bucket has a free slot, place the demoted item in it as before, with no change to slot selection. Only the ordering of occupied slots changes.
- Do not add a new counter, marker, or timestamp.

Measure hit-rate on LIRS workload-a at size 2048. Record per-op-time and metadata-size if reported; no layout change is expected.

## Rationale (optional)

Landing position has been the only lever that moved hit-rate (cycle 0001, MRU landing for stash hits). Every prior landing change touched stash hits. This tests the other insertion boundary, the one where a probing-tier item is demoted, which no earlier cohort varied. Placing demoted items at the LRU end is a different strategy from the cycle 0003 victim-preference idea: it changes insertion rank, not the victim rule, so it avoids the failure mode of discarding recently arrived items by a marker signal.
