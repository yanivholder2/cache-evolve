# H01

Adding a bounded ghost history of recently evicted keys lets a returning key skip the second-hit wait and raise hit-rate on re-referenced items that the current promotion gate discards.

## Parent

cycle/0004/v001

## Changes

Keep v001's MRU landing for stash hits and its occupancy-conditional second-hit gate unchanged, except for one addition in the stash promotion decision:

- Add a fixed-capacity ghost set of recently evicted keys, sized to the stash capacity, owned by the cache struct. Implement it as a small ring buffer plus a membership check (linear scan or a fixed-size hash set is acceptable; keep it allocation-free after construction).
- In `evict_one()`, when an item leaves the stash tier (or is discarded from the normal tier under stash pressure), push its key into the ghost set, overwriting the oldest entry.
- In the promotion path that currently requires the seen-in-stash marker at or above 0.75 stash occupancy, treat a key found in the ghost set as if its marker were set: promote it on this access and remove it from the ghost set.
- Below 0.75 occupancy the gate already promotes on first hit; leave that branch untouched.
- Do not change probing-tier lookup, the probing-hit path, or the victim-selection order. Preserve the seen-in-stash marker semantics for keys not in the ghost set.

Measure hit-rate on the existing LIRS trace at size 2048. Record per-op-time and metadata-size if the harness reports them; the ghost set's memory footprint should be stated in the variant's notes.

## Rationale (optional)

Cycle 0004 showed the occupancy-conditional gate matches its parent exactly, so the gate itself is not the lever. The remaining gap is keys that were promoted-worthy, got evicted before their second hit, and therefore restart their admission wait. A ghost history targets that gap without changing the victim order, which cycle 0003 showed to be harmful.
