# H02

Hold v001's hit-rate while cutting metadata-size by storing the seen-in-stash marker inside an existing per-slot tag bit instead of a separate field.

## Parent

cycle/0003/v001

## Changes

Keep v001's MRU landing and second-hit gate behaviour exactly as implemented in the stash-hit branch of `DashSegment::get`. Change only how the one-bit "seen in stash" marker is stored: place it in an unused high bit of the existing per-slot tag or fingerprint field, rather than in any separately allocated byte or word. Add a compile-time size assertion (or a `const` check in the segment module, not in `tests/` or `src/lib.rs`) that the per-entry layout size is unchanged from the parent. Accessors `set_seen_in_stash()` and `is_seen_in_stash()` (or equivalent helpers introduced by v001) should be the only code that touches the bit. Do not alter `evict_one()` victim selection or the probing-tier logic. If the existing tag has no spare bit, do not invent one by widening the entry; instead report that the hypothesis is infeasible in the insight rather than changing layout.

## Rationale (optional)

Cycle 0003 left metadata-size unmeasured for every variant, and v003's spare-bit relocation produced an unchanged hit-rate with no evidence the layout actually changed. This hypothesis makes the layout change explicit and checkable. The target is metadata-size at or below the baseline's 40 while hit-rate stays at v001's 0.6828 on the LIRS workload-a trace at size 2048.
