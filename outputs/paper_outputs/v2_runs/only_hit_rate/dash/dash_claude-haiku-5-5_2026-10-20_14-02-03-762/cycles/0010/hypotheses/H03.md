# H03

Requiring the second hit to arrive within a bounded recency window, rather than at any later time, will raise hit-rate over v003 on LIRS workload-a at size 2048 by promoting only items whose reuse is temporally local.

## Parent

cycle/0009/v003

## Changes

In v003, the stash-promotion path currently promotes an item once it has been re-referenced (the second-hit gate). Keep that gate and the MRU landing unchanged, and add a recency bound to it. Store, for each item in the stash, the access index (a logical clock or a counter already maintained by the cache) at which it was first seen. When a second hit arrives, promote only if the current clock minus the stored first-seen index is at most W, where W is a named constant set to 2048 for the first run. Items whose second hit falls outside the window are treated as first-time arrivals: reset their first-seen index to the current clock and leave them in the stash.

Use the existing access-counter or clock if one exists; otherwise add a single monotonically increasing u32 counter to the cache state and document its wrap behaviour. Do not change the probing-to-stash demotion path, the eviction victim order, or the stash capacity split from v003.

Expected outcome to test: hit-rate moves above or below 0.6906. A result at or below v003 refutes the claim that temporal locality of the second hit carries signal. Record metadata-size, since the stored index adds bits per item.
