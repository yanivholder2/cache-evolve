# H03

Bypassing stash insertion for probing-tier entries that were never re-hit while resident will reduce stash pressure and raise hit rate on LIRS workload-a at size 2048, because one-off items stop displacing stash residents that have proven reuse.

## Parent

baseline

## Changes

Start from the baseline source. Find the branch in the probing-tier eviction path (where an entry leaving the probing tier is moved toward the stash) and add a check on a per-entry hit indicator: if the entry has zero hits since it entered the probing tier, drop it outright instead of placing it in the stash. Entries with one or more probing hits keep the existing move-to-stash behaviour. Do not change stash promotion, stash landing position, victim selection in `evict_one()`, or normal-tier retries. If the baseline has no per-entry hit indicator, reuse an existing bit or derive it from an existing field; do not add a new metadata word. Preserve the invariant that a dropped entry is removed from the probing tier's index so later lookups miss cleanly.

Note for the implementer: this is an admission filter at probing-tier exit, distinct from the stash-promotion gate tried in cycles 2 and 6. Record the number of bypassed entries in the insight so the effect can be separated from the existing promotion gate.
