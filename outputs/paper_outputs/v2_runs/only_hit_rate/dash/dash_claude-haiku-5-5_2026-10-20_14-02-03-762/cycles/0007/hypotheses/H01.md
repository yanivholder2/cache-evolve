# H01

Counting only re-hits separated by at least one intervening access toward the saturating reuse counter will raise hit rate on LIRS workload-a at size 2048 by filtering out burst re-references that the current counter treats as persistent reuse.

## Parent

cycle/0006/v001

## Changes

Start from the v001 overlay (2-bit saturating reuse counter that replaced the one-bit seen-in-stash marker, with stash promotion gated on counter >= 2). Locate the code path in the v001 overlay that increments the reuse counter on a stash hit. Change that increment so it fires only when the hit is on an entry whose last-touch sequence number is older than the most recent cache access (i.e. at least one other access has happened since the entry was last touched). A hit on an entry that was touched by the immediately preceding access does not increment the counter. Keep the promotion comparison (counter >= 2), the saturation at 3, the reset on demotion and eviction, and the 0.75 occupancy branch exactly as in v001. If the entry has no last-touch sequence field, add one using the existing per-entry metadata word if spare bits allow; otherwise use a global access counter stored alongside the table and report the added bits in the insight. Do not change probing-tier or normal-tier logic.

Note for the implementer: the v001 insight records that the overlay diff was not inspected last cycle, so confirm the counter update site and reset sites before editing.
