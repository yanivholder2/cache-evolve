# H01

Gating stash promotion on a second stash hit, on top of MRU landing, raises hit-rate above the incumbent's 0.6787 on the LIRS workload-a trace at size 2048.

## Parent

cycle/0001/v002

## Changes

Start from cycle/0001/v002, which lands a re-referenced stash item at `InsertPosition::Back` in `DashSegment::get`. Add the admission filter from cycle/0002/v002 to that same stash-hit branch. Add a one-bit "seen in stash" marker to each stash entry, reusing an existing flag or spare bit in the entry metadata so the entry size does not grow. On a first stash hit, set the marker, leave the item in the stash, and return the value without calling `promotion_get`. On a later stash hit where the marker is already set, call `promotion_get` with `InsertPosition::Back`, which is the v002 landing, not the baseline `Front` default. Clear the marker when the item leaves the stash by eviction or demotion. Do not add any occupancy-conditional landing, and do not change the probing-tier path, `promotion_get`'s signature, or the demotion path. Keep probing-tier hits unchanged.

## Rationale (optional)

The two productive levers so far act on different stages: MRU landing (cycle 0001) changes where a promoted item lands, and the second-hit filter (cycle 0002) changes whether a stash hit promotes at all. Neither has been tested in combination. The cycle 0002 continuation asks for the promotion filter to build on the existing winner, so this stacks it on the cross-cycle incumbent rather than on baseline.
