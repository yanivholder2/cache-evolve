# H02

Evicting never-re-hit stash entries before re-hit ones when the stash is full raises hit-rate by keeping items that have proven reuse.

## Parent

cycle/0002/v002

## Changes

Start from cycle/0002/v002, which already has the one-bit "seen in stash" marker set on a first stash hit and cleared on eviction or demotion. Leave the admission rule and the marker's set and clear logic unchanged. Change only the stash victim-selection routine, the code that picks a stash entry to evict when the stash has no free slot. When choosing a victim, first scan for an entry whose marker is clear (it has never been hit while in the stash) and evict the first such entry found. Only if every stash entry has its marker set, fall back to the existing victim order. Do not change `promotion_get`, the probing-tier code, or the demotion path. Add a comment at the new scan naming the marker condition so the two passes are easy to tell apart in review.

## Rationale (optional)

Cycle 0002's insight attributes the second-hit filter's gain to one-off stash hits displacing resident items, but the filter only stops promotion. It does not change which stash entry is sacrificed once the stash is full. Preferring never-re-hit entries as victims targets the same displacement from the eviction side, and it reuses the marker the parent already maintains, so it adds no metadata. The cycle 0001 and 0002 insights left stash eviction order untouched, so this is a lever no prior variant has tested.
