# H01

Remove BIP's blind MRU admission entirely so that a ghost hit is the only way a fresh key can enter the protected stash MRU region, raising hit-rate.

## Parent

cycle/0006/v003

## Changes

This tests the BIP endpoint that cycle 0006 left open. Everything else in v003 stays unchanged: the ghost table and its window size, the ghost-hit MRU override, the second-chance stash scan, `PROMOTE_THRESHOLD`, the MRU re-entry of demoted ex-residents, normal-tier landing and cascades.

1. In the fresh-key insert path of `DashSegment::put`, find the ghost-miss branch. It currently sends 1 in `BIP_PERIOD` fresh keys to the stash MRU end. Make that branch always insert at the stash LRU (probation) end.
2. Remove the BIP counter/RNG state and the `BIP_PERIOD` constant if nothing else uses them. This also removes their per-segment metadata and the per-insert counter update. If removing them is awkward, set the period so high that the MRU path never fires, for example by gating it behind `false`.
3. Leave the ghost-hit branch as it is: on a fingerprint match, clear the slot and insert at the stash MRU end with counter 0.

Invariants: no allocation on the insert path, and the ghost write on stash eviction is unchanged. Fresh keys with no ghost evidence still get one probation residency, and a stash hit there can still promote them through the normal threshold path.

## Rationale (optional)

The 4× rarer BIP won in 0006, which suggests the blind path is a net drain now that the ghost exists. Going all the way to zero tells us whether that trend continues, or whether BIP still catches reuse the ghost window misses. If hit-rate drops, the optimum `BIP_PERIOD` is finite and lies between v003's value and infinity. Either result also simplifies the code.
