# H02

Make ghost evidence recency-gated by storing a coarse eviction epoch next to each ghost fingerprint and honouring a ghost hit only if the key was evicted within roughly half a cache's worth of stash evictions, raising hit-rate.

## Parent

cycle/0006/v003

## Changes

This sharpens the ghost signal without changing its table size or what a ghost hit does. BIP (at v003's period), the second-chance scan, `PROMOTE_THRESHOLD`, the MRU re-entry of demoted ex-residents, normal-tier landing and cascades are unchanged.

1. Add a per-segment `u16` stash-eviction counter `evict_clock` that increments, with wrapping, on every eviction out of the stash, at the same place the ghost fingerprint is written.
2. Widen each ghost entry from a `u16` fingerprint to a `(u16 fingerprint, u8 epoch)` pair, using a second parallel `[u8; GHOST_SLOTS]` array or a packed `u32`. The epoch is `(evict_clock >> EPOCH_SHIFT) as u8`. Choose `EPOCH_SHIFT` so that one epoch covers about `GHOST_SLOTS / 8` evictions, rounded to a power of two.
3. On a ghost lookup in the fresh-key insert path of `DashSegment::put`, compute `age = cur_epoch.wrapping_sub(entry_epoch)`. Treat the lookup as a hit, meaning clear the slot and insert at stash MRU with counter 0, only when the fingerprint matches **and** `age <= 4`, i.e. about half the ghost window. If the fingerprint matches but the entry is too old, clear the slot and fall through to the normal BIP/probation path.
4. Keep the direct-mapped overwrite and the 0 = empty convention. Report the extra metadata (1 byte × `GHOST_SLOTS` plus 2 bytes per segment) in any metadata accounting.

Invariants: no allocation, and the gate is a single wrapping subtraction and compare on lookup.

## Rationale (optional)

Cycle 0006 showed that a 4× window lost because far-back ghost hits displaced residents with shorter reuse. That means evidence quality depends on reuse distance. The direct-mapped table already ages entries implicitly, but stale entries that survive collisions still trigger MRU placement. An explicit recency gate tests whether trimming those weakest hits frees more protected capacity than it loses. This differs from H01, which changes the blind path, while H02 changes the selective path.
