# H02

Shrinking the ghost table to half its entries, matched to the recency-gated horizon, cuts metadata-size while keeping hit-rate within noise of 0.7302.

## Parent

cycle/0008/v001

## Changes

Start from cycle/0008/v001 (recency-gated ghost with age ≤ 4 epochs, no BIP). The ghost table is currently sized at about one cache's worth of fingerprints, but only hits from at most about half the window back (age ≤ 4 epochs) change placement. Entries older than that are dead weight.

- Halve the ghost table capacity constant, for example from about `capacity` entries to `capacity / 2`. Keep it a power of two if the index uses a mask, and update the mask/shift used to index it so the hash still spreads over the whole smaller table. If the table is per segment, halve the per-segment count.
- Keep the epoch length **in evictions** unchanged, so the recency cutoff of 4 epochs keeps its meaning in eviction distance. Do not rescale the cutoff.
- If the per-entry epoch tag is wider than needed, narrow it to the smallest width that still distinguishes ages 0..4 from stale, for example a `u8` with wrapping subtraction where any age > 4 counts as stale. Keep wraparound handling correct.
- If the fingerprint width per ghost entry is larger than 16 bits, you may keep it. Change only the entry count and the tag width.
- Update the metadata-size accounting (whatever reports the cache's metadata footprint) so it reflects the smaller table.

Leave unchanged: the gated ghost-hit → stash MRU path, fresh-key LRU insertion, demotion MRU re-entry with pre-credit, the stash→target threshold, the second-chance scan, and Front landing.

## Rationale (optional)

The cycle-0008 continuation names this as the main metadata hypothesis. A direct-mapped ghost of half the size overwrites entries about twice as fast. If the gated horizon (≤ 4 epochs ≈ half a window) truly bounds useful evidence, the extra overwrites mostly hit entries that would have failed the gate anyway, so hit-rate holds. If hit-rate drops noticeably, collision-driven loss of recent entries matters more than window length. The fix would then be a set-associative ghost, not a larger one.
