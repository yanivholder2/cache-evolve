# H01

Refusing stash admission to a fresh ghost-miss key whenever placing it would evict an evidence-backed stash resident (recording it only as a ghost) raises hit-rate, because fresh keys can then displace only other unproven probation keys.

## Parent

cycle/0008/v001

## Changes

Start from cycle/0008/v001 (recency-gated ghost, no BIP). Edit the stash insertion path for a **fresh key**, meaning a ghost miss or a ghost hit that fails the recency gate. Today that path picks a stash victim (second-chance scan) and inserts the key at the LRU/probation end.

New behaviour on that path only:

1. Before evicting, check the victim candidate that the existing victim-selection logic picks for this insert. Classify it as **evidence-backed** if any of these is true: its promotion counter is > 0, it entered the stash through the demotion path (MRU re-entry with pre-credit), or it entered through a recent ghost hit. Use whatever existing state tells these apart, such as the counter, the reference/second-chance bit, or position at the MRU end. If a 1-bit "admitted with evidence" flag per stash slot is needed, add it to the stash slot metadata, set it on the demotion-insert and gated-ghost-insert paths, and clear it when the slot is overwritten by a fresh key.
2. If the candidate is evidence-backed **and** no free stash slot exists in the target stash bucket(s), do **not** insert the fresh key. Record its fingerprint in the ghost table with the current epoch, exactly as an eviction would, and return. The miss is counted as usual. A later return of the key within the gated horizon then takes the existing recent-ghost-hit path to stash MRU.
3. Otherwise, meaning the candidate is a fresh/probation key with no evidence, or a free slot exists, insert exactly as today.

Leave unchanged: the demotion-from-normal-tier path (it must still be allowed to evict anything, using today's victim logic), the gated ghost-hit path, the epoch counter and cutoff, the ghost table size, the stash→target threshold, and Front landing. The insert API must still report success to the caller. A bypassed fresh insert is treated like an insert of an immediately evicted key, not as an error. Check that the bypass does not break any return-value or size accounting the tests rely on: the `len`/count must not be incremented for a bypassed key.

## Rationale (optional)

Every winner since 0001 filtered admission into protected space. The cycle-0008 continuation says in-stash placement is exhausted and the next lever is *who reaches the stash at all*. Under no-BIP, a fresh key lands at LRU, but the second-chance scan can still pick a credited or demoted resident when the probation slot is occupied by a key with a second-chance bit, or when the scan wraps. This change turns the ghost into a doorkeeper for that case only, so short-reuse fresh keys keep their probation slot when one is available. If hit-rate drops, short-reuse one-touch keys were worth more than the protected residents they displaced, and admission is at its optimum.
