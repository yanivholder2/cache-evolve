# H01

Requiring an item to have collected at least three target-bucket hits, and to be the hottest in its target, before it is promoted to probing will raise hit-rate by keeping lukewarm keys from evicting proven residents of the neighbouring bucket.

## Parent

cycle/0001/v003

## Changes

All edits are in `src/dash/segments/dash_segment.rs`. No change to the Item layout: v003 already resets `Item::lfu_counter` to 0 when an item is promoted stash→target, so inside the target tier the field is free to use as a per-item "target hit" counter.

1. Add `const PROBING_THRESHOLD: usize = 3;` next to `PROMOTE_THRESHOLD`.
2. In `promotion_get`'s target branch, after `get_position` returns `item_idx`, increment
   `core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter` with a saturating add and read back the new value as `hits`. Do this before computing `is_hottest`; the touch does not move the item.
3. Change the promotion condition from `is_hottest` to `is_hottest && hits >= PROBING_THRESHOLD`.
   - When the condition holds: `remove_at`, set `data.lfu_counter = 0`, then `promote_to_probing` as today, keeping the post-insert lookup and its `unreachable!` guard.
   - Otherwise: serve with `get_from_position(item_idx)` as the intra-promote branch does today. The item still moves to MRU, so the "is hottest" position bar stays where it is. The counter adds a frequency bar on top of it.
4. In `demote_from_normal_bucket`'s foreign-resident branch, set `item.lfu_counter = PROBING_THRESHOLD - 1` before the `core.put_at(Slot::Target, ...)` retry. An item pushed out of probing back into its own target has already earned probing once, so the next hottest hit returns it. Leave the stash pre-credit (`PROMOTE_THRESHOLD - 1`) on the direct-to-stash and `cascade` paths unchanged.
5. Leave the stash branch (two-hit filter), the probing branch and `DashSegment::get`'s `InsertPosition::Front` unchanged.
6. Tests: `target_hit_hottest_promotes_to_probing`, `cascade_demotion_probing_to_full_target_to_stash` and `last_bucket_probing_wraps_to_zero` need one extra `seg.get(&k)` on the promoting key so it reaches 3 target hits. `probing_eviction_demotes_to_target` puts the item straight into the target with counter 0, so it needs extra gets too; or set its `lfu_counter` before the put. Add a test showing that a key that is hottest in its target but has only 2 target hits stays in the target.

Invariants: the target→probing move is still one `remove_at` followed by one `put_at`. No new slots are used. The ClassicLRU ordering is unchanged because the counter is never read by the eviction policy.

## Rationale

The cycle-0001 lesson is that stricter admission into the scarce tier wins, and that every normal-tier move starts a cross-bucket demotion cascade. The target→probing edge is the second admission point. It also costs more than the stash edge, because promoting into probing evicts a *neighbour's* resident, and that eviction cascades again. Under Front landing an item now needs only two hits in the target to reach probing (one to climb to MRU, one to promote). A frequency bar filters keys that get two quick hits in a row and then go cold.
