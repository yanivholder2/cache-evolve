# H01

Widen the stash's BIP probation area from one LRU slot to two, so fresh keys with moderate reuse distance survive one extra insert into their bucket and hit-rate rises.

## Parent

cycle/0004/v003

## Changes

v003 inserts 15 of every 16 fresh keys at the stash LRU end (`InsertPosition::Front`, index 0) with counter 0. The second-chance scan in `stash_put` starts at index 0, so a fresh key is evicted by the very next insert into its stash bucket. Keep the BIP decision itself in `DashSegment::put` unchanged (same `BIP_PERIOD`, the 1-in-16 MRU insert stays). Change only where non-MRU fresh keys land and which slot is evicted:

1. Add a constant `PROBATION_SLOTS: usize = 2`. It must be smaller than the stash bucket capacity. If the bucket has 2 or fewer slots, clamp it to 1 so behaviour falls back to v003.
2. In `stash_put`, when a stash bucket is full and a fresh (non-MRU BIP) key is being inserted, restrict the victim search to the probation region, indices `0..PROBATION_SLOTS`. Evict the lowest-index slot with counter 0. If both have counter > 0, evict index 0 and apply the existing second-chance decrement only to the probation slots. Never decrement or touch the counters of slots at index >= `PROBATION_SLOTS`, so the protected ex-resident region stays un-aged as it is in v003.
3. Insert the new fresh key at index `PROBATION_SLOTS - 1` (the MRU end of the probation region), shifting index 1 down to index 0. A fresh key then needs two subsequent fresh inserts into its bucket before it is evicted, which is FIFO inside probation.
4. Inserts of demoted ex-residents (MRU end, `PROMOTE_THRESHOLD - 1` pre-credit) and of 1-in-16 MRU fresh keys keep v003's existing victim scan and placement unchanged.
5. A stash hit on a probation slot follows the existing promotion path and counter increment unchanged.

Invariants: no change to normal-tier landing, cascade routing, `PROMOTE_THRESHOLD`, or metadata layout. No new per-slot fields are allowed; probation membership comes purely from index.

## Rationale (optional)

v003's insight names the cost of BIP as "a fresh key survives only if it is reused before the next insert into its stash bucket". A two-slot FIFO probation doubles that survival window but still keeps one-touch scan keys away from the protected ex-resident slots. That keeps the probation/victim-cache split that produced the 0004 gain. This tests the cycle-0004 open question about probation depth.
