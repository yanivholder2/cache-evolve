**What changed against cycle/0009/v002:**
- **Where demoted keys go:** a normal-tier key going to the stash now lands at the stash MRU end only if it was hit while in the normal tier. If it wasn't, it lands at the LRU (probation) end, the same place a fresh key goes. Either way it keeps the `PROMOTE_THRESHOLD - 1` pre-credit, so one stash hit can still promote it. This applies to both the direct target→stash path and the cascade path.
- **The hit flag:** I added no new state. A key's `lfu_counter` is not used for anything else while the key is in the normal tier, so a non-zero value there now means "hit while in normal tier".
  - It is cleared when a key moves from stash to target. The existing code already resets it to 0 there.
  - It is cleared when a cascade moves a key from probing into its own target.
  - It is set on a `get` hit in the target bucket (both the hottest-item promotion and the in-place hit) and in the probing bucket.
- **Exception under the `Lfu` policy:** there, the counter already is the hit count since the key entered the normal tier, so the code reuses it without extra writes. It also doesn't clear it on a cascade move, because doing so would change which item `Lfu` evicts from the normal tier, and the hypothesis says that must stay the same.
- **Unchanged:** the victim choice inside the normal tier, which stash bucket a key goes to, the ghost route to MRU, the ghost table size and epoch, fresh-key LRU insertion, the promote threshold, the second-chance scan, and the Front landing.

**Tests:** four parent unit tests expected an unhit demoted key to land at MRU. I replaced them with versions that check both cases: unhit lands at the LRU end and hit lands at MRU, under either insert position. I also added tests that the flag is cleared on landing, set on a hit, and cleared on a cascade move.
