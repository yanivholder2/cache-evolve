# H02

Demoted normal-tier residents that took no hit while in the normal tier should re-enter the stash at the LRU (probation) end, not MRU, so that only proven ex-residents keep protected space; this filter raises hit-rate.

## Parent

cycle/0009/v002

## Changes

Start from cycle/0009/v002. Today every item demoted or evicted from a normal (target/probing) bucket re-enters the stash at the MRU end with its pre-credit. This is the only route into stash MRU that has no filter. The ghost route is gated on recency, and BIP is gone.

- Add a 1-bit "hit while in normal tier" flag to each normal-bucket slot, unless equivalent existing state already exists. If the normal slot's counter or reference bit already records hits taken since the key landed in the normal tier, reuse it and add no new state. Clear the flag when a key is placed into a normal slot (stash→target promotion, Front landing, and any cascade move into a foreign bucket). Set it on a `get` hit for that slot.
- In the demotion path that moves a normal-tier victim into the stash:
  - If the flag is set, keep today's behaviour: insert at stash MRU with the existing pre-credit.
  - If the flag is clear, insert at the stash LRU (probation) end, the same position a fresh key uses. Keep the existing pre-credit on the counter so a single stash hit can still promote it back. Only the position changes.
- Do not change the victim choice inside the normal tier, or which stash bucket the demoted key goes to.
- Leave unchanged: the gated ghost-hit → stash MRU path, the ghost table size and epoch, fresh-key LRU insertion, the stash→target threshold, the second-chance scan, and Front landing.

Invariant after this change: a key reaches stash MRU only through a recent ghost hit or a demotion of a key that was hit while in the normal tier.

## Rationale (optional)

Every winner from 0001 to 0009 tightened what earns protected stash space. The demotion route is the last unfiltered one. A key that was promoted into the normal tier and then never touched before demotion has shown no reuse at normal-tier distance, so it is no better evidence than a stale ghost hit. Giving it MRU placement takes protected slots from recent-ghost and genuinely hot keys. This is a filtering move on a different admission route from those tuned so far, so it should stack, as the 0008 gate and BIP removal did. If hit-rate drops, the pre-credited untouched ex-residents were recovering cheaply, and demotion placement is already at its optimum.
