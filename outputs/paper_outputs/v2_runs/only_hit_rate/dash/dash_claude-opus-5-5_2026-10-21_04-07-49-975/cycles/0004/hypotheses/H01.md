# H01

Adding a small per-stash-bucket ghost list of recently evicted key fingerprints, and pre-crediting any re-inserted key found there, will raise hit-rate by letting keys whose reuse distance exceeds residency skip the two-hit stash bar.

## Parent

cycle/0003/v002

## Changes

All edits are in `src/dash/segments/dash_segment.rs`. Every lever tried so far uses information about keys that are currently resident. This one adds non-resident history, as in ARC/LIRS ghost entries. On a LIRS trace, loop-like keys with reuse distance just over the cache size are evicted before their second stash hit, and today each return counts as a brand-new key.

1. Add a ghost table to `DashSegment`: a new field `ghosts: Vec<GhostRing>`, one per stash bucket (`core.stash_size` entries), built in `try_new`. `GhostRing` is a small fixed array `[u32; GHOST_WAYS]` with `GHOST_WAYS = 4`, a `u8` write cursor, and 0 used as the empty sentinel. A fingerprint is a 32-bit hash of the key (hash it with `std::collections::hash_map::DefaultHasher`, take the upper 32 bits, and map 0 to 1). Use a hash that differs from the bucket-index bits given by `get_index`.
2. Recording: whenever an item leaves the cache entirely, insert its fingerprint into the ring for its stash bucket, overwriting the oldest entry. Today that happens only inside `stash_put`, where the victim is returned (from `put`) or dropped (from the demotion paths). Thread `&mut [GhostRing]` through as an extra argument: `promotion_get(&mut self.core, &mut self.ghosts, ...)`, then `promote_to_target`, `promote_to_probing`, `demote_from_normal_bucket` and `stash_put`. Record inside `stash_put` so all three call sites are covered. Use a disjoint field borrow in `get`/`put`, not `core_mut()`.
3. Admission: in `DashSegment::put`, before calling `stash_put`, look up the new key's fingerprint in its stash bucket's ring. On a match, clear that ghost entry and set `item.lfu_counter = PROMOTE_THRESHOLD - 1`. A single `get` hit then promotes the key, and v002's second-chance scan also protects it once. On no match, behaviour is unchanged (counter 0, `InsertPosition::Back`).
4. Keep everything else exactly as in v002: `PROMOTE_THRESHOLD = 2`, `DEMOTE_TO_STASH_POS = Back`, the demotion pre-credits, the second-chance scan and all normal-tier logic.
5. Tests: update the existing direct calls to `promote_to_probing` and `promote_to_target` so they pass a ghost slice. Add a test where a key is evicted from a full stash bucket and then `put` again. It must enter with `lfu_counter == PROMOTE_THRESHOLD - 1`, and one `get` must move it into its target bucket. Add another test showing that a never-seen key still needs two hits.

Invariants: ghosts hold fingerprints only, never values, so a false positive only means a wrong pre-credit and cannot affect correctness. No key is ever in two tiers. The extra metadata is about 17 bytes per stash bucket.

## Rationale (optional)

Cycle 0003 found the design saturated: admission thresholds, stash victim choice and routing all choose between victims the stash can recover cheaply. The remaining loss is keys that the cache cannot keep long enough to prove reuse. Ghost history is the missing information source for those keys. It targets fresh-key misses, which the previous levers never reached, because those levers only re-ranked items that were already resident.
