# H02

Tightening the ghost recency gate from age ≤ 4 epochs to age ≤ 2 epochs raises hit-rate, because ghost evidence from about a quarter of the window back predicts in-cache reuse better than evidence from half a window back.

## Parent

cycle/0007/v002

## Changes

In cycle/0007/v002, find the ghost-hit check in the stash insertion path. It compares `current_epoch - ghost_entry.epoch` (wrapping arithmetic) against the maximum-age constant, currently 4. Change only that cutoff from 4 to 2, so a ghost hit earns stash-MRU placement only when the entry was recorded at most 2 epochs ago. Ghost hits older than that fall through to the existing fresh-key path, the same path as a ghost miss.

Keep everything else identical to v002:

- epoch length, meaning how many evictions advance the epoch
- ghost table size and indexing
- BIP state and period
- demotion MRU re-entry and pre-credit
- the promotion threshold
- the second-chance stash scan

If the epoch tag has wraparound handling, check that it stays correct with the smaller cutoff. Any age above 2, including a wrapped age, must be treated as stale.

## Rationale (optional)

Across cycles, ghost horizons ranked like this: 4× window lost (0006), 1× window won (0005), ~0.5× gated won (0007). The open question is whether the optimum is shorter still. If ≤ 2 beats 0.7274, the trend toward recent evidence continues and the ghost table could shrink. If it loses, the optimum sits between 2 and 4 epochs (or above 4). This is a one-parameter change, so it isolates the cutoff from H01's BIP removal and H03's graded placement.
