# H03

Requiring two stash hits before an item is promoted to its target bucket, with first hits served in place in stash, will raise hit-rate by keeping one-hit wonders from evicting proven residents out of the normal tier.

## Parent

baseline

## Changes

All edits are in `src/dash/segments/dash_segment.rs` (segment extension point).
No Item layout change: the existing `Item::lfu_counter` field is reused as a
per-item "stash hit" counter. The baseline ClassicLRU policy never reads it, so
using it does not change eviction ordering.

Right now every stash hit (`promotion_get` stash branch) removes the item from
stash and calls `promote_to_target`. When the target is full, that evicts the
target LRU. So any key seen twice (put + one get) displaces a normal-tier
resident, and on LIRS-style workloads with many short-reuse keys this churns
the target buckets.

1. In `promotion_get`'s stash branch, after finding `item_idx`:
   - Increment `core.stash_buckets[stash_idx].get_items_mut()[item_idx].lfu_counter`
     with a saturating add.
   - If the counter is now `< PROMOTE_THRESHOLD` (new `const PROMOTE_THRESHOLD: usize = 2;`),
     do not move the item between slots. Call
     `core.stash_buckets[stash_idx].get_from_position(item_idx)` (ClassicLRU
     moves it to the stash MRU end) and return that reference.
   - Otherwise, `remove_at` the item, reset its `lfu_counter` to 0, and call
     `promote_to_target` exactly as today, with the same post-insert lookup and
     `unreachable!` guard.
2. In `demote_from_normal_bucket`, set `item.lfu_counter = PROMOTE_THRESHOLD - 1`
   before each `Slot::Stash` insert (the direct one and the `cascade` one). An
   item that already earned normal-tier residency then needs only one stash hit
   to return. Make the `item` binding `mut`, and likewise `cascade`.
3. Leave the target and probing branches and `DashSegment::get`'s
   `InsertPosition::Front` unchanged.
4. Update the in-file unit tests that assume one stash hit promotes
   (`stash_hit_inserts_at_front_of_target`, `target_hit_*`,
   `cascade_demotion_probing_to_full_target_to_stash`,
   `last_bucket_probing_wraps_to_zero`): add one extra `seg.get(&k)` after each
   `put` so the item reaches the target. Add a test asserting that after
   `put(k)` + one `get(k)` the key is still in stash and absent from target.

Invariants preserved: no new slots are used, all inserts still go through
`put_at`, and a first stash hit only reorders within one bucket. `get` still
searches all three slots and returns the item wherever it now lives.

## Rationale

This is an admission filter on the stash→normal edge, a different lever from
H01 (position within the bucket) and H02 (which bucket). The stash is 3× larger
than the normal tier (24 vs 8 buckets), so it can afford to hold
recently-touched but unproven items, while the scarce normal tier is kept for
items with repeated reuse. It also removes one remove+insert(+cascade) per
first-time stash hit, so get p50 (183 ns) should also improve.
