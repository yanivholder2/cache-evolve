# H02

Sending a stash hit to a free slot in its probing bucket when the target bucket is full, instead of evicting from the target, will raise hit-rate by using normal-bucket capacity that currently sits empty.

## Parent

baseline

## Changes

All edits are in `src/dash/segments/dash_segment.rs` (segment extension point).

Right now a stash hit always goes to `Slot::Target` (`promote_to_target`). The
probing bucket (`target_idx + 1`) only gets an item when that item is already
the hottest in its target. So normal-bucket load is uneven: a hot target keeps
evicting into stash while its neighbour may have free slots. This is Dash's
own "balanced insert" idea applied to the promotion path.

1. Add a helper `fn promote_from_stash(core, item, insert_pos) -> usize` that
   returns the normal-bucket index where the item ended up:
   - Compute `target_idx` and `probing_idx = (target_idx + 1) % segment_size`.
   - If `!core.buckets[target_idx].is_full()`, put into `Slot::Target` (no
     eviction) and return `target_idx`.
   - Else if `!core.buckets[probing_idx].is_full()`, put into `Slot::Probing`
     (no eviction) and return `probing_idx`.
   - Else (both full), fall back to the existing `promote_to_target` behaviour,
     which evicts the target LRU and sends it through
     `demote_from_normal_bucket`, and return `target_idx`.
   Ties when both have space: prefer target (keeps the target→probing
   promotion ladder meaningful).
2. In `promotion_get`'s stash branch, replace `promote_to_target(core, data, insert_pos)`
   and the `core.buckets[target_idx].get_position(key)` lookup with a call to
   `promote_from_stash`. Then look the key up in the returned bucket index, keeping
   an `unreachable!` guard if it is missing.
3. Keep the target branch (hottest → probing, else intra-bucket touch) and the
   probing branch (touch in place) unchanged. An item placed directly in
   probing by step 1 is served by the existing probing branch on later hits.
4. Keep `DashSegment::get` passing `InsertPosition::Front`, so this hypothesis
   tests only the effect of placement choice.
5. Add a unit test: fill target bucket 0 to `bucket_size`, leave bucket 1 with space,
   put+get a fresh key for bucket 0, and assert it lands in bucket 1 with no
   item from bucket 0 moved to stash.

Invariants preserved: probing placement is legal for the key (`check_slot_legality`
accepts target or target+1), and capacity holds because every insert goes through
`put_at`, which only places directly into a non-full bucket. Uniqueness holds
because the item is removed from stash before it is inserted.

## Rationale

With 8 normal × 64 and 24 stash × 64 per segment, the normal tier is small and
hashing skew leaves some buckets saturated while others are not. When a free
legal slot exists, avoiding an eviction should retain more of the working set.
This tests *where* a promoted item lands, which is a different lever from H01's
*position within the bucket*.
