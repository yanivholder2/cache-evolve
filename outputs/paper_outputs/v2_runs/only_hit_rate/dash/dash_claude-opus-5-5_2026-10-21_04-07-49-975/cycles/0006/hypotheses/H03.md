# H03

Raise `BIP_PERIOD` by 4× so that fresh keys with no ghost evidence almost never take a protected stash MRU slot, leaving more protected capacity to ex-residents and ghost-hit keys and raising hit-rate.

## Parent

cycle/0005/v003

## Changes

Change only the BIP blanket-MRU rate in v003. The ghost table, the ghost-hit MRU override, the second-chance scan, `PROMOTE_THRESHOLD`, demoted-ex-resident MRU re-entry, normal-tier landing and cascades are all unchanged.

1. In the fresh-key insert path of `DashSegment::put`, the ghost-miss branch uses BIP. It currently sends roughly 1 in `BIP_PERIOD` fresh keys to the stash MRU end and the rest to the LRU probation slot. Multiply `BIP_PERIOD` by 4 (for example 32 → 128). If the current value is below 16, set it to 64. Keep it a power of two if the code uses a mask (`counter & (BIP_PERIOD-1)`).
2. Leave the BIP counter or RNG mechanism itself unchanged. Only the period constant moves.
3. Leave the ghost-hit branch untouched. It still overrides BIP and inserts at MRU, so from now on the ghost is almost the only route by which a fresh key reaches the protected region.

Expected outcome: if hit-rate rises, the blanket random MRU inserts were wasting protected capacity that the ghost now covers selectively. If hit-rate falls, BIP's random admissions still catch useful keys the ghost window misses. In that case H01's larger window is the better path.

## Rationale (optional)

Cross-cycle insights show that protected stash capacity is close to zero-sum and that only selective, evidence-based admission into it pays off. Before the ghost existed, BIP's 1-in-N MRU inserts were the only way a fresh key could escape probation. Now that the ghost gives a targeted path, the blind path may cost more than it brings. `BIP_PERIOD` was flagged as the one survival knob that has not been tuned. This hypothesis tunes the blind admission rate, while H01 targets the ghost window and H02 targets scan protection.
