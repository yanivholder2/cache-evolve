# H03

Using conservative-update count-min increments (only bump the minimum-valued counters) will make frequency estimates less inflated and raise hit-rate above 0.7406.

## Parent

cycle/0005/v002

## Changes

In the sketch `increment`, first read all row counters for the key (reusing the indices already computed) and find the minimum value m. If m is at saturation, return. Otherwise increment only those row counters whose value equals m (conservative update); leave higher counters untouched. `estimate` remains the min over rows. Keep counter type, width, admission (strict `>`), victim selection, and Node layout unchanged. Any aging/reset logic must be left as in the parent. Expected cost: one extra read pass over already-cached lines, so per-op-time should stay within noise.

## Rationale (optional)

Prior cycles showed width increases give only marginal gains, but conservative update reduces collision inflation without extra memory, a mechanism not yet tried.
