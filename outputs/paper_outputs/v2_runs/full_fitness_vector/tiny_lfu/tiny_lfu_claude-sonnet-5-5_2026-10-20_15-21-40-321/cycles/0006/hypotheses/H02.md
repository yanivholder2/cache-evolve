# H02

Adding only a saturation early-exit to the sketch increment (no hash change) on the cheap-hasher lineage will cut per-op-time without changing hit-rate.

## Parent

cycle/0004/v001

## Changes

In the sketch `increment`, before writing any counter, check whether all row counters for the key are already at the saturation cap (or the minimum of them is at cap); if so return immediately without writes. Additionally, skip the store for any individual counter already at cap. Leave the hashing/index derivation exactly as in the parent, so this isolates the early-exit effect from the hash-derivation effect. No changes to admission, eviction, Node layout, or width.
