# H01

Replacing the multi-hash sketch increment/estimate with one hash plus shift-derived row indices on the best incumbent will lower per-op-time while keeping hit-rate at 0.742.

## Parent

cycle/0004/v003

## Changes

In the sketch module's `increment` and `estimate`, compute a single 64-bit mixed hash of the key once per call. Derive each row's counter index by shifting/bit-slicing that hash (e.g. row i uses `(h >> (i*k)) & mask`, or h1 + i*h2 double hashing from the two 32-bit halves) instead of re-hashing per row. Use the same derivation in both functions so the estimate sees the same counters as increment. Do not change counter width, number of rows, the width factor (keep the parent's value), the admission rule (strict `>`), victim choice, or Node layout. Keep `get`/`put` semantics identical.

## Rationale (optional)

0005 v003 showed this speedup on baseline lineage; this tests whether it stacks on the top incumbent.
