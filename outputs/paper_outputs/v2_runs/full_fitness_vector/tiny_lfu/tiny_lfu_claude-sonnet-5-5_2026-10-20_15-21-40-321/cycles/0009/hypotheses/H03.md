# H03

Replace the hash-map-plus-linked-node layout with an index-addressed slab and open-addressing key table to lower per-op-time from the baseline.

## Parent

baseline

## Changes

Store nodes in a pre-allocated `Vec<Node>` slab sized to capacity, with a free-list for recycling. Replace the `HashMap<key, node pointer>` with a flat open-addressing table (linear probing, power-of-two size at least 2x capacity, load factor at most 0.5) that stores `(key, slab_index)` pairs. Hash the key once per operation with a cheap multiplicative hash and reuse the same 64-bit hash to derive the sketch row indexes, so each get or put hashes only once. Use tombstone-free backward-shift deletion on eviction. Keep the admission rule, the window and main LRU structure, and the sketch semantics identical to the baseline, so hit-rate should match 0.736 or better. The claim is that removing the separate map allocation and the double hashing lowers per-op-time. Do not widen Node beyond baseline size.

## Rationale (optional)

This is a different data structure, which is the open question in the cross-cycle notes. Earlier map-hasher wins suggest that map cost matters.
