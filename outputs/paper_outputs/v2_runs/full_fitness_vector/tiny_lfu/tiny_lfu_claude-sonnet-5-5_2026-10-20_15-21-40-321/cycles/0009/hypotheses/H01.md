# H01

Add a hill-climbing adaptive window size to the cycle 0004 v003 design to raise hit-rate on workload-a without extra per-op hashing.

## Parent

cycle/0004/v003

## Changes

In the TinyLFU cache struct, make the window capacity a runtime field instead of a constant, initialised to the current window size. Keep two counters, `period_hits` and `period_ops`. Every `10 * capacity` operations, compare the period's hit ratio with the previous period's. If it improved, keep moving the window in the current direction by max(1, capacity/100) slots. If it worsened, reverse direction. Clamp the window to [1, capacity/2]. When the window grows, let the main LRU tail demote naturally. When it shrinks, move the window's LRU entries into the main-admission path via the normal strict `incoming_freq > victim_freq` test. Do not touch the sketch, hasher or Node layout, so metadata-size stays at 24. The adaptive-window mechanism is untested so far. Two repeat runs are needed to separate its effect from noise.

## Rationale (optional)

Fixed window tuning, which is exhausted, is a different mechanism from online adaptation.
