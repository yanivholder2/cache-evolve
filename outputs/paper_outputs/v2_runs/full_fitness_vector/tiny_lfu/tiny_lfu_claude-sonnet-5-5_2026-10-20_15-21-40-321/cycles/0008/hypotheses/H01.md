# H01

Shrinking the sketch's counter table to fit in L1/L2 cache (halving width, keeping u8 counters) will reduce per-op-time on the incumbent without losing hit-rate on workload-a.

## Parent

cycle/0007/v001

## Changes

In the sketch module (the Count-Min style frequency sketch used by `increment`/`estimate` in the TinyLFU overlay), reduce the counter table length from its current size to half (round to a power of two, keep the index mask derived from `len - 1`). Keep the single-hash, u8 counters and conservative-update logic unchanged, and keep the aging/reset threshold scaled to the new width so the sample period is unchanged. Do not touch the Node layout, map hasher, or admission comparison (strict greater). Invariants: the admission decision API is unchanged; the Node stays 24 bytes. The experiment tests whether sketch cache footprint, not sketch accuracy, bounds put/get latency; if hit-rate falls more than 0.002, the claim is refuted.

## Rationale (optional)

Prior cycles showed width increases gave no hit-rate gain, so the sketch is likely oversized for workload-a, and cache locality is the lever that has paid off.
