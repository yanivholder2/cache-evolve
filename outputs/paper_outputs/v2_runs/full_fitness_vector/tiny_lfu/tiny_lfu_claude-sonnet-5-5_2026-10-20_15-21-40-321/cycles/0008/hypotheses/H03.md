# H03

Replacing the baseline's Node with a 24-byte compact layout (u32 links, key and packed flags) on the baseline, without segmentation, will cut metadata-size and per-op-time.

## Parent

baseline

## Changes

Starting from the baseline sources, change the LRU node struct so prev/next links are `u32` slab indices (with a sentinel value such as `u32::MAX` for none) instead of `usize`/Option, and store any per-entry flags in spare bits rather than separate fields, targeting `size_of::<Node>() == 24`. Update every place that reads or writes links (list push-front, unlink, move-to-front, eviction of the tail) to use the u32 indices and a helper converting to `usize` for slab indexing. Do not change the sketch, admission rule, window split, or hasher, and do not add segmentation. Invariants: identical eviction order and hit-rate to the baseline. Tests whether the compact Node alone reproduces the speed and size gain seen in cycle 0007 v003.

## Rationale (optional)

Cycle 0007 attributed v003's gain to the compact Node rather than segmentation; this isolates that on the baseline for a clean comparison.
