# H02

Adding an `#[inline]`/branch-hint fast path to `get` (hit check first, sketch increment deferred to a single combined step) on the second incumbent will reduce per-op-time without changing hit-rate.

## Parent

cycle/0005/v002

## Changes

In the `get` path of the overlay, restructure so the map lookup result is checked first. On a hit: if the node is already at the MRU head, skip relinking (extend the existing MRU short-circuit if only partly present) and perform the sketch increment through one inlined function that reuses the hash already computed for the lookup (no second hash computation). On a miss: return immediately after recording the sketch increment, with the miss branch marked cold (`#[cold]` helper). Mark small helpers (`index`, `increment`, `estimate`) `#[inline(always)]`. Replace bounds-checked indexing in the link-relink code with `get_unchecked` only if it can be wrapped safely with debug_asserts; otherwise leave it. Do not change sketch semantics, counter widths, admission rule, or Node size.

## Rationale (optional)

The open question is where `get` spends its time; this targets the non-sketch hot path (relink, duplicate hashing, branch layout) as the insights recommend.
