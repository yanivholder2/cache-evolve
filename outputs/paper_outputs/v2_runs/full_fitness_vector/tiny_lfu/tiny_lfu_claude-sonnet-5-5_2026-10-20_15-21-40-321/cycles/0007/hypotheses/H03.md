# H03

Using a segmented LRU (probation plus protected segment, promotion on second hit) instead of a single LRU list on the baseline will raise hit-rate on workload-a, at modest metadata cost.

## Parent

baseline

## Changes

Keep the sketch and the admission rule (candidate estimate strictly greater than the victim's estimate) as in the baseline. Split the main LRU into a probation list and a protected list, with the protected list capped at about 80% of the main capacity. New admitted entries go to the probation tail. A `get` hit on a probation entry moves it to the protected head; if protected overflows, demote its LRU entry to the probation head. The eviction victim is the probation LRU head (fall back to the protected tail if probation is empty). Track segment membership using one spare bit in an existing field (for example the top bit of the link index or a bool that fits in existing Node padding) so Node size stays at 24 bytes. Do not add a window or doorkeeper.

## Rationale (optional)

Every sketch-side hit-rate lever has failed; insights ask for a structurally different mechanism. Scan resistance in the main region is the untested one.
