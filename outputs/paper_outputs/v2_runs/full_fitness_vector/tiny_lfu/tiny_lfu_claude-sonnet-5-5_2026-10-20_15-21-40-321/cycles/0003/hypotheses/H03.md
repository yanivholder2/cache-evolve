# H03

Admit on `incoming_freq >= victim_freq` (instead of strict `>`) in the baseline's eviction path to raise hit-rate.

## Parent

baseline

## Changes

Start from the baseline source, with no hashing changes. In `put()`, in the admission test of the full-cache branch, change the comparison from `incoming_freq > victim_freq` to `incoming_freq >= victim_freq`. Do not change anything else: no aging, no new state, no sketch change. The `eviction_prefers_hot_items` unit test must still pass. If it does not, keep the strict comparison for the case where `victim_freq` is 0 and use `>=` only when both are nonzero.

## Rationale

On a stable-frequency trace, rejecting every tie keeps stale one-hit entries resident. Admitting on ties lets new keys displace entries that have not proven more popular. The baseline hit-rate (0.736) is close to v001's (0.741), so this is a clean single-variable test of tie policy. It starts from the baseline to diversify away from the v001 lineage.
