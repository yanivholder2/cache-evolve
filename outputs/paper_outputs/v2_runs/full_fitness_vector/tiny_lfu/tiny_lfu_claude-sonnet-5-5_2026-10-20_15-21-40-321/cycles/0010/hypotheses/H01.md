# H01

Porting the flat linear-probing slab table with a single per-op hash onto the cycle-0004 v003 lineage will cut get/put latency (per-op-time) without changing hit-rate.

## Parent

cycle/0004/v003

## Changes

Replace the pointer-based key->node map in the cache with a flat open-addressing (linear probing) table of u32 slab indices, with Nodes stored in a pre-allocated slab Vec and the LRU lists linked by slab indices (as done in cycle/0009/v003). Compute the key hash once per get/put and reuse it both for the table probe and to derive the sketch row indices (keep the cheap hasher/index derivation already in 0004/v003 where compatible). Use backward-shift deletion (or tombstones) on eviction. Preserve admission policy (strict-greater, LRU-head victim), window sizing, aging, and the public API exactly, so hit-rate must stay within 0.001.

## Rationale (optional)

The c0009 flat table was the largest latency win but was only tested on the baseline; this tests transfer to a stronger lineage.
