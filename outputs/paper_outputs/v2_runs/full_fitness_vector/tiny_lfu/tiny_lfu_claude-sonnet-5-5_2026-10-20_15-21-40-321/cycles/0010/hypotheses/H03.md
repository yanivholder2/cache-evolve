# H03

An adaptive hill-climbing window size (adjusting window vs main split by observed hit-rate each sample period) may raise hit-rate on workload-a, which was never tested.

## Parent

baseline

## Changes

Add to the cache a small adaptive controller: count hits and accesses over a sample period of about 10x capacity accesses. At each period end compare the period's hit ratio to the previous one; keep moving the window target in the same direction by a step of ~1% of capacity if it improved, otherwise reverse direction (step decays by 0.98 when the sign flips). Clamp window to [1, 80% of capacity]. Apply the new target lazily: in `put`, when window is over target, move the window LRU tail into main as normally; when under target, promote the main LRU tail into the window rather than evicting. Keep the sketch, admission rule, and API unchanged. Keep the code minimal so that the hit path adds only two counter increments, and check the metadata-size does not grow beyond a few u32 fields.

## Rationale (optional)

Static window sizes have all been flat on workload-a, but adaptivity was never evaluated because of an implementer failure in cycle 0009; the diff is deliberately small to avoid that.
