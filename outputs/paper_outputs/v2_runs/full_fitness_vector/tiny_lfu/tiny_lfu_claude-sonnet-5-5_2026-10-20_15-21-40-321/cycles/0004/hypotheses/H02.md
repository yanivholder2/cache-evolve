# H02

Adding a one-bit Bloom-filter doorkeeper in front of the sketch will raise hit-rate by keeping one-hit wonders out of the counters and breaking low-frequency ties.

## Parent

cycle/0002/v001

## Changes

In the cache source file of the parent, add a `door: Vec<u64>` bitset (size = sketch width bits, power of two) owned by the sketch (heap, not in `Node` or the cache struct's inline size beyond one Vec header; if that grows the struct, box it inside `CountMinSketch`). In the sketch `increment(h)`: derive a bit position from `h` (e.g. `h & (door_bits - 1)`); if the bit is unset, set it and return without touching counters; if set, do the normal conservative-update increment. In `estimate(h)`: return min-counter estimate plus 1 if the door bit is set. Do NOT reset or age the doorkeeper or counters (aging failed on workload-a; its frequencies are stable). Leave admission as strict `incoming_freq > victim_freq` and victim as LRU head. Preserve all other behaviour.

## Rationale (optional)

Cycles 0001-0003 ruled out aging, windows, victim sampling and tie-admission. The open question is a new frequency signal; the doorkeeper changes sketch accuracy without touching the admission comparison.
