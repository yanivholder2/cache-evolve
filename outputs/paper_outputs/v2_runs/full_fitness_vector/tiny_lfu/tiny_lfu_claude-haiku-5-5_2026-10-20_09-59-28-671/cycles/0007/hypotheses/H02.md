# H02

Admitting the candidate on a frequency tie at the admission gate will raise hit-rate on workload-a at size 2048 without changing metadata-size or the get path.

## Parent

cycle/0005/v001

## Changes

In the admission comparison inside the put path (the code that compares the candidate's sketch estimate against the eviction victim's estimate), change the tie case so that when the two estimates are equal the candidate is admitted and the victim is evicted. Keep the strict-greater branch behaviour identical. Do not change the sketch indexing, counter widths, aging, or the seed tables. Do not touch the split unlink/promotion helper introduced in v001, which must remain as the parent has it. No new struct fields; the change is a comparison operator and the branch it selects.

## Rationale (optional)

No cycle so far has tested the tie-break. Every admission-side change tried so far (doorkeeper, window, recency rotation, shorter aging) altered the estimates or the candidate pool; this one changes only the decision on equal estimates, which is common on a skewed trace where many cold keys sit at the same low count. The claim is refuted if hit-rate is unchanged or drops, and it is consistent with the existing finding that the frequency gate already does the protective work by making the tie case the place where recency could matter.
