# H03

Laying out the frequency sketch counters so that all rows for one key fall in the same 64-byte block will lower per-op-time on both get and put while keeping hit-rate within 0.001 of the baseline's 0.736 and metadata-size at 48 or below (per-op-time).

## Parent

baseline

## Changes

Change the `CountMinSketch` counter storage from one array per row to a single flat array of `u8` or `u16` counters, grouped into blocks of 64 bytes. For each key, use the single precomputed hash to select one block, then use the per-row seed to choose a counter offset inside that block for each row, so that every row access for one key touches the same cache line. Keep the sketch's total counter count and width equal to the baseline's, so the reported heap size (65536 bytes at cap=1024) is unchanged.

Implement this inside the sketch type only: change the increment and estimate methods to index the block-and-offset layout, and keep the public method signatures and their delegation unchanged. Do not change the admission comparison, the aging or halving step (it should still walk every counter), the eviction order, the LRU relinks, or the `Node` and `TinyLfuCache` fields.

Because block selection changes which counters collide, the hit rate will move slightly even though the admission logic is unchanged. Record the hit rate and the per-op time for at least three runs on workload-a at size 2048. Accept only if hit-rate stays at or above 0.735 and both get and put p50 fall below the baseline's values. If hit-rate drops below 0.735, reject the variant and record the collision change as the cause.

## Rationale (optional)

Every cycle so far has changed sketch indexing or sketch storage only on a per-row basis, and per-row work has been the recurring cost of index fidelity. Cycle 0005 showed that the public per-row path costs most of the speed. A block layout keeps the per-row variation but puts all rows of a key in one cache line, which targets the memory cost directly rather than the arithmetic. It is an exploratory direction from the baseline because none of the incumbents has tested the storage layout of the counters.
