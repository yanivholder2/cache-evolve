# H02

Making the single-hash sketch helpers derive the same counter indices as the public sketch methods recovers cycle/0002/v001's lost hit rate while keeping its faster put path.

## Parent

cycle/0002/v001

## Changes

Keep v001's hoisting of the key hash out of `put()` and its reuse of that hash for the admission check and the sketch increment. Change only the index derivation inside the precomputed-hash helpers so it matches the public sketch methods:

- Find the public estimate and increment methods on the count-min sketch and the per-row index function they use (seed per row, mask or modulo by the sketch width). The precomputed-hash helpers must produce identical row indices for the same key, including any per-row seed or rotation applied in the public path.
- If the public path rehashes the key once per row with a distinct seed, derive each row index from the single base hash using the same seed scheme, not a shared index. Do not change the counter width, the table size, or the aging step.
- Keep the `get()` path using the shared helpers, since v001 showed the get path also got faster.
- Do not change admission order or eviction. The target is that the hashed `put()` path yields the same admission decisions as baseline on the same trace, so hit rate returns to the baseline level.

Before editing, compare the two index functions in the overlay side by side and note any difference in the variant's insight.

## Rationale (optional)

v001 was the only Winner whose hit rate fell below its parent's intended behaviour (0.7349 against a hypothesis that predicted no change). Its insight says the hashed helper probably diverged from the public lookup, and it names index equivalence as the next check. This hypothesis resolves that check and keeps v001's per-op gain, which is the best per-op-time on the board (54 ns).
