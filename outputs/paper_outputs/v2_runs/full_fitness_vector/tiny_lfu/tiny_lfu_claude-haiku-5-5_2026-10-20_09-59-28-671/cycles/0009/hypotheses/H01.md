# H01

Reusing the candidate's already-read sketch counters to decide the conservative update removes the extra per-increment row pass and recovers per-op time while keeping the hit-rate gain on workload-a at size 2048.

## Parent

cycle/0008/v001

## Changes

Keep the conservative-update rule from cycle/0008/v001 unchanged: on each frequency increment, only the counters in the key's rows whose value equals the minimum across rows are incremented. Remove the separate read-all-rows pass that the parent performs before its conditional write. Instead, compute the per-row counter values and their minimum in a single loop over the key's rows, and write back only the rows that match that minimum in the same loop, using the values already loaded.

Where the admission check already reads the candidate's row counters (the frequency comparison in the put path), reuse those loaded values for the increment when the key is the same, so the put path does not re-read the rows it just read. Do not change the row count, the column count, the per-row index derivation, the seeds, or the counter type, so the counter indices and the minimum-across-rows estimate stay identical to the parent.

Do not add struct fields or per-instance tables; any scratch values should be local to the function. Preserve the eviction order and the admission decisions exactly. The expected result is hit-rate equal to cycle/0008/v001 (about 0.742) and get and put p50 below that parent's 113 ns and 148 ns.
