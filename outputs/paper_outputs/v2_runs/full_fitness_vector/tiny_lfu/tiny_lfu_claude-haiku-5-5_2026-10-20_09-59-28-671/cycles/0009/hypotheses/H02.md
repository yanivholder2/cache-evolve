# H02

Porting the get-path flag-accessor inlining onto the put-split variant should keep its get-side gain without reintroducing the put-side regression seen when that inlining was applied alone.

## Parent

cycle/0005/v001

## Changes

Start from cycle/0005/v001, which splits the put-side unlink and promotion path into a separate helper. Apply only the get-path part of cycle/0004/v002: inline the packed protected-flag accessor calls in `touch()` and in the promotion step that the get hit path reaches, so they read the flag bits directly instead of calling the accessor functions.

Do not inline the accessors inside `unlink()` or in the put-side helper that cycle/0005/v001 introduced. Those keep calling the accessor functions, so the put path matches the parent's code. Keep the flag layout, the node fields, and the eviction order unchanged. Do not change the sketch, the admission gate, or the segment logic.

Confirm against the parent source which call sites are on the get hit path and which are reached from put, and leave any site that put can reach as in the parent. The expected result is hit-rate and metadata-size equal to cycle/0005/v001 (0.7379, 32 bytes), with get p50 below that parent's 93 ns and put p50 not worse than its value. Repeat each timing run at least three times and report the spread, since earlier single-run put results were not reliable.
