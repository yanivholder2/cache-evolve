# H02

Narrowing the frequency-sketch counters to 8-bit saturating values and doubling the columns per row, within the same sketch byte budget, raises hit-rate by reducing count-min collisions while keeping the per-entry metadata at 32 bytes.

## Parent

cycle/0006/v002

## Changes

Apply the cycle 0009 v003 counter-width trade to this parent's sketch, and nothing else:

- Change the sketch counter storage from its current width to `u8`, with a saturating increment capped at 15 (the cap that cycle 0009 v003 used).
- Double the column count per row so the total sketch allocation stays at 65536 bytes, matching the reported `CountMinSketch (heap, cap=1024)` figure. Recompute the column modulus and the column index derivation from the per-row seed table to match the new width.
- Keep the conservative-update and the aging logic of this parent as they are, so that only the counter width and column count change.
- Keep `Node<u64,u64>` at 32 bytes and `TinyLfuCache<u64,u64>` at its parent size. Cycle 0009 v003 grew `Node` to 48 bytes; this variant must not, and if the node layout changes, the variant fails the metadata check and should be rejected rather than adjusted.
- Do not change the eviction order, the segment sizes, or the admission threshold.

Expected signal: hit-rate above 0.7379 on workload-a at size 2048, with metadata-size still 32. A hit-rate that does not move, or that moves only with a metadata regression, refutes the claim. Record the sketch row and column counts in insight.md, since cycle 0009 could not confirm them.
