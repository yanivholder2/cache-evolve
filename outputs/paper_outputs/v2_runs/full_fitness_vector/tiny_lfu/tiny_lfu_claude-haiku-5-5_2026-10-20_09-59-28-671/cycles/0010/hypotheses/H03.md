# H03

Skipping the list relink when a hit lands on a node that is already at the MRU end of its segment lowers get-path p50 per-op-time with hit-rate unchanged.

## Parent

baseline

## Changes

Make the get hit path in the segmented LRU do less pointer work, without changing which entry is evicted:

- In the get routine's hit branch, check whether the hit node is already the head (MRU) of its current list before calling `touch()` or the promotion step. If it is, return the value directly and skip the unlink and relink.
- Where the hit node is in probation and must move to protected, keep the existing promotion path unchanged. Only the already-MRU short-circuit is new.
- Fuse the hash computation: derive the key hash once in the get routine and pass it to the sketch increment, rather than hashing again inside the increment. The increment still runs on every access exactly as before, so admission counts are unchanged.
- Do not change the eviction routine, the protected capacity, the sketch width or row count, or the metadata layout.

Invariants: hit-rate and metadata-size must match the baseline exactly on workload-a at size 2048, because the eviction order is unchanged. Only per-op-time may move. Measure get p50 over at least three repeated runs. Cycle 0009 showed single-run timing shifts on paths a change did not touch, so do not accept a gain from one run.
