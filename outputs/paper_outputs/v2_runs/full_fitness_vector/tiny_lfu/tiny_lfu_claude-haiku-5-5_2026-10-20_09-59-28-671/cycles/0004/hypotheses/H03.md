# H03

Adding a small LRU admission window of about 1% of capacity in front of the TinyLFU gate will raise hit rate on recency-heavy accesses that the frequency gate currently rejects, targeting hit-rate.

## Parent

baseline

## Changes

The current admission gate only compares the frequency estimate of a new key against the eviction victim in the main cache, so a brand-new key that is hot in the short term can be rejected before it accumulates frequency. This variant adds a W-TinyLFU-style admission window, a small LRU region that accepts every new key first.

Changes, all within the cache's admission and resident-list code:
- Add a window LRU sized to roughly 1% of total capacity (at least one slot). New keys are inserted at the MRU end of the window rather than being run through the frequency gate directly.
- When the window is full, its LRU tail is the candidate. Only that candidate goes through the existing frequency gate against the main cache's victim. If the candidate's estimate is higher, it is admitted to the main cache (probation). Otherwise it is evicted.
- A hit in the window moves the key to the window's MRU end and does not change the sketch's behaviour beyond the existing per-access increment.
- Keep the main cache's probation/protected split, the sketch's indexing, and aging exactly as in the baseline.

Invariants to preserve:
- Total capacity accounting must still count window slots toward the cache's capacity, so the cache never holds more entries than the parent.
- The get and put return values and eviction callbacks, if any, must keep their existing signatures.
- Do not change the sketch width, depth, or aging period in this variant.

Expected metadata cost: one extra list anchor pair and one link per entry in the window. Report the metadata-size delta honestly. The baseline source was not available during hypothesis authoring, so confirm the resident-list structure and capacity bookkeeping before editing.
