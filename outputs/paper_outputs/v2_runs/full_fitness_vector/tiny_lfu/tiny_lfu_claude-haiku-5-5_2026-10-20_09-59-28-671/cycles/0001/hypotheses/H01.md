# H01

Rotating the rejected admission victim to the MRU tail instead of leaving it at the LRU head raises hit rate on the lirs workload-a trace by stopping one stale resident from blocking every future admission.

## Parent

baseline

## Changes

Modify the full-cache branch of `TinyLfuCache::put()` in `src/tiny_lfu/mod.rs`. Currently, when `incoming_freq <= victim_freq`, the function does nothing, so the same head node stays the victim on every subsequent miss. Change the `else` path so that, on rejection, the victim is moved to the MRU tail with `self.unlink(victim_idx); self.push_back(victim_idx);`. The newcomer is still dropped, and `map`, `nodes`, and `capacity` are untouched, so the resident count and the key-to-index mapping stay as they are. Do not rotate on admission (the existing replacement branch is unchanged). Do not touch `get()`, the sketch, or `CountMinSketch` logic. Preserve the `expect` on `head` for the full-cache case. The head is always valid because the cache is full and non-empty when capacity is greater than zero.

Expected effect: victims rotate through the resident set instead of pinning a single LRU slot, so frequency estimates for other residents get a chance to win admission. The per-op cost of a rejected put rises by one unlink and one push_back, but no new fields or allocations are added.
