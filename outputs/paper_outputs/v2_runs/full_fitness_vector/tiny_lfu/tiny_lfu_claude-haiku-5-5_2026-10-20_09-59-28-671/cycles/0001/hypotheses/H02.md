# H02

Skipping the unlink and push_back on a get hit when the node is already the MRU tail cuts get p50 latency without a measurable hit-rate loss on the lirs workload-a trace.

## Parent

baseline

## Changes

Modify `TinyLfuCache::get()` in `src/tiny_lfu/mod.rs`. After the map lookup yields `idx`, add an early return when `Some(idx) == self.tail`: skip the `self.unlink(idx)` and `self.push_back(idx)` calls and return `Some(&self.nodes[idx].value)` directly. The sketch increment at the top of `get()` must still run, so frequency tracking is unchanged. Apply the same guard in the update branch of `put()` (the `if let Some(&idx) = self.map.get(&key)` block): if `idx` is already the tail, skip the unlink/push_back pair and only overwrite `value`. Do not change the replacement branch, the sketch, or `Node` layout. Keep the invariant that a hit always returns the value stored at `idx`.

Expected effect: repeated hits on the most recently used key, which are common in skewed traces, avoid four pointer writes and the associated branch work. Eviction order is unchanged for every access except those that would have been a no-op move, so hit rate should match baseline within noise. The target dimension is per-op-time (get p50 and put p50).
