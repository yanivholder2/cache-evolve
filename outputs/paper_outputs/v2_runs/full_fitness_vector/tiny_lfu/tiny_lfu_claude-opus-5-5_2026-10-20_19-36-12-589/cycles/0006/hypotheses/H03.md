# H03

Putting a 10% LRU admission window ahead of the TinyLFU-guarded main LRU, with a duel that does no extra re-hashing, will raise hit-rate above 0.7423 on workload-a by keeping short recency bursts that the strict frequency duel currently rejects.

## Parent

cycle/0005/v002

## Changes

Keep v002's sketch (u16, 2× width, conservative update) and its single-count-per-access fix (`last_miss_hash`/`last_miss_valid`). Also fold in cycle/0005/v001's fused `increment_hash`/`estimate_hash` (four explicit loads in registers, `get_unchecked`), since it leaves behaviour identical.

Split residents into two LRU lists over the same `nodes` arena: a window list (`w_head`, `w_tail`, `w_len`) and a main list (`m_head`, `m_tail`, `m_len`). Set `window_cap = max(1, capacity / 10)` and `main_cap = capacity - window_cap`. Record each node's region in the top bit of its `next` link (`REGION_BIT = 1 << 31`, link value masked with `!REGION_BIT`), as cycle/0005/v003 did, so `Node<u64,u64>` stays 24 bytes. `capacity` must then be `< 2^31`; reject larger in `try_new`.

- `get` hit: relink within the node's own list (read the region bit to choose head/tail fields). No promotion between regions on hit.
- `put` on an existing key: update value, relink within its list.
- `put` new key: always insert at the window MRU end (the sketch increment/estimate path from v002 stays as is to produce `incoming_freq`, but it is now used only for the overflow duel below). If `w_len > window_cap` after insertion, take the window LRU node `c` as the candidate:
  - If `m_len < main_cap`, move `c` to the main MRU end (flip its region bit).
  - Otherwise duel `c` against the main LRU head `v`: compute `estimate_hash(key_hash(&c.key))` and `estimate_hash(key_hash(&v.key))` — exactly two `key_hash` calls on the overflow path, no more. If `freq(c) > freq(v)`, evict `v` (remove from `map`, unlink) and move `c` to main MRU; else evict `c`. Ties go to the resident `v`, as today.
  - Reuse the evicted node's slot for the new arrival so `nodes` never exceeds `capacity`: allocate the incoming node into the freed index (insert into `map` after the eviction is decided), or while still filling, push a new node.
- While the cache is not yet full, fill the window first, then overflow into main without duels.

Update the in-file behavioural tests only if they encode the old no-window admission order at capacity 2 (with `window_cap = 1`); prefer keeping their assertions by noting the window holds the newest key. Add one test showing a burst key re-referenced while in the window survives a scan of one-hit keys.

## Rationale (optional)

The ~1% window in c5 was judged too small to hold recency bursts and paid for repeated re-hashing; insights explicitly leave a 5–20% window as the untested open question. Sketch accuracy and duel inputs are now exhausted, so a structural admission change is the remaining hit-rate lever. Starting from v002 gives the best hit rate so far (0.7423) as the bar to beat.
