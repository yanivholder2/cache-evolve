# H01

Replacing the doubly-linked LRU resident list with a CLOCK ring that marks hits with a reference bit will cut get per-op-time and shrink per-entry metadata from 24 to 16 bytes while keeping hit-rate within noise.

## Parent

cycle/0005/v001

## Changes

Remove `prev`/`next` from `Node` so `Node<u64,u64>` is just `{ key, value }` (16 bytes); update the in-file `node_is_compact` test to assert 16. Delete `unlink`, `push_back`, `head`, `tail`.

Add to `TinyLfuCache` a reference-bit vector `refbits: Vec<u64>` (one bit per slot, `ceil(capacity/64)` words) and a `hand: u32` clock pointer. Nodes stay in `nodes: Vec<Node>` indexed by the `u32` stored in `map`, as now.

- `get` hit: after `increment_only`, set `refbits[idx>>6] |= 1 << (idx & 63)` and return the value. No relinking, no writes to `nodes`.
- `put` on an existing key: overwrite the value and set the ref bit (same as a hit).
- `put` while not full: push the node, insert into `map`, leave its ref bit **clear** (a new entry has not been re-referenced yet; this mirrors it being at the MRU end only once).
- `put` while full: select the victim with the clock sweep — starting at `hand`, while the slot's ref bit is set, clear it and advance `hand = (hand + 1) % capacity`; the first slot with a clear bit is the victim. Do not advance `hand` past the victim yet. Run the existing duel unchanged (`incoming_freq > victim_freq`, victim estimate via `estimate_hash(key_hash(&victim.key))`). If the newcomer wins: remove the victim key from `map`, overwrite the slot in place with the new key/value, insert into `map`, leave its ref bit clear, and advance `hand` by one. If the newcomer loses: leave the victim and `hand` where they are (the victim stays the next candidate, matching LRU where a rejected newcomer leaves the LRU head unchanged).
- Bound the sweep: it terminates within at most `capacity + 1` steps because each step clears a bit; no extra guard needed, but add a `debug_assert!`.

Keep the sketch (u16, 2× width, fused conservative update, `increment_only` on `get`) and `key_hash` exactly as in the parent. Keep the existing behavioural tests passing (`eviction_prefers_hot_items`, `low_frequency_new_item_is_rejected`, `update_promotes_existing_item_and_admits_hot_arrivals`); if any depends on strict LRU ordering for capacity 2, verify the CLOCK victim choice matches and adjust only test commentary, not assertions, unless the assertion is purely LRU-order-specific.

## Rationale (optional)

Cross-cycle insights say per-op cost likely now sits outside the sketch, including relinking on every hit, and that plain LRU is the structure to beat cheaply. CLOCK turns a hit's three-node pointer rewrite into a single bit-OR on a tiny, cache-resident bitmap, and drops 8 bytes per node. LRU-end victims already have near-equal estimates (c2), so CLOCK's coarser recency order should barely move admission outcomes.
