# H02

Replacing the std `HashMap<K, u32>` with an in-house open-addressing index table probed by the existing `key_hash` will lower get and put per-op-time by computing one hash per operation for both lookup and sketch, with hit-rate unchanged bit for bit.

cycle/0005/v001

## Changes

Remove `map: HashMap<K, u32, FxBuild>` (and the now-unused `FxBuild` alias if nothing else uses it; keep `FxLikeHasher` since `key_hash` uses it). Add an index table:

- `slots: Vec<u32>` of length `table_size = (capacity * 2).next_power_of_two()` (load factor ≤ 0.5), initialised to `NIL`; `mask = table_size - 1`.
- Each slot holds a node index; the key itself lives only in `nodes[idx].key` (no second copy of `K` as the std map stores).
- `find(h, key) -> Option<(slot, idx)>`: linear probe from `(h >> 32) as usize & mask` (use the high half so the slot bits are not the same bits as sketch `h1`), stop at `NIL`; compare `nodes[idx].key == *key`.
- `insert_slot(h, idx)`: probe to the first `NIL` and store `idx`.
- `remove_slot(slot)`: backward-shift deletion (Knuth algorithm R): walk forward from `slot`, moving any entry whose home position does not lie cyclically in `(empty, current]` back into the hole, until reaching `NIL`. Computing an entry's home needs its hash: recompute `key_hash(&nodes[idx].key)` for each shifted entry (runs are short at load 0.5).

Rewrite the call sites to compute `let h = key_hash(key)` once and reuse it:
- `get`: `self.sketch.increment_only(h); let (_, idx) = self.find(h, key)?;` then relink as today.
- `put`: `h` feeds `increment_hash(h)` and `find(h, &key)`; on a cold insert use `insert_slot(h, idx)`; on eviction, compute `vh = key_hash(&victim.key)` once and use it both for `estimate_hash(vh)` and to locate the victim's slot (`find(vh, &victim.key)`), then `remove_slot` it, overwrite the node, and `insert_slot(h, victim_idx)`. This also removes the `victim_key.clone()`.

Do not change the LRU list, `Node` layout (stays 24 bytes), the sketch, or the duel rule. Add in-file unit tests: insert/remove churn of > capacity distinct keys keeps every resident findable and every evicted key absent; and a forced-collision test (many keys sharing home slot bits) exercising backward-shift deletion.

## Rationale (optional)

Today each `get` hashes the key twice (Fx inside std `HashMap` plus `key_hash` for the sketch), and an evicting `put` does lookup + remove + insert in the std map plus a key clone. The sketch is exhausted as a lever; this targets the open question of whether the remaining per-op cost is in map lookup and hashing. A `u32`-slot table also takes far less memory than the std map's `(K, u32)` buckets plus control bytes.
