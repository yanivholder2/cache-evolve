# H01

Port cycle/0004/v001's fused single-pass, register-held conservative-update increment onto v003's `u16`/2×-width sketch to lower per-op-time while keeping v003's hit rate.

## Parent

cycle/0004/v003

## Changes

All edits are in `src/tiny_lfu/mod.rs`, inside `CountMinSketch`. Keep the `u16` counter storage (`counts: Vec<u16>`), `SKETCH_WIDTH_FACTOR = 8`, `MAX_COUNT = u16::MAX as u32` and the `heap_bytes()` formula exactly as in v003, so hit rate and metadata stay the same.

1. Add `const _: () = assert!(SKETCH_DEPTH == 4);`. Drop the `depth` field: use `SKETCH_DEPTH` directly in `new`, `heap_bytes` and `estimate_hash`, and remove the dead `if self.depth == 0` branch.
2. Add `#[inline(always)] fn indices(&self, h: u64) -> [usize; 4]`. It computes `h1 = h as u32` and `h2 = ((h >> 32) as u32) | 1`, then calls `index(h1, h2, r)` for r = 0..3. Include a `debug_assert!(i < counts.len())` for each index, as v001 does.
3. Rewrite `increment_hash` as one unrolled pass, like v001's:
   - Load `c0..c3` once each with `get_unchecked`, widening each to `u32`.
   - Compute `min = c0.min(c1).min(c2.min(c3))` and `inc = (min < MAX_COUNT) as u32`.
   - Write each counter back from its local as `(ci + (((ci == min) as u32) & inc)) as u16`, using `get_unchecked_mut`.
   - Return `min + inc`.
   - Keep the SAFETY comment explaining why the indices are in bounds, and why the rows are disjoint so the four indices never alias.
4. Add `increment_only(&mut self, h)`, the same update with no return value, and call it from `TinyLfuCache::get`. `put` keeps calling `increment_hash`, because it uses the returned estimate.
5. Unroll `estimate_hash` the same way: four unchecked loads and a branch-free min.

Don't change `get`/`put` control flow, the strict `>` duel, the hashing, or `Node`. Existing unit tests must still pass. Update `conservative_update_bumps_only_minimum_counters` only if it relied on the removed `depth` field.

## Rationale (optional)

Cycle 0004 left this merge as its top open question. v001's latency gain has a clear cause in the code (no second reload pass, no bounds checks). v003's hit-rate gain comes only from sketch geometry. The two changes are orthogonal, so the merged variant should match v003 on hit rate and v001 on per-op cost.
