# H02

Stop counting a newcomer twice when a `get` miss is followed by a `put` of the same key, so that the TinyLFU duel compares newcomer and victim on equal terms and hit rate rises.

## Parent

cycle/0004/v003

## Changes

All edits are in `src/tiny_lfu/mod.rs`.

Today a simulator access to a key that isn't cached runs `get(key)`, which misses and calls `sketch.increment_hash`, then `put(key, v)`, which calls `sketch.increment_hash` again. So each miss adds +2 to the newcomer's counters, while each hit on a resident adds only +1. That inflates `incoming_freq` against `victim_freq` and lets cold one-hit keys win duels. Cycle 0003 found that tilting ties toward newcomers (`>=`) hurt, which suggests newcomers are already favoured too much.

1. Add a field `last_miss_hash: u64` to `TinyLfuCache`, initialised to `0`, and a `last_miss_valid: bool`, initialised to `false`.
2. In `get`:
   - Compute `let h = key_hash(key);` and call `self.sketch.increment_hash(h)` as now.
   - On a miss, set `last_miss_hash = h` and `last_miss_valid = true`.
   - On a hit, set `last_miss_valid = false`.
3. In `put`:
   - Compute `h` as now.
   - If `last_miss_valid && h == last_miss_hash`, this access was already counted. Set `incoming_freq = self.sketch.estimate_hash(h)` and don't increment.
   - Otherwise call `increment_hash(h)` as now.
   - In both cases, set `last_miss_valid = false` before the rest of `put` runs.
4. Leave everything else unchanged: the existing-key update path, the fill path, the strict `incoming_freq > victim_freq` duel, the `u16` sketch geometry, and `Node` (keep it 24 bytes; the new fields are on the cache struct, not per entry).

Add a unit test checking that `get(&k)` (miss) followed by `put(k, v)` leaves `estimate_hash(key_hash(&k)) == 1`. Existing tests must still pass. In particular, `eviction_prefers_hot_items` and `update_promotes_existing_item_and_admits_hot_arrivals` use repeated `get(&3)` before `put(3, …)`. With this change, key 3's estimate is 2 rather than 3, which still beats key 2's 1, so those tests should still hold. Confirm this; don't weaken the tests.

## Rationale (optional)

Sketch accuracy has stopped giving gains. This is an accounting bias in how accesses are counted, separate from collision noise. It costs one compare per `put` and no per-entry memory. If it works, the duel tells one-hit wonders and resident warm keys apart better, which matches workload-a's preference for stable frequency.
