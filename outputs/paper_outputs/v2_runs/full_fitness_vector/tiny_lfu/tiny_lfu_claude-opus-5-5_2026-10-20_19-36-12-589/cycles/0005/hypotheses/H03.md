# H03

Add a tiny (~1% of capacity) plain-LRU admission window ahead of the TinyLFU duel, with no SLRU and region tags packed into existing link bits, to raise hit rate on recency bursts without growing per-entry metadata.

## Parent

cycle/0004/v001

## Changes

All edits are in `src/tiny_lfu/mod.rs`.

1. **Region tag without growing `Node`.**
   - Reserve the top bit of `Node.next` as the region flag: 1 means window, 0 means main.
   - Add helpers `link_next(i)`, which masks the bit off; `set_next(i, v)`, which keeps the bit; `is_window(i)`; and `set_window(i, bool)`.
   - Change `NIL` to `0x7FFF_FFFF` so it fits in 31 bits, and tighten the capacity check in `try_new` to `capacity < NIL as usize`.
   - `Node<u64,u64>` must stay 24 bytes. Keep the `node_is_compact` test.
2. **Two lists over the same `nodes` arena.**
   - Replace `head`/`tail` with `win_head`, `win_tail`, `main_head` and `main_tail`.
   - Add counters `win_len` and `win_cap = max(1, capacity / 100)`.
   - Generalise `unlink` and `push_back` to take a list selector, which the code can derive from `is_window(idx)`.
3. **`get`:**
   - Do the same sketch increment as v001 (`increment_only`).
   - On a hit, move the node to the tail of the list it is in: window stays window, main stays main. Don't add promotion logic on hit.
4. **`put` for a new key:**
   - The key always enters the window tail. If the cache isn't full, push a new node; otherwise reuse a slot, as described below.
   - Then, if `win_len > win_cap`, take the window head as the candidate.
   - If main still has room (fewer than `capacity - win_cap` main entries), move the candidate to main directly.
   - Otherwise duel the candidate against `main_head` using the strict `>`, with estimates from `estimate_hash`.
     - If the candidate wins, evict `main_head` and move the candidate to the main tail.
     - If it loses, evict the candidate.
   - Either way, the evicted node's slot is the one reused for the next insert. Implement this by evicting before inserting when the cache is full, so `nodes.len()` never exceeds `capacity`.
   - Keep the `put` update path for existing keys as is: update the value and move the node to the tail of its own list.
5. Keep v001's fused sketch, its hashing and its `u32` counters unchanged. This isolates the effect of the window.

Update `eviction_prefers_hot_items` and `low_frequency_new_item_is_rejected` only if needed for capacity 2: `win_cap = 1` leaves a 1-entry main. Prefer behaviour that keeps their assertions true. If an assertion can't hold under window semantics, explain the change in a comment. Add a test that a key put twice in a row while in the window stays resident.

## Rationale (optional)

Cycle 0001's W-TinyLFU lost mainly on cost: per-list arrays, region tags in separate storage, and SLRU relinks on every hit. Here there are no extra per-entry bytes and no promotion relinks, and the duel moves to window overflow. That gives brand-new keys a short grace period instead of an immediate strict duel against the LRU head. This tests the cross-cycle open question of whether the remaining hit-rate gap is in policy structure rather than sketch accuracy.
