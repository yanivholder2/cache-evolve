# H01

Splitting the single LRU resident set into a small admission window plus a segmented-LRU main region (W-TinyLFU) will raise hit rate on the LIRS workload-a trace at capacity 2048 above the baseline's 0.7362.

## Parent

baseline

## Changes

Rework `TinyLfuCache` in `src/tiny_lfu/mod.rs` so the resident set is three
intrusive doubly-linked lists that all live in the existing `nodes` arena:

- **window**: an LRU of size `window_cap = max(1, capacity / 100)`.
- **probation**: the main-region entry segment.
- **protected**: an LRU of at most `protected_cap = (capacity - window_cap) * 80 / 100`
  entries (at least 1 when `capacity - window_cap >= 2`; when capacity is too
  small for the split, e.g. capacity 1 or 2, set `window_cap = 0` or
  `protected_cap = 0` so the cache still holds exactly `capacity` keys).

Add a `region: u8` tag (Window / Probation / Protected) to `Node`, and replace
`head`/`tail` with one `(head, tail, len)` triple per list. Generalise
`unlink(idx)` and `push_back(idx)` to take the list as a parameter (or read the
region tag from the node), and keep the per-list `len` counters updated.

Movement rules:

- `get` hit: still `sketch.increment` first. Window node → move to window MRU.
  Probation node → move to protected MRU; if protected now exceeds
  `protected_cap`, demote protected LRU to probation MRU. Protected node → move
  to protected MRU.
- `put` on an existing key: update the value, then apply the same movement as a
  `get` hit.
- `put` on a new key: always insert at window MRU (push a new arena node while
  `nodes.len() < capacity`). If the window now exceeds `window_cap`, take the
  window LRU as the *candidate*. If the main region (probation + protected)
  has spare room (`total resident < capacity` before this insert), just move
  the candidate to probation MRU. Otherwise run the admission contest between
  the candidate and the probation LRU (the *victim*; if probation is empty,
  use protected LRU): if `estimate(candidate) > estimate(victim)` evict the
  victim (remove from `map`, unlink) and move the candidate into probation
  MRU; else evict the candidate. The freed arena slot is the one the new key
  ends up in — easiest is to evict first and reuse the evicted node's slot for
  the incoming key, mirroring the baseline's slot-reuse (no free list needed:
  at steady state the incoming key always reuses exactly one evicted slot).

Invariants to preserve: `map.len() <= capacity`, every map entry points to a
node that is on exactly one list, list lengths sum to `map.len()`, and
`get`/`put` signatures and the `framework::Cache` impl are unchanged. Leave
`CountMinSketch` untouched so the hit-rate delta is attributable to the
movement policy alone. Update the in-file unit tests only if a test's
expectation is specific to plain-LRU admission (with capacity 2 the window
split must degrade gracefully so existing tests still pass if possible).

## Rationale (optional)

The baseline admits newcomers only by beating the LRU victim on frequency, so
fresh-but-bursty keys are rejected outright and never get a chance to build
frequency. A recency window absorbs bursts, and SLRU keeps keys that proved
reuse protected from the probation victim pool — the standard Caffeine design.
