# H03

Hashing each key once per operation with a fast 64-bit mixer and deriving all four sketch row indices from that single hash in a flattened counter array will cut get p50 per-op time well below the baseline's 132 ns.

## Parent

baseline

## Changes

In `src/tiny_lfu/mod.rs`, leave the resident-set movement (promotion,
admission contest, slot reuse) unchanged and rework only how the sketch is
addressed:

- Flatten `CountMinSketch.counts: Vec<Vec<u32>>` into a single
  `Vec<u32>` of length `depth * width`; row `r` occupies
  `[r * width, (r + 1) * width)`. `heap_bytes()` stays
  `depth * width * size_of::<u32>()`.
- Replace `position(key, seed)` (which builds a fresh SipHash
  `DefaultHasher` per row — 4 SipHash runs per increment and 4 more per
  estimate) with a `fn key_hash<K: Hash>(key: &K) -> u64` that hashes the key
  once using a cheap hasher (e.g. an inline FxHash-style
  `Hasher` implementation: `state = (state.rotate_left(5) ^ word).wrapping_mul(0x517cc1b727220a95)`),
  followed by a finaliser mix (splitmix64/murmur3 fmix64) for avalanche.
- Derive row indices via double hashing: `h1 = h as u32`, `h2 = (h >> 32) as u32 | 1`;
  index for row `r` is `((h1.wrapping_add(r as u32 * h2)) as usize) & (width - 1)`.
- Change `increment` and `estimate` to take the precomputed `u64` hash
  (`increment_hash(h)`, `estimate_hash(h)`), and in `TinyLfuCache::get`/`put`
  compute `key_hash(key)` once and reuse it for both the increment and the
  incoming-key estimate in the admission contest. The victim still needs its
  own `key_hash` call.
- Optionally (same change, perf-only) make `TinyLfuCache.map` use the same
  fast hasher via `HashMap<K, usize, BuildHasherDefault<FxLikeHasher>>`,
  implemented locally in the file (no new Cargo dependencies — `Cargo.toml`
  is off-limits).

Invariants: no new crates; sketch dimensions, depth, saturation, and
admission semantics identical, so hit rate should stay within noise of
0.7362; `framework::Cache` impl and public method signatures unchanged.

## Rationale (optional)

Each baseline `get` performs 4 independent SipHash-1-3 computations just for
the sketch increment, plus a SipHash for the `HashMap` lookup; a miss-`put` at
capacity adds 8 more for the two estimates. Hashing dominates per-op time, and
the nested `Vec<Vec<u32>>` adds a pointer chase per row.
