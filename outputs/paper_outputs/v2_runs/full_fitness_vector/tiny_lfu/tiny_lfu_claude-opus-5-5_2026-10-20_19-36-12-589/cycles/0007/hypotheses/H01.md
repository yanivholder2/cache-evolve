# H01

Replacing the bit-at-a-time CLOCK sweep in `put` with a word-at-a-time `trailing_zeros` scan over the `u64` ref-bit words will lower `put` p99 per-op-time and leave hit rate identical bit for bit.

## Parent

cycle/0006/v001

## Changes

Only the CLOCK sweep loop in `TinyLfuCache::put` changes (the `loop { ... }` block that follows the "CLOCK sweep" comment, which tests and clears one bit per iteration). Replace it with a word-level scan that picks exactly the same victim slot and leaves exactly the same ref-bit state as the current loop:

1. Add a field `last_word_mask: u64` to `TinyLfuCache`. Compute it in `try_new`: if `capacity % 64 == 0`, it is `!0u64`. Otherwise it is `(1u64 << (capacity % 64)) - 1`. It marks the valid slots in the last ref-bit word. Do not change the size of `TinyLfuCache` in any other way. `Node` stays at 16 bytes.
2. Add a helper `#[inline(always)] fn valid_mask(&self, w: usize) -> u64`. It returns `last_word_mask` when `w == refbits.len() - 1` and `!0` for every other word.
3. The new sweep:
   - Start with `i = self.hand as usize`, `w = i >> 6`, `pos = i & 63`.
   - Loop:
     - Compute `cand = !self.refbits[w] & self.valid_mask(w) & (!0u64 << pos)`.
     - If `cand != 0`:
       - Set `b = cand.trailing_zeros()`.
       - Clear the ref bits from `pos` up to but not including `b`: `self.refbits[w] &= !(((1u64 << b) - 1) & (!0u64 << pos))`. When `b == pos` the mask is empty.
       - The victim is `(w << 6) + b`.
       - Break.
     - Otherwise:
       - Clear every bit at or above `pos` in this word: `self.refbits[w] &= !(!0u64 << pos)`. When `pos == 0` this zeroes the word.
       - Advance `w` with wrap: when `w + 1 == refbits.len()` it becomes `0`.
       - Set `pos = 0`.
   - The loop ends within at most `refbits.len() + 1` word visits, because after one full pass every bit is clear. Keep a `debug_assert!` on that bound.
4. Set `self.hand = victim` and `victim_idx = victim as u32`, as now. The admission duel, the strict `>` comparison, the way `self.hand` advances past an admitted victim, and the `get` path are all unchanged.

Invariants to keep:
- Padding bits past `capacity` in the last word are never set (`set_ref` only receives indices below capacity), and they are never chosen as the victim, because `valid_mask` excludes them.
- The victim and the ref bits left behind must equal what the old per-bit loop produces. Add a unit test that drives the old and new sweep over random ref-bit patterns and random hand positions, at capacities 1, 63, 64, 65 and 130, and asserts the same victim and the same `refbits`. The old loop can be kept as a `#[cfg(test)]` reference function.
- All existing tests must still pass.

## Rationale (optional)

Cycle 0006 found that CLOCK's unbounded per-bit sweep worsened `put` p99 (91 ns), and both the cross-cycle open questions and the cycle continuation list word-level scanning as the fix. Because the change leaves behaviour untouched, it isolates the effect on latency.
