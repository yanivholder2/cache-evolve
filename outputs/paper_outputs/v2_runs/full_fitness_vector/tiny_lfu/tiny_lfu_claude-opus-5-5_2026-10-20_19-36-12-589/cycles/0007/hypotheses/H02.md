# H02

Collapsing the `get`-then-`insert` double map probe in `put` into a single `HashMap::entry` probe (and dropping the redundant `key.clone()` on the fill path) will lower `put` p50 per-op-time and leave hit rate unchanged.

## Parent

cycle/0006/v001

## Changes

Restructure `TinyLfuCache::put`. The sketch, the CLOCK sweep and the admission rule are unchanged.

1. Keep `let h = key_hash(&key); let incoming_freq = self.sketch.increment_hash(h);` as the first two statements. Every call must increment the sketch exactly once, as it does now.
2. **Fill phase** (`self.nodes.len() < self.capacity`). Use `match self.map.entry(key.clone())`:
   - `Occupied(e)`: update `self.nodes[*e.get() as usize].value = value`, call `set_ref(idx)`, and return.
   - `Vacant(e)`: set `idx = self.nodes.len() as u32`, call `e.insert(idx)`, then push a `Node { key, value }` that moves the original `key` in. That is one clone in total, not one clone plus a second probe.
   This branch needs only `self.map` and `self.nodes`, so the borrows are disjoint. Bind `let nodes = &mut self.nodes;` before the `match` if the borrow checker needs it.
3. **Full phase** (`self.nodes.len() == self.capacity`). Keep the existing `self.map.get(&key)` hit check, because the victim's removal would conflict with a held `VacantEntry`. When admitting:
   - Use `std::mem::replace(&mut slot.key, key.clone())` to take the old key out.
   - Call `self.map.remove(&old_key)`, then `self.map.insert(key, victim_idx)`.
   This does the same work as today but avoids reading `slot.key` through the map borrow. The rejection path is unchanged.
4. Do not change `get`, `Node`, `CountMinSketch` or the CLOCK ref-bit logic. The order of sketch increments, the hand movement and every admission decision must stay identical, so hit rate matches v001 bit for bit.
5. Add a unit test that inserts `capacity` distinct keys, re-puts one of them during the fill phase (checking that the value updates and `nodes.len()` does not grow), then fills further and checks the eviction behaviour.

## Rationale (optional)

Cycle 0006 found that the median cost does not sit in relinking or sketch hashing. The remaining non-sketch cost on `put` is map work. Today a fill-phase miss probes the SwissTable twice (`get`, then `insert`) and clones the key. This change targets that map cost directly, using std's `entry` rather than a custom table. A custom table lost in cycle 0006.
