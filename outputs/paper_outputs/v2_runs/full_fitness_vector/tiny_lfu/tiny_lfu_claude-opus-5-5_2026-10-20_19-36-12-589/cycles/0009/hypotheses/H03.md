# H03

Placing each key's four counters in a single 64-byte block, with each row on its own disjoint 8-counter lane chosen by independent hash bits, cuts per-access memory traffic from four cache lines to one and lowers median per-op time, while hit rate stays within noise.

## Parent

cycle/0006/v001

## Changes

All changes are in `src/tiny_lfu/mod.rs`, inside `CountMinSketch`. The byte size of the table, the counter type (`u16`), conservative update, saturation, and the CLOCK and duel logic stay as they are.

- Lay `counts` out as `num_blocks = SKETCH_DEPTH * width / 32` blocks of 32 `u16` counters, which is 64 bytes each. Allocate the table aligned to 64 bytes: for example, back it with `Vec<[u16; 32]>` wrapped in a `#[repr(align(64))]` newtype such as `struct Block([u16; 32])`. Splitting it this way also removes the risk of a block straddling two cache lines. `heap_bytes()` must still report `SKETCH_DEPTH * width * 2`.
- Replace `indices(h)` as follows. Re-mix the hash once, `let m = fmix64(h ^ 0x9e37_79b9_7f4a_7c15)` or an equivalent cheap mix, so that block choice and lane choice use bits that don't depend on each other. Then:
  - `block = (h as usize) & (num_blocks - 1)`
  - lane for row `r` (`r` in 0..4): `slot_r = r * 8 + ((m >> (8 * r)) & 7)`. Each row owns its own 8 counters within the block, so the rows never alias one another.
  - Return `[block*32 + slot_0, …, block*32 + slot_3]`.
- Keep `increment_hash` and `estimate_hash` as they are (fused, single-pass, branch-free over four indices). Only the index computation changes. Update the SAFETY comment: the indices fall in disjoint lanes of a single in-bounds block.
- How this differs from cycle 0003's failed blocked layout: the row lanes are disjoint and selected by bits independent of the block index, so two keys that share a block still collide in a given row with probability 1/8, independently for each row. The per-row collision rate is the same as now (1/width). Only the correlation across rows within a block is new, and conservative update limits how much that can inflate estimates.
- Update `conservative_update_bumps_only_minimum_counters` to inflate a counter through the new `indices(h)[0]`, rather than `index(h1, h2, 0)`. Remove the old `index` helper if nothing else uses it.

How to test: compare side by side against cycle/0006/v001. The claim is refuted if hit rate drops by more than 0.001, as it did in cycle 0003. It is confirmed if hit rate stays within noise and `get` p50 drops, because each access now touches one cache line instead of four.
