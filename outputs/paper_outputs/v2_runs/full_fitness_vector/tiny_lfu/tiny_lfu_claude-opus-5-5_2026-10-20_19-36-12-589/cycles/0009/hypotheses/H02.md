# H02

Issuing software prefetches for the key's four sketch counter lines before the map probe, and doing the sketch increment after the probe, overlaps the sketch's cache misses with the HashMap lookup and lowers median per-op time with bit-identical hit rate.

## Parent

cycle/0007/v002

## Changes

All changes are in `src/tiny_lfu/mod.rs`. This is behaviour-preserving. The sketch does not depend on map state, and the map does not depend on the sketch, so reordering the increment relative to the map probe leaves every admission decision unchanged.

- Add `#[inline(always)] fn prefetch_hash(&self, h: u64)` to `CountMinSketch`. It computes `self.indices(h)` and, under `#[cfg(target_arch = "x86_64")]`, calls `core::arch::x86_64::_mm_prefetch(self.counts.as_ptr().add(i) as *const i8, _MM_HINT_T0)` for each of the four indices, inside an `unsafe` block with a SAFETY comment explaining that the indices are in bounds. On other architectures the function is a no-op. Do not add a new crate or edit `Cargo.toml`.
- `TinyLfuCache::get`: compute `let h = key_hash(key);`, call `self.sketch.prefetch_hash(h)`, then `let found = self.map.get(key).copied();`, then `self.sketch.increment_only(h);` (unconditionally, so misses still count exactly once, as now), then `let idx = found?;`, `set_ref(idx)` and return the value.
- `TinyLfuCache::put`: compute `h`, call `prefetch_hash(h)`, then do the existing map lookup or entry probe, then `let incoming_freq = self.sketch.increment_hash(h);` before branching. The increment must still run on every path: update hit, fill phase and full miss. Keep the single-increment-per-access invariant and the cycle 0007/v002 fill-phase `entry` logic as they are.
- On the eviction path, also issue `prefetch_hash` for the victim's hash as soon as the CLOCK sweep settles on `victim_idx`, before the `incoming_freq > victim_freq` comparison loads its counters. In practice this mainly reorders the `estimate_hash` call relative to the existing work.
- Do not add any struct fields, and keep the struct layout unchanged. Cycle 0007 showed that growth in layout hurts.

How to test: hit rate must match the parent bit for bit. Compare `get` and `put` p50 side by side against cycle/0007/v002 and cycle/0006/v001. The mechanism is that cycle 0008 identified the four scattered counter accesses as the main `get` cost. Prefetching lets them run in parallel with the SwissTable probe instead of after it.
