# H01

Narrowing the sketch counters from saturating `u16` to saturating `u8` at the same width halves the sketch footprint and cuts median `get`/`put` per-op time, while hit rate stays within noise.

## Parent

cycle/0006/v001

## Changes

All changes are in `src/tiny_lfu/mod.rs`, inside `CountMinSketch` and its constants. The cache, CLOCK and duel logic stay as they are.

- Change `CountMinSketch::counts` from `Vec<u16>` to `Vec<u8>`. Keep `SKETCH_DEPTH = 4`, `SKETCH_WIDTH_FACTOR = 8` and `MIN_SKETCH_WIDTH` unchanged, so the width (number of columns) is the same and the table is half as many bytes.
- Set `MAX_COUNT` to `u8::MAX as u32` (255). `increment_hash` keeps its fused, branch-free, single-pass conservative-update structure: load four `u8`s widened to `u32`, take the min, compute `inc = (min < MAX_COUNT) as u32`, bump only the counters equal to the min, store back `as u8`, and return `min + inc`. `estimate_hash` changes only the load type.
- Update `heap_bytes()` to use `size_of::<u8>()`, and update the doc comments on `sketch_heap_bytes`/`heap_bytes` to match.
- Update the unit tests in the same file: `conservative_update_saturates` fills with `u8::MAX` and expects `u8::MAX as u32`. Leave the other tests unchanged; they should pass as they are.
- Do not add aging, halving or reset. Counters must not decay, because every decay variant has failed. The strict `incoming_freq > victim_freq` duel stays.

Why it should preserve hit rate: the duel matters most for cold newcomers against cold CLOCK victims, whose counts are far below 255. At 255 both hot sides saturate. A tie keeps the resident, which is the same outcome as now. Hot residents seldom reach the clear-bit victim slot anyway.

How to test: compare side by side against cycle/0006/v001. Hit rate should be within ±0.001. `get` and `put` p50 should drop, because each access touches a table that is now half the size, so it fits better in L1/L2. This is the reverse of cycle 0008's widening, which raised `get` p50 when the table grew.
