# H03

On a full-cache insert, pick the victim as the entry with the lowest sketch estimate among the 4 least-recently-used entries, instead of always the LRU head, to raise hit rate on workload-a.

## Parent

cycle/0001/v003

## Changes

All edits are in `src/tiny_lfu/mod.rs`, applied to v003.

1. Add `const VICTIM_SAMPLE: usize = 4;`.
2. In `TinyLfuCache::put`, change only the full-cache branch. Replace `let victim_idx = self.head.expect(...)` with a short walk:
   - Start at `self.head` and follow `next` links for up to `VICTIM_SAMPLE` nodes, stopping early at `None`.
   - For each node, compute `self.sketch.estimate_hash(key_hash(&node.key))`.
   - Keep the node with the strictly smallest estimate. On ties, keep the earlier (older) node, so with equal frequencies the behaviour reduces to the current LRU-head choice.
3. Use that node's index as `victim_idx` and its estimate as `victim_freq`. The admission test stays `incoming_freq > victim_freq`. If the incoming key is admitted, run the existing replacement code on `victim_idx`: remove the victim key from the map, `unlink(victim_idx)`, overwrite its key and value, `push_back`, and insert into the map. That code already works for any index, not just the head.
4. If the incoming key is rejected, change nothing. Do not touch `get`, the update path, the sketch counting rules, the hasher, or `Node` / struct layout. Metadata size stays 48.

Invariants: the existing unit tests use capacity 2 and must still pass. In `eviction_prefers_hot_items` the candidates are key 2 (est 1) and key 1 (est 2), so the victim is key 2 and key 3 (est 3) is admitted. In `low_frequency_new_item_is_rejected` the victim is key 2 (est 1) and the incoming key 3 has est 1, so it is rejected. Extra work happens only on full-cache misses: at most 4 hashes and estimates. Get latency is unchanged.

## Rationale (optional)

Cycle 0001 suggests the admission signal caps hit rate. Strict LRU-head victims often evict a moderately hot item while a colder one sits right behind it. Sampling the LRU tail for the coldest entry is a cheap way to use the frequency signal for eviction as well as admission. It adds no per-hit relink cost, unlike the SLRU/window restructuring that failed in v001.
