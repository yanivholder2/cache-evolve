# H01

Add periodic sketch aging (halve every counter after a sample window of 10×capacity increments, with counters capped at 15) to raise hit rate on workload-a by keeping the admission signal fresh.

## Parent

cycle/0001/v003

## Changes

All edits are in `src/tiny_lfu/mod.rs`, applied to v003's fast-hash version.

1. Replace `const MAX_COUNT: u32 = u32::MAX;` with `const MAX_COUNT: u32 = 15;`. This is the TinyLFU 4-bit saturation cap, and it still uses the existing `u32` storage. Keep the `if *counter < MAX_COUNT` guard in `CountMinSketch::increment_hash`.
2. Add two fields to `CountMinSketch`: `additions: usize` and `sample_size: usize`. Give `CountMinSketch::new` a second argument, `sample_size`. In `TinyLfuCache::try_new`, pass `capacity.saturating_mul(10).max(16)`.
3. In `increment_hash`, track whether at least one row's counter was actually incremented (not already saturated). If so, do `self.additions += 1`. Then, when `self.additions >= self.sample_size`, call a new method `reset()`.
4. Implement `reset(&mut self)`. It does one linear pass over `self.counts` doing `*c >>= 1`, then sets `self.additions /= 2` (Caffeine-style: it keeps half the history).
5. Keep everything else unchanged: `estimate_hash`, the admission rule `incoming_freq > victim_freq` in `put`, the LRU list, the FxLike hasher and `fmix64`. `heap_bytes()` must still report `depth * width * size_of::<u32>()`.

Invariants: the existing unit tests use capacity 2 (sample_size 20) and must still pass. They perform far fewer than 20 increments, so no reset fires during them. The reset pass is O(depth×width), amortised over 10×capacity operations, so per-op p50 should stay near v003's 33 ns.

## Rationale (optional)

Cycle 0001 found that hit rate stayed flat for every variant that kept the never-aging, uncapped counters. The aging hypothesis (cycle 0001 H02) was never evaluated because of a Maven 429 infra failure. This re-submits it on the fast-hash incumbent.
