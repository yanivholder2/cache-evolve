# H02

Replace the `Option<usize>` prev/next links in `Node` with `u32` indices that use a `u32::MAX` sentinel, shrinking `Node<u64,u64>` from 48 to 24 bytes to reduce metadata size.

## Parent

cycle/0001/v003

## Changes

All edits are in `src/tiny_lfu/mod.rs`, applied to v003.

1. Add `const NIL: u32 = u32::MAX;`. Change `Node` to `{ key: K, value: V, prev: u32, next: u32 }`. Change the `TinyLfuCache` fields `head` and `tail` from `Option<usize>` to `u32`, both initialised to `NIL`.
2. In `try_new`, reject `capacity >= u32::MAX as usize` with a `log::error!` and return `None`, so that every index fits in `u32` and never collides with `NIL`.
3. Change the map type to `HashMap<K, u32, FxBuild>`. Rewrite `unlink` and `push_back` to take `idx: u32`. They index `self.nodes[idx as usize]`, and every `match Some/None` branch becomes an `== NIL` / `!= NIL` comparison with the same semantics: unlinking the head updates `head`, unlinking the tail updates `tail`, and `push_back` onto an empty list sets `head`.
4. In `put`, the victim is `self.head`. Add a `debug_assert!(self.head != NIL)` in place of the `expect`. The insertion path pushes `self.nodes.len() as u32`. In `get`, use `let &idx = self.map.get(key)?;` and index with `idx as usize`.
5. Leave the sketch, the hashing, the admission rule (`incoming_freq > victim_freq`) and the LRU order unchanged, so hit rate stays identical to v003.

Expected: `size_of::<Node<u64,u64>>()` = 8 + 8 + 4 + 4 = 24 bytes, down from 48. The `TinyLfuCache` struct also shrinks, because head and tail are now 4 bytes each. The smaller nodes mean better cache-line density on unlink and relink, which should leave per-op-time equal to or better than 33 ns.

## Rationale (optional)

The metadata-size summary is the per-entry `Node` size. No variant has improved it yet: the 48 bytes are still held by the baseline. Option-wrapped `usize` links cost 16 bytes each, and that padding is pure overhead.
