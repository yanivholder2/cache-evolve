# H03

Switching the sketch to saturating `u16` counters at twice the width (same sketch bytes) will raise hit rate by halving collision overestimation while keeping row independence.

## Parent

cycle/0003/v003

## Changes

All edits are in `CountMinSketch` and `TinyLfuCache::try_new` in `src/tiny_lfu/mod.rs`.

1. Change `counts: Vec<u32>` to `counts: Vec<u16>`, and set `MAX_COUNT` to `u16::MAX as u32`. Do the comparisons in `u32` by widening loaded counters with `as u32`. Narrow on write-back. Keep v003's conservative-update rule exactly: bump only counters equal to the min, `inc = (min < MAX_COUNT) as u32`, return `min + inc`.
2. Change `SKETCH_WIDTH_FACTOR` from 4 to 8. Width stays `(capacity * 8).max(MIN_SKETCH_WIDTH).next_power_of_two()`, so it is still a power of two and the `index()` mask logic is unchanged. Depth stays 4. Keep the double-hash index scheme (`h1 + row*h2`, masked per row, with each row in its own `[row*width, (row+1)*width)` range). This keeps rows independent, unlike the rejected blocked layout from cycle 0003.
3. Update `heap_bytes()` to `depth * width * size_of::<u16>()`, so the reported sketch footprint matches v003's byte count.
4. `estimate_hash` widens each loaded `u16` to `u32` before taking the min.
5. Don't change `Node`, the list, `get`/`put` control flow or admission (strict `>`).

Update `conservative_update_saturates` to fill counters with `u16::MAX` and expect a return of `u16::MAX as u32`. Keep the other tests unchanged.

## Rationale (optional)

v003 showed that estimate accuracy is the only lever that has moved hit rate. A 4-row CountMin with width ≈4×capacity still has significant collision mass. Doubling the width roughly halves each counter's expected collision noise, with no new hashing and no new hot-path branches. On workload-a the hottest keys' counts won't come near 65 535 before eviction matters, so saturating at that value doesn't hurt admission. If they do saturate, only the tie order among very hot keys changes, and those keys are never the LRU-head victim anyway. Per-op cost should stay flat, because the access count and pattern don't change and the sketch is the same size in bytes.
