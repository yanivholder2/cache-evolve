# H01

Change the admission contest in `put` so that frequency ties admit the newcomer instead of keeping the LRU-head victim, to raise hit-rate on workload-a at zero extra per-op cost.

## Parent

cycle/0002/v002

## Changes

In the full-cache branch of `put` (the admission contest that compares the
incoming key's sketch estimate against the LRU-head victim's estimate),
replace the strict `incoming_freq > victim_freq` test with
`incoming_freq >= victim_freq`. When the newcomer wins, evict the victim and
insert the newcomer as before. When it loses, reject it as before. Nothing
else changes:

- Keep the sketch exactly as in v002: `CountMinSketch`, `increment_hash`,
  `key_hash`, counter width, and no aging.
- Keep the compact `u32` links, the `NIL` sentinel and the `try_new`
  capacity check exactly as they are.
- Keep the order of operations in `put`: the incoming key's sketch increment
  still happens before the estimate is compared, so a brand-new key competes
  with an estimate of at least 1.
- Add no new fields, branches or hashing. The change must be a single
  comparison-operator edit plus any comment or test-name updates that the
  edit needs. If an existing test asserts that ties reject the newcomer,
  update only that overlay test's expectation, not the gate tests.

## Rationale (optional)

Cross-cycle insights point at the admission rule (strict `>`, ties going to
the victim) as the likely cause of the hit-rate ceiling. Victim sampling showed
that LRU-end estimates are nearly equal, so ties are common. Breaking ties
toward recency gives some LRU behaviour back without a window structure, which
has been costly. If this helps, the strict `>` was over-rejecting. If it hurts,
workload-a rewards frequency more than recency, and the ceiling is elsewhere.
