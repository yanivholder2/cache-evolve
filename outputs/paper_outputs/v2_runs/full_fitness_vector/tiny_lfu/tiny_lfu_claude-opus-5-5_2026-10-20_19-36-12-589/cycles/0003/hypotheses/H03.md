# H03

Switch the `CountMinSketch` from plain increments to conservative update, so only the counters equal to the current minimum are bumped, to sharpen frequency estimates and raise hit-rate.

## Parent

cycle/0002/v002

## Changes

Change `increment_hash` in `CountMinSketch` to use conservative update:

- With the same single `key_hash` value and the same per-row index
  derivation as v002, first read the key's `depth` counters and compute
  `min`.
- Then write `min + 1` only to the counters whose value equals `min`. Leave
  the larger counters untouched. Write this as a branch-free loop, for example
  `c += (c == min) as Counter`, so that no data-dependent branch enters the
  hot path.
- Keep the existing counter type and the existing saturation behaviour (if
  `min` already sits at the type's max, nothing changes). Do not add aging,
  reset counters or new fields.
- If `get` and `put` currently call increment and then a separate estimate on
  the same key, it is fine to have `increment_hash` return the new `min + 1`
  and use that as the incoming key's estimate in the `put` admission contest.
  This saves one pass. The victim's estimate is computed as before.
- Keep the admission rule (strict `>`, ties to the victim), the `u32` links
  and the rest of `put`/`get` unchanged, so that the only behavioural change
  is how accurate the estimates are.

## Rationale (optional)

Count-min overestimates because of collisions. Without aging, those
overestimates build up, which inflates cold victims' and cold newcomers'
estimates toward each other and creates the near-ties seen at the LRU end.
Conservative update is a well-known way to cut that overestimation. Unlike
cycle 0002's aging, it keeps the long-term frequency gaps that workload-a
seems to reward. Per-op cost should be close to v002, since the counters are
already read for the estimate. This tests the frequency-signal-accuracy side of
the hit-rate ceiling, separately from H01's tie-rule test.
