# H02

Double the CountMin sketch width (`SKETCH_WIDTH_FACTOR` 8 → 16) to further reduce collision-inflated estimates in the admission duel and raise hit rate, at no cost to the per-entry metadata-size summary.

## Parent

cycle/0007/v002

## Changes

In `src/tiny_lfu/mod.rs`, change `const SKETCH_WIDTH_FACTOR: usize = 8;` to `16`.
`try_new` will then size each row at `(capacity * 16).max(MIN_SKETCH_WIDTH).next_power_of_two()`
counters, and `heap_bytes()` reports the doubled table automatically.

Keep everything else unchanged:
- `SKETCH_DEPTH = 4`, with independent rows and double-hashed indices
- saturating `u16` counters
- conservative update via the fused single-pass `increment_hash`
- one count per access
- the CLOCK sweep and hand movement
- the strict `>` duel

The width is a power of two, so `index()` masking keeps working. Don't add struct fields.
Update or extend the in-file tests only where they assume a specific width. They
construct `CountMinSketch::new(16)` directly, so they should be unaffected.

## Rationale (optional)

The metadata-size summary is the `Node<u64,u64>` size (16 B). The sketch heap is reported
but isn't the summary, so extra width costs nothing on that axis. Sketch accuracy is the
only lever that has ever raised hit rate (c3 conservative update, c4 2× width, c5
single-count). The insights call it close to used up, but c4's 2× width still gave a
gain, and nobody has tested another doubling on the CLOCK base. The experiment: compare
hit rate against cycle 0007's v002 (0.7422). If the gain is ≤0.0005, the width lever is
closed. Also check whether the larger (≈256 KB at cap 2048) table hurts `get` p50
through extra cache misses.
