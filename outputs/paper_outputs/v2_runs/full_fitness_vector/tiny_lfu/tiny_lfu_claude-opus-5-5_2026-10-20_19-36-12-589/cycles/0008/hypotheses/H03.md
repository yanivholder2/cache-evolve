# H03

Put a periodically cleared one-bit doorkeeper in front of the CountMin sketch, so first occurrences of a key don't pollute sketch counters, to raise hit rate by sharpening the newcomer-vs-victim duel.

## Parent

cycle/0006/v001

## Changes

Add a `Doorkeeper` inside `CountMinSketch`, so `TinyLfuCache` gains no new top-level
fields. It is a bit array of `width` bits (`Vec<u64>` of `width / 64` words, minimum 1),
plus an `ops: u32` counter and a `reset_period: u32 = 16 * capacity`. Pass capacity into
`CountMinSketch::new` to set the period.

Doorkeeper membership uses two bit positions taken from the same 64-bit `h`, with no
extra hashing:
- `b0 = (h >> 7) & (bits - 1)`
- `b1 = (h >> 29) & (bits - 1)`

Then change the sketch methods as follows.

- `increment_hash(h)`:
  - If the key is not in the doorkeeper (either bit clear), set both bits and return
    `estimate_counts(h) + 1` without touching the counters.
  - Otherwise, run the existing fused conservative update and return `min + inc + 1`.
    The `+1` accounts for the doorkeeper bit.
  - In both cases, increment `ops`. When `ops == reset_period`, zero the doorkeeper
    words and reset `ops`. Leave the counters alone; they are never halved.
- `estimate_hash(h)`: return the counter minimum plus 1 if the key is in the doorkeeper.
- `increment_only` stays a thin wrapper.

Keep everything else exactly as in the parent:
- the CLOCK sweep and hand movement
- the strict `>` duel
- `u16` saturating counters
- width factor 8

Mark the reset branch `#[cold]` or keep it out of line so the hot path adds only two
bit tests. Update the conservative-update unit tests to account for the
doorkeeper-first behaviour: the first increment of a key leaves its counters untouched.
`Node` must stay 16 bytes.

## Rationale (optional)

Doorkeepers are part of the original TinyLFU design but haven't been tried in this run.
Most keys in workload-a show up once and then never again. Under the parent, each of
those still bumps four counters, and the bumps inflate the estimates of resident victims
and of real newcomers that share those counters. With a doorkeeper, a one-hit key only
touches two bits, which are cleared periodically. The counters themselves never decay,
so this avoids the full-sketch halving that lost hit rate in c2 and c4. Hit rate is
refuted if it comes in below the parent's 0.7422.
