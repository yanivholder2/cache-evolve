# H01

Pack the CountMin sketch into 4-bit saturating counters (two per byte, cap 15) to halve the sketch footprint, so that at capacity 2048 it fits in L1D, cutting `get` p50 per-op-time with hit rate unchanged.

## Parent

cycle/0009/v001

## Changes

Change only `CountMinSketch`; `TinyLfuCache`, the CLOCK logic, the strict `>` duel and conservative update all stay as they are.

- Keep the logical geometry: `SKETCH_DEPTH = 4`, `width = (capacity * SKETCH_WIDTH_FACTOR).max(MIN_SKETCH_WIDTH).next_power_of_two()`, and the flat logical index `row * width + col` from `index()`/`indices()`. Don't change how indices are derived, and don't add hash mixes.
- Storage: `counts: Vec<u8>` of length `SKETCH_DEPTH * width / 2`. Logical counter `i` lives in byte `i >> 1`. Its nibble is the low nibble if `i & 1 == 0` and the high nibble otherwise, so `shift = (i & 1) << 2`. Rows stay disjoint because `width` is a power of two ≥ 16, so a byte never holds counters from two different rows. Row independence is preserved; this is not a blocked layout.
- Set `MAX_COUNT` to `15`.
- `increment_hash(h)`:
  1. Compute the four logical indices once, then four byte offsets `b_r = i_r >> 1` and four shifts `s_r = (i_r & 1) << 2`.
  2. Load the four bytes once into locals and extract `c_r = (byte_r >> s_r) & 0xF`.
  3. Compute `min`, then `inc = (min < 15) as u8`.
  4. Write back `byte_r + (((c_r == min) as u8 & inc) << s_r)`. Adding into the nibble cannot carry into the neighbour, because a counter equal to a non-saturated min is ≤ 14.
  5. Return `min + inc`.
  Keep it branch-free and inside `unsafe` with `get_unchecked`. Update the SAFETY comment: the byte offset is `< counts.len()`.
- `estimate_hash` uses the same load and nibble extraction and returns the min.
- `heap_bytes()` returns `SKETCH_DEPTH * width / 2`.
- Update the in-module unit tests that poke at `s.counts[i0]` so they read and write the nibble through a small `#[cfg(test)]` helper (`get_counter(i)` / `set_counter(i, v)`). The saturation test fills every byte with `0xFF` and expects an estimate of 15.

Invariant: every duel outcome should match v001 unless an estimate would have exceeded 15 on both sides. The insights say admission is decided by low counts, so hit rate should stay exactly at 0.7422. If hit rate drops, the cap is binding and the hypothesis is refuted.

## Rationale (optional)

At cap=2048, v001's `u8` sketch is 64 KiB, which is bigger than a typical 32–48 KiB L1D. The 4-bit table is 32 KiB and fits, so the four scattered RMWs on every `get` should hit L1 more often. This is the one sketch lever cycle 0009 flagged as still open. The cost is a shift and a mask per counter.
