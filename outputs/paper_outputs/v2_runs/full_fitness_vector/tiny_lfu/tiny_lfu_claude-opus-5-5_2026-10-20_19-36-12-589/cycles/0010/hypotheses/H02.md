# H02

Replace CLOCK's single reference bit with a 2-bit saturating per-slot usage counter (GCLOCK-style, decremented by the sweep) so that frequently hit residents survive more sweeps, raising hit rate on workload-a.

## Parent

cycle/0009/v001

## Changes

This changes which resident becomes the victim. Admission stays the same: the strict `incoming_freq > victim_freq` duel against the single slot the hand stops on, with no windows, aging or doorkeeper. The sketch is untouched.

- Add a second bit-plane next to `refbits`: `refbits_hi: Vec<u64>` of the same length (`capacity.div_ceil(64)`). Each slot now has a 2-bit counter `u = hi*2 + lo` with values 0–3. Keep `Node` at 16 bytes and don't add per-node fields. One added `Vec` header is acceptable; keep `TinyLfuCache` within two cache lines.
- `set_ref(idx)` (hit on `get`, and update on `put`): saturating increment of the 2-bit counter, done branch-free on the two words. With `lo` and `hi` as the slot's bits, the new values are `hi' = hi | lo` and `lo' = 1`. So 0→1→3→3: a hit after the first sets both bits. Implement it as `w_hi |= w_lo & mask; w_lo |= mask;`, which is two word RMWs.
- Sweep in `put` (full-miss path): at each slot the hand visits, if `u == 0`, stop there; that slot is the victim. Otherwise decrement `u` and advance: `lo' = hi`, `hi' = 0`, which takes 3→1 and 1→0. Wrap at `cap` as now. Termination: each full lap decrements every non-zero counter, so the sweep ends within 3 laps. Change the `debug_assert!` bound to `3 * capacity`.
- Newcomers, whether filled during warm-up or admitted on a won duel, start at `u = 0`. Clear both planes for the victim slot on replacement; they are already 0 at that point. As today, the hand moves past the slot only when the newcomer is admitted, and parks on the victim when the newcomer is rejected.
- Keep the existing unit tests passing. `eviction_prefers_hot_items` still holds: key 1 has `u = 1` after one hit and is decremented to 0, while key 2 at 0 becomes the victim. Add a test showing that a key hit twice survives one full sweep in which a key hit once is evicted.

Invariant: metadata-size (`Node<u64,u64>` = 16) is unchanged. On a sweep-free `get`, the added cost is one more word RMW.

## Rationale (optional)

Every hit-rate lever on the admission side has been used up: sketch accuracy, tie rule, windows, aging and doorkeeper. But the eviction order inside the main region has only been tested as LRU and as 1-bit CLOCK, which tied each other. Min-of-two candidates (c7) failed because it loosened admission. This change instead keeps the admission rule fixed and only changes which resident the duel defends. Multi-hit residents get more lives, and the duel defends residents that were hit once or never.
