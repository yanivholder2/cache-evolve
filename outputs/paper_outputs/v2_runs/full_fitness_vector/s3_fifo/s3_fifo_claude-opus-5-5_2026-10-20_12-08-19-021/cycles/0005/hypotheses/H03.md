# H03

Storing resident values and frequency directly in the `index` map, and dropping the slab indirection, will cut `get` per-op-time, the headline latency metric, while keeping hit-rate identical.

## Parent

cycle/0004/v003

## Changes

This is a policy-neutral data-structure refactor. The aim is a single-probe `get`. Today `get` does an `index` probe, then a random access into `slots`, then an `Option` discriminant check. After this change it should be one hash-map probe that returns the value and bumps freq in place. Hit-rate must stay exactly 0.7283. The eviction order, ghost logic, `fp()` (`FxHash | 1`), adaptive split, clamps, triggers, `freq > 1` graduation and `MAX_FREQ` must all stay behaviourally identical.

- Redefine `pub struct Entry<K, V> { value: V, freq: u8, _k: std::marker::PhantomData<K> }`. Keep the type name and both generic parameters so the metadata-size probe still resolves `Entry<u64,u64>`. The key lives only as the map key. Expected `size_of::<Entry<u64,u64>>()` is 16, down from 24.
- Replace `slots`, `free` and `index: FxHashMap<K, u32>` with `index: FxHashMap<K, Entry<K, V>>`. Change `small` and `main` to `VecDeque<K>`, which hold key clones.
- `get`: `let e = self.index.get_mut(key)?; e.freq = (e.freq + 1).min(MAX_FREQ); Some(&e.value)`.
- `put` hit: `if let Some(e) = self.index.get_mut(&key) { e.value = value; return; }`. On a miss, keep the same branch structure. Insert with `self.index.insert(key.clone(), Entry{value, freq:0, ..})` and push `key` (moved) onto `small` or `main` front. Total cost per miss: one clone, the same as the parent.
- `evict_main`: `while let Some(k) = self.main.pop_back()`, then `let e = self.index.get_mut(&k).expect(..)`. If `e.freq > 0`, decrement and `push_front(k)`. Otherwise `self.index.remove(&k)` and break.
- `evict_small_inner`: pop the key, read its freq through `index.get`, and take the same graduate/ghost decisions as the parent. On a ghost demotion, call `ghost_push(&k)` before or after `index.remove(&k)`. `ghost_push` takes `&K`, so the order does not matter.
- Update the test helpers (`in_main`, `push_main_back_for_test`, `push_small_front_for_test`, `alloc`) and the invariant checks in `index_tracks_residency` and `capacity_bound_never_exceeded` (in-file `#[cfg(test)]` only) to the new layout, with the same assertions: `index.len() == small.len() + main.len()`, and no resident key's fingerprint in `ghost_map`.
- Do not touch `s3_fifo_jni.rs`. It must only rely on `S3Fifo::new/try_new/get/put`. If it names `Entry` fields, stop and report instead.

## Rationale (optional)

`get` has been byte-identical for three cycles, so its number has only moved with noise. This is the first change that removes real work from `get`: one dependent load into a separate allocation and one discriminant branch. The cost moves to `put`, where `evict_main` now does a hash probe per CLOCK step instead of an indexed slab load. That `put` regression is expected and should be reported honestly. The bet is that the headline `get` p50 drops, and as a side effect the measured `metadata-size` falls from 24 to 16.
