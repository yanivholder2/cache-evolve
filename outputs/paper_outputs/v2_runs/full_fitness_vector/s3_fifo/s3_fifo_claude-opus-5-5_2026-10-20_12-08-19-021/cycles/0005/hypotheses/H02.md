# H02

Admitting ghost-hit keys into main with `freq = 1` instead of `freq = 0` will raise hit-rate on workload-a by giving proven-reused keys one extra second-chance lap before main can evict them.

## Parent

cycle/0004/v003

## Changes

One lever: the starting frequency of an entry readmitted through the ghost. The adaptive split, both clamps, both resize triggers, graduation (`freq > 1`), `MAX_FREQ = 3` and the ghost ring all stay byte-identical to the parent.

- In `put`, ghost-hit branch: after `let i = self.alloc_with_key(key, value);` and before `self.main.push_front(i);`, set `self.slot_mut(i).freq = 1;`. Keep `alloc_with_key` as it is (it still creates entries with freq 0) so the small-queue admission path does not change. Alternatively, add an `alloc_with_key_freq(key, value, freq)` that both paths call. Either way, the small-admission path must still start at 0.
- Do not change `evict_main`. A readmitted key now needs one decrement pass (1 → 0) before it can be evicted, unless `get` bumps it further.
- Report where `small_size` settles, for the parent and for this variant. Use a `#[cfg(test)]` accessor and an in-file test on a synthetic skewed stream at capacity 2048. This lever changes how long ghost-readmitted keys stay in main, and therefore how often the "main full on graduation" grow-small trigger fires. So the split may move, and that has to be reported for the result to mean anything.
- Do not edit `tests/` or `src/bin/`. The existing `ghost_hit_promotes_back_to_main` test must still pass.

## Rationale (optional)

A ghost hit is stronger evidence of reuse than a single `get` in small, yet the parent places such keys at the head of main with zero credit, where a single CLOCK sweep can evict them. Earlier movement-rule tweaks (graduation threshold, ghosting main victims) changed *which* keys move, and the adaptation absorbed them. This one changes only how long a readmitted key survives once it is in main, which has not been tested yet.
