# H01

Raise the main-queue frequency cap to 7 using a 3-bit packed counter, and drain it by halving instead of decrementing, to keep the hit-rate gain from 0008 v003 without its eviction-path latency cost.

## Parent

cycle/0008/v001

## Changes

This change is on the packed-index layout in `src/s3_fifo/mod.rs`. It is a policy change to retention depth only. Nothing touches the split, the ghost or the layout beyond the bit width.

- **Widen the packed counter to 3 bits.** Set `FREQ_SHIFT` from 30 to 29, so the slot id becomes 29 bits and `SLOT_MASK = (1 << 29) - 1`. `FREQ_ONE` follows automatically. The capacity guard in `try_new` already compares against `SLOT_MASK + 1`; update its log message to say "29-bit slot id".
- **Raise the cap.** Set `MAX_FREQ = 7`. `get` is unchanged: it does a saturating `+= FREQ_ONE` while `(e >> FREQ_SHIFT) < MAX_FREQ`.
- **Halve instead of decrement in `evict_main`.** When a popped main entry has `f = *e >> FREQ_SHIFT` with `f > 0`, rewrite the word as `((f >> 1) << FREQ_SHIFT) | (*e & SLOT_MASK)` and push it back to the front. When `f == 0`, release it as today. A saturated key (7) now survives 3 laps (7→3→1→0) instead of 7, so the worst-case rotations per eviction stay close to the parent's (3). Frequency is still being distinguished up to 7, which is where 0008 v003 found its hit-rate.
- **Keep graduation as is.** `evict_small_inner` keeps graduating on `freq > 1` and carries the counter into main unchanged.
- **Tests.** In `packed_layout_fits_max_freq`, update the asserts so `SLOT_MASK == (1<<29)-1` and `MAX_FREQ <= u32::MAX >> FREQ_SHIFT`. Make `repeated_get_clamps_frequency` expect 7. In `main_eviction_uses_frequency_second_chance`, keep the same expectations: freq 2 halves to 1, and freq 1 halves to 0, so it still survives one lap. Add a unit test showing that a freq-7 main entry is released after exactly 3 rotations plus a final pop.

## Rationale (optional)

0008 v003 (`MAX_FREQ` 7 with decrement) was the only hit-rate gain of the cycle (0.7325 against 0.7309), but its `put` and `get` p50 rose sharply because of longer CLOCK drains. Halving keeps the high-frequency ranking but bounds the laps at log2. If the hit-rate stays at or above 0.7309 with `get` p50 near 23 ns, the depth lever works without the drain cost. A hit-rate back at 0.7309 would show that v003's gain needed the long linear retention.
