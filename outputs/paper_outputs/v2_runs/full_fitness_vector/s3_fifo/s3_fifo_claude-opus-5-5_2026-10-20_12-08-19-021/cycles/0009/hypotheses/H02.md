# H02

Replace the hashbrown-backed `index` with a custom power-of-two open-addressing linear-probe table of `(K, u32)` buckets to cut `get` per-op-time.

## Parent

cycle/0008/v001

## Changes

This is a policy-neutral layout refactor in `src/s3_fifo/mod.rs`. Hit-rate must stay at exactly 0.7309.

- **New `ResidentIndex<K>` struct.** It replaces `index: FxHashMap<K, u32>`:
  - `buckets: Vec<(MaybeUninit<K>, u32)>` with length `n = (2 * capacity).next_power_of_two()`, so the load factor stays at or below 0.5.
  - `mask = n - 1` and `shift = 64 - log2(n)`.
  - An empty bucket is marked by the value word `EMPTY = u32::MAX`. This is safe because the packed value is `(freq << 30) | slot` and `capacity <= SLOT_MASK`, so a live word never equals `u32::MAX`. Tighten the `try_new` guard to `capacity <= SLOT_MASK as usize` to guarantee this.
- **Bucket position.** The home bucket is `(fx_hash(key).wrapping_mul(FX_SEED) >> shift) as usize`, the high bits of a Fibonacci multiply. Use the existing `FxHasher` to produce `fx_hash`.
- **Operations:**
  - `get_mut(&K) -> Option<&mut u32>`: a linear probe that stops on `EMPTY`.
  - `get(&K)`.
  - `insert(K, u32)`: callers only insert absent keys, so this needs no duplicate check. Use `debug_assert` for it.
  - `remove(&K)`: use backward-shift deletion with no tombstones. Walk forward from the freed bucket. Move each following occupied bucket back into the hole if its home position is cyclically at or before the hole. Stop at the first `EMPTY`.
  - `len()`.
- **Safety.** Write each `K` with `MaybeUninit::write` on insert and read it out with `assume_init_read` on remove and shift. Implement `Drop` for `ResidentIndex` so it drops the keys in occupied buckets.
- **Rewire callers.** Point `get`, `put`'s hit check, `packed_mut`, `alloc_with_key` and `release` at the new table. Keep the exact same call counts as today: one probe on a hit, one insert per alloc, one remove per release. `get` stays as: one probe, a freq bump in the probed bucket word, then `slots[i].value`.
- **Leave the ghost alone.** The ghost `ghost_map` stays a `FxHashMap<u64, u32>`, so only the resident index changes.
- **Tests.** Update the tests that read `cache.index[&1]` or `cache.index.len()` to use the new accessors. Add a randomized insert/remove/get stress test against a `std::collections::HashMap` oracle, including runs that wrap around the bucket array. Keep `entry_is_8_bytes` as it is.

## Rationale (optional)

Three cycles in a row have shown that `get` latency follows the memory and instructions the probe touches. hashbrown's control-byte group scan and its SIMD match add a separate metadata load and some branching before the bucket compare. At load 0.5 with `u64` keys, a direct linear probe averages about 1.5 bucket compares inside one or two cache lines. That should lower `get` p50 below 23 ns. If p50 stays flat, the hash table internals are no longer the bottleneck.
