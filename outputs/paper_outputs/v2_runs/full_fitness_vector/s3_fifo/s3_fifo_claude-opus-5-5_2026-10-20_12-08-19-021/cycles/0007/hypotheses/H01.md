# H01

Move the `freq` byte out of the slab `Entry` into a parallel `freqs: Vec<u8>` so `Entry<u64,u64>` shrinks from 16 to 8 bytes, cutting metadata-size in half without changing hit-rate.

## Parent

cycle/0006/v002

## Changes

This is a policy-neutral layout refactor that continues v002's hot/cold split. The parent's `Entry<K, V>` is `{ value: V, freq: u8, _k: PhantomData<K> }`, and alignment pads it to 16 bytes for u64 values. Change it to `{ value: V, _k: PhantomData<K> }`, so `size_of::<Entry<u64,u64>>() == 8`.

- Add `freqs: Vec<u8>` to `S3Fifo`. It is parallel to `slots` and `keys` and indexed by the same `u32` slot id. Allocate it with `Vec::with_capacity(capacity)` in `try_new`.
- `alloc_with_key`: on the `free.pop()` path, set `freqs[i] = 0`. On the push path, call `freqs.push(0)` next to `keys.push` and `slots.push`. `Entry::new(value)` no longer sets a freq.
- `get`: after `let i = *self.index.get(key)? as usize;`, update `self.freqs[i] = (self.freqs[i] + 1).min(MAX_FREQ)` and return `Some(&self.slots[i].value)`. Both loads depend only on `i`, so they can run in parallel. There is still exactly one `index` probe.
- `evict_main`: read and decrement `self.freqs[i]` in place of `entry.freq`.
- `evict_small_inner`: test `self.freqs[i as usize] > 1` in place of `self.slot(i).freq > 1`.
- `release` stays the same (freq is reset on the next alloc).
- Test helper `alloc(key, value, freq)`: write `freqs[i] = freq`.
- `repeated_get_clamps_frequency`: read `cache.freqs[i]`.
- Rename the size test to `entry_is_8_bytes` and assert `size_of::<Entry<u64,u64>>() == 8` and `size_of::<Entry<i64,i64>>() == 8`. Keep the `(u64, u32) == 16` index-bucket assertion.
- In `adaptive_split_keeps_bounds`, add `assert_eq!(cache.freqs.len(), cache.slots.len())`.

Invariants to preserve: eviction order, the `freq > 1` graduation rule, `MAX_FREQ = 3`, the `capacity/64` floor, the ghost ring and its sizing, and the narrow `FxHashMap<K, u32>` index. Hit-rate must come out bit-identical to the parent. Run `h01_split_report` and put the settled `small_size` figure in the insight.

## Rationale (optional)

v002 showed that moving fields `get` does not need out of the slab speeds up `get`. It also showed the metric counts only `size_of::<Entry>`. With `freq` gone, the padding byte goes away and the slab is a dense `[V]`. This tests whether one extra small, independent load on `get` (into a 1-byte-per-slot array that fits in cache) costs less than the parent's 16-byte stride.
