# H01

Lowering the small→main graduation threshold from `freq > 1` to `freq >= 1` on top of v003's adaptive split raises hit-rate on workload-a by keeping once-reused keys out of the ghost-only path.

## Parent

cycle/0001/v003

## Changes

In `src/s3_fifo/mod.rs`, inside `evict_small_inner(&mut self, adapt: bool)`, change the
graduation predicate `if tail.freq > 1 {` to `if tail.freq >= 1 {` (that is,
any key re-accessed at least once while in the small queue moves to main
instead of being demoted to the ghost queue). This matches the original
S3-FIFO paper's rule. Leave the rest of the branch alone: the `main_full` check,
the `evict_main()` call, `push_front` into main, and v003's `grow_small`
adaptation (small_size += 1 / main_size -= 1, bounded by `capacity / 2`, with the
fix-up `evict_main()`) all stay exactly as they are. Leave the ghost-hit path in
`put`, `evict_main`, `MAX_FREQ`, and the `[capacity/16, capacity/2]` clamps unchanged.

When a key graduates, keep its `freq` value. Do not reset it. That way main's
second-chance decrement still treats it consistently with today's graduates.

Update the in-file unit test `small_eviction_promotes_to_main_after_multiple_hits`
if needed so it still passes (it uses two hits, so it should pass unchanged). Add one
test checking that a key with exactly one hit in small ends up in `main`
and not in `ghost` after `evict_small()`. `adaptive_split_keeps_bounds` must keep
passing.

## Rationale (optional)

This was cycle 0001's H01. It was never evaluated because Maven returned HTTP 429s,
not because of anything in the idea. It changes the movement rule, which is a
different lever from v003's capacity split, so the two should stack. A side effect
is that grow-small will fire more often (more graduates arrive while main is full),
which tests whether v003's balance point is sensitive to the graduation rate.
