# H03

Replacing v003's O(capacity) linear scans with a slab plus a `HashMap` key index for residency and a hashed ghost-membership set cuts `get` p50 per-op-time while leaving hit-rate the same.

## Parent

cycle/0001/v003

## Changes

All of this is in `src/s3_fifo/mod.rs`. Eviction and adaptation decisions must stay
exactly as they are in v003, so hit-rate should be identical. Only the data
structures change.

1. Storage: add `slots: Vec<Entry<K, V>>` (or `Vec<Option<Entry<K,V>>>` with a
   `free: Vec<u32>` free list), and change `small` and `main` to `VecDeque<u32>`
   holding slot indices. Add `index: HashMap<K, u32>` (std `HashMap`, or a
   faster hasher such as FxHash written inline in the file, since `Cargo.toml` cannot
   change) that maps each resident key to its slot. `Entry<K,V>` keeps the fields
   `{key, value, freq}` so the `metadata-size` dimension stays at 24 bytes.
2. `get`: `let &i = self.index.get(key)?;` then bump `slots[i].freq` (saturating,
   clamped to `MAX_FREQ`) and return `&slots[i].value`. No scan.
3. `put` update path: look the key up in `index` and overwrite the value in place.
4. Ghost: keep `ghost: VecDeque<K>` for FIFO order, and add `ghost_set: HashMap<K, u32>`
   (a count, which handles duplicate keys) for O(1) membership. On a ghost hit,
   decrement or remove the key in `ghost_set`, and leave the stale VecDeque entry in
   place (lazy deletion). Do not call `retain`. When popping from the back of ghost
   for capacity, decrement that key's count. To keep the ghost bound semantics
   (`ghost_cap` live entries), track `ghost_live` and skip stale entries whose count
   is already 0. Bound the physical deque at `2 * ghost_cap` by compacting when it
   is exceeded.
5. `evict_main` / `evict_small_inner`: work on indices. Recycling a main tail means
   `pop_back` the index, decrement `slots[i].freq`, and `push_front(i)`. Removing a victim
   means removing its key from `index` and returning the slot to the free list (or
   reusing it right away for the incoming entry).
6. Add `K: Eq + Hash` bounds to the inherent `impl` (the `framework::Cache` impl
   already requires them). Do not touch `s3_fifo_jni.rs`. It uses the cache
   with concrete integer types, so the extra bounds are satisfied.
7. Rewrite the in-file unit tests that poke `cache.main` / `cache.small` directly
   (`main_eviction_uses_frequency_second_chance`,
   `small_eviction_promotes_to_main_after_multiple_hits`,
   `ghost_hit_promotes_back_to_main`) to go through small helper methods
   (`in_main(&key)`, `push_main_back_for_test(entry)`) and keep the same asserts.
   Add a test asserting `index.len() == small.len() + main.len()` throughout the
   `adaptive_split_keeps_bounds` loop.

## Rationale (optional)

At size 2048, `get` walks up to 2048 entries in a chained scan, and `put` misses also
pay a full ghost `iter().any` plus `retain`. With hashing, those costs no longer grow
with capacity. This is the only hypothesis in the cohort that targets per-op-time,
and because it keeps decisions identical it also gives a clean re-measurement of
v003's unexplained latency result.
