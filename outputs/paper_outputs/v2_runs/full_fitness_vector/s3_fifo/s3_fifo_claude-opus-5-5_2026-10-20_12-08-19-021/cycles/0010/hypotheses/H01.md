# H01

Restoring linear decrement on the 3-bit `MAX_FREQ = 7` counter while capping each `evict_main` call at a fixed rotation budget recovers 0008 v003's hit-rate gain (≥0.733) without its put-path latency cost.

## Parent

cycle/0009/v001

## Changes

Keep 0009 v001's 3-bit packed layout unchanged (`MAX_FREQ = 7`, `FREQ_SHIFT = 29`, 29-bit slot id), as well as hashbrown/FxHashMap, the `capacity/64` floor, the ghost ring and direct ghost-to-main readmission. Only `evict_main` changes:

1. Replace the halving decay `*e = ((f >> 1) << FREQ_SHIFT) | (*e & SLOT_MASK)` with a linear decrement `*e -= FREQ_ONE`, as 0008 v001 and 0008 v003 do. A saturated key then survives 7 laps again, not 3.
2. Add `const MAIN_ROTATE_BUDGET: u32 = 32;`. Keep a local `rotations` counter in `evict_main`. While `rotations < MAIN_ROTATE_BUDGET`, behave as before: pop the back entry, and if its freq is > 0, decrement it, push it to the front and increment `rotations`; release the first entry found at freq 0. Once the budget is spent, release the next popped entry unconditionally (`self.release(i); break;`), whatever its freq. This bounds per-eviction work to at most 33 pops and leaves eviction behaviour unchanged in the common case where a freq-0 entry turns up within the budget.
3. Add a `#[cfg(test)]` counter `stats.forced_evictions` to `SplitStats`, and print it in `h01_split_report` next to `main_rotations`.

Update the in-file unit tests in `src/s3_fifo/mod.rs` to match:
- Rename `saturated_main_entry_released_after_three_halvings`. It should assert that a lone saturated entry takes 7 decrements and is then released.
- Add a test that fills main with more than 32 entries, all at freq 7, and asserts that a single `evict_main` releases exactly one entry after at most 32 rotations.
- Make `main_eviction_uses_frequency_second_chance` match decrement semantics.

Do not touch `get`, `put`, `evict_small_inner` or the ghost.

## Rationale (optional)

Cycle 0009 showed that hit-rate comes from the number of retention laps, and that halving gave up the laps. Cycle 0008 v003 showed that the cost of linear laps is unbounded drain work when many saturated keys build up. A budget cuts off only that pathological tail, so the claim can be refuted: if hit-rate falls back to ≈0.730, the gain needed the long drains, and if `put` p99 stays at 0008 v003's level, the budget never binds.
