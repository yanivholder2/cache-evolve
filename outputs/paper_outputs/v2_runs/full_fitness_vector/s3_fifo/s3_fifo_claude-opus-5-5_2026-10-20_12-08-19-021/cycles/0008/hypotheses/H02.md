# H02

Enlarging the ghost ring from the initial main size (`3·capacity/4`) to the full `capacity`, with every other lever pinned, raises hit-rate by letting more medium-reuse-distance keys come back as ghost hits straight into main.

## Parent

cycle/0006/v002

## Changes

This is a single policy lever: ghost capacity. Everything else in 0006 v002 stays
byte-identical. That includes the `capacity/64` floor, the `capacity/2` upper
clamp, both trigger rules (one slot per event), the `freq > 1` graduation rule,
`MAX_FREQ = 3`, and the `Entry`/index layout.

- Add `const GHOST_NUM: usize = 1; const GHOST_DEN: usize = 1;`, with the ghost
  length set to `capacity * GHOST_NUM / GHOST_DEN`. In `try_new`, set
  `let ring_len = (capacity * GHOST_NUM / GHOST_DEN).max(1);` and
  `ghost_cap: ring_len`. Do not derive either from `main_size`. This keeps the
  ghost decoupled from the split, which was the confound in 0003 and 0004.
  Size `ghost_map` with `ring_len + 1` as before.
- Leave `ghost_push` and `ghost_take_fp` unchanged. Hole handling and the
  compare-based wrap stay as they are.
- Update `small_floor_is_capacity_over_64` (or its equivalent) to expect
  `ghost_cap == 2048` and `ghost_ring.len() == 2048` at capacity 2048. Keep
  `split() == (512, 1536)`.
- Extend the parent's split-report test as `h02_split_report`. Replay the same
  Zipf streams with ghost length in {`3·cap/4` (parent), `cap`, `2·cap`}. Use a
  test-only `ghost_len` override, mirroring `floor_div`. For each run, print
  `hit_rate`, `settled_small`, `min_small`, `shrinks`, `floor_blocks`, `grows`,
  and the ghost hit count. That shows whether a bigger ghost just pins small at
  the floor (`floor_blocks` rising) or adds real hits.

Rationale: the cross-cycle insights name ghost capacity as the leading untested
cap on hit-rate. Shrinking it was absorbed by the clamps. Growing it in
isolation, with the clamps fixed, has never been tried. Expect a small
`put`-side cost from a larger `ghost_map`. `get` is untouched.
