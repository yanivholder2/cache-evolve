What changed from the baseline `src/s3_fifo/mod.rs`:
- **Main victims go to ghost:** in `evict_main()`, the zero-frequency entry popped from the tail now has its key added to the ghost queue before the loop breaks, instead of being dropped entirely.
- **Shared helper:** a new private `push_ghost(&mut self, key: K)` does the ghost insert. If the ghost queue already holds `main_size` keys it drops the oldest, then adds the new key at the front. Both `evict_small()` (the demotion branch) and `evict_main()` use it, so the ghost size limit is unchanged.
- **Readmitted entries start at `freq = 1`:** in `put()`, the ghost-hit path still removes the key from ghost (`retain`) and puts it at the front of main, but now with frequency 1 instead of 0.
- **Invariants:** the victim leaves main before its key enters ghost, and a ghost hit removes the key from ghost before it becomes resident again, so a key is never in both. `get()` still doesn't move entries, and `evict_main()` still ends because each pass lowers a frequency that can't exceed 3.
- **Tests:** in the file's own unit tests, `main_eviction_uses_frequency_second_chance` now also checks that the main victim (key 3) ends up in ghost. A new `ghost_readmit_gets_freq_one` checks the `freq = 1` readmission.

One issue was already in the baseline and I left it alone, since fixing it is outside H02's changes. At capacity 1 the main queue's size is 0, so a ghost hit can put an entry in main while small still holds one. That makes 2 resident entries against a capacity of 1. If the invariant gate tests capacity 1, it could fail for this reason and not because of H02.
