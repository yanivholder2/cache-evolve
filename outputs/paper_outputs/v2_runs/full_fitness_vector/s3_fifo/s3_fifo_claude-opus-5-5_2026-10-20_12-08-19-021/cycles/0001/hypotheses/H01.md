# H01

Lower the small-to-main graduation threshold from `freq > 1` to `freq >= 1` so any key re-accessed once while in the small queue graduates, raising hit-rate on workload-a.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, `S3Fifo::evict_small()`: change the graduation condition
`if tail.freq > 1` to `if tail.freq >= 1` (equivalently `tail.freq > 0`). This matches
the original S3-FIFO paper, where one reuse during the small-queue stay is enough
to graduate. Cold entries (freq == 0) still get demoted to the ghost queue as before.

Also, when an entry graduates, reset its `freq` to 0 before `self.main.push_front(tail)`.
That way it has to earn its second chance in the main queue rather than bringing
small-queue hits along, which stops a flood of newly graduated entries from
blocking main eviction.

Nothing else changes. Keep these invariants:
- `small.len() <= small_size` and `main.len() <= main_size`, so total residents never exceed `capacity`.
- If main is full, call `evict_main()` before pushing the graduated entry.
- `get()` still only bumps `freq` (saturating at `MAX_FREQ`) and never moves entries.
- Ghost handling is unchanged.

Update the inline unit test `small_eviction_promotes_to_main_after_multiple_hits` only if it
breaks (it shouldn't, since two gets still give freq 2 ≥ 1). Optionally add a test checking that
one `get` followed by a small-queue eviction graduates the key.

## Rationale (optional)

At 2048 entries, the baseline small queue holds 512. Keys reused exactly once within that
window are currently demoted to the ghost queue. On their next access they come back as misses
and only then get admitted to main. Graduating them right away should turn some of those misses
into hits. Resetting `freq` on graduation keeps main eviction from getting more expensive.
