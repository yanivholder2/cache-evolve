# H02

Record main-queue victims in the ghost queue so keys evicted from main can be re-admitted straight to main, raising hit-rate on workload-a.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, `S3Fifo::evict_main()`: right now the loop `break`s when it pops a
zero-frequency tail and drops it, keys and all. Change it so that when the zero-frequency victim is
popped, its key goes into the ghost queue: if `self.ghost.len() >= self.main_size`, call `self.ghost.pop_back()`, then
`self.ghost.push_front(victim.key)`. Then break. Factor the ghost-insert into a
small private helper `fn push_ghost(&mut self, key: K)` and use it from both
`evict_small()` (the existing demotion branch) and `evict_main()`.

Keep the ghost bound unchanged (`main_size` keys). Keep the existing `put()` ghost-hit path
(`retain` removal + admit to `main` front). Also give ghost-readmitted entries
`freq = 1` instead of 0 in `put()`'s ghost branch, so a key that has proven reuse
twice survives one main-eviction pass.

Keep these invariants:
- Never hold more than `capacity` entries across small and main.
- A key is never both resident and in the ghost queue. The victim is removed from `main` before its key goes into ghost, and the ghost-hit path still removes the key from ghost before admitting it.
- `get()` does not move entries.
- `evict_main()` must still terminate. Each pass decrements `freq` and `freq` is bounded by `MAX_FREQ`, so that's unchanged.

## Rationale (optional)

In the baseline, a main-queue victim is forgotten completely. If it comes back soon, it re-enters through the small queue,
needs another reuse there to graduate, and can be demoted again. Ghosting main
victims gives recently popular keys a fast path back to main. This is a different kind of change from H01's
small→main threshold. It changes the main→ghost→main movement.
