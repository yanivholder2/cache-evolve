# H01

Halving the fingerprint ghost ring to half the initial main size, with no other change, will raise hit-rate above cycle/0003/v002 by shortening ghost memory further in the direction that helped in cycle 0003.

## Parent

cycle/0003/v002

## Changes

Change one thing only: the ghost ring's length. In `S3Fifo::try_new`, replace
`let ring_len = main_size.max(1);` with `let ring_len = (main_size / 2).max(1);`,
and set `ghost_cap: ring_len` instead of `ghost_cap: main_size`. Size
`ghost_map`'s capacity from the new `ring_len` (`ring_len + 1`), as it is now.

Leave everything else byte-identical to the parent:
- `ghost_push` and `ghost_take` keep their current hole semantics (a taken
  entry leaves a 0 hole that still uses up a ring position).
- Keep the fingerprint function `fp`.
- Keep the adaptive resize triggers and clamps (`capacity/16` floor on ghost
  hit, `capacity/2` ceiling on grow-small).
- Keep `freq > 1` graduation, `MAX_FREQ`, `get`, and `evict_main`.

Preserve the invariants the existing tests check: `ghost_live <= ghost_cap`,
`ghost_live == ghost_map.len()`, and the ring is never zero-length
(capacity 1 still gives ring_len 1). Because `adaptive_split_keeps_bounds`
reads `ghost_cap`, `ghost_cap` must equal the actual ring length.

If you can, add a `#[cfg(test)]` accessor or a comment-level note on where
`small_size` settles. Do not change the gate-integrity files.

## Rationale (optional)

Cycle 0003 found that v002's ring holes shortened the ghost's effective
memory, that ghost hits got rarer, and that hit-rate rose slightly. This
variant tests ghost capacity as a deliberate one-lever knob. If hit-rate
falls, that shows the parent's ghost length is near the optimum and that the
direction should be reversed (a longer ghost) in a later cycle.
