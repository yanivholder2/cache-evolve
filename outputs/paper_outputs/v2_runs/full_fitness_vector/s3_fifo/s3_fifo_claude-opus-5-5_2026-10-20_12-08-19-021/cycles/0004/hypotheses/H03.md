# H03

Removing the redundant hashing on v002's `put` miss path will cut per-op-time with hit-rate unchanged: hash the key once, use it for both the resident-index probe and the ghost fingerprint, and replace the ring's modulo wrap with a compare.

## Parent

cycle/0003/v002

## Changes

This is a policy-neutral, `put`-path-only refactor. A miss currently hashes
the key up to three times: `index.get(&key)`, then `fp(&key)` inside
`ghost_take`, then `index.insert(key.clone(), i)` inside `alloc`. A small
victim's key is hashed again in `ghost_push`. Steps:

1. Compute `let f = fp(&key);` once near the top of `put`, after the resident
   check. Change `ghost_take(&mut self, key: &K)` to `ghost_take_fp(&mut self, f: u64)`
   and pass `f` in.
2. Collapse the resident probe and the later insert into one hash lookup.
   Use the std `HashMap::raw_entry`-free approach: call
   `self.index.entry(key)` once. On `Occupied`, overwrite the slot value and
   return. On `Vacant`, keep the `VacantEntry` only if borrowck allows it
   across the evictions. Evictions mutate `index` (through `release`), so this
   usually does not compile. In that case, use a cheaper alternative: keep
   `index.get(&key)` for the probe, but add `alloc_with_key(entry)` that
   inserts without the extra `entry.key.clone()` + insert sequence. For
   example, insert the key into `index` first with a placeholder slot, then
   fill the slab, so only one clone remains. Pick whichever compiles cleanly.
   The required outcome is at most one key clone and at most two `index`
   hash operations per miss, down from today's two hash operations plus a
   clone plus one `fp` hash.
3. In `ghost_push`, replace
   `self.ghost_head = (h + 1) % self.ghost_ring.len();` with
   `let n = h + 1; self.ghost_head = if n == self.ghost_ring.len() { 0 } else { n };`.
4. Mark `evict_main`, `evict_small`, and `evict_small_inner` as `#[inline]`.

Do not touch `get` (its body stays byte-identical), the adaptive resize
logic and clamps, `freq > 1` graduation, the ghost length, or hole semantics.
Hit-rate must match the parent exactly. Any difference means a policy bug.
Keep the `fp` definition (`FxHash | 1`) so fingerprints are unchanged.

## Rationale (optional)

Cross-cycle insights say latency gains are real when they trace to removed
work on `put`. This variant removes specific hash and clone work, and leaves
`get` alone so any `get` delta can be read as noise.
