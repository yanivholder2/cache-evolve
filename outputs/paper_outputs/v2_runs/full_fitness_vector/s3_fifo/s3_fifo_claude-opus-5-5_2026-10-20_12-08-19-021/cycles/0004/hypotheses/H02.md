# H02

Freezing v002's split at a static 10/90 small/main ratio while keeping its `freq > 1` graduation will show whether the adaptation itself earns the incumbent's hit-rate margin, and should lower per-op-time by removing the resize branches.

## Parent

cycle/0003/v002

## Changes

The single lever is turning off split adaptation and fixing the split at 10/90.
Keep the graduation rule (`freq > 1`) and the ghost ring exactly as in the
parent. This is the one-lever split of cycle 0003's H03, which changed both
the split and graduation and lost.

Concretely:
1. In `try_new`, compute `small_size` as
   `if capacity == 1 { 1 } else { (capacity / 10).max(1).min(capacity - 1) }`,
   with `main_size = capacity - small_size`. Keep `ring_len = main_size.max(1)`
   and `ghost_cap = main_size`, so the ghost tracks the new main size, as in
   the parent's construction rule.
2. Make the split immutable. In `put`'s ghost-hit branch, delete the whole
   `if self.adaptive() && self.small_size > ...` block, including its fix-up
   evictions. Keep the `if self.main.len() >= self.main_size { self.evict_main(); }`
   check, the alloc, and `main.push_front`.
3. In `evict_small_inner`, delete the `grow_small` computation and the
   `if grow_small { ... }` block. Keep `if main_full { self.evict_main(); }`
   followed by `self.main.push_front(i)` for graduates (`freq > 1`), and keep
   ghosting non-graduates.
4. Remove the `adapt` parameter. `evict_small_inner` can be folded into
   `evict_small`. Remove `adaptive()` if nothing uses it any more. Update the
   header comment.

Do not change `get`, `evict_main`, `MAX_FREQ`, `fp`, `ghost_push`, or
`ghost_take`. The existing tests must still pass:
`small_size + main_size == capacity` still holds, trivially.
`small_eviction_promotes_to_main_after_multiple_hits` at capacity 4 gives
small_size 1, so `put(2)` evicts key 1 with freq 2 into main as before.

## Rationale (optional)

The adaptive-versus-best-fixed question has been open since cycle 0001. If
10/90 with `freq > 1` matches or beats v002's hit-rate, cycle 0003's H03 loss
came from its `freq >= 1` graduation, and the adaptation can be dropped for a
latency gain. If it loses, the adaptation is earning its margin.
