# H02

Move the key out of the slab `Entry` into a parallel key array behind the narrow `(K, u32)` index, cutting metadata-size from 24 to 16 without slowing `get`.

## Parent

cycle/0005/v001

## Changes

This is a policy-neutral layout refactor in `src/s3_fifo/mod.rs`. Keep v001's `capacity/64` floor, the eviction order, graduation, clamps and ghost ring exactly as they are.

1. Change `pub struct Entry<K, V>` to `{ value: V, freq: u8, _k: PhantomData<K> }`. Drop the `key` field. `Entry<u64,u64>` must be 16 bytes, so add an `entry_is_16_bytes` test.
2. Replace `slots: Vec<Option<Entry<K,V>>>` with `slots: Vec<Entry<K,V>>` plus a parallel `keys: Vec<Option<K>>`, both indexed by the same `u32` slot id. Keep `index: FxHashMap<K, u32>` unchanged: the bucket stays `(K, u32)`, 16 bytes for `u64` keys. Also keep `small` and `main` as `VecDeque<u32>` and keep `free: Vec<u32>`.
3. Change `alloc_with_key(key, value)` as follows:
   - Pop or push a slot id.
   - `index.insert(key.clone(), i)`.
   - Write `keys[i] = Some(key)` and `slots[i] = Entry::new(value)`. When `i == slots.len()`, push to both vectors instead.
4. Change `release(i)` to `let k = self.keys[i].take().expect(..); self.index.remove(&k); self.free.push(i);`. The value in `slots[i]` is left in place and overwritten on the next alloc. This needs no `Option` on the hot entry.
5. `get` becomes `let i = *self.index.get(key)? as usize; let e = &mut self.slots[i]; e.freq = (e.freq + 1).min(MAX_FREQ); Some(&e.value)`. This is one probe plus one dependent load, the same as the parent, but without the `Option` discriminant branch.
6. `slot` and `slot_mut` index `slots` directly. `evict_main` and `evict_small_inner` read `freq` from `slots[i]`. Only `release` and `ghost_push` (through `keys[i]`) touch `keys`. Change `ghost_push` callers to pass `keys[i].as_ref().unwrap()` before release, or have `release` return the key `K` so it can be passed to `ghost_push`.
7. Update the `#[cfg(test)]` helpers (`alloc`, `in_main`, `push_*_for_test`) for the new layout.

## Rationale (optional)

cycle 0005 v003 reached 16 bytes but put the entry inline in the hash buckets, which widened them to 24 bytes and slowed `get`. The cycle 0005 insight names the untested alternative: a key-free `Entry` that stays in the slab behind the narrow index. Here the index bucket width and the `get` probe are unchanged from the parent, so `metadata-size` should fall to 16 and `get` should stay at the parent's speed or slightly better, because the `Option` discriminant goes away. Hit-rate must equal v001's 0.7309 exactly. Any deviation means the refactor broke policy neutrality.
