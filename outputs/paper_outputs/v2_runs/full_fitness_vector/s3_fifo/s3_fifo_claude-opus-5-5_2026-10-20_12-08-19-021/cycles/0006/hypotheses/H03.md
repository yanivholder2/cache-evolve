# H03

Halve how strongly the grow-small trigger acts, so main keeps more of the slots that ghost hits win, to raise hit-rate above 0.7309.

## Parent

cycle/0005/v001

## Changes

There is one policy lever, in `evict_small_inner` in `src/s3_fifo/mod.rs`.

- **The lever.** Today every graduation with `adapt && adaptive() && main_full && small_size < capacity/2` moves one slot from main to small (`small_size += 1; main_size -= 1`). Damp this with a counter: add a field `grow_credit: u8`, initialised to 0. When the `grow_small` condition holds, increment `grow_credit`. Only perform the slot transfer and its follow-up `if self.main.len() > self.main_size { self.evict_main(); }` when `grow_credit` reaches `GROW_SMALL_EVERY` (a new constant, set to 2), and then reset `grow_credit` to 0. The graduate itself is still pushed to main exactly as it is now: the `main_full` → `evict_main()` → `main.push_front(i)` path is unchanged.
- **Unchanged.** Leave the ghost-hit shrink path alone, including v001's `capacity/64` floor and its fix-up evictions. Leave the `capacity/2` upper clamp, the `freq > 1` graduation, `evict_main`, and `get` alone too.
- **Pin the ghost.** `ghost_cap` and `ring_len` must stay at the initial `main_size` (`capacity - capacity/4`). Do not tie them to the new split behaviour.
- **Test.** Add a `#[cfg(test)]` test showing that, on a workload with frequent graduations into a full main, `small_size` grows by about half as many slots as the number of qualifying events. Also extend `adaptive_split_keeps_bounds` to cover the new field.

## Rationale (optional)

The two resize triggers are lopsided: "main full on graduation" fires almost constantly. And loosening the floor, which lets the ghost-hit side push the split further toward main, gave the only hit-rate gain since cycle 0001. That suggests workload-a wants a bigger main than the current balance point gives. Lowering the floor further is expected to give diminishing returns, because it only matters while small sits at the floor. Damping the opposing force moves the whole balance point toward main. Halving the trigger is a single, readable change. If hit-rate drops, the grow-small pressure is protecting small's screening role and should be left alone. If it rises, `GROW_SMALL_EVERY` is a new tunable lever. Latency and metadata-size should be flat: one `u8` field and one branch on the graduation path.
