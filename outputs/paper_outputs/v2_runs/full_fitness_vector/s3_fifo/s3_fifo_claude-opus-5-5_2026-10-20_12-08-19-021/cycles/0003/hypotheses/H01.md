# H01

Replace the lopsided split-adaptation triggers with ARC-correct two-ghost signals (small-ghost hit grows small, main-ghost hit grows main) to raise hit-rate on workload-a.

## Parent

cycle/0002/v003

## Changes

All edits are in `src/s3_fifo/mod.rs`. Keep the slab, `index`, and FxHash layout from v003 unchanged.

1. **Add a second ghost for main victims, separate from the existing one.** Add the fields `mghost: VecDeque<(K, u64)>`, `mghost_set: FxHashMap<K, u64>`, `mghost_live: usize`, and `mghost_cap: usize`. Reuse the existing stamp counter `ghost_stamp`, or add a second one. Implement it with the same stamped lazy-deletion scheme as the current ghost: write `mghost_take`, `mghost_pop_oldest_live`, and `mghost_push` mirroring `ghost_take`, `ghost_pop_oldest_live`, and `ghost_push`, including the `retain` compaction once the deque grows past `2 * mghost_cap`. Set `mghost_cap = capacity / 2`, minimum 1. In `evict_main()`, when an entry with `freq == 0` is released, call `self.mghost_push(entry.key)`. Only do this in `evict_main`. Small-queue victims still go to the existing ghost (`ghost_push` in `evict_small_inner`).

2. **Reverse the small-ghost signal.** In `put()`, a hit in the existing small ghost (`ghost_take`) means the key left small before it could be reused, so small was too small. Change the adaptation in that branch: if `adaptive()` and `small_size < capacity / 2`, do `small_size += 1; main_size -= 1;`. Then, if `main.len() > main_size`, call `evict_main()`. The key itself is still inserted into `main` as before: evict from main if `main.len() >= main_size`, then `alloc` and `main.push_front`.

3. **Add a main-ghost signal.** In `put()`, before the small-ghost check, test `self.mghost_take(&key)`. On a hit: if `adaptive()` and `small_size > (capacity / 16).max(1)`, do `small_size -= 1; main_size += 1;`. Then, if `small.len() > small_size`, call `evict_small_inner(false)`. After that, insert the key into `main`, evicting first if main is full. Do **not** consult or modify the small ghost on this path.

4. **Remove the graduation trigger.** In `evict_small_inner`, delete the `grow_small` computation and the block that runs `small_size += 1; main_size -= 1` on graduation. Graduation still evicts from main when main is full and still pushes the graduate to the front of main. The `adapt` parameter can stay, but it no longer controls anything except possibly being unused. Prefix it with `_` or drop it and update its callers.

5. **Invariants to preserve.** `small_size + main_size == capacity`. `small_size >= 1` and `main_size >= 1`. Resident keys are never present in either ghost. A key is in at most one ghost: when pushing to one ghost, call the other ghost's take function first, defensively. Keep the clamps (`capacity / 16` lower bound for small, `capacity / 2` upper bound). Extend the existing in-module tests `adaptive_split_keeps_bounds` and `index_tracks_residency` to assert the bounds on `mghost` as well, and assert that resident keys are absent from `mghost_set`.

## Rationale (optional)

In v003, a ghost hit from *small* grows *main*, and in steady state the graduate-while-main-full rule keeps pushing back toward small. So the split sits wherever the clamps and the two rates balance, not where the reuse distance would put it. ARC grows the side whose ghost was hit. This hypothesis tests whether correctly directed, symmetric signals beat v003's 0.7282. It also tests the cycle 0002 open question of whether a main-victim ghost helps once it is decoupled from the "grow main on small-ghost hit" trigger. If hit-rate drops, the reversed small-ghost direction is the likely cause, and that is itself a useful negative result.
