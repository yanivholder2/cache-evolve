# H01

Keeping ghost keys in a separate fixed-capacity ring-addressed table instead of the shared tagged index will cut `get` p99 and footprint at unchanged hit rate.

## Parent

cycle/0006/v001

## Changes

In the S3-FIFO overlay, the location-tagged index holds small, main and ghost entries in one hash map, which inflates the table and lengthens probe chains on `get`. Move ghost membership into its own map pre-sized to the ghost bound (same capacity as the ring-buffer ghost), storing only the key and a ring sequence number. `get` probes only the small/main index (which stays sized to cache capacity via `with_capacity`). `put` on a miss does one probe of the main index and, only on a miss there, one probe of the ghost table. On ghost eviction (ring overwrite) remove the key from the ghost table only if its stored sequence matches. Preserve exact eviction order, promotion threshold, small ratio and ghost bound so hit rate is identical.

## Rationale (optional)

Cycle 0006 insight: the tagged index doubled footprint and worsened `get` p99, likely from ghost keys in the main index.
