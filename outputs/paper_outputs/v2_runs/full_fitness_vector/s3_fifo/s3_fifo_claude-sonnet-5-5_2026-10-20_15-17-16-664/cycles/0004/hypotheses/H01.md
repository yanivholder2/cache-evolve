# H01

Replace linear ghost/main membership scans in `put` with a hash-set index to cut per-op-time without changing hit rate.

## Parent

cycle/0003/v002

## Changes

In the S3-FIFO overlay source (the file defining the small/main/ghost queues and `put`/`get`/evict), keep the 5% small-queue ratio and all promotion/eviction semantics exactly as in v002. Add a `HashMap<Key, usize>` / `HashSet<Key>` shadow index for each of: ghost queue membership, and small/main key lookup. Maintain the index on every push/pop/remove in the queues (insert on enqueue, remove on dequeue/eviction, including ghost trimming to its size bound). Replace each `iter().any(..)`/`position(..)` linear scan used for lookup in `get`, `put`, and ghost-hit checks with an index lookup; only fall back to a queue scan when the position must actually be removed from the middle. Invariants: identical hit/miss sequence to v002 (hit-rate must remain 0.7275), identical eviction order, no new unsafe. Metadata-size is a fixed reported value (24); do not alter the reported accounting.

## Rationale (optional)

Open question from cycle 3: linear scans dominate `put` cost; this is a mechanism-backed latency change.
