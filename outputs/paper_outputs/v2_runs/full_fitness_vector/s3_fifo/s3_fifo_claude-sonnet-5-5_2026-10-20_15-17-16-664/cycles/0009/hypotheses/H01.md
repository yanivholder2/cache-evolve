# H01

Replacing the linear small/main scan in `find_entry_mut` with a single key-to-entry hash map (queues holding only keys) will cut per-op-time without changing hit rate.

## Parent

cycle/0008/v003

## Changes

In `src/s3_fifo/mod.rs`, `find_entry_mut` does a hash-set check and then a linear `iter_mut().chain().find()` over `small` and `main` on every hit, which is O(n). Replace `resident: FxSet<K>` with `resident: FxMap<K, Slot<V>>` where `Slot { value: V, freq: u8, in_main: bool }`. Change `small` and `main` to `VecDeque<K>` (keys only). `get` and the update branch of `put` become a single `resident.get_mut` probe: bump freq (capped at MAX_FREQ) or replace the value. `evict_main` pops a key from the main back and looks up its slot: if freq>0, decrement and push_front the key; else remove it from `resident` and stop. `evict_small` pops a key from the small back and looks up its slot: if freq>1, set `in_main=true` and move the key into main (evicting main first if full); otherwise remove the slot and ghost the key exactly as now. No stale queue entries exist because removal only happens at queue pop. Keep the 3% small ratio, FxLikeHasher, ghost ring and `ghost_map` logic, MAX_FREQ=3, the promotion threshold (freq>1) and the Cache trait impl unchanged. Update the in-file unit tests so `resident.len() == small.len() + main.len()` still holds. Evictions and hit rate must be identical to the parent.
