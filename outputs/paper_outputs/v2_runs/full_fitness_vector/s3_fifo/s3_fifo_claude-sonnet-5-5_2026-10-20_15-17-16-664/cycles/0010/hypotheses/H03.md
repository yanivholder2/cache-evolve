# H03

Hashing the key once per `put` and reusing the hash for the resident, ghost, and insert probes will cut `put` tail latency from fewer hash computations.

## Parent

cycle/0008/v003

## Changes

In `put`, compute the key hash a single time at entry. Use `raw_entry` or `hash_one` and `from_hash` style APIs (or a pre-hashed wrapper key type with an identity hasher) so the resident-map probe, the ghost-map probe, and the final insertion all reuse that hash instead of rehashing. Do the same in `get` if the map type allows it. Keep policy logic, sizes, thresholds, and eviction order identical, so hit rate must stay bit-identical. Do not bundle in any other change (no pre-sizing and no hasher swap). Only the hash reuse is in scope.

## Rationale (optional)

Insights show that hash-map traffic is the `put` bottleneck. The earlier wins cut probe count. This cuts the hashing cost of the remaining probes.
