# H01

Capping the fingerprint ghost at half the main-queue capacity with batched, push-counted expiry on top of the id-keyed index should raise hit-rate above 0.7222 while keeping put-path p50 at or below the cycle 0008 incumbent's level (hit-rate target: hit-rate dimension).

## Parent

cycle/0008/v001

## Changes

Start from the parent's id-keyed `index` (the `HashMap<K, Slot>` plus `small_head` / `main_head` counters that replace the linear `position` scans). Leave the resident path, the frequency logic, and `evict_one()`'s second-chance rotation unchanged.

1. Ghost capacity: in the code path that pushes an evicted key into the ghost, cap the ghost population at `main_capacity / 2`. When the cap is reached, the oldest ghost fingerprint is dropped before the new one is inserted.
2. Ghost expiry: do not prune ghost entries on every insert. Instead, count pushes and run a single batched prune every `K` pushes (start with `K = main_capacity / 8`) that removes all expired fingerprints in one pass. This is the push-count window from cycle 0007's ghost change, reused here so the cap does not add a per-insert drain.
3. Ghost hit: a ghost hit still admits the key directly to main, and removes its fingerprint from the set, exactly as the parent does.
4. Keep the fingerprint representation (a hash set of fingerprints, not stored keys) so the put-side gain from earlier cycles is preserved.

Invariants: resident hit/miss results for any key must not change. The `index` must stay consistent with both queues after every batched prune. Do not change `Entry`.

Measure hit-rate on workload-a at 2048 first, then on any other trace and capacity available. Report p50 and p99 for put separately from get, and compare get only after a baseline rerun.

## Rationale (optional)

Cycle 0009's ghost cap (v003) gained hit-rate (0.7223) but paid for it with a per-insert drain (put p50 174 ns). Cycle 0007's push-count window addressed the drain cost in isolation but did not test the cap. Combining the two is the cheapest way to test whether the cap's gain survives once its drain cost is batched.
