# H02

Replacing backward-shift deletion in the flat ghost table with tombstones, and sizing the table to keep its load factor at or below 0.5, should cut the put-miss p99 regression seen in cycle 0009's v002 while leaving hit-rate unchanged (per-op-time target: put tail).

## Parent

cycle/0009/v002

## Changes

Start from the parent's flat linear-probing ghost table. The parent's `insert` on a full-ghost put does backward-shift deletion to remove an entry, and that probe work lands on the put-miss tail.

1. Deletion: replace backward-shift deletion with a tombstone marker. On delete, mark the slot as a tombstone rather than shifting the following run. Lookup must skip tombstones and keep probing; insert may reuse the first tombstone seen on its probe path after confirming the key is absent.
2. Rebuild: track live entries and tombstones. When tombstones exceed `capacity / 4`, rebuild the table in place by reinserting live fingerprints into a cleared table of the same capacity. Do this rebuild on the put-miss path only, never on get.
3. Load factor: size the table so the live ghost cap is at most half the slot count (for example, allocate `2 * ghost_cap` rounded up to a power of two). Do not change the ghost cap itself.
4. Keep the fingerprint values and the ghost's eviction order identical to the parent. Hit-rate must match the parent's 0.7195 exactly on workload-a at 2048; any difference is a bug.

Invariants: the same keys are reported present or absent as in the parent at every step. `Entry` and the main/small queues are not touched. Do not change `get()` beyond what is needed to skip tombstones.

Report put p50 and p99 separately, and compare against the parent's 106 / 224 ns numbers from the same run. Also report the ghost table's heap bytes (allocated slot count times slot size) in the insight, since the container-size probe does not see heap-allocated table storage.

## Rationale (optional)

Cycle 0009's insight attributed the put-tail regression to probe work on full-ghost inserts, specifically backward-shift deletion. It also noted that the load factor was never varied. Tombstones plus a lower load factor address both possible causes at once, and the change is policy-neutral, so it should not move hit-rate.
