# H03

Replacing the ghost's exact fingerprint set with a two-hash bit array that is cleared in epochs, instead of expiring individual keys, should remove the per-key ghost drain from the put path and shrink ghost storage while keeping hit-rate within 0.002 of the baseline's 0.716 (container-size and put-path target).

## Parent

baseline

## Changes

Start from the baseline's ghost queue, and replace its key storage with an approximate membership structure. Leave the main and small queues, `evict_one()`, the frequency counter, and the second-chance rotation unchanged.

1. Membership: allocate a bit array of `m = 8 * ghost_cap` bits. For each ghost insert, set two bits chosen from two independent hashes of the key (for example, two seeded multiply-shift hashes). For ghost lookup, test both bits; report present only if both are set.
2. Expiry by epoch: keep a counter of ghost inserts. Divide the stream into epochs of `ghost_cap` inserts. When an epoch ends, clear the entire bit array and start a new one. This replaces per-key expiry, so no insert or lookup walks an expiry structure.
3. Keep the ghost-hit admission rule as in the baseline: a hit in the ghost admits the key to main. Because the array does not remove keys on a hit, clear the two bits for that key on admission only if doing so does not clear bits shared with other keys; otherwise leave them and let the epoch clear them.
4. Do not store keys in the ghost at all. Ghost storage is the bit array only.

Invariants: resident hit/miss results must match the baseline for keys that do not hit a ghost false positive. False positives will promote a cold key to main early; this is the expected cost, and it should be measured rather than suppressed.

Report hit-rate on workload-a at 2048 and any other available trace. Report the whole-structure footprint including the bit array, since `Entry` size is unchanged and the container-size probe may not see heap bytes. Report put p50 and p99 separately and compare against the baseline run from the same session.

## Rationale (optional)

Cycles 0003 through 0005 found that fingerprint storage cut put-side cost, but its remaining cost was per-key expiry bookkeeping and a hash set at container level. An epoch-cleared bit array removes both at the cost of some false positives. This is a different representation from the fingerprint set already tested, and it is untested in the cycle history.
