# H03

Raise the small-queue share of capacity to about 20% of the total budget to lift hit-rate on workload-a at capacity 2048, without changing any per-op code path.

## Parent

baseline

## Changes

This is a capacity-partition change, not a promotion-rule change, so it does not touch the `freq` threshold that cycle 0001 showed to be harmful.

- In the constructor where the S3Fifo capacity is split between the small queue and the main queue, locate the constant that sets the small-queue target size (the baseline's small-queue fraction) and change it to 20% of the total capacity. Main queue gets the remaining 80%.
- Keep the ghost queue sized to the main queue as in the baseline, so its capacity follows the main queue rather than the small queue.
- Leave `evict_small()`, `evict_one()`, the promotion condition (`freq > 1`), `get()` and `find_entry_mut()` untouched.
- Do not add any new fields: `S3Fifo<u64,u64>` must stay at its baseline size so the metadata-size dimension is unchanged.

Invariants to preserve: total resident entries never exceed the configured capacity; the eviction order within each queue is unchanged. Expected effect: a larger small queue absorbs more one-hit wonders before they reach main, so hit-rate on workload-a at capacity 2048 should rise slightly, with per-op-time unchanged because only the split constant moves.
