# H01

Capping the fingerprint ghost at half the main queue's size raises hit rate on workload-a at capacity 2048 while keeping the put-path gain of fingerprint ghosts.

## Parent

cycle/0004/v002

## Changes

Work in `src/s3_fifo/mod.rs` and keep everything else in the parent overlay as it is.

- Add a field `ghost_cap: usize` to `S3Fifo`, set in `try_new` to `(main_size / 2).max(1)`. Replace the `self.ghost_set.len() >= self.main_size` check in `ghost_push` with `>= self.ghost_cap`. This is the only change to the ghost population limit.
- Keep the fingerprint representation, `ghost_set`, `ghost_copies`, and the lazy stale-copy drain in `ghost_pop_oldest` unchanged. Ghost hits in `put` keep removing the fingerprint from `ghost_set` and leave the queue copy stale.
- Bound the physical ghost queue as well. The parent lets stale copies accumulate when the live set is below capacity, because `ghost_pop_oldest` only runs on overflow. Before `ghost.push_back`, while `self.ghost.len() >= self.ghost_cap`, pop from the front: decrement `ghost_copies` for that fingerprint, and remove it from `ghost_set` when its count reaches zero. Preserve the invariant that `ghost_copies` counts match the queue contents.
- Leave `get`, `evict_main`, `evict_small`, `small_size`, `main_size`, `MAX_FREQ`, and the frequency counters unchanged. Entry stays 24 bytes.

Expected effect: fewer keys re-admitted to main from the ghost, so hit rate should move up or stay flat. Put latency should stay near the parent. Record the ghost queue length over the trace to confirm it stays at or below `ghost_cap`. The change is only a win if the hit-rate gain holds on the trace tested and does not trade away put-path cost.
