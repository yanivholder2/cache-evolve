# H03

Combining cycle 0004 v003's side-array frequency counters with v002's fingerprint ghost keeps v003's 16-byte entry and v002's put-path gain, and the two wins compose without losing hit rate.

## Parent

cycle/0004/v003

## Changes

Work in `src/s3_fifo/mod.rs`. Start from the parent overlay, which keeps the per-entry frequency counters in the parallel deques `small_freq` and `main_freq`. Keep those deques, their lockstep invariants, `bump_freq`, `MAX_FREQ`, and the promotion rules unchanged.

Replace the ghost queue with the fingerprint ghost from cycle/0004/v002:

- Remove `ghost: VecDeque<K>`. Add `ghost: VecDeque<u64>`, `ghost_set: HashSet<u64>`, and `ghost_copies: HashMap<u64, u32>`. Add the `fingerprint<K: Hash>(key: &K) -> u64` function using `DefaultHasher`.
- In `put`, replace the `self.ghost.iter().any(...)` check and the `retain` call with this sequence: compute `fp = fingerprint(&key)`, then `if self.ghost_set.remove(&fp)` promotes to main. The stale queue copy stays behind. This is the same as v002.
- In `evict_small`, replace `self.ghost.push_front(tail.key)` with `ghost_push(fingerprint(&tail.key))`. Keep the `freq > 1` branch that moves to main, and keep the `evict_main` call before the push. Add `ghost_push`, `ghost_pop_oldest`, and the ghost capacity check (`ghost_set.len() >= main_size`) exactly as in v002.
- Widen the impl bounds where needed. `K` needs `Hash` for the fingerprint, and `put` already requires `K: Hash` through the framework impl. Keep `Clone` and `PartialEq` as they are.
- Keep `Entry<K, V>` as `{ key, value }` with no freq field, so it stays 16 bytes for `u64`/`u64`.

Expected effect: `Entry<u64,u64>` stays at 16 bytes. Put p50 and tail should drop, as in v002, because the ghost no longer clones keys on eviction. Hit rate should match v002 and v003 (0.7195), since the frequency semantics are unchanged and both incumbents tested the same policy. The container will be larger than either parent. Record the whole `S3Fifo` size, not only `Entry`, and report it next to the get path, which may still carry the indirection cost seen in v003.
