# H02

A per-queue key-to-slot hash index replaces the linear `get()` scan and cuts get p50 on hits without changing eviction order or hit rate.

## Parent

cycle/0004/v002

## Changes

Work in `src/s3_fifo/mod.rs`. Keep the fingerprint ghost, the eviction logic, and the policy exactly as in the parent.

- Add two indexes, `small_index` and `main_index`, of type `HashMap<K, u64>`. Each maps a resident key to a monotonic id. Add a `small_head: u64` and a `main_head: u64`, one per queue. Start each at 0.
- Id scheme: on every `push_front` to a queue, increment that queue's head and store the entry's id as the new head value. For a queue with deque `D` (front is newest), the entry at deque index `i` has id `head - i`. Therefore `index_of(id) = head - id`. Entries only leave a queue from the back, so this mapping never needs to be rewritten for entries that stay.
- `get`: look up the key in `small_index`. If found, compute the index as `small_head - id` and bump `freq` on that entry. Otherwise look up `main_index` the same way. Remove the linear `iter().position` scan.
- `put` for a resident key: use the indexes instead of `find_entry_mut` to find the entry and update its value.
- Every `pop_back` must remove the key from its index. This applies in `evict_small`, in `evict_main` when a zero-frequency tail is dropped, and in the rotation loop.
- Every `push_front` must insert or update the index entry with the new id. This includes the rotation in `evict_main` and in `evict_small` when an entry moves to main, which gives the rotated entry a fresh id.
- Widen the impl bounds to `K: Eq + Hash + Clone`, which the framework impl already satisfies.
- Keep `Entry` as it is. Only the two indexes and the head counters are new state.

Invariants to check: after every operation, each key appears in exactly one index, and that index maps it to the id that makes `head - id` equal to its actual deque position. Add a test that replays a trace and compares `get` results against the parent.

Expected effect: get p50 drops on hits because the scan is replaced by a hash lookup. Hit rate should match the parent exactly. The cost is larger container state and extra hashing on put, so record put p50 and the container size too.
