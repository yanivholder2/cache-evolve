# H01

Adding the id-keyed resident index from cycle/0007/v003 to the push-sequence ghost window of cycle/0007/v002 should cut get p50 from 91 ns toward the 41–46 ns range while hit rate stays at 0.7222 and metadata-size stays at 16.

## Parent

cycle/0007/v002

## Changes

This composes the two directions that cycle 0007 left untested together. Keep the ghost window in `cycle/0007/v002` exactly as it is: the single `ghost: HashMap<u64, u64>`, the `ghost_seq` counter, `ghost_cap = (main_size / 2).max(1)`, the batched `retain` sweep in `ghost_push`, and the sequence-liveness check in `put()`. Do not change `Entry`, the small/main sizing, the `freq` rule, or the promotion and second-chance rules.

Replace the two linear `position` scans on the resident path with the id-keyed index used in `cycle/0007/v003`:

- Add `index: HashMap<K, Slot>` with `Slot { in_small: bool, id: u64 }`, plus `small_head` and `main_head` counters that rise on each `push_front`. A resident at deque position `i` has `id = head - i`, so its position is `head - id`.
- Route every push and pop through four helpers (`push_small`, `push_main`, `pop_small`, `pop_main`) so the index and head counters stay in step with the deques. A pop removes its key from the index. A second-chance re-push in `evict_main()` updates the slot's id.
- `get()`: one index lookup, then `queue.get_mut(head - id)` to bump `freq` and return the value. Remove the two `position` scans.
- `put()` on a resident key: index lookup, then write the value at `head - id`. Keep the ghost-window check exactly as it is in `cycle/0007/v002`.
- Add a test-only `check_indexes` that confirms every index slot matches its deque position, and run it on a seeded trace.

Expected result: hit rate 0.7222 on workload-a at 2048 (unchanged from v002), metadata-size 16, and get p50 well below 91 ns. Report the whole `S3Fifo` container, since the index adds fixed state. If the put-side gain from the ghost window disappears when the index is present, record that the two do not compose.
