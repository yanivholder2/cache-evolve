# H02

Replacing the default SipHash on the resident index with a fixed, dependency-free multiplicative hasher for `u64` keys should lower get p50 below 41 ns while hit rate and metadata-size stay at 0.7195 and 16.

## Parent

cycle/0007/v001

## Changes

This is a constant-factor change to the hashing cost on the get and put hit paths. No eviction, ghost, or promotion logic changes.

- In the S3-FIFO module (not `Cargo.toml`, which is gate-protected), add a small `BuildHasher` implementation and a `Hasher` that folds the key with a fixed odd 64-bit multiplier and a right shift (multiply-shift, for example `h = (x ^ (x >> 32)).wrapping_mul(0x9E37_79B9_7F4A_7C15)`, then take the top bits). It must accept `write_u64` directly and fall back to a byte loop for any other write.
- Use it for the resident key-to-slot map in `cycle/0007/v001` (the single index lookup per hit). If the parent also keeps a ghost hash set, switch that map to the same hasher, but only if it is keyed by `u64` fingerprints.
- Keep the map type, its key and value types, and every call site unchanged, so only the hasher parameter moves.
- Keep `freq` in the index record and the `head - id` access exactly as `cycle/0007/v001` has them.

Expected result: hit rate 0.7195 (identical, since the eviction order is unchanged), metadata-size 16, and get p50 below the parent's 41 ns. Put p50 should also fall or stay flat. Rerun the get-path baseline before crediting any get-latency change, because cycle 0007 showed shared timing noise on get paths whose code was unchanged.
