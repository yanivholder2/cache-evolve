# H02

Replacing the linear ghost-queue scans with an auxiliary hash-set index lowers put p50 and p99 latency without changing hit rate.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, keep the `ghost: VecDeque<K>` as the FIFO order but add a `ghost_index: std::collections::HashSet<K>` field to `S3Fifo`, initialised empty in `try_new()`. Tighten the bounds on the struct and the inherent `impl` from `K: PartialEq + Clone` to `K: PartialEq + Eq + std::hash::Hash + Clone` (the framework trait impl already requires these, so no caller changes). In `put()`, replace `self.ghost.iter().any(...)` with `self.ghost_index.contains(&key)`; on a ghost hit, remove the key from both `ghost` and `ghost_index` instead of `ghost.retain(...)`. In `evict_small()`, when pushing a key onto the ghost, insert it into `ghost_index`; when `ghost.len() >= main_size` and `ghost.pop_back()` runs, remove the popped key from `ghost_index` too. Behaviour must be identical to the baseline: same ghost capacity, same eviction order, same promotion rules. Do not touch `find_entry_mut()` or `get()`.

## Rationale (optional)

The baseline does an O(n) scan of the ghost queue on every put that misses the resident set and an O(n) `retain` on every ghost hit, where n is roughly main_size. A hash index makes the membership test O(1) while leaving the policy decisions untouched, so this hypothesis targets per-op-time only and should show a hit-rate delta of zero.
