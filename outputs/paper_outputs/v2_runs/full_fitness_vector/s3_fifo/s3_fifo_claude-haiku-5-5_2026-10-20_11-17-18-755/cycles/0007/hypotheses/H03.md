# H03

Adding the id-indexed resident lookup to the fingerprint-ghost variant should combine the parent's put-side ghost gain with the index's get and put speedup, lowering per-op-time with hit rate unchanged.

## Parent

cycle/0005/v003

## Changes

This is the first test of the two incumbent edits together. Port the resident index onto the fingerprint ghost, and leave the ghost as it is.

- Add a single key-to-slot index covering both queues, `index: HashMap<K, Slot>`, where `Slot { in_small: bool, id: u64 }`. Add `small_head` and `main_head` counters that rise on each `push_front`. The slot for a resident at deque position `i` has `id = head - i`, so its position is `head - id`. Use the layout in `cycle/0006/v002/attempts/01/overlay/src/s3_fifo/mod.rs` as the reference, including its `push_small`, `push_main`, `pop_small`, and `pop_main` helpers.
- Route every push and pop through those four helpers so the index and head counters stay in step with the deques. A pop removes the key from the index.
- `get()`: replace the two linear `position` scans with one index lookup, then `queue.get_mut(head - id)` to bump `freq` and return the value.
- `put()` on a resident key: replace the two linear scans with the index lookup and write the value at `head - id`. Keep the existing fingerprint ghost check (`ghost_set.remove`) and the ghost-hit promotion path as they are.
- `evict_main()` and `evict_small()` keep their current logic. Their pushes and pops now go through the helpers, so a second-chance re-push updates the slot's id.
- Keep the fingerprint ghost exactly as in the parent: `ghost`, `ghost_set`, `ghost_copies`, `ghost_pop_oldest`, and the compaction rule. Do not add the ghost cap.
- Add a test-only `check_indexes` that confirms the index matches each deque position, and run it on a seeded trace as the reference variant does.

Expected result: hit rate unchanged from the parent (0.7195), per-op-time below the parent's p50 of 91 ns, and metadata-size held at 16. Report the whole `S3Fifo` container, since the index adds fixed state. If the index and the fingerprint ghost do not compose (for example, if the put-side gain disappears), record which of the two is responsible.
