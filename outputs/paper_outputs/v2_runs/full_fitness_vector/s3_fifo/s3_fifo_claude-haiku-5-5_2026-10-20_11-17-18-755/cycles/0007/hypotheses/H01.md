# H01

Moving each resident's frequency counter into its index slot shrinks `Entry<u64,u64>` from 24 to 16 bytes, improving metadata-size while leaving hit rate and the get-path lookup count unchanged.

## Parent

cycle/0005/v002

## Changes

Remove the `freq: u8` field from `Entry` so it is back to `{ key, value }`. Store the counter in the per-key index record that already exists in this variant (the id record that `index = head - id` uses). Add a `freq: u8` field to that record, initialised to 0 in `push_small` and `push_main`.

Update every site that touches the counter so the policy is unchanged:

- `get()`: look up the index record once, bump its `freq` with the existing saturating-min-3 rule, then read the value from the queue at `head - id`. This keeps one hash lookup on the hit path, as the parent already does.
- `put()` on a resident key: read the record from the index and write the value through the queue as before. Do not touch `freq`.
- `evict_small()`: when the tail leaves `small`, read its `freq` from the record it held before `pop_small` removed it. If `freq > 1`, carry that value into `push_main`; otherwise push the fingerprint to the ghost. Make `pop_small` return the removed record's `freq` alongside the entry (or read it first), since the index entry is removed in the same step.
- `evict_main()`: the second-chance loop reads and decrements `freq` from the popped record, and re-inserts the record with the decremented value through `push_main`. The loop breaks on the first entry with `freq == 0`, as now.

Leave the ghost queue, fingerprint logic, small/main sizing, and promotion rules untouched. Keep the `check_indexes` test helper working by comparing only the key and slot fields.

The expected result is a hit rate identical to the parent (0.7195 on workload-a at 2048) and metadata-size 16. Report the whole `S3Fifo` container size as well as `Entry`, because the index record grows by one byte.
