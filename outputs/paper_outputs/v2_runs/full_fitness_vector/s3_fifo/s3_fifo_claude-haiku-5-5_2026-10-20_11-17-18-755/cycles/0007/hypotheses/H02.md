# H02

Expiring fingerprints by push sequence instead of eagerly draining them bounds the ghost to about half the main queue and should raise hit rate without adding per-eviction removal cost on the put path.

## Parent

cycle/0005/v003

## Changes

Replace the three-structure ghost (`ghost: VecDeque<u64>`, `ghost_set: HashSet<u64>`, `ghost_copies: HashMap<u64, u32>`) with a single `ghost: HashMap<u64, u64>` mapping each fingerprint to the value of a `ghost_seq: u64` counter at its last push, plus the `ghost_seq` field itself. Add `ghost_cap = (main_size / 2).max(1)` in `try_new`.

- `ghost_push(fp)`: increment `ghost_seq`, insert `fp -> ghost_seq`. If `ghost.len() > 2 * ghost_cap`, prune with `ghost.retain(|_, seq| *seq + ghost_cap as u64 > ghost_seq)`. This is a batched sweep that runs about once every `ghost_cap` pushes, so its cost is amortised O(1) per push and no fingerprint is removed one at a time on the eviction path.
- A fingerprint is live when it is in the map and its stored sequence satisfies `seq + ghost_cap > ghost_seq`, meaning it was among the last `ghost_cap` pushes.
- Ghost-hit check in `put()`: `ghost.remove(&fp)` returns the stored sequence. The hit counts only if that sequence is still live. Either way the fingerprint is gone afterwards, as now.
- Remove `ghost_pop_oldest` and `ghost_compact`; they are not needed.

This is a deliberate approximation. The window counts pushes, not live fingerprints, so the ghost population can differ slightly from the parent's when hits remove entries. Report the population it actually holds and the hit rate it gives.

Leave `Entry`, the small/main queues, `freq` handling, and the promotion and second-chance rules exactly as the parent has them.

The target is hit rate above 0.7195 on workload-a at 2048 (the 0006/v001 experiment reached 0.7223 with a strict cap). Put-side time should stay close to the parent's 91 ns p50 put, which is the cost the strict drain added in 0006/v001.
