# H02

Replacing the ghost's hash set of fingerprints with a fixed-size open-addressing table should cut put-miss latency and container bytes while leaving hit rate exactly unchanged.

## Parent

cycle/0007/v003

## Changes

Keep the resident index, the two queues, the eviction policy, and the fingerprint width exactly as the parent has them, so every hit/miss decision is identical. Change only the storage of the ghost fingerprint set:

- Replace the ghost's `HashSet` of fingerprints with a `Vec<u32>` (or the parent's fingerprint integer type) of length `next_power_of_two(2 * ghost_capacity)`, with 0 reserved as the empty marker. Store each fingerprint with linear probing.
- Keep the ghost's FIFO eviction order. When the ghost is full and a new fingerprint is inserted, remove the oldest one by backward-shift deletion so no tombstones accumulate. Track the oldest entry with the same ring or queue the parent uses for ordering.
- The ghost-hit check on the put-miss path becomes a probe on the table. It must return the same boolean the parent's `HashSet::contains` returns for every key.
- Do not change the ghost capacity, the fingerprint function, or the promotion/eviction code that calls into the ghost.

Invariants to preserve: the ghost holds at most `ghost_capacity` fingerprints; a fingerprint is removed when it falls off the ghost; resident-key get and put paths are untouched.

## Rationale (optional)

Cycles 0003 through 0005 showed that fingerprint ghost storage is the one ghost edit with a repeated put-side benefit, and cycle 0007's insight names the ghost's hash-set check as the remaining put-miss cost. A flat table avoids per-entry allocation and hashing overhead from the standard set. Because the fingerprints and eviction order are unchanged, hit rate should match the parent exactly, so any gain is purely latency and footprint.
