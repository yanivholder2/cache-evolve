# H03

Capping the fingerprint ghost at half the main queue's capacity should raise hit rate slightly by keeping the ghost from admitting keys to main that are not reused.

## Parent

cycle/0007/v001

## Changes

Keep the parent's id-keyed index, the frequency counter, the fingerprint ghost, and the batched ghost expiry exactly as they are. Change only the ghost's capacity:

- Where the parent sets the ghost capacity, set it to `min(ghost_capacity_parent, main_capacity / 2)`, where `main_capacity` is the main queue's slot budget, computed once at construction. Use integer division.
- When the ghost shrinks, the expiry path should drop the oldest fingerprints until the ghost is within the new cap. Reuse the parent's expiry routine. Do not add a second expiry path.
- Leave the small queue size, the promotion threshold (`freq > 0`), the second-chance budget, and `MAX_FREQ` unchanged.

Invariants to preserve: the ghost never holds more fingerprints than its cap; the index and head counters are unchanged; get and put for resident keys are unchanged.

## Rationale (optional)

Cross-cycle notes record that capping the ghost at half the main queue gained slightly on one trace and only in combination with fingerprints, which is the configuration this parent uses. Enlarging the ghost to full capacity lost hit rate in cycle 0004, so the cap is a direction toward the smaller ghost. Cycle 0007 batched the ghost expiry, which makes a smaller cap cheap to enforce. This hypothesis tests whether the small gain survives on the same trace with the current lineage.
