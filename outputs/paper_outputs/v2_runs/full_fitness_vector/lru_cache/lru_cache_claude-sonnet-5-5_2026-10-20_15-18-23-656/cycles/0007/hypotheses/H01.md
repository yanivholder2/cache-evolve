# H01

Add a ghost fingerprint table of recently evicted probationary keys so that re-referenced evictees are inserted directly into the protected segment, raising hit-rate.

## Parent

cycle/0006/v003

## Changes

In `src/lru_cache/mod.rs` add a field `ghost: Vec<u32>` to `LruCache`, length = next power of two >= capacity (zero-initialised; use 0 as empty and force fingerprints to be nonzero with `| 1`). Compute a per-key hash with `self.map.hasher().hash_one(&key)` (BuildHasher::hash_one) only on the put-miss path. In the eviction branch of `put`, before reusing the victim slot, if the victim is in the probation segment, compute its hash and store `(h >> 32) as u32 | 1` into `ghost[(h as usize) & mask]`. For the new key, compute hash h; if `ghost[h & mask] == fingerprint`, clear that slot and, instead of `push_back(idx, PROB)`, do `push_back(idx, PROT)` followed by the same overflow-demotion step used in `promote` (if `protected_len > protected_cap`, move `heads[PROT]` to PROB MRU). Otherwise keep the existing PROB insertion. Leave `get` unchanged. Preserve all existing unit tests (a ghost hit only happens after an eviction, so they should pass; re-check `hit_protects_from_eviction`). Metadata per node is unchanged; ghost table is a separate array.

## Rationale (optional)

Cross-cycle notes name ghost history as the next structurally different hit-rate lever beyond segment-boundary constants.
