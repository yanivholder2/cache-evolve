# H02

Demoting the protected-segment LRU node to the LRU end (next-to-evict) of the probationary list, instead of its MRU end, will raise hit-rate on the scan-heavy trace.

## Parent

cycle/0005/v003

## Changes

In `LruCache::promote` in `src/lru_cache/mod.rs`, the overflow branch currently does `self.unlink(h); self.push_back(h, PROB);` for the protected head `h`. Add a `push_front(idx, s)` helper that mirrors `push_back` at the head (LRU end) of segment `s`. It must set the segment flag, the prev/next links, `heads[s]`, `tails[s]` when the list was empty, and `protected_len` for PROT. Use `push_front(h, PROB)` in the demotion branch. A demoted node is the coldest protected entry, so it should be the first eviction candidate rather than outliving fresh one-shot scan entries. Keep eviction (`put`), the hasher, u32 links and the segment bit unchanged. Preserve the invariant that `protected_len <= protected_cap` after each promote.

## Rationale (optional)

Demoted nodes currently get a fresh probationary lifetime. The scan-heavy trace should do better if they do not.
