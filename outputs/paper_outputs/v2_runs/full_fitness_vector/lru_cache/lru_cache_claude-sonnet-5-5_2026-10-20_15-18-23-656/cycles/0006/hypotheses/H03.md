# H03

Making `put` on an existing key refresh recency only within its current segment, with no promotion to protected, will improve hit-rate by keeping write-updates from polluting the protected segment.

## Parent

cycle/0005/v003

## Changes

In `LruCache::put` in `src/lru_cache/mod.rs`, the existing-key branch currently calls `self.promote(idx)` after updating the value. Replace this with a new `touch_same_segment(idx)`. If the node is already at the tail of its segment, return at once. Otherwise read its segment `s = segment()`, call `unlink(idx)`, then `push_back(idx, if s { PROT } else { PROB })`. Leave `get` using `promote` so only reads promote probationary nodes to protected. Do not change `promote`, eviction, the hasher or the link layout. Preserve `protected_len` accounting, which `unlink` and `push_back` already handle.

## Rationale (optional)

Only reads signal reuse. Treating overwrites as hits may promote entries that are never read. The tail early return also removes a relink on repeated updates, which may help per-op-time.
