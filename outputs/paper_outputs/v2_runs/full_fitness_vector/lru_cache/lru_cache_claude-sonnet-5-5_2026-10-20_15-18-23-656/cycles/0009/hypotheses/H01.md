# H01

Shrinking the ghost table by another half on top of the halved-ghost variant will keep hit-rate within noise while cutting put tail latency and off-node memory.

## Parent

cycle/0008/v001

## Changes

In the ghost-table construction (where the ghost capacity/slot count is derived from the cache capacity), halve the slot count again relative to the parent (round down to a power of two, minimum 16 slots so tiny caches still work). Do not change the ghost lookup/insert logic, the hash used, or the insertion-position rules. Keep all eviction ordering, segmentation and protected share exactly as in the parent. Read the parent overlay first to find the single constant or shift that sizes the table and change only that.

## Rationale

Open question: how far can the ghost table shrink before hit-rate degrades? Halving was tolerated in cycle 0008; this probes the next step in isolation.
