# H03

Inserting ghost-hit keys at the probation MRU end, rather than the parent's ghost-hit position, will raise hit-rate by giving returning keys a full probation stay before eviction.

## Parent

cycle/0007/v002

## Changes

In `put` of the parent, locate the branch that handles a new key whose hash is remembered by the ghost table. Change its insertion so the node is linked at the MRU (head) end of the probation segment (not protected, and not the LRU end used for cold keys). Cold keys not in the ghost table keep going to the probation LRU end. Do not change the ghost table size, ghost recording, protected share, promotion-on-hit logic, or `get`. If the parent already inserts ghost hits at probation MRU, instead insert them at the midpoint-equivalent: link after the current probation head node (second position), keeping a single extra pointer read only.

## Rationale

Open question in cross-cycle insights: a middle path between cold-end insertion and direct protected promotion (which hurt hit-rate) is untested.
