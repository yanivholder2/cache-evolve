# H03

Make the capped second-chance eviction walk adaptive, capping it at a small number of steps only while recent ghost hits are low, to keep the put tail gain from a capped walk without losing hit-rate.

## Parent

baseline

## Changes

Start from the baseline source and port the second-chance walk in the eviction function. The walk looks for an unreferenced victim from the probation tail and clears reference bits as it passes. Add a cap on the number of steps with an adaptive value. Keep a single `u8` field in the cache struct, `walk_cap`, starting at 2. Every 256 puts, check how many ghost hits occurred in that window. If the ghost-hit count is above a threshold (for example 8), raise `walk_cap` toward 8, so more second chances are given. Otherwise lower it toward 1. When the cap is reached, evict the current tail regardless of its reference bit. Do not change get, promotion, or demotion. Per-node layout stays unchanged, so metadata-size is unchanged.

## Rationale (optional)

A fixed cap cut put p99 but cost hit-rate. An adaptive cap tests whether both can be had.
