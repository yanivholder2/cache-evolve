# H01

Replace the remove-then-insert map sequence in the evicting `put` path with a single combined map operation to lower per-op-time without changing hit-rate.

## Parent

cycle/0009/v001

## Changes

In `put` (the miss path that evicts when full), the current code does a map `remove` for the victim key and then a map `insert` for the new key. Restructure so that the victim's key is removed and the new key is inserted with the fewest hash-map operations possible. For example, probe the map once for the new key (an entry-style or raw lookup), then remove the victim. Reuse the victim's node index for the new key's value. Also avoid the separate `get`-style lookup before insert when the key is already known to be absent. Keep all policy behaviour identical: segmented LRU, ghost-gated insertion position, single-hash ghost path, and the smaller ghost table. Do not change eviction order, promotion/demotion rules, or the ghost record logic. Keep node layout (u32 links) so metadata-size stays at 24. Only touch overlay files, not the gate-integrity surface.

## Rationale (optional)

Cross-cycle notes say map remove and insert dominate put cost, and that node-slot reuse alone did nothing. This tests a structural cut in map ops instead.
