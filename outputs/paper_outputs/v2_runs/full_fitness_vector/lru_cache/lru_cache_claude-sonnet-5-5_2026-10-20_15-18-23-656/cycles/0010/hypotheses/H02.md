# H02

Add a frequency-based admission check at the probation victim, so a candidate whose ghost history is stronger than the victim's replaces it, to raise hit-rate on mixed workloads.

## Parent

cycle/0008/v003

## Changes

In the eviction path of `put`, when the probation tail victim is about to be evicted, consult the ghost filter state for both the incoming key and the victim key. Keep a small saturating counter (2 bits) packed into spare bits of the existing ghost entries. It is incremented whenever a key is re-seen in the ghost table. If the incoming key is not in the ghost table and the victim has counter >= 1, insert the incoming key at the next-to-evict slot, as the existing cold-key rule does. Otherwise, evict the victim and insert normally. Do not promote ghost hits (that failed twice before). Counters are used only to protect victims from cold newcomers. Decay counters by halving when the ghost table wraps. Do not grow node size, so metadata-size stays at 24. Keep `get` untouched.

## Rationale (optional)

Insertion-position and protected-share levers are exhausted. Admission is the open lever for hit-rate.
