# H03

Replacing promotion-triggered tail demotion with a lazy, one-step demotion in the segmented LRU will reduce put p99 and per-op-time without lowering hit-rate.

## Parent

cycle/0002/v001

## Changes

In v001, promotion from probation to protected currently unlinks the node and, if protected is over its cap, immediately demotes the protected tail (second unlink and relink). Change this so the over-cap check is done only in `put` (insertion path), not in `get`: `get` promotion just moves the node to protected head and increments a protected-count; excess is tolerated temporarily. On `put` eviction, if protected count exceeds its cap, demote exactly one protected tail node to the probation head before evicting the probation tail (this pairs the demotion with work `put` already does). Add a fast path in `get` for hits already in protected: skip relinking if the node is within the head position, else standard move-to-head. Preserve eviction victim choice otherwise (probation tail first). Hit-rate may shift slightly; the experiment measures whether it stays at ~0.7241 while get p99 and put p99 drop.
