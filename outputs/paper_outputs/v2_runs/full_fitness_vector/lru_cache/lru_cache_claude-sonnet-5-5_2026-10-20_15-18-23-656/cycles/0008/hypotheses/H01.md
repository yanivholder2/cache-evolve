# H01

Halving the ghost fingerprint table in v002 will cut put-tail cost and side memory while keeping most of its hit-rate gain.

## Parent

cycle/0007/v002

## Changes

In `try_new`, change `ghost_len` from `capacity.next_power_of_two().max(2)` to `(capacity.next_power_of_two() / 2).max(2)`, so the ghost table has roughly capacity/2 slots (`ghost_mask` follows). Nothing else changes: `ghost_slot`, the lookup/clear in `put`, the write on eviction, and LRU-end insertion for unseen keys stay as in v002. Size-only change, so the effect on hit-rate (more ghost collisions) and put time (fewer cache misses on the table) is attributable.
