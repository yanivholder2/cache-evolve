# H01

Splitting the recency list into a probationary segment and a protected segment (SLRU, protected capped at 80% of capacity) will raise hit-rate on the LIRS workload-a trace at size 2048 above the baseline's 0.6652 by keeping one-touch scan keys from flushing keys that are reused.

## Parent

baseline

## Changes

Rewrite `src/lru_cache/mod.rs` (do not touch `lru_cache_jni.rs`; keep the public API `try_new`, `new`, `get`, `put` and the `framework::Cache` impl exactly as they are).

Data structure:
- Keep the arena `nodes: Vec<Node<K, V>>` and `map: HashMap<K, usize>`.
- Add a `seg: u8` field to `Node` (0 = probationary, 1 = protected). If you can, put it in the padding by using `u32` link indices with `u32::MAX` as the "none" sentinel in place of `Option<usize>`, so the node does not get bigger than 48 bytes.
- Replace the single `head`/`tail` pair with two intrusive lists over the same arena: `prob_head/prob_tail` and `prot_head/prot_tail`, plus a `prot_len: usize` counter. Make `unlink(idx)` and `push_back(idx)` take the segment as a parameter (or read `node.seg`) so they update the right list's head and tail.
- `prot_cap = max(1, capacity * 4 / 5)`. With `capacity == 1`, everything stays in probation and the cache acts as plain LRU.

Behaviour:
- `get` hit on a probationary node: unlink it from probation, set `seg = 1`, and push it to the protected MRU end. Increment `prot_len`. If `prot_len > prot_cap`, demote the protected LRU (head) by unlinking it, setting `seg = 0`, and pushing it to the probationary MRU end.
- `get` hit on a protected node: move it to the protected MRU end (same as the baseline promote).
- `put` on an existing key: update the value in place, then apply the same promotion rule as `get`.
- `put` on a new key when `nodes.len() < capacity`: push the new node to the probationary MRU end.
- `put` on a new key when full: the victim is the probationary LRU (head). If probation is empty, which can only happen briefly, the victim is the protected LRU. Remove the victim's key from `map`, reuse its slot in place (as the baseline does), set `seg = 0`, and push it to the probationary MRU end.

Invariants to preserve: `map.len() <= capacity` at all times. Every resident key maps to exactly one linked node, and that node is in exactly one segment. No phantom keys.

Several in-file unit tests assume strict LRU order, for example `eviction_removes_lru`, `get_middle_node_promotes_correctly` and `repeated_get_preserves_eviction_order`. Update them to reflect SLRU semantics, or replace them with SLRU-specific tests. The gate tests in `tests/` and `src/test_utils/` must pass unchanged.

## Rationale (optional)

LIRS traces are built to include loops and scans that are larger than the cache, and plain LRU does badly on them. Requiring a second touch before a key is protected is the cheapest way to resist scans. It adds no per-op cost apart from one branch on the segment tag.
