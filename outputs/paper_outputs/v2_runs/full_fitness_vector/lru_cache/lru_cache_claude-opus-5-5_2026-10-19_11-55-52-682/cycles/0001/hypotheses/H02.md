# H02

Replacing the doubly-linked recency list with a CLOCK (second-chance) ring of reference bits will cut get p50 per-op-time below the baseline's 41 ns and shrink `Node<u64,u64>` from 48 bytes to 24 bytes or less, because a hit stops moving any nodes.

## Parent

baseline

## Changes

Rewrite `src/lru_cache/mod.rs` (do not touch `lru_cache_jni.rs`; keep the public API `try_new`, `new`, `get`, `put` and the `framework::Cache` impl exactly as they are).

Data structure:
- `Node<K, V> { key: K, value: V, referenced: bool }`. Remove `prev` and `next` entirely. The metadata-size bench reports `size_of::<Node<u64,u64>>()`, so this is the main lever for the metadata dimension.
- `LruCache { map: HashMap<K, usize>, nodes: Vec<Node<K, V>>, hand: usize, capacity: usize }`. Drop `head` and `tail`.

Behaviour:
- `get(key)`: look up `idx` in `map`. On a hit, set `nodes[idx].referenced = true` and return `&nodes[idx].value`. Do not change any links or order. This is the hot path being targeted.
- `put` on an existing key: update the value in place and set `referenced = true`.
- `put` on a new key when `nodes.len() < capacity`: push `Node { key, value, referenced: false }` and insert it into `map`.
- `put` on a new key when full: run the clock sweep. Loop: if `nodes[hand].referenced`, clear the bit and set `hand = (hand + 1) % capacity`. Otherwise this slot is the victim, so stop. Remove the victim's key from `map`, overwrite the key and value in place, set `referenced = false`, and advance `hand` by one. A full sweep clears every bit, so the loop always ends within `capacity + 1` steps.
- Use a branch (`if hand + 1 == capacity { 0 } else { hand + 1 }`) instead of `%` in the sweep.

Invariants to preserve: `map.len() <= capacity`. A slot is reused only after its old key has been removed from `map`. No phantom keys.

Update the in-file unit tests that assume exact LRU victim order, for example `eviction_removes_lru`, `access_updates_lru_order`, `put_updates_lru_order`, `get_middle_node_promotes_correctly`, `repeated_get_preserves_eviction_order`, `slot_reuse_after_promotion_and_re_eviction` and `overwrite_mru_at_capacity`. Change them so they check CLOCK semantics instead, and keep the capacity, overwrite and fidelity tests. The gate tests must pass unchanged.

## Rationale (optional)

In the baseline, every hit does an `unlink` plus a `push_back`. That touches up to 3 extra nodes' cache lines in the arena, which dominates `get` time once the hash lookup is done. CLOCK approximates LRU and usually lands within about 1–2 points of its hit rate. So this hypothesis trades a small, measurable hit-rate risk for latency and metadata gains.
