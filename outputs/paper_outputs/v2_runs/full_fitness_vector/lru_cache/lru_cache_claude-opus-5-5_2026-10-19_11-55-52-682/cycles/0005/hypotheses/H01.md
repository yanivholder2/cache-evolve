# H01

Porting cycle 0004 v002's Fx-style hasher and `u32` map values onto v003's packed side-array SIEVE will bring get p50 back to about 27 ns (per-op-time) while keeping the 16-byte node and the exact same eviction order.

## Parent

cycle/0004/v003

## Changes

Start from v003's `src/lru_cache/mod.rs` (Node = `{ key, value }`, policy state in `links: Vec<u32>` with bit 31 = visited, low 31 bits = next, `NIL = 0x7FFF_FFFF`). Make only these representation changes:

1. Copy v002's in-file `FxHasher` verbatim: `FX_SEED = 0x517c_c1b7_2722_0a95`, `add_to_hash` = `(hash.rotate_left(5) ^ w).wrapping_mul(FX_SEED)`, plus the `write`, `write_u8/u32/u64/usize/i64` and `finish` impls. Add `type FxBuild = BuildHasherDefault<FxHasher>;`.
2. Change `map: HashMap<K, usize>` to `map: HashMap<K, u32, FxBuild>`, built with `HashMap::with_capacity_and_hasher(capacity, FxBuild::default())`. Cast to `usize` wherever an index is read from the map (`get`, the existing-key branch in `put`), and insert `idx as u32`.
3. On the eviction path of `put`, drop `let evicted_key = self.nodes[victim].key.clone(); self.map.remove(&evicted_key);`. Use v002's swap instead: `let old_key = std::mem::replace(&mut self.nodes[victim].key, key.clone()); self.map.remove(&old_key);`. That removes one clone per miss.
4. Leave `find_victim`, `push_back`, `next`/`set_next`/`set_visited`, the hand/hand_prev logic and the `capacity >= NIL` guard unchanged. The eviction order must stay bit-for-bit identical, so hit-rate stays exactly 0.7264.
5. Update the in-file tests: use `c.map.get(&n.key).map(|&v| v as usize) == Some(i)` in `check_structure`, cast `cache.map[&k]` to `usize`/`u32` as needed, and add v002's `fx_hasher_distinguishes_keys` test. Keep a `size_of::<Node<u64,u64>>() <= 16` assertion.

## Rationale

Both cycle-4 winners changed only the representation and are orthogonal: v002 is a hashing lever (27 ns get p50, 86 ns put p99) and v003 is a layout lever (16 B node). v003 still uses SipHash, which explains its 33 ns get. This experiment tests whether they stack cleanly or whether the second memory touch per hit (`links[idx]` as well as `nodes[idx]`) erodes the hashing gain once hashing is cheap. If the combined variant measures ≥30 ns get p50, the side array costs real latency.
