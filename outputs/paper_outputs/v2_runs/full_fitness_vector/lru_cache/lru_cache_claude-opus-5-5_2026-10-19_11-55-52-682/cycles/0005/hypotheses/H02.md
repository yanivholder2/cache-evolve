# H02

Replacing `std::collections::HashMap` in Fx-hashed SIEVE with an in-file open-addressing index of `u32` slot ids, where each miss-path `put` reuses one computed hash for both lookup and insert, will cut put p99 and get p50 (per-op-time) with no change in hit-rate.

## Parent

cycle/0004/v002

## Changes

Keep v002's Node layout (`key, value, next: u32, visited: bool`), the SIEVE queue, `find_victim`, `push_back` and the hand/hand_prev logic exactly as they are. Only the key→slot index changes.

1. Remove the `map: HashMap<K, u32, FxBuild>` field. Add `table: Vec<u32>` (buckets hold a node slot index, `EMPTY = u32::MAX`) and `mask: usize`. Size the table to `(capacity * 2).next_power_of_two()` (load factor ≤ 0.5) and keep `len` implicit via `nodes.len()`. Keys live only in `nodes`; the table stores no keys.
2. Add `#[inline] fn hash(key: &K) -> u64` that runs v002's `FxHasher` over the key, then a final avalanche mix (`h ^ (h >> 32)`), because Fx leaves weak low bits and the bucket is `h as usize & mask`.
3. Add `fn find(&self, key: &K, h: u64) -> Result<usize /*bucket*/, usize /*first empty bucket*/>`: linear probe from `h & mask`. Stop at `EMPTY` (returns `Err(bucket)`) or at a bucket whose `nodes[slot].key == *key` (returns `Ok(bucket)`).
4. `get`: `let h = hash(key); if let Ok(b) = find(key,h) { let s = table[b]; nodes[s].visited = true; Some(&nodes[s].value) } else { None }`.
5. `put`: compute `h` once and call `find`. On `Ok(b)`, update value and visited and return. On a miss at capacity, run `find_victim` and unlink exactly as v002 does, then delete the victim's old key from the table with **backward-shift deletion**: hash `nodes[victim].key`, probe to the bucket holding `victim`, set it `EMPTY`, then shift later entries of the cluster back when their home bucket is at or before the hole (standard linear-probing delete with no tombstones). Write the new key into the slot. **Re-probe** for the insert bucket with the saved `h`, because the earlier `Err(bucket)` may have moved after the shift. If no shift touched the cluster, reusing the saved bucket is fine; the implementer can recompute it to be safe. Set `table[bucket] = victim as u32`. When not at capacity, push the node and fill the `Err(bucket)` from the first probe directly.
6. Update the in-file tests: `check_structure` verifies that every linked slot is findable through `find`, and that the number of non-EMPTY buckets equals `nodes.len()`. Add a randomized test with capacities {1,2,3,7,16,1000} that hammers insert/evict and checks every resident key is findable and no evicted key is (this covers the backward-shift deletion).
7. `try_new` keeps the `capacity >= NIL` guard and also rejects a capacity whose doubled power of two overflows.

## Rationale

v002 showed latency is now almost all map work. A miss-path `put` in v002 does three SipHash-free but still full hashbrown probes (`get`, `remove(old)`, `insert(new)`), and each one hashes again. Here, one hash serves the lookup and the insert, and the table is a dense `u32` array (4 B per bucket against 16 B for `(u64,u32)` buckets), so probes touch fewer cache lines. Eviction order is unchanged, so hit-rate must stay 0.7264. Any per-op-time gain or loss is therefore purely the cost of the index structure.
