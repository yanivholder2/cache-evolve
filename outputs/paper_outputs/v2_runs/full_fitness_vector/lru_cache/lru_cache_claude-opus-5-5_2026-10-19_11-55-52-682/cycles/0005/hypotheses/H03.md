# H03

Turning Fx-hashed SIEVE into an S3-FIFO split (10% probationary FIFO, then a 90% main SIEVE, plus a fingerprint ghost table that admits returning keys straight to main) will raise hit-rate above 0.7264 on workload-a.

## Parent

cycle/0004/v002

## Changes

Keep v002's `FxHasher`, the `HashMap<K, u32, FxBuild>` index and the `u32` arena. Change the policy as follows.

1. **Node**: add `small: bool` next to `visited` (it fits in existing padding, so `Node<u64,u64>` stays ≤ 24 bytes; keep the size assertion). `visited` is the S3-FIFO 1-bit frequency.
2. **Two singly-linked queues** sharing `next`. The *small* queue (`s_head`, `s_tail`, `s_len`) is a pure FIFO: pop at head, push at tail, so it needs no hand. The *main* queue keeps v002's `head`/`tail`/`hand`/`hand_prev` SIEVE logic unchanged. Set `small_target = max(1, capacity / 10)`.
3. **Ghost**: `ghost: Vec<u32>`, direct-mapped, size `capacity.next_power_of_two()`. A key's hash `h` (from the map's `FxBuild`, computed once per miss with `BuildHasher::hash_one`) indexes `ghost[(h as usize) & gmask]` and stores the fingerprint `((h >> 32) as u32) | 1`, so it is never 0 (0 means empty). On a ghost lookup hit, clear the entry back to 0.
4. **`get` / existing-key `put`**: unchanged. Set `visited = true`; never relink.
5. **Miss in `put`**: compute `h`. If `nodes.len() < capacity`, push a new node; otherwise call a new `evict() -> usize` that returns a free slot. Then admit the key: if the ghost holds its fingerprint, append it to the **main** tail (`small = false`); otherwise append it to the **small** tail (`small = true`, `s_len += 1`). `visited = false` either way.
6. **`evict()`**: loop:
   - If `s_len > 0 && (s_len >= small_target || main is empty)`, pop the small head `x` (`s_len -= 1`). If `nodes[x].visited`, clear the bit, set `small = false`, append `x` to the main tail, and `continue`. This is the promotion, with no eviction yet. If main had been empty, set `head = tail = x`. Otherwise record `x`'s key fingerprint in the ghost, `map.remove` its key, and return `x`.
   - Otherwise run v002's `find_victim` on main, unlink it using `hand_prev` exactly as v002 does, `map.remove` its key, and return it. Main evictions are **not** written to the ghost (as in the S3-FIFO paper).
   - The loop ends because each promotion shrinks `s_len`, and main eviction always succeeds within `capacity + 1` steps.
7. **Tests**: extend `check_structure` to walk both queues and check that the two lengths sum to `map.len()`, that `small` flags match queue membership, and that `s_len` is correct. Add tests showing that (a) a one-touch scan stays inside the small queue and never evicts a visited main key, (b) a key evicted from small and re-inserted lands in main, and (c) the randomized workload at caps {1,2,3,7,16} keeps the structure valid.

## Rationale

Cycle 4 v001 showed that a ghost grafted onto a single queue only displaces residents, because nothing exists to bypass. Its insight notes said S3-FIFO's ghost pays off only with a probationary queue. Here, one-hit wonders die after a small 10% FIFO residence instead of a full main sweep. That keeps main space for keys with proven reuse, and ghost hits skip probation instead of merely extending a stay. This is the open question flagged in both the cycle-4 insight and the cross-cycle insights. The cost is a second `hash_one` per miss (cheap with Fx) and one random read and write to `ghost`, so a small put-p99 regression is acceptable if hit-rate rises.
