# H01

Adding a rustc-hash-v2-style rotate finalizer to `FxHasher::finish` will spread keys across hashbrown buckets and tags more evenly, which should cut `get` and `put` per-op-time while leaving eviction order bit-for-bit identical.

## Parent

cycle/0009/v001

## Changes

All edits go in `src/lru_cache/mod.rs`.

1. `FxHasher::finish` currently returns the raw product `self.hash`. A single Fx multiply leaves the low bits of the hash depending only on the low bits of the key. hashbrown takes its bucket index from those low bits and its 7-bit control tag from the top bits. So keys that differ only in their high bits (strided block addresses, for example) collide on bucket groups and lengthen probes. Change `finish` to return `self.hash.rotate_left(26)`, the same fix rustc-hash 2.x made. The well-mixed high bits of the product then feed the bucket index, and bits around 31..38 feed the tag.
2. Keep ghost behaviour identical to the parent. Add a helper `#[inline(always)] fn ghost_hash(h: u64) -> u64 { h.rotate_right(26) }`. In every place that derives a ghost slot or fingerprint from `self.map.hasher().hash_one(..)`, apply it to the hash first: the ghost lookup in `put`, both ghost writes in `evict` (small-head eviction and main eviction), and the `in_ghost` test helper. `gslot = (g as usize) & self.gmask` and `fingerprint(g)` then see exactly the pre-change values. This keeps the hit-rate at 0.7314.
3. Leave everything else unchanged: node layout, the `links` and `visited` arrays, `find_victim`, queue logic and map value type.
4. Add a unit test checking that `ghost_hash(hasher.hash_one(&k))` equals the old un-rotated Fx product for a few keys. Keep `fx_hasher_distinguishes_keys` passing.

## Rationale (optional)

Cycles 0008 and 0009 found that the map probe is now the floor for `get` and that map work dominates `put`. Bucket width was the only probe lever tried so far, and widening it hurt. Probe length, which depends on hash quality, has not been touched. This is a representation-only change, so hit-rate should stay identical to the parent. If `get` p50 doesn't drop, the trace's keys already hash well under plain Fx, and the remaining probe cost is memory latency rather than collisions.
