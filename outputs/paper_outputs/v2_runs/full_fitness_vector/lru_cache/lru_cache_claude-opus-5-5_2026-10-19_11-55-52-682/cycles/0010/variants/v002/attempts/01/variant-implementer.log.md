- **Ghost entries record where the key came from.** `fingerprint(h)` is now `(((h >> 32) as u32) | 2) & !1`. It is never 0 and bit 0 is always clear. Keys evicted from the small queue store this value as is; keys evicted from main (by SIEVE) store it with bit 0 set. In `put`, a lookup counts as a hit when `(g & !1) == fingerprint(h)`. The slot is cleared on a hit, as before.
- **Adapting the target.** This happens in `put` before `evict()` runs:
  - A hit on a key evicted from the small queue raises `small_target` by one, up to `max_small`.
  - A hit on a key evicted from main lowers it by one, down to `min_small`.
  - The two new fields are set in `try_new`: `min_small = (cap/50).max(1)` and `max_small = (cap*2/5).max(1)`. The start stays `(cap/10).max(1)`, which at capacity 2048 gives bounds 40–819 and a start of 204.
- **Left unchanged:** a ghost hit still sends the key to the main tail unvisited. The eviction condition, `find_victim`, the ghost size and the memory layout are all the same as the parent.
- **In-file tests:**

  - Existing eviction tests now also check that the source is recorded correctly.
  - New `small_target_bounds` test: checks the bounds and start value at capacities 2048 and 1.
  - New small-queue test at capacity 20: the target goes from 2 to 3.
