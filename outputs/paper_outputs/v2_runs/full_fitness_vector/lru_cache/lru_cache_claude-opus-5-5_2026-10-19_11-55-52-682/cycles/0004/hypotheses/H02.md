# H02

Replacing the default SipHash `HashMap<K, usize>` in singly-linked SIEVE with a `HashMap<K, u32>` using an in-file multiplicative (Fx-style) hasher will cut get p50 per-op-time below 34 ns while keeping hit-rate identical.

## Parent

cycle/0003/v001

## Changes

Edit `src/lru_cache/mod.rs` only. The eviction policy and `Node` layout stay identical, so hit-rate must be bit-for-bit 0.7264 and metadata-size stays at 24.

1. Define a private `FxHasher` in the file: a `struct FxHasher { hash: u64 }` implementing `std::hash::Hasher`. Use `add_to_hash(w) = self.hash = (self.hash.rotate_left(5) ^ w).wrapping_mul(0x51_7c_c1_b7_27_22_0a_95)`. Override `write_u64`, `write_u32`, `write_usize`, `write_i64` and `write_u8` to call it directly. `write(&[u8])` folds 8-byte chunks, then the remaining bytes. `finish()` returns `self.hash`. Do not add a crate, because `Cargo.toml` is off-limits. Define `type FxBuild = std::hash::BuildHasherDefault<FxHasher>;`.
2. Change `map: HashMap<K, usize>` to `map: HashMap<K, u32, FxBuild>`. Construct it with `HashMap::with_capacity_and_hasher(capacity, FxBuild::default())`. Map values become `u32` indices, matching the existing `u32` link width, since capacity is already bounded below `NIL`. Cast to `usize` at use sites in `get`, `put` and `find_victim`'s callers.
3. In `put`, avoid the double probe on a miss. Keep the existing `map.get(&key)` fast path for updates. On the miss path, replace `self.map.remove(&evicted_key)` (which clones the evicted key first) with removal by reference: take `std::mem::replace` of the victim node's key with the new key, then `self.map.remove(&old_key)`. That drops the `evicted_key.clone()`. Keep only the one `key.clone()` needed for the node or the map.
4. Update the test helper `check_structure` and the other tests for `u32` map values, e.g. `c.map.get(&n.key).map(|&v| v as usize)` and `cache.map[&3]` with no `as u32` cast.

Invariants: no `unsafe`. Same eviction order. All existing tests pass after the type adjustments.

## Rationale (optional)

The per-op-time summary is get p50, and on v001 get is just a map lookup plus one bit write. Cycles 0001–0003 showed that node compaction no longer moves latency, and per-op-time has sat at 33–34 for two cycles. So the remaining cost is most likely SipHash-1-3 over a `u64` key. This hypothesis targets the map path on hits, and the clone on misses, directly. That is the "HashMap path" lever that cycle 0003 named as the untested suspect for both get and put latency.
