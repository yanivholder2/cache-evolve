# H01

Adding a fixed-size ghost fingerprint table of recently evicted keys to singly-linked SIEVE, so that keys re-requested after eviction are re-admitted pre-marked as visited, will raise hit-rate on workload-a without growing the 24-byte node.

## Parent

cycle/0003/v001

## Changes

Edit `src/lru_cache/mod.rs` only (the v001 overlay). Keep `Node<K, V>` exactly as it is (`key`, `value`, `next: u32`, `visited: bool`, 24 bytes for `<u64,u64>`). Leave the `node_is_24_bytes` test and all existing tests passing.

1. Add two fields to `LruCache`: `ghost: Vec<u32>` and `ghost_mask: usize`. In `try_new`, size the table to `capacity.next_power_of_two()` slots, all set to `0` (0 means empty), and set `ghost_mask = len - 1`.
2. Add a private helper `fn ghost_hash(&self, key: &K) -> u64` that returns `self.map.hasher().hash_one(key)` (std `BuildHasher::hash_one`, so no new crates). Slot = `(h as usize) & ghost_mask`. Fingerprint = `((h >> 32) as u32) | 1`, so it is never 0.
3. Eviction path in `put` (the `nodes.len() >= capacity` branch): once `find_victim` returns, and before overwriting the victim's key, compute the evicted key's hash and write its fingerprint into the ghost slot. Every victim is unvisited when evicted, which is the point. Overwrite whatever was there, so the table is direct-mapped with no chaining. Do this before `self.map.remove(&evicted_key)`.
4. New-key path in `put` (both the eviction branch and the arena-push branch, after deciding `idx`): compute the new key's hash. If `ghost[slot] == fingerprint`, initialize the new node with `visited = true` and set `ghost[slot] = 0`. Otherwise use `visited = false` as now. Then call `push_back` and `map.insert` as before.
5. `get`, in-place update in `put`, `find_victim` and `push_back` stay unchanged. Hits never touch the ghost table, so get latency should not move.

Invariants: the ghost table never affects map/list consistency (`check_structure` must still pass). A ghost hit only changes the initial visited bit. Add one unit test: capacity 2. Put 1, 2, then 3 (evicts 1 into the ghost), then put 1 again. Assert that node 1 is visited and that the next eviction skips it.

## Rationale (optional)

Cycles 0002–0003 showed that in-queue reuse signals (counters, sweep caps) have run out on SIEVE. The open question is whether a signal from outside the queue helps. This is the S3-FIFO ghost-queue idea with the smallest possible change: a key evicted while unvisited and then quickly requested again was misclassified as one-hit, so it gets one extra pass of protection. The table lives on `LruCache`, not on `Node`, so the metadata-size summary stays at 24.
