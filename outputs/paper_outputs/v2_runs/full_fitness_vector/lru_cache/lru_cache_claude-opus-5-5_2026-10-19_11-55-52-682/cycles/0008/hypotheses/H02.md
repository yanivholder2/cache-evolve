# H02

Recording the fingerprints of SIEVE main-queue victims in the ghost, so that keys returning after a main eviction are re-admitted straight to main, will raise hit-rate over v001's 0.7306.

## Parent

cycle/0007/v001

## Changes

Make these changes in `src/lru_cache/mod.rs`, in `LruCache::evict`, in the main-eviction branch after `let (victim, victim_prev) = self.find_victim();`.

1. Before unlinking the victim, compute `let h = self.map.hasher().hash_one(&self.nodes[victim].key);` and write `self.ghost[(h as usize) & self.gmask] = fingerprint(h);`. This is the same write the small-head eviction path already does, so both eviction sources now feed the same direct-mapped ghost.
2. Leave everything else as it is:
   - Ghost lookup happens before eviction in `put`.
   - A ghost hit clears the slot and admits with full main admission at the main tail, unvisited.
   - The ghost size stays `capacity.next_power_of_two()`.
   - The small target stays at 10%.
   - The bitset VISITED handling, the hand and `hand_prev` maintenance, and the key swap are unchanged.
3. Update the module header comment, which currently says "Main evictions are not recorded in the ghost", to describe the new behaviour.

Tests:
- In `main_sieve_eviction_when_small_drains`, flip the assertion `assert!(!in_ghost(&cache, 1), ...)` to `assert!(in_ghost(&cache, 1), "main evictions are ghosted")`.
- Add a test where a key is evicted from main and then re-`put`. It must land in main (`!is_small`) with its ghost slot cleared.
- `check_structure` and the randomized test must still pass.

## Rationale

This is the one policy probe cycle 0007 still lists as open. v002 showed that a key evicted from main loses its fast path. In v001, such a key re-enters through the 10% small FIFO and must earn a second touch again before it can return to main. Ghosting main victims means a key with proven past reuse that SIEVE evicted only slightly too early (one that comes back while its fingerprint survives) skips probation.

The risk is ghost dilution: main victims will overwrite fingerprints of small-queue victims in the direct-mapped table. The result shows whether a main-eviction reuse signal is worth more than the small-eviction signal it displaces. The hypothesis is refuted if hit-rate is at or below 0.7306. Latency should barely move, because main evictions are a minority of misses and the hash is a cheap Fx multiply on a key already in cache.
