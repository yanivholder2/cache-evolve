# H03

Storing the VISITED flag in a spare bit of the hash map's `u32` value, instead of in a separate bitset, will cut get p50 below v001's 27 ns, because a hit will touch only the map bucket it already probed and `nodes[idx]`.

## Parent

cycle/0007/v001

## Changes

Make all changes in `src/lru_cache/mod.rs`. The map value is currently `u32` holding a slot index of at most 30 bits (capacity is limited below `NIL = 2^30 - 1`), so bit 31 is free.

1. Add `const MVISITED: u32 = 1 << 31;` and `const IDX_MASK: u32 = !MVISITED;`. Remove the `visited: Vec<u64>` field and its allocation, along with `vbit_set`, `vbit_clear`, `vbit_test`, `set_visited`, `clear_visited` and `is_visited`.
2. `get`: use `let e = self.map.get_mut(key)?; let w = *e; if w & MVISITED == 0 { *e = w | MVISITED; } let idx = (w & IDX_MASK) as usize; Some(&self.nodes[idx].value)`. The flag write lands on the map bucket line the probe just read, so the hit path no longer touches a third structure.
3. `put`, existing-key branch: use `map.get_mut(&key)` and set `MVISITED` in the same way, then update `nodes[idx].value`. On the miss path, `map.insert(key, idx as u32)` already inserts with the flag clear, so drop the `vbit_clear` calls on slot reuse and on push. This makes every miss one write cheaper.
4. Small-head pop in `evict`: read the flag with `let e = self.map.get_mut(&self.nodes[x].key).unwrap();`.
   - If it is visited, clear `MVISITED` in place and promote as now.
   - If it is not visited, the key will be evicted. Keep the existing `hash_one` for the ghost fingerprint. The map lookup and the hash are the same cost class, so optionally compute `h` once and use it for both.
5. `find_victim`: on each step, look up the node's flag with `self.map.get_mut(&self.nodes[i].key)`.
   - If it is visited, clear it and advance.
   - If it is not visited, return the victim.
   Because this borrows `self.map` mutably while reading `self.nodes` and `self.links`, split the borrows explicitly (`let map = &mut self.map; let nodes = &self.nodes; let links = &self.links;`). Hand semantics, wrap-to-head, and `hand`/`hand_prev` handling stay identical, so eviction order and hit-rate must match v001 exactly.
6. Everywhere else that reads an index from the map must mask with `IDX_MASK`. This includes the tests (`check_structure`'s `map.get(...).map(|&v| v as usize)` and `cache.map[&k] as usize`). Rewrite the tests' `is_visited(i)` checks through a helper that looks up `map[&nodes[i].key] & MVISITED`. Delete `visited_bitset_sizing_and_ops`. Replace the "no visited bit beyond arena" check in `check_structure` with a check that every map value's index (after masking) is less than `nodes.len()`.

## Rationale

v001's insight says further `get` gains "would need to avoid the separate structure altogether". The node cannot hold the flag without growing past 16 bytes, but the map's `(K, u32)` bucket has a free high bit, and a `get` already pulls that bucket into L1. The trade-off is deliberate: each step of a SIEVE hand sweep and each small-head pop now pays one Fx hash and one map probe instead of one bitset access, so put p99 may rise.

The headline per-op-time summary tracks get p50, and hit-rate must not change because only the flag's storage moves. Metadata stays at 16, and the `LruCache` struct shrinks by one `Vec` header. The hypothesis is refuted if get p50 is not below 27 ns, or if hit-rate differs from 0.7306.
