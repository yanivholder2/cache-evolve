# H01

Halving the direct-mapped ghost on top of v001's VISITED-bitset layout will keep v001's get latency and raise hit-rate to at least v003's 0.7312, because the two changes touch independent state.

## Parent

cycle/0007/v001

## Changes

Make one change in `LruCache::try_new` in `src/lru_cache/mod.rs`: size the ghost table at half its current size. Replace
`let gsize = capacity.next_power_of_two();` with
`let gsize = (capacity.next_power_of_two() / 2).max(1);`
and keep `ghost: vec![0u32; gsize]` and `gmask: gsize - 1`. At capacity 2048 this gives 1024 slots (4 KiB) instead of 2048. The `.max(1)` keeps capacity 1 valid with a single slot and `gmask = 0`.

Do not change anything else. The VISITED bitset, the `links` packing, `find_victim`, the small-queue target (`capacity / 10`), ghost probe-before-evict ordering, full main admission on a ghost hit, and the key swap on eviction all stay exactly as they are in v001. Main evictions stay un-ghosted.

Tests: existing tests should pass unchanged. Add one test, `ghost_is_half_capacity_pow2`, that asserts `ghost.len() == 1024` for capacity 2048, `ghost.len() == 1` for capacity 1, and `gmask == ghost.len() - 1`.

## Rationale

Cycle 0007's continuation recommends exactly this stack. v001 (bitset) changed only where VISITED is stored and kept eviction order identical. v003 (half ghost) changed only ghost recall, and on v002's layout it gained a little hit-rate (0.7312 vs 0.7306) and slightly lowered put p50 through a smaller, cache-friendlier ghost. These should combine with no interaction.

The prediction can be falsified two ways. If hit-rate falls below 0.7306, the v003 gain was noise or depended on layout. If get p50 regresses above 27 ns, the layouts interact. Expected result: hit-rate about 0.731, metadata 16, get p50 at most 27 ns, and put p50 at or below v001's 43 ns.
