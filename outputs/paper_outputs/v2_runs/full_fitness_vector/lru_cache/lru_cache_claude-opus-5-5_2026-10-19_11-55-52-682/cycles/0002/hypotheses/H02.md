# H02

Replacing CLOCK's single reference bit with a 2-bit saturating frequency counter (GCLOCK, max 3, decremented by the sweep) will raise hit-rate on LIRS workload-a at size 2048 above v002's 0.6754, keeping `Node<u64,u64>` at 24 bytes.

## Parent

cycle/0001/v002

## Changes

Edit `src/lru_cache/mod.rs` only (do not touch `lru_cache_jni.rs`; keep the public API and the `framework::Cache` impl). Keep v002's ring arena, `hand`, and in-place slot reuse.

Data structure:
- Rename `Node.referenced: bool` to `freq: u8`. It sits in the same padding byte, so `size_of::<Node<u64,u64>>()` must stay at 24. Keep the `node_is_compact` test asserting `<= 24`.
- Add `const FREQ_MAX: u8 = 3;`.

Behaviour:
- `get` hit: `if node.freq < FREQ_MAX { node.freq += 1 }`. Still no relinking or moving, so the hit path stays a single byte write. Write it branch-free if convenient, e.g. `node.freq = (node.freq + 1).min(FREQ_MAX)`.
- `put` on an existing key: update the value in place and apply the same saturating increment.
- `put` on a new key while the ring has room: push with `freq = 0`.
- `put` on a new key when full (sweep): loop over `nodes[hand]`. If `freq > 0`, decrement it by 1 and advance `hand` with the existing wrap branch. Otherwise it is the victim. Remove the victim's key from `map`, overwrite the key and value, set `freq = 0`, insert into `map`, and set `hand` to victim + 1 (wrapping).
- Termination: each full revolution lowers every non-zero counter by 1, so the sweep ends within `FREQ_MAX * capacity + 1` steps. Add a `debug_assert!` step counter that checks this bound.

Rationale for the choice of 3: one bit cannot tell a key hit once in the last revolution apart from a hot key hit many times, so on a loop larger than the cache the hot keys lose their bit as often as the cold ones. With 2 bits, frequently reused keys survive up to 3 extra revolutions while one-touch loop and scan keys (freq 0) are evicted on the first pass.

Tests: rewrite the bit-specific in-file tests (`access_grants_second_chance`, `put_update_grants_second_chance`, `repeated_get_is_single_bit`, `full_sweep_when_all_referenced`, `slot_reuse_with_second_chance`, `capacity_one`) for counter semantics. In particular, ten `get`s now buy three chances (saturation) instead of one. Add a test where all slots are at `FREQ_MAX` and one `put` must still terminate and evict slot `hand`. Add a randomized test checking `map.len() <= capacity` and that `map[nodes[i].key] == i` for every slot. The gate tests must pass unchanged.

## Rationale (optional)

This keeps v002's cheapest-in-class metadata (24 B) and its relink-free hit path, and targets its weakest dimension, hit-rate, which trails v001 by about 5 points. It also tests the open question about the CLOCK sweep tail: put p99 shows whether the longer worst-case sweep costs anything on this trace.
