# H01

Replacing SIEVE's doubly-linked queue with a singly-linked queue whose hand tracks its own predecessor will shrink `Node<u64,u64>` from 32 to 24 bytes, improving metadata-size while leaving SIEVE's eviction decisions and hit-rate unchanged.

## Parent

cycle/0002/v003

## Changes

Work in `src/lru_cache/mod.rs` of cycle/0002/v003 (SIEVE, `u32` links, `NIL = u32::MAX`).

1. **Node layout.** Remove the `prev: u32` field from `Node<K, V>`. The node becomes
   `{ key: K, value: V, next: u32, visited: bool }`. For `u64,u64` that is 8+8+4+1 = 21 bytes,
   padded to 24. Update the in-module test `node_is_32_bytes` to assert `<= 24` and rename it to `node_is_24_bytes`.

2. **Cache struct.** Add `hand_prev: u32` next to `hand`. It always holds the predecessor of the
   node `hand` points at, or `NIL` when the hand is at `head` or is `NIL`. Keep `head`, `tail`, `hand`, `hand_prev`
   as `u32` so the struct packs tightly.

3. **`find_victim()`** now returns `(victim, victim_prev)`. Start at
   `h = if hand == NIL { head } else { hand }` with
   `p = if hand == NIL { NIL } else { hand_prev }`. Each time the walk advances past a visited node, clear the bit
   and set `p = h; h = node.next`. On wrap (`h == NIL`), set `h = head; p = NIL`. The loop still ends
   within `capacity + 1` steps.

4. **Victim removal in `put()`** (replace the `unlink(victim)` call). Let `nxt = nodes[victim].next`.
   If `victim_prev == NIL`, set `head = nxt`. Otherwise set `nodes[victim_prev].next = nxt`. If
   `victim == tail`, set `tail = victim_prev`. Then set the new hand state: `hand = nxt` and
   `hand_prev = if nxt == NIL { NIL } else { victim_prev }`. Delete the general `unlink()` function,
   which is no longer needed because nodes are only ever removed at the hand.

5. **`push_back(idx)`** sets `nodes[idx].next = NIL`. If `tail == NIL`, it sets `head = idx`.
   Otherwise it sets `nodes[tail].next = idx`. Then `tail = idx`.
   **Invariant:** if `hand_prev == NIL` and `hand == NIL`, the next sweep starts at `head`, which is still correct.
   If the slot being appended was `hand_prev` (possible only when the victim's predecessor was the victim itself,
   at capacity 1), reset `hand = NIL; hand_prev = NIL` before calling `push_back`. Handle capacity 1
   explicitly: the victim is both head and tail, so after removal `head = tail = NIL` and the hand resets.

6. **`get()` / update-in-place `put()`**: unchanged. They set `visited = true` and do no relinking.

7. **Tests.** Update `check_structure` to walk only `next` links. It should check that `tail` is the last
   node and that, when `hand != NIL`, `hand_prev` is either `NIL` with `hand == head`, or a linked node whose
   `.next == hand`. Keep all existing behavioural tests: eviction order must be identical to the parent's, so
   `visited_key_survives_eviction_without_moving`, `hand_resumes_after_victim`, `hand_wraps_to_head` and
   `capacity_one_hand_resets` should pass unchanged apart from the field accesses.

The policy itself does not change. Only the representation does, so hit-rate should match v003 exactly (0.7264).

## Rationale (optional)

SIEVE only removes nodes at the hand and appends at the tail. The hand already walks forward through
`next`, so it can carry the predecessor for free. A back-link is therefore unnecessary. Cross-cycle evidence says
node layout is the dependable metadata lever and that compact nodes also help per-op-time through
locality. This would give the best hit-rate together with the smallest node seen so far (24 B, on par with
CLOCK/GCLOCK).
