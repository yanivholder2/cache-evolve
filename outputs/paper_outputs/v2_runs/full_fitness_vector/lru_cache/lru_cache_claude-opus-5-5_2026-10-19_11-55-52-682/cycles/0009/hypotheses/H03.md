# H03

Storing each value in the map bucket next to its slot index lets a `get` hit touch only the map bucket and the L1-resident VISITED bitset, never `nodes[idx]`, which should lower per-op-time (`get` p50 below 26 ns) and shrink `Node<u64,u64>` to 8 bytes with eviction order unchanged.

## Parent

cycle/0008/v002

## Changes

All changes are in `src/lru_cache/mod.rs`. This is a representation-only change: eviction order, the ghost (full size, fed by small and main evictions), the VISITED bitset, packed `links` and `find_victim` must all stay identical.

1. **New types.** Add `struct Slot<V> { idx: u32, value: V }`. Change the map to `HashMap<K, Slot<V>, FxBuild>`. Reduce `Node<K, V>` to `{ key: K }` and keep it `pub`. Keep the `V` type parameter by adding `PhantomData<V>` only if the compiler requires it; it is fine for `Node<K, V>` to be `struct Node<K, V> { key: K, _v: PhantomData<V> }`. The arena stays `nodes: Vec<Node<K, V>>`, so the hand and small-queue pops still read keys by index.

2. **`get`.** Use disjoint field borrows so the immutable map borrow and the bitset write can coexist:
   ```rust
   let s = self.map.get(key)?;
   let i = s.idx as usize;
   let w = &mut self.visited[i >> 6];
   let bit = 1u64 << (i & 63);
   if *w & bit == 0 { *w |= bit; }
   Some(&s.value)
   ```
   Write the code inline like this rather than calling `&mut self` helpers, which would break the borrow.

3. **`put`, existing key.** Use `if let Some(s) = self.map.get_mut(&key) { s.value = value; set the VISITED bit for s.idx via the visited field directly; return; }`.

4. **`put`, miss with reuse.**
   - `x = evict()`.
   - `old = mem::replace(&mut nodes[x].key, key.clone())`.
   - `self.map.remove(&old)`, dropping the old value.
   - `links[x] = NIL | flags`, then `vbit_clear(x)`.

5. **`put`, miss with push.** Push `Node { key: key.clone() }`.

6. **Map insert.** Both miss paths finish with `self.map.insert(key, Slot { idx: idx as u32, value })`. Move `value` into the insert. Do not write it into `nodes`.

7. **Tests.**
   - Update the in-file tests that read `c.map[&k]` or `c.map.get(..).map(|&v| v as usize)` to use `.idx`.
   - Change `node_is_16_bytes` to assert `size_of::<Node<u64,u64>>() <= 8`.
   - `check_structure` must still check map/slot agreement through `.idx`.
   - Add a test that overwriting a value on a full cache and then evicting another key keeps every surviving value correct.

8. **Header comment.** Update it to describe the new layout.

Keep `#[derive(Debug)]` working: `Slot<V>` needs `Debug`, and `V: Debug` is already a bound. Do not touch `lru_cache_jni.rs`. If it names `Node` fields or `map` value types, stop and keep the public surface it uses.

## Rationale (optional)

Cycle 0008 found the hit path near its floor at "one map probe plus one value line". The value line is the `nodes[idx]` read on a separate, scattered cache line. Moving the value into the hashbrown bucket that the probe has already loaded removes that second scattered miss. The flag stays in the index-addressed bitset, so v003's mistake is avoided: the SIEVE hand and small pops still never hash. The miss path is unchanged: `remove(&old)` and `insert` were already happening, and the buckets get bigger by 8 bytes. The `put` tail should therefore hold. The risk is that larger buckets make probes slightly slower. If `get` p50 does not drop, the value line was not the bottleneck.
