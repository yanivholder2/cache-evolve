# H02

Adding a TinyLFU-style frequency duel at small-queue exit will raise hit-rate above the S3-FIFO plateau of 0.7312. An unvisited small-head key whose count-min frequency estimate exceeds that of the SIEVE hand's main victim is admitted to main in place of that victim.

## Changes

All edits are in `src/lru_cache/mod.rs`. Keep the ghost, its sizing, main-eviction ghosting, the VISITED bitset, packed `links` and the 16-byte `Node` as they are.

1. **Frequency sketch.** Add a field `sketch: Vec<u64>` that holds 4-bit counters, 16 per word, and is used as a 4-row count-min sketch. Give each row `w = next_power_of_two(capacity).max(16)` counters (`w/16` words per row, 4 rows, about 4 KiB at capacity 2048). Also add `sketch_mask: usize`, `sample: u32` and `sample_limit: u32 = 10 * capacity`.
   - Derive the 4 row indices from the 64-bit Fx hash `h` the code already computes: `idx_r = (h.rotate_left(16 * r) as usize ^ (h >> 32) as usize * r) & sketch_mask` for r = 0..3. Any cheap, distinct mixing per row is acceptable.
   - `fn freq_incr(&mut self, h: u64)`: add 1 to each of the 4 counters, saturating at 15, then `sample += 1`. When `sample >= sample_limit`, age the sketch: halve every counter (`word = (word >> 1) & 0x7777_7777_7777_7777`) and set `sample /= 2`.
   - `fn freq_est(&self, h: u64) -> u8`: return the minimum of the 4 counters.

2. **Where to count.** Keep the hot hit path free of extra hashing:
   - In `put`, on a miss, call `freq_incr(h)` with the hash that is already computed for the ghost lookup.
   - In `get`, and in `put`'s existing-key branch, call `freq_incr(self.map.hasher().hash_one(key))` only when the VISITED bit goes from 0 to 1, inside `set_visited`'s `!vbit_test` branch. Repeated hits on a key that is already visited do no sketch work.

3. **The duel.** It lives in `evict`, in the small-head pop branch, when the popped node `x` is unvisited and `self.head != NIL`, so main is non-empty:
   - Compute `hx = hash_one(&nodes[x].key)`. This hash is needed for the ghost anyway.
   - Call `find_victim()` to get `(victim, victim_prev)`. Clearing VISITED bits as the hand walks is acceptable, because a real main eviction would do the same.
   - Compute `hv = hash_one(&nodes[victim].key)`.
   - **If `freq_est(hx) > freq_est(hv)`:** `x` wins.
     - Unlink `victim` from main exactly as the existing main-eviction code does: update head/tail/hand/hand_prev and clear its link.
     - Record `fingerprint(hv)` in the ghost.
     - `set_small(x, false)` and `push_back_main(x)`.
     - Return `victim` as the freed slot.
   - **Otherwise**, evict `x` exactly as today: ghost `fingerprint(hx)`, set its next to NIL, return `x`.
     - The hand has already moved past the visited nodes it cleared. Leave `hand`/`hand_prev` pointing at `victim`, which is still linked, so the next main eviction resumes from it. This needs `find_victim` to have left `(hand, hand_prev)` consistent. If it has not, assign `self.hand = victim as u32; self.hand_prev = victim_prev;` before returning.
   - Factor the existing main-unlink sequence into a helper, `fn unlink_main(&mut self, victim: usize, victim_prev: u32)`, so the duel and the normal main path share it.

4. **Invariants.**
   - `s_len` is decremented once per pop, as now.
   - The map still holds the freed slot's key. The caller in `put` swaps the key and removes the old one, unchanged.
   - `check_structure` must keep passing, and `randomized_workload_preserves_structure` must pass with the duel enabled.
   - Some existing tests encode exact small/main membership. Adjust them only where the duel legitimately changes the outcome. With counters at 1 apiece, ties go to eviction of `x`, so most of these tests should keep their current outcomes.
   - Add a test: a key put three times, each separated by enough other inserts that it is evicted from small, wins the duel against a fresh main entry. Also add a test checking that aging halves the counters.

## Rationale (optional)

Cycles 6–8 showed that S3-FIFO knobs and ghost sizing have plateaued, and that main capacity is the scarce resource. The open-questions list names frequency-aware admission (TinyLFU) as the next structural signal. The ghost only remembers whether a key was seen once recently. The sketch remembers how often it was seen across a window of about 10×capacity, and it guards main's admission against victims that are colder than the candidate. If hit-rate does not move, the plateau holds even against frequency signals on workload-a. Expect a small `put` p50/p99 cost from the extra hash and sketch work. The `get` path changes only on its first hit.
