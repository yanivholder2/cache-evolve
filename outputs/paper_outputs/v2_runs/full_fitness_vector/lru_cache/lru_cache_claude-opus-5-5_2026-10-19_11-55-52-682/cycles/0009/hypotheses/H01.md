# H01

Halving the direct-mapped ghost on top of cycle/0008/v002's main-eviction ghosting will stack the two small hit-rate gains, lifting hit-rate strictly above 0.7312 with no metadata or latency cost.

## Parent

cycle/0008/v002

## Changes

In `src/lru_cache/mod.rs`, change only the ghost sizing in `LruCache::try_new`:
replace `let gsize = capacity.next_power_of_two();` with
`let gsize = (capacity.next_power_of_two() / 2).max(1);` (so 1024 slots at
capacity 2048; capacity 1 still gets a 1-slot ghost and `gmask = 0`). Keep
`gmask = gsize - 1`.

Leave everything else exactly as in v002:
- small-head unvisited evictions and SIEVE main victims (in `evict`) both
  still write `fingerprint(h)` into `ghost[(h as usize) & gmask]`;
- the ghost lookup in `put` still happens before `evict`, and a ghost hit
  still clears the slot and admits the key straight to the main tail
  (unvisited);
- the VISITED bitset, packed `links`, 16-byte `Node`, Fx hasher, and
  `find_victim` stay unchanged.

Update the module's header comment to say the ghost is half-size. All
existing unit tests should still pass. Small capacities (1, 2, 3, 4) are
used in tests that check `in_ghost(...)` right after one eviction, and
nothing else writes the ghost in those steps, so the smaller table cannot
cause a collision there. Check `capacity_one` and `ghost_hit_admits_straight_to_main`
anyway. Add one test asserting `c.ghost.len() == 1024` for capacity 2048.

## Rationale (optional)

Cycle 0008 showed a half ghost (+0.0006 on v001's layout) and main-eviction
ghosting (v002) each giving a small gain. Its continuation asked for one
combined check before ghost probing is closed. The open risk is that a
smaller table is diluted more by main victims. If the combination does not
beat 0.7312, that settles it: the effects interfere, and ghost tuning on
workload-a is done.
