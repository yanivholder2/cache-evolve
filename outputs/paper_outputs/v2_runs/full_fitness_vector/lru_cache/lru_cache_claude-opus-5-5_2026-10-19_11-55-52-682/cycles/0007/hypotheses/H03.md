# H03

Halving the direct-mapped ghost from `capacity.next_power_of_two()` to `(capacity / 2).next_power_of_two()` slots, which shortens how far back a returning key can be recognised, will raise hit-rate and lower put latency on S3-FIFO.

## Parent

cycle/0005/v003

## Changes

In `src/lru_cache/mod.rs`, `try_new`: change the ghost sizing from
`let gsize = capacity.next_power_of_two();` to
`let gsize = (capacity / 2).max(1).next_power_of_two();`, so capacity 2048 gives 1024 slots.
`ghost: vec![0u32; gsize]` and `gmask: gsize - 1` follow automatically.

Change nothing else. The fingerprint function, the lookup before eviction in `put`, the clearing
of the ghost slot on a hit, ghost recording only on small-queue unvisited eviction, the
`small_target = capacity / 10` split, the node layout and the Fx hasher all stay as they are.
Because the ghost is direct-mapped, a smaller table means more overwrite collisions, so older
small-queue evictions are forgotten sooner. That is the intended "shorter reach" filter.

Adjust any unit test that assumes a specific ghost size, such as small-capacity tests using
`in_ghost`. `.max(1)` keeps capacity 1 valid (gsize 1, gmask 0). Make sure
`ghost_hit_admits_straight_to_main` still passes at capacity 4 (gsize 2). If it collides, pick
test keys that land in distinct slots rather than changing the policy.

## Rationale (optional)

Cycle 0006 v003 doubled the ghost and made it 2-way associative. It lost hit-rate (0.7288 vs
0.7306) and put p99 got worse (101 vs about 88 ns), and the cycle insight concluded that the
ghost's bounded reach acts as a useful filter. This is the opposite test along the same axis:
if shorter reach helps, hit-rate should rise above 0.7306. The half-size table should also put
less cache pressure on the random ghost probe in `put`. Refuted if hit-rate drops, which would
mean the ghost size of 1x capacity is already the optimum.
