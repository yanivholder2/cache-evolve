# H01

Moving the VISITED bit out of the 8 KB `links` array into a dense L1-resident `u64` bitset will cut `get` latency in the 16-byte-node S3-FIFO without changing its eviction order or per-node metadata, targeting per-op-time.

## Parent

cycle/0006/v002

## Changes

In `src/lru_cache/mod.rs`:

- Add a field `visited: Vec<u64>` to `LruCache`, allocated in `try_new` as
  `vec![0u64; (capacity + 63) / 64]` (for capacity 2048 that is 256 bytes, which stays hot in L1).
  Add helpers `#[inline(always)] fn vbit_set(&mut self, i)`, `vbit_clear`, `vbit_test`, which use
  word `i >> 6` and bit `i & 63`.
- Remove the `VISITED` constant from the `links` word. `links` now holds only `SMALL` (bit 30) and
  the 30-bit forward link. Keep `LINK_MASK`/`NIL` unchanged so the capacity checks still hold.
  Rewrite `set_visited`, `clear_visited` and `is_visited` to use the bitset.
- `get`: do a map probe, then `vbit_set(idx)`, then return `&self.nodes[idx].value`. The hit path
  should no longer touch `links` at all. Make the write conditional, setting the bit only when
  `vbit_test` is false, so repeated hits on hot keys do not dirty the word.
- `put` existing-key path: same change (bitset set, value write).
- `put` miss path: when a slot is (re)initialised, clear its bit explicitly with
  `vbit_clear(idx)`. That covers both `links[x] = NIL | flags` on reuse and the push path. The new
  `flags` value is just `SMALL` or `0`.
- `evict` small-head pop: test and clear the bit through the bitset. The logic is otherwise unchanged.
- `find_victim`: keep the same hand walk over `links` for the next pointer, but test and clear
  VISITED in the bitset. Hold a local `&mut self.visited` alongside `links`, which is fine because
  the borrows are of disjoint fields. Preserve the exact order: test → if unvisited return
  `(h, p)`; else clear → advance → wrap to head on NIL.
- Update the tests' `is_visited` uses and `check_structure` as needed. Keep the
  `node_is_16_bytes` test.

Invariants: the eviction order must match v002 exactly, so hit-rate should stay at 0.7306.
`Node<u64,u64>` stays 16 bytes. Do not change the ghost, `small_target` or the hasher.

## Rationale (optional)

v002's insight attributes its `get` regression (29 vs 26 ns) to a cold hit touching two cache lines
(`links[idx]` + `nodes[idx]`). A 256-byte bitset is effectively always cached, so the second touch
becomes an L1 hit. This tests the "can VISITED avoid the extra get line" open question from a
different angle than putting it back inline. Refuted if `get` p50/p99 do not improve over v002.
