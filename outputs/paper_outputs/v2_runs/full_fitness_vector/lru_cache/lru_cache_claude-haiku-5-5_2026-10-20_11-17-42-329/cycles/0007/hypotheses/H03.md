# H03

Pack the PROTECTED and REFERENCED flags into the top two bits of each node's `prev` field and drop the separate `flags` byte, so `Node<u64,u64>` shrinks from 32 to 24 bytes on the metadata-size dimension with hit-rate unchanged at 0.7058.

## Parent

cycle/0006/v002

## Changes

Change the `Node` layout to `key: K, value: V, prev: u32, next: u32` and remove the `flags: u8` field. Define `const IDX_MASK: u32 = 0x3FFF_FFFF`, `const NIL: u32 = IDX_MASK`, `const PROTECTED_BIT: u32 = 1 << 31`, and `const REFERENCED_BIT: u32 = 1 << 30`. Store the flags in the top two bits of `prev`.

Add small inline helpers on `Node` or as free functions: `prev_idx(&self) -> u32` returns `prev & IDX_MASK`, `set_prev_idx(&mut self, idx)` preserves the flag bits, and `is_protected`, `is_referenced`, `set_referenced`, `clear_referenced`, and `set_protected(bool)` read and write the two bits. Route all existing reads and writes of `prev`, `next`, and `flags` through these helpers. `next` needs no flags and stays a plain `u32` holding an index or `NIL`.

In `try_new`, change the capacity cap from `u32::MAX` to `IDX_MASK as usize - 1` (so indices stay below `NIL`), and update the comment and the log message to match. Keep `NIL` semantics for `prob_head`, `prob_tail`, `prot_head`, `prot_tail`.

Keep the hot paths clean. `get` only sets the REFERENCED bit (`prev |= REFERENCED_BIT`, with no mask) and reads the value, so it does no index masking. `select_victim`, `demote_prot_head`, `unlink`, and `push_back` keep their current logic and only change how they read and write flags and indices. Do not change any policy: `protected_cap`, the second-chance rescue, the single retry in `demote_prot_head`, and the `REFERENCED` clear points stay identical, so hit-rate must stay at 0.7058 on workload-a at 2048.

Keep the `framework::Cache` impl and the test module behavior unchanged. Update the top-of-file comment to describe the packed layout.

## Rationale (optional)

Cycle 0003 v002 reached a 24-byte node by dropping link discriminants, and cycle 0002 showed that packing a flag into spare index bits shrank a node at no hit-rate cost. Cycle 0006 v002 still carries a 32-byte node because of the padding after the flags byte. This variant removes that padding without changing the policy. The main risk, based on cycles 2 to 4, is that masking on every index access slows get or put, so compare the get p50 against v002's 35 ns and do not credit the change unless the per-op-time summary holds.
