# H01

Replacing the protected-head rotation in cycle/0003/v001 with a flag-clear retry removes the extra unlink and push from the demotion path and lowers per-op-time, while keeping hit-rate near 0.71.

## Parent

cycle/0003/v001

## Changes

Keep the single bounded second chance on the protected side, but change how it is taken. In the protected-segment demotion branch, where v001 currently unlinks a referenced protected head and pushes it to the protected MRU end, instead clear the head's referenced flag and retry demotion on the next candidate, using a loop bounded to one retry per eviction. Do not move any node pointers for the rescued head; it stays in place and is only demoted on its second visit if it is still unreferenced. Make no changes to `get()` or to the hit path: the referenced flag is set exactly where v001 sets it today. Node layout and `LruCache` fields stay unchanged, so metadata-size should match the parent at 40. Preserve the existing invariants that the protected and probationary lengths stay consistent after each eviction and that a rescued key is never dropped without being demoted or evicted exactly once.

## Rationale (optional)

The cycle 0003 insight for v001 attributes its per-op cost to the extra unlink and push taken when a referenced protected head is demoted. The rescue's hit-rate benefit comes from delaying demotion, not from moving the node, so a flag-only retry should keep the benefit while removing the list surgery. The result also tests whether the `get` movement seen in v001 was caused by that path or by layout noise.
