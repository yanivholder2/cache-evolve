# H02

Writing the REFERENCED bit on a hit only when it is still clear lowers get p50 on workload-a by skipping a redundant store to the node's cache line.

## Parent

cycle/0008/v001

## Changes

In `src/lru_cache/mod.rs`, change the hit path in `get` so it reads the packed `prev` word first and performs the store only when `REFERENCED_BIT` is clear. Concretely, replace `node.set_referenced();` in `get` with a conditional: if `node.prev & REFERENCED_BIT == 0`, call `set_referenced()`, otherwise do nothing. Make the same change to the existing-key branch of `put`, where `node.set_referenced()` follows the value overwrite. The value write in `put` stays unconditional.

Keep `set_referenced` as the single place that sets the bit, so `REFERENCED_BIT` remains set only through that helper. Keep the `link_index` masking and all list code unchanged. The map lookup, the arena indexing, and the eviction logic are untouched, so hit-rate should be identical to the parent.

Expected effect: on a trace with many repeat hits to the same keys, most hits find the bit already set, so the store is skipped and fewer dirty writes hit the arena. The insight should report get p50 and p99 against the parent and say whether the change moved get, since the gain is expected to be small.
