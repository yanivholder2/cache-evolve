# H03

Replacing the arena links with one CLOCK ring and a per-slot 2-bit reference counter shrinks Node<u64,u64> from 24 to 16 bytes at a small hit-rate cost on workload-a at 2048.

## Parent

cycle/0008/v001

## Changes

In `src/lru_cache/mod.rs`, remove the `prev` and `next` link fields from `Node`, so a node holds only `key` and `value`. Store the per-slot metadata in a parallel `refs: Vec<u8>` owned by `LruCache`, parallel to `nodes`. Use the low two bits as a saturating reference counter, 0 to 3.

Remove the two segment lists and the `prot_head`, `prot_tail`, `prot_len`, `prob_head`, and `prob_tail` fields. Add a `hand: u32` field that indexes the ring.

- `get`: look up the index in `map`, then increment `refs[idx]` up to 3 and return the value.
- `put` on an existing key: overwrite the value, then increment its counter the same way.
- `put` on a new key below capacity: push the node onto `nodes` and `refs`, set its counter to 0, and insert into `map`.
- `put` on a new key at capacity: advance `hand` over the ring. For each slot, if its counter is non-zero, decrement it and move on. Stop at the first slot with counter 0. Remove its key from `map`, reuse that slot for the new key with counter 0, and set `hand` to the next index.

Keep the `FastBuildHasher` map and the `framework::Cache` impl unchanged. The `link_index`, `INDEX_MASK`, and `NIL` items can go, along with their callers. `try_new` keeps its capacity check.

Report the parallel `refs` storage in the insight as unmeasured by the Node-size metric, since it is a heap allocation outside the struct. The insight should give hit-rate and metadata-size against the parent, and say whether the trade is worth it.
