# H02

Narrowing the arena links and map values of the cycle/0004/v001 segmented cache to `u32` with a sentinel should cut `Node<u64,u64>` from 40 to 32 bytes without changing hit-rate (targets metadata-size).

## Parent

cycle/0004/v001

## Changes

Layout-only change to the segmented overlay of cycle/0004/v001, in `src/lru_cache/mod.rs`. No policy change.

- Replace `NIL: usize = usize::MAX` with `NIL: u32 = u32::MAX`.
- Change `Node.prev` and `Node.next` to `u32`. Change `prob_head`, `prob_tail`, `prot_head`, and `prot_tail` to `u32`. Change the map to `HashMap<K, u32>`.
- Keep `Node.flags` as a separate `u8` (`PROTECTED`, `REFERENCED` unchanged). Keep `prot_len` and `capacity` as `usize`. Expected node layout: key 8 + value 8 + prev 4 + next 4 + flags 1, padded to 32 bytes.
- In `try_new`, reject `capacity > u32::MAX as usize` with `log::error!` and return `None`, as cycle/0002/v003 does. Add a comment that every arena index fits in a `u32` after that check.
- Write the `as usize` and `as u32` casts inline at the existing index sites only, and keep the number of casts close to the current count. Do not add hoisted or helper accessors: cycle/0004/v002 showed they slow both `get` and `put`.
- Leave `get()`, `put()`, `select_victim()`, `demote_prot_head()`, `unlink()`, and `push_back()` logically identical, apart from the type changes.
- Keep the flag-only retry logic and the single rescue exactly as in v001. All existing tests must pass unchanged.

Expected effect: hit-rate stays at 0.7058 (layout is policy-neutral, as seen in cycle/0002/v003). metadata-size drops from 40 to 32. The main risk is `get` slowing from the width conversions, which happened in cycle/0002/v003 and cycle/0003. Measure `get` p50 against v001's 46 and keep the change only if the metadata gain does not cost more per-op time than it saves in the score.
