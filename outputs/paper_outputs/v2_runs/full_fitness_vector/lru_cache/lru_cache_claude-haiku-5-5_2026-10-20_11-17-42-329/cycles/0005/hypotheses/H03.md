# H03

Removing the sketch update from `get()` in the shared-hash admission cache should bring `get` back near baseline cost while the put-side admission decision keeps its hit-rate gain (targets per-op-time).

## Parent

cycle/0004/v003

## Changes

Single-function change to the admission overlay of cycle/0004/v003, in `src/lru_cache/mod.rs`.

- In `get()`, delete the `self.record(key_hash(key));` call. After the change, `get()` is only the map lookup, `unlink`, `push_back`, and returning the value, as in the baseline.
- Frequency is now counted only on `put()`, which already calls `record(hash)` once per put, for both new keys and overwrites. Keep that call as it is.
- Keep unchanged: `SketchHasher`, `key_hash`, `sketch_index`, `estimate`, the 4-bit counters and their halving, `sample_limit`, the admission comparison in `put()`, and the `Node` layout (48 bytes).
- Update the doc comment on `get()` and the module header to say that only puts feed the sketch, and why: hits no longer pay for hashing.
- Add one unit test: a key read many times with `get` but never written is not admitted over a hot resident key with the same put count. This documents the new behaviour and keeps the admission path covered. Keep every existing test passing.

Expected effect: `get` p50 should fall from v003's 50 toward the baseline's 41, and `put` should stay about 72. hit-rate may drop a little from 0.696, because keys that are only read no longer gain frequency. If it drops below about 0.69, the trade is not worth keeping. metadata-size stays at 48.
