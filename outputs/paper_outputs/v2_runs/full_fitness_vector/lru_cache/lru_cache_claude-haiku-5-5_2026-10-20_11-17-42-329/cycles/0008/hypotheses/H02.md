# H02

Performing the miss-path `put` with one key-map hash instead of two, by folding the existing-key check and the insert into a single `HashMap::entry` call, will lower `put` p50 and p99 on cycle/0006/v002 without changing hit-rate.

## Parent

cycle/0006/v002

## Changes

The parent's `put` path calls `map.get` to test for an existing key and then `map.insert` on a miss, so every miss hashes the key twice through `FastBuildHasher`. Change `put` only:

- Replace the `map.get` / `map.insert` pair with one `self.map.entry(key)` call. On `Occupied`, run the existing overwrite branch unchanged (update the value, set REFERENCED, leave the list alone). On `Vacant`, do the insertion.
- Because the vacant entry borrows the map, eviction cannot run while the entry is held. For a vacant key at capacity, first call `select_victim()` and record the victim's key, then take the entry, insert the new node at the probationary head as the parent does, and remove the victim's key and node. Keep the victim choice and the relink order identical to the parent so that policy is unchanged.
- Leave `get`, `select_victim`, `demote_prot_head`, `unlink`, `push_back`, and `FastBuildHasher` untouched. Do not change the hasher's `finish()`; cycle 0007 showed extra finish-step work costs per lookup.
- Handle capacity 1 explicitly: if the new node would be the only node in the list, keep the parent's order of operations.

Invariants: hit-rate must be exactly 0.7058 on workload-a at 2048, since the eviction sequence should be identical. Node and `LruCache` sizes must not change. Report `put` p50/p99 and `get` p50/p99 against the parent in the same run; `get` should be flat.

## Rationale (optional)

Cycle 0006 showed that hashing on the key map is a real hot-path cost. The parent still pays for it twice on every miss, and the put path is the one that has not been reduced yet.
