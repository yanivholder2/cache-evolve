# H01

Splitting the list into a probationary and a protected segment (SLRU) will raise hit-rate on workload-a by keeping one-hit-wonder keys from evicting re-referenced keys.

## Parent

baseline

## Changes

In `src/lru_cache/lru_cache.rs`, replace the single HEAD/TAIL list in `LruCache` with two intrusive lists over the same arena: a probationary list and a protected list. Add `prob_head`, `prob_tail`, `prot_head`, `prot_tail`, a `prot_len` counter, and a per-node `in_protected: bool`. Keep `capacity` and the public `try_new`/`new`/`get`/`put` signatures and the `framework::Cache` impl unchanged.

- `put` for a new key: if the arena has room, allocate a slot and push it to the tail of the probationary list. If full, evict the head of the probationary list when it is non-empty, otherwise the head of the protected list. Reuse the evicted slot as today, and remove the evicted key from `map`.
- `put` for an existing key: update the value in place and treat it as a hit (see `get`).
- `get` on a probationary node: unlink it from the probationary list and push it to the tail of the protected list, setting `in_protected = true`. If the protected list then exceeds `max(1, capacity * 4 / 5)`, demote its head to the tail of the probationary list. `get` on a protected node: unlink and re-push to the protected tail, as the baseline does.
- Keep `unlink`/`push_back` helpers generic over a segment selector, or write one helper per segment. Do not add `unsafe` or external crates. Preserve the existing `debug_assert!` on map length. Update the existing unit tests only if they depend on strict global LRU order; add one test showing a scan of one-hit keys does not evict a key that was read twice.

Do not modify `lru_cache_jni.rs`, `Cargo.toml`, `src/lib.rs`, `tests/`, `src/test_utils/`, or `src/bin/`.

## Rationale (optional)

The baseline insight says the only knob is capacity, and workload-a is a LIRS trace with scan-like segments. Segmenting by reuse should trade a small per-op cost on `get` for a higher hit rate, and should leave metadata size roughly unchanged apart from one flag per node.
