# H03

A doorkeeper that refuses a key's first sighting at capacity raises hit rate on workload-a at 2048 by keeping one-hit scan keys out of the cache, and adds cost only to misses.

## Parent

cycle/0008/v001

## Changes

In `src/lru_cache/mod.rs`, add a doorkeeper of saturating `u8` counters that is consulted only on the `put` miss path at capacity. Leave the `get` path, the existing-key `put` branch, and `select_victim` unchanged.

Add two fields to `LruCache`: `door: Vec<u8>`, initialised in `try_new` to length `(capacity * 2).next_power_of_two()` and filled with zeros; and `door_ops: usize`, starting at 0. Compute the slot as `door_slot(&key) = hash & (door.len() - 1)`, where `hash` is `FastBuildHasher.build_hasher()` fed with `key.hash(&mut h)` and then `h.finish()`. Use the existing `FastHasher`; do not add a new hash function.

In `put`, after the existing-key branch returns and before the new-key branch, check `if self.nodes.len() >= self.capacity`. If so, compute `slot = door_slot(&key)`, read `seen = door[slot]`, and set `door[slot] = seen.saturating_add(1)`. Increment `door_ops`. If `seen == 0`, the key is seen for the first time, so return from `put` without inserting it or evicting anything. If `door_ops >= 10 * capacity`, zero the whole `door` array and set `door_ops = 0` as an aging step; do this after the admission decision so the current key is still judged on its pre-reset count.

Below capacity, the doorkeeper is not consulted and every new key is inserted as before. Keep the `framework::Cache` impl and `try_new`'s capacity check unchanged, and keep `Node<u64,u64>` at 24 bytes. Report the `door` allocation size alongside the struct size in the insight, since the metadata-size dimension does not count it.

The insight should report hit rate against cycle/0008/v001 (0.7058), the `put` p50 and p99 against the parent (since `put` now hashes on every miss at capacity), and the `get` numbers, which should not move because the get path is untouched. If the hit rate rises, say whether the gain comes from rejected one-hit keys or from aging.
