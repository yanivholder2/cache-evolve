# H01

Inserting new keys at the probationary eviction end instead of the MRU end raises hit rate on workload-a at 2048 by evicting one-hit scan keys before older probationary keys.

## Parent

cycle/0009/v001

## Changes

In `src/lru_cache/mod.rs`, keep the 9/10 `protected_cap()` unchanged and add a second insertion path for the probationary list. Add `push_front(idx)` that links a node at the probationary head (`prob_head`), setting `next` to the old head and `prev` to NIL, updating the old head's `prev` index via `set_prev_idx`, and setting `prob_tail` to the node when the list was empty. It must keep the packed `PROTECTED_BIT` clear and leave `REFERENCED_BIT` as it is.

In `put`, the new-key branch currently ends with `self.push_back(idx, false);`. Change that call to `self.push_front(idx)` (probationary, unprotected). Do not change the existing-key branch, the rescue path in `select_victim` (which still uses `push_back(head, true)`), or `demote_prot_head` (which still uses `push_back(victim, false)`, so demoted protected nodes keep MRU placement).

`select_victim` stays as it is. A new key inserted at the head is the next eviction candidate, so it survives only if a `get` or overwrite sets its reference bit before the next miss at capacity. Keep the single second chance for the probationary head unchanged.

Keep `link_index`, `get`, the hit path, `try_new`, and the metadata layout unchanged, so `Node<u64,u64>` stays 24 bytes. Keep the `debug_assert` on `prot_len` and `map.len()`.

The insight should report hit-rate against cycle/0009/v001 (0.7091) and `put` and `get` p50 and p99 separately, and note that the win should come from scan resistance on workload-a. If hit rate drops, the insight should say whether the loss comes from new keys that are re-referenced after one miss.
