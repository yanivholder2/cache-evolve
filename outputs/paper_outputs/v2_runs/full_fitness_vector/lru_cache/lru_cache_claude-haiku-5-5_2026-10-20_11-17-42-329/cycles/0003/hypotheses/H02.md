# H02

Replacing v003's `Option<u32>` links with a plain `u32` NIL sentinel shrinks `Node<u64,u64>` from 32 to 24 bytes, improving metadata-size with no change to hit-rate.

## Parent

cycle/0002/v003

## Changes

Keep v003's arena design, eviction policy, and move-to-MRU behaviour in `get()` and `put()` unchanged. Change only the link representation.

1. Define `const NIL: u32 = u32::MAX;` in `src/lru_cache/mod.rs`.
2. In `Node<K, V>`, change `prev: Option<u32>` and `next: Option<u32>` to `prev: u32` and `next: u32`, initialised to `NIL`.
3. In `LruCache<K, V>`, change `head: Option<u32>` and `tail: Option<u32>` to `head: u32` and `tail: u32`, initialised to `NIL`.
4. In `try_new`, tighten the bound to `capacity >= u32::MAX as usize` (so an index never equals `NIL`). Keep the existing log and `None` return.
5. Rewrite `unlink`, `push_back`, `get`, and `put` to compare with `NIL` instead of matching on `Option`. For example, `unlink` becomes `if prev != NIL { self.nodes[prev as usize].next = next } else { self.head = next }`. Keep the `as usize` cast at each arena index, since indexing requires it.
6. In `put`, the arena-full branch reads `self.head` directly, and the `expect` on `head` goes away, since `head` is now a `u32` that is non-`NIL` whenever the arena is full.

Invariants to preserve: a node's `prev`/`next` must be `NIL` when detached; `head == NIL` iff the list is empty; the key stays in `map` exactly while its node is linked. The `debug_assert!(self.map.len() <= self.capacity)` stays.

Do not change `get()`'s relink behaviour, `put()`'s slot reuse, or the eviction order. This is a pure representation change, so hit-rate must match v003 exactly.

Do not edit `tests/`. The `node_has_no_padded_flag`-style size check, if added, belongs in the module's own `#[cfg(test)]` block, not in `tests/`.

## Rationale (optional)

v003 (cycle 0002) showed that narrowing to `u32` cut the node, but it still carries `Option<u32>`, whose discriminant adds 4 bytes per link, so each node is 32 bytes. Two `u32` links plus `K` and `V` in a `u64,u64` node come to 24 bytes. The v003 insight notes that `get` slowed from the width conversions. Removing the `Option` match on every link access may recover some of that cost. The hypothesis is that the node-size gain is real, and that the sentinel removes at least part of the regression.
