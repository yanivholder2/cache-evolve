# H03

Shrinking the arena links from `usize` to `u32` will cut `Node<u64,u64>` from 48 to 32 bytes and lower metadata-size, with the baseline eviction policy and hit-rate unchanged.

## Parent

baseline

## Changes

Keep the single recency list and the move-to-MRU behaviour on hit exactly as in the baseline. Change only the node and index representation.

- `Node<K, V>`: change `prev` and `next` from `Option<usize>` to `Option<u32>` (or to a `u32` sentinel of `u32::MAX` if that is simpler). Keep `key` and `value` unchanged. The resulting `Node<u64,u64>` is 8 + 8 + 8 + 8 = 32 bytes.
- `LruCache`: change `head` and `tail` to `Option<u32>`. Change `map: HashMap<K, usize>` to store `u32` node indices. Change `nodes` indexing with `as usize` at each access site, and keep the `unlink` and `push_back` logic otherwise identical.
- `try_new(capacity)`: return `None` (with the existing `log::error!` pattern) when `capacity > u32::MAX as usize`, so every index fits. Do not change the public signatures of `new`, `get`, `put`, or the `framework::Cache` impl.
- Keep the arena slot reuse on eviction: `put()` still reuses `victim` as the new slot and does not touch the free-list logic.
- Do not add any new fields and do not change the eviction order.
- Update the existing unit tests only where they reference `usize` indices directly. The tests in the baseline module should otherwise pass unchanged.

Expected trace: metadata-size should drop from 48 to 32 bytes for `Node<u64,u64>`. Hit-rate on lirs workload-a at size 2048 should match the baseline 0.665 exactly, since the policy is unchanged. Per-op-time may improve slightly from the smaller node footprint in the arena, but this is a secondary effect and is not the target.
