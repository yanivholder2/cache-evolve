# H01

Replacing v001's relink-on-hit promotion with a lazy referenced bit will keep the segmented hit-rate gain while cutting get and put per-op-time.

## Parent

cycle/0001/v001

## Changes

Keep the probationary/protected split and `protected_cap()` (capacity * 4 / 5), but stop relinking on hits.

- `get()`: instead of calling `promote(idx)`, set `nodes[idx].referenced = true` and return the value. No list pointers are touched.
- `put()` on an existing key: set the value and `referenced = true`; do not call `promote`.
- `put()` on a miss with a full arena: pick the victim with a bounded rescue. Look at `prob_head` (or `prot_head` if the probationary list is empty). If it is referenced, clear the bit and move it to the protected tail via `push_back(idx, true)`; if that overflows `protected_cap()`, first demote the protected head to the probationary tail with `referenced = false`. Allow at most one such rescue per miss; after it, evict the current probationary head regardless of its bit (clear the bit on reuse). This keeps the eviction cost O(1) per miss.
- Reuse the victim slot as before and set `referenced = false` on the new entry.
- Node layout: `in_protected` already exists. Store `referenced` so that `Node<u64,u64>` stays at or below the baseline 48 bytes (for example, pack it into the top bit of `prev`, since indices are far below 2^63). Do not add a separate padded bool.
- Preserve `unlink`/`push_back` for the rescue and demotion paths, and keep the `debug_assert!` on `prot_len <= protected_cap()`.

Expected trace: lirs workload-a at size 2048 should keep hit-rate close to v001's 0.724; get p50 should fall toward the baseline 41 ns, and put p50 should fall below v001's 84 ns.
