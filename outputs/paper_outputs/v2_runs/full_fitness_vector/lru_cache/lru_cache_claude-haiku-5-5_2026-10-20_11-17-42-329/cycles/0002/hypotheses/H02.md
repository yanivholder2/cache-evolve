# H02

Capping v002's second-chance eviction scan at two reprieves per miss will lower put p99 per-op-time while keeping the referenced-bit hit-rate gain.

## Parent

cycle/0001/v002

## Changes

Keep the single-list layout, the `referenced` bit on hit, and the overwrite path that only sets the bit. Change only the victim search.

- `find_victim()`: replace the unbounded `loop` with a loop that performs at most `MAX_REPRIEVES = 2` rescues. Each rescue checks `head`; if it is referenced, clear the bit, `unlink` it, and `push_back` it, then continue. If the head is still referenced after two rescues, clear its bit and return it as the victim. This bounds the work on a miss to at most three head inspections.
- Keep the `debug_assert!(self.head.is_some(), ...)` precondition and the `expect` on the head.
- Keep `put()` as is: the victim slot is reused, and `referenced` is set to `false` on the new entry.
- Node layout: v002 added a `referenced: bool` that pads `Node<u64,u64>` from 48 to 56 bytes. Fold the bit into the top bit of `prev` (or of `next`) so `Node<u64,u64>` returns to 48 bytes. Do not keep a padded bool field.
- Leave `get()` unchanged: it only sets the bit and does no relinking.
- Update the doc comments on `find_victim` and the module header to describe the bounded scan.

Expected trace: put p99 should fall from v002's 171 ns toward the baseline range, and metadata-size should return to 48. Hit-rate should stay near 0.675, since the bounded scan may evict a few referenced entries that v002 would have spared.
