# H02

Add an exact per-normal-bucket "foreign items" counter to `SegmentCore`, so `promotion_get` skips the probing-bucket scan when that bucket holds no key from its left neighbour, lowering cycle-6 v002's get p50 below 72 ns with hit-rate unchanged at 0.7095.

## Parent

cycle/0006/v002

## Changes

This applies v002's successful `borrowed` pattern to the normal tier.

1. **New field in `SegmentCore` (`src/dash/segments/mod.rs`):** `pub(crate) foreign: Vec<u8>`, one entry per normal bucket (`segment_size` entries), zero-initialised in `try_new`. `foreign[i]` = the number of items in `buckets[i]` whose target index is not `i`, i.e. items placed there as their probing slot (target `(i + segment_size - 1) % segment_size`). Do not add per-item fields; `Item` and `Dash` must stay the same size.

2. **Keep it exact, using information the callers already have:**
   - `put_at(Slot::Probing, …)`: the inserted item is foreign by definition, so `foreign[probing_idx] += 1` with no extra hash. `put_at(Slot::Target, …)` inserts a native item, so no increment.
   - Evictions from a normal bucket: `put_at` returns the evictee. Do not hash it inside `put_at`. Every evictee from a normal bucket flows into `demote_from_normal_bucket(core, item, source_idx, …)`, which already computes `true_target`. Decrement `foreign[source_idx]` there when `true_target != source_idx`, before the existing branch. Find every call site where a normal-bucket evictee does not go through `demote_from_normal_bucket` and add the same decrement there. Grep for `put_at(Slot::Target` / `put_at(Slot::Probing` and `buckets[..].put/remove_at`.
   - `remove_at` on a normal bucket: in `promotion_get`'s hottest branch the removed item is in its own target (native), so no change. If any other normal-bucket `remove_at` exists, route it through a helper `remove_normal_at(idx, item_idx, is_foreign)` that decrements.
   - Probing hits (`get_from_position`) only reorder within a bucket and leave the count unchanged.

3. **Gate the probing scan in `promotion_get`:** replace `if let Some(item_idx) = core.buckets[probing_idx].get_position(key)` with `if core.foreign[probing_idx] != 0 { if let Some(item_idx) = … }`. `foreign[probing_idx] == 0` proves no key whose target is `target_idx` is in `probing_idx`, so the skip cannot miss a resident key. Lookups, hits and mutations stay identical. Keep the `s0 → target → probing → s1` order and the `borrowed[s1]` gate.

4. **Debug invariant:** add `SegmentCore::check_foreign_counts()`, which recomputes every counter from bucket contents. Assert it next to `check_borrowed_counts()` in the existing tests and in `borrowed_counts_exact_under_random_ops`. Tests that pre-fill normal buckets directly (`buckets[i].put(...)`) must switch to a counter-aware helper such as `put_normal_at_index(idx, pos, item)`, or skip the foreign-count assertion for those negative fixtures. `force_push_normal_bucket` is an invariant-suite negative fixture, so leave it raw.

New tests:
- (a) A hottest→probing promotion sets `foreign[probing] == 1`. Evicting that item back to its target via the one-more-chance cascade returns it to 0.
- (b) A miss on a key whose probing bucket holds only native items returns `None`.
- (c) A probing hit still works when `foreign != 0`.

## Rationale (optional)

v002 showed that an exact counter stored per segment is a cheap lossless filter: one byte load and a branch cost less than a 2-slot scan. After the `s1` gate, a miss still scans `s0`, target and probing. In steady state many probing buckets hold only their own native items, because hottest→probing promotions are rare compared with target fills, so `foreign[probing] == 0` should be common. Unlike v002's counter, this one needs no re-hashing: the slot type tells insertion, and `demote_from_normal_bucket` already computes `true_target` for evictions. Put cost should therefore barely move. **Confirmed** if hit-rate is exactly 0.7095 and get p50 drops clearly below 72 ns, with put p50/p99 within noise of v002. **Refuted** if get p50 does not move, meaning probing buckets almost always hold a foreign item or the branch costs as much as the scan. Any change in hit-rate means a bookkeeping bug.
