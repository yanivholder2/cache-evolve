# H01

Add stash-victim rescue to cycle-6 v002, with the borrowed counter maintained from hashes the insert/evict path already computes, to reach v001's 0.7118 hit-rate with get p50 well below v001's 87 ns and put p99 below v002's 185 ns.

## Parent

cycle/0006/v002

## Changes

Edits go in `src/dash/segments/dash_segment.rs` and `src/dash/segments/mod.rs` (plus `src/shared/utils.rs` only if a raw-hash helper is needed).

1. **One hash per key, multiple indices.** Add `#[inline] fn key_hash<K: Hash>(key: &K) -> u64` that uses exactly the same hashing as `get_index`, and refactor `get_index(key, n)` to be `index_from_hash(key_hash(key), n)` so both forms always agree. Add a debug assertion or unit test that `index_from_hash(key_hash(k), n) == get_index(k, n)` for many keys and for both `stash_size` and `segment_size`. If `src/shared/utils.rs` cannot be changed safely, put `key_hash`/`index_from_hash` in `segments/mod.rs`, copying `get_index`'s body exactly.

2. **Counter maintenance without re-hashing (`SegmentCore`):**
   - Add `put_stash_at_index_known(&mut self, stash_idx, item_s0, pos, item) -> Option<(Item, usize /*evictee s0*/)>`. It increments `borrowed[stash_idx]` iff `stash_idx != item_s0`, with no hash of `item.key`. On eviction it hashes the evictee once, computes its `s0`, decrements if `e_s0 != stash_idx`, and returns the evictee together with its raw hash (or its `s0` and its target index) so the caller can reuse it.
   - Keep `put_stash_at_index` as a thin wrapper (it computes `s0` itself) for tests and fixtures only.
   - `stash_insert` already computes `(s0, s1)` from the item's key. Pass `s0` through to `put_stash_at_index_known`, which removes the redundant `get_index` in today's `put_stash_at_index`.

3. **Rescue (ported from cycle-6 v001), reusing the evictee hash.** Add `stash_insert_with_rescue(core, pos, item)`. It calls `stash_insert`. If a victim comes back (both `s0` and `s1` were full), take its target `t = index_from_hash(victim_hash, segment_size)` from the hash computed in step 2, not from a new `get_index`, and set `p = (t + 1) % segment_size`. If `!buckets[t].is_full()`, call `put_at(Slot::Target, Front, victim)`. Else if `!buckets[p].is_full()`, call `put_at(Slot::Probing, Front, victim)`. Else drop the victim. Prefer adding `put_at_normal_idx(bucket_idx, pos, item)` so `put_at` does not re-hash. Add `debug_assert!` that neither insert evicts. Send all three stash inserts through the wrapper: the fresh put in `DashSegment::put`, and both `stash_insert(core, DEMOTE_TO_STASH_POS, …)` calls in `demote_from_normal_bucket`.

4. **Keep `promotion_get` as it is in v002:** `s0` → target → probing → `s1` only if `borrowed[s1] != 0`. Rescue only writes into normal buckets, so it never changes `borrowed`.

5. `remove_stash_at` in `stash_hit` keeps its single hash of the removed key for the decrement. Optionally, `stash_hit` can pass `known_native = (stash_idx == s0)`: on an `s0` hit the key is native, so no decrement and no hash; on an `s1` hit with `s1 != s0` it is borrowed, so decrement without hashing. Add `remove_stash_at_known(stash_idx, item_idx, is_borrowed)` for this.

Invariants: no new per-item fields, `Item` stays 40 bytes, `check_borrowed_counts()` and `check_slot_legality()` hold after every op. Extend the random-op test (`borrowed_counts_exact_under_random_ops`) to run with rescue active. Port v001's rescue tests (victim lands at target index 0 when its target has a free slot; victim is dropped when everything is full).

## Rationale (optional)

This is the continuation that both cycle 6 and the cross-cycle narrative name as the next step. v001's rescue is the best hit-rate seen (0.7118) but costs get p50, while v002's lossless counter recovers get p50 but costs put p99 by re-hashing. Rescue already needs the victim's target index, and the counter needs the victim's `s0`, so one hash can serve both. **Confirmed** if hit-rate is exactly 0.7118 (counter and rescue are both state-neutral with respect to each other), get p50 is clearly below 87 ns, and put p99 is below v002's 185 ns. **Refuted** if get p50 stays near 87: that would mean rescue's fuller normal buckets dominate and the `s1` skip no longer pays, for example because rescue changes stash turnover so `borrowed[s1]` is rarely zero. Any change to hit-rate other than reaching 0.7118 points to a bug in the counter or the port.
