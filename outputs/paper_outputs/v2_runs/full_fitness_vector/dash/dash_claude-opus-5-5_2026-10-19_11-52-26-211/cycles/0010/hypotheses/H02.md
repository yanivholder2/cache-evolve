# H02

Stacking cycle-8's scan-free target-only stash-victim rescue onto the tag-filtered buckets of cycle-9 v002 will raise hit-rate to at least 0.711 while keeping get p50 at or below 72 ns, because tags make the extra target residents cheap to skip.

## Parent

cycle/0009/v002

## Changes

Port the rescue hook from cycle/0008/v002 into `src/dash/segments/dash_segment.rs` of this parent, adapted to the hash-and-tag API.

1. Add `stash_insert_with_rescue(core, pos, item, h)` around the existing stash insert, which ends in `core.put_stash_at_index_h(...)`. If the insert returns `Some(victim)`:
   - compute `hv = hash(&victim.key)` once, then `t = hv % core.segment_size`;
   - if `!core.buckets[t].is_full()`, insert the victim into the target bucket at `InsertPosition::Front` with `core.put_at_h(Slot::Target, InsertPosition::Front, victim, hv)`. This keeps the tag array in sync through `put_at_tagged` with `tag_of_hash(hv)`, and the target put leaves `foreign` unchanged. Add `debug_assert!` that it evicts nothing;
   - otherwise drop the victim, as the parent does.
2. Never rescue into the probing bucket, so that `foreign` and the probing gate are unaffected. Rescue only fills an existing hole, so it never cascades and never calls `demote_from_normal_bucket`.
3. Route all stash-insert sites through the wrapper: the fresh put in `DashSegment::put`, and both demotion stash inserts in `demote_from_normal_bucket`. Pass in the hash the caller already has where one exists.
4. Leave everything else unchanged: lookup order `s0` → target → probing (only if `foreign != 0`) → `s1` (only if `borrowed != 0`), tag-filtered probes, stash placements (fresh at Front, demotees at Back), and the parent's header layout.
5. In-file tests (in `dash_segment.rs`, not `tests/`):
   - a victim with a hole in its target lands at target index 0, and `check_tags_consistent`, `check_foreign_counts` and `check_borrowed_counts` all hold;
   - a victim whose target is full is dropped;
   - a random-op test asserts every invariant checker after each op.

## Rationale (optional)

Cycle 8 found that target-only rescue recovers almost all of rescue's hit-rate (0.711). It paid for it with about 13 ns of get p50, because fuller target buckets meant more residents to walk per probe. Cycle 9's tags remove the item-buffer load for every non-matching resident, which is exactly the cost that scales with how full a bucket is. This tests the open question directly: with cheaper probes, is rescue's hit-rate now worth it? Confirmed if hit-rate is ≥ 0.711 and get p50 is ≤ 72 ns. Refuted if get p50 is ≥ 78 ns. That would mean the remaining cost is promotion cascades into full targets, not scanning.
