# H02

Keep an exact per-stash-bucket "borrowed items" counter in `SegmentCore`, so `promotion_get` skips the `s1` scan whenever `s1` holds no overflow from `s0`, lowering cycle-5 v001's get p50 with no change in hit-rate.

## Parent

cycle/0005/v001

## Changes

1. **New field in `SegmentCore` (`src/dash/segments/mod.rs`):** `pub(crate) borrowed: Vec<u8>` of length `stash_size`, zero-initialised in `try_new`. `borrowed[j]` = the number of items currently in `stash_buckets[j]` whose primary bucket is `(j + stash_size - 1) % stash_size`, i.e. whose `s1 == j` and `s0 != j`. A stash bucket holds `bucket_size` items, so `u8` is enough; add a `debug_assert!(bucket_size <= 255)`. Do not add per-item fields. `Item` and the `Dash` struct must stay the same size.

2. **Keep the counter exact at every stash mutation point.** Put the bookkeeping in `SegmentCore` helpers so no call site can skip it:
   - `put_stash_at_index(stash_idx, pos, item)`: before inserting, compute `s0 = get_index(&item.key, stash_size)`. If `stash_idx != s0`, `borrowed[stash_idx] += 1`. If the insert returns an evicted item `e` with `get_index(&e.key, stash_size) != stash_idx`, run `borrowed[stash_idx] -= 1`.
   - Add `SegmentCore::remove_stash_at(stash_idx, item_idx) -> Item` that wraps `stash_buckets[stash_idx].remove_at(item_idx)` and decrements `borrowed[stash_idx]` if the removed item's `s0 != stash_idx`. Use it in `stash_hit` in `dash_segment.rs` instead of the direct `remove_at`.
   - `put_at(Slot::Stash, …)` writes to `s0`, so it never borrows. Only its evictions can drop a borrowed item; apply the same eviction decrement there.
   - Check `dash_segment.rs` for any other direct `stash_buckets[..].put/remove_at/get_items_mut` use outside tests. Send each through the helpers. Tests that pre-fill stash buckets directly (`stash_buckets[s1].put(...)`) must switch to `put_stash_at_index`, or the counter will be stale.

3. **Gate the `s1` probe in `promotion_get`.** Replace the final block with:
   `let s1 = core.stash_neighbor(s0); if s1 != s0 && core.borrowed[s1] != 0 { …existing s1 lookup… }`.
   `borrowed[s1] == 0` proves no key with primary `s0` is in `s1`, so skipping the scan cannot miss a resident key. Hits, misses and mutations stay identical.

4. **Add a debug invariant:** `SegmentCore::check_borrowed_counts()` recomputes every counter from bucket contents. Call it from `check_slot_legality()`, or assert it in tests, so drift is caught.

Tests: all v001 tests pass after the direct stash pre-fills switch to the helpers. New tests:
- (a) After a fresh put overflows into `s1`, `borrowed[s1] == 1`. After `get` promotes that key out of `s1`, it is 0.
- (b) A key's home `s1`-native items fill `s1`, then a borrowed item is evicted by a native insert into `s1`. The counter goes down.
- (c) A random op sequence (puts and gets over ~200 keys on `small_dash_settings`) keeps `check_borrowed_counts()` true after every op.
- (d) A miss on a key whose `s1` holds only native items returns `None`.

## Rationale (optional)

Cycle 5 found that v001's remaining get gap is the extra 2-slot `s1` scan on every miss. Probing `s1` last is already the best fixed order. In steady state most stash buckets are full of their own native keys, so most `s1` buckets hold no borrowed item from their left neighbour. This exact filter should skip most miss-path `s1` scans for one byte per stash bucket, stored in the segment rather than per item. The tracked metadata (`Item`, `Dash`) does not change. **Confirmed** if hit-rate equals v001's 0.7095 exactly and get p50 drops clearly below 77 ns in the same run. **Refuted** if get p50 does not move: either borrowed counts are rarely zero, or the extra counter load and branch cost as much as the 2-slot scan. Any change in hit-rate means a bookkeeping bug. Put p50 may rise slightly from the extra hash in `put_stash_at_index`. Report it.
