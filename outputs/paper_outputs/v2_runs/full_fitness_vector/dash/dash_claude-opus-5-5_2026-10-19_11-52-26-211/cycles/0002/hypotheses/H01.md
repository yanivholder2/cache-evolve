# H01

Add v001's back-of-stash demotion to v003's target→probing→stash lookup order, so one variant keeps v001's 0.684 hit rate and also gets v003's cheaper get path for lower per-op-time.

## Parent

cycle/0001/v003

## Changes

All edits are in `src/dash/segments/dash_segment.rs`. v003 already runs `promotion_get` in this order: target first (with the hottest → `promote_to_probing` vs. intra-bucket `get_from_position` logic), then probing, then the stash. The stash check is the last step, and `stash_idx = get_index(key, core.stash_size)` is computed lazily, only when that step is reached. Keep that structure as it is.

Port v001's stash-placement change on top of it:
- Add a module-level `const DEMOTE_TO_STASH_POS: InsertPosition = InsertPosition::Back;` with an SLRU doc comment. The reason: an item leaving the target/probing tier has proven reuse, so it should enter the stash at its MRU end.
- In `demote_from_normal_bucket`, both stash inserts must use `DEMOTE_TO_STASH_POS` instead of the caller's `insert_pos`. That covers the `true_target == source_idx` branch, `core.put_at(Slot::Stash, ..)`, and the `cascade` branch.
- The one-more-chance retry `core.put_at(Slot::Target, insert_pos, item)` keeps using `insert_pos`. Promotions in `promote_to_target` / `promote_to_probing` also keep using `insert_pos`, and `get` still passes `InsertPosition::Front`.
- Update the in-file tests the same way v001 did. Rename `direct_to_stash_at_front_when_*` / `cascade_to_stash_at_front_when_*` to `*_at_back_when_*`. Both the Front- and Back-caller cases now expect the demoted item at stash index 1, behind `stash_pre`.

Invariants: the cache-state sequence must match v001 exactly for any trace, because lookup order cannot change the result under the uniqueness invariant. So hit-rate should equal 0.684 and metadata-size stays 40. Avoid holding borrows across branches: use the `if let Some(idx) = ... { ...; return ...; }` early-return form.

## Rationale (optional)

The cycle 0001 insight names this combination as the recommended next parent. The two edits touch independent code (stash insert position vs. lookup order). The experiment checks whether they compose: hit-rate should be about 0.684, and get p50 should be at or below v001's in the same run. A get p50 at or below v001's confirms that v003's lookup-order gain carries over and is not run-to-run noise.
