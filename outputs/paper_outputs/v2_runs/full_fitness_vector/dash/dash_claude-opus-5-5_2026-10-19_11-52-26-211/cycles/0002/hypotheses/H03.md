# H03

Insert brand-new `put` arrivals at the stash's LRU end (Front) instead of its MRU end (Back), so never-reused one-hit items are evicted before reuse-proven demotees, raising hit rate.

## Parent

cycle/0001/v001

## Changes

Edits go in `src/dash/segments/dash_segment.rs`. Also edit the `Segment` trait module (`src/dash/segments/mod.rs` or wherever `Segment::put` is defined) if the default `put` must be split to allow an override.

Today `Segment::put` inserts a new key into its stash bucket with `InsertPosition::Back` (MRU). Since v001, demoted items also enter the stash at Back. So in eviction order, new arrivals and reuse-proven demotees are mixed purely by recency. This change makes the stash behave like a scan-resistant probationary queue: a new arrival is the first stash victim unless it is read again before the next overflow in its stash bucket.

Change:
- Give `DashSegment` its own `put` in its `impl Segment for DashSegment` block. Keep the default trait `put` semantics exactly: if the key is already resident in any slot (target, probing or stash), update its value in place, with the same position/touch behaviour as today. Only the fresh-insert case changes: call `core.put_at(Slot::Stash, InsertPosition::Front, item)` instead of `Back`. Any item evicted by that insert leaves the cache, as today.
- If the default `put` is not overridable as written (for example, the update-in-place logic is private), factor it into a helper on `SegmentCore` that takes the fresh-insert `InsertPosition`. Make the default trait `put` call it with `Back` and `DashSegment::put` call it with `Front`. Behaviour for other segment types must not change.
- Leave `DEMOTE_TO_STASH_POS = Back`, `promotion_get`, and all promotion positions unchanged.
- Update the `put_goes_to_stash` test to also assert that a second fresh key landing in the same stash bucket sits at index 0. Add a test: fill a stash bucket with one demoted item (via `promote_to_target` overflow) and fresh puts, overflow it with one more fresh put, then assert that the demoted item survives and the oldest fresh arrival was evicted.

Invariants: no duplicate keys. An updated key must not be moved or re-inserted as a fresh item. Slot legality holds. Metadata-size stays 40.

## Rationale (optional)

The stash holds 75% of capacity and is the proven hit-rate lever (v001). The LIRS-style workload-a probably contains many one-hit keys. Placing them at Front tests whether shielding reuse-proven items from cold arrivals pays off. The risk: keys with a moderate first-reuse distance get evicted before their second access. A hit-rate drop below 0.684 would therefore show that first-reuse distances are longer than one stash-bucket turnover.
