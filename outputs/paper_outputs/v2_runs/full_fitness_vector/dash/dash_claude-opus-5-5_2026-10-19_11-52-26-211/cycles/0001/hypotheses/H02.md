# H02

When promoting a stash hit, place the item in its probing bucket if that bucket has free space and the target bucket is full, which avoids a needless eviction cascade and raises hit rate.

## Parent

baseline

## Changes

All edits are in `src/dash/segments/dash_segment.rs`. Real Dash uses balanced insert: an item may live in either its target or its probing bucket, and the bucket with spare room is chosen. The baseline ignores this on the stash → normal path. `promote_to_target` always writes into the target bucket, so a full target evicts an item to the stash even when the neighbouring probing bucket `(target_idx + 1) % segment_size` has empty slots.

Change:
- In `promotion_get`, stash-hit branch: after `remove_at` from the stash, decide where the item goes.
  - If `core.buckets[target_idx].is_full()` and `!core.buckets[probing_idx].is_full()`, insert with `core.put_at(Slot::Probing, insert_pos, data)`. This cannot evict because the bucket has room.
  - Otherwise call `promote_to_target(core, data, insert_pos)` as today.
- Change how the returned reference is found. Look up the key in the bucket it was actually placed in: check `core.buckets[target_idx].get_position(key)` first, then `core.buckets[probing_idx]`. Keep the `unreachable!` if it is in neither.
- Optional tie-break, which should go in the same variant: if both buckets have room, still prefer the target. This keeps the "hottest in target promotes to probing" tier meaningful.
- Leave the target-hit branch (hottest → probing) and the probing-hit branch unchanged. An item placed in its probing bucket this way is a "foreign resident" there. The existing `demote_from_normal_bucket` already handles that case correctly: when evicted later, it retries its own true target before going to the stash.

Invariants to keep: the item ends up in exactly one bucket, and that bucket is either its target or its probing index, so `check_slot_legality` holds. No bucket may exceed `max_size`. `get` must still search stash, target and probing. Add a unit test: fill a target bucket, leave its probing bucket partly empty, then put and get a stash key for that target. Assert the key is now in the probing bucket and that no target resident was demoted.

## Rationale (optional)

With only 8 normal buckets, load across them is skewed. Hot targets keep pushing items out to the stash while neighbouring buckets sit partly empty. Using the free capacity in normal buckets instead of evicting should raise effective occupancy and hit rate. Per-op cost should barely change, because `is_full()` is O(1).
