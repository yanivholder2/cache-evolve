# H01

Derive every bucket index from a single key hash per item and pass known indices and borrowed/native flags down the stash-hit and demotion paths, cutting cycle-7 v002's get p50 below 69 ns and put p99 at least back to its level, with hit-rate unchanged at 0.7095.

## Parent

cycle/0007/v002

## Changes

Edits go in `src/dash/segments/mod.rs` and `src/dash/segments/dash_segment.rs`. Touch `src/shared/utils.rs` only if a raw-hash helper is needed there. This is a strictly state-neutral refactor: it changes no placement, order or victim decision.

**Current hash count.** On a v002 stash hit that evicts from a full target, the code hashes the same keys many times:
- `promotion_get` hashes the key for `s0` and again for `target_idx`.
- `remove_stash_at` → `note_stash_removal` hashes the removed key again.
- `promote_to_target` → `put_at(Slot::Target)` hashes it again.
- `demote_from_normal_bucket` hashes the evictee for `true_target`.
- `stash_insert` → `stash_indices` hashes the evictee again, and `put_stash_at_index` hashes it a third time.
- If the stash overflows, `note_stash_removal` hashes the stash victim.

Every first reuse in this lineage goes through a stash hit, so this path is a large share of all gets.

1. **One hash, many indices.** Add `#[inline] fn key_hash<K: Hash>(k: &K) -> u64` and `#[inline] fn index_from_hash(h: u64, n: usize) -> usize`, and rewrite `get_index(k, n)` as `index_from_hash(key_hash(k), n)`. Read `get_index` first. If it mixes `n` into the hash, or takes the modulus in a way that can't be split, copy its exact arithmetic so that `index_from_hash(key_hash(k), n) == get_index(k, n)` holds bit-for-bit. Add a unit test of that identity over 10k keys for both `stash_size` and `segment_size`.

2. **`promotion_get`:** compute `h = key_hash(key)` once, then derive `s0` and `target_idx` from it.

3. **Stash removal without a hash.** Add `remove_stash_at_known(stash_idx, item_idx, is_borrowed: bool)`. `stash_hit` passes `is_borrowed = (stash_idx != s0)`: an `s0` hit is native, and an `s1` hit with `s1 != s0` is borrowed. Keep `remove_stash_at` as a wrapper for tests.

4. **Normal-bucket insert with a known index.** Add `put_normal_known(bucket_idx, is_foreign: bool, pos, item) -> Option<Item>`. It increments `foreign[bucket_idx]` iff `is_foreign` and does no hash. Use it in:
   - `promote_to_target`: `target_idx`, `false`.
   - `promote_to_probing`: `probing_idx`, `true`.
   - The one-more-chance retry in `demote_from_normal_bucket`: `true_target`, `false`.

   Keep `put_at` for tests and fixtures.

5. **Evictees hashed exactly once.** In `demote_from_normal_bucket`, compute `eh = key_hash(&item.key)` and derive both `true_target` and the evictee's `(s0, s1)` from it. Do the same for the `cascade` evictee. Add `stash_insert_known(core, pos, item, s0)`, which takes `s0` and calls a new `put_stash_at_index_known(stash_idx, is_borrowed = stash_idx != s0, pos, item)` with no hash. The fresh put in `DashSegment::put` hashes once and calls `stash_insert_known`. If a stash insert evicts, hash the victim once for `note_stash_removal`. That hash is unavoidable.

6. Keep the debug-only `debug_assert_eq!(…get_index…)` checks. They compile out in release builds, and they guard the new known-index paths.

Invariants: `Item` stays 40 bytes and no fields are added. `check_borrowed_counts()`, `check_foreign_counts()` and `check_slot_legality()` must hold after every op in `borrowed_counts_exact_under_random_ops` and `foreign_counts_exact_under_skewed_random_ops`. Every existing test must pass unchanged.

## Rationale (optional)

Cycle 4's bookkeeping refactor missed get p50, but it trimmed redundant re-scans and only some of the hashes, on a lineage where stash hits were rarer. In v002 the stash-hit → promote → demote → stash-insert chain is the common reuse path and runs about 7 hashes. This change takes it to about 2, and it also removes the `borrowed` re-hash that cycles 6–7 blamed for put cost. **Confirmed** if hit-rate is exactly 0.7095, get p50 is clearly below 69 ns, and put p50/p99 are no worse than v002's. **Refuted** if get p50 doesn't move, which would mean hashing is not a material share of the median and the scans dominate. Any change in hit-rate means an index-derivation bug.
