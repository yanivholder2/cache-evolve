# H02

Adding a one-byte key tag per slot to the `DashBucket` header will let lookups reject non-matching buckets without dereferencing the item buffer, which should lower get p50 and p99 while leaving hit-rate exactly at 0.7095.

## Parent

cycle/0008/v003

## Changes

Keep v003's concrete `DashBucket` stored contiguously in `Vec<DashBucket>` inside `SegmentCore`, and add an inline tag array to each header.

- Add `tags: [u8; MAX_SLOTS]` to `DashBucket`, where `MAX_SLOTS` is the largest bucket capacity the parent uses (normal or stash). The tag is a byte taken from the key hash that the lookup has already computed, e.g. `(h >> 56) as u8`. Pick bits that are not used for segment, bucket or stash indexing, and add no new hash. Keep `tags[j]` in sync with the item at position `j` in the bucket's `Vec<Item>`. Every mutation must shift the tag array the same way it shifts the items: `put_at` (Front/Back insert), `remove_at`, `evict_item`, and the recency reorder in `get_from_position`. Paths that insert an item without a hash in hand (demotion, cascades) must get the hash passed in from the caller. If no hash is available, the caller computes `key_hash` once at that point.
- In `DashBucket::get_position`, compare `tags[0..len]` against the probe tag first. Only for slots whose tag matches, load the `Item` from the heap buffer and compare the full key. If no tag matches, return `None` without touching the item buffer.
- Thread the probe tag from `promotion_get` into each bucket probe (`s0`, target, the gated probing bucket, the gated `s1`), and do the same on the put/exists path.
- To offset the stride growth v003 suffered from, shrink the header where it costs nothing. For example, store `max_size` as `u8` next to the tags, so the header grows by at most a few bytes. `Item` and the `Dash` struct must not change, so metadata-size stays 40/24.
- Behaviour must stay identical: tags only filter. A tag match always falls through to the full key compare.

## Rationale (optional)

v003's analysis named the item-buffer miss as the cost that remains after the bucket became concrete. Most probes on the common path end in "not here": a miss on `s0` before a target hit, and every probe of a full miss. With tags inline in the header, which the probe already loads, those probes never chase the `Vec<Item>` pointer. This is a different lever from H01's layout rewrite: it keeps the heap buffers and only avoids touching them. Pass/fail criteria: hit-rate must equal 0.7095, and get p50 must fall below 70 ns. If p50 is flat while p99 falls, item-buffer misses are a tail effect only.
