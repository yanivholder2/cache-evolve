# H01

Storing every bucket's slots inline in one flat per-segment item array, with a statically dispatched position-ordered policy, will lower get p50 below 69 ns while keeping hit-rate exactly at 0.7095.

## Parent

cycle/0007/v002

## Changes

Change only the storage layout inside `SegmentCore` (and the bucket code it owns). The observable cache behaviour must not change at all.

- Remove the per-bucket `Vec<Item>` and the per-bucket `Box<dyn EvictionPolicy>`, and drop `Vec<Box<dyn Bucket>>` as the container. In their place, `SegmentCore` holds two things for the normal buckets (target/probing): one contiguous `Vec<Item<K,V>>` of length `num_normal_buckets * NORMAL_SLOTS`, and a matching `Vec<u8>` of per-bucket lengths. It holds the same pair for the stash buckets, sized `num_stash_buckets * STASH_SLOTS`. Bucket `i` owns the slice `[i*N .. i*N + len[i]]`. Use the bucket capacities the parent already uses, and allocate each array once in the segment constructor.
- Add free functions or inherent methods on `SegmentCore` that work on a `&mut [Item]` slice plus its `&mut u8` length: `find_in(slice, key) -> Option<usize>`, `touch(slice, pos)`, `insert_at(slice, len, item, Front|Back)`, `remove_at(slice, len, pos)`, and `victim(slice, len)`. Each must reproduce the parent's `EvictionPolicy` semantics exactly: the same position ordering, the same recency move on hit in `get_from_position`, the same Front/Back meaning in `put_at`, and the same victim index in `evict_item`. They are plain `#[inline]` functions, with no trait objects.
- Rewrite `promotion_get`, `promote_to_target`, `demote_from_normal_bucket`, `stash_insert_known`, `put_stash_at_index` and the put path to call these helpers on slices of the flat arrays instead of the bucket trait methods. Keep the lookup order `s0 → target → (probing if foreign[probing_idx] != 0) → (s1 if borrowed[s1] != 0)`. Keep every `borrowed`/`foreign` increment and decrement at the same logical event.
- Do not add fields to `Item`, and do not grow the `Dash` struct. The new arrays live behind `SegmentCore`'s heap allocation, so metadata-size stays at 40/24.
- If the `Bucket` trait is still needed for compilation by files outside the authoring scope, leave it defined but unused on the hot path.

## Rationale (optional)

Cycle 8 showed that the median get no longer responds to fewer hashes (v001) or to removing the `Box<dyn Bucket>` hop (v003). What remains is two dependent loads per probe (bucket header → heap item buffer) plus a vtable call into the boxed policy on hits. A flat array makes the location of bucket `i`'s slots computable from `i` alone, which removes both. Pass/fail criteria: hit-rate must equal 0.7095 exactly (the change is state-neutral), and get p50 must drop below 69 ns. If p50 stays flat, slot walking itself is the floor, not indirection.
