# H03

Admit a new key into the table only on its second miss, using a one-bit doorkeeper, to raise hit rate on scan-heavy LIRS traces.

## Parent

baseline

## Changes

Add an admission check on the put path for keys that are not already resident. Keep a doorkeeper bit per hashed key in unused segment padding, so the metadata-size dimension stays at 40 bytes per item and 24 bytes per segment. On a first miss for a key, set its doorkeeper bit and do not insert the key. On a second miss while the bit is set, insert the key as the baseline does and clear the bit. Resident keys, the get path, the eviction path, and the promotion logic are unchanged. Clear all doorkeeper bits in a segment when that segment is evicted from or resized, so stale bits cannot admit keys out of order.

The experiment: run workload-a at size 2048 and compare hit rate against the baseline (0.663 on the leaderboard). Also run the scan-heavy trace subset to check that the gain is not limited to workload-a. The hypothesis is refuted if hit rate does not rise, or if put p50 rises by more than the cost of the extra probe.

## Rationale (optional)

Every prior cycle changed where a key sits after it is admitted (insert position) or which resident is displaced (victim choice). None has changed whether a key is admitted at all. Scan-like one-shot keys currently displace residents on first touch, which is the failure mode that v003's counter was built to limit. A doorkeeper filters them before they enter the table. This is a new axis, not a rephrasing of the insert-position work that lost hit rate in cycles 0001 and 0002.
