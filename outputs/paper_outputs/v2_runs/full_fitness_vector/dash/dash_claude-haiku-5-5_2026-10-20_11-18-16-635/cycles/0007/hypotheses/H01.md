# H01

Stopping the lowest-counter victim scan in `evict_one()` at the first zero-counter slot lowers put-path per-op-time while leaving hit rate and metadata size exactly at the parent's values.

## Parent

cycle/0004/v002

## Changes

Keep the full-scan frequency-aware victim selection from the parent unchanged in ranking. In `evict_one()`, replace the scan over every slot in the target bucket with a scan that returns immediately when it reaches a slot whose saturating access counter is 0. Because the counter is unsigned, 0 is the global minimum, and the first zero slot in slot order is the same victim the full scan picks today under its first-minimum tie-break. Do not change how the counter is incremented on target hits, the stash-to-target promotion path, the get path, insert placement, or the record layout. If the parent's tie-break is not first-minimum in slot order, match whatever order the parent uses and state it in the variant's insight.

Invariant to preserve: victim choice is identical to the parent on every access, so hit rate and metadata size must match the parent exactly. Only put per-op-time should move.

## Rationale (optional)

Cycle 0004 v002 showed that the put path pays for the lowest-counter search when a full bucket has to evict, and cycle 0005 v001 showed that cutting the search short by sampling two slots did not make puts cheaper. This hypothesis tests a different cut: an exact early exit that keeps the ranking, so any put gain would show the scan length matters, and no gain would show the cost is elsewhere. It also needs no extra state, which avoids the incremental-minimum cost seen in cycle 0006 v001.
