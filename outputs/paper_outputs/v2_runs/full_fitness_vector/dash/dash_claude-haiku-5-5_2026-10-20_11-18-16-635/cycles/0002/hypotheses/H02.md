# H02

Skip the stash bucket scan on a get miss in the target and probing buckets only when the stash bucket is known empty, so stash hits stop paying for two earlier misses.

## Parent

cycle/0001/v003

## Changes

v003 reordered `promotion_get()` to check the target and probing buckets before the stash bucket. That makes stash hits pay for two extra lookups. Add a cheap occupancy check so the stash scan can be bypassed when it cannot match:

- Maintain a per-stash-bucket occupancy count in `DashSegment`, incremented and decremented wherever a slot in a stash bucket is filled or freed (insert, remove, demotion into stash, and promotion out of stash).
- In `promotion_get()`, after the target and probing checks miss, read the stash bucket's occupancy count first. If it is zero, return the miss without running the stash linear scan. If it is non-zero, run the existing scan unchanged.

Keep the target and probing scan order from v003. Do not change eviction, insert position, or promotion targets, so hit rate should be identical to v003. Keep the occupancy counter in the segment struct rather than in the per-item metadata so that the reported metadata-size does not change. Preserve all invariants on the count: it must equal the number of occupied stash slots at all times.

## Rationale (optional)

v003's takeaway left stash-hit latency unmeasured and noted it now pays for two earlier misses. A zero-occupancy fast path targets exactly that cost. If stash buckets are rarely empty under the workload, the change will show no gain, which is itself a useful result.
