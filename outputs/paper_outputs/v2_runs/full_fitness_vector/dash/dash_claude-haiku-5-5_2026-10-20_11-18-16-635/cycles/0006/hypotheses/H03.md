# H03

Re-admitting keys that were recently evicted directly into their target bucket will raise hit rate on re-referenced keys without blocking first-touch admission.

## Parent

baseline

## Changes

Add a small ghost table that remembers the fingerprints of recently evicted keys. Size it as a fixed ring of about one-quarter of the table's slot count, storing only a 16-bit key fingerprint per entry, with no values. Insert the fingerprint of each key that `evict_one()` removes. On a later insert of a key whose fingerprint is found in the ghost table, place the key directly into its target bucket (the main table). Otherwise keep the baseline insert path unchanged, so first-touch keys still take the existing admission route. This targets re-reference rather than first touch, which is the opposite of the blocked-admission variant that cycle 0003 showed loses hit rate on workload-a.

Keep the existing promotion logic and the get path intact. On a ghost hit, clear that fingerprint from the ring so one eviction admits one re-entry. The ring costs metadata, so record its size in the metadata report and expect a metadata-size increase; the hypothesis is judged on whether the hit-rate gain on workload-a justifies that cost. Do not change the record layout in this variant.
