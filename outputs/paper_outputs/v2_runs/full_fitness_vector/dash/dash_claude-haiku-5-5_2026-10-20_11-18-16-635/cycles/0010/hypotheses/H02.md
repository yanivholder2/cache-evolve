# H02

A one-byte tag stored in the record's spare bits lets get reject non-matching slots before the full key compare, lowering get p50 without changing eviction order.

## Parent

cycle/0008/v001

## Changes

In the packed 32-byte record, carry an 8-bit tag derived from the key's hash in bits that the current layout does not use. Use only existing spare bits; if the current layout has no spare bits, do not widen the record and do not adopt this change. In the `get` probe loop over the target and probe buckets (and the stash scan), compare the tag first and perform the full key comparison only when the tag matches. Set the tag in the insert path and clear it on eviction and replacement. The counter field, the saturating increment, the full-scan victim selection, and the stash-to-target promotion must remain unchanged, so hit rate and metadata-size should match the parent exactly. Measure get p50 and p99 separately for target hits and stash hits if the harness allows, since the stash-hit tail has never been reported.

## Rationale (optional)

Cycle 0009 v002 showed that removing the per-hit counter write did not lower get latency, so the get cost sits elsewhere in the probe and decode path. Cycle 0009 v001 showed that reordering the stash scan did not help. A tag check attacks a different cost: unnecessary full key comparisons on probed slots. Caveat: the source of the packed layout could not be read while drafting, so the spare-bit assumption must be confirmed before the record is touched.
