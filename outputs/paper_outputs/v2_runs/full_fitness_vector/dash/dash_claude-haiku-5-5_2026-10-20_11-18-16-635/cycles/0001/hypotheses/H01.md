# H01

Swapping a probing-tier hit back into its target at MRU raises hit rate on the LIRS workload-a trace at 2048 entries.

## Parent

baseline

## Changes

Edit `promotion_get()` in `src/dash/segments/dash_segment.rs`, in the branch that handles a key found in `buckets[probing_idx]` (currently `return Some(core.buckets[probing_idx].get_from_position(item_idx))`). Instead of touching the item in place, remove it from the probing bucket with `remove_at(item_idx)` and reinsert it through `promote_to_target(core, data, InsertPosition::Back)`, so it lands at MRU in its true target. The existing demotion cascade in `promote_to_target` / `demote_from_normal_bucket` handles any displaced target resident (probing first, then stash). After the reinsert, look the key up in `buckets[target_idx]` and return a reference to it, following the same `unreachable!` pattern the stash-hit branch already uses.

Keep the stash-hit branch, the target-hit branch, and the `get_index` computations unchanged. Keep `InsertPosition::Front` for the stash-to-target path. Update the in-file test `probing_hit_touches_in_place`, which asserts the old in-place behaviour, so it asserts the new target-recovery behaviour.

## Rationale (optional)

The baseline never moves an item back out of probing once it lands there, so a hot item that was demoted from target into probing stays in the displaced slot until it is evicted. Recovering it on hit should keep hot keys in their home bucket and free probing slots for other keys. This is a bucket-movement change only; `Item`, geometry, and the eviction policy are untouched.
