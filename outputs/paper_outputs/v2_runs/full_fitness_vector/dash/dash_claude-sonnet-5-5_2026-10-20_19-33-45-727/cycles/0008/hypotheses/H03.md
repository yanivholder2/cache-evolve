# H03

Make the second-hit filter's first-sighting memory a tiny direct-mapped table of 8-bit key fingerprints instead of the baseline structure, to lower put latency on the baseline without hurting hit-rate.

## Parent

baseline

## Changes

Starting from the baseline source, add a per-segment direct-mapped array of 256 `u8` fingerprints (inside the segment struct, not in the per-item struct, so item metadata stays at 40). On put of a key not present: compute fp = (hash >> 56) as u8 | 1 (nonzero) and slot = (hash >> 40) & 0xFF. If table[slot] == fp, treat as a second hit: clear the slot and insert normally. Otherwise write table[slot] = fp and return without inserting or evicting. Updates of existing keys bypass the filter. Do not change get, eviction, or lock structure. No aging; collisions simply overwrite.

## Rationale (optional)

This is a fingerprint (not bit) doorkeeper with a lower false-positive rate than bit-set filters at a similar footprint (256 B). It is a distinct mechanism from the bit-array filters tried in cycles 0006 and 0007.
