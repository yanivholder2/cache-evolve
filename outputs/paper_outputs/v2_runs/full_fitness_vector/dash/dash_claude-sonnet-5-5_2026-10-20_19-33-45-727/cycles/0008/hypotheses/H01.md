# H01

Shrink cycle 0007 v001's two-hash aged doorkeeper to a single 64-byte cache line per segment to keep its hit-rate while cutting put-side latency.

## Parent

cycle/0007/v001

## Changes

In the doorkeeper introduced by v001, replace the large bit array with a fixed 512-bit (64-byte, `#[repr(align(64))]`) array per segment. Keep the two-hash probe, but derive both bit indices from one hash computation (the low 9 bits and the next 9 bits of the same 64-bit hash), so both probes land in the same cache line. Keep the aging reset, but trigger it from a cheap counter of set bits (increment when a probe sets a new bit; reset when it exceeds ~256, i.e. 50% fill) and clear the 8 u64 words directly with no popcount pass. Leave get paths, eviction and metadata item layout untouched. Preserve metadata-size at 40 (the doorkeeper must stay outside the per-item struct).

## Rationale (optional)

v001 showed that the bigger doorkeeper gives hit-rate but costs put latency through cache misses and popcount resets. A one-line filter should remove those costs.
