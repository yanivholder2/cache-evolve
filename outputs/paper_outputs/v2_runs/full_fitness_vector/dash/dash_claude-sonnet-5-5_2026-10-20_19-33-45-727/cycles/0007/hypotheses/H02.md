# H02

Add a one-shot "ghost hit" bypass to the cycle 0002 incumbent's second-hit filter so recently evicted keys are re-admitted on first sighting, raising hit-rate.

## Parent

cycle/0002/v002

## Changes

In the put/admission path of the bit-packed second-hit filter, when a key misses the filter, additionally check a tiny per-segment ghost record (a single u16/u32 fingerprint of the most recently evicted key, stored in existing spare bits or a field of the segment/bucket header rather than the item, so item size stays at baseline and metadata-size stays 40). If the incoming key's fingerprint matches the ghost, admit it immediately (skip the second-hit requirement) and clear the ghost. On eviction, write the victim's fingerprint into the ghost. Keep the get path unchanged. Invariants: no extra allocation, no new atomics on get, and the filter behaviour is unchanged for non-ghost keys.

## Rationale

Recency-skewed LIRS trace: keys evicted just before being reused are wrongly rejected by a strict second-hit gate; this recovers them cheaply.
