# H03

Stripping the baseline's per-operation bookkeeping down to a minimal bit-packed second-hit filter, with no extra hot-path work, will improve hit-rate and per-op-time together relative to baseline.

## Parent

baseline

## Changes

Starting from baseline, implement the second-hit admission filter so that an item inserted on its first access is placed in the cold region. Store the "seen once" flag in spare bits of the existing item header, so item size stays 40. Promote an item on its second hit only. On a first hit, do nothing: do not remove-and-promote. Make no other policy changes (no counters, ref bits or position tweaks). Remove any baseline per-get statistics updates or timestamp writes that the hit-rate policy does not read.

## Rationale (optional)

This is an independent re-derivation of the one clean win from cycle 0001 from a different parent. If it matches the incumbent, it separates real effects from noise. If it beats the incumbent, the cleanup of baseline bookkeeping is responsible.
