# H01

Removing redundant locking and re-hashing work from the get-hit path of the fastest incumbent will cut per-op-time without changing hit-rate.

## Parent

cycle/0001/v001

## Changes

Starting from cycle/0001/v001 (lowest per-op-time, 66), edit only the lookup/get path in the overlay files. Compute the key hash once and reuse it for segment, bucket and fingerprint selection. Where the get-hit path takes a write lock or exclusive access just to set the admission/promotion bit, use an atomic or relaxed update on the bit-packed flag, or skip the write if the bit is already set. Perform the bucket scan on the primary bucket first and return early on a match before probing the stash. Do not change admission or eviction policy, and do not change item layout (metadata-size must stay 40). Do not add conditional guards that only sometimes succeed. Cycle 0003 showed such branches cost latency.

## Rationale (optional)

Cycle 0003 concluded that hit-rate is saturated and the open question is where get/put time goes. This targets the untried lookup/locking path.
