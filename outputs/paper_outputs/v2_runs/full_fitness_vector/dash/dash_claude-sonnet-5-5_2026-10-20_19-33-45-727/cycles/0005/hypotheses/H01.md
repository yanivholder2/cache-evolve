# H01

Deleting remaining write-only bookkeeping from the fastest incumbent's get and put paths will lower per-op-time at unchanged hit-rate and metadata size.

## Parent

cycle/0001/v001

## Changes

Starting from cycle/0001/v001 (the lowest per-op-time incumbent, 66), audit the DASH overlay's get, put and eviction paths for stores that no code path ever reads: leftover counters, timestamps, stats fields, redundant flag writes, and duplicate stores to the same slot field. Delete each one. Do not add any new branches, atomics, early returns or fast paths. Keep the second-hit admission filter logic and its bit-packed flag exactly as is, and keep the item at 40 bytes. Do not change eviction order or insert position. Any hit-rate change should be zero; if hit-rate moves, revert that deletion.

## Rationale (optional)

Cross-cycle notes say subtractive changes were the only mechanics-level latency wins. This applies that to the fastest incumbent.
