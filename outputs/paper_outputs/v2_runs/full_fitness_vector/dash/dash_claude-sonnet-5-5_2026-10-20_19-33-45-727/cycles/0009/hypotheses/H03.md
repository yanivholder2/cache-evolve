# H03

Make the 40-byte-metadata cycle 0005 v001 incumbent skip its second-hit filter's bookkeeping on already-resident keys to reduce per-op-time without losing hit-rate.

## Parent

cycle/0005/v001

## Changes

In cycle 0005 v001's put path, ensure that when the key is found already resident (update case), the function returns right after the value overwrite, before any second-hit bit read, set or clear. Admission-filter state should only be consulted on the insert-miss branch. Do not alter eviction, promotion or the get path. Preserve item size and metadata-size 40, and the existing admission semantics for non-resident keys.

## Rationale (optional)

Cycle 0005 v001 has the lowest per-op-time (65) among incumbents; trimming filter work on update puts targets latency only, with hit-rate unchanged by construction.
