# H03

Making the second-hit admission filter probabilistic via a small bit-packed per-segment doorkeeper (a few bits of hash per key) in place of per-item flags will raise hit-rate on the LIRS trace at baseline item size.

## Parent

baseline

## Changes

Starting from the baseline cache, add a second-hit doorkeeper to the put path. On a miss-insert of key K, compute a 16-bit fingerprint from the existing hash. Check it against a fixed-size ring of recently seen fingerprints, for example 64 u16 entries per segment, stored in existing spare segment-header bits or a fixed array inside the segment struct. This must not add per-item metadata, so item size stays 40. If the fingerprint is absent, record it and decline to insert. If present, insert the item as usual and clear the entry. Overwrite ring entries round-robin using a segment-local cursor. Leave get, eviction, and promotion unchanged. Tune the ring size so that segment-struct growth is not counted in metadata-size. If it would be counted, size the ring to fit inside already-padded bytes.

## Rationale (optional)

This tests the same admission idea as earlier winners but with the filter state held outside the items. That may filter one-touch keys earlier and avoid evicting resident items for them.
