# H01

Replacing the bucket-slot linear scan with a single-pass tag comparison over packed tag bytes will cut get per-op-time without changing hit-rate or metadata-size.

## Parent

cycle/0005/v001

## Changes

In the lookup path of the DASH bucket (the function that scans a bucket's slots for a matching key/tag on get and on put's existing-key check), restructure the scan so the per-slot tag bytes are compared first in one tight loop (or one u64/u128 SWAR compare if the tags are contiguous), and only dereference/compare the full key for slots whose tag matches. Return on the first full-key match. Do not change the second-hit admission filter, the bit-packed flags, the item layout (metadata-size must stay 40), or eviction order. If tags are not already stored contiguously, pack them into spare bits already available in the existing bucket header rather than adding fields. Preserve the lock acquisition order and the existing probing sequence (bucket, then neighbour/stash).

## Rationale (optional)

Prior cycles showed that deleting stores and hoisting hash work did not help. Bucket scan is an untested structural candidate for where hit-path time goes.
