# H02

Letting get take a shared (read) lock on the bucket and upgrade to exclusive only when a promotion or admission state change is needed will lower get per-op-time on hit-heavy traces without hurting hit-rate.

## Parent

cycle/0002/v002

## Changes

In the get path, replace the unconditional exclusive bucket/segment lock with a shared read lock (e.g. the existing lock type's read mode, or `RwLock::read`) for the lookup. If the hit requires a state mutation (setting the second-hit flag, promoting a slot), drop the read guard and re-acquire exclusively, then re-validate the slot before mutating. Hits on already-promoted items must complete under the read lock with no writes. Do not touch put, the admission filter semantics, bit-packing, or item size (metadata-size stays 40). If the current implementation already uses a reader-writer lock, instead make already-hot hits skip the write guard entirely. If a mutation under the read lock is needed, use a relaxed atomic bit-set on the packed flag word.

## Rationale (optional)

Lock acquisition has never been profiled or changed. This is a structural locking change rather than a blind edit of arithmetic.
