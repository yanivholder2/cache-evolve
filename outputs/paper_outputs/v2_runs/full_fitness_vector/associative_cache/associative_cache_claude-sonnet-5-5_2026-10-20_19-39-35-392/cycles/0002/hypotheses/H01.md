# H01

Replace strict LRU bucket eviction with a per-slot 1-bit reference (CLOCK / second-chance) policy to raise hit rate without increasing per-op time.

## Parent

baseline

## Changes

In the associative cache overlay file (the one implementing the bucket and its get/put/evict paths), stop reordering items inside a bucket on a hit. Instead, give each slot a reference bit (packed into an existing padding or a single `u8`/bitmask per bucket, keeping metadata-size at or near the baseline's 40 bytes). On `get` hit: set the slot's ref bit only, with no item movement. On `put` into a full bucket: scan the slots from a per-bucket clock hand (a small `u8`). Clear the ref bit of each referenced slot and advance. Evict the first slot whose ref bit is 0. Insert the new item with its ref bit cleared, and leave the hand just past it. Preserve the public API and the update-in-place behaviour for existing keys. Do not touch the gate-integrity files (the JNI file, factory, lib.rs, Cargo.toml).

## Rationale (optional)

Cycle 0001 showed that item movement doesn't dominate get time and that weaker recency hurts. A reference bit keeps recency information but makes the hit path cheaper (a single bit-set), and it gives a scan-resistance signal that LRU lacks.
