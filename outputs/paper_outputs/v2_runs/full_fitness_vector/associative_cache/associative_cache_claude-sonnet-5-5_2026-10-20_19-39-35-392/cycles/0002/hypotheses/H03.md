# H03

Insert new items at the LRU-adjacent (second-eviction) position instead of the MRU position, so one-hit-wonders are evicted first and hit rate rises.

## Parent

cycle/0001/v001

## Changes

Starting from v001 (wider buckets, the cycle's best hit rate at 0.664), change the insertion position in the put path for a new key in the bucket. Currently a new item goes to the MRU end. Place it at roughly the 1/4 position from the LRU end, which is index `len/4` of the bucket's ordering, so it sits near the eviction end but not at the very edge. Items promote to MRU only on a hit, using the existing full move-to-back, which cycle 0001 showed matters. The update-in-place path for an existing key keeps full promotion. If the bucket is not full, still insert at that relative position. Add no per-slot metadata. Keep eviction as removing the LRU-end item.

## Rationale (optional)

This is an LIP/BIP-style scan-resistance idea using only position, and it changes the insertion path rather than the hit path (which cycle 0001 showed is the wrong place). Wider buckets from v001 give enough slots for the insertion point to differentiate items.
