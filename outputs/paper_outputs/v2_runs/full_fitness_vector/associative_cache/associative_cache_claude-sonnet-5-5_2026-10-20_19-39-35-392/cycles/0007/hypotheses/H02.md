# H02

Update the value in place without reordering on put-of-existing-key to cut put latency from the fast-put incumbent.

## Parent

cycle/0004/v001

## Changes

In the put path, where a key match is found in the bucket during the tag/key scan, overwrite the value and return immediately without any promotion swap or move (currently the matched entry is transposed/promoted). Also make sure the miss path performs a single scan pass: do the match scan and the empty-slot/victim determination in one loop so no second pass over the bucket is needed on insertion. Keep the swap-based insertion at len/4 and transpose promotion on get hits unchanged. Metadata-size must stay 40.

## Rationale (optional)

Put-hit reordering costs a write and branch per op; get-hit promotion already supplies recency signal. Tests whether put latency drops with hit rate within noise of v001 (0.7135).
