# H01

Packing per-bucket key tags into a contiguous array scanned before touching entries will cut get latency on cycle/0002/v003's policy.

## Parent

cycle/0002/v003

## Changes

In the associative cache overlay, keep the mid-insertion plus transpose-promotion policy unchanged. Change the lookup path in `get` so each bucket keeps a small contiguous array of compact tags (e.g. u8/u16 derived from the already-computed hash) stored alongside the entries, and the scan compares tags first, then compares full keys only on a tag match. Tags must be kept in sync whenever entries are inserted, swapped, or promoted (swap tags with their slots). Do not add per-slot metadata beyond the tags if metadata-size can be avoided: derive the tag from the existing stored key hash or store tags only if the metadata-size stays at 40. Preserve hit-rate behavior exactly (same victim selection and ordering). Goal: reduce memory touched per get, lowering per-op-time with identical hit rate.

## Rationale (optional)

Four cycles found no get gain from arithmetic or item movement; memory layout is the untested suspect.
