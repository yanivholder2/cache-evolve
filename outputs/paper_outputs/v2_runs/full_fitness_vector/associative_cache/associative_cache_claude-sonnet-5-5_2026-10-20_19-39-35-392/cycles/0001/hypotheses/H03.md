# H03

Replacing ClassicLRU's `Vec::remove` + `push` move-to-back with an in-place slice rotation (and a fast path for already-last items) will lower get per-op-time while keeping hit rate identical.

## Parent

baseline

## Changes

In `src/shared/eviction_policy.rs`, modify only `ClassicLRU::get_from_position`. Let `last = items.len() - 1`. If `position == last`, return `last` immediately (no movement). Otherwise call `items[position..].rotate_left(1)` (a single memmove of the tail, no intermediate copy of the removed Item and no capacity check from `push`) and return `last`. Resulting ordering must be exactly identical to the baseline (item moved to the back, others shifted down), so the hit rate must stay 0.6611 and the invariant gate must still pass. Do not touch eviction_candidate_index or promotion_candidate_index, nor the enum.

## Rationale (optional)

Targets per-op-time (baseline get p50 69ns) with a behaviour-preserving micro-optimisation of the hot hit path.
