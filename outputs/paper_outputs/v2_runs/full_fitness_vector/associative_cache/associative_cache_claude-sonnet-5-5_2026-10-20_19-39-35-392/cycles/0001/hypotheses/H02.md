# H02

Making ClassicLRU hits promote an item only halfway toward the MRU end (partial promotion) will raise hit rate on workload-a by making buckets more scan/one-hit-wonder resistant.

## Parent

baseline

## Changes

In `src/shared/eviction_policy.rs`, modify only `impl EvictionPolicy for ClassicLRU::get_from_position`. Instead of `remove(position)` + `push`, compute `target = position + (items.len() - 1 - position + 1) / 2` (clamped to len-1), and if target > position do `items[position..=target].rotate_left(1)` so the item moves to `target`; return `target`. Keep `eviction_candidate_index` = 0 and `promotion_candidate_index` = len-1 unchanged, and don't change the enum, names, or indices. Items hit repeatedly climb gradually toward the back while single-touch items stay near the eviction end. The returned index must point to the hit item (the Bucket contract reads `items[index]`).

## Rationale (optional)

Approximates a segmented-LRU / gradual-promotion scheme within the existing bucket-movement hook, with no metadata growth.
