# H03

A small global ghost ring of 4 recently evicted 16-bit key tags, which sends re-referenced keys to insertion index len/2 instead of len/4, will raise hit rate on scan-heavy traffic.

## Parent

cycle/0007/v002

## Changes

Add to the cache struct a ring of 4 `u16` tags (8 bytes) plus a 1-byte cursor; use existing padding where possible and keep the total additions at the minimum needed (confirm metadata-size impact is small). On eviction in the put-miss path, store a 16-bit tag derived from the already-computed key hash of the evicted entry's key (rehash only if the hash is stored; otherwise tag the evicted entry's key via the same hash function) into the ring at the cursor and advance it mod 4. On put-miss for a new key, compare the new key's 16-bit hash tag against the 4 ring entries (unrolled compares, no loop branch). If it matches, insert at index len/2 (proven reuse, so deeper), otherwise at len/4 as today. Do not touch the get path or promotion. Clear nothing; stale tags are harmless.

## Rationale (optional)

The earlier one-entry ghost was too weak. A 4-entry history is a more selective reuse signal that sits entirely on the put path, where extra work has been cheap.
