# H01

Switching insertion depth between len/4 and len/2 using a sampled global hit/miss counter (1-in-16 buckets) will raise hit rate over fixed len/4 at near-zero get cost.

## Parent

cycle/0002/v003

## Changes

Add a single `u32` (or two `u16`) global counter pair to the cache struct, placed in existing padding so metadata-size stays at 40. In the get path, update the counters only when `(bucket_index & 15) == 0` (sampled buckets): increment `hits` on a hit, `misses` on a miss. Do this as one predictable branch with the counter update on the cold side; no other per-hit work, promotion stays transpose-by-one.
In the put (miss-insert) path, every 1024 puts (cheap `puts & 1023 == 0` check) compare `hits` vs `misses`. If the sampled hit ratio is above a threshold (start at 0.5), set a `deep_insert` bool to use insertion index len/2, otherwise len/4. Then halve both counters (decay). Use the `deep_insert` flag in the existing insertion-index computation. Preserve all other behaviour of v003 (eviction of tail, put-hit handling).

## Rationale (optional)

Cycle 0008's global hit/miss adaptivity was the only adaptive gain with a real mechanism. Sampling should amortize the get-path tax that sank earlier per-hit additions.
