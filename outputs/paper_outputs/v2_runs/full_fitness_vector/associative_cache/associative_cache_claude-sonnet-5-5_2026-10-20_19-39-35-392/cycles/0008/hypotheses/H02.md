# H02

Fuse the put path's existence scan and free-slot search into a single pass with an unconditional swap-insert on miss to lower put latency without changing hit rate.

## Parent

cycle/0004/v001

## Changes

In `put`, the bucket is currently scanned for the key and then, on miss, handled separately (empty-slot search / eviction / swap-based insertion at ~len/4). Restructure into one loop over the bucket that (a) compares keys, returning after updating the value on a match without any reorder, and (b) records the first empty slot index while scanning. After the loop, on miss: if an empty slot was recorded, write the new item there and swap it into the len/4 position; otherwise overwrite the last (victim) slot and swap into len/4. Precompute the len/4 index as a shift (`len >> 2`) once, reuse the single hash computed for the bucket index, and avoid modulo by using a mask when the bucket count is a power of two. Do not touch the get path. Invariants: identical final bucket contents to the parent for every sequence of operations (hit rate must stay at 0.7135), metadata-size unchanged.

## Rationale (optional)

Insights say put-miss/insertion cost is the only lever that has moved; put-hit tweaks failed because puts are mostly misses, so this targets the miss path directly.
