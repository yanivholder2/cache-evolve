# H03

Adapt the insertion index between len/4 and len/2 using a single global saturating hit/miss counter to raise hit rate across scan-heavy and reuse-heavy phases.

## Parent

baseline

## Changes

Starting from baseline LRU, implement mid-bucket insertion with one-step transpose promotion on get-hit (as in the proven policy), but make the insertion index adaptive. Add one small saturating counter (u8, in struct padding if it keeps metadata-size at 40; otherwise reuse a spare field) to the cache struct. On each get: a miss increments the counter, a hit decrements it, saturating at 0 and 15. In put-miss, choose the insertion index as `len/4` when the counter is >= 8 (scan-heavy, miss streak) and `len/2` when below 8 (reuse-heavy). Insertion is done by swap, not shift. Eviction remains the last slot. No per-slot state is added. Invariants: correctness of get/put unchanged; the counter update is branch-free (arithmetic with saturating ops) to avoid get-latency cost.

## Rationale (optional)

Position-only tuning is saturated at a fixed len/4; a workload-adaptive choice is untested and uses no per-slot metadata.
