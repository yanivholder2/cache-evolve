# H01

Gate get-hit promotion on a one-bit "seen once" flag packed into existing item bits so only twice-reused entries climb, raising hit rate on the scan-heavy trace at no metadata-size cost.

## Parent

cycle/0002/v003

## Changes

In the get-hit path, currently a one-step transpose (swap with the neighbour toward the front), add a 1-bit reuse flag per slot. Pack it into spare bits of an existing field (e.g. the top bit of the stored hash/tag or key-length word) so that `Item` and the cache struct do not grow; if no spare bit exists, derive it from slot position (entries at or below the len/4 insertion index count as "unseen"). Behaviour: first hit on an entry only sets the flag (no movement); subsequent hits perform the one-step transpose. Newly inserted entries (put-miss at ~len/4) start with flag clear. Clear the flag when an entry is displaced by a swap. Keep the put path, eviction (last slot) and insertion index unchanged. Mask the flag out in all key comparisons. Invariant: get/put semantics and returned values unchanged.

## Rationale (optional)

Open question in cross-cycle insights: a small real reuse signal inside 40 bytes. Earlier counters cost per-hit work; a single-bit flag touches only data already loaded.
