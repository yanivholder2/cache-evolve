# H03

Lowering the counter saturation ceiling to 3 makes the saturated-counter store skip fire on more hot get hits, cutting get-side write traffic at a small retention cost.

## Parent

cycle/0009/v001

## Changes

Locate the constant at which a slot's access counter stops incrementing (the saturation ceiling) and set it to 3. If the parent's ceiling is already 3 or lower, skip this hypothesis and report that instead of changing anything.

Keep the parent's get-hit behaviour: increment the counter only while it is below the ceiling, and skip the counter store once it has reached the ceiling. The skip condition is therefore reached sooner, because the ceiling is lower. Keep the put-miss victim search, which still takes the exact minimum counter, unchanged. Keep the periodic global halving schedule unchanged; halving still runs on its existing schedule and must still reduce counters from the new ceiling.

Invariants to preserve: no counter ever exceeds 3; the counter width can stay as it is, or shrink if the parent stores it in a wider field than it needs; metadata layout is unchanged; the put path is unchanged apart from the lower ceiling's effect on which slot holds the minimum.

## Rationale (optional)

Cycle 0009 v001 showed a small get-tail gain from skipping saturated stores, but its get median moved the wrong way, so the skip has not yet paid off on the headline number. A lower ceiling makes the skip apply to more hot keys, which tests whether the get-side write is the cost worth removing when the skip fires often enough. The trade-off is that a lower ceiling compresses the frequency range, so hit-rate could fall if the victim choice needs finer counts to separate re-referenced keys from one-shot inserts. Cycle 0002 showed frequency signal drives the hit-rate gain, so this is a direct test of how much range that signal needs.
