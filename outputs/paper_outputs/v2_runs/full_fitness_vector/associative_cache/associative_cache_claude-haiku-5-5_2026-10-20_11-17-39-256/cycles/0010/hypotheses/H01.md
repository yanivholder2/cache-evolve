# H01

Rotating the starting slot of the minimum-counter victim scan per eviction stops equal-counter ties from always evicting the lowest-index slot, raising hit-rate on workload-a at no metadata cost.

## Parent

cycle/0002/v003

## Changes

Keep the exact minimum-counter victim search on the put-miss eviction path unchanged in what it selects as the minimum: the victim is still a slot with the global minimum counter in the bucket. Change only the tie-break among slots that share that minimum. Today the scan takes the first minimum it meets in index order, so within a bucket the low-index slots absorb most evictions among equal-counter candidates.

Add a rotating start cursor for the victim scan. Preferred form: derive the start offset from a counter that already advances on each eviction or put, taken modulo the bucket width, so no new per-bucket storage is added. If no such counter exists, add one `usize` cursor field to the cache struct, advanced by one on each eviction (wrapping modulo the bucket width), and check whether the struct-size probe moves. The scan visits the bucket's slots starting at the cursor, wrapping around, and selects the first slot whose counter equals the bucket minimum.

Invariants to preserve: the minimum is computed over every slot in the bucket, so the victim's counter is always the bucket minimum; the periodic global halving schedule is unchanged; the get path is unchanged; the metadata layout of items is unchanged.

## Rationale (optional)

Cycle 0002 v003 established frequency-based victim selection as the hit-rate lever, and later cycles only moved timing around it. Its tie-breaking has never been examined. Under heavy one-shot pressure many slots sit at the same low counter, so the index-order tie-break may repeatedly churn the same few slots, which would hold back the protection the counters are meant to give re-referenced keys. The change is small, keeps the exact-minimum policy that cycles 0004 to 0009 found to be load-bearing, and adds no hot-path work beyond a modular offset.
