# H03

Gating put-miss admission on the eviction victim's frequency, so that a new key displaces only a slot with a low access counter, will raise hit-rate on workload-a by protecting re-referenced items from one-shot inserts.

## Parent

cycle/0002/v003

## Changes

Start from cycle/0002/v003 (frequency-based victim selection with per-slot access counters and periodic halving). Keep the get path, the counter increment on hits, and the periodic halving unchanged.

In the put-miss path, when the target bucket has no free slot, the exact minimum-counter victim search already runs. After it selects the victim, compare the victim's counter against an admission threshold T. If the victim's counter is at or below T, evict it and insert the new key as before. If the victim's counter is above T, do not evict: skip the insert and return without modifying the bucket. Set T = 1 as the starting value. Do not add a sketch, a bitset, or any new per-key storage. The decision uses only counters already in the bucket.

Free-slot inserts are unaffected: when a slot is empty, insert the key without consulting T.

Keep the cache's externally visible put return value semantics unchanged, so a rejected insert looks the same to callers as a normal insert that was not retained.

## Rationale (optional)

This is a different admission signal from the doorkeeper tried in cycles 0006 to 0008: it does not track first sightings, it protects frequently referenced residents directly, and it adds no storage. Cycle 0002 showed frequency protection is the main hit-rate lever on workload-a, and cycle 0007 showed the frequency protection is fragile when a shortcut distorts the victim choice, so this variant keeps the exact victim search and only adds a refusal rule. Risk: if too many inserts are refused, hit-rate can fall on workloads with genuine recency, which is what the run should show.
