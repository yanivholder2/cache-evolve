# H01

Skipping the access-counter write-back on saturated get hits, applied on top of the Fibonacci-hash parent, will lower get-side p99 latency (per-op-time) while keeping hit-rate at or above 0.7262.

## Parent

cycle/0008/v002

## Changes

Start from cycle/0008/v002, which swaps the bucket index for a Fibonacci multiplicative hash and keeps the per-slot access counter inside the item. Keep the hash and the victim search unchanged.

In the get-hit path (the function that looks up a key and returns its value), read the item's counter as before. Only issue the counter store when the counter is below its saturation cap. When the counter is already at the cap, return the value without writing the counter back. Keep the counter in the item: do not move it to a parallel array, since cycle 0008 v003 showed that layout change removes the gain.

Leave the put path, the periodic halving schedule, and the victim scan exactly as in the parent. Do not change the metadata layout or the item size. Preserve the existing counter type and cap constant.

Measure with at least three runs on the same session against cycle/0008/v002 to separate the effect from run-to-run spread.

## Rationale (optional)

Cycle 0006 v002 showed a get-tail gain from this store skip, and cycle 0008 v003 showed the gain disappears when the counter moves out of the item, which points at the skipped store as the cause. Cycle 0008 v002 is the best per-op-time incumbent (get p50 61 ns), so this tests whether the two timing levers stack. Hit-rate should stay flat, because a saturated counter already ranks as maximally protected.
