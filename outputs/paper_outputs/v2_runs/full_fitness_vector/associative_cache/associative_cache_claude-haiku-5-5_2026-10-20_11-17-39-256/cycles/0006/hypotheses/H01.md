# H01

Restricting the frequency victim search on full-bucket puts to slots that are not reference-marked will cut put p99 latency while keeping hit-rate within 0.002 of the parent.

## Parent

cycle/0005/v002

## Changes

Keep the per-bucket reference mask and the word-level scan from the parent. In the put-path victim selection (the frequency min-counter scan that runs when the target bucket is full), first build a candidate word by ANDing the bucket's reference mask with the bucket's occupied-slot mask, then run the minimum-counter scan over only those candidate slots. If the candidate word is empty, fall back to the parent's full-bucket min-counter scan so victim choice is never undefined. Do not change the get path, the aging/halving schedule, the counter width, or the mask update rules. The mask is read only; no new state is added, so metadata-size must stay at the parent's value.

Invariants to preserve: the victim is always a valid occupied slot; the reference mask is cleared exactly where the parent clears it; the periodic halving schedule is unchanged.

Verification target: put p99 below the parent's 205 ns on the same trace and size (lirs workload-a, size 2048), hit-rate within 0.002 of 0.7244, metadata-size 40.

## Rationale (optional)

The cycle 0005 insight says the put tail was not explained by the aging rounds or the zero-counter early exit, and that the victim search on full-bucket puts is the next thing to profile. Restricting the scan to unreferenced candidates shrinks the scanned set on the common full-bucket put, which targets the tail directly rather than the median that v002 already improved.
