# H03

Giving each bucket a small ring of recently evicted keys, and reinserting a returning ghost key at the bucket midpoint instead of the back, raises hit-rate on workload-a by protecting re-referenced items that were evicted too early.

## Parent

baseline

## Changes

Overlay `src/associative_cache/associative_cache_bucket.rs` only. Keep the `AssociativeCacheBucket` struct name and its `new(settings)` constructor signature.

1. Add a field `ghosts: Vec<K>` (capacity 4, allocated in `new()` with `Vec::with_capacity(4)`) and a field `ghost_next: usize` as a round-robin write index. Keep the existing `items`, `max_size`, and `eviction_policy` fields as they are.

2. Override `put` in `impl Bucket<K, V> for AssociativeCacheBucket<K, V>` with a full body (the trait default in `src/shared/traits/bucket.rs` is not called):
   - If the key already exists (`get_position` is `Some`), update the value in place and call `get_from_position` as the default does, returning `(item, None)`.
   - Otherwise, if the bucket is full, call `evict_item()`. Before returning, record the evicted key into `ghosts` at `ghost_next` (overwrite if at capacity 4), then advance `ghost_next` modulo 4.
   - If the new key is present in `ghosts`, remove that entry from `ghosts` and insert the item at index `items.len() / 2` (midpoint of the post-eviction bucket) instead of pushing to the back.
   - Otherwise push to the back as the default does.
   - Return `(&self.items[idx], evicted)` for the index where the item landed. Do not rely on `items.last()` for the midpoint case.

3. Leave `get`, `get_from_position`, the eviction policy, and the geometry untouched. Lookups still use the default `get_position` linear scan.

Expected trade-off: hit-rate should move on workload-a, since returning keys reenter in a protected position. `put` gets a small extra cost from the ghost membership scan over 4 keys and a `Vec::insert` in the ghost case, so per-op-time p50 for `put` should rise slightly. `metadata-size` should increase by the `Vec` header and the 4-slot ghost buffer per bucket. Record the measured delta against the baseline's 24-byte `AssociativeCache` and 40-byte `Item` figures so the cost is visible.

## Rationale (optional)

Ghost tracking is the bucket-local analogue of ARC/2Q-style admission memory. It stays inside the bucket extension point, so it needs no change to cross-bucket routing, which this cycle does not touch.
