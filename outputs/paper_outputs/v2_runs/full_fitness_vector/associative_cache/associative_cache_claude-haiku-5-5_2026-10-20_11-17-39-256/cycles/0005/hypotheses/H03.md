# H03

Replacing the iterative aging rounds in the 2-bit re-reference victim search with a single max-scan and one bulk aging step will cut the put tail latency of the re-reference policy while keeping its hit-rate unchanged.

## Parent

cycle/0004/v003

## Changes

In the victim search that runs on a full-bucket put, replace the loop that checks for a slot at the maximum re-reference value and, when none is found, increments every slot's value and repeats (up to three rounds), with a two-step procedure:

1. One pass over the bucket's slots to compute `max_rrpv`, the largest re-reference value present, and the first slot index that holds it.
2. Compute `delta = RRPV_MAX - max_rrpv`. If `delta > 0`, add `delta` to every slot's value, saturating at `RRPV_MAX`. Select the first slot (by the same index order the parent uses) whose value is now `RRPV_MAX` as the victim.

This is equivalent to the parent's round-by-round aging, because each parent round adds 1 to every slot and the search stops at the first round where some slot reaches the maximum. The bulk add therefore yields the same victim and the same post-eviction values, and it needs one scan plus one update pass instead of up to three of each.

Keep the insert value (2), the clear-to-0 on hit, the get-hit write, and the victim tie-break order exactly as in the parent. Do not change the number of bits per slot or the bucket layout, so metadata-size stays 40.

Invariant to preserve: for any bucket state, the chosen victim and the stored values after eviction must equal the parent's. Hit-rate on workload-a should match the parent exactly (0.6827).

## Rationale (optional)

Cycle 0004's insight says the re-reference policy's cost has moved to the put tail, from the bounded aging rounds on a full-bucket put, and that follow-ups should keep hit-rate fixed. Capping the rounds would change behaviour and could lose hit-rate, so this hypothesis instead removes the repeated passes while preserving the exact aging semantics. If put p99 does not drop, the tail is coming from something other than the aging loop, such as the victim scan itself, and that would change the next cycle's direction.
