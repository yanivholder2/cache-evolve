**What the overlay does (CLOCK in the baseline's `ClassicLRU`)**

The hypothesis asks to replace the baseline's recency-ordered victim choice, so I changed `ClassicLRU` in place rather than adding a new policy kind. That keeps the eval and invariant paths, which use `ClassicLRU`, exercising the change.

- **Hit:** `get_from_position` sets the item's reference bit and no longer moves the item.
- **Eviction:** `eviction_candidate_index` runs a per-bucket clock hand (a `Cell<usize>` in the policy). It clears set bits as it passes and evicts the first slot whose bit is clear. The scan is capped at 2n steps, so it always terminates.
- **Insert:** new items start with the bit clear.
- Insert, get-miss and key lookup are unchanged. There is no fingerprint prefilter, no ghost memory, no per-slot counters, and bucket width is unchanged.

**Files written under `overlay/`**

- `src/shared/item.rs`: adds `referenced: Cell<bool>` to `Item`. The `Cell` is needed because the eviction scan only holds `&[Item]`.
