# H01

Stacking the cycle 0006 doorkeeper admission gate onto the frequency-counter incumbent, with an inline bitset and an amortised clear, raises hit-rate on workload-a above 0.7278 without adding put-tail cost.

## Parent

cycle/0006/v002

## Changes

Start from the v002 overlay (saturated-counter store skip on get hits, frequency-based victim selection). Port the doorkeeper gate from cycle/0006/v003 onto the put-miss path in the insert routine, before the victim scan is entered:

- Replace the boxed bit array in the doorkeeper with a fixed-size inline `[u64; W]` field on the cache struct, sized as a power of two so the bit index is a mask, not a modulo. Keep the hash of the key as the bit index source.
- Do not perform a whole-structure clear every N put misses. Instead, keep a clear cursor on the struct and, on each put miss, zero one word of the bitset at the cursor and advance it. A full sweep then completes over the same N misses, and no single put pays for the whole clear.
- On a put miss, if the key's bit is unset, set it and reject the insert (skip the victim scan). If the bit is already set, proceed with the normal victim scan and insert path. Get-hit behaviour and the saturated-counter store skip stay exactly as in v002.
- Keep the victim-selection code of v002 unchanged, so frequency state and eviction order match v002 except for the keys the gate filters out.

Invariants to preserve: no per-item metadata change (Item layout unchanged), no change to the get path beyond what v002 already does, and the doorkeeper struct field must be inline so the struct size growth is visible to the size probe.

Measure hit-rate on workload-a at size 2048, then the put and get p50/p99 over repeated runs.
