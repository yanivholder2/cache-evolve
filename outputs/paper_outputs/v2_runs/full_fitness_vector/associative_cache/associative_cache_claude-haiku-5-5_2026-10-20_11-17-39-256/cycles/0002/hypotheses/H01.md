# H01

Adding a per-bucket one-byte key fingerprint array in front of the linear slot scan will cut get-path p50 latency back below baseline while keeping v001's hit-rate gain.

## Parent

cycle/0001/v001

## Changes

Keep v001's `BaselineGeometry::layout` change (64 buckets × 32 slots for the 2048-slot budget) unchanged. Add a fixed-size `[u8; 32]` fingerprint array to each bucket, holding a truncated hash of the key stored in each occupied slot (0 for empty). In `get_position()`, compute the one-byte fingerprint of the probe key once, scan the fingerprint array first, and only compare full keys at slots whose fingerprint matches. Update the fingerprint array wherever a slot is written or cleared: insertion, eviction/replacement, and the `remove` + `push` promotion path on get hits. Do not change the eviction order, promotion order, or hit/miss semantics, so hit-rate should match v001 exactly on the same trace. Preserve the existing public API and the `AssociativeCache` metadata layout apart from the added bucket field.

## Rationale (optional)

v001 showed the widened bucket is a clear hit-rate win, but `get` latency rose because `get_position` compares full keys across 32 slots. Fingerprint pre-filtering targets exactly that cost without touching policy. The fingerprint array adds bucket state, so the metadata-size probe should be checked to see that it now reports the extra bytes.
