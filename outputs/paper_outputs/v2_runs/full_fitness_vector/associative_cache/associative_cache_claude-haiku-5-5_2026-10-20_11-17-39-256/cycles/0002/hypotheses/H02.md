# H02

Enlarging the bucket-local ghost ring from four to sixteen keys will raise hit-rate on workload-a by letting returning keys be recognised after longer reuse distances.

## Parent

cycle/0001/v003

## Changes

Keep v003's ghost-ring structure and midpoint reinsertion on ghost hit unchanged. Change the ghost ring capacity per bucket from four keys to sixteen, so the ring holds the sixteen most recently evicted keys of that bucket (oldest dropped first). Keep the ghost lookup on the miss path as in v003. To limit the added `put` cost, store the ghost keys in a fixed-size array with a rolling index rather than growing a `Vec`, so no allocation happens on eviction. Do not add a hit-count gate in this variant; this hypothesis isolates ring length. Update the size probe to include the ghost array so metadata-size reflects it.

## Rationale (optional)

v003's insight suspected the four-slot ring was expiring returning keys before they came back. Sixteen slots tests that directly. If hit-rate still does not move at sixteen, the reinsertion idea itself is weak on this trace and should be dropped rather than tuned further.
