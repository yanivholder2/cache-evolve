# H02

Moving a bucket's evicted item into its alternate bucket, cuckoo-style with a bounded displacement chain, will raise hit rate above the baseline 0.6611 by keeping recently used items that lost only a local LRU contest.

## Parent

baseline

## Changes

Edit `src/associative_cache/mod.rs` (`AssociativeCache::put` and `get_and_update_item`), `src/shared/utils.rs`, and `src/shared/eviction_policy.rs`.

1. **Alternate bucket.** Add a helper in `src/shared/utils.rs`, `alt_index(key, n) -> usize`, that derives a second bucket index from the upper hash bits: `((h >> 32) ^ h.rotate_left(29)) % n`. If it equals the primary index `h % n`, use `(primary + 1) % n` instead. Each key therefore has exactly two legal buckets: primary `p` and alternate `a`.

2. **Put.**
   - If the key already exists in `p` or `a`, update it in place. No movement happens.
   - Otherwise always insert the new item into its **primary** bucket `p` with `bucket.put(...)`.
   - If that returns an evicted item `e`, do not drop it right away. Run a displacement loop with a constant `MAX_KICKS = 2`:
     - Compute `e`'s *other* legal bucket. If `e` is in its primary now, that is `alt_index(e.key)`; otherwise it is `get_index(e.key)`.
     - If that bucket has free space, push `e` there and stop.
     - If it is full, push `e` only if `e.timestamp` is newer than that bucket's eviction-candidate timestamp (the front item for ClassicLRU). That evicts the candidate, which becomes the new `e` for the next iteration.
     - If `e` is older than the candidate, drop `e` and stop. This is a true eviction.
     - After `MAX_KICKS` iterations, drop whatever item is still displaced.
   - Use `Bucket::put` for inserts and `evict_item`/`eviction_candidate_index` for victim selection, so the bucket's eviction policy still decides *which* item leaves a bucket.

3. **Get.** Probe `p` first, then `a`. On a hit, call `get_from_position` on the bucket that holds the key, which applies the ClassicLRU move-to-back. On a hit in `a`, do **not** move the item back to `p`; keep the get path cheap.

4. **Recency signal.** Change ClassicLRU's `get_from_position` to refresh `items[position].timestamp = Instant::now()`. Then the timestamp comparison in step 2 reflects last access, not insertion time. `Item::new` already stamps insertion time.

5. **Invariants to keep:**
   - A key is in at most one bucket, and only in its `p` or `a`. The displacement loop must compute each item's legal buckets from its key, never from where it currently sits.
   - Bucket sizes never exceed `max_size`.
   - Total capacity is unchanged; do not touch `geometry.rs`.
   - Exactly one item leaves the cache per put that overflows, or none if a free slot absorbs it.

   Update the editable in-file test `eviction_when_bucket_full` in `mod.rs` to match the new semantics.

## Rationale (optional)

H01 picks a bucket once, at insert time. This hypothesis instead always inserts into the primary bucket and relocates items *after* they lose a local eviction. Its cost lands on the put path (bounded at 2 extra bucket operations) rather than on placement logic, so it tests whether post-eviction migration beats load-aware placement.
