# H01

Placing each new key in the less-loaded or staler of two hash-chosen candidate buckets (power-of-two-choices) will raise hit rate above the baseline 0.6611 by smoothing per-bucket load imbalance.

## Parent

baseline

## Changes

Edit `src/associative_cache/mod.rs` (`AssociativeCache`) and, where noted, `src/shared/utils.rs` and `src/shared/eviction_policy.rs`. Keep `src/shared/traits/bucket.rs` default methods unchanged unless a helper is clearly needed.

1. **Two candidate buckets per key.** Add `pub fn get_two_indices<K: Hash + Debug>(key: &K, n: usize) -> (usize, usize)` to `src/shared/utils.rs`. It calls `hash(key)` once. It returns `i1 = h % n` and `i2 = ((h >> 32) ^ (h.rotate_left(17))) % n`. If `i2 == i1`, set `i2 = (i1 + 1) % n` so the two buckets always differ when `n > 1`. When `n == 1`, return `(0, 0)` and fall back to single-bucket behaviour. Keep `get_index` as it is.

2. **Get (`get_and_update_item`).** Compute `(i1, i2)`. Look up the key with `bucket.get_position(key)` in `i1` first, then in `i2`. On a hit, call `get_from_position` on the bucket that holds the key, so ClassicLRU still moves the item to the back. Return `None` only when both buckets miss. This changes the borrow pattern a little: find the bucket index first, then take one `&mut self.buckets[idx]`.

3. **Put (`put`).** Compute `(i1, i2)`.
   - If the key already exists in either bucket, update it in place through that bucket's `put`, which takes the existing-key path. Never insert a duplicate. **No key may be in both buckets at once.**
   - Otherwise choose the target bucket like this:
     - (a) If exactly one bucket is not full, use it. If both are not full, use the one with the smaller `size()`; on a tie, use `i1`.
     - (b) If both are full, compare their eviction candidates. Use the bucket whose ClassicLRU candidate (index 0, the front item) has the older `timestamp`, so the globally staler item of the two is evicted.
   - Call `bucket.put(Item::new(key, value))` on the chosen bucket. Nothing else moves; after insertion an item stays in the bucket where it was placed.

4. **Recency signal for step 3b.** Today ClassicLRU's `get_from_position` does not refresh `Item.timestamp`. Change it to set `items[position].timestamp = Instant::now()` before the remove/push, so the front item's timestamp reflects its last access. Do not change ClassicLRU's ordering semantics.

5. **Invariants to keep:**
   - Total capacity is unchanged: same `num_of_buckets` × `bucket_size`, and `geometry.rs` is not touched.
   - Each bucket holds at most `max_size` items.
   - A key is found in at most one bucket.
   - `put` followed by `get` of the same key always hits.

   Update the in-file unit test `eviction_when_bucket_full` in `mod.rs` (it is in the editable overlay) so it no longer assumes single-bucket placement. For example, fill both candidate buckets, or assert only that total occupancy is bounded.

## Rationale (optional)

With 128 buckets of 16 ways, hash skew and hot sets that cluster in a few buckets cause early evictions while other buckets are underused. Two-choice placement is a well-known way to reduce the maximum load. Its cost is a second probe on misses, so get p50 per-op time may rise somewhat (baseline 69 ns). Metadata size should stay the same.
