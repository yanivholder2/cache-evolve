# H01

Replacing v003's split home/partner halves with one plain ClassicLRU over each merged 32-way physical bucket will raise hit rate above baseline (0.6611) while keeping v003's per-op time (get p50 ≈ 56 ns).

## Parent

cycle/0001/v003

## Changes

Keep v003's mechanics: hash once per op in `AssociativeCache::put` / `get_and_update_item`, map to `p = h % buckets.len()`, and keep one contiguous `Vec<Item>` per physical bucket. `AssociativeCache::try_new` still builds `(n + 1) / 2` physical buckets. Paired buckets hold `2 * bucket_size` slots and the odd trailing bucket holds `bucket_size`, so total capacity stays `n * bucket_size`.

In `src/associative_cache/associative_cache_bucket.rs`, remove the half logic completely:

1. Delete the `len0`, `half_size`, `paired`-dependent half routing, and `divisor` fields. Also delete `home_half_of_hash`, `home_half_of_key`, `range`, `half_len`, `half_of_position`, `push_half`, `insert_half_at`, `candidate_in` and `evict_from`. Keep `max_size`, which is `2 * bucket_size` when paired and `bucket_size` otherwise. `with_layout(settings, paired, _divisor)` may keep its signature so `mod.rs` doesn't change, but it only uses `paired` to set `max_size`.
2. `pair_get(key, _h)`: run one linear scan `items.iter().position(|d| d.key == *key)` over the whole bucket. On a hit, apply `eviction_policy.get_from_position_in_slice(&mut items[..], pos)` and return `&items[new_pos]`. There is no promotion and no partner probe.
3. `pair_put(item, _h)`: scan once for an existing key. If it is found, update the value in place and touch it. Otherwise, if `items.len() >= max_size`, remove `items[eviction_candidate_index(&items)]` and return it as the dropped item. Then `items.push(item)`. There is no demotion and no timestamp comparison.
4. `remove_at` becomes a plain `items.remove(index)`. Update `Display` to drop the `[half]` tag.
5. In `src/shared/eviction_policy.rs`, remove the `items[position].timestamp = Instant::now()` line from `ClassicLRU::get_from_position_in_slice`. ClassicLRU orders by position, so the wall-clock read is pure overhead now that no cross-half comparison needs it. Leave TimestampLRU unchanged. Update the test `classic_lru_slice_touch_moves_to_back_and_refreshes` so it only checks ordering.
6. Tests in `mod.rs`: delete `partner_hit_promotes_home`. Keep `pair_capacity_and_slot_legality_under_overfill`. Rewrite `eviction_when_bucket_full` so it fills one physical bucket past `max_size` and asserts that the first-inserted key is gone and the rest are present.

Invariants: each key lives only in bucket `hash % buckets.len()`, `size() <= max_size`, and there are no duplicates.

## Rationale (optional)

Cycle 0001 could not tell v003's speedup apart from its split-LRU policy, which it suspected of costing hit rate. True LRU over 32 ways is a closer approximation of global LRU than 16-way LRU, so conflict misses should drop. This variant is the clean control for every later policy experiment.
