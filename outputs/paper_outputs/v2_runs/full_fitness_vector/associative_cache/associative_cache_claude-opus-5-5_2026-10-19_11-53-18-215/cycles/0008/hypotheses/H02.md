# H02

Laying out the bucket hot/cold, with tags stored inline in the bucket struct and the ghost, meta and policy state moved out of the get path, will lower per-op-time (get p50) below v001's 45 ns with hit-rate unchanged.

## Parent

cycle/0007/v001

## Changes

The get path does not use most of the bucket. Today one get touches:
- the `buckets` Vec element, which is `AssociativeCacheBucket` at about 150 bytes, or 3 cache lines, holding `items`, `tags`, `ghosts` and `meta` Vec headers, `usize` counters, a `bool`, and a `Box<dyn EvictionPolicy>`;
- then the separate heap allocation for `tags`;
- then the separate heap allocation for `items`.

This hypothesis cuts each get to about one struct line plus one items line. It
changes no replacement decision.

Edit `src/associative_cache/associative_cache_bucket.rs`:

1. **Inline tags.** Replace `tags: Vec<u16>` with a fixed inline array
   `tags: [u16; INLINE_TAGS]`, where `const INLINE_TAGS: usize = 32`. The
   live length is always `items.len()`. Keep the `Vec<u16>` path as a
   fallback only for buckets with `max_size > INLINE_TAGS`. A small enum or
   a `Box<[u16]>` used only when needed is acceptable. The common case
   (`max_size <= 32`) must not allocate for tags.
   - Mirror every current `tags.insert`, `tags.remove`, `rotate_left` and
     `push` with `copy_within` or a `rotate_left` on
     `tags[..len]`/`tags[a..b]`.
   - `find_tagged` scans `&tags[..items.len()]` with the same 16-wide
     branch-free mask.
2. **Narrow, hot-first fields.**
   - Store `len0`, `protected_cap` and `max_size` as `u16`, or `u32`
     everywhere they are used.
   - Pack `slru` and `ghost_head` into the same word.
   - Order the fields so `items`, `len0`, `protected_cap` and the first
     tag block are in the first 64 bytes. Use `#[repr(C)]` to fix the
     order.
3. **Cold side state.** Move `ghosts`, `ghost_head`, `meta` and
   `eviction_policy` into a `Box<ColdState<K, V>>`. Only the miss/put path
   and the non-SLRU fallback read it, so `pair_get_tagged` and `hit` (SLRU
   branch) never dereference it.
   - Do not touch the ghost logic: same ring length, same
     `record_ghost`/`take_ghost` semantics, same use of the stored tag.
   - The `Bucket` trait's `get_eviction_policy` returns
     `&*self.cold.eviction_policy`.

Preserve these exactly:
- every SLRU decision in `hit` and `pair_put_tagged`: mid-probation cold
  insert, ghost-hit insert at probation MRU, `len0 == 0` fallback, 7/8 cap
  with a probation floor of 2 at 16+ slots;
- `remove_at` and `sync_tags`, which must still rebuild the tags when
  `items` is edited externally through `get_items_mut`;
- `check_structure` must still hold. Adapt it and
  `tags_stay_in_lockstep_under_10k_mixed_ops` so they compare
  `tags[..items.len()]`.

`mod.rs` stays as it is (one hash, `tag_of_hash`). Do not change `Item`,
which must stay 16 bytes, or the cache header, which must stay 24 bytes.

## Rationale (optional)

The 0005 and 0007 results show that this design's cost is mostly data
movement and memory touched, not decision logic. The narrow `Item` and the
tag-first scan each helped without changing hit rate. Bucket-struct
locality is the remaining memory-touch cost on get. It is separate from
H01's cap change and H03's placement change.
