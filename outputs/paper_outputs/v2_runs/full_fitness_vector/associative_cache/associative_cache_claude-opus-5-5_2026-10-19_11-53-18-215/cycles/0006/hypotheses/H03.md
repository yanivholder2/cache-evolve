# H03

Doubling the per-bucket ghost ring from max_size/2 to max_size entries, with the fingerprint taken from the single bucket hash, will raise hit-rate on cycle 0005 v003 by catching longer reuse distances.

## Parent

cycle/0005/v003

## Changes

There are two coordinated edits. Both serve the ghost-history axis.

1. **Larger ring.** In `AssociativeCacheBucket::with_layout`
   (`src/associative_cache/associative_cache_bucket.rs`), change
   `let ghost_len = if slru { (max_size.saturating_add(1) / 2).max(1) } else { 0 };`
   to `let ghost_len = if slru { max_size.max(1) } else { 0 };`.
   Leave `record_ghost`, `take_ghost` (clear on hit), and the placement rules
   unchanged:
   - a ghost hit goes to probation MRU
   - a cold key goes to `len0 / 2`
   - nothing ever enters protected directly

2. **No second hash.** `AssociativeCache::put` in
   `src/associative_cache/mod.rs` already computes `hash(&key)` to pick the
   bucket, and `fingerprint()` calls the same `hash` again. Do these steps:
   - Compute `let h = hash(&key);` once in `put`.
   - Use `h % self.buckets.len()` to pick the bucket.
   - Call a new `pair_put_hashed(item, fp)` with `fp = fingerprint_from_hash(h)`.
     The new helper is `((h as u64) >> 48) as u16`, with 0 mapped to 1, which
     is the same bits as today.

   In the bucket, keep `pair_put(item)` as a thin wrapper that computes the
   fingerprint itself and delegates. `Bucket::put` and the tests call it.
   - `take_ghost` uses the passed `fp`.
   - `evict_front` and the cold-path eviction still call
     `record_ghost(&old.key)`. That hashes the *evicted* key, and that hash is
     unavoidable.

Do not change:
- `get_and_update_item`
- `hit()`
- `protected_cap` (stay at 3/4, so this measures the ring effect on its own)
- `Item`, which stays 16 bytes

Update the `ghost_ring_wraps_and_stays_bounded` test so it expects
`b.ghosts.len() == 8` for `bucket8()`. Add a test:
- Fill `bucket8()`.
- Evict 6 distinct keys in a row with cold puts.
- Re-put the first evicted key.
- Assert it lands at probation MRU (`len0 - 1`). That shows it was still
  remembered past the old 4-entry window.

## Rationale (optional)

Ghost history helps only when it decides placement (cycles 0004–0005), and
the cross-cycle open question asks whether a larger ring would catch longer
reuse distances on this LIRS-like trace. A ring of max_size/2 forgets a key
after half a bucket's worth of evictions. The parent's ring stores 16-bit
fingerprints in a side `Vec`, so the extra ghost memory is outside the
metadata-size dimension. Removing the second hash on put offsets the slightly
longer linear ring scan, so any put-tail change can be attributed to ring
length rather than hashing.
