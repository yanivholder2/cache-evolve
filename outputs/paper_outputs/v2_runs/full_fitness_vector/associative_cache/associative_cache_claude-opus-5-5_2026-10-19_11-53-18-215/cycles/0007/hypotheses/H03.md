# H03

Raising the SLRU protected cap from 7/8 to 15/16 on buckets of 16 or more slots will raise hit rate above cycle 0006 v001's 0.7295 and leave metadata-size at 16.

## Parent

cycle/0006/v001

## Changes

Start from cycle/0006/v001's `src/associative_cache/associative_cache_bucket.rs`. The only code change is the `protected_cap` computation in `with_layout`.

Replace

```rust
let probation_min = if max_size >= 16 { 2 } else { 1 };
let protected_cap = (max_size * 7 / 8).min(max_size.saturating_sub(probation_min));
```

with

```rust
// 15/16 of the slots on large buckets, keeping a probation floor of
// max(1, max_size / 16): 4 -> 3, 8 -> 7, 16 -> 15, 32 -> 30, 64 -> 60; 1 -> 0.
let protected_cap = if max_size >= 16 {
    max_size - (max_size / 16).max(1)
} else {
    (max_size * 7 / 8).min(max_size.saturating_sub(1))
};
```

Buckets with fewer than 16 slots keep exactly 0006 v001's caps (4 → 3, 8 → 7, 2 → 1, 1 → 0). Larger buckets give protected one extra slot per 16.

Keep the ghost ring at `(max_size + 1) / 2` slots. Keep cold-key insertion at `len0 / 2`, ghost-hit insertion at probation MRU, the demote-at-cap rule and the 16-byte `Item` unchanged. With `len0` usually equal to 1 on a 16-slot bucket, `mid = 0`, so a cold key replaces the probation LRU in place. That is already a valid path in the existing code and needs no new branch.

Update the test `protected_cap_is_seven_eighths_with_scaled_floor`: rename it `protected_cap_is_fifteen_sixteenths_on_large_buckets` and set the expected values to `(1,false,0) (2,false,1) (2,true,3) (4,true,7) (8,true,15) (16,true,30)`. All other tests should pass unchanged. Make sure `long_scan_never_evicts_protected` still passes on a 16-slot bucket as well.

## Rationale

Every increase of the protected share so far has raised hit rate on this LIRS-style trace: 3/4 → 7/8 gave +0.005. Cycle 0005 v002 showed that a probation floor of 2 cancels the cap's gain at 8 slots, and the 16-slot case still keeps 2 probation slots under 0006 v001's rule. This variant tests whether the hit-rate curve keeps rising above 7/8 or has flattened, which is an open question carried in the cross-cycle insights. It is a hit-rate probe, accepted as a trade-off: get and put may slow slightly because the protected segment is longer. If the factory resolves to buckets smaller than 16 physical slots, this variant is a deliberate no-op, and an unchanged hit rate tells us the geometry rather than the policy is the limit.
