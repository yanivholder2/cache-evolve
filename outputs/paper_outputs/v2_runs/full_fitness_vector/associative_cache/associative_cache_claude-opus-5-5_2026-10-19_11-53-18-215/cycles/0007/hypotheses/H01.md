# H01

Adding cycle 0005 v001's tag-first single-hash `find` to cycle 0006 v001's 7/8-cap 16-byte SLRU will lower the get-p50 per-op-time and leave hit rate at 0.7295 and metadata-size at 16.

## Parent

cycle/0006/v001

## Changes

Start from cycle/0006/v001 (`src/associative_cache/associative_cache_bucket.rs` and `mod.rs`, attempt 01). Keep the 16-byte `{ key, value }` `Item` in `src/shared/item.rs` exactly as it is. Do not add any field to `Item`. Keep the 7/8 protected cap and the scaled probation floor in `with_layout` (`probation_min = if max_size >= 16 { 2 } else { 1 }`) unchanged.

Port the tag machinery from cycle/0005/v001's `associative_cache_bucket.rs`:

1. **Tag array.** Add a `tags: Vec<u16>` field parallel to `items`, allocated with capacity `max_size`. Invariant: `tags.len() == items.len()` and `tags[i] == tag_of_hash(hash(&items[i].key))` at all times. Add `pub(crate) fn tag_of_hash(h: usize) -> u16 { (((h as u64) >> 48) as u16).max(1) }` and redefine `fingerprint` as `tag_of_hash(hash(key))`.
2. **Lookup.** Add `find_tagged(&self, key, tag)` using the block scheme from 0005 v001: `TAG_BLOCK = 16`, a branch-free match bitmask per `chunks_exact` block, full-key confirmation at set bits in ascending order, then the remainder loop. Make `find` call `find_tagged(key, fingerprint(key))`.
3. **Single hash per op.** In `mod.rs`, compute `let h = hash(&key);` once in `put` and in `get_and_update_item`. Use `h % buckets.len()` for the bucket index and `tag_of_hash(h)` for the tag. Call new `pair_get_tagged(key, tag)` and `pair_put_tagged(item, tag)`. Keep `pair_get` and `pair_put` as thin wrappers that compute the tag, for the tests and the `Bucket` trait.
4. **Keep tags in lockstep with every move of `items`:**
   - In `hit()`, the protected-hit rotate, the `protected_cap == 0` rotate and the probation-promote rotate each get an identical `tags[..].rotate_left(1)` over the same range.
   - The ghost-hit / `len0 == 0` branch does `tags.insert(self.len0, tag)`.
   - The cold-key full branch does `mem::replace` on `tags[0]` plus `tags[0..=mid].rotate_left(1)`. Read the evicted tag from `tags[0]` before replacing it, and pass that tag to `record_ghost`. Do not rehash the evicted key.
   - The cold-key non-full branch does `tags.insert(mid, tag)`.
   - `remove_at` also does `tags.remove(index)`.
   - `evict_front` reads `tags[0]` before removal and records that tag. Change `record_ghost` to take a `u16`.
   - `take_ghost` uses the passed-in tag, so the ghost path no longer computes a second hash.
5. **Fallback (non-SLRU) path.** Keep 0006 v001's `meta` vector. After any fallback reorder (`get_from_position_meta`, eviction, push), also keep `tags` in sync, either by mirroring the remove/push or by calling a `rebuild_tags()` helper after `get_from_position_meta`. `Bucket::put` should use `find_tagged` for its re-find.

Add a debug-only `check_structure` assertion that every tag matches its item's key. Run it in the existing bucket tests, plus one test that drives 10k mixed get/put operations through an 8-slot and a 16-slot SLRU bucket.

## Rationale

Cycle 0005 v001 lowered the get median with this lookup, but it was never carried forward. Cycle 0006 v001 got slower on get partly because every probation hit compares full 16-byte keys across the whole bucket, and partly because protected rotates are longer. The tag scan removes most full-key compares on hits and misses, and the single hash removes one hash per op. Tag upkeep adds one rotate of 2-byte elements next to each 16-byte rotate, roughly 12% more bytes moved. Comparing get-p50 against 0006 v001 (59 ns) isolates the lookup lever on the higher-hit-rate base.
