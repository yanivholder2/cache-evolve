# H01

Stacking the 15/16 protected cap on v003's probation-LRU cold entry, with probation kept at two or more slots on buckets of 16+ slots, raises hit rate above 0.7333.

## Parent

cycle/0008/v003

## Changes

Only `AssociativeCacheBucket::with_layout` in
`src/associative_cache/associative_cache_bucket.rs` changes: the `protected_cap` formula.

Current v003 formula: `probation_min = if max_size >= 16 { 2 } else { 1 }; protected_cap = (max_size * 7 / 8).min(max_size - probation_min)`.

New formula:

```rust
let protected_cap = if max_size >= 16 {
    max_size - (max_size / 16).max(2)
} else {
    (max_size * 7 / 8).min(max_size.saturating_sub(1))
};
```

The resulting caps are 1 -> 0, 2 -> 1, 4 -> 3, 8 -> 7, 16 -> 14, 32 -> 30, 64 -> 60 and 128 -> 120. This is cycle 0008 v001's 15/16 cap, except that probation is never narrower than 2 slots once the bucket has 16+ slots. That keeps a real gap between probation LRU (where cold keys now enter) and probation MRU (where demoted-protected items and ghost-hit keys land). With a 1-slot probation the two positions would be the same and v003's lever would disappear.

Leave everything else in v003 as it is: tag-first find, single hash, ghost ring size, cold keys at index 0 with in-place replacement when full, ghost hits at probation MRU, and eviction only from `items[0]`. Update the `protected_cap_is_seven_eighths_with_scaled_floor` unit test to the new expected table (rename it, for example to `protected_cap_fifteen_sixteenths_floor_two`), and update the doc comment at the top of the file. `check_structure` invariants stay as they are.

## Rationale (optional)

v001 (the 15/16 cap) and v003 (LRU cold entry) were each Winners because they changed separate axes. The cycle 0008 insight warned that at 15/16 the probation at 16 slots shrinks to 1, which cancels LRU entry. This variant tests whether the two stack when probation is held at 2 or more slots. If hit rate does not beat 0.7333, then cap and admission are substitutes on this trace rather than complements.
