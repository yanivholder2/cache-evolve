# H02

Adding a small per-bucket aged miss-frequency counter array, so repeat-missing cold keys enter probation at MRU instead of LRU, raises hit rate over v003's single-bit ghost signal.

## Parent

cycle/0008/v003

## Changes

All changes are in `src/associative_cache/associative_cache_bucket.rs` and apply to the SLRU path only. The non-SLRU fallback is untouched.

1. **New fields on `AssociativeCacheBucket`:**
   - `freq: Vec<u8>`, with length `F = max_size.next_power_of_two().max(8)` when `slru` and empty otherwise.
   - `freq_ops: u32` (a puts-since-aging counter).

   Initialise both in `with_layout`.

2. **Helpers (both `#[inline]`):**
   - `fn freq_estimate(&self, tag: u16) -> u8` returns `min(freq[i1], freq[i2])`, where `i1 = tag as usize & (F-1)` and `i2 = (tag.rotate_left(8) as usize) & (F-1)`. This is a 2-row count-min over the tag the caller already has. It needs no extra hashing.
   - `fn freq_bump(&mut self, tag: u16)` saturating-increments both counters with a cap of 15. It then increments `freq_ops`, and when `freq_ops >= 4 * max_size` it halves every counter (`*c >>= 1`) and resets `freq_ops = 0`. The aging step is a simple loop over at most `F` bytes.

3. **In `pair_put_tagged`, new-key SLRU path only:**
   - Right after `let ghost_hit = self.take_ghost(tag);`, compute `let seen = self.freq_estimate(tag) >= 2;` and then call `self.freq_bump(tag);`. The estimate is read before the bump, so a key needs at least two earlier misses inside the aging window.
   - Change the condition `if ghost_hit || self.len0 == 0` to `if ghost_hit || seen || self.len0 == 0`. Frequency-qualified cold keys then take the existing ghost-hit branch: evict `items[0]` if full, then insert at probation MRU (`len0`).
   - All other keys keep v003's probation-LRU in-place entry.
   - Do **not** bump on get hits or on resident-key updates. The get path must stay exactly as it is.

4. **Invariants:**
   - Keys are never admitted to protected on a put.
   - Eviction still happens only at `items[0]`.
   - `tags` stays in lockstep with `items`.
   - The ghost ring is unchanged.
   - `Item` stays `{ key, value }`. The counters are per-bucket and are not stored per item.

5. **Tests:**
   - Add a unit test showing that a key put-evicted-put-evicted (missing three times) lands at probation MRU even when its ghost entry has been overwritten.
   - Add a unit test showing that a never-seen key still lands at index 0.
   - Extend `slru_bucket_has_no_meta` to assert that `freq.len() == F`.

## Rationale (optional)

The ghost ring is about half a bucket long, and a bigger ring was shown to hurt. So the ring only remembers a key for roughly the last `max_size/2` probation evictions. A count-min array with periodic halving keeps frequency over a longer window for almost no space, about one byte per slot. Ghost history only works as a placement signal, so this strengthens the signal without touching protected. That avoids the failure mode where protected shrinks or gets displaced.
