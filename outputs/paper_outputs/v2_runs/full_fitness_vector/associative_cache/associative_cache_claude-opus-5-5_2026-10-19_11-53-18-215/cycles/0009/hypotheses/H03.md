# H03

Replacing the whole-bucket remove and insert shifts on the miss path with in-place probation-only rotates, and scanning the ghost ring branch-free, lowers per-op time below 45 with hit rate unchanged.

## Parent

cycle/0008/v001

## Changes

All changes are in `src/associative_cache/associative_cache_bucket.rs`. The behaviour must stay bit-for-bit identical to the parent in item order, `len0`, ghost ring contents and evicted item, so hit rate must stay 0.7303.

1. **Ghost-hit / all-protected put branch when the bucket is full** (`if ghost_hit || self.len0 == 0` in `pair_put_tagged`):
   - Today this calls `evict_front()`, which does `remove_at(0)` (shifting all `max_size` items and tags left), and then does `items.insert(self.len0, ..)` (shifting all of protected right again). That is two whole-bucket memmoves.
   - When `full && self.len0 > 0`, replace this with an in-place path:
     - Take `old = mem::replace(&mut items[0], item)` and `old_tag = mem::replace(&mut tags[0], tag)`.
     - Then run `items[0..len0].rotate_left(1)` and the same on `tags`, so the newcomer ends at `len0 - 1` (probation MRU).
     - Call `record_ghost(old_tag)` and return `Some(old)`.
     - `len0` does not change.
   - The result matches the parent: the old probation LRU is evicted, the survivors move down one slot, and the newcomer sits at probation MRU. The move only touches probation, which is 1–2 slots at the 15/16 cap.
   - Keep the existing code for the `len0 == 0` all-protected fallback and for the not-full case.

2. **`take_ghost`:** replace `iter().position()` (a branchy early-exit loop) with a branch-free match-mask loop over the ring, in the same style as `find_tagged`:
   - Build a `u32` mask of `(g == fp) << j` over at most 32 entries per chunk.
   - If the mask is non-zero, clear entry `trailing_zeros()` and return true.
   - Fall back to chunking for rings longer than 32 entries.
   - Semantics must match: the first matching index is cleared.

3. **`hit()`:** add an early `if pos == self.items.len() - 1 { return pos; }` before the protected-hit rotate. This skips the slice-rotate call setup for MRU re-hits, which are common because hot keys sit at MRU.

Do not change the cap, the cold-key mid-probation entry, tag-first find, or the `Item` layout. Add a unit test that runs 10k mixed ops on the old path and the new path side by side. Simplest option: keep a `#[cfg(test)]` reference implementation of the old full ghost-hit branch, then assert identical `items`, `len0` and `ghosts` after every op on 16-slot and 32-slot buckets.

## Rationale (optional)

Across cycles, the reliable latency wins have come from removing data movement, and the miss-path cost is the open question that has gone unmeasured longest. This change is purely mechanical and keeps hit rate the same, so any per-op change measures miss-path movement directly. If it wins, it carries over to the v003 lineage with no conflict, because v003 uses the same ghost-hit branch.
