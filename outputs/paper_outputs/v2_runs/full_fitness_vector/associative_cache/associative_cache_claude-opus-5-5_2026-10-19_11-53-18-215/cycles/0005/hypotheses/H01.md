# H01

Scanning a per-slot 16-bit tag array derived from the existing key hash before comparing full keys will lower get p50 (the per-op-time summary) below v003's 55 ns at unchanged hit rate.

## Parent

cycle/0004/v003

## Changes

Work in `src/associative_cache/mod.rs` and `src/associative_cache/associative_cache_bucket.rs`.

1. **Hash once and pass it in.** In `AssociativeCache::put` and
   `AssociativeCache::get_and_update_item`, compute `let h = hash(&key) as u64`
   once. Use `h as usize % self.buckets.len()` for the bucket index, which must
   give the same bucket as today (P2 slot_legality). Derive
   `tag = ((h >> 48) as u16).max(1)`, the same formula as the current
   `fingerprint()`. Add `pair_get_tagged(&mut self, key, tag)` and
   `pair_put_tagged(&mut self, item, tag)`. Keep `pair_get` / `pair_put` and
   the `Bucket` trait methods as thin wrappers that compute the tag with
   `fingerprint(&key)`, so trait callers and tests still work.
2. **Parallel tag array.** Add `tags: Vec<u16>` (capacity `max_size`) to
   `AssociativeCacheBucket`. Invariant: `tags[i]` is the tag of `items[i]` for
   every `i`, at all times. Every operation that moves items must make the same
   move on `tags`:
   - `rotate_left(1)` on `items[a..b]` → `tags[a..b].rotate_left(1)`
   - `insert(i, ..)` → `tags.insert(i, tag)`
   - `remove(i)` → `tags.remove(i)`
   - `mem::replace(&mut items[0], ..)` → write `tags[0]`

   This covers `hit()`, `remove_at()`, the non-SLRU fallback (after
   `eviction_policy.get_from_position` returns, rebuild the moved range by
   recomputing tags with `fingerprint`, or do a simple full recompute in that
   rarely used path), and every branch of `pair_put`.
3. **Tag-first `find`.** Change `find_tagged(&self, key, tag)` to scan
   `self.tags.iter().position(|&t| t == tag)` forward, from index 0. On a tag
   match, confirm `items[i].key == *key`. If the keys differ (a false positive),
   continue scanning from `i + 1`. Write the loop so the compiler can
   auto-vectorise the u16 compare: a plain slice iteration, no early `break` on
   anything except a match. Keep the forward (index 0 first) order. Do not
   switch to `rposition`; cycle 4 showed that order hurts the get median.
4. **Remove the second hash on the ghost path.** In `pair_put_tagged`, use the
   passed `tag` for `take_ghost`. In `evict_front` and the cold-key full
   branch, record the evicted item's `tags[0]` (read before overwriting) into
   the ring instead of calling `fingerprint(&old.key)`.
5. Keep all SLRU semantics exactly as in v003: 3/4 protected cap, mid-probation
   cold insertion, ghost hits to probation MRU, and the ghost ring size.

The tag array is per-bucket heap memory. It does not change
`size_of::<Item<u64,u64>>()` (24) or `size_of::<AssociativeCache>()` (24).
Add a unit test asserting that `tags` matches the item keys after a randomised
get/put workload.

## Rationale (optional)

Get p50 is the summary, and every get scans the bucket at a 24-byte stride.
Misses (about 28% of the trace) scan every slot. A 2-byte tag stride puts a
whole 16-slot bucket in one cache line. As a side effect, removing the second
hash also trims v003's put tail.
