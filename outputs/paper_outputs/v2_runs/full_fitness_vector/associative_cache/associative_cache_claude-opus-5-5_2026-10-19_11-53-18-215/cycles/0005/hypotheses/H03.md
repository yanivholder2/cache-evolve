# H03

Removing the never-read `timestamp` and `lfu_counter` fields from `Item` so that `Item<u64,u64>` packs into 16 bytes will cut metadata-size from 24 to 16 with hit rate unchanged.

## Parent

cycle/0004/v003

## Changes

1. **`src/shared/item.rs`.** Reduce `Item<K, V>` to `{ key: K, value: V }`.
   `Item::new` no longer calls `tick()`. Keep the `tick` / `now` / `is_newer`
   helpers if anything else still uses them. Update `Display` and the unit
   tests: replace `item_u64_u64_is_24_bytes` with a 16-byte assertion, and
   remove the `lfu_counter` / timestamp tests or rewrite them against the new
   side storage below.
2. **SLRU path (the evaluated path, `ClassicLRU`).** No change is needed. The
   bucket's `hit()` and `pair_put` are purely position-based and never read
   either field. Verify this by compiling.
3. **Non-SLRU fallback policies** (`src/shared/eviction_policy*` and
   `src/shared/traits/eviction_policy.rs`). Every policy that currently reads
   or writes `item.timestamp` or `item.lfu_counter` must get that state
   somewhere other than `Item`:
   - LRU/FIFO-style policies: make them purely positional (move to end on
     hit, evict index 0), which is equivalent to their timestamp ordering.
   - LFU-style policies: keep a per-bucket `meta: Vec<u32>` in
     `AssociativeCacheBucket`, used only when `!slru`, kept parallel to
     `items` (every insert, remove and move in the fallback path makes the same
     edit to `meta`). Pass it to the policy by extending the
     `EvictionPolicy` trait methods with a `&mut [u32]` meta slice, or add a
     sibling trait for the fallback.

   Preserve each policy's observable eviction order. Any existing in-crate
   unit tests for those policies must still pass, after mechanical updates
   where they constructed `Item`s with explicit counters.
4. **Gate-integrity check first.** Before editing, check whether anything
   under `tests/`, `src/test_utils/`, `src/bin/`, `src/factory.rs` or
   `associative_cache_jni.rs` reads `.timestamp` or `.lfu_counter`, or builds
   `Item { .. }` with those fields. If anything does, keep the public API
   those files use working without editing them. For example, keep
   `Item::new(k, v)` as the only constructor, and keep any accessor they call
   as a method that reads from the side storage or returns a neutral value.
   Do not edit those files.
5. Leave all v003 SLRU and ghost logic untouched, so hit rate and the get
   path stay identical.

## Rationale (optional)

Cycle 3 showed that under SLRU these fields are dead weight. Shrinking them
from 16 to 8 bytes was free on hit rate and helped latency. Removing them
fully takes the metadata dimension to its floor for `<u64,u64>`. Moving a
16-byte stride instead of 24 also makes every rotate and scan cheaper, so
get p50 may improve as a side effect.
