# H01

Stacking v002's movement fixes onto v001's 24-byte SLRU and returning the insert index from `pair_put` will lower per-op-time below 55 with hit rate and metadata unchanged.

## Parent

cycle/0003/v001

## Changes

All edits are in `src/associative_cache/associative_cache_bucket.rs`. Keep `src/shared/item.rs` (the 24-byte `Item`) and the SLRU semantics exactly as v001 has them: same segments, promotion and demotion rules, victim choice and 3/4 `protected_cap`.

1. **MRU-first lookup (from cycle/0003/v002).** `find()` uses `self.items.iter().rposition(..)` instead of `position`. Add a `get_position` override in the `Bucket` impl that delegates to `find`.
2. **Skip the no-op rotate (from v002).** In `hit()`, compute `last = items.len() - 1`. On a protected hit with `pos == last`, return `last` without rotating.
3. **Probation-only eviction (from v002).** In the SLRU branch of `pair_put`, when the bucket is full and `len0 > 0`, do `let old = mem::replace(&mut items[0], item); items[0..len0].rotate_left(1); return Some(old);` and leave `len0` unchanged. Keep the all-protected fallback (`len0 == 0`): `remove_at(0)`, then `insert(len0, item)`, then `len0 += 1`.
4. **Return the index instead of re-finding.** Add a private `fn put_indexed(&mut self, item) -> (usize, Option<Item>)` holding the body of `pair_put`. Each branch returns the final index of the key:
   - resident key: the index returned by `hit(p)`
   - probation-rotate eviction: `len0 - 1`
   - SLRU insert at `len0` before the increment: the old `len0`
   - non-SLRU push: `items.len() - 1`

   `pair_put` becomes `self.put_indexed(item).1`. `Bucket::put` calls `put_indexed` and indexes `items[idx]` directly. Remove the `get_position(&key).expect(..)` re-scan.

Preserve the invariants: each key appears at most once per bucket, `items.len() <= max_size`, `len0 <= items.len()`, and the non-SLRU fallback still sets `len0 = items.len()`. Port v002's unit tests (`full_miss_with_probation_evicts_items0_and_keeps_protected`, `full_miss_all_protected_evicts_protected_lru`, `protected_mru_hit_is_stable`). Add one test that `Bucket::put` returns a reference to the inserted key for each branch.

## Rationale (optional)

v001 (narrower slots) and v002 (shorter, MRU-first moves) each made both get and put faster, and neither changed hit rate. Their mechanisms are orthogonal, and both cycle insights flag the stack as untested. The re-find in `Bucket::put` walks all of protected, because the new item sits at probation MRU behind it. Returning the index removes that walk.
