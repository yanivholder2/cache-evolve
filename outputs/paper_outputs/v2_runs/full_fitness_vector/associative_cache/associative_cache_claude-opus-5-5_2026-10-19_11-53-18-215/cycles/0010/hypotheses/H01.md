# H01

Collapsing the SLRU get-hit path into one rotate with branch-free boundary updates and removing hot-path `debug!` logging will lower per-op-time (get p50) without changing hit rate.

## Parent

cycle/0009/v001

## Changes

This change only removes fixed per-op instructions. Replacement decisions must stay bit-identical to the parent, so hit rate should land exactly on 0.7342. Edit `src/associative_cache/mod.rs` and `src/associative_cache/associative_cache_bucket.rs`. Carry every other parent file over unchanged: the 16-byte `item.rs`, tag-first `find_tagged`, the 15/16 cap with a floor of 2, LRU cold entry and the ghost ring.

1. **Remove logging from the hot path (`mod.rs`).** Delete the `debug!(...)` calls in `AssociativeCache::put` and `AssociativeCache::get_and_update_item`. Each one costs a runtime log-level check (an atomic load plus a compare) on every op, and the get one also evaluates `data.is_some()` for its arguments. Keep the `info!`/`error!` calls in `try_new`, which run once. If `debug` becomes an unused import, drop it.

2. **Precompute a fast-path flag (`associative_cache_bucket.rs`).** Add a field `fast_slru: bool` and set it in `with_layout` to `slru && protected_cap > 0`. Then `hit()` checks `if self.fast_slru { ... }` first and leaves the existing `!slru` fallback and the `protected_cap == 0` branches below it, as the cold path. This replaces two checks on every hit with one predictable one.

3. **Use one rotate for both hit kinds.** A protected hit and a probation hit both already do `items[pos..].rotate_left(1)` and `tags[pos..].rotate_left(1)`. Only the `len0` bookkeeping differs. In the fast path, do the two rotates once, then update `len0` without branching:
   ```
   let n = self.items.len();
   let in_prob = (pos < self.len0) as usize;
   self.len0 -= in_prob;
   self.len0 += ((n - self.len0) > self.protected_cap) as usize;
   return n - 1;
   ```
   This gives the same result as before. On a protected hit, `len0` does not change and protected is already at or below the cap, so nothing is added. On a probation hit, the item is promoted, and the protected LRU item is demoted only when the cap is exceeded.

4. Mark `pair_get_tagged` and `hit` as `#[inline(always)]` so the fast path folds into the caller. Do not add any new branches to `find_tagged`.

Invariants to keep: `tags` stays parallel to `items`; `len0 <= items.len()`; `items.len() - len0 <= protected_cap`; the non-SLRU fallback behaves exactly as before. Add a unit test that runs 10k mixed ops on a parent-equivalent reference bucket and on the new bucket side by side, and asserts identical `items` order and `len0` after every op.

## Rationale (optional)

Cycle 0009 found that latency now depends on fixed instructions per op, not bytes moved. These changes remove instructions and add no new state.
