# H02

Replacing the linear ghost ring with a direct-mapped, tag-indexed ghost table of the same size will lower per-op-time (put p50/p99) while keeping hit rate within 0.001 of the parent.

## Parent

cycle/0009/v001

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`. Carry every other parent file over unchanged.

1. **Table size.** In `with_layout`, size the ghost store as `G = ghost_len.next_power_of_two()`, where `ghost_len` is the parent's `(max_size + 1) / 2` (for example, 16 for a 32-slot bucket). Store `ghost_mask = G - 1`. When `slru` is false, keep an empty table with `ghost_mask = 0`. Remove `ghost_head`.

2. **Slot index.** A ghost's slot is `idx = (tag as usize) & ghost_mask`. The tag holds the upper 16 bits of the hash and the bucket index comes from `h % buckets.len()`, so the tag's low bits are independent of the bucket choice.

3. **`record_ghost(tag)`.** Write `ghosts[idx] = tag` with a single store and no ring-head bookkeeping. A collision overwrites the older entry, and that overwrite is how entries age out. With G close to the old ring length, an entry survives about G evictions on average, which matches the ring's recency window. Do not make the table bigger than `next_power_of_two(ghost_len)`: cycle 0006 showed that longer windows lose hit rate.

4. **`take_ghost(tag)`.** Load `g = ghosts[idx]`, compute `hit = g == tag`, and if `hit` set `ghosts[idx] = 0`. This is one load, one compare and at most one store, with no loop. Tags are never 0, so 0 still means empty.

5. Leave the rest of `pair_put_tagged` unchanged: ghost hit → probation MRU, cold → probation LRU in place, and the `len0 == 0` fallback.

Update the `ghost_ring_wraps_and_stays_bounded` unit test to check the table length (`G`), and add a test that a key evicted from probation and then put again immediately lands at probation MRU. Before measuring, log or test the ghost-hit rate on the `tags_stay_in_lockstep` workload for both ring and table to check they are close, then run the full eval.

## Rationale (optional)

Every miss-path put runs the linear `position()` scan over 8–16 entries, plus ring-head writes on each eviction. Cycle 0009 v003 showed that a branch-free full scan made put worse. An O(1) lookup removes the scan entirely instead of reshaping it, so it adds no fixed cost. This is the "non-linear ghost lookup" open question that has been carried since cycle 0006.
