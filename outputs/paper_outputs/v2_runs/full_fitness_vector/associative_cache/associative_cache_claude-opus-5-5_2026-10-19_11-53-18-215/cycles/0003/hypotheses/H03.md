# H03

Adding a per-bucket ghost list of recently evicted key fingerprints to v002's SLRU, so that a re-inserted ghost key skips probation and goes straight to protected, raises hit rate above 0.718.

## Parent

cycle/0002/v002

## Changes

Edit `src/associative_cache/associative_cache_bucket.rs` only. `Item` and the `AssociativeCache` struct do not change, so metadata-size is unaffected.

1. Add to `AssociativeCacheBucket` a fixed-size ghost ring: `ghost: Box<[u16]>` of length `max_size`, plus `ghost_head: usize`. Initialise all entries to `0`. Fingerprint is `fp(key) = ((hash(&key) >> 32) as u16) | 1`, using `crate::shared::utils::hash` with high bits (the low bits picked the bucket). The `| 1` keeps `0` free as the "empty" sentinel.
2. **Record on eviction.** In `pair_put`, SLRU branch, when a resident item is evicted (`remove_at(0)` because the bucket is full), write `fp(evicted.key)` into `ghost[ghost_head]` and advance `ghost_head = (ghost_head + 1) % max_size`. Do this only when the victim came from probation (`len0 > 0` before removal). Protected-LRU victims are not recorded.
3. **Ghost hit on insert.** Before inserting a new key in the SLRU branch, linearly scan `ghost` for `fp(item.key)`. On a match, set that ghost slot to `0` and insert the item as protected MRU: `items.push(item)`, leaving `len0` unchanged. If protected then exceeds `protected_cap`, demote protected LRU by `len0 += 1`, the same as the existing promotion path in `hit()`. Do the eviction first so capacity is never exceeded. On no match, keep the current insert at probation MRU (`insert(len0, item); len0 += 1`).
4. Keep the `protected_cap = 3/4` rule, the get-path hit rule, and the non-SLRU fallback unchanged. If `protected_cap == 0` (1-slot bucket), skip the ghost logic.

Invariants: P2 slot legality, capacity conservation, no duplicate keys. `slru_second_hit_protects` must still pass, because the scan keys there are new and not in the ghost list. Add a test: in a 4-slot bucket, a key evicted from probation and then re-put lands in the protected segment (index `>= len0`).

## Rationale (optional)

v002's gain shows workload-a (a LIRS trace) rewards scan resistance. SLRU's weak spot is keys whose reuse distance is a bit longer than probation's lifetime. They get evicted from probation before a second hit and never reach protected. That is the case ARC/LIRS/S3-FIFO handle with ghost history. The ghost list sits in the bucket's heap allocation, not in `Item` or the cache struct, and is scanned only on misses (puts), so get-path cost should be unchanged. This tests whether history-aware admission adds hit rate beyond plain SLRU inside the single-bucket rule.
