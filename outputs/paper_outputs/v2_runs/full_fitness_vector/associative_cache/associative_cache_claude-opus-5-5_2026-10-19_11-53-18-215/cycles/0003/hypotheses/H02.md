# H02

Scanning v002's SLRU bucket from the MRU end and replacing the miss path's two whole-bucket shifts with a probation-only rotate lowers get p50 (per-op-time) without changing which items are evicted.

## Parent

cycle/0002/v002

## Changes

All edits are in `src/associative_cache/associative_cache_bucket.rs`. SLRU semantics (segments, promotion rule, demotion rule, victim choice) must stay bit-for-bit identical, so hit rate should not move.

1. **MRU-first lookup.** Change `find()` to scan `self.items` in reverse (`self.items.iter().rposition(|d| d.key == *key)`). Protected MRU sits at the tail, so re-referenced hot keys are found after a few compares instead of after walking all of probation and most of protected. Misses still scan everything, same as now.
2. **Cheap protected-MRU hit.** In `hit()`, for a protected hit at `pos == items.len() - 1`, return immediately with no rotate. Otherwise keep `items[pos..].rotate_left(1)`. With MRU-first scanning, hot hits land near the tail, so the rotate span is small.
3. **Miss on a full bucket without two shifts.** In `pair_put`, SLRU branch, when `items.len() >= max_size`:
   - If `len0 > 0` (probation not empty): do `self.items[0..self.len0].rotate_left(1)` and then `self.items[self.len0 - 1] = item`. This evicts probation LRU and places the new item at probation MRU in one move that spans only probation (about 1/4 of the bucket). `len0` is unchanged. Return the old `items[0]`: copy it out before the rotate (`Item` is `Clone`; K and V are `Copy`).
   - If `len0 == 0` (all protected): keep the current behaviour, `remove_at(0)` then `insert(len0, item)`, `len0 += 1`.
   - When not full, keep `insert(len0, item); len0 += 1`.
4. Leave the fallback (non-SLRU) path and the `Bucket` trait impl unchanged, apart from `find` now scanning in reverse. `get_position` should return the same index `find` does.

Invariants: no duplicates, P2 slot legality, `len0 <= items.len()`, protected size `<= protected_cap`, and `slru_second_hit_protects` still passes. Add a unit test showing that a full-bucket miss with non-empty probation evicts exactly the previous `items[0]` and leaves the protected segment untouched.

## Rationale (optional)

Cycles 0001 and 0002 both report that get p50 keeps rising because of full-bucket forward scans and memmoves the size of the protected segment. v002's insight names `remove_at(0)` plus `insert(len0)` (two shifts across most of the bucket) and forward scanning as the costs. This hypothesis tests whether access order and move span, rather than the policy itself, explain the median-read regression.
