# H02

Stacking v002's even bucket split with a frequency-gated stash admission filter compounds their hit-rate gains rather than cancelling them.

## Parent

cycle/0001/v002

## Changes

Start from v002's source (which already overlays `src/shared/geometry.rs`
with the even 16/16 normal/stash split) and additionally overlay
`src/dash/segments/dash_segment.rs` to add a stash→target frequency gate,
mirroring the mechanism that variant v003 introduced.

Concretely, in `dash_segment.rs`:

1. Add a module constant `const STASH_PROMOTE_THRESHOLD: usize = 2;`.
2. In `promotion_get`, inside the `if let Some(item_idx) =
   core.stash_buckets[stash_idx].get_position(key)` branch, before removing
   the item and calling `promote_to_target`, increment the resident's
   `lfu_counter` (`core.stash_buckets[stash_idx].get_items_mut()[item_idx]
   .lfu_counter += 1;`) and, if it is still `< STASH_PROMOTE_THRESHOLD`,
   return the item in place from its stash bucket without promoting. Only
   once the counter reaches the threshold does the existing
   `remove_at` + `promote_to_target` path run.

Leave the geometry overlay from v002 untouched, keep the baseline
`InsertPosition::Front` promotion, and preserve all slot-legality and
uniqueness invariants (the held-in-stash item stays in its legal stash
bucket, so no duplicate and no illegal slot). This isolates whether the two
strongest cycle-0001 stash-protection levers — capacity reallocation and
selective admission — are additive or redundant, the open question the
cycle insight raised.

## Rationale (optional)

v002 (0.697) and v003 (0.677) both attack the stash-vs-normal imbalance from
different angles; if the gains come from independent mechanisms, stacking
should beat v002 alone, and if they overlap it will reveal diminishing
returns — either outcome is informative.
