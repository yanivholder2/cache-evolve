# H02

Adapting stash-hit promotion strategy based on stash bucket occupancy balances aggressive tier-skipping with tier filtering to improve hit rate under varying load conditions.

## Parent

baseline

## Changes

Modify the stash-hit promotion path in `promotion_get()` to sense stash bucket occupancy and switch promotion strategy accordingly.

In `src/dash/segments/dash_segment.rs` at the stash-hit branch (around line 154–162), add a check for stash capacity before deciding the promotion target:

```rust
if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key) {
    debug!("promotion_get: key={key:?} found in stash");
    let data = core.stash_buckets[stash_idx].remove_at(item_idx);
    
    // Check stash bucket occupancy: if above 75%, bypass tier filtering
    let stash_occupancy = core.stash_buckets[stash_idx].get_items().len() 
        / core.stash_buckets[stash_idx].capacity();
    if stash_occupancy >= 0.75 {
        // Under stash pressure: aggressive skip to probing at MRU
        promote_to_probing(core, data, InsertPosition::Back);
    } else {
        // Stash has room: tier-by-tier filtering (v001 style)
        promote_to_target(core, data, InsertPosition::Back);
    }
    // ... rest of insertion logic
}
```

This tests whether stash load triggers a switch from the conservative tier-by-tier filtering (v001) to aggressive tier-skipping (v003), adapting the acceleration strategy to cache pressure.

## Rationale

The cycle insight noted that both v001 and v003 converged on stash-hit acceleration but diverged on depth. This variant tests a pressure-sensitive middle ground: when the stash bucket is full (≥75% occupied), items cascading back from that bucket are more likely to be problematic, warranting aggressive direct bypass to avoid stash evictions. When stash has capacity, tier filtering provides safer candidate selection. The hypothesis tests whether the optimal strategy shifts with operational load.
