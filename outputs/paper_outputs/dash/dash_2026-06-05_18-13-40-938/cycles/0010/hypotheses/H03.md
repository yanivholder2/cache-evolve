# H03

Improve hit rate by implementing per-bucket saturation-triggered early cascades to proactively demote items when individual buckets reach 80% occupancy, rather than relying on tier-wide occupancy thresholds.

## Parent

cycle/0007/v001

## Changes

Modify the eviction and demotion logic in `src/dash/segments/dash_segment.rs` to add bucket-level saturation detection and triggering:

1. In `promote_to_probing()`, before inserting an item into the probing bucket, check the target bucket's current occupancy. If the target bucket (not the entire target tier) exceeds 80% capacity, proactively evict its LRU item and demote it directly to stash with back insertion (MRU).

2. In `promote_to_target()`, before inserting into the target bucket, check if the probing bucket that shares the same buckets[idx] cluster is approaching saturation. If any probing bucket in the same cluster exceeds 80% capacity, evict its LRU item to stash with back insertion.

3. Preserve all other mechanisms from v001 intact:
   - Three-tier hierarchy (Stash, Target, Probing)
   - Demotion cascade structure with MRU back-insertion for demoted items
   - Front insertion for stash→target promotion
   - LRU-based eviction within buckets

4. The threshold of 80% is chosen as a balance: strict enough to prevent bucket saturation but lenient enough to avoid cascading too aggressively. Adjust only if needed for compile/correctness.

This tests whether per-bucket saturation—localized eviction pressure when individual buckets fill—is a better signal than tier-wide occupancy for cascade triggering. Tier-level thresholds treat all buckets equally; bucket-level saturation allows hot buckets to trigger cascades independently, potentially improving hit rate by protecting hot spots from eviction pressure while less-hot buckets retain residents longer.
