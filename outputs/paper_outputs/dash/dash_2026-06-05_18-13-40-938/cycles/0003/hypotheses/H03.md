# H03

Inserting demoted items at MRU (back) position improves hit rate by preserving promotion eligibility for items cascading through the tier hierarchy during eviction.

## Parent

baseline

## Changes

Modify the demotion cascade in `demote_from_normal_bucket()` (around line 108–137 in `src/dash/segments/dash_segment.rs`) to consistently use back insertion for demoted items, preserving their MRU status across tier transitions:

```rust
fn demote_from_normal_bucket<K, V>(
    core: &mut SegmentCore<K, V>,
    item: Item<K, V>,
    source_idx: usize,
    insert_pos: InsertPosition,
) {
    let true_target = get_index(&item.key, core.segment_size);
    if true_target == source_idx {
        // Demoting from target to stash: use Back insertion to keep item MRU
        debug!(
            "demote_from_normal_bucket: key={:?} target={source_idx} -> stash (MRU)",
            item.key
        );
        core.put_at(Slot::Stash, InsertPosition::Back, item);
    } else {
        // Demoting from probing to target: use Back insertion
        debug!(
            "demote_from_normal_bucket: key={:?} probing={source_idx} -> target={true_target} (MRU)",
            item.key
        );
        if let Some(cascade) = core.put_at(Slot::Target, InsertPosition::Back, item) {
            // Cascade to stash: also use Back insertion
            debug!(
                "demote_from_normal_bucket: cascade key={:?} target={true_target} -> stash (MRU)",
                cascade.key
            );
            core.put_at(Slot::Stash, InsertPosition::Back, cascade);
        }
    }
}
```

This change ensures that items evicted from higher tiers and flowing through the demotion cascade maintain MRU positioning in their destination tiers, making them immediately eligible for re-promotion on next access.

## Rationale

Items that reach higher tiers have proven their value through competition and advancement. When they are evicted and cascade back down, they currently insert at front (LRU), forcing them to wait for other items to be accessed before they can re-promote. By inserting demoted items at back (MRU), we preserve the signal that these items are valuable: they've already climbed the hierarchy once and deserve rapid re-promotion eligibility. This is consistent with the MRU strategy proven successful in v001 and keeps hot items moving through tiers efficiently rather than stalling in lower tiers. The change respects the one-more-chance demotion logic while optimizing insertion position within that cascade.
