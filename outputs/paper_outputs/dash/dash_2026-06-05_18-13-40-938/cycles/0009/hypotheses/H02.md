# H02

Improve hit rate by adding occupancy-gated stash-to-hot tier-skip to the unified hot tier architecture, enabling selective acceleration of high-confidence stash items while maintaining filtering discipline during congestion.

## Parent

cycle/0008/v002

## Changes

Extend the unified hot tier implementation (from v002) with conditional tier-skip logic similar to v003's gating mechanism, but adapted to unified-tier semantics:

1. Keep the two-tier unified architecture from v002 (Stash + Hot, with all 28 normal buckets in Hot tier).

2. In `src/shared/item.rs`, add a `skip_history_flag: bool` field to Item struct to mark items that have bypassed the normal promotion path.

3. In `promotion_get()` within `src/dash/segments/dash_segment.rs`, implement occupancy-gated tier-skip:
   - When a stash item is accessed, check if it has access_count ≥ 2 (indicating proven interest)
   - Additionally check Hot tier occupancy: if occupancy < 75%, permit direct stash-to-hot promotion (skipping the normal wait period) and set skip_history_flag = true
   - If Hot tier occupancy ≥ 75%, use standard promotion without skip
   - This creates a soft filtering gate: high-confidence items skip forward during low-congestion, but normal gating applies under pressure

4. In `demote_from_normal_bucket()`, implement recovery enforcement: when an item with skip_history_flag=true is evicted from Hot tier, demote it back to Stash with back insertion (MRU) as per cycle 0003's proven mechanism, ensuring recovery opportunity.

This tests whether conditional acceleration (gating skip to low-congestion periods) can preserve the filtering benefits of v002's unified architecture while safely incorporating v003's acceleration strategy, creating a hybrid that adapts promotion discipline to load state.
