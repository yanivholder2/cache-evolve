# H01

Improve hit rate by implementing occupancy-coordinated demotion where cascade paths prioritize target tier for intermediate placement only when target occupancy is below saturation, reducing eviction pressure on the hot probing tier.

## Changes

Modify the demotion logic in `src/dash/segments/dash_segment.rs` in the `demote_from_normal_bucket()` function to implement occupancy-aware eviction destination selection:

Currently, when items are evicted from probing, they are demoted to target with back insertion (MRU), and if target is full, cascaded to stash. This cascade pattern is fixed regardless of occupancy state.

Change this to:
1. Before demoting from probing to target, check target tier occupancy
2. If target occupancy < 70%, demote to target with back insertion (existing behavior, which has proven beneficial for demotion recovery)
3. If target occupancy >= 70%, demote directly to stash with back insertion instead, bypassing the congested target tier to reduce cascade depth when target is saturated
4. Keep the existing demotion-recovery back-insertion strategy intact

This tests whether coordinating eviction destination based on tier occupancy state can reduce cascade overhead during high-load periods, potentially unlocking hit-rate gains by improving eviction flow without changing the fundamental demotion-recovery principle that has proven stable across all prior winners.
