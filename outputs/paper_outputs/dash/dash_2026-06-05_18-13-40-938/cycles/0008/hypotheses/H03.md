# H03

Enable controlled tier-skip for frequently-accessed stash items while maintaining structural demotion recovery by marking skipped items for target-tier re-entry on eviction, reconciling stash acceleration with demotion-recovery safety.

## Parent

baseline

## Changes

Modify promotion and demotion logic in `src/dash/segments/dash_segment.rs` and `src/shared/item.rs` to implement gated stash-skip with recovery-path enforcement:

1. Add a `skip_history_flag: bool` field to the Item struct in `src/shared/item.rs` to mark items that have skipped from stash to probing
2. In `promotion_get()`, when considering promotion of a stash resident, check if it has been accessed multiple times in the stash tier (use an existing or new access-count field). If access_count >= 2 in stash, promote directly to probing (skipping target) but set `skip_history_flag = true`
3. In `demote_from_normal_bucket()`, when demoting an item from probing that has `skip_history_flag = true`, demote it to target (not directly to stash) with back insertion, allowing it a second chance to prove value in the target tier before final stash demotion
4. Items without `skip_history_flag` follow the existing demotion path (stash residents demoted directly to stash)

This tests whether we can reconcile two previously incompatible strategies: stash-acceleration (which improved hit rate in cycles 0001-0002) with demotion-recovery (which has been the only working mechanism since cycle 0003). By gating the skip to proven stash-resident items and enforcing a target-tier recovery step on their eviction from probing, this variant tests whether structured tier-skip can coexist with demotion recovery without creating the "unvetted hot-tier residents" problem that broke tier-skip approaches in cycles 0004 and 0006.
