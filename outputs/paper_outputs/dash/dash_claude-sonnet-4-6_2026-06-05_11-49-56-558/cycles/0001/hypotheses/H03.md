# H03

Rebalancing topology from 8 normal / 24 stash to 16 normal / 16 stash buckets — keeping total capacity fixed — raises hit rate by doubling the hot-tier (target + probing) space available to proven-popular items.

## Parent

baseline

## Changes

In `src/shared/geometry.rs`, override the `BucketGeometry::layout` implementation on `BaselineGeometry` to repartition the total bucket count evenly between normal and stash rather than returning the harness-provided split verbatim.

Replace the existing `impl BucketGeometry for BaselineGeometry` block:

```rust
impl BucketGeometry for BaselineGeometry {
    fn layout(&self, _total_capacity: usize) -> DashGeometry {
        self.topology
    }
}
```

with:

```rust
impl BucketGeometry for BaselineGeometry {
    fn layout(&self, _total_capacity: usize) -> DashGeometry {
        // Baseline harness ships 8 normal + 24 stash = 32 total buckets.
        // Rebalance to a 50/50 split so the hot tier (target + probing) holds
        // as many slots as cold storage, keeping total capacity constant.
        let total_buckets =
            self.topology.num_of_normal_buckets + self.topology.num_of_stash_buckets;
        let normal = total_buckets / 2;   // 16
        let stash = total_buckets - normal; // 16
        DashGeometry {
            num_of_segments:       self.topology.num_of_segments,
            num_of_normal_buckets: normal,
            num_of_stash_buckets:  stash,
            bucket_size:           self.topology.bucket_size,
        }
    }
}
```

`for_settings` is unchanged — it still seeds `self.topology` from the harness-provided `DashSettings`. The invariant `segments * (normal + stash) * bucket_size == total_capacity` is preserved: `1 * 32 * 64 = 2048`. The `DashSettings::validate()` constraint `num_of_normal_buckets >= 2` and `num_of_stash_buckets > 0` are both satisfied (16 ≥ 2, 16 > 0). No changes are needed to `dash_segment.rs` or any other file.
