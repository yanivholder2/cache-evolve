# H03

Raising the ClassicLRUFreqProtect eviction guard threshold from zero to one — evicting items with `lfu_counter <= 1` before those with `lfu_counter >= 2` — will extend protection to the genuinely hot working set and improve hit rate over cycle/0006/v001's binary zero-access guard.

## Parent

cycle/0006/v001

## Changes

In `src/shared/eviction_policy.rs`, replace the body of `ClassicLRUFreqProtect::eviction_candidate_index` with a two-stage priority scan:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    // Stage 1: prefer items that have never been accessed in this tier
    if let Some((i, _)) = items.iter().enumerate().find(|(_, it)| it.lfu_counter == 0) {
        return i;
    }
    // Stage 2: next prefer items accessed exactly once (single-touch, not yet confirmed hot)
    if let Some((i, _)) = items.iter().enumerate().find(|(_, it)| it.lfu_counter == 1) {
        return i;
    }
    // Fallback: evict the LRU-position item (index 0)
    0
}
```

No other changes to `eviction_policy.rs`. No changes to `src/dash/dash_bucket.rs`, `src/shared/geometry.rs`, or `src/shared/item.rs` relative to v001. The `lfu_counter = 0` reset on stash demotion in `src/dash/segments/dash_segment.rs` remains unchanged — items entering stash start at zero, so Stage 1 of the new guard correctly treats freshly demoted items as cold stash residents.

## Rationale

v001's guard creates a binary cold/warm split at the zero-access boundary: items with `lfu_counter == 0` are evicted before any accessed item. On workload-a's Zipfian distribution the truly hot items accumulate many accesses; items with exactly one access may effectively be as transient as never-accessed newcomers — they have been seen once but not confirmed to recur. A two-tier guard preserves doubly-confirmed residents (`lfu_counter >= 2`) at the expense of singly-touched items (`lfu_counter == 1`), which could help in crowded probing buckets where single-touch arrivals compete with high-frequency incumbents. The cross-cycle insight explicitly lists "is zero the right threshold, or would a slightly higher threshold yield further improvement?" as an open question — this hypothesis tests it directly.
