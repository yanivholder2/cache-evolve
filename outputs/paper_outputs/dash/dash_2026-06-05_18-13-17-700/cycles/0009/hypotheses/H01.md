# H01

Halving bucket width while doubling bucket count under a conserved budget raises hit-rate by spreading colliding hot keys across more addressable target buckets.

## Parent

cycle/0008/v003

## Changes

Modify `BaselineGeometry::layout` in `src/shared/geometry.rs` to attack the
"small-bucket occupancy ceiling" head-on by trading depth for addressability —
the one direction cross-cycle insight says still pays ("addressability beats
depth"; only the reverse trade has been tested and regressed).

Currently `layout` conserves the budget and keeps `bucket_size` exactly as
seeded, applying a 3:1 normal/stash split. Keep the 3:1 split logic, but first
re-derive the geometry against a *narrower* bucket:

1. Compute the seeded total capacity `cap = num_of_segments * (num_of_normal_buckets + num_of_stash_buckets) * bucket_size` from `self.topology` (do not trust the `_total_capacity` arg; rename it in if convenient).
2. Choose a new `bucket_size' = max(1, self.topology.bucket_size / 2)`.
3. Compute the new total bucket count per segment as `total_buckets' = (self.topology.num_of_normal_buckets + self.topology.num_of_stash_buckets) * (self.topology.bucket_size / bucket_size')` so that `num_of_segments * total_buckets' * bucket_size'` stays as close as possible to `cap`. When `bucket_size` is odd or 1 (so halving is impossible without remainder), fall back to the seeded geometry unchanged so capacity conservation cannot drift.
4. Apply the existing 3:1 clamp to split `total_buckets'` into normal/stash, preserving `num_of_normal_buckets >= 2` and `num_of_stash_buckets >= 1`.

Invariants to preserve: `num_of_segments * (normal + stash) * bucket_size'`
must equal the seeded total capacity exactly (so `check_conservation` / P6
`capacity_conservation` still pass) — if the halving leaves any remainder,
abandon the rewrite and return the seeded `DashGeometry` verbatim. Do not touch
`dash_segment.rs`; the segment logic (two-speed promotion, touch counter, stash
relocation) is inherited unchanged from the parent.

## Rationale (optional)

The winner's gains saturated against a structural per-bucket occupancy ceiling,
not against rule shape. Narrower-but-more-numerous buckets reduce the number of
hot keys that share a target bucket, which is the most direct lever on that
ceiling and is the *un-tested* half of the bucket-count/width trade.
