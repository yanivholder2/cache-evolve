# H01

Replacing the winner's single-hop stash relocation with v003's bounded multi-hop cuckoo cascade converts more overflow drops into survivors and raises hit-rate where the single hop overlapped.

## Parent

cycle/0007/v001

## Changes

The incumbent v001 rescues a stash overflow victim with exactly one hop: in
`stash_insert`, if the victim's `stash_alt_index` bucket is distinct and
non-full it lands there, otherwise it is dropped. Cycle 0007 found single-hop
relocation grafted onto this winner was flat (it only rescued keys the
protected tier already reclaimed), but on a clean baseline the *deep* cascade
(v003) beat the single hop because most single-hop rescues died on a full
alternate. This hypothesis tests whether depth — which beat single-hop on the
clean baseline — survives on top of the protected-tier winner where breadth-of-1
did not.

Port v003's bounded cuckoo cascade into v001's `stash_insert`, keeping
everything else in v001 unchanged:

- Add the `RELOCATION_MAX_HOPS: usize = 3` constant and the
  `other_stash_home(key, current, stash_size)` helper from v003's
  `dash_segment.rs` (returns the key's legal home that is not `current`, or
  `None` when primary and alternate collapse or `current` is neither home).
- Rewrite `stash_insert` so that after the initial `core.put_at(Slot::Stash,
  pos, item)` returns an overflow `victim`, the victim is carried as a single
  "homeless" item through up to `RELOCATION_MAX_HOPS` hops: at each step find
  `other_stash_home`; if that bucket is non-full, `put_at` the homeless item
  there (`InsertPosition::Back`) and stop; if it is full, displace its LRU
  resident via `put_at` (which seats one and evicts one), set the displaced
  resident as the new homeless item, advance `from = dest`, and continue. Drop
  the final homeless item when the budget is exhausted or no distinct home
  exists.

Preserve every other v001 behaviour exactly: the two-speed promotion
(`promote_to_target` Front landing, `promote_to_probing` Back), the
`target_touches` counter, the `is_in_top_quarter` gate, and the both-homes
stash-hit search in `promotion_get`. The invariant to hold is occupancy
conservation: exactly one item homeless at any time and at most one dropped per
`put`, identical to v003's proof.

## Rationale (optional)

This is the direct, single-diff test of the standing cross-cycle question —
does cascade depth compound with the protected-tier winner, or overlap like
the single hop did — and it cites the proven best-so-far so any gain banks
immediately.
