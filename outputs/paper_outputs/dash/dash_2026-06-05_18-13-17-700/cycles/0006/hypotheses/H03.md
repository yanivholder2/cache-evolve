# H03

Allow both residents of a len-2 target bucket to be promotable on a hit instead of only the hottest, testing whether the deliberately-held len-2 boundary actually suppresses hit-rate.

## Parent

cycle/0005/v001

## Changes

v001's insight explicitly notes that len-2 target buckets are *deliberately*
held to hottest-only ("threshold `len - 1`") "to avoid over-admitting," and
that len-1/len-2 buckets dominate this heavily-hashed trace. That assumption
has never been tested directly — it was asserted, not measured. Since len-2
buckets are the single most common size with any rank ambiguity, even a small
change to their promotability touches a large slice of accesses. This
hypothesis flips that specific boundary and measures it.

Edit `is_in_top_quarter` (the promotion gate) in
`src/dash/segments/dash_segment.rs`, keeping every other part of v001 intact
(the `div_ceil(2)` half-gate for larger buckets, the small-bucket fallback for
`len < 2`, all landing positions, the two-speed/demotion logic). Change only
the `len == 2` case: instead of promoting solely the hottest resident
(`item_idx == promotion_candidate_index`), make **either** resident promotable
on a target hit — i.e. for `len == 2` return `true` for both `item_idx` values
when the key is hit. Leave `len == 1` exactly as today (the sole resident
already promotes via the candidate test) and leave `len >= 3` on the existing
fractional half-gate.

Preserve invariants: do not alter bucket capacities, the stash admission step,
the demotion cascade, or insert positions. Only the predicate that decides
whether a hit on a len-2 target bucket migrates the key into probing changes.
Keep the existing tests passing by updating only the len-2 expectation if one
exists.

## Rationale (optional)

The cohort concluded gate-fraction is saturated, but that conclusion rests on
the unverified premise that loosening len-2 would "over-admit." len-2 is the
densest bucket size that still has rank ambiguity, so this is the cheapest
direct probe of whether the assumed over-admission penalty is real or whether
the second resident of a len-2 bucket is a warm key being needlessly withheld
from the protected tier. A clean, falsifiable boundary test on the gate lineage.
