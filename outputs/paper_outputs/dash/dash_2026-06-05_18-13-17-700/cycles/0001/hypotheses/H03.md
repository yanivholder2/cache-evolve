# H03

Gating stash→target promotion behind a minimum stash hit count turns the stash into a frequency admission filter, raising hit rate by stopping one-hit-wonders from evicting warm items out of the normal tier.

## Parent

baseline

## Changes

In `src/dash/segments/dash_segment.rs`, modify the stash-hit branch of
`promotion_get` (the first `if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key)`
block). Today it unconditionally removes the item and calls
`promote_to_target`. Replace that with a frequency gate that reuses the existing
`Item::lfu_counter` field (present on every item, see `src/shared/item.rs`) as a
stash hit counter:

1. Increment the resident stash item's `lfu_counter` in place
   (`core.stash_buckets[stash_idx].get_items_mut()[item_idx].lfu_counter += 1`).
2. Define a small constant `STASH_PROMOTE_THRESHOLD: usize = 2`.
3. If the updated counter is `< STASH_PROMOTE_THRESHOLD`, leave the item in the
   stash and return a reference to it
   (`return Some(&core.stash_buckets[stash_idx].get_items()[item_idx]);`) —
   it stays resident, just not yet promoted.
4. Only when the counter reaches the threshold do `remove_at(item_idx)` and call
   `promote_to_target(core, data, InsertPosition::Front)` exactly as today,
   then return the resident-in-target reference.

Leave the target→probing and probing branches, the demotion cascade, and all
`Slot`/index math untouched. Invariants hold: the item never leaves a legal
slot (it stays in its own stash bucket until promotion), uniqueness is
preserved (no second copy is created), and capacity bounds are unchanged.

Test intent: on a skewed trace, transient keys that are touched once and never
again will now age out of the stash without ever displacing a promoted hot key
from a normal bucket, so the protected working set survives longer and hit rate
rises. The threshold (2) is the experimental knob a later cycle can sweep.
