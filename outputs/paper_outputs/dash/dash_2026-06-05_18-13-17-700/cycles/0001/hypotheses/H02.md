# H02

Repartitioning the fixed capacity budget toward more normal buckets and a smaller stash raises hit rate by enlarging the promotion-protected tier and reducing target-bucket hash collisions.

## Parent

baseline

## Changes

In `src/shared/geometry.rs`, change `BaselineGeometry::layout` so that instead
of echoing the harness split (8 normal / 24 stash / size 64) it rebalances the
normal/stash ratio while conserving the total budget.

Concretely, in `layout(&self, total_capacity)` compute from the seeded
`self.topology`:
- `let total_buckets = num_of_normal_buckets + num_of_stash_buckets;`
- choose `num_of_normal_buckets' = total_buckets / 2` and
  `num_of_stash_buckets' = total_buckets - num_of_normal_buckets'`
  (e.g. 16 / 16 for the baseline's 32 buckets),
- leave `num_of_segments` and `bucket_size` exactly as seeded.

This keeps `num_of_segments * (normal + stash) * bucket_size` identical, so the
factory's `check_conservation` (`resolved.capacity() == budget`) and
`P6 capacity_conservation` still pass. It also keeps `num_of_normal_buckets >= 2`
and `num_of_stash_buckets >= 1`, so `DashSettings::validate` accepts it.

Rationale to test: the baseline puts ¾ of capacity in the cold stash admission
area and only ¼ in the normal (target+probing) tier where promoted, hot items
live. Shifting the split toward normal buckets gives the working set more room
in the protected tier and finer hashing (fewer keys per target bucket, fewer
forced evictions), which should lift hit rate on a skewed trace. Keep the type
name `BaselineGeometry` and the `for_settings` entry point unchanged so the
construction glue still resolves.
