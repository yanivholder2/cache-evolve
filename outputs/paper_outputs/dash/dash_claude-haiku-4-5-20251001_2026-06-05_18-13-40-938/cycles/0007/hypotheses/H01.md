# H01

Prioritize eviction from target tier before probing to protect hot-tier residents and prevent degradation when buckets fill.

## Parent

cycle/0005/v002

## Changes

Modify `src/dash/segments/dash_segment.rs` in the `promote_to_probing()` function to implement target-first eviction priority:

When promoting an item to the probing bucket and eviction becomes necessary, check if the target bucket (computed as `true_target_idx = get_index(item.key, core.segment_size)`) is non-empty. If target has residents and probing is full, explicitly demote one resident from the target tier to stash **before** inserting into probing. This shifts the eviction burden away from the hot probing tier to the intermediate target tier.

Specifically:
1. In `promote_to_probing()`, before calling `core.put_at(Slot::Probing, ...)`, compute `target_idx = get_index(&item.key, core.segment_size)`
2. If `core.buckets[target_idx].size() > 0` and `core.buckets[probing_idx].is_full()`, evict the LRU item from target and demote it to stash
3. Then proceed with the normal probing insertion
4. Keep all demotion logic (Back insertion) unchanged from the parent

This tests whether asymmetric eviction pressure—favoring target over probing—can protect the hot tier's quality and break the 0.684 ceiling that demotion-back-insertion alone could not exceed.
