# H02

Compose optimal 80/20 geometry with adaptive threshold divisor 3 to unlock simultaneous hit-rate and latency improvements across both dimensions.

## Parent

baseline

## Changes

In `src/shared/geometry.rs` and `src/dash/segments/dash_segment.rs`, implement both geometry allocation and frequency-gated promotion:

1. **Geometry allocation** in `BaselineGeometry::for_settings()`:
   - Change normal bucket allocation to `num_of_normal_buckets = (total_buckets * 4) / 5` (80%)
   - Adjust stash allocation to `num_of_stash_buckets = total_buckets - num_of_normal_buckets`
   - Clamp `num_of_normal_buckets` to at least 2 using `.max(2)` for small bucket counts
   - For baseline's 32 buckets: yields 26 normal + 6 stash (80/20)
   - Keep `bucket_size`, `segment_size`, and all other geometry parameters unchanged

2. **Adaptive threshold with divisor 3** in `src/dash/segments/dash_segment.rs`:
   - Add a threshold calculation function:
   ```rust
   fn compute_promotion_threshold(stash_buckets: usize) -> u16 {
       ((stash_buckets / 3).max(1)) as u16
   }
   ```
   - Store the computed threshold in DashSegmentCore (or pass as parameter to promotion_get)
   - On 80/20 with 6 stash buckets: threshold = max(1, 6/3) = 2
   - Replace hardcoded constant with the adaptive value in the gating check (around line 166–170):
   ```
   if is_hottest && core.buckets[target_idx].get_items()[item_idx].lfu_counter >= core.promotion_threshold {
       // proceed with promotion to probing
   }
   ```

3. Keep stash→target promotion ungated (all stash hits promote immediately).

4. Keep all other promotion logic, demotion cascades, and Item struct layout unchanged.

## Rationale

Cycle 0006's explicit continuation guidance recommends this composition as "the definitive next step": v002's 80/20 pure geometry achieved exceptional results (hit-rate 0.7132, 37% get-latency improvement from baseline), establishing the optimal allocation point within the saturation zone. v003's divisor 3 formula proved that more permissive gating (allowing threshold=8 on baseline 25/75) improves both hit-rate and latency by reducing over-filtering of promotion candidates. The open question asks whether these two orthogonal improvements (geometry and formula refinement) compose without regression. On 80/20 geometry with divisor 3, the composition maintains v002's geometry benefits while applying v003's formula insight, testing whether adapting promotion selectivity to the improved stash capacity yields both hit-rate and latency gains from both parents, or encounters composition interference similar to v001.
