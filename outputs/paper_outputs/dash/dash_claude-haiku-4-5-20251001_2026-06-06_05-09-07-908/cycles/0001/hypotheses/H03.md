# H03

Reduce Item metadata footprint by shrinking the lfu_counter field, lowering memory per item and improving cache locality.

## Parent

baseline

## Changes

In `src/shared/item.rs`, modify the `Item` struct (lines 20–30):
- Change `lfu_counter: usize` to `lfu_counter: u16`
- Keep all other fields (`key`, `value`, `timestamp`, `lfu_counter` semantics) unchanged
- Keep the `Item::new(key, value)` constructor signature unchanged

In `src/shared/eviction_policy.rs`, update all operations on `lfu_counter` in the `Lfu` implementation:
- `Lfu::get_from_position()` (line 118): `items[position].lfu_counter += 1` works unchanged with u16
- `Lfu::eviction_candidate_index()` (lines 122–126): comparison works unchanged with u16
- `Lfu::promotion_candidate_index()` (lines 131–135): comparison works unchanged with u16

This saves 6 bytes per item on 64-bit systems (usize is 8 bytes; u16 is 2 bytes). Total Item size drops from 40 bytes to 34 bytes. The u16 range (0–65535) is sufficient for LFU counters in a 64-item bucket (the LRU victim is found before any counter exceeds a few thousand).

## Rationale

Per-item metadata overhead (timestamp + lfu_counter = 16 bytes) is 40% of baseline Item size. Reducing lfu_counter to u16 saves 6 bytes (15% reduction overall, 25% of metadata). Compact items improve CPU cache line utilization: more items fit per cache line, reducing memory pressure and improving hit latency. The u16 ceiling is safely above any practical LFU counter value in small buckets.
