# H01

Add frequency-gated promotion (threshold 2) to the best-so-far 75/25 geometry to test composition with the incumbent.

## Parent

cycle/0003/v003

## Changes

In `src/dash/segments/dash_segment.rs`, modify the `promotion_get()` function to gate target→probing promotion on a frequency threshold, applied on top of v003's 75/25 bucket geometry:

1. Add a promotion counter threshold constant at module level: `const PROMOTION_THRESHOLD: u16 = 2;`

2. In the section checking "is_hottest" (around line 166–170 in the current codebase), add a condition before promoting to probing:
   ```
   let is_hottest = Some(item_idx) == core.buckets[target_idx].promotion_candidate_index();
   if is_hottest && core.buckets[target_idx].get_items()[item_idx].lfu_counter >= PROMOTION_THRESHOLD {
       // proceed with promotion to probing
   } else if is_hottest {
       // increment lfu_counter and stay in target (intra-promote only)
   }
   ```

3. Stash→target promotion remains ungated (all stash hits promote immediately to target).

Keep v003's 75/25 bucket geometry (24 normal + 8 stash buckets) unchanged.

## Rationale

v003 achieved the best hit-rate (0.714) and strong latency (109 ns) using only geometry reallocation to 75/25, outperforming all gating-based variants from cycle 0003. However, frequency-gating (threshold ≥ 2) was demonstrated to work well on concentrated geometries (62.5/37.5 in cycle/0002/v002, which achieved 0.7078 hit-rate). The cycle 0003 analysis notes that the gating threshold is well-calibrated for concentrated geometry because it filters mostly false-positives in the smaller stash tier. On 75/25 geometry (even more concentrated with only 8 stash buckets), the threshold selectivity should be even better-calibrated. This hypothesis tests whether frequency gating composes cleanly with v003's winning geometry to amplify both hit-rate and latency gains, or whether the simpler geometry-only approach is optimal.
