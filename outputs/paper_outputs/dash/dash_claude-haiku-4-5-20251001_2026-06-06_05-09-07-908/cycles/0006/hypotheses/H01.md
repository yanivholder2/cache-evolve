# H01

Adaptive threshold on aggressive 85/15 geometry preserves hit-rate while improving latency through geometry-aware selectivity scaling.

## Parent

cycle/0004/v001

## Changes

Extend v001's 75/25 geometry allocation and frequency-gated promotion to both a more aggressive allocation and adaptive threshold computation:

1. In `src/shared/geometry.rs`, update the geometry allocation in `BaselineGeometry::for_settings()`:
   - Change `num_of_normal_buckets = (total_buckets * 3) / 4` (75%) to `num_of_normal_buckets = (total_buckets * 17) / 20` (85%)
   - Adjust stash allocation accordingly: `num_of_stash_buckets = total_buckets - num_of_normal_buckets`
   - For baseline's 32 buckets: yields 27 normal + 5 stash (85/15)

2. In `src/dash/segments/dash_segment.rs`, replace the hardcoded `PROMOTION_THRESHOLD: u16 = 2` constant with adaptive computation:
   - Add a threshold calculation function:
   ```rust
   fn compute_promotion_threshold(stash_buckets: usize) -> u16 {
       ((stash_buckets / 4).max(1)) as u16
   }
   ```
   - Store the computed threshold in DashSegmentCore or pass as parameter to promotion_get()
   - Replace hardcoded constant with the adaptive value in the gating check (around line 166–170)
   - On 85/15 with 5 stash buckets, this yields threshold = max(1, 5/4) = 1, down from v001's hardcoded 2

3. Keep all other promotion logic, demotion cascades, and Item struct layout unchanged. Stash→target promotion remains ungated.

## Rationale

v001 achieved the highest hit-rate (0.7161) at 75/25 with hardcoded threshold=2, but cycle 0005's v002 showed that pure 85/15 geometry improves latency (105 ns vs 112 ns) at the cost of hit-rate regression (0.7099 vs 0.7161). However, cycle 0005 v003 proved that adaptive threshold scaling enables geometry-independent composition by aligning selectivity to capacity: on different geometries, the formula `stash_buckets / 4` automatically calibrates the gate to filter false-positives without over-filtering true candidates. On 85/15 (only 5 stash buckets), the adaptive formula naturally reduces the threshold from 2 to 1, allowing more items to promote while still filtering single-access noise. This tests whether v003's composition breakthrough generalizes to more aggressive geometry, potentially reclaiming both the latency gains of v002 and the hit-rate margin of v001.
