# H03

Refined adaptive threshold formula (stash_buckets / 3) increases promotion permissiveness on balanced geometry to improve hit-rate.

## Parent

baseline

## Changes

In `src/dash/segments/dash_segment.rs`, implement adaptive frequency-gating on the baseline geometry (25/75) using a more permissive formula than cycle 0005 v003:

1. Add a threshold calculation function with divisor 3:
   ```rust
   fn compute_promotion_threshold(stash_buckets: usize) -> u16 {
       ((stash_buckets / 3).max(1)) as u16
   }
   ```

2. Store the computed threshold as a field in the DashSegmentCore struct (or pass it as a parameter to promotion_get()).

3. In the promotion_get() gating check (around line 166–170), replace the hardcoded constant with the adaptive value:
   ```
   if is_hottest && core.buckets[target_idx].get_items()[item_idx].lfu_counter >= core.promotion_threshold {
       // proceed with promotion to probing
   }
   ```
   - On baseline 25/75 (24 stash buckets): threshold = max(1, 24 / 3) = 8 (versus max(1, 24 / 4) = 6 in v003)
   - This higher threshold is less selective, allowing more items to promote

4. Stash→target promotion remains ungated (all stash hits promote immediately to target).

5. Keep all other promotion logic, demotion cascades, and baseline 25/75 bucket geometry unchanged.

## Rationale

Cycle 0005 v003 applied adaptive threshold with divisor 4 on baseline geometry and achieved exceptional latency (105 ns, 43% improvement) while maintaining hit-rate relative to the gating-less baseline. However, the measured hit-rate (0.6634) did not exceed baseline (0.663), suggesting the threshold=6 formula may over-filter promotion candidates on balanced 25/75 geometry. The open question asks whether the adaptive formula itself can be refined to shift the frontier. Testing divisor 3 (yielding threshold=8 on baseline) explores whether more permissive gating—allowing items to promote more readily—can improve hit-rate without sacrificing the latency gains from adaptive threshold scaling. This directly tests formula sensitivity and whether a less selective gate better suits the candidacy distribution of balanced-geometry workloads, potentially unlocking the hit-rate improvement that remains elusive on baseline.
