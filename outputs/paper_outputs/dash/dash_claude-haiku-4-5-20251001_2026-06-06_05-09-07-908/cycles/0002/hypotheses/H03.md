# H03

Frequency-gated promotion reduces noisy tier transitions and raises hit-rate by conserving stash capacity for genuinely hot items.

## Parent

baseline

## Changes

In `src/dash/segments/dash_segment.rs`, modify the `promotion_get()` function (around lines 141–189) to gate target→probing promotion on a frequency threshold:

1. Add a promotion counter threshold constant: `const PROMOTION_THRESHOLD: u16 = 2;` at the module level.

2. In the section checking "is_hottest" (line 166), add a condition before promoting:
   ```
   let is_hottest = Some(item_idx) == core.buckets[target_idx].promotion_candidate_index();
   if is_hottest && core.buckets[target_idx].get_items()[item_idx].lfu_counter >= PROMOTION_THRESHOLD {
       // proceed with promotion to probing
   } else if is_hottest {
       // increment lfu_counter and stay in target (intra-promote only)
   }
   ```

Stash→target promotion remains ungated (all stash hits promote immediately to target). The threshold gates only target→probing, the most expensive tier transition.

Keep all demotion logic and cascade behavior unchanged.

## Rationale

The baseline promotes items to probing on first hit within their target bucket (if hottest), which can elevate occasionally-accessed items to the hottest tier and waste probing capacity. Frequency-gating (N=2 threshold) ensures only items with sustained access patterns claim space in the expensive probing tier. This reduces churn in the probing bucket, keeping it reserved for genuinely hot keys, and reduces the frequency of cascading demotions when probing overflows. The tradeoff is slightly delayed promotion of truly hot items (they need 2 hits before promotion), but on Zipfian traces with small hot sets, this cost is minimal compared to the benefit of reducing false-positive promotions.
