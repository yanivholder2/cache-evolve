# H03

Inserting cold items directly into their target bucket at the LRU end instead of routing them through stash reduces the number of accesses required for hot items to reach the probing tier and raises hit rate by eliminating the stash as an admission bottleneck.

## Parent

baseline

## Changes

Modify only `dash_segment.rs`. No geometry overlay — the harness-provided split (baseline) is used. The `fn get` implementation keeps `InsertPosition::Front` (baseline stash-to-target promotion behavior).

### Override `Segment::put` in the `impl Segment<K, V> for DashSegment<K, V>` block

Add `fn put` to the existing impl (the trait has a default; we override it):

```rust
fn put(&mut self, item: Item<K, V>) {
    let core = self.core_mut();
    debug_assert!(
        !core.contains_key(&item.key),
        "put: key={:?} already present — caller must not re-insert a resident key",
        item.key
    );
    debug!("DashSegment.put: key={:?} -> target(Front) [skip-stash admission]", item.key);

    // Route the cold item directly into its target bucket at the LRU end.
    // Any item evicted from target cascades via the normal demotion path,
    // landing in stash (or a true-target retry), which now serves as a
    // demotion-only buffer rather than an admission filter.
    let target_idx = get_index(&item.key, core.segment_size);
    let Some(evicted) = core.put_at(Slot::Target, InsertPosition::Front, item) else {
        return; // target had space — nothing evicted
    };
    demote_from_normal_bucket(core, evicted, target_idx, InsertPosition::Front);
}
```

All other functions (`promotion_get`, `promote_to_target`, `promote_to_probing`, `demote_from_normal_bucket`) are unchanged from the baseline. The stash continues to receive items demoted from target/probing; it is no longer the gateway for newly inserted keys.

### Why `InsertPosition::Front` (LRU end) for cold admission

Inserting at Front means the new item occupies the lowest-seniority position in the target bucket. The ClassicLRU policy will evict it first if another insertion arrives before it earns a hit. This is the conservative choice: the item must climb to the MRU position via accesses before it can promote to probing, maintaining the existing earned-promotion design while shortening the total number of hops (stash → target, instead of stash → (miss) → target).

## Rationale

In the baseline (and all winning variants to date), every new item enters through stash. An item can only escape stash by being accessed while resident there — it must absorb one hit in stash before it can compete in the target+probing tier. For a workload with a stable hot set (workload-a), this means every hot item pays a mandatory "stash tax" on cold start or re-insertion, delaying the first useful hit in the promotion tier. Bypassing stash entirely for cold items removes this tax: a hot item that enters at the LRU end of its target bucket needs only one access to become the MRU and qualify for probing, instead of two (stash hit + target hit). The stash is preserved as a demotion buffer for items falling out of the normal tier, so cold re-entry after eviction still benefits from the stash safety net.
