# H01

Reducing stash capacity to a 7/8 normal-bucket split (28 normal / 4 stash for 32-bucket total) will raise hit-rate by enlarging the hot tier, now that second-chance recovery makes stash evictions non-terminal.

## Parent

cycle/0007/v001

## Changes

In `src/shared/geometry.rs`, change the single multiply constant in `layout()` from `3 / 4` to `7 / 8`:

```rust
// current (v001):
let normal = (total_buckets * 3 / 4).max(2);  // 24 normal / 8 stash for total=32

// proposed:
let normal = (total_buckets * 7 / 8).max(2);  // 28 normal / 4 stash for total=32
let stash = (total_buckets - normal).max(1);
```

The edge-case clamps (`max(2)` for normal, `max(1)` for stash) and the pass-through of `num_of_segments` and `bucket_size` are unchanged from v001.

No changes to `dash_segment.rs`, `eviction_policy.rs`, `dash_bucket.rs`, or `item.rs`. The `ClassicLRUFreqProtect` policy, Back-insertion promotions, second-chance recovery at Front, and lfu_counter reset on demotion are all inherited from v001 without modification.

**Invariant to preserve**: `num_of_normal_buckets >= 2` (required for probing-bucket indexing, guaranteed by the `max(2)` clamp) and `num_of_stash_buckets >= 1` (guaranteed by `max(1)`).
