### geometry.rs

Implement the 75/25 split (same formula as cycle/0004/v002 — copy it exactly):

```rust
impl BucketGeometry for BaselineGeometry {
    fn layout(&self, _total_capacity: usize) -> DashGeometry {
        let total_buckets =
            self.topology.num_of_normal_buckets + self.topology.num_of_stash_buckets;
        let normal = (total_buckets * 3 / 4).max(2);
        let stash = (total_buckets - normal).max(1);
        DashGeometry {
            num_of_segments:       self.topology.num_of_segments,
            num_of_normal_buckets: normal,
            num_of_stash_buckets:  stash,
            bucket_size:           self.topology.bucket_size,
        }
    }
}
```

## Rationale

`ClassicLRU`'s `get_from_position` physically moves the item to the back (MRU vector position), making `promotion_candidate_index` (= last position) equivalent to "most recently moved." With `InsertPosition::Back`, a new arrival from stash lands at the back and is immediately the promotion candidate — it is "most recently moved" even though it has never been accessed in target. `TimestampLRU` decouples promotion candidacy from insertion order: `promotion_candidate_index` returns the item with the maximum `timestamp`, which is updated to `Instant::now()` on every `get_from_position` call. A just-inserted item starts with its creation timestamp; if another bucket resident was accessed more recently, that resident becomes the promotion candidate instead. This aligns promotion with genuine recency of access rather than recency of tier entry, which could better identify the truly hottest target item on workload-a's Zipfian distribution. Stash behaviour is unchanged: stash items are always removed by `remove_at` (not `get_from_position`), so `TimestampLRU`'s timestamp update never fires in stash — eviction falls back to oldest creation timestamp = FIFO order, identical in effect to `ClassicLRU + Back` insertion for unaccessed cold items.
