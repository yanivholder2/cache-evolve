# H03

Maintain a shadow ghost list of recently-evicted keys; when a key is re-inserted, place it at the middle of the LRU order instead of the tail (MRU) to give re-accessed items a second chance without displacing hot items.

## Parent

baseline

## Changes

Add a `ghost_list: std::collections::VecDeque<K>` field to `LruCache` to track recently-evicted keys. Initialize it as empty in `try_new()`. The ghost list is bounded to a maximum size of `2 * capacity`; when inserting a new ghost entry would exceed this size, evict the oldest entry from the ghost list first.

Modify `put()` to check the ghost list on new insertions (i.e., when the key does not already exist in the map):
- If the key exists in the `ghost_list`, remove it from the ghost list and insert the new node at the **middle** of the linked list. To find the middle, traverse the list from the head approximately `len / 2` steps and insert the node at that position, preserving the doubly-linked list invariants.
- If the key is not in the ghost list, insert it at the tail (standard baseline MRU behavior).

When evicting a node in the arena-full case, add its key to the `ghost_list` (at the tail), and trim the ghost list if it exceeds `2 * capacity`.

Preserve all value-fidelity invariants and capacity bounds. The LRU ordering and linked-list structure remain intact; the change affects only the insertion point for re-inserted items and maintains shadow metadata.
