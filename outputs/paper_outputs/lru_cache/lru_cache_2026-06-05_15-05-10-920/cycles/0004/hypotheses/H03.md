# H03

Replace binary right-shift frequency decay (divide by 2) with exponential multiplicative decay (multiply by 0.75) to provide smoother forgetting that preserves frequency discrimination while enabling phase shifts.

## Parent

cycle/0002/v003

## Changes

In the `check_and_perform_frequency_reset()` method, replace the right-shift decay mechanism with multiplicative decay. Instead of `node.freq >>= 1` (which divides by 2), apply `node.freq = (node.freq as f64 * 0.75) as u8` for each node (or use integer arithmetic: `node.freq = (node.freq * 3) / 4`). Apply this change to all nodes in the decay loop (around lines 139–140). Keep the reset interval threshold at `capacity * 16` operations unchanged. This provides gentler decay per reset cycle (0.75× multiplier vs. 0.5× from right-shift), potentially better preserving frequency discrimination between items while still fading old hotspots. All other logic (eviction selection, promotion, initial frequencies) remains unchanged.

## Rationale

The current right-shift decay halves frequencies every `capacity * 16` operations, which may be too aggressive. Multiplicative decay at 0.75× provides a smoother exponential decay curve: old frequencies fade gradually while recent frequency differences remain discriminative longer. This may improve hit-rate by allowing the cache to distinguish between moderately-hot and very-hot items across phase shifts without losing them to premature eviction.
