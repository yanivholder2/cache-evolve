# H02

Improve hit rate by combining frequency-based eviction in a protected hot zone with LRU eviction in a cold zone to capture both access skew and temporal locality.

## Parent

baseline

## Changes

Implement a hybrid eviction policy that merges the frequency-counter strategy from v001 with the zone-partitioning structure from v002.

Add these fields to the `Node` struct: `freq: u8` (initialized to 0) and `gen: u8` (0=cold, 1=hot).

Add these fields to `LruCache`: `hot_capacity = capacity / 3` (computed in `try_new()`).

In `get()`: increment `freq` by 1 (saturating at 255) after lookup. If the node is in cold zone (`gen == 0`) and `freq >= 2`, unlink the node, set `gen = 1`, and re-insert at tail (promote to hot).

In `put()` eviction (when `self.nodes.len() >= self.capacity`): count nodes in cold zone (`gen == 0`). If cold_count > 0, find and evict the LRU node from the cold zone. Otherwise, find the minimum-frequency node from the hot zone and evict it. When a new node is allocated, initialize `gen = 0` and `freq = 0`.

This combines v001's frequency-based prioritization (applied to hot items that have shown reuse) with v002's zone structure (evicting cold items first, protecting hot items from cold-zone churn).

## Rationale

Both v001 and v002 improved hit rate significantly by protecting frequently-accessed items. A hybrid approach may achieve superior results by: (1) using LRU within the cold zone to quickly discard one-time accesses, (2) using frequency-based selection in the hot zone to ensure the most-used items survive eviction, and (3) promoting items based on demonstrated reuse (frequency threshold) rather than arbitrary access count.
