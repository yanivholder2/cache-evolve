# H03

Maintain a per-key "resurrection count" to detect and protect re-inserted items, reducing hit rate loss from thrashing on working-set boundaries.

## Parent

baseline

## Changes

Add a `Vec<u8>` alongside the existing `map` HashMap to track resurrection count for evicted keys (indexed by a secondary map `eviction_history: HashMap<K, usize>` that maps evicted keys to their resurrection count). On `put()` of a new key: if the key was previously evicted, increment its resurrection count; if the resurrection count exceeds a threshold (e.g., 2), reserve an extra hot slot for it on next eviction by preferring to evict keys with no resurrection history.

On eviction, prefer evicting keys with resurrection count == 0 over keys with count > 0. Periodically flush the `eviction_history` map (every `capacity * 10` evictions) to prevent unbounded memory growth. This targets hit rate by giving second chances to items that are part of an active working set, while preserving O(1) amortized behavior.
