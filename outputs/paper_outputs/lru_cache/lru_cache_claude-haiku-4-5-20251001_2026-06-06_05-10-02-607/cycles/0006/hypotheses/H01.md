# H01

Integrate adaptive bucketing's saturation-aware activation with incremental queue draining to combine workload awareness and amortized work distribution, improving per-op-time without sacrificing hit rate.

## Parent

cycle/0003/v003

## Changes

Cycle 0003's adaptive bucketing successfully activates frequency bucketing only when saturation ≥ 75%, improving latency under high load while staying lightweight on underutilized caches. Cycle 0005's V002 demonstrated that incremental queue draining (check queue during get(), drain a small batch when depth exceeds threshold Q, flush remaining at put()) achieves 42% put p99 improvement with manageable trade-offs. Combine both strategies:

1. Preserve Cycle 0003 v003's entire low-saturation mode (simple LRU without frequency updates).
2. In high-saturation mode (saturation ≥ 75%), apply frequency bucketing from v003.
3. Implement Cycle 0005 v002's incremental promotion queue draining within high-saturation mode:
   - Maintain a pending_promotions queue to batch frequency bucket updates.
   - In get(), after processing the node, check if queue depth exceeds threshold Q (start with 8).
   - If threshold exceeded, drain and process the first K items (start with 4) from the queue.
   - In put(), preserve v003's bucket eviction logic but benefit from reduced accumulated queue size.
4. When transitioning from high to low saturation (saturation < 60%), flush any pending promotions and revert to immediate updates.

This architecture combines saturation-aware activation (avoiding metadata/logic overhead on underutilized caches) with amortized work distribution (reducing peak put latency spikes), targeting per-op-time improvement while maintaining hit rate and metadata-size.

## Rationale

Cycle 0003's v003 proved that workload-aware conditional activation is the path forward: it achieves 34% get p99 improvement relative to baseline by staying lightweight under light load. Cycle 0005's v002 proved that incremental batching (spreading work across operations) distributes load better than all-at-once deferral (42% put p99 gain vs. Cycle 0004's 56% regression). The cross-cycle insight "Workload-aware activation wins when conditions fire" and "Incremental amortization outperforms operation-shifting" are complementary: activate the expensive bucketing only when saturation is high, and within that mode, use incremental draining to smooth the per-operation cost. This tests whether combining the best properties of two proven approaches yields a strictly better variant.
