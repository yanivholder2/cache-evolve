# H02

Multi-level frequency preferences within the bounded search window to improve V001's hit rate without sacrificing latency guarantees.

## Parent

cycle/0002/v001

## Changes

V001's find_evictable_node() uses a coarse binary frequency threshold: return the first node with freq <= 1 within the min(capacity/4, 256) node window, else return the window's first node. This binary distinction is too coarse-grained to capture frequency gradations. Enhance the bounded search to rank candidates by frequency more granularly: scan the entire window collecting all candidates, then return the candidate with the lowest frequency count (prefer freq=1, then freq=2, then freq=3, etc.). If all candidates have the same frequency, use position in the window (LRU order) as the tiebreaker. This allows the bounded window to make smarter eviction decisions by preferring lower-frequency items over arbitrary positional selection, potentially improving hit rate on workloads where frequency distribution is non-binary within the window, while preserving the O(1) worst-case latency guarantee of the bounded scan.

Modify find_evictable_node() to track the minimum frequency and corresponding index while scanning the window, returning the node with lowest frequency rather than the first occurrence of freq <= 1.
