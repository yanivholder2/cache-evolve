# H01

Replacing the confirmed-inert referenced-bit tie-breaker in protected demotion and probationary eviction with IRR timestamps, while keeping ghost admission intact, will raise hit rate above the cycle/0006/v001 incumbent by providing a meaningful signal at equal-frequency collisions.

## Parent

cycle/0006/v001

## Changes

Starting from cycle/0006/v001's source (SLRU 80/20, ghost admission, frequency-aware scans, freq-cap MAX_FREQ=8, counter halving on demotion, referenced-bit tie-breaker):

1. **Node struct**: Remove the `referenced: bool` field. Add `last_access: u64` and `prev_access: u64` (both zero-initialized). Add `op_clock: u64` to `LruCache<K,V>`, initialized to `1` in `try_new()`.

2. **get()**: Before the segment dispatch, advance IRR timestamps: `self.nodes[idx].prev_access = self.nodes[idx].last_access; self.nodes[idx].last_access = self.op_clock; self.op_clock += 1;`. Remove the `self.nodes[idx].referenced = true;` line in the Protected branch. No other changes to get().

3. **put() — arena allocation**: When pushing a fresh Node, set `last_access: self.op_clock, prev_access: 0`, then `self.op_clock += 1`. When recycling an evicted slot, reset `prev_access = 0`, `last_access = self.op_clock`, `op_clock += 1`.

4. **irr() helper**: Add the function from cycle/0009/v001 verbatim — returns `u64::MAX` when `prev_access == 0`, otherwise `last_access - prev_access`.

5. **demote_prot_head()**: Replace the `(freq, r)` score tuple with `(freq, irr)`. Change the comparison: a candidate beats the current victim when `freq < victim_freq || (freq == victim_freq && irr > victim_irr)`. Rename `victim_score: (u32, u32)` to `victim_freq: u32` / `victim_irr: u64`. Remove the `let r = if self.nodes[idx].referenced { 1u32 } else { 0u32 };` line. Keep freq-halving on demotion unchanged. Do NOT reset `last_access` or `prev_access` on demotion — IRR timestamps survive segment transitions exactly as in cycle/0009/v001.

6. **Probationary eviction scan in put()**: Replace the purely frequency-based comparison with the `(freq, irr)` composite from cycle/0009/v001 — add `victim_irr: u64 = 0` tracking, use `is_better_victim = freq < victim_freq || (freq == victim_freq && irr > victim_irr)`.

7. **Ghost infrastructure**: Keep `ghost: VecDeque<K>`, `ghost_set: HashSet<K>`, `ghost_cap`, `add_to_ghost()`, the ghost-hit path in `put()` step 2, and the defensive ghost cleanup in `get()` all exactly as in cycle/0006/v001. Ghost capacity remains `prob_cap`.

8. **Unit tests**: Remove the `referenced_bit_shields_recently_accessed_protected_entry` test (the mechanism no longer exists). Keep the `ghost_hit_admits_to_protected` test and the `h03_demoted_entry_survives_over_cold_newcomer` test, adapting field names where needed (`last_access`/`prev_access` instead of `referenced`). Add the `irr_timestamps_preserved_across_demotion` test from cycle/0009/v001 to verify demotion preserves last_access/prev_access.

## Rationale

cycle/0006/v001's referenced-bit was confirmed inert by cycle-6 (equal-freq collisions are rare in the LRU-quarter scan). IRR timestamps are a strictly more informative tie-breaker because they measure the density of recent accesses rather than a single-bit "was this touched since last scan." Cycle/0009/v001 showed no lift from IRR as a secondary over a ghost-less design, but ghost admission routes re-arriving warm keys into protected in one step — producing a different distribution of same-frequency candidates. The IRR tie-breaker may activate meaningfully in the context where ghost-admitted entries (freshly in protected, zero referenced-bit on arrival) compete against long-tenured protected entries at the same frequency.
