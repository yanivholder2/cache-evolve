# H02

Restoring a bounded ghost set (capacity equal to prob_cap) to the frequency-primary, IRR-tie-breaker design of cycle/0009/v001 will recover the hit-rate regression from its parent and yield a net improvement above 0.7316 by fast-tracking recently evicted probationary keys directly into protected on re-arrival.

## Parent

cycle/0009/v001

## Changes

Starting from cycle/0009/v001's source (SLRU 80/20, frequency primary + IRR tie-breaker, no ghost, op_clock, last_access/prev_access timestamps, MAX_FREQ=8):

1. **LruCache struct**: Add three fields: `ghost: VecDeque<K>`, `ghost_set: HashSet<K>`, and `ghost_cap: usize`. Add `use std::collections::{HashMap, HashSet, VecDeque};` (currently only HashMap is imported).

2. **try_new()**: Set `ghost_cap = prob_cap`. Initialize `ghost: VecDeque::with_capacity(ghost_cap + 1)` and `ghost_set: HashSet::with_capacity(ghost_cap + 1)`. Include both in the returned `Self { ... }` struct literal.

3. **add_to_ghost() helper**: Add this method to the impl block — identical to cycle/0006/v001:
   ```rust
   fn add_to_ghost(&mut self, key: K) {
       if self.ghost_cap == 0 { return; }
       if self.ghost.len() >= self.ghost_cap {
           if let Some(oldest) = self.ghost.pop_front() {
               self.ghost_set.remove(&oldest);
           }
       }
       self.ghost_set.insert(key.clone());
       self.ghost.push_back(key);
   }
   ```

4. **put() — probationary eviction path**: After `self.map.remove(&evicted_key)` and `self.unlink_prob(evict_idx)` and `self.prob_count -= 1`, call `self.add_to_ghost(evicted_key)`. The evicted slot is then recycled for the new key as before. Protected evictions (the fallback else-branch) are NOT added to the ghost set.

5. **put() — step 2, segment placement**: Replace the current unconditional probationary placement with a ghost-hit check:
   ```
   if self.ghost_set.contains(&key) {
       self.ghost_set.remove(&key);
       self.ghost.retain(|k| k != &key);
       self.nodes[idx].segment = Segment::Protected;
       self.push_back_prot(idx);
       self.prot_count += 1;
       self.map.insert(key, idx);
       if self.prot_count > self.prot_cap {
           self.demote_prot_head();
       }
   } else {
       self.nodes[idx].segment = Segment::Probationary;
       self.push_back_prob(idx);
       self.prob_count += 1;
       self.map.insert(key, idx);
   }
   ```
   Ghost-admitted entries start with `referenced = false` (n/a here — no referenced field) and their IRR timestamps are set to `last_access = op_clock, prev_access = 0` at slot-reset time, which is already handled in step 1 of the arena-full branch before step 2.

6. **get()**: Add a defensive ghost cleanup when promoting probationary to protected — before `self.nodes[idx].segment = Segment::Protected`:
   ```rust
   if self.ghost_set.remove(key) {
       self.ghost.retain(|k| k != key);
   }
   ```
   This prevents stale ghost entries for keys that were re-inserted via normal probationary and then promoted.

7. **All IRR scoring logic**: Keep unchanged — `irr()` helper, op_clock advancement, `last_access`/`prev_access` tracking, `(freq, irr)` composite comparisons in both `demote_prot_head()` and the probationary eviction scan.

8. **Unit tests**: Add the `ghost_hit_admits_to_protected` test from cycle/0006/v001 (adapting field names to the IRR-based Node — no `referenced` field, but otherwise the same observable behavior). The existing IRR-related tests need no changes.

## Rationale

Cycle/0009/v001 regressed from its parent cycle/0006/v001 specifically because ghost admission was removed — the insight confirmed that ghost was routing recurring warm keys into protected in a single step and eliminating that shortcut forced them through the slower one-hit-then-promote path. The cycle-9 continuation explicitly identifies ghost restoration as the highest-priority thread. The IRR tie-breaker and ghost admission are structurally orthogonal: ghost acts at insertion time (choosing which segment to place a new key in), while IRR acts at eviction time (choosing which resident to remove). Their interaction has not been tested, and the mechanisms target different miss classes.
