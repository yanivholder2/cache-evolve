# H02

Replacing the SLRU+frequency policy with the SIEVE algorithm will test whether a simpler, single-queue eviction philosophy can match or exceed the incumbent hit rate on workload-a.

## Parent

baseline

## Changes

Complete rewrite of `mod.rs`. Discard the two-segment SLRU structure, ghost set, frequency counters, and referenced bit entirely. Implement SIEVE:

**Node**:
```
key: K
value: V
prev: Option<usize>   // toward LRU head (older)
next: Option<usize>   // toward MRU tail (newer)
visited: bool
```

**LruCache fields**: `map: HashMap<K, usize>`, `nodes: Vec<Node<K,V>>`, `head: Option<usize>` (LRU/oldest end), `tail: Option<usize>` (MRU/newest end), `hand: Option<usize>` (eviction hand), `count: usize`, `capacity: usize`.

**`get(key)`**: if `map.get(key)` finds `idx`, set `nodes[idx].visited = true`, return `Some(&nodes[idx].value)`. Otherwise return `None`. Do not change list position.

**`put(key, value)`**:
1. Re-put (key already resident): update `nodes[idx].value`, return.
2. New key: acquire a slot —
   - If `nodes.len() < capacity`: push a fresh `Node { visited: false, ... }` onto `nodes`; slot = len-1.
   - Else: run the SIEVE eviction hand to find a victim slot, reclaim it for the new key (`freq=`, `visited=false`). SIEVE hand scan: starting at `hand` (default to `tail` if `hand` is `None`), scan toward head. For each node encountered: if `visited == true`, clear visited, advance hand to `nodes[hand].prev`, continue. If `visited == false`, this is the victim — evict it (`map.remove(key)`, unlink from list), set `hand = nodes[victim].prev` (which becomes `None` if victim was the head), stop. If hand reaches `None` (scanned past head without finding an unvisited node), reset hand to `tail` and continue scanning from there (wrap-around). The scan is guaranteed to terminate because at most one full cycle visits every node.
3. Insert the new node at the MRU tail of the list (push_back), with `visited = false`. Insert into `map`.

Preserve all existing unit tests that can reasonably apply (capacity invariants, hit/miss semantics, overwrite behavior, capacity-one). Update or remove tests specific to SLRU segment logic.

## Rationale

The cross-cycle insight recommends exploring "a genuinely different eviction philosophy that does not share the local optimum of the current SLRU design." SIEVE (2024) has been shown to outperform LRU on web-cache workloads with lower implementation complexity than SLRU. It has never been evaluated in this evolution series. A neutral or positive result on workload-a would indicate the SLRU complexity is unnecessary; a regression would confirm the structural value of the two-segment design.
