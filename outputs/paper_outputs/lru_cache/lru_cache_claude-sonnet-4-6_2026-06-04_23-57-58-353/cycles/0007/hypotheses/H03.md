# H03

Replacing accumulated frequency counters with inter-reference recency (IRR) timestamps as the victim selection criterion will better exploit the temporal locality structure of the LIRS-style workload-a trace and improve hit rate.

## Parent

baseline

## Changes

Build a fresh SLRU cache (80/20 protected/probationary split, no ghost set) with IRR-based victim selection in place of frequency counters. This is a full rewrite of `mod.rs`.

**Node** — add two timing fields; remove `freq`, `referenced`:
```
key: K
value: V
prev: Option<usize>
next: Option<usize>
segment: Segment
last_access: u64    // op_clock value at most recent hit
prev_access: u64    // op_clock value at second most recent hit (0 if < 2 hits)
```

**LruCache** — remove `ghost`, `ghost_set`, `ghost_cap`; add:
```
op_clock: u64       // monotonic counter, incremented on every get() and every put() for a new key
```

**IRR helper** (inline in eviction code):
```
irr(idx) = if nodes[idx].prev_access == 0 { u64::MAX } else { nodes[idx].last_access - nodes[idx].prev_access }
```
Small IRR means the entry was accessed twice in quick succession — hot. Large IRR (or MAX if fewer than two recorded accesses) means cold.

**`get(key)`**: on a hit, do `nodes[idx].prev_access = nodes[idx].last_access; nodes[idx].last_access = self.op_clock; self.op_clock += 1`. Return `Some(&value)`.

**New node creation** (arena allocation or slot reuse): set `last_access = self.op_clock; prev_access = 0`. Increment `op_clock`.

**`demote_prot_head()`**: scan LRU quarter of protected (`scan_len = (prot_count / 4).max(1)` from `prot_head`). Among the scanned nodes, select the one with the **maximum IRR** (coldest). On demotion: move to probationary MRU tail. Do NOT reset `last_access` or `prev_access` — the timestamps are preserved across segment transitions, so a previously hot entry retains its small IRR in probationary.

**Probationary eviction**: scan LRU half of probationary (`scan_len = (prob_count / 2).max(1)` from `prob_head`). Among the scanned nodes, select the one with the **maximum IRR** (coldest). Evict it.

**Promotion on probationary hit**: same as current — unlink from probationary, move to protected MRU tail, increment protected count, call `demote_prot_head()` if protected overflows.

Remove: `freq`, `referenced`, `MAX_FREQ`, counter halving, ghost mechanism. No frequency increment on hit — only `last_access`/`prev_access` are updated.

**Segment split**: `prot_cap = capacity * 4 / 5; prob_cap = capacity - prot_cap` (same as baseline 80/20).

Preserve all capacity invariants and existing unit tests where applicable; update tests that reference frequency or ghost semantics.

## Rationale

The LIRS paper models eviction quality by distinguishing low-IRR entries (LIR, hot — two most recent accesses were close in time) from high-IRR entries (HIR, cold — large gap between last two accesses). Workload-a is a LIRS-generated trace, so IRR is the theoretically correct signal. The current frequency counter measures how many times an entry has been accessed in total; IRR instead measures how recently those accesses occurred relative to each other. An entry accessed 100 times long ago has a large IRR and should be evictable; the frequency counter would incorrectly protect it. Timestamp preservation across demotion eliminates the need for explicit counter halving — a demoted hot entry (small IRR) naturally competes against cold newcomers (IRR = MAX) in probationary without any manual signal adjustment.
