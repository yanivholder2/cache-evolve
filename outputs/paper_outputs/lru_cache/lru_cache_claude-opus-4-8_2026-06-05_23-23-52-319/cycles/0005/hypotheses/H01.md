# H01

Demote the least-frequently-used protected node instead of the protected LRU to raise hit-rate by retaining genuinely hot keys against probationary churn.

## Parent

cycle/0004/v001

## Changes

Introduce a frequency signal into the incumbent SLRU's protected-tier
retention decision. The recency axis is nearly consumed (per cross-cycle
insights); frequency is the untapped axis, and because fitness measures
only hit-rate the O(n) scan this requires carries no cost penalty.

Concretely, in `src/lru_cache/mod.rs`:

1. Add a field `freq: u64` to `Node`. Initialise it to `1` everywhere a
   node is created or its slot is reused for a new key (the `nodes.push`
   branch in `put`, and the evicted-slot-reuse branch where
   `nodes[evict_idx].key`/`value` are overwritten — set `freq = 1`
   there too).
2. Increment `freq` on every access that counts as a hit: at the top of
   `get` after the map lookup succeeds, and in the existing-key branch
   of `put`. Do the increment before the unlink/promote.
3. Change `enforce_protected_budget` so that when `prot_len >
   protected_cap` it does **not** demote `prot_head` unconditionally.
   Instead scan the protected segment from `prot_head` following `next`
   links, find the node with the minimum `freq` (tie-break: keep the
   first one found, i.e. the LRU-most among the minima), then `unlink`
   that node and `push_back_probationary` it. Exactly one node is over
   budget per promotion, so a single demotion still restores the bound.

Preserve all existing invariants: the protected/probationary budgets
still sum to `capacity`, net resident count is unchanged by a demotion,
`prob_len + prot_len == map.len()`, and the eviction path in `put`
(probationary LRU first, then protected LRU) is untouched. The `freq`
counter is read only at demotion time; do not let it alter promotion
timing (first-hit promotion is confirmed correct). No change to
`lru_cache_jni.rs`.

## Rationale (optional)

Every prior gain came from deciding which resident dies first; this keeps
that lever but swaps the protected-tier victim selector from pure recency
to access frequency, the one signal the cohort has never applied at the
retention point (W-TinyLFU was tested only as an admission filter and was
harmful — a different mechanism at a different point).
