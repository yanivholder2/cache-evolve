# H02

Replace the SLRU skeleton with a from-scratch LIRS policy that classifies residents by inter-reference recency to raise hit-rate on this LIRS-derived trace.

## Parent

baseline

## Changes

Rebuild `src/lru_cache/mod.rs` as a genuine LIRS cache rather than tuning
SLRU geometry. The prior ghost probes (cycle 0004 v002 and earlier) were
*marginal re-admission* bolted onto SLRU; this is the canonical policy the
workload-a LIRS trace was designed to reward, reorganising the entire
eviction priority around measured reuse distance rather than blindly
promoting every first hit. Because fitness measures only hit-rate, the
extra bookkeeping (a stack plus pruning) is free.

Implement standard LIRS over the existing `HashMap<K, usize>` + arena
`Vec<Node>` substrate:

- Partition `capacity` into an LIR budget `L_lir = capacity - L_hir` and a
  small resident-HIR budget `L_hir = max(1, capacity / 100)` (≈1%). Tune
  this split as a secondary knob but keep `L_hir` tiny.
- Maintain stack **S**: an LRU-ordered list (reuse the prev/next arena
  links) holding all LIR blocks plus HIR blocks that are resident *or*
  non-resident, used only to measure inter-reference recency. Add a
  per-node `status` enum {LIR, HIR_RESIDENT, HIR_NONRESIDENT} replacing
  the boolean `protected`.
- Maintain list **Q**: the resident-HIR blocks in recency order; its
  front is the eviction victim.
- On access to a resident block: if it is LIR, move it to the top of S and
  prune S's bottom (remove trailing HIR entries, freeing non-resident
  slots). If it is HIR-resident and present in S, promote it to LIR
  (demoting the current LIR at S's bottom to HIR-resident, appending it to
  Q) and prune; if HIR-resident but not in S, move it to S top and Q's
  MRU end, staying HIR.
- On a miss (insert): if the cache is full, evict Q's front (the resident
  HIR LRU), marking it HIR_NONRESIDENT if it is still in S, and reuse its
  arena slot. Insert the new block as HIR-resident at Q's MRU end and at
  S's top; if it was found in S as a non-resident HIR (a short reuse
  distance) promote it straight to LIR with the usual demotion/prune.
- Non-resident HIR entries occupy only S (no value, no arena value slot);
  cap their count by pruning S's bottom so the structure stays bounded.

Preserve the externally observable contract: `get` returns
`Option<&V>` and promotes on hit, `put` inserts/updates and never exceeds
`capacity` resident blocks, capacity-1 works, overwrite at full capacity
does not evict. Keep all the existing unit tests passing (adjust their
internal-state comments but not their assertions). Do not touch
`lru_cache_jni.rs`.

## Rationale (optional)

The open question across cycles is whether a genuinely different workload
signal remains once recency/promotion is consumed. Inter-reference
recency is that signal — LIRS distinguishes short-reuse-distance blocks
that SLRU's blunt "protect every first hit" cannot, and the trace family
is its home turf.
