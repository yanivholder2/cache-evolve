# H01

Enlarging the LIRS resident-HIR window from ~1% to ~5% of capacity catches genuine reuses before eviction and raises hit-rate.

## Parent

cycle/0005/v002

## Changes

In `try_new`, the LIRS rebuild reserves a resident-HIR budget of
`let l_hir = std::cmp::max(1, capacity / 100);` (about 20 slots at
capacity 2048) and sets `l_lir = capacity.saturating_sub(l_hir)`. That
resident-HIR list `Q` is the de-facto probationary drain window: every
new key enters as `HirResident` (once the LIR set is warm) and must earn
promotion before it falls off the front of a ~20-slot queue. The SLRU
incumbent's *winning* configuration drains one-hit-wonders through a
~100-slot probationary floor (5% of capacity), and the cross-cycle record
shows reuse on this trace arrives within that wider window but not within
a tiny one — so a 1% HIR window almost certainly evicts genuine reuses
before their second touch.

Change the budget to a ~5% resident-HIR window to mirror the proven SLRU
95/5 floor:

```rust
let l_hir = std::cmp::max(1, capacity / 20);
let l_lir = capacity.saturating_sub(l_hir);
```

Preserve everything else: the LIR warm-up fill in `insert_new`, the
non-resident metadata bookkeeping and bound, `enforce_lir_budget`,
`prune_stack`, and all S/Q/NR link maintenance. The only edit is the
`l_hir` / `l_lir` split in `try_new` (and its log line). The test is
whether LIRS at a 5% HIR window beats both its own 1% configuration
(0.7204) and approaches or exceeds the 95/5 SLRU incumbent (0.7313).

## Rationale (optional)

LIRS underperformed SLRU in cycle 5; the most likely cause is that its
reuse-detection window for resident blocks (the HIR queue) is five times
narrower than the SLRU probationary floor already shown to be the binding
constraint. This isolates that single geometry lever.
