# H01

Enlarging the probationary segment from ~20% to ~40% of capacity raises hit-rate by widening the window in which a reused key can earn promotion before eviction.

## Parent

cycle/0001/v001

## Changes

In `try_new`, change the protected-segment budget from `let protected_cap = (capacity * 4) / 5;` to `let protected_cap = (capacity * 3) / 5;`, so the protected segment is ~60% of capacity and the probationary segment is ~40% (currently ~20%). The probationary budget remains the implicit remainder (`capacity - protected_cap`), so the segments still sum to exactly `capacity` and the P1 capacity bound is unchanged. Update the `log::info!` line in `try_new` to reflect the new split. Leave all other logic — `get`, `put`, `push_back_probationary`, `push_back_protected`, `enforce_protected_budget`, and the probationary-first eviction order — exactly as in the parent.

Preserve the existing invariants: `prob_len + prot_len == map.len()`, `map.len() <= capacity`, and the capacity-1 edge case (the new formula still floors to `protected_cap == 0` at capacity 1, leaving a single probationary slot, identical to the parent).

## Rationale (optional)

In SLRU a key is only promoted if it gets a second access while still resident in the probationary segment. v001's narrow 20% probationary tier may evict genuinely-reused keys before their second touch arrives. Giving probationary more room is the cheapest directional probe of the assumed-but-untuned 80/20 ratio the cycle insight flagged.
