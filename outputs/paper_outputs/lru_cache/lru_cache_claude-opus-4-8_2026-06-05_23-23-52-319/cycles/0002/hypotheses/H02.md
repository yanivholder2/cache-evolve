# H02

Adding a bounded ghost list of recently-evicted keys so a key re-requested shortly after eviction enters the protected segment directly raises hit-rate by exploiting the short reuse distances of the LIRS trace.

## Parent

cycle/0001/v001

## Changes

Add reuse-distance detection to the SLRU parent via a metadata-only ghost history that holds keys (no values) and does not count toward `capacity` or `map`, so the P1 capacity bound is untouched.

1. Add two fields to `LruCache`: `ghost_queue: std::collections::VecDeque<K>` and `ghost_set: std::collections::HashSet<K>`, both initialized empty in `try_new`. Bound the ghost history to at most `capacity` entries.
2. In `put`, on the eviction branch (when `self.nodes.len() >= self.capacity`), after computing `evicted_key` and removing it from `map`, record it in the ghost history: push it onto the back of `ghost_queue` and insert into `ghost_set`; if `ghost_queue.len() > capacity`, pop the front key and remove it from `ghost_set`. (Keep the in-place slot reuse exactly as the parent does.)
3. In `put`, for the new-key (miss) path, before choosing the segment, check `ghost_set`. If the incoming `key` is present, treat it as a recognized reuse: remove it from `ghost_set` (and lazily from the queue or tolerate a stale queue entry), and after acquiring the arena slot insert via `push_back_protected(idx)` followed by `enforce_protected_budget()` instead of `push_back_probationary(idx)`. A fresh key not in the ghost set still enters probationary exactly as in the parent.
4. When a key is successfully reinserted (hit or ghost-promoted), ensure it is no longer tracked as a ghost.

Preserve all parent invariants: `prob_len + prot_len == map.len()`, `map.len() <= capacity`, probationary-first eviction, and the 80/20 segment split. The ghost structures are pure metadata: they must never hold a key that is currently resident in `map`.

## Rationale (optional)

LIRS-style traces reward distinguishing short-reuse-distance keys (hot) from one-hit-wonders. v001 only learns reuse from a second access *while still resident*; a ghost list extends that memory across one eviction, letting an immediately-reaccessed key skip probation — an ARC/LIRS-style additivity test on top of the winning segmentation.
