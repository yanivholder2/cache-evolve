# H02

Clamp ARC's adaptation target `p` to a small ceiling so the frequency tier stays near 95% of capacity, importing the winning SLRU split into ARC's structure to raise hit-rate.

## Parent

cycle/0008/v002

## Changes

In the ARC variant's `src/lru_cache/mod.rs`, constrain the adaptation
target `p` (the target size of the recency list T1) so it can never grow
large enough to shrink the frequency list T2 below ~95% of capacity. The
cross-cycle continuation explicitly calls for "tuning ARC's T2 sizing"
because untuned ARC measured 0.7201 — a real lift over baseline (0.665) but
short of the 95/5 SLRU incumbent (0.7313).

Concretely, introduce a `p_cap` equal to `capacity / 20` (5% of capacity,
matching the incumbent's probationary budget) and apply it wherever `p` is
raised. In the B1-ghost-hit branch of `put`, change
`self.p = (self.p + delta).min(self.capacity);` to
`self.p = (self.p + delta).min(self.capacity / 20);`. The B2-ghost-hit
branch already uses `saturating_sub`, so it needs no change but will now
operate against the smaller ceiling. Leave `replace()`, the ghost arenas,
the four-list bookkeeping, admission into T1/T2, and all canonical ARC
cases otherwise untouched.

With `p` capped near 5% of capacity, `replace()` will almost always demote
the T1 (recency) LRU rather than T2, so re-accessed keys accumulate in a
large, protected T2 — structurally mirroring the 95/5 SLRU split while
retaining ARC's ghost-driven promotion. Preserve the invariant
`res_len[T1] + res_len[T2] <= capacity`.

## Rationale (optional)

This isolates the single hypothesis the cross-cycle insight names as the
live thread: that ARC underperforms the incumbent only because its adaptive
`p` lets the recency tier grow too large for this reuse-heavy trace.
