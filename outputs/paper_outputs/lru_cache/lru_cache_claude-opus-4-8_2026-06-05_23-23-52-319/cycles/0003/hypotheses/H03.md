# H03

Remembering keys recently evicted from probationary and, on their return, admitting them with weak protection (protected-LRU end) recovers reuse-distance hits and raises hit-rate.

## Parent

cycle/0001/v001

## Changes

Add a bounded ghost record to the cache: a `VecDeque<K>` (FIFO) named `ghost`
plus a `HashSet<K>` (`ghost_set`) mirroring its contents for O(1) membership,
capped at `capacity` keys. Store keys only, never values.

When a probationary node is evicted in `put` (the LRU/victim path), push its key
into `ghost`/`ghost_set` before the slot is overwritten; if the ghost FIFO is at
its cap, pop the oldest key and remove it from `ghost_set` first. Do NOT record
keys evicted from the protected fallback path.

On a `put` for a NEW key (the miss branch), check `ghost_set`. If the returning
key is present, this is evidence of reuse just outside the probationary window:
after obtaining the arena slot, insert the node at the **LRU end of the
protected segment** (a new `push_front_protected` helper) rather than the
probationary MRU end, then run `enforce_protected_budget`. Remove the key from
`ghost`/`ghost_set` on this re-admission. A new key NOT in the ghost set keeps
the existing behavior (probationary MRU). Always admit the key — never reject —
so put-then-get visibility holds.

Crucially this grants only *weak* protection: entering at the protected LRU end
makes the returning key the first protected eviction candidate and lets
`enforce_protected_budget` demote it straight back to probationary if protected
is full, so it never displaces a genuinely hot key at the protected MRU end.
This is the corrected form of cycle 0002's H02, which inserted ghost hits at the
protected MRU end and crowded the hot set.

Preserve all invariants: `prob_len + prot_len == map.len()`, residency never
exceeds `capacity` (the ghost list holds no values and does not count toward
residency), in-place slot reuse, and the existing probationary-first eviction
order. Ensure ghost bookkeeping stays bounded and is cleared of any key that
becomes resident again.

## Rationale (optional)

Cycle 0002 found ghost/reuse-distance memory was "directionally right but
mis-placed" and asked whether routing ghost hits to a weaker tier recovers the
signal without crowding the hot set. Weak protection (protected-LRU insertion)
tests exactly that, distinct from a pure ratio change and from frequency-based
eviction.
