# H03

Transplanting IRR timestamps as the primary eviction signal into cycle/0006/v001 while keeping its ghost-admission set intact will reveal whether ghost admission adds measurable hit-rate lift when paired with IRR eviction, potentially beating cycle/0007/v003 if cross-residency warmth detection and temporal clustering are complementary signals.

## Parent

cycle/0006/v001

## Changes

Start from the cycle/0006/v001 overlay (`src/lru_cache/mod.rs`). Apply the following modifications, leaving ghost-set logic, the `referenced` bit, and all linked-list helpers untouched.

### 1. Add IRR fields to `Node`

Add two fields after the existing `referenced: bool` field:

```rust
last_access: u64,   // op_clock value at most recent access
prev_access: u64,   // op_clock value at second most recent access; 0 if < 2 accesses
```

Remove the `freq: u32` field entirely. Remove the `MAX_FREQ` constant.

### 2. Add `op_clock` to `LruCache`

Add a `op_clock: u64` field (initialize to `1` in `try_new()`). This is the same monotonic counter used in cycle/0007/v003.

### 3. Add the `irr()` helper

```rust
#[inline]
fn irr(&self, idx: usize) -> u64 {
    if self.nodes[idx].prev_access == 0 {
        u64::MAX
    } else {
        self.nodes[idx].last_access - self.nodes[idx].prev_access
    }
}
```

### 4. Update timestamp on every hit in `get()`

Immediately after the arena lookup (before the segment branch), add:

```rust
self.nodes[idx].prev_access = self.nodes[idx].last_access;
self.nodes[idx].last_access = self.op_clock;
self.op_clock += 1;
```

### 5. Initialize timestamps on new entries in `put()`

When allocating a new arena slot (both the `free_slots.pop()` branch and the `push` branch), set:

```rust
last_access: self.op_clock,
prev_access: 0,
```

Increment `op_clock` after the slot is filled (same as v003).

For the defensive re-put path (key already resident), update timestamps the same way as `get()`.

### 6. Remove counter halving in `demote_prot_head()`

Delete the `node.freq = (node.freq / 2)` (or equivalent halving) line that was applied on demotion. IRR timestamps are preserved across demotion unchanged — this is the same deliberate choice as in v003.

Also clear the `referenced` bit on demotion: `self.nodes[victim_idx].referenced = false;` (this was already present in v001; keep it).

### 7. Replace freq-based victim selection in `demote_prot_head()`

Change the inner comparison from the `(freq, !referenced)` ascending sort to `(irr, !referenced)` descending: prefer the node with the **highest** IRR; among ties at the same IRR value, prefer an unreferenced node over a referenced one.

```rust
// before (schematic)
if (cur_freq, !cur_ref) < (victim_freq, !victim_ref) { victim = cur; }

// after (schematic)
let cur_irr = self.irr(cur_idx);
if cur_irr > victim_irr
    || (cur_irr == victim_irr
        && !self.nodes[cur_idx].referenced
        && self.nodes[victim_idx].referenced)
{
    victim_idx = cur_idx;
    victim_irr = cur_irr;
}
```

The scan bounds (`scan_len = (prot_count / 4).max(1)`) and all other loop structure stay the same.

### 8. Replace freq-based victim selection in `evict_from_probationary()`

Change the inner comparison from min-frequency to max-IRR:

```rust
// before
if cur_freq < victim_freq { victim = cur; }

// after
let cur_irr = self.irr(cur_idx);
if cur_irr > victim_irr {
    victim_idx = cur_idx;
    victim_irr = cur_irr;
}
```

The scan bounds (`scan_len = (prob_count / 2).max(1)`) stay the same.

### 9. Keep ghost-set logic entirely unchanged

The ghost set (key tracking on probationary eviction, ghost-hit fast-path to protected) is not modified. The ghost-hit path should no longer set a `freq` counter on the admitted entry — instead the entry arrives at protected with `prev_access = 0` (IRR = MAX) just like any other new insertion, because it has only been accessed once. The important thing is the *placement* (direct to protected) not a freq credit.

### Invariants to preserve

- Every `get` hit and every new-key `put` increments `op_clock` exactly once.
- `irr()` returns `u64::MAX` for any node whose `prev_access` is `0`.
- Timestamps are NOT reset or modified on demotion — only the `referenced` bit is cleared.
- The ghost set eviction/insertion/lookup logic is byte-for-byte identical to v001.
