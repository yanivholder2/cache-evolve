# H03

Widening the protected segment from 80% to 85% of capacity will improve hit rate by reducing demotion churn on a workload whose hot working set is dense enough to overflow the current 80% floor.

## Parent

cycle/0006/v001

## Changes

Every prior cycle tested the 80/20 split or failed by *shrinking* the protected segment (cycles 2 and 8 both regressed when probationary was widened to 30%). No cycle has ever tested the opposite direction: shrinking probationary below 20% to give protected more space. The cycle 8 and cycle 2 failures both point to the same root cause — the hot working set is dense and 80% protected is "at or near the minimum" — which implies the active set might benefit from more, not less, protected capacity.

### Single change in `try_new()`

Replace:

```rust
let prot_cap = capacity * 4 / 5;
```

with:

```rust
let prot_cap = capacity * 17 / 20;
```

`prob_cap = capacity - prot_cap` and `ghost_cap = prob_cap` follow automatically, so probationary shrinks from 20% to 15% of capacity and the ghost window shrinks proportionally.

No other code changes. All eviction logic (frequency-aware demotion scanning LRU quarter of protected, probationary half-scan, counter halving on demotion, MAX_FREQ cap, referenced-bit tie-breaker, ghost admission) is identical to cycle/0006/v001.

### Edge case

For small capacities (e.g., capacity = 4), `capacity * 17 / 20` rounds down (4 * 17 / 20 = 3), giving prot_cap = 3, prob_cap = 1, which is the same result as the current formula (4 * 4 / 5 = 3). The change only has effect at capacity >= 20, well below the evaluated capacity of 2048.

## Rationale

The evidence pattern is directional: every failure from *reducing* protected space confirms the active set is large and dense. Expanding protected space in the complementary direction is a direct, untested prediction of the same evidence. At 85% protected (15% probationary), the one-hit filter is weaker (fewer slots in probationary means faster eviction of cold newcomers — which is actually stricter filtering, not looser), while the hot set gets 5% more room. The risk is that 15% probationary reduces the cold-filter window too aggressively on access bursts; the hypothesis is that the benefit of holding more warm entries outweighs this cost on the dense working set of workload-a.
