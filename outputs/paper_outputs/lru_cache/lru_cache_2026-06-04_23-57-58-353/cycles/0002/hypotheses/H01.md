# H01

Widening the SLRU probationary segment from 20% to 30% of capacity will raise hit rate by giving scan traffic more room to exhaust before it can displace protected entries.

## Parent

cycle/0001/v001

## Changes

In `try_new()`, change the protected-capacity formula from

```rust
let prot_cap = (capacity * 4 / 5).min(capacity.saturating_sub(1));
```

to

```rust
let prot_cap = (capacity * 7 / 10).min(capacity.saturating_sub(1));
```

`prob_cap` is derived as `capacity - prot_cap`, so it automatically grows to 30% of capacity. No other logic changes. The log line should reflect the new values. All invariants, promotion path, and demotion path in `get()` and `put()` remain identical to v001 — only the capacity allocation ratio shifts.

## Rationale

v001 uses an 80/20 split but the ratio was never tuned. A larger probationary buffer means cold scan traffic must fill more slots before it overflows into evicting probationary entries; genuinely warm entries get more time to receive a second access and earn promotion to protected. The risk is that protected shrinks, reducing the space for hot entries — testing directly measures whether the scan-filtering benefit outweighs the smaller hot-set budget on workload-a.
