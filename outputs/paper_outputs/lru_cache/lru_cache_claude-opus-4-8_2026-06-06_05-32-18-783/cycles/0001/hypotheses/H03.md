# H03

Swap the HashMap's default SipHash for an inline integer hasher to cut get/put per-op-time without changing policy.

## Parent

baseline

## Changes

In `src/lru_cache/mod.rs`, replace the standard-library default hasher
(SipHash 1-3, cryptographically strong but slow) on the key map with a
fast non-cryptographic integer hasher defined inline (no external
crates, since `Cargo.toml` is out of scope):

- Define a small `struct FastHasher(u64);` implementing
  `std::hash::Hasher`. Use an FxHash-style finalizer: in `write_u64`
  (and a general `write` that folds bytes 8 at a time, falling back to
  byte-wise for tails) accumulate with
  `self.0 = (self.0 ^ value).wrapping_mul(0x517cc1b727220a95);` and
  return `self.0` from `finish`.
- Define `#[derive(Default, Clone)] struct FastBuildHasher;` implementing
  `std::hash::BuildHasher` whose `build_hasher` returns
  `FastHasher(0)` (or a fixed seed constant).
- Change the `map` field type from `HashMap<K, usize>` to
  `HashMap<K, usize, FastBuildHasher>` and construct it with
  `HashMap::with_capacity_and_hasher(capacity, FastBuildHasher)` in
  `try_new`. All `map.get`/`insert`/`remove` call sites stay the same.

Keep the generic `K: Hash + Eq` bound; the hasher works for any key but
is tuned for the `u64` keys the harness uses. Note this changes the
`LruCache` struct's size only by the (zero-sized) build-hasher, so
metadata-size is unaffected; the lever is the `get` p50 (41ns) and
`put` p50 (75ns), both dominated by hashing.

Invariants to preserve: hashing strategy is the only change, so P1/P2/P3
and hit-rate are bit-identical to the baseline. Correctness must not
depend on hash quality — `Eq` still resolves collisions. No external
crates, no `unsafe`.

## Rationale (optional)

For a workload of 8-byte integer keys, SipHash is the dominant cost in
both `get` and `put`. A single multiply-xor per key is several times
faster and is the standard win for integer-keyed maps, targeting the
per-op-time dimension while leaving every other dimension fixed.
