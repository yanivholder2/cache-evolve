# H01

Split the recency list into probationary and protected segments (segmented LRU) so that one-hit-wonders are evicted before reused items, raising hit-rate on the LIRS workload.

## Parent

baseline

## Changes

Convert the single global LRU list in `src/lru_cache/mod.rs` into a
two-segment SLRU within the same arena. Concretely:

- Add a `protected: bool` flag to `Node<K, V>` and replace the single
  `head`/`tail` pair on `LruCache` with two pairs:
  `prot_head`/`prot_tail` and `prob_head`/`prob_tail`. Add a
  `prot_len: usize` counter and derive a `prot_cap = capacity * 4 / 5`
  (clamp to at least 1, and to at most `capacity - 1` so the
  probationary segment is never starved).
- Generalize `unlink`/`push_back` so they operate on whichever segment
  the node belongs to (selected by `node.protected`). Keep them O(1).
- In `get`: on a hit, if the node is in the probationary segment,
  promote it — unlink from probation, set `protected = true`, push to
  the protected MRU, and increment `prot_len`. If promotion makes
  `prot_len > prot_cap`, demote the protected LRU node back to the
  probationary MRU (`protected = false`, decrement `prot_len`). If the
  node is already protected, just move it to the protected MRU. Then
  return the value (preserve the existing `&self.nodes[idx].value`
  return shape).
- In `put` for a brand-new key: insert into the probationary MRU with
  `protected = false`.
- In `put`'s eviction branch (`self.nodes.len() >= self.capacity`):
  choose the victim as the probationary LRU (`prob_head`); only if the
  probationary segment is empty, evict the protected LRU
  (`prot_head`, decrementing `prot_len`). Reuse the victim's arena slot
  exactly as today (clear/overwrite key+value, re-link as a
  probationary node).
- Updating an existing key's value in `put` keeps its current segment
  and promotes within that segment (mirror the existing
  unlink/push_back-to-MRU behavior).

Invariants to preserve: total residents never exceed `capacity`
(arena length is still the sole admission gate, so P1 holds);
value fidelity (P2) and no-phantom (P3) are untouched because every
insert still registers in `map` and every eviction still removes the
victim's key from `map`. The cache must remain O(1) per op and use no
external crates.

## Rationale (optional)

The trace is a `lirs:` workload, the family LRU is known to handle
poorly because scan/loop patterns flush reused blocks. Protecting
twice-referenced items behind a probationary gate is the cheapest
classical defense and directly targets the hit-rate dimension.
