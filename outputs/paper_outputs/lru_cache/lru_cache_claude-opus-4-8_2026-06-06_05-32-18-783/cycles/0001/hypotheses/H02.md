# H02

Replace the `Option<usize>` arena links with `u32` sentinel indices to shrink `Node` from 48 bytes toward 24 bytes, improving the metadata-size dimension.

## Parent

baseline

## Changes

In `src/lru_cache/mod.rs`, change the link representation so each node
pointer costs 4 bytes instead of 16:

- Change `Node<K, V>.prev` and `.next` from `Option<usize>` to `u32`,
  and likewise `LruCache.head`/`.tail` and `capacity`-related index
  fields used as links. Introduce a module constant
  `const NONE: u32 = u32::MAX;` to stand in for the absent link.
- Rewrite `unlink` and `push_back` to compare against `NONE` instead of
  matching `Option`, and to write `NONE` where they previously wrote
  `None`. Index the arena with `idx as usize` at the `nodes[...]`
  access sites.
- Update `get`/`put` to use `u32` indices internally; keep `map`'s value
  type as the index (it may stay `usize` or also become `u32`, but the
  arena slot math must stay consistent). The new-slot branch computes
  `let idx = self.nodes.len() as u32;` and the capacity comparison stays
  `self.nodes.len() >= self.capacity`.
- Add a `debug_assert!(capacity <= u32::MAX as usize)` in `try_new` so
  the `u32` index space cannot overflow; the evaluation capacity (2048)
  is far below this bound.

For `Node<u64, u64>` this yields key(8) + value(8) + prev(4) + next(4) =
24 bytes versus the baseline's 48, which is exactly the metadata-size
summary the fitness vector reports.

Invariants to preserve: behavior must be byte-for-byte equivalent to the
baseline LRU (P1/P2/P3 all hold unchanged) — this is a pure
representation change, not a policy change. Per-op-time should be
unaffected or slightly better (smaller nodes, better cache-line use); it
must not regress hit-rate. No external crates.

## Rationale (optional)

`Option<usize>` is 16 bytes (no niche, 8-byte alignment), so two links
dominate the node. A `u32` sentinel halves node size with no algorithmic
change, the lowest-risk way to move the metadata-size dimension.
