# H03

A single-list second-chance CLOCK over the FastHasher arena, carrying no recency links at all, lowers get per-op-time versus the segmented champion while holding hit-rate near LRU.

## Parent

baseline

## Changes

A fresh architectural bet distinct from the segmented champion: drop the
doubly-linked recency list entirely and approximate LRU with a CLOCK
(second-chance) hand over the arena. This removes *all* per-hit pointer
surgery — a hit becomes a single boolean write — and tests whether the
simpler structure beats the SLRU champion on latency at acceptable
hit-rate. The cross-cycle note that "the protected-segment surgery-skip
does not transfer to single-list LRU" was about the *MRU fast path*;
CLOCK is a different mechanism (no list to be MRU of) and has not been
tried here.

Rewrite `src/lru_cache/mod.rs` starting from the baseline:

- Port the champion's zero-sized `FastHasher` / `FastBuildHasher` and use
  it for the `HashMap<K, usize, FastBuildHasher>` (this is the proven
  free hot-path win underlying every champion).
- Replace `Node` with `Node { key: K, value: V, referenced: bool }`. With
  `u64` key and value this is 24 bytes (16 data, the flag padded to the
  8-byte alignment) — no recency links, so the scored `Node<u64,u64>`
  metadata-size stays at the 24-byte class honestly, with the recency
  state held in-node rather than in any parallel array.
- Add a `hand: usize` clock pointer to `LruCache` (drop `head`/`tail`).
- `get()`: on a map hit, set `nodes[idx].referenced = true` and return the
  value — no list mutation. On miss, `None`.
- `put()` existing key: overwrite value, set `referenced = true`, return.
- `put()` new key with arena room: push a `Node { referenced: false }`,
  insert into map.
- `put()` new key at capacity: advance the clock — while
  `nodes[hand].referenced`, set it `false` and `hand = (hand + 1) %
  capacity`; the first slot with `referenced == false` is the victim.
  Remove its key from the map, overwrite key/value in place, set
  `referenced = false`, insert the new key->slot, and advance `hand` past
  it.

Preserve correctness invariants the gate checks: capacity is never
exceeded, every map entry points at a live arena slot holding that key,
overwrite of an existing key never evicts, and capacity-zero still fails
in `try_new` as the baseline does. Keep the public API and the
`framework::Cache` impl identical.

## Rationale (optional)

CLOCK's hit path is one write versus the champion's unlink+push_back, so
if hit-rate stays within range of LRU on this short-reuse trace the
latency dimension should improve. Citing baseline rather than the
champion because this discards segmentation wholesale — it is a clean
alternative lineage, not an edit to the SLRU line.
