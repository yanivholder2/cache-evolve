# H01

Re-issue the single-entry last-key get cache on the champion so repeated gets of the hottest protected-MRU key skip the HashMap hash-and-probe, lowering get p50 (per-op-time).

## Parent

cycle/0006/v003

## Changes

This re-runs the Cycle 0007 H03 thread, which died on a simulator/build
infra failure and was never measured — not on merit. Apply it to the
current champion source unchanged in intent.

Add two fields to `LruCache`: `last_key: Option<K>` and `last_idx: u32`,
initialized to `None` and `NIL` in `try_new`. These live on the cache
struct, not on `Node`, so `Node<u64,u64>` stays 24 bytes and the scored
metadata-size (the Node size) is unchanged; only the `LruCache` footprint
grows.

At the very top of `get`, before `self.map.get(key)?`, add a single-entry
fast path: if `self.last_idx != NIL` and `self.last_key.as_ref() == Some(key)`
and, with `last = self.last_idx as usize`, both `self.prot_tail == self.last_idx`
(the cached node is still the protected MRU, so the access changes no links)
and `self.nodes[last].key == *key` (guards against the slot having been
reused for another key by eviction), return `Some(&self.nodes[last].value)`
without touching the HashMap.

Keep the cached key primed on any normal get that ends with the accessed
node at the protected MRU: in the existing protected-MRU fast-path return
and after the promote/refresh `push_back` into the protected segment, set
`last_key = Some(key.clone())` and `last_idx = link(idx)`. Do not add
explicit invalidation on eviction or demotion — a stale `last_idx` simply
fails the `nodes[last].key == *key` guard and falls through to the normal
map lookup. Do not change put, eviction, geometry, promotion, or node
layout.

Confirmed if get p50 drops below 26 ns with hit-rate held at ~0.729;
refuted if key churn makes the guard mispredict often enough that the
extra compares regress get p50. This is the conservative, single-key,
no-relink variant — contrast H02, which keeps several alternating hot
keys and skips the probe even when relinking is still required.
