# H03

Add gentle ghost-key probation re-entry on the champion so a recently-evicted key that returns is readmitted directly into the protected segment, testing whether reuse-distance admission lifts hit-rate on this short-reuse trace.

## Parent

cycle/0006/v003

## Changes

This settles the standing cross-cycle open question — "does the
gated-ghost hit-rate gain actually reproduce on the short-reuse workload,
or was it trace/size-contingent?" It is deliberately distinct from the
refuted two-hit promotion gate (Cycle 0005/0007 v002), which made
admission *stricter* and drained short-reuse repeaters out of probation.
This goes the other way: it makes admission *smarter* for keys that have
demonstrated reuse across an eviction boundary, without delaying any
first-hit promotion.

Add a bounded ghost record of recently-evicted keys to `LruCache`: a
`ghost: std::collections::VecDeque<K>` plus a companion
`HashMap<K, (), FastBuildHasher>` membership set (or a single `HashMap`
preserving insertion order via a counter), capped at `capacity / 2`
entries and initialized empty in `try_new`. These live on the cache
struct, not on `Node`, so `Node<u64,u64>` stays 24 bytes and the scored
metadata-size (the Node size) is unchanged; only the `LruCache` footprint
grows.

In `put`, on the eviction branch (where `evicted_key` is computed before
`self.map.remove(&evicted_key)`), push `evicted_key` into the ghost set;
if the ghost set exceeds its cap, pop its oldest entry. When a brand-new
key is being inserted (the `self.map.get(&key)` miss path in `put`),
check the ghost set first: if the key is a ghost hit, remove it from the
ghost set and admit the new node directly into the protected segment
(set the node protected, `push_back`, `prot_len += 1`, and run the
existing `if self.prot_len > self.prot_cap { self.demote_protected_lru() }`
overflow check) instead of into probation. A non-ghost new key is admitted
into probation exactly as today. Do not change `get`, the protected
geometry/cap, the fast hasher, or node layout.

Confirmed if hit-rate rises above ~0.729 with metadata-size held at 24
and no material get p50 regression; refuted if direct-to-protected
re-admission overshoots and evicts genuinely hot protected keys (the
failure mode seen with unconditional ghost-to-protected promotion),
dropping hit-rate back toward or below pure SLRU.
