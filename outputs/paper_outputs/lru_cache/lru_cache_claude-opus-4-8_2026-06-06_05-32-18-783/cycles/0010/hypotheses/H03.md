# H03

Lowering the protected cap to 3/4 enlarges the probationary segment, giving short-reuse repeaters more time to land their second hit before probation eviction and raising hit-rate.

## Parent

cycle/0004/v001

## Changes

In `try_new`, change the protected sizing fraction from `capacity * 7 / 8`
to `capacity * 3 / 4` when computing `prot_cap` (keep the existing
`.max(1).min(capacity.saturating_sub(1))` clamps). Nothing else changes:
promotion still happens on the first probationary hit, eviction still takes
the probationary LRU first, demote-on-overflow is unchanged, and the
24-byte node layout is preserved.

Motivation: the geometry axis has only ever been pushed *upward* (toward a
bigger protected segment), which Cycle 0007 showed hits a starvation cliff
at 15/16. The opposite direction is unexplored. On this repeatedly-cited
short-reuse trace, a too-small probation (1/8 of capacity = ~256 slots at
2048) may evict genuine repeaters before their second access arrives.
Enlarging probation to 1/4 (~512 slots) lengthens the window in which a
short-reuse key can earn promotion, which should lift hit-rate if probation
eviction — not protected eviction — is the limiting factor.

Confirm: hit-rate rises above the parent's 0.724 with get/put p50 holding
(a roomier probation should not starve the protected-MRU fast path).
Refute: hit-rate falls, indicating the protected segment was already the
binding retention constraint and shrinking it discards proven-hot keys.

## Rationale (optional)

Distinct from the upward geometry probe (H01): this tests the competing
hypothesis that probation-side eviction, not protected-side retention,
caps hit-rate on a short-reuse workload — the two bracket the 7/8 champion
from opposite directions on the same parameter for different reasons.
