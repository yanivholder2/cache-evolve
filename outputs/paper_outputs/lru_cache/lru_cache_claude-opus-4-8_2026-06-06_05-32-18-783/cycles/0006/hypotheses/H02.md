# H02

Fuse the unlink-then-push_back relink into a single move-to-MRU pass that removes the dead sentinel writes, lowering per-op-time.

## Parent

cycle/0004/v001

## Changes

In `src/lru_cache/mod.rs`, the get-refresh path (protected node that is not
the protected MRU) and the put-refresh path (existing key not at its
segment MRU) both call `self.unlink(idx); self.push_back(idx);`. That pair
does measurably redundant work: `unlink` ends by writing
`set_prev_link(NIL)` and `set_next_link(NIL)` on `idx`, and `push_back`
immediately overwrites both with `tail`/`NIL`; it also re-reads the
`protected()` flag that `unlink` already read.

Add a private `#[inline] fn move_to_mru(&mut self, idx: usize)` that does the
whole relink in one pass: read `protected` once; detach `idx` from its
neighbors by repointing its `prev`/`next` neighbors (or the segment
head/tail) exactly as `unlink` does; then append it at the segment tail —
but skip the two intermediate `NIL` writes to `idx` because the append
overwrites them anyway. Write each of `idx`'s own link words exactly once
(final `prev = old_tail`, `next = NIL`, flags preserved). Replace both
`unlink(idx); push_back(idx);` call sites on the refresh paths with
`self.move_to_mru(idx)`.

Do NOT touch the eviction path's `unlink(victim)` (the victim is detached
then reinitialized, so its sentinel writes are not dead there) — keep
`unlink`/`push_back` as-is for that use. This differs from cycle/0005/v003's
failed fusion: that collapsed promote+demote, which performed the identical
four surgeries; here the fusion genuinely elides real writes and a duplicate
flag read on the single-node move. Node stays 24 bytes; hit-rate must be
byte-identical (same final ordering). Confirmed if p50/p99 fall with
hit-rate and metadata-size unchanged.
