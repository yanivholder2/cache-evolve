# H02

Gate protected promotion behind a second probationary hit using a spare link bit, raising hit-rate without growing the 24-byte node or adding ghost structures.

## Parent

cycle/0004/v001

## Changes

Add a 2Q/LRU-2-style frequency gate to v001's promotion path, entirely
in-node so metadata-size stays at 24 and no external history is
introduced. v001's `next` link word never carries a flag and arena
indices stay well under `2^31` at harness capacities, so bit 31 of
`next` is free for a per-node "referenced" marker:

- Add `const REF_MASK: u32 = 1 << 31;` and `Node` helpers
  `referenced(&self) -> bool`, `set_referenced(&mut self)`, and
  `clear_referenced(&mut self)` that test/set/clear that bit. Update
  `next_link`/`set_next_link` to mask `REF_MASK` off on read and
  preserve it on write (exactly as `prev_link`/`set_prev_link` already
  do for `PROT_MASK`), so all list traversal ignores the marker. New
  nodes are created with the bit clear in both `put` allocation sites.
- Change `get`'s probationary branch. On a probation hit, if
  `referenced()` is false: `set_referenced()` and refresh the node to
  the probation MRU (`unlink` + `push_back`, staying probationary, flag
  untouched) instead of promoting — optionally skip the surgery when the
  node is already `prob_tail`. If `referenced()` is true: `clear_referenced()`,
  then promote into protected exactly as v001 does today
  (`unlink`, `set_protected(true)`, `push_back`, `prot_len += 1`, demote
  on overflow).
- When a probationary node is overwritten via `put`'s update path, leave
  its referenced bit as-is (a refresh is not a second distinct hit), and
  ensure eviction/slot-reuse clears the bit when a slot is repurposed.

Preserve v001's `FastHasher`, `prot_cap` geometry, probation-first
eviction, and the protected-MRU fast path. The change must not alter the
`Node` size (the marker is packed into the existing `next` word).

## Rationale (optional)

The open question across cycles is whether tuning the repeated-hit
threshold yields retention headroom without the latency tax of blunt
cap-widening. Requiring two probationary hits before a slot enters
protected keeps one-hit-wonders out of the protected segment, reducing
protected churn — a hit-rate lever orthogonal to the ghost approach and
free of any size cost since it reuses a spare link bit.
