# H03

Gate admission on estimated access frequency (TinyLFU-style) so that an incoming key only displaces the LRU victim when it is at least as frequently seen, raising hit-rate by rejecting cold scan traffic.

## Parent

baseline

## Changes

Keep the baseline's single LRU list and arena, but add a frequency-sketch
admission filter on the eviction path. Add a `freq: Vec<u8>` count-min-style
sketch with a fixed width (e.g. `1 << 14` counters across 4 hash rows, derived
by mixing the `i64` key with distinct seeds) and a `sample: usize` counter.
Provide:
- `bump(key)`: increment the 4 row counters (saturating at 15) and increment
  `sample`; when `sample` reaches `10 * capacity`, halve **every** counter
  (the TinyLFU aging/reset step).
- `estimate(key)`: return the minimum of the 4 row counters.

Behaviour:
- `get(key)`: call `bump(key)` regardless of hit/miss, then perform the existing
  hit-path promotion to MRU and return the value (unchanged on miss).
- `put(key, value)` (called on miss): call `bump(key)`. If the arena is **not**
  full, insert at MRU as today. If the arena **is** full, compute the LRU victim
  at `head` and compare `estimate(key)` against `estimate(victim_key)`: admit the
  newcomer (evict the victim, reuse its slot at MRU) only when
  `estimate(key) >= estimate(victim_key)`; otherwise **reject** the newcomer —
  do not evict, do not insert (the victim stays, newcomer is simply not cached).

Rejecting an admission must leave the cache state unchanged except for the
sketch. Preserve invariants: residents stay `<= capacity` (rejection only ever
keeps residents flat), every resident reads back its value, and a rejected or
never-put key reads `None`.
