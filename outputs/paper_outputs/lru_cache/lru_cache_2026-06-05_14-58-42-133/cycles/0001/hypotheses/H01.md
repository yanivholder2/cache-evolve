# H01

Split the cache into a probationary and a protected segment with promotion on the second hit (SLRU) to raise hit-rate by resisting one-hit-wonder pollution.

## Parent

baseline

## Changes

Convert the single LRU list into a two-segment SLRU. Add a per-node flag
`protected: bool` to `Node` (default `false` = probationary). Keep the existing
arena (`nodes: Vec<Node>`), `map: HashMap<K, usize>`, and the `unlink` /
`push_back` primitives, but maintain **two** intrusive lists instead of one:
keep the current `head`/`tail` as the probationary list and add
`prot_head: Option<usize>` / `prot_tail: Option<usize>` plus a running
`prot_len: usize`. Introduce a protected-capacity cap
`prot_cap = (capacity * 4) / 5` (≈80%).

Behaviour:
- `get(key)` on a hit: if the node is in the probationary segment, unlink it
  from the probationary list, set `protected = true`, push it to the protected
  MRU tail, and increment `prot_len`; if `prot_len > prot_cap`, demote the
  protected-LRU node (set `protected = false`, move it to the probationary MRU
  tail, decrement `prot_len`). If the node is already protected, just move it to
  the protected MRU tail. Return `&value` as today.
- `put(key, value)` on a new key always inserts into the **probationary** MRU
  tail with `protected = false`.
- Eviction (arena full) must always take the **probationary head** (the
  probationary-LRU). If the probationary segment is empty, fall back to evicting
  the protected head. Reuse that slot in place exactly as the baseline does.
- `put` on an existing key updates the value in place and promotes within
  whichever segment the node currently occupies (mirror the get-hit promotion).

Generalise `unlink`/`push_back` to take the relevant head/tail fields (or add
`unlink_seg`/`push_back_seg` helpers) so both segments share the splice logic.
Preserve invariants: total residents (`map.len()`) must stay `<= capacity`,
every resident key must still read back its stored value, and no ghost/never-put
key may become resident.
