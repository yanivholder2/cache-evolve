# H02

Gate arena-full admission on a count-min frequency estimate so a cold newcomer cannot evict a probationary victim it does not out-rank, raising hit-rate under scan pollution.

## Parent

cycle/0001/v001

## Changes

Layer a lightweight TinyLFU-style frequency sketch onto the SLRU
admission decision in `put`, keeping all segment/list mechanics intact:

- Add a count-min sketch to `LruCache`: a fixed `sketch: Vec<u8>` of
  `4 * 16384` saturating 8-bit counters arranged as 4 rows of 16384,
  plus a `sketch_ops: usize` counter and a reset threshold
  `sketch_reset = 10 * capacity`. Initialise in `try_new`.
- Add a private `bump(&self, key)`/`bump(&mut self, key)` that hashes the
  key (use `std::hash::Hash` via `DefaultHasher`, mixing a distinct
  per-row seed) and increments each row's counter saturating at 255, and
  an `estimate(&self, key) -> u8` returning the minimum across rows. On
  each `get` hit and each `put` (existing or new key), call `bump(key)`;
  increment `sketch_ops` and, when it reaches `sketch_reset`, halve every
  counter (`c >>= 1`) and reset `sketch_ops`.
- In `put`, in the arena-full branch only: after selecting the
  probationary-LRU `victim` but **before** removing/overwriting it,
  compare `estimate(&key)` (incoming) against `estimate(&victim_key)`.
  If the incoming estimate is strictly less than the victim's, **reject
  admission**: do not evict, do not insert into `map`, leave the arena
  untouched, but still `bump(&key)` so a persistently reused key climbs
  and is admitted on a later attempt. Otherwise proceed with the
  existing eviction-and-insert (probationary) path. Only apply this gate
  when the chosen victim is the probationary-LRU; if the cache must fall
  back to a protected victim (probationary empty), admit unconditionally.

Preserve every existing invariant: O(1) per op, in-place slot reuse,
`prot_len <= prot_cap`, eviction order (probationary first), and
`map.len() <= capacity`. The sketch must add at most one bump per access
and never allocate after construction.

## Rationale (optional)

v003 showed an `estimate(key) >= estimate(victim)` admission gate is the
decisive lever on this trace; v001 showed segmentation is. Combining a
frequency gate with SLRU should reject cold scan keys that SLRU would
still briefly admit into probationary, protecting reused keys harder.
