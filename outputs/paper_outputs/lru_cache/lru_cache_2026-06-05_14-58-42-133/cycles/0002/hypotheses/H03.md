# H03

Replace the flat LRU with an ARC-style adaptive policy that uses two ghost lists and a self-tuning recency/frequency target to raise hit-rate without hand-set segment sizes.

## Parent

baseline

## Changes

Re-implement `LruCache` as an Adaptive Replacement Cache (ARC) over the
existing arena + `HashMap` machinery, replacing the single intrusive
list with four logical lists and an adaptive target `p`:

- Maintain four intrusive doubly-linked lists, each with its own
  head/tail endpoints stored on `LruCache`: `T1` (recent, seen once,
  resident), `T2` (frequent, seen ≥2 times, resident), `B1` (ghost of
  evicted-from-T1 keys, value-less), `B2` (ghost of evicted-from-T2
  keys, value-less). Resident nodes (T1∪T2) still live in the arena
  `nodes` Vec and reuse slots in place; ghosts (B1/B2) store only the
  key (a `K` plus list links, no value) and are kept in a separate small
  arena or as `VecDeque<K>` bounded so `|T1|+|B1| <= capacity` and
  `|T2|+|B2| <= capacity`. Track an adaptive target `p: usize`
  (0..=capacity), initialised to 0.
- Tag each resident node with which list it belongs to (extend `Node`
  with an enum/`u8` list-id) so `unlink`/`push_back` fix up the correct
  endpoints, mirroring how the parent's two-segment variants thread a
  flag through those helpers.
- `get(key)`: on a hit in T1 or T2, move the node to the MRU end of T2
  (a second reference promotes to frequent). Return the value.
- `put(key,value)`: implement the standard ARC cases — (a) hit in
  T1/T2: update value, move to T2 MRU; (b) hit in ghost B1: increase
  `p` by `max(1, |B2|/|B1|)` clamped to `capacity`, `REPLACE(p)`, move
  key into T2 MRU as a resident; (c) hit in ghost B2: decrease `p` by
  `max(1, |B1|/|B2|)` clamped to 0, `REPLACE(p)`, move into T2 MRU; (d)
  full miss: enforce the L1=T1∪B1 / L2=T2∪B2 size bounds (evicting the
  ghost ends as in the ARC paper), `REPLACE(p)`, then insert the new key
  at the MRU end of T1. `REPLACE(p)` evicts the LRU of T1 to B1 when
  `|T1| >= max(1,p)` (or T1 nonempty and the ghost-hit was in B2),
  otherwise evicts the LRU of T2 to B2; the evicted resident's arena
  slot is reused in place for the incoming key.

Preserve baseline invariants: capacity > 0 guard in `try_new`, O(1)
per operation, in-place arena slot reuse for residents, no `unsafe`, no
external crates, and total resident count `|T1|+|T2| <= capacity` so
`map` (key -> resident index) never exceeds capacity. Ghost lists hold
only non-resident keys and never overlap the resident `map`.

## Rationale (optional)

The cohort's three policies all used fixed splits or static gates; ARC
self-tunes the recency/frequency balance per trace via its ghost-driven
`p`, which can outperform a hand-set 80/20 SLRU when the workload's
reuse mix shifts. Exploring from baseline keeps this a clean,
independent adaptive strategy rather than a tweak of v001.
