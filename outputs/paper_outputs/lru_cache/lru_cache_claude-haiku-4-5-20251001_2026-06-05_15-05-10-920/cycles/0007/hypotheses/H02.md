# H02

Implement selective threshold-dependent decay that preserves weak frequency signals for newly-accessed items while aggressively decaying strong signals, maintaining fine discrimination within the hot-item tier to raise hit-rate.

## Parent

cycle/0005/v001

## Changes

The parent variant applies uniform 0.75× multiplicative decay to all frequency values when the reset threshold is reached. This blanket decay equally affects both weak signals (freq 1-3) for newly-accessed items and strong signals (freq ≥ 4) for established hot items.

Modify the `check_and_perform_frequency_reset()` method to apply selective decay based on frequency thresholds. Instead of:

```rust
for node in &mut self.nodes {
    node.freq = (node.freq as u16 * 3 / 4) as u8;
}
```

Implement:

```rust
for node in &mut self.nodes {
    if node.freq >= 4 {
        node.freq = (node.freq as u16 * 3 / 4) as u8;
    }
    // Items with freq < 4 are not decayed; retain their weak signals unchanged
}
```

This preserves the weak-signal items (freq 0-3) at their current levels while applying the proven 0.75× decay only to items with freq ≥ 4. Keep the reset interval at capacity × 16 (unchanged from parent) and all other eviction logic intact.

## Rationale

Cycle 0006 v003 attempted selective decay but was rejected due to backend failure. This fresh implementation targets the same hypothesis: selective decay can better balance protection of hot items (freq ≥ 4) with preservation of weak temporal signals for items being newly discovered. By preserving weak signals, the cache can more quickly elevate newly-hot items without being forced to compete from frequency 0, potentially reducing the gap between discovery and protection. This approach explicitly targets hit-rate improvement for workloads with gradual item discovery patterns without requiring new mechanisms—only a simple frequency-threshold check during decay.
