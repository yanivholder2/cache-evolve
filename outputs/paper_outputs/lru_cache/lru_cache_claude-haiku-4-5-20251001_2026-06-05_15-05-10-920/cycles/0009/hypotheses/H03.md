# H03

Trigger frequency decay adaptively based on observed hit-rate decline rather than fixed operation count to improve cache responsiveness when workload access patterns shift.

## Parent

cycle/0005/v001

## Changes

The parent variant triggers decay every capacity × 16 operations using a fixed `frequency_reset_counter`. This interval assumes uniform phase-shift behavior, but workloads with irregular transitions may benefit from adaptive triggering that detects degradation.

Replace the fixed-interval decay trigger with adaptive hit-rate monitoring:

1. Add new fields to LruCache:
   ```rust
   hit_count: u64,
   miss_count: u64,
   last_hit_rate: f64,
   decay_interval_multiplier: u64,
   ```

2. Track hit/miss with counters in `get()` (hit on success, counted in get()) and `put()` (miss on cache fill/eviction)

3. Periodically (every capacity × 8 operations), check hit-rate trend:
   ```rust
   let current_hit_rate = hit_count as f64 / (hit_count + miss_count) as f64;
   if current_hit_rate < last_hit_rate * 0.95 {  // 5% hit-rate drop detected
       // Phase shift detected: decay immediately instead of waiting for capacity × 16
       self.perform_frequency_decay();
       self.reset_counters();
       // Optionally increase decay interval slightly to avoid over-decaying
       decay_interval_multiplier = (decay_interval_multiplier + 1).min(24);
   } else {
       // Stable phase: allow interval to relax toward capacity × 16
       decay_interval_multiplier = (decay_interval_multiplier - 1).max(16);
   }
   last_hit_rate = current_hit_rate;
   ```

4. Use `decay_interval_multiplier` as the threshold for the next decay trigger instead of fixed capacity × 16

Keep the 0.75× multiplicative decay formula and frequency counter representation identical to the parent.

## Rationale

Cycle 0008 and cross-cycle insights both note that the fixed capacity × 16 interval is "robustly tuned" but leave open whether this is truly optimal or merely a local optimum. The question "Are there phase shifts or mode transitions in the workload that remain unexploited?" suggests periodic boundaries may miss real transitions. Adaptive triggering based on hit-rate trends could detect when the current frequency distribution is becoming stale and proactively reset without requiring frequency-distribution statistics (which previous adaptive attempts found too costly). This isolates whether the bottleneck is the interval value itself or the non-adaptive triggering mechanism.
