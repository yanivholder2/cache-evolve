# H03

Extend the feedback-controller idea to a second runtime knob — adaptive ghost capacity driven by ghost-hit productivity — to capture more re-admission signal and raise hit-rate.

## Parent

cycle/0008/v001

## Changes

Build on v001, but make the ghost queue's capacity its own runtime-adaptive
knob instead of statically tracking `main_size`. All edits in
`src/s3_fifo/mod.rs`:

1. Add fields `ghost_size: usize` (the adaptive ghost capacity) and two
   windowed counters `ghost_probe: u32` and `ghost_hit: u32` to `S3Fifo`. In
   `try_new()` initialize `ghost_size = main_size` (its current effective
   value) and both counters to 0.

2. Define bounds and a window: `fn ghost_lower(&self) -> usize { (self.capacity / 2).max(1) }`,
   `fn ghost_upper(&self) -> usize { (self.capacity * 2).max(1) }`, and a
   constant `const GHOST_WINDOW: u32 = 256;`.

3. Replace every comparison `self.ghost.len() >= self.main_size` (in
   `evict_main`, `evict_small`, and the in-ghost branch of `put` if present)
   with `self.ghost.len() >= self.ghost_size`, and update
   `VecDeque::with_capacity(main_size)` for the ghost to use the initial
   `ghost_size`.

4. Instrument productivity. On every `put` that misses the resident set,
   increment `ghost_probe`; when that miss lands in the ghost (the in-ghost
   branch), also increment `ghost_hit`. When `ghost_probe >= GHOST_WINDOW`,
   evaluate the conversion rate: if `ghost_hit * 100 >= ghost_probe * 25` (>=25%
   of recent misses converted from ghost), grow `ghost_size` by
   `(self.capacity / 16).max(1)` clamped to `ghost_upper()`; if
   `ghost_hit * 100 <= ghost_probe * 10` (<=10%), shrink `ghost_size` by the
   same amount clamped to `ghost_lower()`; otherwise leave it. Then reset both
   counters to 0.

Leave the partition adaptation (`small_size`/`main_size` steering on
`from_main`) exactly as v001 has it — this hypothesis changes only the ghost
capacity controller, which now runs independently. Preserve all existing
invariants: the ghost still stores keys only (`GhostKey`), `evict_ghost_one`
still drops weak records first, and resident-queue bounds are untouched. The
ghost never exceeds `ghost_size`.

## Rationale (optional)

The cross-cycle history settled that ghost *depth/window length* is exhausted
under a *fixed* budget, but capacity was always pinned to `main_size`. The
cycle-0008 open question explicitly asks whether the feedback-controller framing
extends to adaptive ghost capacity now that capacity is the binding ghost
constraint. Sizing the ghost to its own measured conversion productivity tests
exactly that: a high hit-conversion rate means more remembered history would pay,
a low rate means the budget is wasted — a self-tuning second controller distinct
from both static depth changes and the partition steering.
