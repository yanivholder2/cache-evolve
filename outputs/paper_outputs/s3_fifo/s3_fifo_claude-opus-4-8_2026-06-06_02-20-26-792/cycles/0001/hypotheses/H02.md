# H02

Shrink the small admission queue to ~10% of capacity (from 25%), giving the main resident queue more room to hold hot items and raising hit-rate.

## Parent

baseline

## Changes

In `try_new()` in `src/s3_fifo/mod.rs`, change the `small_size` derivation.
Currently, for `capacity > 1`, `small_size = (capacity / 4).max(1).min(capacity - 1)`.
Replace the `capacity / 4` term with `capacity / 10`, keeping the same
`.max(1).min(capacity - 1)` clamps so the partition stays valid for small
capacities. Leave `main_size = capacity - small_size` and the `capacity == 1`
special case unchanged. The ghost queue's `with_capacity(main_size)` and all
downstream uses of `small_size`/`main_size` continue to read the new values
automatically. Preserve the capacity-bound invariant: `small_size +
main_size == capacity` must still hold by construction.

## Rationale (optional)

The S3-FIFO paper uses a ~10% small / ~90% main split, versus the baseline's
25/75. A larger main queue means hot items survive more second-chance passes
before eviction, and a smaller admission queue still filters one-hit-wonders
into the ghost queue. This is purely a sizing change, distinct from the
admission-threshold (H01) and ghost-depth (H03) strategies, so the cohort can
measure the partition ratio's effect in isolation.
