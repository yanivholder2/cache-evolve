# H03

Re-admitting main-evicted ghost hits with one second-chance credit (freq=1), while small-evicted ghost hits still re-admit at freq=0, raises hit-rate.

## Parent

cycle/0006/v002

## Changes

In the parent (`src/s3_fifo/mod.rs`), every ghost hit in `put` is re-admitted
to the main front identically via `Entry::new(key, value)`, which starts at
`freq == 0` — so a freshly re-admitted key is dropped on the very next
`evict_main` pass that reaches it before any reaccess can bump its freq.

Make re-admission protection conditional on ghost source:

1. Tag ghost records by origin (as in a source-aware ghost): change
   `ghost: VecDeque<K>` to hold `struct GhostKey<K> { key: K, from_main: bool }`.
   Push `from_main: true` from `evict_main`'s drop branch and
   `from_main: false` from `evict_small`'s demotion branch. Update the
   `in_ghost` scan and `retain` in `put` to use `ghost_key.key`.
2. In `put`'s in-ghost branch, capture the matched record's `from_main` flag
   before removing it. Construct the re-admitted entry with
   `freq = if from_main { 1 } else { 0 }` (add a small constructor like
   `Entry::with_freq(key, value, f)` or set `.freq` after `Entry::new`).
   Keep the existing `evict_main()`-if-full guard and `push_front`.

Do NOT warm-start small-evicted re-admissions (they stay freq 0 — prior cycles
proved warm-starting the weak population regresses). Leave the partition ratio,
move-to-front `get`, and the `evict_main` rotation unchanged. The single
behavioural change is that a re-admitted *main-evicted* key survives one
eviction pass before needing a reaccess.

## Rationale (optional)

Frequency warm-start on re-admission regressed in cycle 0004, but only over the
weak small-evicted population. This tests whether the strong main-evicted
population — already proven worth ghosting — additionally deserves a single
pass of eviction protection on return, a distinct lever from ghost depth or
retention priority.
