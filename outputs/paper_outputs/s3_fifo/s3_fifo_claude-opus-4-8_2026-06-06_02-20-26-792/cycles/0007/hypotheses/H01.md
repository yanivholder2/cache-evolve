# H01

Deepening the ghost queue beyond `main_size` raises hit-rate now that the stronger main-evicted population is ghosted.

## Parent

cycle/0006/v002

## Changes

In the parent (`src/s3_fifo/mod.rs`), the ghost queue is bounded by
`main_size` everywhere it is trimmed: `try_new` reserves
`VecDeque::with_capacity(main_size)`, and both `evict_main` and
`evict_small` pop the ghost tail when `self.ghost.len() >= self.main_size`.

Introduce a dedicated `ghost_size` field on `S3Fifo`, set it in `try_new`
to a deeper window than `main_size` — use `ghost_size = (main_size * 2).min(...)`
is not required; instead set `ghost_size = capacity` (i.e. roughly 2×
the current bound, since `main_size ≈ capacity·23/24`). Then replace the
two `>= self.main_size` ghost-trim comparisons in `evict_main` and
`evict_small` with `>= self.ghost_size`. Leave the `with_capacity` hint
alone or bump it to `ghost_size`.

Do not change the partition ratio (`small_size = (capacity/24)...`), the
move-to-front `get`, the `evict_main` rotation, or the direct-to-main
re-admission path in `put`. The only behavioural change is a longer ghost
history window, so that a main-evicted entry that cooled to `freq == 0`
survives in history long enough for a longer-gap reaccess to re-admit it
directly to main.

## Rationale (optional)

Prior cycles found ghost *depth* inert-to-harmful, but always over the weak
small-evicted one-hit-wonder population. The cycle-0006 winner proved the
main-evicted population is worth ghosting; this isolates whether depth — the
previously dead lever — becomes live now that history holds strong-reuse keys.
