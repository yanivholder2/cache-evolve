# H02

Warm-starting the frequency of ghost-readmitted entries so they survive a second-chance round in main raises hit-rate by protecting confirmed-reuse keys during their main residency.

## Parent

cycle/0003/v001

## Changes

This targets the second-chance/frequency mechanic — the other lever the
cross-cycle insights name as untried — while keeping the validated
direct-to-main re-admission path fully intact (no gating).

Today, when a ghosted key is re-accessed, the `in_ghost` branch of `put()`
inserts it via `Entry::new(key, value)`, which sets `freq = 0`. That means a
re-admitted key — despite being *proven* reuse evidence — is evicted on the very
first `evict_main()` pass that reaches it with `freq == 0`, no better protected
than a brand-new admission.

Change: in the `in_ghost` branch of `put()`, after removing the key from ghost
and (if needed) calling `evict_main()`, construct the entry and set its
frequency to a warm value before `push_front` into `main`. Concretely, build
the entry and assign `entry.freq = 1` (one second-chance round of protection;
must stay `<= MAX_FREQ`). Do this ONLY for the ghost re-admission path; keep
fresh small-queue admissions at `freq = 0` and keep small→main promotions
(`evict_small`, `freq > 1`) unchanged.

Leave `MAX_FREQ`, the `get()` increment, the `evict_main()` decrement loop, and
the partition ratio (`capacity / 24`) exactly as in the parent. Preserve the
capacity-bound, value-fidelity, and no-phantom invariants.

## Rationale (optional)

Raising the frequency *ceiling* was inert because hot keys already clear the
gate; this is different — it raises the *starting* frequency of exactly the
keys with the strongest reuse signal (a ghost hit), so they outlast one cohort
of FIFO churn instead of being dropped immediately on re-entry.
