# H03

Apply a periodic global frequency-aging sweep that halves every main entry's freq once per fixed access budget, so the eviction scan can reach keys that were hot under a stale hotset and raise hit-rate on the shifting LIRS workload.

## Parent

cycle/0004/v003

## Changes

Add a global aging mechanism orthogonal to eviction-time decay. Introduce a
`tick: usize` field on `S3Fifo` (initialise to 0 in `try_new`). Increment `tick`
once per call in `put()`. When `tick` reaches an aging budget — use `self.main_size`
as the budget (one sweep per roughly a full main turnover) — reset `tick` to 0 and
sweep every entry in `main`, replacing each `entry.freq` with `entry.freq >> 1`
(integer halving). Do not touch the small queue, the ghost queue, the
move-to-front main-hit path, or `evict_main`'s rotation.

Rationale: today `freq` only decays lazily during an `evict_main` rotation, so a
key that became very hot during one phase of the trace keeps a high `freq` and
stays sticky in main long after its hotset has moved on, blocking the second-chance
scan from reaching it. A periodic halving ages *all* residents uniformly so the
currently-cold-but-formerly-hot keys become reachable victims while genuinely hot
keys (still being reaccessed) quickly rebuild `freq` via the clamp. This is an
untouched mechanism: prior cycles tuned the partition, ghost, and ordering, but
never added time-based aging.

Invariants to preserve: `MAX_FREQ` clamp on bumps; capacity bound; the rotation in
`evict_main` and move-to-front in `get()` stay intact; halving must never panic
(use `>> 1`, which is safe for `u8`). Keep the budget tied to `main_size` so it
scales with capacity rather than being a hard-coded constant.
