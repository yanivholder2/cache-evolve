# H03

Routing ghost-queue hits back through the small queue with a one-step frequency head-start, instead of pushing them straight into main, raises hit-rate by gating long-gap reaccesses behind a re-confirmation before they can displace hot main residents.

## Parent

baseline

## Changes

In `put`, modify the `in_ghost` branch (currently: remove the key from
ghost, conditionally `evict_main`, then `self.main.push_front(Entry::new(key, value))`).
Replace the direct-to-main admission with admission into the small queue
carrying a freq head-start so a single subsequent reaccess promotes it:
after `self.ghost.retain(...)`, do `if self.small.len() >= self.small_size { self.evict_small(); }`,
construct an `Entry::new(key, value)`, set its `freq = 1`, and
`self.small.push_front(entry)`. Drop the `evict_main()` call and the
`main.push_front` from this branch entirely. Net effect: a ghost hit no
longer crowds main directly; it re-enters small at `freq = 1`, so its next
hit lifts `freq` to 2 and `evict_small` (gate `freq > 1`) graduates it to
main on the normal path. Keep `MAX_FREQ`, the baseline `capacity / 4`
partition, ghost sizing (`main_size`), and all other logic unchanged.
Preserve the capacity invariant — small never exceeds `small_size`.

## Rationale (optional)

Cycle 0001 found that every path feeding main directly (looser promotion in
v001, deep-ghost direct re-admission in v003) regressed because main is
contention-sensitive. This tests the insight's open question: gate the
direct-to-main re-admission path rather than widening history, re-admitting
reuse candidates via the small queue instead.
