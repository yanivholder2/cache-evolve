# H02

Seed ghost-hit re-admissions into the main queue with a non-zero frequency so reuse-proven keys survive the next main eviction pass, raising hit-rate.

## Parent

baseline

## Changes

In `put()` (src/s3_fifo/mod.rs), the `in_ghost` branch currently inserts
the re-admitted key via `self.main.push_front(Entry::new(key, value))`,
which starts the entry at `freq = 0` and leaves it immediately
vulnerable to `evict_main()`'s second-chance decrement. Change this
branch to construct the entry and set its `freq` to a protective initial
value (e.g. `1`, clamped to `MAX_FREQ`) before pushing it to the front
of `main` — for example build `let mut e = Entry::new(key, value);
e.freq = 1; self.main.push_front(e);`. Keep the ghost removal
(`self.ghost.retain(...)`) and the pre-eviction check
(`if self.main.len() >= self.main_size { self.evict_main(); }`) exactly
as they are so the capacity bound (P1) and value fidelity (P2) hold. A
ghost hit is strong evidence of reuse, so giving these entries one extra
second chance in the main queue should improve hit-rate without altering
the small-queue or metadata layout.
