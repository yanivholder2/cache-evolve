# H03

Shrink the small admission queue to ~10% of capacity (from 25%) so the main resident queue holds more reuse-proven items, raising hit-rate.

## Parent

baseline

## Changes

In `try_new()` (src/s3_fifo/mod.rs), change the `small_size` derivation
for the `capacity > 1` case from `(capacity / 4).max(1).min(capacity - 1)`
to a ~10% split: `(capacity / 10).max(1).min(capacity - 1)`. Keep the
`capacity == 1` special case (`small_size = 1`) and keep
`main_size = capacity - small_size` so the partition still sums to
exactly `capacity` and the P1 capacity bound holds. The `VecDeque`
preallocations and ghost sizing follow `main_size` automatically. This
mirrors the 10%/90% small/main ratio recommended in the S3-FIFO paper:
the small queue only needs to be large enough to filter one-hit-wonders,
and devoting the freed space to the main queue should retain more
frequently reused entries and lift hit-rate on workload-a. This is a
pure bucket-sizing change, orthogonal to the promotion-threshold (H01)
and ghost-seeding (H02) movement strategies.
