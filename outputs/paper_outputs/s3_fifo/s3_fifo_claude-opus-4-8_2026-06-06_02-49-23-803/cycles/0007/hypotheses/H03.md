# H03

Add a short dedicated `hot` queue scanned first in `get` so median hits resolve in a tiny segment instead of a full `main` walk, lowering get-p50 (per-op-time).

## Parent

cycle/0006/v002

## Changes

Where H02 reorders `main` in place, this introduces an explicit two-tier
resident structure so the common hot hit never touches `main` at all:

- Add a field `hot: VecDeque<Entry<K,V>>` to `S3Fifo` with capacity
  `hot_size = (main_size / 8).max(1)`, and reduce `main_size` by `hot_size` in
  `try_new` so total resident capacity (`small_size + hot_size + main_size`)
  still equals `capacity` — this keeps hit-rate ~neutral by holding the resident
  budget fixed.
- `get`/`find_entry_mut`: scan `hot.iter_mut()` first, then `main`, then `small`
  (extending v002's main-before-small order with hot-before-main). The median
  get, which lands on a hot key, now finds it after scanning only the short
  `hot` segment → get-p50 drops.
- Promotion into `hot`: in `get`, when an entry resident in `main` reaches
  `freq == MAX_FREQ`, remove it from `main` and `push_front` it onto `hot`. If
  `hot` is already at `hot_size`, demote its back entry (`hot.pop_back`) to the
  front of `main` first, so counts stay bounded.
- Eviction: keep `evict_small`/`evict_main`/ghost logic exactly as v002. `hot`
  holds only proven-saturated keys and is not an eviction source; because the
  resident budget was reduced from `main`, total occupancy is unchanged and the
  capacity invariant becomes `small.len() + hot.len() + main.len() <= capacity`.
- Keep the `Entry<K,V>` struct unchanged at 24 bytes (the new `hot` field grows
  only the unscored `S3Fifo` container, not the scored `Entry`).

Update the in-module `#[cfg(test)]` tests for the new capacity invariant and the
hot-segment promotion path.

## Rationale (optional)

A segmented hot front-queue gives the median hit a bounded short scan (length
`hot_size`) regardless of how large `main` grows, which is a different mechanism
than H01 (hash index) or H02 (in-place main reorder). Risk is confined to
get-p50 (target) and a small hit-rate perturbation from reserving `hot_size`
slots, mitigated by taking that budget out of `main` rather than adding capacity.
