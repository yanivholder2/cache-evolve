# H02

Stacking the proven-reuse freq-ceiling raise (`MAX_FREQ` 3 to 7) on top of v001's narrow `capacity / 16` split lifts hit-rate further, confirming retention durability and capacity reallocation are orthogonal levers.

## Parent

cycle/0002/v001

## Changes

Change the module constant `MAX_FREQ` from `3` to `7`, keeping v001's
`small_size = (capacity / 16).max(1).min(capacity - 1)` split exactly as-is.
The `get` path already clamps with `.min(MAX_FREQ)`, so raising the ceiling
lets the highest-reuse main entries bank more second chances and survive extra
`evict_main` decrement passes. Preserve the load-bearing strict thresholds
untouched: the `freq > 1` promotion test in `evict_small` and the `freq > 0`
second-chance / `freq = 0` ghost re-admission logic in `evict_main` must not
change. Do not add struct fields (keep metadata-size at 24).

## Rationale (optional)

The freq-ceiling lever gave a small real gain in isolation (cycle/0002/v003),
and the cycle-0002 insight explicitly asks whether it still helps *combined*
with the narrow split, or whether the two interfere the way split and ghost
did. This directly tests that orthogonality question on the best-so-far parent.
