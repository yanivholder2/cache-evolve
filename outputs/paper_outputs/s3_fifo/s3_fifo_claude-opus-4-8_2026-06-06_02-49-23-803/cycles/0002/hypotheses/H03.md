# H03

Raising the frequency ceiling (MAX_FREQ from 3 to 7) lets genuinely hot main entries bank more second chances and survive eviction longer, raising hit-rate without loosening the promotion filter.

## Parent

baseline

## Changes

In src/s3_fifo/mod.rs change the `const MAX_FREQ: u8 = 3;` to
`const MAX_FREQ: u8 = 7;`. This only raises the cap that `get` saturates
`entry.freq` toward; it leaves the strict `freq > 1` small-to-main
promotion rule and the `freq = 0` ghost re-admission untouched, so weakly-
reused one-touch items are still filtered exactly as in the baseline. The
effect is concentrated in `evict_main`, where its second-chance loop
decrements `freq` once per pass: a higher ceiling means a key that has
earned many real `get` hits needs more eviction passes before it can be
discarded, proportionally rewarding actual reuse rather than handing a
blanket extra chance to lightly-touched entries (the move that hurt in
v002). Preserve all queue sizing and the small/main split unchanged.

## Rationale (optional)

The cycle warned against making main stickier for *weakly*-reused items.
This change is the opposite: it raises durability only for entries with
demonstrated high reuse, while keeping the load-bearing strict promotion
and ghost thresholds. It is a distinct retention-shape lever, not a
capacity reallocation, so it explores orthogonally to H01/H02.
