# H02

Enlarging the ghost queue beyond `main_size` widens the reuse-distance detection window, promoting more genuinely-reused keys back into main and raising hit-rate.

## Parent

cycle/0001/v003

## Changes

In src/s3_fifo/mod.rs the ghost queue is currently capped at `main_size`:
`VecDeque::with_capacity(main_size)` in `try_new`, and the bound check
`if self.ghost.len() >= self.main_size { self.ghost.pop_back(); }` in
`evict_small`. Decouple ghost capacity from `main_size` by adding a new
`ghost_size` field to `S3Fifo`, set it to `main_size * 2` in `try_new`
(clamped to at least 1), allocate the ghost `VecDeque` with that capacity,
and change the eviction bound to compare against `self.ghost_size` instead
of `self.main_size`. Keep v003's `capacity / 10` small/main split and all
promotion/eviction thresholds exactly as they are. Ghost stores only keys,
so this does not change `Entry`/`S3Fifo` metadata-size of resident
entries; it only lengthens how far back a re-access can still be recognized
as reuse-proven.

## Rationale (optional)

Ghost sizing is a capacity-allocation knob the cycle insight flagged but
nobody has tested. A wider ghost catches longer reuse distances, and
because ghost holds keys only it should not hurt the metadata-size
dimension. Stacking it on the winner (v003) also probes whether split and
ghost knobs are orthogonal.
