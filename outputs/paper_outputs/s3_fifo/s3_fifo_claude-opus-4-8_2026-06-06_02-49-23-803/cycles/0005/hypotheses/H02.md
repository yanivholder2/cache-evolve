# H02

Seeding ghost-readmitted keys with frequency 1 (instead of 0) protects demonstrated near-reuse through one extra main second-chance pass and raises hit-rate.

## Parent

cycle/0004/v001

## Changes

In `put()`, on the `in_ghost` branch, replace the
`self.main.push_front(Entry::new(key, value))` re-admission with an
entry whose `freq` starts at 1 rather than 0 (construct the `Entry`
normally, then set `freq = 1` before pushing, so the struct layout is
unchanged). A ghost hit is by definition a proven near-reuse — the key
was demoted and then requested again — so it earns one guaranteed
survival of the `evict_main()` second-chance decrement, exactly like a
graduated small-queue entry that carries its earned frequency. Do NOT
change the admission filter: keep `freq > 1` graduation, `freq == 0`
demotion, `small_size = capacity / 32`, `MAX_FREQ = 3`, and the ghost
cap at `(main_size / 2).max(1)`. Only the seed frequency of
re-admitted ghost keys changes.

## Rationale (optional)

Cross-cycle insight says rewarding *demonstrated* reuse helps and is
orthogonal to the split, while loosening the admission filter hurts.
This rewards an already-proven key without loosening any filter — a
previously untested cell of the durability axis. The asymmetry it fixes:
graduated keys preserve their freq into main, but re-admitted ghost keys
currently reset to 0.
