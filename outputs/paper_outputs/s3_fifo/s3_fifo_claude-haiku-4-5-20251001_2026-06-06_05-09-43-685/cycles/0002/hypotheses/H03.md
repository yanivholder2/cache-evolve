# H03

Defer main-queue eviction when queue occupancy is below 90% in v001 to extend item lifetime and recover hit-rate without sacrificing latency on bursty workloads.

## Parent

cycle/0001/v001

## Changes

In `src/s3_fifo/mod.rs`, modify the `evict_main()` function to implement lazy eviction. Before the main eviction loop, check if `self.main.len() < self.main_size * 9 / 10` (below 90% capacity). If true, return immediately without evicting. If at or above 90%, proceed with the existing frequency-decrement logic. This makes main-queue eviction adaptive, deferring costly evictions when spare capacity exists.

## Rationale

v001 achieves latency through strict admission filtering, not aggressive main-queue eviction. The current evict_main() always decrements frequency on overflow. By deferring eviction when main queue has spare capacity (below 90%), we retain more candidate items for future hits without forcing evictions from a queue that isn't full. This targets hit-rate recovery (items persist longer in main queue) while preserving v001's latency benefits since we avoid unnecessary evictions. Trade-off: When main queue reaches capacity, the deferred items will cascade, requiring larger evictions; this is acceptable since it only happens under true contention.
