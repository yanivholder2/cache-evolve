# H02

Replace v006/v002's fixed ghost re-admission boost with an occupancy-responsive formula to scale re-access aggressiveness with main-queue load and recover hit-rate.

## Parent

cycle/0006/v002

## Changes

In `src/s3_fifo/mod.rs`, modify the ghost re-admission logic in `put()` to use an occupancy-scaled boost formula instead of the fixed value:

1. Keep the ghost structure as `VecDeque<(K, i8)>` unchanged (v006/v002's design).

2. Keep the eviction logic for both `evict_main()` and `evict_small()` unchanged:
   - Items decay by 1 frequency level when moving to ghost
   - Discard items when `ghost_freq < -2`
   - This preserves the efficient decay pipeline v006/v002 established

3. In `put()`, when a ghost hit is detected, replace the fixed boost formula with occupancy-responsive logic:
   ```
   let occupancy_ratio = self.main.len() as f64 / self.main_size as f64;
   let boost = 2 + (occupancy_ratio * 2.0).floor() as i8;
   let boosted_freq = (ghost_freq + boost).max(0) as u8;
   let freq = boosted_freq.min(MAX_FREQ);
   ```
   - At occupancy 0.0 (empty main queue): boost = 2 (conservative)
   - At occupancy 0.5 (half full): boost = 3 (moderate)
   - At occupancy 1.0 (full main queue): boost = 4 (aggressive)

4. When creating the re-admitted entry, use the computed `freq` from the formula above.

5. Keep all other logic from v006/v002 intact: ghost frequency decay rates, discard thresholds, and main-queue eviction behavior.

This directly addresses the open question from cycle 0006: whether adaptive re-admission formulas can preserve v006/v002's latency breakthrough (49% faster puts) while tuning hit-rate closer to the baseline by scaling re-access opportunities with available main-queue capacity.

## Rationale

v006/v002's fixed `ghost_freq + 3` boost overshoots during load phases and undershoots during underutilized periods, corrupting the hit-rate signal. By tying boost magnitude to main-queue occupancy, we give items stronger re-access chances when the main queue has spare capacity (likely to be retained), and weaker chances when contending for space (more selective). This adaptive scaling preserves the architectural breakthrough v006/v002 demonstrated (dramatic latency gains from pre-computed ghost state) while recovering hit-rate from 0.7074 toward 0.7222.
