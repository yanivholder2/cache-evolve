# H03

Implement age-aware promotion thresholds that tighten for items near eviction from small queue to prevent frequency-starvation.

## Parent

cycle/0001/v001

## Changes

In `src/s3_fifo/mod.rs`, modify `evict_small()` to use a promotion threshold that depends on the item's position (age) within the small queue:

1. In `evict_small()`, before the promotion decision, compute the item's relative age:
   - `age_ratio = self.small.len() as f64 / self.current_small_size as f64`
   - This ranges from 1.0 (item at front, just entered) to approaching 0.0 (item at back, about to evict)

2. Use a variable promotion threshold based on age:
   - If `age_ratio <= 0.3` (item is in the back 30% of small queue): use `threshold = 1` (looser: freq > 1 promotes)
   - Otherwise: use `threshold = 2` (standard: freq > 2 promotes)

3. Apply the threshold: `if tail.freq > threshold { promote } else { to_ghost }`

4. Keep all other logic from the parent (v001's fixed `freq > 2` threshold in general flow, but override in this specific aging case).

5. When expanding small queue (if parent has resizing logic), preserve current sizing behavior.

This creates a "graduation pressure curve" where items that are about to age out of the small queue can promote with lower frequency, preventing the cold-streak pattern where an item with freq=1 gets evicted to ghost before accumulating the freq=2 needed for main-queue graduation.

## Rationale

Across all cycles, admission filtering via frequency thresholds consistently improves latency but costs hit-rate because items with freq=1 are evicted from small queue to ghost without graduation opportunity. This fundamentally different mechanism (threshold-per-age, not threshold-per-occupancy) targets the timing constraint: items that have waited long in small queue but haven't yet reached freq=2 are given a second promotion chance. The boost is minimal (only at age_ratio ≤ 0.3) to preserve latency gains. Expected outcome: improved hit-rate (targeting 0.720+) by preventing frequency-starvation, while maintaining the latency advantage v001 achieved (per-op-time near or under 140 ns), since age-aware logic adds minimal overhead—just a positional check at eviction time.
