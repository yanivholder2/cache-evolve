# H01

Relax selective ghost-queue filtering from freq > 0 to freq >= -1 to recover hit-rate lost to excessive signal purity while retaining latency gains.

## Parent

cycle/0008/v001

## Changes

Modify the ghost-queue population logic in both `evict_small()` and the occupancy-gated small-queue adjustment (lines 160-180 in cycle 0008 v001) to lower the bar for adding items to ghost. Currently, items are only added to ghost if `tail.freq > 0`, which is too selective. Instead, always add items to ghost by computing `ghost_freq = (tail.freq as i8) - 1` and retaining them if `ghost_freq >= -1` (instead of the current `ghost_freq >= -2` threshold). This change preserves items with `freq=0` (which map to `ghost_freq=-1`) and allows them one re-admission chance, recovering the hit-rate candidates discarded by v001's pure-signal-fidelity strategy while maintaining the zero-hot-path-overhead architecture of frequency-based ghost filtering at eviction time.

## Rationale

Cycle 0008/v001 achieved dramatic put-latency improvement (63% faster) through aggressive ghost-queue filtering but sacrificed 0.61% hit-rate by excluding freq=0 items that might re-access. The cycle 0008 insight explicitly raises this question: "Can v001's ghost-admission threshold be relaxed (e.g., freq >= -1 instead of freq > 0) to recover lost hit-rate candidates while retaining most of the latency benefit?" This hypothesis directly tests that trade-off boundary, moving from pure-frequency-only admission to a slightly more inclusive diversity model without reintroducing per-operation overhead.
