# H02

Lowering the small-to-main promotion threshold from two accesses to one (any hit while in the small queue qualifies) raises hit rate by keeping re-accessed entries in the resident set rather than ghosting them.

## Parent

baseline

## Changes

In `evict_small()` in `src/s3_fifo/mod.rs`, change the promotion condition from

```rust
if tail.freq > 1 {
```

to

```rust
if tail.freq > 0 {
```

This is the only change. With the baseline threshold (`> 1`), an entry that received exactly one access while in the small queue (freq == 1) is ghosted rather than promoted. The new threshold (`> 0`) promotes any entry that was accessed at least once, reserving ghosting only for entries that arrived cold and were never touched. All other invariants — ghost overflow trimming, main-queue second-chance eviction, `MAX_FREQ` cap, ghost-hit promotion path — remain identical.

## Rationale

For the LIRS workload-a trace, items with a single re-access while queued in small are meaningful signal: they represent one reuse within the admission window. The baseline throws that signal away by ghosting them. Promoting at freq > 0 retains those items in the resident set. The cost is a higher pressure on main, but main's second-chance eviction already handles overflow gracefully by preferring zero-frequency victims.
