# H03

Doubling the ghost queue's capacity allows more recently evicted keys to be tracked, increasing the fraction of re-accesses that trigger direct promotion into the main queue and raising hit rate.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, make the following three targeted edits:

1. **Add a `ghost_size` field** to the `S3Fifo` struct:

```rust
pub struct S3Fifo<K: PartialEq + Clone, V> {
    small: VecDeque<Entry<K, V>>,
    main: VecDeque<Entry<K, V>>,
    ghost: VecDeque<K>,
    small_size: usize,
    main_size: usize,
    ghost_size: usize,   // <-- new field
}
```

2. **Compute and store `ghost_size`** in `try_new()`, replacing the inline `main_size` used for ghost capacity:

```rust
let ghost_size = main_size * 2;
Some(Self {
    small: VecDeque::with_capacity(small_size),
    main: VecDeque::with_capacity(main_size),
    ghost: VecDeque::with_capacity(ghost_size),
    small_size,
    main_size,
    ghost_size,
})
```

3. **Update the ghost overflow guard** in `evict_small()` to use `self.ghost_size` instead of `self.main_size`:

```rust
if self.ghost.len() >= self.ghost_size {
    self.ghost.pop_back();
}
```

No other logic changes. The ghost queue still stores only keys (no values), ghost-hit promotion into main is unchanged, and all capacity invariants for `small` and `main` are preserved.

## Rationale

The baseline caps the ghost queue at `main_size` (1536 for a 2048-slot cache). When the ghost overflows, older evicted keys are dropped, losing re-access signal. For the LIRS workload-a trace — which has bursty, phase-changing access patterns — evicted items often re-appear after a burst of other accesses. Doubling the ghost window (to 3072 keys for the same cache) means those re-accesses are more likely to find a ghost entry and get promoted directly into main with no further small-queue admission overhead.
