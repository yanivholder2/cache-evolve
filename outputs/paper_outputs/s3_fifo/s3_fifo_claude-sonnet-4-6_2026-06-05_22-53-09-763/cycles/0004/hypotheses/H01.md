# H01

Raising MAX_FREQ from 3 to 4 on top of cycle/0002/v003's ghost-precision configuration will improve hit rate by granting the hottest main-queue items one additional second-chance credit before eviction.

## Parent

cycle/0002/v003

## Changes

In `src/s3_fifo/mod.rs`, change the top-level constant at the top of the file from:

```rust
const MAX_FREQ: u8 = 3;
```

to:

```rust
const MAX_FREQ: u8 = 4;
```

No other changes are required. The `get()` path (which increments `entry.freq` up to the saturation ceiling via `.min(MAX_FREQ)` or equivalent saturating arithmetic) and the `evict_from_main()` second-chance path (which decrements `freq` for items with `freq > 0` and re-queues them at the head) both consume MAX_FREQ solely as a ceiling constant, so changing only this value adjusts the entire second-chance budget throughout.

Keep all other logic from the v003 overlay intact:
- `ghost_size = (main_size / 2).max(1)` and the `ghost_size` struct field
- `small_size = (capacity / 10).max(1).min(capacity - 1)` (10% of capacity)
- Small-queue promotion threshold remains `tail.freq > 1`
- All existing tests from the v003 overlay are preserved unchanged

## Rationale

Cross-cycle analysis identifies MAX_FREQ elevation as the highest-priority unexplored axis. v003 holds the best-known hit rate (0.7272) by combining the baseline structure with ghost precision at `main_size/2`; the one remaining unprobed knob on that configuration is the eviction ceiling. Items whose hot phase spans more than three access cycles currently exhaust their second-chance credits prematurely — raising the ceiling from 3 to 4 directly tests whether additional retention yields measurable re-use on this workload, without touching any other structural parameter.
