# H01

Raising MAX_FREQ from 4 to 5 in the cycle/0004/v001 configuration will further improve hit rate by extending second-chance retention for the hottest items whose frequency genuinely reaches the current ceiling.

## Parent

cycle/0004/v001

## Changes

In `src/s3_fifo/mod.rs`, change the single constant declaration:

```
const MAX_FREQ: u8 = 4;
```

to:

```
const MAX_FREQ: u8 = 5;
```

No other code changes. All other parameters inherited from cycle/0004/v001 remain identical: `small_size = capacity / 10`, `ghost_size = main_size / 2`, promotion threshold `tail.freq > 1` in `evict_small()`, and ghost re-admission at `freq = 0` via `Entry::new()`. The `get()` saturation clamp `(entry.freq.saturating_add(1)).min(MAX_FREQ)` and the `evict_main()` reprieve condition `tail.freq > 0` both reference the constant and will automatically pick up the new ceiling.

## Rationale

The 3→4 step yielded a real but small gain (0.727→0.728), suggesting a non-trivial hot-set tail reaches the ceiling. The 4→5 step probes whether this tail extends further or whether the distribution truncates sharply at 4. Low expectations are warranted per the cycle-0004 insight, but this is the last unprobed point on the sizing axis before declaring it exhausted.
