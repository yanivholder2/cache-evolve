# H01

Eagerly migrating small-queue items to main the moment their frequency crosses the promotion threshold raises hit rate by shortening the time newly-warm items spend in the vulnerable small queue.

## Parent

cycle/0006/v001

## Changes

Modify `get()` to search small and main as separate passes rather than via a chained iterator, so that small-queue items can be eagerly relocated.

In the small-queue search branch, after computing `new_freq = (entry.freq.saturating_add(1)).min(MAX_FREQ)`, check whether `new_freq >= 2` (i.e., the item has just crossed or already sits at the promotion threshold). If so:

1. Record the index via `self.small.iter().position(|e| &e.key == key)`.
2. Set `self.small[pos].freq = new_freq`.
3. Remove the entry with `self.main.remove(pos)` — wait, use `self.small.remove(pos)` to extract the `Entry`.
4. If `self.main.len() >= self.main_size`, call `self.evict_main()` to make room.
5. Push the entry to the front of main with `self.main.push_front(entry)`.
6. Return a reference to `self.main.front().map(|e| &e.value)`.

If `new_freq < 2`, update freq in place and return the value reference without relocating.

For the main-queue branch, keep the existing in-place increment logic unchanged.

The `evict_small()` promotion branch (`if tail.freq > 1 { ... main.push_front(tail) }`) remains as a fallback for items that were never accessed via `get()` while in small queue — it will fire rarely once eager promotion is active, but must be preserved for correctness.

All other v001 parameters are unchanged: `small_size = capacity / 10`, `ghost_size = main_size / 2`, `MAX_FREQ = 5`, and the `freq > 1` second-chance gate in `evict_main`.

## Rationale

In the current code, an item promoted by `evict_small()` may have been sitting in the small queue for several insertions after it first reached `freq >= 2`, remaining vulnerable to being shadowed by the ghost mechanism or simply consuming a small-queue slot that could have admitted a new item sooner. Eager promotion eliminates that lag: the first `get()` that pushes the item across the threshold moves it immediately to the protected main queue, freeing the small slot at that instant. The workload-a trace is Zipfian, so the items that accumulate freq quickly in small are precisely the hot-set items most worth protecting early.
