# H02

Stacking unconditional move-to-front on main-queue hits onto the cycle/0008/v002 configuration combines the confirmed recency-refresh gain from v003 with v002's proven queue-sizing improvement, yielding an additive hit-rate advance over either feature in isolation.

## Parent

cycle/0008/v002

## Changes

In the `get()` method, replace the in-place frequency increment for main-queue hits with a position-extract-then-push_front sequence, identical to the approach implemented in cycle/0008/v003 but applied to v002's codebase (which uses `capacity / 14` in `try_new()`).

Change the main-queue lookup block from:

```rust
// --- main queue: in-place increment, no relocation ---
if let Some(entry) = self.main.iter_mut().find(|e| &e.key == key) {
    entry.freq = (entry.freq.saturating_add(1)).min(MAX_FREQ);
    return Some(&entry.value);
}
```

to:

```rust
// --- main queue: freq increment + move-to-front ---
if let Some(pos) = self.main.iter().position(|e| &e.key == key) {
    self.main[pos].freq = (self.main[pos].freq.saturating_add(1)).min(MAX_FREQ);
    let entry = self.main.remove(pos).unwrap();
    self.main.push_front(entry);
    return self.main.front().map(|e| &e.value);
}
```

All other logic stays identical to cycle/0008/v002 — `capacity / 14` small queue, eager promotion at freq >= 2 in the small-queue path of `get()`, `freq > 1` eviction threshold in `evict_main()`, ghost cap at `main_size / 2`, and MAX_FREQ = 5. Update the comment block at the top of the file to describe both H01 (eager promotion, carried from cycle 0007) and the new MTF behaviour.

The hypothesis is that the two gains are independent: queue-sizing improves resident quality by reducing cold-item admission, while MTF prevents hot residents from silently drifting to the eviction frontier between accesses. If additive, the combined variant should outperform both v002 (no MTF) and v003 (larger small queue with MTF).
