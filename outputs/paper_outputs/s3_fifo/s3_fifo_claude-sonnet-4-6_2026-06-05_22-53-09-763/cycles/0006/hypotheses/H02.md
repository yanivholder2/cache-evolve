# H02

Moving a main-queue item to the front of `main` the instant its frequency first reaches `MAX_FREQ` during a `get()` call will improve hit rate by proactively pinning the absolute hottest items away from the eviction frontier rather than waiting for the eviction scan to eventually reach and reposition them.

## Parent

cycle/0005/v001

## Changes

Refactor `get()` to search `small` and `main` separately so that main-queue hits can trigger conditional repositioning. The new implementation replaces the chained `small.iter_mut().chain(main.iter_mut()).find(...)` with two sequential searches:

1. Search `self.small` first. If found: increment freq (clamped to `MAX_FREQ`), return the value. Behavior identical to current.

2. Search `self.main` using `self.main.iter().position(|e| &e.key == key)` to obtain the index `pos`. If found:
   - If `self.main[pos].freq < MAX_FREQ - 1`: increment freq in place, return value without repositioning.
   - If `self.main[pos].freq == MAX_FREQ - 1` (i.e., incrementing will reach the ceiling) **and** `pos != 0`: increment freq to `MAX_FREQ`, then physically relocate: `let entry = self.main.remove(pos).unwrap(); self.main.push_front(entry);`. Return the value via `self.main.front().map(|e| &e.value)`.
   - If `self.main[pos].freq == MAX_FREQ` already (saturated): increment with `min` clamp (stays at `MAX_FREQ`), no repositioning.

3. If neither queue contains the key: return `None`.

Repositioning triggers exactly once per item — on the access that first saturates its counter — not on every subsequent access. This avoids churning hot items on every hit while still pulling them to safety when they become maximally hot.

All other methods (`put`, `evict_main`, `evict_small`, ghost handling) and all configuration values (`MAX_FREQ=5`, `small_size=capacity/10`, `ghost_size=main_size/2`) remain identical to cycle/0005/v001.

Rationale: Currently, a maximally-hot item in the middle of `main` can drift toward the eviction tail if it receives no accesses during a long eviction scan. Proactive repositioning on max-freq saturation ensures such items are immediately pulled to the head, where eviction pressure cannot reach them until the entire queue drains ahead of them.
