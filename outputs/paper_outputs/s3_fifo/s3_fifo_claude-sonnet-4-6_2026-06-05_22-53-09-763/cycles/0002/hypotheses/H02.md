# H02

Capping the ghost queue at half of `main_size` (`main_size / 2`) sharpens re-access signal precision and raises hit rate by eliminating noise from distant, non-recurring evictions.

## Parent

baseline

## Changes

Make three targeted edits to `src/s3_fifo/mod.rs`:

1. Add a `ghost_size` field to the `S3Fifo` struct:

```rust
pub struct S3Fifo<K: PartialEq + Clone, V> {
    small: VecDeque<Entry<K, V>>,
    main: VecDeque<Entry<K, V>>,
    ghost: VecDeque<K>,
    small_size: usize,
    main_size: usize,
    ghost_size: usize,   // new field
}
```

2. In `try_new()`, compute `ghost_size` as half of `main_size` and wire it into construction:

```rust
let ghost_size = (main_size / 2).max(1);
Some(Self {
    small: VecDeque::with_capacity(small_size),
    main: VecDeque::with_capacity(main_size),
    ghost: VecDeque::with_capacity(ghost_size),
    small_size,
    main_size,
    ghost_size,
})
```

3. In `evict_small()`, replace the overflow guard from `self.main_size` to `self.ghost_size`:

```rust
if self.ghost.len() >= self.ghost_size {
    self.ghost.pop_back();
}
```

The small queue stays at baseline (`capacity / 4`). The promotion threshold (`freq > 1`) and all remaining logic are unchanged. For a 2048-slot cache this shrinks the ghost window from 1536 keys to 768 keys.

## Rationale

Cycle 0001's v003 showed that doubling the ghost window (1536→3072) degraded hit rate because the extended history captured distant re-accesses — single appearances of long-ago evicted keys — that are noise for workload-a's LIRS trace. The cross-cycle insight stated that "precision of ghost tracking matters more than coverage." This hypothesis tests the opposite extreme from v003: halving the baseline ghost window to 768 keys keeps only very recent evictions in view, so every ghost hit corresponds to a key evicted within the last ~768 insertions. If the workload's re-use distance is shorter than the baseline window, removing the tail of the ghost queue strips out the noise without losing any true re-access signal.
