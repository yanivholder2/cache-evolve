# H03

Reducing MAX_FREQ from 3 to 2 on the baseline configuration accelerates second-chance aging in the main queue and raises hit rate by preventing cold items from accumulating excessive frequency credit that delays their eviction.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, change the constant at the top of the file from:

```rust
const MAX_FREQ: u8 = 3;
```

to:

```rust
const MAX_FREQ: u8 = 2;
```

This is the only edit. The `get()` method already clamps via `(entry.freq.saturating_add(1)).min(MAX_FREQ)` and the `evict_main()` loop already decrements and checks `freq > 0` — both automatically use the new constant without further changes. All other baseline settings remain intact: `small_size = capacity / 4`, ghost cap at `main_size`, promotion threshold `freq > 1`.

With MAX_FREQ = 2, main-queue entries can accumulate at most 2 frequency credits instead of 3, so each item cycles through at most two second-chance passes before eviction. Items in the main queue that are accessed moderately (but not frequently) age out in two passes instead of three, freeing resident slots sooner for newly promoted items. The `evict_small()` promotion guard (`freq > 1`) is unchanged and continues to require at least two hits in small before promotion.

## Rationale

MAX_FREQ = 3 has never been altered across any cycle; it is a completely unexplored axis. The second-chance mechanism in `evict_main()` is the sole retention barrier in main: an item with freq=3 survives up to three eviction passes before finally being displaced. For workload-a's LIRS trace — which has been shown to benefit from tight eviction windows (shrinking ghost, shrinking small) — items that reach freq=3 may be over-retained at the cost of newer, genuinely hot items. Reducing the ceiling to 2 tests whether the current credit cap is too generous: if the workload's hot set turns over faster than three eviction cycles, a tighter cap should improve hit rate; if it is genuinely sticky, the cap reduction will hurt and expose the lower bound. This probes a structural parameter no prior cycle has touched, keeping the experiment orthogonal to the queue-sizing and promotion-threshold changes explored in H01 and H02.
