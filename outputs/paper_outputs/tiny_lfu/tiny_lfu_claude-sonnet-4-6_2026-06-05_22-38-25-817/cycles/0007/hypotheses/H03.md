# H03

Replacing sequential row-index seeds (0, 1, 2, 3) with diverse fixed-constant seeds in the CountMinSketch hash function reduces correlated collisions across rows, tightening the minimum frequency estimate to raise hit rate.

## Parent

cycle/0006/v002

## Changes

In `src/tiny_lfu/mod.rs`, add a new module-level constant array of four well-separated
u64 seeds, one per sketch row:

```rust
const HASH_SEEDS: [u64; SKETCH_DEPTH] = [
    0x9e3779b97f4a7c15,  // Knuth multiplicative / golden-ratio constant
    0x6c62272e07bb0142,  // FNV-1a prime-derived constant
    0x517cc1b727220a95,  // large prime used in splitmix32
    0xbf58476d1ce4e5b9,  // splitmix64 first mixing step constant
];
```

Modify the `position()` helper to accept a `row: usize` argument (replacing
`seed: u64`) and look up the corresponding constant:

```rust
fn position<K: Hash>(&self, key: &K, row: usize) -> usize {
    let mut hasher = DefaultHasher::new();
    hasher.write_u64(HASH_SEEDS[row]);
    key.hash(&mut hasher);
    (hasher.finish() as usize) & (self.width - 1)
}
```

Update both callers to pass `row` instead of `row as u64`:

- In `increment()`: change `let pos = self.position(key, row as u64);` to
  `let pos = self.position(key, row);`.
- In `estimate()`: change `.map(|(row, _)| self.counts[row][self.position(key, row as u64)])`
  to `.map(|(row, _)| self.counts[row][self.position(key, row)])`.

`SKETCH_DEPTH` remains 4, so `HASH_SEEDS[row]` is always in-bounds.  All other
logic inherited from cycle/0006/v002 is preserved unchanged: conservative update
in `increment()`, `PROMO_THRESHOLD=8` with `was_protected` bypass, k=4 victim
scan, 90/10 split.

## Rationale

The current `position()` uses the row index itself (0, 1, 2, 3) as the seed
written before the key.  Because the seed values are small sequential integers,
keys with similar internal hash structure can produce correlated positions across
multiple rows — both hashing to the same column in row 0 and to the same column
in row 1.  When two keys collide in every row their estimates contaminate each
other equally across all rows, and the minimum-based estimate provides no benefit
over any single row.  Using four diverse, well-separated seed constants from
established hash-mixing sequences breaks this correlation: keys that collide under
one seed are very unlikely to collide under a structurally different seed,
restoring the independence assumption the CMS minimum estimator depends on.  This
is orthogonal to both conservative update (which limits per-collision inflation)
and sketch width (which reduces collision probability); it targets the case where
collisions, if they do occur, cluster across all rows simultaneously.
