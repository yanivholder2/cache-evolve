# H02

Adding a fixed-size ghost set of recently evicted key hashes and admitting ghost-set hits directly to the protected segment will increase hit rate above the baseline by eliminating the probationary staging delay for hot items that were recently evicted under memory pressure.

## Parent

baseline

## Changes

The baseline is a single-segment LRU with TinyLFU admission; this hypothesis builds a new SLRU-plus-ghost-cache variant from scratch rather than layering on an existing SLRU variant, to avoid interaction effects with the 90/10 split already tested.

**Data structures to add to `TinyLfuCache`:**
- `ghost: Vec<u64>` — a ring buffer of raw key hashes, length `capacity / 8` (minimum 4). Represents the most recently evicted items.
- `ghost_head: usize` — ring-buffer write pointer (index into `ghost`), wraps around modulo `ghost.len()`.

**Ghost-set helpers (new private methods):**
```
fn ghost_insert<K: Hash>(&mut self, key: &K) {
    let h = self.hash_key(key);
    self.ghost[self.ghost_head] = h;
    self.ghost_head = (self.ghost_head + 1) % self.ghost.len();
}

fn ghost_contains<K: Hash>(&self, key: &K) -> bool {
    let h = self.hash_key(key);
    self.ghost.iter().any(|&g| g == h)
}

fn hash_key<K: Hash>(&self, key: &K) -> u64 {
    use std::hash::Hasher;
    let mut hasher = std::collections::hash_map::DefaultHasher::new();
    key.hash(&mut hasher);
    hasher.finish()
}
```

**SLRU structure:** Use the same 80/20 split as the baseline's cycle/0001/v003 parent (protected = 80 % of capacity, probationary = 20 %). The `Node` struct retains the `in_protected: bool` field.

**Eviction path change in `put()`:** When a victim is evicted (the `incoming_freq > victim_freq` branch), before removing the victim, call `self.ghost_insert(&victim_key)` to record the evicted key's hash in the ring buffer.

**Admission path change in `put()`:** After the victim is selected and the incoming item passes the admission gate (`incoming_freq > victim_freq`), check `self.ghost_contains(&key)`:
- If `true`: place the incoming item directly into the protected segment (`prot_push_back`, set `in_protected = true`, increment `protected_len`). If `protected_len` then exceeds `protected_capacity`, demote `prot_head` to probationary as usual.
- If `false`: place the incoming item into probationary as normal (`prob_push_back`, `in_protected = false`, increment `probationary_len`).

Also ghost-admit items inserted into a not-yet-full arena: when `nodes.len() < capacity`, check `ghost_contains`; if true, place in protected instead of probationary (applying the same overflow demotion logic if needed).

**`get()` promotion:** No change from the standard SLRU `get()` logic (probationary → protected on any access, protected → MRU within protected).

**`try_new()`:** Initialize `ghost` as `vec![u64::MAX; (capacity / 8).max(4)]` and `ghost_head` as `0`. The `u64::MAX` sentinel ensures empty slots do not spuriously match real key hashes.

No changes to `CountMinSketch`.
