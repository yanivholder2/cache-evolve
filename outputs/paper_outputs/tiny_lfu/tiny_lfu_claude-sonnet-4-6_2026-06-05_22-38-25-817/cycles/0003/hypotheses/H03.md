# H03

Raising the probationary-to-protected promotion threshold to 8 and pairing it with immediate re-promotion for items that carry a `was_protected` flag will increase hit rate above cycle/0002/v001 by suppressing protected-segment churn from borderline-hot items while preserving zero-delay re-entry for confirmed-hot items displaced by overflow.

## Parent

cycle/0002/v001

## Changes

Start from cycle/0002/v001 (90/10 SLRU split, no sketch aging, unconditional promotion on any probationary access).

**1. Add `was_protected: bool` to `Node`:**

```rust
struct Node<K, V> {
    key: K,
    value: V,
    prev: Option<usize>,
    next: Option<usize>,
    in_protected: bool,
    was_protected: bool,   // NEW: set when demoted from protected → probationary
}
```

Initialize `was_protected: false` in both the arena-allocation path (`nodes.push(Node { ... })`) and the victim-recycling path in `put()`.

**2. Set `was_protected` on demotion:**

In `get()`, in the block that demotes `prot_head` to probationary when `protected_len > protected_capacity`:

```rust
let demote_idx = self.prot_head.expect("...");
self.prot_unlink(demote_idx);
self.protected_len -= 1;
self.nodes[demote_idx].in_protected = false;
self.nodes[demote_idx].was_protected = true;   // NEW
self.prob_push_back(demote_idx);
self.probationary_len += 1;
```

**3. Change the promotion gate in `get()`:**

Replace the current unconditional promotion (v001 promotes on any probationary access) with a two-branch check:

```rust
if !self.nodes[idx].in_protected {
    let should_promote = self.nodes[idx].was_protected
        || self.sketch.estimate(key) > PROMO_THRESHOLD;
    if should_promote {
        self.nodes[idx].was_protected = false;   // clear flag on re-promotion
        // ... same promotion + overflow-demotion logic as v001 ...
    } else {
        // Below threshold, not a returning protected item — refresh within probationary
        self.prob_unlink(idx);
        self.prob_push_back(idx);
    }
}
```

**4. Add the constant:**

```rust
const PROMO_THRESHOLD: u32 = 8;
```

**Eviction path (`put()`):** When a victim's arena slot is recycled for an incoming key, reset `was_protected = false` on the recycled node (it is already reset in v001's slot-reuse path).

No changes to `CountMinSketch`, `try_new`, or `put()` beyond the `was_protected = false` reset noted above.

## Rationale

Cycle 0002/v003 showed that a threshold of 2 landed in a dead zone: borderline items either were too rare to matter or promoted themselves naturally within one or two more accesses. The cycle insight explicitly recommended testing the 5–10 range. Threshold 8 is aggressive enough to gate out items that gained access counts primarily during a cold-start burst rather than through sustained demand. The `was_protected` bypass ensures that genuinely hot items — those displaced from protected purely by LRU overflow pressure, not by low frequency — are not penalized by the same gate, preserving v001's fast-path for confirmed hot items.
