# H01

Increasing `SKETCH_DEPTH` from 4 to 6 rows reduces minimum-estimator variance by adding two independent hash witnesses, raising hit rate above v001's 0.7435.

## Parent

cycle/0007/v001

## Changes

In the overlay `src/tiny_lfu/mod.rs`, change the single constant at the top of the file:

```
const SKETCH_DEPTH: usize = 4;
```
to:
```
const SKETCH_DEPTH: usize = 6;
```

No other changes are required. `CountMinSketch::new()` already reads `SKETCH_DEPTH` to allocate the row matrix (`vec![vec![0; width]; depth]`), `increment()` already iterates `0..self.depth` for the conservative-update scan, and `estimate()` already calls `.min()` across all rows — all three automatically cover 6 rows once the constant is updated.

The 8× sketch width from v001 is preserved unchanged. Memory cost increases by 50 % relative to 4 rows, but the total sketch allocation (6 × 16384 u32 cells at capacity=2048) remains modest. The SLRU structure, k=4 victim scan, PROMO_THRESHOLD=8, and was_protected bypass are all kept exactly as in v001.

## Rationale

Width and depth reduce distinct error sources in a Count-Min Sketch: width lowers the per-row collision probability, while depth lowers the probability that *all* rows simultaneously give an inflated estimate. With 4 rows the minimum estimator still has non-negligible variance from the small number of independent witnesses; adding 2 more rows cuts the probability that every row is contaminated by the same ghost count without any collision-probability reduction (which would require wider rows). Conservative update already prevents overcounting on the first increment past the true value, but it cannot eliminate pre-existing inflation from unrelated keys sharing a bucket; extra rows provide additional chances for a clean (uncontaminated) minimum. This is the exact axis flagged as unexplored in the cycle-0007 insight.
