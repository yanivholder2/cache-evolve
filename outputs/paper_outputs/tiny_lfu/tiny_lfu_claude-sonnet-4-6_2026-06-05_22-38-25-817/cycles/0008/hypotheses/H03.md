# H03

Admitting newcomers whose sketch estimate already meets `PROMO_THRESHOLD` directly into the protected segment bypasses the unnecessary probationary gauntlet for re-discovered hot items, reducing churn and raising hit rate above v001's 0.7435.

## Parent

cycle/0007/v001

## Changes

In the overlay `src/tiny_lfu/mod.rs`, modify `TinyLfuCache::put()` in two places — the fill phase and the eviction phase — so that a newly admitted key goes to protected rather than probationary when its sketch estimate at admission time is at or above `PROMO_THRESHOLD`. The sketch is incremented before these checks (as today), so `incoming_freq` reflects the count after the put-call's own increment.

**1. Fill phase (arena not yet full), replace:**

```rust
        if self.nodes.len() < self.capacity {
            let idx = self.nodes.len();
            self.nodes.push(Node {
                key: key.clone(),
                value,
                prev: None,
                next: None,
                in_protected: false,
                was_protected: false,
            });
            self.prob_push_back(idx);
            self.probationary_len += 1;
            self.map.insert(key, idx);
            return;
        }
```

with:

```rust
        if self.nodes.len() < self.capacity {
            let idx = self.nodes.len();
            let freq = self.sketch.estimate(&key);
            self.nodes.push(Node {
                key: key.clone(),
                value,
                prev: None,
                next: None,
                in_protected: false,
                was_protected: false,
            });
            if freq >= PROMO_THRESHOLD {
                self.prot_push_back(idx);
                self.protected_len += 1;
                self.maybe_demote_from_protected();
            } else {
                self.prob_push_back(idx);
                self.probationary_len += 1;
            }
            self.map.insert(key, idx);
            return;
        }
```

**2. Eviction phase (arena full), inside the `if incoming_freq > victim_freq` block, replace:**

```rust
            self.nodes[victim_idx].key = key.clone();
            self.nodes[victim_idx].value = value;
            self.nodes[victim_idx].was_protected = false;
            self.prob_push_back(victim_idx);
            self.probationary_len += 1;
            self.map.insert(key, victim_idx);
```

with:

```rust
            self.nodes[victim_idx].key = key.clone();
            self.nodes[victim_idx].value = value;
            self.nodes[victim_idx].was_protected = false;
            if incoming_freq >= PROMO_THRESHOLD {
                self.prot_push_back(victim_idx);
                self.protected_len += 1;
                self.maybe_demote_from_protected();
            } else {
                self.prob_push_back(victim_idx);
                self.probationary_len += 1;
            }
            self.map.insert(key, victim_idx);
```

No changes to `get()`, `CountMinSketch`, or any constants. SLRU capacities (90/10 split), k=4 victim scan, PROMO_THRESHOLD=8, was_protected bypass, conservative update, and 8× sketch width all remain exactly as in v001. The `maybe_demote_from_protected()` call ensures the protected segment never overflows its budget regardless of how many items are admitted directly.

## Rationale

In v001 every admitted key enters probationary regardless of its sketch frequency. On a Zipfian trace, many re-encountered keys have already accumulated counts ≥ PROMO_THRESHOLD from prior access before the current put — they are demonstrably hot but must survive eviction pressure in probationary before `get()` can promote them. Forcing them through probationary introduces a window where they can be evicted by lower-frequency competitors before the first get call. Direct-to-protected admission collapses that window for keys that have already earned protected status by their observed frequency, while the TinyLFU gate continues to block genuinely cold newcomers (those with `incoming_freq ≤ victim_freq`).
