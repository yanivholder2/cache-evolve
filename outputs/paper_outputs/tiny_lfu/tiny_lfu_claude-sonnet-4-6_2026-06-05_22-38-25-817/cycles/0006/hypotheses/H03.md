# H03

Requiring incoming items to have accumulated at least 2 sketch hits before they can displace a probationary victim — a hard admission floor — reduces cache churn from first-encounter items and improves hit rate on a stable Zipfian trace.

## Parent

cycle/0005/v001

## Changes

Add a new constant and tighten the admission gate condition in `put()`.

**Step 1 — add constant** (place near the other constants at the top of `mod.rs`, after `PROMO_THRESHOLD`):

```rust
/// Absolute minimum sketch frequency an incoming item must reach before it
/// can displace a probationary victim via the eviction-path admission gate.
/// Guards against first-encounter items (freq == 1 after the put() increment)
/// displacing incumbents purely by chance.
const MIN_ADMISSION_FREQ: u32 = 2;
```

**Step 2 — modify the admission gate in `put()`**.

Current condition (approximately line 273 in the full-arena branch):
```rust
if incoming_freq > victim_freq {
```

New condition:
```rust
if incoming_freq > victim_freq && incoming_freq >= MIN_ADMISSION_FREQ {
```

No other code changes. The `else` branch (reject newcomer) is unchanged. The victim selection scan, the recycle-slot logic, and all other paths are unchanged.

**Effect:** an item calling `put()` for the very first time — with no prior `get()` misses to accumulate frequency — will have `incoming_freq == 1` after the increment at the top of `put()`. This item can no longer displace any probationary resident regardless of the victim's frequency. An item that was seen at least once via a `get()` miss before being `put()` will have `incoming_freq >= 2` and is subject only to the existing `incoming_freq > victim_freq` comparison as before.

## Rationale

The k=4 victim scan already ensures the evicted item is the coldest probationary candidate, but the admission gate only asks "is the newcomer hotter than the victim?" For a cold victim with frequency 1 and a brand-new item also with frequency 1 (after its first put() increment), the gate correctly rejects (strict `>`). However, a truly first-seen item with frequency 1 could in principle beat a victim at frequency 0, which can occur early in trace replay. More importantly, raising the floor to 2 establishes a clean invariant: only items with at least one prior encounter beyond the insert call itself can enter the cache via eviction — exactly the principle the TinyLFU admission gate is designed to enforce. Five cycles have not tested this axis at all; the existing gate has never had an absolute floor.
