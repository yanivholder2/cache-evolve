# H02

Doubling the victim-scan window from k=4 to k=8 in the cycle/0004/v003 SLRU improves hit rate by exposing lower-frequency eviction candidates deeper into the probationary LRU tail.

## Parent

cycle/0004/v003

## Changes

In the cycle/0004/v003 overlay (`src/tiny_lfu/mod.rs`), change the single constant on line 14 from:

```rust
const EVICTION_SCAN_K: usize = 4;
```

to:

```rust
const EVICTION_SCAN_K: usize = 8;
```

No other changes. The scan loop in `put()` already handles any k value; it stops early if probationary holds fewer than k items:

```rust
let mut cursor = self.nodes[ph].next;
for _ in 1..EVICTION_SCAN_K {   // runs 7 iterations instead of 3
    let Some(c) = cursor else { break };
    ...
}
```

The 90/10 SLRU split, unconditional promotion on access, and admission gate (`incoming_freq > victim_freq`) are all unchanged from v003.

## Rationale

With capacity=2048 the probationary segment holds ~205 items. k=4 scans roughly 2% of probationary candidates; k=8 scans ~4%. On a Zipfian trace, access frequency varies sharply even within the LRU tail: doubling the scan window increases the probability of skipping a high-frequency outlier at the tail and finding a genuinely cold victim. The cycle 0004 insight explicitly named k=8 as the lowest-cost probe to run after the combined-gate hypothesis.
