# H02

Applying v003's promotion gate symmetrically to the `put()` update path for existing probationary items will improve hit rate by promoting hot keys that are updated (not just read) without waiting for a subsequent `get()` call.

## Parent

cycle/0003/v003

## Changes

The only code to change is the `put()` method's existing-key update branch. All other v003 logic — 90/10 SLRU split, `PROMO_THRESHOLD=8`, `was_protected` flag, `get()` promotion logic, eviction logic — stays identical.

**Current v003 `put()` for an existing key (lines ~141–150):**
```rust
if let Some(&idx) = self.map.get(&key) {
    self.nodes[idx].value = value;
    if self.nodes[idx].in_protected {
        self.prot_unlink(idx);
        self.prot_push_back(idx);
    } else {
        self.prob_unlink(idx);
        self.prob_push_back(idx);
    }
    return;
}
```

**Replace the `else` branch (probationary case) with the same threshold-or-bypass check that `get()` uses:**
```rust
if let Some(&idx) = self.map.get(&key) {
    self.nodes[idx].value = value;
    if self.nodes[idx].in_protected {
        self.prot_unlink(idx);
        self.prot_push_back(idx);
    } else {
        let should_promote = self.nodes[idx].was_protected
            || self.sketch.estimate(&key) > PROMO_THRESHOLD;
        if should_promote {
            self.nodes[idx].was_protected = false;
            self.prob_unlink(idx);
            self.probationary_len -= 1;
            self.nodes[idx].in_protected = true;
            self.prot_push_back(idx);
            self.protected_len += 1;
            if self.protected_len > self.protected_capacity {
                let demote_idx = self
                    .prot_head
                    .expect("TinyLfuCache: protected list non-empty when overflowing");
                self.prot_unlink(demote_idx);
                self.protected_len -= 1;
                self.nodes[demote_idx].in_protected = false;
                self.nodes[demote_idx].was_protected = true;
                self.prob_push_back(demote_idx);
                self.probationary_len += 1;
            }
        } else {
            self.prob_unlink(idx);
            self.prob_push_back(idx);
        }
    }
    return;
}
```

Note: the sketch is incremented for the key at the top of `put()` before this branch is reached, so by the time `estimate()` is called here the count already reflects the current `put()` call — consistent with how `get()` increments before checking `estimate()`.

**Invariant to preserve:** The overflow demotion block must set `was_protected = true` on the demoted node (exactly as in `get()`). The `was_protected` flag on the updated node must be cleared before promotion (again matching `get()` behaviour).

## Rationale

In v003, `get()` carefully gates promotion through `was_protected || sketch.estimate > PROMO_THRESHOLD`, but `put()` for an existing probationary item skips this check entirely and always stays in probationary. On a workload where hot keys are also frequently re-inserted (write-heavy access bursts), those keys accumulate frequency via `sketch.increment` but never get promoted until a subsequent `get()` call. Making `put()` symmetric with `get()` closes this promotion gap with a minimal, isolated code change.
