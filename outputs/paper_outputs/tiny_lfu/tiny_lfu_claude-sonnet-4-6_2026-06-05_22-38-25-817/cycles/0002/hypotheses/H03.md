# H03

Requiring a minimum sketch frequency before promoting a probationary item to the protected segment reduces churn in the protected zone and raises hit rate on top of v003's SLRU structure.

## Parent

cycle/0001/v003

## Changes

In v003, every cache hit on a probationary item unconditionally promotes it to the protected segment. This means an item that has been accessed only twice (once via `put`, once via this `get`) immediately occupies a protected slot, potentially evicting a longer-lived resident. This hypothesis adds a promotion threshold: a probationary item is only promoted if its sketch frequency at the time of the hit exceeds `PROMO_THRESHOLD`; otherwise it is refreshed within probationary (moved to the MRU tail of the probationary list) without crossing the segment boundary.

**Add a constant near the top of the file (after the existing consts):**
```rust
const PROMO_THRESHOLD: u32 = 2;
```

A threshold of 2 means the sketch estimate must be strictly greater than 2 — so the item needs at least 3 observed accesses before qualifying for protected. (Since `get()` already called `sketch.increment` before this check, an estimate of 2 corresponds to one prior access — the `put` — plus this hit; an estimate of 3 corresponds to one prior access and two hits.)

**Modify the `get()` method's probationary branch** (the `if !self.nodes[idx].in_protected` arm):

```rust
if !self.nodes[idx].in_protected {
    let freq = self.sketch.estimate(key);
    if freq > PROMO_THRESHOLD {
        // Promote to protected (MRU end) — same as v003's original logic.
        self.prob_unlink(idx);
        self.probationary_len -= 1;
        self.prot_push_back(idx);
        self.nodes[idx].in_protected = true;
        self.protected_len += 1;

        // If protected segment overflows, demote its LRU end to probationary.
        if self.protected_len > self.protected_capacity {
            let demote_idx = self
                .prot_head
                .expect("TinyLfuCache: protected list non-empty when overflowing");
            self.prot_unlink(demote_idx);
            self.protected_len -= 1;
            self.nodes[demote_idx].in_protected = false;
            self.prob_push_back(demote_idx);
            self.probationary_len += 1;
        }
    } else {
        // Below threshold — refresh within probationary to MRU tail.
        self.prob_unlink(idx);
        self.prob_push_back(idx);
    }
} else {
    // Already in protected — move to MRU position within the segment.
    self.prot_unlink(idx);
    self.prot_push_back(idx);
}
```

All other logic (the 80/20 protected/probationary split, frequency-gated admission in `put()`, the SLRU demotion path) remains identical to v003. Only the promotion gate inside `get()` changes.

## Rationale

The cycle insight noted that SLRU's protection is "partially redundant with the existing admission gate" and the gain was narrow. One reason for the narrow gain: items entering probationary immediately after a single access (frequency ≈ 2) can displace longer-lived protected items the very next time they are touched. The promotion threshold adds a second frequency check at the segment boundary — consistent with the TinyLFU philosophy of using frequency to gate transitions — which should stabilise the protected zone around items with genuinely elevated access counts.
