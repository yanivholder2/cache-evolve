# H01

Eliminate frequency-aware victim selection overhead by reverting to pure LRU eviction to validate whether frequency awareness is necessary for maintaining hit-rate.

## Parent

cycle/0006/v001

## Changes

In the `put()` method eviction block (lines 98–131 in `src/tiny_lfu/mod.rs`), replace the frequency-aware victim selection logic with unconditional LRU head eviction. Remove the candidate scanning loop and frequency comparison; instead, always evict the LRU head (`self.head`) without consulting the frequency sketch.

Simplify the eviction section to:

```rust
// Always evict the LRU head (pure LRU, no frequency checks)
let victim_idx = self.head.expect("TinyLfuCache: full cache has no victim");
let victim_key = self.nodes[victim_idx].key.clone();

// Still check admission (incoming_freq > victim_freq) to prevent low-frequency items
// but do not scan for alternative victims
let victim_freq = self.sketch.estimate(&victim_key);
let incoming_freq = self.sketch.estimate(&key);
if incoming_freq > victim_freq {
    self.map.remove(&victim_key);
    self.unlink(victim_idx);
    self.nodes[victim_idx].key = key.clone();
    self.nodes[victim_idx].value = value;
    self.push_back(victim_idx);
    self.map.insert(key, victim_idx);
}
```

Remove the loop that scans for N=2 candidate items (lines 103–117). Keep the sketch geometry (depth-3, width-4) and admission threshold (`incoming_freq > victim_freq`) unchanged. The admission gate remains active; only the victim selection strategy changes from frequency-aware to pure recency-based.

## Rationale

Cycle 0006's v001 (N=2 frequency-aware selection) achieved 30% p99 latency reduction on put operations with negligible hit-rate cost (0.7355→0.7354). However, the cycle-0006 insight explicitly asks: "Is N=2 the true minimum for frequency-aware selection, or is N=1 (pure LRU head, no frequency checks) competitive?" This hypothesis directly answers that open question. If pure LRU (N=1) maintains similar hit-rate and per-op-time, then the frequency-aware scanning overhead is unnecessary. If it degrades hit-rate materially, it confirms that frequency awareness, even minimal (checking only 2 items), is load-bearing. This is the boundary test for the eviction policy frontier.
