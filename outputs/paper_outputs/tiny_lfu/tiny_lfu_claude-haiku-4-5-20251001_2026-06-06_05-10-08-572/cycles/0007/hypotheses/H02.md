# H02

Cache frequency estimates during victim candidate scanning to eliminate redundant sketch queries and reduce eviction latency while preserving N=2 frequency-aware benefits.

## Parent

baseline

## Changes

In the `put()` method victim selection block (lines 98–131 in `src/tiny_lfu/mod.rs`), optimize the candidate scanning loop by computing each victim's estimated frequency exactly once and reusing the result in comparisons. Currently, `sketch.estimate()` is called multiple times per item; refactor to call it once per candidate and cache the result.

Pseudocode for the optimized scanning:

```rust
// Frequency-aware victim selection with cached estimates
let mut victim_idx = self.head.expect("TinyLfuCache: full cache has no victim");
let mut min_freq = self.sketch.estimate(&self.nodes[victim_idx].key);
let mut candidate = victim_idx;
let mut current = self.nodes[victim_idx].next;

// Scan only 1 more item (2 total) and cache frequencies
for _ in 0..1 {
    if let Some(idx) = current {
        let freq = self.sketch.estimate(&self.nodes[idx].key);
        if freq < min_freq {
            min_freq = freq;
            candidate = idx;
        }
        current = self.nodes[idx].next;
    } else {
        break;
    }
}

// Use cached min_freq directly; no re-estimation
victim_idx = candidate;
let victim_key = self.nodes[victim_idx].key.clone();
// Note: victim_freq is already computed as min_freq
let victim_freq = min_freq;  // Reuse cached value
let incoming_freq = self.sketch.estimate(&key);
if incoming_freq > victim_freq {
    // Evict and insert as before
    self.map.remove(&victim_key);
    self.unlink(victim_idx);
    self.nodes[victim_idx].key = key.clone();
    self.nodes[victim_idx].value = value;
    self.push_back(victim_idx);
    self.map.insert(key, victim_idx);
}
```

The loop structure and N=2 candidate pool remain identical; only the redundant `sketch.estimate(&victim_key)` call on line 122 is eliminated by reusing the cached `min_freq` computed during scanning. Admission threshold and sketch geometry unchanged.

## Rationale

The current implementation computes sketch frequencies redundantly: once during candidate scanning (lines 101, 108) and again when evaluating admission (line 122). The sketch query is O(depth) work; eliminating one redundant call per eviction reduces per-operation overhead. This optimization preserves the N=2 frequency-aware strategy proven effective in cycle 0006, while targeting per-op-time through better algorithmic efficiency. The change is minimal (reuse cached frequency) and maintainability-preserving, unlike deeper refactors that alter the eviction policy itself.
