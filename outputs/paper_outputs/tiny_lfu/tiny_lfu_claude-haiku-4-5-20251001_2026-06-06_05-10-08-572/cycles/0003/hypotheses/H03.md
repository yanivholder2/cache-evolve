# H03

Implement periodic frequency sketch decay to refresh frequency estimates and improve responsiveness to workload phases, raising hit-rate.

## Parent

baseline

## Changes

Modify `struct CountMinSketch` in src/tiny_lfu/mod.rs to add an operation counter:

1. Add a field `op_count: u64` to track cumulative sketch operations (increments and estimates).

2. Add a private method `fn decay_if_needed(&mut self)` that checks if `self.op_count >= 500_000`. If true, halve all sketch counts using bitwise right-shift (`counts[i][j] >>= 1` for each row and column), then reset `op_count` to 0.

3. Call `decay_if_needed()` at the start of both `increment()` and `estimate()` methods, before any hash computation, then increment `op_count`.

4. Keep admission condition (`>`), eviction logic, and all LRU behavior unchanged.

## Rationale

Frequency sketches accumulate unbounded counts and never discount old access patterns. On workloads with phase changes or temporal locality shifts, stale high frequencies can incorrectly guide eviction decisions toward keeping aged items. Periodic decay (every ~500k operations, roughly 250 full cache eviction cycles at 2048 capacity) makes the sketch responsive to recent working sets while preserving its core frequency-ranking ability. This targets a potential accuracy vector orthogonal to sketch geometry (width and depth), testing whether temporal freshness of frequency estimates improves hit-rate on phase-sensitive traces.
