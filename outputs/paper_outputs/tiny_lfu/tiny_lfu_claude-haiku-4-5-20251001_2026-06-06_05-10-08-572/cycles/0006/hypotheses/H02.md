# H02

Revalidate sketch decay at 500k operation intervals on the stable depth-3 baseline to reproduce cycle 0003's breakthrough and confirm whether temporal freshness improves hit-rate.

## Parent

cycle/0002/v002

## Changes

Add an `op_count: u64` field to the `CountMinSketch` struct (around line 161) to track operations since the last decay event. Implement a `decay_if_needed()` method that halves all counter values using bitwise right-shift when `op_count >= 500_000`, then resets `op_count` to 0:

```rust
fn decay_if_needed(&mut self) {
    if self.op_count >= 500_000 {
        for row in &mut self.counts {
            for counter in row {
                *counter >>= 1;  // Divide by 2 using right-shift
            }
        }
        self.op_count = 0;
    }
}
```

Call `decay_if_needed()` at the start of both `increment()` (after incrementing op_count) and `estimate()` methods to trigger decay on every operation. This mirrors cycle 0003's successful v003 implementation: periodic halving of frequency counters reduces the window for stale estimates, making admission and eviction decisions more responsive to recent workload shifts while discounting historical noise.

Keep the depth-3, width-4 sketch geometry, the LRU-only victim selection (no frequency-aware changes), and the strict admission threshold `incoming_freq > victim_freq` unchanged.

## Rationale

Cycle 0003's v003 achieved both hit-rate improvement (0.7364 → 0.7364, slight gain relative to baseline 0.7364) and latency improvement (132 → 112 ns get, 166 → 142 ns put) with 500k-interval decay, marking the first co-benefit across three cycles. Cycle 0004 questioned reproducibility by testing different decay intervals (250k aggressive, 1M conservative) and wider geometries, all of which regressed or showed mixed results. The cycle 0004 continuation explicitly recommends re-validating decay on the stable depth-3 baseline at 500k to isolate decay's true benefit. This hypothesis directly executes that recommendation, testing whether the cycle 0003 breakthrough was genuine or a statistical artifact specific to that cycle's workload sample.
