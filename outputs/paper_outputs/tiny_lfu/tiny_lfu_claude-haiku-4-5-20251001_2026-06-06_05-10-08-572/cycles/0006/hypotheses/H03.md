## Changes

Implement two orthogonal modifications to the baseline:

**1. Sketch decay (as in H02):**
Add an `op_count: u64` field to the `CountMinSketch` struct and implement the `decay_if_needed()` method:

```rust
fn decay_if_needed(&mut self) {
    if self.op_count >= 500_000 {
        for row in &mut self.counts {
            for counter in row {
                *counter >>= 1;
            }
        }
        self.op_count = 0;
    }
}
```

Call `decay_if_needed()` at the start of `increment()` and `estimate()` methods.

**2. Lightweight frequency-aware victim selection (N=2, as in H01):**
In the `put()` method (around line 98), modify victim selection to scan only the head and next item (N=2 total):

```rust
let mut victim_idx = self.head.expect("TinyLfuCache: full cache has no victim");
let mut min_freq = self.sketch.estimate(&self.nodes[victim_idx].key);
let mut candidate = victim_idx;
let mut current = self.nodes[victim_idx].next;

// Scan only 1 more item (2 total)
if let Some(idx) = current {
    let freq = self.sketch.estimate(&self.nodes[idx].key);
    if freq < min_freq {
        candidate = idx;
    }
}

victim_idx = candidate;
```

Keep the admission condition `incoming_freq > victim_freq` unchanged. The sketch will automatically benefit from decay's temporal freshness, potentially making frequency estimates more responsive during selection.

## Rationale

Cycles 0005 and earlier identified two independent beneficial levers: (1) decay improves responsiveness to workload phase changes (cycle 0003), and (2) frequency-aware eviction improves hit-rate (cycle 0005). However, each comes with a cost: decay adds overhead; frequency-aware selection adds latency variance. This hypothesis tests whether decay's fresher frequency signals reduce the latency variance problem of frequency-based eviction by ensuring estimates better reflect current workload hot/cold distribution, reducing the number of mispredicted evictions. The minimal pool size (N=2) keeps scanning overhead low while allowing decay-improved estimates to guide selection. If successful, this combines the benefits of both approaches into a stable, latency-respecting variant.
