# H03

Pair periodic sketch decay at 500k operations with the high-frequency width-8 geometry to synergize improved hit-rate with reduced latency penalties that width-8 alone incurred.

## Parent

cycle/0001/v001

## Changes

Add an `op_count: u64` field to the `CountMinSketch` struct to track operations since the last decay event. Implement a `decay_if_needed()` method that halves all counter values using bitwise right-shift when `op_count >= 500_000`, then resets `op_count` to 0. Call `decay_if_needed()` at the start of both `increment()` and `estimate()` methods. This cycle-0003-proven decay interval (500k) is applied to cycle-0001's v001 (SKETCH_DEPTH=4, SKETCH_WIDTH_FACTOR=8) to test whether periodic decay removes staleness-induced noise in high-frequency sketches. The hypothesis is that v001's width-8 suffered latency penalties partly because unbounded count growth created noisy estimates during phase transitions; decay resets provide fresher frequency signals that reduce eviction churn, potentially enabling v001's superior hit-rate (0.7409) without repeating the 60% latency penalty that width-8 alone suffered.
