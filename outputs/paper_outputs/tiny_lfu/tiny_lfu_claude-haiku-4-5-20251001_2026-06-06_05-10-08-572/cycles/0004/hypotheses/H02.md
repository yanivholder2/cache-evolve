# H02

Apply sketch decay at a conservative 1M operation interval to the depth-3 baseline to reduce decay overhead while retaining temporal freshness benefits for hit-rate.

## Parent

cycle/0002/v002

## Changes

Add an `op_count: u64` field to the `CountMinSketch` struct to track operations since the last decay event. Implement a `decay_if_needed()` method that halves all counter values using bitwise right-shift when `op_count >= 1_000_000`, then resets `op_count` to 0. Call `decay_if_needed()` at the start of both `increment()` and `estimate()` methods to ensure decay is checked on every operation. This more conservative decay schedule (1M vs. v003's 500k) tests whether longer decay intervals reduce per-operation decay overhead (fewer halving operations executed) while still providing sufficient temporal freshness for responsive admission decisions on this workload. The extended interval explores the lower bound of decay frequency before losing effectiveness.
