# H02

Improve frequency estimation accuracy by implementing a higher-quality composite hash function to reduce collision-induced errors and raise hit-rate.

## Changes

In the `position()` method (around line 177), replace the single `DefaultHasher`-based hash with a composite hashing strategy using independent hash functions. Implement two independent hashes and XOR their results:

```rust
fn position<K: Hash>(&self, key: &K, seed: u64) -> usize {
    // First hash: DefaultHasher with seed
    let mut hasher1 = DefaultHasher::new();
    hasher1.write_u64(seed);
    key.hash(&mut hasher1);
    let hash1 = hasher1.finish() as usize;
    
    // Second hash: seed × 31 + key bits (simulating FNV-like behavior)
    let mut hasher2 = DefaultHasher::new();
    hasher2.write_u64(seed.wrapping_mul(31).wrapping_add(73));
    key.hash(&mut hasher2);
    let hash2 = hasher2.finish() as usize;
    
    // XOR to mix bit patterns, reducing correlation
    (hash1 ^ hash2) & (self.width - 1)
}
```

This composite approach decorrelates the hash inputs to each sketch row, reducing the probability that collisions in one row align with collisions in another row (the "correlated collision" problem in count-min sketches). Target: hit-rate improvement through more accurate frequency estimates.

## Rationale

Count-min sketches depend critically on independent hash functions for correctness. The baseline's single `DefaultHasher` may produce correlated collisions when applied across multiple rows with simple seed variation. Cycle 0004 identifies hash function choice as an unexplored tuning lever. XOR-combined independent hashes are a standard technique in sketch literature to improve estimation quality without changing the data structure or admission logic.
