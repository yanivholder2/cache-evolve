# H01

Short-circuit the sampled-coldest eviction walk the moment a floor-frequency victim is found, cutting per-op-time on the put path with bit-identical hit-rate.

## Parent

cycle/0005/v001

## Changes

In `TinyLfuCache::put`, the full-cache branch walks up to `SAMPLE_VICTIMS`
(=5) candidates forward from `head`, calling `self.sketch.estimate` on each
and keeping the strictly-lowest. An estimate can never go below 0 (the
count-min floor), so once the running `victim_freq` reaches 0 no later
candidate can beat it — the chosen victim is already final.

Add an early exit so the walk stops as soon as `victim_freq == 0`:

- After initialising `victim_idx`/`victim_freq` from the head, if
  `victim_freq == 0`, skip the sampling loop entirely.
- Inside the `while sampled < SAMPLE_VICTIMS` loop, after the
  `candidate_freq < victim_freq` update that may set a new best, break out of
  the loop when `victim_freq == 0`.

This must preserve victim selection exactly: the current code replaces the
victim only on a *strictly* lower estimate and visits older candidates
first, so the first candidate to reach 0 is precisely the one the unmodified
walk would have settled on. Hit-rate, admission (`incoming_freq >
victim_freq`), and all list surgery (`unlink`/`push_back`) stay untouched —
the only effect is fewer `sketch.estimate` calls (each a hash plus a
depth-row min) on the common case where a cold entry sits near the LRU head,
trimming the put-path eviction-walk work and its p99 tail.

## Rationale (optional)

Cycle 9 named the eviction walk as the one remaining cost surface and ruled
the increment loop and list structure dead. This is the cheapest possible
walk cut: provably hit-rate-neutral because the victim identity is unchanged,
targeting only redundant estimate calls past the frequency floor.
