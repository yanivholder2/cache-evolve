# H03

Replace the pointer-chasing LRU eviction walk with random sampling of contiguous `nodes` slots, cutting per-op-time by eliminating the walk's cache misses.

## Parent

cycle/0005/v001

## Changes

The eviction walk in `put` follows `next` links from `head`, indexing
`self.nodes[cursor]` at each step. Because the linked-list order is unrelated
to physical `Vec` order, each hop is an effectively random jump into `nodes`
— a chain of cache misses on the put path. Since the cache is full when this
branch runs, every slot in `0..self.nodes.len()` holds a live entry, so we
can sample victims by direct index instead of by link traversal.

- Add a cheap PRNG to `TinyLfuCache`: a single `rng_state: u64` field seeded
  in `try_new` (e.g. from `HASH_SEED`), advanced with an inline xorshift.
  This lives on the cache struct, not on `Node`, so the scored Node
  metadata-size stays at 24 bytes.
- In the full-cache branch of `put`, replace the `head`/`next` sampling loop
  with `SAMPLE_VICTIMS` draws of `rng_state` reduced to `0..self.nodes.len()`
  (mask or multiply-shift). Track the lowest `sketch.estimate` among the
  sampled indices exactly as today, breaking on a strictly-lower estimate,
  and keep the floor early-exit spirit by stopping if the best hits 0.
- Keep the rest intact: the `incoming_freq > victim_freq` admission gate, the
  `unlink`/`push_back`/`map` bookkeeping when a victim is replaced, and the
  LRU list itself (`get` still reorders) so recency still governs nothing but
  is preserved for other paths.

This swaps LRU-window sampling for Redis-style random sampled-LFU eviction:
victim *quality* is still set by the sketch estimate (cross-cycle finding:
eviction is accuracy-saturated, not sample-source-bound), while the sampling
source becomes contiguous-friendly index draws instead of a pointer chase.

## Rationale (optional)

The walk's cost is dominated by random `Vec` indexing through the link chain,
not by estimate count. Drawing direct indices keeps the same victim-selection
rule while removing the chain dependency, targeting put-path per-op-time and
its tail; hit-rate should hold because frequency, not recency, picks the
victim.
