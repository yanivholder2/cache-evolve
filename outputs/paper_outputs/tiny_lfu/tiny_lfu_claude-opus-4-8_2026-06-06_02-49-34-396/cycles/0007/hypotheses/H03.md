# H03

Adding amortized counter halving with a wide reset interval keeps the frequency estimate fresh against shifting hot sets, lifting hit-rate on the wide sketch.

## Parent

cycle/0005/v001

## Changes

In `src/tiny_lfu/mod.rs`, add classic TinyLFU frequency aging to
`CountMinSketch`, done the way the cross-cycle log sanctions revisiting it
(wide decay interval, amortized non-inline sweep). Concretely:

1. Add two fields to `CountMinSketch`: `additions: u64` (running count of
   `increment` calls since the last reset) and `reset_at: u64` (the
   threshold). Initialize `additions = 0` in `new`, and set
   `reset_at = width as u64` so a halving occurs roughly once every
   `width` (≈ 16 × capacity) increments — a deliberately wide interval so
   the sweep is O(width) work amortized to O(1) per op and the frequency
   signal is decayed slowly, not erased.
2. At the end of `CountMinSketch::increment`, after the per-row counter
   bumps, do `self.additions += 1; if self.additions >= self.reset_at {
   self.reset(); }`.
3. Add `fn reset(&mut self)` that performs one linear pass over every
   counter (`for row in &mut self.counts { for c in row.iter_mut() { *c
   >>= 1; } }`) and sets `self.additions = 0`. Right-shift halving
   preserves relative frequency ordering while bounding counter inflation.

Leave `estimate`, `position_for`, `base_hash`, the `MAX_COUNT` saturation
guard, node layout, and the sampled-coldest eviction logic unchanged. The
premise: counters on a long trace monotonically inflate toward saturation,
flattening the frequency distinction between persistently-hot and
once-hot keys; periodic halving restores contrast so admission/eviction
favor *currently* hot keys. Unlike the prior mistuned aging attempt, the
interval here is wide (tied to sketch width, not a small fixed tick) and
the sweep is a single amortized pass, not inline per-access decay.
Preserve the invariant that `estimate` returns the min across rows and is
never called mid-sweep (sweep runs only inside `increment`).
