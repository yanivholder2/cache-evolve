# H02

Segmenting the main LRU list into a small probation segment and a protected segment (SLRU) raises hit-rate by shielding proven-reused entries from eviction by one-hit newcomers.

## Parent

cycle/0005/v001

## Changes

Replace the single intrusive LRU list in `TinyLfuCache` with a
two-segment SLRU within the existing `nodes`/`map` arena. Concretely:

- Add a second pair of head/tail sentinels (`prot_head`, `prot_tail` as
  `u32` with the `NIL` sentinel) and a per-`Node` `bool`/`u8` flag
  `protected`, alongside the existing `head`/`tail` (now the probation
  segment). Keep `prev`/`next` as the single link pair shared by whichever
  segment a node currently sits in.
- Track a protected-segment size cap of ~80% of `capacity`
  (`protected_cap = capacity - capacity/5`), leaving the remaining ~20%
  as probation.
- On `get` hit: if the node is in probation, move it to the protected
  segment's MRU and set `protected = true`; if protected is now over
  `protected_cap`, demote the protected-segment LRU (its head) back to the
  probation MRU and clear its flag. If the node is already protected, just
  move it to protected MRU. This replaces the current unconditional
  `unlink`+`push_back` into one list.
- On `put` of a full cache: select the victim only from the **probation**
  segment, reusing the existing sampled-coldest `sketch.estimate` walk
  (SAMPLE_VICTIMS along probation `next` from `head`); new admissions enter
  probation (`protected = false`). Keep the existing
  `incoming_freq > victim_freq` admission gate unchanged.

Preserve all sketch, hashing, and node-footprint semantics; this is a
list-structure change only. Update the existing unit tests' expectations
only if segment placement legitimately changes an assertion's outcome.

Rationale: the prior recency-*window* probe (0004) was inert because a 1%
front buffer was too small to matter, but SLRU restructures the *main*
cache so a single-access newcomer cannot evict a twice-proven entry — a
structurally different lever than a window or a one-count margin. This
directly probes the open question of whether any new eviction structure
moves the saturated hit-rate.
