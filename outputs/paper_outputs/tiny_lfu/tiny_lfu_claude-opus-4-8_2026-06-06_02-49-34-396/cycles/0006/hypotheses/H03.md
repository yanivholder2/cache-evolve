# H03

Give the sketch rows two independent base hashes instead of double-hashing one 64-bit value, buying back row independence to lift hit-rate.

## Parent

cycle/0005/v001

## Changes

The current sketch derives every row's column from a single base hash: `h1 = h`
and `h2 = (h >> 32) | 1`, so all `depth` rows are correlated projections of one
64-bit value. That correlation is the tolerated "double-hashing dip" noted in
the cross-cycle log. Replace it with two genuinely independent hashes:

- Add a second seed constant (e.g. `HASH_SEED2 = 0xff51_afd7_ed55_8ccd`).
- Change `base_hash` to run two `FastHasher` passes over the key — one seeded
  with `HASH_SEED`, one with `HASH_SEED2` — and return the pair `(h1, h2)`.
- Change `position_for` to take both: `position = (h1.wrapping_add((row as u64)
  .wrapping_mul(h2 | 1)) as usize) & (width - 1)`, where `h2` now comes from the
  independent second pass rather than the high bits of `h1`.
- Update `increment` and `estimate` to call the new `base_hash` once and pass
  the pair through.

Keep `SKETCH_DEPTH = 4`, `SKETCH_WIDTH_FACTOR = 16`, the `MAX_COUNT` cap, and the
eviction logic unchanged. Independent rows decorrelate collisions so the
per-key `min` over rows is a less biased frequency estimate, which should
sharpen admission and victim selection and raise hit-rate above v001's 0.7425.
Accept a small per-op-time increase from the second hash pass; the experiment is
whether the accuracy gain is worth that speed.

## Rationale (optional)

Answers the standing open question — "is buying back row independence from
double-hashing worth the speed it costs?" — head-on, on the current best
hit-rate incumbent, isolating hash independence from every other lever.
