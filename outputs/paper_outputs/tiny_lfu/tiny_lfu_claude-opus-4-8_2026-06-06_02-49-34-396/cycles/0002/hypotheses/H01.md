# H01

Narrowing v002's counters from `u32` to `u8` cuts sketch heap 4x while keeping its single-hash per-op-time win, dominating both v002 and v003.

## Parent

cycle/0001/v002

## Changes

Take v002 (single-hash double-hashing sketch) and change the counter
element type from `u32` to `u8` throughout `CountMinSketch`:

- Change `counts: Vec<Vec<u32>>` to `counts: Vec<Vec<u8>>` and the
  initializer in `new()` from `vec![vec![0; width]; depth]` to
  `vec![vec![0u8; width]; depth]`.
- Change the module constant `MAX_COUNT: u32 = u32::MAX` to
  `MAX_COUNT: u8 = u8::MAX` so the saturating-increment guard in
  `increment()` (`if *counter < MAX_COUNT { *counter += 1; }`) operates
  on `u8`.
- Keep `estimate()` returning `u32` for the admission comparison: map
  each `u8` counter to `u32` (`.map(|c| c as u32)`) before `.min()`.
- Update `heap_bytes()` to use `size_of::<u8>()` and adjust the doc
  comment accordingly.

Preserve v002's `base_hash()` (one SipHash per op) and `position_for()`
double-hashing derivation exactly — do not reintroduce per-row hashing.
Preserve the eviction/admission logic and all inline tests. The win:
v002's p50=50ns hashing cost stays, but the sketch table shrinks from
65536 to 16384 bytes; the question is whether the 8-bit ceiling costs
any hit-rate on this trace (v003 showed it did not).
