# H02

Computing one hash per key and deriving all sketch row positions by double-hashing cuts per-op-time by eliminating the three redundant SipHash computations per get/put.

## Parent

baseline

## Changes

In `src/tiny_lfu/mod.rs`, the baseline runs a fresh `DefaultHasher` (SipHash)
for every sketch row: `position()` is called `SKETCH_DEPTH` (4) times per
`increment()` and per `estimate()`, each time re-hashing the full key with a
different seed. Replace this with a single hash per key plus cheap per-row
derivation.

Add a private helper `base_hash<K: Hash>(&self, key: &K) -> u64` that hashes the
key once with a `DefaultHasher` (no seed write) and returns the finished value.
Then change `increment()` and `estimate()` to compute `h = self.base_hash(key)`
once and, for each `row in 0..self.depth`, derive the column index by double
hashing: split `h` into `h1 = h as usize` and `h2 = (h >> 32) as usize`, and use
`pos = (h1.wrapping_add(row.wrapping_mul(h2)) | 1) & (self.width - 1)`
(the `| 1` keeps `h2` odd-ish so successive rows actually differ). Remove or
bypass the old per-row `position()` so SipHash runs once instead of four times.

Keep `depth`, `width`, the counter table layout, the admission test, and the LRU
list untouched — this is purely a hashing-cost optimization. Estimation
semantics stay equivalent (still `min` over `depth` independent-ish columns), so
admission decisions and therefore residency are unchanged; all three invariants
hold because keys, values, and capacity logic are not touched.

## Rationale (optional)

Per-op-time (baseline p50 get 132ns / put 166ns) is dominated by sketch hashing:
every operation pays 4 SipHash passes. Double-hashing is the standard way to get
`k` independent positions from one hash and should roughly quarter the hashing
work while preserving sketch accuracy.
