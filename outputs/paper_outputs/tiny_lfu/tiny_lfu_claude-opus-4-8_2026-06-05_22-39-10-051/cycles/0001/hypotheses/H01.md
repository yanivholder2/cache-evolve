# H01

Periodically aging the count-min sketch by halving all counters keeps frequency estimates fresh and raises hit-rate on workloads with shifting popularity.

## Parent

baseline

## Changes

The baseline's `CountMinSketch` only ever increments counters (saturating at
`MAX_COUNT`) and never decays them, so keys that were hot early in the trace
keep winning admission long after they go cold. Add classic TinyLFU aging:

- In `CountMinSketch`, add two fields: `total: u64` (running count of
  increments) and `sample_size: u64` (the aging threshold).
- Initialise `sample_size` in `CountMinSketch::new` proportional to the
  resident capacity — use the W-TinyLFU convention of ~10× the cache
  capacity. Since `new` currently only receives `width`, thread the cache
  `capacity` (or derive from `width / SKETCH_WIDTH_FACTOR`) into the sketch so
  the threshold tracks capacity rather than sketch width.
- In `increment`, after bumping the `SKETCH_DEPTH` counters, do `self.total +=
  1`. When `self.total >= self.sample_size`, call a new private `fn reset()`
  that right-shifts every counter by one (`*c >>= 1`) across all rows and
  columns and sets `self.total = self.total >> 1` (so partial progress toward
  the next reset is preserved, matching Caffeine).
- `estimate` is unchanged.

Preserve all invariants: aging only lowers counters, so admission stays
deterministic w.r.t. residency, capacity_bound (P1), value_fidelity (P2), and
no_phantom_items (P3) are untouched. Target dimension: hit-rate.
