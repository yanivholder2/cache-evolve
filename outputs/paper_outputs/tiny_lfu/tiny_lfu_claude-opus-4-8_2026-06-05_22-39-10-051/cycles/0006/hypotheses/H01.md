# H01

Combining v001's probationary victim sampling with v002's frequency-gated promotion compounds the two confirmed-positive refinements into a larger hit-rate gain than either alone.

## Parent

cycle/0005/v002

## Changes

Take the winner v002 (SLRU with a frequency contest gating protected-tier
promotion) and graft in v001's frequency-ranked probationary victim selection.

Concretely:
- Add a module constant `const SAMPLE: usize = 5;` (match v001's sweet-spot
  sample size — do NOT widen it, since wider samples are refuted as reversing
  the gain).
- Add the `sample_prob_victim(&self) -> usize` helper from v001: starting at
  `prob_head`, walk up to `SAMPLE` nodes along the probationary `next` chain and
  return the index with the lowest `sketch.estimate`, breaking ties toward the
  most-LRU (head-nearest) node with a strict `<`. The walk stays within the
  probationary list because protected nodes live on a separate chain.
- In `put()`, replace the line that takes `self.prob_head` as the single victim
  with `let victim_idx = self.sample_prob_victim();`. Keep the existing
  `incoming_freq > victim_freq` admission gate and the replace-in-place eviction
  body exactly as in v002.
- Leave `promote()` completely untouched: the frequency contest that gates
  promotion against the protected LRU head when the protected tier is full must
  remain exactly as v002 implements it.

Preserve all invariants: a full cache always has at least one probationary node
(so `sample_prob_victim` never touches the protected tier), `protected_len`
accounting stays correct, and the protected-cap demotion path is unchanged.

## Rationale (optional)

The cycle-0005 insight explicitly poses this as the cheap, final hit-rate probe:
victim choice (v001) and promotion gating (v002) are each real but marginal — this
tests whether they fire on disjoint rare cases (and thus add) or overlap (and net
to nothing).
