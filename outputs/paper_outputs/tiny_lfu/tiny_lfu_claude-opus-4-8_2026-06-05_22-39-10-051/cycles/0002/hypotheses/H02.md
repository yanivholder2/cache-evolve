# H02

Adding a Bloom-filter doorkeeper in front of the count-min sketch so first-sight keys never increment the long-term counters sharpens frequency estimates and raises hit-rate.

## Parent

cycle/0001/v003

## Changes

Build on the v003 overlay (`src/tiny_lfu/mod.rs`). Today every `get`/`put`
calls `sketch.increment(key)` unconditionally, so one-hit-wonder keys inflate
count-min cells and overestimate the frequency of cold keys that collide with
them — exactly the estimates v003's victim ranking and the admission gate
depend on. Add a canonical TinyLFU **doorkeeper**: a small Bloom filter that
absorbs first sightings so they never reach the main sketch.

Concretely:

- Add a `doorkeeper` bit array to `TinyLfuCache` (or to `CountMinSketch`),
  sized to the sketch `width`, with k=2 hash positions derived the same way as
  `CountMinSketch::position` (reuse distinct seeds).
- Replace the unconditional `sketch.increment(key)` with: if the doorkeeper
  already has all of the key's bits set, increment the main sketch as before;
  otherwise only set the doorkeeper bits and do NOT touch the main sketch.
- Define the frequency used by `estimate` for admission/eviction as
  `(doorkeeper_contains(key) as u32) + sketch.estimate(key)`, so a key seen
  exactly once still scores 1 and the main counters stay reserved for genuinely
  recurring keys.
- To prevent saturation over a long trace, clear ONLY the doorkeeper bits each
  time total observations reach `8 * capacity`; the main count-min counters are
  never decayed, so the baseline's long-term frequency signal is fully
  preserved (this is the short-term recency filter, not aging of the sketch).

Keep v003's forward-sampling eviction and the in-place slot overwrite intact.
Preserve invariants: capacity is never exceeded, values are unchanged, and a
never-resident key is never admitted unless its (doorkeeper+sketch) score beats
the sampled victim. The testable assertion: filtering one-hit wonders out of
the sketch lifts hit-rate above v003's 0.7381 on workload-a.
