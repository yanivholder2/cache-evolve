# H02

Score the incoming key at the eviction gate by its prior (pre-increment) frequency instead of its post-increment count, tightening admission to lift hit-rate by sparing warm probationary residents.

## Parent

cycle/0008/v002

## Changes

In `put`, the eviction contest currently reads
`let incoming_freq = self.sketch.estimate(&key);` *after*
`self.sketch.increment(&key)` has already run, so the incoming key's current
access is double-counted: a key seen exactly once before returns with
`incoming_freq = 2` and beats a victim at frequency 1, even though its only
demonstrated reuse is this very access. This is the same self-bias the
promotion path already avoids by capturing `prior` pre-increment (and that
`PROMOTE_FLOOR` is evaluated against).

Make the eviction gate consistent with the promotion gate. The function
already captures `let prior = self.sketch.estimate(&key);` before
incrementing. In the cache-full branch, replace
`let incoming_freq = self.sketch.estimate(&key);` with
`let incoming_freq = prior;`, leaving the comparison `if incoming_freq >
victim_freq` and everything else unchanged.

Effect: admission now requires the incoming key's *history excluding the
current touch* to strictly exceed the victim's estimate. Single-occurrence
scan keys (prior 0) can never evict, and a key with prior 1 no longer
displaces an equally-warm resident on a tie. Keep the victim selection
(`prob_head`), the sketch, and the SLRU machinery untouched — this is purely
the admission scoring becoming stricter and self-consistent with `promote`.
