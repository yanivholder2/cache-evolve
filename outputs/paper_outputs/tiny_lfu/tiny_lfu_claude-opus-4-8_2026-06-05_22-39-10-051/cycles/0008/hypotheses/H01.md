# H01

Increasing the count-min sketch depth from 4 to 8 hash rows raises hit-rate by tightening the frequency estimate's upper bound, cutting the false-hot admissions that the width axis cannot remove.

## Parent

cycle/0007/v001

## Changes

The estimator-fidelity work across cycles 0002–0004 swept only the count-min
*width* (`SKETCH_WIDTH_FACTOR`, now 64) and declared it plateaued once cells
separate the trace's distinct keys. The orthogonal collision-reduction axis —
*depth*, the number of independent hash rows whose minimum is taken in
`estimate()` — has never been a hypothesis target and sits at its original
value of 4. Adding rows lowers (or leaves equal) every estimate, so it can only
reduce overestimation, which is exactly what causes a cold incoming key to
falsely out-score a warm probationary victim in the admission gate at
`put()` lines 133–135 and the promotion contest at lines 193–195.

Concretely, in `src/tiny_lfu/mod.rs`:

1. Change `const SKETCH_DEPTH: usize = 4;` to `const SKETCH_DEPTH: usize = 8;`.

That is the only change. `CountMinSketch::new` already allocates `depth` rows
(`vec![vec![0; width]; depth]`), `increment()` already loops `0..self.depth`,
and `estimate()` already takes the `min` across all rows, each seeded by its
row index via `position(key, row as u64)`. So doubling the constant
transparently adds four more independently-seeded rows with no other code
change. Preserve every policy mechanic exactly — SLRU segments, `PROMOTE_FLOOR`,
the frequency-gated promotion, and `sample_prot_demotee` all stay untouched;
this hypothesis isolates estimator depth as the sole variable so any hit-rate
movement is attributable to reduced sketch overestimation rather than a policy
change.

## Rationale (optional)

Estimator fidelity was the single clearest historical lift on this trace, but
only its width was ever probed. Depth attacks overestimation through a
different mechanism (more independent collisions to min away) and may still
have headroom where width is exhausted; if it too is inert, that is a clean,
distinct confirmation that the estimator is fully saturated.
