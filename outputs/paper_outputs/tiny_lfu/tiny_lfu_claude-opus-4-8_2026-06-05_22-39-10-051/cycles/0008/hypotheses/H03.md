# H03

Gating full-protected promotion on the *sampled demotion victim's* frequency instead of the protected LRU head's loosens the contest exactly when a colder node sits behind the head, admitting more proven-warm keys to protection and raising hit-rate.

## Changes

There is a latent inconsistency in the incumbent's promotion path. When the
protected tier is full, `promote()` admits the promotee only if
`promotee_freq > head_freq` (the protected *LRU head's* estimate, lines
193–195), but the node it actually demotes is `sample_prot_demotee()` — the
coldest node within a `DEMOTE_SAMPLE`-wide window starting at the head. Because
the sampled victim is by construction no hotter than the head
(`best_freq <= head_freq`), the admission test is stricter than it needs to be:
a promotee whose frequency falls between the sampled victim's and the head's is
rejected even though swapping it in for the genuinely coldest protected node
would strictly improve the protected set's total frequency.

Concretely, in `src/tiny_lfu/mod.rs` `promote()` (the `Some(head_idx)` branch,
lines 191–209):

1. Compute the demotion candidate *first*: `let demotee = self.sample_prot_demotee();`.
2. Replace the gate `let head_freq = self.sketch.estimate(&self.nodes[head_idx].key);`
   / `if promotee_freq > head_freq` with a contest against the demotee:
   `let demotee_freq = self.sketch.estimate(&self.nodes[demotee].key);`
   then `if promotee_freq > demotee_freq`.
3. In the win branch, demote that same already-chosen `demotee` (unlink it,
   `protected_len -= 1`, `push_back_prob(demotee)`) and promote `idx`
   (`push_back_prot(idx)`, `protected_len += 1`) — identical bookkeeping to
   today, just reusing the `demotee` computed in step 1.
4. In the lose branch, keep the current behaviour exactly: `push_back_prob(idx)`
   (promotee stays probationary, recency refreshed), protected segment
   untouched.

`prot_head` is no longer needed for the comparison but is still the segment
anchor used elsewhere, so leave `sample_prot_demotee` and all linking helpers
unchanged. Preserve the `None` (no protected segment) branch verbatim. The net
effect: the contest compares the promotee against the node that would actually
leave, never displacing a hotter resident, but admitting warming keys the
head-based gate spuriously blocked.

## Rationale (optional)

Every SLRU steering point has been probed except the *coherence* between the
promotion gate's comparison target and its demotion target. This is not a new
mechanism but a correctness alignment of the existing one, and it fires
precisely on the "head hides a colder neighbour" case the demotion sampler was
built to exploit — the one rare event prior cycles identified as where any lever
can still move.
