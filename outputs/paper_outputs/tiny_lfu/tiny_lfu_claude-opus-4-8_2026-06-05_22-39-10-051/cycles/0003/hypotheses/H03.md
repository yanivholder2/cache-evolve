# H03

An admission-only doorkeeper with a long clear window — filtering one-hit-wonder arrivals without ever touching the main frequency counters — raises hit-rate by blocking churn keys that would otherwise evict warmer residents.

## Parent

cycle/0002/v003

## Changes

In `src/tiny_lfu/mod.rs`, add a small separate bit-array doorkeeper used *only*
at admission, deliberately distinct from cycle 0002's refuted doorkeeper (which
gated/cleared the main count-min counters). Concretely:

- Add a `doorkeeper: Vec<u64>` bloom-style bit array sized to roughly the
  sketch width, plus a `doorkeeper_ops: usize` counter, both initialized in
  `try_new`.
- In `put`, on the eviction branch only (the `else` where the cache is full and
  a new key is not already present), before the existing
  `incoming_freq > victim_freq` test, check the doorkeeper for the incoming
  key. If the key's doorkeeper bit is NOT yet set, set it, reject admission for
  this occurrence (do not evict the victim), and return. If the bit IS already
  set (the key has been seen at least once recently), fall through to the
  existing frequency comparison unchanged. This requires a key to appear twice
  within the clear window before it can ever displace a resident.
- Implement a *long* clear window: every time `doorkeeper_ops` reaches a
  threshold of `capacity * 8` admission-path checks, zero the entire
  doorkeeper bit array and reset the counter. This window is much longer than
  cycle 0002's, so warming keys are not repeatedly stripped.

Critically, the main `CountMinSketch` (increment on every get/put, estimate,
width/depth) is left completely untouched — the doorkeeper never resets,
decays, or gates the long-term frequency signal. Preserve all existing
victim-selection logic for keys that pass the doorkeeper.

## Rationale (optional)

The cross-cycle notes explicitly flag an admission-only doorkeeper with a long
clear window as the one parked mechanism worth isolating. Building it on top of
v003's wider, more accurate sketch tests it in the best available context while
honoring the rule that the main counters are never reset.
