# H02

Divide the cache into age cohorts and always evict from the oldest cohort first to improve hit-rate by ensuring that replacement targets genuinely stale items before touching items in active working sets.

baseline

## Changes

In the victim-selection loop within the `put()` method (where capacity is full), implement age-bucketed hierarchical eviction:

1. Compute the age (current_time - last_access_time) for all cached items.
2. Divide items into four age cohorts based on their position in the sorted age distribution:
   - Cohort 1 (oldest 25%): items with age in the top quartile
   - Cohort 2 (older 25%): items in the second quartile
   - Cohort 3 (recent 25%): items in the third quartile
   - Cohort 4 (newest 25%): items in the bottom quartile
3. Victim selection proceeds in cohort order:
   - Iterate through Cohort 1 items and compute the eviction score `(age as f64) / (frequency + 2.0)` for each
   - Select the item with the highest score from Cohort 1 as the victim
   - If Cohort 1 is empty (should not occur), move to Cohort 2 and repeat
4. Keep the admission gate logic unchanged: `incoming_freq > victim_freq`.

## Rationale

The current victim-selection algorithm scores all items globally and can occasionally evict items from the middle of the working set if they happen to have high age relative to their frequency. This hypothesis tests whether a hierarchical age-first approach can improve hit-rate by imposing an ordering constraint: genuinely old items must be exhausted before newer items are considered for eviction. This is distinct from frequency-tiering (which H02 in Cycle 0007 showed regresses) because it partitions by age, not frequency, and because age is known to be orthogonal to frequency in this cache (confirmed by Cycle 0005). The four-cohort structure trades off implementation overhead for finer-grained age distinction, allowing the algorithm to preferentially target the tail without abandoning frequency-age scoring within each cohort.
