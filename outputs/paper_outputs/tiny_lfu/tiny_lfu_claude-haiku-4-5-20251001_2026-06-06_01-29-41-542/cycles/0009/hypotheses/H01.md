# H01

Tighten the frequency-cohort threshold to 15th percentile to reduce eviction of warm-but-old items and improve hit-rate.

## Parent

cycle/0008/v001

## Changes

In the victim-selection loop within the `put()` method, modify the percentile calculation that partitions the cold-item cohort. Replace the 25th-percentile threshold computation with a 15th-percentile threshold to create a tighter, more selective cold-item pool.

Specifically, change:
```
let percentile_25_idx = (frequencies.len() * 25) / 100;
```
to:
```
let percentile_15_idx = (frequencies.len() * 15) / 100;
```

And update the filtering condition:
```
if victim_freq <= percentile_25 {
```
to:
```
if victim_freq <= percentile_15 {
```

Keep all other logic intact: the first-pass cold-cohort scoring, the fallback full-cache scan, the admission gate threshold, and the age/(frequency+2) formula.

## Rationale

Cycle 0008 demonstrated that the 25th-percentile frequency-cohort partitioning breaks the locked optimum by explicitly targeting cold items. The open question directly asks whether the 25th percentile is optimal. This hypothesis tests the conservative direction: a tighter threshold (15th percentile) may reduce contamination of warm-but-old items in the victim pool, ensuring only genuinely unused items are eviction targets before touching moderately-warm residents. This targets the precision side of the cold-cohort trade-off.
