# H03

Broaden the frequency-cohort threshold to 40th percentile to capture more candidate victims and improve hit-rate when the 25th percentile is overly selective.

## Parent

cycle/0008/v001

## Changes

In the victim-selection loop within the `put()` method, modify the percentile calculation that partitions the cold-item cohort. Replace the 25th-percentile threshold computation with a 40th-percentile threshold to create a broader cold-item pool.

Specifically, change:
```
let percentile_25_idx = (frequencies.len() * 25) / 100;
```
to:
```
let percentile_40_idx = (frequencies.len() * 40) / 100;
```

And update the filtering condition:
```
if victim_freq <= percentile_25 {
```
to:
```
if victim_freq <= percentile_40 {
```

Keep all other logic intact: the first-pass cold-cohort scoring, the fallback full-cache scan, the admission gate threshold, and the age/(frequency+2) formula.

## Rationale

Cycle 0008's breakthrough with frequency-cohort partitioning at 25th percentile established the architectural approach, and the open question directly asks whether other percentiles (specifically 10th or 50th) would improve hit-rate further. This hypothesis tests the permissive direction: a broader threshold (40th percentile) may capture borderline items that should be eviction targets but fall just outside the 25th-percentile cold pool. On workloads where the frequency distribution has a gentler slope or longer transition zone from cold to hot, a wider cold-item pool could reduce false positives (keeping items that are actually not part of the working set). This tests the recall side of the cold-cohort trade-off.
