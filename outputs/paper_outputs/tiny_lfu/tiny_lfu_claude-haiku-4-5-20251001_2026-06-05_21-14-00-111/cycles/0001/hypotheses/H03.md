# H03

Use probabilistic admission for items within one frequency count of the victim to smooth the admission boundary and capture phase-shifted workloads.

## Changes

In `src/tiny_lfu/mod.rs`, replace the deterministic admission check at line 93:

```rust
if incoming_freq > victim_freq {
```

with a probabilistic variant:

```rust
let freq_gap = incoming_freq.saturating_sub(victim_freq);
let should_admit = match freq_gap {
    0 => {
        // Equal frequency: admit with 50% probability using a simple deterministic hash-based choice
        let hash_val = (key.hash(hasher) as usize) ^ self.nodes.len();
        hash_val % 2 == 0
    },
    _ if incoming_freq > victim_freq => true,  // Incoming strictly hotter: always admit
    _ => false,  // Incoming colder: never admit
};
if should_admit {
```

This softens the hard admission boundary to allow items competing at equal frequency to have a probabilistic chance of readmission. The hash-based decision is deterministic and reproducible given the same key and cache state, avoiding external RNG dependencies. This targets workloads with phase shifts where tied-frequency items represent genuine alternating access patterns.
