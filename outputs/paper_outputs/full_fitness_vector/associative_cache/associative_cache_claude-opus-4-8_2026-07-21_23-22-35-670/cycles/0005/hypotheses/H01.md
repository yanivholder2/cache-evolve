# H01

Replace move-to-back-on-hit with single-step promotion so hot items must earn their way out of the eviction zone, raising hit-rate above the 0.7182 stateless-front incumbent.

## Parent

cycle/0003/v003

## Changes

v003 keeps ClassicLRU's `get_from_position` (remove + push-to-back) while
overriding the concrete bucket's `put` to insert misses at index 0 (the
eviction end). Change only the promotion geometry, not admission:

- Override `get_from_position` on `AssociativeCacheBucket` so a hit at
  `position` swaps the item one slot toward the back
  (`items.swap(position, position + 1)` when `position + 1 < items.len()`,
  else leave it in place) and returns the new index. Do **not** relocate the
  item all the way to the back.
- Keep front admission (`items.insert(0, item)`) and eviction at index 0
  exactly as v003 has them.

The effect is gradual promotion: a scan item touched once climbs only a
single slot and is still evicted soon, while a genuinely hot key repeatedly
hit ratchets toward the protected back. This is a pure base-ordering change
on the promotion axis — the axis cycle 4 flagged as the only remaining
source of hit-rate headroom.

Invariants to preserve: no new `Item` fields (metadata stays at the 16-byte
floor), O(1) per hit (single swap, no scan), and eviction still removes the
index-0 probationary item.

## Rationale (optional)

Move-to-back grants full protection on the first touch, which over-rewards
one-hit scan noise; single-step promotion demands sustained reuse before an
item leaves the eviction zone, a frequency-like signal bought purely from
ordering with zero per-item state.
