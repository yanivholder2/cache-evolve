# H03

Restructure each bucket into probationary and protected segments (SLRU) so scan items never displace twice-hit items, lifting hit-rate above the segment-free front-admission ceiling.

## Parent

baseline

## Changes

Give `AssociativeCacheBucket` a genuine two-segment ordering instead of the
single ClassicLRU list. Orientation: index 0 is the eviction end; higher
indices are more protected. Add one off-`Item` field to the bucket struct,
`protected_len: usize`, initialised to 0. The protected segment occupies the
top `protected_len` indices `[len - protected_len, len)`; the probationary
segment is `[0, len - protected_len)`. Cap protected at
`max(1, bucket_size / 2)`.

- Override the concrete bucket's `put`: a miss inserts at index 0
  (probationary oldest). `protected_len` is unchanged (the new item is
  probationary). Eviction always removes index 0 — a probationary item is
  never chosen while any probationary item exists.
- Override `get_from_position`: on a hit,
  - if the item is already in the protected segment, move it to the very back
    (protected MRU) via an index-preserving rotation, leaving `protected_len`
    unchanged;
  - if the item is probationary, promote it into the protected segment by
    rotating it to index `len - protected_len` and incrementing
    `protected_len`; if that exceeds the cap, demote the protected LRU (the
    item now at `len - protected_len`) back to probationary MRU by
    decrementing `protected_len` (a pure boundary move, no data shuffle
    needed beyond the rotation).
- Keep eviction at index 0 unconditionally.

Invariants: `Item` stays key+value (16-byte metadata floor — `protected_len`
lives on the unmeasured bucket struct); `protected_len <= items.len()` and
`<= cap` at all times; all relocations are single-element rotations, not
scans or rebuilds, so per-op cost stays bounded by bucket_size.

## Rationale (optional)

Front-admission plus move-to-back is a degenerate SLRU with a zero-width
protected floor: any single hit fully protects. A real protected segment with
a demotion rule gives twice-hit hot keys a reservation that one-hit scan
bursts cannot evict, which is the classic 2Q/S3-FIFO win the cross-cycle
notes flagged as reachable without per-item state.
