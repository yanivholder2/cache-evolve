# H03

Drop the 16-byte Instant timestamp from Item, shrinking Item<u64,u64> from 40 to 24 bytes to improve the metadata-size dimension.

## Parent

baseline

## Changes

Target the metadata-size fitness dimension (currently summary 40 bytes for
`Item<u64,u64>`), which is dominated by the 16-byte `timestamp: Instant` field.
The eval path uses `ClassicLRU`, which never reads `timestamp`, so removing it
is free on hit rate.

Overlay two writable files:

1. `src/shared/item.rs`: delete the `timestamp: Instant` field from the `Item`
   struct, remove its initialization in `Item::new`, drop the
   `use std::time::Instant`, and remove `timestamp` from the `Display` format
   string. Keep `key`, `value`, and `lfu_counter`; leave `PartialEq`/`Eq`
   (key+value equality) unchanged. This drops `Item<u64,u64>` to 24 bytes
   (8 + 8 + 8) with no `Instant`-driven 16-byte alignment slack.

2. `src/shared/eviction_policy.rs`: the `TimestampLRU` impl currently reads and
   writes `item.timestamp`, which no longer exists, so reimplement it to compile
   without timestamps. Keep the `TimestampLRU` type name and its
   `EvictionPolicyKind` variant/index/name intact (JNI ordinals must not shift),
   but make its three methods delegate to insertion-order semantics identical to
   `Fifo`: `get_from_position` returns `position` unchanged,
   `eviction_candidate_index` returns `0`, `promotion_candidate_index` returns
   `items.len() - 1`. Do not touch `ClassicLRU`, `Lfu`, `Lifo`, `Fifo`, or
   `Swap`.

Update any inline `#[cfg(test)]` assertions in `eviction_policy.rs` and
`associative_cache_bucket.rs`/`bucket.rs` that assert timestamp-ordered eviction
so they match the new insertion-order `TimestampLRU` semantics. All four
invariants (P1–P4) still hold: capacity, slot-legality, and phantom-item
behaviour are unaffected by the field removal, and geometry is unchanged.
