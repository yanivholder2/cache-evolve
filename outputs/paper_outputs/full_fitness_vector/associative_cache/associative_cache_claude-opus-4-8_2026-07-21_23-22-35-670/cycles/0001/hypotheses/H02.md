# H02

Protect items that have been reused at least once from eviction so one-hit-wonder scan entries are evicted first, raising hit rate under the workload's scan pattern.

## Parent

baseline

## Changes

Overlay `src/shared/eviction_policy.rs`, modifying **only** the `ClassicLRU`
implementation (leave `TimestampLRU`, `Lifo`, `Lfu`, `Fifo`, `Swap`, and the
`EvictionPolicyKind` enum — its variants, `index`, `name`, `all` — untouched so
JNI ordinals and names are unchanged).

Give `ClassicLRU` a frequency-protection tweak that reuses the existing
`Item.lfu_counter` field (so no change to item layout or metadata size):

- `get_from_position`: keep the current move-to-back behaviour
  (`remove(position)` then `push`), but after pushing, increment the moved
  item's `lfu_counter` via `items.last_mut().unwrap().lfu_counter += 1` to mark
  it as reused. Return `items.len() - 1`.
- `eviction_candidate_index`: scan the items front-to-back and return the index
  of the first item whose `lfu_counter == 0` (a never-reused entry, evicted
  in LRU-front order among such entries). If every resident item has
  `lfu_counter >= 1`, fall back to returning `0` (the classic LRU front).
- `promotion_candidate_index`: unchanged (`items.len() - 1`).

This preserves P1 (no capacity change), P2 (no key moves across buckets), and
P3 (residents stay retrievable). The hypothesis is that on the LIRS-style
workload-a trace, protecting reused items while preferentially discarding
single-touch entries improves scan resistance and lifts hit rate above the
0.6611 ClassicLRU baseline, at negligible per-op cost (one extra counter compare
per candidate). Update any inline `#[cfg(test)]` assertions in this file that
encode the old ClassicLRU eviction order to match the new behaviour.
