# H02

Break ties among fully-protected buckets by evicting the least-frequently-reused item using the already-present `lfu_counter`, probing for hit-rate headroom beyond binary protection at zero extra metadata cost.

## Parent

cycle/0002/v001

## Changes

v001's scan-resistant `ClassicLRU` already increments `item.lfu_counter` on
every hit (its reuse marker) but only ever reads it as a binary predicate:
`eviction_candidate_index` returns the first slot with `lfu_counter == 0`,
and when *every* resident item has been reused it falls back blindly to the
LRU front (index 0). That fallback discards accumulated frequency
information that v001 is already paying to maintain.

In `src/shared/eviction_policy.rs`, change only the `ClassicLRU`
`eviction_candidate_index` impl:

- First pass unchanged: if any resident item has `lfu_counter == 0`, evict
  the first such (front-most one-hit-wonder). This preserves v001's proven
  scan-resistance exactly.
- New behaviour only when the bucket is fully protected (no zero-counter
  item): instead of returning index 0, return the index of the item with
  the minimum `lfu_counter`, breaking ties toward the front (lowest index).
  This evicts the least-frequently-reused hot item rather than the merely
  oldest one.

Leave `get_from_position` (increment + move-to-back) and
`promotion_candidate_index` untouched, so this is purely a refinement of the
victim choice on saturated hot buckets. `Item` layout is unchanged
(metadata-size stays 24). Note this is not aging/second-chance (which failed
in cycle 2): counters are never decayed or reset, so permanent protection is
preserved — the counter is used only as a tiebreak, not to shed immunity.

Success = hit-rate strictly above v001's 0.7267 with metadata-size still 24.

## Rationale (optional)

Tests the open question "is there hit-rate headroom beyond binary
protection?" using a field the winner already maintains, so the probe is
byte-free and preserves the mechanism the cross-cycle notes say must not be
weakened.
