# H01

Replace v001's O(n²) key-matched `realign_reuse` with an index-preserving permutation of the reuse bits to cut the per-op-time p99 tails while holding hit-rate at 0.7267 and metadata at 16.

## Parent

cycle/0003/v001

## Changes

In the overlaid `src/associative_cache/associative_cache_bucket.rs`, rework
`get_from_position` so the `reuse: Vec<bool>` set is moved by mirroring the
policy's single-element relocation instead of rebuilt by key search.

Concretely: `self.eviction_policy.get_from_position(&mut self.items, position)`
returns the item's new index after the policy relocated the element from
`position`. Both eval-relevant policies do a single-element move — `ClassicLRU`
removes at `position` and pushes to the back, `Swap` swaps `position` with
`position-1`. Mirror that on the parallel bit vector with the same shape of
operation: `let bit = self.reuse.remove(position); self.reuse.insert(index, bit);`
then set `self.reuse[index] = true`. This reproduces the exact
`reuse[i] ↔ items[i]` correspondence in O(n) (a single `Vec::remove` + `Vec::insert`)
rather than the current O(n²) per-item `find`-by-key rebuild.

Delete the `realign_reuse` helper and the `before` snapshot allocation in
`get_from_position` entirely. Keep `eviction_candidate_index` (first LRU-front
slot with `reuse == false`, else index 0), `remove_at` (which already keeps
`reuse` aligned), and `put` (push at back, `reuse.push(false)`) unchanged.
Preserve the invariant `reuse.len() == items.len()` at every exit. `Item` stays
key+value only, so metadata-size remains 16.

## Rationale (optional)

Both cycle-0003 and cross-cycle insights name this exact fix as the open
continuation: v001 already reaches 0.7267 at the 16-byte floor; its only tax is
the quadratic rebuild that inflates p99. An index-preserving swap should recover
v003-clean tails without losing the explicit-protection hit-rate.
