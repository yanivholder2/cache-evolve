# H03

Add saturation-triggered lazy demotion — clear the reuse mask only when a bucket is fully protected at eviction time — to re-open stale-protected slots and test for hit-rate headroom without the falsified aggressive-aging cost.

## Parent

cycle/0009/v002

## Changes

The incumbent grants permanent one-hit protection: once a slot's reuse bit is
set it stays set until the item is evicted, and `eviction_candidate_index`
falls back to evicting index 0 (global LRU front) only when *every* resident
bit is set. Prior hit-rate probes that weakened this protection failed because
they aged/demoted bits on a schedule or per-access, shedding immunity in the
common case where protection is doing useful work. This hypothesis weakens
protection in exactly one narrow regime the sweep never isolated: the moment a
bucket is *fully* saturated with protected items, where the binary signal has
lost all discriminating power (it cannot rank the survivors).

In `src/associative_cache/associative_cache_bucket.rs`, change only the
eviction path:

- Keep `eviction_candidate_index` returning the frontmost unreused slot
  (`unreused = !reuse_mask & live`, `trailing_zeros`) whenever `unreused != 0` —
  the common, well-tuned case is untouched.
- When `unreused == 0` (fully protected), still select index 0 as the victim as
  today, but additionally mark the bucket for an epoch reset so the *next*
  round re-discriminates: after `remove_at` completes for a
  fully-protected eviction, set `reuse_mask = 0` (clear all surviving bits).
  Implement this by having `evict_item`/`remove_at` detect the fully-protected
  condition (e.g. compute `live` before removal, compare `reuse_mask & live ==
  live`) and, when true, zero the mask after the item is removed and the
  remaining bits are re-aligned by `mask_remove`.
- Preserve every existing invariant: bits at positions `>= len` stay 0, the
  mask stays index-aligned with `items`, and the `bucket_size <= 64` assertion
  is unchanged. Freshly inserted items remain unprotected as before, so after a
  reset the resident hot set must re-earn protection on its next hit.

No change to `put`, `get_from_position`, the hash, the policy, or `Item` — the
metadata floor (16) and latency floor (100) are inherited untouched; only the
victim-quality behaviour in the saturated regime changes.

## Rationale (optional)

Under permanent protection a bucket that fills with once-hit keys degenerates to
plain LRU-front eviction and can pin keys that went cold long ago. Resetting the
mask only at full saturation forces the currently-resident set to re-prove
reuse, discarding stale protection precisely when it is worthless — a targeted
test of whether any hit-rate headroom survives above the "firm" ceiling without
paying the per-access aging cost that regressed before.
