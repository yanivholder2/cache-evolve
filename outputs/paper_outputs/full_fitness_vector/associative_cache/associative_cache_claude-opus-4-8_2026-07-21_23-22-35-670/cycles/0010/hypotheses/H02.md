# H02

Repartition the fixed capacity budget into more, narrower sets via the geometry seam to test whether increased set diversity lifts hit-rate above the SLRU ceiling.

## Parent

cycle/0009/v002

## Changes

The frontier has only ever pushed bucket width *up* (wider buckets, which
coarsen the hash spread and regress), leaving the opposite direction —
more sets, each narrower — untested, even though the cross-cycle note states
"set diversity beats per-set depth here." The `src/shared/geometry.rs` file is
the explicitly overlayable extension point for exactly this: `resolve_geometry`
in `factory.rs` calls `BaselineGeometry::for_settings(settings).layout(budget)`
and enforces only that the returned `(num_of_buckets, bucket_size)` conserve the
total `budget = num_of_buckets * bucket_size`.

Overlay `src/shared/geometry.rs` only. Keep the `BaselineGeometry` type name,
its `for_settings` constructor signature, and the `BucketGeometry` impl (the
construction glue and the invariant gate both reference them). Change the
`layout(&self, total_capacity: usize)` body so that instead of returning
`(self.num_of_buckets, self.bucket_size)` unchanged, it repartitions toward
narrower sets while conserving `total_capacity`:

- While `bucket_size` is even and `> 1` and `bucket_size / 2 >= 1`, halve
  `bucket_size` and double `num_of_buckets` — do this for one or two doublings
  (i.e. quarter the bucket width, quadruple the set count) so the split lands at
  a genuinely narrower associativity than the harness default.
- Guard the invariants the seam must preserve: the returned product must equal
  `total_capacity` exactly, both returned values must be `>= 1`, and the
  resulting `bucket_size` must stay `<= 64` (it only shrinks here, so this is
  automatically satisfied) so the incumbent `u64` reuse-mask still fits one bit
  per slot.
- If `bucket_size` is not evenly divisible (odd), fall back to returning the
  harness split unchanged so `check_conservation` never rejects the variant.

Do not touch `associative_cache_bucket.rs` or any policy file — the bucket
internals (u64 reuse-mask, one-hit protection) are inherited from the parent
unchanged; only the buckets-vs-slots factoring of the same total budget moves.

## Rationale (optional)

Narrower sets trade per-set depth for a finer hash partition. On a scan-heavy
LIRS trace, more independent sets can localize conflict pressure and keep hot
keys resident that a deeper shared bucket would let a scan flush — the one
structural hit-rate lever the sweep has approached only from the losing (wider)
side.
