# H01

Widening the buckets (fewer, larger buckets over the same total capacity) gives the segmented incumbent more slots per set and raises hit-rate above the SLRU ceiling.

## Parent

cycle/0006/v001

## Changes

Overlay `src/shared/geometry.rs` only — leave the SLRU bucket
(`associative_cache_bucket.rs`), `item.rs`, and `eviction_policy.rs`
exactly as the parent `cycle/0006/v001` left them so the 16-byte `Item`
floor and the segmented put/get logic are inherited unchanged.

Change `BaselineGeometry::layout` so that instead of returning the
harness-provided split verbatim it re-factorises the **same total
capacity** into fewer, wider buckets. Concretely: derive a new
`bucket_size` by multiplying the harness `bucket_size` by a small factor
(start with 2, i.e. double the associativity) and a new `num_of_buckets`
by dividing the harness count by the same factor. Compute this from the
`total_capacity` argument passed into `layout`, not from the stored
fields, so the product invariant holds by construction.

Hard requirements (the invariant gate's P4 capacity_conservation will
reject a violation, so guard them explicitly):
- `new_num_of_buckets * new_bucket_size == total_capacity` exactly.
- Both values `> 0`.
- If the factor does not divide evenly, fall back to the largest factor
  that keeps the product equal (e.g. pick a divisor of the harness
  `num_of_buckets`); never round in a way that changes the product.

Keep the `BaselineGeometry` struct name and its `for_settings`
constructor signature intact — construction glue and the gate both build
the geometry through them.

The motivation: cross-cycle insights repeatedly attribute the SLRU
hit-rate ceiling to "short associative buckets lacking the slots for
gradual promotion." This is the first hypothesis to test the geometry
lever directly rather than the per-bucket policy. Watch per-op-time:
`get_position` and the SLRU rotations are linear in `bucket_size`, so a
wider bucket could push the p99 tail; if the summary per-op-time metric
regresses past 100 the trade is not worth it, but at these sizes the
scan should stay cheap.
