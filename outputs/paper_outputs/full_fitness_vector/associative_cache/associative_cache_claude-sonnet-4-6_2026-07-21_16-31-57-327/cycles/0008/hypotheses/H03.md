# H03

Reversing the scan direction in `eviction_candidate_index` to iterate inward-to-outward (from the warmest position in the scan window toward the coldest tail) will improve hit rate by preferring the oldest never-accessed item as the eviction victim rather than the most-recently-inserted never-accessed item, aligning cold-item eviction with LRU semantics.

## Parent

cycle/0006/v003

## Changes

In `src/shared/eviction_policy.rs`, `ClassicLRU::eviction_candidate_index`, change the loop to remove the `.rev()` reversal:

```rust
// Current: scans from position len-1 inward (coldest first)
for i in (len - scan_depth..len).rev() {
    if items[i].lfu_counter == 0 {
        return i;
    }
}

// New: scans from position len-scan_depth outward (oldest-cold first)
for i in len - scan_depth..len {
    if items[i].lfu_counter == 0 {
        return i;
    }
}
```

The scan depth (`len.min(8)`), the condition (`lfu_counter == 0`), and the fallback (`len - 1`) all remain identical. Only the iteration order within the scan window changes.

Also include `src/shared/item.rs` in the overlay, carrying it forward verbatim from the `cycle/0006/v003` overlay (32-byte `#[repr(C)]` struct: `key`, `value`, `lfu_counter: usize`, `_pad: u64`). Do not modify it.

No changes to `get_from_position`, `promotion_candidate_index`, the scan depth, the trait, or any other file.

## Rationale

The current scan iterates from `len-1` downward, returning the first cold item encountered. Because items with `lfu_counter == 0` cluster at the absolute cold tail (`len-1`) immediately after insertion, the current scan evicts them in last-in-first-out order: the most recently inserted cold item is always evicted first. This is at odds with LRU semantics, which dictate that the OLDEST unaccessed item should be evicted. A cold item at position `len - scan_depth` (the inner edge of the scan window) has survived more eviction cycles than a cold item at `len-1`: it was inserted earlier, never accessed, and then carried toward the hot zone by passive displacement during neighbouring items' 3-swap promotions. Evicting it first (reversed scan) is therefore more faithful to LRU ordering among cold candidates. This hypothesis provides symmetric coverage of the cold-selection design space alongside H01 (window reduction) and H02 (window expansion), testing a qualitatively different dimension — selection order — rather than window geometry.
