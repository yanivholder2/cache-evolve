# H01

Teleporting first-touch cold-zone items directly to the warm-cold boundary on their first access improves hit rate by ensuring once-accessed items immediately escape the second-chance scan's eviction window.

## Parent

cycle/0008/v003

## Changes

Modify `get_from_position` in the `ClassicLRU` impl inside `src/shared/eviction_policy.rs`.

Split the current single promotion path into two branches based on whether this is the first access:

**First-touch path (`lfu_counter == 0`):** Set `lfu_counter = 1`, then move the item to the warm-cold boundary via a swap loop rather than the fixed 3-swap loop. The boundary position is `items.len().saturating_sub(scan_depth + 1)` where `scan_depth = items.len().min(8)`. Use `while pos > boundary_pos { items.swap(pos, pos - 1); pos -= 1; }` so the item lands at `boundary_pos` regardless of how deep in the cold zone it started. Do not apply the standard 3-swap cap on this path.

**Repeat-access path (`lfu_counter == 1`):** Apply the existing 3-swap promotion loop unchanged (`for _ in 0..3 { items.swap(pos, pos-1); pos -= 1; if pos == 0 { break; } }`).

The position-0 early-return guard (`if position == 0 { return 0; }`) must remain at the top of the function, unchanged.

The `eviction_candidate_index` function is unchanged: it still scans `len - scan_depth..len` in forward (LRU-among-cold) order and falls back to `len - 1`.

`src/shared/item.rs` must be carried forward verbatim from `cycle/0008/v003` (32-byte `#[repr(C)]` layout with `_pad: u64`).

**Rationale:** Items in the cold zone with `lfu_counter == 0` are placed there by the eviction path and currently receive only 3 swaps on first access. With a 16-slot bucket and an 8-slot cold window, a first-touch item at position 15 only moves to position 12 — still deep inside the cold zone, still vulnerable to immediate re-eviction. The teleport ensures it clears the cold window entirely on first touch, requiring a genuine re-access to evict it next time.

## Rationale (optional)

The confirmed eviction base evicts items at inner-edge-first (LRU-among-cold) order. A cold item at the inner edge of the window (`len - 8`) that receives its first access during a scan cycle gets promoted 3 positions to `len - 11` — safely outside the window. But a cold item at the tail (`len - 1`) that receives its first access only reaches `len - 4`, which is still INSIDE the cold window. Teleporting to the boundary position eliminates this positional dependency: any first-touch item, regardless of depth, immediately exits the cold zone and gains a full eviction cycle's worth of protection.
