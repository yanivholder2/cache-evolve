# H01

Pairing the write-once second-chance flag with a single positional swap per access will preserve v003's hit-rate lift while eliminating the multi-swap write pressure that raises per-op-time.

## Parent

cycle/0006/v003

## Changes

Modify `ClassicLRU::get_from_position` in `src/shared/eviction_policy.rs`.

Starting from v003's overlay, make exactly one change: replace the three-iteration promotion loop with a single unconditional swap. The write-once flag write and the position-0 early return stay identical to v003.

Before (v003):
```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;
    }
    if items[position].lfu_counter == 0 {
        items[position].lfu_counter = 1;
    }
    let mut pos = position;
    for _ in 0..3 {
        items.swap(pos, pos - 1);
        pos -= 1;
        if pos == 0 {
            break;
        }
    }
    pos
}
```

After (H01):
```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;
    }
    if items[position].lfu_counter == 0 {
        items[position].lfu_counter = 1;
    }
    // Single swap only — one step toward head, no loop.
    items.swap(position, position - 1);
    position - 1
}
```

Leave `eviction_candidate_index` and `item.rs` unchanged from v003 (second-chance scan up to 8 items from the cold tail, write-once `lfu_counter` field, 32-byte `#[repr(C)]` layout).

The invariant to preserve: the flag is still written on first touch (counter 0 → 1) before the swap, so the item carries its "ever-accessed" marker regardless of how far it travels. The `eviction_candidate_index` second-chance scan remains the hit-rate lever; only the per-get write volume is reduced.

## Rationale

Cycle 0006's insight identified that the per-op-time regression in v003 traces to the three-swap loop, not the second-chance flag. Reducing to one swap per access recovers the position-0 guard pattern from Cycle 0003 while keeping the flag mechanism intact. If the second-chance scan is the dominant hit-rate driver, one swap should suffice to keep hot items out of the scan window while halving per-get write volume relative to v003.
