# H02

Removing all positional promotion swaps and relying solely on the write-once second-chance flag to discriminate cold from warm items will test whether eviction-candidate quality alone sustains hit rate near v003's level without any per-get movement cost.

## Parent

cycle/0006/v003

## Changes

Modify `ClassicLRU::get_from_position` in `src/shared/eviction_policy.rs`.

Starting from v003's overlay, replace the entire body of `get_from_position` with a write-once flag write followed by an immediate return of the original position. No swaps, no loop, no position-0 early return branch (the unified path handles position 0 correctly because the flag write is guarded by `counter == 0`).

Before (v003):
```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;
    }
    if items[position].lfu_counter == 0 {
        items[position].lfu_counter = 1;
    }
    let mut pos = position;
    for _ in 0..3 {
        items.swap(pos, pos - 1);
        pos -= 1;
        if pos == 0 {
            break;
        }
    }
    pos
}
```

After (H02):
```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    // Write-once flag: 0 → 1 on first access only. No positional movement.
    if items[position].lfu_counter == 0 {
        items[position].lfu_counter = 1;
    }
    position
}
```

Leave `eviction_candidate_index` and `item.rs` unchanged from v003 (second-chance scan up to 8 items from the cold tail, 32-byte `#[repr(C)]` layout).

Invariants to preserve: the flag write is still guarded (`counter == 0` check), so it is a single write on first access and a no-op on subsequent accesses — the hot path remains write-free after warmup. Without promotion, bucket order becomes pure insertion order (FIFO), so positional index reflects age since last eviction cycle rather than recency of access. The second-chance scan continues to skip counter==1 items and evict counter==0 (never-accessed) items from the tail zone; the fallback on full-warm buckets is still position `len - 1`.

## Rationale

Cycle 0006 explicitly posed this experiment: "Does a zero-swap get path combined with the second-chance eviction scan still outperform strict LRU, or does recency ordering degrade too quickly without any promotion?" Without promotion, positional order reflects insertion age; the second-chance flag becomes the sole mechanism for distinguishing cold items (counter==0, never accessed) from warm ones (counter==1, accessed at least once). If the flag's discrimination is strong enough on this Zipfian workload, hit rate should remain elevated while per-op-time drops to the write-only-once-per-item baseline.
