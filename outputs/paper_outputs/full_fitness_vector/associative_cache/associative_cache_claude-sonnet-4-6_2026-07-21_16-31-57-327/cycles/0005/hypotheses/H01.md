# H01

Extending the per-access promotion budget from one unconditional swap to three unconditional swaps will lift hit rate beyond cycle/0004/v002's 0.714 by letting mid-bucket items converge to the head zone faster under Zipfian access patterns.

## Parent

cycle/0004/v002

## Changes

In `eviction_policy.rs`, modify `ClassicLRU::get_from_position` to replace the single `items.swap(position, position - 1)` call with a loop of up to 3 unconditional swaps toward index 0 (the head). Retain the `if position == 0 { return 0; }` early-exit guard. Break out of the loop early when `pos` reaches 0 to avoid underflow. No `lfu_counter` reads or writes are introduced — the policy remains purely positional.

The resulting implementation should look like:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;
    }
    let mut pos = position;
    for _ in 0..3 {
        items.swap(pos, pos - 1);
        pos -= 1;
        if pos == 0 {
            break;
        }
    }
    pos
}
```

`eviction_candidate_index` stays unchanged at `items.len() - 1` (pure positional tail eviction). `promotion_candidate_index` stays at 0.

Carry the 32-byte `Item` struct from `cycle/0004/v002` forward unchanged: both `src/shared/item.rs` (with `_pad: u64` and the `size_is_32_bytes_for_u64_keys_and_values` test) and `src/shared/eviction_policy.rs` must be included in the overlay.

## Rationale

v002 (1 swap, 0.714) beat v001 (3 conditional swaps, 0.699), showing that unconditional recency promotion outperforms frequency-gated promotion. The open question is whether *more* unconditional steps are better than one: with a single swap, items at distance 2–3 from the head still converge slowly and risk being evicted before reaching the protected zone. Three unconditional swaps eliminates that convergence lag without reintroducing the frequency gate that stranded recently-reused items in v001. The early-break on `pos == 0` keeps the hot-path cost at one iteration for already-near-head items, mirroring the benefit cycle/0004/v001 demonstrated for the conditional case.
