# H02

Adding `lfu_counter` increments on each access and selecting the eviction candidate via a two-tail frequency comparison (rather than always evicting the positional tail) will lift hit rate beyond cycle/0004/v002's 0.714 by occasionally sparing a recently-reused penultimate item in favour of its colder neighbour.

## Parent

cycle/0004/v002

## Changes

In `eviction_policy.rs`, make two changes to `ClassicLRU`:

**1. `get_from_position`** — before performing the unconditional single-step swap, increment the accessed item's `lfu_counter`:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;  // hot-path early return preserved
    }
    items[position].lfu_counter += 1;   // accumulate frequency signal
    items.swap(position, position - 1); // single unconditional recency step
    position - 1
}
```

**2. `eviction_candidate_index`** — compare the last two items by `lfu_counter` and return the index of the colder one:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    let len = items.len();
    if len < 2 {
        return 0;
    }
    // Prefer evicting the item with the lower accumulated frequency.
    // Tie-breaks to len-1 (the positional tail), preserving the default behaviour.
    if items[len - 2].lfu_counter < items[len - 1].lfu_counter {
        len - 2
    } else {
        len - 1
    }
}
```

`promotion_candidate_index` stays at 0. Carry the 32-byte `Item` struct from `cycle/0004/v002` forward unchanged: both `src/shared/item.rs` (with `_pad: u64`) and `src/shared/eviction_policy.rs` must be included in the overlay.

## Rationale

`cycle/0004/v003` demonstrated that two-tail eviction selection gives a small but real hit-rate lift — but its overlay omitted `item.rs`, reverting to the 40-byte layout and erasing the alignment benefit. More critically, v003 (cycle 4) derived from a parent that tracked `lfu_counter`, so its tail items carried meaningful frequency data. `cycle/0004/v002` never writes to `lfu_counter`, meaning any two-tail comparison on top of v002 would compare all-zero counters and be a no-op. This hypothesis fixes both problems: it re-introduces `lfu_counter` writes (so counters carry real signal) and applies the two-tail comparison correctly, while preserving v002's 32-byte struct and single-step recency promotion.
