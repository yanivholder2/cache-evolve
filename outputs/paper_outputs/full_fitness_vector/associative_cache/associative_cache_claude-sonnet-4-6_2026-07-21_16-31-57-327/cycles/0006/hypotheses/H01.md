# H01

Extending the `ClassicLRU` promotion budget from 3 to 5 swaps per access raises hit rate by allowing items sitting 4–5 positions from the head to converge to the hot zone faster under Zipfian re-access patterns.

## Parent

cycle/0005/v001

## Changes

In `src/shared/eviction_policy.rs`, modify `ClassicLRU::get_from_position` to loop up to 5 swaps instead of 3:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;
    }
    let mut pos = position;
    for _ in 0..5 {          // was 0..3 in v001
        items.swap(pos, pos - 1);
        pos -= 1;
        if pos == 0 {
            break;
        }
    }
    pos
}
```

All other behaviour is identical to cycle/0005/v001:
- `eviction_candidate_index` returns `items.len() - 1` (strict tail eviction)
- `promotion_candidate_index` returns `0`
- `item.rs` stays at the 32-byte `#[repr(C)]` layout with `lfu_counter` unused and `_pad: u64`
- No frequency counter reads or writes on the get path

The early-break on `pos == 0` preserves the hot-path short-circuit: items already at position 0 return immediately with zero iterations, and items 1–2 hops from the head still exit after 1–2 swaps. The extended budget only activates for items that start 4–5 positions from the head.

## Rationale

Cycle 0005's cycle-level open question asks whether diminishing returns set in at 3 swaps or whether 4–5 continue to improve convergence speed. The jump from 1→3 swaps was a clear win (cycle 0004 v001 → cycle 0005 v001 hit-rate 0.719). This hypothesis is the direct measurement at the next rung of the ladder.
