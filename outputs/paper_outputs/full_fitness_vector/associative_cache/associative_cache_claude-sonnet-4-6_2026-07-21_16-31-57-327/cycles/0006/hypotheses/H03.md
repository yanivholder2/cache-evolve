# H03

A write-once "accessed" flag (lfu_counter set to 1 on the very first get only, never incremented again) combined with a bounded second-chance tail scan raises hit rate over strict positional-LRU by protecting recently-inserted items that have been touched at least once from being the first eviction victim.

## Parent

baseline

## Changes

This variant re-implements both `src/shared/item.rs` and `src/shared/eviction_policy.rs` from scratch, incorporating every confirmed structural lesson from cycles 1–5 and adding a novel second-chance eviction step.

### `src/shared/item.rs`

Replace the baseline `Item` struct (which carries an `Instant` timestamp and is 40 bytes) with the compact 32-byte `#[repr(C)]` layout confirmed safe in cycle 0002 onward:

```rust
#[repr(C)]
pub struct Item<K, V> { ... }
// fields: key: K, value: V, lfu_counter: usize, _pad: u64
// sizeof::<Item<u64,u64>>() == 32
```

`lfu_counter` is initialised to `0` in `Item::new`. Remove the `timestamp` field entirely; drop the `use std::time::Instant` import.

### `src/shared/eviction_policy.rs` — `ClassicLRU`

**`get_from_position`**: Implement the 3-swap unconditional loop from cycle/0005/v001, but add a single conditional write that sets `lfu_counter = 1` on the first access to any item, and then never writes it again:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    if position == 0 {
        return 0;  // hot-path early return: no writes
    }
    // Write lfu_counter exactly once per item lifetime (0 → 1).
    // On all subsequent gets the item already has counter == 1, so no write occurs.
    if items[position].lfu_counter == 0 {
        items[position].lfu_counter = 1;
    }
    // 3-swap promotion loop, identical to cycle/0005/v001
    let mut pos = position;
    for _ in 0..3 {
        items.swap(pos, pos - 1);
        pos -= 1;
        if pos == 0 { break; }
    }
    pos
}
```

**`eviction_candidate_index`**: Replace the baseline tail eviction with a bounded second-chance scan. Scan at most the last 8 positions (or `len`, whichever is smaller) from the tail inward. Return the index of the first item found with `lfu_counter == 0` (never accessed since insertion). If all scanned items have been accessed at least once, fall back to the positional tail (`len - 1`) — identical to v001 behaviour:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    let len = items.len();
    let scan_depth = len.min(8);
    // Scan from the tail inward, looking for an un-accessed item
    for i in (len - scan_depth..len).rev() {
        if items[i].lfu_counter == 0 {
            return i;
        }
    }
    len - 1  // all scanned items have been accessed: fall back to LRU tail
}
```

The scan is bounded at 8 iterations regardless of bucket size, so the eviction path remains O(1) in practice.

**All other policies** (TimestampLRU, Lifo, Lfu, Fifo, Swap) must be updated to compile without `timestamp`: remove the `Instant::now()` call from `TimestampLRU::get_from_position` and its `use std::time::Instant` import. Replace `item.timestamp` references in `TimestampLRU` with `item.lfu_counter` (the field previously used for timestamps now serves as a monotonically-bumped counter for TimestampLRU, or simply leave `TimestampLRU` as a no-op get). The simplest safe change: make `TimestampLRU::get_from_position` a no-op (return `position` unchanged) and its `eviction_candidate_index` return `0`, mirroring the non-timestamp behaviour already tested. The focus of this variant is `ClassicLRU`; the other policies exist only to satisfy the `EvictionPolicyKind` enum and tests.

`src/shared/geometry.rs` is unchanged (baseline identity geometry). Do not touch `src/factory.rs`, `src/lib.rs`, `Cargo.toml`, or any test file.

## Rationale

Every past cycle that wrote `lfu_counter` on EVERY get suffered p99 tail-latency pressure. The write-once variant amortises that cost: a cold item's first get triggers a single write (0→1), and every subsequent get on the same item is write-free (counter is already 1). In the Zipfian steady state, the working set of hot items has `lfu_counter == 1` and generates no writes during normal access — matching v001's write-free hot path. The benefit is in the eviction decision: when the bucket is full, the second-chance scan can skip past items that have at least proven their relevance once and evict a truly-cold newcomer instead. This is structurally distinct from the two-tail frequency comparison (which compared counter magnitudes between adjacent items and hurt hit rate in cycles 0004–0005) — here the bit is binary and the scan covers up to 8 candidates, not just 2.
