# H01

Replacing the full bubble loop in `ClassicLRU::get_from_position` with a position-0 early-return guard plus a single conditional swap will eliminate unnecessary cache-line writes for already-hot items and recover per-op-time to near baseline.

## Parent

cycle/0002/v001

## Changes

In `src/shared/eviction_policy.rs`, modify `ClassicLRU::get_from_position` as follows:

1. Add an early-return guard at the top: if `position == 0`, return `0` immediately — the item is already the hottest, so neither the counter write nor a bubble step is needed.
2. For `position > 0`, increment `lfu_counter` **once** then perform **at most one** conditional swap: `if items[position].lfu_counter > items[position - 1].lfu_counter { items.swap(position, position - 1); return position - 1; }` Otherwise return `position` unchanged.
3. Remove the existing `while` loop entirely.

Leave `eviction_candidate_index` (`items.len() - 1`) and `promotion_candidate_index` (`0`) unchanged — the tail still holds the item with the lowest counter under the soft LFU ordering that converges over repeated hits.

The invariant is softened: the bucket may not be perfectly sorted after a single hit, but an item migrates left by one position per hot access, converging to the head after as many hits as its separation from the front. The eviction candidate is still always the least-used item because a hot item will have bubbled past it over time. The key win is that the common case — re-hitting an already-hot item at position 0 — now costs zero memory writes instead of one counter increment plus a neighbor load.

## Rationale

v001 achieved 0.703 hit-rate (well above baseline's 0.661) but regressed per-op-time from 69 ns to 100 ns. The cycle-insight identified "unconditional loop entry on every get" as the cause. The counter write at position 0 dirties the cache line on every repeated hot hit, pushing latency into the next timing bucket. Eliminating that write for the dominant Zipfian hot case is the minimal change needed to recover speed without abandoning the LFU ordering signal.
