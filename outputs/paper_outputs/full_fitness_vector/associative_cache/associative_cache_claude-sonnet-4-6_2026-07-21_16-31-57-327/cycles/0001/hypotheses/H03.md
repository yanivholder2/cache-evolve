# H03

Removing the unused `timestamp: Instant` field from `Item` shrinks per-item metadata from 40 bytes to 24 bytes, cutting the metadata-size fitness dimension by 40%.

## Parent

baseline

## Changes

Two files require edits; all other source files are left untouched.

**1. `src/shared/item.rs`**

Remove the `timestamp` field and its initialisation:

- Delete the `use std::time::Instant;` import line.
- In the `Item` struct body, delete the line `pub timestamp: Instant,`.
- In `Item::new`, delete the field initialiser `timestamp: Instant::now(),`.
- The `Display` impl's format string currently prints `timestamp: {:?}`; remove that clause (and
  its `, self.timestamp` argument) so the formatter no longer references the deleted field.

After the edit `Item<u64, u64>` will contain: `key: u64` (8 bytes), `value: u64` (8 bytes),
`lfu_counter: usize` (8 bytes) — totalling 24 bytes, matching the `higher_is_better: false`
metadata-size dimension.

**2. `src/shared/eviction_policy.rs`**

`TimestampLRU` currently reads and writes `item.timestamp`, which no longer exists. Replace its
three method bodies with position-based (FIFO-order) fallbacks so the code compiles and the
policy remains behaviourally consistent with its "oldest entry is evicted" intent:

- `get_from_position`: return `position` unchanged (no mutation needed).
- `eviction_candidate_index`: return `0` (oldest-inserted position, matching FIFO order).
- `promotion_candidate_index`: return `items.len() - 1` (newest-inserted position).

Remove the `use std::time::Instant;` import from this file if it is no longer used after the
edit.

Do not modify any other policy (`ClassicLRU`, `Lfu`, `Fifo`, `Lifo`, `Swap`), the
`EvictionPolicyKind` enum, the `Bucket` trait, or any file in the protected surface. The
`lfu_counter` field is retained because it is used by the existing `Lfu` policy and costs
only 8 bytes.

## Rationale

`Item` currently carries `timestamp: Instant` (16 bytes on the target platform, verified by the
baseline measurement of 40 bytes for `Item<u64,u64>`). ClassicLRU — the baseline policy — never
reads or writes this field; neither do `ClassicLRU`, `Fifo`, `Lifo`, or `Swap`. Only
`TimestampLRU` uses it, and `TimestampLRU` is not the active policy in the evaluated
configuration. Removing the field makes the struct layout `[key(8), value(8), lfu_counter(8)]`
= 24 bytes, a saving of 16 bytes per cached entry. At the swept cache size of 2048 entries that
is 32 KB recovered. The change is mechanical: no algorithmic behaviour changes for the default
ClassicLRU path.
