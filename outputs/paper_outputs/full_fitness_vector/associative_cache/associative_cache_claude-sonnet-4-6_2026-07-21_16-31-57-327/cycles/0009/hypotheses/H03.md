# H03

Resetting the access flag of the item displaced into the absolute tail (`position len-1` or `len-2`) when promoting from that same deep-cold position prevents stale warm markers from permanently shielding aging items and improves hit rate.

## Parent

cycle/0008/v003

## Changes

One targeted addition to `ClassicLRU::get_from_position` in `src/shared/eviction_policy.rs`. `eviction_candidate_index`, `item.rs`, and all other logic are unchanged.

### Mechanism

When `get_from_position` promotes an item from starting position `position`, the first swap moves the item that was at `position - 1` into `position`. If `position` is `len - 1` or `len - 2` (the two deepest cold positions), the displaced item has just fallen to the absolute tail — a zone from which it is highly unlikely to receive another access before the next eviction. Resetting its `lfu_counter` to 0 at this point clears any stale warm marker it holds, so the subsequent eviction scan can treat it as a never-accessed cold candidate rather than shielding it.

### Implementation

After the 3-swap promotion loop in `get_from_position`, add the following block (using `position`, the parameter — the starting position of the promoted item — not `pos`, the final position after promotion):

```rust
// Flag expiry for deep-cold displacement: when the promoted item started at
// one of the two deepest tail positions, the item displaced into `position`
// (originally at `position - 1`) has fallen to the absolute tail. Expire its
// warm flag so the next eviction scan treats it as a cold candidate.
let len = items.len();
if position >= len.saturating_sub(2) {
    items[position].lfu_counter = 0;
}
```

After the 3-swap loop, `items[position]` holds the item that was originally at `items[position - 1]` (the first swap partner). The condition `position >= len - 2` activates only for accesses that started at the last two positions of the bucket — a small fraction of all hits on a Zipfian workload. The conditional write path is therefore NOT the hot path; it fires only when a genuinely cold or rarely-accessed item gets a hit while sitting at the deepest tail.

### Invariants to preserve

- The write-once flag logic (`if items[position].lfu_counter == 0 { items[position].lfu_counter = 1; }`) remains unchanged and executes **before** the swap loop and **before** the expiry block (the expiry block fires after the swaps have already placed the displaced item at `position`).
- The 3-swap promotion loop with early-break at `pos == 0` is unchanged.
- The `eviction_candidate_index` scan (8-slot, LRU-among-cold, forward direction) is unchanged.
- The `#[repr(C)]` 32-byte struct layout in `item.rs` is unchanged.
- Do not reset the flag of the **promoted item** itself (it was already correctly set to 1 before the swap loop); only reset `items[position]` (the displaced item now occupying the starting position).
