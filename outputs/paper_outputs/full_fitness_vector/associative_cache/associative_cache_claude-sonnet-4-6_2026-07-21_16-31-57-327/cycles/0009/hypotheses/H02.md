# H02

Extending the write-once access flag to a two-generation saturating counter (0 = never, 1 = once, 2 = twice or more) and scanning cold candidates in two priority passes improves hit rate by identifying one-hit wonders as higher-priority eviction targets than confirmed-warm items.

## Parent

cycle/0008/v003

## Changes

Two modifications to `ClassicLRU` in `src/shared/eviction_policy.rs`; `item.rs` is unchanged (`lfu_counter: usize` already holds values 0, 1, 2+, and the 32-byte layout is preserved).

### 1. `get_from_position`: change flag write to two-generation saturation

Replace:
```rust
// Write-once flag: 0 → 1 on first access only.
if items[position].lfu_counter == 0 {
    items[position].lfu_counter = 1;
}
```
With:
```rust
// Two-generation saturation: 0 → 1 on first access, 1 → 2 on second access,
// no write on any subsequent access (counter already at 2).
if items[position].lfu_counter < 2 {
    items[position].lfu_counter += 1;
}
```

This retains the write-on-first-access behaviour and adds one additional write on the second access only. Items accessed twice or more find `lfu_counter == 2` and skip the write entirely — the hot-path is write-free after the second access, identical to the parent for all items beyond their second hit. The total lifetime write budget per item is exactly 2, not per-get.

### 2. `eviction_candidate_index`: change single-pass scan to two-pass prioritised scan

Replace the single forward scan with two sequential forward scans over the same window:

```rust
let len = items.len();
let scan_depth = len.min(8);
// First pass: prefer generation-0 (never-accessed) candidates — highest eviction priority.
for i in len - scan_depth..len {
    if items[i].lfu_counter == 0 {
        return i;
    }
}
// Second pass: prefer generation-1 (accessed exactly once) candidates — one-hit wonders.
for i in len - scan_depth..len {
    if items[i].lfu_counter == 1 {
        return i;
    }
}
// All scanned items are generation-2 (confirmed warm): fall back to the LRU tail.
len - 1
```

Both passes use the same LRU-among-cold (inner-edge-first) direction as the parent. The scan depth and fallback index (`len - 1`) are unchanged from the parent. The only new cost is the second pass, which executes at most 8 comparisons and only when no generation-0 item is found — a rare case on workloads with frequent cold insertions.

### Invariants to preserve

- The `#[repr(C)]` 32-byte aligned struct in `item.rs` must not be modified.
- The 3-swap promotion loop and early-break at position 0 in `get_from_position` are unchanged.
- The scan direction (inner-edge-first, `len - scan_depth..len` forward) must be preserved in both passes.
