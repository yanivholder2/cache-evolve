# H02

Combine wider buckets (64×32) from v002 with FIFO eviction to preserve hit-rate gains while reducing per-operation latency through zero per-hit bookkeeping overhead.

## Parent

cycle/0002/v002

## Changes

Modify two files:

1. **src/shared/geometry.rs** - Ensure `BaselineGeometry::layout()` implements the same repartitioning as v002 (halve bucket count, double bucket size):

```rust
fn layout(&self, total_capacity: usize) -> (usize, usize) {
    let new_num_buckets = self.num_of_buckets / 2;
    if new_num_buckets == 0 {
        return (self.num_of_buckets, self.bucket_size);
    }
    if total_capacity % new_num_buckets == 0 {
        let new_bucket_size = total_capacity / new_num_buckets;
        (new_num_buckets, new_bucket_size)
    } else {
        (self.num_of_buckets, self.bucket_size)
    }
}
```

For baseline (128 × 16 = 2048), this yields 64 × 32 = 2048.

2. **src/associative_cache/associative_cache_settings.rs** - In the `Default` implementation, change the `eviction_policy` field from `EvictionPolicyKind::ClassicLRU` to `EvictionPolicyKind::Fifo`.

Keep all other settings and implementations unchanged.

## Rationale

Variant v002 proved that wider buckets (64×32) improve hit-rate by +0.24% (0.6611 → 0.6635), but paired with ClassicLRU it incurred a -45% latency regression (69→100ns p50 get). This is because ClassicLRU's O(n) vector operations (remove + append) scale poorly as bucket size increases: scanning and moving items in a 32-item bucket is more expensive than in a 16-item bucket.

FIFO eviction performs zero per-hit bookkeeping: cache hits do not move or update items, only evictions (removing the oldest item at position 0) require action. This makes FIFO's cost orthogonal to bucket size in the hot path—a get() is equally fast whether the bucket has 8, 16, or 32 items.

By combining v002's hit-rate-improving geometry with FIFO's latency-efficient policy, this variant should retain the +0.24% hit-rate gain while achieving lower per-operation latency than v002. The result may yield overall fitness gain, since v002 already improved fitness score over baseline (-0.0877 vs. -0.0899) despite latency regression.

Although cycle 0002 v003 tested FIFO on 128×16 and regressed latency, that reflects FIFO on the baseline geometry. FIFO's zero per-hit cost should scale differently (better) to wider buckets than ClassicLRU's movement operations.
