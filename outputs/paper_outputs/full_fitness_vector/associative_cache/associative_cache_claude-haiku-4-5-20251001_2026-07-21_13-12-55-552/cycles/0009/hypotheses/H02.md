# H02

Enable frequency-aware eviction with minimal per-item metadata overhead by using a 1-byte probabilistic Morris counter per item instead of exact frequency tracking to guide victim selection toward cold items.

## Parent

baseline

## Changes

Add a `freq_approx: u8` field (1 byte) to the `Item` struct in `src/shared/item.rs`, replacing exact frequency tracking with a probabilistic Morris counter. Implement Morris-counter increment logic in the get() hot path in `src/associative_cache/associative_cache_bucket.rs`: on each get, increment the counter with probability `1 / (2^counter)` to maintain an O(1)-space logarithmic frequency estimate. In the eviction_candidate_index() function in `src/associative_cache/associative_cache_bucket.rs`, select the victim as the item with the lowest Morris-counter estimate instead of purely position-based LRU selection. This provides frequency guidance to eviction without adding per-item tracking fields (only 1 byte total overhead vs. 8+ bytes for explicit frequency counters), avoiding the bookkeeping cost that defeated cycle 0006 v003's hot/cold partitioning.
