# H02

Selecting the eviction victim from the two oldest probationary items using a lightweight flat frequency table will improve hit-rate over strict FIFO eviction without adding per-hit overhead or graduation gating.

## Parent

cycle/0007/v001

## Changes

This implements the eviction-ordering idea raised as the key open question in the cycle-0007 insight: use a frequency hint to pick among probationary candidates at eviction time, never at graduation time.

### 1. Add a flat frequency table to `LruCache<K, V>`

Add one field to the struct:

```rust
/// 64-entry flat frequency table; each slot is a saturating u8 count.
/// Indexed by the low 6 bits of the key's hash. Used only for eviction
/// victim selection within the probationary queue.
freq_table: [u8; 64],
```

Initialize it in `try_new()`:
```rust
freq_table: [0u8; 64],
```

### 2. Increment the table on every cache access

At the top of both `get()` and the existing-key branch of `put()`, before calling `self.promote(idx)`, compute the frequency index and saturating-increment it:

```rust
let freq_idx = {
    use std::collections::hash_map::DefaultHasher;
    use std::hash::{Hash, Hasher};
    let mut h = DefaultHasher::new();
    self.nodes[idx].key.hash(&mut h);
    (h.finish() & 0x3F) as usize
};
self.freq_table[freq_idx] = self.freq_table[freq_idx].saturating_add(1);
```

This records recency-weighted frequency for all items that receive hits, purely as a u8 per 64-bucket slot. No branching on the promotion path; no change to promotion logic.

### 3. Use 2-candidate selection in `evict_one()`

Replace the unconditional probationary-head eviction with a 2-candidate selection when at least two probationary items exist:

```rust
fn evict_one(&mut self) -> usize {
    if self.prob_len > 0 {
        // 2-candidate frequency-guided eviction: compare head vs. second item.
        let head = (self.prob_head & IDX_MASK) as usize;
        let victim = if self.prob_len >= 2 {
            let second = (self.links[head].next & IDX_MASK) as usize;
            // Hash both candidate keys to get their frequency table indices.
            use std::collections::hash_map::DefaultHasher;
            use std::hash::{Hash, Hasher};
            let freq_idx_head = {
                let mut h = DefaultHasher::new();
                self.nodes[head].key.hash(&mut h);
                (h.finish() & 0x3F) as usize
            };
            let freq_idx_second = {
                let mut h = DefaultHasher::new();
                self.nodes[second].key.hash(&mut h);
                (h.finish() & 0x3F) as usize
            };
            // Evict the candidate with lower estimated frequency;
            // tie-break to the FIFO head (oldest first).
            if self.freq_table[freq_idx_second] < self.freq_table[freq_idx_head] {
                second
            } else {
                head
            }
        } else {
            head
        };
        let evicted_key = self.nodes[victim].key.clone();
        self.map.remove(&evicted_key);
        self.unlink(victim);
        self.prob_len -= 1;
        victim
    } else {
        debug_assert!(self.prot_len > 0, "no items to evict");
        let h = (self.prot_head & IDX_MASK) as usize;
        let evicted_key = self.nodes[h].key.clone();
        self.map.remove(&evicted_key);
        self.unlink(h);
        self.prot_len -= 1;
        h
    }
}
```

When `victim != head`, unlinking a non-head node is already supported by the existing `unlink()` implementation (it uses PROT_BIT dispatch and `prev`/`next` pointers, not head-only removal). No changes to `unlink()`, `push_back_prob()`, `push_back_prot()`, or `promote()`.

### Invariants preserved

- `prob_len` and `prot_len` still decrease by 1 per eviction.
- `map.remove` is called before `unlink` (unchanged order).
- No change to the graduation threshold (immediate one-hit graduation stays).
- `freq_table` is not consulted on the promotion path, only on the eviction path.
- `Node<K,V>` stays at 16 bytes; `LruCache<u64,u64>` grows by 64 bytes (one cache line) for the frequency table.
