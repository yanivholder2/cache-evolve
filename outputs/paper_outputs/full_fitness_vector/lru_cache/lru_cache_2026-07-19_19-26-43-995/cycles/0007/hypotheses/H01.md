# H01

Reducing prob_cap from capacity/8 to capacity/16 (pushing the protected quota from 87.5% to 93.75%) will further improve hit-rate on the Zipfian workload by reducing demotion pressure for moderately-frequent items, continuing the monotonic gain seen from the 75% → 87.5% transition.

## Parent

cycle/0006/v001

## Changes

In `try_new()`, change the single line that computes `prob_cap`:

```rust
// Before:
let prob_cap = (capacity / 8).max(1);

// After:
let prob_cap = (capacity / 16).max(1);
```

At capacity=2048 this shrinks the probationary pool from 256 slots (12.5%) to 128 slots (6.25%), expanding the protected quota to 93.75%. All downstream logic is unaffected: `promote()` derives `prot_cap = self.capacity - self.prob_cap` directly, so the new quota propagates automatically. `evict_one()` still drains probationary first and falls back to protected — the fallback path becomes more reachable but the code path is unchanged.

Update the inline comment at the top of the file (policy sketch section) and the field-declaration doc comment for `prob_cap` to reflect the new divisor and resulting percentages.

No other changes. `Node<K,V>`, `Link`, `LruCache` struct layout, and all methods remain identical to cycle/0006/v001.
