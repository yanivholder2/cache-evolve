# H01

Replacing the default SipHash `RandomState` with a zero-sized FNV-1a `BuildHasher` on the cycle/0007/v002 baseline reduces both `LruCache` struct size and per-op hashing cost without altering the protected-queue policy or hit-rate.

## Parent

cycle/0007/v002

## Changes

This is the "FNV-1a in isolation" experiment that cycle 0009 v003 confirmed works but only ever tested paired with a quota increase to capacity/16 (which regressed latency). Apply the FNV-1a hasher change alone, keeping `prob_cap = (capacity / 8).max(1)` unchanged.

**Implementation steps:**

1. At the top of `src/lru_cache/mod.rs`, add the following two zero-sized types (no external crate needed — implement FNV-1a inline):

   ```rust
   use std::hash::{BuildHasher, Hasher};

   #[derive(Clone, Default)]
   struct FnvBuildHasher;

   impl BuildHasher for FnvBuildHasher {
       type Hasher = FnvHasher;
       fn build_hasher(&self) -> FnvHasher {
           FnvHasher(0xcbf2_9ce4_8422_2325)
       }
   }

   struct FnvHasher(u64);

   impl Hasher for FnvHasher {
       fn write(&mut self, bytes: &[u8]) {
           for &b in bytes {
               self.0 ^= b as u64;
               self.0 = self.0.wrapping_mul(0x0000_0100_0000_01b3);
           }
       }
       fn finish(&self) -> u64 { self.0 }
   }
   ```

2. Change the `map` field declaration in `LruCache<K, V>` from `HashMap<K, …>` (with default `RandomState`) to `HashMap<K, …, FnvBuildHasher>`, matching whatever value type the incumbent uses (e.g., `HashMap<K, (V, u32), FnvBuildHasher>`).

3. In `LruCache::new()` (and any `with_capacity` constructor), replace `HashMap::with_capacity(capacity)` with `HashMap::with_capacity_and_hasher(capacity, FnvBuildHasher)`.

4. Make no other changes: keep `prob_cap = (capacity / 8).max(1)`, the Node layout, the promotion/demotion logic, and the eviction path exactly as in cycle/0007/v002.

**Expected effect**: `FnvBuildHasher` is a zero-sized type (no seed fields), so it removes 16 bytes from the `LruCache` struct relative to `RandomState`'s two-`u64` seed storage. FNV-1a also has lower per-byte hash computation cost than SipHash-1-3, which should either lower or preserve per-op-time. Node size stays at 16 bytes. Hit-rate is unchanged (hash function does not affect eviction policy).

## Rationale

Cycle 0009 v003 confirmed that FNV-1a delivers a genuine struct-size benefit and lower hash cost, but those gains were masked by the simultaneous quota increase to 93.75% which dominated latency. At 87.5% (the confirmed zero-latency-cost ceiling), there is no demotion overhead to mask the hasher benefit. This is the cleanest remaining structural win that has not been directly measured.
