# H02

Replacing `Option<usize>` prev/next link fields with `u32` sentinel-based links will reduce `Node<u64,u64>` metadata from 48 bytes to 24 bytes.

## Parent

baseline

## Changes

In `src/lru_cache/mod.rs`, change the `Node<K, V>` struct and all code that reads or writes the `prev`/`next` fields:

**Node definition — change link types:**
```
prev: Option<usize>  →  prev: u32
next: Option<usize>  →  next: u32
```
Use `u32::MAX` (i.e., `!0u32`) as the null sentinel in place of `None`. The sentinel value is safe because arena capacity is validated to fit within `u32::MAX - 1` (see below).

**`try_new` — add a capacity guard:**
After the existing `capacity == 0` check, add:
```rust
if capacity > (u32::MAX as usize - 1) {
    log::error!("LruCache.try_new: capacity exceeds u32 sentinel range");
    return None;
}
```
Initialise nodes with `prev: !0u32, next: !0u32`.

**`head` / `tail` fields — change to `u32`:**
Store `head: u32` and `tail: u32` on `LruCache`, initialised to `!0u32` (empty list). This avoids the `Option<usize>` overhead on the cache struct as well.

**`unlink(idx: usize)` — rewrite sentinel checks:**
Replace every `match prev { Some(p) => …, None => … }` / `match next { … }` pattern with:
```rust
let prev = self.nodes[idx].prev;
let next = self.nodes[idx].next;
const NULL: u32 = !0u32;
if prev != NULL { self.nodes[prev as usize].next = next; } else { self.head = next; }
if next != NULL { self.nodes[next as usize].prev = prev; } else { self.tail = prev; }
self.nodes[idx].prev = NULL;
self.nodes[idx].next = NULL;
```

**`push_back(idx: usize)` — same sentinel style:**
```rust
const NULL: u32 = !0u32;
let idx32 = idx as u32;
self.nodes[idx].prev = self.tail;
self.nodes[idx].next = NULL;
if self.tail != NULL { self.nodes[self.tail as usize].next = idx32; } else { self.head = idx32; }
self.tail = idx32;
```

**`get` and `put`** — cast arena indices to `u32` when storing, cast back to `usize` when indexing into `self.nodes`. The `map` value type stays `usize` for indexing convenience; only the node link fields change type.

No changes to the `Cache<K, V>` trait implementation, `try_new`/`new` signatures, or eviction semantics. All three invariants (capacity_bound, value_fidelity, no_phantom_items) are preserved unchanged.
