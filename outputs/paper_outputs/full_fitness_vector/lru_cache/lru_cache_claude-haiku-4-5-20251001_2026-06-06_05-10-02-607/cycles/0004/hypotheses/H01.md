# H01

Reduce per-operation mode-transition decision overhead in adaptive bucketing via periodic sampling to improve put p50 latency.

## Parent

cycle/0003/v003

## Changes

In the adaptive bucketing logic, replace per-operation checks of `should_use_bucketing()` and `update_hit_rate()` with periodic sampling every 16th operation. Specifically:

1. Add an `operation_counter` field to track operations since the last mode-decision check.
2. In both `get()` and `put()`, increment `operation_counter` but only call `should_use_bucketing()`, `update_hit_rate()`, and evaluate mode-transition logic when `operation_counter % 16 == 0`.
3. Reset `operation_counter` to 0 immediately after a mode transition to ensure responsive switching if saturation or hit rate deteriorates rapidly under high load.
4. Preserve all mode-switching infrastructure, bucketing structures, and frequency decay logic unchanged.

This strategy trades slightly delayed mode-transition detection (max 16 operations latency) for 94% reduction in decision-path overhead on normal operations, improving put p50 median latency while maintaining v003's adaptive bucketing benefit on long-running or saturation-prone workloads.
