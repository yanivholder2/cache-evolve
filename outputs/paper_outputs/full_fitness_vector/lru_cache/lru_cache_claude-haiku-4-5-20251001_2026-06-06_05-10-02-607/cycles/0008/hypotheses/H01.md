# H01

Reduce get p50 latency regression by aggressively tuning batch-swap parameters in a deferred-promotion queue-flush mechanism to minimize bookkeeping overhead while preserving tail-latency gains.

## Parent

cycle/0003/v003

## Changes

Starting from cycle/0003/v003's adaptive bucketing baseline with saturation-aware mode switching (75% threshold), integrate the deferred-promotion queue + two-batch swap mechanism from cycle/0007/v001, but with tuned parameters: reduce batch size from 16 items to 8 items, and reduce swap-trigger hysteresis by swapping when the main batch reaches 50% capacity instead of full. The goal is to amortize the two-vector bookkeeping overhead across more swap operations, reducing per-get cost. Maintain the dual-mode (simple/bucketing) activation logic based on saturation, and measure whether smaller batch size and more frequent swaps reduce the 20% get p50 regression observed in cycle/0007/v001 (35→42 ns) without sacrificing the p99 improvements (both ~42-50% reduction).

## Rationale

Cycle/0007/v001 achieved breakthrough simultaneous improvement of get p99 (42%) and put p99 (50%), but at the cost of a measurable 20% get p50 regression (35→42 ns) due to two-batch swap bookkeeping on every get. Cycle/0007's open question explicitly asks whether batch size and swap frequency tuning can reduce this overhead while preserving p99 gains. This hypothesis directly addresses that question by testing aggressive parameter reduction on the proven incumbent, cycle/0003/v003, which established adaptive bucketing as a cross-cycle winner.
