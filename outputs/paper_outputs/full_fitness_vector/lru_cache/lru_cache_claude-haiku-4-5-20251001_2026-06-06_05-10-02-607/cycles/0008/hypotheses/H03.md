# H03

Enable saturation-aware deferred-promotion tail-latency improvements by lowering activation threshold and preserving LRU correctness at all saturation states.

## Parent

cycle/0004/v002

## Changes

Starting from cycle/0004/v002's deferred-promotion queue framework (which achieved 23% get p99 improvement by deferring promotion updates from get to put), add saturation-aware conditional activation with a corrected threshold: enable deferred promotions only when saturation exceeds 45% (vs. the failed 80% threshold from cycle/0007/v003). Implement dual-path promotion logic to preserve LRU correctness: in low-saturation mode (<45%), perform immediate promotions on get (baseline correct semantics); in high-saturation mode (≥45%), defer promotions to the queue and flush only when queue depth exceeds a capacity threshold (e.g., 32 items). This ensures that when the condition is inactive, the cache operates identically to the baseline, avoiding the correctness violations that caused cycle/0007/v003 to fail (9.4% hit-rate drop). Measure whether the lower threshold causes the saturation condition to fire frequently enough on the test workload to deliver meaningful latency gains while maintaining baseline hit rate.

## Rationale

Cycle/0007/v003 attempted saturation-aware conditional deferred promotions but failed catastrophically (9.4% hit-rate drop, 71% get p50 regression) because the 80% saturation threshold never fired on the underutilized test workload, leaving the cache in an inconsistent state (deferred promotions without feedback). Cross-cycle insights explicitly identify "conditional logic protecting correctness must activate universally or preserve baseline semantics when inactive" as a critical lesson. Cycle/0004/v002 and Cycle/0006 confirmed that deferred promotions improve get p99 (23% gain) at the cost of put regression, and a lower saturation threshold (45% vs. 80%) is more likely to fire on typical workloads. This hypothesis salvages the saturation-aware architecture by ensuring correctness preservation at all states and using a threshold derived from empirical workload saturation curves rather than assumption.
