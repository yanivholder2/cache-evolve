# H03

Replace frequency-counter eviction with operation-count-based recency tracking to achieve hit-rate selectivity without per-operation frequency overhead, reducing per-op-time.

## Parent

baseline

## Changes

The baseline LRU evicts items in strict FIFO order without frequency awareness. Cross-cycle analysis reveals that frequency tracking consistently adds per-operation latency overhead (counter increments, bucket pointer chasing) without proportional hit rate gains on this workload. Implement approximate recency-aware eviction using a global operation counter instead of per-item frequency:

1. Add a global operation_counter: u64 to LruCache, incremented once per get() or put() operation (regardless of cache hit/miss).
2. On each Node, replace frequency tracking with a single `last_access_count: u64` field (captures the operation_counter value when the node was last accessed).
3. Remove all per-operation frequency increment code.
4. During eviction, scan the bounded candidate window (e.g., first min(capacity/4, 256) LRU-ordered nodes) and prefer to evict the node with the oldest `last_access_count` value—i.e., accessed furthest in the past (by operation count, not wall-clock time).
5. Preserve the bounded-window sequential search structure from Cycle 0002 v001 to maintain latency predictability.

This substitutes frequency counting (expensive: atomic/barrier overhead per access) with operation-count tracking (cheap: simple counter increment) and recency-based selection within the bounded window (approximate the Zipfian hot-set via recent access time).

## Rationale

Multiple cycles show frequency tracking adds latency without proportional benefit: Cycle 0001–0005 variants consistently penalize the fast path. Cycle 0004 v003 gained only 1.3% hit rate while causing 2.8× put p99 regression. However, we know selective eviction (biasing toward hot items) improves hit rate. Access-count-based recency offers a middle ground: instead of counting frequency (per-operation work), track when each access occurred in the sequence of operations (single counter increment, cheap assignment). Within a bounded search window, evicting the oldest-accessed item approximates frequency-based selection for Zipfian workloads where recent items are likely hot. This tests whether the per-operation counting overhead is the bottleneck, not the eviction strategy itself, and whether recency (a cheaper signal) suffices in place of frequency.
