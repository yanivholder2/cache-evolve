# H03

Requiring two separate probationary accesses before graduating an item to the protected queue will improve hit-rate by preventing one-hit wonders from briefly occupying protected slots and displacing genuinely recurring items.

## Parent

cycle/0002/v001

## Changes

**Step 1 — add a SEEN_BIT constant and shrink IDX_MASK.**

Encode a "seen-once" flag in bit 30 of the `prev` field alongside the existing `PROT_BIT` (bit 31). Valid slot indices therefore fit in bits 0–29.

Replace the existing constants:

```rust
// Old
const NULL:     u32 = 0x7FFF_FFFF;
const IDX_MASK: u32 = 0x7FFF_FFFF;

// New
const NULL:     u32 = 0x3FFF_FFFF;   // bits 30-31 both 0; acts as "no predecessor" sentinel
const SEEN_BIT: u32 = 0x4000_0000;   // bit 30: probationary node has been accessed once
const IDX_MASK: u32 = 0x3FFF_FFFF;   // strip PROT_BIT and SEEN_BIT to get raw index
```

Update the capacity guard in `try_new` to reflect the reduced index range:

```rust
if capacity > 0x3FFF_FFFFusize - 1 {   // max valid index = 0x3FFF_FFFE
```

For the test capacity of 2048 this is trivially satisfied.

**Step 2 — preserve SEEN_BIT of a node's successor in `unlink()`.**

The current `unlink()` preserves only `PROT_BIT` when updating the successor's prev field. Change the successor update to preserve both flag bits:

```rust
// Old
let succ_prot_bit = self.nodes[next as usize].prev & PROT_BIT;
self.nodes[next as usize].prev = succ_prot_bit | prev_idx;

// New
let succ_flags = self.nodes[next as usize].prev & (PROT_BIT | SEEN_BIT);
self.nodes[next as usize].prev = succ_flags | prev_idx;
```

All other logic in `unlink()` is unchanged; `IDX_MASK` now correctly strips both flag bits wherever it is used.

**Step 3 — implement two-hit graduation in `promote()`.**

In the probationary-hit branch of `promote()` (the `else` arm, when `protected` is false), replace the immediate graduation with a two-phase check:

```rust
} else {
    // Probationary hit.
    let has_seen = (self.nodes[idx].prev & SEEN_BIT) != 0;
    if !has_seen {
        // First hit: refresh position in probationary and mark as seen.
        // Move to probationary MRU to extend the window before eviction.
        self.unlink(idx);
        self.push_back_prob(idx);              // clears SEEN_BIT and PROT_BIT (sets plain index)
        self.nodes[idx].prev |= SEEN_BIT;      // re-apply SEEN_BIT after push_back_prob
        // prob_len and prot_len are unchanged; no graduation occurs.
        return;
    }
    // Second+ hit: graduate to protected (SEEN_BIT is cleared automatically
    // by unlink → NULL, then push_back_prot → PROT_BIT | prot_tail).
    self.unlink(idx);
    self.prob_len -= 1;
    self.push_back_prot(idx);
    self.prot_len += 1;
    // Existing demotion enforcement block is unchanged.
    let prot_cap = self.capacity - self.prob_cap;
    if self.prot_len > prot_cap {
        let h = (self.prot_head & IDX_MASK) as usize;
        self.unlink(h);
        self.prot_len -= 1;
        self.push_back_prob(h);
        self.prob_len += 1;
    }
}
```

**Step 4 — verify SEEN_BIT lifecycle.**

- `push_back_prob(idx)`: assigns `self.nodes[idx].prev = self.prob_tail` (a raw index with bits 30–31 = 0). SEEN_BIT is naturally cleared. ✓
- `push_back_prot(idx)`: assigns `self.nodes[idx].prev = PROT_BIT | self.prot_tail`. SEEN_BIT is naturally cleared. ✓
- Eviction in `evict_one()` → `unlink(h)` clears prev to NULL, then `put()` calls `push_back_prob` on the reused slot — SEEN_BIT is cleared. ✓
- Demotion from protected to probationary in `promote()` → same path as above. ✓

No changes to `push_back_prob`, `push_back_prot`, `evict_one`, or the `put()` fast path. `Node<K,V>` layout is unchanged at 24 bytes.

**Step 5 — add a unit test for the two-hit contract.**

```rust
#[test]
fn two_hit_filter_defers_graduation() {
    // capacity=3: prob_cap=1 (capacity/4=0, max(1)=1), prot_cap=2.
    let mut cache = LruCache::new(3);
    cache.put(1, 10); // slot 0 → prob
    cache.put(2, 20); // slot 1 → prob
    cache.put(3, 30); // slot 2 → prob

    // First get on key 1: sets SEEN_BIT, refreshes to prob MRU. Still in prob.
    cache.get(&1);
    // Key 1 should be alive (not evicted) and still accessible.
    assert_eq!(*cache.get(&1).unwrap(), 10); // this is the second hit → graduates key 1 to prot
    // Key 1 is now protected; keys 2 and 3 remain in prob.
    // A new put fills from prob (evicts key 2 or 3, not key 1).
    cache.put(4, 40);
    assert_eq!(*cache.get(&1).unwrap(), 10); // key 1 protected, must survive
}
```

## Rationale

cycle/0002/v001 graduates any probationary hit to protected immediately. On a Zipfian workload the hot items are accessed far more than once and will quickly re-enter protected after any eviction from it. However, items that happen to be accessed twice in a short burst (e.g., a scan that repeats a key before moving on) also graduate, temporarily displacing true recurring items. Requiring a second, independent probationary hit filters out these burst artefacts with minimal cost: the first hit only does unlink + push_back_prob (cheaper than the graduation path), leaving SEEN_BIT as the persistent signal. The node layout is unchanged (SEEN_BIT lives in an already-present field's spare bit), keeping metadata-size at 24 bytes and avoiding any new allocations.
