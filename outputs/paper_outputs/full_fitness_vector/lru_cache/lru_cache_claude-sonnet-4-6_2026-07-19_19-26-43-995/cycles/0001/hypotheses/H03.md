# H03

Replacing the doubly-linked-list LRU with a CLOCK (second-chance) eviction algorithm will reduce `get` p50 latency by eliminating all list-pointer writes on cache hits.

## Parent

baseline

## Changes

Rewrite `src/lru_cache/mod.rs` to use a CLOCK eviction algorithm in place of the doubly-linked-list LRU. The public API (`get`, `put`, `try_new`, `new`, `Cache<K,V>` impl) remains identical; only the internal data structure changes.

**New node type — replace `Node<K,V>` with a flat slot:**
```rust
struct Slot<K, V> {
    key:     K,
    value:   V,
    occupied: bool,
    ref_bit:  bool,
}
```
For `K=u64, V=u64` this lays out as 8+8+1+1 = 18 bytes, padded to 24 — half the 48-byte baseline.

**New `LruCache<K,V>` fields:**
```rust
struct LruCache<K, V> {
    map:      HashMap<K, usize>,  // key → slot index
    slots:    Vec<Slot<K, V>>,    // fixed-size ring, pre-allocated to `capacity`
    hand:     usize,              // CLOCK hand position
    len:      usize,              // number of occupied slots
    capacity: usize,
}
```
In `try_new`, pre-fill `slots` with `capacity` unoccupied `Slot` values (use a dummy default or an `Option`-free sentinel approach with `occupied: false`). `K` and `V` must supply `Default` if needed, or use `MaybeUninit` to avoid the constraint — the simplest path is to require `K: Default + …` and `V: Default` for the initial fill and emit un-occupied slots with zeroed keys.

Alternatively, use `Vec<Option<Slot<K,V>>>` with `None` = empty, at the cost of slightly larger per-slot overhead; prefer the `bool occupied` approach.

**`get(&mut self, key: &K) -> Option<&V>`:**
```rust
let &idx = self.map.get(key)?;
self.slots[idx].ref_bit = true;   // only write: set the reference bit
Some(&self.slots[idx].value)
```
No list unlinking, no push_back — just a HashMap lookup and a single field write.

**`put(&mut self, key: K, value: V)`:**
- If key already in `map`: update `slots[idx].value = value; slots[idx].ref_bit = true;` return.
- Otherwise, advance the clock hand until an empty slot (`!occupied`) or an occupied slot with `ref_bit == false` is found, clearing `ref_bit` on every occupied slot skipped. Evict the target slot: `map.remove(&slots[hand].key)` if it was occupied; decrement `len`. Write the new entry at `hand`, set `occupied = true, ref_bit = true`, insert `map.insert(key, hand)`, increment `len`. Advance `hand = (hand + 1) % capacity`.

**Eviction invariant:** The clock hand will always find a victim within at most `capacity` steps because at least one slot must have `ref_bit == false` after a full sweep (each pass clears bits). Guard with a `debug_assert` that `len < capacity` before the eviction loop to catch bugs.

**Invariant preservation:** capacity_bound holds because `len` is incremented only on new insertions and `len <= capacity` is maintained; value_fidelity holds because the value is written into the slot and returned from `map`-resolved index; no_phantom_items holds because keys are only in `map` when their slot is occupied.

Remove `unlink`, `push_back`, `head`, `tail`, and all linked-list bookkeeping. The `K: Clone` bound may be relaxed to only where the eviction path calls `map.remove(&slots[hand].key)` — keep or drop `Clone` as needed by the borrow checker.
