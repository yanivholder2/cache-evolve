# H03

Replacing the per-eviction key clone in `put()` with a field-split borrow will eliminate a redundant allocation on the steady-state put path and reduce per-op-time for non-trivial key types.

## Parent

baseline

## Changes

In `put()`, inside the arena-full eviction branch, replace the two-step clone-and-remove pattern:

```rust
// Before:
let evicted_key = self.nodes[head_idx].key.clone();
self.map.remove(&evicted_key);
```

with a single field-split borrow that removes the key directly from the node without cloning:

```rust
// After:
self.map.remove(&self.nodes[head_idx].key);
```

This is valid under Rust's NLL borrow rules: `self.map.remove(...)` requires `&mut self.map`, and `&self.nodes[head_idx].key` borrows only `self.nodes`. Because `map` and `nodes` are different fields of the struct, the compiler allows both borrows to coexist simultaneously. The temporary `evicted_key: K` binding is eliminated entirely, which also removes its `Drop` call at the end of the block.

After this removal, `self.unlink(head_idx)` follows on its own line — no overlap with any live borrow, so `&mut self` is available.

The second clone in the same branch:
```rust
self.nodes[head_idx].key = key.clone();
// ...
self.map.insert(key, head_idx);
```
can also be eliminated by moving `key` into the node first and then cloning from the node for the map insert — but this trade only saves a clone when the map insert path is taken while the prior remove is not, so it is a secondary concern. The primary change is the `evicted_key` clone removal above.

Apply the same field-split pattern to both the hit path (where map.get is called before unlink) and any other location in `put()` or future helpers that clone a node key solely to pass to a map method.

All existing unit tests must pass. Node layout (`Option<usize>` prev/next) and struct fields are unchanged.
