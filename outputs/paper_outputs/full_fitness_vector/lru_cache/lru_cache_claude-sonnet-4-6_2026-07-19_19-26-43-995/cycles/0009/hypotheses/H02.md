# H02

Batching two protected→probationary demotions per trigger event at `prob_cap = capacity/16` will reduce per-op-time from 100 ns to 0 while preserving the 93.75% hit-rate gain.

## Parent

cycle/0006/v001

## Changes

Two modifications relative to cycle/0006/v001:

**1. Change the probationary capacity in `try_new()`:**

```rust
// Old:
let prob_cap = (capacity / 8).max(1);

// New:
let prob_cap = (capacity / 16).max(1);
```

**2. Change the protected-budget enforcement in `promote()` to batch demotions:**

```rust
// Old (in promote(), after push_back_prot / prot_len += 1):
let prot_cap = self.capacity - self.prob_cap;
if self.prot_len > prot_cap {
    let h = (self.prot_head & IDX_MASK) as usize;
    self.unlink(h);
    self.prot_len -= 1;
    self.push_back_prob(h);
    self.prob_len += 1;
}

// New:
let prot_cap = self.capacity - self.prob_cap;
if self.prot_len > prot_cap + 1 {
    // Batch: demote two items at once instead of one at a time.
    for _ in 0..2 {
        let h = (self.prot_head & IDX_MASK) as usize;
        self.unlink(h);
        self.prot_len -= 1;
        self.push_back_prob(h);
        self.prob_len += 1;
    }
}
```

No other changes. The invariant `prob_len + prot_len == map.len() <= capacity` still holds because `prot_len` can temporarily reach `prot_cap + 1` only while `prob_len >= prob_cap - 1 >= 0`. `evict_one()` is unmodified; when `prob_len == 0` (possible with the slack) it falls back to evicting from protected as before.

**Mechanism:** With the original single-item demotion, every overflow event (i.e., every probationary graduation when protected is full) pays the unlink+push_back overhead. With batch-2, overflow fires only when protected exceeds quota by 2, halving the frequency of demotion events at the cost of doubling their magnitude. At the p50 latency level, the median operation now encounters a demotion event roughly half as often, which may keep the p50 measurement below the 100 ns floor while the total amortised demotion work is unchanged.

## Rationale

Cycle 0008 confirmed that the per-op-time regression at 93.75% is demotion-induced, not measurement noise. The cross-cycle insights ask whether batching or amortising demotion events could reduce the per-op penalty without changing effective quota. This hypothesis directly tests that question with the simplest possible batching scheme (SLACK = 1, batch size = 2). The effective average protected quota under this scheme is ≈ `prot_cap + 0.5`, a negligible deviation from 93.75%.
