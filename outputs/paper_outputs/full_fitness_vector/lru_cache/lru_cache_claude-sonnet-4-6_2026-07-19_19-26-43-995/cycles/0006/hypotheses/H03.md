# H03

Adding a bounded second-chance rescue at eviction time — reinserting a SEEN_BIT-marked probationary head to the MRU end instead of evicting it — recovers hit-rate lost in cycle/0005/v001 without touching the common-case access path.

## Parent

cycle/0005/v001

## Changes

Modify only `evict_one()` in the cycle/0005/v001 overlay (`src/lru_cache/mod.rs`). The access paths (`promote()`, `push_back_prob()`, `push_back_prot()`, `unlink()`) are left untouched.

Replace the existing probationary branch of `evict_one()` with the following logic:

```rust
fn evict_one(&mut self) -> usize {
    if self.prob_len > 0 {
        let h = (self.prob_head & IDX_MASK) as usize;
        // Bounded second-chance rescue: if the probationary head has been seen
        // at least once and there is another candidate behind it, give it one
        // more chance by moving it to the MRU end of probationary and evicting
        // the new head instead. The rescue fires at most once per eviction call,
        // so the path remains O(1).
        if self.prob_len > 1 && (self.nodes[h].prev & SEEN_BIT) != 0 {
            // Unlink h from the LRU head of prob and push to MRU end.
            // push_back_prob clears SEEN_BIT so the entry starts fresh.
            self.unlink(h);
            self.push_back_prob(h);
            // prob_len is unchanged (we just moved h within prob); fall through
            // to evict the new head unconditionally.
        }
        let h2 = (self.prob_head & IDX_MASK) as usize;
        let evicted_key = self.nodes[h2].key.clone();
        self.map.remove(&evicted_key);
        self.unlink(h2);
        self.prob_len -= 1;
        h2
    } else {
        debug_assert!(self.prot_len > 0, "no items to evict");
        let h = (self.prot_head & IDX_MASK) as usize;
        let evicted_key = self.nodes[h].key.clone();
        self.map.remove(&evicted_key);
        self.unlink(h);
        self.prot_len -= 1;
        h
    }
}
```

Key invariants to preserve:
- `prob_len` is decremented exactly once per eviction call (the unlink/push_back for the rescue does not change `prob_len`).
- When `prob_len == 1`, the rescue branch is skipped to avoid pushing the sole probationary item to its own tail (which would leave `prob_head == prob_tail == h` and the subsequent eviction of `h2 == h` would be correct but wasted work; skipping is cleaner).
- `push_back_prob()` clears `SEEN_BIT` in the rescheduled item's `prev` field, so the rescued item re-enters probationary without a second-chance flag.

## Rationale

cycle/0005/v001's hit-rate regression (0.713 vs. v002's 0.7202) occurs because SEEN_BIT-marked probationary items stay at their FIFO position and can reach the eviction head before receiving their second hit. The SEEN_BIT mechanism correctly defers the promotion work to the common hit path; this hypothesis moves the "rescue" decision to the eviction path instead — where it fires only on eviction, not on every access. This is structurally distinct from the CLOCK variants in cycles 0001 and 0004: there is no hand sweep over the queue; the check is a single bit test at the one point (eviction head) where the cost is already incurred. The rescue is bounded to one reinsert per eviction call, guaranteeing O(1) worst-case behavior.
