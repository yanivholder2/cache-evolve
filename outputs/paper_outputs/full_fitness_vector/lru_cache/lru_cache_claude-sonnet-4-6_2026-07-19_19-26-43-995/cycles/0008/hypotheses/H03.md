# H03

Applying the 93.75% protected quota (prob_cap = capacity/16) directly to the link-array structural baseline of cycle/0005/v002 will reproduce the hit-rate gain seen in cycle/0007/v001 (0.7316) while preserving the per-op-time=0 result by starting from a confirmed non-anomalous parent.

## Parent

cycle/0005/v002

## Changes

In `try_new()`, change the single line that computes `prob_cap`:

```
// before (cycle/0005/v002):
let prob_cap = (capacity / 4).max(1);

// after:
let prob_cap = (capacity / 16).max(1);
```

No other changes. At `capacity=2048` this gives `prob_cap=128`, leaving 1920 protected slots (93.75%).

### Rationale for parent choice

cycle/0007/v001 tested the same quota (capacity/16, 93.75% protected) and recorded hit-rate=0.7316 — the highest ever measured — but the per-op-time summary showed 100 ns, which the variant's own insight attributed to "baseline anomaly resolution rather than introduced cost." The parent of cycle/0007/v001 was cycle/0006/v001, whose per-op-time p50 had an anomalous zero-floor at the time of measurement.

cycle/0005/v002 is the structural baseline that introduced the link-array split (Node<K,V> = {key, value}, Vec<Link> parallel array). It has a confirmed per-op-time=0, a non-anomalous measurement baseline, and is one of the three cross-cycle incumbents. Starting from this parent and applying only the quota change should reproduce the hit-rate benefit of cycle/0007/v001 without inheriting the measurement-noise regression in per-op-time, thereby confirming that the combination of 93.75% protected + link-array layout is a clean winner on both dimensions simultaneously.

All other code — `unlink()`, `push_back_prob()`, `push_back_prot()`, `promote()`, `evict_one()`, the struct fields, the test suite — is inherited unchanged from cycle/0005/v002.
