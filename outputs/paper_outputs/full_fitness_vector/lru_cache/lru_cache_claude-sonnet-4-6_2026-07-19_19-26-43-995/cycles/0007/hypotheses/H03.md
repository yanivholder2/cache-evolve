# H03

Demoting overflow-protected items to the LRU end (oldest position) of the probationary queue — instead of the current MRU end — will improve hit-rate by evicting failed-protected items quickly and preserving probationary slots for fresh insertions that have not yet had any access opportunity.

## Changes

### New method: `push_front_prob`

Add alongside the existing `push_back_prob` in the `impl<K,V>` block:

```rust
/// Prepend a node to the LRU end (eviction-candidate end) of the probationary queue.
/// Used when demoting an overflow-protected item so it is evicted before newer probationary entries.
/// Clears PROT_BIT in `prev` (PROT_BIT = 0 → probationary).
fn push_front_prob(&mut self, idx: usize) {
    let idx32 = idx as u32;
    // This node has no predecessor: prev = NULL with PROT_BIT = 0.
    self.links[idx].prev = NULL;
    self.links[idx].next = self.prob_head;
    if self.prob_head != NULL {
        // Update the old head's prev: preserve its own PROT_BIT (should be 0 for
        // probationary nodes, but mask-and-or to be safe) and set index = idx32.
        let old_head = self.prob_head as usize;
        let old_prot = self.links[old_head].prev & PROT_BIT;
        self.links[old_head].prev = old_prot | idx32;
    } else {
        // Probationary queue was empty: this node is also the tail.
        self.prob_tail = idx32;
    }
    self.prob_head = idx32;
}
```

### Change to `promote()`

In `promote()`, inside the probationary graduation branch, the demotion of an overflow-protected item currently calls `push_back_prob` (MRU end). Replace it with `push_front_prob` (LRU end):

```rust
// Before:
self.push_back_prob(h);

// After:
self.push_front_prob(h);
```

The surrounding context (inside the `if self.prot_len > prot_cap` block) remains identical:

```rust
if self.prot_len > prot_cap {
    let h = (self.prot_head & IDX_MASK) as usize;
    self.unlink(h);
    self.prot_len -= 1;
    self.push_front_prob(h);   // ← changed from push_back_prob
    self.prob_len += 1;
}
```

No other code changes. All other callers of `push_back_prob` — in `put()` (new insertion) and `evict_one()` fallback — remain unchanged.

### Rationale for correctness

`push_front_prob` sets the new node's `prev` to `NULL` with `PROT_BIT = 0`, correctly marking it as the probationary head with no predecessor. The existing head's `prev` index is updated to `idx32` (also PROT_BIT = 0, which is correct for a probationary node). `unlink()` reads `PROT_BIT` from `prev` to dispatch to the correct head/tail pointer; since the demoted node's `prev = NULL` (no PROT_BIT), `unlink()` will correctly update `prob_head` when this node is eventually evicted.

### Expected effect

Currently, demoted items occupy the MRU end of probationary and survive until all newer probationary items are evicted — often outlasting many fresh insertions that never get a second access. By placing demoted items at the LRU end, they are evicted on the next probationary eviction call, freeing the slot for a new insertion. New insertions (at the MRU end) then survive longer, increasing the window in which they can receive a hit and graduate. On a Zipfian workload where the moderate-frequency population is large relative to the 12.5% probationary budget, this reordering may meaningfully reduce wasted probationary residence by expired-protected items.
