# H03

Fuse the promote-and-demote pair into a single list operation on v001's get path to cut per-op-time when the protected segment is at its cap.

## Parent

cycle/0004/v001

## Changes

At steady state on this trace the protected segment sits at `prot_cap`,
so almost every probationary promotion in v001's `get` first
`push_back`s the promoted node into protected and then immediately calls
`demote_protected_lru`, which `unlink`s the protected LRU, flips it to
probationary, and `push_back`s it into probation. That is two independent
list surgeries per hot `get`. Replace them with one fused routine that
removes the redundant head/tail churn:

- Add `fn promote_with_demote(&mut self, idx: usize)` that, in one pass:
  `unlink(idx)` from probation; reads the demotion victim `prot_head`
  via `slot`; `unlink`s that victim; sets `idx`'s flag protected and
  appends it at the protected MRU; sets the victim's flag probationary
  and appends it at the probation MRU. `prot_len` is net-unchanged, so
  it is neither incremented nor decremented in this path.
- In `get`'s probationary branch, after `unlink`/`set_protected` logic,
  branch on capacity: when `prot_len == prot_cap` (promotion would
  overflow) call `promote_with_demote(idx)`; otherwise keep the existing
  `set_protected(true)` + `push_back(idx)` + `prot_len += 1` path
  unchanged.

All access MUST go through v001's `slot`/`link`/`set_prev_link`/
`set_next_link`/`set_head`/`set_tail` helpers and the `NIL` sentinel so
the packed `PROT_MASK` flag is preserved. The fused path must leave the
exact same final list ordering and residency as today's
promote-then-demote sequence, so hit-rate stays byte-identical at 0.7241
and the 24-byte node layout is untouched; only per-op-time should move.

## Rationale (optional)

The cross-cycle pattern is that cheap hot-path changes which *remove*
work pay off without a paying axis. The promote+demote double-surgery is
pure redundant pointer churn on the most common hot `get`; collapsing it
into a single reshuffle targets per-op-time (v001's record 27) while
provably preserving eviction behavior.
