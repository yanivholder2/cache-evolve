# H01

Elide arena bounds checks on the get/put hot paths with unchecked indexing to cut per-op-time below the champion's 27 ns.

## Parent

cycle/0004/v001

## Changes

In `src/lru_cache/mod.rs`, replace the bounds-checked `self.nodes[idx]`
indexing on the proven-valid hot paths with unchecked access. Every index
that reaches `get`, `put`, `unlink`, `push_back`, and `demote_protected_lru`
originates either from `self.map` (which only ever holds live arena slots)
or from a node's own `prev`/`next` link decoded through `slot()` (which is
maintained as a valid index or `NIL`), so the bounds check is provably
redundant.

Concretely: add small private `#[inline]` helpers `node(&self, idx: usize)
-> &Node<K,V>` and `node_mut(&mut self, idx: usize) -> &mut Node<K,V>` whose
bodies use `unsafe { self.nodes.get_unchecked(idx) }` /
`get_unchecked_mut(idx)`, and route the hot-path accesses in `get`, `put`,
`unlink`, and `push_back` through them. Leave the cold/allocation path
(`self.nodes.push(...)` and `self.nodes.len()`) and all `slot()`/`link()`
encoding untouched. Add a focused `// SAFETY:` comment at each helper
explaining the live-slot invariant.

Preserve every behavioral invariant exactly: segment flags, `prot_len`
accounting, the protected-MRU fast path, eviction order, and all existing
unit tests must pass unchanged. This is a pure layout/codegen change — no
policy, no node-size change (stays 24 bytes), hit-rate must be identical to
the parent. The hypothesis is confirmed if p50/p99 drop while hit-rate and
metadata-size hold.
