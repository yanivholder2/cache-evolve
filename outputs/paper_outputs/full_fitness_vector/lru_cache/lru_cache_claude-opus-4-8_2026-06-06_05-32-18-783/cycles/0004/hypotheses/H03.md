# H03

Raise the SLRU champion's protected-segment cap from 80% toward 90% of capacity to shield hot LIRS keys longer and lift hit-rate above the 0.724 record.

## Parent

cycle/0002/v002

## Changes

In the SLRU-plus-fast-hasher champion (`cycle/0002/v002`), the protected
soft cap is set in `try_new` as `prot_cap = (capacity * 4 / 5).max(1)
.min(capacity.saturating_sub(1))` — an 80% protected / 20% probation
split. On the LIRS workload the working set of genuinely hot keys is large
relative to capacity, so an 80% protected fraction may be demoting hot
keys back into probation too aggressively, where they are then exposed to
eviction.

Change the ratio to a larger protected fraction — set `prot_cap =
(capacity * 9 / 10).max(1).min(capacity.saturating_sub(1))` (a 90/10
split) so the protected set holds more of the re-referenced working set
before demotion kicks in. This is a pure-policy, single-constant change:
it touches only the `prot_cap` computation and nothing else. Leave the
node layout, the fast hasher, the segment-MRU fast path, victim selection
(probation LRU first, protected LRU fallback), and the
demote-on-overflow path exactly as they are.

The claim is testable as a direct hit-rate comparison against the 0.724
champion at the same capacity (2048). Preserve the invariant that at least
one slot remains reserved for probation (`min(capacity - 1)`) so brand-new
entries always have a probationary landing spot and the
probation-first eviction rule still has a victim source. Target axis:
hit-rate; metadata-size and the hot-path latency profile are expected to
be unchanged.
