# H02

Implement adaptive divisor formula that scales based on both stash bucket count and normal-bucket ratio to achieve geometry-independent promotion selectivity and reliable cross-geometry composition.

## Parent

baseline

## Changes

In `src/dash/segments/mod.rs`, replace the fixed divisor constant with an adaptive formula that computes divisor based on both stash capacity AND the normal-to-stash ratio:

1. Add a new function in mod.rs to compute adaptive divisor:
   ```rust
   fn compute_adaptive_divisor(stash_buckets: usize, normal_buckets: usize) -> usize {
       // Ratio-based formula: tight geometry (high normal/stash) needs stricter gate (higher divisor)
       // For example: divisor scales from 2 (baseline 25/75) to 3-4 (aggressive 80/20 or beyond)
       let ratio = (normal_buckets * 100) / (normal_buckets + stash_buckets);
       if ratio >= 80 {
           3  // aggressive geometry: divisor 3
       } else if ratio >= 75 {
           3  // mid-aggressive geometry: divisor 3
       } else {
           2  // baseline or balanced geometry: divisor 2
       }
   }
   ```

2. Modify `compute_promotion_threshold()` to use the adaptive divisor:
   ```rust
   fn compute_promotion_threshold(stash_buckets: usize, normal_buckets: usize) -> u16 {
       let divisor = compute_adaptive_divisor(stash_buckets, normal_buckets);
       ((stash_buckets / divisor).max(1)) as u16
   }
   ```

3. Update SegmentCore::try_new() to pass both stash and normal bucket counts:
   ```rust
   pub fn try_new(settings: &DashSettings) -> Option<Self> {
       // ... existing code ...
       let promotion_threshold = compute_promotion_threshold(
           settings.num_of_stash_buckets, 
           settings.num_of_normal_buckets
       );
       // ... rest of initialization ...
   }
   ```

4. Keep all other promotion logic, demotion cascades, and bucket insertion unchanged.

## Rationale

Cycle 0007 revealed that threshold divisor inversely couples with geometry aggressiveness: tight geometry (85/15) needs divisor 2 for proper selectivity, while baseline (25/75) tolerates divisor 2 but benefits from divisor 3 on mid-aggressive allocations like 80/20. The open question asks: "Can a meta-formula that scales the divisor based on both geometry ratio and stash bucket count achieve universal optimality?" This hypothesis directly tests this by making divisor adaptive to the normal-bucket allocation ratio, eliminating the need for per-geometry manual tuning. If a geometry-aware divisor formula succeeds, it enables reliable composition across the entire allocation spectrum and removes the brittleness that plagued cycles 0004–0006, positioning future cycles to explore orthogonal optimization axes (eviction policies, tier-crossing heuristics) without re-tuning thresholds.
