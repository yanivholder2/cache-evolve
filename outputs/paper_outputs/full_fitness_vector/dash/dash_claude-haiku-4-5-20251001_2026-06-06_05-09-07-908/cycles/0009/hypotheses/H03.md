# H03

Pair the adaptive divisor formula with 75/25 geometry to test whether meta-parametrization succeeds when combined with larger stash capacity than v002's configuration.

## Parent

cycle/0007/v002

## Changes

In `src/shared/geometry.rs`, rebalance geometry to 75/25 (75% normal, 25% stash), shifting stash capacity from v002's unknown baseline toward more capacity-generous allocation. In `src/dash/segments/dash_segment.rs`, implement the adaptive divisor formula: compute `promotion_threshold = max(1, stash_bucket_count / 4)` at initialization time rather than using a hardcoded constant. Apply this threshold to the promotion-gating logic so that the selectivity of which items promote automatically scales with stash capacity. This pairs a meta-formula (divisor scaling) with a geometry that provides more stash headroom, testing whether v002's latency gains (57% on get p50) generalize across broader allocations when stash capacity is increased to absorb adaptive promotion pressure.

## Rationale

Cycle 0008/v002 achieved dramatic latency wins (57% on get p50) via an adaptive divisor formula but regressed hit-rate (0.6634 vs 0.7166 baseline). The cycle insight identifies v002's breakthrough as a meta-parametrization concept but notes it "encounters interference or fails to unify the behavior" of the three variants. This hypothesis tests whether the formula's hit-rate regression was caused by parameter misalignment: if v002 paired the adaptive divisor with baseline or tight geometry, increased stash capacity (75/25) may provide more buffer for adaptive promotion without triggering cascading false-positive promotions. This tests the universality of the adaptive formula in a less constrained geometry space, separating the question "does the formula work?" from "does it work in all geometries?" and moving toward a geometry-aware meta-formula that could enable threshold tuning to be truly orthogonal.
