# H01

Applying v003's slim `Item` to v001's MRU-promotion winner compounds the wins, holding hit-rate at ~0.679 while dropping metadata-size from 40 to 24 and trimming per-op-time.

## Parent

cycle/0001/v001

## Changes

v001 is the MRU-promotion winner: its only change from baseline is
`promotion_get(&mut self.core, key, InsertPosition::Back)` in
`DashSegment::get`, which gives the best measured hit-rate (0.6787) but
still carries the fat baseline `Item` (metadata-size 40, per-op 91).

Keep v001's `get` exactly as-is (the `InsertPosition::Back` promotion is
load-bearing for the hit-rate). On top of it, port v003's `Item` slimming
into `src/shared/item.rs`:

- Remove the `timestamp: Instant` field and the `use std::time::Instant`
  import; delete the `timestamp` initialiser in `Item::new` and the
  `timestamp` formatting in the `Display` impl.
- Change `lfu_counter` from `usize` to `u8` (keep the field so the `Lfu`
  policy still compiles).

Also mirror v003's `src/shared/eviction_policy.rs` adjustment: drop the
now-unused `use std::time::Instant;` and update `TimestampLRU`'s
`get_from_position` / candidate methods so the file still compiles without
the `timestamp` field (i.e. make `TimestampLRU` fall back to positional
behaviour the way v003 did). Preserve all `Item` `PartialEq`/`Eq`
semantics (compare key+value only) and keep every existing public method
signature so the gate tests pass.

## Rationale (optional)

v001 and v003 moved orthogonal axes (placement vs. footprint) with no
shared code beyond `Item`, so the effects should add rather than cancel —
this is the cheapest path to dominating two incumbents at once.
