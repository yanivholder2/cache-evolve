# H02

Devirtualize the eviction policy on the hot get/put path by replacing the bucket's `Box<dyn EvictionPolicy>` calls with a directly-inlined ClassicLRU implementation, targeting per-op-time.

## Parent

cycle/0002/v001

## Changes

Every bucket operation currently routes through dynamic dispatch:
`put_at`, `get_from_position`, `evict_item`, and the candidate-index
helpers all call methods on `get_eviction_policy() -> &dyn
EvictionPolicy<K,V>`. On the hot path a single `get` triggers several
vtable indirections (the `get_from_position` remove+push, plus
`eviction_candidate_index`/`promotion_candidate_index` on inserts), none
of which the compiler can inline across the trait-object boundary. This
is a per-operation structural cost — not a one-scan micro-saving — so it
is sized to clear the harness noise floor that swallowed cycle/0003/v003's
branch reorder.

Concretely, in `src/shared/traits/bucket.rs` (overlay-editable) add a
fast path that bypasses the trait object when the bucket's policy is
ClassicLRU:

1. Implement ClassicLRU's three operations as free, monomorphized,
   `#[inline]` functions over `Vec<Item<K,V>>`:
   `lru_get_from_position` (remove at `position`, push to back, return
   `len-1`), `lru_eviction_index` (`0`), `lru_promotion_index`
   (`len-1`) — mirroring the bodies in `eviction_policy.rs` exactly.

2. In `put_at`, `get_from_position`, and `evict_item`, branch once on a
   cheap policy-kind check (store the `EvictionPolicyKind` enum or a
   `bool is_classic_lru` on the bucket struct at construction) and call
   the inlined functions directly for the ClassicLRU case, falling back
   to the existing `get_eviction_policy()` virtual call for all other
   policies.

Preserve invariants: behaviour must be identical for every policy
(ClassicLRU results bit-for-bit unchanged), hit-rate and metadata-size
must not move, and the `Box<dyn EvictionPolicy>` field stays for the
non-specialized policies. The only intended effect is lower get/put
p50/p99 from eliminated vtable indirection and now-inlinable
remove+push. Do not edit the locked gate-integrity files
(`factory.rs`, `jni.rs`, etc.); the kind check must be derivable from
data the bucket already owns.

## Rationale (optional)

Per-op-time is the one fitness dimension the cross-cycle narrative still
calls open, with the explicit question "what granularity of structural
change IS resolvable by this harness?" Removing a per-op vtable
indirection plus enabling inlining is a structurally larger lever than
the sub-noise single-scan reorders that previously failed.
