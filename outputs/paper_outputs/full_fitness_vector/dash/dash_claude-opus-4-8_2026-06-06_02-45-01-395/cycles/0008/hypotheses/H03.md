# H03

Drop the one-more-chance retry in probing demotion and route evicted items straight to stash, removing the cascade eviction that bounds put-p99.

## Parent

cycle/0007/v001

## Changes

In `src/dash/segments/dash_segment.rs`, simplify `demote_from_normal_bucket`
so a probing-evicted foreign resident no longer re-inserts into its true
target before falling to the stash.

Current behaviour: when `true_target != source_idx` (the item was a
foreign resident in someone else's probing slot), the function retries
`put_at(Slot::Target, ...)`, and if that target is full it cascades the
target's LRU victim down to the stash with a second `put_at(Slot::Stash,
...)`. That retry-plus-cascade is the eviction/cascade work cycle 0007
(v003) located as the put-p99 bound.

Replace the whole `else` branch with a single unconditional
`core.put_at(Slot::Stash, insert_pos, item)` — i.e. always demote a
normal-bucket eviction directly to its stash, collapsing the two-tier
cascade to one hop. Keep the `true_target == source_idx` branch as is
(it already goes straight to stash), so the two branches become
identical and the function reduces to one stash insert. Keep the
`insert_pos` plumbing intact so cold/hot placement still honors
Front/Back.

The testable claim is a latency-vs-hit-rate trade that the cross-cycle
evidence predicts is free on hit-rate: the insight establishes hit-rate
is firmly capacity/compulsory-bound and conflict-insensitive on this
trace, so removing the one-more-chance step (a conflict-mitigation
mechanism) should leave hit-rate at 0.6794 while cutting the per-put p99
cascade. If hit-rate holds and put-p99 drops, the one-more-chance retry
is confirmed pure latency overhead under ClassicLRU.

Note the existing cascade unit tests (`evicted_from_probing_cascades_to_target`,
`target_retry_lands_*`, `cascade_to_stash_*`) assert the old two-tier
behaviour and will need to be updated to the single-hop semantics as part
of this change; do not touch the gate-integrity/invariant suites.

## Rationale (optional)

This probes the eviction cascade directly, as the cycle-0007 continuation
recommended, rather than economizing the per-put side-table probe (already
the cheapest form of its operation). It converts the insight that hit-rate
is conflict-insensitive into a concrete latency win.
