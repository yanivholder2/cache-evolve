# H03

Bypassing the target tier on stash hits when the target bucket is already full will improve hit rate by eliminating the cascading eviction that displaces a resident target item for every returning stash item.

## Parent

cycle/0001/v003

## Changes

Modify `src/dash/segments/dash_segment.rs` only (inheriting v003's slimmer `Item` struct and its position-based `TimestampLRU`, but using `InsertPosition::Front` from v003's baseline segment, not v001's `Back`).

In `promotion_get`, replace the stash-hit branch with a full/not-full decision:

```
// current stash-hit branch (v003 / baseline):
if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key) {
    let data = core.stash_buckets[stash_idx].remove_at(item_idx);
    promote_to_target(core, data, insert_pos);
    let Some(item_new_idx) = core.buckets[target_idx].get_position(key) else {
        unreachable!("...");
    };
    return Some(&core.buckets[target_idx].get_items()[item_new_idx]);
}

// replacement:
if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key) {
    let data = core.stash_buckets[stash_idx].remove_at(item_idx);
    if core.buckets[target_idx].is_full() {
        // Target is saturated: skip it and land directly in probing,
        // preserving the target's current residents.
        promote_to_probing(core, data, insert_pos);
        let item_new_idx = core.buckets[probing_idx]
            .get_position(key)
            .expect("promote_to_probing must leave key in probing (stash bypass)");
        return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
    } else {
        // Target has capacity: use the normal path.
        promote_to_target(core, data, insert_pos);
        let item_new_idx = core.buckets[target_idx]
            .get_position(key)
            .expect("promote_to_target must leave key in target");
        return Some(&core.buckets[target_idx].get_items()[item_new_idx]);
    }
}
```

The target-hit branch and probing-hit branch are unchanged. The `insert_pos` argument is still `InsertPosition::Front` (v003 default). The existing `promote_to_probing` function is reused unchanged; it already handles the demotion cascade if probing is full.

## Rationale

In the current design (baseline and v003), every stash hit unconditionally calls `promote_to_target`. When the target is already full, this evicts a resident item, which then cascades toward stash — replacing one eviction with another, effectively penalising an existing resident to admit a returning item. Skipping the target entirely when it is full stops this churn: the returning item earns probing placement directly (a higher-value tier), and the target's resident set is not disturbed. The cost is that the returning item skips the target warm-up step, but that is a net benefit when the target would have immediately turned it into an eviction event anyway.
