# H03

Lowering the vacancy-gated probing re-entry threshold from counter≥2 to counter≥1 will shorten the hot-item recycling path between the probing and target tiers, increasing effective hit rate on Zipfian traces.

## Parent

cycle/0006/v001

## Changes

In `src/dash/segments/dash_segment.rs`, in `promotion_get`'s probing lookup branch, change the counter threshold for the vacancy-gated probing re-entry from `counter >= 2` to `counter >= 1`:

```rust
// Before:
if counter >= 2 && target_has_space {

// After:
if counter >= 1 && target_has_space {
```

The surrounding logic is unchanged: `lfu_counter` is still incremented by 1 on every probing hit, `target_has_space` is still checked (vacancy gate preserved), and the re-entry fires `promote_to_target(core, data, InsertPosition::Back)`. All other code from cycle/0006/v001 is kept verbatim: MRU-end insertion, vacancy-gated frequency promotion at freq≥2 in the non-hottest target branch, ClassicLRU (LFU-min) eviction, `promote_to_target`, `promote_to_probing`, `demote_from_normal_bucket`. No changes to `eviction_policy.rs` or `item.rs`.

Update the test `vacancy_gated_probing_reentry_fires_when_target_has_space` to reflect the new threshold: pre-set `lfu_counter = 0` (not 1) before the triggering get, verify that after one get the counter reaches 1 and re-entry fires. Update `probing_hit_stays_when_counter_below_threshold` to confirm the gate is still silenced at counter=0 (before the first increment on a fresh probing item with no prior hits, though this case requires a freshly placed item with counter left at 0 that is never accessed — the test should confirm counter=0 before the get and that gate does not fire on the very first access because the increment makes counter=1 which IS ≥1; so this test must be replaced with one that verifies gate fires on first probing hit when target has space).

## Rationale

Cross-cycle analysis identifies the probing re-entry vacancy gate as "persistently thin on saturated caches" — the binding constraint is the vacancy condition, not the counter threshold. With threshold ≥2 and a thin vacancy window, items that do get probing hits may exhaust those hits before the window opens. Dropping to ≥1 makes every probing hit — however sparse — immediately eligible to recycle the item to target when space exists. This shortens the promotion ladder for the top Zipfian items by one required access per cycle, without changing the vacancy safety property that prevents cascade evictions.
