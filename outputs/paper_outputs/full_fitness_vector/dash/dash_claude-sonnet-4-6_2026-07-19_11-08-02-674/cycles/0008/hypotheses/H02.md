# H02

Bypassing the target tier for warm stash items (lfu_counter ≥ 2) that find probing has space will improve hit-rate on cycle/0006/v001 by shortening the re-promotion path for frequently-accessed items that temporarily fell to stash.

## Parent

cycle/0006/v001

## Changes

In `src/dash/segments/dash_segment.rs`, modify only the stash-hit branch of `promotion_get`. All other code from cycle/0006/v001 (vacancy-gated frequency promotion, vacancy-gated probing re-entry, MRU-end insertion, no clock) remains unchanged.

**Current stash-hit branch:**
```rust
if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key) {
    let data = core.stash_buckets[stash_idx].remove_at(item_idx);
    promote_to_target(core, data, insert_pos);
    let Some(item_new_idx) = core.buckets[target_idx].get_position(key) else { unreachable!(...) };
    return Some(&core.buckets[target_idx].get_items()[item_new_idx]);
}
```

**Replace with:**
```rust
if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key) {
    let data = core.stash_buckets[stash_idx].remove_at(item_idx);
    // Frequency-gated stash bypass: if the stash item already has enough
    // access history (lfu_counter >= 2) AND probing has a vacancy, skip
    // the target tier and insert directly into probing. The vacancy gate
    // ensures no cascade eviction occurs on this fast path.
    let probing_has_space = !core.buckets[probing_idx].is_full();
    if data.lfu_counter >= 2 && probing_has_space {
        promote_to_probing(core, data, insert_pos);
        let item_new_idx = core.buckets[probing_idx]
            .get_position(key)
            .expect("promote_to_probing must leave key in probing");
        return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
    } else {
        // Cold item or probing full: normal stash→target path.
        promote_to_target(core, data, insert_pos);
        let Some(item_new_idx) = core.buckets[target_idx].get_position(key) else {
            unreachable!("promote_to_target must leave key resident in target")
        };
        return Some(&core.buckets[target_idx].get_items()[item_new_idx]);
    }
}
```

`probing_idx` is already computed as `(target_idx + 1) % core.segment_size` at the top of `promotion_get`, so no extra computation is needed.

**Preserve `item.rs`** unchanged from cycle/0006/v001 (no struct fields added; metadata-size stays at 24).

**Threshold**: use `lfu_counter >= 2` to match the existing frequency-gate threshold, keeping the warm/cold boundary consistent across the code. Items arriving from stash with lfu_counter=0 or lfu_counter=1 always take the normal target path.

**Why the vacancy gate is sufficient for safety**: `promote_to_probing` is already used by the vacancy-gated frequency promotion path; when `!probing.is_full()` is true, `put_at(Slot::Probing, ...)` returns `None` (no eviction), so no cascade can occur.

## Rationale

In cycle/0006/v001, a stash item must travel stash → target → (two non-hottest hits to reach lfu_counter ≥ 2) → probing. For an item that was warm before it fell to stash (lfu_counter ≥ 2 already preserved in stash), this two-step re-promotion is unnecessary — the item has already earned its place in probing. This change collapses that path to a single step when the gate fires, reducing the window during which a hot item sits in target and is exposed to eviction pressure. The mechanism is orthogonal to H01 (no clock involved) and to probing re-entry (which moves items from probing back to target, the opposite direction). Prior "stash bypass" experiments in cycles 2–3 were triggered by target fullness; this bypass is triggered by item warmth, a distinct and untested condition.
