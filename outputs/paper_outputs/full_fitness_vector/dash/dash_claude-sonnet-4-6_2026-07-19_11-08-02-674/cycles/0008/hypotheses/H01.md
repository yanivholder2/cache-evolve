# H01

Adding a two-chance clock eviction to cycle/0006/v001 using the high bit of `lfu_counter` as an independent "clock chance" flag — leaving the low bits as the unmodified frequency counter — will improve hit-rate without the counter-corruption regression that destroyed cycle/0007/v001.

## Parent

cycle/0006/v001

## Changes

The root conflict diagnosed in cycle/0007 is that `clock_evict_prepare` decrements `lfu_counter`, corrupting the frequency signal that the vacancy-gated promotion gate reads. The fix is to encode the clock's "warm" signal in the *high bit* of `lfu_counter` so the clock and the frequency counter share the same field without interfering.

In `src/dash/segments/dash_segment.rs`, starting from cycle/0006/v001's code (MRU-end insertion, vacancy-gated frequency promotion ≥ 2, vacancy-gated probing re-entry ≥ 2, no clock):

1. **Add module-level constant:**
   ```rust
   const CLOCK_BIT: usize = 1 << (usize::BITS - 1);
   ```

2. **Add `clock_evict_prepare`** that tests and clears `CLOCK_BIT` instead of decrementing the counter:
   ```rust
   fn clock_evict_prepare<K, V>(items: &mut Vec<Item<K, V>>)
   where K: Hash + Eq + Clone, V: Eq + Clone,
   {
       let n = items.len();
       for _ in 0..n {
           if items[0].lfu_counter & CLOCK_BIT == 0 {
               break; // cold (clock bit clear): evict this item
           }
           items[0].lfu_counter &= !CLOCK_BIT; // clear clock bit (second chance consumed)
           items.rotate_left(1);
       }
   }
   ```
   Cold means CLOCK_BIT is not set (item has not been accessed since it entered this bucket, or since it last gave up its clock chance). Warm means CLOCK_BIT is set.

3. **Modify `promote_to_target`** to set CLOCK_BIT on the incoming item if it carries historical frequency (arrived from stash with freq > 0), and to run the clock pre-pass before eviction:
   ```rust
   fn promote_to_target<K, V>(core: &mut SegmentCore<K, V>, mut item: Item<K, V>, insert_pos: InsertPosition)
   where ... {
       // If item has historical frequency, mark it warm to the clock on arrival.
       if item.lfu_counter & !CLOCK_BIT > 0 {
           item.lfu_counter |= CLOCK_BIT;
       }
       let target_idx = get_index(&item.key, core.segment_size);
       if core.buckets[target_idx].is_full() {
           clock_evict_prepare(core.buckets[target_idx].get_items_mut());
       }
       let Some(evicted) = core.put_at(Slot::Target, insert_pos, item) else { return; };
       demote_from_normal_bucket(core, evicted, target_idx, insert_pos);
   }
   ```

4. **Modify `demote_from_normal_bucket`** to run clock pre-pass before the target-retry insert (the `else` branch):
   ```rust
   if core.buckets[true_target].is_full() {
       clock_evict_prepare(core.buckets[true_target].get_items_mut());
   }
   ```
   Apply this immediately before the `core.put_at(Slot::Target, insert_pos, item)` in the `else` branch. No change to the `core.put_at(Slot::Stash, ...)` calls.

5. **Modify `promotion_get` non-hottest target branch** to set CLOCK_BIT alongside the frequency increment, and update the gate check to mask out CLOCK_BIT:
   ```rust
   // Replace:
   core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter += 1;
   let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
   let probing_has_space = !core.buckets[probing_idx].is_full();
   if counter >= 2 && probing_has_space { ... }

   // With:
   let items_mut = core.buckets[target_idx].get_items_mut();
   items_mut[item_idx].lfu_counter = (items_mut[item_idx].lfu_counter + 1) | CLOCK_BIT;
   let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
   let freq = counter & !CLOCK_BIT;
   let probing_has_space = !core.buckets[probing_idx].is_full();
   if freq >= 2 && probing_has_space { ... }
   ```

6. **Modify `promotion_get` probing re-entry branch** to use `(counter & !CLOCK_BIT) >= 2` for the re-entry gate (counter increment in the probing branch remains as-is; CLOCK_BIT is only tracked for target items, not probing):
   ```rust
   core.buckets[probing_idx].get_items_mut()[item_idx].lfu_counter += 1;
   let counter = core.buckets[probing_idx].get_items()[item_idx].lfu_counter;
   let target_has_space = !core.buckets[target_idx].is_full();
   if counter >= 2 && target_has_space { ... } // probing counter doesn't use CLOCK_BIT
   ```
   (Probing re-entry logic is unchanged except that when `promote_to_target` is called from re-entry, the item's CLOCK_BIT will be set by `promote_to_target` if freq > 0.)

7. **Keep `item.rs` identical** to cycle/0006/v001 — no new fields, no struct layout change; metadata-size stays at 24.

The invariant: `CLOCK_BIT` (high bit) is set on target-item access and cleared by the clock rotation. `lfu_counter & !CLOCK_BIT` is the frequency count, incremented on non-hottest target hits and never touched by the clock. The two signals now occupy independent bit ranges within the same word.

## Rationale

Cycle/0007/v001 grafted a standard two-chance clock (with counter decrement) onto cycle/0006/v001 and hit-rate fell from 0.692 to 0.681 because buckets are counter-rich on the 0006/v001 base — the clock rotated all items (O(k·n)) and evicted suboptimally, while also corrupting the ≥ 2 promotion threshold. The CLOCK_BIT encoding eliminates this conflict: the clock never touches the frequency bits, so the promotion gate continues to fire correctly, and the clock's early-exit on CLOCK_BIT=0 items remains meaningful even in a bucket where all frequencies are ≥ 2.
