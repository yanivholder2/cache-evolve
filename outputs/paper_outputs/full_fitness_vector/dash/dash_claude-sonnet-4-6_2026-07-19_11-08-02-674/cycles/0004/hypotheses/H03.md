# H03

Resetting the lfu_counter to zero when an item is promoted from stash into its target bucket will improve hit rate by ensuring the vacancy-gate threshold is evaluated against only fresh post-promotion accesses, preventing stale pre-demotion counts from triggering premature frequency promotion.

## Parent

cycle/0003/v003

## Changes

In `src/dash/segments/dash_segment.rs`, inside the stash-hit branch of `promotion_get`, reset `lfu_counter` to zero on the item before it is placed back into the target tier. Specifically, immediately after:

```rust
let data = core.stash_buckets[stash_idx].remove_at(item_idx);
```

add:

```rust
let mut data = core.stash_buckets[stash_idx].remove_at(item_idx);
data.lfu_counter = 0;
```

(The variable binding must be `mut` to allow field assignment; change the existing `let data` to `let mut data`.)

The subsequent `promote_to_target(core, data, insert_pos)` call is unchanged; the reset item arrives in target with a clean counter.

No changes to `demote_from_normal_bucket`, the non-hottest target branch, the probing branch, or any eviction policy. The vacancy gate itself (`if counter >= 2 && probing_has_space`) remains exactly as in v003; only the counter state carried into target from stash is affected.

Add a unit test `stash_promoted_item_enters_target_with_zero_counter` that: puts an item, manually pre-sets its stash bucket's `lfu_counter` to a non-zero value, performs a stash-hit `get`, then reads back the item from its target bucket and asserts `lfu_counter == 0`. Also add a test `stash_promoted_item_must_re_earn_vacancy_gate` that verifies a stash-promoted item (counter reset to 0) is not vacancy-gate promoted on the first target hit (counter becomes 1, gate stays silent) but is promoted on the second target hit (counter reaches 2, gate fires if probing has space).

No changes to `src/shared/item.rs` or any other file.

## Rationale

Under v003, an item may accumulate `lfu_counter` hits while in its target bucket, earn a vacancy-gate promotion to probing, then be cascade-evicted back to target (via `demote_from_normal_bucket`) or eventually demoted to stash. When it reaches stash and is later re-accessed (a stash hit), it carries its old `lfu_counter` forward. Upon re-entering target at the MRU end (Back insertion), its counter is already ≥ 2, so a single additional target hit immediately re-triggers the vacancy gate. This can create rapid oscillation between target and probing for items whose counter was accumulated long before their stash demotion — a frequency signal that may no longer reflect current access patterns. Resetting the counter at the stash-to-target boundary forces each re-entry to the target tier to re-earn promotion eligibility from fresh evidence, making the frequency signal strictly post-promotion and potentially increasing the hit-rate accuracy of vacancy-gate promotions.
