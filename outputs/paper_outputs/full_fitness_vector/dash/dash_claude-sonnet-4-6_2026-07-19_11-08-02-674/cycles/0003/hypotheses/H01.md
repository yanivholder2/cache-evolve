# H01

Layering saturation-aware stash routing (bypass a full target to probing) onto the MRU-end plus timestamp-free base will improve hit rate by eliminating the cascade eviction triggered on every stash hit when target is saturated.

## Parent

cycle/0002/v001

## Changes

Modify `promotion_get` in `src/dash/segments/dash_segment.rs`. In the stash hit branch — the `if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key)` block — after removing the item with `core.stash_buckets[stash_idx].remove_at(item_idx)`, add a fullness check on `core.buckets[target_idx]` before choosing the promotion path:

```rust
if core.buckets[target_idx].is_full() {
    // Target saturated: skip it and land directly in probing.
    promote_to_probing(core, data, insert_pos);
    let item_new_idx = core.buckets[probing_idx]
        .get_position(key)
        .expect("promote_to_probing must leave key in probing (stash bypass)");
    return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
} else {
    // Target has capacity: use the normal path.
    promote_to_target(core, data, insert_pos);
    let item_new_idx = core.buckets[target_idx]
        .get_position(key)
        .expect("promote_to_target must leave key in target");
    return Some(&core.buckets[target_idx].get_items()[item_new_idx]);
}
```

`InsertPosition::Back` is kept throughout. No other branches are modified. No changes to `item.rs` or `eviction_policy.rs` are needed (cycle/0002/v001 already removed the timestamp field).

## Rationale (optional)

cycle/0002/v003 proved stash bypass improves hit rate but was built on the LRU-end baseline (InsertPosition::Front). cycle/0002/v001 is the stronger base — it already has MRU-end insertion and a compact 24-byte Item. These two improvements have never been tested together; this variant closes that gap and tests whether the bypass benefit is additive on the best-in-class foundation.
