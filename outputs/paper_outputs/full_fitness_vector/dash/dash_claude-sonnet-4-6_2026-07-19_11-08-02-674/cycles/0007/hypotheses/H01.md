# H01

Replacing cycle/0006/v001's O(n) LFU-minimum eviction scan with a two-chance clock pre-pass — while retaining its vacancy-gated target promotion and probing re-entry — will improve hit rate above 0.692 by making frequency-aware eviction available at O(1) amortized cost.

## Parent

cycle/0006/v001

## Changes

`cycle/0006/v001` currently achieves frequency-aware eviction by scanning the entire target bucket for the item with the lowest `lfu_counter` (in `ClassicLRU::eviction_candidate_index`). This O(n) scan is the mechanism that Cycle 6 identified as the component most in need of replacement. `cycle/0006/v003` solved the same problem with a two-chance clock pre-pass that terminates early on cold items. This hypothesis grafts the clock onto v001's complete promotion stack.

### `src/shared/eviction_policy.rs`

Revert `ClassicLRU::eviction_candidate_index` from the LFU-minimum loop back to the constant-zero positional form used in `cycle/0006/v003`:

```rust
fn eviction_candidate_index(&self, _items: &[Item<K, V>]) -> usize {
    0
}
```

Leave `ClassicLRU::get_from_position` (rotate-to-back) and `ClassicLRU::promotion_candidate_index` (last position) unchanged; they are the same in both v001 and v003.

Carry forward all other policies (`TimestampLRU`, `Lifo`, `Lfu`, `Fifo`, `Swap`) and the full `EvictionPolicyKind` enum unchanged from v001's `eviction_policy.rs`.

### `src/dash/segments/dash_segment.rs`

Retain ALL promotion logic from `cycle/0006/v001` exactly (vacancy-gated target frequency promotion in the non-hottest target branch, vacancy-gated probing re-entry in the probing branch, hottest-target → probing promotion, stash → target promotion, and `demote_from_normal_bucket`). Do not alter any threshold values or gate conditions.

Add the `clock_evict_prepare` function from `cycle/0006/v003`:

```rust
fn clock_evict_prepare<K, V>(items: &mut Vec<Item<K, V>>)
where
    K: Hash + Eq + Clone,
    V: Eq + Clone,
{
    let n = items.len();
    for _ in 0..n {
        if items[0].lfu_counter == 0 {
            break;
        }
        items[0].lfu_counter -= 1;
        items.rotate_left(1);
    }
}
```

Insert a clock pre-pass into `promote_to_target` before calling `core.put_at(Slot::Target, ...)`:

```rust
fn promote_to_target<K, V>(...) {
    let target_idx = get_index(&item.key, core.segment_size);
    if core.buckets[target_idx].is_full() {
        clock_evict_prepare(core.buckets[target_idx].get_items_mut());
    }
    let Some(evicted) = core.put_at(Slot::Target, insert_pos, item) else { return; };
    demote_from_normal_bucket(core, evicted, target_idx, insert_pos);
}
```

Insert a clock pre-pass into `demote_from_normal_bucket` before the target retry insertion (in the `else` branch where `true_target != source_idx`):

```rust
if core.buckets[true_target].is_full() {
    clock_evict_prepare(core.buckets[true_target].get_items_mut());
}
if let Some(cascade) = core.put_at(Slot::Target, insert_pos, item) {
    core.put_at(Slot::Stash, insert_pos, cascade);
}
```

Do not add clock pre-passes to `promote_to_probing` (probing items are always the hottest in their target bucket and have the highest counters in the bucket, so positional LRU there is already frequency-correlated).

### `src/shared/item.rs`

Inherit unchanged from `cycle/0006/v001` (no `timestamp` field, `lfu_counter: usize` only).

## Rationale

`cycle/0006/v001`'s `lfu_counter` is incremented on every non-hottest target hit and on every probing hit (re-entry path). When this variant's target bucket needs to evict, it scans all items for the global minimum — an O(n) operation. The two-chance clock replaces the scan with an early-exit rotation: items with `lfu_counter > 0` are given one reprieve (counter decremented, rotated to MRU end) and the first cold item found at position 0 is evicted. On a Zipfian workload the cold tail dominates, so the clock terminates early. Because v001's promotion gates ensure `lfu_counter` is non-zero for genuinely warm items, the clock's frequency-awareness is fully activated — unlike in v003 where counters are always zero and the clock degenerates to positional LRU. The expected outcome is that all three fitness dimensions hold or improve: hit rate stays at or above 0.692 (frequency-aware eviction preserved), per-op time stays at 100 ns (scan cost removed), and metadata-size stays at 24 bytes (struct unchanged).
