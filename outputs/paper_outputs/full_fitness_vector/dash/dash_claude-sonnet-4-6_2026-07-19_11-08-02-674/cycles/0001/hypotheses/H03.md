# H03

Removing the `timestamp: Instant` field from `Item` will shrink per-item metadata by 16 bytes (from 40 to 24 bytes) and eliminate the `Instant::now()` syscall on every `put`, reducing insert latency as a side effect.

## Parent

baseline

## Changes

Three files must be overlaid together; they form a closed dependency set.

### 1. `src/shared/item.rs`

Remove the `timestamp` field and its initialiser:

```rust
// Remove this import
use std::time::Instant;

// Item struct: drop the timestamp field
pub struct Item<K, V> { ... } {
    pub key: K,
    pub value: V,
    pub lfu_counter: usize,
    // timestamp: Instant  ← remove
}

// Item::new: drop the timestamp line
pub fn new(key: K, value: V) -> Self {
    Self {
        key,
        value,
        lfu_counter: 0,
        // timestamp: Instant::now()  ← remove
    }
}
```

Update `Display::fmt` to remove the `, timestamp: {:?}` part and the corresponding `self.timestamp` argument from the `write!` call. The existing `item.rs` tests (`new_initializes_fields`, `equality_*`, `clone_*`) do not reference `timestamp` and require no changes.

### 2. `src/shared/eviction_policy.rs`

`TimestampLRU` accesses `item.timestamp` in all three trait methods. With the field gone the file will not compile. Degrade `TimestampLRU` to position-based LRU (identical to `ClassicLRU` behaviour):

```rust
impl<K, V> EvictionPolicy<K, V> for TimestampLRU { ... } {
    fn name(&self) -> &'static str { "TimestampLRU" }

    fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
        // was: items[position].timestamp = Instant::now(); position
        let item = items.remove(position);
        items.push(item);
        items.len() - 1
    }

    fn eviction_candidate_index(&self, _items: &[Item<K, V>]) -> usize {
        // was: min_by_key(item.timestamp)
        0
    }

    fn promotion_candidate_index(&self, items: &[Item<K, V>]) -> usize {
        // was: max_by_key(item.timestamp)
        items.len() - 1
    }
}
```

Remove `use std::time::Instant` from this file as well (no longer needed).

### 3. `src/shared/traits/bucket.rs`

Two `TimestampLRU` tests in the inline test suite rely on the field's previous no-reorder behaviour and must be updated:

- **`timestamp_lru_get_does_not_reorder_vec`**: The updated `TimestampLRU` now physically moves the accessed item to the back (ClassicLRU behaviour). Change the post-`get` assertion from `vec![1, 2]` to `vec![2, 1]` and rename the test to `timestamp_lru_get_moves_to_back` to reflect the new semantics.

- **`timestamp_lru_evicts_oldest_timestamp`**: The test already passes under the new implementation. After `bucket.get(&1)` moves key 1 to the back, the LRU candidate is key 2 (position 0), which is what the assertion checks. No change needed.

All other `TimestampLRU` tests and all tests for `ClassicLRU`, `Lfu`, `Fifo`, `Lifo`, and `Swap` are unaffected.
