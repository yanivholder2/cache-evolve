# H02

Forcing LFU eviction across all buckets by overriding the harness-supplied eviction policy in `DashSegment::try_new` will improve hit rate on Zipfian traces and reduce per-get time by replacing O(n) Vec shifts with a single counter increment on every bucket access.

## Changes

In `src/dash/segments/dash_segment.rs`, modify `DashSegment::try_new` to shadow the harness-supplied policy with `EvictionPolicyKind::Lfu` before constructing the `SegmentCore`. Add the necessary import and build a modified-settings copy:

```rust
use crate::shared::eviction_policy::EvictionPolicyKind;

pub fn try_new(settings: &DashSettings) -> Option<Self> {
    let lfu_settings = DashSettings {
        eviction_policy: EvictionPolicyKind::Lfu,
        ..*settings
    };
    if let Some(core) = SegmentCore::try_new(&lfu_settings) {
        info!("DashSegment.try_new");
        Some(Self { core })
    } else {
        log::error!("DashSegment.try_new: core initialization failed");
        None
    }
}
```

`DashSettings` is `Copy`, so the spread is zero-cost. All normal and stash buckets in the segment now use `Lfu`, regardless of the policy the Caffeine harness configures.

**Behavioral consequences of Lfu:**

- `get_from_position` increments `items[position].lfu_counter` in place and returns the same position — O(1), no `Vec::remove + push`, no element shifting.
- `eviction_candidate_index` scans for the minimum `lfu_counter`, evicting the least-frequently accessed item rather than the LRU item.
- `promotion_candidate_index` scans for the maximum `lfu_counter`. An item earns promotion to probing when it accumulates more accesses than any other item in its target bucket — not just by being the most recent.

On a Zipfian trace the most popular keys quickly dominate every bucket's frequency distribution and resist eviction; cold keys (counter=0) are evicted first regardless of when they arrived.

**Inline test updates in `dash_segment.rs`:**

The tests `new_segment(EvictionPolicyKind::ClassicLRU)` now implicitly run with Lfu (the argument is overridden). Two tests assume ClassicLRU's in-place physical reordering and need updating:

- **`target_hit_not_hottest_promotes_within_bucket`**: After the two-item setup (keys[1] at pos 0, keys[0] at pos 1, both `lfu_counter=0`), `seg.get(&keys[1])` finds keys[1] not-hottest (tied counters break to the last position, pos 1 = keys[0]), increments keys[1].lfu_counter to 1, and leaves it at position 0. Change the assertions to `assert_eq!(items[0].key, keys[1])` and `assert_eq!(items[1].key, keys[0])` to reflect that Lfu never physically moves items on a hit.

- **`stash_hit_inserts_at_front_of_target`**: Positions after `put_at(InsertPosition::Front, ...)` are unaffected by policy — the insert path in `Bucket::put_at` uses `Vec::insert(0, item)` regardless of the eviction policy. This test still passes without modification.

All other tests (`target_hit_hottest_promotes_to_probing` with its two-get sequence, `probing_hit_touches_in_place`, wraparound and cascade tests) remain valid under Lfu because the promotion sequence requires two accesses under both policies.
