# H01

Replacing position-first victim selection in `ClassicLRU::eviction_candidate_index` with a linear scan that evicts the item with the lowest `lfu_counter` will improve hit-rate by retaining frequently-accessed items when a bucket overflows.

## Parent

cycle/0003/v003

## Changes

This variant inherits all three overlay files from cycle/0003/v003 and modifies only `eviction_policy.rs`. All three files must be present in the overlay to avoid the coverage-gap regression seen in cycle/0004.

**`src/shared/item.rs`** — Carry forward unchanged from cycle/0003/v003: `Item<K, V>` has `key`, `value`, and `lfu_counter` fields only; no `timestamp` field; `new()` does not call `Instant::now()`; `Display` does not print a timestamp.

**`src/shared/eviction_policy.rs`** — Carry forward all struct definitions and the `TimestampLRU` positional-clone variant unchanged. In the `ClassicLRU` implementation of `EvictionPolicy`, change `eviction_candidate_index` from returning the constant `0` to performing a linear scan: iterate over the `items: &[Item<K, V>]` slice with `.iter().enumerate()`, track the index that yields the minimum `lfu_counter`, and return that index. Use `0` as the tiebreaker when multiple items share the minimum counter value. No other methods or structs change. The `use std::time::Instant` import must remain absent (as in the parent).

**`src/dash/segments/dash_segment.rs`** — Carry forward entirely unchanged from cycle/0003/v003: MRU-end insertion via `InsertPosition::Back`; vacancy-gated frequency promotion in the non-hottest target branch (`lfu_counter >= 2` AND probing bucket not full); all existing unit tests including `vacancy_gated_frequency_promote_fires_when_probing_has_space` and `vacancy_gated_promote_does_not_fire_when_probing_full`.

## Rationale

The current `ClassicLRU` always evicts the item at position 0 (the LRU end), which is correct when recency is the only signal. But after MRU-end insertion and intra-bucket promotion, position 0 holds the item that has gone longest without *recent* access — its `lfu_counter` may still be high (it was a hot item that had a brief access gap), while a freshly inserted cold item at position N-2 carries `lfu_counter = 0`. Frequency-minimum victim selection evicts the genuinely coldest item rather than the most-recently-cold item, which on the Zipfian workload-a trace should reduce false evictions of hot items temporarily sitting at cold positions.
