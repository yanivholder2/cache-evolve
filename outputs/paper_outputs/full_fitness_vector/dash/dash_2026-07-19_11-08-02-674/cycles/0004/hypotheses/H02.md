# H02

Adding a probing-vacancy guard to the stash-saturation bypass will improve hit rate by routing stash-promoted items directly into probing only when a slot is available, eliminating the cascade eviction that made the unguarded bypass regress in cycle/0003/v001.

## Parent

cycle/0003/v003

## Changes

In `src/dash/segments/dash_segment.rs`, inside the stash-hit branch of `promotion_get` (the `if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key)` arm), add a dual-condition bypass path between the existing `remove_at` call and the `promote_to_target` call.

Current code in that branch (after removing the item from stash):

```rust
let data = core.stash_buckets[stash_idx].remove_at(item_idx);
promote_to_target(core, data, insert_pos);

let Some(item_new_idx) = core.buckets[target_idx].get_position(key) else {
    unreachable!(...)
};
return Some(&core.buckets[target_idx].get_items()[item_new_idx]);
```

Replace with:

```rust
let data = core.stash_buckets[stash_idx].remove_at(item_idx);
let target_full = core.buckets[target_idx].is_full();
let probing_has_space = !core.buckets[probing_idx].is_full();
if target_full && probing_has_space {
    // Vacancy-gated stash bypass: target is saturated but probing has room.
    // Land directly in probing with zero cascade cost.
    debug!("promotion_get: key={key:?} stash bypass -> probing={probing_idx} (target full, probing has space)");
    promote_to_probing(core, data, insert_pos);
    let item_new_idx = core.buckets[probing_idx]
        .get_position(key)
        .expect("promote_to_probing must leave key in probing (vacancy-gated stash bypass)");
    return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
} else {
    // Normal path: target has capacity, or both tiers are full (must cascade).
    promote_to_target(core, data, insert_pos);
    let Some(item_new_idx) = core.buckets[target_idx].get_position(key) else {
        unreachable!("promote_to_target must leave key in target")
    };
    return Some(&core.buckets[target_idx].get_items()[item_new_idx]);
}
```

Update the struct-level and `promotion_get` doc comments to describe the vacancy-gated bypass. Add a unit test `stash_bypass_fires_only_when_target_full_and_probing_has_space` that: (a) fills target, leaves probing with one vacancy, does a stash hit, and asserts the item lands in probing; (b) fills both tiers, does a stash hit, and asserts the item goes through target as before. No changes to any other file.

## Rationale

cycle/0003/v001 showed that stash bypass without a vacancy guard regresses under MRU-end insertion because back-insertion keeps target saturated most of the time, causing the bypass to fire far too often and turning probing into a spillover sink. The vacancy-gated frequency promotion in v003 proved that tying any upward-tier move to probing capacity structurally eliminates cascade cost. Applying the same guard to the stash bypass creates the analogous cascade-safe path: bypass fires only when the receiving tier has room, so no eviction can occur from that insertion. On traces where stash hits are common and probing vacancies exist at the time of those hits, this should recover hit rate without latency regression.
