# H03

Building from the baseline with MRU-end insertion, timestamp removal, and LFU-minimum eviction victim selection — but deliberately omitting any frequency-gated promotion — will improve hit-rate and metadata-size by retaining high-frequency items through better eviction choices alone, isolating the eviction mechanism's contribution without the cascade risk of a promotion gate.

## Parent

baseline

## Changes

This variant starts from the unmodified baseline and introduces three coordinated changes across the same three files used by the leading incumbents.

**`src/shared/item.rs`** — Remove the `pub timestamp: Instant` field from `Item<K, V>`. Remove the `use std::time::Instant` import. In `Item::new()`, remove the `timestamp: Instant::now()` field initializer. In `impl Display for Item`, remove the timestamp line. The resulting struct has only `key`, `value`, and `lfu_counter` fields, matching the incumbent variants. This eliminates the per-item syscall and reduces the per-item footprint toward the 24-byte target.

**`src/shared/eviction_policy.rs`** — Remove `use std::time::Instant`. Replace the real timestamp-based `TimestampLRU` implementation with a positional clone of `ClassicLRU`: `get_from_position` does a `remove(position)` then `push(item)` at the back (no timestamp write or read); `eviction_candidate_index` returns `0`; `promotion_candidate_index` returns `items.len() - 1`. In `ClassicLRU::eviction_candidate_index`, replace the constant-`0` return with a linear scan over `items: &[Item<K, V>]` using `.iter().enumerate()` to find and return the index with the minimum `lfu_counter`, using `0` as the tiebreaker on ties. All other policy structs (`Lfu`, `Lifo`, `Fifo`, `Swap`) carry forward unchanged.

**`src/dash/segments/dash_segment.rs`** — Change the insertion position for items promoted from stash to target from `InsertPosition::Front` to `InsertPosition::Back`, so newly promoted items land at the MRU end. Do NOT add any frequency gate or vacancy-gated inter-tier promotion logic — leave the non-hottest target branch as a plain intra-bucket MRU update with no `lfu_counter` check and no probing-vacancy check. This intentionally isolates the effect of LFU-minimum eviction from the effect of frequency-gated promotion, which is already validated in cycle/0003/v003.

## Rationale

Every incumbent variant stacks MRU-end insertion, timestamp removal, and vacancy-gated frequency promotion together. This conflates two independent mechanisms: (a) promoting items based on frequency and (b) evicting items based on frequency. Hypothesis H01 adds LFU-minimum eviction on top of v003's full feature set; this hypothesis tests whether LFU-minimum eviction alone — without any inter-tier promotion gating — can achieve meaningful hit-rate improvement over the baseline. If it can, it points to eviction selection as the dominant lever. If it cannot match v003's result, it confirms that promotion gating carries unique value not captured by eviction selection alone.
