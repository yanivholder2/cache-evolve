# H03

Adding a probing-vacancy pre-check to frequency-gated promotion will preserve the frequency signal while eliminating the cascade cost entirely by ensuring gate-fires only occur when probing has spare capacity.

## Parent

cycle/0002/v001

## Changes

Modify `promotion_get` in `src/dash/segments/dash_segment.rs`. In the non-hottest target branch — the `else` block inside `if let Some(item_idx) = core.buckets[target_idx].get_position(key)` where `is_hottest` is false — add counter tracking and a vacancy-gated early-promotion path that only fires when `probing_idx` has room:

```rust
} else {
    core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter += 1;
    let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
    let probing_has_space = !core.buckets[probing_idx].is_full();
    if counter >= 2 && probing_has_space {
        debug!("promotion_get: key={key:?} found in target item_idx={item_idx} lfu_counter={counter} probing={probing_idx} has space (vacancy-gated frequency-promote)");
        let data = core.buckets[target_idx].remove_at(item_idx);
        promote_to_probing(core, data, insert_pos);
        let item_new_idx = core.buckets[probing_idx]
            .get_position(key)
            .expect("promote_to_probing must leave key in probing");
        return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
    }
    debug!("promotion_get: key={key:?} found in target item_idx={item_idx} lfu_counter={counter} (intra-promote)");
    return Some(core.buckets[target_idx].get_from_position(item_idx));
}
```

The gate threshold stays at `>= 2` (same as cycle/0002/v002), but the second condition `!core.buckets[probing_idx].is_full()` must also be true. When probing is full the gate is silenced regardless of counter value; the item receives the normal intra-bucket touch via `get_from_position`. `InsertPosition::Back` is maintained throughout. No changes to `item.rs` or `eviction_policy.rs`.

## Rationale (optional)

cycle/0002/v002's latency regression was attributed to cascade evictions triggered each time the frequency gate fired into a full probing bucket — each gate-fire displaced a probing resident and cascaded downstream. Raising the threshold (H02) reduces gate-fire rate but still allows cascades when they do fire. This variant instead eliminates the cascade at its source: gate-fires are structurally guaranteed to find room in probing, so no eviction cascade can occur. The trade-off is that items whose frequency qualifies them for promotion must wait until probing has vacancy, which may delay their residency there. Whether the zero-cascade guarantee outperforms the higher-threshold approach (H02) is the question this variant answers alongside it.
