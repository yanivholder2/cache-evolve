# H02

Raising the frequency-gate promotion threshold from two to three accesses will reduce cascade-eviction frequency enough to recover cycle/0002/v002's per-op-time regression while retaining most of its hit-rate gain.

## Parent

cycle/0002/v001

## Changes

Modify `promotion_get` in `src/dash/segments/dash_segment.rs`. In the non-hottest target branch — the `else` block inside `if let Some(item_idx) = core.buckets[target_idx].get_position(key)` where `is_hottest` is false — replace the current single-line `get_from_position` intra-promote return with counter tracking and threshold-gated early promotion:

```rust
} else {
    core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter += 1;
    let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
    if counter >= 3 {
        debug!("promotion_get: key={key:?} found in target item_idx={item_idx} lfu_counter={counter} (frequency-promote to probing={probing_idx})");
        let data = core.buckets[target_idx].remove_at(item_idx);
        promote_to_probing(core, data, insert_pos);
        let item_new_idx = core.buckets[probing_idx]
            .get_position(key)
            .expect("promote_to_probing must leave key in probing");
        return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
    }
    debug!("promotion_get: key={key:?} found in target item_idx={item_idx} lfu_counter={counter} (intra-promote)");
    return Some(core.buckets[target_idx].get_from_position(item_idx));
}
```

The only difference from cycle/0002/v002's gate is `>= 3` instead of `>= 2`. `InsertPosition::Back` is kept throughout. No changes to `item.rs` or `eviction_policy.rs` (cycle/0002/v001 already removed the timestamp field; lfu_counter is already present in Item).

## Rationale (optional)

cycle/0002/v002 showed the frequency signal is real — the workload contains re-accessed non-hottest items — but threshold ≥ 2 fires broadly enough that cascade churn erases most of the latency budget. The cycle insight explicitly nominated ≥ 3 or ≥ 4 as the next calibration point. This variant tests ≥ 3 on the best-scored base (cycle/0002/v001, which cycle/0002/v002 never had access to since v002 was parented on cycle/0001/v001 and retained the 40-byte Item).
