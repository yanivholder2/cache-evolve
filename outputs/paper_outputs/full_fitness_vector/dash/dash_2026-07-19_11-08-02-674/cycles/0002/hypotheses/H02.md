# H02

Incrementing `lfu_counter` on each non-hottest target hit and using a frequency threshold as a secondary promotion gate will raise hit rate by fast-tracking repeatedly-accessed items to the probing tier.

## Parent

cycle/0001/v001

## Changes

Modify `src/dash/segments/dash_segment.rs` only. In the `promotion_get` function, in the branch where the key is found in its target bucket but `is_hottest` is `false`, add frequency tracking and a secondary promotion check before falling through to the in-place `get_from_position` return:

```
// current (v001) non-hottest branch:
} else {
    return Some(core.buckets[target_idx].get_from_position(item_idx));
}

// replacement:
} else {
    // Track access frequency via lfu_counter even under ClassicLRU.
    core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter += 1;
    let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
    if counter >= 2 {
        // Frequency threshold met: promote early without waiting for positional hottest.
        let data = core.buckets[target_idx].remove_at(item_idx);
        promote_to_probing(core, data, insert_pos);
        let item_new_idx = core.buckets[probing_idx]
            .get_position(key)
            .expect("promote_to_probing must leave key in probing");
        return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
    }
    return Some(core.buckets[target_idx].get_from_position(item_idx));
}
```

The threshold of `2` means an item must be accessed at least twice from its target bucket before earning early probing residency. Items that hit the positional `is_hottest` gate on their first target access still take the existing fast path (unchanged). Items below the threshold still call `get_from_position` to perform the ClassicLRU move-to-back. The stash-hit branch and probing-hit branch are untouched.

Keep `InsertPosition::Back` from v001 for all promotion calls.

## Rationale

Under ClassicLRU (v001), `lfu_counter` is never incremented — it stays at zero for every item. The field therefore carries no cost but also no signal. By manually incrementing it on non-hottest target hits, we create a frequency signal at zero structural overhead, then use it to break the positional promotion deadlock for items that are genuinely re-accessed but not yet at the MRU end. The hypothesis is that a working-set workload like workload-a contains items that re-enter target multiple times before reaching the positional hottest slot; early probing placement for those items should reduce their eviction rate and lift hit-rate above v001's 0.6787.
