# H01

Combining the bijective-remix hash from cycle/0005/v002 with the amortized 1-in-8 best-of-2 victim selection from cycle/0004/v002 will improve hit rate over either mechanism applied in isolation.

## Parent

cycle/0005/v002

## Changes

Add a `evict_counter: u32` field to `TinyLfuCache`. Initialise it to `0` in `try_new`. In `put()`, in the full-cache eviction branch, replace the single plain `self.head.expect(...)` victim selection with the following:

```rust
self.evict_counter = self.evict_counter.wrapping_add(1);
let victim_idx = if self.evict_counter & 7 == 0 {
    // Every 8th eviction: pick the lower-frequency of LRU head vs second-oldest.
    let head_idx = self.head.expect("TinyLfuCache: full cache has no victim");
    match self.nodes[head_idx].next {
        None => head_idx,
        Some(second_idx) => {
            let head_freq = self.sketch.estimate(&self.nodes[head_idx].key);
            let second_freq = self.sketch.estimate(&self.nodes[second_idx].key);
            if second_freq < head_freq { second_idx } else { head_idx }
        }
    }
} else {
    // 7 out of 8 evictions: plain LRU-head selection, no extra sketch probes.
    self.head.expect("TinyLfuCache: full cache has no victim")
};
```

Everything that follows (clone victim key, compute `victim_freq`, compute `incoming_freq`, compare `incoming_freq > victim_freq`, swap the node) is identical to the parent. The `seeded_hash`, `remix`, `increment`, and `estimate` functions are left entirely unchanged from cycle/0005/v002.

## Rationale

cycle/0004/v002 demonstrated that 1-in-8 best-of-2 victim selection improves hit rate at latency-neutral cost when built on the single-hash bit-slice base. cycle/0005/v002 independently replaced the second SipHash with a cheaper bijective remix while preserving hit rate and per-op latency. These two mechanisms target independent failure modes — one corrects frequency-blind victim selection, the other reduces serial hash dependency — and have never been combined. The hypothesis is that stacking them on the bijective-remix base yields additive hit-rate benefit without a latency regression, since the amortization rate (1-in-8) is the proven latency-neutral ceiling.
