# H01

Replacing `prot_flags: Vec<bool>` with a packed `Vec<u64>` bitset in the protected-segment implementation will reduce the flag-array heap footprint 8× while preserving the segment-split's hit-rate gain and leaving `Node<u64,u64>` size at 48 bytes.

## Parent

cycle/0008/v002

## Changes

In `TinyLfuCache`, change the field declaration from:

```rust
prot_flags: Vec<bool>,
```

to:

```rust
prot_flags: Vec<u64>,
```

In `try_new`, change the initialiser from:

```rust
prot_flags: vec![false; capacity],
```

to:

```rust
prot_flags: vec![0u64; (capacity + 63) / 64],
```

Replace every read of `self.prot_flags[idx]` (boolean test) with the inline bit-test:

```rust
(self.prot_flags[idx / 64] >> (idx % 64)) & 1 != 0
```

Replace every write of `self.prot_flags[idx] = true` with the bit-set:

```rust
self.prot_flags[idx / 64] |= 1u64 << (idx % 64);
```

Replace every write of `self.prot_flags[idx] = false` (demotion path and victim reuse) with the bit-clear:

```rust
self.prot_flags[idx / 64] &= !(1u64 << (idx % 64));
```

All four extra fields (`prot_head`, `prot_tail`, `prot_count`, `prot_capacity`) and all chain-management methods (`prot_unlink`, `prot_push_back`) remain byte-for-byte identical to `cycle/0008/v002`. The protected-zone ratio stays at `(capacity / 5).max(1)`. The admission gate comparison (`incoming_freq > victim_freq`) is unchanged.

At `capacity = 2048` the `Vec<bool>` occupied 2048 heap bytes; the `Vec<u64>` bitset occupies 32 × 8 = 256 heap bytes. `Node<u64,u64>` is not modified and remains 48 bytes.
