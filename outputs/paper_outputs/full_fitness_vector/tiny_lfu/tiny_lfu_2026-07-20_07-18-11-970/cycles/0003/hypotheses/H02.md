# H02

Replacing four independent `DefaultHasher` invocations per sketch call with a single key hash followed by four bit-slice position derivations will reduce per-op-time by eliminating three redundant hash computations.

## Parent

baseline

## Changes

Remove the `CountMinSketch::position()` helper entirely. Add a private free function (or associated fn) `hash_key`:

```rust
#[inline(always)]
fn hash_key<K: Hash>(key: &K) -> u64 {
    let mut hasher = DefaultHasher::new();
    key.hash(&mut hasher);
    hasher.finish()
}
```

Rewrite `CountMinSketch::increment()` to call `hash_key` once and derive each row position inline:

```rust
fn increment<K: Hash>(&mut self, key: &K) {
    let h = hash_key(key);
    for row in 0..self.depth {
        let pos = ((h >> (row * 16)) as usize) & (self.width - 1);
        let counter = &mut self.counts[row][pos];
        if *counter < MAX_COUNT {
            *counter += 1;
        }
    }
}
```

Rewrite `CountMinSketch::estimate()` the same way:

```rust
fn estimate<K: Hash>(&self, key: &K) -> u32 {
    let h = hash_key(key);
    (0..self.depth)
        .map(|row| {
            let pos = ((h >> (row * 16)) as usize) & (self.width - 1);
            self.counts[row][pos]
        })
        .min()
        .unwrap_or(0)
}
```

All other logic is unchanged: `SKETCH_DEPTH = 4`, `Vec<Vec<u32>>` storage, the saturation guard, the `min()` aggregation. The mask `self.width - 1` is always valid because `width` is guaranteed a power of two by `next_power_of_two()` in `try_new`. The four positions derive from non-overlapping 16-bit windows of the 64-bit SipHash output (offsets 0, 16, 32, 48); at the evaluated sketch width of 4096 (12-bit mask) the bit mixing in DefaultHasher (SipHash-1-3) provides sufficient independence across windows.

## Rationale

The baseline calls `DefaultHasher::new()`, `hasher.write_u64(seed)`, and `key.hash(&mut hasher)` four separate times per `increment()` and four times per `estimate()`. Three of those four invocations hash the same key with a different u64 seed prefix — redundant work. Unlike the cycle/0001/v003 h1→h2 chain (which introduced a serial data dependency on the multiplied-and-incremented hash), bit-slicing a single hash value has no intra-iteration dependency: each row's position is derived by an independent shift+mask on the same source value, which the CPU can compute in parallel.
