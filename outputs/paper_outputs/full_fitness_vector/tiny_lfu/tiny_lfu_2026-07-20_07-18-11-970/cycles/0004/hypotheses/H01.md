# H01

Using two seeded hashes — each sliced into two row positions — instead of one unseed hash sliced into four windows will recover per-row independence and improve hit rate while preserving the per-op-time gain of cycle/0003/v002.

## Parent

cycle/0003/v002

## Changes

In `src/tiny_lfu/mod.rs`, replace the single-hash bit-slice scheme in `CountMinSketch` with a two-phase hashing scheme that uses exactly two seeded hash calls.

**Remove** the `hash_key` free function (or make it private and unused), since the new scheme no longer needs an unseeded hash.

**Add** a private helper (or inline the logic) that computes two seeded 64-bit digests. Each seed should be injected the same way cycle/0003/v003's `position()` did it — by calling `hasher.write_u64(seed)` before `key.hash(&mut hasher)` — so that `DefaultHasher` sees a different initial state for each seed:

```
h0 = seeded_hash(key, seed=0)   // covers rows 0 and 1
h1 = seeded_hash(key, seed=1)   // covers rows 2 and 3
```

**Rewrite `CountMinSketch::increment` and `estimate`** to use these two digests. Derive the four row positions without a generic loop, since the SKETCH_DEPTH=4 constant makes the layout fixed:

- row 0 position: `(h0 as usize) & (self.width - 1)`
- row 1 position: `((h0 >> 16) as usize) & (self.width - 1)`
- row 2 position: `(h1 as usize) & (self.width - 1)`
- row 3 position: `((h1 >> 16) as usize) & (self.width - 1)`

Within each hash the two windows are derived by non-overlapping 16-bit slices of a 64-bit value (same as v002), but the two hashes carry independent seeds so rows 0–1 and rows 2–3 are statistically independent. This recovers the pairwise independence that four separate hashes provided, while still cutting hash invocations from four to two.

Preserve all other logic: the `TinyLfuCache` struct and its `put`/`get` paths, the admission check (`if incoming_freq > victim_freq`), the LRU link operations, and all tests. Only `CountMinSketch::increment` and `CountMinSketch::estimate` (and any helper they call) should change.

## Rationale

v002 eliminated three redundant hash calls by deriving all four row positions from a single 64-bit value, yielding a measurable median-latency win. The cycle-0003 insight observed that the four 16-bit windows of one hash value provide weaker per-row independence than four independently seeded hashes, which showed up as slight tail regressions on write-heavy and collision-sensitive paths. Two seeded hashes is the natural midpoint: it halves the hash work compared to the original baseline while giving rows 0–1 and rows 2–3 genuinely independent seeds, reducing sketch estimation noise without re-introducing the full serial hash overhead.
