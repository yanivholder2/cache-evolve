# H03

Distinguish admission policy between updates to existing cache items (always admit) and insertions of new items (strict gate), reducing churn from low-frequency new entries evicting proven cache residents.

## Changes

In `src/tiny_lfu/mod.rs`, in the `put()` method where the admission check occurs (around line 122 in prior cycles), modify the condition to check whether the incoming key is already in the cache, using asymmetric logic:

```rust
// Old:
if incoming_freq > victim_freq {
    // admit and evict victim
    self.map.remove(&victim_key);
    // ... insert new item
}

// New:
let is_existing = self.map.contains_key(&key);
let admission_ok = if is_existing {
    true  // Always admit updates to existing items
} else {
    incoming_freq > victim_freq + 1  // New items: require stronger frequency advantage
};

if admission_ok {
    // admit and evict victim
    self.map.remove(&victim_key);
    // ... insert new item
}
```

Keep the sketch geometry (depth=3, width=4 from baseline), victim selection strategy (LRU-only, N=1 from baseline), and all other eviction mechanics unchanged. The modification is purely in the admission gate logic, not the selection or placement strategy.

## Rationale

The cross-cycle insights reveal that admission threshold tuning is "brittle and workload-encoded," with all relaxations failing to improve hit-rate. However, the frontier between relaxation and tightening remains under-explored. This hypothesis adopts an asymmetric gate: updates to proven-hot cache items (already present) always succeed, while new items face a stricter barrier (requiring `incoming_freq > victim_freq + 1` instead of `>`). The rationale is that cache residents have demonstrated value through prior accesses, whereas new items are unproven and should not displace them based on marginal frequency advantages. Updates represent the hot path where frequency estimation is most reliable; new inserts are cold-path entries where noise/collisions in estimates pose higher risk. This targets hit-rate by protecting cache continuity while remaining selective about new entries. Orthogonal to N-parameter tuning or sketch geometry: pure admission-policy refinement based on entry type.
