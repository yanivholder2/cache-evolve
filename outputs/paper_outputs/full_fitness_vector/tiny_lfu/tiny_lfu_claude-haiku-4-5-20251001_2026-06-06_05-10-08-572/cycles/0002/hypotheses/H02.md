# H02

Reduce sketch depth to 3 layers to balance per-op latency gains against hit-rate preservation, finding the sweet spot v002 missed.

## Parent

baseline

## Changes

In src/tiny_lfu/mod.rs line 8, change SKETCH_DEPTH from 4 to 3. This reduces the number of
independent hash rows in the count-min sketch from 4 to 3, cutting per-operation hash work by
25% compared to baseline while reducing memory cost slightly.

v002 proved that aggressive depth reduction to 2 backfires—hit-rate fell to 0.7243 despite
latency improvement to 117 ns. v003 showed that per-op latency can be improved orthogonally via
admission policy. This hypothesis tests whether a moderate depth reduction to 3 preserves hit-rate
closer to baseline (0.736) while extracting some latency gains, finding the lower bound on sketch
depth before accuracy degrades. Maintain SKETCH_WIDTH_FACTOR=4 and admission condition (>) to
isolate depth as the only variable.
