# H01

Replacing v002's `u32`-sentinel node link fields with `Option<NonZeroU32>` restores niche-optimization-based pattern matching to recover per-op-time while preserving the 50% reduction in per-node metadata size.

## Parent

cycle/0001/v002

## Changes

v002 shrank `Node<K,V>` from 48 bytes to 24 bytes by replacing `Option<usize>` prev/next with `u32` (plus a `NULL_IDX = u32::MAX` sentinel), but that doubled per-op latency because explicit sentinel comparisons replace the compiler's well-predicted discriminant tests for `Option`.

This hypothesis keeps the 24-byte node by using `Option<NonZeroU32>` instead — the same size as `u32` due to niche optimization, but with idiomatic `Option` pattern matching.

**Concrete changes to `src/tiny_lfu/mod.rs`:**

1. Add `use std::num::NonZeroU32;` at the top.

2. In `Node<K, V>`, change:
   ```
   prev: u32,
   next: u32,
   ```
   to:
   ```
   prev: Option<NonZeroU32>,
   next: Option<NonZeroU32>,
   ```
   `Option<NonZeroU32>` is 4 bytes (same as `u32`) due to niche optimization, so `Node<u64, u64>` stays at 24 bytes.

3. Encode indices as 1-based so that index 0 is representable: when writing a link to arena index `i`, store `NonZeroU32::new((i as u32).wrapping_add(1)).unwrap()`; when reading, decode with `(p.get() - 1) as usize`. `None` (all-zero bits) encodes the nil sentinel — no `NULL_IDX` constant needed.

4. Change `TinyLfuCache.head` and `TinyLfuCache.tail` from `u32` (v002's form) back to `Option<NonZeroU32>` using the same 1-based encoding. This keeps all nil checks as `match` arms rather than `== NULL_IDX` guards.

5. Delete the `NULL_IDX` constant.

6. Rewrite `unlink` using `match` on `Option<NonZeroU32>`:
   - `match self.nodes[idx].prev { None => self.head = next, Some(p) => self.nodes[(p.get()-1) as usize].next = next }`
   - similarly for `next` field and `tail`
   - Set `self.nodes[idx].prev = None; self.nodes[idx].next = None;`

7. Rewrite `push_back` similarly: `self.nodes[idx].prev = self.tail; ...` (already `Option<NonZeroU32>`), `match self.tail { None => self.head = Some(nz_idx), Some(t) => self.nodes[(t.get()-1) as usize].next = Some(nz_idx) }`.

8. Update `try_new` to initialize `head: None, tail: None` (reverting v002's `NULL_IDX` initialization for those fields).

9. Remove the `assert!(capacity < u32::MAX as usize, ...)` guard (v002-only artefact for sentinel safety); the 1-based encoding already limits usable indices to `u32::MAX - 1`.

All other logic — `get`, `put`, admission threshold, sketch, JNI boundary — stays identical to v002.

## Rationale

v002's insight was "the compiler's Option-based codegen outweighs the cache-density benefit of smaller nodes." `Option<NonZeroU32>` achieves both: the same 4-byte field width as v002's `u32` and the same discriminant-test codegen quality as the baseline's `Option<usize>`. If the niche optimization is the deciding factor, this variant should match baseline per-op-time (≈132 ns) while keeping v002's 24-byte node.
