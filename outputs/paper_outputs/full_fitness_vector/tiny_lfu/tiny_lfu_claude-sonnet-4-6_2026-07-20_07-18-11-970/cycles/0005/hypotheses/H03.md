# H03

Pairing cycle/0004/v003's stricter admission gate with cycle/0004/v002's amortised best-of-2 eviction will compound their hit-rate improvements while v002's reduced eviction-firing rate neutralises v003's latency regression.

## Parent

cycle/0004/v002

## Changes

Start from cycle/0004/v002's full implementation (single-hash bit-slice sketch,
amortised best-of-2 victim comparison at 1-in-8, `evict_counter` field). Apply
exactly one additional change: tighten the admission gate in `TinyLfuCache::put`
from strict-greater to greater-by-more-than-one:

```rust
// Current (v002):
if incoming_freq > victim_freq {

// Change to (matching v003's gate):
if incoming_freq > victim_freq.saturating_add(1) {
```

All other code from v002 is preserved verbatim:
- `CountMinSketch` uses the single-hash bit-slice encoding (rows 0–3 all
  derived via `(h >> (row * 16)) & mask` from one `hash_key` call).
- The `evict_counter` wrapping-add and the `& 7 == 0` amortisation mask remain
  unchanged.
- The `evict_counter` field stays on `TinyLfuCache`, keeping the struct size
  at v002's 160 bytes for `TinyLfuCache<u64,u64>`.
- The best-of-2 path (head vs second-oldest, evict lower-frequency candidate)
  is unchanged.

The hypothesis is that v003's latency regression arose because its stricter
gate forced a higher proportion of incoming keys to be rejected, altering the
effective eviction-firing cadence in a way that disrupted memory-access
patterns. v002's 7-in-8 skip already reduces eviction-path overhead; stacking
the stricter gate on top may leave the cadence close enough to v002's baseline
that the latency pressure does not compound, while both hit-rate signals
(better victim selection + stricter admission) accumulate.

Do not change the sketch, node layout, or any test in this file.

## Rationale

v003 was a loser in isolation due to latency disruption (per-op-time doubled),
but its hit-rate signal was the highest of any cycle 0004 variant (0.7374).
v002 demonstrated that reducing eviction overhead is latency-stabilising. The
cross-cycle insight explicitly lists this compound as the third open question
for cycle 0005. This is the lowest-risk path to testing it: the only diff
against v002 is a single comparison operator change in one branch.
