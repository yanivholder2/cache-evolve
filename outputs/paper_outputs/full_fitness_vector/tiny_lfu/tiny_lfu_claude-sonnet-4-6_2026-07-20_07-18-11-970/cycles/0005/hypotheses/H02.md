# H02

Replacing the second seeded SipHash call in cycle/0004/v001's sketch with a cheap multiply-xorshift re-mix of the first hash output will preserve the hit-rate gain while closing the p99 tail latency regression.

## Parent

cycle/0004/v001

## Changes

In the `CountMinSketch::increment` and `CountMinSketch::estimate` methods, the
current code calls `seeded_hash(key, 1)` to produce `h1` independently of
`h0`. Replace that call with a bijective multiply-xorshift transform of `h0`:

```rust
// In increment() and estimate(), after computing h0:
let h0 = seeded_hash(key, 0);
// Replace: let h1 = seeded_hash(key, 1);
// With a cheap bijective re-mix — no extra hash invocation:
let h1 = h0
    .wrapping_mul(0x9e3779b97f4a7c15_u64)
    .rotate_right(32)
    ^ h0;
```

The `seeded_hash` function and its import of `DefaultHasher` remain in the
file for `h0`; `seeded_hash(key, 1)` is removed entirely. All four row
position derivations (`pos0` through `pos3`) and their counter update /
read logic are unchanged — only the source of `h1` changes.

The multiply constant `0x9e3779b97f4a7c15` is the Knuth multiplicative hash
for 64-bit integers (Fibonacci hashing). The `rotate_right(32)` mixes the
high and low 32-bit halves before the XOR, so positions derived from the
upper bits of `h1` (rows 2–3) are not simple affine functions of the upper
bits of `h0` (rows 0–1). The operation is a single multiply + rotate + XOR —
three 64-bit ALU instructions with no data dependency on a second SipHash
computation.

The `seeded_hash` helper can be kept in the file (it is still used for `h0`)
or inlined; either is fine. Do not touch the `eviction`, `admission`, or
`push_back`/`unlink` logic.

## Rationale

v001's two-call seeded hash introduces a serial ILP dependency: the second
`DefaultHasher` must complete before positions for rows 2–3 are known. The
cross-cycle insight flags this as the source of v001's p99 regression. A
bijective re-mix executes in a handful of ALU cycles with no I-cache pressure,
and the independence it introduces — while weaker than two independent SipHash
outputs — may be sufficient given that v001's pair-wise independence (rows 0–1
vs rows 2–3) was already a compromise. If the re-mix preserves hit rate while
flattening p99, the axis is confirmed as latency-bounded, not accuracy-bounded.
