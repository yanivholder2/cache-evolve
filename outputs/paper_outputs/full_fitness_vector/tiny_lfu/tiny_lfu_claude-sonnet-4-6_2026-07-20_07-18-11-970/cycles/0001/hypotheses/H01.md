# H01

Adding periodic counter halving to the frequency sketch will raise hit-rate by preventing stale high-frequency counts from permanently blocking newly-popular keys.

## Parent

baseline

## Changes

Add an `additions: usize` field to `CountMinSketch`. In `increment()`, after updating the four counters, increment `self.additions`; when `self.additions` reaches `self.width / 2`, call a new private method `reset()` and set `self.additions = 0`.

`reset()` iterates over every cell in `self.counts` (all `depth * width` entries) and shifts each value right by 1 (`*c >>= 1`). This halves all counters without clearing them, so relative frequency ordering is preserved while absolute magnitudes decay — the same aging strategy used in Caffeine's W-TinyLFU sketch.

The reset threshold `width / 2` already scales with capacity (width ≈ 4 × capacity), so no new parameter is needed. No changes to `TinyLfuCache`, `put`, `get`, `unlink`, or `push_back`.

## Rationale

workload-a is a LIRS trace with phase-shift behaviour. Without decay, a key that was hot in an early phase accumulates a count that can never be overtaken by a key popular only in a later phase, causing the cache to admit stale residents over genuinely hot newcomers. Periodic halving gives recent accesses a chance to dominate, which should lift hit-rate above the 0.7362 baseline.
