# H03

Computing two independent key hashes once and deriving all four sketch row positions via linear combination will reduce per-op time by eliminating three redundant full hash round-trips per sketch call.

## Parent

baseline

## Changes

Add a private free function to `CountMinSketch`:

```rust
fn double_hash<K: Hash>(key: &K) -> (u64, u64) {
    let mut h1 = DefaultHasher::new();
    key.hash(&mut h1);
    let v1 = h1.finish();

    let mut h2 = DefaultHasher::new();
    v1.hash(&mut h2);
    let v2 = h2.finish();

    (v1, v2)
}
```

Replace `position<K: Hash>(&self, key: &K, seed: u64) -> usize` with:

```rust
fn row_pos(&self, h1: u64, h2: u64, row: usize) -> usize {
    h1.wrapping_add((row as u64).wrapping_mul(h2)) as usize & (self.width - 1)
}
```

Rewrite `increment<K: Hash>`:
```rust
fn increment<K: Hash>(&mut self, key: &K) {
    let (h1, h2) = Self::double_hash(key);
    for row in 0..self.depth {
        let pos = self.row_pos(h1, h2, row);
        let counter = &mut self.counts[row][pos];
        if *counter < MAX_COUNT {
            *counter += 1;
        }
    }
}
```

Rewrite `estimate<K: Hash>` analogously, calling `double_hash` once and using `row_pos` for each row.

Remove the old `position` method. No changes to `TinyLfuCache`, `Node`, or any public API.

## Rationale

The baseline `position()` hashes the key four times per `increment` or `estimate` call (once per row), totalling eight `DefaultHasher` round-trips per `put` and four per `get`. The double-hash scheme hashes the key twice total per sketch call, deriving the remaining positions arithmetically. The linear combination `h1 + i*h2 mod width` gives each row a distinct position with good uniformity when width is a power of two. This eliminates half the hashing work per sketch call, directly targeting the get-p50 summary dimension.
