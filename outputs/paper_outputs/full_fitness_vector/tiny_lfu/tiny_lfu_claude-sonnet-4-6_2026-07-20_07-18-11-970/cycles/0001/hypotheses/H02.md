# H02

Replacing `Option<usize>` prev/next links in `Node` with `u32` sentinel-nil fields will halve the per-node metadata size from 48 B to 24 B.

## Parent

baseline

## Changes

Define a module-level constant `const NULL_IDX: u32 = u32::MAX;` to serve as the nil sentinel.

Change `Node<K, V>`:
```
prev: Option<usize>  →  prev: u32
next: Option<usize>  →  next: u32
```
Initialise both to `NULL_IDX` when a node is pushed.

Change `TinyLfuCache<K, V>`:
```
head: Option<usize>  →  head: u32
tail: Option<usize>  →  tail: u32
```
Initialise both to `NULL_IDX` in `try_new`.

Add `assert!(capacity < u32::MAX as usize, "capacity must fit in u32")` in `try_new` before constructing the cache (capacity=2048 is well within range).

Rewrite `unlink(idx: usize)`:
- Treat `self.nodes[idx].prev == NULL_IDX` as "no predecessor" (update `self.head`).
- Treat `self.nodes[idx].next == NULL_IDX` as "no successor" (update `self.tail`).
- Set both link fields to `NULL_IDX` after unlinking.

Rewrite `push_back(idx: usize)`:
- Set `self.nodes[idx].prev = self.tail`.
- Set `self.nodes[idx].next = NULL_IDX`.
- If `self.tail != NULL_IDX`, set `self.nodes[self.tail as usize].next = idx as u32`; otherwise set `self.head = idx as u32`.
- Set `self.tail = idx as u32`.

All casts between `usize` arena indices and `u32` link fields use `as u32` / `as usize`; no other logic changes. `sketch`, `map`, `get`, `put`, and `sketch_heap_bytes` remain identical.

## Rationale

`Option<usize>` has no niche on 64-bit targets, so each field is 16 bytes (8-byte discriminant + 8-byte payload). Two such fields cost 32 bytes of the 48-byte Node. Replacing them with sentinel-encoded `u32` (4 bytes each) cuts link overhead to 8 bytes, bringing Node<u64,u64> to 24 bytes — a 50 % reduction in the metadata-size fitness dimension.
