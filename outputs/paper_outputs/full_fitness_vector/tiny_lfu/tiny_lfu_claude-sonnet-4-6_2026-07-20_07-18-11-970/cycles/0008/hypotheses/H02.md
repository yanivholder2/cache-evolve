# H02

Introducing a protected LRU segment that shields frequently-hit items from the eviction victim pool raises hit-rate on a stable Zipfian trace by preventing hot resident items from being displaced when the cold end of the LRU is exhausted.

baseline

## Changes

In `src/tiny_lfu/mod.rs` (starting from the baseline), modify `TinyLfuCache` to maintain two separate doubly-linked chains within the shared `nodes` arena — a probationary chain (the existing `head`/`tail` pair) and a protected chain — using the existing `prev`/`next` pointers in `Node` (a node belongs to exactly one chain at a time).

**Struct changes (`TinyLfuCache`):** Add four fields:
```rust
prot_head: Option<usize>,
prot_tail: Option<usize>,
prot_count: usize,
prot_capacity: usize,
```
Initialise all to `None`/`0` in `try_new()`. Set `prot_capacity = (capacity / 5).max(1)` to reserve up to 20 % of capacity for protected items.

**`get()` — promote on hit:** After the `self.map.get(key)?` succeeds and yields `idx`, call `self.unlink(idx)` (same as now), then call a new `prot_push_back(idx)` instead of `push_back(idx)`. Increment `self.prot_count`. If `prot_count > prot_capacity`, demote the protected head: call `self.prot_unlink(prot_head_idx)`, decrement `prot_count`, then call `self.push_back(prot_head_idx)` to move the demoted node to the probationary tail.

**`put()` for an existing key:** Same promotion logic as `get()` — unlink, `prot_push_back`, manage overflow.

**`put()` for a new key (eviction path):** The victim is always the probationary head (`self.head`). If `self.head` is `None` (probationary chain empty, all nodes in protected), first demote the protected head to probationary (`prot_unlink(prot_head_idx)`, `push_back(prot_head_idx)`, decrement `prot_count`), then evict the new probationary head via the existing admission-gate logic. New items are inserted into the probationary chain via the existing `push_back`.

**New helpers:** Add `prot_unlink(idx)` (mirrors `unlink` but updates `prot_head`/`prot_tail`) and `prot_push_back(idx)` (mirrors `push_back` but updates `prot_head`/`prot_tail` and `prot_count` externally).

Do not change `Node`, the `CountMinSketch`, the hash computation, the admission-gate comparison, or the `evict_counter` logic. Preserve all existing unit tests unchanged.

## Rationale

Every prior cycle has treated the LRU as a single flat chain. The protected/probationary split is the core structural improvement in W-TinyLFU (Ben Manes 2015) but has never been attempted in this run. On a stable Zipfian trace the working set is small and tightly accessed; a protected segment ensures that items which have proven their hotness (at least one `get` hit) cannot be displaced by the eviction gate until the protected zone overflows. The baseline admission gate already provides frequency-based filtering — the protected segment adds recency-based shielding as an orthogonal second axis, with no impact on sketch heap or node metadata size.
