# H03

Double-incrementing the frequency sketch on confirmed cache hits steepens the frequency gradient between resident hot keys and cold incomers, improving hit-rate on a stable Zipfian trace by making the admission gate more conservative against displacing frequently-read items.

## Parent

cycle/0007/v003

## Changes

In `src/tiny_lfu/mod.rs` (starting from cycle/0007/v003's overlay), modify `get()` to add a second sketch increment for confirmed hits only:

```rust
pub fn get(&mut self, key: &K) -> Option<&V> {
    self.sketch.increment(key);       // existing increment (hit or miss)
    let &idx = self.map.get(key)?;
    self.sketch.increment(key);       // ← ADD: second increment on confirmed hit only
    self.unlink(idx);
    self.push_back(idx);
    Some(&self.nodes[idx].value)
}
```

The second `self.sketch.increment(key)` is inserted after the `map.get(key)?` guard, so it executes only when the key is present in cache (a hit). Cache misses continue to accumulate exactly one increment per `get` call (from the existing first line). `put()` is unchanged — new keys and updates each accumulate one increment from the `put` path.

Do not change `SKETCH_WIDTH_FACTOR`, `SKETCH_DEPTH`, counter types, the admission gate logic, `evict_counter`, or any other path. The sketch heap and node sizes are unchanged.

## Rationale

Currently `get()` and `put()` each contribute one increment regardless of whether the key is in cache. This means a resident key that is accessed K times accumulates exactly K increments from gets — the same rate as a cold key that is requested K times but always misses. On a stable Zipfian trace the resident hot set receives far more hits than the cold population receives misses, so doubling the per-hit signal widens the frequency gap between "hot and in cache" and "cold but occasionally requested." The admission gate (`incoming_freq > victim_freq`) then becomes structurally harder to satisfy for cold incomers trying to displace frequently-read residents, which should reduce harmful eviction of the hot set without requiring any extra sketch probes on the eviction path. This axis has not been explored in any prior cycle.
