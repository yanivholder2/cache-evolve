# H01

Flatten the count-min sketch from `Vec<Vec<u8>>` to one contiguous `Vec<u8>` to recover the wide-sketch per-op-time tax without touching hit-rate.

## Parent

cycle/0005/v001

## Changes

v001 holds the best hit-rate (0.7425) but the worst per-op-time among the
cycle-5 winners (get p50 44ns), because its wide (factor-16) sketch spills
cache lines and every op chases `depth` separate heap allocations through the
outer `Vec<Vec<u8>>`. Replace that nested structure with a single flat
backing buffer:

- In `CountMinSketch`, change `counts: Vec<Vec<u8>>` to `counts: Vec<u8>` of
  length `depth * width`. In `new`, allocate `vec![0u8; depth * width]`.
- In `increment` and `estimate`, index the flat buffer as
  `counts[row * self.width + pos]` instead of `counts[row][pos]`.
- Keep `heap_bytes` returning `depth * width * size_of::<u8>()` (the value is
  unchanged; only the allocation shape changes).

Preserve everything else exactly: `SKETCH_DEPTH = 4`, `SKETCH_WIDTH_FACTOR = 16`,
the double-hashing `position_for` formula, the `MAX_COUNT` saturation cap, and
the sampled-victim eviction loop. Because the indexed values are byte-for-byte
identical to v001, hit-rate must stay at 0.7425; the only expected movement is a
lower get/put per-op-time from contiguous, prefetch-friendly memory and the
removal of per-row pointer indirection.

## Rationale (optional)

Directly tests the standing cross-cycle question: "is the sketch's per-op tax
recoverable via layout/locality work, or is it the new floor price of sharper
admission?" This isolates layout from semantics — a clean answer either way.
