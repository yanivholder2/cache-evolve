# H01

Cutting the wide sketch's row count from 4 to 3 lowers per-op-time by reducing per-access counter touches while the already-large width holds hit-rate.

## Parent

cycle/0005/v001

## Changes

In `src/tiny_lfu/mod.rs`, change the constant `SKETCH_DEPTH` from `4` to
`3`. This is the only edit. `CountMinSketch::new` allocates
`depth * width` counters from `SKETCH_DEPTH`, and both
`CountMinSketch::increment` and `CountMinSketch::estimate` iterate
`0..self.depth`, so dropping one row removes one counter read+write per
`increment` (called on every get and put) and one counter read per
`estimate` (called once per incoming key plus once per sampled victim in
the eviction walk). Keep `SKETCH_WIDTH_FACTOR` at 16, `position_for`'s
double-hashing column derivation, the `MAX_COUNT` saturation guard, and
the sampled-coldest eviction logic byte-for-byte unchanged. The premise
(from the cross-cycle "width/depth sweet spot" open question): on the
factor-16 sketch, collision over-count is already low, so the 4th min-row
contributes little additional accuracy — removing it should trade
essentially-flat hit-rate for cheaper hot-path and eviction-path work.
Preserve the invariant that `estimate` returns the minimum across all
remaining rows.
