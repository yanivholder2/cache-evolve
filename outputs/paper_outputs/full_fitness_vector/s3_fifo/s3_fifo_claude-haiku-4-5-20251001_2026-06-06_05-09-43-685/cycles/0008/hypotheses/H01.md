# H01

Add selective ghost-queue frequency tracking to cycle/0005/v002 to admit only high-frequency items, concentrating re-admission opportunities on genuinely warm candidates.

## Parent

cycle/0005/v002

## Changes

In `src/s3_fifo/mod.rs`, enhance the ghost queue with frequency tracking while preserving v005/v002's lean threshold-based architecture and overhead-free latency profile:

1. Change the `ghost` field type from `VecDeque<K>` to `VecDeque<(K, i8)>` to track frequency decay states.

2. In `evict_main()`, when an entry reaches freq=0 and is selected for eviction:
   - Only add to ghost if `tail.freq > 0` (discard freq=0 items—they were never accessed in main)
   - Compute `ghost_freq = tail.freq - 1` (preserve frequency with one level of decay)
   - Push to ghost if `ghost_freq >= -2`: `self.ghost.push_front((tail.key, ghost_freq))`

3. In `evict_small()`, when the promotion decision fails:
   - Only add to ghost if `tail.freq > 0` (discard freq=0 items—never had re-access chance)
   - Compute `ghost_freq = tail.freq - 1`
   - Push to ghost if `ghost_freq >= -2`: `self.ghost.push_front((tail.key, ghost_freq))`
   - Keep the same promotion threshold logic as v005/v002 (fixed freq > 2, no occupancy-responsive variation)

4. In `put()`, when a ghost hit occurs:
   - Extract both key and preserved frequency from the ghost entry
   - Compute re-admission frequency: `boost_freq = (ghost_freq + 2).max(1) as u8`
   - Clamp to MAX_FREQ: `freq = boost_freq.min(MAX_FREQ)`
   - Create entry with computed frequency and push to main (same flow as v005/v002)

5. Keep v005/v002's threshold logic, queue sizing, and all other mechanisms intact. No occupancy-responsive thresholds, no dynamic sizing, just the filtered ghost admission.

This targets the hypothesis that ghost-queue noise from freq=0 items (which never accumulated meaningful access patterns) corrupts re-admission signals. By admitting only items that proved at least one access (freq >= 1), we create a purer "warm candidates" queue, improving hit-rate precision without any per-operation overhead beyond the zero-cost eviction-time filtering. Expected outcome: recover hit-rate toward 0.725+ while maintaining v005/v002's industry-leading latency profile of 131 ns.

## Rationale

Cycle 0005/v002 achieved the best latency (131 ns) and strong hit-rate (0.7222) through a lean overhead-free design. Ghost-queue variants (v006, v007) introduced state tracking and complex re-admission logic, but the key issue is signal fidelity—current ghost implementations include freq=0 items that clutter the candidate pool and mislead re-admission decisions. By filtering ghost to freq > 0 items only, we reduce noise, concentrate capacity on genuinely warm items, and use a simpler re-admission boost formula (ghost_freq + 2 instead of +3). This filtering happens at eviction time (infrequent) and requires zero additional logic on the hot path, preserving the latency foundation v005/v002 established. The hypothesis directly tests the open question: can ghost-queue signal fidelity be improved through selective input filtering rather than complex re-admission logic?
