# H03

Implement adaptive promotion threshold that scales with main-queue occupancy to balance hit-rate and latency across workload phases.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, modify `evict_small()` to use occupancy-aware promotion thresholds:

1. In `evict_small()`, before the promotion decision, compute the main queue's occupancy ratio: `occupancy_ratio = self.main.len() as f64 / self.main_size as f64`.

2. Determine the promotion threshold dynamically:
   - If `occupancy_ratio < 0.5`: use `threshold = 1` (loose: freq > 1 promotes)
   - If `occupancy_ratio >= 0.5 && occupancy_ratio < 0.8`: use `threshold = 2` (medium: freq > 2 promotes)
   - If `occupancy_ratio >= 0.8`: use `threshold = 3` (strict: freq > 3 promotes)

3. Replace the fixed `if tail.freq > 2` check with `if tail.freq > threshold`.

## Rationale

Cross-cycle analysis shows tight thresholds maximize latency but cost hit-rate uniformly. The bimodal-threshold recommendation suggests varying strictness based on queue state. This adaptive approach allows loose filtering (freq > 1) when main queue has spare capacity, giving more items a chance to graduate and improving hit-rate during low-contention phases. Under high occupancy (>80%), threshold tightens to freq > 3 to protect latency when contention peaks. Expected outcome: higher hit-rate during normal operation (low occupancy) while preserving latency gains during load spikes (high occupancy), achieving better balanced multi-metric performance than fixed-threshold variants.
