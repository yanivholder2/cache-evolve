# H03

Increase small queue capacity to provide longer validation window for admission filtering and improve hit rate.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, modify the `try_new()` function to expand the small queue's proportion of total capacity. Change the small queue sizing calculation from:
```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 4).max(1).min(capacity - 1)
};
```
to:
```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 3).max(1).min(capacity - 1)
};
```
This increases the small queue from approximately 25% to 33% of total capacity, giving more items a longer opportunity to demonstrate hotness before main queue admission.

## Rationale

The current small queue (capacity / 4) evicts items quickly, forcing promotion/eviction decisions with limited history. By increasing to capacity / 3, items have more chances to accumulate frequency signals before eviction. This reduces premature evictions of items with irregular access patterns (like reuse with gaps) that would be classified as cold in a smaller queue. The tradeoff reduces main queue size, but the improved filtering should more than compensate by reducing main eviction pressure and improving overall hit rate on temporal skew.
