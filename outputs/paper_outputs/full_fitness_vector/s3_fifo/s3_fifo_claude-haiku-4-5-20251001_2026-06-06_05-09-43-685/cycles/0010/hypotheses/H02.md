# H02

Combine occupancy-responsive re-admission formula with batch-amortized frequency decay to unlock dual-metric improvements on hit-rate and latency.

## Parent

cycle/0009/v003

## Changes

Modify v003's ghost-hit re-admission logic to use occupancy-responsive boost scaling instead of the fixed +2 boost:

In the ghost-hit re-admission path (around line 98 of `src/s3_fifo/mod.rs`), replace:
```rust
let boosted_freq = ((ghost_freq as i32 + 2).max(0)) as u8;
```

With:
```rust
let occupancy_ratio = self.main.len() as f64 / self.main_size as f64;
let boost = (2.0 + occupancy_ratio * occupancy_ratio).min(MAX_FREQ as f64 - ghost_freq as f64) as u8;
let boosted_freq = ((ghost_freq as i32 + boost as i32).max(0)) as u8;
```

This integrates v002's occupancy-responsive adaptation strategy with v003's batch-amortized decay infrastructure. The combination preserves v003's dramatic latency wins (44% faster gets, 37% faster puts) from amortized decay while adding v002's adaptive re-admission signal that responds to queue load. The cold-path occupancy computation is zero-cost when placed at ghost-hit re-admission time, as validated by v002's latency measurements.

## Rationale (optional)

Cycle 0009 identified two orthogonal successful mechanisms: v002's occupancy-responsive cold-path computation (19% get latency improvement) and v003's batch-amortized decay (44% get latency improvement, hit-rate maintenance). Cycle 0009's open question explicitly asks whether combining these "unlock dual-metric gains." v003 preserves rich frequency depth through batch decay; v002's occupancy-responsive boost can exploit that depth adaptively. v003's fixed +2 boost is the limiting factor preventing full utilization of preserved frequency; occupancy scaling addresses this without adding overhead.
