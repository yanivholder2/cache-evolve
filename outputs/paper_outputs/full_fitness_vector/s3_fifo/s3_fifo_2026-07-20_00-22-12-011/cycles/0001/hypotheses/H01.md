# H01

Shrinking the small-queue fraction from 1/4 to 1/10 of capacity gives the main queue more resident headroom for hot entries, improving hit rate on skewed access workloads.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, inside `try_new()`, change the small-queue size formula from

```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 4).max(1).min(capacity - 1)
};
```

to

```rust
let small_size = if capacity == 1 {
    1
} else {
    (capacity / 10).max(1).min(capacity - 1)
};
```

No other code changes are required. The `main_size` derivation (`capacity - small_size`) and ghost capacity (initialised as `main_size`) update automatically. The invariant `small_size >= 1` and `main_size >= 1` is preserved by the existing `.max(1).min(capacity - 1)` clamps.

For the evaluation capacity of 2048, this changes `small_size` from 512 to 204 and `main_size` from 1536 to 1844 — giving the main queue 20% more slots to retain recently-promoted and ghost-reinstated entries.
