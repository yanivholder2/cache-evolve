# H02

Adding a `resident_set: HashSet<K>` membership guard to `cycle/0004/v002` short-circuits the double `position()` scan on cache misses in both `get()` and `put()`, reducing per-op-time for the miss path without restructuring the hit-path data layout.

## Parent

cycle/0004/v002

## Changes

Starting from the `cycle/0004/v002` overlay (`src/s3_fifo/mod.rs`), apply the following targeted changes. The `Entry<K,V>` struct, parallel `small_freq`/`main_freq` deques, `position()`-based hit path, and all eviction logic remain untouched. This hypothesis tests whether miss-path scanning (not hit-path scanning) is a material fraction of total per-op cost.

### 1. Add `resident_set: HashSet<K>` field

In `S3Fifo<K,V>`, add:

```rust
/// Set of all keys currently resident in `small` or `main`. Maintained in
/// lock-step with admissions and evictions to enable O(1) membership checks.
resident_set: HashSet<K>,
```

`HashSet` is already imported via `use std::collections::HashSet;`. In `try_new()`, add:

```rust
resident_set: HashSet::with_capacity(capacity),
```

### 2. Maintain `resident_set` in `put()` on new admission

In `put()`, in the normal-admission branch (after the ghost-hit and update checks), insert the key before pushing to small:

```rust
self.resident_set.insert(key.clone());
self.small.push_front(Entry::new(key, value));
self.small_freq.push_front(0);
```

In the ghost-hit branch, insert the key before pushing to main:

```rust
self.resident_set.insert(key.clone());
self.main.push_front(Entry::new(key, value));
self.main_freq.push_front(0);
```

### 3. Remove key from `resident_set` on eviction

In `evict_main()`, in the `freq == 0` (eviction) branch, before `break`:

```rust
self.resident_set.remove(&tail.key);
```

In `evict_small()`, in the cold (ghost) branch, remove before pushing to ghost:

```rust
self.resident_set.remove(&tail.key);
```

Do NOT remove in the hot (promote) branch — the key moves from small to main and remains resident.

### 4. Guard `get()` with an O(1) miss check

Insert an early-return at the very top of `get()`, before the two `position()` calls:

```rust
pub fn get(&mut self, key: &K) -> Option<&V> {
    if !self.resident_set.contains(key) {
        return None;  // O(1) miss: skip both position() scans
    }
    // Hot path: key is resident — use existing position()-based lookup.
    if let Some(pos) = self.small.iter().position(|e| &e.key == key) {
        let f = &mut self.small_freq[pos];
        *f = f.saturating_add(1).min(MAX_FREQ);
        return Some(&self.small[pos].value);
    }
    if let Some(pos) = self.main.iter().position(|e| &e.key == key) {
        let f = &mut self.main_freq[pos];
        *f = f.saturating_add(1).min(MAX_FREQ);
        return Some(&self.main[pos].value);
    }
    None
}
```

The `resident_set.contains` is O(1); on a miss (~27% of accesses on this Zipfian workload) both `position()` scans are skipped entirely.

### 5. Guard `put()` update path with an O(1) resident check

Replace the two `position()` update checks at the top of `put()` with a guarded block:

```rust
pub fn put(&mut self, key: K, value: V) {
    // O(1) guard: only scan for the entry when key is known to be resident.
    if self.resident_set.contains(&key) {
        if let Some(pos) = self.small.iter().position(|e| e.key == key) {
            self.small[pos].value = value;
            return;
        }
        if let Some(pos) = self.main.iter().position(|e| e.key == key) {
            self.main[pos].value = value;
            return;
        }
    }
    // ... ghost check and admission continue unchanged ...
}
```

For new keys (`resident_set.contains` = false), both `position()` scans are skipped and the code falls through directly to the ghost-check and admission path, eliminating O(n) work on every non-update `put()`.

### 6. No changes to unit tests required

All existing tests exercise only the public API (`put`/`get`) and white-box fields that are unchanged (`small`, `main`, `ghost`, `ghost_set`, `small_freq`, `main_freq`). The `resident_set` field is internal bookkeeping and no test directly inspects it. Add the `resident_set` field access to `S3Fifo` without the `pub` modifier so it remains crate-private.
