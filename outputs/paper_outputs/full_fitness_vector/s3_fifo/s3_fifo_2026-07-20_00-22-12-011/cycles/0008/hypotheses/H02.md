# H02

Lowering the small-to-main promotion threshold from `freq > 1` to `freq >= 1` in cycle/0005/v001 will capture marginally-warm entries in main before they are ghosted, improving hit-rate by giving single-re-accessed keys second-chance protection in the main queue instead of deferring their fate through the ghost path.

## Parent

cycle/0005/v001

## Changes

In `src/s3_fifo/mod.rs`, inside `evict_small()`, change the promotion guard from:

```rust
if freq > 1 {
    // Hot entry: promote to main; entry stays in data and freq_map.
    if self.main.len() >= self.main_size {
        self.evict_main();
    }
    self.main.push_front(tail);
} else {
    // Cold entry: move key to ghost ...
}
```

to:

```rust
if freq >= 1 {
    // entry with any re-access while in small: promote to main.
    if self.main.len() >= self.main_size {
        self.evict_main();
    }
    self.main.push_front(tail);
} else {
    // freq == 0: no re-access, move key to ghost ...
}
```

The only change is `freq > 1` → `freq >= 1`. Everything else (ghost logic, evict_main() call, data/freq_map handling) is unchanged.

**Semantics shift**: entries with exactly `freq = 1` (accessed once while in small) now promote directly to main instead of going to ghost. Entries with `freq = 0` still go to ghost. The ghost queue becomes exclusively occupied by entries that showed zero demand while in small. This makes ghost a filter for true one-timers: a ghost hit for a freq=0 entry indicates the key made a round-trip (evicted cold, now re-requested) and still deserves main promotion via the existing ghost-hit path.

**Test adjustments**: The existing unit test `small_eviction_promotes_to_main_after_multiple_hits` uses `get(&1)` twice (freq=2) before triggering eviction — it still passes unchanged. The test `ghost_hit_promotes_back_to_main` evicts key 1 with freq=0 (no gets before eviction), so key 1 still goes to ghost and still promotes on re-request — that test also passes unchanged. Update the inline doc comment on the promotion branch to reflect `freq >= 1`.

## Rationale

Currently, an entry that gets exactly one re-access while in small exits to ghost (freq=1 is not > 1). On Zipfian, these entries represent moderately-warm keys: popular enough to be re-requested during their small-queue residency, but not popular enough for the `freq > 1` gate. Routing them through ghost introduces a round-trip: evict → ghost → wait for re-request → main. With this change they reach main immediately, getting second-chance protection from evict_main(). Ghost now acts solely as a recency oracle for completely-cold small entries, which is a cleaner role separation. The expected tradeoff is slightly more main churn (more entries enter main) offset by better hit-rate on the freq=1 segment of the Zipfian hot set.
