# H01

Merging `data` and `freq_map` into a single `resident_map<K,(V,u8)>` reduces the `get()` hot path from two sequential hash probes to one, targeting get p50 latency.

## Parent

cycle/0007/v003

## Changes

Replace the two separate fields `data: HashMap<K, V>` and `freq_map: HashMap<K, u8>` with a
single field `resident_map: HashMap<K, (V, u8)>` throughout `src/s3_fifo/mod.rs`.

**Struct definition**: Remove `data` and `freq_map`; add `resident_map: HashMap<K, (V, u8)>`.

**`try_new()`**: Replace two `HashMap::with_capacity()` calls with one:
```rust
resident_map: HashMap::with_capacity(capacity),
```

**`get()`**: Replace the two-probe sequence with a single mutable lookup that both reads
and updates frequency in one operation:
```rust
pub fn get(&mut self, key: &K) -> Option<&V> {
    if let Some(entry) = self.resident_map.get_mut(key) {
        entry.1 = entry.1.saturating_add(1).min(MAX_FREQ);
        Some(&entry.0)
    } else {
        None
    }
}
```

**`put()` — update path**: Replace `self.data.contains_key(&key)` + `self.data.insert(key, value)` with:
```rust
if let Some(entry) = self.resident_map.get_mut(&key) {
    entry.0 = value;
    return;
}
```

**`put()` — ghost-hit path**: Replace `self.data.insert(key.clone(), value); self.freq_map.insert(key.clone(), 0);` with `self.resident_map.insert(key.clone(), (value, 0));`.

**`put()` — normal admission path**: Same replacement: `self.resident_map.insert(key.clone(), (value, 0));`.

**`evict_main()`**: Replace the two-map reads with a single probe:
```rust
let freq = self.resident_map.get(&tail.key).map_or(0, |e| e.1);
if freq > 0 {
    if let Some(e) = self.resident_map.get_mut(&tail.key) { e.1 -= 1; }
    self.main.push_front(tail);
} else {
    self.resident_map.remove(&tail.key);
    break;
}
```

**`evict_small()`**: Replace `self.freq_map.get(&tail.key).copied().unwrap_or(0)` with
`self.resident_map.get(&tail.key).map_or(0, |e| e.1)`. Replace removal calls
`self.data.remove(&tail.key); self.freq_map.remove(&tail.key);` with
`self.resident_map.remove(&tail.key);`.

**White-box tests**: Update `main_eviction_uses_frequency_second_chance` and
`ghost_set_len_bounded_after_ghost_hit` to use `resident_map.insert(key, (value, freq))` when
seeding entries directly into the struct, replacing the paired `data.insert` + `freq_map.insert` calls.

Preserve all other invariants from cycle/0007/v003: `MAX_FREQ = 5`, `small_size = capacity / 40`,
`freq > 1` promotion gate in `evict_small()`, `freq = 0` on ghost-hit admission, lazy ghost
tombstoning, and the key-only `Entry<K, V>` struct.

## Rationale

The current `get()` path makes two hash probes: first into `freq_map` (to update frequency), then
into `data` (to return the value). On the Zipfian hot set — which accounts for the majority of
hits — these probes land in two different memory regions, touching two distinct cache-line pools.
Merging into a single `resident_map<K,(V,u8)>` halves the probe count on every hit, consolidates
the hot data onto fewer cache lines, and eliminates the latency of the second lookup. This
directly targets the get p50 dimension, which is the primary fitness signal and has not moved
in multiple cycles despite eviction-path optimisations.
