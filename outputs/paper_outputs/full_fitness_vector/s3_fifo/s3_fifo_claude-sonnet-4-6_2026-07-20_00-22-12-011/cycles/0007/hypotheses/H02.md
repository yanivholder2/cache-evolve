# H02

Initialising ghost-promoted keys at `freq=1` instead of `freq=0` when they re-enter the main queue gives demand-confirmed entries an immediate second-chance buffer in `evict_main()`, extending their main-queue residency and raising hit-rate without changing any queue sizing.

## Parent

cycle/0005/v001

## Changes

In the `put()` method, locate the ghost-hit branch (guarded by `if self.ghost_set.contains(&key)`). Within that branch, change the frequency initialisation line from:

```rust
self.freq_map.insert(key.clone(), 0);
```

to:

```rust
self.freq_map.insert(key.clone(), 1);
```

This is the only change. The rest of the ghost-hit branch — removing the key from `ghost_set`, conditionally calling `evict_main()`, inserting into `data`, and pushing a key-only `Entry` to the front of `main` — remains identical to cycle/0005/v001.

All other logic is preserved: the 1/40 small-queue fraction (`capacity / 40`), the `freq > 1` small-queue promotion threshold in `evict_small()`, the split `data`+`freq_map` layout, `MAX_FREQ = 3`, and the ghost lazy-deletion pattern (tombstone-on-hit, capacity-guard drain loop in `evict_small()`).

## Rationale

A ghost hit means the key was evicted from the main queue at some point and then re-requested — it carries a recency signal that distinguishes it from a cold first-time miss. In the current implementation, such a key enters main with `freq=0`, so the very next `evict_main()` pass will evict it immediately unless a `get()` intervenes and increments its frequency first. Starting at `freq=1` grants one free pass through the second-chance loop, giving the re-promoted entry time to accumulate further accesses before it risks eviction. On Zipfian workloads the hot set is small and re-requests are clustered, so ghost-hit keys are likely to be accessed again soon after promotion; the single extra second-chance credit should translate into a measurable hit-rate improvement without meaningfully increasing eviction scan depth.

The `freq > 1` small-queue threshold is unaffected — it governs which small-queue entries qualify for promotion to main, which is a different code path from the ghost-hit initialisation changed here.
