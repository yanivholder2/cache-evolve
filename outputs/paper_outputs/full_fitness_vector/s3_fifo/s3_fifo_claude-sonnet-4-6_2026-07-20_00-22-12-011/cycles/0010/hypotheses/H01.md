# H01

Encoding ghost membership as a `None` sentinel in a single `state_map: HashMap<K, Option<(V, u8)>>` eliminates the `ghost_set: HashSet<K>` entirely and collapses the two-probe resident/ghost check in `put()` to a single map lookup, reducing put p50 on cold-key traffic.

## Parent

cycle/0007/v003

## Changes

Starting from cycle/0007/v003, which has `data: HashMap<K, V>`, `freq_map: HashMap<K, u8>`, `ghost: VecDeque<K>`, and `ghost_set: HashSet<K>`:

1. **Remove** `data`, `freq_map`, and `ghost_set` from the struct. Replace them with a single field:
   ```rust
   state_map: HashMap<K, Option<(V, u8)>>,
   ```
   Semantics: `Some((v, f))` = resident (has value + freq), `None` = ghost (evicted, no value stored), absent = cold (never seen or fully expired).

2. **`get()`**: Look up `state_map.get_mut(key)`. If `Some(Some((v, f)))`, increment `f` (saturating, capped at MAX_FREQ) and return `Some(v)`. Otherwise return `None`. One probe total.

3. **`put()`**: Use the entry API for a single probe:
   - `Occupied(Some((ref mut v, _)))` → resident update, `*v = value`, return.
   - `Occupied(None)` → ghost hit: set slot to `Some((value, 0))`, call `evict_main()` if `main.len() >= main_size`, push key onto `main`, return. No `ghost_set.remove()` needed — the slot is overwritten in place.
   - `Vacant` → cold admission: call `evict_small()` if `small.len() >= small_size`, insert `state_map[key] = Some((value, 0))`, push key onto `small`.

4. **`evict_small()` cold path**: After popping `tail` from `small`, the entry is already `Some((v,f))` in `state_map`. To ghost it: overwrite `state_map[tail.key] = None` (converts resident to ghost in place, no remove + reinsert needed). Then run the capacity guard:
   ```rust
   while ghost.len() >= main_size {
       if let Some(old_key) = ghost.pop_back() {
           // Still a ghost if the slot is Some(None); re-admitted if Some(Some(...)).
           if matches!(state_map.get(&old_key), Some(None)) {
               state_map.remove(&old_key);
               break; // evicted one live ghost
           }
           // Stale (re-admitted lazily): loop again.
       }
   }
   ghost.push_front(tail.key);
   ```

5. **`evict_main()`**: Each iteration, read `state_map.get_mut(&tail.key)` → `Some(Some((_, f)))`, decrement freq by 1 or evict (remove from `state_map`) when freq = 0.

6. **`try_new()`**: Allocate `state_map: HashMap::with_capacity(capacity)`. Remove `ghost_set` and the old `data`/`freq_map` allocations.

7. **`Entry<K,V>`**: Keep the key-only struct with PhantomData (unchanged from v003).

8. **Tests**: Update white-box tests to drive `state_map` directly instead of `data`/`freq_map`/`ghost_set`. The `ghost_set_len_bounded_after_ghost_hit` test should become a check that `state_map` values of `None` do not exceed `ghost.len()`.

**Invariants to preserve**: `ghost.len()` may exceed the number of live ghosts (lazy deletion), but `ghost_set` is now gone; the number of `None` values in `state_map` is the true live ghost count and must not exceed `main_size`. The `ghost` deque is still used for age-ordered eviction of old ghost slots. MAX_FREQ remains 5 (unchanged from v003).

## Rationale

The cross-cycle open question explicitly asks whether the `ghost_set` HashSet probe on every `put()` is measurable. Cycles 1–9 have never directly targeted it. Currently every cold `put()` pays two independent map probes: `data.contains_key` (resident check) then `ghost_set.contains` (ghost check). The sentinel approach folds both checks into one `state_map.entry()` call, removing one probe from the hot put path. Ghost hits additionally save a `ghost_set.remove()` call. The struct also sheds two entire HashMap/HashSet headers (~96 bytes), improving metadata-size.
