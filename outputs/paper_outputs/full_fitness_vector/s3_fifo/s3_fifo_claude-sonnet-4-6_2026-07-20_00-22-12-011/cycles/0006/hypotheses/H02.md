# H02

Expanding the ghost queue capacity from main_size to twice main_size in cycle/0005/v003's resident_map design will improve hit-rate by widening the temporal window in which evicted keys can be ghost-promoted back into the main queue.

## Parent

cycle/0005/v003

## Changes

Add a `ghost_capacity: usize` field to `S3Fifo` and initialize it to `2 * main_size` in `try_new()`. Update every place that references the ghost bound:

1. **Struct definition** — add `ghost_capacity: usize` alongside `small_size` and `main_size`.

2. **`try_new()`** — compute `ghost_capacity = 2 * main_size` (after `main_size` is derived), initialize `ghost: VecDeque::with_capacity(ghost_capacity)`, and store `ghost_capacity` in the struct. `ghost_set` should also be initialized with `HashSet::with_capacity(ghost_capacity)`.

3. **`evict_small()`** — in the ghost capacity guard loop, replace the guard condition
   ```rust
   while self.ghost.len() >= self.main_size {
   ```
   with
   ```rust
   while self.ghost.len() >= self.ghost_capacity {
   ```
   The body of the loop (lazy tombstone drain: pop until a live ghost_set entry is found, then remove from ghost_set and break) is unchanged.

All other code — resident_map layout, get()/put() logic, evict_main() second-chance loop, evict_small() `freq > 1` promotion threshold, 1/20 small-queue fraction — must be preserved exactly as in the parent. Only the ghost queue bound changes.

## Rationale

The ghost queue is currently bounded at `main_size` ≈ 95% of capacity (with 1/20 small queue). On Zipfian workloads, evicted entries concentrate in the long tail of the frequency distribution: they leave main after their second-chance frequency drains to zero, but some may be re-requested within a window longer than `main_size` accesses. Doubling the ghost window to `2 * main_size` costs only 8 bytes per key-slot (ghost stores keys only, no values), adding roughly `main_size * 8` bytes of deque memory. The claim is falsified if hit-rate does not improve beyond 0.7292 or if the additional memory pressure causes latency regression.
