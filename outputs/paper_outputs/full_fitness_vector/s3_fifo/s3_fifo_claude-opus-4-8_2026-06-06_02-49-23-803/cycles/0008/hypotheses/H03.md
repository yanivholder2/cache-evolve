# H03

Fold ghost membership into the existing `entries` map as value-less tombstone entries, giving O(1) put membership with no separate ghost hash structure (per-op-time + container memory).

## Parent

cycle/0007/v001

## Changes

This pursues the same O(1)-ghost-membership target as the separate-HashSet
approach but with the opposite memory tradeoff: instead of adding a third hash
structure, reuse the `entries` map that `put` already probes on its fast path,
so a ghosted key is resolved by the *same* `entries.get` call rather than a
linear `ghost.iter().any(...)`.

Change `entries` to carry an explicit residency state. Replace
`entries: HashMap<K, Entry<K,V>>` with `entries: HashMap<K, Slot<K,V>>` where
`enum Slot<K,V> { Resident(Entry<K,V>), Ghost }` (the `Ghost` variant holds no
value — it is the tombstone). Keep the `ghost: VecDeque<K>` solely for FIFO
eviction order.

Rewire the paths:
- `find_entry_mut`/`get` match only `Slot::Resident`, returning `None` for a
  `Ghost` slot (a ghosted key is not a cache hit).
- In `put()`, the existing `self.find_entry_mut(&key)` miss is followed by a
  single `matches!(self.entries.get(&key), Some(Slot::Ghost))` check (O(1))
  replacing `ghost.iter().any(...)`. On a ghost hit, overwrite the slot in place
  with `Slot::Resident(Entry::new(...))` and push the key to `main` (after
  `evict_main` if full). The `ghost.retain(...)` removal is dropped; leave a
  tombstone-free entry because the slot is now Resident, and let the order
  VecDeque carry a stale copy that is skipped on pop.
- In `evict_main`/`evict_small`, when a victim is ghosted, set its slot to
  `Slot::Ghost` (do **not** `entries.remove`) and push the key into the `ghost`
  order queue. When the live ghost count exceeds `(main_size/2).max(1)`, pop the
  order queue's back, and only then `entries.remove` keys whose slot is still
  `Ghost` (skip any that became Resident again).

Invariants: enforce the ghost capacity bound on the count of `Ghost` slots, not
queue length; preserve freq=0 ghost re-admission and freq=0 re-proof; keep
two-touch small→main promotion. Note the scored `size_of::<Entry>` must stay ≤ 24
— `Slot` wraps `Entry`, so confirm the measured `Entry<u64,u64>` size is unchanged
(the enum lives in the container value type, not in the `Entry` the metadata
binary measures).

## Rationale (optional)

Distinct from a bolt-on ghost HashSet: this removes the linear put scan *and*
avoids a second key-keyed hash table, directly addressing the open question of
whether the hash index's unscored key duplication becomes the binding cost.
