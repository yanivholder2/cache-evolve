# H01

Adding a branchless, masked conservative update to the blocked 4-bit sketch of the window/SLRU winner raises hit-rate, mainly at the 131072 cache size, while keeping get p50 near 35 ns.

## Parent

cycle/0003/v001

## Changes

Change only `CountMinSketch::increment_hashed` in `src/tiny_lfu/mod.rs`. Leave `position`, `block_index`, `estimate_hashed`, `reset`, `SAMPLE_FACTOR` and the counter width as they are.

The layout already gives each row `i` its own words `2i` and `2i+1`. Two rows therefore never share a nibble, so the re-read guard in cycle/0003/v003 is not needed. The new body has no data-dependent branches inside the loop:

1. Compute `bi` and take `block = &mut self.table[bi].0`. Compute the four `(w_i, s_i)` with `position(h, i)`. Unroll by hand or use a fixed `[_; SKETCH_DEPTH]` array so the compiler emits straight-line code.
2. Load the four nibbles `c_i = (block[w_i] >> s_i) & 0xF`. Compute `min = c0.min(c1).min(c2).min(c3)`, which compiles to cmov.
3. Set `live = (min < 15) as u64`. For each row, `block[w_i] += (((c_i == min) as u64) & live) << s_i`. There is no `if` around the add.
4. Set `self.additions += live as u32`. Keep one branch, `if self.additions >= self.sample_size { self.reset() }`, with `reset` still `#[cold]`. Remove the `moved` flag.

Invariants: counters still saturate at 15, because the add happens only when `min < 15` and the only counters that move equal `min`. The estimate remains the minimum over the four rows. Aging semantics do not change. Existing tests must pass: `sketch_saturates_at_15`, `sketch_ages_by_halving` (8 increments of one key on a fresh sketch give 8) and `sketch_counts_increment`. Add a unit test like v003's `conservative_update_spares_shared_counter`, written against this variant's `position` bit layout (byte `i`: bit 4 selects the word, bits 0..4 select the nibble).

## Rationale (optional)

v003 showed that conservative update fixes the large-cache slip, but its branchy two-pass version pushed get p50 to 67 ns. This hypothesis tests two things together. First, whether the hit-rate gain holds on top of window/SLRU. Second, whether a branch-free form costs about the same as v001's current single-pass increment, which also has a per-row branch.
