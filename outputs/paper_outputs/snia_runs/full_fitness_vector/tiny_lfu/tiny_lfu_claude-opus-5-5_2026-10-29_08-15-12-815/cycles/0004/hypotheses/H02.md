# H02

Porting v001's cache-line-blocked 4-bit aging sketch into the 24-byte u32-link variant brings hit-rate to about 0.556 and cuts the sketch heap to 8 KiB, while node metadata stays at 24 bytes.

## Parent

cycle/0003/v002

## Changes

Keep v002's whole residency layer unchanged: u32 `prev`/`next` with the region tag in bits 30–31, `NIL`/`NIL_USIZE`, `RegionList`, `unlink`/`push_back`/`on_hit`/`evict_one`, the capacity guard in `try_new`, and the prehashed `HashedKey` map. Replace only the frequency sketch with the one from cycle/0003/v001 `src/tiny_lfu/mod.rs`, copied exactly:

- the `SAMPLE_FACTOR = 10`, `COUNTERS_PER_BLOCK = 128` and `RESET_MASK = 0x7777_7777_7777_7777` constants;
- `#[repr(align(64))] struct Block([u64; 8])`;
- `CountMinSketch { table: Vec<Block>, block_mask, additions: u32, sample_size: u32 }`, with `new(width, capacity)`, `block_index` (high 32 bits), `position` (byte `i`, bit 4 = word, bits 0..4 = nibble), the saturating `increment_hashed` with the sample counter, the `#[cold] reset` that halves, and `estimate_hashed`;
- `heap_bytes()` returning `table.len() * 64`.

Construct it in `try_new` as `CountMinSketch::new(width, capacity)`. Bring over v001's sketch unit tests (`sketch_saturates_at_15`, `sketch_ages_by_halving`, `sketch_heap_within_budget` asserting 8 KiB at cap 1024). Keep v002's link round-trip test and its `size_of::<Node<u64,u64>>() <= 24` const assert.

Do not add conservative update here (H01 tests that). Keeping it out means any hit-rate or latency change comes from the sketch swap alone.

## Rationale (optional)

v002 has the smallest node (24 B) but still uses the old 64 KiB sketch, and its hit-rate is v001's minus the aging gain. Earlier merges have always added up. This one tests whether the 24-byte layout and v001's hit-rate (0.555975) can coexist. It also runs both link layouts on the same sketch, which settles the open question of whether v002's latency regression (57 vs 35 ns) comes from the links or from the old sketch's scattered memory access.
