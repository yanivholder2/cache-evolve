# H02

Prefetching the hit node's list neighbours and the destination-list tail before `on_hit` relinks them will cut get p99, and so per-op-time, on cycle/0006/v003 without changing hit-rate.

## Parent

cycle/0006/v003

## Changes

All edits are in `src/tiny_lfu/mod.rs` and touch only the hit path.

1. Add `#[inline(always)] fn prefetch_node(&self, i: u32)`. If `i != NIL`, it issues `_mm_prefetch(self.nodes.as_ptr().add(i as usize) as *const i8, _MM_HINT_T0)` (gated on `x86_64`, a no-op elsewhere). This is safe for any live index and is skipped for the sentinel.
2. `get`: once the map probe returns `Some(idx)`, and before the existing `increment_hashed(h)`, which stays between the probe and `on_hit`, load `let n = self.node(idx);`, read `n.prev & !REGION_MASK` and `n.next`, and prefetch both neighbours. Also prefetch the destination tail: `lists[PROTECTED].tail` if `n.region() == PROBATION`, otherwise `lists[n.region()].tail`. If the region is PROBATION and `lists[PROTECTED].len >= protected_cap`, also prefetch `lists[PROTECTED].head`, the demotion node, and `lists[PROBATION].tail`. The sketch RMW then overlaps these node misses.
3. `put`, on the update-in-place branch: apply the same neighbour prefetch before `node_mut(idx).value = value`.
4. `on_hit`, `unlink` and `push_back` keep their logic unchanged. In the `else if self.list(r).tail != idx` branch, skip the prefetches when `idx` is already the tail. Put that check before issuing them so the common hot-key repeat pays nothing.

Hit-rate must stay bit-identical: prefetches have no semantic effect. Keep the existing list-consistency test and add one that checks hit sequences against the parent order. Measure get p99 with interleaved A/B runs against v003.

## Rationale (optional)

v003's sketch prefetch moved get p50 but not get p99. Both cycle insights point to the dependent node and neighbour-link misses in probation→protected promotion, which touches up to 5 scattered 24-byte nodes. This hypothesis tests that diagnosis directly.
