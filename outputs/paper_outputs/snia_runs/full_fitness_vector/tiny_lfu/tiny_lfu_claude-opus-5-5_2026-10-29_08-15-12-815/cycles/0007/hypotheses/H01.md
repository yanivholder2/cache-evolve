# H01

Porting cycle/0006/v003's sketch-block prefetch, probe-before-increment reorder and paired `evict_one` prefetch onto v001's merged line will lower per-op-time (get p50 and put p99) below v001's 36 while keeping v001's 0.5603 hit-rate bit-identical.

## Parent

cycle/0006/v001

## Changes

Start from v001's `src/tiny_lfu/mod.rs` and change only the op ordering. Keep the pairwise conservative update, `window_size` floor, 24-byte node and odd-count `reset()` exactly as they are.

1. Add `#[inline(always)] fn prefetch(&self, h: u64)` to `CountMinSketch`. It issues `core::arch::x86_64::_mm_prefetch(self.table.as_ptr().add(self.block_index(h)) as *const i8, _MM_HINT_T0)` under `#[cfg(target_arch = "x86_64")]` and is a no-op on other targets. Port it from cycle/0006/v003's overlay.
2. `get`: `let h = key_hash(key); self.sketch.prefetch(h); let found = self.map.get(&probe).copied(); self.sketch.increment_hashed(h); let idx = found?; self.on_hit(idx); ...`. The increment must still run on a miss.
3. `put`: same pattern. Hash, prefetch, probe the map, then `increment_hashed(key_h)`, then branch on the probe result. Increment exactly once per call, as now.
4. `evict_one`: compute `cand_h` and `victim_h`, prefetch both blocks, then call the two `estimate_hashed`. Keep the strict `cand_freq > victim_freq` contest.

Add a test, `reordered_ops_match_parent_exactly`, that drives a seeded skewed op stream at capacities 1/2/7/64 through this cache and through an inline copy of v001's op order. It asserts identical hit sequences, identical resident sets and identical sketch tables, so hit-rate is guaranteed unchanged. Judge latency with interleaved runs against v001, because single-run deltas have been noise.

## Rationale (optional)

The cycle 0006 continuation names this merge as the open question: v003's gain came from memory-level parallelism, v001's from inlining. If the two gains overlap, get p50 will match v001. If they stack, it will fall further.
