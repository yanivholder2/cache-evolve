# H02

Replace v003's flat four-row u32 count-min sketch with a cache-line-blocked sketch of packed 4-bit counters, where each key's four counters sit in one 64-byte block, to cut the `get` p99 and per-op-time.

## Parent

cycle/0001/v003

## Changes

Rewrite the `CountMinSketch` storage and the `increment_hashed` / `estimate_hashed` paths in v003. Use a Caffeine-style FrequencySketch layout:

- Storage is a `Vec<u64>`, grouped into 64-byte blocks of 8 u64 words. Each word holds 16 four-bit counters.
- Make the number of blocks a power of two, sized so that total counter count is at least the current `depth × width` budget. The sketch heap must stay ≤ 65536 bytes at cap=1024, so it does not regress metadata-size. 4-bit packing gives 8× the counters per byte, so it can also shrink.
- From the single 64-bit key hash (v003's multiply-rotate plus splitmix64 finish), pick the block from the high bits: `block = (h >> 32) & block_mask`. Derive four counter positions inside that block from disjoint low-bit slices of `h`. Each position is one of the block's 8 words plus a 4-bit nibble index. Use a different word for each of the 4 "rows" where possible, for example word `i*2 + ((h >> (8*i)) & 1)` for row i.
- `estimate_hashed` takes the min of the four nibbles. `increment_hashed` bumps each nibble that is < 15, which saturates at 15. Use a plain increment, not conservative update, to keep it single-pass.
- Aging: keep an `additions: u32` counter. When it reaches `sample_size = 10 × capacity`, run a reset that halves every counter in place with `(w >> 1) & 0x7777_7777_7777_7777`, then halve `additions`. Without aging, 4-bit counters would saturate and pin stale keys.
- Align the `Vec` to 64 bytes, for example with a `#[repr(align(64))] struct Block([u64; 8])` and `Vec<Block>`, so a key never straddles two cache lines.

Leave `TinyLfuCache`'s admission logic, map, hashing and LRU residency structure unchanged.

## Rationale (optional)

The v003 insight attributes its `get` p99 increase to four scattered cache misses across the sketch rows, now that hashing no longer hides them. A blocked layout makes each access touch one line. The halving sweep is cheap over packed words, which addresses v002's latency cost from aging over u32 counters. The sweep could also add a hit-rate gain, but the claim targets per-op-time.
