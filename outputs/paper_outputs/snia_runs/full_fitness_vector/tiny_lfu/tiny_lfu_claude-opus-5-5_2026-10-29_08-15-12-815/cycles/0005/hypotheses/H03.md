# H03

Replacing the exact four-way `min` in conservative update with a pairwise minimum within row pairs (0,1) and (2,3) will cut get p50 back to about 35 ns while keeping most of conservative update's hit-rate gain at 131072.

## Parent

cycle/0004/v001

## Changes

Rewrite only `CountMinSketch::increment_hashed` in `src/tiny_lfu/mod.rs`. Keep `position`, `block_index`, `estimate_hashed`, `reset` and the residency code unchanged.

The four loads `c0..c3` stay as they are. Replace the serial chain `min = c0.min(c1).min(c2).min(c3)` and the four compares against the global `min` with two independent pair minimums:

```rust
let m01 = c0.min(c1);
let m23 = c2.min(c3);
let live01 = (m01 < 15) as u64;
let live23 = (m23 < 15) as u64;
block[w0] += (((c0 == m01) as u64) & live01) << s0;
block[w1] += (((c1 == m01) as u64) & live01) << s1;
block[w2] += (((c2 == m23) as u64) & live23) << s2;
block[w3] += (((c3 == m23) as u64) & live23) << s3;
self.additions += (live01 | live23) as u32;
```

This cuts the dependency depth from load → min → min → min → cmp → add to load → min → cmp → add. The two halves are independent, so the CPU can run them in parallel. Rows own disjoint words, so updating the pairs separately stays safe without re-reads. Each pair still grows only its smaller counter (both counters on a tie). That removes about half of the collision inflation that full conservative update removes, at the latency of a plain increment. The `if self.additions >= self.sample_size { self.reset() }` check stays the same. Aging fires whenever either pair moved, so the cadence matches the parent whenever the global minimum is below 15.

Update `conservative_update_spares_shared_counter` so it holds under pairwise semantics. With the existing hashes `a` and `b`, b's row-0 counter (shared with a, value 3) is paired with b's row-1 counter (value 0), so it is still spared. The test's assertions should therefore still hold; check this, and only adjust the comment. Add a test where one key's pair (2,3) sits at a lower level than its pair (0,1). It should check that both pairs advance their own minimum independently.

## Rationale (optional)

Cycle 0004's v001 found that conservative update's latency cost comes from the serial `min` chain, not from branches. It also found that the hit-rate gain comes from reducing overestimation at the large size. This hypothesis tests the open question "can a pairwise or approximate min keep the accuracy at the old increment latency?". It measures the trade directly against v001: per-op-time should improve, and hit-rate at 131072 should fall at most halfway back toward cycle/0003/v001.
