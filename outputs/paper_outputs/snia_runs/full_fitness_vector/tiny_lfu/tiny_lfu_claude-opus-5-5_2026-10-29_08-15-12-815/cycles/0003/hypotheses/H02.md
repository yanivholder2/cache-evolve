# H02

Shrinking v001's node links to sentinel-encoded u32 indices, with the region tag packed into `prev`, will cut `Node<u64,u64>` from 40 to 24 bytes and lower metadata-size without hurting per-op-time.

## Parent

cycle/0002/v001

## Changes

Edit v001's `src/tiny_lfu/mod.rs`. This changes only the link encoding. Keep the eviction policy and the sketch as they are.

- Change `Node` to `{ key: K, value: V, prev: u32, next: u32 }`. With u64 key/value and no padding, that is 8 + 8 + 4 + 4 = 24 bytes. Replace the `<= 48` const assert with `const _: () = assert!(size_of::<Node<u64,u64>>() <= 24);`.
- Redefine the tag constants for 32-bit links: `REGION_SHIFT: u32 = 30`, `REGION_MASK: u32 = 0b11 << 30`, and `NIL: u32 = !REGION_MASK` (= 0x3FFF_FFFF). `next` stores a raw untagged index, with `NIL` meaning "no next", so `Option<usize>` goes away entirely. `prev` keeps the 2-bit region tag in bits 30–31 and the index in bits 0–29.
- Update the accessors: `prev_idx()`, `set_prev_idx()`, `region()`, `set_region()`, and `next_idx()` (which now just returns `self.next`). Add `set_next_idx()`. These should return and accept `usize` at the call sites, converting with `as u32` / `as usize`, so `unlink()`, `push_back()`, `evict_one()`, and `on_hit()` only change where they currently write `Some(..)`/`None` into `next`. Those writes become `idx as u32` / `NIL`. The comparisons `== NIL` must compare against `NIL as usize`. Alternatively, define a `NIL_USIZE: usize = NIL as usize` and use it for `RegionList.head/tail` and every comparison. `RegionList` can stay `usize`-typed.
- In `try_new`, reject `capacity >= NIL as usize` by logging `log::error!` and returning `None`, so no real index can collide with the sentinel. All benchmark sizes (≤131072) are far below 2^30.
- Update the in-file test `region_tag_roundtrips_without_corrupting_links` to construct `Node { prev: NIL, next: NIL, .. }`, and add a test asserting that `size_of::<Node<u64,u64>>() == 24`.

Invariants: behaviour is bit-identical to v001 (same hit-rates), the map key stays `HashedKey`, and there is one hash per op.

## Rationale

v001's insight names `next: Option<usize>` (16 bytes with its discriminant) as the obvious remaining node fat. Going straight to u32 links takes the next step past `NIL`-on-`next` (32 bytes) to 24 bytes. A smaller node also packs 2.67 nodes per cache line instead of 1.6, which should help `get`/`on_hit` relinks on the 131072-entry arena.
