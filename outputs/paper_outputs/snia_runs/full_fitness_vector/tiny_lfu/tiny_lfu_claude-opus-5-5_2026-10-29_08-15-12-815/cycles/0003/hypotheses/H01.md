# H01

Replacing v001's flat u32 count-min sketch with v002's cache-line-blocked 4-bit aging sketch will raise hit-rate at the 16384-entry size and cut put latency, while v001's window/SLRU and prehashed map key stay unchanged.

## Parent

cycle/0002/v001

## Changes

Start from v001's `src/tiny_lfu/mod.rs`. Leave all residency logic as it is: `TinyLfuCache` with `map: HashMap<HashedKey<K>, usize, PrehashedBuildHasher>`, the three `RegionList`s, `evict_one()`, `on_hit()`, `unlink()`/`push_back()`, the sentinel-tagged `prev`, and the hash-once `get`/`put` paths. Replace only the `CountMinSketch` struct and its impl with the blocked design from cycle/0002/v002:

- Add the constants `SAMPLE_FACTOR = 10`, `COUNTERS_PER_BLOCK = 8 * 16`, and `RESET_MASK = 0x7777_7777_7777_7777`. Remove `MAX_COUNT`.
- Add `#[repr(align(64))] struct Block([u64; 8])`. The sketch becomes `{ table: Vec<Block>, block_mask: usize, additions: u32, sample_size: u32 }`. Size it as `new(width, capacity)`, exactly as v002 does: blocks = ceil(`SKETCH_DEPTH * width` / 128), rounded up to the next power of two, and `sample_size = capacity * SAMPLE_FACTOR` clamped to u32.
- `block_index(h) = (h >> 32) & block_mask`. `position(h, i)` uses the low 32 bits exactly as in v002, so block selection and in-block positions use disjoint hash bits. Keep in mind that v001's hashbrown map also uses this same `h`. Hashbrown uses the top 7 bits for control bytes and the low bits for the bucket. That overlap is acceptable, but do not change `key_hash`.
- `increment_hashed` saturates each nibble at 15, counts an addition only when at least one counter actually moved, and calls a `#[cold] fn reset()` that halves every word with `(w >> 1) & RESET_MASK` and halves `additions`.
- `estimate_hashed` returns the minimum of the four nibbles. `heap_bytes()` returns `table.len() * 64`.
- In `try_new`, call `CountMinSketch::new(width, capacity)`.
- Port v002's sketch unit tests (`sketch_saturates_at_15`, `sketch_ages_by_halving`, `sketch_heap_within_budget`) into the in-file test module. Keep v001's existing cache tests passing. They rely on a strict `cand_freq > victim_freq` contest at tiny capacity, which 4-bit counters still satisfy.

Invariants: `Node<u64,u64>` stays at 40 bytes, the sketch heap at cap=1024 stays ≤ 64 KiB (it should drop to 8 KiB), and there is exactly one `key_hash` per key per op on the get path.

## Rationale

The cycle-0002 insight explicitly asks for this merge. v001 changed residency and the map key; v002 changed sketch storage and aging. These are disjoint parts of the cache, and the previous orthogonal merge added up. Aging should help the window/SLRU contest at the small size, where stale probation victims block new arrivals. The single-line sketch access should also lower the put p50/p99, which currently does three scattered 4-row sketch accesses per eviction.
