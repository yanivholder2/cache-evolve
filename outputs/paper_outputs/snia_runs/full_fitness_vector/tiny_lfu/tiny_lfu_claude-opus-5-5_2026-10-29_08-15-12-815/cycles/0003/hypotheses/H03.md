# H03

Switching v002's blocked 4-bit sketch to conservative update, which increments only the counters equal to the key's current minimum, will remove the hit-rate slip at the 131072-entry size.

## Parent

cycle/0002/v002

## Changes

Edit only `CountMinSketch::increment_hashed` in v002's `src/tiny_lfu/mod.rs`. Leave the block layout, `position()`, `estimate_hashed`, `reset()`, `SAMPLE_FACTOR`, and the cache's admit-or-drop policy unchanged.

- First pass: for `i in 0..SKETCH_DEPTH`, compute `(w, shift) = position(h, i)` and read the nibble `c_i = (block[w] >> shift) & 0xF`. Track `min = min(c_i)`. All the reads are in the same 64-byte block that is already loaded, so no extra cache misses are added.
- If `min == 15`, return without counting an addition. The key is saturated.
- Second pass: for each row whose `c_i == min`, do `block[w] += 1 << shift`. Leave counters above the minimum untouched. If two rows map to the same `(w, shift)` nibble, increment it only once. Guard this by re-reading the nibble before incrementing, and skip if it is now greater than `min`.
- Count `additions += 1` once per call whenever at least one counter moved, which is always the case when `min < 15`. Keep the existing `if additions >= sample_size { reset() }` trigger.
- Keep the `sketch_counts_increment`, `sketch_saturates_at_15`, and `sketch_ages_by_halving` tests passing. A single key's four counters are all equal, so conservative update behaves the same as before for them. Add one test: increment key A 10 times, then increment a key B that collides with A in one row. Do this by constructing hashes directly, for example an `h_b` that equals `h_a` in the bits row 0 uses. Assert that `estimate_hashed(h_a)` is unchanged and that the shared counter did not move unless it was B's minimum.

## Rationale

v002's insight lists correlated in-block collisions as one candidate cause of the web_0@131072 slip: all four rows share one 64-byte block, so overestimation is correlated and the min-of-four estimate inflates. Conservative update is a known count-min fix for overestimation. It also slows how fast collided counters reach the 15 ceiling, which addresses the saturation candidate too, without widening the counters or changing the aging period. If the large-cache cell recovers while small-cache cells hold, the slip was caused by estimate inflation rather than by the aging period. If it does not recover, that points the next cycle at `SAMPLE_FACTOR` instead.
