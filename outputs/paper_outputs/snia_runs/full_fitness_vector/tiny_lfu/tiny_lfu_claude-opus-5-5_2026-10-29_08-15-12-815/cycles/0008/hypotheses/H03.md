# H03

Replacing move-to-tail on protected-region hits with a CLOCK-style reference bit cuts get p99 and p50 (per-op-time), because a protected hit no longer touches neighbour nodes or list heads.

## Parent

cycle/0006/v001

## Changes

All edits are in `src/tiny_lfu/mod.rs`. Today every protected hit in `on_hit` runs `unlink` + `push_back`. That writes the prev neighbour, the next neighbour and the old tail node, which can mean up to three dependent cache-line misses after the hit node itself is loaded. This is the pointer chase the cycle 0007 prefetch could not hide.

1. **Reference bit.** Define `const REF_BIT: u32 = 1 << 31;` and keep it in `Node::next`. `NIL` (0x3FFF_FFFF) and every valid index fit below bit 30, so every read of `next` as an index must use `next & !REF_BIT`. That covers `unlink` (`let next = ...`), `next_idx()`, the `check_lists` test helper, and any other place that walks `next`. Every write of `next` as a link must keep the node's own `REF_BIT`. In `unlink`, `node_mut(prev).next = next` must become `(old & REF_BIT) | next_idx`. In `push_back`, `node_mut(tail).next = idx` must keep the old tail's bit. `push_back` sets the moved node's own `next = NIL`, which clears its bit. That is intended, because a relinked node starts unreferenced.
2. **`on_hit`.** Keep the PROBATION branch: promote to protected, then demote on overflow (see 3). Add a new branch for `r == PROTECTED` that does only `self.node_mut(idx).next |= REF_BIT;`, with no unlink or push_back. Leave the WINDOW branch as it is now (move to tail if not already the tail).
3. **Demotion with second chance.** Where `on_hit` demotes the protected head after the protected list overflows, loop at most `MAX_SECOND_CHANCE = 4` times. Take `d = protected.head`. If `d` has `REF_BIT` set, `unlink(d)` and `push_back(d, PROTECTED)`, which clears the bit, then continue. Otherwise stop. After the loop, demote the current head to PROBATION as before. The bound keeps the worst-case cost of a promotion fixed, so the change does not just move the tail spike somewhere else.
4. `evict_one` falls back to the protected head when probation is empty. It ignores the bit there, because that path is rare.
5. Sketch, window sizing, admission test and hashing stay unchanged.

Invariants: the node stays at 24 bytes and `try_new`'s capacity guard is unchanged. `check_lists` must still pass, with links masked. Add a test where repeated protected hits do not reorder the protected list, and where a referenced head survives one demotion. Hit-rate may move slightly, because CLOCK approximates protected LRU. Report each cell. Judge per-op-time in an interleaved run against cycle/0006/v001.
