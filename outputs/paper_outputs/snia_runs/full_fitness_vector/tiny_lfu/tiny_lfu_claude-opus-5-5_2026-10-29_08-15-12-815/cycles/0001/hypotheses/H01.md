# H01

Adding a 1% LRU admission window in front of a segmented-LRU main region (20% probation / 80% protected), with the TinyLFU contest only between window evictees and probation victims, will raise mean hit-rate on the MSR grid above the baseline's 0.504.

## Parent

baseline

## Changes

Restructure `TinyLfuCache` in `src/tiny_lfu/mod.rs` into W-TinyLFU with three regions that share the existing `nodes` arena. Each region is its own doubly-linked recency list over the arena.

- Add a per-node region tag to `Node` (`region: u8` with values Window / Probation / Protected). Replace the single `head`/`tail` with a head/tail pair per region plus a length counter per region. Generalise `unlink(idx)` and `push_back(idx)` to take the region, or read it from the node's tag.
- Sizes: `window_cap = max(1, capacity / 100)`, `main_cap = capacity - window_cap`, `protected_cap = main_cap * 80 / 100`. Probation gets whatever is left of main. If `capacity == 1`, everything goes in the window and there is no contest.
- `get` hit: in Window, promote to Window MRU. In Probation, move to Protected MRU, and if Protected is over `protected_cap`, demote Protected's LRU to Probation MRU. In Protected, promote to Protected MRU. Keep the sketch increment on every access.
- `put` of a new key: always insert at Window MRU. Use a fresh arena slot while `nodes.len() < capacity`; otherwise reuse a freed slot as described below. If the window is now over `window_cap`, take the window LRU as the `candidate`:
  - If main is not full yet, move `candidate` to Probation MRU.
  - Otherwise run the admission contest between `candidate` and the `victim` (Probation LRU, or Protected LRU if Probation is empty). If `estimate(candidate) > estimate(victim)`, remove the victim from `map` and keep its slot to reuse, then move `candidate` to Probation MRU. If not, remove the candidate from `map` and reuse its slot.
  - Order matters: work out the reusable slot before inserting the newcomer, so that `nodes.len()` never goes above `capacity`. A simple way is to pick the evictee first and then write the newcomer into its slot.
- `put` update of a resident key: update the value and apply the same region-aware promotion as `get`.
- Invariants to keep: `map.len() <= capacity`, every key in `map` points to a live node in exactly one region list, and region lengths add up to `map.len()`. The sketch and its sizing stay unchanged so this experiment isolates the effect of the region structure.

## Rationale (optional)

The baseline's admission filter rejects every newcomer whose count is not strictly higher than the LRU victim's. On MSR block traces with bursty recency, new blocks never get a chance to build up frequency, so they are dropped before their second access. A small window absorbs these bursts. SLRU protects proven-hot blocks from the probation churn.
