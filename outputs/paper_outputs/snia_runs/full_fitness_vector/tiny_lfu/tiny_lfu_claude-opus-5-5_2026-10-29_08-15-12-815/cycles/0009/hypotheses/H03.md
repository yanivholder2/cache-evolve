# H03

Replacing move-to-tail on protected-segment hits with a reference bit in a separate per-slot bitset, so a protected hit sets one bit and writes no links, will cut get p50/p99 per-op-time with hit-rate within about 0.001 of the parent.

## Parent

cycle/0006/v001

## Changes

This tests the "reference bit outside `Node`" question from the cycle 0008 insight. `Node` stays 24 bytes, and every link store stays blind: no flag bits go into `prev`/`next`.

- Add a field `ref_bits: Vec<u64>` to `TinyLfuCache`, sized `(capacity + 63) / 64` words and zeroed in `try_new`. Add helpers `#[inline(always)] fn set_ref(&mut self, i: u32)`, `fn take_ref(&mut self, i: u32) -> bool` (test-and-clear) and `fn clear_ref(&mut self, i: u32)`. Use unchecked indexing, with the same SAFETY argument as `node()`.
- `on_hit`:
  - In the PROTECTED branch (`r == PROTECTED`), replace the `unlink` + `push_back` with `self.set_ref(idx)`.
  - The WINDOW branch keeps the parent's move-to-tail. The window is small, so its hits are not the hot pointer chase.
  - The PROBATION branch keeps `unlink` + `push_back(idx, PROTECTED)` and calls `clear_ref(idx)` on the promoted node.
  - Protected overflow handling changes. Let `d` be the protected head. If `take_ref(d)` returns true, give it one second chance: `unlink(d); push_back(d, PROTECTED)`, then take the new head as `d`. After that, demote `d` unconditionally to probation without checking its bit, and clear its bit. Cap the second chances at exactly 1. Cycle 0008 v003 showed that a 4-rotation loop moves the tail cost into promotion.
- `put` on an existing key goes through `on_hit`, so it gets the same behaviour automatically.
- `evict_one`: when the victim comes from PROTECTED (probation empty), and on every slot reuse in `put`, call `clear_ref(slot)` so a reused slot never inherits a stale bit.

Add tests:
- A protected hit leaves the list order unchanged and sets the bit.
- When protected overflows, a referenced head is rotated once and the next head is demoted.
- `check_lists` still passes under `mixed_ops_keep_lists_consistent`.

The sketch, window floor, admission rule and hashing are not touched. Report get/put p50 and p99 against the parent. Interleaved repeat runs are preferred, because single-run latency verdicts have been unreliable.

## Rationale

Protected hits are the most common hit type at steady state. Each one currently does an unlink plus a push_back, which touches the prev neighbour, the next neighbour and the old tail: up to three extra cache lines on a random 24-byte-node array. Cycle 0008 v003 failed because the bit lived in `next`, which turned blind stores into RMWs, and because the rotation loop was unbounded. This variant avoids both causes. If get p99 still does not move, the protected relink is ruled out as its source.
