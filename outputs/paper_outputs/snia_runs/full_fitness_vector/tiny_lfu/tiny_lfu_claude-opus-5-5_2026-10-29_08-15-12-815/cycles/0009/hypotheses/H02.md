# H02

On cycle 0008 v002's dedup plus tie-break line, counting each deduplicated miss→put toward the sketch's aging clock (`additions`) will restore the aging rate and raise hit-rate at the large cache size without losing the small-size gains.

## Parent

cycle/0008/v002

## Changes

Combine v002's tie-break with cycle 0008 v001's clock-preserving tick. This answers the open question in the cycle 0008 insight.

- In `CountMinSketch`, add:
  ```rust
  /// Advances the aging clock by one addition without touching counters.
  #[inline(always)]
  fn tick(&mut self) {
      self.additions += 1;
      if self.additions >= self.sample_size {
          self.reset();
      }
  }
  ```
  `reset()` stays `#[cold]` and unchanged.
- In `TinyLfuCache::put`, replace
  `if !already_counted { self.sketch.increment_hashed(key_h); }`
  with
  `if already_counted { self.sketch.tick(); } else { self.sketch.increment_hashed(key_h); }`.
  Everything else stays as it is: the `already_counted` computation, the `last_miss_valid = false` clear, the `get` body, `admit()` with `TIE_WIN_MIN_FREQ = 2`, the window floor, pairwise conservative update, and the Node layout.

Add a unit test: with a small `sample_size` (for example capacity 1, so the sample size is 10), alternating `get` miss → `put` of fresh keys triggers a reset after the same number of accesses as two increments per key would. For example, check that `additions` after 3 miss→put pairs is 6 (or has wrapped through a reset at 10). The frequency estimate of a miss→put key must still be 1, so keep `miss_then_put_counts_once` passing.

## Rationale

Cycle 0008 split cycle 0007 v003's dedup into two parts:
- The slower aging clock, which v001 restored without the tie-break.
- The lost tie edge, which v002 restored without the clock.

Restoring the clock fixed most of the large-size web_0 loss. Restoring the tie edge kept the small-size gains. If the two effects are independent, applying both should beat v002 at 131072 on web_0. Expected results:
- If the cells are flat or better, the clock and the tie edge are complementary.
- If hm_0 @ 16384 drops back the way it did in v001, the small-size gain came from slower aging. That would argue for a size-dependent `SAMPLE_FACTOR` next.

There is no hot-path change on hits. The miss→put path executes the same branch, with `tick()` instead of nothing.
