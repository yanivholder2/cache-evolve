# H01

Letting a window candidate win equal-estimate admission contests once its estimate is at least 3, on the incumbent line that keeps the miss→put double count, will raise hit-rate in all four cells over cycle/0007/v001.

## Parent

cycle/0007/v001

## Changes

Port cycle 0008 v002's guarded tie-break onto the incumbent line. Do not port v002's miss dedup (`last_miss_h` / `last_miss_valid`). `get` and `put` stay byte-identical to the parent, including the prefetch and the probe-before-increment order, and the parent's miss→put double count stays.

- Add `const TIE_WIN_MIN_FREQ: u32 = 3;` next to `WINDOW_FLOOR_MAX`.
- Add a branchless helper, written like v002's:
  `#[inline(always)] fn admit(cand_freq: u32, victim_freq: u32) -> bool { (cand_freq > victim_freq) | ((cand_freq == victim_freq) & (cand_freq >= TIE_WIN_MIN_FREQ)) }`
- In `evict_one`, replace `if cand_freq > victim_freq` with `if admit(cand_freq, victim_freq)`. Leave the rest of `evict_one` unchanged, including both prefetches and the cand/victim unlink order.

Why the threshold is 3, not 2: on this line a newcomer's miss→put already gives it an estimate of 2. So `>= 2` would let a one-hit wonder win ties, which would undo the guard that kept v002 safe at the small size. With the double count, an estimate of 3 is the first value that needs at least one more reference after insertion, so it matches what v002's `>= 2` meant on the dedup line.

Add unit tests:
- `admit(3,3)` is true.
- `admit(2,2)`, `admit(1,1)` and `admit(0,0)` are false.
- `admit(1,0)` and `admit(3,2)` are true.
- Cap-2 scenario 1: a candidate inserted by miss→put alone (estimate 2) loses a tie against a victim at 2.
- Cap-2 scenario 2: a candidate with one extra `get` hit (estimate 3) beats a victim at 3.

Update any existing test that depended on strict `>` (for example `eviction_prefers_hot_items`) only if the new rule changes its outcome. The Node layout, the sketch, the window floor and the reset logic are not touched.

## Rationale

Cycle 0008 showed that the double count acts as an implicit "seen again" bonus, and that an explicit bounded tie-break helps every cell. These are separate mechanisms. This tests whether they stack on the incumbent line with the aging clock unchanged, instead of rebuilding the bonus on the dedup line. The change touches only the full-cache eviction path, so per-op-time should match the parent.
