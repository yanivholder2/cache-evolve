# H01

Removing the miss→put `tick()` and aging small caches more slowly (`SAMPLE_FACTOR` 16 at capacity ≤ 32768, 10 above) will raise small-size hit-rate above cycle 0008 v002 and leave the large size unchanged.

## Parent

cycle/0009/v002

## Changes

The work is in `src/tiny_lfu/mod.rs` and has two parts.

1. **Revert the clock-preserving tick.** In `TinyLfuCache::put`, change the
   `if already_counted { self.sketch.tick(); } else { self.sketch.increment_hashed(key_h); }`
   block to `if !already_counted { self.sketch.increment_hashed(key_h); }`.
   A deduplicated miss→put then advances neither the counters nor
   `additions`, which is exactly cycle 0008 v002's behaviour. Delete
   `CountMinSketch::tick()` and its unit test `tick_advances_clock_without_touching_counters`.
   Rewrite `miss_then_put_advances_aging_clock_twice` so it asserts one
   addition per miss→put pair: after 3 pairs at capacity 1,
   `additions == 3`. Update the `last_miss_valid` field doc comment to
   match.

2. **Make the aging period depend on capacity.** Replace the single
   `SAMPLE_FACTOR` constant with `SAMPLE_FACTOR_SMALL: usize = 16`,
   `SAMPLE_FACTOR_LARGE: usize = 10` and `SMALL_CAPACITY_MAX: usize = 32_768`.
   Add `fn sample_factor(capacity: usize) -> usize` that returns
   `SAMPLE_FACTOR_SMALL` when `capacity <= SMALL_CAPACITY_MAX` and
   `SAMPLE_FACTOR_LARGE` otherwise. Use it in `CountMinSketch::new`
   (`capacity.saturating_mul(sample_factor(capacity))`, keeping the
   existing clamp to `u32::MAX`).
   - Unit tests in the file that rely on `sample_size == 10 * capacity` at
     tiny capacities (`sketch_ages_by_halving` uses capacity 1, and the
     miss→put clock test) must be updated to the new period of 16. For
     example, `sketch_ages_by_halving` should do 15 increments (estimate
     15, which is saturation), then one more that triggers the reset
     (estimate 7 or 8, depending on the halving of 15). Alternatively,
     build those sketches with an explicit test-only constructor that
     takes `sample_size`. Pick whichever keeps the assertions exact.
   - Add a test `sample_factor_by_size`:
     `sample_factor(16384) == 16`, `sample_factor(131072) == 10`.

Leave everything else unchanged: the `TIE_WIN_MIN_FREQ = 2` tie-break,
the window floor, the pairwise conservative update, the `reset()`
odd-count correction, the 24-byte node and all `#[inline(always)]`
attributes. The hot path of `get` must stay byte-identical. Since
131072 > 32768 keeps factor 10, the large-size cells should be
bit-identical to cycle 0008 v002.

## Rationale (optional)

Cycle 0009 showed that the 16384-size gain of cycle 0008 v002 came from
slower aging: re-adding the tick (this parent) gave it back. This
variant first restores 0008 v002 exactly. It then moves only the
small-size aging lever further in the direction that helped, and
leaves the large size alone. That matches the cross-cycle rule that
safe levers touch only one size. A confirming result is hit-rate at
hm_0 and web_0 @ 16384 at or above 0008 v002, with the 131072 cells
unchanged. A refuting result is the small cells falling back, which
would mean 4-bit saturation or stale history caps the benefit near
factor 10.
