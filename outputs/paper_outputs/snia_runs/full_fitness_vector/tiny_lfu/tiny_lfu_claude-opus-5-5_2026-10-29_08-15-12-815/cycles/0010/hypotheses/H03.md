# H03

Replacing the `HashMap<HashedKey<K>, u32>` index with a custom linear-probing table of packed `u64` (hash tag | node index) slots will lower get p50/p99 per-op-time, with hit-rate unchanged.

## Parent

cycle/0008/v002

## Changes

All changes are in `src/tiny_lfu/mod.rs`. The admission and eviction
policy is untouched, so hit-rate must be bit-identical to the parent.

1. **New `IndexTable` struct** that replaces the `map` field:
   - `slots: Vec<u64>`, length `(capacity * 2).next_power_of_two()`
     (minimum 8), and `mask: u32 = len - 1`. Each slot is either
     `EMPTY = u64::MAX` or `((h as u32) as u64) << 32 | idx as u64`.
     The high half is the low 32 bits of the key hash, which is the
     tag. The low half is the node index (always `< NIL`).
   - The home slot is `(h as u32) & mask`. It is computed from the
     stored tag, which backward-shift deletion needs. The sketch block
     index uses `h >> 32` and the row positions use the low bytes, so
     sharing the low bits with the map is fine. If the implementer
     prefers, use `(h as u32).rotate_right(16) & mask` for the home
     slot, but apply the same function everywhere.
   - `#[inline(always)] fn find(&self, h: u64, nodes: &[Node<K,V>], key: &K) -> Option<u32>`:
     linear-probe from the home slot. Stop at `EMPTY` and return
     `None`. On a tag match (`slot >> 32 == h as u32`), compare
     `nodes[idx].key == *key` through unchecked indexing. Return
     `Some(idx)` on equality and keep probing otherwise. Use
     `get_unchecked` with the mask, so there are no bounds checks.
   - `fn insert(&mut self, h: u64, idx: u32)`: probe to the first
     `EMPTY` and store there. Callers guarantee the key is absent, as
     the parent already ensures before every insert.
   - `fn remove(&mut self, h: u64, idx: u32)`: probe for the slot whose
     low half equals `idx` and whose tag matches. Because indices are
     unique, no key compare is needed. Then do standard backward-shift
     deletion. Starting at the next slot, move each entry back into the
     hole while the hole lies cyclically within
     `[home(entry), current)`, and stop at `EMPTY`. Write `EMPTY` into
     the final hole. Do not use tombstones.
   - `fn len(&self) -> usize`, kept as a counter, for the unit tests.
2. **Call sites:**
   - `get`: `let found = self.index.find(h, &self.nodes, key);`. This
     removes the `key.clone()` and the `HashedKey` probe construction.
     Everything else stays the same.
   - `put`: the update-path lookup becomes `self.index.find(key_h, &self.nodes, &key)`.
     The fill path calls `self.index.insert(key_h, idx)` after the
     push. On the eviction path, call `self.index.remove(old_h, slot)`
     before swapping in the new key, then `self.index.insert(key_h, slot)`.
     The old key no longer needs to be built into a `HashedKey`, but
     `std::mem::replace` (or a plain assignment) of the node key stays.
   - Delete `HashedKey`, `PrehashedHasher` and `PrehashedBuildHasher`
     if nothing else uses them. Keep `FastHasher`/`key_hash` unchanged,
     because sketch indices must not change.
3. **Invariants:** load factor ≤ 0.5, which `try_new` guarantees by
   construction since the node count never exceeds `capacity`. `idx`
   always fits in 30 bits. `try_new`'s capacity guard stays. Keep the
   24-byte `Node` and all existing `#[inline(always)]` attributes.
4. **Tests (in-file):** in `check_lists`, replace `cache.map.len()` with
   `cache.index.len()`. Add a test that inserts colliding hashes (the
   same low 32 bits, different keys), removes the one in the middle of
   the cluster, and asserts the other two are still found. Add a
   randomized insert/remove test against a `std::collections::HashMap`
   oracle. `mixed_ops_keep_lists_consistent` must still pass. Do not
   touch `tiny_lfu_jni.rs`. Check that it only uses the public
   `new`/`try_new`/`get`/`put`/`sketch_heap_bytes` API.

## Rationale (optional)

The cross-cycle insights rule out list links and pointer chasing as
the source of get p99. They name the map probe and the inlined sketch
update as the remaining suspects. Today each `get` clones the key into
a `HashedKey`. It then runs a hashbrown SIMD group probe over 24-byte
buckets that duplicate the key and the hash already in `Node`. The
packed table touches one 8-byte slot (load ≤ 0.5, so probes are
nearly always 1–2 slots in one cache line), then the node line it
needs anyway to return the value. Map growth and rehash never happen.
A confirming result is lower get p50/p99 in interleaved A/B runs
against cycle 0008 v002, with all hit-rate cells identical. If latency
does not move, the map probe is ruled out and the sketch update is
the last suspect.
