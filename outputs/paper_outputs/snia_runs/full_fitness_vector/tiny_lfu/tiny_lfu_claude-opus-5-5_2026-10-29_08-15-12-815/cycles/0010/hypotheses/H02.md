# H02

Picking the main-region victim as the colder of the first two probation entries, not just the LRU head, will raise large-size hit-rate by keeping warm probation items that happen to sit at the head.

## Parent

cycle/0008/v002

## Changes

Only `TinyLfuCache::evict_one` in `src/tiny_lfu/mod.rs` changes, plus
unit tests. `get`, `on_hit`, the sketch, `admit()` and the window/SLRU
sizing stay exactly as they are in the parent.

New victim selection:

1. As today, `cand = lists[WINDOW].head`. If probation is non-empty,
   `a = lists[PROBATION].head`. Otherwise fall back to the protected
   head with the existing single-victim logic, unchanged.
2. If `lists[PROBATION].len >= 2`, set `b = self.node(a).next` (it is
   not `NIL` when len ≥ 2). Compute `a_h`, `b_h` with `key_hash` and
   `a_freq`, `b_freq` with `estimate_hashed`. The victim is `b` only
   when `b_freq < a_freq` (strictly). Otherwise it is `a`. So ties keep
   LRU order and evict the older entry. When probation has exactly one
   entry, the victim is `a`, as today.
3. Run the existing contest `admit(cand_freq, victim_freq)` against the
   chosen victim. If the candidate wins, `unlink(victim)` (the general
   `unlink` already handles a mid-list node, because `b`'s `prev` is `a`),
   `unlink(cand)`, `push_back(cand, PROBATION)`, and return
   `(victim, victim_h)`. If the candidate loses, behaviour is the same
   as today: `unlink(cand)` and return `(cand, cand_h)`. The probation
   order is not touched.
4. Keep the existing early-return branches for `cand == NIL` and
   `victim == NIL`.

This adds at most one extra `key_hash` and one `estimate_hashed`, and
only on the full-cache miss→put path. The `get` hot path does not
change.

Unit tests: keep every existing test passing. If a tiny-capacity test
changes outcome because it now has two probation entries, recompute
its expected result by hand rather than deleting it. Add
`evict_prefers_colder_of_two_probation_heads`. Build a cache (e.g.
capacity 8) where the probation head has a higher estimate than its
successor, insert a candidate that beats the successor, and assert
that the successor is evicted and the head stays resident. Run
`check_lists` after the eviction to verify the list links.

## Rationale (optional)

Probation is pure LRU, so its head is the oldest entry, not the
coldest. At 131072 the probation segment is large, with mid-range
frequencies close together (the cycle 0004 diagnosis). The head is
often an item that was re-referenced in the sketch's view, but its
hits came while it was still in the window and never promoted it.
Looking at two candidates is a bounded, sampled-eviction refinement.
It acts on the victim side of the contest, not the candidate side, so
it does not overlap with the candidate bonuses that cycle 0009 showed
fail to stack. A confirming result is a large-size gain (web_0 @
131072 especially) with the small size flat. A refuting result is a
loss from evicting fresh-but-cold probation entries too early.
