# H01

Remembering the last confirmed-absent key per bucket, so a put right after a get miss skips its second tag scan, will lower put p50 per-op-time and leave hit-rate bit-identical.

## Parent

cycle/0007/v003

## Changes

All edits go in `src/associative_cache/associative_cache_bucket.rs`. Only the ClassicLRU (`lip`) path changes.

Background: on the miss path, `get` already runs `tag_of(key)` plus a full `get_position_tagged` scan, which finds nothing. The next `put(item)` on the same key repeats both from scratch: `tag_of` again, then the tag scan again over all `n` tags. Insights say the only reliable speed wins removed whole units of work. This change removes one full scan from each put-after-miss.

1. **Bijective-hash detection.** Extend `TagHasher` with a `writes: u8` counter and a `bytes_used: bool` flag. The integer `write_*` methods increment `writes`, and `write(&[u8])` sets `bytes_used = true`. Add `fn tag_hash<K: Hash>(key) -> (u64 /*h*/, bool /*exact*/)` where `exact = writes == 1 && !bytes_used`. For one integer write, `h = x * TAG_MUL` with an odd `TAG_MUL` is a bijection on u64, so `h` identifies the key exactly. `tag_of` becomes `(tag_hash(key).0 >> 56) as u8`. Tags do not change.
2. **Memo fields.** Add `miss_hash: AtomicU64` and `miss_valid: AtomicBool`. Use atomics with `Relaxed` plain `load`/`store` only: no RMW and no LOCK prefix. This keeps the bucket `Sync`, and `get_position(&self)` can still write them. `miss_valid` fits in the existing padding. `miss_hash` grows the bucket stride from 80 to 88 bytes. Update `bucket_size_matches_parent` to assert 88, and note in its comment that stride is a deliberate change here.
3. **Set on miss.** In the lip branch of `get_position`, compute `(h, exact)` once. If `get_position_tagged` returns `None` and `exact`, store `miss_hash = h` and `miss_valid = true`.
4. **Use in put.** In the lip branch of `put`, compute `(h, exact)` once and take `t = (h >> 56) as u8`. If `exact && miss_valid && miss_hash == h`, skip `get_position_tagged` and go straight to the miss/insert code. Otherwise run the lookup as today.
5. **Invalidate.** Set `miss_valid = false` at the start of every mutating path: `put` (both hit and miss, before returning), `evict_item`, `remove_at`, `get_items_mut`, and the fused path. A get hit does not set the memo. A get on a different key that misses overwrites it. This keeps the invariant "if `miss_valid`, the key with hash `miss_hash` is absent".
6. Do not change BIP counting, insertion depth, the fused rotation, or the non-lip paths.

Tests (overlay unit tests):
- Extend `fused_matches_reference_remove_insert` so that each miss does `get` then `put`, which exercises the memo. Order and evictions must still match `RefBucket` exactly.
- Add `memo_never_duplicates`: get-miss key A, put key B, put key A. The bucket must contain A exactly once. Also check that `get_items_mut` clears the memo.

## Rationale (optional)

The cycle 8 insight says the tag scan itself is no longer worth widening. Skipping a scan entirely is a different lever, the same kind that won in 0005 (fewer compares) and 0006 (one fewer memmove). The stride increase is the open question from 0006 ("does stride hide a cost?"), now measured against a clear work saving. If put p50 does not fall, stride cost and memo savings cancel, which isolates the stride question. Judge only with repeated same-session runs against cycle/0007/v003.
