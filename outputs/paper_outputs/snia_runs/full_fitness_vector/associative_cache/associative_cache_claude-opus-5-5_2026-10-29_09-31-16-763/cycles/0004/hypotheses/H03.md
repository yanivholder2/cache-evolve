# H03

Narrowing the non-key/value bookkeeping fields of `Item` so that `Item<u64,u64>` packs into 24–32 bytes instead of 40 will reduce metadata-size, and get/put p50 should fall too because more items fit per cache line during the bucket scan.

## Parent

cycle/0003/v001

## Changes

Edit `src/shared/item.rs`. Also edit any non-gated overlay file that reads or writes the narrowed fields, such as `src/shared/eviction_policy.rs` and `src/associative_cache/associative_cache_bucket.rs`. Do not edit `tests/`, `src/test_utils/`, `src/bin/`, `src/lib.rs`, `src/factory.rs`, or the JNI file.

1. Read `Item<K, V>`. Beyond `key: K` and `value: V` (16 bytes for u64/u64), it carries 24 bytes of bookkeeping, for example `lfu_counter` and any timestamp or insertion counter. Narrow each of these fields to the smallest width its users need:
   - Make `lfu_counter` a `u16` or `u32`. Every place that increments it must use `saturating_add`, and comparisons must still work.
   - Make any recency or timestamp counter a `u32`, using wrapping arithmetic where it is compared only relative to other items.
   - Order the fields largest-first (`key`, `value`, then the narrow fields), so `#[repr(Rust)]` padding brings `size_of::<Item<u64,u64>>()` to 24 bytes if the bookkeeping fits in 8 bytes, or 32 at most.
2. Keep every field name, the constructor signature (`Item::new(...)` arguments), the derives, and the `Display` impl the same. If a field's type is fixed by an external signature (check `tests/`, `src/test_utils/`, `src/bin/`, `factory.rs`, and the JNI file for literal uses), leave that field's width alone and narrow only the others.
3. Update the users of each narrowed field (eviction policies, buckets) to the new type with explicit `as` casts or saturating operations. Policy semantics must not change in any reachable case for the trace lengths used. A u32 recency counter wraps only after 4·10⁹ ops, so use wrapping comparisons if it is ordered.
4. Keep all of the parent's bucket logic (LIP quarter-depth, BIP period 32, reverse scan) as it is. ClassicLRU under the parent does not use `lfu_counter` for decisions, so the hit-rate cells should match cycle/0003/v001 exactly.

Invariants: the crate compiles with the gated tests unchanged, the hit rate is identical to the parent, and `size_of::<Item<u64,u64>>()` drops strictly below 40.

## Rationale (optional)

Metadata-size has been 40 for every variant in three cycles. No hypothesis has targeted it, yet it is a fitness dimension in its own right. Shrinking the 40-byte item also cuts the bytes touched by the linear `get_position` scan (cycle insights: get cost tracks the number of keys compared, and the scan strides over 40-byte items), and it cuts the bytes moved by the quarter-depth `Vec::insert` memmove on put. That gives a plausible secondary per-op-time gain without any policy change.
