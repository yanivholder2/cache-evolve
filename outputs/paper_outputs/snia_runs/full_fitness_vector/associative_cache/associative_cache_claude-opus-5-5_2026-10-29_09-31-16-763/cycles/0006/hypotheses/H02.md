# H02

Replacing v002's full-bucket `evict_item` + quarter-depth `Vec::insert` with one fused partial rotation of only the first quarter of `items` and `tags` will lower put p50 and p99 with hit rate unchanged.

## Parent

cycle/0005/v002

## Changes

In `src/associative_cache/associative_cache_bucket.rs` (v002), rewrite
the miss path of the `self.lip` branch of `put` for the case
`self.is_full()` and a non-BIP admission:

- Today that path calls `evict_item()`, which runs
  `eviction_policy.eviction_candidate_index` through a dynamic call, then
  `items.remove(idx)` (a memmove of the whole bucket) and
  `tags.remove(idx)`. It then runs `items.insert(len/4, item)` and
  `tags.insert(len/4, t)`, which memmoves about 3/4 of the bucket again.
- Replace that with a fused rotation. The ClassicLRU victim is always
  index 0. Assert this once at construction by caching a
  `victim_is_front: bool` next to `lip`, so there is no dynamic call per
  miss. Let `p = (max_size - 1) / INSERT_DEPTH_DIVISOR`, which is the index
  the parent's insert would use after the removal. Then:
  1. Take `evicted = items[0]` (by copy, since `Item: Copy`-able through
     `K, V: Copy`, or by `ptr::read`).
  2. `ptr::copy(items.as_ptr().add(1), items.as_mut_ptr(), p)`, which
     shifts `items[1..=p]` down by one.
  3. Write the new item at `items[p]`.
  4. Do the same for `tags` (`tags.copy_within(1..=p, 0); tags[p] = t;`).
  `len` stays unchanged, so no reallocation and no tail memmove. Use
  `unsafe` only around the `ptr::copy`/`ptr::write` with a `SAFETY:`
  comment, or use `items[..=p].rotate_left(1)` and then overwrite `[p]`
  if that is measurably no worse.
- The BIP branch (every 32nd miss) that fills a full bucket keeps the
  parent's behaviour (evict front, push at back). It can be fused the same
  way with `p = len - 1`, i.e. `rotate_left(1)` over the whole slice plus
  an overwrite.
- The non-full path (bucket still filling) keeps the parent's
  `insert(len/4)`.
- Return the evicted item exactly as `evict_item` did. Keep the `debug!`
  out of the hot path, or behind `log_enabled!`.

Invariants: the resulting `items` order must be identical to the
parent's remove-then-insert sequence for every operation, so all four
hit-rate cells match exactly. `tags` stays in lockstep. Add a unit test
that runs the fused bucket and a reference remove+insert bucket in
lockstep on a random trace and asserts identical key order.

## Rationale (optional)

Cross-cycle insights name the quarter-depth memmove as the main put cost.
The fused rotation (cycle 0004 v001) was never measured cleanly, because
the atomic-clock regression hid its effect. Measured on its own against
v002 in the same session, it isolates the memmove saving: about 1/4 of
the bucket is moved instead of about 1.75×.
