# H03

Giving ClassicLRU/LIP a bounded second chance at eviction time, using a per-item reuse bit stored in `lfu_counter` (set on hit, cleared when spared), will raise hm_0 hit rate without losing web_0 scan resistance.

## Parent

cycle/0005/v002

## Changes

All edits are in `src/associative_cache/associative_cache_bucket.rs`
(v002), on the `self.lip` path only:

1. **Grow (hit):** in `get_from_position`, after the policy has promoted
   the item to the back, do a single store
   `self.items[index].lfu_counter = 1`. This covers hits from `get` and
   value-updates from `put`. New items keep `lfu_counter == 0` from
   `Item::new`. Do not change the ClassicLRU policy code itself.
   Before relying on this, check that it does not read or write
   `lfu_counter`. If it does, make the bucket the only writer on the lip
   path.
2. **Decay (eviction):** in the lip branch of `put`, when
   `self.is_full()`, replace the direct `evict_item()` call with a bounded
   loop of at most `SECOND_CHANCE_MAX = 2` iterations. While
   `items[0].lfu_counter != 0`:
   - clear it (`= 0`), and
   - rotate the item to quarter depth `q = (len - 1) / INSERT_DEPTH_DIVISOR`
     with `items[..=q].rotate_left(1)` and `tags[..=q].rotate_left(1)`.
     It goes to the probationary region, not MRU, so it must earn a hit
     again to survive.
   After the loop, evict index 0 as before (through `evict_item`, so tag
   mirroring is unchanged). If every checked item was spared, still evict
   whatever is now at index 0, so the work per miss is bounded.
3. Keep BIP period 32, quarter-depth admission, and the tag scan
   unchanged. Non-lip policies are untouched.

Invariants: `tags.len() == items.len()` and
`tags[i] == tag_of(items[i].key)` after every operation (extend
`tag_tests` with hits so spare-rotations are exercised). Metadata-size
stays at 24 because it reuses the existing `lfu_counter` field. Put does
at most 2 extra rotations of ≤ len/4 elements.

## Rationale (optional)

Earlier reuse signals all failed because they were external or blind:
BIP's period, a 16-key ghost ring, a hashed bit set, and hit position.
This is the remaining candidate the insights call for: an explicit
per-item probationary bit with symmetric grow (hit) and decay (spared
once at eviction). Scan keys are never hit, so their bit stays 0 and
they are still evicted first, which preserves web_0. hm_0 items that
were reused once but aged to the LRU end get one more round instead of
being lost to the next scan admission.
