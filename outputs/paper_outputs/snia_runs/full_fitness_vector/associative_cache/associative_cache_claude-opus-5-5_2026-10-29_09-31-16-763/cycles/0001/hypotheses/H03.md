# H03

Choosing the ClassicLRU victim as the lowest-frequency item among the 8 least-recent slots (using a saturating 2-bit hit counter with aging) instead of always the front item will raise hit rate on frequency-skewed MSR traces.

## Parent

baseline

## Changes

Touch `src/shared/eviction_policy.rs` (the `ClassicLRU` impl) and `src/associative_cache/associative_cache_bucket.rs`. Do not change other policies, `EvictionPolicyKind`, or `Item`.

1. `ClassicLRU::get_from_position`: before the existing `remove` and `push`, set `items[position].lfu_counter = (items[position].lfu_counter + 1).min(3)`. The move-to-back stays unchanged.
2. `ClassicLRU::eviction_candidate_index`: let `w = items.len().min(EVICT_WINDOW)` with `const EVICT_WINDOW: usize = 8`. Return the index in `0..w` with the minimum `lfu_counter`, breaking ties toward the lowest index (the least recent). Use an explicit loop with strict `<` so ties keep the earlier index. With w=1 this reduces exactly to baseline behaviour.
3. Leave `ClassicLRU::promotion_candidate_index` as `len - 1`.
4. Aging, in `AssociativeCacheBucket`: override `evict_item` in the `Bucket` impl. When `self.eviction_policy.name() == "ClassicLRU"`, do the following:
   - Compute `idx` via `eviction_candidate_index()`.
   - Decrement (saturating) the `lfu_counter` of every other item in the window `0..w`.
   - Return `remove_at(idx)`.

   For other policies, keep the default body. Decaying only the scanned window ages items as they drift toward the LRU end. This stops a once-hot item from pinning a slot forever, at O(8) cost.
5. New items keep `lfu_counter = 0` from `Item::new`, so a never-reused scan item is always preferred as a victim over any window item that has been hit since it entered the window.

Invariants to preserve:
- Exactly one eviction per put into a full bucket.
- The candidate index is always `< len`.
- The `ClassicLRU` name and ordinal are unchanged.
- Metadata-size is unchanged because the existing `lfu_counter` field is reused.

## Rationale (optional)

MSR hm_0 and web_0 mix a stable hot set with one-touch blocks. Pure LRU evicts a reused block that has drifted to the front even when a never-reused block sits right behind it. A small, frequency-aware victim window (in the spirit of LRU-K or sampled LFU on the LRU tail) keeps the reused block and evicts the one-touch block. This hypothesis changes which item is chosen as the victim, not where items are inserted (H01) or how hits move items (H02), so the three test independent levers.
