# H02

Replacing ClassicLRU's move-to-back on every hit with an in-place CLOCK scheme (a reference bit set on hit, a per-bucket hand that sweeps on eviction, and in-place slot replacement) will cut get and put per-op-time while keeping hit rate close to baseline.

## Parent

baseline

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`.

1. Add a field `hand: usize` to `AssociativeCacheBucket`, initialised to 0 in `new`.
2. Apply the CLOCK behaviour only when `self.eviction_policy.name() == "ClassicLRU"`. Cache the result once in `new` as a `clock: bool` field so the string compare does not run on every op. For all other policies, delegate to the current code paths unchanged.
3. Override `get_from_position(&mut self, position)` in the `Bucket` impl. When `clock` is true, set `self.items[position].lfu_counter = 1` (reuse the existing field as the reference bit, so `Item` size is unchanged), do not reorder `items`, and return `&self.items[position]`. Otherwise keep the existing dispatch to `self.eviction_policy.get_from_position`.
4. Override `put` in the `Bucket` impl. When `clock` is true:
   - Existing key: update the value, set its ref bit to 1, and return `(ref, None)`.
   - New key, bucket not full: `push` the item with `lfu_counter = 0` and return `(last, None)`.
   - New key, bucket full: loop over `self.items[self.hand]`. If its `lfu_counter != 0`, clear it to 0 and advance `hand = (hand + 1) % len`. Otherwise this slot is the victim: `std::mem::replace(&mut self.items[self.hand], item)`, take the old item as the evicted value, advance `hand`, and return `(&self.items[victim_idx], Some(old))`. The loop always ends within two passes.
5. Override `evict_item` and `eviction_candidate_index` the same way when `clock` is true, so external callers and the gate see a consistent CLOCK victim. `eviction_candidate_index` must be read-only: scan from `hand` for the first slot with `lfu_counter == 0`, and fall back to `hand` if every bit is set. `evict_item` should do the clearing sweep, call `remove_at(idx)`, and then fix up `hand` (if `idx < hand`, decrement it; clamp it to `len`, wrapping to 0).

Invariants to preserve:
- `len <= max_size`.
- Exactly one eviction per put into a full bucket.
- The returned reference is the inserted item.
- No change to `Item` layout or to `AssociativeCache`'s size. The extra per-bucket `usize` and `bool` are not in the metadata-size dimension.

## Rationale (optional)

With 128 buckets the bucket width is 128 or 1024 items. Every ClassicLRU hit does `Vec::remove` plus `push`, an O(width) memmove of 40-byte items, and every eviction does `remove(0)`, another full-width memmove. CLOCK removes both: hits become a single store and puts become an in-place swap. CLOCK is a well-known close approximation of LRU, so hit rate should land within about 1 point of baseline while get and put p50 fall.
