# H01

Inserting newly admitted items at a quarter-depth point instead of the MRU end of the bucket (hits still move to the back) will raise hit rate on the scan-heavy MSR web_0/hm_0 traces.

## Parent

baseline

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`.

In the `impl Bucket<K, V> for AssociativeCacheBucket<K, V>` block, override the trait's default `put` method. Keep the existing-key path exactly as the default does: if `get_position(&item.key)` finds the key, overwrite `.value`, call `self.get_from_position(position)`, and return `(that_ref, None)`.

For a new key, apply the new behaviour only when `self.eviction_policy.name() == "ClassicLRU"`. For every other policy, keep the default code path unchanged (evict if full, then `push`) so that Fifo/Lifo/Lfu/Swap/TimestampLRU semantics and their tests stay the same.

ClassicLRU new-key path:
1. If `is_full()`, call `self.evict_item()` as now. ClassicLRU evicts index 0, the LRU end.
2. Compute `insert_pos = self.items.len() / 4`, which is the item count after eviction. With an empty or nearly empty bucket this is 0, which is fine.
3. Use `self.items.insert(insert_pos, item)` instead of `push`.
4. Return `(&self.items[insert_pos], evicted)`.

As a result, a new item sits about 1/4 of the way from the eviction end. It has to be hit once to be promoted to the back. A one-hit scan item now survives about 25% of the bucket's turnover instead of 100%, so a scan can no longer flush the reused working set. Put the fraction in a `const INSERT_DEPTH_DIVISOR: usize = 4;` so later cycles can tune it.

Invariants to preserve:
- The bucket never exceeds `max_size`.
- At most one item is evicted per put.
- The returned reference points to the inserted item.
- No new fields are added to `Item`, so metadata-size is unchanged.
- `ClassicLRU::get_from_position` is unchanged: a hit still means remove plus push to the back.

## Rationale (optional)

The geometry is 128 buckets, so each bucket holds 128 items at size 16384 and 1024 items at size 131072. Each bucket therefore behaves almost like a full LRU, and LRU is known to be weak on MSR block traces because of sequential scans. LIP/BIP-style insertion is the cheapest form of scan resistance and needs no extra metadata. The per-op cost is unchanged: `insert` does a memmove just as `remove` does today.
