# H02

Upgrade v002's 1-bit CLOCK to a 2-bit generalized CLOCK (saturating hit counter, bounded 16-slot sweep that evicts the minimum-counter slot) to raise hit rate by protecting frequently reused keys.

## Parent

cycle/0001/v002

## Changes

All edits are in `src/associative_cache/associative_cache_bucket.rs` (v002 overlay). Only the
`self.clock == true` paths change; non-ClassicLRU paths stay byte-for-byte the same.

1. Hit recording. In `get_from_position` and in the existing-key branch of `put()`, replace
   `lfu_counter = 1` with a saturating increment capped at `GCLOCK_MAX = 3`
   (`if c < GCLOCK_MAX { c += 1 }`). New items still enter with `lfu_counter = 0` (keep v002's
   clear-on-insert, which earned its hit-rate gain).
2. Bounded sweep. Rewrite `clock_sweep()` so it looks at no more than `SWEEP_LIMIT = 16` slots
   starting at `hand` (wrap at `len`):
   - if a slot has `lfu_counter == 0`, return it right away;
   - otherwise decrement its counter by 1 (not clear to 0), remember the index of the smallest
     *post-decrement* counter seen so far (first one wins on ties), and advance;
   - if the limit is reached, return the remembered minimum index.
   Leave `hand` pointing at the returned index, as now. The callers in `put()` (in-place
   `mem::replace` plus `hand = victim+1`) and `evict_item()` (`remove_at` plus hand fixup) stay as
   they are.
3. Update `eviction_candidate_index()` to match without mutating anything: scan the same
   `min(SWEEP_LIMIT, len)` window from `hand` and return the first zero-counter index, or else the
   index of the smallest `lfu_counter.saturating_sub(1)`.

Do not change `Item` or `AssociativeCache` (reuse the `lfu_counter` field), so metadata-size stays
at 40.

## Rationale (optional)

v002 showed that a reference bit with clear-on-insert beats LRU slightly. The traces (MSR web_0,
hm_0) mix scans with a skewed hot set, and a 2-bit counter lets keys hit several times survive
several sweeps rather than one. The 16-slot cap fixes the unbounded two-pass sweep that hurt v002's
put p99. Unlike v003's tail window, this changes the code paths v002 already showed are active in
the harness (its hit rate moved), so the effect will be measurable.
