# H03

Add a dense parallel key array to v002's CLOCK bucket and override `get_position` to scan it, cutting get p50 (per-op-time) by touching 8-byte keys instead of 40-byte items during lookup.

## Parent

cycle/0001/v002

## Changes

All edits are in `src/associative_cache/associative_cache_bucket.rs` (v002 overlay). Keep the CLOCK
replacement policy exactly as in v002.

1. Add a field `keys: Vec<K>` to `AssociativeCacheBucket`, allocated in `new()` with
   `Vec::with_capacity(settings.bucket_size)`. Invariant: `keys.len() == items.len()` and
   `keys[i] == items[i].key` for every i, on every path (clock and non-clock).
2. Override `fn get_position(&self, key: &K) -> Option<usize>` in the `Bucket` impl as
   `self.keys.iter().position(|k| k == key)`. This is a tight loop over contiguous `u64` values,
   about 5x fewer cache lines than striding through `Item<u64,u64>`, and the compiler can
   auto-vectorize it.
3. Keep `keys` in sync at every point that changes `items`:
   - every `self.items.push(item)` → also `self.keys.push(item.key)` (take the key before the move);
   - the CLOCK in-place replacement in `put()` (`mem::replace(&mut self.items[victim_idx], item)`)
     → also `self.keys[victim_idx] = new_key`;
   - `evict_item()`: both the clock and non-clock branches call `remove_at(idx)`, so also run
     `self.keys.remove(idx)`. If `remove_at` is a trait default, override it in this impl so it
     removes from both vectors, and route every removal through it;
   - non-clock paths that reorder through `eviction_policy.get_from_position(&mut self.items, ..)`
     (move-to-back): after the call, if the returned index differs from `position`, do the same
     rotation on `keys` (`self.keys[position..=index].rotate_left(1)` for move-to-back), or rebuild
     `keys` from `items` on that path. Correctness matters more than speed here, because the
     benchmarked policy is ClassicLRU, which takes the clock path that never reorders.
   - If `get_items_mut()` is used by external callers to change the items, add a debug assert, or
     rebuild `keys` lazily, so the invariant cannot silently break.
4. Do not change `Item` or `AssociativeCache`. The extra Vec lives only inside the bucket, so the
   measured metadata-size types stay at 40 and 24 bytes.

## Rationale (optional)

Cycle 0001 showed that get p50 (the per-op-time summary) did not move even when the hit path
became a single store. The cost is the linear `get_position` scan over 128- and 1024-wide buckets
of 40-byte items. v002 is the right parent because CLOCK never reorders on a hit, so keeping the
key mirror in sync costs one store per insert or replacement, with no extra memmoves.
