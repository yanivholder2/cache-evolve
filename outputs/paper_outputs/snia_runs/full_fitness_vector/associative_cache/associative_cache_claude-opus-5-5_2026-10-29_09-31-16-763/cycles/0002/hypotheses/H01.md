# H01

Switch v001's fixed quarter-depth ClassicLRU insertion to bimodal insertion (quarter-depth normally, MRU end on every 32nd miss per bucket) to raise hit rate, mainly at the 128-wide bucket size where pure LIP gained little.

## Parent

cycle/0001/v001

## Changes

All edits are in `src/associative_cache/associative_cache_bucket.rs` (v001 overlay).

1. Decide the policy once. Add a `lip: bool` field to `AssociativeCacheBucket`, set in `new()` from
   `eviction_policy.name() == "ClassicLRU"` (build the policy into a local first, as v002 did).
   Replace the per-put `self.eviction_policy.name() == "ClassicLRU"` string comparison in `put()`
   with `if self.lip`.
2. Bimodal insertion (BIP). Add a `bip_tick: u32` field (start at 0) and a constant
   `BIP_MRU_PERIOD: u32 = 32`. In the new-key branch of `put()` when `self.lip` is true, after the
   optional `evict_item()`:
   - `self.bip_tick = self.bip_tick.wrapping_add(1);`
   - if `self.bip_tick % BIP_MRU_PERIOD == 0`, `push` the item at the back (MRU), the same as
     baseline, and return `self.items.last()`;
   - otherwise keep v001's `insert(self.items.len() / INSERT_DEPTH_DIVISOR, item)` with
     `INSERT_DEPTH_DIVISOR = 4`.
3. Leave the existing-key update path, `get_from_position`, `evict_item` and every non-ClassicLRU
   path exactly as in v001. Return `(&Item, Option<evicted>)` with the same semantics.

Do not change `Item` or `AssociativeCache`, so metadata-size stays at 40. The MRU pushes also
reduce the average memmove length on put a little.

## Rationale (optional)

Pure LIP can lock a stale working set at the MRU end, and on 128-wide buckets the new item has
only about 32 slots of turnover to earn a hit. BIP's occasional MRU insert lets a working set that
is changing move into the protected region (Qureshi et al., ISCA 2007). Dropping the string
compare removes the policy-unrelated put overhead noted in cycle 0001.
