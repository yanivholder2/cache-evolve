# H01

Replace the ClassicLRU hit path's dynamic `get_from_position` call and paired `Vec::remove`+`push` memmoves with one in-place `rotate_left(1)` on `items[position..]` and `tags[position..]`, to lower get p50 (per-op-time).

## Parent

cycle/0006/v002

## Changes

All edits are in `src/associative_cache/associative_cache_bucket.rs`, in `Bucket::get_from_position` for `AssociativeCacheBucket`.

- When `self.lip` is true, do not call `self.eviction_policy.get_from_position(...)` (a `Box<dyn>` virtual call on every hit). Do the move-to-back inline instead:
  - Let `n = self.items.len()`.
  - If `position + 1 < n`, run `self.items[position..].rotate_left(1)` and `self.tags[position..].rotate_left(1)`.
  - If `position == n - 1` (already MRU), skip all data movement. The parent always paid a remove+push here, even for an item already at the back.
  - Return `&self.items[n - 1]`.
- This replaces the parent's `tags.remove(position)` + `tags.push(t)` pair and the policy's own `items.remove(position)` + `items.push(..)`. Each of those does a shift, a length update and a capacity check. The new code does one bounded shift of the same suffix and leaves `len` unchanged.
- Semantics must match ClassicLRU's `get_from_position` exactly. Before writing the inline version, read the ClassicLRU policy implementation under `src/shared/` (the `EvictionPolicy` impl for ClassicLRU). If it writes any `Item` field on a hit (for example `timestamp` or `lfu_counter`), make the same store on `items[n-1]` after the rotation, so this variant changes only the movement mechanism.
- Leave the non-lip branch unchanged: it still calls the dynamic policy.
- Check once at construction that this is valid. Add a field-free check in `new` (or reuse `victim_is_front`, which is already true only for ClassicLRU) and take the inline path only when `self.lip && self.victim_is_front`. Do not add a new struct field: bucket stride is a suspected hidden cost (cycle 0006 v001).
- Keep `debug_check_tags()` and the `fused_matches_reference_remove_insert` / `tags_stay_in_lockstep` tests. The reference model's `get` is remove+push, so the lockstep test checks that order is preserved. Add one test case where the hit key is already at the MRU end.
- Do not touch `put`, the fused eviction rotation or `get_position_tagged`.

## Rationale (optional)

Cycle 0006 left get p50 flat at 48 ns. The hit path is now the main get cost that the tag filter does not cover. Under LIP, hits land throughout the bucket, so the suffix shift itself can't be avoided. What can be removed is the virtual call, a second length/capacity bookkeeping step and the no-op move for MRU hits. Hit rate should match all four cells exactly.
