# H03

Making the LIP insertion depth adaptive per bucket, so that it grows when hits land on still-probationary items (recently admitted, below the insertion point) and slowly decays on misses, will raise hit-rate on hm_0 without giving up web_0 scan resistance, beating the fixed quarter depth.

## Parent

cycle/0003/v001

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`. Do not touch the gate-integrity surface.

1. Add per-bucket, non-atomic fields: `depth: u32`, initialised to `max_size / INSERT_DEPTH_DIVISOR` (the parent's quarter depth); `miss_ctr: u32 = 0`; plus constants `DEPTH_MIN = max_size / 16` (at least 1), `DEPTH_MAX = max_size / 2`, and `DECAY_PERIOD: u32 = 8`.
2. **Hit signal** (lip path only), in the bucket's `get_from_position(position)`: before calling the policy, if `self.lip && position < self.depth as usize`, do `self.depth = min(self.depth + 1, DEPTH_MAX)`. A hit below the insertion point means an item admitted recently was reused before it was promoted, so the bucket is under-admitting (hm_0's slowly shifting working set). This adds one compare and one add to the hit path and no extra memory traffic.
3. **Decay signal**, in `put` on the new-key path when the bucket is full (an eviction is happening): `self.miss_ctr = self.miss_ctr.wrapping_add(1); if self.miss_ctr % DECAY_PERIOD == 0 { self.depth = max(self.depth - 1, DEPTH_MIN) }`. Streams of one-touch scan keys give no probationary hits, so depth drifts down and new items are evicted sooner (web_0).
4. **Use the depth**: replace `let insert_pos = self.items.len() / INSERT_DEPTH_DIVISOR;` with `let insert_pos = min(self.depth as usize, self.items.len());`. Before the bucket is full, keep the parent's `len / INSERT_DEPTH_DIVISOR` so warm-up behaviour is unchanged.
5. Keep the BIP MRU admission (period 32, `bip_tick` timing), the reverse `rposition` scan, the 40-byte `Item`, and all non-LIP policy paths exactly as in the parent.

Invariants: `DEPTH_MIN <= depth <= DEPTH_MAX` at all times. `items.len() <= max_size`. Non-LIP policies are byte-for-byte unchanged. The gated tests compile and pass. Report the four hit-rate cells against the parent's (0.4138 / 0.558 / 0.4558 / 0.7347). The claim is confirmed if the hm_0 cells rise and the web_0 cells drop by less than that gain, giving a higher hit-rate summary.

## Rationale (optional)

Cross-cycle insights record three failed attempts to replace BIP's blind period with a reuse filter (16-entry ghost ring, hashed bit set). Each was too short, saturated, or cost hashing on the miss path. They also leave open whether insertion depth should scale with workload. This variant gets an adaptive signal for free, from where hits land in the bucket's own LRU order, without ghost state, hashing or atomics. It is a set-local analogue of ARC/DIP adaptation. The per-op cost is one compare on hits and a counter on evictions, which keeps the put-path additions within what the insights allow (per-bucket, non-atomic). Branching from cycle/0003/v001 (40-byte item, no atomic tick) keeps per-op-time comparable to the 55 ns incumbent and isolates the policy change.
