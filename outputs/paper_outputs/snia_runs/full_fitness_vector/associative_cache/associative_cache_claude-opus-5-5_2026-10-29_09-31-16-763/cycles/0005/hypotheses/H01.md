# H01

Replacing v003's process-wide `AtomicU32::fetch_add` logical clock in `Item::new` with a plain non-atomic per-bucket counter (or no write at all when no policy reads `timestamp`) will lower get and put p50/p99 (per-op-time) while keeping the 24-byte `Item` and every hit-rate cell exactly unchanged.

## Parent

cycle/0004/v003

## Changes

Files: `src/shared/item.rs`, `src/associative_cache/associative_cache_bucket.rs`, plus any non-gated eviction-policy file that calls `item::tick()` or `item::now()`. Do not touch the gate-integrity surface (JNI file, `factory.rs`, `Cargo.toml`, `lib.rs`, `tests/`, `src/test_utils/`, `src/bin/`).

1. Audit first. Search the overlay and the baseline crate for every reader of `Item::timestamp` and every caller of `item::tick()` / `item::now()`. In cycle 0004 these were added as a stand-in for `Instant::now()`, so policies that once used `Instant` age (for example, a timestamp-based LRU or FIFO, if one exists) now call them.
2. In `src/shared/item.rs`, delete `static LOGICAL_CLOCK`, `tick()` and `now()`. `Item::new(key, value)` keeps its signature and sets `timestamp: 0` and `lfu_counter: 0`. Keep the field order `key, value, lfu_counter: u32, timestamp: u32` so `size_of::<Item<u64,u64>>() == 24` still holds. Keep the existing unit test `item_u64_u64_is_24_bytes`.
3. If step 1 found any policy that reads `timestamp`, add a field `clock: u32` to `AssociativeCacheBucket`, initialised to 0. In `put`, on the new-key path, right before the item is inserted (all branches: quarter-depth insert, BIP MRU push, and the non-LIP push), do `self.clock = self.clock.wrapping_add(1); item.timestamp = self.clock;` (make `item` `mut`). Every policy call site that used `item::now()` for age (`now().wrapping_sub(ts)`) or that refreshed `timestamp` with `tick()` on hit must receive the bucket's clock instead. Do this by having the bucket stamp `items[index].timestamp` after `get_from_position` returns, rather than by changing the `EvictionPolicy` trait signature, if the trait is gated or used by tests. Timestamps are only compared within one bucket, so a per-bucket clock keeps the relative order of every comparison the policies make. If no policy reads `timestamp`, skip this step entirely, so neither path writes anything extra.
4. Change nothing else: LIP quarter-depth insertion (`INSERT_DEPTH_DIVISOR = 4`), BIP period 32 and `bip_tick` handling, the reverse `rposition` scan, and the two-step evict-then-insert must stay exactly as in the parent.

Invariants: the crate compiles against the gated tests unchanged. `Item<u64,u64>` stays 24 bytes. The four hit-rate cells match the parent exactly (0.4138 / 0.558 / 0.4558 / 0.7347). Nothing atomic or shared across buckets is touched on any get or put.

## Rationale (optional)

The cycle 0004 insight for v003 put its per-op regression (get 70 / put 131 ns p50, against 55 / ~123 for cycle/0003/v001) down to the locked RMW on one shared cache line per put. The cycle-level insight also pointed to environment drift. This variant isolates the one variable: if per-op-time returns to or below cycle/0003/v001's level, the denser 24-byte layout pays off and the atomic was the cost. If it stays at ~70, the cycle 0004 regression was environmental, which re-anchors all later speed comparisons.
