# H03

Replacing the byte-at-a-time fingerprint scan in `get_position_tagged` with a SWAR scan that compares 8 tags per `u64` load will lower get and put-miss per-op-time, with hit-rate and metadata-size unchanged.

## Parent

cycle/0007/v003

## Changes

Rewrite the inner loop of `get_position_tagged`, the dense 1-byte `tags` pre-filter scan used by both get and put lookup, as a word-at-a-time scan:

1. Broadcast the probe tag: `let pat = (tag as u64) * 0x0101_0101_0101_0101;`.
2. Walk `tags[0..n]` in 8-byte chunks. Load each chunk with `u64::from_le_bytes` over `chunks_exact(8)`, or with `ptr::read_unaligned`.
3. Compute `x = word ^ pat` and the exact zero-byte mask `const L: u64 = 0x7f7f_7f7f_7f7f_7f7f; let y = (x & L).wrapping_add(L); let m = !(y | x | L);`. This sets bit 7 of a byte exactly when that byte of `x` is zero. It is the carry-free variant, so it gives no false byte flags.
4. While `m != 0`, take `i = chunk_base + (m.trailing_zeros() / 8)`. Run the full key compare against `items[i]`. Return `Some(i)` on a match, otherwise clear the lowest set byte with `m &= m - 1` and continue.
5. Handle the remaining `n % 8` tail bytes with the existing scalar loop.

Keep the search order identical to the current one. The scan currently runs from index 0 upward, so take matches in ascending index order. That way, any tie-breaking on duplicate tags and the returned position stay exactly the same as the parent's, and hit-rate cells stay bit-identical.

Leave the tag computation itself, and how `tags` is kept in step on insert, evict and hit-move, unchanged. No new fields, so stride stays at 80 bytes.

Add an overlay unit test that fills a bucket with forced tag collisions and checks that the SWAR scan and the scalar reference return the same position for every key, including absent keys. Use sizes that are not multiples of 8, for example 13 and 300.

## Rationale

The cross-cycle insights say miss-path wins come from cutting full-key compares and scan cost. Widening the tag scan is an open question, and so far it has only been done one byte at a time. On 1024-wide buckets, a get miss currently does up to 1024 byte compares. SWAR cuts that to about 128 word operations without adding SIMD intrinsics or memory.
