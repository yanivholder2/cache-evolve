# H01

Replacing the ClassicLRU (lip) hit-path `remove(position)` + `push` with an inline, devirtualised, hand-written `ptr::read`/`ptr::copy`/`ptr::write` one-slot shift (and the same for `tags`) will lower get p50 per-op-time while leaving hit-rate and metadata-size bit-identical.

## Parent

cycle/0007/v003

## Changes

In the lip branch of `get_from_position` (the branch reached after `get_position_tagged` returns a hit `position` while the `lip && victim_is_front` flags are set), drop the dispatch through the policy object's generic remove+push. Inline the MRU move instead:

1. Let `n = items.len()`. If `position == n - 1` (the hit is already at the MRU end), return the value immediately and do no move. This is the MRU-skip.
2. Otherwise, inside one `unsafe` block, using raw pointers from `items.as_mut_ptr()`:
   - `let hit = ptr::read(p.add(position));`
   - `ptr::copy(p.add(position + 1), p.add(position), n - 1 - position);`
   - `ptr::write(p.add(n - 1), hit);`
3. Do the same for the `tags` byte array: save `tags[position]`, run `tags.copy_within(position + 1..n, position)`, then write the saved tag at `n - 1`. Or use the equivalent `ptr::copy` on `u8`.

Do **not** use `slice::rotate_left`. Cycle 7 v001 showed it falls into a slow scalar loop on short suffixes.

Apply the same hand-written shift to the update-on-hit branch of `put`, the branch where the key already exists. That branch overwrites the value and then moves the item to MRU.

Invariants:
- `len` is never changed and no `Vec` reallocation happens, so the raw-pointer writes stay in bounds.
- Do not write any `Item` field on a hit. This keeps eviction order identical to the reference.
- No new struct fields. Bucket stride stays at 80 bytes and `Item` at 24 bytes.
- Non-lip policies (CLOCK and the others) keep their current path.
- Keep the existing lockstep or reference-order tests passing. Add a unit test in the overlay that checks the post-hit order of `items` and `tags` against `remove` + `push` for positions 0, mid and n-1.

## Rationale

This closes the top open question from the cycle 6 and 7 insights. On put, the fused hand-written rotation won where generic helpers lost. v001's `rotate_left` showed that the move primitive matters, not the devirtualisation by itself.
