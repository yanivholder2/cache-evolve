# H02

Using a width-keyed BIP MRU-admission period of 1/64 on wide buckets (keeping 1/32 on narrow ones) will raise the summary hit-rate above both the fixed-1/32 incumbent and the 1/128 variant, by keeping most of web_0's wide-bucket gain while giving back less of hm_0's.

## Parent

cycle/0007/v003

## Changes

Port cycle/0007/v002's width-keyed BIP selection onto v003's clock-free base, with a different period on wide buckets:

- Add a constant `BIP_WIDE_BUCKET = 256`, the same threshold v002 used.
- Where the put-miss path decides whether a new item goes to MRU or to LIP quarter depth, replace `counter % BIP_MRU_PERIOD == 0` with `counter & bip_mask == 0`. Set `bip_mask = 31` when `max_size <= BIP_WIDE_BUCKET` and `bip_mask = 63` otherwise. In v003 the counter is the per-bucket `u32` field `clock`, which ClassicLRU now uses only as the BIP miss counter.
- Compute `bip_mask` from `max_size`, which is already loaded. Do not add a struct field. Bucket stride stays at 80 bytes and the `bucket_size_matches_parent` test must still pass.
- Keep the increment-then-test order of the counter exactly as in v003, so the narrow-bucket (16384) cells stay bit-identical to the parent.

Extend `fused_matches_reference_remove_insert`, or add an overlay unit test, to cover sizes 256, 300 and 1024. It should check that MRU admission fires every 32nd miss below the threshold and every 64th miss above it.

Expected result: both 16384 cells are unchanged. web_0@131072 falls between 0.5580 and 0.5610, and hm_0@131072 falls between 0.7339 and 0.7347, with a net summary above 0.541125. If the result lands at either end, the tradeoff curve is flat and we stop tuning this knob.

## Rationale

This is the single bounded probe that the cycle 7 insight and the cross-cycle insights allow on wide-bucket BIP. It also merges v002's policy split with v003's measured-fastest base, which is the merge the cycle 7 continuation recommends.
