# H03

Adding a self-organizing "swap halfway toward the front" step on CLOCK hits will move hot keys near index 0, shortening the forward key scan and lowering get p50 (the per-op-time summary).

## Parent

cycle/0001/v002

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`. In the parent (CLOCK), a hit only sets `lfu_counter = 1` and never reorders, so a hot key can stay deep in a 128- or 1024-wide bucket. The trait-default `get_position` then walks over it on every get.

1. In `get_from_position`, on the `self.clock` branch: set `self.items[position].lfu_counter = 1` as now. Then, if `position >= SWAP_MIN` (`const SWAP_MIN: usize = 4`), compute `target = position / 2` and call `self.items.swap(position, target)`. Return `&self.items[target]`. Otherwise return `&self.items[position]`. The reference bit travels with the item. The item it swaps with keeps its own bit.
2. Apply the same reordering on the `put` existing-key branch for CLOCK (value update plus bit set), and return the reference at its new index.
3. Leave the CLOCK hand (`hand`), `clock_sweep`, the in-place replacement on a miss, `evict_item` and `eviction_candidate_index` unchanged. A swap only exchanges two slots, so the set of reference bits is preserved and the sweep stays correct. A swapped item may be visited one extra time or skipped once by the hand, which is acceptable for an approximation.
4. Leave the non-CLOCK policies unchanged. Add no new fields or side arrays.

Invariants: keys stay unique within a bucket. The returned reference must point at the item that was hit, at its new index. `items.len()` does not change.

## Rationale (optional)

Insights from both cycles agree that get p50 is set by the linear lookup and not by hit-path bookkeeping, and that a separate key Vec hurt locality. This change keeps one allocation and makes the layout itself put popular keys first. Halving the position on each hit sends a key hit k times to depth about p/2^k, so the Zipf-like head of the MSR traces gathers in the first cache lines within a few hits. The cost is a single 40-byte swap per hit, not a memmove. The parent already has the best per-op-time (54), so this tests whether layout self-organization can push it lower without giving back its hit rate.
