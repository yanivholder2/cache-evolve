# H01

Requiring one extra stash hit (three instead of two) before a stash item may promote into a *full* target bucket, while keeping the two-hit threshold for non-full targets, will recover v001's lost large-cache hit-rate without adding any work to the common target/probing hit path.

## Parent

cycle/0002/v001

## Changes

Edit `src/dash/segments/dash_segment.rs` (v001's version), function `promotion_get`, stash-hit branch only.

1. Add a constant `FULL_TARGET_PROMOTE_THRESHOLD: usize = 3` next to `PROMOTE_THRESHOLD` (which stays 2).
2. After computing `count` and writing it back to the stash item, replace the single test `if count < PROMOTE_THRESHOLD` with:
   - if `count < PROMOTE_THRESHOLD` → touch in stash (`get_from_position`), same as now;
   - else if `count < FULL_TARGET_PROMOTE_THRESHOLD && core.buckets[target_idx].is_full()` → also touch in stash and return. The counter keeps its incremented value, so the next stash hit promotes;
   - otherwise → the existing `remove_at` + `lfu_counter = 0` + `promote_to_target` path, unchanged.
   Evaluate `is_full()` only once `count >= PROMOTE_THRESHOLD`, so one-hit stash touches stay as cheap as they are now.
3. Do not read the victim (`eviction_candidate_index()`) or any normal-tier counters. Normal-tier hits stay write-free and compare-free beyond what v001 already does. Leave `demote_from_normal_bucket` unchanged.

Tests: keep `two_stash_hits_promote_to_target`, since the target is not full there. Change `two_hit_stash_item_enters_full_target_demoting_lru` so that after two hits the key is still in stash and the target is unchanged. After a third get the key is in target and the LRU resident has been demoted to stash. Leave the other tests as they are. Do not touch the gate-integrity files.

## Rationale (optional)

v001 lost hit-rate only in the large-cache cells, mostly hm_0, because any 2-hit stash key could push out a reused target resident. Cycle 0002 left this open: can a write-free victim guard win those hits back? This guard looks only at occupancy, not the victim's counter. It runs only on stash hits that have reached the threshold, which are rare, so get p50 should stay near 80. The change also tests the put-p99 theory, because fewer promotions into full targets means fewer forced demotions into stash.
