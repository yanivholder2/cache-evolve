# H02

Narrowing `Item::lfu_counter` from a word-sized integer to a `u8` and reordering `Item`'s fields to remove padding will reduce the metadata-size of `Item<u64,u64>` below 40 bytes while leaving hit-rate and per-op-time unchanged.

## Parent

cycle/0002/v001

## Changes

This is the first change to Item layout. Every earlier variant left it alone, and metadata-size has been stuck at 40 bytes since baseline.

1. In `src/shared/item.rs`, change the type of `lfu_counter` to `u8`. Before doing so, list every non-key/value field of `Item` and its size. If another metadata field is also word-sized but holds small values (a flag, a small frequency, or a bucket-local index), narrow it to the smallest integer type that safely holds its range. Then order the fields from largest to smallest alignment, or add `#[repr(C)]` with an explicit order, so the struct has no internal padding. Keep `Item::new` and the public field names the same.
2. Fix every use of the field across the overlay-writable code, including the eviction policies (LFU etc. in `src/shared/`), the buckets and `src/dash/segments/dash_segment.rs`:
   - Increments must use `saturating_add(1)`, so a counter stops at 255 rather than wrapping.
   - Comparisons with `usize` constants must cast explicitly, e.g. `PROMOTE_THRESHOLD` becomes `const PROMOTE_THRESHOLD: u8 = 2`.
   - Halving with `>>= 1` works unchanged.
   - Any LFU-policy logic that compares counters keeps its ordering semantics. Saturation at 255 is acceptable.
3. Do not change any segment, bucket or promotion logic. Behaviour must be the same as v001 for every counter value below 255.
4. Gate-integrity check: `src/dash/jni.rs`, `tests/`, `src/test_utils/` and `src/bin/` cannot be edited. If any of them assigns or reads `lfu_counter` as `usize`, choose the narrowest type that still compiles there. Try `u8`, then `u16`, then `u32`, and add `From`/`as` conversions only on the writable side. If the field type can't change at all, still reorder the fields and narrow any other padded metadata field.

Update the in-file tests that set `it.lfu_counter = 5` or `= 6` only as far as the type change requires. Add a unit test asserting `std::mem::size_of::<Item<u64,u64>>() < 40`.

## Rationale (optional)

Metadata-size is a scored dimension that no variant has tried to move. Item is 40 bytes for a 16-byte key/value pair, so 24 bytes is metadata. A counter that v001 caps at about 2 does not need 8 bytes. Shrinking it gives a direct metadata win, and the smaller footprint may also make bucket scans slightly faster.
