# H02

Turning on v001's three-hit full-target guard only in caches whose total capacity is large (keeping the plain two-hit gate in small caches) will keep v001's large-cache hit-rate gains and recover its small-cache slip, raising summary hit-rate.

## Parent

cycle/0003/v001

## Changes

Edit `src/dash/segments/dash_segment.rs` (v001's version).

1. Add a field `full_target_guard: bool` to `DashSegment`. Compute it once in `DashSegment::try_new` from `settings`: total cache capacity in items (the number of segments times `(num_of_normal_buckets + num_of_stash_buckets) * bucket_size`, or whatever total-capacity value `DashSettings` exposes) must be `>= GUARD_MIN_CAPACITY`, where `const GUARD_MIN_CAPACITY: usize = 65536`. That value is the geometric middle between the 16384 and 131072 evaluation sizes. If `DashSettings` only exposes per-segment sizes, use the per-segment stash item capacity (`num_of_stash_buckets * bucket_size`) instead, with the cutoff halfway between the values those two sizes produce. Log the decision with `info!`.
2. Change `promotion_get` to take an extra `full_target_guard: bool` argument, passed from `DashSegment::get` as `self.core`'s sibling field. Because `get` borrows `self.core` mutably, read the bool into a local first. In the stash-hit branch, the guard becomes `if full_target_guard && count < FULL_TARGET_PROMOTE_THRESHOLD && core.buckets[target_idx].is_full()`. Short-circuit on the bool first, so in small caches `is_full()` isn't even called.
3. Leave everything else unchanged: `PROMOTE_THRESHOLD = 2`, `FULL_TARGET_PROMOTE_THRESHOLD = 3`, the counter reset on promotion, the halving on demotion, and the target/probing paths. Normal-tier hits stay write-free.

Tests: `small_dash_settings` is probably below the cutoff. For `two_hit_stash_item_enters_full_target_demoting_lru`, call `promotion_get(..., true)` directly, or build the segment and then set `full_target_guard = true`, so the three-hit behaviour is still checked. Add a test with the guard off showing that two stash hits enter a full target and demote its LRU. Don't touch the gate-integrity files.

## Rationale (optional)

v001's insight showed that the guard helps both 131072 cells (hm_0 most) and slightly hurts both 16384 cells. In a small cache, stash residence is too short to collect a third hit. Cycle 0003's continuation asks for exactly this size-aware threshold. The experiment is cleanly testable: the large cells should match v001, and the small cells should match cycle/0002/v001 or do better.
