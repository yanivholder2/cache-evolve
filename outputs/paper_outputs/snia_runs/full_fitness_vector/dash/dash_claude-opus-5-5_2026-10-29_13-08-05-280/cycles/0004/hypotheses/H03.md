# H03

Adding a door guard to target→probing promotion, so the hottest target resident needs two consecutive hottest hits before it may enter a *full* probing bucket, will cut demotion cascades and raise large-cache hit-rate.

## Parent

cycle/0003/v001

## Changes

Edit `src/dash/segments/dash_segment.rs` (v001's version), function `promotion_get`, target-hit branch, `is_hottest` arm only.

1. Add `const FULL_PROBING_PROMOTE_THRESHOLD: usize = 1;`.
2. When `is_hottest` is true:
   - If `core.buckets[probing_idx].is_full()` is false, promote to probing as now (`remove_at` + `promote_to_probing`).
   - If probing is full and the resident's `lfu_counter < FULL_PROBING_PROMOTE_THRESHOLD`, set `core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter = 1`, then `return Some(core.buckets[target_idx].get_from_position(item_idx))` (an in-place touch, so the item stays at MRU).
   - If probing is full and the counter is `>= 1`, set it to 0 on the removed item before calling `promote_to_probing`, and promote as now.
   Check `is_full()` and write the counter only inside the `is_hottest` arm. The common non-hottest target hit and the probing hit stay byte-for-byte unchanged and write-free.
3. Keep the invariant that counters entering stash are small. A target resident with counter 1 that is demoted to stash is halved to 0 by the existing `>>= 1` in `demote_from_normal_bucket`, so the stash gate's two-hit count isn't inflated. Leave the stash-hit branch, including v001's full-target guard, unchanged.

Tests: update `cascade_demotion_probing_to_full_target_to_stash` and `probing_eviction_demotes_to_target`. Both promote into a full probing bucket, so add one more `get` of the hottest key before the assertions. Add a test showing that the first hottest hit against a full probing bucket leaves the key in target with `lfu_counter == 1` and probing unchanged, and that the second hit promotes it and resets the counter to 0. Update `normal_tier_hits_do_not_touch_counter` only if the setup creates a full probing bucket (it shouldn't). Don't touch the gate-integrity files.

## Rationale (optional)

Every cycle so far, the gains have come from deciding *who enters* a tier and from cutting multi-bucket moves. A promotion into a full probing bucket is the most expensive move: probing LRU → retry into its true target → that target's LRU → stash. It is also driven by a single MRU-position hit, which is weak evidence of reuse. The cross-cycle notes list "requiring reuse before promotion" into probing as untested. This applies v001's proven door-guard pattern one tier higher. It is distinct from H02, which tunes the stash→target guard.
