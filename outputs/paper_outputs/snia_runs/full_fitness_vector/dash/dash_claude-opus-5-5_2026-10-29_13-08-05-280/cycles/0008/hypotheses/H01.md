# H01

On cycle 0007 v003's window-throttled full-probing arm, replace the two-bucket swap with a single outright eviction of the probing LRU entry, to cut get/put p99 (per-op-time) while holding hit-rate ≥ 0.3952.

## Parent

cycle/0007/v003

## Changes

cycle/0007/v003 = cycle/0006/v001 (24-byte Item with `u8` `lfu_counter` + `u32` per-segment tick, guarded full-probing promotion as a direct two-bucket swap, no stash-side `full_target_guard` size gate) plus the lazy `PROBE_WINDOW` tick-age check on the `is_hottest` arm where the destination probing bucket `is_full()`.

Change only the promoting branch of that arm: `lfu_counter >= 1` **and** `age = seg_tick.wrapping_sub(item.timestamp) <= PROBE_WINDOW`. Today it swaps (hot key → probing at `promote_pos`; probing LRU entry → freed target slot at `Back` with `lfu_counter = 0`). Replace it with:

1. Remove the probing bucket's LRU-position entry and drop it from the cache. Do not reinsert it into the target slot, a neighbour, or stash. Update item count / occupancy exactly as the normal eviction path does.
2. Remove the hot key from its target slot and insert it into the probing bucket at `promote_pos`, applying the same counter/timestamp reset the existing promote path applies.
3. Leave the freed target slot empty.

Keep everything else exactly as in v003: the first-hit branch (`lfu_counter == 0` → set to 1, stamp tick, no promote), the stale-hit branch (age > window → treat as a fresh first hit), the `PROBE_WINDOW` definition (segment total slot count), the non-hottest arm (no reads/writes of `lfu_counter`/`timestamp`), the stash→target guard, put, put-eviction, the per-segment tick, and the 24-byte layout. No size gate is re-added.

## Rationale

Cycle 0007 v002 showed the probing evictee is disposable (dropping it cost no hit-rate, and v002 had the best hit-rate of the cohort, 0.395275), while cycle 0006 showed swaps keep buckets saturated so later gets/puts take slow full-bucket paths. v003 throttles how often the arm fires; this change also makes each firing free a slot. Confirmation: get p99 < 148 ns or put p99 < 100 ns with hit-rate ≥ 0.3952 and metadata-size 24. Refutation: hit-rate below 0.3950, which would mean that without the cascade/size gate the swap's retention of the probing resident mattered on this lineage. Note: v002's uniform 2× latency regression is suspected noise; if this variant shows a similar uniform shift, treat it as environmental.
