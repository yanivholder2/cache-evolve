# H03

When the stash is full on insert, evict a never-hit stash entry (`lfu_counter == 0`) in preference to the LRU-position one, so stash entries that have collected reuse survive to reach the gate and raise hit-rate, especially web_0-131072.

## Parent

cycle/0007/v003

## Changes

In cycle/0007/v003, change only the victim choice on the put/displacement path that must free a slot in a **full stash bucket** (the path that today evicts the stash bucket's LRU-position entry, or the first-choice victim, to make room for an incoming or demoted item).

New victim choice:

1. Scan that stash bucket's occupied slots starting from the LRU/eviction end toward the MRU end. Pick the first entry whose `lfu_counter == 0` (it has had no stash hit since it entered stash).
2. If every entry has `lfu_counter >= 1`, fall back to the existing victim (the LRU-position entry), unchanged.

Evict the chosen entry exactly as the existing path evicts its victim (same removal, occupancy update, and position bookkeeping), then insert the new item as today. The scan is bounded by the stash bucket's slot count and reads only `lfu_counter`; it writes nothing extra.

Do not touch the hit paths (target, probing, stash hits), the stash reuse gate threshold, the stash→target full-target guard, the full-probing arm (swap + `PROBE_WINDOW`), non-stash eviction, the per-segment tick, or the 24-byte Item. If the stash hit path does not currently increment `lfu_counter` for stash residents (i.e. the gate uses a different field), use whatever per-item value the stash reuse gate already reads as "stash hits so far" instead — do not add a new field.

## Rationale

Every cycle so far has varied *who enters* the full tiers; none has varied *who leaves* the stash, which is where reuse evidence for the gate is collected. Cycles 0003–0004 found keys in stash are evicted before they can collect another hit, especially in small caches, and placement by free space alone never moved web_0-large, the remaining hit-rate frontier. Preferring never-hit stash victims keeps keys that are partway to passing the gate without adding work to any hit path; the cost is confined to the stash-full put arm. Confirmation: hit-rate > 0.395225, with web_0-131072 > 0.4241 or hm_0-16384 > 0.3518, and get p50 unchanged at ~76 ns. Refutation: hit-rate unchanged or lower, which would mean stash survivors with one hit rarely become reused residents, or that one-hit entries crowd out fresh arrivals (scan resistance lost).
