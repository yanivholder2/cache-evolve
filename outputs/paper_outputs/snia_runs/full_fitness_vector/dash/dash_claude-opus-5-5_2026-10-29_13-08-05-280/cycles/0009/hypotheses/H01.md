An identical copy of incumbent cycle/0007/v003 will measure within a few ns of its recorded per-op-time (get p50 76), giving a noise control for every per-op-time verdict in this cohort.

## Parent

cycle/0007/v003

## Changes

This is a deliberate noise-control variant. It has no behavioural change. Copy the parent's overlay unchanged. The only allowed edit is one comment line at the top of the Dash segment source file that holds the get-path `is_hottest` / `PROBE_WINDOW` logic, for example `// cycle 0009 H01: identical-copy noise control of cycle/0007/v003`. That gives the overlay a non-empty diff.

Do NOT:
- change any constant (`PROBE_WINDOW`, gate thresholds);
- change any field, layout, or `#[inline]` attribute;
- reorder any function;
- add or remove any import.

The Item must stay 24 bytes and the per-segment `u32` tick must stay as it is. The window-throttled two-bucket swap on the full-probing arm must stay as it is. Hit-rate must reproduce the parent exactly in all four cells (web_0/hm_0 at 16384 and 131072). Any hit-rate difference means the copy is not identical and the variant is invalid.

## Rationale (optional)

For seven cycles, every cycle insight has asked for an identical-baseline re-run, and none has been done. Uniform latency shifts that also hit untouched `put` paths have shown up in cycles 3 and 5 through 8. Because of them, no latency verdict can be trusted, and that includes cycle 0008 v001's apparent regression (p50 115).

This variant is timed in the same session and on the same host as H02 and H03. That gives the direct comparison the cycle 0008 Continuation asked for: incumbent copy vs. 0008 v001 descendants.

How to read the result:
- **Confirmed:** get p50 lands within about ±5 ns of 76, and the p99 values land near the parent's. The benchmark is stable across sessions.
- **Refuted:** a large uniform shift shows up on an unchanged binary. That proves the shift is environmental. Later cycles should then score latency only relative to a same-session control.
