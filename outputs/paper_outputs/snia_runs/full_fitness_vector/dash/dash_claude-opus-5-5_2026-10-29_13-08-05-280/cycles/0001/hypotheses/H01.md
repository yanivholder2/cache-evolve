# H01

Landing promoted and demoted items at the MRU end (`InsertPosition::Back`) instead of the LRU end will raise hit-rate on the MSR traces, because items that have shown reuse will no longer be the next eviction victim in the bucket they move into.

## Parent

baseline

## Changes

Edit only `src/dash/segments/dash_segment.rs`.

In the baseline, `DashSegment::get` calls `promotion_get(&mut self.core, key, InsertPosition::Front)`. That one `insert_pos` value is passed down to every move, so every move inserts at index 0:
- `promote_to_target`: stash → target;
- `promote_to_probing`: target → probing;
- `demote_from_normal_bucket`: the demotion moves, i.e. probing → true target, target → stash, and the cascade into stash.

Under ClassicLRU, `eviction_candidate_index` is 0. So an item that was just promoted from stash is the first thing evicted from its target bucket. An item demoted into stash is the first thing evicted from stash, ahead of new items that have never been hit (`Segment::put` adds those at `Back`). The result is that items that have been hit are treated as colder than items that never have.

Separate the two directions so each has its own position:

1. Change `promotion_get`, `promote_to_target`, `promote_to_probing` and `demote_from_normal_bucket` to take two arguments in place of the single `insert_pos`: `promote_pos: InsertPosition` and `demote_pos: InsertPosition`.
   - `promote_pos` applies to the `core.put_at(Slot::Target, ..)` call in `promote_to_target` and the `core.put_at(Slot::Probing, ..)` call in `promote_to_probing`.
   - `demote_pos` applies to every `core.put_at` call inside `demote_from_normal_bucket`: the stash insert, the retry into the true target, and the cascade into stash.
2. In `DashSegment::get`, call `promotion_get(&mut self.core, key, InsertPosition::Back, InsertPosition::Back)`. Hits move to MRU, and demoted items enter stash at MRU. They then get a full trip through the stash LRU before falling out, just like new puts.
3. Leave the search order, the "hottest in target → probing" rule (`promotion_candidate_index`) and the `unreachable!` lookups unchanged. Keys still land in the same bucket as before, so slot legality and capacity invariants still hold.
4. Update the existing unit tests in this file. Tests that assert front placement (`stash_hit_inserts_at_front_of_target`, `target_hit_not_hottest_promotes_within_bucket`, and the helpers `target_retry_position`, `direct_to_stash_position`, `cascade_to_stash_position`) must use the new two-argument signatures. Tests that check `get` ordering should expect Back placement. The helper tests should keep covering both positions by passing the same value for `promote_pos` and `demote_pos`.

Expected outcome: higher hit-rate on all four (trace, size) cells of the MSR profile. There is no change to Item layout, so metadata-size should stay the same. Per-op time should be about the same or slightly lower, because `Vec::push` is cheaper than `insert(0, ..)`.
