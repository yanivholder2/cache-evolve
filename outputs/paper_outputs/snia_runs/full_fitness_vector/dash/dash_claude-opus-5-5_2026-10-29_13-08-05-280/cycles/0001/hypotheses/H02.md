# H02

Placing an item in whichever of its two normal buckets (target or probing) has a free slot, and filling those free slots before sending anything to stash, will raise hit-rate by using normal-tier capacity that the fixed target-only routing leaves empty.

baseline

## Changes

Edit only `src/dash/segments/dash_segment.rs`. The idea is Dash-style balanced insertion between the two legal normal buckets of a key: target `t = get_index(key, segment_size)` and probing `p = (t + 1) % segment_size`. Both buckets are already legal for the key under `check_slot_legality`.

1. **Stash hit (`promotion_get`, first branch).** After `remove_at` from stash, pick a destination instead of always calling `promote_to_target`:
   - If `core.buckets[t]` is not full, insert into target (`Slot::Target`).
   - Otherwise, if `core.buckets[p]` is not full, insert into probing (`Slot::Probing`).
   - Otherwise, fall back to the current `promote_to_target` path, which evicts the target LRU into the cascade.

   Use `insert_pos` for each of these inserts, as today. Afterwards, look the key up in `t` first and then in `p`, and return the reference from whichever bucket holds it. Rewrite the `unreachable!` so it fires only if the key is in neither bucket.
2. **Demotion (`demote_from_normal_bucket`).** Before any item goes to stash, try the other legal normal bucket, but only if it has space. Never evict to make room there.
   - Case `true_target == source_idx` (evicted from its own target): if `buckets[(true_target+1) % segment_size]` is not full, put it into `Slot::Probing`. Otherwise send it to stash as today.
   - Foreign-resident case (evicted from probing): keep the current retry into `Slot::Target`. If that retry evicts a `cascade` item, give the cascade item the same "probing if not full, else stash" treatment, but only one level deep. Do not recurse further. This keeps every operation's work bounded.
3. **Target → probing promotion** (the hottest item in target) is unchanged.
4. Add unit tests:
   - A stash hit with a full target and a non-full probing bucket lands in probing, and nothing is evicted.
   - A target eviction with free space in probing does not reach stash.
   - `check_slot_legality` and `check_capacity_bound` hold after a random put/get sequence.

   Keep the existing tests passing. Change their setup only where a test relied on a probing bucket being empty while a target eviction happened.

Expected outcome: fewer stash spills and stash overflows (the only path that removes items from the cache). That should give a higher hit-rate, most of all at size 16384, where pressure is highest. Metadata-size should not change. Per-op time may rise slightly because of the extra `is_full` checks.
