# H02

On top of v003's reuse gate, landing demoted items at the MRU end only when they carry reuse evidence (`lfu_counter > 0` before halving) will raise hit-rate without v001's promotion churn.

## Parent

cycle/0001/v003

## Changes

Edit `src/dash/segments/dash_segment.rs` (v003's version). Promotions keep
`InsertPosition::Front` everywhere. `promote_to_target` and `promote_to_probing`
still pass `insert_pos` (Front) to their own `put_at` call. Only the demotion
landing position changes:

1. In `demote_from_normal_bucket`, compute a per-item landing position before any
   halving: `let pos = if item.lfu_counter > 0 { InsertPosition::Back } else { InsertPosition::Front };`.
   - `true_target == source_idx` branch: halve the counter as now, then
     `core.put_at(Slot::Stash, pos, item)`.
   - Foreign-resident branch (retry in true target): `core.put_at(Slot::Target, pos, item)`.
     For the `cascade` item that falls out of the target, compute its own
     position the same way from `cascade.lfu_counter` (before halving), then halve
     and `put_at(Slot::Stash, cascade_pos, cascade)`.
   - Ignore the `insert_pos` parameter inside this function for landing position.
     Keep the parameter in the signature so call sites and tests compile, or rename
     it `_insert_pos`.
2. Back landing in the target bucket puts the item where
   `promotion_candidate_index()` ("hottest") looks. To avoid v001's
   re-promotion churn, change the target-hit branch of `promotion_get` so that
   target → probing fires only when `is_hottest && item.lfu_counter >= 2`
   (read the counter after the existing increment). Otherwise take the existing
   `get_from_position` path.
3. Leave everything else as in v003: the stash gate (`PROMOTE_THRESHOLD = 2`),
   the victim comparison, and the counter increments.

Tests: `target_retry_position`, `direct_to_stash_position` and
`cascade_to_stash_position` currently pass `insert_pos` and assert the landing
index. Rewrite them so they set `lfu_counter` on the demoted item (0 → expect
index 0 / Front, ≥1 → expect Back index). Adjust `target_hit_hottest_promotes_to_probing`
and `cascade_demotion_probing_to_full_target_to_stash` so the item has enough
hits to meet the new `>= 2` promotion condition. Do not touch the gate-integrity
files.

## Rationale (optional)

v001 showed that MRU landing protects reused items (hit-rate rose on all four
cells), but applying it to promotions made per-op time worse. The cycle-0001
insight asks whether demotion-only Back landing would work, and whether it adds
to the gate. Using the counter v003 already keeps, only items that were actually
hit get the protected landing spot. Cold evictees still land at the LRU end and
are the next to leave.
