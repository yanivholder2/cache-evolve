# H03

Limiting v002's no-evict free-slot placement to evictees that were hit while in the normal tier (one-bit reuse flag in `lfu_counter`) will recover hit-rate at the large cache size and keep v002's low per-op-time.

## Parent

cycle/0001/v002

## Changes

Edit `src/dash/segments/dash_segment.rs` (v002's version). Use the unused
`Item::lfu_counter` field as a one-bit "hit since it entered the normal tier"
flag (0 or 1). Do not add new fields, so `Item` stays at 40 bytes.

1. `promotion_get`, target-hit branch: before the `is_hottest` check, set
   `core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter = 1`. Write
   it only if it is currently 0, which avoids a store on hot repeats. Probing-hit
   branch: same, on `core.buckets[probing_idx]`.
2. `promotion_get`, stash-hit branch: after `remove_at`, set `data.lfu_counter = 0`
   before placing it. The three-way placement (free target → free probing →
   evicting `promote_to_target`) stays as is.
3. `place_in_other_or_stash`: take the free-slot branch only when
   `!core.buckets[other_idx].is_full() && item.lfu_counter != 0`. In that branch,
   clear the flag (`item.lfu_counter = 0`) before `put_at`, so the item must be
   hit again to earn another free-slot move. Otherwise, or if the item is cold,
   send it to stash with `lfu_counter = 0`, as now.
4. `demote_from_normal_bucket`: unchanged. The foreign-resident retry into the
   true target still happens, and its `cascade` still goes through
   `place_in_other_or_stash`, which now applies the flag check.
5. Keep `InsertPosition::Front` everywhere.

Tests: update any v002 test that expects a cold evictee to move into a free
other bucket. Set `lfu_counter = 1` on that evictee, and add a matching test
showing that a cold evictee (`lfu_counter = 0`) goes to stash even when the other
bucket has room. Do not touch the gate-integrity files.

## Rationale (optional)

v002's insight says its latency gain comes from shorter demotion chains. Its
hit-rate loss on web_0 at size 131072 came from cold target-LRU victims taking
free probing slots that hot items needed. The flag keeps the cheap no-evict move
only for items with reuse evidence, so free slots go to hot items. This tests
the cycle-0001 open question of whether chain shortening can be kept without
parking cold evictees. Unlike H01 and H02, this is a separate line that builds on
v002's latency winner, not v003's gate.
