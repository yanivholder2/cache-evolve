# H03

Sending normal-tier items that were demoted without being hit since their promotion to the stash LRU end (and keeping MRU demotion only for items that were reused) raises hit rate over cycle/0004/v002, because stash slots stop going to items that are already dead.

## Parent

cycle/0004/v002

## Changes

All changes are in `src/dash/segments/dash_segment.rs`. While an item is in the normal
tier, its `lfu_counter` field doubles as a "reused" bit. Promotion out of stash already
sets `lfu_counter = 0`, so every item enters target or probing unmarked. Metadata size does
not change.

1. **Mark reuse on normal-tier hits.** In `promotion_get`, set
   `core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter = max(lfu_counter, 1)`
   before both returns in the target branch: the room-gated probing promotion (set it on
   the item before `remove_at`, or on `data` before `promote_to_probing`) and the
   in-place touch. In the probing branch, do the same on
   `core.buckets[probing_idx]` before `get_from_position`.
2. **Choose the demotion position by reuse.** In `demote_from_normal_bucket`, read
   `let reused = item.lfu_counter > 0;` before clearing it, then clear it as today.
   - Direct-to-stash branch (`true_target == source_idx`): insert at
     `InsertPosition::Back` (MRU) if `reused`, else at `InsertPosition::Front` (LRU).
   - Foreign-resident retry: keep the retry into the true target at `Front`, and leave the
     item's counter as it is for that retry, so the reuse bit carries over. If that retry
     evicts `cascade`, read `cascade.lfu_counter > 0` in the same way, clear it, and insert
     into stash at `Back` if it was reused, else at `Front`.
3. Do not change anything else. The two-hit stash gate still clears the mark on promotion.
   The first-hit and second-hit stash logic, probing overflow, the room gate and `put` all
   stay unchanged.

Under the `Lfu` policy, `get_from_position` already increments the counter on normal-tier
hits, so the bit gets set either way. Using `max(.., 1)` keeps the two policies consistent.

Tests: update `direct_to_stash_at_mru` and `cascade_to_stash_at_mru`. Their victims are
created with a non-zero `lfu_counter`, so they count as reused and must still land at stash
MRU with the counter cleared. Add `unreused_demotion_lands_at_stash_lru`: a target victim
with `lfu_counter = 0` that is evicted by `promote_to_target` lands at index 0 of its stash
bucket with the counter at 0. Add `target_hit_marks_reuse`: after a target hit, the item's
`lfu_counter >= 1`. Do not touch `tests/`.

## Rationale (optional)

MRU demotion is the strongest retention lever found so far, but it gives a full stash
residency to every demoted item. That includes items that were promoted on two quick stash
hits and never touched again in the normal tier. Under the gate those items are often
two-hit bursts, not long-term hot keys. Sending them to the stash LRU end makes them the
next stash victim, so the slots go to new puts and to items that were actually reused. This
is a retention-quality change, unlike H01 (scan cost) and H02 (cascade limit). The test is
hit rate on hm_0 at the large size. If it drops there, then unreused demoted items do get
re-referenced at long gaps, and MRU-for-all should stay.
