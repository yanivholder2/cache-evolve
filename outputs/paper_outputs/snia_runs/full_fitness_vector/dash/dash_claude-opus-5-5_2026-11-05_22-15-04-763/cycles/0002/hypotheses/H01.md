# H01

Leaving a first-hit stash item in place (setting its mark only, with no MRU reorder) lowers v002's `get` per-op time while keeping most of its two-hit hit-rate gain.

## Parent

cycle/0001/v002

## Changes

All changes are in `src/dash/segments/dash_segment.rs`, in the stash-hit branch
of `promotion_get`.

Today the `counter == 0` path sets `lfu_counter = max(1)` and then returns
`core.stash_buckets[stash_idx].get_from_position(item_idx)`. Under ClassicLRU
that call removes the item from the bucket `Vec` and re-pushes it at the MRU
end, which shifts up to the whole bucket and is the likely main source of the
extra `get` latency.

Replace that return with an in-place read: after setting the mark through
`get_items_mut()[item_idx]`, return
`Some(&core.stash_buckets[stash_idx].get_items()[item_idx])`. Do not call
`get_from_position` on this path, so no reordering happens and the policy hook
(including the Lfu increment) is skipped. Write the mark as
`item.lfu_counter = item.lfu_counter.max(1)` so the semantics stay the same
under every policy.

Leave the `counter >= 1` path (remove_at, reset counter to 0,
`promote_to_target`, `unreachable!` guard) unchanged. Leave the clearing of
`lfu_counter` in `demote_from_normal_bucket` unchanged. Leave the target and
probing branches unchanged.

Tests: rename/rewrite `single_stash_hit_stays_in_stash_at_mru` to
`single_stash_hit_stays_in_place`. Put `a` then `b` into the same stash bucket,
`get(&a)`, and assert that `a` is still at index 0 (not moved), is not in
target, and has `lfu_counter >= 1`. All the other tests (two gets promote, Lfu
still needs two hits) should pass unchanged. Do not touch `tests/`.

## Rationale (optional)

This answers the open question from cycle 0001: does the gate need the MRU move?
Without the move, a marked item can still be evicted from the stash LRU end
before its second hit. This makes the filter a little stricter: the item must
come back within roughly one stash residency, the same as 2Q's A1in FIFO. The
expected cost is a small hit-rate loss compared with v002. The expected gain is
a cheaper first stash hit (a field write, with no `Vec` shift) and better `get`
p50/p99.
