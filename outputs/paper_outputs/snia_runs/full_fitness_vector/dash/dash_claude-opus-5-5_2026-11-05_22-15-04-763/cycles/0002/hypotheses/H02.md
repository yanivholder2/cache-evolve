# H02

Adding balanced promotion to v002's gated stash promotion (send a twice-hit stash item to the probing bucket when its target is full and probing has free space) lowers per-op time by avoiding demotion cascades and keeps or raises v002's hit rate.

## Parent

cycle/0001/v002

## Changes

All changes are in `src/dash/segments/dash_segment.rs`, in the
`counter >= 1` (second stash hit) path of `promotion_get`. Leave the first-hit
path as v002 has it.

After `let mut data = core.stash_buckets[stash_idx].remove_at(item_idx);
data.lfu_counter = 0;`:

1. Read `max = core.buckets[target_idx].get_max_size()`,
   `t_len = core.buckets[target_idx].size()`, and
   `p_len = core.buckets[probing_idx].size()`.
2. If `t_len < max`: call `promote_to_target(core, data, insert_pos)`, look the
   key up in `core.buckets[target_idx]`, and return it (keep the existing
   `unreachable!` guard). No eviction happens here.
3. Else, if `p_len < max`: call `promote_to_probing(core, data, insert_pos)`.
   Probing has room, so nothing is evicted and no cascade runs. Look the key up
   in `core.buckets[probing_idx]` and return it, with its own `unreachable!`
   guard.
4. Else (both full): call `promote_to_target` as v002 does today. The existing
   `demote_from_normal_bucket` cascade still applies.

Probing placement is already legal (the target-hit branch already uses
`promote_to_probing`), and the lookup branches already search probing, so `get`
and `contains_key` stay correct. Do not change the target-hit branch, the
probing-hit branch, or `demote_from_normal_bucket`, which still clears
`lfu_counter` on entry to stash. Keep `InsertPosition::Front` for promoted
items.

Tests: add `second_stash_hit_uses_probing_when_target_full`. Fill target with
`max` direct `buckets[target_idx].put` items, put the key in stash, `get` it
twice, then assert that the key is in probing, target's contents are unchanged,
and no target item moved to stash. Add a test where both buckets are full and
check that the key lands in target (fallback). Existing tests should still pass,
since they fill target from empty. Do not touch `tests/`.

## Rationale (optional)

Cycle 0001's H03 idea was never measured because the build failed with HTTP 429.
Here it sits on top of the winning gate instead of the baseline. The gate made
each promotion rarer but no cheaper: every promotion into a full target still
runs a target→stash demotion and a stash insert/evict. Using free probing space
skips that whole chain, which should lower `get` p99 the most. It should also
lower stash pressure, the suspected cause of v002's `put` slowdown, because
fewer demoted items are pushed into stash. Hit rate should hold or rise, because
fewer protected items get evicted from the normal tier.
