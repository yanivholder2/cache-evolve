# H02

Set two hash-derived bits per stash key in the existing 64-bit stash presence mask (a k=2 Bloom test) to cut its false-positive rate, lowering `get` p50 per-op-time on normal-tier hits.

## Parent

cycle/0008/v003

## Changes

Change only how a key maps into the per-stash-bucket `stash_masks` u64 word. Make no other change.

- Add a helper in `src/shared/utils.rs`, e.g. `stash_mask_bits(h: u64) -> u64`, that returns `(1u64 << (h & 63)) | (1u64 << ((h >> 6) & 63))`. It must use the low 12 bits of the precomputed `hash_key` value. The bucket indexes come from the high bits through `index_from_hash`, and the segment index from the low 32 bits, but both reductions are multiply-shift, so the low 12 bits stay well mixed by `fmix64`. If the two positions coincide, the key sets a single bit, which is still correct.
- Every place that sets mask bits (stash insertion, and the per-item rebuild in `refresh_stash_mask`) ORs in `stash_mask_bits(h)` instead of the single bit.
- The read-side reject test in `get` / `promotion_get` changes from `mask & bit != 0` to `let m = stash_mask_bits(h); stash_masks[i] & m == m`. This is still one load and one AND plus a compare against a value computed in registers. Skip the `get_position` stash scan when the test fails, exactly as now.
- Keep `refresh_stash_mask` as the only removal mechanism, so a removal clears bits correctly by full rebuild. Do not add counters.

Invariants: no false negatives (every live stash key's bits are all set), lookup order stays stash-first, and hit rate stays bit-identical to the parent. Update or add a unit test that inserts N random keys into a mask and checks that every key passes the test.

## Rationale (optional)

0008 v001 showed that the p50 lever for this filter is its false-positive rate. Shrinking the filter made it worse than having no filter. With n items per stash bucket, the single-bit FP rate is about n/64. Using k=2 bits in the same word gives about (2n/64)^2, which is roughly 4–5× fewer false positives at n=4–8. Each false positive avoided saves a full stash scan on a normal-tier hit. The read path keeps the dense single-word structure, which 0008 showed is the fastest reject.
