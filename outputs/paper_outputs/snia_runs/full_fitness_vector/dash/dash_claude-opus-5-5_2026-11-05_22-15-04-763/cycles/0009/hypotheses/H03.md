# H03

When a full stash bucket must evict, drop the LRU-most item that has never been hit (`lfu_counter == 0`) from the two least-recent slots instead of always the strict LRU slot, raising hit rate by protecting items that are partway to their two-hit promotion.

## Parent

cycle/0008/v003

## Changes

Modify only the stash-bucket victim selection, at the point where inserting into a full stash bucket (a demotion arriving at stash MRU, or a new item) currently drops the strict LRU slot.

- Look at the LRU slot (position `len-1` in the parent's LRU ordering) and the next-least-recent slot (`len-2`).
- If the LRU slot has `lfu_counter >= 1`, which means it already took its first stash hit under the two-hit gate, and the `len-2` slot has `lfu_counter == 0`, evict the `len-2` slot. Otherwise evict the LRU slot as today.
- When the `len-2` slot is evicted, the LRU item stays at the LRU end, so the next eviction considers it again. This bounds how long a once-hit item can be protected: after one more insertion it competes again, which avoids the unbounded-residency failure seen in the 0004/0005 deferral line.
- Removing the non-tail slot uses the existing in-bucket remove-and-shift path. Afterwards, maintain the stash presence mask exactly as the parent does for any stash removal (`refresh_stash_mask` on that bucket), so the read-side mask invariant holds.
- Do not change the `lfu_counter` semantics, the two-hit gate, MRU demotion, probing overflow, the probing room gate, or the hasher. Metadata size must stay at 40 bytes, so add no new fields.

Measure hit rate per cell, with hm_0 at 131072 as the first check. Expect per-op-time to stay close to the parent: one extra counter compare on stash eviction only.

## Rationale (optional)

Hit rate has been flat at about 0.535 since 0004. Every lever that worked was "keep proven items longer". This one applies that to stash eviction, which nothing has targeted so far. The cycle 0005–0007 deferral signals gated promotion. This one picks the eviction victim using per-item hit state, not bucket fill level, so it is a new kind of signal. Limiting the change to a two-slot window keeps stash draining.
