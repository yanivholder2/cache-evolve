# H01

Add a per-stash-bucket 64-bit collision word so most stash removals clear their mask bit in O(1) instead of calling `refresh_stash_mask`, cutting per-op-time on `put` and the `get` tail while leaving the dense read-side mask unchanged.

## Parent

cycle/0008/v003

## Changes

Keep the existing dense `stash_masks` u64 word for each stash bucket and the read path that tests it (one AND in `get`/`promotion_get` before the `get_position` scan). Do not change its width, bit selection (low 6 bits of `hash_key`) or lookup order.

Next to each stash mask word, add a second u64 `stash_collide` word in the same storage (a parallel array of u64 in the segment, laid out like `stash_masks`). Its invariant: bit b is set if, at some point since the last full refresh, two or more live stash items in that bucket mapped to bit b. It may be conservatively stale-set, and it must never be wrongly clear.

- On stash insert (demotion into stash, or a new item landing in stash): compute bit b from the already-computed hash. If `stash_masks[i]` already has bit b set, set bit b in `stash_collide[i]`. Then set bit b in `stash_masks[i]` as before.
- On stash removal (promotion out of stash, LRU eviction from stash, or explicit removal): compute bit b for the removed key, reusing the hash where the caller already has it, as `promotion_get` does. If bit b of `stash_collide[i]` is clear, clear bit b of `stash_masks[i]` and skip the refresh. Otherwise call `refresh_stash_mask(i)`.
- Extend `refresh_stash_mask` so it rebuilds both words in the same pass. As it re-hashes each item, a bit that is already set in the fresh mask becomes set in the fresh collision word. This keeps the collision word tight after any fallback.

Preserve these invariants: the mask must never under-report presence (no false negatives), and hit rate must be bit-identical to the parent, because only mask bookkeeping changes. Add a `#[cfg(debug_assertions)]` check that recomputes the mask after each fast-path clear and asserts it matches. That check must compile out of release builds. Do not touch the item-shift code on promotion.

## Rationale (optional)

0008 v001/v002 showed that O(1) mask upkeep fully recovers `put`. They lost `get` p50 only because they changed the read structure. Here the read structure stays exactly as it is in 0008 v003. With only a few items per stash bucket over 64 bits, collisions are rare, so almost every removal takes the O(1) path.
