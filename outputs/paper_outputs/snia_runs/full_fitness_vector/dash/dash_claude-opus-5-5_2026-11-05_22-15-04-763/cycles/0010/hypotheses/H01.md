# H01

Add a per-bit stash collision word to 0009 v002's k=2 Bloom mask so that each stash removal clears only that key's uncollided bits in O(1), without calling `refresh_stash_mask`, cutting `put` per-op-time while keeping hit rate bit-identical.

## Parent

cycle/0009/v002

## Changes

Keep the k=2 read-side test exactly as it is in 0009 v002: `let m = stash_mask_bits(h); stash_masks[i] & m == m`, with `stash_mask_bits` in `src/shared/utils.rs` unchanged. Do not change mask width, bit selection, or lookup order (stash first).

Add a parallel `stash_collide: u64` word for each stash bucket, stored in the segment and laid out like `stash_masks`. Invariant: if bit b of `stash_collide[i]` is clear, then at most one live item in stash bucket i maps to bit b, and `stash_masks[i]` bit b is set exactly when that item is present. Collide bits may be stale-set, but never wrongly clear.

- **Stash insert** (a demotion arriving at stash MRU, or a new item placed in stash): `let m = stash_mask_bits(h); stash_collide[i] |= stash_masks[i] & m; stash_masks[i] |= m;`. A key whose two positions coincide sets one bit. That is fine, because a key never collides with itself.
- **Stash removal** (promotion out of stash on the second hit, stash LRU eviction, explicit remove): reuse the hash the caller already has (as `promotion_get` does), then `stash_masks[i] &= !(m & !stash_collide[i]);`. This clears only the bits this key owned alone. Collided bits stay set, which can only over-report. Do not call `refresh_stash_mask` on this path.
- **Lazy rebuild:** stale collided bits slowly raise the false-positive rate. After the O(1) clear, call `refresh_stash_mask(i)` only when `stash_collide[i].count_ones() > COLLIDE_REFRESH` (start with 6). This bound keeps the FP rate close to 0009 v002's and makes rebuilds rare.
- Extend `refresh_stash_mask` to rebuild both words in one pass. For each live item: `collide |= mask & m; mask |= m;`.

Invariants: no false negatives, and hit rate bit-identical to the parent, because only mask bookkeeping changes. Add a `#[cfg(debug_assertions)]` check after each fast-path clear. It recomputes the exact mask from the bucket and asserts `exact & !stash_masks[i] == 0` (no false negatives). It must compile out of release builds. Add a unit test that runs random insert/remove sequences on one bucket and checks for no false negatives. Do not touch the item-shift code on promotion.

## Rationale (optional)

Cycle 0009 found that v001's O(1) clear and v002's k=2 mapping are stackable, but v001's all-or-nothing collision check would send many k=2 removals to the fallback. Clearing per bit avoids that: a removal clears whatever it can, and the lazy popcount trigger replaces the per-removal fallback. The test is whether `put` p50 (105 ns in v002, versus 91 ns in v001) drops toward v001's figure while `get` p50 stays at 59.
