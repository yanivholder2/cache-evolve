# H02

Move the stash-hit promotion chain out of line into one `#[cold] #[inline(never)]` function that moves items with single slice rotations, lowering `get` p99 per-op-time with policy-identical hit rate.

## Parent

cycle/0009/v002

## Changes

Change only the cost and code layout of the second-stash-hit promotion path: remove the item from stash, insert it at normal-tier MRU (target or probing per the existing room gate and overflow rules), demote the normal-tier victim to stash MRU, and drop the stash LRU if needed. Do not change any policy decision.

- Pull this entire chain, including its mask maintenance (`refresh_stash_mask` calls), out of `get` / `promotion_get` into one new function, e.g. `fn promote_from_stash(&mut self, stash_idx: usize, pos: usize, h: u64, ...)`. Mark it `#[cold]` and `#[inline(never)]`. The hot `get` body should keep only the following: hash, k=2 mask test, normal-bucket scan, stash scan, the first-hit `lfu_counter` bump with its MRU move, and a call into the cold function when the gate fires. Pass in the precomputed `hash_key` value so the function does not hash again.
- Inside the function, replace every element-by-element shift loop with one slice op on the bucket's item array. Removing slot `pos` and inserting at MRU slot 0 in the same bucket becomes `items[..=pos].rotate_right(1)`. Removing from stash without reinserting there becomes `items[pos..len].rotate_left(1)` followed by `len -= 1`. Inserting at MRU into a full normal bucket becomes "take the LRU item out, `rotate_right(1)` over the bucket, write slot 0". Apply the same pattern to the demotion into stash MRU. Each step becomes one memmove and no per-item branches.
- Keep the 0006 v003 lesson in mind: that fused rotate hurt `put` p99 because it was duplicated at a second inlined call site. Here, `put`-side callers that reuse any of these helpers must call the same out-of-line function or helper. Do not duplicate it inline.
- Do not add any fields, counters, or extra checks to the shift. Item ordering after every operation must be identical to the parent's. Add a unit test that runs a fixed op sequence through the parent-equivalent ordering logic and asserts the same bucket contents.

Invariants: hit rate bit-identical to 0009 v002, metadata size stays at 40 bytes, and stash mask maintenance is unchanged in semantics.

## Rationale (optional)

Every cycle since 0006 has placed the `get` tail on the stash-hit promotion path. That path is rare per op but expensive. In 0006 v003 the fused rotate improved `get` p99 and lost only through layout effects on `put`. Making the path cold and out of line also shrinks the hot `get` body, which may help p50 through better i-cache use. Making every move a single memmove targets the shift cost without adding work to it. Measure `get` p99 against v002's 151 ns.
