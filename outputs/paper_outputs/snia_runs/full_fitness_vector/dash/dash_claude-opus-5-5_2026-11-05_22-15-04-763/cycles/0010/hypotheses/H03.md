# H03

When a full stash bucket must evict and its LRU item is partway to promotion, evict the LRU-most never-hit item from anywhere in the bucket instead, sparing each once-hit item at most once, to raise hit rate (hm_0 at 131072 first).

## Parent

cycle/0009/v003

## Changes

Widen 0009 v003's two-slot victim window to the whole stash bucket and add a protect-once bound. The change is limited to stash-bucket victim selection, where an insert into a full stash bucket (a demotion arriving at stash MRU, or a new item) drops a slot.

- **Protect-once flag in the existing `lfu_counter`:** reserve a high bit (e.g. `SPARED = 0x80`) as a flag meaning "already spared once in this stash stay". Every existing gate comparison must use the low bits only, e.g. `lfu_counter & 0x7F`, so the two-hit gate behaves exactly as before. Clear the flag whenever the item leaves stash (on promotion) and whenever an item enters stash (demotion or new insert), so it covers one stash stay only.
- **Victim rule:** let `lru = len-1`.
  - If `items[lru].lfu_counter & 0x7F == 0`, or the `SPARED` flag is already set on that item, evict `lru` as the parent does today.
  - Otherwise, scan from `len-2` toward MRU for the first slot `j` with `lfu_counter & 0x7F == 0`. If one is found, set `SPARED` on the LRU item and evict slot `j` with the existing in-bucket remove-and-shift. If none is found, evict `lru`.
  - This replaces v003's `len-2`-only check. The spared item stays at the LRU end, so on the next eviction it is evicted unless a hit refreshed it first. That bounds residency and avoids the 0004/0005 jam.
- **Mask maintenance:** keep exactly the parent's maintenance for any non-tail stash removal (`refresh_stash_mask` on that bucket). The read-side mask invariant is unchanged.
- Do not change MRU demotion, probing overflow, the probing room gate, the hasher, or the mask encoding. Add no fields, so metadata size stays at 40 bytes. Add a unit test that fills a stash bucket and checks that a once-hit LRU item is spared exactly once, then evicted on the next insert.

## Rationale (optional)

0009 v003 found the "once-hit LRU, never-hit neighbour" pattern too rare to move hit rate, though every cell moved the right way. A whole-bucket window fires whenever any never-hit item exists in the bucket, which should be the common case. The protect-once bit keeps stash draining. Per cycle 0009's plan, this is the decisive test of stash victim choice: if hm_0 at 131072 does not rise past noise (about ±0.001), drop the lever.
