# H02

Requiring two stash hits before an item is promoted from stash into its target bucket raises hit rate, because one-hit items stop flushing the small normal tier during scans.

## Parent

baseline

## Changes

All changes are in `src/dash/segments/dash_segment.rs`. `Item` already has a
`lfu_counter: usize` field, which the active ClassicLRU policy never reads, so
no change to `item.rs` is needed.

In `promotion_get`, rewrite the stash-hit branch
(`if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key)`):

1. Read `core.stash_buckets[stash_idx].get_items()[item_idx].lfu_counter`.
2. If it is `0` (first stash hit since the item entered stash): set it to `1`
   through `get_items_mut()[item_idx].lfu_counter = 1`. Then call
   `core.stash_buckets[stash_idx].get_from_position(item_idx)`, which under
   ClassicLRU moves the item to the stash MRU end, and return that reference.
   No promotion happens.
3. If it is `>= 1`: `remove_at(item_idx)` as today, reset
   `data.lfu_counter = 0`, then call `promote_to_target(core, data, insert_pos)`
   and return the target reference exactly as the current code does (keep the
   `unreachable!` guard).

In `demote_from_normal_bucket`, set `item.lfu_counter = 0` before any
`Slot::Stash` insert (both the direct branch and the `cascade` branch), so a
demoted item must prove itself again with two stash hits. New items from the
default `Segment::put` start with `lfu_counter = 0` through `Item::new`, so no
change to `put` is needed.

Do not change the target-hit and probing-hit branches. Do not change
`InsertPosition::Front` for the promoted item.

Update or add in-file unit tests. `stash_hit_inserts_at_front_of_target` and
other tests that do `put` + one `get` and expect the key in target now need
two `get`s. Add a test that one stash hit leaves the key in stash at the MRU
position. Do not touch `tests/`.

Caveat for the implementer: if the bucket policy is `Lfu`, its
`get_from_position` also increments `lfu_counter`. That still gives the right
gating (the counter becomes ≥1 after the first hit), so no special-casing is
needed. Write step 2 so it uses `max(counter, 1)` semantics rather than
assuming the counter is exactly 1.

## Rationale (optional)

The normal tier is only 8 of 32 buckets per segment, and in the baseline any
single re-reference promotes an item into it, evicting a hotter resident to
stash's LRU end. MSR block traces have many re-references that happen only
once (read-after-write, short sequential re-scans). Gating promotion on a
second stash hit is a 2-hit SLRU/2Q-style filter: it keeps the protected tier
for items with real reuse. Per-op cost: a stash hit becomes cheaper on the
first touch (an in-bucket move only), and the second hit costs the same as
today.
