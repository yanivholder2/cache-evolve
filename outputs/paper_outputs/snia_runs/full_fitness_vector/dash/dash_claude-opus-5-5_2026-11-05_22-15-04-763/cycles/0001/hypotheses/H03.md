# H03

Load-balancing promotions out of stash between an item's target and probing buckets, sending each to whichever has free space, raises hit rate because the normal tier is used more fully and fewer demotion cascades push items into stash.

## Parent

baseline

## Changes

All changes are in `src/dash/segments/dash_segment.rs`. Today a stash hit always
calls `promote_to_target`, even when the target bucket is full and its
neighbour (the probing bucket `(target_idx + 1) % segment_size`) has empty
slots. That forces an eviction from target into stash, while capacity sits
unused next door. Probing slots only fill through the narrower
"hottest-in-target" path.

Change the stash-hit branch of `promotion_get`:

1. After `remove_at(item_idx)` from stash, compute
   `t_len = core.buckets[target_idx].size()` and
   `p_len = core.buckets[probing_idx].size()`. Also read
   `max = core.buckets[target_idx].get_max_size()`.
2. If `t_len < max`, call `promote_to_target(core, data, insert_pos)`. This is
   the baseline behaviour with no eviction.
3. Else, if `p_len < max`, call
   `promote_to_probing(core, data, insert_pos)` and return the reference from
   `core.buckets[probing_idx]` (no eviction, so no cascade).
4. Else (both full), fall back to `promote_to_target` as in the baseline, so
   the existing demotion cascade still applies.

After the move, look up the returned reference in whichever bucket was chosen
(`target_idx` or `probing_idx`). Keep an `unreachable!` guard for each branch.
Probing placement is already legal under `check_slot_legality`, and
`get`/`contains_key` already search the probing bucket, so lookups stay
correct.

Do not change the target-hit branch (hottest-in-target → probing) or the
probing-hit branch. Do not change `demote_from_normal_bucket`. Keep
`InsertPosition::Front` for promoted items.

Update or add in-file unit tests. Add a test where target is full and probing
is not: after one stash hit the key must be in probing and target must be
unchanged. Existing tests that fill target via promotion still pass, since
they hit the free-space branch first. Do not touch `tests/`.

## Rationale (optional)

This is Dash's original "balanced insert" idea applied to the promotion path.
Hash skew across the 8 normal buckets leaves some buckets full and churning
while neighbours are under-filled. Using the free probing space first turns
some evict-to-stash cascades into no-ops, which keeps more re-referenced items
in the normal tier. The extra cost is two `size()` reads per stash hit, which
is negligible next to the `Vec` insert, and avoiding the cascade can lower p99
get time.
