# H02

Adding a 64-bit per-stash-bucket presence mask, so `promotion_get` skips the stash `get_position` scan when the key's bit is clear, will lower `get` p50 on normal-tier hits without changing hit rate.

## Parent

cycle/0004/v002

## Changes

Goal: keep stash-first lookup order (cycle 0003 showed stash-last is worse) but make the stash probe nearly free for keys that are definitely not in stash.

1. In `SegmentCore` (the segment core module next to `dash_segment.rs`, not a gate file), add `stash_masks: Vec<u64>` with one word per stash bucket, all zeroed in `try_new`. Add `#[inline] fn stash_bit(key: &K) -> u64`, which returns `1u64 << (h >> 58)` for a hash `h` of the key. Use high bits of the same hash `get_index` uses, so the bit is independent of the bucket-index bits. If getting at the raw hash is awkward, a second cheap hash such as FxHash over the key is acceptable, but it must be deterministic.
2. Keep the mask conservative (no false negatives):
   - Every time an item is inserted into stash bucket `s`, through any path (`put` into stash, `put_at(Slot::Stash, ..)`, demotions from `demote_from_normal_bucket`, and any insertion inside `SegmentCore`'s put/eviction code), OR in `stash_bit(&item.key)`.
   - Every time an item leaves stash bucket `s` (`remove_at` on a stash bucket, a stash eviction of its LRU, or an explicit `remove`/delete), recompute `stash_masks[s]` by OR-ing `stash_bit` over the remaining items. Stash buckets are small, so this costs a few hashes and only runs on removals. Put the recompute in one helper, `refresh_stash_mask(s)`, and call it from every removal site. To find them, grep for every mutation of `stash_buckets[`.
3. In `promotion_get`, before `core.stash_buckets[stash_idx].get_position(key)`, test `core.stash_masks[stash_idx] & stash_bit(key) != 0`. If the bit is clear, skip straight to the target branch. Otherwise run the existing stash branch unchanged.
4. Add a `debug_assert!` in the skip path that `get_position` really returns `None`. This catches any missed mask update in tests.

Invariants: the mask may give false positives, but never false negatives. Because of that, lookup results, bucket contents and hit rate are bit-identical to the parent. `Item` stays 40 B and `Dash` stays 24 B. The new data is 8 B per stash bucket inside the segment. Leave the gate, MRU demotion, probing overflow and room gate unchanged. Do not touch `tests/`.

## Rationale (optional)

Cycle 0006 eliminated the MRU shift. That leaves the stash probe on every normal-tier hit as the last suspect on the common `get` path. A full stash bucket of N slots, scanned linearly with key compares, is paid on every target or probing hit and every miss. A one-word mask turns that into a single AND for most non-stash keys. The false-positive rate is about 1 − (63/64)^N, which for small N is well under 15%. This is a direct test: a p50 drop with identical hit rate pins the gap on the stash probe. Watch `put` p99, since mask refreshes add work to stash removals.
