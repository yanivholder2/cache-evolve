# H01

Replacing 0007 v002's per-stash-bucket presence bitmask with a 16×4-bit counting mask, updated in O(1) on every stash insertion and removal, will keep its `get` p50 gain while removing the `refresh_stash_mask` re-hash cost from `put` and the `get` tail (per-op-time).

## Parent

cycle/0007/v002

## Changes

Cost-only change to the stash presence filter added in 0007 v002 (in the segment core module next to `dash_segment.rs`, i.e. wherever `stash_masks`, `stash_bit` and `refresh_stash_mask` live). Policy behaviour must stay bit-identical.

1. Keep `stash_masks: Vec<u64>` (one u64 per stash bucket), but reinterpret each word as 16 counters of 4 bits each. Replace `stash_bit(key) -> u64` with `stash_nibble(key) -> u32`, which returns `((h >> 60) & 0xF) * 4`, the bit shift of the counter for that key. Use the high bits of the same hash the variant already uses for `stash_bit`, so the counter choice stays independent of the bucket-index bits.
2. Insertion into stash bucket `s` (every site that ORs `stash_bit` today): `stash_masks[s] += 1u64 << stash_nibble(&item.key)`. Add a `debug_assert!` that the counter was below 15 before the increment. Stash buckets have far fewer than 15 slots, so a counter cannot overflow. If the stash bucket capacity constant is ≥ 15, fall back to 8 counters × 8 bits (`(h >> 61) * 8`) and note this in a comment.
3. Removal from stash bucket `s` (every site that calls `refresh_stash_mask(s)` today, including stash LRU eviction, `remove_at` on a stash slot, promotion out of stash and explicit delete): `stash_masks[s] -= 1u64 << stash_nibble(&removed.key)`. The removed item is already in hand at each site, so this is one hash plus one subtraction, with no scan of the bucket. Add a `debug_assert!` that the counter was non-zero before the decrement. Delete `refresh_stash_mask`, or keep it only under `#[cfg(debug_assertions)]` to cross-check that the counters match a recomputation.
4. Lookup in `promotion_get`: replace `mask & stash_bit(key) != 0` with `(mask >> stash_nibble(key)) & 0xF != 0`. Keep the existing `debug_assert!` that the skip path really finds nothing with `get_position`.
5. Audit every in-place stash mutation (swap or overwrite of a stash slot without a separate remove and insert) so that it does a decrement for the outgoing key and an increment for the incoming key.

Invariants: no false negatives, so lookup results and hit rate are bit-identical to 0007 v002. `Item` stays 40 B, `Dash` stays 24 B, and the mask is still 8 B per stash bucket. Do not change the gate, MRU demotion, probing overflow, room gate or lookup order. Do not touch `tests/`.

## Rationale (optional)

0007 v002 showed the mask is a real p50 lever (93 → 84 ns). It also showed that recomputing the mask on every stash removal is what pushed `put` p50 from 128 to 239 ns and `get` p99 from 164 to 274 ns. Counting filters support deletion with exactly the cost of an insertion. If `put` returns to about 130 ns and `get` p99 returns to about 165 ns while p50 stays at about 84 ns, upkeep cost is confirmed as the whole regression. With 16 counters instead of 64 bits, false positives rise slightly. If p50 creeps up compared with v002, that measures how much the false-positive rate matters.
