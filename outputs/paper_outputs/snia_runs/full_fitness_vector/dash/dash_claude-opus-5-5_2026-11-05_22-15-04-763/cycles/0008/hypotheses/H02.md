# H02

Replacing 0007 v002's per-bucket stash bitmask with a per-slot 1-byte fingerprint array stored next to each stash bucket's items (Dash-paper style), written and cleared in O(1) at the slot being changed, will lower `get` p50 below 84 ns and remove the mask-refresh regression on `put` and `get` p99 (per-op-time).

## Parent

cycle/0007/v002

## Changes

Cost-only change. Policy behaviour must stay bit-identical.

1. Remove `stash_masks`, `stash_bit` and `refresh_stash_mask` from the segment core. Add a fingerprint array to the stash bucket itself, not a separate segment-level Vec. For example, give the bucket type used for stash buckets a `fps: [u8; CAP]` field (CAP is the bucket's slot capacity), placed before the items array so it shares the bucket header's cache line. If the bucket type is shared with normal buckets, adding the field there is acceptable as long as `Item` stays 40 B. Normal buckets can simply leave their `fps` unused. Do not grow `Item`, and do not change `Dash`.
2. Fingerprint function: `fp(key) = ((h >> 56) as u8) | 1`, where `h` is the hash already used for the bucket index (high bits, independent of index bits). The `| 1` makes 0 mean "empty slot".
3. Maintenance happens at the slot level, with no scans and no re-hashing of other items:
   - Writing item `it` into stash slot `i`: `fps[i] = fp(&it.key)`.
   - Removing or evicting slot `i`: `fps[i] = 0`.
   - If the bucket keeps its items ordered (LRU→MRU) and shifts them on insert or remove, apply exactly the same shift or rotate to `fps` in the same helper, so `fps[i]` always describes `items[i]`. Put this logic inside the bucket's own insert/remove/move-to-MRU methods so no call site can miss it.
4. Lookup: in the stash bucket's `get_position(key)`, compute `f = fp(key)` once. Compare against `fps[0..len]` first, a byte loop that the compiler can vectorise, and only run the full key compare on slots whose fingerprint matches. In `promotion_get`, drop the separate mask test entirely, because the fingerprint-filtered `get_position` is the fast path.
5. Add a `debug_assert!` (debug builds only) after every bucket mutation that each occupied slot's `fps[i] == fp(&items[i].key)` and that empty slots are 0.

Invariants: `get_position` must return exactly what the plain scan returns, so hit rate is bit-identical to 0007 v002. `Item` stays 40 B and `Dash` stays 24 B. Keep the gate, MRU demotion, probing overflow, room gate and stash-first lookup order unchanged. Do not touch `tests/`.

## Rationale (optional)

This is distinct from a counting mask (H01). It gives per-slot exactness: 8-bit fingerprints cut false positives from about 1 − (63/64)^N to about N/256. It removes the separate `stash_masks` cache line that 0007 v002's insight flagged, and the fingerprint lives on the bucket's own line. Stash hits also get faster, because only the matching slot is key-compared, which targets the `get` tail that the plain bitmask could not help. The cost is one byte write per stash mutation plus a shift that follows the existing item shift. If p50 drops below 84 ns and `put` p50 returns to about 130 ns, then false positives and cache-line placement both mattered. If p50 is about 84 ns and the tails recover, the gain came only from upkeep.
