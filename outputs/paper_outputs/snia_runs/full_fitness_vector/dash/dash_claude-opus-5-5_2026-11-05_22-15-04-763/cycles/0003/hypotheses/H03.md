# H03

Applying only v003's MRU stash demotion to the baseline, without the two-hit gate, raises hit rate above the baseline's 0.51 while keeping `get` p50 close to the baseline's 75 ns, which separates MRU demotion's retention gain from the gate's latency cost.

## Parent

baseline

## Changes

All changes are in `src/dash/segments/dash_segment.rs` of the baseline. Do not add
the two-hit gate. Leave the stash-hit branch of `promotion_get` exactly as the
baseline has it: one stash hit still runs `remove_at` + `promote_to_target`. Do not
read or write `lfu_counter` anywhere.

In the baseline, `demote_from_normal_bucket` takes an `insert_pos: InsertPosition`
parameter, which `promote_to_target` / `promote_to_probing` pass through from
`DashSegment::get` (`InsertPosition::Front`). It uses this value for its stash
inserts, so normal-tier victims enter stash at index 0, the LRU end and next victim.
Change it as follows:

- Remove the `insert_pos` parameter from `demote_from_normal_bucket` and update its
  two call sites in `promote_to_target` and `promote_to_probing`. The promoted item
  itself keeps the caller's `insert_pos`.
- Direct branch (`true_target == source_idx`): call
  `core.put_at(Slot::Stash, InsertPosition::Back, item)` (stash MRU).
- Foreign-resident retry: keep `core.put_at(Slot::Target, InsertPosition::Front, item)`.
  If the baseline used `insert_pos` here, hard-code `Front`, which is the value it
  always received.
- Cascade from that retry: call `core.put_at(Slot::Stash, InsertPosition::Back, cascade)`.

These are the same edits that cycle/0002/v003 made to its `demote_from_normal_bucket`.
Use v003's version as the reference, minus the `lfu_counter = 0` lines.

Tests: update the baseline's in-file tests that assert the demoted or cascaded
item's stash position (the direct-to-stash and cascade-to-stash position tests) so
they expect `stash_items.len() - 1` for both promote positions. Collapse each
front/back pair into one MRU assertion. Change the target-retry position tests to
expect index 0. Leave the other tests unchanged. Do not touch `tests/`.

## Rationale (optional)

Every gated variant has `get` p50 at 93–96 ns, against the baseline's 75, and none
has won because of that cost. v003's insight attributes its hit-rate gain to MRU
demotion giving normal-tier victims a full stash residency. That mechanism does
not depend on the gate: without the gate, a demoted item that gets one hit during
that residency goes straight back to target. This variant tests whether the
retention lever works alone. If hit rate rises above 0.51 while `get` p50 stays
near 75 (`Vec::push` is cheaper than `insert(0)`, and there is no extra gate state
or two-touch path), the result dominates the baseline on the Pareto front and gives
a low-latency branch that does not depend on the gate. If hit rate stays at
baseline, the MRU gain needs the gate to keep demoted items from cycling straight
back.
