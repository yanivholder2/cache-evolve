# H02

Adding cycle-0002 v002's probing overflow to v003 (a twice-hit stash item goes into free probing space when its target is full, instead of evicting a target resident) raises hit rate above v003's 0.534, because promotion and demotion placement are independent retention levers.

## Parent

cycle/0002/v003

## Changes

All changes are in `src/dash/segments/dash_segment.rs`, in the second-stash-hit
path of `promotion_get` (the code after `if counter == 0 { ... return ... }`).
Leave the first-hit path, `demote_from_normal_bucket` (which keeps v003's MRU
`InsertPosition::Back` stash inserts with `lfu_counter = 0`), and the target and
probing branches unchanged.

After `let mut data = core.stash_buckets[stash_idx].remove_at(item_idx); data.lfu_counter = 0;`:

1. Read `let max = core.buckets[target_idx].get_max_size();`,
   `let t_len = core.buckets[target_idx].size();` and
   `let p_len = core.buckets[probing_idx].size();`.
2. If `t_len < max`, call `promote_to_target(core, data, insert_pos)` and return
   the target reference with the existing `unreachable!` guard.
3. Else, if `p_len < max`, call `promote_to_probing(core, data, insert_pos)`.
   Probing has room, so nothing is evicted and no cascade runs. Look the key up in
   `core.buckets[probing_idx]` and return it, with its own `unreachable!` guard.
4. Else (both full): call `promote_to_target(core, data, insert_pos)` as v003
   does. The MRU-demotion cascade still applies.

Promoted items keep `InsertPosition::Front`. Probing placement is already legal,
because the target-hottest branch uses `promote_to_probing` and the probing lookup
branch finds the item.

Tests: add `second_stash_hit_uses_probing_when_target_full`. Fill target with `max`
direct `buckets[target_idx].put` items, put the key in stash and `get` it twice. Then
assert that the key is in probing, target's contents are unchanged, and no target
item was demoted to stash. Add `second_stash_hit_falls_back_to_target_when_both_full`.
Fill both buckets, get the key twice, and assert that the key is in target and that
the target's former LRU is at the stash MRU end with `lfu_counter == 0`. All existing
v003 tests must still pass. Do not touch `tests/`.

## Rationale (optional)

v002 (+probing overflow) and v003 (+MRU demotion) each improved on the gate alone
by acting on different decisions: where a promotion lands, and where a demotion
lands. The cross-cycle notes list stacking them as the top open question. Overflow
also means fewer demotions into stash, which should partly offset the stash
pressure that v003 adds to `put` p99. The main test is hit rate, especially on hm_0
at size 131072. A combined hit rate above 0.534 confirms the levers stack, and a
result at or below v003 refutes it. The known cost is v002's slower lookup for
overflowed items (a third bucket). It is accepted here so the hit-rate effect can
be measured on its own, and H01's reorder would address it separately.
