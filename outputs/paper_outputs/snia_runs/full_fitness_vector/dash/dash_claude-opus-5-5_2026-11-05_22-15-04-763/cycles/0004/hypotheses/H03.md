# H03

Adding probing overflow to the ungated MRU-demotion branch (cycle/0003/v003), so that a stash hit whose target is full but whose probing bucket has room lands in probing instead of evicting a target resident, recovers `put` p99 while keeping v003's lower `get` p99 and `put` p50.

## Parent

cycle/0003/v003

## Changes

All changes are in `src/dash/segments/dash_segment.rs`, inside the stash branch of
`promotion_get`. There is no two-hit gate on this line, so a single stash hit
promotes.

Today: `remove_at(item_idx)` → `promote_to_target(core, data, insert_pos)` →
re-scan target with `get_position`.

New behaviour, after `remove_at`:

- Read `max = core.buckets[target_idx].get_max_size()`,
  `t_len = core.buckets[target_idx].size()`, `p_len = core.buckets[probing_idx].size()`.
- If `t_len >= max && p_len < max`: call `promote_to_probing(core, data,
  insert_pos)`, then look the key up in `core.buckets[probing_idx]` and return it.
  Use `unreachable!` if it is missing, because probing had room and so nothing
  can have displaced it.
- Otherwise: today's `promote_to_target` path, unchanged.

Do not add the two-hit gate, and do not touch `lfu_counter`. Keep
`demote_from_normal_bucket` exactly as in v003 (MRU stash inserts, no mark
clearing). Leave the target and probing branches and `put` unchanged.

Tests: add `stash_hit_uses_probing_when_target_full`, modelled on cycle/0003/v002's
`second_stash_hit_uses_probing_when_target_full` but with a single `get` after
`put`. Fill the target with `max` fillers, put the key, get it once, and assert:
the key is in probing and not in target or stash, the target contents are
unchanged, and no filler is in any stash bucket. Add
`stash_hit_falls_back_to_target_when_both_full`. With target and probing full, it
asserts that the key goes to target and the former target LRU goes to stash
MRU. Keep every existing v003 test. Do not touch `tests/`.

## Rationale (optional)

This tests the open question from cycle 0003 about the cheaper ungated line.
v003 already has the best `get` p99 (165) and `put` p50 (116) of any evaluated
variant, and its hit rate (0.5333) is within 0.001 of v002. Its weak point is
`put` p99 (151), which comes from stash pressure. On the gated line, overflow fixed
exactly that by skipping `promote_to_target` → demote → stash chains. Without the
gate, every stash hit promotes, so overflow should skip even more cascades here.
That makes this branch a plausible route to a better score than v002 without
the gate's extra branch and mark bookkeeping.
