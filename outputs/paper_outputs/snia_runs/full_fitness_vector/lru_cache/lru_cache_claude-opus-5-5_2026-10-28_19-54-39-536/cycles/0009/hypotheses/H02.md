# H02

Giving a one-shot probation reprieve to entries demoted from protected, flagged in a spare `prev` bit with no ghost table, will raise hit-rate on the incumbent cycle-0004 v002 while keeping its ~33 ns get p50 (per-op-time), because no extra heap structure is added.

## Parent

cycle/0004/v002

## Changes

Edit `src/lru_cache/mod.rs` of cycle/0004/v002. Do not add a ghost table, a hasher or any new header field.

- **Flag bit.** Add `const SC_BIT: u32 = 1 << 30;` and `const FLAGS: u32 = PROT_BIT | SC_BIT;`, and narrow `IDX_MASK` to `(1 << 30) - 1`. `NIL` stays equal to `IDX_MASK`. The `capacity >= IDX_MASK` check in `try_new` adjusts automatically. Change `set_prev` to `self.prev = (self.prev & FLAGS) | idx`, keeping the `debug_assert` and dropping the redundant mask. `set_protected(true)` stays a single OR. `set_protected(false)` stays `self.prev &= IDX_MASK`, which clears both flags. Add a `has_second_chance()` accessor.
- **Mark on demotion only.** In `on_hit`'s promotion branch, set the flag on the demoted node right after `self.push_back(demoted, false)`, with `self.nodes[demoted as usize].prev |= SC_BIT;`. This runs only when the protected segment overflows. Leave the protected-hit branch and the `protected_cap == 0` branch untouched. When a probation entry is promoted, `push_back(idx, true)` ORs in `PROT_BIT`, so first clear the flag there with `self.nodes[idx as usize].prev &= !SC_BIT` before calling `push_back`. Protected nodes must never carry `SC_BIT`.
- **Reprieve at eviction.** In `put`'s `Vacant` eviction arm, before choosing `victim`, check the probation head. If `prob_head != NIL` and it has `SC_BIT` set, clear the flag and move it to the probation MRU end. Use the same O(1) head-to-tail relink as cycle/0008/v001's reprieve block, including the case where it is the only probation node and just has its flag cleared in place. Then choose the victim as usual. Allow at most one reprieve per put.
- Reused slots go through `set_protected(false)`, so they still start with no flags. New keys are inserted with no flag.
- Keep the single-`Entry` put, the insert-before-remove order, the `capacity + 1` presize, the 24-byte node and the header size, which must not grow.
- Update `check_segments` to assert that protected nodes have no `SC_BIT`, and update `capacity_at_index_limit_rejected` for the 30-bit mask.
- Add unit tests for these cases: a demoted key survives one extra probation eviction and is then evicted; promoting a flagged key clears the flag; a key that was never protected gets no reprieve.

## Rationale

Every ghost variant reached hit-rate 0.539 but paid get p50 of 42–43 ns. The incumbents sit at 0.53785 / 32–34 ns. Cycle 8 traced the get cost to the ghost's heap footprint. Keys demoted from protected have already shown reuse, so this applies the "selective second chance" idea to keys proven reusable, using only state the node already has. The result splits the explanations. If hit-rate rises and get p50 stays near 33, the reprieve logic is cheap and the footprint was the cost. If get p50 jumps anyway, the extra branch in the reprieve or demotion path is to blame.
