# H01

Combining cycle-0008 v001's capacity/4 large-size ghost with cycle-0008 v002's 8-bit ghost tags will lower get p50 (per-op-time) below both parents, with hit-rate unchanged from v001.

## Parent

cycle/0008/v001

## Changes

Start from cycle/0008/v001's `src/lru_cache/mod.rs`. Keep `ghost_len_for` exactly as it is: full width `capacity.next_power_of_two()` for `capacity <= GHOST_MAX_CAPACITY`, `(capacity / 4).next_power_of_two()` above that. Then switch the tag width to 8 bits, the way cycle/0008/v002 did:

- Change `ghost: Box<[u16]>` to `Box<[u8]>`. Allocate it in `try_new` with `vec![0u8; len].into_boxed_slice()`, and update the type annotation of the `(ghost, ghost_shift)` tuple to match.
- Change `ghost_slot_tag` to return `(usize, u8)`. Keep the slot as `h.checked_shr(shift).unwrap_or(0) as usize`, so it still comes from the top bits. Take the tag as `((h >> 16) as u8) | 1`, so it is never 0 and 0 still means an empty slot. It must stay a single Fx multiply with no second hash.
- Leave everything else byte-identical to v001: the put/Vacant ghost logic, the reprieve block, `on_hit`, `unlink`, `push_back`, the header field order, and `ghost_shift`. The header stays within 128 bytes, `Node<u64,u64>` stays 24 bytes, and the ghost is still touched only in the `Vacant` arm.
- At 131K the ghost goes from 64 KB to 32 KB; at 16K it goes from 32 KB to 16 KB.

Add a spurious-reprieve counter that is compiled only under `#[cfg(test)]`, so it adds no work to release builds. Store it in a `#[cfg(test)]` field, or count from a test-only helper that replays a trace against a shadow `HashSet` of truly evicted keys. Add a unit test that replays a deterministic pseudo-random workload with ~4x capacity distinct keys on a 1024-entry cache. It should assert that the ratio of spurious reprieves (ghost tag matched, but the key was never evicted within the window) to genuine ones is below 1/16. This shows how often collisions happen without touching the hot path. Update the existing `ghost_slot_tag_in_range_and_nonzero` and `occupied_put_leaves_ghost_untouched` tests for the `u8` type.

## Rationale

Both cycle-0008 Winners shrank ghost bytes on unchanged get code, and both lowered get p50. v002 was the cleaner of the two, isolating the tag width alone. If footprint is what drives the regression, the two levers should add up: a quarter of cycle-0007 v002's ghost bytes at 131K. If get p50 does not drop below both parents, footprint is not the whole story.
