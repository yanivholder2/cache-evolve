# H03

Replacing the 8-bit tag ghost with a 1-bit-per-slot bitset ghost, aged by a rotating word-clearing cursor, will cut ghost bytes several-fold and lower get p50 (per-op-time) while keeping hit-rate within 0.0005 of the parent.

## Parent

cycle/0008/v002

## Changes

Edit `src/lru_cache/mod.rs` of cycle/0008/v002, which has the capacity/2 large-size ghost and `u8` tags.

- **Representation.** Replace `ghost: Box<[u8]>` with `ghost: Box<[u64]>`, a bitset of `GHOST_BITS = 4 * ghost_len_for(capacity)` bits, so `GHOST_BITS / 64` words. Keep v002's `ghost_len_for` unchanged. Using 4x the parent's slot count keeps the false-positive rate low (bitset occupancy ≤ ~22%). The table is still much smaller than the parent's: at 131K it is 256K bits = 32 KB instead of 64 KB, and at 16K it is 64K bits = 8 KB instead of 16 KB. Set `ghost_shift = 64 - log2(GHOST_BITS)`. The bit index is the top bits of the single Fx hash, `h.checked_shr(shift).unwrap_or(0) as usize`, so the word is `bit >> 6` and the bit within it is `bit & 63`. There is no tag.
- **Lookup (Vacant arm).** If the bit is set, clear it and set `second_chance = true`, as the parent does on a tag match.
- **Record (eviction).** Set the victim's bit where the parent writes `vtag`.
- **Aging.** Add `ghost_cursor: u32`. To keep the header at ≤128 bytes, change `capacity: usize` to `capacity: u32` (it is always < `IDX_MASK`) and cast at the use sites. On every evicting put, increment an eviction count. Every `AGE_PERIOD = 16` evictions, zero `ghost[ghost_cursor]` and advance the cursor modulo the word count. Store the count in the low 4 bits of `ghost_cursor` and the word index in the upper bits, or use any equivalent single-u32 encoding. One full sweep then takes `words * 16 = GHOST_BITS / 4 = ghost_len` evictions. This keeps the parent's reuse window of about `ghost_len` evictions, and the bitset can never saturate.
- Leave `on_hit`, `unlink`, `push_back`, the reprieve relink block, the single-`Entry` put, and the rule that the ghost is touched only in the `Vacant` arm unchanged. `Node<u64,u64>` stays 24 bytes. For capacity 1, use a 1-word bitset with shift 64 and slot 0.
- **Tests.** Update the ghost tests for the bitset: index in range, sequential keys spread, the occupied put leaves the ghost untouched, and the reprieve-exactly-once tests still pass with `ghost.fill(0)`. Add a test that, after `10 * capacity` evicting puts of distinct keys, the bitset popcount is at most 30% of `GHOST_BITS`.

## Rationale

This answers cycle 8's open question of how small the ghost can get before hit-rate suffers. A bitset needs no tag compare and stores far fewer bytes per remembered key. The cursor gives it the direct-mapped table's bounded memory without the overwrite-on-collision behaviour. If get p50 falls along with the bytes and hit-rate holds, the footprint lever has more to give. If hit-rate drops, one bit is too lossy, and that marks the floor for footprint shrinking.
