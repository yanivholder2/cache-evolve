# H01

Replacing the default SipHash `RandomState` in v002's `HashMap` with a hand-written FxHash-style multiplicative hasher will cut get p50 below v002's 33 ns, with hit rate and the 24-byte node unchanged.

## Parent

cycle/0001/v002

## Changes

Keep v002's CLOCK policy and `Node` layout in `src/lru_cache/mod.rs` exactly as they are. Change only the hasher used by `map`. No new crates are allowed (`Cargo.toml` is off-limits), so implement the hasher in `mod.rs`.

- Add a private `struct FxHasher { hash: u64 }` that implements `std::hash::Hasher`. Use the rustc-hash/FxHash algorithm with `const SEED: u64 = 0x51_7c_c1_b7_27_22_0a_95;`. Each word `w` updates the state with `hash = (hash.rotate_left(5) ^ w).wrapping_mul(SEED)`.
  - Override `write_u64`, `write_u32`, `write_u16`, `write_u8` and `write_usize` to apply that step once to the widened integer. `u64` keys must take a single multiply.
  - Override `write_i64` and the other signed variants to forward to the unsigned versions. Hashing `i64` calls `write_i64`, and the default forwards to `write`.
  - Implement the generic `write(&mut self, bytes: &[u8])` by consuming 8-byte chunks with `u64::from_le_bytes` and then the remaining tail bytes, so arbitrary `K: Hash` still works.
  - `finish()` returns `self.hash`. FxHash puts weak entropy in the low bits, and hashbrown uses the top 7 bits as the control tag, so to be safe it can return `self.hash.rotate_left(26)` (or apply one final xor-shift `h ^ (h >> 32)`). Pick one and note it in a comment.
- Add `#[derive(Default, Clone, Copy)] struct FxBuildHasher;` implementing `BuildHasher<Hasher = FxHasher>` with `FxHasher { hash: 0 }`.
- Change the field to `map: HashMap<K, usize, FxBuildHasher>` and construct it with `HashMap::with_capacity_and_hasher(capacity, FxBuildHasher)` in `try_new`. No other code changes. `get` and `put` keep identical logic.
- Do not narrow the map value to `u32` in this variant; isolate the hasher effect.
- The existing `#[cfg(test)]` tests must pass unmodified. Add one test that inserts 10 000 sequential `u64` keys into a capacity-10 000 cache and reads them all back, to guard against a broken hasher producing wrong lookups.

## Rationale (optional)

Both cycle-0001 winners showed that list maintenance is not the cost of a hit: v002 removed all relinking and get p50 moved only 34→33 ns. What remains is the `HashMap` probe, and with the default `RandomState` that probe is dominated by SipHash-1-3 (roughly 15–20 ns for a `u64`). A single-multiply hash should take 10+ ns off get p50. The policy does not change, so hit rate should match v002 exactly (0.529875) and metadata-size stays at 24. Expect put p50 to drop as well, since it does two to three map operations. Hash-flooding resistance is lost, which is acceptable for a simulator workload.
