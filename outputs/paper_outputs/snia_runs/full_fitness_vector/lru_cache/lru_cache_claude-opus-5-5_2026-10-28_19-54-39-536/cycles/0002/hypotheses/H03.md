# H03

Re-implementing v001's 20/80 segmented LRU on v003's `u32`-index node, with the segment flag packed into the high bit of `prev`, will keep SLRU's hit-rate gain (≥0.535) at 24 bytes of metadata, instead of v001's 56.

## Parent

cycle/0001/v003

## Changes

Start from v003's `src/lru_cache/mod.rs` (`u32` links, `NIL = u32::MAX`, `HashMap<K, u32>`) and add v001's SLRU policy without growing `Node`.

- **Node layout.** Keep `Node { key, value, prev: u32, next: u32 }`, so it stays exactly 24 bytes; the existing `node_u64_is_24_bytes` test must still pass. Reserve bit 31 of `prev` as the segment flag: `const PROT_BIT: u32 = 1 << 31;` and `const IDX_MASK: u32 = PROT_BIT - 1;`. Store NIL for `prev` as `IDX_MASK` (0x7FFF_FFFF), with the flag OR-ed on top. `next` stays a plain index with `NIL = u32::MAX`, or uses `IDX_MASK` as well for symmetry; pick one and be consistent.
- **Accessors.** Add small `#[inline]` helpers: `prev_idx(n) -> u32`, `is_protected(n) -> bool`, `set_prev(n, idx)` (which preserves the flag) and `set_protected(n, bool)`. All link reads and writes must go through these helpers, so the flag never leaks into an index.
- **Capacity check.** In `try_new`, tighten the check to reject `capacity >= IDX_MASK as usize`, with a `log::error!`. Keep the zero check.
- **Cache state.** Replace `head`/`tail` with `prob_head`, `prob_tail`, `prot_head` and `prot_tail` (all `u32`), plus `prob_len: u32`, `prot_len: u32` and `protected_cap: u32`. Compute `protected_cap = if capacity == 1 { 0 } else { max(1, capacity * 8 / 10) }`, as v001 does.
- **List operations.** Port v001's `unlink`, `push_back` and `on_hit` logic one-for-one. They pick the segment list from `is_protected(idx)` and keep the length counters correct. Promotion from probation to protected and demotion of the protected LRU to the probation MRU on overflow work exactly as in v001. Eviction takes `prob_head`, falling back to `prot_head`, and the reused slot is reset to probation.
- **Tests.** Port v001's SLRU-order unit tests. Add a test that cycles one key through probation → protected → demoted and checks that its flag and links stay consistent (for example, that eviction order is still correct afterwards). Keep `debug_assert_eq!(prob_len + prot_len, map.len())`.

## Rationale (optional)

This answers cycle 0001's top open question. v001 had the best hit rate (0.53785), but it lost because its `Option<usize>` links plus a `bool` pushed `Node` to 56 bytes, and its extra branching slowed get to 40 ns. v003 showed that `u32` links are free in hit-rate terms and give exactly 24 bytes with no spare padding, so the flag has to live inside an existing field. The 2³¹ capacity ceiling is far above the 131 072 maximum. Hit rate should match v001 exactly, since the policy is identical, and metadata should match v003. The open risk is get latency, which is expected around v003's 34 ns plus a few ns for masking. This variant tests whether SLRU's hit-rate gain can be had without the metadata cost.
