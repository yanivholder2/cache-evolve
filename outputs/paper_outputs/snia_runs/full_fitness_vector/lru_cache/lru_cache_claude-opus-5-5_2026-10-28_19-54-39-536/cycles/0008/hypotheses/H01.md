# H01

Narrowing the large-size ghost from capacity/2 to capacity/4 slots raises summary hit-rate, because it removes most of hm_0/131K's leaked loop-key reprieves and keeps most of web_0/131K's gain.

## Parent

cycle/0007/v002

## Changes

In `src/lru_cache/mod.rs`, change only the above-threshold branch of
`ghost_len_for`: for `capacity > GHOST_MAX_CAPACITY` return
`(capacity / 4).next_power_of_two()` instead of
`(capacity / 2).next_power_of_two()`. At 131072 this gives a 32768-slot ghost
with `ghost_shift = 64 - 15`. Leave the `capacity <= GHOST_MAX_CAPACITY` branch,
`GHOST_MAX_CAPACITY = 32768`, the Fx `GhostHasher`, the `ghost_slot_tag` layout,
the vacant-only ghost path in `put`, the one-shot reprieve logic and `on_hit`
exactly as they are. The 16K results must therefore stay byte-identical to the
parent.

Update the tests that encode the old width:
- in `ghost_size_gating`, the `GHOST_MAX_CAPACITY + 1` case should expect
  `((GHOST_MAX_CAPACITY + 1) / 4).next_power_of_two()`, and the 131072 case should
  expect length 32768 and shift `64 - 15`;
- in `large_cache_reinserted_key_gets_second_chance`, assert `ghost.len() == cap / 4`
  and the matching shift. The rest of that test's logic still holds.

Update the header comment so it says capacity/4.

## Rationale (optional)

Cycle 6 put the ghost at capacity/8, which was too short for web_0/131K (neutral).
Cycle 7 put it at capacity/2, a net gain, but hm_0/131K dipped from 0.7332 to 0.7329.
capacity/4 is the midpoint the cycle-7 insight recommends. It also halves the
hidden heap footprint of the ghost at 131K, from 128 KB to 64 KB, which may reduce
cache pressure on the get path.
