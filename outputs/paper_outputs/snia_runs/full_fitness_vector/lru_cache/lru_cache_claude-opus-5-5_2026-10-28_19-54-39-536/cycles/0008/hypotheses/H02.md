# H02

Shrinking ghost fingerprints from 16-bit to 8-bit tags halves the ghost table's cache footprint, which lowers per-op-time (get p50) while keeping hit-rate within noise of the parent.

## Parent

cycle/0007/v002

## Changes

In `src/lru_cache/mod.rs`, change the ghost storage from `Box<[u16]>` to
`Box<[u8]>` and keep its length unchanged (`ghost_len_for` is untouched, so
16K still gets 16384 slots and 131K gets 65536). That cuts the table from 32 KB to
16 KB at 16K, and from 128 KB to 64 KB at 131K.

- `ghost_slot_tag` returns `(usize, u8)`. The slot is still taken from the top
  `64 - shift` bits. The tag becomes `((h >> 24) as u8) | 1`, taken from bits that
  never overlap the slot bits at these sizes, so the tag is always non-zero and
  0 still means an empty slot.
- Allocate with `vec![0u8; len].into_boxed_slice()` in `try_new`.
- Every other ghost read and write in `put`'s `Vacant` arm (lookup, clear on hit,
  and recording the victim tag) keeps the same control flow, only with `u8`
  values. Do not change the reprieve logic, `on_hit`, `unlink`, `push_back`, the
  node layout, or the header field order. The `LruCache` header should keep its
  size, since a fat pointer is the same size either way.
- Update the tests: `ghost_slot_tag_in_range_and_nonzero` checks `tag != 0`
  for `u8`. `occupied_put_leaves_ghost_untouched` and other tests that plant
  tags use the `u8` type.

## Rationale (optional)

Cycles 3–7 repeatedly found that side structures hurt get p50 even when get never
touches them, and the ghost's cache footprint is one of the two suspects left. This
change tests that suspect directly: the policy stays the same, only the table's
bytes shrink. The cost is a higher spurious-reprieve rate, about 1/128 per
non-matching slot instead of about 1/32768. This should move hit-rate only
marginally, because a spurious reprieve only grants one extra probation pass.
