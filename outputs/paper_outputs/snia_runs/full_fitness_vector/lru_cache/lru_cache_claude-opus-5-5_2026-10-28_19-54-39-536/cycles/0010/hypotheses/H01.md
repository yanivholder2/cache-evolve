# H01

Replacing the map's SipHash `RandomState` with a fixed-seed folded-multiply (128-bit multiply, hi^lo fold) hasher will lower get p50 (the per-op-time summary) and put p50 without changing hit-rate.

## Parent

cycle/0004/v002

## Changes

Add a small private hasher to `src/lru_cache/mod.rs`. This is not the Fx hasher from cycle 2: Fx left the low bits of structured block keys with almost no entropy, which most likely made hashbrown's h1 collide and caused that get regression.

- `struct FoldHasher { acc: u64 }` implementing `std::hash::Hasher`, with one mixing step
  `fn mix(&mut self, x: u64) { let m = ((self.acc ^ x) as u128).wrapping_mul(0x9E37_79B9_7F4A_7C15u128); self.acc = (m as u64) ^ ((m >> 64) as u64); }`.
  `write_u64`/`write_u32`/`write_u16`/`write_u8`/`write_usize` each call `mix` once with the widened value. `write(&[u8])` mixes zero-padded 8-byte little-endian chunks, the same way as the cycle-9 `GhostHasher::write`. `finish()` returns a second fold, `let m = (self.acc as u128).wrapping_mul(0xD6E8_FEB8_6659_FD93u128); (m as u64) ^ ((m >> 64) as u64)`, so that the top 7 bits (hashbrown h2) and the low bits (h1) are both well mixed.
- `#[derive(Clone, Copy, Debug, Default)] struct FoldBuild;` implementing `BuildHasher<Hasher = FoldHasher>`. `build_hasher` returns `FoldHasher { acc: 0x243F_6A88_85A3_08D3 }`, a fixed non-zero seed, so runs are deterministic.
- Change the field to `map: HashMap<K, u32, FoldBuild>`. In `try_new`, use `HashMap::with_capacity_and_hasher(capacity + 1, FoldBuild)`. The `Entry` import and all of `put`/`get`/`on_hit`/`unlink`/`push_back` stay byte-identical, so this only changes hashing. The `LruCache` header gets 16 bytes smaller because `RandomState` is gone, and `Node` stays 24 bytes.
- Keep every existing test. Add three tests: (a) `FoldHasher` output for `u64` keys `k * 4096` (block-aligned) over 0..65536 spreads across more than half of 65536 low-bit buckets (`h & 0xFFFF`); (b) the same holds for the top 7 bits, with all 128 h2 values hit; (c) `churn_does_not_resize_map` still passes, so the map is still pre-sized.

Invariants: policy, node layout, and single-`Entry` put stay unchanged. Hit-rate must be bit-identical to the parent, because the hasher does not affect eviction order. Any hit-rate change means a bug.

## Rationale (optional)

The per-op-time summary is get p50. Every lever tried on get since cycle 1 left SipHash in place, apart from cycle 2's Fx swap, and that one is explained by poor low-bit entropy rather than by hashing being cheap. SipHash-1-3 on a u64 costs roughly 15–20 cycles of a ~100-cycle get. A well-mixed folded multiply costs about 4. Put does the same hash once per call, so put p50 should drop as well, which fits the multi-cycle rule that put cost tracks hash cost.
