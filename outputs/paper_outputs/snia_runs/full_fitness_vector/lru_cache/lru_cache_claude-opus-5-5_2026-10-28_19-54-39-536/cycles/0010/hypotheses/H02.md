# H02

Escalating repeat ghost returners (keys that hit the ghost a second time after their first ghost-granted stay also ended in eviction) to the protected segment on re-insertion will raise hit-rate on both traces, mainly web_0 at 131K.

## Parent

cycle/0009/v001

## Changes

All edits are in `src/lru_cache/mod.rs`. This changes how ghost-hit reprieves are granted, as cycle 9's continuation asked, rather than the ghost width.

1. **Returner bit in the node.** Shrink the index to 29 bits by setting `IDX_MASK = (1 << 29) - 1` (and therefore `NIL`). Add `RET_BIT: u32 = 1 << 29` in `prev`, and set `FLAGS = PROT_BIT | SC_BIT | RET_BIT`. `set_prev` keeps preserving `FLAGS`. `set_protected(false)` still clears every flag. Update `capacity_at_index_limit_rejected` to the new limit.
2. **Mark returners.** In the `Vacant` arm, a ghost hit (`second_chance == true`) inserts the new node with `SC_BIT | RET_BIT` instead of `SC_BIT` alone. This applies to both the filling-phase push and the eviction-phase `prev |= SC_BIT` line. The reprieve at eviction clears only `SC_BIT` and keeps `RET_BIT`. To do that, replace `h.prev = tail` with `h.prev = tail | (h.prev & RET_BIT)`, and in the sole-node case use `prev = NIL | (prev & RET_BIT)`. Promotion in `on_hit` changes `prev &= !SC_BIT` to `prev &= !(SC_BIT | RET_BIT)`. That is still a single AND with a different immediate, so the get path gets no new instruction.
3. **Repeat bit in the ghost byte.** Ghost bytes become `(tag7 << 1) | repeat`, where `tag7 = ((h >> 16) as u8 & 0x7F) | 1`, which is never zero, so 0 still means empty. `ghost_slot_tag` returns the 7-bit tag already shifted. When recording the victim's fingerprint, set `repeat = 1` if the victim node has `RET_BIT` set. Read it before the slot is reset. On lookup, match with `(ghost[slot] & 0xFE) == tag`, and read `repeat = ghost[slot] & 1`.
4. **Escalation.** On a ghost hit with `repeat == 1`, do not insert the new key into probation with SC. Use `push_back(idx, true)` instead, so it goes to the protected MRU with no flags. Then, if `prot_len > protected_cap`, demote the protected LRU to the probation MRU. This is the same code as the demotion branch in `on_hit`, so factor it into a small `#[inline] fn demote_overflow(&mut self)` used by both. The victim is still chosen before insertion exactly as it is now. A `repeat == 0` ghost hit keeps today's behaviour, with `RET_BIT` added.
5. Tests: update the spurious-reprieve test for 7-bit tags, relaxing the ratio to `spurious * 8 < genuine`. Add a test where a key is evicted, re-inserted (ghost hit → SC|RET), evicted again without a hit, and re-inserted, and it lands in protected (`is_protected()`). Add another test showing that a returner promoted by a get has `RET_BIT` cleared. Extend `check_segments` to assert that protected nodes carry neither `SC_BIT` nor `RET_BIT`.

Invariants: `Node<u64,u64>` stays 24 bytes and the header stays within 128 bytes. Occupied puts still do no ghost work. There is still at most one reprieve per put, and the ghost hashing stays zero-seeded and deterministic.

## Rationale (optional)

Every cycle so far shows that only a re-reference seen after eviction predicts reuse. A key that has come back after eviction twice within the ghost window has a stable reuse distance just above the cache size, which is the pattern web_0 at 131K loses. Only these keys get the stronger protected placement. Cycle 3 sent every ghost hit to protected and lost; this sends only the much smaller set of proven repeat returners.
