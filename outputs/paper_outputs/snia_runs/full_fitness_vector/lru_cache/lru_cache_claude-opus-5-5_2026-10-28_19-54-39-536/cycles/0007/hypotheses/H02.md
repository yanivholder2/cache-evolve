# H02

Enable the fingerprint-ghost reprieve at large cache sizes, with the ghost sized at capacity/2 instead of being disabled, to raise hit rate on web_0 at 131K without readmitting hm_0's long-loop keys.

## Parent

cycle/0006/v001

## Changes

In `try_new`, replace the binary `capacity <= GHOST_MAX_CAPACITY` gate with a size-dependent ghost length:

- If `capacity <= GHOST_MAX_CAPACITY` (32768), use the current length, `capacity.next_power_of_two()`.
- Otherwise use `(capacity / 2).next_power_of_two()`. At 131072 that is 65536 `u16` slots (128 KB). Set `ghost_shift = 64 - len.trailing_zeros()` as now.

Keep the Fx `GhostHasher` with its fixed zero seed, so ghost slots and tags are deterministic and hit-rate deltas are reproducible run to run. Keep the slot/tag derivation (`ghost_slot_tag`), the vacant-only ghost work, the one-shot reprieve that keeps the entry in probation, and `set_protected` exactly as they are. Do not touch `get` or `on_hit`.

Update the `ghost_size_gating` and `large_cache_ghost_disabled_matches_plain_slru` tests in the overlay's own `#[cfg(test)]` module to match. The first should assert that `GHOST_MAX_CAPACITY + 1` gives a ghost of length `((GHOST_MAX_CAPACITY + 1) / 2).next_power_of_two()`. The second should become a test that a re-inserted key at 131K gets a second chance. Tests under `tests/` must not be edited.

Invariants: 16K results must be identical to the parent's, `Node<u64,u64>` must stay 24 bytes, and the header must not grow.

## Rationale (optional)

c6 v003 showed that a capacity/8 ghost is too short a reuse window for web_0 at 131K: it was nearly neutral, with a tiny hm_0 dip. c4 v003's full-width ungated reprieve lifted web_0 at 131K but cost hm_0. A capacity/2 ghost is the untested midpoint the cross-cycle open questions call for. It tests whether web_0's useful re-references at 131K return within about 64K evictions, while hm_0's longer loops still fall outside the window.
