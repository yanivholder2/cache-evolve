# H01

Move the evicting-put work into a separate `#[cold] #[inline(never)]` function and force-inline the hit-path helpers, so `get` compiles to a small, tight body and per-op-time (get p50) drops below the incumbent's.

## Parent

cycle/0004/v002

## Changes

This is a code-layout change only. Policy, node layout and eviction order stay byte-for-byte the same as cycle/0004/v002 (single-`Entry`, no-clone SLRU put on the 24-byte flag-packed `u32` node).

1. In `put`, keep the `Entry::Occupied` arm and the filling-phase branch of the `Entry::Vacant` arm inline. Move the entire eviction branch (victim selection, `mem::replace` of the key, `v.insert(victim)`, `unlink`, `set_protected(false)`, `map.remove(&old_key)`, `push_back`) into a new private method `fn evict_and_insert(&mut self, v: VacantEntry<'_, K, u32>, value: V)`, marked `#[cold]` and `#[inline(never)]`. The `VacantEntry` borrows `self.map`, so the borrow checker will reject `&mut self` here. Pass the disjoint fields instead (`nodes`, the four head/tail fields, `prob_len`/`prot_len`), or make it a free function taking `&mut Vec<Node<K,V>>` plus a small `&mut Lists` struct. If that is too invasive, use `v.into_key()` and re-enter the map. Do not add a second hash of the new key on the common path.
2. Mark `on_hit`, `unlink` and `push_back` `#[inline(always)]`, and mark `get` `#[inline]`. Split `on_hit` into a hot part (the protected-hit relink) and a `#[cold]` `#[inline(never)]` `promote(idx)`. `promote` holds the probation→protected promotion plus the demotion of the protected LRU. On a promotion-heavy hit, the steady state is mostly protected hits.
3. Change nothing in `LruCache` fields or their order, `Node` or `try_new`. The header must stay within its current size and on one cache line.

Invariants: hit rate must be exactly equal to the parent's on all four trace/size points, `Node<u64,u64>` must stay 24 bytes, and all existing tests must pass unchanged.

## Rationale (optional)

Across cycles, get p50 has not responded to list work, bit-ops, hashers or table layout. The one suspect nobody has isolated is code layout and inlining: every put restructure since c2 changed how the shared helpers get inlined, and get p50 drifted each time. Separating the cold eviction and promotion code from the hot hit path tests that suspect directly, with zero hit-rate risk.
