# H01

Replacing SLRU's fixed 80% protected share with a header-only hill-climber that adapts `protected_cap` from hit counts will raise hit rate, mainly at the small cache size and on web_0 at the large size, without changing node metadata.

## Parent

cycle/0002/v003

## Changes

Work in `src/lru_cache/mod.rs` (the flag-packed SLRU on `u32` nodes). Leave the `Node` layout, `PROT_BIT`/`IDX_MASK`/`NIL` encoding, `unlink`, `push_back` and eviction order (probation LRU, then protected LRU) unchanged.

1. Add these header fields to `LruCache` (no new per-node state and no hashed structure): `prob_hits: u32`, `prot_hits: u32`, `ops_in_epoch: u32`, `epoch_len: u32` (= `max(capacity, 64)`), `step: u32` (= `max(1, capacity / 50)`, which is 2% of capacity), `min_prot: u32` (= `capacity * 5 / 10`), `max_prot: u32` (= `capacity * 95 / 100`), `last_hit_rate: u32`, and `direction: i8` (+1 grows protected, -1 shrinks it; starts at -1, meaning a larger probation). The initial `protected_cap` stays at 80%. For `capacity == 1`, keep `protected_cap = 0` and switch adaptation off (`step = 0`). For small capacities, clamp so that `min_prot <= protected_cap <= max_prot` and `max_prot <= capacity - 1`.
2. In `on_hit`, increment `prob_hits` when the entry was in probation and `prot_hits` when it was protected, reading the flag before the relink. In both `get` (hit or miss) and `put`, increment `ops_in_epoch`. Keep the per-hit cost to a single increment and a single compare.
3. When `ops_in_epoch >= epoch_len`, call a cold `#[inline(never)] fn adapt(&mut self)`. It computes `rate = (prob_hits + prot_hits) * 1024 / ops_in_epoch` and climbs like Caffeine's hill-climber: if `rate < last_hit_rate`, flip `direction`. Then apply `protected_cap = clamp(protected_cap ± step, min_prot, max_prot)`, store `last_hit_rate = rate` and reset the counters. Use saturating arithmetic.
4. If `protected_cap` shrinks below `prot_len`, do not demote in bulk inside `adapt`. Instead, change the overflow check in the promotion branch of `on_hit` from `if` to a bounded `while self.prot_len > self.protected_cap` loop that demotes at most 2 entries per hit. Protected then drains lazily, and the latency of a single op stays bounded. Relax the `check_segments` assertion `prot_len <= protected_cap` to allow this transient overshoot, for example `prot_len <= max_prot`.
5. Tests: keep all existing tests passing. Tiny caches may need their expected values changed only if adaptation fires within the test, so set `epoch_len` large enough (≥ 64) that the existing small tests never reach it. Add a test that runs a scan-heavy workload, then a recency-heavy one, and asserts that `protected_cap` stays within `[min_prot, max_prot]` and that `check_segments` passes throughout.

## Rationale (optional)

Earlier cycles found SLRU weak at the small size, where the probation share is untuned, and found web_0 at the large size sensitive to how aggressive admission is in both directions. An adaptive split addresses both while respecting the cross-cycle rule that per-cache side structures hurt get: the only added state is a few header words, and the work is amortised once per epoch.
