# H03

Giving new keys whose 16-bit fingerprint appears in a small direct-mapped ghost array a single in-node "second chance" bit at probation eviction will raise hit rate on hm_0 without the web_0 losses that eager ghost promotion caused in cycle 3.

## Parent

cycle/0002/v003

## Changes

Work in `src/lru_cache/mod.rs`. Keep the 24-byte `Node` and the SLRU promotion and demotion logic in `on_hit` unchanged.

1. **Second-chance bit with no new node field.** `next` currently uses only 31 bits (`NIL = IDX_MASK`). Add `const SC_BIT: u32 = 1 << 31;` stored in bit 31 of `Node::next`. Make `next_idx()` return `self.next & IDX_MASK`. Make `set_next(idx)` preserve `SC_BIT`, as `set_prev` already preserves `PROT_BIT`. Add `has_second_chance()` and `set_second_chance(bool)`. Clear the bit whenever a node is promoted to protected (in `push_back(.., true)`) and when a slot is reused.
2. **Fingerprint ghost.** Add one header field `ghost: Box<[u16]>` of length `ghost_len = next_power_of_two(capacity)` (≈2 bytes per entry, no `HashSet`, no SipHash sketch), zero-initialised. Fingerprint: compute `h = self.map.hasher().hash_one(&key)` once, only on the eviction and insert paths, never in `get`. Slot = `(h as usize) & (ghost_len - 1)`. Tag = `((h >> 48) as u16) | 1`, which is never 0, so 0 means empty.
   - When a victim is evicted in `put`, hash `evicted_key` and write its tag into its slot. This overwrites the slot, so the ghost is lossy and bounded.
   - When a fresh key is inserted, hash it. If `ghost[slot] == tag`, set the new node's `SC_BIT` and clear `ghost[slot] = 0`. The key still enters **probation MRU** exactly as now. It is never inserted into protected and never forces a demotion, which is the gentle admission cycle 3 called for.
   Each put then adds at most 2 extra hash operations, and only on misses.
3. **Eviction.** In `put`'s victim selection, if `prob_head != NIL` and the head node has `SC_BIT` set, clear the bit, `unlink` it and `push_back(head, false)` to probation MRU, then take the new `prob_head` as the victim. Skip at most **one** node per eviction so the latency stays bounded. If the new head also has the bit, evict it anyway. The fallback to `prot_head` is unchanged.
4. Update `check_segments` so that `next_idx()` masks the bit. Add tests:
   - A key evicted from probation and re-inserted gets `SC_BIT` and survives exactly one extra eviction round.
   - The ghost tag is cleared on use.
   - `SC_BIT` never leaks into an index: random workload plus `check_segments`.
   - `Node<u64,u64>` is still 24 bytes.

## Rationale (optional)

Cycle 3 found that a full-key ghost was too eager, because jumping to protected and forcing demotion hurt web_0, and that per-cache hashed side structures cost get latency through cache pressure. This design keeps history to about 2 bytes per entry, never touches it on `get`, and expresses reuse only as a one-shot reprieve inside probation. It tests whether gentle use of recency history can capture hm_0's reuse gain while leaving web_0 essentially unchanged.
