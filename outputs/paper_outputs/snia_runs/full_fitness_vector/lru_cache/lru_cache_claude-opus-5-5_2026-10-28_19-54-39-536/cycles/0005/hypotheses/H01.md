# H01

Port cycle-0004 v003's probation-only fingerprint reprieve onto the single-`Entry` SLRU, with the second-chance bit moved into `prev` bit 30 and the ghost enabled only for small caches, to raise hit-rate without the get-p50 regression.

## Parent

cycle/0004/v002

## Changes

Start from v002's `src/lru_cache/mod.rs` (single `map.entry(key)` put, `mem::replace` of the victim key, map pre-sized to `capacity + 1`). Leave `get`, `on_hit` and the `next` field **unchanged**: `next` stays an unmasked plain index, and `next_idx`/`set_next` stay a load and a store with no AND or read-modify-write.

1. **Flag layout.** Keep `PROT_BIT = 1 << 31` in `prev`. Add `SC_BIT = 1 << 30` in `prev` too. Set `IDX_MASK = (1 << 30) - 1`, `NIL = IDX_MASK`, and `FLAGS = PROT_BIT | SC_BIT`. `prev_idx()` returns `prev & IDX_MASK`. `set_prev(idx)` becomes `prev = (prev & FLAGS) | idx`, which is the same instruction count as before. `set_protected(true)` must also clear `SC_BIT` (`prev = (prev | PROT_BIT) & !SC_BIT`), so promotion clears the reprieve without an extra branch in `push_back`. `try_new` rejects `capacity >= IDX_MASK`. Update the inline `capacity_at_index_limit_rejected` test to match.
2. **Ghost, size-gated.** Add `ghost: Box<[u16]>` to `LruCache`. When `capacity <= 32768` its length is `capacity.next_power_of_two()`. Otherwise it is an empty boxed slice and the ghost is disabled. Cache `ghost_mask: u32` (0 when disabled) in the existing `u32` slots so the header grows by the fat pointer only (stays ≤ 128 B). Reuse v003's `ghost_slot_tag` (slot = low bits of the hash, tag = `(h >> 48) as u16 | 1`).
3. **put, vacant path only.** Skip all ghost work when the ghost is disabled, so large-cache behaviour and cost match v002 exactly. When enabled, compute `h = self.map.hasher().hash_one(&key)` before `self.map.entry(key)`. Do it only once, and reuse it for both the lookup of the new key's tag and nothing else. If `ghost[slot] == tag`, clear the slot and remember `second_chance = true`.
   - **Eviction phase:** if `prob_head != NIL` and its `SC_BIT` is set, clear the bit, `unlink` it and `push_back(.., false)`. This happens once at most. Then pick the victim as before. Before the `mem::replace`, hash the victim's key and write its tag to the ghost. After `push_back(victim, false)`, set the victim's `SC_BIT` from `second_chance`.
   - **Filling phase:** set `SC_BIT` in the initial `prev` value when `second_chance`.
4. Keep the insert-before-remove order and the `+1` pre-size.
5. Add inline tests:
   - A key evicted from probation and re-inserted survives exactly one extra probation eviction.
   - Promotion clears `SC_BIT`.
   - With capacity 131072, the ghost is empty and eviction order is identical to plain SLRU.
   - `node_u64_is_24_bytes` still passes.

## Rationale (optional)

In v003 the reprieve lifted web_0 at both sizes and hm_0 at 16K, but it lost hm_0 at 131K and paid for it in get p50 by masking `next` on every relink. Putting the bit in `prev`, where every write already preserves a flag, keeps the `on_hit` path the same as v002's. Gating by size avoids the large-cache hm_0 loss.
