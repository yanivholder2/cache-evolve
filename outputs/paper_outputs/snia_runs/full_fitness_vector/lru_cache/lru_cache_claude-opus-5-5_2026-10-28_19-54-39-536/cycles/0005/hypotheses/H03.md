# H03

Set the SLRU probation share statically by cache size, using 1/3 probation for small caches and keeping 20% for large ones, to raise hit-rate at the 16K size at zero runtime cost.

## Parent

cycle/0004/v002

## Changes

Edit only the `protected_cap` computation in `LruCache::try_new` in v002's `src/lru_cache/mod.rs`. Nothing changes in `get`, `put`, `on_hit`, `unlink`, `push_back`, the node layout or the header fields.

- `capacity == 1` → `protected_cap = 0` (unchanged).
- `2 <= capacity <= 32768` → `protected_cap = max(1, capacity * 2 / 3)`, which gives about 33% probation.
- `capacity > 32768` → `protected_cap = max(1, capacity * 8 / 10)` (unchanged from v002, so the 131K results should be bit-identical).

Name the threshold and both fractions as `const`s (`SMALL_CACHE_MAX = 32768`, `SMALL_PROT_NUM/DEN = 2/3`, `LARGE_PROT_NUM/DEN = 8/10`) and log them in the existing `log::info!`.

Update the inline `protected_cap_formula` test to the new values (cap 2 → 1, cap 10 → 6, cap 2048 → 1365, cap 131072 → 104857). Re-check the inline tests that assume the 80% split at tiny capacities (`protected_survives_probation_churn` with cap 5 → protected_cap 3, `protected_overflow_demotes_to_probation_mru` and `protected_hit_moves_to_protected_mru` with cap 4 → protected_cap 2, `flag_cycle_probation_protected_demoted` with cap 3 → protected_cap 2). Adjust their expected segment contents to the new caps while keeping what each test is meant to check.

## Rationale (optional)

Three independent signals point to probation being undersized at the 16K size:
- v001's adaptive split won only web_0 at 16K (c4).
- v003's reprieve, which in effect extends probation residency, gained at 16K on both traces (c4).
- Cycle 1 CLOCK's web_0 small-size gain.

A static per-size share tests that hypothesis directly, without the online-adaptation noise that sank v001. Because the 131K split is left untouched, any change in the summary comes from the small size alone. Per-op-time and metadata should equal v002's.
