# H02

Replace the protected segment's move-to-MRU relink with a CLOCK-style reference bit that is set in place on protected hits, cutting get p50 by not touching neighbour nodes on the commonest hit.

## Parent

cycle/0004/v002

## Changes

Edit v002's `src/lru_cache/mod.rs`. The probation segment, eviction victim choice, single-`Entry` put and node size (24 B) all stay as they are.

1. **Ref bit.** Add `REF_BIT = 1 << 30` in `prev`. Set `IDX_MASK = (1 << 30) - 1`, `NIL = IDX_MASK`, and `FLAGS = PROT_BIT | REF_BIT`. `set_prev` preserves `FLAGS`. `next` stays an unmasked plain index. `push_back` always clears `REF_BIT`, since a newly linked node starts unreferenced. Adjust the `try_new` capacity limit and the `capacity_at_index_limit_rejected` test.
2. **`on_hit`, protected branch.** Replace `unlink(idx); push_back(idx, true)` with: load `prev`; if `REF_BIT` is clear, store `prev | REF_BIT`. Do no list work at all. This touches only the hit node's own cache line, instead of up to three other nodes (prev, next, prot_tail) plus the header.
3. **Promotion path (probation hit) is unchanged:** `unlink` + `push_back(idx, true)`. When `prot_len > protected_cap`, call a new `demote_one()` in place of the direct demotion:
   - Loop at most `MAX_SWEEP = 8` times. Let `h = prot_head`. If `h` has `REF_BIT` set, clear it and move `h` to the protected tail (`unlink` + `push_back(h, true)`).
   - Otherwise `unlink(h)` + `push_back(h, false)` (demote to probation MRU) and return.
   - If the cap is reached, demote the current `prot_head` regardless, so cost stays bounded.
4. **Eviction fallback** (`prob_head == NIL`, which only happens at tiny capacities) takes `prot_head` as before and ignores the ref bit.
5. `put` on an occupied key still calls `on_hit`, so it gets the same cheap path.
6. Update inline tests that assert exact protected LRU→MRU order after protected hits (`protected_hit_moves_to_protected_mru`, `protected_overflow_demotes_to_probation_mru`). They should assert the CLOCK semantics instead: a referenced protected head is rotated past instead of demoted. Add a test that 9 referenced protected entries still lead to a demotion (the sweep bound).

## Rationale (optional)

Four cycles show get p50 is memory-bound: list micro-optimisation did nothing, and any extra hit-path work hurt. But every protected hit still dereferences the prev, next and tail nodes, and each is a likely cache miss at 131K entries. Turning that hit into one store on a line that is already loaded removes those misses. Protected-segment CLOCK approximates LRU closely, so hit rate should stay within noise of 0.53785. The extra cost moves to promotions, which are rarer and happen on the probation-hit path.
