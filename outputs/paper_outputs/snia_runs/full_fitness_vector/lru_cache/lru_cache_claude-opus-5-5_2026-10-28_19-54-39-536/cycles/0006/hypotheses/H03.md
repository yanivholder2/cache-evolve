# H03

Enable the fingerprint reprieve at large cache sizes with an undersized ghost (capacity/8 slots), so that only short-distance re-references earn a second chance, which should raise hit rate on web_0 at 131K without the hm_0 loss of the ungated cycle-4 reprieve.

## Parent

cycle/0005/v001

## Changes

Work in `src/lru_cache/mod.rs`. Keep the node layout, the reprieve semantics (one-shot `SC_BIT`, which stays inside probation and is consumed at eviction), and all small-cache behaviour exactly as in v001.

1. **Ghost sizing in `try_new`.** Replace the binary `capacity <= GHOST_MAX_CAPACITY` gate with a two-regime sizing rule:
   - `capacity <= GHOST_MAX_CAPACITY`: unchanged, `len = capacity.next_power_of_two()`.
   - `capacity > GHOST_MAX_CAPACITY`: `len = (capacity / 8).next_power_of_two()`, which is 16384 slots for 131072. The direct-mapped table overwrites old fingerprints quickly, so a returning key finds its tag only if it comes back within about `len` evictions. This acts as a reuse-distance filter: keys returning soon after eviction (web_0's pattern) get reprieved, while long-loop re-references (the hm_0 pattern that cycle 4 lost on) mostly miss the ghost and are admitted normally.
   - Add a constant `LARGE_GHOST_DIV: usize = 8`. Leave `GHOST_MAX_CAPACITY` as the threshold between the two regimes.
2. **No other policy changes.** The put path, reprieve and victim-tag recording stay as in v001. `ghost_slot_tag` already masks with `ghost_mask`, so the smaller table works without further changes.
3. **Tests.** Update `ghost_size_gating`: at `GHOST_MAX_CAPACITY + 1` the ghost is now non-empty with length `((GHOST_MAX_CAPACITY + 1) / 8).next_power_of_two()`. Replace `large_cache_ghost_disabled_matches_plain_slru` with a test that a key re-inserted right after eviction at capacity 131072 gets `SC_BIT`. Add a test that a key re-inserted after `> ghost.len()` intervening evictions of distinct keys usually does not get `SC_BIT`. Wipe the ghost slot explicitly so the test is deterministic.

## Rationale

web_0 at 131K is the one trace that no mechanism has improved. Cycle 4's ungated reprieve lifted web_0 at both sizes but cost hm_0 at the large size. Cycle 5 removed the loss by turning the ghost off entirely at 131K, which also threw away the web_0 gain. A ghost far smaller than the cache bounds how old a remembered eviction can be. That makes it a cheap reuse-distance filter, using the gentle, selective second-chance idea that has worked before. The expected result is a small hit-rate gain on web_0 at 131K and hm_0 at 131K held near 0.7332, with unchanged 16K results. The added put cost appears only at the large size, and the timing benchmark already pays it at 16K. The 32 KB ghost is also smaller than v001's largest ghost of 64 KB.
