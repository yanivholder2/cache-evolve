# H01

Compute the fingerprint-reprieve ghost tags with a one-multiply Fx-style hasher, do ghost work only on the vacant path, and keep `set_protected(true)` a single OR, which should bring back cycle-4 put and get per-op-time while keeping v001's 16K hit-rate gain.

## Parent

cycle/0005/v001

## Changes

Work in `src/lru_cache/mod.rs`. Keep the policy, the size gate (`GHOST_MAX_CAPACITY`), the node layout (24 B, flags in `prev` bits 31/30) and the header size (≤128 B) exactly as they are.

1. **Cheap ghost hasher.** Add a private `struct GhostHasher(u64)` that implements `std::hash::Hasher`:
   - `write_u64(x)`: `self.0 = (self.0.rotate_left(5) ^ x).wrapping_mul(0x517c_c1b7_2722_0a95)`.
   - `write_u32`/`write_u16`/`write_u8`/`write_usize`: widen to u64 and use the same step.
   - `write(&[u8])`: process the bytes in 8-byte little-endian chunks, then a zero-padded tail, using the same step.
   - `finish()`: return `self.0`.

   Add `fn ghost_hash<K: Hash>(k: &K) -> u64` that starts from `GhostHasher(0)`, calls `k.hash(&mut h)` and then `h.finish()`. Replace both `self.map.hasher().hash_one(..)` calls with `ghost_hash(..)`. The map keeps its default `RandomState`; only the ghost changes hashers.
2. **Slot and tag from the high bits.** An Fx multiply leaves the low bits poorly mixed. Change `ghost_slot_tag` to take the ghost's log2 length `shift = 64 - log2(len)` (store it in place of `ghost_mask` so the header does not grow, or recompute it as `ghost.len().trailing_zeros()`). Then set `slot = (h >> shift) as usize` and `tag = ((h >> 16) as u16) | 1`. When the ghost is disabled, its length is 0, so guard the shift.
3. **Ghost work only for new keys.** Move the ghost lookup, the reprieve step and the victim-tag recording out of the code before `self.map.entry(key)` and into the `Entry::Vacant` arm. Since the map already holds the `VacantEntry`, compute the new key's tag from `v.key()` and do the reprieve and victim choice with direct field access to `self.nodes`, `self.prob_head` and so on. If the borrow checker objects, split the borrows (for example, destructure `self` into `map`, `nodes`, `ghost` and the heads up front), or turn the reprieve into a small free function over `&mut [Node]` plus the head/tail fields. `Entry::Occupied` puts must do no ghost work at all.
4. **Single-OR `set_protected(true)`.** Change `set_protected(true)` to `self.prev |= PROT_BIT`. Clear `SC_BIT` explicitly only where a flagged node can become protected, which is the probation→protected promotion branch of `on_hit`: clear it there before `push_back(idx, true)`. Leave the protected-hit branch untouched. `set_protected(false)` stays `self.prev &= IDX_MASK`. Keep the `check_segments` assertion that protected nodes never carry `SC_BIT`.

Update the ghost unit tests for the new hasher. `put_clean` still wipes the ghost, so the reprieve-ordering tests should pass unchanged. Add a test that an `Occupied` put leaves the ghost array untouched.

## Rationale

Cycle 5 found that v001's put regression comes from four SipHash computations per evicting put, and that its get-p50 regression comes from the extra AND in `set_protected`. Real reuse of the map's hash would need `hashbrown`'s raw API, which we cannot add because `Cargo.toml` is gate-locked. A one-multiply hash for a 16-bit fingerprint is the next-best option: it costs a few cycles instead of a full SipHash, and collisions only cost an occasional spurious reprieve. Expected result: hit rate stays at v001's 0.5386 (it may shift by a hair because tags collide on different keys), and put p50 moves back toward v002's roughly 84 ns.
