# H02

Replace `std::collections::HashMap<K, u32>` with a custom dense open-addressing index table of packed `u64` slots (32-bit hash fragment | 32-bit arena index), which should cut get p50 per-op-time by improving probe locality, with the SLRU policy and hit rate unchanged.

## Parent

cycle/0004/v002

## Changes

Work in `src/lru_cache/mod.rs`. This is a representation-only change. The SLRU policy, `Node` layout (24 B), `on_hit`, `unlink` and `push_back` must stay byte-for-byte identical in behaviour, so hit rate must match the parent exactly.

1. **New index table.** Add a private `struct IndexTable { slots: Box<[u64]>, mask: usize, hasher: std::collections::hash_map::RandomState }`.
   - Size `slots.len()` to `(2 * (capacity + 1)).next_power_of_two()`, which keeps the load factor at or below 0.5.
   - `EMPTY = u64::MAX` marks an empty slot.
   - Each occupied slot holds `((h >> 32) << 32) | idx as u64`. To keep a live slot from ever equalling `EMPTY`, force the stored fragment's low bit off.
   - Hash with `hasher.hash_one(key)`, the same SipHash the parent uses, so this tests layout and not hasher speed. Use linear probing that starts at `h as usize & mask`.
2. **Lookup.** `find(&self, key, nodes) -> Option<(slot, idx)>` walks slots until it reaches `EMPTY`. It dereferences `nodes[idx].key == *key` only when the 32-bit fragment matches, so most mismatching probes never touch the arena.
3. **Insert.** `insert_vacant(slot, h, idx)`: `put` first runs a probe that returns either the matching slot (`Occupied`) or the first `EMPTY` slot (`Vacant`, with the hash kept). This keeps the parent's single-probe put. Occupied updates the value and calls `on_hit`. Vacant fills the slot.
4. **Delete.** `remove_by_key(key, nodes)` finds the victim's slot (rehashing the victim key, as the parent's `map.remove` does). It then uses **backward-shift deletion** with no tombstones: walk forward from the hole, and move any entry whose home slot is not cyclically in `(hole, j]` into the hole, until you reach `EMPTY`. This keeps probe chains short under constant churn.
   - On eviction, remove the victim's key **before** inserting the new one, so the evicting put can reuse the slot. Do the vacant probe after the removal, or redo it if the backward shift moved entries.
   - Because the table always has spare room, the parent's `capacity + 1` pre-sizing trick is no longer needed.
5. **Header.** Replace the `map` field with the table. Store `Box<[u64]>` as a fat pointer and `mask` as `u32`, so `LruCache<u64,u64>` stays at or under the parent's size. `get` becomes: `find`, then `on_hit(idx)`, then return `&nodes[idx].value`.
6. **Tests.** Update the tests that use `cache.map` (`check_segments`, `churn_does_not_resize_map`, and the index lookups `cache.map[&k]`) to use a test-only `index_of(&k)` helper. Add a randomized test that mixes 100k put/get operations over a small key space and checks, after every operation, that every resident key's `find` returns its arena index and that no slot is orphaned.

## Rationale

Five cycles show that get p50 is bound by the map probe and memory, not by hash speed or list work. The open question "map/arena locality and table density" has never been tested. hashbrown buckets hold `(K, u32)`, which is 16 B for u64 keys, plus control bytes. An 8 B slot with an inline hash fragment halves the table footprint. For 131K entries at load ≤0.5 that is 2 MB. Mismatches are rejected without touching the 24 B node, so a hit costs about one table line plus one node line.
