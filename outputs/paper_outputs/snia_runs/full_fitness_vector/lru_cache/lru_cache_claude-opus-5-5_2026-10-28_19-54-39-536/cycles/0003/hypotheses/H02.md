# H02

Replacing v003's generic unlink/push_back pair in `on_hit` with segment-specialised move-to-MRU routines, plus an early return when the hit node is already its segment's MRU, will lower per-op-time (get p50 and put p50) and leave hit rate exactly unchanged.

## Parent

cycle/0002/v003

## Changes

Base: `src/lru_cache/mod.rs` from cycle/0002/v003. Eviction order must stay identical to v003, so hit rate must not change. Keep the node layout and flag encoding as they are.

1. **Early-exit fast path.** At the top of `on_hit(idx)`, read the node's flag once.
   - If the node is protected and `idx == self.prot_tail`, return immediately. It is already protected MRU.
   - If `protected_cap == 0` and `idx == self.prob_tail`, return immediately.
2. **Same-segment move without length or branch overhead.** Add `#[inline] fn move_to_prot_mru(&mut self, idx: u32)` for protected hits. Its precondition is that the node is protected and not the tail, so `next != NIL` is guaranteed:
   - Splice out: if `prev == NIL`, set `prot_head = next`, otherwise set `nodes[prev].set_next(next)`. Then `nodes[next].set_prev(prev)`. No tail check is needed because the node is not the tail.
   - Append: `nodes[prot_tail].set_next(idx)`. Set the node's prev to `prot_tail` while keeping `PROT_BIT`, set the node's next to `NIL`, then set `prot_tail = idx`.
   - Do not touch `prot_len` or `prob_len`, and do not call `set_protected`. Use the same pattern for `move_to_prob_mru` in the `protected_cap == 0` case.
3. **Promotion path.** For probation→protected promotion, replace `unlink` + `push_back(idx, true)` with a direct `promote(idx)`. It splices the node out of the probation list using probation head and tail only, with no `protected` branch. It then appends the node to protected, sets `PROT_BIT` with a single OR that also writes the prev index, and adjusts `prob_len -= 1; prot_len += 1`. Write the demotion that follows as a direct `demote(prot_head)`: splice out from protected head, append at probation tail, and clear the bit. Both paths go through `#[inline(always)]` helpers so the code has no per-call `if protected { .. } else { .. }` selection of head and tail.
4. **Drop dead stores.** In the remaining generic `unlink`, which is still used by eviction, remove `set_prev(NIL)` / `set_next(NIL)`. The `push_back` that always follows overwrites both fields.
5. Put on an existing key keeps calling `on_hit`, so it gets the same fast paths.
6. Keep every existing unit test passing unchanged. Add a test that replays the existing random workload on both the old generic path (keep it under `#[cfg(test)]` as a reference) and the new path, and asserts that both produce identical `check_segments()` output after each operation.

## Rationale (optional)

v003's remaining cost is SLRU branching and relinking on the hit and update paths. On the large cache, most hits land in protected, often on hot keys that are already at or near MRU. Removing the three-way segment selection, the length updates and the redundant stores should cut get and put work without changing policy behaviour. This targets per-op-time cleanly, the way representation-only changes moved metadata cleanly in earlier cycles.
