# H01

Adding a bounded ghost history of keys recently evicted from probation, and admitting a returning ghost key straight into the protected segment, will raise hit-rate above v003, with most of the gain on web_0 at the large size.

## Parent

cycle/0002/v003

## Changes

Base: `src/lru_cache/mod.rs` from cycle/0002/v003 (flag-packed SLRU on `u32` nodes). Do not change the `Node` layout. `Node<u64,u64>` must stay at 24 bytes.

1. Add two fields to `LruCache`: `ghost_set: HashSet<K>` and `ghost_fifo: VecDeque<K>`, plus `ghost_cap: usize`. Set `ghost_cap = max(1, capacity / 2)` in `try_new`. Allocate both containers with `ghost_cap` capacity. The ghost is per-cache state, not per-node, so the metadata-size summary does not change.
2. Eviction path in `put` (new key, arena full): read the victim's segment flag before calling `unlink`. If the victim came from probation (`!is_protected()`), push the clone of `evicted_key` onto the back of the ghost (`ghost_set.insert(k.clone())`, `ghost_fifo.push_back(k)`). Victims taken from protected, which only happens when probation is empty, are not added to the ghost. After each insert, pop from the front while `ghost_fifo.len() > ghost_cap`, and call `ghost_set.remove(&popped)` for each popped key. That remove does nothing if the entry is stale, so stale deque entries cause no harm.
3. Admission in `put` (new-key branch, after a slot is chosen): if `ghost_set.remove(&key)` returns true, insert the node with `push_back(idx, true)` (protected MRU) instead of `push_back(idx, false)`. Then run the same demotion check `on_hit` uses: if `prot_len > protected_cap`, demote `prot_head` to probation MRU. Move that demotion block into a small `#[inline] fn demote_if_over(&mut self)` helper and call it from both places. When `protected_cap == 0` (capacity 1), always insert to probation.
4. Leave `get` exactly as it is. It must not touch the ghost, so get p50 is unaffected.
5. Invariants: `prob_len + prot_len == map.len()`, `prot_len <= protected_cap` after every op, and `ghost_set.len() <= ghost_cap`. No key may be in both `map` and `ghost_set` (step 3 removes the key from the ghost when it is admitted). Add unit tests for: a key that is evicted from probation and then reinserted lands in protected; ghost size stays bounded; and `check_segments` passes under the existing random workload.

## Rationale (optional)

Neither recency segmentation (SLRU) nor small counters (GCLOCK) fixed web_0 at the large size, which points to reuse distances just beyond the probation window. A 2Q-style A1out ghost catches exactly those keys on their second reference. It does this without inflating nodes and without adding cost to the hit path, which the summary per-op-time metric (get p50) measures.
