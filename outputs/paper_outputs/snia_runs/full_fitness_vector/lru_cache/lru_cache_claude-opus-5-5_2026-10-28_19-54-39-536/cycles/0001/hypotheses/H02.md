# H02

Replacing move-to-MRU on hit with CLOCK-style lazy promotion (a hit only sets a reference bit and never relinks the node) will cut get p50 latency below the baseline 34 ns.

## Parent

baseline

## Changes

Rewrite `LruCache` in `src/lru_cache/mod.rs` as a CLOCK (second-chance) cache over the arena. Keep the public API and the `framework::Cache` impl unchanged, and do not touch the JNI file.

- Remove `prev` and `next` from `Node` and add `referenced: bool`. Remove `head` and `tail` from `LruCache` and add `hand: usize`. The arena `Vec<Node>` is now the clock ring in slot order.
- `get(key)`: look the key up in `map`. On a hit, set `nodes[idx].referenced = true` and return `&nodes[idx].value`. Do no unlinking and no pointer writes. This is the core of the hypothesis.
- `put` for an existing key: overwrite the value in place and set `referenced = true`.
- `put` for a new key while `nodes.len() < capacity`: push a new node with `referenced = false`. Fresh inserts get no second chance until they are hit.
- `put` for a new key when the arena is full: run the clock. While `nodes[hand].referenced` is true, clear it and advance `hand = (hand + 1) % capacity`. Use a compare-and-reset, not `%`, if that is faster. When an unreferenced slot is found, remove its key from `map`, overwrite the key and value in place, set `referenced = false`, insert the new key into `map`, and advance `hand` once. The loop ends within one full rotation because each step clears a bit.
- Delete the now-unused `unlink` and `push_back`.
- The `#[cfg(test)]` unit tests in `mod.rs` that encode strict-LRU victim order may be rewritten to assert CLOCK victim order. The P1–P3 invariants must still hold.

## Rationale (optional)

In the baseline, get is a hash lookup plus about six scattered arena writes for unlink and push_back, which also touch neighbouring nodes' cache lines. CLOCK reduces a hit to one lookup and one byte write on the node already loaded. Per-op time (get p50) is the target. Two side effects are expected:

- **Metadata size.** `Node<u64,u64>` should also shrink from 48 bytes to about 24.
- **Hit rate.** CLOCK usually tracks LRU closely, so the hit rate should stay within a few tenths of a point.
