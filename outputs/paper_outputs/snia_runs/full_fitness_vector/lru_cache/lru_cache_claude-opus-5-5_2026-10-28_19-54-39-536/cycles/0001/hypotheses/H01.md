# H01

Splitting the single recency list into a segmented LRU (20% probation, 80% protected), where new keys enter probation and move to protected only on a second hit, will raise the MSR hit-rate summary above the baseline 0.528 by keeping one-touch block scans away from reused blocks.

## Parent

baseline

## Changes

Rewrite `LruCache` in `src/lru_cache/mod.rs` as a two-segment SLRU over the existing arena. Do not touch the JNI file or the public API (`try_new`, `new`, `get`, `put`, the `framework::Cache` impl).

- Add a `segment: u8` (or `bool`) field to `Node` that marks it as probation or protected. Replace the single `head`/`tail` pair with two pairs, `prob_head/prob_tail` and `prot_head/prot_tail`, plus counters `prob_len` and `prot_len`. Generalise `unlink(idx)` and `push_back(idx)` so they use the node's segment to pick which head and tail to update, and so they keep the matching length counter correct.
- Compute `protected_cap = max(1, capacity * 8 / 10)` in `try_new`. When `capacity == 1`, use `protected_cap = 0` so the single slot always stays in probation.
- `get` on a hit: if the node is in probation, unlink it, mark it protected, and push it to the protected MRU. If `prot_len > protected_cap` after that, demote the protected LRU (`prot_head`) to the probation MRU; do not evict it. If the node is already protected, move it to the protected MRU as the baseline does today.
- `put` for an existing key: update the value in place and apply the same promotion as `get`.
- `put` for a new key: insert at the probation MRU. When `nodes.len() >= capacity`, evict the probation LRU (`prob_head`) and reuse its slot, just as the baseline reuses `head`. Fall back to `prot_head` only if probation is empty. Keep slot reuse in place, with no free list.
- Keep the `map.len() <= capacity` debug assertion.
- The `#[cfg(test)]` unit tests in `mod.rs` that assert strict-LRU eviction order (`access_updates_lru_order`, `put_updates_lru_order`, `repeated_get_preserves_eviction_order`, `get_middle_node_promotes_correctly`, `slot_reuse_after_promotion_and_re_eviction`) may be rewritten to assert SLRU order instead. The P1–P3 invariants (capacity bound, value fidelity, no phantoms) must still hold.

## Rationale (optional)

The MSR web_0 and hm_0 traces are block-I/O traces with heavy sequential and one-touch traffic. In strict LRU, every cold block goes straight to MRU and pushes reused blocks out. SLRU is the smallest change that filters on frequency while keeping O(1) operations. Hit rate is the target. `Node` gains one byte, which padding should absorb, so metadata-size should stay flat. get and put take one extra branch.
