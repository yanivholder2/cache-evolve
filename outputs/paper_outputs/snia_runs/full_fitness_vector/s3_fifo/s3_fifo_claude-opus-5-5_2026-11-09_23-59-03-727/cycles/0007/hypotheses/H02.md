# H02

Halving freq on each main-eviction sweep (`freq >>= 1`) instead of decrementing it by one raises hit rate on hm_0 at 16384, because keys that were hot long ago leave main sooner and free space for keys that are hot now.

## Parent

cycle/0006/v003

## Changes

Make one change to `S3Fifo::evict_main` in `src/s3_fifo/mod.rs`. Everything else in cycle-6 v003 stays the same, including the source-tagged ghost and the `freq = 1` credit for main-victim ghost hits.

1. In `evict_main`, in the branch where the popped entry has `freq > 0`, replace `entry.freq -= 1;` with `entry.freq >>= 1;`. Then `main.push_front(i)` as before. The `freq == 0` branch is unchanged: release the entry, and ghost it with `from_main = true` only if `reused` is set.
   - A key at MAX_FREQ 7 now survives 3 sweeps (7→3→1→0) instead of 7. A key at freq 1 or 2 survives exactly 1 sweep, the same as freq 1 does today, so the v003 ghost credit (`freq = 1`) means the same thing.
   - Hits while resident still increment freq by 1 up to MAX_FREQ 7 in `get`, so a key that stays hot rebuilds its count between sweeps.
2. Keep `MAX_FREQ = 7`, the `freq > 1` graduation threshold in `evict_small`, the reset on graduation, and the small share 1/4.
3. This change also lowers the worst-case work per miss in `evict_main`, since each resident can be recycled at most 3 times instead of 7. Do not add any other loop or multi-pop logic.
4. Update the unit tests in `mod.rs`. `main_eviction_uses_frequency_second_chance` should still pass: a key at freq 1 survives once and a key at freq 0 is evicted. Add a test where a main resident at freq 7 is evicted on the 4th sweep that reaches it, with no hits in between. Keep `entry_fits_in_padding` (24 bytes) and `repeated_get_saturates_at_max_freq`.

## Rationale (optional)

The cross-cycle open question says hm_0 at 16384 needs a lever that acts on every main eviction, because ghost-hit mechanisms fire too rarely there. The sweep decrement is that lever. MAX_FREQ 7 gave the only small-cache hm_0 gain so far. However, linear decay lets a key that was hot long ago stay through up to 7 sweeps, and in a 12K-entry main that is a lot of dead residency. Halving keeps the range of the deeper cap for keys that are hit often but ages stale counts out roughly twice as fast, in the style of CLOCK-Pro/LFU aging. The parent is cycle-6 v003 so this can also check whether faster aging offsets v003's slight web_0 cost at 131072, where returning main victims overstayed.
