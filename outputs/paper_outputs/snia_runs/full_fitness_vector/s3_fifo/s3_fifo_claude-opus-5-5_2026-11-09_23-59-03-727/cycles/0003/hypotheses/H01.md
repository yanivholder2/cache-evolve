# H01

Ghosting only main-queue victims that were hit at least once while in main will keep hm_0's main-victim-history gain and recover web_0 hit rate, raising the hit-rate summary above v003.

## Parent

cycle/0002/v003

## Changes

Change exactly one mechanism in `src/s3_fifo/mod.rs`: which main victims get ghosted.

- Add a `reused: bool` field to `Entry<K, V>`. With `K = V = u64` it fits in the padding next to `freq`, so `size_of::<Entry<u64,u64>>()` must stay at 24 bytes. Check this and keep `freq: u8` and `reused: bool` next to each other. `Entry::new` sets `reused = false`.
- In `get()`, set `entry.reused = true` on every hit, along with the existing freq increment. Entries promoted from small to main (in `evict_small`) keep their existing `reused` value: they needed two or more hits to graduate, so it is already true. Entries admitted to main through a ghost hit in `put()` start with `reused = false`.
- In `evict_main()`, when the scan finds a victim with `freq == 0`, call `release(i)`. Then call `push_ghost(key)` only if the victim's `reused` flag was true (read it before releasing). Otherwise drop the key without recording it in the ghost. The second-chance decrement and re-queue logic stays the same.
- `evict_small()` stays the same: small-queue demotees are still always ghosted. The graduation threshold (`freq > 1`), the ghost bound (`ghost_index.len() >= main_size`), lazy deletion and the `retain` compaction are all unchanged. Ghost hits still go straight to main with `freq = 0`.
- Update the in-module `main_victim_is_ghosted` unit test. Have `test_insert` set `reused = true` when it is given `freq > 0`, or add a `reused` parameter. Mark key 4 as reused so the test still asserts that it gets ghosted. Add a test showing that a never-hit main victim is *not* ghosted.

## Rationale (optional)

Cycle 2 concluded that web_0's large-size loss most likely comes from freq-0 keys going through the main-victim ghost and being re-admitted straight into main, where they push out useful residents. This variant isolates that suspect. Keys that were scanned once into main through a ghost hit and never touched again no longer earn a second express ticket. Keys that proved reuse in main still do, which is the case hm_0 rewards. Read it this way: web_0 improving while hm_0 holds confirms the hypothesis, and web_0 staying flat refutes it.
