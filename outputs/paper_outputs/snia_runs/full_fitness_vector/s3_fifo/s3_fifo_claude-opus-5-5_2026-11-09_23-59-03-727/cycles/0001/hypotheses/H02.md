# H02

Recording main-queue victims in the ghost queue (not just demoted small-queue entries) raises hit rate by letting keys evicted from main skip the small queue on their next reference.

## Parent

baseline

## Changes

In `evict_main` (src/s3_fifo/mod.rs), when the second-chance loop reaches a
zero-frequency tail, it currently drops the entry with `break`, discarding the
key. Change that branch to push the victim's key onto the ghost queue before
breaking, using the same bounded-insert logic as `evict_small`: if
`self.ghost.len() >= self.main_size`, `pop_back()` first, then
`push_front(tail.key)`. Factor this into a small helper (e.g.
`fn push_ghost(&mut self, key: K)`) and call it from both `evict_small`'s
demote branch and `evict_main`'s victim branch.

The rest of `put` is unchanged: a ghost hit is removed from the ghost queue
and admitted at the main-queue front (running `evict_main` first if main is
full). Graduation threshold, second-chance decrement, and the small/main
partition are untouched. Invariants to preserve: `ghost.len() <= main_size`;
a key is never simultaneously in ghost and in small/main (the victim is
already popped from main when it is ghosted, and `put` removes the key from
ghost when re-admitting); `small.len() + main.len() <= capacity`.

## Rationale (optional)

In the baseline, a key that graduated to main and later ages out loses all
history, so its next reference enters the small queue and must prove itself
again — on MSR block traces with long, repeating reuse distances (hm_0's 0.73
hit rate at 131072 suggests a large recurring working set) this costs a
probation period and risks a second demotion. Ghosting main victims turns
the ghost into a broader "recently resident" history, closer to the
ARC/2Q-style ghost behaviour. Per-op time may rise slightly because the ghost
`iter().any` scan in `put` sees more churn, but its length bound is unchanged.
