# H03

Adapting the small/main split online from ghost-hit and main-reinsertion signals raises hit rate across both cache sizes by letting each trace find its own admission-window size.

## Parent

baseline

## Changes

In `S3Fifo` (src/s3_fifo/mod.rs), make `small_size` mutable at runtime
instead of fixed at construction. Add fields `capacity: usize` and
`min_small: usize`/`max_small: usize` (e.g. `max(1, capacity/100)` and
`capacity/2`, both clamped so `main_size >= 1` when `capacity > 1`), and
keep `main_size = capacity - small_size` derived after every adjustment.
Initial `small_size` stays at the baseline `capacity/4`.

Adjustment rules (step `delta = max(1, capacity / 1000)`):
- In `put`, on a ghost hit (key found in ghost): the small queue was too
  short to catch that reuse, so `small_size = min(small_size + delta, max_small)`.
- In `evict_main`, each time the loop pops a tail whose `freq > 0` and
  reinserts it (second chance granted): main is holding useful entries, so
  `small_size = max(small_size - delta, min_small)`. Apply this at most once
  per `evict_main` call to avoid over-reacting to long reinsertion runs.

Because sizes change, enforce the bound lazily: before pushing into small,
loop `while self.small.len() >= self.small_size { self.evict_small() }`;
before pushing into main (both ghost re-admit and graduation), loop
`while self.main.len() >= self.main_size && !self.main.is_empty() { self.evict_main() }`.
If small is over its new target but main has room, that is fine — the
invariant that must hold after every `put` is `small.len() + main.len() <= capacity`;
if a resize leaves the total over capacity, evict from whichever queue is
over its target until the total fits. Ghost queue capacity stays fixed at
the initial `main_size` (do not resize it, to keep ghost behaviour stable).
Keep `capacity == 1` behaviour identical to baseline (no adaptation).

## Rationale (optional)

web_0 and hm_0 have very different reuse structure, and the fixed 25% split
is unlikely to be right for both at 16K and 131K. Ghost hits are direct
evidence of reuse distances just beyond the small window (grow it);
second-chance reinsertions in main are evidence main holds a hot working set
worth protecting (shrink small). This is ARC-style partition adaptation
applied to S3-FIFO's queue movement, and is distinct from picking a new
fixed ratio or changing what gets ghosted.
