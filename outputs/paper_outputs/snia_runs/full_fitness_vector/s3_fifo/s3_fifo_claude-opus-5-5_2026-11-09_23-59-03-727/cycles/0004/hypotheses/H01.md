# H01

Merging cycle-3's two filters (reset freq on graduation and ghost only main victims that were reused) into the Fx-hashed incumbent will raise the hit-rate summary above 0.5446 while keeping per-op-time near 30.

## Parent

cycle/0003/v003

## Changes

Start from cycle/0003/v003 (`src/s3_fifo/mod.rs`: slab + Fx-hashed `index`/`ghost_index`). Port exactly two policy edits from the other cycle-3 Winners and change nothing else:

1. **Reuse-gated main-victim ghosting (from cycle/0003/v001).** Add `reused: bool` to `Entry<K, V>` after `freq`. It must fit in the existing padding, so `size_of::<Entry<u64,u64>>()` stays 24. Add a unit test asserting this. `Entry::new` sets `reused = false`. In `get()`, set `entry.reused = true` next to the freq increment. In `evict_main()`, in the `else` (freq == 0) branch, read `reused` before `release(i)`, then call `push_ghost(key)` only when `reused` is true. Otherwise drop the key with no ghost. `evict_small()` keeps ghosting every small demotee without a gate.
2. **Freq reset on graduation (from cycle/0003/v002).** In `evict_small()`, in the `freq > 1` branch, set `self.slab[i].freq = 0` after the possible `evict_main()` call and before `self.main.push_front(i)`. Also set `reused = false` at the same point. This way the gate in (1) only counts reuse that happens inside main, which matches the meaning of the reset. Keep the graduation threshold at `freq > 1`. Ghost-hit re-admissions into main still go through `alloc`, which yields freq 0 and reused false.

Leave these unchanged: `push_ghost` (bound `ghost_index.len() >= main_size`, compaction at `2 * main_size`), the small/main split (`capacity / 4`), `MAX_FREQ = 3`, and the FxHasher. Update `test_insert` to set `reused = freq > 0`. Update the existing `main_victim_is_ghosted` test so the victim is marked reused, using a `test_set_reused` helper as in cycle/0003/v001. Add one test checking that an unreused main victim is not ghosted.

## Rationale

Cycle 3 showed that the two filters act on different mechanisms (ghost-slot budget vs. carried-over freq), and neither one cost web_0 anything. The cycle-3 insight calls for this merge before any new probe. Per-trace hit rates should come out at or above the better of v001 and v002 on each of the four points. If they don't, the two effects interact rather than add.
