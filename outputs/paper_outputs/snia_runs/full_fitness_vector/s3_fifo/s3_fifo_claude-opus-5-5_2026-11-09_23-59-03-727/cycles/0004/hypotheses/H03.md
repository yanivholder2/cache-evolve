# H03

Merging the resident index and the ghost index into a single Fx-hashed map lowers per-op-time below 30 ns by reducing hash probes per miss and per ghost hit from three to two, while keeping hit rates bit-identical.

## Parent

cycle/0003/v003

## Changes

This is a purely structural change to cycle/0003/v003 (`src/s3_fifo/mod.rs`). Every policy decision must stay identical, and the four per-trace hit rates must match v003 exactly.

- Replace the two maps `index: HashMap<K, u32, FxBuild>` and `ghost_index: HashMap<K, u64, FxBuild>` with one map `index: HashMap<K, Slot, FxBuild>`. Define `#[derive(Clone, Copy, PartialEq, Eq, Debug)] enum Slot { Resident(u32), Ghost(u64) }`, where the `u64` is the ghost seq. Add a counter `ghost_live: usize` to stand in for `ghost_index.len()`. Size the map at `capacity + main_size`.
- `get()`: return the value only for `Some(Slot::Resident(i))`. `Ghost` and absent keys both return `None`.
- `put()`: do one `self.index.get(&key).copied()` probe, then branch:
  - `Resident(i)`: update the value.
  - `Ghost(_)`: the order has to match today's code, where `ghost_index.remove` runs before `evict_main()`. So first, in the same probe via `get_mut`, overwrite the value with a pending marker `Slot::Resident(u32::MAX)` and decrement `ghost_live`. The key's stale deque tuple then no longer counts as live, and the bound check inside a following `evict_main()` sees the same live count it sees today. Next, do any needed `evict_main()`. Then place the entry in the slab without touching the map, and fix up the value to `Resident(i)` with one more `get_mut`. That makes 2 probes instead of 3. Split `alloc` into `slab_alloc` (slab only) and an indexing step. Do not hold a map reference across `evict_main()`, because it mutates the map. `get()` and the test helpers never see the `u32::MAX` marker, because it is fixed up within the same `put`.
  - absent: run the existing small path and `insert(key, Resident(i))`.
- Eviction to ghost (`evict_main` freq==0 and `evict_small` demotion): replace `release` + `push_ghost` with an in-place transition, setting the key's map value to `Ghost(seq)` via `get_mut` (one probe instead of remove + insert). Free the slab slot, push `(key, seq)` to the ghost deque, and increment `ghost_live`. Keep the bound exactly as it is now: before transitioning, if `ghost_live >= main_size`, pop from the back of the deque until a tuple with `index.get(k) == Some(&Slot::Ghost(s))` is found, remove that key from the map, and decrement `ghost_live`. To keep behaviour identical, do this bound check before pushing the new ghost, the same order as today.
- Compaction: when `ghost.len() > 2 * main_size`, `retain` tuples where `index.get(k) == Some(&Slot::Ghost(*s))`.
- Test helpers: `in_ghost` becomes a check for `Slot::Ghost`. The capacity test counts `Resident` slots, and the disjointness test becomes a check that every key in the deque that is live is `Ghost`, with `ghost_live <= main_size`.

`Entry<u64,u64>` stays 24 bytes. The struct gets smaller because one map is removed.

## Rationale

The only timing gains so far that their diffs explain came from structural changes (slab+hash, Fx hasher). The cycle-3 continuation names cutting hash probes per miss as the next one. On the trace-replay hot path (get miss → put), the current code probes `index`, then `ghost_index`, then `index` again, and each eviction to ghost does a remove and an insert across two tables. A unified map halves those probes and touches one table's cache lines instead of two.
