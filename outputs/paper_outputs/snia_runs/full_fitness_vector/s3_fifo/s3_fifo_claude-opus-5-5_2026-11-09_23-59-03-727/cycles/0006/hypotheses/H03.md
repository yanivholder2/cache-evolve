# H03

Re-admitting keys that hit a main-victim ghost into main with `freq = 1`, while small-demotee ghost hits keep `freq = 0`, raises hm_0 hit-rate at 16384 by giving proven-reuse keys one survived sweep.

## Parent

cycle/0005/v002

## Changes

Tag each ghost record with its source so that `put` can tell main victims from
small demotees on a ghost hit:

- Change `push_ghost(&mut self, key: K)` to
  `push_ghost(&mut self, key: K, from_main: bool)`. Encode the source in the
  low bit of the stored sequence:
  `let tag = (self.ghost_seq << 1) | from_main as u64; self.ghost_seq += 1;`.
  Push `(key, tag)` to `ghost` and insert `tag` into `ghost_index`. The liveness
  checks (`ghost_index.get(&k) == Some(&s)`) in both the bounded pop loop and
  the `retain` compaction compare the full tagged value and stay correct
  without changes.
- In `evict_main()`, call `push_ghost(key, true)` (still only when `reused`).
  In `evict_small()`, call `push_ghost(key, false)`.
- In `put()`, change the ghost-hit branch from
  `if self.ghost_index.remove(&key).is_some()` to
  `if let Some(tag) = self.ghost_index.remove(&key)`. After `alloc` and
  `push_front` into main, if `tag & 1 == 1` set `self.slab[i].freq = 1`.
  Leave `reused = false`, so the key must still be hit inside main again before
  it can be re-ghosted. Small-demotee ghost hits keep `freq = 0` as today.

Everything else stays the same: `MAX_FREQ = 7`, small share 1/4, the ghost bound
`main_size`, the `freq > 1` graduation threshold, and the reset at graduation.
`Entry` stays 24 bytes. Update the `main_victim_is_ghosted` test, or add a new
one, to assert that the key re-admitted after a main-victim ghost hit has
`freq == 1`, and that a key re-admitted from a small-demotee ghost has
`freq == 0`.

## Rationale (optional)

hm_0 is driven by main retention, and the gains still available sit at the
small cache size. A main-victim ghost hit is the strongest reuse signal the
cache has: the key was reused in main, evicted, and then requested again.
Today such a key re-enters main with zero credit and can be the very next
victim. Limiting the credit to main-victim ghosts keeps web_0's unproven
small-demotee re-admissions from pushing out live residents.
