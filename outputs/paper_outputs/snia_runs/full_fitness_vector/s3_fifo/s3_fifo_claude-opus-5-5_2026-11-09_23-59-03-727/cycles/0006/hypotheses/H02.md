# H02

Giving each small-queue key with exactly one hit a single reinsertion into small, instead of demoting it, raises web_0 hit-rate by extending probation only for keys that have already shown reuse.

## Parent

cycle/0005/v002

## Changes

Add one field `extended: bool` to `Entry`, initialised to `false` in
`Entry::new`. With `u64` keys and values the struct still fits in 24 bytes
(8 + 8 + u8 + bool + bool, padded), so the `entry_fits_in_padding` test must
still assert 24.

Rewrite `evict_small()` as a loop that always ends by freeing exactly one
small slot:

- Pop the tail index `i` from `small`.
- If `freq > 1`, graduate it exactly as today: evict from main if main is
  full, reset `freq = 0` and `reused = false`, also set `extended = false`,
  push it to the front of `main`, and return.
- Else if `freq == 1 && !extended`, set `extended = true`, keep `freq = 1`
  (one more hit makes it `2` and lets it graduate at its next turn at the
  tail), push `i` back to the front of `small`, and `continue` the loop.
- Otherwise (`freq == 0`, or already extended), release it and `push_ghost`
  its key as today, then return.

The loop terminates because each entry can be extended at most once per
residency, so after at most `small.len()` pops some entry graduates or is
demoted. The graduation threshold stays `freq > 1`, so freq-1 keys never enter
main directly. This avoids cycle 2's `freq >= 1` regression. Everything else is
unchanged: `MAX_FREQ = 7`, small share 1/4, the ghost bound, and the main-victim
reuse gate. `alloc` must reset `extended` through `Entry::new`, and the
ghost-hit path that puts keys straight into main needs no change. Add an inline
test: in a capacity-4 cache, put key 1, `get` it once, then fill small so that
1 reaches the tail. It must still be resident in small (not in ghost) after the
first eviction pass, and it must graduate to main if it gets one more hit
before its next tail visit.

## Rationale (optional)

web_0's large-size gap is a probation-window problem. Enlarging small (H01)
lengthens probation for every key, including one-hit wonders. This change
lengthens it only for keys that already have one hit, so it tests the
"easier graduation inside probation" branch of the open question as a separate
mechanism.
