# H01

Shrinking the small (probation) queue from `capacity / 4` to `capacity / 10` on the two-filter parent raises hit rate, mainly by closing web_0's large-size gap.

## Parent

cycle/0004/v001

## Changes

This changes one variable in `S3Fifo::try_new` in `src/s3_fifo/mod.rs`. Replace the small-queue sizing expression
`(capacity / 4).max(1).min(capacity - 1)` with
`(capacity / 10).max(1).min(capacity - 1)`. That matches the 10% small queue from the S3-FIFO paper. Keep the `capacity == 1` special case and `main_size = capacity - small_size`, so main grows from 75% to about 90% of capacity.

Everything else stays byte-for-byte the same as cycle/0004/v001:
- Fx hasher, slab and indexes.
- The `freq > 1` graduation threshold in `evict_small`.
- The freq/reused reset on graduation.
- Reuse-gated main-victim ghosting in `evict_main`.
- `MAX_FREQ = 3`.
- The ghost live bound `ghost_index.len() >= self.main_size`, and the `2 * main_size` compaction trigger.

Note that the ghost bound follows `main_size`, so it rises automatically to about 90% of capacity. That is still within the "≤ main_size" rule. Do not decouple it. The ghost bound tracking main is part of the experiment.

Update the `VecDeque::with_capacity` hints so they follow the new sizes. The existing in-file unit tests use tiny capacities (4, 5, 8). With integer division, `capacity / 10` gives 0, which clamps to 1, so the small queue holds 1 entry at those capacities. Check every test that depends on small-queue occupancy, such as `ghost_hit_promotes_back_to_main` with capacity 4, which previously had small = 1. Each should still pass. Adjust a test's setup only if its intent is preserved. Do not weaken the assertions.

## Rationale (optional)

Cross-cycle insights name the small-queue share as the last untested candidate for web_0's large-size loss. The 10% split from cycle 1 was neutral, but it ran on the unfiltered baseline, where a larger ghost and main let stale freq-0 reuse back in. The cycle-4 filters now keep main free of unreused keys, so the extra main space should hold genuinely reused keys. That favours hm_0 as well. If web_0 regresses, the probation window is confirmed as web_0's limiting factor, which is the opposite conclusion and still informative.
