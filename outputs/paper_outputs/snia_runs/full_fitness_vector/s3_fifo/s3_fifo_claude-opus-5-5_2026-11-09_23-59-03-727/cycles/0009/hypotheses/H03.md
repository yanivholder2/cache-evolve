# H03

Replacing the main queue's pop_back/push_front reinsertion sweep with an equivalent in-place CLOCK hand over a fixed `Vec<u32>` ring will lower `put` p99 (per-op-time) while leaving hit rate bit-identical.

## Parent

cycle/0005/v002

## Changes

This is a pure implementation change in `src/s3_fifo/mod.rs`, and the eviction order must match the parent exactly. FIFO-with-reinsertion is equivalent to CLOCK: popping the oldest entry, decrementing it, and re-pushing it as newest is the same as decrementing it in place and moving a hand forward.

- Replace `main: VecDeque<u32>` with `main: Vec<u32>`, preallocated with `with_capacity(main_size)`, and add `main_hand: usize`, starting at 0.
- **Fill phase** (`main.len() < main_size`): new main entries are pushed with `main.push(i)`. While the ring is not full, the hand stays at 0, so index 0 is the oldest entry and the end of the vector is the newest. This matches the parent's `push_front` order (back = oldest).
- **Invariant:** once `main` reaches `main_size` it never shrinks. In the parent, `evict_main` is only ever called right before a push into main, on both the ghost-hit path in `put` and the graduation path in `evict_small`. Make that explicit by replacing `evict_main()` plus `main.push_front(i)` with a single `main_replace(i)`:
  - If `main.len() < main_size`, push `i` and return.
  - Otherwise loop on `slot = main[main_hand]`. If `slab[slot].freq > 0`, decrement it and set `main_hand = (main_hand + 1) % main_size`; use a compare-and-reset instead of `%`. If the freq is 0, this is the victim. Run the parent's victim logic (read `reused`, `release(slot)`, and `push_ghost(key)` if `reused`), then write `main[main_hand] = i` and advance the hand by one. The new entry sits just behind the hand, which is the newest position, exactly like the parent's `push_front`.
- Keep the order of side effects the same as in the parent. The victim is released and ghosted before `alloc` for the new key on the ghost-hit path. In `put`, call `main_replace` with a freshly allocated slot only after the victim's release, so the free-list reuse pattern and the ghost state are unchanged. On the ghost-hit path, do the eviction step first, then `alloc`, then write the slot. Split `main_replace` into `main_make_room() -> Option<usize /*position*/>` and `main_place(pos, i)` if needed to preserve this order.
- Update the `#[cfg(test)]` helpers. `in_main` iterates the `Vec`. `test_insert(.., into_main = true, at_back)` must place the entry so that `at_back = true` means "oldest", which is the position at `main_hand` or index 0 during fill. Do this by inserting at `main_hand` with `Vec::insert` (test-only cost), and `push` for `at_back = false`. `main_eviction_uses_frequency_second_chance` and `main_victim_is_ghosted` must pass with unchanged assertions. `capacity_bound_never_exceeded` should use `main.len()` as before.

Do not touch the small queue, the ghost structures, `MAX_FREQ`, or any thresholds.

## Rationale

Cycles 5 and 8 attributed `put` p99 rises to longer second-chance sweeps. Each sweep step currently does a `VecDeque` `pop_back` and `push_front`, which means two head/tail updates and a write to a different cache line. CLOCK makes each step a read, a slab decrement and a hand increment, with the victim slot overwritten in place. The number of sweep steps is unchanged, but each step is cheaper, so this targets the "sweep steps per miss" tail driver without touching hashing. That makes it independent of H02.
