# H02

Collapsing the get-then-remove and get-then-insert hash probe pairs on the miss path into single `entry()` probes will lower `put` p99 (per-op-time) while leaving hit rate bit-identical.

## Parent

cycle/0005/v002

## Changes

This is a pure implementation change in `src/s3_fifo/mod.rs`. Policy decisions must stay identical to the parent, so all four hit-rate cells should reproduce exactly. Import `std::collections::hash_map::Entry as MapEntry`, renamed so it does not clash with the crate's own `Entry<K, V>`.

1. **`push_ghost` eviction loop.** The parent pops `(k, s)` from `ghost.pop_back()`, then calls `ghost_index.get(&k) == Some(&s)` and, if live, `ghost_index.remove(&k)`. That is two probes for each live victim. Replace it with a single `match self.ghost_index.entry(k)`. On `Occupied(e)` where `*e.get() == s`, call `e.remove()` and `break`. Otherwise (a stale tuple, either `Vacant` or `Occupied` with a different seq) continue the loop. One hash per popped tuple.
2. **`push_ghost` insert.** Keep `self.ghost_index.insert(key, seq)` as one probe. Remove the redundant `key.clone()` by pushing `(key.clone(), seq)` into the deque only once and moving `key` into the index. This is already the parent's shape, so verify that no extra clone was introduced.
3. **`put` resident check plus `alloc` insert.** The resident `index.get(&key)` miss and the later `index.insert(key, i)` in `alloc` are separated by eviction, which mutates `index`. They therefore cannot share one `entry()` borrow. Leave them as they are, and do not hold a map borrow across `evict_*`.
4. **`put` resident hit.** Replace `if let Some(&i) = self.index.get(&key)` with `if let Some(&mut i) = self.index.get_mut(&key)` only if it compiles cleanly without borrow conflicts. Otherwise leave it as it is. This is optional and must not add probes.

Do not change the `retain` compaction at `2 * main_size`, the ghost bound, or any data-structure type or capacity. Keep all in-file tests passing unchanged.

## Rationale

The cycle 7 ring ghost and the cycle 8 fingerprint ghost showed that the `put` tail tracks the number of hash probes per miss, not footprint or container shape. Every main or small eviction that ghosts a key past the live bound currently costs two `ghost_index` probes for the expired ghost. This change removes one of them per ghosting, without adding hashing anywhere else. If p99 does not move, probe count on the ghost-expiry path is not the tail driver, and the remaining candidate is the eviction sweep (see H03).
