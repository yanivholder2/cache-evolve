# H03

Keying the ghost index and ghost FIFO by a 32-bit hash fingerprint instead of the full key shrinks the ghost tables and removes key clones on the miss path, cutting per-op time.

## Parent

cycle/0005/v002

## Changes

This is a structural change to ghost bookkeeping in `src/s3_fifo/mod.rs`. Policy decisions stay the same apart from rare fingerprint collisions.

1. Add a helper `fn fingerprint(key: &K) -> u32`. It hashes `key` with a fresh `FxHasher` (`key.hash(&mut h)`), takes `let x = h.finish();`, and returns `((x >> 32) ^ x) as u32`. Hash a key at most once per `put` miss, and reuse that one value for both the ghost lookup and any later `push_ghost` of the same key.
2. Change the field types:
   - `ghost: VecDeque<(K, u64)>` becomes `ghost: VecDeque<(u32, u32)>` (fingerprint, seq).
   - `ghost_index: HashMap<K, u64, FxBuild>` becomes `ghost_index: HashMap<u32, u32, FxBuild>`.
   - `ghost_seq` becomes a `u32` that increments with `wrapping_add(1)`.
   Liveness stays "a tuple is live iff `ghost_index[fp] == seq`". Seq wraparound is safe because the deque is compacted whenever it exceeds `2 * main_size` entries, which is far below 2^32.
3. In `put()`, replace `self.ghost_index.remove(&key)` with `self.ghost_index.remove(&fingerprint(&key))`. Leave the ghost-hit → main branch as it is.
4. Change `push_ghost` to take `fp: u32` instead of `K`. Callers compute it before `release()`:
   - `evict_small` already has the key, so it passes `fingerprint(&key)` after `release` returns the key.
   - `evict_main` also passes `fingerprint(&key)`, but only when `reused` is set.
   Drop the `key.clone()` in `push_ghost`. The live bound check (`ghost_index.len() >= main_size`), the pop-oldest-live loop, and the `retain` compaction at `2 * main_size` all stay as they are, now over `(u32, u32)` tuples.
5. Remove `release()`'s returned key in any caller that does not need it. `release()` still removes the key from `index` and pushes the slot onto `free`.
6. Update the in-file tests:
   - `in_ghost(&self, key)` should check `ghost_index.contains_key(&Self::fingerprint(key))`.
   - `ghost_live_bound_and_disjoint_from_resident` should check disjointness through fingerprints.
   - The `ghost.len() <= 2 * main_size` and `ghost_index.len() <= main_size` assertions must still hold.

`Entry` stays 24 bytes. The resident `index` is untouched. Fingerprint collisions are possible (on the order of `main_size / 2^32` per lookup) and only cause a rare spurious ghost hit. Expect hit rate to match the parent to roughly 4 significant digits.

## Rationale (optional)

Cycles 5 and 7 found that the `put` tail is driven by memory footprint and probes per miss, not by amortized cleanup. "Shrink the ghost index first" is the open timing direction no cycle has tried. Each ghost slot shrinks from (K + u64) to 8 bytes in both the deque and the hash table. For `u64` keys that halves both. The change also drops one `K` clone per ghosting and lets the compaction `retain` work over a denser array. The container shape and probe count stay as they are, unlike cycle-7 v003's ring and cycle-4 v003's merged index, which both lost. Only the bytes touched per probe change.
