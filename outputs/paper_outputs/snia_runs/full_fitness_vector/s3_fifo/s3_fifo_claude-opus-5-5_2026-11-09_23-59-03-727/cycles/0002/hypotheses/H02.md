# H02

Lowering the small-to-main graduation threshold in v001's 10% small-queue configuration from `freq > 1` to `freq >= 1` raises hit rate on web_0 at 131072, because one re-reference during the short probation window is enough to promote a key and it no longer gets demoted to the ghost queue.

## Parent

cycle/0001/v001

## Changes

All edits are in `src/s3_fifo/mod.rs`, starting from v001's overlay (10% small queue, ghost bounded by `main_size`).

1. In `evict_small`, change the promotion test on the popped tail from `tail.freq > 1` to `tail.freq >= 1`. A tail with freq 0 is still pushed to the ghost queue. A tail with freq ≥ 1 is promoted to the front of main, running `evict_main()` first if `main.len() >= main_size`.
2. On promotion, reset the entry's frequency before pushing it into main (`tail.freq = 0;` right before `self.main.push_front(tail)`). Main residency then has to be earned by hits that happen inside main, which matches the S3-FIFO reference implementation. This stops a single small-queue hit from also buying a free second-chance pass in `evict_main`.
3. Update the in-file tests whose expectations depend on the old threshold, such as `small_eviction_promotes_to_main_after_multiple_hits` and `main_eviction_uses_frequency_second_chance`, so they still check the intended behaviour under `>= 1`. Do not touch anything under `tests/`.

Leave everything else as in v001: 10% small queue, ghost re-admission straight into main with freq 0, the second-chance loop in `evict_main`, and `MAX_FREQ = 3`. Invariants: `small.len() + main.len() <= capacity`, and a key lives in at most one of small, main, or ghost.

## Rationale (optional)

The v001 insight puts the web_0@131072 loss down to the 10% probation window being too short: entries reach the ghost queue before their second reference. Under the current `freq > 1` rule, a key needs two hits while in small to graduate, which is a very strict filter for a window that small. With a one-hit threshold, the short window still filters one-hit wonders while letting keys with a single reuse graduate. That should recover web_0@131072 and keep v001's hm_0 gains. Resetting freq on promotion keeps main from filling up with keys that were reused only once. The change is a single comparison plus one store, so v001's per-op-time profile should hold.
