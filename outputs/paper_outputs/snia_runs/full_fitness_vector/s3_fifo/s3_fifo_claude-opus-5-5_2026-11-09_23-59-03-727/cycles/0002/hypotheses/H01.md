# H01

Splitting v002's single ghost queue into two separately bounded ghost regions, one for small-queue demotees at the original `main_size` bound and one for main-queue victims, raises hit rate by keeping v002's hm_0 gain without crowding out the demotee history that web_0 at 131072 depends on.

## Parent

cycle/0001/v002

## Changes

All edits are in `src/s3_fifo/mod.rs`, starting from v002's overlay.

1. Rename the field `ghost: VecDeque<K>` to `ghost_small: VecDeque<K>` and add `ghost_main: VecDeque<K>` and `ghost_main_size: usize` to `S3Fifo`. In `try_new`, set `ghost_main_size = (main_size / 2).max(1)` and pre-allocate both deques: `ghost_small` with `main_size` and `ghost_main` with `ghost_main_size`. Leave the small/main split at the baseline 25%/75%.
2. Replace `push_ghost` with two helpers:
   - `push_ghost_small(key)`: if `ghost_small.len() >= main_size`, `pop_back()`; then `push_front(key)`. This matches the baseline's bound exactly.
   - `push_ghost_main(key)`: the same logic against `ghost_main_size`.
   `evict_small`'s demote branch calls `push_ghost_small`. `evict_main`'s zero-frequency victim branch calls `push_ghost_main`.
3. In `put`, look the key up in `ghost_small` first, then in `ghost_main`. On a hit in either region, remove the key from that deque with `retain`, run `evict_main()` if `main.len() >= main_size`, and push the new entry to the front of main with freq 0. A miss in both regions goes to the small queue as before.
4. Update the in-file test `main_victim_is_ghosted` to check `ghost_main` instead of `ghost`. Rename any other in-file references to `ghost`.

Invariants to keep:
- `ghost_small.len() <= main_size` and `ghost_main.len() <= ghost_main_size`.
- A key is never in a ghost region and in small/main at the same time, and never in both ghost regions. A key is ghosted only after it has been popped from a resident queue, and a ghost hit removes it.
- `small.len() + main.len() <= capacity`.

`Entry` stays 24 bytes. `S3Fifo` gains one `VecDeque` and one `usize`.

## Rationale (optional)

The cycle-1 analysis found that v002 shrank the ghost space for small-queue demotees because main victims competed for the same `main_size` slots. That is the likely cause of its web_0@131072 and hm_0@16384 losses. With two regions, the baseline's demotee history stays exactly as it was, and main-victim history becomes extra capacity instead of a replacement. If hit rate beats v002 on web_0@131072 while holding hm_0@131072, the coupling explanation is confirmed. If not, main-victim ghosting itself is the problem. Ghost lookups now scan up to 1.5× as many keys, so per-op-time may rise a little.
