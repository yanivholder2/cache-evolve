**File:** `overlay/src/s3_fifo/mod.rs` (based on v002's overlay)

The eviction rules are unchanged from v002. Only the data structures behind them changed:

- **Bounds:** The struct and inherent impl now require `K: Eq + Hash + Clone`.
- **Entry storage:** Entries now live in one array, with freed slots kept on a free list for reuse. `Entry` itself is unchanged, so it stays 24 bytes for `u64`/`u64`. The small and main queues now hold slot numbers (`u32`) instead of entries. Moving an entry between queues, or giving it a second chance in main, only moves that number.
- **Resident lookup:** A hash map from key to slot covers both queues. `get` and the resident check in `put` are now one hash lookup instead of a linear scan. When a key is evicted, it is removed from the map and its slot goes back on the free list. The key is cloned rather than moved out, so no `V: Default` bound is needed.
- **Ghost lookup:** The ghost queue now stores each key with a sequence number, and a second hash map records the current number for each ghosted key. A ghost hit in `put` just removes the key from that map. Its old queue record stays behind and is ignored later, which keeps "is this key a ghost?" to one lookup instead of a scan.
  - When the ghost is full (live count at least `main_size`), the oldest still-valid key is dropped, which is the same choice v002 makes.
  - The queue is cleaned of ignored records once it grows past `2 * main_size`.
- **Capacity:** `try_new` pre-allocates all the new storage. It also rejects capacities that don't fit in `u32`; v002 had no such check, but it doesn't matter at any capacity actually used.
- **Tests:** The three tests that reached into the queues directly now go through `#[cfg(test)]` helpers (`test_insert`, `in_main`, `in_ghost`). I also added two checks beyond the hypothesis:
  - The capacity test now also checks that the key map has exactly as many entries as the two queues hold.
  - A new test checks that the ghost never holds more than `main_size` live keys and that no key is both resident and a ghost.

Nothing under `tests/` or in the other pinned files was touched.

The eviction, promotion and ghost decisions should match v002 step for step, so hit rate should equal v002's 0.541575. v002 has a quirk at capacity 1 (its ghost holds one key even though `main_size` is 0), and I kept that unchanged on purpose.
