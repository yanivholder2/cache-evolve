# H03

Sending freq ≥ 1 ghost returnees whose ghost age exceeds half the ghost capacity back to small with freq 1, rather than straight into main, raises hit-rate on web_0 by keeping late one-off rereferences out of main.

## Parent

cycle/0005/v002

## Changes

In v002's `src/s3_fifo/mod.rs`, add an age ceiling to the freq-based branch of the ghost→main gate. v002 put an age floor on the freq-0 branch; this does the mirror image on the freq ≥ 1 branch:

- Add `const GHOST_STALE_AGE_DIVISOR: usize = 2;` and a helper `fn ghost_stale_age(&self) -> u64 { (self.main_size / GHOST_STALE_AGE_DIVISOR).max(1) as u64 }`. `main_size` is the ghost's live capacity, so this is half the ghost window.
- In `put`, compute `age = self.next_stamp - stamp` once. Change the strong-returnee guard to:
  `(freq >= GHOST_TO_MAIN_FREQ && age <= self.ghost_stale_age()) || age <= recent`
  - Recent returnees still go to main whatever their freq, as in v002.
  - Freq ≥ 1 returnees older than half the ghost window now take the existing weak arm. That arm removes the ghost record, evicts from small if full, re-admits into small with `GHOST_RETURN_SMALL_FREQ` (1), and on a single further reuse graduates under the main-full freq ≥ 2 rule.
- No other code paths change. If a stale freq-1 returnee is ghosted again from small without a hit, it carries freq 1, so a later quick return still reaches main.
- Update the `Reference` oracle's ghost branch to the same condition (`main_size / GHOST_STALE_AGE_DIVISOR`, max 1).
- Add a unit test: a key ghosted with freq 1 whose age is pushed past `ghost_stale_age()` lands in small with freq 1 on `put`.
- Existing tests at capacity 4 have `main_size` 3, so the stale age is 1. Check `small_tail_with_single_hit_goes_to_ghost_when_main_full` and `ghosted_with_freq_one_returns_into_main`: both return at age 1, so they should still go to main. Adjust filler puts where needed.
- `hit_miss_identical_to_linear_reference` must pass.

## Rationale

The cross-cycle notes describe web_0 as dominated by exactly-twice keys and late one-off rereferences, which punishes lenient admission. Every ghost-path change so far has only re-routed freq-0 returnees. Freq-1 returnees still enter main unconditionally, no matter how long they have been in the ghost. Main stays full, so each such admission displaces a resident. Filtering these keys in small instead of at main admission follows the "filter in small, not main" pattern that has worked before. The window scales with `main_size`, so the test can also reach web_0 @ 131072. This tightens admission, the opposite direction to H01 and H02.
