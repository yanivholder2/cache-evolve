# H02

Widening the freq-0 ghost-returnee recency window from one to two small-queue turnovers raises hit-rate on hm_0 at both cache sizes, because more of its squeezed-out real reuses go straight to main.

## Parent

cycle/0005/v002

## Changes

In v002's `src/s3_fifo/mod.rs`, change the recency window from a divisor to a multiplier and set it to 2:

- Replace `const GHOST_RECENT_AGE_DIVISOR: usize = 1;` with `const GHOST_RECENT_AGE_MULTIPLIER: usize = 2;`.
- Change `ghost_recent_window()` to return `(self.small_size * GHOST_RECENT_AGE_MULTIPLIER).max(1) as u64`.
- Since `ghost_live <= main_size = 3 * small_size`, the new window covers the youngest two-thirds of the ghost. The gate still filters freq-0 returnees older than that.
- Leave everything else unchanged: the strong-returnee condition (`freq >= GHOST_TO_MAIN_FREQ || next_stamp - stamp <= recent`), the weak path back into small with freq 1, graduation thresholds and main eviction.
- Update the `Reference` oracle so its `recent` uses the same formula.
- Fix unit tests that depend on the window size. With capacity 4, the window becomes 2. In `old_freq_zero_ghost_returnee_goes_to_small_with_freq_one`, `weak_ghost_returnee_lands_in_small_then_graduates_after_one_get` and `weak_ghost_returnee_reghosted_with_freq_one`, add one more filler `put` so the key's age exceeds 2 before it returns. Keep `ghost_hit_promotes_back_to_main` correct: age 3 > 2, so it still goes back to small.
- `hit_miss_identical_to_linear_reference` must still pass.

## Rationale

This is the first point on the `GHOST_RECENT_AGE_DIVISOR` sweep that cycle 0005 asked for. v002 showed that a key's ghost age is the strongest per-key signal so far, and its window scales with `small_size`, so it can move the large cache size. The test: if hm_0 gains and web_0 holds, the optimum is wider than one turnover. If web_0 @ 16384 falls, the late one-off rereferences start getting in at about two turnovers, which locates the boundary. web_0 @ 131072 is the cell to watch for any movement.
