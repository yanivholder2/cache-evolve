# H01

Narrowing the correlated-reference window from `small_size / 8` to `small_size / 32` raises hit-rate by keeping most of 0009-v003's hm_0 burst filtering while letting web_0's genuine quick reuses graduate again.

## Parent

cycle/0009/v003

## Changes

In `src/s3_fifo/mod.rs`, change the constant `CRP_DIVISOR` from `8` to `32`.
Nothing else changes: `crp_window()` stays `(small_size / CRP_DIVISOR).max(1)`,
`get()` still caps small hits with `clock - entry.small_tick < crp` at
`freq = max(freq, 1)`, and the ghost paths, graduation thresholds, and
`evict_main`/`evict_small` stay exactly as in 0009-v003.

Update the comment block that documents the cycle-0009 rule so it names the new
divisor. Fix the tests that depend on the window size. `big_cache_with_full_main`
asserts `crp_window() == 2` for capacity 64, and with divisor 32 that becomes
`16/32 → max(1) = 1`. Update that assertion to 1. In
`spaced_reuse_increments_and_graduates`, make sure the second `get` still lands
outside the window: one intervening small insertion is enough, so keep the
two `put`s. The linear `Reference` model reads `CRP_DIVISOR` directly, so it
follows automatically.

## Rationale (optional)

At 16384 the small queue is 4096 slots, so the window shrinks from 512 small
insertions to 128. At 131072 it shrinks from 4096 to 1024. hm_0's burst-only
keys tend to repeat within a handful of requests, so a tighter window should
still catch them. web_0's real reuses, which arrived after a short but not
immediate gap and were hurt at 16384 (the 0009-v003 insight reports a loss
there relative to its 0005-v002 parent), should now count as spaced reuse. Expected outcome: hm_0
gains at both sizes are mostly kept, and web_0 @ 16384 recovers. If hm_0 loses
most of its gain, the burst structure is wider than 128 insertions and the
window is not the axis where the trade-off can be broken.
