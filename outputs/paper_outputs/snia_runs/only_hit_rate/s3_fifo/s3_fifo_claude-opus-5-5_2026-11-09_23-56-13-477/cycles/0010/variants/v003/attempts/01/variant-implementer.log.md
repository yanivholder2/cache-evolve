**What changed:**
1. **`main_hit` flag on each entry.** It starts `false`. A hit on an entry in main sets it to `true`, alongside the usual freq increment. It is cleared again whenever an entry enters main: on graduation from small (with `freq = 0`) and on any new main admission.
2. **A separate main-victim ghost.** It has its own location type (`Loc::MainGhost { stamp }`), queue (`mghost`), live count (`mghost_live`), stamp counter (`next_mstamp`) and budget (`mghost_cap = (main_size/4).max(1)`). None of these are shared with the small-victim ghost, which is what broke the ghost gate in 0007. Old entries are deleted lazily, the same way as the small ghost, and the queue is compacted once it grows past `2 * mghost_cap`.
3. **Main eviction.** When the tail has freq 0 and its `main_hit` is set, the key is recorded in the main-victim ghost instead of being forgotten. Victims that were never hit in main are dropped as before.
4. **Re-putting a remembered key.** Its record is deleted, main evicts if full, and the key goes back to the front of main with freq 1 (one second chance) and `main_hit = false`. A `get` on a remembered key is a miss.
   - The record is deleted *before* main evicts. Otherwise the eviction could find the key's own leftover queue slot, treat it as live, and remove its index entry and decrement the live count twice. The existing weak-returnee path already guards against the same problem this way.
