# H03

Remembering only main victims that were hit during their main residency, in a separate small victim ghost, and readmitting them into main with one second-chance credit raises hit-rate on web_0 at the large size.

## Parent

cycle/0009/v003

## Changes

In `src/s3_fifo/mod.rs`, and building on 0009-v003 unchanged otherwise:

1. Add `main_hit: bool` to `Entry` (default `false`). In `get()`, when the hit
   is on a `Loc::Main` entry, set `entry.main_hit = true` alongside the
   existing freq increment. Clear `main_hit = false` in `evict_small` when an
   entry graduates (alongside `freq = 0`) and on every new main admission.
2. Add a new `Loc::MainGhost { stamp: u64 }` variant and a dedicated deque
   `mghost: VecDeque<(K, u64)>` with its own `mghost_live: usize` and
   `next_mstamp: u64`. Its budget is `mghost_cap = (main_size / 4).max(1)`.
   This is a separate FIFO and budget, so it must not share the small-victim
   ghost's `ghost`/`ghost_live`/`next_stamp`; sharing them broke the ghost gate
   in 0007. Use the same lazy deletion as `ghost_insert`: pop stale entries
   until a live one is evicted, then compact with `retain` once
   `mghost.len() > 2 * mghost_cap`.
3. In `evict_main()`, when the tail has `freq == 0` and is removed, record it
   only if `entry.main_hit` is true. In that case replace its index entry with
   `Loc::MainGhost { stamp }` instead of removing it. Never-hit main victims are
   removed as now.
4. In `put()`, add a `Some(Loc::MainGhost { .. })` arm. Decrement `mghost_live`,
   evict from main if it is full, allocate, push to the main front with
   `freq = 1` (one second-chance pass), set `main_hit = false`, and point the
   index at `Loc::Main`. `get()` must treat `Loc::MainGhost` as a miss, like
   `Loc::Ghost`.
5. Fix the invariants and tests: `index.len() == resident + ghost_live +
   mghost_live`. Extend `ghost_compaction_bound_holds` to check
   `mghost.len() <= 2 * mghost_cap` and `mghost_live <= mghost_cap`. Add the
   same main-victim ghost to the test `Reference` model (with a `main_hit`
   flag, a capped FIFO and freq-1 readmission) so that
   `hit_miss_identical_to_linear_reference` still passes.

## Rationale (optional)

This is the single web_0 @ 131072 probe the cycle-0009 continuation allows. It
tests the two untried levers together, the `main_hit` gate and the returnee
freq. 0009-v002 showed that a large, ungated `main_ghost` did nothing, which
suggests most main victims are dead keys. Gating on an observed main hit
remembers only victims with proven residency value, and a budget of
`main_size / 4` keeps the metadata cost small. Readmitting with freq 1, rather
than 0, protects the returnee from the next tail sweep, which a recently
evicted key with real reuse needs. Refutation criterion: if web_0 @ 131072
moves less than ±0.001, treat that cell as a plateau for this policy family
and stop targeting it.
