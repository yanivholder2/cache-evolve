# H02

Letting keys that saturated their small-queue freq (freq == MAX_FREQ at graduation) enter main with freq 1 instead of 0, while every other main admission still starts at freq 0, raises hit-rate by reordering main eviction toward weakly-evidenced entries.

## Parent

cycle/0005/v002

## Changes

This change targets main's eviction order, not ghost or small routing. Today every entry enters main with freq 0: graduates are reset in `evict_small()` and ghost admissions come from `alloc`. So on its first lap through main, a key reused three or more times in small is exactly as exposed as a key that got in on a single quick ghost return. The change uses the per-key small-queue freq at graduation time to give only the strongest graduates one protected lap.

1. Add `const GRADUATE_HOT_MAIN_FREQ: u8 = 1;`.
2. In `evict_small()`, in the graduation branch, replace the unconditional `entry.freq = 0;` with: `entry.freq = if entry.freq >= MAX_FREQ { GRADUATE_HOT_MAIN_FREQ } else { 0 };`. Read the freq before overwriting it. The threshold logic (`GRADUATE_FREQ_MAIN_FULL` / `GRADUATE_FREQ_MAIN_ROOM`) and the `evict_main()` call before the push stay exactly as they are.
3. Ghost→main admissions in `put()` (both freq ≥ 1 returnees and recent freq-0 returnees) keep starting at freq 0. `evict_main()` itself stays unchanged, including the decrement-by-1 second chance and `MAX_FREQ = 3`.
4. Update the `Reference` oracle's `evict_small` in the same way, so `hit_miss_identical_to_linear_reference` still passes. Change the existing test `small_eviction_promotes_to_main_after_single_hit_with_reset_freq` only if needed (it graduates at freq 1, so it should still expect 0). Add a test: a small entry with freq 3 graduating into a full main lands with `freq_of == Some(1)`, and survives one `evict_main()` pass while a freq-0 neighbour is evicted.

## Rationale

Cycle 0001 found that carrying the *full* small freq into main hurt, which is why the reset exists. That was a blanket rule, though. The lineage's consistent lesson is that per-key evidence wins when it targets a narrow population, and keys that saturate freq within one small residence are the narrowest, strongest such population. Main is always full, so the protection has to come from somewhere. Here it comes from entries with the weakest admission evidence (quick freq-0 ghost returns and exactly-twice graduates), because they now reach freq 0 at the tail first. Because the small queue scales with capacity, the population this affects grows with cache size, so the change can reach the large-size cells.
