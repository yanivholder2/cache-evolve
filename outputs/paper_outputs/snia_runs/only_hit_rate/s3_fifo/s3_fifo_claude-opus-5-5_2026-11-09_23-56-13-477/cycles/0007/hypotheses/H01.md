# H01

Ghosting main-queue victims that were hit at least once during their main residence with ghost freq 1, so that a quick return re-enters main directly instead of re-qualifying through small, raises hit-rate on web_0 at the large cache size.

## Parent

cycle/0005/v002

## Changes

Every policy change so far has worked on keys evicted from *small*. Keys evicted from *main* currently leave no trace: `evict_main()` calls `self.index.remove(&entry.key)` and frees the slot. If such a key comes back, it lands in the `None` branch of `put()` as a brand-new key and has to earn two reuses in small again (main is always full). This hypothesis gives main victims a ghost record, but only when they carry their own evidence of value.

1. Add a `main_hit: bool` field to `Entry` (default `false` in `Entry::new`). In `get()`, when the index lookup yields `Loc::Main(i)`, set `self.slab[i].main_hit = true` in addition to the existing freq increment. `Loc::Small` hits do not set it. Reset `main_hit = false` wherever an entry enters main: the graduation path in `evict_small()` (next to `entry.freq = 0`) and both ghost→main admissions in `put()` (the slot comes from `alloc`, so `Entry::new` already covers this).
2. In `evict_main()`, in the `else` branch where the tail has `freq == 0`: if `entry.main_hit` is true, clone the key, push `idx` to `free`, and call `self.ghost_insert(key, GHOST_TO_MAIN_FREQ)` rather than `self.index.remove(&entry.key)`. `ghost_insert` overwrites the index entry with `Loc::Ghost`, so no separate remove is needed. If `main_hit` is false, keep today's behaviour (remove from the index, free the slot, no ghost).
3. Watch for re-entrancy: `ghost_insert` may pop and remove an older ghost. It never touches small or main, so calling it from inside `evict_main` is safe. However, `evict_main` is called from the ghost→main branch of `put()` *after* `self.ghost_live -= 1` and before the new index insert. Make sure the returning key's own stale ghost slot can't be mistaken for a live ghost. Its index entry is still `Loc::Ghost { stamp }` with a matching stamp at that point, so a ghost eviction triggered inside could remove it and decrement `ghost_live` twice. Fix this by `self.index.remove(&key)` at the top of that branch, before `evict_main()`, as the weak-returnee branch already does.
4. Keep the ghost capacity bound (`ghost_live <= main_size`), the compaction rule, and every other branch unchanged. Main victims and small victims share the one ghost FIFO.
5. Update the linear `Reference` oracle in the tests the same way: give `Entry` a `main_hit` flag, set it in `get` for main entries, and in `Reference::evict_main` push `(key, GHOST_TO_MAIN_FREQ, stamp)` into the ghost (applying the same capacity eviction and stamp increment as `evict_small`) when the evicted tail had `main_hit`. Add a unit test: a main entry that is hit, decays to freq 0 and is evicted becomes a freq-1 ghost and returns straight into main; a never-hit main victim leaves no ghost.

Note that ghost stamps (`next_stamp`) now also advance on main→ghost insertions, so the freq-0 age window counts both kinds of ghost insertion. This is intended and should be stated in the header comment.

## Rationale

web_0 at the large size has not moved under any small or ghost routing change. A plausible limit is keys with long reuse distances. They survive one main lap on a hit, fall out, and then on return have to fight back through small's strict two-reuse filter, which mostly ghosts them again. The per-key `main_hit` flag gives evidence like the cycle 0004/0005 gates, and never-hit main victims stay excluded so the ghost isn't flooded with dead keys.
