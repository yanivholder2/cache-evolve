# H02

Switching the small-queue graduation threshold between 1 and 2 using a windowed ghost-return rate, a signal that keeps moving in steady state, will raise hit-rate above cycle/0002/v001 by recovering hm_0@16384 without giving back web_0.

## Parent

cycle/0002/v001

## Changes

In `src/s3_fifo/mod.rs` of cycle/0002/v001, replace the main-occupancy gate in `evict_small` with an adaptive threshold:

- Add these fields to `S3Fifo`: `threshold: u8` (start at 2), `win_ghosted: u32` (small tails sent to ghost in the current window), `win_ghost_hits: u32` (ghost hits in `put` in the current window), and `win_len: u32 = small_size.max(16) as u32`.
- In `put`, on the ghost-hit branch, increment `win_ghost_hits`.
- In `evict_small`, when a tail goes to ghost, increment `win_ghosted`. Once `win_ghosted >= win_len`, compute `r = win_ghost_hits as f32 / win_ghosted as f32`. Set `threshold = 1` if `r > 0.30`, set `threshold = 2` if `r < 0.15`, and otherwise leave it unchanged (hysteresis). Then reset both counters to 0.
- The graduation test becomes `tail.freq >= threshold`, with no occupancy dependency. Keep the cold-start exception, though: while `main.len() < main_size`, use a threshold of 1 as v001 does. Keep the freq reset to 0 on graduation, and keep calling `evict_main` before pushing when main is full.
- Don't change `get`, `evict_main`, `MAX_FREQ`, the ghost capacity (`main_size`) or the 25% split.
- Add a debug-only counter of the windows spent at each threshold value (behind `#[cfg(test)]` or a `pub fn threshold_stats()`) so analysis can report where each trace settles.

Invariants: capacity is never exceeded, ghost length ≤ `main_size`, and `threshold` is always in {1, 2}. Add unit tests for these cases: a trace whose ghosted keys always return flips the threshold to 1, and a scan-only trace keeps it at 2.

## Rationale (optional)

Cycles 1–2 showed that threshold 1 helps only hm_0@16384 and that main occupancy saturates, so it can't serve as a gate. The ghost-return rate measures how often keys we refused to promote came back within the ghost window. That is exactly the cost of being strict, and it keeps varying in steady state. If the rate never crosses 0.30 on web_0, behaviour stays at v001's, so web_0 is protected.
