# H03

Re-admitting ghost-hit keys into main with one second-chance credit (freq = 1 instead of 0) will raise hit-rate over cycle/0002/v001, because proven-reuse keys will survive their first pass of the main CLOCK sweep.

## Parent

cycle/0002/v001

## Changes

Change only how entries enter main in `src/s3_fifo/mod.rs` of cycle/0002/v001, and leave which keys get admitted alone:

- In `put`, on the ghost-hit branch (`in_ghost == true`), create the main entry with `freq = 1` instead of `Entry::new`'s 0. Add a helper `Entry::with_freq(key, value, f)`. Keep the `evict_main()` call before the push when main is full.
- In `evict_small`, a small graduate (freq ≥ threshold) still has its freq reset to 0 as in v001. That keeps the asymmetry deliberate: ghost returnees have shown reuse beyond the small window, while small graduates have only shown short-range reuse.
- In `evict_main`, add a guard against an unbounded rotation. Count rotations in the loop, and once the count exceeds `main.len()`, evict the current tail no matter what its freq is. Since MAX_FREQ is 3, the loop already terminates; this only caps the worst case.
- Don't change the graduation thresholds, `MAX_FREQ = 3`, the ghost capacity or the 25% split.

Add a unit test: a key that is evicted to ghost and then re-put survives exactly one `evict_main` sweep in which it isn't accessed, and is evicted on the second. Keep all of v001's tests passing, and update `ghost_hit_promotes_back_to_main` if it asserts freq 0.

## Rationale (optional)

Cross-cycle evidence says admission strictness into main is the only lever that has paid off. This hypothesis keeps v001's admission set exactly and changes only how long a re-admitted key is protected. Ghost returnees are the strongest reuse evidence S3-FIFO has, yet v001 inserts them at freq 0. They can be evicted on the next sweep before they get a hit, which is costly at web_0@131072, where reuse distances are long. It's a different lever from H02, which changes who gets in. If hit-rate falls, main is already well-filtered and extra credit only slows the eviction of dead keys.
