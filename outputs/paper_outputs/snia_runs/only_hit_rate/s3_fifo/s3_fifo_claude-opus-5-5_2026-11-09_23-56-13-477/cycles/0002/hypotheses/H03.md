# H03

Combine v001's single-reuse graduation with a 15% small queue (instead of 25%) to raise aggregate hit-rate, since a looser threshold removes what limited the small-queue shrink in cycle 0001's v003.

## Parent

cycle/0001/v001

## Changes

In `src/s3_fifo/mod.rs`, `S3Fifo::try_new()`: change the small-queue sizing from
`(capacity / 4).max(1).min(capacity - 1)` to `(capacity * 15 / 100).max(1).min(capacity - 1)`.
Keep the `capacity == 1` special case. `main_size` stays `capacity - small_size`, and the ghost
queue stays bounded by `main_size`, so it grows slightly with the larger main.

Leave everything else from v001 unchanged: `evict_small()` graduates at `tail.freq >= 1` with
`freq` reset to 0, plus `MAX_FREQ = 3`, `get()`, `put()` and `evict_main()`. Use integer arithmetic
that cannot overflow for the trace sizes (16384 and 131072). Check that the existing unit tests
still pass at capacity 4 and 5. Both 15% and 25% give `small_size == 1` at those capacities, so
behaviour in the tests is unchanged. Adjust a test only if it
depends on the exact split.

## Rationale (optional)

v003 (10/90) lost on web_0 because keys had to be accessed twice within a much shorter small
window. v001 lost on web_0 because of main pollution. A 15% window with a one-reuse threshold
directly tests the cycle insight's open question: does changing the split and the threshold
together, at a value between 10% and 25%, keep hm_0's gain without web_0's loss? This is a
static-constant control for H02's adaptive split.
