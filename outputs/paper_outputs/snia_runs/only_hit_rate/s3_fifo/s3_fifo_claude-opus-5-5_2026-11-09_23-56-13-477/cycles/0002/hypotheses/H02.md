# H02

Make the small/main split adaptive online, ARC-style, by growing the small queue on small-ghost hits and shrinking it on hits to a new main-eviction ghost, to raise hit-rate on both hm_0 and web_0 without a fixed split.

## Parent

cycle/0001/v001

## Changes

In `src/s3_fifo/mod.rs`, starting from v001 (graduation at `freq >= 1` with freq reset):

1. Add fields `capacity: usize`, `main_ghost: VecDeque<K>` and keep `small_size`/`main_size`, but
   treat `small_size` as a mutable *target*. Initialise `small_size` to `capacity / 4`
   (clamped as now) and `main_size = capacity - small_size`. Bound the target to
   `[max(1, capacity / 20), max(1, capacity / 2)]`, and keep it `<= capacity - 1` when `capacity > 1`.
2. In `evict_main()`, when the loop pops a tail with `freq == 0` and drops it, push its key to
   the front of `main_ghost`. Bound `main_ghost` to `capacity / 2` entries by popping its back.
3. In `put()` on a miss:
   - If the key is in `ghost` (evicted from small, so small was too short), increase
     `small_size` by `max(1, small_size / 16)` up to the upper bound, and recompute `main_size`.
     Then take the existing ghost path.
   - Else, if the key is in `main_ghost` (evicted from main, so main was too short), remove it
     from `main_ghost` and decrease `small_size` by `max(1, small_size / 16)` down to the lower
     bound, then recompute `main_size`. Then insert the key into **main** with the same
     path as a ghost hit (call `evict_main()` if `main.len() >= main_size`).
4. Because targets move, eviction must use the combined budget. Before any insert, while
   `small.len() + main.len() >= capacity`, evict from small (`evict_small()`) if
   `small.len() > small_size`, else from main (`evict_main()`). If main is empty, fall back to
   small. Keep `evict_small()`'s graduation logic, but make graduation call `evict_main()` only
   when `small.len() + main.len()` would exceed `capacity`.
5. Keep the `ghost` bound at the current `main_size` value.

Invariant: `small.len() + main.len() <= capacity` after every `put`. Keep linear-scan lookups,
since no hashing is required, and leave `get()` unchanged. Add a unit test checking the capacity bound
across a long mixed sequence, plus one checking that `small_size` stays within its bounds.

## Rationale (optional)

Cycle 0001 showed that hm_0 and web_0 want opposite splits, so any fixed constant is a compromise.
The two ghost queues give a direct online signal of which side was too short. This is the
adaptive signal the cycle insight asked for.
