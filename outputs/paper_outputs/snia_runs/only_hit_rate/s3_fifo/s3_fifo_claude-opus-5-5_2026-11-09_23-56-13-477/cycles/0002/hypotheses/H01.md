# H01

Allow single-reuse graduation from small to main only while main has free capacity, otherwise require two reuses, to keep v001's hm_0 gain while removing its web_0 main-pollution loss on hit-rate.

## Parent

cycle/0001/v001

## Changes

In `src/s3_fifo/mod.rs`, modify `S3Fifo::evict_small()` only. Today it graduates the small tail
whenever `tail.freq >= 1`. Replace that condition with an occupancy-gated threshold:

- If `self.main.len() < self.main_size` (main has room), graduate when `tail.freq >= 1`. This is
  v001's behaviour, and no `evict_main()` call is needed because there is room.
- If main is full (`self.main.len() >= self.main_size`), graduate only when `tail.freq >= 2`
  (the baseline rule). In that case call `evict_main()` before `push_front`, as now.
- Otherwise push the key to the ghost queue, using the existing ghost path with its
  `main_size` bound, so a later re-access re-admits it via the ghost-hit path in `put()`.

Keep resetting `tail.freq = 0` on graduation, as v001 does. Leave `MAX_FREQ`, the 25/75 split, `get()`,
`put()`, `evict_main()` and the ghost bounds unchanged. Preserve the invariant
`small.len() + main.len() <= capacity`. Update the unit test
`small_eviction_promotes_to_main_after_single_hit_with_reset_freq` if needed. It runs with an
empty main, so it should still pass. Add a test showing that a freq==1 small tail goes to ghost
when main is full.

## Rationale (optional)

The v001 insight says the web_0 loss comes from promoting keys accessed exactly twice, because
each promotion forces an extra `evict_main` pass that wears down hot entries' second-chance
credit. That cost only exists when main is full. Gating the looser threshold on spare room in
main tests whether admission pressure is the lever. Expected result: hm_0 stays near v001 and
web_0 recovers toward baseline.
