# H03

Collapsing small-queue hits that arrive within a short correlated-reference window after insertion into a single reuse will stop bursty, short-lived keys from graduating into a full main, raising hit-rate mainly on web_0.

## Parent

cycle/0005/v002

## Changes

All edits are in `src/s3_fifo/mod.rs`. This targets first-admission handling of never-seen keys, which has not been probed yet. It does not touch the ghost path, the ghost budget, the stamp clock or the small/main split.

1. Add `const CRP_DIVISOR: usize = 8;` and a field `small_clock: u64` on `S3Fifo`, initialised to 0. Every insertion into small increments it: the `None` (first-admission) arm and the weak ghost-returnee arm of `put()`. Small→main graduation and ghost→main entry do not.
2. Add a field `small_tick: u64` to `Entry` (default 0 in `Entry::new`). When an entry is pushed into small, set `small_tick = self.small_clock` after incrementing the clock.
3. Add a helper `fn crp_window(&self) -> u64 { (self.small_size / CRP_DIVISOR).max(1) as u64 }`.
4. In `get()`, split the `Loc::Small(i)` and `Loc::Main(i)` cases:
   - Main hits keep the existing `freq = min(freq + 1, MAX_FREQ)`.
   - For a small hit with `self.small_clock - entry.small_tick < crp_window`, the hit is correlated: set `freq = freq.max(1)`, so a burst counts as at most one reuse. The value is still returned, so this is still a hit.
   - Small hits outside the window increment freq as before.
   This means a key needs at least one reuse outside its insertion burst to reach `GRADUATE_FREQ_MAIN_FULL` (2). A burst-only key still gets ghosted with freq 1 and keeps the freq ≥ 1 ghost→main return. Weak returnees inserted with freq 1 are unaffected by the cap, but their next small hit, if it lands inside the window, also stays at 1.
5. Leave `evict_small`, `evict_main`, `ghost_insert`, the age gate and the occupancy-gated threshold unchanged.
6. Update the in-file test module. Mirror the clock, tick and correlated-hit rule in `Reference` (the linear oracle), so `hit_miss_identical_to_linear_reference` still compares like with like. Add unit tests:
   - At a capacity where `small_size >= 16`, so the window is ≥ 2, two back-to-back gets right after `put` leave freq at 1, and the key is ghosted rather than graduated when main is full.
   - A get after `crp_window` further small insertions increments freq to 2 and graduates the key.

## Rationale (optional)

Every gain so far has come from per-key evidence. A main slot is costly once main is full, and cycle 0001 found web_0 pollution from short-lived, rarely reused keys. A key whose reuses all fall inside one burst is weaker evidence than a reuse spaced out over the small queue: this is the 2Q/LRU-K correlated-reference idea. Because the window scales with `small_size`, the effect should reach the large cache size, where web_0 has plateaued. The parent is 0005 v002 rather than the incumbent so that the result is not confounded by v003's doubled ghost.
