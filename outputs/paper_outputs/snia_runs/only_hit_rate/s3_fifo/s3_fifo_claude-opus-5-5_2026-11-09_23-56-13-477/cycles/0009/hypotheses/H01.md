# H01

Tiering the doubled ghost so that records older than `main_size` small→ghost insertions lose the direct ghost→main path will keep cycle/0008/v003's hm_0 small-size gain and recover its web_0 losses, raising hit-rate.

## Parent

cycle/0008/v003

## Changes

All edits are in `src/s3_fifo/mod.rs`. Keep `GHOST_BUDGET_MULT = 2`, the `next_stamp` clock, `GHOST_RECENT_AGE_DIVISOR = 1` and the graduation rules exactly as they are.

1. Add `const GHOST_PRIVILEGED_AGE_MULT: usize = 1;` and a helper
   `fn ghost_privileged_window(&self) -> u64 { (GHOST_PRIVILEGED_AGE_MULT * self.main_size).max(1) as u64 }`.
   This boundary matches the old single-`main_size` ghost horizon used before v003.
2. In `put()`, compute `age = self.next_stamp - stamp` for a `Loc::Ghost { stamp, freq }` hit and change the guard on the strong-returnee arm to
   `(freq >= GHOST_TO_MAIN_FREQ && age <= privileged) || age <= recent`.
   The freq-0 recent window (`age <= recent`, about one small turnover) still sends a key to main. A freq ≥ 1 record goes straight to main only if it is in the inner tier (`age <= main_size`).
3. Every other ghost hit, meaning freq-0 records older than `recent` and freq ≥ 1 records older than `main_size`, takes the existing weak-returnee arm: drop the ghost record before `evict_small`, re-admit into small with `freq = GHOST_RETURN_SMALL_FREQ` (1). One further reuse in small graduates the key. If it is ghosted again it carries freq 1, and because it gets a fresh stamp it is back in the inner tier.
4. Leave lazy deletion, `ghost_live` accounting, compaction (`2 * ghost_cap`) and `evict_main` unchanged.
5. Update the in-file test module: give the linear `Reference::put` the same tiered guard. Add a unit test in which a freq-1 ghost aged past `main_size` (at capacity 4: main_size 3, so 4 or more later small→ghost insertions while the key's record is still live under the 6-record budget) returns into small with freq 1 rather than main. Add a second test in which a freq-1 ghost with age ≤ `main_size` still goes to main. `hit_miss_identical_to_linear_reference` and `ghost_compaction_bound_holds` must keep passing.

## Rationale (optional)

Cycle 0008 found that v003's doubled ghost helps hm_0 at the small size, but giving extended-zone records the same privileges as recent ones costs web_0, which punishes privileges for keys that return after a long gap. With tiering, old records still save a key from a cold first admission (they skip the freq-0 small path), but only fresh evidence buys a main slot.
