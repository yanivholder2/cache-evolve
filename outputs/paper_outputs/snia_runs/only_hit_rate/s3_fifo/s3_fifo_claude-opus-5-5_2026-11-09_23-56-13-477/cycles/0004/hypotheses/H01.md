# H01

Gate the ghost-hit fast path into main on the small-queue frequency each key had when it was ghosted, sending ghost returnees that never got a reuse back into small instead, to raise hit-rate on web_0 without losing hm_0.

## Parent

cycle/0003/v001

## Changes

Work in `src/s3_fifo/mod.rs` of cycle/0003/v001 (the O(1) slab/index structure with the occupancy-gated two-reuse graduation and the freq reset on graduation).

1. **Carry per-key evidence into the ghost.** Change `Loc::Ghost(u64)` so it also records the key's small-queue freq at ghosting time, e.g. `Loc::Ghost { stamp: u64, freq: u8 }`. Ghost liveness checks (`ghost_insert`'s eviction loop and the `retain` compaction) must match on the **stamp only**. Use a helper such as `fn ghost_stamp_matches(loc: Option<&Loc>, s: u64) -> bool`, or keep the deque tuple as `(K, u64)` and compare the stamp field. Change `ghost_insert(key)` to `ghost_insert(key, freq)`. In `evict_small`'s non-graduating branch, read `self.slab[idx].freq` before freeing the slot and pass it in. In steady state (main full) that value is 0 or 1. While main has room it is 0, because freq ≥ 1 graduates.

2. **Split the ghost-hit branch in `put` (`Some(Loc::Ghost { freq, .. })`):**
   - `freq >= 1` (the key was reused in small, ghosted, and has now returned, so at least three accesses): behave as now. Decrement `ghost_live`, run `evict_main()` if main is full, allocate the entry, push it to the front of main and set `Loc::Main`.
   - `freq == 0` (one access, ghosted, returned): do **not** touch main. Decrement `ghost_live`, then follow the normal new-key path. If small is full, run `evict_small()`. Then allocate, push the entry to the front of small and set `Loc::Small`, but initialise the entry's `freq` to 1. One further reuse while in small then reaches the steady-state threshold of 2 and graduates the key. If no reuse comes, it is ghosted again, this time with freq 1, so its next return goes to main.

3. **Keep these invariants:** the graduation thresholds (`GRADUATE_FREQ_MAIN_ROOM`/`_FULL`), the freq reset on graduation, `MAX_FREQ`, the 25% small split, the ghost capacity (`ghost_live <= main_size`) and the `2 * main_size` compaction bound all stay unchanged. Capacity must never be exceeded, and `index.len() == resident + ghost_live` must still hold.

4. **Tests:** update the in-file `Reference` linear model inside `#[cfg(test)]` so it applies the same ghost rule. It should store `(key, freq)` in its ghost and route freq-0 returnees into small with freq 1. Keep `hit_miss_identical_to_linear_reference` passing against the updated reference. Adjust `ghost_hit_promotes_back_to_main`: with capacity 4, key 1 is ghosted with freq 0, so it now lands in small. Add a test where a key is ghosted with freq 1 and returns into main. Add another where a freq-0 returnee lands in small with freq 1 and graduates after one `get`. Keep `ghost_compaction_bound_holds`.

## Rationale

Cross-cycle insights say the ghost mostly holds weak single-reuse keys, and that rewarding the ghost path, whether through looser admission or returnee credit, has always cost hit-rate. They also say the price of a bad admission is paid when the key enters main. Today, any ghost hit inserts straight into a full main and forces a main eviction, which is the least filtered way into main. This hypothesis tightens that path using evidence the key carries with it, which cycle 0003 recommended, and avoids the global rate proxies that failed in cycles 0002 and 0003. The prediction is that hit-rate rises on web_0, which punishes weak admissions, at both sizes and holds on hm_0. If it falls, ghost returns are stronger evidence than the insights claim.
