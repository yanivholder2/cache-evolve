# H02

Replace SipHash with an inline multiply-shift hasher, shrink `Loc` to 8 bytes with a u32 ghost stamp, and remove redundant index lookups to cut per-op-time and metadata-size with bit-identical hit-rate.

## Parent

cycle/0003/v001

## Changes

This is a cost-only change to `src/s3_fifo/mod.rs` of cycle/0003/v001. The policy must not change, and the existing `hit_miss_identical_to_linear_reference` oracle test must pass **unmodified**.

1. **Fast hasher with no new dependency** (Cargo.toml is off-limits). Define a private `struct FastHasher(u64)` that implements `std::hash::Hasher`, plus a `#[derive(Default, Clone)] struct FastBuild` that implements `BuildHasher`. `write_u64`/`write_i64`/`write_u32`/`write_usize` should mix with `h = (h.rotate_left(5) ^ x).wrapping_mul(0x9E37_79B9_7F4A_7C15)`. The generic `write(&[u8])` should fold 8-byte chunks through the same step. `finish()` must return a value whose **high bits** are well mixed, because hashbrown uses the top 7 bits as control bytes. For example, apply a final `h ^ (h >> 29)` followed by one more multiply. Change `index: HashMap<K, Loc>` to `HashMap<K, Loc, FastBuild>` and build it with `HashMap::with_capacity_and_hasher(...)`.

2. **Shrink `Loc` from 16 to 8 bytes.** Change `Loc::Ghost(u64)` to `Loc::Ghost(u32)`, the ghost deque to `VecDeque<(K, u32)>` and `next_stamp` to `u32`, advanced with `wrapping_add(1)`. This is safe because only stamp *equality* is used and the deque never holds more than `2 * main_size + 1` slots, far below 2^32, so a stale slot can never alias a live stamp. Add `const _: () = assert!(std::mem::size_of::<Loc>() == 8);` so the size is enforced at compile time.

3. **Remove redundant hashing on the hot path:**
   - In `evict_small`'s graduating branch, don't use `self.index.get_mut(&entry.key)`. Use `if let Some(loc) = self.index.get_mut(..)` only once, or better, use `self.index.insert(key, Loc::Main(idx))` with no extra lookup. Keep exactly one hash lookup per graduation.
   - In `put`, the `Ghost` branch does `index.get` and then `index.insert` on the same key. Replace that with a single `match self.index.entry(key)`, or re-point the existing `Loc` in place through `get_mut` once the slab slot is allocated. Take care that `evict_main()`/`evict_small()` borrow `self` mutably, so run the eviction **before** taking the entry handle.
   - Clone keys only where a second owned copy is truly required: one copy in the slab and one in the index.

4. **Leave unchanged:** every policy constant, the order of evictions, the ghost capacity rule (`ghost_live >= main_size`), the `2 * main_size` compaction trigger, and the public `try_new`/`new`/`get`/`put` API and the `framework::Cache` impl.

5. **Tests:** keep all existing tests. Add one test asserting `size_of::<Loc>() == 8`, and another that runs about 1M skewed ops at capacity 4096 and checks `index.len() == resident + ghost_live` at the end.

## Rationale

Three cycles of policy work have produced at most about +0.005 hit-rate, and the insights describe the policy as plateaued. The leaderboard now reports per-op-time (227) and metadata-size (24), both still held by the linear baseline, so the O(1) incumbent's cost advantage is unproven. Its main per-op costs are SipHash, which is slow for integer keys, the 16-byte `Loc` enum and repeated lookups. Each change here is behaviour-preserving, so any per-op-time or metadata-size movement relative to cycle/0003/v001 can be attributed entirely to the hashing and layout. The prediction is that per-op-time drops below the parent and below the baseline's 227 on the large cache sizes, with identical hit-rate in all four cells.
