# H03

Give single-reuse small-queue tails one reinsertion lap inside small, instead of ghosting them, while main is full, so keys can prove a second reuse without ever entering main, to raise hit-rate on hm_0 at the small size without the web_0 pollution of a looser threshold.

## Changes

Work in `src/s3_fifo/mod.rs` of cycle/0003/v001.

1. **Add a per-entry lap bit.** Add `relapped: bool` to `Entry`, initialised to `false` in `Entry::new`. (Packing it into the high bit of `freq` is also acceptable. If you do, mask it out everywhere freq is compared or incremented, and keep `MAX_FREQ = 3`.)

2. **Change `evict_small()` to a loop.** It must free at most one resident slot or move at most one entry into main per call, so the capacity accounting stays exactly as it is now. Repeat the following until one entry has graduated or been ghosted:
   - Pop the small tail `idx` and compute `main_full`/`threshold` as now.
   - If `freq >= threshold`, graduate exactly as now: evict from main if it is full, reset freq to 0, set `Loc::Main`, push to the front of main. Stop.
   - Else, if `main_full && freq == 1 && !relapped`, the key has one reuse but not two. Set `relapped = true` and `freq = 0`, push it back to the **front of small** (its `Loc::Small(idx)` is unchanged) and continue the loop to examine the next tail. A key on its extra lap needs **one** further reuse (`freq >= 1`) to graduate. Express this as: if `relapped && freq >= 1` then graduate, checked in addition to the normal threshold.
   - Else, ghost it exactly as now and stop.
   - Termination: each entry can relap at most once (`relapped` is never cleared while the entry is in small), so the loop ends within `small.len() + 1` iterations.

3. **Ghost and main behaviour is unchanged:** ghost hits still go to main with freq 0, main eviction is still the freq-decrement second chance, and `GRADUATE_FREQ_MAIN_ROOM`/`_FULL`, the freq reset on graduation, the 25% split and the ghost sizing all stay as they are. Freed and recycled slab slots must start with `relapped = false`.

4. **Tests:** update the in-file `Reference` linear model under `#[cfg(test)]` to apply the same relap rule, and keep `hit_miss_identical_to_linear_reference` passing against it. Update `small_tail_with_single_hit_goes_to_ghost_when_main_full`: the freq-1 tail now relaps and stays in small, so if small has only that one entry, the loop must ghost it on its second visit. Add a test where a relapped key gets one `get` and then graduates on its next tail visit. Add another where a relapped key with no hit is ghosted. Keep `capacity_bound_never_exceeded` and `ghost_compaction_bound_holds`.

## Rationale

Cycles 0001 and 0002 showed that graduating on a single reuse helps hm_0 at the small size but pollutes main on web_0 and on hm_0 at the large size. The insights say the cost of a bad admission is paid when the key enters main. This variant tests the opposite split: a key with one reuse gets more time to *prove* itself, but that time is spent in small, where a wrong guess costs a small slot for one lap and not a main slot. Ghosting it would send a later return straight into main with no filter. Main admission stays as strict as the incumbent's: two observed reuses in total, just spread over a longer window. The prediction is that hm_0 at 16384 gains, because medium-reuse keys survive, while web_0 holds, because main stays clean. If web_0 drops, the loss comes from new keys losing small capacity, which would mean the bottleneck is small-queue churn, not main pollution.
