# H02

Shrinking the small queue to 10% of capacity only at large cache sizes, while pinning the ghost-age window to its old 25% value, will raise web_0 hit-rate at the large size without disturbing the small-size cells.

## Parent

cycle/0007/v001

## Changes

In `S3Fifo::try_new` in `src/s3_fifo/mod.rs`, make the split depend on size:

- Add `const LARGE_CAPACITY: usize = 65_536;` and `const LARGE_SMALL_DIVISOR: usize = 10;`.
- If `capacity >= LARGE_CAPACITY`, set `small_size = (capacity / LARGE_SMALL_DIVISOR).max(1).min(capacity - 1)`. Otherwise keep the existing `(capacity / 4).max(1).min(capacity - 1)`. `main_size = capacity - small_size` as before. The ghost bound (`main_size`) and compaction bound follow automatically.
- Add a new struct field `recent_window: u64`. Compute it once in `try_new` as `((capacity / 4).max(1).min(capacity - 1) / GHOST_RECENT_AGE_DIVISOR).max(1)`, i.e. the window the parent would have had. Change `ghost_recent_window()` to return `self.recent_window`. This isolates the split change from the age-gate window, which is a confirmed 1× local optimum.
- Leave all routing, graduation, main-hit ghosting and the freq reset unchanged.
- Update the `Reference` oracle in the same way: the size-dependent `small_size`, plus a stored `recent` computed from the 25% value. Add a unit test checking that `capacity = 131072` gives `small_size = 13107` and `recent_window = 32768`, and that `capacity = 16384` is unchanged.

## Rationale (optional)

web_0 at the large size has resisted every ghost and small routing change. The small/main split at that size is the one lever named as unprobed in the cross-cycle insights. Earlier split tweaks applied to all sizes, and they also moved the age window, which scales with `small_size`. This variant changes only the large-size split, so if the small-size cells move by even one ulp, that points to an implementation error. Any change in the large-size cells can be attributed to the split, since the window is held fixed.
