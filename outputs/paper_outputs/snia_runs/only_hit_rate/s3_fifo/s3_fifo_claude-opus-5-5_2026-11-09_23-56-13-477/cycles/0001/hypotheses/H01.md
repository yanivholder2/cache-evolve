# H01

Graduating any small-queue entry that was reused at least once (freq ≥ 1), and resetting its frequency to 0 when it enters the main queue, will raise hit rate on the MSR traces.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, `S3Fifo::evict_small()`:

- Change the graduation test from `tail.freq > 1` to `tail.freq >= 1`. Right now a key needs two hits while in the small queue before it can move to main. With the change, one hit is enough. In the baseline a key that was hit exactly once in the small queue gets demoted to ghost, so the next access misses and then re-admits it straight to main anyway.
- When an entry graduates, set `tail.freq = 0` before `self.main.push_front(tail)`. Hits it collected in the small queue then don't also buy it extra second-chance passes in main. In main it has to earn its protection again through `get` hits.
- The demote branch stays as it is: entries with `freq == 0` go to ghost, and ghost is still bounded by `main_size`.

Leave everything else alone: the ghost re-admission path in `put`, `evict_main`, `MAX_FREQ = 3`, the capacity split, and the `Entry` layout. The invariant `small.len() + main.len() <= capacity` must still hold, and `evict_main` must still run before any push into a full main queue.

The unit test `small_eviction_promotes_to_main_after_multiple_hits` still passes because it hits twice. `main_eviction_uses_frequency_second_chance` puts a freq-2 small entry into main and checks which main keys survive. That test still holds, because the graduating entry's reset frequency doesn't change how `evict_main` treats the existing main entries.

## Rationale (optional)

The threshold-2 rule sends one-time-reused keys to ghost, which costs them an extra miss. MSR web_0/hm_0 have many keys with short reuse distances and only a few accesses each, so a threshold of 1 should turn those misses into hits. The frequency reset keeps graduated entries from crowding out main.
