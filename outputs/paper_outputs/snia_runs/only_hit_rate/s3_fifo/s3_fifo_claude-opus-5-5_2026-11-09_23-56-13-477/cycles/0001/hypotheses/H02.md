# H02

Replacing the linear scans over the small, main and ghost queues with a hash index from key to queue location will cut get/put per-op time and leave hit rate unchanged.

baseline

## Changes

Today every operation in `src/s3_fifo/mod.rs` is O(capacity) because of these scans:

- `get` and `find_entry_mut` both run `small.iter_mut().chain(main.iter_mut()).find(..)`.
- `put` runs `ghost.iter().any(..)` and then `ghost.retain(..)`.

At sizes 16384 and 131072 these scans make up most of the per-op time. Restructure the code like this, and keep the eviction decisions exactly the same:

- Add an index `HashMap<K, Loc>` with `enum Loc { Small, Main, Ghost }`. You can also store a per-key insertion stamp in it (see the ghost bullet). Change the `S3Fifo` struct bounds to `K: Eq + Hash + Clone`. The framework `Cache` impl already requires these. Do not edit `s3_fifo_jni.rs`; it uses concrete `u64` keys, so the tighter bounds still compile.
- Store resident entries in a slab, `Vec<Entry<K, V>>` plus a free list. `small` and `main` become `VecDeque<u32>` of slab indices. The index maps a key to its slab slot, so `get` becomes a hash lookup followed by a freq bump. `Entry` must stay `{key, value, freq}`, or get smaller, so metadata-size doesn't regress.
- Ghost: replace `ghost.retain` with a lazy-deletion scheme. Push `(key, stamp)` into the ghost `VecDeque`, and record that the key is in ghost in the index together with the stamp.
  - On a ghost hit, remove the key from the index (or overwrite it with a resident `Loc`), and leave the deque slot as it is.
  - When popping the ghost tail to stay within bounds, only remove the index entry if its stamp matches.
  - The ghost bound is still `main_size` live entries. Count live ghost entries separately from the deque length, and if the deque grows past 2× `main_size`, compact it. That keeps capacity behaviour identical to the baseline.
- Keep the index in sync on every move: insert into small, graduate, demote, ghost re-admission, and main eviction (drop the index entry for the victim). Main-queue second-chance reinsertion only moves the slab index and doesn't touch the hash index.
- Keep all policy logic the same: graduation threshold `freq > 1`, `MAX_FREQ = 3`, the 25%/75% split, and the ghost size. Hit rate should match the baseline bit for bit.

Update the in-file unit tests that touch `cache.main` / `cache.small` directly so they go through the new representation. You can add small test helpers inside `mod.rs`. The tests in `tests/` must not be changed.

## Rationale (optional)

The baseline's p50 put is 926 ns and its p99 is 2640 ns, which is dominated by scanning the deques. A hash index makes every operation O(1) amortised. This hypothesis isolates the per-op-time dimension; the policy is untouched.
