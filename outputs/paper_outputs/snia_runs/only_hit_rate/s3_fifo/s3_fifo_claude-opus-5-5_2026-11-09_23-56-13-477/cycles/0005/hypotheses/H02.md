# H02

Letting a freq-0 ghost returnee go straight into main only when its own ghost age is short (it returned within roughly one small-queue turnover) will recover v001's hm_0@16384 loss while keeping its web_0@16384 gain, raising summary hit-rate.

## Parent

cycle/0004/v001

## Changes

Start from cycle/0004/v001's `src/s3_fifo/mod.rs`. The only behavioural change is in the weak-returnee branch of `put()`.

1. Ghost stamps already increase by one on every `ghost_insert`. So for a ghost hit, `age = self.next_stamp - stamp` is the number of small→ghost evictions since this key was ghosted. That is a per-key reuse-distance measure available at no extra cost. Add a constant `GHOST_RECENT_AGE_DIVISOR: usize = 1` and compute the recency window as `recent = (self.small_size / GHOST_RECENT_AGE_DIVISOR).max(1) as u64`. That is about one small-queue turnover, compared with a full ghost window of `main_size`, which is about 3× small.
2. In `put()`, split the current `Some(Loc::Ghost { .. })` (freq-0) arm by age:
   - **Recent** (`freq == 0 && next_stamp - stamp <= recent`): take the same path as the strong-returnee branch. Decrement `ghost_live`, call `evict_main()` if main is full, `alloc`, push to the front of main with freq 0, and re-point the index to `Loc::Main`. The match guard has to admit this case, so either extend the first arm's guard to `freq >= GHOST_TO_MAIN_FREQ || next_stamp - stamp <= recent`, or copy its body.
   - **Old** (any other freq-0 returnee): unchanged from v001. Remove the index entry *before* `evict_small()`, decrement `ghost_live`, and readmit to small with `freq = GHOST_RETURN_SMALL_FREQ`.
   Freq ≥ 1 returnees keep going straight to main whatever their age.
3. Update the linear `Reference` oracle: store `(key, freq, stamp)` in its ghost deque, keep its own `next_stamp` counter that is incremented on each ghost push, and apply the same age rule, so `hit_miss_identical_to_linear_reference` stays an exact oracle. Add unit tests:
   - a freq-0 key that returns after fewer than `small_size` ghost insertions lands in main;
   - one that returns after more lands in small with freq 1.
   For the test at capacity 4, `small_size` is 1, so `recent` is 1. Adjust the existing `weak_ghost_returnee_*` and `ghost_hit_promotes_back_to_main` tests so they still exercise the old-returnee path (insert enough ghosts first), or update their expectations to match.

Invariants to keep: `index.len() == resident + ghost_live`, the ghost deque bound, and `resident <= capacity`.

## Rationale

v001's insight says that some of hm_0's freq-0 ghost returnees are real reuses, and routing them through small makes them miss main hits. On web_0, the freq-0 returnees mostly come back late in the ghost window, as weak one-off rereferences. A key's own ghost age is per-key evidence, which has worked in this lineage, unlike global rate signals. It separates a tight reuse that was simply squeezed out of a 25% small queue from a long-distance rereference.
