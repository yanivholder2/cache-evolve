# H02

Demoting entries evicted from protected to the probation LRU end instead of the probation MRU end gives newly admitted candidates a longer probation stay and raises hit-rate on hm_0 small without lowering the admission bar.

## Parent

cycle/0005/v003

## Changes

Change only where protected-overflow demotions land in probation; leave the admission contest, sketch (double counting kept), climbers and coldest-of-4 victim sampling exactly as in cycle/0005/v003.

1. Add a `push_front(idx, region)` helper next to `push_back()` that links a node at the list head (LRU end): set `region`, `prev = None`, `next = old head`, fix the old head's `prev` (or set `tail` if the list was empty), set `head = idx`, increment `len`.
2. In `promote()`, in the `Region::Probation` branch, the `while self.protected.len > self.protected_cap` demotion loop must call `self.push_front(d, Region::Probation)` instead of `self.push_back(d, Region::Probation)`.
3. Also apply the same demote-to-head rule anywhere else protected entries are pushed into probation because protected is over its cap after a climber retarget (if the parent has such a lazy rebalance path); window spills and contest winners still go to probation MRU via `push_back`.
4. Nothing else changes: `sampled_main_victim()` still samples the 4 nodes from the probation head and picks the lowest estimate, so a demoted entry with a genuinely high count survives the sample while a stale, cold demotee is now evicted before freshly admitted keys.
5. Add a unit test: capacity 100, fill, hit enough probation keys to overflow protected, and assert the demoted node is `probation.head`. Keep `check_structure` passing.

## Rationale (optional)

Cross-cycle insights repeatedly say hm_0 wants changes to where entries land in probation and how long they stay, not to the admission contest. In the parent, every demotion from protected is pushed to probation MRU, ahead of newly admitted candidates, so fresh admissions reach the sampled LRU end sooner and their probation stay is shorter. Demoted entries have already had their protected tenure; making them face the victim sample first lengthens new admissions' chance to get a second hit and be promoted. The rule does not change who wins the contest, so it should not open the bar on web_0 large.
