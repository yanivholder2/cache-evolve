# H01

Replacing the sticky window `reused` flag with a residency-normalised "late window hit" signal keeps the small-cache hit-rate gains of the reuse-gated tie-break while removing its large-cache hit-rate losses.

## Parent

cycle/0008/v003

## Changes

Keep everything in cycle/0008/v003 except the meaning of the reuse signal used in the `evict_for_insert()` contest.

1. Add a monotonically increasing `u64` insert clock `tick` to `TinyLfuCache`, incremented once per new-key insertion in `put()` (both the not-full and the full path; not on updates of existing keys).
2. Replace `Node::reused: bool` with two `u64` fields: `win_enter: u64` (set to `tick` when the node is pushed into the window as a newcomer, i.e. both insertion paths in `put()`, including the recycled slot) and `last_win_hit: u64` (set to 0 on insertion/recycle; set to the current `tick` in `promote()` when `region == Region::Window`).
3. In `evict_for_insert()`, compute the candidate's reuse as "late hit":
   `let resid = tick - win_enter; let since_hit = tick - last_win_hit;`
   `let late_reuse = last_win_hit != 0 && last_win_hit > win_enter && since_hit * 4 <= resid;`
   i.e. the last window hit must have happened in the most recent quarter of the candidate's window residency. Because the threshold is relative to the candidate's own residency (measured in inserts, which is how fast the window advances), its precision does not drift as the climber grows or shrinks the window. Use `last_win_hit >= win_enter` safely (handle the insert at the same tick by comparing with `>=` and requiring `last_win_hit != 0`; start `tick` at 1 so 0 means "never hit").
4. The admission rule becomes `cand_freq > victim_freq || (late_reuse && cand_freq == victim_freq)`. Strict `>` is otherwise preserved; the victim still wins all other ties.
5. Update the in-file unit tests `reused_window_candidate_wins_tie` / `unreused_window_candidate_loses_tie` to assert on the new fields (the test in the first must make the window hit late enough relative to residency, which for capacity 2 is trivially true since the hit happens just before the contest). Keep `check_structure` and all other tests passing.

Do not touch the sketch, the climbers, the victim sample size (4), or the SLRU logic.

## Rationale (optional)

c8 v003's insight showed the boolean flag was precise when the window was short and acted like a blanket `>=` when the window was large, because one early hit anywhere in a long residency set it. A hit in the last quarter of residency means the key is still being referenced as it reaches the window LRU — the evidence is fresh at decision time regardless of window size. This is the one tie-related redesign the cycle 0008 continuation said was still worth trying.
