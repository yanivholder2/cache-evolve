# H03

Giving returning window candidates a +1 frequency bonus in the admission contest, when they were recently rejected (tracked in a bounded ghost FIFO of key hashes), will raise hm_0 small hit-rate without costing web_0.

## Parent

cycle/0005/v003

## Changes

All changes are in v003's `src/tiny_lfu/mod.rs`. Do not touch the climbers, the victim sampling, or sketch counting.

1. **Ghost state.** Add `rejected_ghost: std::collections::HashSet<u64>` and `rejected_fifo: std::collections::VecDeque<u64>` to `TinyLfuCache`, plus `ghost_cap: usize`. In `try_new`, set `ghost_cap = (capacity / 2).max(1)`. Add a free function `key_hash<K: Hash>(key: &K) -> u64` that uses an unseeded `DefaultHasher`.
2. **Record rejections.** In `evict_for_insert`, find the branch of the main contest where the candidate loses (`else { self.evict(cand); cand }`). Before evicting, compute `h = key_hash(&self.nodes[cand].key)`. If `h` is not already in the set, push it to the back of `rejected_fifo` and insert it into `rejected_ghost`. While `rejected_fifo.len() > ghost_cap`, pop from the front and remove that hash from the set. Only contest rejections are recorded. Do not record direct main evictions, the defensive no-window path, or the capacity-1 no-contest path.
3. **Apply the bonus.** In the same contest, compute `let bonus = if self.rejected_ghost.contains(&key_hash(&self.nodes[cand].key)) { 1 } else { 0 };` and admit when `cand_freq.saturating_add(bonus) > victim_freq`. Keep the comparison strict. When a ghost-hit candidate is admitted, remove its hash from `rejected_ghost`. Leave the stale FIFO entry in place, and make the pop loop tolerate hashes that are no longer in the set.
4. Leave the newcomer insert path unchanged: newcomers still enter at window MRU.

Invariants:
- Ghost size is bounded by `ghost_cap`. Metadata cost is about `capacity/2` u64 hashes plus HashSet overhead, and should be reported.
- If the ghost is empty, behaviour is identical to v003.
- All existing tests pass.
- Add one test: with capacity 2, a candidate tied with the victim is rejected once, and after it returns it is admitted on the tie.

## Rationale

The cycle 0005 analysis found two things. First, hm_0 small had relied on an accidental re-entry bonus: under double counting, keys that returned after eviction got extra frequency. Second, hm_0 wants an *explicit* recency or re-entry signal rather than a different choice among the oldest entries.

This change makes that bonus deliberate and narrow. Only keys that recently lost the contest, and then came back within about half a cache's worth of rejections, get +1. That is enough to break ties and near-ties in their favour. Scan keys on web_0 seldom return within that horizon, so the frequency filter there should stay intact. This is not a window-size controller, so it avoids the ghost-ratcheting failure seen in c5/v002.
