# H01

Counting each miss-then-insert access once in the sketch, on top of v003's sampled probation victim, will raise the hit-rate summary above 0.5617 by reducing collision noise on web_0 small.

## Parent

cycle/0005/v003

## Changes

Port cycle/0005/v001's single-count sketch accounting into v003's `src/tiny_lfu/mod.rs`, and change nothing else. Leave the victim sampling (`sampled_main_victim`, `VICTIM_SAMPLE = 4`), both climbers, and the strict `>` contest exactly as they are.

- Add a free function `key_hash<K: Hash>(key: &K) -> u64` that hashes the key with `DefaultHasher` (no seed) and returns `finish()`.
- Add a field `last_miss_hash: Option<u64>` to `TinyLfuCache` and initialise it to `None` in `try_new`.
- In `get`, keep `self.sketch.increment(key)` where it is. After the map lookup, set `self.last_miss_hash = Some(key_hash(key))` on a miss and `None` on a hit.
- In `put`, replace the unconditional `self.sketch.increment(&key)` with: compute `h = key_hash(&key)`, and increment only if `self.last_miss_hash != Some(h)`. Then always reset `self.last_miss_hash = None`. This applies before both the update-existing branch and the insert branches.

Invariants: the sketch geometry is unchanged, so metadata-size grows by only one `Option<u64>`. A put with no preceding get still counts once. All existing unit tests must pass. In `sampled_victim_picks_coldest_of_lru_sample`, the warm-up puts now count once each, and the test still has to choose key 1.

## Rationale

The cycle 0005 continuation listed this combination first. The two gains come through different routes: v003 sharpens the contest bar, and v001 removes the inflated estimate of 2 that every one-time key used to get. v001 gained on web_0 small (0.4308 vs v003's 0.4279) and lost on hm_0 small. The test is whether the web_0 gain adds to v003's result and whether the sampled victim, which already prefers truly cold residents, softens the hm_0 small loss.
