# H01

Placing a small (~1% of capacity) LRU admission window in front of the frequency-gated main LRU, so that new keys enter unconditionally and only window evictees face the admission contest, will raise hit rate on the MSR web_0/hm_0 traces.

## Parent

baseline

## Changes

Turn the single recency list in `src/tiny_lfu/mod.rs` into two recency lists sharing the same `nodes` arena: a **window** list and a **main** list. Each `Node` gains a one-byte region tag (`Window`/`Main`); `TinyLfuCache` keeps `win_head/win_tail/win_len` and `main_head/main_tail/main_len` instead of `head/tail`. Generalise `unlink`/`push_back` to take the list (region) the node is in so they update the correct head/tail/len.

Sizing: `window_cap = max(1, capacity / 100)`, `main_cap = capacity - window_cap`. For `capacity == 1` use `window_cap = 1, main_cap = 0` (everything lives in the window; no contest).

Behaviour:
- `get`: unchanged sketch increment; on hit, promote the node to the MRU (tail) of whichever list it is currently in.
- `put` on an existing key: update value, promote within its own list.
- `put` on a new key: always insert at window MRU (push a new node while `nodes.len() < capacity`, otherwise reuse a slot freed below). If `win_len > window_cap` afterwards, take the window LRU (the *candidate*) and:
  - if `main_len < main_cap`, move it to main MRU (retag, relink) — no contest;
  - otherwise run the admission contest between the candidate and the main LRU (*victim*) using `sketch.estimate`: if `candidate > victim` evict the victim (remove from map, unlink) and move the candidate to main MRU; otherwise evict the candidate. Either way exactly one key leaves the map.
- Slot reuse: to keep the arena allocation-free, perform the overflow/contest *before* inserting the newcomer when the cache is full (`win_len + main_len == capacity`): compute who is evicted, reuse that slot index for the newcomer, which goes to window MRU. Note the candidate must be determined first (the window LRU before insertion), then the newcomer is pushed.

Invariants to preserve: `map.len() == win_len + main_len <= capacity`; every map entry points to a live node in exactly one list; sketch increments happen on every get/put before any residency change. Leave `CountMinSketch`, `sketch_heap_bytes`, and the `framework::Cache` impl untouched. Update the in-file unit tests only if their expectations depend on newcomers being rejected outright (e.g. `low_frequency_new_item_is_rejected` with capacity 2: window=1, main=1 — adjust assertions to the new semantics where the newcomer sits in the window and key 2 is the contested one).

## Rationale (optional)

The baseline rejects every first-time key once full, so bursts of short-term recency (common in block I/O: read-after-write, sequential re-reads within a short span) never hit. W-TinyLFU's window recovers these hits while the filter still guards the bulk of the cache from scans.
