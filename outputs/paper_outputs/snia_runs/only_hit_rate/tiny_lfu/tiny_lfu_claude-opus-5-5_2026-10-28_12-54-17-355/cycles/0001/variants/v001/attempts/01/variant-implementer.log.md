I've written the v001 overlay, but I couldn't compile or test it. This session had only file read/write tools, no shell, so none of the four gates (build, contract, universal invariant, invariant) have been run. The harness will be the first thing to build it.

The change is a single file, `overlay/src/tiny_lfu/mod.rs`. It applies H01: newly seen keys always get into the cache through a small window, and only keys pushed out of that window have to compete on frequency to get into the main cache.

- **Two lists in one array of nodes:** each node is tagged as being in the window or the main list. The cache now tracks the front, back and length of both lists instead of one front/back pair. The shared remove/append helpers update whichever list the node is tagged with.
- **Sizing:** the window gets 1% of capacity, at least one slot; the main list gets the rest. With capacity 1, the window is the whole cache and there is no contest.
- **`get` and updating an existing key:** the key moves to the most-recent end of the list it's already in. The frequency counter is still bumped before anything else changes.
- **New key, cache not full:** the key goes to the most-recent end of the window. If the window is then over size, its oldest key moves into the main list with no contest.
- **New key, cache full:** the contest runs first. The window's oldest key is compared with the main list's oldest key using the frequency estimate. If the window key is strictly more frequent, it moves into the main list and the main key is evicted; otherwise the window key is evicted. Exactly one key leaves, and the newcomer reuses its slot at the most-recent end of the window, so no new memory is allocated.
- **Unchanged:** the frequency sketch, `sketch_heap_bytes`, and the `framework::Cache` impl.

I traced the in-file unit tests against the new behaviour by hand. One baseline test assumed newcomers are rejected outright, which is no longer true, so I renamed it `newcomer_enters_window_and_cold_candidate_loses_contest`. It now checks that key 3 is admitted, key 2 loses the contest and key 1 survives. The other two size-2 tests still hold as written. I added two tests: one where the window key wins the contest, and one for capacity 1.

The invariant suite and the JNI file both use only the public `new`/`try_new`/`get`/`put` API, so the internal restructuring shouldn't affect them. I didn't write `src/factory.rs`; it doesn't exist in the subject, and the change didn't need it.
