# H02

Replacing the single main LRU with a segmented LRU (20% probation / 80% protected) whose admission-contest victim is always the probation LRU will raise hit rate by shielding re-referenced keys from displacement.

## Parent

baseline

## Changes

In `src/tiny_lfu/mod.rs`, split the one recency list into two lists over the same `nodes` arena: **probation** and **protected**. Add a region tag to `Node` (`Probation`/`Protected`), and replace `head/tail` in `TinyLfuCache` with `prob_head/prob_tail/prob_len` and `prot_head/prot_tail/prot_len`. Generalise `unlink`/`push_back` to operate on the list identified by the node's tag (update the correct head/tail/len).

Sizing: `protected_cap = capacity * 8 / 10` (may be 0 for tiny capacities); probation has no hard cap — it holds whatever the protected segment does not.

Behaviour:
- New keys (spare capacity, or winning the contest) are inserted at **probation MRU**.
- On a hit (`get`, or `put` updating an existing key):
  - node in probation → unlink from probation, push to **protected MRU**; if `prot_len > protected_cap`, demote protected LRU to **probation MRU** (retag, relink).
  - node in protected → promote to protected MRU.
  - If `protected_cap == 0`, a probation hit just promotes within probation.
- Admission contest at capacity: the *victim* is `prob_head` if probation is non-empty, otherwise `prot_head`. Compare `sketch.estimate(incoming) > sketch.estimate(victim)` exactly as today; on admission evict the victim, reuse its slot, and insert the newcomer at probation MRU. On rejection nothing moves.

Invariants: `map.len() == prob_len + prot_len <= capacity`; `prot_len <= protected_cap` after every operation; each mapped node lives in exactly one list; sketch increment precedes any residency change on every get/put. Do not change `CountMinSketch` or the `framework::Cache` impl. The existing unit tests should still hold (capacity 2 → protected_cap 1); re-check `eviction_prefers_hot_items` and adjust only if the victim identity legitimately changes.

## Rationale (optional)

In the baseline, a key hit once and then idle drifts to the LRU head and becomes the victim as readily as a one-hit key. SLRU makes the victim pool consist of keys not yet re-referenced since admission, so the contest compares the newcomer against the weakest residents, while proven-reused keys survive longer — a different bucket-movement axis from adding an admission window.
