# H01

Splitting v001's main region into an SLRU with 20% probation and 80% protected, and taking the admission victim from the probation LRU, will raise hit-rate above 0.5425, with most of the gain on web_0.

## Parent

cycle/0001/v001

## Changes

Work in `src/tiny_lfu/mod.rs` and keep the window logic from v001 exactly as it is (1% window, `WINDOW_PERCENT`, the u32 sketch with no aging). The only change is that the main region becomes a segmented LRU.

- Replace `Region::Main` with two variants, `Region::Probation` and `Region::Protected`. Replace the single `main: List` with `probation: List` and `protected: List`, and update `list_mut` to match. Add a `protected_cap` field equal to `main_cap * 80 / 100` (integer floor). Probation has no hard cap of its own: it holds whatever main space protected does not use, so `probation.len + protected.len <= main_cap`.
- Spilling the window LRU into main, both in the not-full path of `put` and when a candidate wins in `evict_for_insert`, now does `push_back(cand, Region::Probation)`.
- `promote(idx)` behaves as follows:
  - Window: move to the window MRU, as before.
  - Protected: move to the protected MRU.
  - Probation: unlink the node and push it to the protected MRU. If `protected.len` is now greater than `protected_cap`, demote the protected LRU (`protected.head`) to the probation MRU. If `protected_cap == 0` (tiny caches), keep the node in probation and move it to the probation MRU instead.
- In `evict_for_insert`, the guard `self.main.len < self.main_cap` becomes `probation.len + protected.len < main_cap`. The victim is `probation.head`, falling back to `protected.head` if probation is empty. If both are empty, the candidate leaves, as before. The contest rule stays strict `cand_freq > victim_freq`.
- Everything else stays the same: `get` and `put` increment the sketch before the lookup, freed arena slots are reused, and `evict` removes the key from the map.
- Update the existing unit tests in the file only where they reference `Region::Main`. Their observable behaviour at capacities 1 and 2 must not change: with capacity 2, main_cap=1 and protected_cap=0, so main acts as a single probation slot, the same as v001.

## Rationale (optional)

Cycle 0001's v002 showed that SLRU helps on its own (biggest gain on scan-heavy web_0), and v001's window is the incumbent. The two were never combined. Isolating this one step tells us whether the SLRU gain adds to the window gain, which is the first open question in the cycle insight.
