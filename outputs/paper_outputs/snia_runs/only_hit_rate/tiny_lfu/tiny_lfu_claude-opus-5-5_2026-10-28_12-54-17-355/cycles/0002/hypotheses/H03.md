# H03

Replacing v001's fixed 1% window with a hill-climbing window that is resized every capacity accesses based on the change in sampled hit-rate will raise hit-rate, mostly at the large size where the 1% window's gain shrank.

## Parent

cycle/0001/v001

## Changes

Work in `src/tiny_lfu/mod.rs`. Keep v001's single main LRU, the u32 sketch with no aging, and the strict `>` contest. The only change is that `window_cap` and `main_cap` become adaptive.

- Add these fields to `TinyLfuCache`:
  - `sample_hits: u64`, `sample_count: u64`
  - `prev_hit_rate: f64` (initially 0.0)
  - `step: isize` (initially `+(capacity as isize * 5 / 100).max(1)`, which grows the window first)
  - `sample_period: u64 = capacity.max(64) as u64`
- In `get`, increment `sample_count` on every call and `sample_hits` on every hit. When `sample_count >= sample_period`, call a new `climb()` method and then reset both counters to zero.
- `climb()` works as follows:
  - Compute `hr = sample_hits / sample_count`.
  - If `hr < prev_hit_rate - 0.001`, reverse direction (`step = -step`). Otherwise keep the direction.
  - Then shrink `|step|` by multiplying it by 0.98, keeping a floor of 1.
  - Set `window_cap = clamp(window_cap as isize + step, 1, capacity as isize * 80 / 100)`, with a further floor of 1 and the constraint `window_cap <= capacity - 1` whenever capacity >= 2. Set `main_cap = capacity - window_cap`, and set `prev_hit_rate = hr`.
- Do not move nodes eagerly when the caps change. Rebalance lazily:
  - In the not-full path of `put`, spill window LRU nodes to main while `win.len > window_cap && main.len < main_cap`.
  - In `evict_for_insert`, when the cache is full:
    - If `win.len > window_cap`: run the existing contest with the window LRU as candidate.
    - If `win.len < window_cap`, so main is over its cap: evict the main LRU directly (the victim leaves without a contest) and return its slot. The window then grows by one through the newcomer insert.
    - If `win.len == window_cap`: run the contest exactly as in v001.
  - `win.len + main.len` must never exceed `capacity`, and every node must stay in exactly one list.
- `capacity == 1` keeps window_cap=1 and main_cap=0, and the climber is a no-op there. For tiny capacities (≤ 64), sampling is effectively disabled for the existing unit tests, because they never reach 64 `get`s, so their behaviour does not change.

## Rationale (optional)

v001's gain shrank as capacity grew, and the cycle insight asks whether 1% is the best window size. This hypothesis tests that question as its own axis, separate from H01 (SLRU) and H02 (aging): instead of guessing one size, the window adapts to each trace and capacity.
