# H03

Rebalancing the window eagerly on each retarget and ending each climber sample after one window turnover, rather than after `capacity` gets, will make the hill climber effective at both cache sizes and raise hit-rate, especially for web_0 at 131072.

## Parent

cycle/0003/v001

## Changes

Work in `src/tiny_lfu/mod.rs` of cycle/0003/v001.

1. **Eager rebalance on retarget.** At the end of `climb()`, after `window_cap`, `main_cap` and `protected_cap` are updated, move entries immediately so that each list fits its new cap:
   - While `win.len > window_cap` and `win.len > 1`: move the window LRU (`win.head`) to probation MRU. If main would then exceed `main_cap`, first evict the main victim (`main_victim()`), using the existing `evict()`. Treat this as a contest: if the window LRU's sketch estimate is not `>` the victim's, evict the window LRU instead of moving it.
   - While `main_len() > main_cap`: move the probation LRU (or protected LRU if probation is empty) to window **LRU** (head side), so it is the next candidate, not a fresh one. If needed, add a `push_front` helper mirroring `push_back`.
   - Then demote protected LRU entries to probation MRU while `protected.len > protected_cap`.
   - This costs O(|step|) once per sample and keeps `win.len + main_len() <= capacity` and `win.len >= 1` (when nodes exist). Freed arena slots must remain reusable. Push any evicted slot index onto a new `free: Vec<usize>` list, and in `put()` take slots from `free` before `nodes.push` or `evict_for_insert`, so the arena never exceeds `capacity`. The `nodes.len() < capacity` fill check becomes `map.len() < capacity`.
2. **Turnover-tied sample period.** Replace the `sample_count >= sample_period` trigger in `get()` with a dual condition. Keep counting `sample_hits`/`sample_count` per `get`, and add `window_inserts: u64`, incremented in `put()` on every new key inserted at window MRU. Fire `climb()` when `window_inserts >= window_cap as u64` **and** `sample_count >= MIN_SAMPLE_PERIOD`, then reset all three counters. One full window turnover is the time it takes a window retarget to show its effect. That time scales with the current window (small window → fast feedback, large → slow), not with total capacity or with a fixed constant, both of which have failed before.
3. Remove the `sample_period` field (or leave it unused). Keep the step size, `STEP_DECAY`, `REVERSE_TOLERANCE`, the 80/20 SLRU and the admission rule unchanged.
4. Update in-file tests: `check_structure` must also assert `map.len() + free.len() == nodes.len()` and `map.len() <= capacity`. The existing `adaptive_window_keeps_structure_sound` workload must still pass for capacities 1, 2, 3, 8 and 100.

## Rationale

Cycle 0003's v003 showed that the climber's feedback must match how fast the cache responds. Lazy one-per-insert rebalancing meant retargets were scored before they took effect, and a capacity-tied period was too slow at 131072. Eager rebalancing removes the lag, and a window-turnover period ties the sample to the region that the retarget actually changed. The hypothesis is refuted if web_0 at 131072 does not improve over 0.5846, or if either small-size point regresses.
