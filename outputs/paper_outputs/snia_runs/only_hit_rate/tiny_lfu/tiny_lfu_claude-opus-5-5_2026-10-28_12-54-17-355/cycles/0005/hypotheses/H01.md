# H01

Counting each miss-then-insert once in the sketch, instead of twice, will raise hit-rate, mainly on hm_0 at the small size, because one-hit keys will no longer reach an estimate of 2 and beat genuinely reused probation victims.

## Parent

cycle/0004/v001

## Changes

This is a correctness change to `src/tiny_lfu/mod.rs` only. Leave the window climber, the protected-split climber, the SLRU, and the strict `>` admission exactly as they are in the parent.

Today `get()` calls `self.sketch.increment(key)` on every lookup, and `put()` calls `self.sketch.increment(&key)` again. On the usual driver pattern (`get` misses, then `put` the same key) a single access is counted twice.

- Add a field `last_miss_hash: Option<u64>` to `TinyLfuCache` and initialise it to `None` in `try_new`. Compute the hash with a small helper `fn key_hash(key: &K) -> u64` that uses `DefaultHasher` with a fixed seed different from the sketch row seeds (for example `0xA5A5_A5A5`).
- In `get()`: keep the unconditional `self.sketch.increment(key)`. On a miss, set `self.last_miss_hash = Some(key_hash(key))`. On a hit, set it to `None`.
- In `put()`: compute `h = key_hash(&key)`. If `self.last_miss_hash == Some(h)`, skip the sketch increment. Otherwise increment as today. In both cases set `self.last_miss_hash = None` afterwards. A `put` with no preceding `get` (as the in-file unit tests do) or an update `put` still counts once.
- Do not change `CountMinSketch` itself: no cap, no aging, no conservative update. Keep `MAX_COUNT` as is.
- Keep the existing unit tests passing. If `eviction_prefers_hot_items` or `update_promotes_existing_item_and_admits_hot_arrivals` changes outcome, check the scenario by hand. Those tests call `get(&3)` twice before `put(3)`, so the last miss is key 3 and its `put` is skipped: key 3 gets estimate 2 against key 2's estimate 1, so they should still pass. Do not weaken any assertion.

Extra metadata is one `Option<u64>`. Extra per-op cost is one hash on a `get` miss and one hash per `put`.

## Rationale

The cycle 0004 insight flagged this double count as a cross-cutting defect. It has never been tested on its own. With the double count, a newcomer touched once ties with, or beats, a probation victim that was hit once after admission. This is the recency-vs-frequency confusion that keeps hurting hm_0 at the small size.
