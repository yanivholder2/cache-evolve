# H03

Choosing the admission victim as the lowest-estimate entry among the 4 least-recent probation entries, instead of always the probation LRU, will raise hit-rate, mainly on hm_0, because cold probation entries get evicted ahead of recently admitted recency-driven ones.

## Parent

cycle/0004/v001

## Changes

All edits are in `src/tiny_lfu/mod.rs`, in `main_victim()` and the contest in `evict_for_insert()`. Leave both climbers, the window and protected sizing, the sketch, `promote()`, and strict `>` admission unchanged.

- Add `const VICTIM_SAMPLE: usize = 4;`.
- Add `fn sampled_main_victim(&self) -> Option<usize>`:
  - Walk from `self.probation.head` along `next` for up to `VICTIM_SAMPLE` nodes. Compute `self.sketch.estimate(&self.nodes[i].key)` for each and return the node with the lowest estimate. On ties, keep the earliest node (the most LRU), so that with equal counts the behaviour matches the parent.
  - If probation is empty, sample the first `VICTIM_SAMPLE` nodes from `self.protected.head` the same way.
- In `evict_for_insert()`, use `sampled_main_victim()` for the admission contest (the `let victim = match self.main_victim()` site). Compare `cand_freq > victim_freq` against the sampled victim's estimate, which is then the minimum of the sample. Reuse that value and do not re-estimate.
- The direct-evict paths (`win.len < window_cap` and the defensive window-empty branch) should also use `sampled_main_victim()`, so that main always sheds its coldest sampled entry.
- `evict(victim)` already unlinks from whichever list the node is in, so no other list bookkeeping is needed. Keep `main_victim()` if other code still uses it. Otherwise it may be removed.

Per-op cost is up to 4 extra sketch estimates (4 hashes each) per full-cache insert. Metadata is unchanged.

## Rationale

Cycles 0003 and 0004 found that hm_0 loses under SLRU because probation is strict LRU. A recency-driven entry that was just admitted, and just won its contest, can be evicted before a stale, colder entry that sits one or two slots further along. Sampling the probation tail (a small-k form of the sampled eviction in Redis and Caffeine) lets frequency choose among the oldest few entries. It touches neither the feedback loops that keep failing nor the tie-break rule, which is settled.
