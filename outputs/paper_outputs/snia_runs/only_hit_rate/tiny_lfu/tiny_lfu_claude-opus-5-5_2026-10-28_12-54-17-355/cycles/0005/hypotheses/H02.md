# H02

Replacing the hit-rate-delta window climber with a ghost-list controller (ARC-style), where a hit on a recently rejected window candidate grows the window and a hit on a recently evicted main victim shrinks it, will raise hit-rate, especially at the large size where the climber stalls.

## Parent

cycle/0004/v001

## Changes

All edits are in `src/tiny_lfu/mod.rs`. Keep SLRU, the strict `>` admission contest, the sketch, and lazy rebalancing (`evict_for_insert`, the `put` spill loop) unchanged. The point is to give the window size a counterfactual signal in place of noisy sampled deltas.

1. **Two bounded ghost sets of key hashes (no values):**
   - `ghost_win`: keys of window candidates that lost the admission contest, plus window nodes evicted directly. Fed from the `self.evict(cand)` branches in `evict_for_insert`.
   - `ghost_main`: keys of main victims evicted, fed from `self.evict(victim)` and the `main_victim()` direct-evict branch.

   Implement each as a `HashSet<u64>` plus a `VecDeque<u64>` FIFO for ordering, each capped at `capacity` entries (pop the oldest when full). Hash with `DefaultHasher` and a fixed seed different from the sketch row seeds.
2. **Controller, in `put()` for a key not already resident, before `evict_for_insert`:**
   - If the hash is in `ghost_win`, remove it and grow the window: `window_cap += delta`, where `delta = max(1, ghost_main.len() / ghost_win.len().max(1))` and is capped at `capacity / 32` (at least 1).
   - Otherwise, if the hash is in `ghost_main`, remove it and shrink the window by the symmetric delta.
   - Clamp `window_cap` to `[1, upper]` with the existing `upper` formula (`MAX_WINDOW_PERCENT`, `cap - 1`). Then recompute `main_cap = capacity - window_cap` and `protected_cap = main_cap * protected_pct / 100`, as `climb()` does today.
3. **Remove the window turn from `climb()`.** Drop the `climb_turn` alternation, so every sample period runs the existing protected-split branch unchanged (same `prot_step`, `REVERSE_TOLERANCE`, and `STEP_DECAY`). The `step` and `prev_hit_rate` fields can be deleted. Keep the `protected_pct` bounds, which `check_structure` asserts.
4. Keep the starting window at `WINDOW_PERCENT` = 1%.
5. Keep every invariant in `check_structure`: `window_cap >= 1`, `window_cap + main_cap == capacity`, `window_cap <= capacity - 1` when `capacity >= 2`, and the `protected_cap` formula. With `capacity == 1`, skip the controller.

Metadata cost is up to `2 * capacity` u64 hashes plus deque overhead. The implementer should report this, since metadata-size has not been measured for four cycles.

## Rationale

Every timing retune of the hill climber has failed (cycles 0002–0004). The cause was the feedback signal: it is noisy, lags behind lazy rebalancing, and is biased by warmup. Ghost hits are a direct, per-event counterfactual for "would a bigger or smaller window have hit this?". They do not need sample periods or step decay, which removes the timing knobs that kept failing.
