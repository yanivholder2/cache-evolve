# H03

Letting a window candidate win admission ties only when it was hit at least once while in the window (an explicit reuse signal) lets demonstrably reused newcomers through without opening the bar to one-hit wonders, and raises the hit-rate summary above cycle/0005/v003.

## Parent

cycle/0005/v003

## Changes

Work in `src/tiny_lfu/mod.rs`. Leave the sketch untouched: no aging, double counting kept, plain update, independent row hashes. The climbers and `sampled_main_victim` also stay as they are.

1. Add `reused: bool` to `Node<K, V>`. Set it to `false` wherever a node enters the window as a newcomer: the `nodes.push` path in `put`, and the slot-reuse path after `evict_for_insert`, where `self.nodes[freed].reused = false` must be reset explicitly because the slot is recycled.
2. In `promote`, in the `Region::Window | Region::Protected` arm, set `self.nodes[idx].reused = true` when `region == Region::Window`. Hits in protected or probation do not touch the flag, since it is only read for window candidates.
3. In `evict_for_insert`, change the contest to
   ```rust
   let cand_reused = self.nodes[cand].reused;
   if cand_freq > victim_freq || (cand_reused && cand_freq == victim_freq) {
   ```
   Keep strict `>` for candidates that were never re-referenced in the window.
4. Add a unit test where a window candidate with a window hit ties the sampled victim's estimate and is admitted into probation. Add another where an un-hit candidate with the same tie is rejected.

## Rationale

Every sketch-side change to the tie rule (cycle 0004 `>=` at estimate ≥ 2, cycle 0007 conservative update) moved the bar for *all* candidates. That cost either web_0 large, where fewer warm newcomers were admitted, or hm_0 small, where more false admissions got in. This hypothesis instead gates the tie-break on direct evidence of reuse, which the window can observe but the sketch cannot distinguish from collision noise. It should lower the bar only for candidates that showed temporal locality while in the window, which is the recency signal hm_0 seems to want. Scan and one-hit traffic on web_0 still face strict `>`.
