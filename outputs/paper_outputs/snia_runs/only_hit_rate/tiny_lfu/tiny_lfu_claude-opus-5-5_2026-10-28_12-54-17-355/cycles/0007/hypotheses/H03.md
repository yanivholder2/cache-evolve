# H03

Hashing each key only once per sketch operation, with row indexes derived by double hashing, will lower per-op-time below the parent's while keeping hit-rate within ±0.001 of the parent's 0.5617.

## Parent

cycle/0005/v003

## Changes

Today every `increment` or `estimate` on `CountMinSketch` builds a new `DefaultHasher` (SipHash) for each of the 4 rows. That is 4 full hashes per sketch call. A full-cache insert costs about 4 + 4 + 16 + 4 of them (get increment, put increment, 4 victim estimates, candidate estimate). Replace this with a single hash per key.

1. Add `fn hash_key<K: Hash>(key: &K) -> u64`. It hashes the key once with one `DefaultHasher` and passes the result through a 64-bit finaliser (splitmix64 / murmur3 fmix64) so the high and low halves are well mixed.
2. Add `fn positions(&self, h: u64) -> [usize; SKETCH_DEPTH]`. Let `h1 = h as u32 as u64` and `h2 = ((h >> 32) | 1)`, so `h2` is odd and never zero. Row `i` gets index `(h1.wrapping_add((i as u64).wrapping_mul(h2))) as usize & (self.width - 1)`. This is Kirsch–Mitzenmacher double hashing.
3. Rewrite `increment` and `estimate` to call `hash_key` once and then index rows through `positions`. Keep plain (non-conservative) increments, `u32` counters and `MAX_COUNT`. Remove the per-row `position(key, seed)` function.
4. Flatten `counts: Vec<Vec<u32>>` into a single `Vec<u32>` of length `depth * width`, indexed `row * width + col`. This removes one pointer chase per row. `heap_bytes` must still return `depth * width * size_of::<u32>()`.

Do not change the climbers, the `sampled_main_victim` sample size, the admission rule, or the double counting. Every existing test must keep passing. Add one test checking that `estimate` never under-counts: increment 1000 distinct keys a random number of times (1–5) on a small sketch, and assert that each estimate is at least its true count.

## Rationale (optional)

Six cycles of insights have flagged per-op-time as never targeted. Every hit-rate gain in this lineage has added sketch estimates, and v003's sampled victim adds 4 more per full-cache insert. This change targets the per-op-time dimension directly with nearly no effect on hit-rate. Collision behaviour changes from independent per-row seeds to double hashing, which is known to keep count-min error bounds. A measurable latency drop with flat hit-rate would give the lineage headroom for later changes that need more sketch work, such as aging or larger samples.
