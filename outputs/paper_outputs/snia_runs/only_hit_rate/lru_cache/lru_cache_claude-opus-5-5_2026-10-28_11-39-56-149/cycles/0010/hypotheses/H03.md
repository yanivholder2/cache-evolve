# H03

Switching the count-min sketch to conservative update (increment only the rows that hold the current minimum) will raise hit-rate on hm_0 by removing collision-inflated estimates that let one-shot candidates tie or beat warm victims under the long aging periods.

## Parent

cycle/0009/v002

## Changes

The only change is in `FreqSketch::increment()` in `src/lru_cache/mod.rs`, on the branch where `self.door_contains(hash)` is true. The doorkeeper branch (first touch only sets the bits) is untouched.

Replace the loop that bumps all four rows with a two-pass conservative update:

1. For rows 0..4, compute `(w, shift) = self.slot(hash, row)`, read `c = (self.table[w] >> shift) & 0xF`, and track `min`. You can keep the four `(w, shift, c)` tuples in a small stack array so `slot()` is not computed twice.
2. If `min < 15`, add `1u64 << shift` to every row whose `c == min`. Rows with `c > min` are left alone. This guarantees no counter exceeds 15, so the saturation guard is still respected.

Keep everything else as it is:
- `estimate()` (min over rows plus the doorkeeper bit)
- the `count += 1` and reset logic (halving with the `0x7777...` mask, doorkeeper clear, `count /= 2`)
- `reset_mult` (32 × at 64..=32_768, 16 × otherwise), the width, the climber, the protected split, and the duel

This applies at all capacities that use the sketch, i.e. whenever `win_cap > 0`. No size gate is needed, because the change only lowers overestimates and never pushes an estimate below a key's true post-doorkeeper count.

The existing tests should still pass. A single repeated key has all rows equal, so it still saturates at 15 + 1 = 16 in `sketch_saturates_and_halves`. Add one unit test: hash two distinct keys into a small sketch, increment key A many times and key B once past the doorkeeper, and assert that `estimate(B) <= 2`.

## Rationale (optional)

Every cycle since c4 has made the sketch's memory longer: 16 ×, and now 32 × at small size. More increments between halvings means more collision mass piles up in shared counters. Under plain count-min, a one-shot or cold key that collides in all four rows with warm keys picks up inflated counts. Because ties admit, that inflation directly weakens the strict one-shot filtering that hm_0 depends on. Conservative update is the standard fix: it tightens estimates for cold keys without changing what warm keys score. Unlike the c8 doorkeeper resize, it leaves the uniform first-touch +1 intact, which is the property that change destroyed.
