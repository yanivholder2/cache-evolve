# H02

Doubling the sketch aging period to 32 × capacity at large sizes (capacity > 32_768) will raise hit-rate on web_0@131072 by keeping its long-reuse keys warm in the admission duel.

## Parent

cycle/0009/v002

## Changes

This is a single-lever change to `reset_mult()` in `src/lru_cache/mod.rs`. Give capacities above 32_768 the same longer memory that small sizes already have:

```rust
fn reset_mult(capacity: usize) -> usize {
    if capacity >= 64 { 32 } else { 16 }
}
```

This sets 32 × for 64 <= capacity <= 32_768 (unchanged) and 32 × for capacity > 32_768 (new). Capacities below 64 stay at 16 ×. Nothing else changes: not the doorkeeper, the sketch width, the halving rule, the climber (including the large-size `step_init = min(capacity / 128, 1024)`), the 75% large-size protected share, or the duel.

Update the header comment and the `reset_mult` doc comment. In the unit test `sketch_aging_period_is_size_gated`, change the expectations for 131_072 and 32_769 to `* 32`. The 63 and 1 cases keep `* 16`.

Invariant: both 16384 cells must match the parent exactly. Only the 131072 cells may move.

## Rationale (optional)

At large size, the recent levers (the step gate in c7, the 75% split in c8) each traded hm_0 against web_0. The one lever that has helped both traces together is longer frequency memory, and it was tested only at small size (c9). Cycle 0009 also showed that protected residency for web_0's long-reuse keys is load-bearing at 131072. Under the 16 × period those keys can be halved twice between reuses and then lose duels. hm_0@131072 is frequency-driven, and its one-shot filtering should get stricter with longer memory, not weaker. So this is the first large-size lever expected to help both cells rather than trade one for the other.
