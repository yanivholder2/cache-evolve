# H01

Raising the small-size sketch aging period from 32 × to 64 × capacity will raise hit-rate on both 16384 cells by keeping frequency history across even longer multi-fill reuse gaps.

## Parent

cycle/0009/v002

## Changes

This is a single-lever change to `reset_mult()` in `src/lru_cache/mod.rs`. For `(64..=32_768).contains(&capacity)`, return `64` instead of `32`. All other capacities keep `16`. Nothing else changes: not the doorkeeper, the width (`max(4 * capacity, 64).next_power_of_two()`), the halving rule (`(w >> 1) & 0x7777...`, `count /= 2`), the climber, the 80%/75% protected split, or the duel.

Update the comments that describe the aging period: the file header and the doc comment on `reset_mult`. Update the in-file unit test `sketch_aging_period_is_size_gated` so that 16_384, 32_768 and 64 expect `* 64`. The 131_072, 32_769, 63 and 1 cases keep their current expectations. `sketch_saturates_and_halves` uses capacity 4, which falls back to 16 ×, so it stays unchanged.

Invariant: the 131072 cells must match the parent exactly. The size gate guarantees this.

## Rationale (optional)

Cycle 0009 showed that small-size memory length was the bottleneck: going from 16 × to 32 × lifted web_0@16384 and hm_0@16384 together. This variant asks how far that gain extends. A loss here, especially on hm_0@16384, would show that stale saturated counts (4-bit, capped at 15) have begun to lock out newly hot keys. That would bound the useful range at between 32 × and 64 ×.
