# H03

In cycle/0003/v002, unconditionally admitting window candidates that were re-referenced while in the window will raise small-size web_0 hit-rate without hurting hm_0, because hm_0's one-shot blocks never earn the flag.

## Parent

cycle/0003/v002

## Changes

All changes are in `src/lru_cache/mod.rs`. The sketch (width, doorkeeper, 16x reset, dedup) and the window and protected sizes stay exactly as in v002.

1. Add a `win_ref: bool` field to `Node`, placed after `segment: u8` so it sits in existing padding.
   The `node_fits_baseline_size` test (`<= 48` bytes for `Node<u64,u64>`) must still pass.
2. In `place`, set `win_ref = false` for every newly placed node.
3. In `touch`, in the `seg == WIN` branch, set `self.nodes[i].win_ref = true` before
   re-linking to window MRU. This branch covers both `get` hits and `put`-on-existing-key in
   the window.
4. In `put_tinylfu`, on a full arena, change the admission predicate to
   `admit = victim != NIL && (self.nodes[cand].win_ref || cand_est >= victim_est)`.
   Short-circuit so the two `hash_key`/`estimate` calls are skipped when `win_ref` is true.
   Handle the cand/victim indices as `usize` the same way as the existing code.
5. When a node leaves the window (in `move_to` to `PROB`, or on eviction), clear `win_ref`,
   so the flag means only "re-referenced during its current window stay".
6. Don't change the free-room path (`nodes.len() < capacity`), which already admits without a
   duel, or the `win_cap == 0` SLRU path.
7. Add one unit test. With capacity 10, put a key, `get` it while it is still in the window,
   build up a hotter probation victim with repeated gets, then push the key out of the window
   with fresh puts. Assert it is still resident (admitted despite a lower estimate). Make sure
   all existing tests still pass. Their candidates are never window-hit, except
   `overwrite_mru_at_capacity`, which already expects admission.

## Rationale

Cycle 0003's insight blamed the small-size web_0 loss on recency-reused candidates (estimate around 2, colder after the doorkeeper) losing the duel to probation victims with stale counts. A hit inside the roughly 160-entry window is direct, fresh evidence of short-range reuse, and is stronger than the sketch's decayed history. hm_0's scan traffic is mostly one-shot, so it rarely sets the flag, and its filtering gain should hold. This lever is independent of the reset period (H01) and of window sizing (H02).
