# H02

Fixing v002's sketch accounting will raise hit-rate, especially on web_0 at the small capacity, by sharpening the admission duel without changing segment sizes: count each access once, give the sketch 4x width, and use a longer halving period with a doorkeeper bit.

## Parent

cycle/0002/v002

## Changes

Change only the frequency-estimation path. Leave the window fraction (1%), the SLRU split (80% protected), `touch`, and the tie-admitting comparison `cand_est >= victim_est` in `put_tinylfu` exactly as in v002.

1. **Remove the double increment.** Add `last_miss_hash: u64` and `last_miss_valid: bool` to `LruCache`. In `get`, compute `h = hash_key(key)` once and increment the sketch as today. On a miss, set `last_miss_hash = h` and `last_miss_valid = true`. On a hit, set `last_miss_valid = false`. In `put_tinylfu`, compute `h = hash_key(&key)`, skip `self.sketch.increment(h)` when `last_miss_valid && last_miss_hash == h`, and always clear `last_miss_valid` afterwards. A put that was not preceded by a get-miss of the same key still increments once. Put on an existing key (the `touch` path in `put`) must also clear `last_miss_valid`.
2. **Wider sketch.** In `FreqSketch::new`, use `width = max(4 * capacity, 64).next_power_of_two()` instead of `max(capacity, 64)`. Leave `slot()` unchanged; it already derives the column from `row_shift`.
3. **Doorkeeper plus a longer reset.** Add a doorkeeper bitset to `FreqSketch`: `door: Vec<u64>` of `width` bits (4 hashed positions per key, using the existing `ROW_SEEDS` with a different multiplier such as `0x2545_f491_4f6c_dd1d`). In `increment(hash)`, if not all of the key's doorkeeper bits are set, set them and return without touching the counters (still increment `count`). Otherwise increment the 4-bit counters as before. `estimate(hash)` returns `counter_min + (1 if doorkeeper says present else 0)`. Change `reset_at` to `max(1, capacity * 16)`. On a reset, halve the counters as today and also clear the whole doorkeeper (`fill(0)`).
4. **Tests.** Update `sketch_saturates_and_halves` for the new reset period and the doorkeeper offset: with width 256 for `new(4)`, `reset_at = 64`, the first increment only sets the doorkeeper, and after saturation `estimate <= 16`. Then assert the post-halving bound. Existing behavioural tests (`admission_rejects_colder_candidate` and the others) must still pass. Check them carefully: one-shot keys now estimate 1 through the doorkeeper, and a key whose `get` missed and was then `put` estimates 1, not 2. Add a test that `get(&k)` (miss) followed by `put(k, v)` leaves `estimate(hash_key(&k)) == 1`.
5. **Cost.** Per-node size is unchanged. The sketch grows from about 0.5 to about 2.1 bytes per cache entry, plus 1 bit per counter-width for the doorkeeper. All operations stay O(1) except the existing amortised halving.

## Rationale (optional)

v002's insight puts the small-size web_0 slip partly on sketch noise rather than the window. A capacity-wide sketch collides often, frequent halving washes out evidence, and miss-then-put counts a never-reused key as 2, which inflates victims and penalises second-access candidates. This isolates the sketch-tuning lever so it can be compared directly against H01's window lever.
