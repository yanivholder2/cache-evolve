# H01

Replacing v002's fixed 1% admission window with a hill-climbed adaptive window/main split will raise hit-rate, mainly by recovering web_0 at the small capacity while keeping the hm_0 gains.

## Parent

cycle/0002/v002

## Changes

Keep v002's arena, three segments (PROB/PROT/WIN), `FreqSketch`, and the tie-admitting rule `cand_est >= victim_est` in `put_tinylfu` exactly as they are. Make `win_cap` (and with it `prot_cap`) change at runtime using a Caffeine-style hill climber:

1. **Initial split.** In `try_new`, for `capacity >= 3`, start with `win_cap = max(1, capacity / 100)` as before. Add fields `min_win = max(1, capacity / 100)` and `max_win = max(min_win, capacity * 8 / 10)`. Recompute `prot_cap = max(1, (capacity - win_cap) * 8 / 10)` whenever `win_cap` changes (add a helper `fn set_win_cap(&mut self, new: usize)` that does this). Keep `capacity < 3` on the plain SLRU path (`win_cap == 0`, no climbing).
2. **Sampling.** Add `sample_hits: u32`, `sample_ops: u32`, `prev_hit_rate: f64` (start at 0.0), `step: isize` (start at `+max(1, capacity / 16)` as isize, so the first move grows the window), and `sample_period = max(1000, 10 * capacity)` (an access count). In `get`, count every call as an op and count a hit when the key is found. Do not count `put` calls. When `sample_ops >= sample_period`, call `fn climb(&mut self)`.
3. **`climb()`.** Compute `rate = hits / ops`. If `rate < prev_hit_rate - 0.0005` (got worse), reverse direction: `step = -step`. Then decay the step: `step = step * 98 / 100`, but never let `|step|` fall below `max(1, capacity / 256)`. Set `prev_hit_rate = rate`, reset both counters, and apply `new_win = clamp(win_cap as isize + step, min_win, max_win)` through `set_win_cap`.
4. **Rebalancing after a resize (lazy and O(1) amortised).** Never evict during `climb`. Instead:
   - If the window shrank and `win_len > win_cap`: in `put_tinylfu`, before the normal full-arena path, move up to 2 window-LRU entries per call to `PROB` with `move_to` (no admission check, no eviction) until `win_len <= win_cap`. The arena stays full, so the next full-arena insert still runs the normal admission duel.
   - If the window grew: on the full-arena path, when `win_len < win_cap`, take the incoming key's slot from the main victim (probation LRU, else protected LRU) with no duel, `evict(victim)`, and `place(victim, key, value, WIN)`. This grows the window by one per insert.
   - If `prot_len > prot_cap` after a resize, demote up to 2 protected-LRU entries to probation-MRU per `touch` or `put`, using the same demotion code as in `touch`.
   - The full-arena path in `put_tinylfu` currently assumes `head[WIN] != NIL`. Keep that true: `min_win >= 1`, and the window is only drained down to `win_cap >= 1`.
5. **Invariants.** `map.len() <= capacity` always. All operations stay O(1) amortised (climb is O(1)). Add no new per-node fields, so `Node<u64,u64>` stays `<= 48` bytes. Existing unit tests use capacities 1–10 and fewer accesses than `sample_period` (≥1000), so no climb fires in them and they should still pass unchanged. Add a test that runs 50k accesses on capacity 1000 and asserts `win_cap` stays within `[min_win, max_win]` and `map.len() <= capacity`.

## Rationale (optional)

Both cycle insights single out the fixed 1% front segment as the cause of the repeated small-size web_0 shortfall (about 160 entries at 16384). A larger fixed fraction would likely cost hm_0 and large-size web_0. Hill-climbing lets each trace and size find its own split, which tests the main open question carried over from cycle 0002.
