# H03

Replacing the baseline LRU with a LIRS policy, ranking blocks by inter-reference recency through an LIR stack S and a resident-HIR queue Q, will raise hit-rate above v001 on both MSR traces, most of all on hm_0 and at the small capacity.

## Changes

Rewrite `src/lru_cache/mod.rs` as LIRS. Keep the public API (`try_new`, `new`, `get`, `put`, the `framework::Cache` impl), the `pub mod lru_cache_jni;` line, and the `capacity == 0 → None` / panic semantics, all unchanged.

Data structures, std only and no unsafe:
- One arena `Vec<Entry<K, V>>` indexed by `u32`, with a NIL sentinel. Each entry has `key`, `value: Option<V>` (None means a non-resident HIR), a `status` enum (`Lir`, `HirResident`, `HirNonResident`), and two independent intrusive link pairs: `s_prev/s_next` for stack S and `q_prev/q_next` for queue Q, plus `in_s`/`in_q` flags.
- `map: HashMap<K, u32>` covers every tracked key, resident or not. Keep a free list of arena slots for removed non-resident entries.
- Sizes: `hir_cap = max(1, capacity / 100)` and `lir_cap = capacity - hir_cap`. For capacity 1, treat everything as HIR.

Behaviour (standard LIRS, Jiang & Zhang 2002):
- **Hit on LIR:** move to the top of S. If it was the S bottom, run `prune()`, which pops HIR entries from the S bottom until the bottom is LIR, freeing arena slots for non-resident entries that are no longer in S.
- **Hit on resident HIR:** if the entry is in S, promote it to LIR, remove it from Q, move it to the S top, turn the S-bottom LIR into a resident HIR pushed to the Q tail, and `prune()`. If it is not in S, push it to the S top and move it to the Q tail; it stays HIR.
- **Miss (`put` of an untracked or non-resident key):** if resident count == capacity, evict the Q head. Drop its value and mark it `HirNonResident`; if it is not in S, remove it from `map` and free its slot. While LIR count < `lir_cap`, a new key becomes LIR at the S top. Otherwise, if the key was non-resident and still in S, it becomes LIR (with the same demotion of the S-bottom LIR plus `prune`). If not, it becomes a resident HIR at the S top and the Q tail.
- **`put` on a resident key** updates the value and applies the hit logic.
- Bound the metadata: if the number of non-resident entries in S exceeds `2 * capacity`, remove the oldest non-resident entries (track them with a third FIFO or scan from the S bottom up) so memory stays O(capacity).

Rewrite the in-file unit tests for LIRS semantics. Include a scan test where a hot LIR set survives a one-shot scan of `10 * capacity` keys, plus capacity-1/2 edge cases. Integration tests in `tests/` must pass unchanged.

## Rationale (optional)

Cycle 0001 found that soft scan resistance wins and that the benefit is limited by how far back reuse detection reaches. LIRS keeps reuse-distance history for non-resident blocks, so it detects long reuse distances that SLRU's probation list misses. It is a different family from both v001's segmentation and H02's frequency sketch, and it is the policy the trace format is named after.
