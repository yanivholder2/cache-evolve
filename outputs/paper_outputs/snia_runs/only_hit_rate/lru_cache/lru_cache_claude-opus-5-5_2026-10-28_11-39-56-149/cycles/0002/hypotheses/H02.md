# H02

Turning v001's SLRU into a W-TinyLFU cache, with a 1% admission-free LRU window in front of the SLRU main area and a lenient count-min-sketch admission (ties admitted), will raise mean hit-rate across both traces by adding frequency filtering on hm_0 without losing web_0's short-range recency hits.

## Parent

cycle/0001/v001

## Changes

Start from v001's `src/lru_cache/mod.rs` and add a third segment to the same arena:
- Add a segment constant `WIN: u8 = 2` and widen `head`/`tail` to `[u32; 3]`. Window capacity is `win_cap = max(1, capacity / 100)`. The main area is `capacity - win_cap`, split as in v001 (protected = 80% of main, at least 1; probation = the rest). For capacities below 3, fall back to v001 behaviour exactly (`win_cap = 0`).
- Add a frequency sketch implemented in the module with no crates. Use a 4-row count-min sketch of 4-bit counters packed into a `Vec<u64>`, with the width rounded up to a power of two near `capacity`. Derive the four row indices from one `std::hash` hash (`DefaultHasher` or `ahash`-free FxHash-style multiply) by using different seeds or rotations. `increment(key)` saturates each counter at 15. `estimate(key)` returns the min over the rows. Count increments; when the count reaches `10 * capacity`, halve every counter (shift right by 1, masking each nibble) and halve the count too.
- Call `sketch.increment(key)` on every `get` (hit or miss; on a miss, call it from `get` before returning `None`) and on every `put` of a new key.
- New keys go to the window MRU. A hit in the window moves the node to window MRU. Probation and protected hits keep v001's `touch` semantics (probation→protected promotion with protected-LRU demotion).
- When the window exceeds `win_cap`, its LRU becomes the *candidate*. If the main area has free room (arena not full), move the candidate to probation MRU. Otherwise compare against the *victim*, which is the probation LRU (or protected LRU if probation is empty). Admit the candidate if `estimate(candidate) >= estimate(victim)`; ties admit, the reverse of v003's strict-greater rule. If admitted, evict the victim and move the candidate to probation MRU. If rejected, evict the candidate. In both cases, remove the evicted key from `map` and reuse its arena slot for the incoming key.
- Keep `map: HashMap<K, u32>`, the in-place slot reuse, and the `u32` NIL sentinel.

Update the in-file unit tests so that eviction-order tests reflect window-then-main ordering for capacities of 3 or more. Add one test where a hot key survives a scan of `10 * capacity` one-shot keys. Integration tests in `tests/` must still pass unchanged.

## Rationale (optional)

The cycle 0001 continuation recommends this directly. v003 lost on web_0 because a cold sketch with strict-greater rejection blocked second accesses. Here the window absorbs short-range reuse and ties are admitted, while the sketch protects hm_0's frequent blocks from one-shot traffic.
