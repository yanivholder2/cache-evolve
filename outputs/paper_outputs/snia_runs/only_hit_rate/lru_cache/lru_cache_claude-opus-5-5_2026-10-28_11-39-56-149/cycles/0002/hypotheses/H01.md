# H01

Adding a bounded ghost list of recently evicted probation keys to v001's SLRU, so a returning ghost key goes straight into the protected segment, will raise hit-rate most at the 16384 size, where the 20% probation list is too short to catch long reuse distances.

## Parent

cycle/0001/v001

## Changes

Start from v001's `src/lru_cache/mod.rs` (arena SLRU, u32 indices, `PROB`/`PROT` segments, 80% `prot_cap`). Keep the `get` path, `touch`, `unlink`, and `push_back` as they are.

Add a ghost history of keys only (no values):
- New fields: `ghost_map: HashMap<K, u64>`, which maps a key to the sequence number it was given at eviction; `ghost_fifo: VecDeque<(K, u64)>`; `ghost_seq: u64`; and `ghost_cap: usize = capacity` (the same as the cache capacity). Use only std, no new crates.
- In `put`, when a victim is evicted from **probation** (`segment == PROB` at eviction time), push its key into the ghost: `ghost_seq += 1`, `ghost_map.insert(key.clone(), ghost_seq)`, `ghost_fifo.push_back((key, ghost_seq))`. When `ghost_fifo.len() > ghost_cap`, pop from the front and remove the popped key from `ghost_map` only if its stored sequence matches (lazy deletion, which handles keys that were re-ghosted). Do not ghost keys evicted from protected; that only happens when probation is empty.
- In `put`, for a new key (the miss path), check `ghost_map.remove(&key)` first. If the key was present (a ghost hit), insert the new node with `segment = PROT`, `push_back` it to protected MRU, and `prot_len += 1`. If `prot_len > prot_cap`, demote the protected LRU into probation MRU, exactly as in `touch`. Otherwise insert into probation as today. Keep the victim choice unchanged (probation LRU first, else protected LRU). Fill the reused slot first and only then pick its segment.
- For capacity 1 (`prot_cap == 0`), skip the ghost logic entirely.
- Leave stale `ghost_fifo` entries in place (lazy deletion); `ghost_map` holds the truth.

Update and extend the in-file unit tests. Add a test showing that a key evicted from probation and then re-put lands in protected and survives a following scan of `capacity` new keys. All existing behavioural tests in `tests/` must still pass; nothing there changes.

## Rationale (optional)

The cycle 0001 insight shows v001's gain is smallest at 16384: entries are evicted from the short probation list before their second access. A ghost list gives reuse detection a window equal to the full capacity, without spending a value slot on it. It costs extra key-only metadata, about one key per cache slot.
