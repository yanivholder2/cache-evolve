# H01

Raise the climber's initial step to 1024 only at large capacity (above 32_768) and keep 256 at small capacity, to lift large-size web_0 hit-rate without touching any small-size cell.

## Parent

cycle/0004/v002

## Changes

Only change how `step_init` is computed in `LruCache::try_new`. Today it is
`std::cmp::min(std::cmp::max(1, capacity / 64), 256)`. Replace it with:

```rust
let step_init = if capacity > 32_768 {
    std::cmp::min(capacity / 128, 1024)
} else {
    std::cmp::min(std::cmp::max(1, capacity / 64), 256)
};
```

At 131072 this gives 1024, which is about 0.8% of capacity, below the
roughly 1.5% safety bound from cycle 0006. At 16384 it stays at 256, and at
1000 it stays at 15, so the in-file `climber_keeps_window_in_bounds`
assertion `step_init == 15` still holds. Leave everything else as it is in
cycle/0004/v002: `sample_period` (clamp(10*cap, 2_000, 50_000)), the 2% decay
and reset-to-`step_init` rule in `climb()`, flip-on-drop, the 1%–40% window
range, the sketch (4x width, 16x reset, doorkeeper, dedup) and the duel rules.
Update the header comment that describes the step magnitude to match.

## Rationale (optional)

Cycle 0006 v001 used a 4x step (1024) at both sizes. At 131072 it scored
web_0 0.5887 against the incumbent's 0.5874, and hm_0 0.7456 against 0.7458.
At 16384 it lost badly on hm_0, because 1024 is 6.25% of capacity there.
This variant keeps v001's large-size behaviour and the incumbent's small-size
behaviour. If cell effects add up, the expected summary is about 0.5599,
which would be the first strict gain over the incumbent since cycle 0004.
