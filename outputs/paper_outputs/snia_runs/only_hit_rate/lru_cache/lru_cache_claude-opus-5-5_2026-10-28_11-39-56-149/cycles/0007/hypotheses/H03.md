# H03

Admit a warm candidate (sketch estimate at least 2) that lost the full-window admission duel with probability 1/64, to raise web_0 hit-rate by breaking lockout from stale inflated victim counts while keeping one-shot filtering intact.

## Parent

cycle/0005/v003

## Changes

Change only the full-window admission decision in `put_tinylfu`, the
`let admit = victim != NIL && { ... cand_est >= victim_est };` block after
"Window at (or above) target".

1. Add a field `rng: u64` to `LruCache`, seeded in `try_new` with a fixed
   non-zero constant (e.g. `0x9E37_79B9_7F4A_7C15`) so runs are deterministic.
   Add a private `#[inline] fn next_rand(&mut self) -> u64` that does an
   xorshift64 step (`x ^= x << 13; x ^= x >> 7; x ^= x << 17`) and returns
   the new state.
2. Compute the admit decision as: admit if `victim != NIL` and either
   `cand_est >= victim_est` (unchanged tie-admitting rule), or
   `cand_est >= 2 && (self.next_rand() & 63) == 0`. Only call the RNG when
   the deterministic rule has already rejected and `cand_est >= 2`, so the
   common path costs nothing extra. Compute the estimates before calling
   `next_rand` to avoid borrow conflicts.
3. Do not change the growing-window branch (`win_len < win_cap`), the
   sketch, doorkeeper, dedup, climber or the segment split. Keep cycle 0005
   v003's 75% `max_win` ceiling as it is.

Candidates seen only once have estimate 1 (doorkeeper bit only), so they
can never take the random path. hm_0's strict one-shot filtering is
preserved. Existing in-file tests involve estimate-1 candidates, or one
explicit reject (`admission_rejects_colder_candidate`: candidate estimate
1), so they stay deterministic and should pass unchanged.

## Rationale (optional)

Every recent loss came from loosening admission for one-shot keys or from
counting in-window reuse twice. This lever is different. It never helps
one-shot keys, and it adds no recency signal that the sketch already
counts. It targets a different failure: with the long 16x reset, a main
victim with a stale, saturated count can reject a series of genuinely
recurring candidates. Caffeine uses a similar random admission of warm
candidates. Parent is cycle/0005/v003, which behaves the same as
cycle/0004/v002 on every cell, so this also tests the other incumbent
lineage.
