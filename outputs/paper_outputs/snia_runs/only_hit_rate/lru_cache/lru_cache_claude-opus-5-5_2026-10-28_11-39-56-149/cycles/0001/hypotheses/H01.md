# H01

Splitting the single LRU list into a segmented LRU (20% probationary, 80% protected) so that only re-referenced entries reach the protected segment will raise hit-rate on the MSR web_0/hm_0 traces by resisting one-touch scan pollution.

## Parent

baseline

## Changes

Rework `LruCache` in `src/lru_cache/mod.rs` into a Segmented LRU (SLRU) on top of the existing arena:

- Add a `segment: u8` (or `bool protected`) field to `Node<K, V>`. To keep `Node<u64,u64>` at or below the baseline's 48 bytes, change `prev`/`next` from `Option<usize>` to `u32` indices using `u32::MAX` as the NIL sentinel (this makes room for the segment flag inside the same size).
- Replace `head`/`tail` with two lists: `prob_head/prob_tail` (probationary) and `prot_head/prot_tail` (protected), plus `prot_len: usize` and `prot_cap: usize = max(1, capacity * 8 / 10)` computed in `try_new`. For `capacity == 1`, `prot_cap` should be 0 and everything stays in probation (guard so the cache still works).
- Generalise `unlink(idx)` and `push_back(idx)` to take the list identity from `nodes[idx].segment`, so each node is always on exactly one list.
- `put` on a new key: insert at the MRU end of the **probationary** list. If `nodes.len() >= capacity`, evict the LRU of probation (`prob_head`); if probation is empty, evict the LRU of protected instead. Reuse the evicted slot in place as the baseline does (remove the evicted key from `map`, overwrite key/value).
- `get` hit (and `put` on an existing key): if the node is in probation, unlink it and push it to protected MRU and `prot_len += 1`; if `prot_len > prot_cap`, demote protected LRU (`prot_head`) to probation MRU and `prot_len -= 1`. If already protected, just move it to protected MRU.
- Keep these invariants: `map.len() <= capacity`; every key in `map` points to a live node on exactly one list; values read back as written (P1–P3 in the invariant gate).
- The unit tests in `mod.rs` that assert exact LRU eviction order (e.g. `eviction_removes_lru`, `access_updates_lru_order`, `put_updates_lru_order`, `get_middle_node_promotes_correctly`) can be updated to match SLRU semantics; do not touch `tests/` or `src/test_utils/`.

## Rationale (optional)

MSR block-I/O traces have many one-off reads mixed with a re-used working set. Plain LRU lets each one-off read push a useful block one step toward eviction. SLRU only lets those reads churn the 20% probation segment. Moving entries between the two segments costs about the same as the baseline's O(1) relinking, so per-op time should stay close to baseline.
