# H02

Doubling the sketch's aging period `reset_at` to 32 × capacity at small size only (capacity ≤ 32_768) will raise small-size hit-rate, because longer frequency memory sharpens the duel at tight capacity.

## Parent

cycle/0008/v002

## Changes

All changes are in `src/lru_cache/mod.rs`, inside `FreqSketch::new`. Change `reset_at` from `max(1, capacity * 16)` to:

```
let mult = if capacity >= 64 && capacity <= 32_768 { 32 } else { 16 };
reset_at: max(1, capacity.saturating_mul(mult)),
```

The `>= 64` lower bound keeps tiny caches exactly as they are, so the `sketch_saturates_and_halves` unit test, which builds `FreqSketch::new(4)` and expects `reset_at == 64`, still passes unchanged. It also keeps the window-disabled `FreqSketch::new(1)` path unchanged.

Nothing else changes: not the width, the doorkeeper (it is still cleared on each halving), the halving rule, the climber, or the splits. Large-size behaviour must be exactly the same as the parent's. Add a unit test asserting that `FreqSketch::new(16_384).reset_at == 16_384 * 32` and `FreqSketch::new(131_072).reset_at == 131_072 * 16`. Update the top-of-file doc comment and log the multiplier in `try_new`'s `log::info!`.

## Rationale (optional)

The cycle 0008 insight lists `reset_at` at small size only as an untested lever for the limit on small-size web_0. The c4 result showed that faster aging hurts small-size hm_0. The opposite direction has never been tried. At 16384 entries, the current period of about 262k accesses is short compared with hm_0 and web_0 reuse distances measured in cache-fills. A longer period keeps warm keys' counts above one-shot scan keys for longer, which strengthens the strict one-shot filtering that small-size hm_0 depends on. The size gate keeps the large-size cells unchanged, so any change is attributable to this one lever.
