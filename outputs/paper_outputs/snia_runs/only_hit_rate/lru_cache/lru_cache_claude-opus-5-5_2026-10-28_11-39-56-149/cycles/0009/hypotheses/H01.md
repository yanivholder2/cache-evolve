# H01

Letting a slow second hill climber adapt the protected share `prot_pct` at large size only, between 60% and 85%, will raise summary hit-rate by finding the best split for each trace at runtime instead of using a fixed 75%.

## Parent

cycle/0008/v002

## Changes

All changes are in `src/lru_cache/mod.rs`. Nothing changes for capacities ≤ 32_768. Small size keeps `prot_pct = 80` fixed and its code path must be bit-for-bit the same as the parent's.

Add these fields to `LruCache`: `prot_adapt: bool` (true iff `capacity > 32_768`), `prot_step: isize` (initial `-2`, so the first move continues the parent's shift toward a longer probation), `prot_rounds: u32`, `prot_hits: u64`, `prot_accesses: u64`, `prot_prev_hr: f64` (initial `0.0`), and the constants `PROT_MIN = 60`, `PROT_MAX = 85`, `PROT_EVERY = 4`.

In `climb()`, keep the window climber exactly as it is: same flip-on-drop, same decay, same `win_cap` update, every round. Before `self.sample_hits` and `self.sample_accesses` are reset, if `prot_adapt` is set, add them to `prot_hits` and `prot_accesses` and increment `prot_rounds`. When `prot_rounds == PROT_EVERY`:
- compute `hr = prot_hits / prot_accesses`;
- if `hr < prot_prev_hr`, negate `prot_step`;
- set `prot_pct = clamp(prot_pct + prot_step, PROT_MIN, PROT_MAX)`;
- set `prot_prev_hr = hr` and reset the three accumulators.

The aggregation over 4 rounds lets the window climber's moves average out, so the two climbers do not fight over the same single sample. The existing `prot_cap` recompute and demotion loop at the end of `climb()` already uses `self.prot_pct`, so a shrink demotes protected LRUs to probation immediately. A grow just lets `touch()` fill the larger protected segment lazily. Do not decay `prot_step`; it stays at ±2.

Keep these invariants: `prot_len <= prot_cap` after `climb()`, and `prot_cap >= 1`. Update the doc comment at the top of the file. Leave the `protected_share_is_size_gated` test valid: `prot_pct` starts at 75 for large and 80 for small. Add a unit test showing that `prot_pct` stays within [60, 85] for a large cache under the mixed workload of `climber_keeps_window_in_bounds`.

## Rationale (optional)

c7 and c8 showed that the large-size split trades web_0 (wants a longer probation) against hm_0 (wants a larger protected segment). A static gate cannot satisfy both. A hill climber on the split can, because each trace pushes `prot_pct` in its own direction. Climbing slowly, once every 4 rounds, leaves the proven window climber unchanged.
