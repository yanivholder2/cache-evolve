# H03

Raising the hill climber's window ceiling from 40% to 75% of capacity will raise web_0 hit-rate at the small size, where the climbed window is likely pinned at its current ceiling.

## Parent

cycle/0004/v002

## Changes

In `LruCache::try_new` in `src/lru_cache/mod.rs`, change
`let max_win = std::cmp::max(min_win, capacity * 40 / 100);`
to
`let max_win = std::cmp::max(min_win, capacity * 75 / 100);`.

Leave everything else exactly as it is in v002:
- sample-period cap 50,000 and step cap 256
- 2% step decay and reset
- the `min_win` 1% floor
- sketch settings: 4x width, `reset_at = 16 * capacity`, doorkeeper, dedup
- the duel with ties admitted, and the grow-path `victim_est <= 1` rule

**Invariant to check.** When `win_cap` is large, the main area is `capacity - win_cap`, which is at least 25% of capacity. `climb()` recomputes `prot_cap = max(1, main * 8 / 10)` and demotes overflowing protected entries. That logic already handles any `win_cap <= capacity - 1`. Make sure `max_win < capacity` for every capacity of 3 or more (for capacity 3, 75% truncates to 2, which is fine). Add a `debug_assert!(max_win < capacity)` in `try_new`. Update the header comment from "40%" to "75%". `climber_keeps_window_in_bounds` reads `max_win` from the struct, so it should still pass.

Optional: add a `log::info!` in `climb()` when `win_cap` reaches `max_win`. It should be logging only, with no change in behaviour. This shows whether the old ceiling was actually binding.

## Rationale

The only lever that has ever moved small-size web_0 a lot is enlarging the front recency segment (c3, c4). v002 started at about 163 entries and climbed in steps of up to 256. On web_0@16384 the climber only reverses when hit rate drops, so it probably kept growing until it hit the 40% ceiling (6553). If that ceiling binds, a higher one lets the window become an almost-LRU front for this recency-driven trace. The 1% floor stays, so hm_0 can still be climbed back down. If web_0@16384 stays the same, the ceiling was not binding. That result would focus future work on the period and step caps (see H01) or on admission signals (see H02).
