# H02

Giving a window candidate that was re-referenced while in the window a bounded +1 bonus on its sketch estimate in the TinyLFU duel will raise web_0 hit-rate without reopening the hm_0 burst leak that cycle 0004's unconditional bypass caused.

## Parent

cycle/0004/v002

## Changes

All edits are in `src/lru_cache/mod.rs`.

1. **Per-node reuse flag.** Record whether a node was hit while it sat in the window segment. Store the flag in the existing `segment: u8` field so the node stays the same size (`node_fits_baseline_size` must still pass):
   - Use bit `0x80` for the flag and add `const WIN_REUSED: u8 = 0x80;`.
   - Read the segment everywhere as `segment & 0x7F`. This applies to `unlink`, `push_back`, `evict`, `move_to`, `touch`, and the tests that compare `segment` with `WIN` or `PROB`. Using a separate `bool` field instead is acceptable only if the size test still passes.
   - In `touch()`, in the `seg == WIN` branch, set the flag.
   - Clear the flag whenever a node leaves the window: in `move_to` when the target segment is not `WIN`, and in `place` for a new key.

2. **Bounded duel bonus.** Add a helper `cand_score(idx) -> u64`. It returns `self.sketch.estimate(hash_key(&key))`, plus 1 if the node has `WIN_REUSED` set and that estimate is at least 2. Requiring an estimate of at least 2 means the doorkeeper bit and at least one real counter increment both exist. A key that was seen once and then hit once within the same window stay still gets the bonus. A key that never got past the doorkeeper does not.
   - Use `cand_score` instead of the raw `cand_est` in both duel sites in `put_tinylfu`: the window-growing branch and the window-at-target `admit` computation.
   - Keep the comparison as `cand >= victim`, so ties still admit. Keep the grow-path `victim_est <= 1` clause.
   - The victim side gets no bonus.

3. Do not change anything else. That includes the climber (period cap 50,000, step cap 256, 1% floor, 40% ceiling), the sketch (4x width, `reset_at = 16 * capacity`, doorkeeper, dedup) and the SLRU split. No candidate skips the duel.

4. Add a unit test. Build a cache where a window candidate with an in-window hit and estimate 2 faces a probation victim with estimate 3. The test checks that the candidate is admitted with the bonus, and that a candidate with the same estimate but no in-window hit is rejected.

## Rationale

Cycle 0004 v003 showed that in-window reuse carries signal on web_0. Used as a bypass, though, it let burst-then-dead hm_0 blocks into main and cost about 3.3 points of small-size hm_0. A +1 bonus only decides duels that the candidate loses by exactly one count. Hot main residents (estimate ≥ cand + 2) are still protected. The cross-cycle insights point the same way: soft, relative signals win and hard overrides lose. The test is whether web_0@16384 rises above 0.4205 while hm_0@16384 stays close to 0.485.
