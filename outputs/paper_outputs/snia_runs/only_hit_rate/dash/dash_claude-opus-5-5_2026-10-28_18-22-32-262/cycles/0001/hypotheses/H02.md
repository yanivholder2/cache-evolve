# H02

Requiring two stash hits before an item is promoted from the stash into its target bucket will raise hit-rate on the scan-heavy MSR traces by keeping items reused only once from pushing proven residents out of the normal buckets.

## Changes

All edits are in `src/dash/segments/dash_segment.rs`. No Item layout change: reuse the existing `Item::lfu_counter` field, which the ClassicLRU policy never reads.

Today, in `promotion_get`, the first stash hit removes the item from stash and calls `promote_to_target`. Every target insert evicts the target's LRU resident into the stash once the target is full. With a 24:8 stash:normal split, most data goes through the stash, so a scan or a burst of keys reused once churns the small normal tier.

New stash-hit branch in `promotion_get`:

1. Find `item_idx` in `core.stash_buckets[stash_idx]` as today.
2. Read `lfu_counter` through `get_items_mut()[item_idx]` and increment it (saturating).
3. If the counter is now `< 2` (this is the item's first hit while in stash):
   - Do not promote. Call `core.stash_buckets[stash_idx].get_from_position(item_idx)` so the stash's policy refreshes it (ClassicLRU moves it to MRU).
   - Return that reference. The key stays in the stash.
4. Otherwise (second or later stash hit):
   - Reset the counter to 0 before moving, so the gate starts fresh if the item is later demoted back to stash.
   - Then `remove_at` and `promote_to_target(core, data, insert_pos)`, exactly as today, including the existing `unreachable!` check that finds the key in the target.

Also reset `lfu_counter` to 0 on items that enter the stash through demotion. Do this in `demote_from_normal_bucket` before both `core.put_at(Slot::Stash, ...)` calls, by making the item binding `mut`. Each stay in the stash then needs two fresh hits.

Leave the target-hit, probing-hit and miss branches unchanged. `Segment::put` keeps its default (stash Back), and `Item::new` already starts `lfu_counter` at 0.

Invariants to keep: the stash-hit-without-promotion path returns `Some` with the matching key, so the get postcondition holds. No item changes slot on the first hit, so slot legality and no-duplicates are trivially preserved.

The baseline tests `stash_hit_inserts_at_front_of_target`, `target_hit_not_hottest_promotes_within_bucket`, `target_hit_hottest_promotes_to_probing`, `cascade_demotion_probing_to_full_target_to_stash` and `last_bucket_probing_wraps_to_zero` assume promotion on the first stash hit. Update them in the same file's `#[cfg(test)]` module: add one extra `seg.get(&k)` after each `put` so the item crosses the two-hit gate. Add one test: a single stash hit leaves the key in its stash bucket at the MRU end.

## Rationale (optional)

This works like the probation step of SLRU/2Q: the normal tier only takes items with repeated reuse inside the stash's lifetime. Expected side effect: slightly cheaper first stash hits, because a move within one Vec replaces a cross-bucket cascade. That could help per-op-time a little too. Metadata-size stays the same because no field is added.
