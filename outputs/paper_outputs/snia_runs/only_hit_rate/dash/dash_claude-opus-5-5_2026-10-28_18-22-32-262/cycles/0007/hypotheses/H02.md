# H02

Rescuing each stash-overflow victim into a free slot in its own target or probing bucket (at the LRU end) instead of evicting it from the cache should lift the long-flat `web_0` 16K hit-rate by using normal-bucket capacity that sits idle while stash buckets overflow.

## Parent

cycle/0006/v001

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep every v001 constant, the ghost lifecycle and every branch of `promotion_get` unchanged.

1. Add `const RESCUE_STASH_VICTIMS: bool = true;`. Its doc comment: "a stash-overflow victim is placed into a free slot of its own target (else its probing) bucket at the LRU end, and is evicted from the cache only when both are full."
2. Rewrite `put_stash_recording`. When `core.put_at(Slot::Stash, pos, item)` returns `Some(mut evicted)`:
   - Compute `t = get_index(&evicted.key, core.segment_size)` and `p = (t + 1) % core.segment_size`.
   - If `RESCUE_STASH_VICTIMS` is set and `core.buckets[t].get_items().len() < core.buckets[t].get_max_size()`, set `evicted.lfu_counter = 0` and call `core.put_at(Slot::Target, InsertPosition::Front, evicted)`.
   - Otherwise, if `core.buckets[p]` has a free slot, call `core.put_at(Slot::Probing, InsertPosition::Front, evicted)`.
   - Otherwise, record `fingerprint(&evicted.key)` in the ghost exactly as today.
   - Rescue happens only into a slot that is actually free, so neither rescue `put_at` may evict anything. Add `debug_assert!(ret.is_none())` on both. There is no recursion and no cascade.
3. Do not rescue into the bucket that the current promotion has just filled. This holds automatically, because that bucket is full. Do not touch the ghost for rescued items, since they are still resident.
4. Update the struct doc with a line "New (cycle 0007): ...", and note that the change adds no metadata.

Tests:
- Add `stash_victim_rescued_into_free_target`. Fill one stash bucket past capacity using keys whose target bucket is empty. Assert that the would-be victim is now in its target at index 0, that it is not in the ghost, and that `get` finds it.
- Add `stash_victim_evicted_when_target_and_probing_full`. In it, both normal buckets are pre-filled and the ghost records the victim.
- `ghost_put_promotes_on_first_stash_hit` fills target 0 with only one filler, so `k` would now be rescued and not evicted. Pre-fill both target 0 and probing bucket 1 directly through `core.buckets[..].put` so that the eviction still happens. Apply the same adjustment to any other test whose assertions depend on a stash eviction.

Invariants:
- A rescued item enters at the LRU end, so it is the first victim when a real promotion or demotion arrives. It never displaces a resident and never takes MRU priority.
- No duplicates: the item was just removed from the stash.
- The slot legality rule is unchanged: a key lives only in its own target, its own probing bucket, or its own stash bucket.
- The lookup in `promotion_get` already checks target and probing, so rescued items are found.
- Metadata is unchanged. Per-op-time adds two length checks per stash overflow.

## Rationale (optional)

`web_0` 16K has resisted the gate, the ghost, longer ghost reach and probing placement, all of which act on admission or recency. This probes capacity instead. Under hash skew, small caches can have empty normal slots while stash buckets churn, and every one of those churned evictions is a lost item. Unlike the failed "easier routes into a crowded target", this rescue only fills slots that are actually free, at the LRU end, and only for items that would otherwise leave the cache. It cannot outrank a resident. This is borrowed from Dash's displacement idea: use neighbouring free slots before evicting.
