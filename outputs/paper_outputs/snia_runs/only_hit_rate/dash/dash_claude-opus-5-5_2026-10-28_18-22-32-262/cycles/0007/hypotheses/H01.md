# H01

When a foreign probing resident is displaced and its own target bucket is full, sending it straight to the stash instead of evicting a target resident should recover cycle-0006 v001's `web_0` 128K hit-rate giveback while keeping its `hm_0` gains, raising mean hit-rate above 0.4028.

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep everything else exactly as in v001: `GhostRing`, `GHOST_FACTOR = 2`, the ghost-credited `put`, `put_stash_recording`, `STASH_DEMOTION_POS = Back`, `STASH_PROMOTION_TARGET_POS = Back`, `PROBING_PROMOTION_POS = Back`, the two-hit gate with `STASH_GATE_BYPASS_FREE_SLOTS = 2`, and every branch of `promotion_get`.

1. Add `const FOREIGN_RETRY_REQUIRES_FREE_SLOT: bool = true;`. Its doc comment: "a displaced foreign resident retries its own target only if that target has a free slot; otherwise it goes straight to the stash, so target residents are never displaced by an item that just lost its slot."
2. In `demote_from_normal_bucket`, change the `else` branch (where `true_target != source_idx`). Before calling `core.put_at(Slot::Target, retry_pos, item)`, check `core.buckets[true_target].is_full()`. If `FOREIGN_RETRY_REQUIRES_FREE_SLOT` is set and the bucket is full, set `item.lfu_counter = 0`, call `put_stash_recording(core, ghost, stash_pos, item)` with the foreign item itself, log it with `debug!`, and return. Otherwise keep the current behaviour: `put_at` at `retry_pos`, which cannot evict because there is room. Keep the existing cascade-to-stash handling as a defensive fallback.
3. Do not give the foreign item any ghost credit or counter credit. Earlier cycles showed that easier routes back into a crowded target lose.
4. Update the doc comment of `demote_from_normal_bucket` and the struct doc, adding a line "New (cycle 0007): ...".

Tests: `evicted_from_probing_cascades_to_target` and `target_retry_position` have targets with room, so they must still pass unchanged. `cascade_to_stash_position` currently expects `target_filler_a` to cascade into the stash. Rewrite it as `full_target_foreign_goes_to_stash`, which asserts:
- `foreign` is in its stash bucket at the MRU index.
- `target_filler_a` and `target_filler_b` are both still in the target.

Use `foreign`'s stash index for `stash_pre`. Add a test `foreign_retry_with_room_still_lands_in_target`.

Invariants:
- Each displacement still causes at most one stash insert, so stash pressure is unchanged in count. Only the identity of the item sent to the stash changes: the foreign item instead of the target's LRU resident.
- No duplicates, slot legality, the `get` postcondition (the promoted key stays in probing), and ghost recording on every stash eviction are all preserved.
- Metadata is unchanged. Per-op-time should drop slightly, since the second `put_at` is skipped.

## Rationale (optional)

v001's insight blames the `web_0` 128K slip on foreign probing residents. With `Back` probing placement, these residents are now always the probing victim. Each one retries its target at the cold `Front` end, which evicts that target's LRU resident into the stash. It then sits there as the target's next victim anyway. That resident earned its slot, and the foreign item has just lost its own. The recurring lesson that "an item that lost its slot should not outrank current residents" says the foreign item should be the one to leave. This tests that lesson on the cascade path, which has not been tried before.
