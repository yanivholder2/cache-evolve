# H03

Halving the ghost ring to `GHOST_FACTOR = 1` should keep cycle-0006 v001's mean hit-rate at or above 0.4028 while halving the ghost's metadata-size, because it drops the stale credit given to late-returning keys, which cost hit-rate at 16K, and keeps the recent returns that drive the `web_0` 128K gain.

## Parent

cycle/0006/v001

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. This is a deliberately minimal change.

1. Change `const GHOST_FACTOR: usize = 2;` to `const GHOST_FACTOR: usize = 1;`. The ghost then holds exactly `num_of_stash_buckets * bucket_size` fingerprints per segment, one per stash slot.
2. Update every doc comment that states the ring size or metadata cost: the struct doc "Metadata cost" paragraph, the `GhostRing` doc and the `GHOST_FACTOR` doc. They should now say `1 × stash slots × 8 bytes` per segment. Add a struct-doc line "New (cycle 0007): ghost ring shortened to factor 1".
3. Change nothing else. That covers the FIFO overwrite, consume-on-put, recording only on stash evictions, `lfu_counter = STASH_PROMOTION_HITS - 1` credit, `PROBING_PROMOTION_POS = Back`, the gate and the bypass, and every `promotion_get` branch.

Tests: `ghost_ring_overwrites_oldest` builds its own `GhostRing::new(2)` and is unaffected. In `ghost_put_promotes_on_first_stash_hit`, the key is evicted and immediately re-put, so it is still within one ring length of evictions and should pass unchanged. Verify this. If the small test settings make the ring length 1 or 2, the fingerprint must still be the most recent entry at re-put time. If it is not, re-put `k` directly after its eviction. Add `ghost_forgets_after_one_stash_capacity_of_evictions`. It evicts `k`, then forces `num_of_stash_buckets * bucket_size` further stash evictions, re-puts `k`, and asserts that `k` still needs two stash hits when the bypass is off.

Invariants: there is no behavioural change other than ghost reach. Metadata for the ghost halves, and per-op-time drops because each `put` does a linear `GhostRing::remove` scan over half as many slots.

## Rationale (optional)

This answers an open question from both cycle 0005 and cycle 0006. Cycle 0006 v002 showed that a four-times-longer ring credited keys returning too late and hurt most at `web_0` 16K. So reach and stale credit are monotonically linked, and factor 2 has never been shown to be the floor. The metadata and per-op-time dimensions have been unmeasured for six cycles. This variant gives the first clean cost signal: the hit-rate stays near v001's while the ghost's bytes and scan length halve. It acts on a different axis (ghost reach) from H01 (the foreign-resident cascade) and H02 (stash-victim rescue into free normal slots).
