# H01

Choosing the normal-bucket victim with a CLOCK-style reference bit, so a resident hit since it was placed is spared over one never hit, should lift the capacity-saturated `web_0` 16K hit-rate by changing which resident leaves a full bucket instead of looking for free slots.

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep every v002 constant and the ghost unchanged. Keep `put_stash_recording` (rescue included), the two-hit gate and bypass, and every placement position as they are.

1. **Reference bit lifecycle in normal buckets.** Inside a target or probing bucket, `Item::lfu_counter` serves as a 1-bit reference flag (0 or 1). In the stash it keeps its meaning as a hit count.
   - **Set to 0 on every entry into a normal bucket.** Stash→target promotions already enter at 0. Rescue already sets 0. Also set `item.lfu_counter = 0` in `promote_to_probing` before `put_at`. A target→probing promotee starts a fresh lifecycle. Also set it in the foreign-resident retry `core.put_at(Slot::Target, retry_pos, item)` inside `demote_from_normal_bucket`.
   - **Set to 1 on a hit while resident.** In `promotion_get`, set `core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter = 1` before `get_from_position` in the target non-hottest branch. Do the same with `core.buckets[probing_idx]...` in the probing-hit branch.
   - **Reset on demotion.** Every stash entry already resets the counter to 0. Keep that.
2. **Add `const NORMAL_VICTIM_SECOND_CHANCE: bool = true;`** and a helper `fn make_room_clock(core, ghost, bucket_idx, retry_pos)`. It runs only when `core.buckets[bucket_idx]` is full. It scans `get_items()` from index 0 (LRU) toward MRU, looking for the first item with `lfu_counter == 0`, and clears each `lfu_counter == 1` item it passes (second chance).
   - If an unreferenced item is found at index `j`, remove it with `remove_at(j)` and route it with `demote_from_normal_bucket(core, ghost, removed, bucket_idx, retry_pos, STASH_DEMOTION_POS)`, the same cascade an LRU eviction takes today.
   - If every item was referenced, do nothing. All bits are now cleared, and the normal `put_at` evicts the LRU item as before.
3. Call `make_room_clock` at the top of `promote_to_target`, using the target index, and at the top of `promote_to_probing`, using the probing index, before their `put_at`. The following `put_at` then finds a free slot and returns `None`. Otherwise it evicts LRU as today. Do not apply it to the rescue (free slots only) or to the foreign-resident retry.
4. The cascade from a removed foreign probing resident can only touch its own true target, never `bucket_idx`. Assert this with `debug_assert!` that the bucket is not full after `make_room_clock` removed an item.

## Rationale (optional)

Both cycle-0007 insights point here: `web_0` 16K is capacity-saturated, so the remaining lever is which resident leaves a full bucket. Pure LRU in a 2-slot bucket can't tell "hit since placement" from "just placed at MRU by promotion, rescue, or retry". The reference bit encodes exactly that. Unlike the failed counters (c2, c4), it has a lifecycle: it is set on a hit and cleared on entry, on a spare and on demotion, so it can neither stay near zero nor become a permanent pin.
