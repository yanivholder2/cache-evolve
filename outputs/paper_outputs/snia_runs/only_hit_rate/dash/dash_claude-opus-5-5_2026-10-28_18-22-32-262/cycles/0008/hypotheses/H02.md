# H02

Splitting the ghost ring into a near zone (the newest one stash-capacity of fingerprints, which always gives credit) and a far zone (older entries, which give credit only when the key's target bucket has a free slot) should raise mean hit-rate by keeping `web_0`'s short-ring gain without dropping `hm_0` 128K's long-tail returns.

## Parent

cycle/0007/v002

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep `GHOST_FACTOR = 2`, the FIFO overwrite, consume-on-put, the rescue, and every placement and gate constant as they are.

1. Change `GhostRing::remove(fp) -> bool` to `GhostRing::take(fp) -> Option<usize>`. It returns the entry's **age**: the number of inserts since it was written, computed as `(self.head + len - idx - 1) % len`. It still zeroes the slot. Keep a `#[cfg(test)] contains`.
2. Add `const GHOST_NEAR_FRACTION_DENOM: usize = GHOST_FACTOR;`. The near zone holds ages `< len / GHOST_NEAR_FRACTION_DENOM`, which equals one stash-capacity.
3. In `DashSegment::put`:
   - On `Some(age)` with `age` in the near zone, set `lfu_counter = STASH_PROMOTION_HITS - 1`, as today.
   - On `Some(age)` in the far zone, grant the same credit only if the key's target bucket `core.buckets[get_index(&item.key, core.segment_size)]` has at least one free slot (`get_items().len() < get_max_size()`). Otherwise use `lfu_counter = 0`. The fingerprint is consumed either way.
   - On `None`, use `lfu_counter = 0`.
   - Log the zone and the decision with `debug!`.
4. Update the struct doc with a line "New (cycle 0008): occupancy-conditioned far-zone ghost credit". Metadata is unchanged.

Tests:
- `ghost_ring_take_reports_age`: insert 3 and 5 into a ring of 4. `take(3)` returns `Some(1)` and `take(5)` returns `Some(0)`.
- `far_ghost_hit_no_credit_when_target_full`: insert the fingerprint of `k` into the ghost, then push `len/2` other fingerprints. Fill target 0 and probing 1 directly. `put(k)` and one `get(k)` must leave `k` in the stash.
- `far_ghost_hit_credits_when_target_has_room`: same setup with one target slot free. One `get` promotes.
- `ghost_put_promotes_on_first_stash_hit` stays valid, because it is a near-zone hit.

Invariants: there is still exactly one fingerprint per evicted key, and a hit still consumes it. Credit only changes the stash counter, never placement. Promotion with a free target slot never cascades, so far-zone credit can no longer outrank a resident.

## Rationale (optional)

Fixed ghost reach is a trade-off across traces. Factor 1 helped `web_0` through less stale credit (c7 v003). Factor 2 is needed for `hm_0` 128K's returns at 1–2 stash-capacities. The harm of stale credit comes from a promotion that evicts a resident, which goes against the lineage's "lost-slot items must not outrank residents" rule. Conditioning far credit on a free target slot removes exactly that harm. At 128K, where free slots exist, it keeps the tail's value.
