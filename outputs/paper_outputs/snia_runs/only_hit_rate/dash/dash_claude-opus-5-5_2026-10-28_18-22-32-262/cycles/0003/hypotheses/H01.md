# H01

Restricting v001's two-hit stash-promotion gate to fresh `put` arrivals, so that items demoted from a normal bucket promote on their first stash hit, will raise mean hit-rate above 0.395975 by recovering the `web_0` 128K regression while keeping the 16K gains.

## Parent

cycle/0002/v001

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep `STASH_DEMOTION_POS = InsertPosition::Back`, `STASH_PROMOTION_HITS = 2`, and the stash-hit branch of `promotion_get` (saturating increment, then the `hits < STASH_PROMOTION_HITS` check) unchanged.

1. In `demote_from_normal_bucket`, replace both `item.lfu_counter = 0;` (direct-to-stash branch) and `cascade.lfu_counter = 0;` (cascade branch) with `= STASH_PROMOTION_HITS - 1` (that is, 1). A demoted item has already earned a normal-bucket slot, so its first stash hit brings the counter to 2 and promotes it straight away. Do not change the counter on the `Slot::Target` retry path.
2. Fresh puts stay unchanged: `Segment::put` and `Item::new` start at `lfu_counter = 0`, so a brand-new key still needs two stash hits.
3. Keep the `lfu_counter = 0` reset just before `remove_at` in the promotion branch, so an item that later lands in the target starts clean and gets the demotion marker again only if it is demoted.
4. Update the doc comments on the struct and on `demote_from_normal_bucket` to say "fresh puts need two hits, demoted items one".

Tests: keep all existing tests. Add `demoted_item_promotes_on_first_stash_hit`. Use `direct_to_stash_position`-style setup to demote `victim` into stash via `promote_to_target`, call `seg.get(&victim)` once, and assert that it is now in `core.buckets[target_idx]` and no longer in its stash bucket. Keep `single_stash_hit_stays_in_stash_at_mru` as the check that fresh puts are still gated.

Invariants: the item is moved only by the existing promotion path, so the no-duplicates, slot-legality and get-returns-matching-key invariants are unchanged.

## Rationale (optional)

The cycle 0002 v001 insight traced the `web_0` 128K loss to the counter reset on demotion, which makes demoted items (the ones `Back` placement is meant to favour) wait two more hits. This hypothesis keeps the gate's filtering of one-hit-wonder puts, which is the source of the 16K gains, and removes the penalty on proven-reuse items. If `web_0` 128K does not recover, the regression comes from gating fresh keys, not from the reset.
