# H03

Adding a per-segment, aged count-min frequency sketch and refusing a gated stash→full-target promotion when the promotee's estimated frequency is below the displaced LRU resident's should raise hit-rate at 16K, because only promotions that beat the resident they evict get through.

## Parent

cycle/0007/v002

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. The parent is the c7 rescue winner, with plain LRU victims and no CLOCK, so the displaced resident is always index 0 of the full target. Keep the ghost, rescue, gate, bypass and every placement constant unchanged.

1. **`FreqSketch` struct**, owned by `DashSegment` next to `ghost`.
   - Storage: `counters: Vec<u8>`, with 4 rows of `width = next_power_of_two(max(64, 2 × total segment slots))`. Total segment slots is `(num_of_normal_buckets + num_of_stash_buckets) × bucket_size` from `DashSettings` in `try_new`.
   - Each counter saturates at 15.
   - Row `r` index: `(fp.rotate_left(16 * r) ^ SEEDS[r]).wrapping_mul(0x9E3779B97F4A7C15) >> (64 - log2(width))`, with `fp = fingerprint(key)`.
   - `increment(fp)` is conservative update: only the counters equal to the current minimum are incremented. `estimate(fp)` returns the min over rows.
   - Aging: `additions: usize`. When it reaches `SKETCH_SAMPLE_FACTOR (10) × total slots`, halve every counter (`c >>= 1`) and halve `additions`.
2. **Record every access.** At the top of `DashSegment::get`, before `promotion_get`, call `sketch.increment(fingerprint(key))` for hits and misses alike. `put` does not record, because every put follows a recorded miss.
3. **Admission check in the stash branch of `promotion_get`.** It runs only when the gate has passed (`hits >= STASH_PROMOTION_HITS`) and the bypass did not fire, and only when `core.buckets[target_idx].is_full()`.
   - Let `victim = &core.buckets[target_idx].get_items()[0]`.
   - If `sketch.estimate(fp(key)) < sketch.estimate(fp(victim.key))` (a strict less-than, so ties admit), refuse the promotion. Leave the hit count at `STASH_PROMOTION_HITS - 1`, preserving ghost-carried counts, so the next hit re-checks. Return `get_from_position(item_idx)`, which refreshes the item to the stash MRU end exactly like a sub-gate hit.
   - Otherwise promote as today.
   - Pass `&FreqSketch` into `promotion_get` as a new parameter.
   - Bypass promotions (empty target) and rescues are never checked: they displace no one.
4. Add `const SKETCH_ADMISSION: bool = true;` to switch the check off.

Tests:
- `sketch_estimate_monotone_and_ages`: increments raise the estimate, and halving after the sample window lowers it.
- `cold_promotee_refused_by_hot_resident`: fill the target through `fill_target_via_stash`. Read the key at index 0 and call `seg.sketch.increment(fingerprint(&k0))` 10 times. Then put a fresh key `c` and `get` it twice. Assert that `c` is still in the stash and the target is unchanged.
- `hot_promotee_admitted`.
- Existing tests must pass. Where a test pre-fills targets through `bucket.put` (sketch count 0) and expects a gated promotion, the promotee has at least 2 recorded gets, so `>=` holds.

Invariants: no duplicates, slot legality, and the `get` postcondition (the key is returned from the stash on refusal, or from the target on promotion). Metadata grows by `4 × width` bytes per segment, about 8 bytes per slot.

## Rationale (optional)

c2's TinyLFU-style comparison failed because it compared in-item `lfu_counter` values, which reset on every move and stayed near zero. Here the frequency lives outside the items, survives eviction, and decays by periodic halving, which are the properties that made the ghost work. The comparison makes promotion stricter instead of easier, which avoids the repeated "easier route into a crowded target" failure. It also judges the actual displaced resident, as the c8 continuation asked. This is a different lever from H01, which changes victim choice inside the item, and from H02, which changes how ghost credit is spent.
