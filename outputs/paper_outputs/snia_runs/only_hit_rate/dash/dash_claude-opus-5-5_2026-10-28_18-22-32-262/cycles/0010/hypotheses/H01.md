# H01

Replacing the 1-bit CLOCK victim choice with a 2-bit aged reuse level that persists through normal-bucket entry, stash stays and probing promotion should raise hit-rate at `web_0` 16K, because victim choice then sees reuse history that LRU position does not encode.

## Parent

cycle/0009/v001

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep these exactly as in v001: the ghost ring (factor 2, consume-on-put), the rescue, the two-hit gate and its two-free-slot bypass, every placement constant, and `GHOST_ORIGIN_FLAG` masking in the stash.

1. **Split `Item::lfu_counter` (`usize`) into two fields.**
   - The low bits (`LOW_MASK = 0xFFFF`) hold what v001 stores today: the stash hit count, or the CLOCK reference bit in a normal bucket.
   - A new field holds the reuse level: `const LEVEL_SHIFT: u32 = 16; const LEVEL_MASK: usize = 0b11 << LEVEL_SHIFT; const LEVEL_MAX: usize = 3;`. `GHOST_ORIGIN_FLAG` stays at the top bit.
   - Add helpers `level(c) -> usize`, `with_level(c, l) -> usize` and `low(c) -> usize`.
2. **Every existing `lfu_counter = X` reset becomes a low-bits-only update.**
   - Each one becomes `lfu_counter = with_level(X, level(lfu_counter))`. That is: stash entry on demotion and cascade, rescue, `promote_to_probing`, foreign retry, and the stash→target promotion (including its ghost-carried bit).
   - Every existing read of the bit or count (`== 0`, `& !GHOST_ORIGIN_FLAG`) must mask with `LOW_MASK`. Also mask out the level bits in the stash count arithmetic.
   - The level is lost only when the item leaves the cache. The ghost still stores only fingerprints.
3. **Raise the level on every hit.** Saturate at `LEVEL_MAX` in three places in `promotion_get`: a stash hit (before the gate check), a target hit on the non-hottest item, and a probing hit. A target-hottest hit raises the level before `remove_at`, so the item carries it into probing.
4. **New victim rule in `make_room_clock`.** Keep the name and call sites, and keep it a no-op unless the bucket is full.
   - First pass: pick the item with the lowest `level`, breaking ties toward the lower index (closer to LRU).
   - Before choosing, apply the v001 reference-bit second chance as a tie-breaker. Among items with equal minimal level, skip one whose ref bit is 1 if another has ref bit 0.
   - Age every item scanned that was **not** chosen: `level -= 1` (saturating) and ref bit cleared. This is the decay, so no item can be pinned for more than `LEVEL_MAX` contested promotions without new hits.
   - Remove the chosen item and route it through `demote_from_normal_bucket` exactly as today.
   - Always remove a victim when full. Drop the "all referenced → do nothing → LRU fallback" branch: the minimum is always well defined.
5. Add `const PERSISTENT_REUSE_LEVEL: bool = true;`. When it is false, fall back to v001's `make_room_clock` body unchanged.

Tests:
- Add `level_survives_stash_round_trip`: a key with level 2 is demoted to stash and promoted back, and still has level 2 (or 3 after the hits along the way).
- Add `min_level_victim_spares_hot_mru_neighbour`: target `[a(level 3), b(level 0)]` with `b` at MRU. Promoting `c` evicts `b`, and `a`'s level drops to 2.
- Add `aging_unpins_after_level_max_contests`.
- Update existing CLOCK tests where they assert exact `lfu_counter` values, so they compare `low(lfu_counter)`.

Invariants: no duplicates, slot legality, the `get` postcondition, and ghost recording on every out-of-cache eviction. No new metadata: the level reuses spare bits of `lfu_counter`.

## Rationale (optional)

c8 and c9 showed that a 1-bit reference in 2-slot buckets is cleared by entry and by the sweep before anything reads it, so it only repeats LRU order. Counters failed earlier because they reset on moves (c2) or never decayed (c4). This level does neither: moves don't reset it, and each contested promotion ages it. It is the "multi-bit persistent counter" that both the c9 cycle insight and the cross-cycle open questions name as the main remaining lever for `web_0` 16K.
