# H03

Evicting the LRU-most stash item that has zero stash hits, instead of the plain LRU slot, when inserting into a full stash bucket will raise mean hit-rate above 0.398925, mostly at 16K, because items halfway through the two-hit gate will no longer be flushed by one-hit arrivals.

## Parent

cycle/0003/v003

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep the two-hit gate, `STASH_DEMOTION_POS = Back`, `STASH_PROMOTION_TARGET_POS = Back`, the `lfu_counter` semantics (stash-hit count during the current stay, reset to 0 on stash entry from a normal bucket and on promotion), and every `promotion_get` branch unchanged.

1. Add a helper `fn stash_insert<K, V>(core: &mut SegmentCore<K, V>, pos: InsertPosition, item: Item<K, V>)`. It computes `stash_idx = get_index(&item.key, core.stash_size)`. If `core.stash_buckets[stash_idx].is_full()`, it scans `get_items()` from index 0 (the LRU end) towards MRU for the first item with `lfu_counter == 0`. If one is found at index `v`, it calls `remove_at(v)` and drops that item (a cache eviction, the same outcome the LRU eviction would have had). If no zero-hit item exists, it does nothing extra, and the bucket evicts its LRU slot as before. It then calls `core.put_at(Slot::Stash, pos, item)` and discards the return value. That value is `None` when a slot was freed, otherwise the normal LRU victim.
2. Replace both `core.put_at(Slot::Stash, stash_pos, ...)` calls in `demote_from_normal_bucket` (direct-to-stash and cascade) with `stash_insert(core, stash_pos, ...)`.
3. Fresh puts: if `Segment::put` is a provided (default) trait method that inserts into the stash through `core.put_at(Slot::Stash, ...)`, override `put` in `impl Segment for DashSegment`. Keep the existing semantics exactly: update in place if the key is already resident in stash, target or probing, otherwise insert into the stash at the same position the default uses. For that new-key stash insert only, use `stash_insert`. If overriding `put` would require editing a gate-integrity file, apply the change only to the demotion paths in step 2 and say so in a comment.
4. Document the victim rule on `stash_insert` and in the `DashSegment` doc comment.

Tests: add `full_stash_spares_item_with_one_hit`. Fill a stash bucket using `find_keys_for_bucket(stash_idx, stash_size, cap + 1)` and `put`. `get` the LRU-most key once (its counter becomes 1, and it moves to MRU, so make it LRU again by putting enough later keys, or by setting its `lfu_counter = 1` directly through `core_mut()` on an item at index 0). Insert one more key, then assert that the one-hit item survives and the oldest zero-hit item was evicted. The existing `direct_to_stash_*` and `cascade_to_stash_*` tests start with stash buckets that are not full, so their expected indices should stay the same. Confirm this.

Invariants: exactly one item leaves a full stash per insert, as before. Only the choice of victim changes. No duplicates. Normal-bucket behaviour is untouched.

## Rationale (optional)

All previous stash levers changed where items enter, or what it takes to leave by promotion. None changed which stash item is evicted. Under the two-hit gate, an item with one hit is evidence of reuse, but plain LRU can still flush it in small, contested stash buckets at 16K. This is a stash-eviction lever and does not overlap H01 (gate bypass) or H02 (probing delay).
