# H01

Adding v002's two-hit stash-promotion gate on top of v001's MRU-end stash demotion will raise mean hit-rate above v001's 0.3956, because the two changes protect reused items at different points (stash exit vs stash entry).

## Parent

cycle/0001/v001

## Changes

All edits are in `src/dash/segments/dash_segment.rs`. Keep v001's `STASH_DEMOTION_POS = InsertPosition::Back` and its `demote_from_normal_bucket(core, item, source_idx, retry_pos, stash_pos)` signature unchanged. Do not change the Item layout: reuse `Item::lfu_counter`, which ClassicLRU never reads.

1. Stash-hit branch of `promotion_get`: after `get_position` finds `item_idx` in `core.stash_buckets[stash_idx]`, use `get_items_mut()[item_idx]` to saturating-increment `lfu_counter`.
   - If the counter is now `< 2`, do not promote. Return `Some(core.stash_buckets[stash_idx].get_from_position(item_idx))`, which refreshes the item to the stash MRU end under ClassicLRU. The key stays in the stash.
   - Otherwise, set `lfu_counter = 0`, then `remove_at` and `promote_to_target(core, data, insert_pos)` as today. Keep the existing `unreachable!` lookup in the target.
2. In `demote_from_normal_bucket`, make the item and the cascade item binding `mut` and set `lfu_counter = 0` before each `core.put_at(Slot::Stash, stash_pos, …)`. Every stay in the stash then needs two fresh hits. Do not reset the counter on the `Slot::Target` retry path.
3. Leave the target-hit, probing-hit and miss branches and `Segment::put` unchanged.

Tests in the same file's `#[cfg(test)]` module: the tests that call `seg.put(...); seg.get(...)` and expect the key in the target bucket (`stash_hit_inserts_at_front_of_target`, `target_hit_not_hottest_promotes_within_bucket`, `target_hit_hottest_promotes_to_probing`, `cascade_demotion_probing_to_full_target_to_stash`, `last_bucket_probing_wraps_to_zero`) need one extra `seg.get(&k)` after each put so the item passes the gate. Add a test showing that a single stash hit leaves the key in its stash bucket at the last (MRU) index.

Invariants: no duplicates, slot legality, and the get postcondition (it returns `Some` with the matching key) all hold, because a first hit moves the item only within the same stash Vec.

## Rationale (optional)

Cycle 0001 found that v001 gains most at 128K and v002 gains most at 16K. If the effects are independent, the combination should beat v001 at 16K and roughly match it at 128K. If it doesn't, the two changes overlap. Either result answers the cycle-0001 open question.
