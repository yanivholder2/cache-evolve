# H02

Replacing v001's unconditional first-hit stash→target promotion with a frequency-comparison admission test (promote only if the stash item's hit count is at least the hit count of the target bucket's LRU victim, or the target has a free slot) will raise hit-rate over v001 at both cache sizes, because the gate adapts to how contended each target bucket actually is.

## Parent

cycle/0001/v001

## Changes

All edits are in `src/dash/segments/dash_segment.rs`. Keep v001's `STASH_DEMOTION_POS = Back` behaviour. Use the existing `Item::lfu_counter` field (ClassicLRU never reads it) as a per-item saturating hit counter. No new fields.

1. Count hits everywhere. In `promotion_get`, saturating-increment `lfu_counter` on every hit (stash, target hottest, target non-hottest and probing) before any move. Use `get_items_mut()[item_idx]` on the bucket that holds the item.
2. Admission test in the stash-hit branch. Read the target bucket `core.buckets[target_idx]`:
   - If it is not full (`!is_full()`), promote as today.
   - If it is full, find the victim a `put_at(Slot::Target, insert_pos, …)` would evict. Under ClassicLRU that is the item at index 0 (LRU end). Prefer the bucket's eviction-candidate accessor if one exists. Otherwise use `get_items()[0]`. Promote only if `stash_item.lfu_counter >= victim.lfu_counter`. Ties go to the newcomer so the first-hit behaviour stays the default.
   - If admission fails, do not move the item. Return `Some(core.stash_buckets[stash_idx].get_from_position(item_idx))` to refresh it to the stash MRU end. Then halve the victim's counter (`victim.lfu_counter >>= 1`) through `get_items_mut()`, so long-idle residents eventually lose to repeated challengers (aging).
3. Aging on demotion. In `demote_from_normal_bucket`, halve `lfu_counter` (make the binding `mut`) before both `core.put_at(Slot::Stash, …)` calls and before the `Slot::Target` retry. A demoted item keeps part of its frequency history. It does not get a full reset.
4. `Segment::put` stays unchanged: new items start at `lfu_counter = 0` from `Item::new`.

Tests: `stash_hit_inserts_at_front_of_target`, the target-hit tests and `last_bucket_probing_wraps_to_zero` all fill the target from an empty state. With ties going to the newcomer, the first two promotions still succeed when the counters are equal. Check each assertion, and where a full target now rejects the newcomer, add one extra `seg.get` to raise its counter. Add a test: with a full target whose LRU resident has `lfu_counter = 3`, one stash hit on a counter-0 item leaves it in the stash and halves the resident's counter to 1.

Invariants: the admission-fail path keeps the item in its stash bucket and returns it, so the get postcondition, no-duplicates and slot legality are preserved.

## Rationale (optional)

v002's fixed two-hit gate lost hit-rate on web_0 at 128K, where first-hit promotion was already cheap. This is a TinyLFU-style per-bucket comparison instead. It admits freely when the target is uncontested or holds cold items, and filters only against residents that are actually hot. That addresses the "gate should scale with occupancy" question directly, and it is a different mechanism from H01's fixed gate.
