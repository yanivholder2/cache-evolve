# H02

Requiring one extra stash hit before a promotion when every resident of the full target has its CLOCK reference bit set should lift hit-rate, mostly at 16K: admission then depends on the value of the resident it would displace, not on free slots.

## Parent

cycle/0008/v001

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep the ghost, the rescue, `make_room_clock`, the two-free-slot bypass, and every placement position as in v001.

1. **Add the constants.**
   - `const VALUE_AWARE_GATE: bool = true;`
   - `const REFERENCED_TARGET_EXTRA_HITS: usize = 1;`
2. **Add a helper** `fn target_all_referenced(core, target_idx) -> bool`. It returns true when `core.buckets[target_idx].is_full()` and every item in `get_items()` has `lfu_counter != 0`. In a normal bucket the counter is the 1-bit reference flag. This is a read-only scan of 2 slots. It must not clear any bits, so the CLOCK state is untouched when a promotion is refused.
3. **Change the stash branch of `promotion_get`.**
   - After computing `hits`, `free` and `target_has_room`, compute `required`:
     - `STASH_PROMOTION_HITS + REFERENCED_TARGET_EXTRA_HITS` when `VALUE_AWARE_GATE && !target_has_room && target_all_referenced(core, target_idx)`;
     - `STASH_PROMOTION_HITS` otherwise.
   - Replace `hits < STASH_PROMOTION_HITS` with `hits < required` in the refresh condition.
   - Effects:
     - A fresh key needs 3 hits to enter a target whose residents have both been hit since placement.
     - A ghost-credited key, which starts at count 1, needs 2 hits.
     - Whenever at least one resident is unreferenced, everything behaves as in v001. That resident is exactly the one `make_room_clock` would displace.
   - The bypass is unchanged. With 2 or more free slots the first hit still promotes.
4. **Keep the stash count intact on refusal.** The `saturating_add(1)` refresh path already does this. The count resets only on promotion and on every stash entry, as today. A key that reaches `required` promotes through `promote_to_target`, where `make_room_clock` clears both bits and evicts the LRU resident as before. That clearing is the decay, so a target cannot block admission forever.
5. **Refresh `promotion_get`'s doc comment** and the struct doc to describe the value-aware gate.

Tests:
- Add `referenced_full_target_requires_extra_hit`:
  - fill target 0 with `fill_target_via_stash` and set both residents' `lfu_counter = 1` via `get_items_mut`;
  - put a third key and hit it twice: it stays in the stash at MRU;
  - hit it a third time: it promotes, and one former resident is now in its stash.
- Add `unreferenced_resident_keeps_two_hit_gate`: with one resident at bit 0, two hits promote, as in v001.
- Add `ghost_key_needs_two_hits_into_referenced_target`.
- Keep all existing tests passing.

Invariants: no duplicates, slot legality, the `get` postcondition (a refused key is returned from its stash slot), and ghost recording on every eviction out of the cache. There is no new metadata. The per-op cost is one 2-item scan on gated stash hits.

## Rationale (optional)

The c8 continuation asks for admission based on how valuable the displaced resident is. All previous gate changes were keyed on occupancy, and the ones that eased entry into crowded targets lost at 16K (c3 v001/v002, c6 v003). This hypothesis tightens entry only in the one state where every possible victim has shown reuse since it was placed, which is exactly the saturated `web_0` 16K regime. It leaves admission unchanged wherever a cold resident exists, which preserves `hm_0` 128K's profitable displacements.
