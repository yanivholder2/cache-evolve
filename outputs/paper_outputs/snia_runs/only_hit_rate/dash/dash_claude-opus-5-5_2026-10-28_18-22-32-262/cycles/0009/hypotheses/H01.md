# H01

Letting a ghost-returning key enter its target with the CLOCK reference bit already set should raise hit-rate, mainly at `web_0` 16K: proven returnees outlast fresh promotees in full 2-slot buckets, a victim signal that LRU order does not carry.

## Parent

cycle/0008/v001

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep every constant, the ghost lifecycle (factor 2, consume-on-put), the rescue, the two-hit gate with its two-free-slot bypass, `make_room_clock`, and all placement positions exactly as in v001. Admission does not change. Only the reference bit of the newly placed item changes.

1. **Ghost-origin flag in the stash counter.**
   - Add `const GHOST_ORIGIN_FLAG` as a high bit of `Item::lfu_counter`. Check the field's integer type in `src/shared/item.rs` and use e.g. `1 << 7` for `u8` or `1 << 15` for `u16`. Add `const CARRY_GHOST_HISTORY: bool = true;`.
   - In `DashSegment::put`, a ghost hit sets `item.lfu_counter = (STASH_PROMOTION_HITS - 1) | GHOST_ORIGIN_FLAG`. A miss still sets 0.
2. **Hit counting ignores the flag.** In the stash branch of `promotion_get`, compute the hit count on `lfu_counter & !GHOST_ORIGIN_FLAG`:
   - add 1, saturating;
   - store the result back with the flag preserved;
   - compare the unflagged count against `STASH_PROMOTION_HITS`.

   The gate and the bypass therefore behave exactly as in v001.
3. **Carry the flag into the target.** On the promotion path, replace the unconditional `lfu_counter = 0` before `remove_at(item_idx)`:
   - read `flagged = lfu_counter & GHOST_ORIGIN_FLAG != 0`;
   - set `lfu_counter = if flagged && CARRY_GHOST_HISTORY { 1 } else { 0 }`.

   `promote_to_target` does not touch the counter, and `make_room_clock` runs before the `put_at`, so the newcomer lands at MRU with bit 1. On the next promotion into that bucket, CLOCK spares it once: its bit is cleared and an unreferenced resident goes instead. After that its lifecycle is the normal one.
4. **The flag never escapes the stash elsewhere.** These paths already assign `lfu_counter = 0`, which clears the flag: rescue in `put_stash_recording`, every `demote_from_normal_bucket` path, and `promote_to_probing`. Keep them. A flagged item evicted out of the cache is recorded in the ghost as before.

Tests:
- Extend `ghost_put_promotes_on_first_stash_hit` to assert that the promoted `k` has `lfu_counter == 1` in its target.
- Add `fresh_promotee_enters_with_bit_zero`: a non-ghost two-hit promotee has `lfu_counter == 0`.
- Add `ghost_flag_does_not_change_gate`: a ghost-credited key in the stash promotes on exactly its first hit, and its stored stash count reads 1 when masked.
- Keep all existing tests passing.

Invariants: no duplicates, slot legality, the `get` postcondition, and ghost recording on every out-of-cache eviction. There is no new metadata, because the flag reuses a spare bit of `lfu_counter`.

## Rationale (optional)

c8 showed that CLOCK in 2-slot buckets agrees with LRU because every entry starts at bit 0, so the bit only repeats recency. The ghost is the only signal in the lineage that holds reuse across a stay outside the cache. Today that evidence is spent entirely on admission and then dropped. This hypothesis moves it into the victim choice. It does not loosen admission, so it avoids the recurring "easier route into a crowded target" failure. What it changes is which resident pays for the next promotion: a fresh one-stay promotee rather than a key that has already come back once.
