# H03

Splitting the segment-wide ghost ring into per-stash-bucket sub-rings of equal total capacity should cut per-op-time by shrinking the put-path ghost scan from `2 × stash slots` to `2 × bucket_size` entries, with hit-rate within noise of the incumbent.

## Parent

cycle/0008/v001

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. No policy logic changes: the gate, bypass, rescue, CLOCK, placement and `GHOST_FACTOR = 2` all stay as in v001.

1. **Restructure `GhostRing`** into `slots: Vec<u64>`, `heads: Vec<u8>` (one head per stash bucket) and `width: usize`.
   - `width = GHOST_FACTOR * bucket_size`. Assert that `width <= u8::MAX + 1`, or use `u16` heads.
   - `slots.len() = num_of_stash_buckets * width`, so total capacity is unchanged.
   - Change `GhostRing::new(len)` to `GhostRing::new(num_buckets, width)` and update `DashSegment::try_new` to match.
2. **Make the operations sub-ring local.**
   - `insert(sb, fp)` writes `slots[sb * width + heads[sb]]` and advances `heads[sb]` modulo `width`. This is FIFO overwrite within the sub-ring.
   - `remove(sb, fp)` scans only `slots[sb*width .. (sb+1)*width]`, zeroes the first match, and returns whether it found one.
   - `contains(sb, fp)` is the `#[cfg(test)]` equivalent.
3. **Change the call sites.** The bucket index is `sb = get_index(&key, core.stash_size)`, the same stash bucket the key would occupy.
   - In `put_stash_recording`, compute it from `evicted.key` before `ghost.insert`.
   - In `DashSegment::put`, compute it from `item.key` before `ghost.remove`. `core.stash_size` is reachable through `self.core`.
   - The fingerprint function is unchanged.
4. **Update the doc comments**: the metadata line, which is now `slots × 8 + num_of_stash_buckets` bytes, and the decay description. A fingerprint now survives about `GHOST_FACTOR × bucket_size` evictions from its own stash bucket, not about that many evictions segment-wide.

Tests:
- Rewrite `ghost_ring_overwrites_oldest` for a single sub-ring: `new(1, 2)`, then insert 3, 5, 7 and check that 3 was overwritten.
- Add `ghost_sub_rings_are_independent`: overflowing bucket 0's sub-ring must not evict a fingerprint stored in bucket 1.
- Update the `seg.ghost.contains(...)` assertions in existing tests to pass the stash index of the key.
- Keep all other tests passing unchanged.

Invariants: no duplicates, slot legality, the `get` postcondition, and every out-of-cache eviction is recorded in its key's sub-ring. The consume-on-put lifecycle is unchanged.

## Rationale (optional)

Per-op-time and metadata-size have gone unmeasured for 8 cycles, and the ghost's linear scan on every `put` is the most obvious cost the lineage has added since baseline. Partitioning by stash bucket keeps the overall reach (factor 2) while scanning only `1/num_of_stash_buckets` of the ring. Every key's stash bucket is fixed by its hash, so a returning key always lands in the sub-ring it was recorded in, and recall does not drop. The only hit-rate effect is that reach becomes local to each bucket. Stash overflow is roughly balanced by the hash, so returns that came within one to two stash-capacities, which c7 identified as where the ghost's value lies, should be credited about as often as before.
