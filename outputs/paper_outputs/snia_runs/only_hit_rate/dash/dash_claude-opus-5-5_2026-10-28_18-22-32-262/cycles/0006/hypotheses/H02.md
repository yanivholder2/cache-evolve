# H02

Raising `GHOST_FACTOR` from 2 to 8, so the ghost ring remembers four times as many stash-evicted keys, will raise mean hit-rate above 0.40195, mostly by lifting `web_0` 16K, whose returning keys currently come back after their fingerprints have been overwritten.

## Parent

cycle/0005/v003

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. This is a single-lever reach test. Do not change placement, the gate, the bypass, the probing trigger, or the stash LRU eviction.

1. Change `const GHOST_FACTOR: usize = 2;` to `const GHOST_FACTOR: usize = 8;`. The ring length is still computed in `DashSegment::try_new` as `GHOST_FACTOR * settings.num_of_stash_buckets * settings.bucket_size`.
2. The ring is now 4× longer, so the linear scans in `GhostRing::remove` (run on every `put`) cost 4× more. To keep per-op-time bounded, replace the single-scan design with a scan that exits early: keep `slots: Vec<u64>` and `head`, and add a compact counting membership pre-filter, `filter: Vec<u8>` of length `slots.len().next_power_of_two()`. Each byte is a saturating count of live fingerprints whose `fp & mask` maps to it. `insert` increments the filter byte of the new fp and decrements the byte of the overwritten non-zero fp. `remove` returns `false` straight away when the filter byte is 0, and otherwise does the linear scan; on a successful remove it zeroes the slot and decrements the byte. Saturating counts may go stale at 255, which is harmless: a stale non-zero byte only forces a scan. If this pre-filter complicates things, implementing just step 1 is acceptable. State in the doc comment which one was done.
3. Update the doc comments on `GHOST_FACTOR`, `GhostRing` and the struct header to the new metadata cost: `8 × stash slots × 8 bytes` per segment of fingerprints, plus the filter bytes if added. Add a "New (cycle 0006)" line.

Tests: `ghost_ring_overwrites_oldest` (which uses `GhostRing::new(2)`) and the other ghost tests must pass unchanged. Add `ghost_reach_scales_with_factor`. Build a segment, evict `2 * stash_slots + 1` distinct keys out of one stash bucket through `put`, and assert that the first evicted key's fingerprint is still in the ghost, which it would not be at `GHOST_FACTOR = 2`. If the filter is added, also add a unit test confirming that `remove` of an absent fp returns `false` and that insert, overwrite and remove keep the filter counts consistent.

Invariants: the ghost holds only fingerprints, and a false positive costs at most one early promotion. Ghost hits are still consumed on `put`. Behaviour is identical to the parent except for how long a fingerprint survives.

## Rationale (optional)

The v003 insight attributes the flat `web_0` 16K cell to the ring's short span, since the ring is tied to stash size, which is small at 16K. This hypothesis tests that directly. The risk is stale credit on `hm_0` 16K. The FIFO decay still bounds it, and v003 showed that one early promotion costs little there. If `web_0` 16K moves and `hm_0` 16K holds, ghost reach is a live lever. If neither moves, the 16K bottleneck lies elsewhere. This is distinct from H01 (probing placement) and H03 (ghost credit on demotion).
