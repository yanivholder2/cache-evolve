# H01

Adding cycle-0005 v001's MRU-end (`Back`) placement for target→probing promotees on top of cycle-0005 v003's ghost ring will raise mean hit-rate above 0.40195, because the two levers act on different tiers (probing placement lifts `hm_0`, ghost admission lifts `web_0` 128K) and should stack.

## Parent

cycle/0005/v003

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep the `GhostRing`, `GHOST_FACTOR = 2`, `put_stash_recording`, the ghost-credited `put`, `STASH_DEMOTION_POS = Back`, `STASH_PROMOTION_TARGET_POS = Back`, the two-hit gate with `STASH_GATE_BYPASS_FREE_SLOTS = 2`, the `lfu_counter` resets, and the stash-hit, probing-hit and miss branches of `promotion_get` exactly as they are. `DashSegment::get` keeps passing `InsertPosition::Front` as `insert_pos`.

1. Add `const PROBING_PROMOTION_POS: InsertPosition = InsertPosition::Back;`, with the doc comment "where an item promoted from its target into its probing bucket lands; MRU end so a proven-hottest item is not the next probing victim".
2. Change `promote_to_probing` to take separate placement and retry positions, mirroring `promote_to_target`: `fn promote_to_probing(core, ghost, item, place_pos: InsertPosition, retry_pos: InsertPosition)`. It calls `core.put_at(Slot::Probing, place_pos, item)`. On eviction it calls `demote_from_normal_bucket(core, ghost, evicted, probing_idx, retry_pos, STASH_DEMOTION_POS)`, so a displaced foreign probing resident still retries its own target at the cold `retry_pos`.
3. In the target-hit `is_hottest` branch of `promotion_get`, call `promote_to_probing(core, ghost, data, PROBING_PROMOTION_POS, insert_pos)`. Leave the `unreachable!` lookup in the probing bucket as it is.
4. Update the `promotion_get` doc comment (the `insert_pos = Front` paragraph) and the struct doc: probing promotions now land at `PROBING_PROMOTION_POS`; only foreign-resident retries use `insert_pos`. Add a "New (cycle 0006)" line to the struct doc.

Tests: update the direct callers of `promote_to_probing` (`evicted_from_probing_cascades_to_target`, `target_retry_position`, `cascade_to_stash_position`) to pass `(insert_pos, insert_pos)` (or `(InsertPosition::Back, InsertPosition::Back)` where `Back` is passed today). Their expected indices stay the same, because the victim is still the probing LRU item that was already resident. Add `target_hottest_promotion_lands_at_probing_mru`: put one filler key in the probing bucket, run `fill_target_via_stash` and then one `get` on the target's MRU key, and assert that the promoted key sits at `items.len() - 1` in the probing bucket. All ghost tests must pass unchanged.

Invariants: only the slot position inside the same probing bucket changes. No-duplicates, slot legality, the `get` postcondition and ghost recording on every stash eviction are preserved. Metadata is unchanged from the parent.

## Rationale (optional)

This is the top continuation candidate from cycle 0005. v001 (Back probing placement) had no regressions and gained only on `hm_0` (128K 0.4530, 16K 0.3593). v003 (ghost) gained on `web_0` 128K and `hm_0`. They touch disjoint code paths: the probing-placement branch and the stash admission counter. The placement rule ("don't put a just-proven item in the victim slot") has won three times in this lineage.
