# H03

Keeping a key's ghost fingerprint after its ghost-credited return, and letting a normal-bucket item demoted to the stash enter with one credited hit only if its fingerprint is still in the ghost, will raise mean hit-rate above 0.40195, because repeat-reuse keys will skip the second stash hit after demotion while one-time keys stay fully gated.

## Parent

cycle/0005/v003

## Changes

All edits go in `src/dash/segments/dash_segment.rs`. Keep placement constants, the two-hit gate, `STASH_GATE_BYPASS_FREE_SLOTS = 2`, `GHOST_FACTOR = 2`, the probing trigger and the LRU stash eviction unchanged.

1. `DashSegment::put`: today it calls `self.ghost.remove(fp)` and credits on a hit, which consumes the fingerprint. Switch this to a non-consuming lookup. Make `GhostRing::contains` available outside `#[cfg(test)]` and use `let ghost_hit = self.ghost.contains(fp)`. The credit rule stays the same (`lfu_counter = STASH_PROMOTION_HITS - 1` on a hit, `0` otherwise). The fingerprint now stays in the ring until FIFO overwrite or until it is consumed in step 2.
2. `demote_from_normal_bucket`: in both stash-insert branches (the direct `true_target == source_idx` branch and the `cascade` branch), replace the unconditional `lfu_counter = 0` with `lfu_counter = if ghost.remove(fingerprint(&x.key)) { STASH_PROMOTION_HITS - 1 } else { 0 }`, where `x` is `item` or `cascade`. A demoted item with ghost evidence then returns to its target on its first stash hit, and the evidence is consumed, so each eviction-from-cache event grants at most one put credit plus one demotion credit.
3. `put_stash_recording`: since fingerprints are no longer consumed on `put`, the same key could be recorded twice. Insert into the ghost only when `!ghost.contains(fp)`, to avoid duplicate entries shrinking the ring's effective reach.
4. Promotion out of the stash still resets `lfu_counter = 0` (unchanged). Update the struct doc, the `GhostRing` doc and the `demote_from_normal_bucket` doc to describe the new lifecycle: recorded on stash eviction, read without being consumed on put, consumed on demotion, decayed by FIFO. Add a "New (cycle 0006)" line, and note the extra ghost scan per demotion (per-op-time).

Tests: update `ghost_put_promotes_on_first_stash_hit`. Its assertion that the put consumes the fingerprint now expects the fingerprint to be **still present** after the re-put. Add `ghost_backed_demotion_promotes_on_first_stash_hit`. Evict `k` into the ghost and re-put it, promote it into a target that holds a filler, then force `k`'s demotion back into the stash (fill the target via `promote_to_target` with another same-target key so `k` is the LRU victim). Assert that one `get` moves `k` back into its target, and that the fingerprint is now gone. Add `plain_demotion_still_needs_two_hits`: the same setup without prior ghost history requires two hits. The `direct_to_stash_position` and `cascade_to_stash_position` tests use keys that have no ghost history, so they must pass unchanged.

Invariants: no slot or placement changes. Only the `lfu_counter` an item starts with on demotion differs, and only for keys with ghost evidence. Ghost metadata size is unchanged.

## Rationale (optional)

This answers the cycle-0005 open question "should demotions from a normal bucket also check the ghost?". Cycle 0003 v001 gave every demoted item a one-hit return, and it lost at 16K because one-hit keys got an easier route into a crowded target. This version gives the shortcut only to keys that have already been evicted from the cache once and then come back: the reuse evidence that has worked, unlike in-item counters. It acts on the demotion path, not the fresh-put path (the parent) or the probing tier (H01), and it does not change ghost reach (H02).
