# H03

Adding a small per-segment ghost ring of key fingerprints evicted from the stash, and letting a stash item whose key is in the ghost skip the two-hit gate on its first stash hit, will raise mean hit-rate above 0.39905, because it separates keys with reuse from one-hit keys using a signal that decays by FIFO overwrite.

## Parent

cycle/0004/v001

## Changes

Edits go in `src/dash/segments/dash_segment.rs`. If eviction returns are only visible there, edits may also go in the `SegmentCore` / `put` path under `src/dash/segments/` (not in `jni.rs`, `factory.rs` or `lib.rs`). Keep the placement constants, the two-free-slot bypass, the target and probing branches, and the LRU stash eviction unchanged.

1. Ghost structure: add a field `ghost: Vec<u64>` plus `ghost_head: usize` to `DashSegment` (or to `SegmentCore` if the helper functions can only reach `core`; preferably as a separate `GhostRing` struct passed alongside `core`). Size it to `GHOST_FACTOR * num_of_stash_buckets * stash_bucket_capacity` with `const GHOST_FACTOR: usize = 2;`, and initialise it to 0. A fingerprint is a 64-bit hash of the key (reuse the hasher behind `get_index`), forced non-zero with `| 1`. `ghost_insert(fp)` writes at `ghost_head` and advances it modulo the length (FIFO overwrite, which is the decay). `ghost_contains(fp)` is a linear scan. `ghost_remove(fp)` zeroes the matching slot.
2. Record evictions out of the cache: every `core.put_at(Slot::Stash, ...)` call currently drops its return value. That happens in `demote_from_normal_bucket` (both branches) and in the fresh-put path. Capture the evicted item and call `ghost_insert(fp(evicted.key))`. For the fresh-put path, override `put` in `impl Segment for DashSegment` if the trait allows it. Otherwise, apply the same capture at the stash insert in the shared `put` path. Keep the item placement exactly as it is today.
3. Mark ghost-returning puts: when a fresh `put` arrives and `ghost_contains(fp(key))` is true, call `ghost_remove` and insert the item into the stash with `lfu_counter = STASH_PROMOTION_HITS - 1` (so 1). That way the existing gate in `promotion_get` (`hits < STASH_PROMOTION_HITS && !target_has_room`) lets it promote on its first stash hit. Non-ghost puts keep `lfu_counter = 0`. Do not change `promotion_get` itself.
4. Demotions from a normal bucket still reset `lfu_counter = 0` as they do today. Only fresh puts consult the ghost.

Tests: add `ghost_put_promotes_on_first_stash_hit`. Fill the target with one filler key (so the bypass is off), then evict key `k` out of a full stash bucket by putting enough same-stash-bucket keys. Re-`put` `k`, `get` it once, and assert that it is in its target. Add `non_ghost_put_still_needs_two_hits`, which mirrors the existing `single_stash_hit_stays_in_stash_at_mru`. Existing tests should still pass unchanged, because they never re-put an evicted key. If any test puts the same key twice after an eviction, adjust its expectations.

Invariants: no change to which slots items occupy. The ghost holds only fingerprints, never values, and a false-positive fingerprint only costs one early promotion. The extra metadata is `2 × stash slots × 8 bytes` per segment. Note this in doc comments, since metadata-size is a fitness dimension, even though it has not been measured yet.

## Rationale (optional)

All four cycles found that counters in `lfu_counter` fail because they are reset when items move (0002) or never decay (0004 v003). A ghost of recently evicted keys is the ARC/2Q "A1out" idea. Its history survives eviction, which an in-item counter cannot do, and the FIFO overwrite gives the explicit decay the cycle-0004 insight asks for. It targets the reuse distances just beyond what the cache holds, especially at 16K, where the gate currently makes a re-referenced key pay two stash hits again. This lever is distinct from H01 (probing placement) and H02 (target→probing trigger).
