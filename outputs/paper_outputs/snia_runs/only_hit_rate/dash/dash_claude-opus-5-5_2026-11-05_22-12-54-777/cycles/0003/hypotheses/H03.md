# H03

Narrowing v002's victim-scan window from 8 to 4 slots and lowering the counter cap from 15 to 7 will reduce per-op-time, which is the eviction-path cost v002 added, while keeping hit-rate within 0.003 of v002's 0.5392.

## Parent

cycle/0002/v002

## Changes

Start from v002's overlay. Edit only the `ClassicLRU` impl in `src/shared/eviction_policy.rs`. Do not touch the segment code, the topology or the stash-hit counting.

1. **Narrower window.** In `ClassicLRU::eviction_candidate_index`, change the scan window from `0..min(8, items.len())` to `0..min(4, items.len())`. Keep the tie-break toward the lower (older) index, i.e. `min_by_key(|(i, it)| (it.lfu_counter, *i))`.
   - Put the window width in a named `const EVICTION_WINDOW: usize = 4;` so it is easy to sweep later.
2. **Lower cap.** Change the saturating cap from 15 to 7 everywhere v002 applies it:
   - in `ClassicLRU::get_from_position`;
   - in the stash-hit increment in `promotion_get`, if v002 added one there. Do not change that file except for the constant.

   Put the cap in a named `const LFU_CAP: u8 = 7;`. Keep halve-on-cap ageing: when an increment reaches the cap, halve every `lfu_counter` in the bucket. With the lower cap this happens more often, but each halving costs the same.
3. **Faster ageing loop.** Make the halving loop a single pass with `for it in items.iter_mut() { it.lfu_counter >>= 1; }`, with no branching or allocation.
4. Leave `promotion_candidate_index` (MRU) and all other policies unchanged. Adjust any existing ClassicLRU unit tests that hard-code 8 or 15 so they use the new constants.
5. **Measurement.** This hypothesis targets per-op-time. The evaluation must measure per-op-time against baseline's 75 and against v002, as well as hit-rate. Metadata-size must stay at 40.

## Rationale (optional)

v002 is the incumbent, but two cycles in a row have flagged its eviction-path cost as unmeasured. The 8-slot scan and the bucket-wide halving both run on every eviction, and the halving runs on every capped hit. The largest share of the filter's benefit should come from avoiding the one or two oldest one-touch items, so a 4-slot window should catch most of it. A 3-bit cap ages faster, which may even help web_0's phase changes. If hit-rate holds and per-op-time drops, this becomes a cheaper incumbent for later stacking. If hit-rate falls sharply, the 8-slot window is the source of the gain.
