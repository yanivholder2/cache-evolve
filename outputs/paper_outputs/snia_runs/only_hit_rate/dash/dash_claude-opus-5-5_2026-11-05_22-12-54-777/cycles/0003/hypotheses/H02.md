# H02

Re-inserting items demoted from the normal tier at the stash MRU end only when their `lfu_counter` is at least 2 will raise hit-rate on hm_0 by giving proven-reused, long-gap blocks a second stash residency, and it will not hurt web_0.

## Parent

cycle/0002/v002

## Changes

Start from v002's overlay. Keep the topology, the 8-slot frequency-aware tail victim, stash-hit counting and halve-on-cap ageing unchanged. Edit only `src/dash/segments/dash_segment.rs`.

1. In `demote_from_normal_bucket`, find each `core.put_at(Slot::Stash, ..)` call, which is the path where a normal-tier victim falls back into stash. Before each call, choose the insert position from the demoted item's own counter:
   - if `item.lfu_counter >= 2`, use `InsertPosition::Back`, the MRU end of the stash bucket;
   - otherwise use the position currently passed in (`Front` in v002), so that one-hit items are still the first to leave.
2. Leave the foreign-resident retry into `Slot::Target` inside `demote_from_normal_bucket` unchanged.
3. Carry the item's `lfu_counter` through the demotion unchanged. Do not reset it, so the stash tail scan can still tell reused items from one-touch items.
4. Do not change promotion landing (`promote_to_target` and `promote_to_probing` keep their v002 positions), the target→probing trigger, or `Segment::put`.
5. Add one in-file unit test:
   - demote an item with `lfu_counter = 3` and assert that it lands at the last index of its stash bucket;
   - demote an item with `lfu_counter = 0` and assert that it lands at index 0.

Do not change `Item`, so metadata-size stays at 40. Leave the trait signatures and the gate-integrity files untouched.

## Rationale (optional)

The cross-cycle open questions ask two things: which part of v001's bundle (mid-stash demotion or the hit-bit guard) hurt web_0, and whether hm_0's long-gap reuse can be served without growing the stash. Unconditional softer demotion protects web_0's scan victims too. A counter-gated demotion protects only blocks that were reused at least twice, which scans almost never are. hm_0 gains from the longer residency of these blocks, while web_0's one-touch blocks still exit first. This tests the demotion lever on its own, with a frequency guard that v001 did not have.
