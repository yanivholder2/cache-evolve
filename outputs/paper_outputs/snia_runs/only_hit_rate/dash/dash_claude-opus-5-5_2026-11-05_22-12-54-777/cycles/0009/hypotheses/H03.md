# H03

A per-segment feedback score that tracks whether bypass-admitted ghost returners get re-hit in target before eviction, and that lets returners bypass even all-warm windows while the score is positive, will raise mean hit-rate by tuning the bypass to each trace and cache size.

## Parent

cycle/0008/v002

## Changes

v002's fixed gate (free slot or counter-0 tail slot) helps at 16384 but blocks useful returners on web_0 at 131072. Replace the fixed rule with one that learns from outcomes, inside `DashSegment`:

1. Add a per-segment signed saturating counter `bypass_score: i8`, clamped to [-16, 15] and starting at 0. Add one bit per normal-bucket slot, `ghost_admitted`, kept in a per-bucket `u32`/`u64` bitmap field (or a spare bit that already exists). Do **not** take this bit from `lfu_counter`, and do not lower the counter cap. c0008 v001's broad regression may have come from exactly that.
2. Whenever a ghost hit takes the bypass into target (by any gate branch), set `ghost_admitted` on the slot it lands in.
3. On a hit to a target slot with `ghost_admitted` set: `bypass_score += 1` (saturating), then clear the bit.
4. When a slot with `ghost_admitted` still set is evicted or demoted out of target (in the victim scan or the `demote_from_normal_bucket` cascade): `bypass_score -= 1` (saturating), then clear the bit. Clear the bit on delete and overwrite as well, and move it with the item if slots shift within a bucket.
5. Gate: take the bypass if the target bucket has a free slot, or the tail window has a counter-0 slot (as in v002), **or** `bypass_score > 0`. In that last case the victim is the normal min-counter slot from the existing scan. If none of these hold, use v002's stash fallback unchanged.
6. Keep everything else unchanged: window 8, counter cap and ageing rules, demotion and stash-hit halving, the ghost table, and the 24/8 topology.

Expected effect: at 131072 on web_0, returners that the cold-slot gate admits often get re-hit, so the score turns positive and the blocked returners are let through again, recovering cycle 0007 v002's large-size gain. At 16384, un-re-hit arrivals push the score negative, and the gate reverts to v002's cold-slot-only rule, which keeps the small-size gains. Report metadata-size (the bitmap plus one byte per segment) and per-op-time.

## Rationale (optional)

The cross-cycle insights ask whether bypass rules should depend on cache size, because no single static rule wins every cell. This answers it without a hard-coded size threshold: the segment measures whether bypasses pay off and adjusts itself.
