# H02

When the target bucket's tail window is all warm, sending a ghost-hit returner to the probing (neighbour) bucket's Front, if that bucket has a free or counter-0 tail slot, will raise hit-rate on web_0 at 131072 without displacing warm target residents.

## Parent

cycle/0008/v002

## Changes

In v002's `DashSegment::put`, the ghost-hit path currently takes the bypass only when the target bucket has a free slot or a counter-0 slot in its 8-slot tail window. Otherwise it falls back to inserting into the stash with counter 1. Add one fallback tier between those two outcomes:

1. If the target-bucket gate refuses, run the same gate-plus-victim-scan helper on the key's probing bucket: the neighbour bucket that Dash already searches on lookup for this hash. If the probing bucket has a free slot or a tail-window slot with `lfu_counter == 0`, insert the key there at Front with `lfu_counter = 1`. Use the probing bucket's own victim choice and its own `demote_from_normal_bucket` cascade, exactly as the target path does.
2. Only if both buckets refuse, use v002's existing stash fallback, with the ghost-entry handling unchanged.
3. Before writing this, check that the get/lookup path, the update path and the delete path all find a key stored in the probing bucket. If the probing bucket only accepts keys displaced from target, set the same displacement/overflow metadata (for example a probing or displaced bit, or an overflow fingerprint) that the existing insert-into-probing code sets. Reuse that code, do not duplicate it. Do not change lookup, and do not touch `src/dash/jni.rs` or any gate-integrity file.
4. Keep everything else unchanged: window 8, counter cap and ageing rules, demotion halving, stash-hit halving, ghost size and fingerprint, the 24/8 topology, and the exact counter-0 gate condition on the target bucket.

Expected effect: web_0 at 131072 recovers part of what c0008 gave back, because returners that were sent back to the stash now find cold capacity next door. The 16384 cells stay roughly flat or gain slightly, because the probing bucket is also gated on cold slots, so no warm resident is displaced. Watch per-op-time: in the refused case the ghost-hit path reads a second window.

## Rationale (optional)

c0008 showed that what matters is who gets displaced, not whether the returner is admitted. This keeps the "never displace warm" rule and enlarges the pool of cold slots a returner can use. It is a placement change, not a threshold change, so it is distinct from relaxing the gate.
