# H01

Relaxing the ghost-bypass gate from "the tail window has a counter-0 slot" to "the coldest tail-window counter is no higher than the returner's credit (1)" will raise mean hit-rate by winning back large-size web_0 while keeping the small-size gains.

## Parent

cycle/0008/v002

## Changes

In v002's `DashSegment::put`, find the ghost-hit path. Its gate currently takes the stash bypass (`promote_to_target(..., Front)` with `lfu_counter = 1`) only when the target bucket has a free slot or a slot in the 8-slot tail window has `lfu_counter == 0`. Otherwise the key goes to the stash.

1. Change only the gate predicate in that combined gate-plus-victim-scan helper. Take the bypass when the target bucket has a free slot, or when `min(lfu_counter)` over the 8-slot tail window is `<= GHOST_CREDIT`, where `GHOST_CREDIT` is the existing credit of 1. Add it as a named constant if it is not one already. In practice this also admits the returner when the coldest candidate is a counter-1 slot, for example an earlier un-re-hit ghost arrival or a fresh Front arrival that has aged into the tail, and keeps refusing when every candidate has counter 2 or more.
2. The helper already computes the min-counter candidate for the victim scan. Reuse that value for the comparison so the window is still read only once. Do not add a second pass.
3. Leave the victim choice unchanged: the same min-counter slot in the window, with the same tie-break. Leave the refused-bypass fallback unchanged: stash insert with counter 1, and keep the ghost-entry handling exactly as v002 has it.
4. Keep everything else unchanged: window 8, counter cap and halve-on-cap ageing, halving on demotion into the stash, halving on stash hits, the size and full-width fingerprints of the direct-mapped ghost, and the 24/8 topology.

Expected effect: web_0 at 131072 recovers toward cycle 0007 v002's value, because all-warm windows there mostly sit at counter 1, not 2 or more. The 16384 cells should mostly keep their gains, because the gate still refuses when the window holds proven multi-hit residents. If hm_0 at 16384 drops, then counter-1 residents in contended targets are worth protecting too, and the gate should depend on size. Report per-op-time if the harness provides it.
