# H02

Admitting ghost-hit keys directly into their target bucket (instead of the stash) will raise hit-rate on large-size hm_0, because proven long-gap returners will skip the stash, whose short residency is where they are lost again before their next reuse.

## Parent

cycle/0006/v003

## Changes

Start from cycle/0006/v003's overlay. Edit only `src/dash/segments/dash_segment.rs`. Keep the ghost table's size, indexing, fingerprints, and the `lfu_counter = 1` credit. Keep v003's halving on demotion into the stash, the 24/8 topology, `eviction_policy.rs`, and all landing positions for `get`-driven promotions.

1. In `DashSegment::put`, branch on the ghost result:
   - **Ghost miss** (fresh key): unchanged. `put_into_stash(core, ghost, InsertPosition::Back, item)` with counter 0.
   - **Ghost hit**: set `item.lfu_counter = 1`, then call `promote_to_target(&mut self.core, &mut self.ghost, item, InsertPosition::Front)` instead of `put_into_stash`. The item lands at the target bucket's LRU end (Front), the same landing a stash→target promotion uses. Any target victim flows through the existing `demote_from_normal_bucket` cascade, including v003's halving and ghost recording of any stash drop.
2. Invariants: the `put` debug_assert (key not resident) stays. After a ghost-hit `put` the key must be resident in its target bucket. `promotion_get` already checks the stash first and then the target, so a later `get` finds it in target with no change to `promotion_get`. Do not add the key to the stash as well; it must be in exactly one place.
3. Tests:
   - Update `key_evicted_from_stash_and_reput_starts_with_counter_one`: after the re-put, assert that the victim is in `core.buckets[get_index(&victim, core.segment_size)]` with `lfu_counter == 1`, and that `stash_counter(&seg, victim)` is `None`.
   - Add `fresh_put_still_goes_to_stash` (equivalent to the existing `put_goes_to_stash` / `fresh_key_starts_with_counter_zero`; keep those passing).
   - Add a test that a ghost-hit put into a full target demotes exactly one resident to the stash with its counter halved.
4. Report per-op-time: a ghost-hit `put` now takes the target insertion path (one extra bucket insert and possible cascade) instead of a stash insert.

## Rationale (optional)

Ghost reach and ghost credit size are both ruled out (c0005, c0006). In both cases the credited key still re-enters the stash, a small 8-bucket tier. At the large cache size, hm_0's long-gap returners must survive the stash again *and* get a second hit there before they can reach the protected tier, so the credit is often wasted. This is the ARC/2Q rule that a ghost hit goes straight to the frequency (protected) list. It changes *where* the credited key is placed, not how much credit it gets. Because it lands at target Front with counter 1, the tail scan can still evict it quickly if it doesn't get re-hit, so stickiness is limited. web_0 should stay flat: its ghost rarely fires.
