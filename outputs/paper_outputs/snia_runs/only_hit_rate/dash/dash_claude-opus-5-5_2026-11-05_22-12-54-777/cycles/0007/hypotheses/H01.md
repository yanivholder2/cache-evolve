# H01

Decrementing the `lfu_counter` of the normal-bucket tail-window survivors each time a normal-tier victim is demoted will raise hit-rate on hm_0 by ageing stale target-tier frequency at the point of eviction, without penalising any hit.

## Changes

Start from cycle/0006/v003's overlay. Edit only `src/dash/segments/dash_segment.rs`. Do not touch `src/shared/eviction_policy.rs`: `record_hit` keeps its cap-15 halve-on-cap ageing, `lru_tail_lfu_victim` keeps window 8, and the stash's ageing is unchanged. Keep the ghost (capacity-sized, direct-mapped, credit 1), the 24/8 topology, every landing position, and v003's halving on demotion into the stash.

1. Add a helper `age_tail_survivors(items: &mut [Item<K, V>])` in `dash_segment.rs`. For the first `min(items.len(), LRU_TAIL_WINDOW)` slots (import `LRU_TAIL_WINDOW` from `crate::shared::eviction_policy`), it applies `lfu_counter = lfu_counter.saturating_sub(1)`. These are the least-recent residents that just out-competed the victim.
2. In `promote_to_target` and `promote_to_probing`, when `core.put_at(...)` returns `Some(evicted)`, call `age_tail_survivors(core.buckets[idx].get_items_mut())` on the bucket that just evicted (`target_idx` or `probing_idx`). Do this before calling `demote_from_normal_bucket`. In `demote_from_normal_bucket`'s probing→own-target retry, when `core.put_at(Slot::Target, ...)` returns `Some(cascade)`, also age `core.buckets[true_target]`. Never age stash buckets.
3. Note on indexing: the newly inserted item lands at `Front` (index 0), so it falls inside the aged window. Only skip it if it is easy to identify (for example, by comparing keys with the item just inserted). Otherwise aging it is acceptable, since a promoted item usually carries counter ≥1 and goes to ≥0. State in the code comment which choice was made.
4. Tests: add `normal_eviction_ages_tail_survivors`. Fill target bucket 0 via `find_keys_for_bucket` with `put` + `get`. Set every resident's counter to 5. Force one demotion by promoting one more key. Assert that the residents still in the first `LRU_TAIL_WINDOW` slots (other than the newcomer, if it was skipped) now have counter 4, and that slots beyond the window still have 5. Keep all existing tests passing.
5. Report per-op-time if the harness allows: this adds at most 8 decrements per normal-tier eviction.

## Rationale (optional)

Cycle 0006 left this question open: does ageing at other tier boundaries help the way demotion-ageing did? Today, normal-tier counters only age through the halve-on-cap rule, which almost never fires for medium-frequency items. Items that were hot once therefore stay protected in the tail window indefinitely and crowd out promoted ghost returners. This is like CLOCK's second-chance decrement: each eviction costs the survivors one unit of protection, so an item has to keep being hit to stay. No hit is penalised. That is the property that made v003's demotion-halving safe and that removing the stash-hit halving lacked. If this works it should show in hm_0 at both sizes; web_0 should stay flat.
