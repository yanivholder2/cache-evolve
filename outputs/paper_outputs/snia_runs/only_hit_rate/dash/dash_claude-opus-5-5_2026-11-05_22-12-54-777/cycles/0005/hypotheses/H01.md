# H01

Replacing the 64-entry linear-scan ghost ring with a direct-mapped ghost table sized to the segment's item capacity will raise hit-rate on hm_0 by extending ghost credit to reuse distances well beyond stash residency, without adding per-`put` scan cost.

## Parent

cycle/0004/v002

## Changes

Start from cycle/0004/v002's overlay. Keep everything else unchanged: the 24/8 topology, the 8-slot `lru_tail_lfu_victim` with cap 15 and halve-on-cap ageing, stash-hit counting, all landing positions, and the ghost-hit bonus (`lfu_counter = 1`). The only change is the ghost's reach and lookup structure. It lives in `src/dash/segments/dash_segment.rs`.

1. **Sizing.** Replace `slots: [u16; GHOST_SLOTS]` and `head` in `struct Ghost` with `slots: Box<[u16]>` and `mask: usize`.
   - In `DashSegment::try_new`, compute the segment's resident item capacity from `core`: normal buckets × bucket max size + stash buckets × stash bucket max size. Use the existing `get_max_size()` on `core.buckets[0]` and `core.stash_buckets[0]`.
   - Round that capacity up to the next power of two, with a floor of 64. Allocate that many slots, all set to `GHOST_EMPTY`.
   - Keep `GHOST_SLOTS = 64` only as the floor constant, or rename it to `GHOST_MIN_SLOTS`.
2. **Indexing.** Keep the stored fingerprint as the top 16 bits of `hash(key)`, as today. Compute the slot index from a *different* mix of the hash, so the index bits and fingerprint bits are independent: apply a splitmix64 finalizer (`h ^= h >> 30; h *= 0xbf58476d1ce4e5b9; h ^= h >> 27; h *= 0x94d049bb133111eb; h ^= h >> 31`) to the 64-bit hash, then `idx = (mixed as usize) & mask`. Put both in one helper `ghost_key(&K) -> (usize, u16)` so the hash is computed only once.
3. **Record.** `record(idx, fp)` writes `slots[idx] = fp` and overwrites whatever was there. This is direct-mapped, so a collision replaces the older entry, which approximates FIFO ageing at table scale. The call sites in `put_into_stash` do not change: still only for keys dropped out of the stash, never for normal→stash demotions.
4. **Take.** `take(idx, fp)` checks only `slots[idx]`. On a match it clears that slot to `GHOST_EMPTY` and returns `true`. This makes lookup O(1), versus the 64-entry linear scan.
5. **Tests.** Update the unit tests:
   - `ghost_ring_overwrites_oldest` becomes a test that recording two different fingerprints at the same index keeps only the latest.
   - Add a test that table length is a power of two and at least the segment's item capacity.
   - Keep `key_evicted_from_stash_and_reput_starts_with_counter_one` and `fingerprint_never_empty` passing.
6. **Reporting.** Report metadata-size: the table adds about 2 bytes per resident slot, so 40 becomes about 42 per entry. Report per-op-time: the `put` path drops from a 64-compare scan to one compare plus a multiply-mix.

## Rationale (optional)

v002's insight says the ghost works but reaches too short: it holds 64 drops per segment, which covers only gaps just past stash residency. ARC's ghost lists are sized to the cache itself, so this matches ghost reach to resident capacity. Making the table direct-mapped answers the cost worry raised in every cycle since the ring was added, so any hit-rate change can be attributed to reach alone. web_0 should stay flat, since scan keys rarely return. If hm_0 does not improve, ghost reach is not the binding limit and the bonus size is (see H02).
