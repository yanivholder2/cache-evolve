# H01

Give each ghost-admitted target item a one-time exemption from the frequency tail-scan victim choice to raise small-size hm_0 hit-rate.

## Parent

cycle/0007/v002

## Changes

In v002, a ghost hit in `DashSegment::put` calls `promote_to_target(..., Front)`
with `lfu_counter = 1`. At size 16384 these arrivals sit inside the 8-slot
tail window and are evicted by the frequency-aware scan before they can be
hit again (cycle 0007 insight).

1. Add a one-bit `ghost_admitted` (probation) flag to each slot's metadata.
   If a spare bit exists in the existing counter/metadata byte, use it, for
   example by taking the top bit and keeping the counter cap below it. Only add
   a field if no spare bit exists, and report the change in metadata size.
2. Set the flag only on the ghost-hit → `promote_to_target(Front)` path. Clear
   it when the item gets any hit, when it is demoted, and when it is moved.
3. In the normal-tier tail victim scan (the 8-slot window used when target
   is full, including the `demote_from_normal_bucket` cascade), if the chosen
   min-counter candidate has `ghost_admitted` set, clear the flag and pick the
   next-best candidate in the same window instead. This is a single second
   chance with no re-scan loop. If every candidate in the window is flagged,
   fall back to the original choice so eviction always succeeds.
4. Keep everything else unchanged: Front landing, counter 1, window 8, all
   halving rules (on cap, on stash hit, on demotion), ghost size and fingerprint
   width.

The flag does not touch counters, so it is not a form of ageing. It only
delays the first eviction of a credited key, which answers the cycle 0007
question about exempting ghost-admitted keys from the scan for a short time.
Expected effect: hm_0 at 16384 goes up, the large size stays the same or goes
up, and web_0 stays flat. Report per-op-time.

## Rationale (optional)

v002's gains scale with target capacity. The small size loses the credited
keys to the scan. Protection that the key cannot keep beyond one exemption
avoids the items-get-stuck problem seen in c5.
