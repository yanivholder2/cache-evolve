**What the overlay does** (four files, all edited from the parent v002):
- **The flag:** it lives in the top bit of `lfu_counter`. The counter is capped at 15, so that bit was free. `Item` stays the same size and there is no metadata size change to report. Small helpers read the counter without the flag, set or clear it, and halve the counter while keeping the flag.
- **Victim choice** (in the policy and bucket files): the 8-slot window scan still finds the lowest-counter candidate. If that item has the flag, the victim becomes the best unflagged item in the same window, all in one pass. If every item in the window is flagged, the original choice is evicted, so eviction always succeeds. This choice lives in the bucket, so it also applies inside the `demote_from_normal_bucket` cascade.
- **Clearing the flag:** each item skipped this way loses its flag, so it is protected once only. The flag is also cleared on any hit (in `record_hit` and on target and probing hits), on demotion (including the cascade victim, before its counter is halved) and when the item moves to probing.
- **Setting the flag:** only on the ghost-hit path in `DashSegment::put`, together with the existing counter of 1. Everything else is unchanged: Front landing, window of 8, cap and all halving rules, ghost table size and fingerprint width.

**Two behaviours to know about:**
- **Several flagged items in one window:** every flagged item that ranked ahead of the chosen victim uses up its exemption, not just the first one. Otherwise an item could be skipped without its exemption being counted.
- **Other policies:** the exemption only applies when the policy is `ClassicLRU`, the frequency tail scan in the hypothesis. The `Lfu` policy now ignores the flag when comparing counters, so a flagged item doesn't look like it has a huge count there.
