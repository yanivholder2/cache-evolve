# H03

Replacing v002's bucket-wide halve-on-cap ageing with eviction-pressure ageing, where each eviction decrements the counters of the window's surviving slots by one, will raise hit-rate on web_0 by retiring stale frequent items faster after phase changes.

## Parent

cycle/0002/v002

## Changes

Start from v002's overlay. Keep the 24/8 topology, `LRU_TAIL_WINDOW = 8`, the victim rule (lowest `lfu_counter` in the window, ties go to the older slot), the stash-hit counting and all landing positions unchanged. Change only how counters age.

1. **Remove halve-on-cap.** In `record_hit` in `src/shared/eviction_policy.rs`, delete the bucket-wide halving loop. Replace it with a plain saturating increment, `items[position].lfu_counter = (items[position].lfu_counter + 1).min(LFU_COUNTER_CAP);`, and keep `LFU_COUNTER_CAP = 15`.
2. **Add eviction-pressure ageing.** In the same file, add `pub fn age_tail_window<K, V>(items: &mut [Item<K, V>], window: usize)`. It decrements `lfu_counter` by 1, saturating at 0, for each of the first `window.min(items.len())` slots.
3. **Call it after each eviction.** In `src/dash/segments/dash_segment.rs`, find every place that removes the item chosen by `eviction_candidate_index` from a bucket. That includes both the stash eviction and the normal-bucket victim that is demoted to stash.
   - Immediately after the removal, call `age_tail_window(&mut bucket_items, LRU_TAIL_WINDOW)` on that bucket's item vector.
   - This ages the up-to-8 slots that were just the victim's competitors, now shifted down by one.
   - Call it only when the policy is `ClassicLRU`, or route the call through a no-op default so that other policies are not affected. Do not change the `EvictionPolicy` trait signatures.
4. A demoted item keeps the counter it had when it left the normal bucket. Do not age it a second time.
5. Update the tests:
   - Rewrite `classic_lru_counter_ages_at_cap` so it asserts that the counter saturates at 15 and that no other slot changes.
   - Add a test for `age_tail_window`: it decrements only the first 8 slots, and saturates at 0.
6. `Item` must not grow, so metadata-size stays at 40. Report per-op-time: the 8-slot decrement per eviction replaces the full-bucket halving on capped hits.

## Rationale (optional)

Cycle 0003 v003 changed the cap and the window together, so whether ageing matters is still open. The insights also ask whether a different ageing rule would help. Halve-on-cap only fires when some item in the bucket reaches 15 hits. In a bucket of moderately reused items it may never fire, so stale items with counts of 3–6 can sit in the tail indefinitely and shield themselves from eviction. Under CLOCK-style decrement-on-pressure ageing, only items that keep being hit hold their protection, and how fast items age follows the eviction rate rather than the hit count. This should mainly help web_0, where v002's gains were smallest. If hit-rate falls instead, slow, rare ageing is part of why the filter works.
