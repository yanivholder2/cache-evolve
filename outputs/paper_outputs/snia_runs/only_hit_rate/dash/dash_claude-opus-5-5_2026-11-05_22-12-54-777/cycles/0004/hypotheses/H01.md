# H01

Widening v002's frequency-aware victim scan from the 8 least-recent slots to 16 will raise hit-rate above 0.5392, with the largest gain on hm_0 at size 16384.

## Parent

cycle/0002/v002

## Changes

Start from v002's overlay. Edit only `src/shared/eviction_policy.rs`. Leave the topology (24 normal / 8 stash), the stash-hit counting in `promotion_get`, the segment code and every landing position unchanged.

1. Change `pub const LRU_TAIL_WINDOW: usize = 8;` to `16`. `lru_tail_lfu_victim` already clamps with `items.len().min(LRU_TAIL_WINDOW)`, so the 8-slot stash buckets now get a full-bucket scan and the 24-slot normal buckets get a 16-slot tail scan.
2. Keep the tie-break toward the older (lower-index) slot: use the existing strict `<` comparison and do not change it to `<=`.
3. Keep `LFU_COUNTER_CAP = 15` and `record_hit`'s halve-on-cap ageing exactly as they are, so this variant changes only the window.
4. Update `classic_lru_victim_prefers_low_count_in_tail` so it still holds with a 16-slot window. Build a bucket of 20 items, put counter ≥1 on slots 0..16 with one minimum at a known index, and set counter 0 on slots 16..20, which sit outside the window. Assert that the known index is chosen. Add one test showing that a slot at index 12 with counter 0 now beats index 0 with counter 1.
5. `Item` must not grow, so metadata-size stays at 40. The evaluation should report per-op-time against baseline's 75, because the scan doubles.

## Rationale (optional)

Cycle 0003 v003 showed that narrowing the window to 4 cost hit-rate on every cell, and cost the most on hm_0 at the small size. So window width is a live lever, and the cross-cycle insights ask directly whether a width above 8 helps. With Front landing, new arrivals and newly promoted items sit at the LRU end. A wider window lets one-touch items further up the bucket be evicted before reused residents that have aged toward the tail. If hit-rate rises, the curve is still climbing. If it stays flat or falls, 8 is close to optimal and the window lever is spent.
