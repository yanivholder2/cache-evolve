# H01

Raising the ghost-hit admission counter from 1 to 2 on top of the capacity-sized direct-mapped ghost, with full 16-bit fingerprints kept, will raise hit-rate on hm_0 because ghost-credited keys survive one more round of the 8-slot tail scan and of halve-on-cap ageing.

## Parent

cycle/0005/v001

## Changes

Start from cycle/0005/v001's overlay. Edit only `src/dash/segments/dash_segment.rs`. Keep everything else unchanged: the 24/8 topology, the `Ghost` table (sized to `normal_cap + stash_cap`, rounded up to a power of two, splitmix64 index, top-16-bit fingerprint, `GHOST_EMPTY = 0` remap), the call sites of `record` (only for keys dropped out of the stash), Front landing on promotion, stash-hit `record_hit` with halving, and `src/shared/eviction_policy.rs` (window 8, cap 15).

1. Add a constant `pub const GHOST_ADMIT_COUNTER: usize = 2;` next to `GHOST_MIN_SLOTS`.
2. In `DashSegment::put`, when `self.ghost.take(idx, fp)` returns `true`, set `item.lfu_counter = GHOST_ADMIT_COUNTER` and not `1`. Update the `debug!` message to match. Placement stays the same: `put_into_stash(..., InsertPosition::Back, item)`.
3. Do **not** store the evicted item's old counter and do **not** narrow the fingerprint. Cycle 0005 v002 combined the bonus with 12-bit fingerprints, and that combination cost web_0. This variant isolates the bonus size.
4. Tests: rename `key_evicted_from_stash_and_reput_starts_with_counter_one` to `..._starts_with_ghost_admit_counter` and assert `Some(GHOST_ADMIT_COUNTER)`. Keep all other tests passing unchanged. In particular, `fresh_key_starts_with_counter_zero` must still hold.
5. Update the doc comments on `Ghost` and `DashSegment` that say "`lfu_counter = 1`".

## Rationale (optional)

v001's insight says that at the large size, the next limit is the bonus weight rather than ghost reach. A single step can be erased by a single halving. Cycle 0005 v002 tested a stronger bonus, but only on the 64-slot ring and with narrowed fingerprints, so the stronger bonus was never tested on its own. Now that the ghost fires much more often, a +2 credit should matter more. web_0 should stay flat because its ghost seldom fires. If hm_0 at 131072 still does not move, the large-size loss is not an admission-strength problem.
