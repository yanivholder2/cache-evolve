# H01

Making the ghost-bypass gate depend on how warm the window is (admit over a counter-1 minimum only when at most 2 of the 8 tail-window slots hold counter ≥ 2, and otherwise keep the strict counter-0 rule) will raise mean hit-rate by recovering web_0 at 131072 without the hm_0 16384 loss seen in c0009 v001.

## Parent

cycle/0009/v002

## Changes

In the parent's `DashSegment::put` ghost-hit path, find the combined gate-plus-victim-scan helper that reads the target bucket's 8-slot tail window. Today it takes the bypass (Front insert, `lfu_counter = 1`) only if the bucket has a free slot or a window slot with `lfu_counter == 0`. If neither holds, it tries the probing-bucket fallback and then the stash.

1. In the same single pass over the window, compute two values:
   - `min_ctr`: the existing minimum counter, which also gives the victim index.
   - `warm_cnt`: the number of window slots with `lfu_counter >= 2`.
2. Replace the gate predicate on the target bucket with:
   `free_slot || min_ctr == 0 || (min_ctr <= GHOST_CREDIT && warm_cnt <= WARM_TOLERANCE)`.
   - `GHOST_CREDIT` is the existing credit of 1.
   - `WARM_TOLERANCE` is a new named const, set to 2.

   So a window full of counter-1 slots (the large-size web_0 case that c0009 v001 identified) admits the returner. A window holding several proven multi-hit residents (contended small-size hm_0) keeps the strict c0008 rule.
3. Apply the same predicate to the probing-bucket fallback so the two tiers stay consistent.
4. Leave the rest unchanged:
   - victim choice: the min-counter slot, with the existing tie-break
   - the stash fallback and ghost-entry handling
   - window 8, the counter cap and halve-on-cap
   - halving on demotion and on stash hits
   - ghost size and fingerprint width
   - the 24/8 topology
5. Do not read the window a second time. Do not add per-segment state.

Expected effect: web_0 at 131072 moves toward c0009 v001's 0.5785. hm_0 at 16384 stays near v002's 0.452. If hm_0 at 16384 still drops, lower `WARM_TOLERANCE` to 1 in a follow-up. If web_0 at 131072 does not move, the counter-1 windows there are dense with counter ≥ 2 slots after all.

## Rationale (optional)

The c0009 insight says the global threshold moves the trade-off between sizes but never improves both. This gate adapts to contention using only information already present in the window, with no size constant and no learned signal. It is the occupancy-dependent gate named as the top open question.
