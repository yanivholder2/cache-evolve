# H02

Giving a ghost entry a one-bit "refused once" strike, so that a key refused by the bypass gate and then dropped and returning again gets credit 2 and may displace a counter-1 window minimum, will raise hit-rate on web_0 at 131072 while keeping the strict gate for first-time returners on hm_0 at 16384.

## Parent

cycle/0009/v002

## Changes

The parent's direct-mapped, capacity-sized ghost table stores a full-width fingerprint per entry. The ghost-hit path in `DashSegment::put` takes the bypass only if there is a free or counter-0 slot (target bucket, then probing bucket). Otherwise it inserts into the stash with counter 1.

1. Add one `refused` bit to each ghost entry. Pack it into the existing entry word if a spare bit exists, for example by stealing the top fingerprint bit only if the fingerprint is already wider than 16 bits. Otherwise use a parallel bit-vector sized to the ghost table. Do not narrow the fingerprint below its current width, because c0005 showed false matches hurt web_0.
2. On a ghost hit where both gate tiers refuse and the key goes to the stash, record that refusal on the key's ghost slot. When that key is later dropped from the stash and re-inserted into the ghost, set `refused = 1` on its new ghost entry. Implement this by carrying a one-bit flag on the stash slot, reusing a spare metadata bit if one exists, or by re-setting the bit when the drop path writes the ghost entry.
3. On a ghost hit with `refused == 1`:
   - Use credit `GHOST_CREDIT_STRIKE = 2`.
   - Pass the gate if the window has a free slot or `min_ctr <= 1`.
   - Insert at target Front with `lfu_counter = 1`, as for any bypass. The credit only decides whether the key is admitted. It does not raise the inserted counter, so ageing behaviour is unchanged.
   - Clear the bit when the key is admitted.
4. Keys with `refused == 0` use the parent's gate exactly. Leave everything else unchanged: victim choice, window 8, the ageing rules, the 24/8 topology, and the probing fallback.

Expected effect: keys that keep returning (the valuable large-size web_0 returners) get in on their second return. One-time returners on small hm_0 are still blocked from displacing counter-1 residents. hm_0 at 16384 should stay within noise. If nothing moves, refused keys rarely return twice within ghost reach. Report metadata-size if the harness provides it, because the bit adds metadata if it cannot be packed.

## Rationale (optional)

c0009 showed that the global threshold cannot separate the two sizes. This hypothesis separates by evidence per key (a repeated return) instead of by size or by window state. That makes it distinct from H01's contention gate, and also distinct from the ghost-bonus sweeps, which raised the counter for every ghost hit.
