# H02

Swapping the per-segment split from 8 normal / 24 stash buckets to 24 normal / 8 stash, with the same total capacity, will raise hit-rate by making the protected target/probing tier the majority of capacity, as in SLRU's roughly 80/20 protected/probation split.

## Parent

baseline

## Changes

Edit only `src/shared/geometry.rs`. Keep the `BaselineGeometry` type name, `BaselineGeometry::for_settings(&DashSettings) -> Self`, and the `BucketGeometry::layout` signature.

In `for_settings`, keep `num_of_segments` and `bucket_size` exactly as given by the settings. Then:

- Compute `total_buckets = settings.num_of_normal_buckets + settings.num_of_stash_buckets` (32 under the harness geometry).
- Set `num_of_stash_buckets = max(1, total_buckets / 4)` (8).
- Set `num_of_normal_buckets = total_buckets - num_of_stash_buckets` (24).
- If that would leave `num_of_normal_buckets < 2` (the `SegmentCore::try_new` validation rejects a single normal bucket), fall back to the settings' split unchanged.

Total capacity, `num_of_segments * total_buckets * bucket_size`, must stay exactly equal to the harness value. Only the normal/stash ratio changes. Store the result in `topology` as before, so `layout()` still returns it unchanged.

Do not touch the segment, bucket, policy, or item code. The admission path (put → stash), the promotion cascade, and the ClassicLRU ordering stay exactly as in baseline. The experiment isolates the effect of topology.

## Rationale (optional)

In the baseline, every new item enters stash, which holds 75% of capacity. Only items hit while in stash move to the normal tier, which holds 25%. MSR web_0 and hm_0 are block-I/O traces with a large reused working set mixed with one-touch scans. A small protected tier means frequently reused blocks keep getting pushed back to stash by promotion churn: each target→probing promotion evicts a probing resident. A 75%-protected / 25%-probation split matches the classic SLRU tuning and should hold the reused set better. The effect should be larger at size 16384, where baseline hit-rate is about 0.41. Per-op time and metadata size should not change.
