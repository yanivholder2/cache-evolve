# H03

Making ClassicLRU frequency-aware will raise hit-rate on scan-heavy MSR traces: hits bump a saturating per-item counter, and eviction picks the lowest-count item among the 8 least-recent slots instead of always slot 0.

## Parent

baseline

## Changes

Edit `src/shared/eviction_policy.rs` (the `ClassicLRU` impl) and make one small edit in `src/dash/segments/dash_segment.rs`.

1. `ClassicLRU::get_from_position`: before moving the item to the back, do `items[position].lfu_counter = (items[position].lfu_counter + 1).min(15)`, a 4-bit saturating counter. Then keep the existing `remove` + `push` move-to-MRU and return `items.len() - 1`.

2. `ClassicLRU::eviction_candidate_index`: instead of always returning `0`, scan the window `0..min(8, items.len())`, which holds the 8 least-recently-used positions. Return the index with the smallest `lfu_counter`, breaking ties toward the lower index (the older item), e.g. `min_by_key(|(i, it)| (it.lfu_counter, *i))`. This method takes `&self, &[Item]`, so it must stay read-only.

   Do the ageing in `ClassicLRU::get_from_position` instead, which has `&mut Vec`. When the incremented counter reaches 15, halve `lfu_counter` for every item in the bucket, then do the move-to-back. This keeps the trait signatures unchanged and stops old frequency from going stale.

3. `ClassicLRU::promotion_candidate_index` stays `items.len() - 1`, the MRU slot. The segment's "hottest in target → probing" rule is unchanged.

4. In `promotion_get` in `dash_segment.rs`, a stash hit currently does `remove_at` without calling the policy, so stash hits never count. In the stash-hit branch, change `let data = ...remove_at(item_idx);` to `let mut data = ...;` and add `data.lfu_counter = (data.lfu_counter + 1).min(15);` before `promote_to_target`. Make no other change to the segment.

Do not change the `Item` layout. `lfu_counter` already exists, and `Item::new` initialises it to 0. Fresh inserts from `put` arrive with counter 0, so in the stash, one-touch scan blocks lose to anything that has been hit at least once. The other policies (`Lfu`, `TimestampLRU`, and so on) are untouched. Existing ClassicLRU unit tests that assert `eviction_candidate_index == 0` on all-zero counters still pass, because ties resolve to index 0. Check `classic_lru_eviction_chain` and the segment tests, and adjust any that rely on strict LRU-victim order after hits.

## Rationale (optional)

Baseline eviction is pure recency within each 64-slot bucket. The MSR web_0 and hm_0 traces have sequential scan bursts that flush reused blocks out of stash, and stash holds 75% of capacity. A small frequency filter over the LRU tail is a bucket-local approximation of LRU-K or TinyLFU-style admission. It adds an 8-element scan only on eviction, so per-op time should stay close to the baseline 75 ns p50.
