# H02

Replacing pure-LRU victim selection on v002's 24/8 topology with v003's frequency-aware LRU-tail victim, with stash hits counted, will raise hit-rate above 0.53015 on both traces and both sizes.

## Parent

cycle/0001/v002

## Changes

Start from v002's overlay and keep its 24 normal / 8 stash split. Port v003's frequency filter onto it as follows:

1. **Victim choice.** Change the eviction/victim function so it no longer takes the ClassicLRU-order least-recent slot directly:
   - Look at the 8 least-recent slots of the bucket, or fewer if the bucket holds fewer items.
   - Pick the slot with the lowest `lfu_counter`. Break ties toward the older slot.
   - Apply this to both normal (target/probing) and stash buckets.
2. **Counting.** Increment `lfu_counter` on every hit, and that includes stash hits in `promotion_get`, so that an item promoted out of stash keeps a non-zero count.
   - The counter must move with the item on promotion (stash→target, target→probing) and on demotion back to stash.
   - New items from `put` start at 0.
3. **Ageing.** Cap the counter at 15. When an increment would pass the cap, halve every `lfu_counter` in that bucket. This is the same as v003.
4. **Invariants.** Reuse the existing `lfu_counter` field and do not add anything to `Item`, so metadata-size stays at 40. Leave the trait signatures and the gate-integrity files untouched.

## Rationale (optional)

v003 improved on baseline at both sizes, and hm_0 gained the most. v002's gains came mostly at the large size. The two attack different weaknesses: v002 enlarges the protected tier, and v003 picks better victims inside each bucket. This variant tests directly whether they add up. Because the change sits on the eviction path, per-op-time should be measured against baseline's 75.
