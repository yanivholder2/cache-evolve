# H03

Ignoring probation hits that arrive within a short correlated-reference window after insertion (the newest `small_len / 16` probation slots) when deciding promotion raises hit-rate on web_0 at both sizes, by keeping burst-only blocks out of main.

## Parent

cycle/0007/v001

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0007/v001. The main region, sweep, `steps`, `scan_min_from`, recency-gated
halving, `probation_len` and **reset-to-0 on promotion** stay exactly as they
are. Only the hit path changes, and only for slots in probation.

1. **Constant and helper.** Add `const CRP_DIV: usize = 16;` and a method
   `fn probation_age(&self, pos: usize) -> usize` that returns
   `(self.small_hand + self.small_len - 1 - pos) % self.small_len`. It is valid
   only when `split_active()` and `pos < small_len`. The newest probation
   insertion sits at `small_hand - 1` (age 0), and the slot at `small_hand` is
   the oldest (age `small_len - 1`).
2. **Correlated-hit filter.** Add
   `fn is_correlated_probation_hit(&self, pos: usize) -> bool`, which returns
   `self.split_active() && pos < self.small_len && self.probation_age(pos) < self.small_len / CRP_DIV`.
   The window is 4 slots in 128-slot buckets (`small_len = 64`), 16 slots in
   1024-slot buckets (`small_len = 256`), and 0 for `small_len < 16`, so tiny
   buckets and the existing small-size unit tests behave as before.
3. **Hit paths.** In `get_from_position` and in `put`'s existing-key branch,
   if `is_correlated_probation_hit(position)`, still set
   `recent[position] = true` (harmless: probation decisions ignore it and
   promotion clears it) and still update the value in `put`, but **do not**
   bump `lfu_counter`. All other hits (later probation hits, main hits,
   non-split buckets) bump as now. A block re-referenced only inside the window
   therefore reaches the FIFO head with counter 0 and is evicted. A block that
   is hit again after the window is promoted as before.
4. **No other changes.** `eviction_candidate_index` reads only counters, so it
   stays exact. `remove_at` can shift slots below `small_hand`, which perturbs
   ages slightly after `evict_item`. That is acceptable, since ages only
   affect the filter and never bounds.
5. **Tests (`clock_tests`).**
   - Existing tests use buckets of size ≤ 8 (window 0) or random workloads, so
     they must pass unchanged. `candidate_matches_sweep` already covers size
     128, where the filter is active.
   - Add `correlated_probation_hit_not_promoted`: in `bucket(128)`, fill it,
     insert key X by a miss, `get(X)` immediately (age 0), then run 64 more
     distinct misses. Assert that X was evicted from probation and never
     reached main.
   - Add `late_probation_hit_promoted`: same setup, but hit X after 10
     intervening misses (age 10 ≥ 4). Assert that X ends up in main
     (`pos >= small_len`) with counter 0.

Invariants: unchanged from v001. No new per-slot state, and the hit path only
does an O(1) modular computation.

## Rationale (optional)

Every working lever since cycle 0004 has *tightened* admission into main
(probation itself, the depth floor, reset-to-0), and every loosening failed.
Promotion is the only admission signal left untouched: any single probation
hit, however soon after insertion, earns a main slot. This is the classic
LRU-K / 2Q correlated-reference problem. Back-to-back accesses (such as
read-after-write or request bursts on web_0) look like reuse but are not
long-term reuse. Under reset-to-0 those promotions are exactly the never-re-hit
counter-0 residents that cycle 0007 found dominate main's victims. Each one
also displaces a real main resident. Requiring the reuse to be separated by
at least `small_len / 16` insertions filters them while keeping hm_0's
long-distance reuse, which by definition arrives later.

Refutation: if web_0 does not rise above 0.4182 @ 16384 or 0.5731 @ 131072,
early probation hits are not a meaningful share of wasted promotions. If hm_0
drops at either size by more than web_0 gains, short-gap reuse is real reuse
on hm_0, and the window should be dropped, not tuned.
