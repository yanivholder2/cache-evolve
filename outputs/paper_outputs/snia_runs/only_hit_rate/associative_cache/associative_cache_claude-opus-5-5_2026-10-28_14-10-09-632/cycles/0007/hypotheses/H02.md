# H02

Capping cycle 0006 v003's promotion sweep at one rotation of main, and evicting the hit probation item instead of a hot main block when that rotation finds no zero-counter slot, raises hit-rate on web_0 at 131072 by protecting main's established blocks under heavy promotion pressure.

## Parent

cycle/0006/v003

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0006/v003. Keep `GCLOCK_MAX = 7`, `probation_len`, the never-hit
probation eviction, and reset-to-0 on promotion. The plain-GCLOCK path
(`small_len == 0`) stays exactly as it is.

1. **Budgeted sweep** (the split-active branch of `put`, hit-in-probation
   case). Replace the unbounded `while self.items[hand].lfu_counter > 0` loop
   with a loop of at most `main_len = len - small_len` visits, starting at
   `main_hand()`:
   - if the visited slot's counter is 0, it is the victim `m`. Promote exactly
     as now: the promoted item gets counter 0 and goes into slot `m`, the new
     item takes slot `p`, `hand` moves to the slot after `m`, and the old
     occupant of `m` is returned as evicted;
   - otherwise decrement it by 1 and advance, wrapping from `len - 1` to
     `small_len`.

   If all `main_len` visits pass without finding a zero, the sweep has
   decremented every main slot once and the hand is back where it started.
   **Reject the promotion:** `std::mem::replace(&mut self.items[p], item)`,
   return the old probation item as evicted, and leave `self.hand` at the
   start position. `small_hand` has already advanced past `p`, as now.
2. **Prediction.** In `eviction_candidate_index`, split-active branch, when
   `items[sh].lfu_counter != 0`: scan the main region from `main_hand()` for
   the first slot with counter 0, wrapping. If one exists, return it.
   Otherwise return `sh`, the rejected probation item. Note that within one
   rotation the victim is the first *zero* from the hand, not the first
   minimum, because decremented slots are not revisited. Replace the
   `scan_min_from` call on this path with a helper `first_zero_from(lo,
   start) -> Option<usize>`. Keep `scan_min_from` for the plain path.
3. **Tests** (in `clock_tests`):
   - `candidate_matches_sweep` must pass for all existing cases. This is the
     key check that prediction and rejection agree.
   - `probation_hit_item_survives_into_main` must still pass. Main items 5..8
     have counter 0, so the promotion succeeds.
   - Add `hot_main_rejects_promotion`: in `bucket(8)`, fill the bucket, give
     every main slot a counter of at least 1, hit a probation item, then miss.
     Assert that the evicted key is that probation item, that every main
     counter fell by exactly 1, and that the prediction matched.
   - Add `rejection_is_temporary`: after a rejection, a second hit-in-probation
     promotion succeeds once some main counter reaches 0.

Invariants: those of v003. Metadata is unchanged. A promotion sweep now does
at most `main_len` visits instead of up to 7 × `main_len`, so worst-case
per-op-time falls (flag this for when per-op-time is measured).

## Rationale (optional)

Every hit-in-probation item currently gets into main, even when all of main is
hotter than it. The sweep then grinds hot blocks down, through as many as 7
rotations at the new ceiling, until one of them is evicted. On web_0, where
many blocks are hit once in probation and never again, that pushes out
established blocks. This is a TinyLFU-flavoured admission gate built from
existing state: promotion succeeds only if main already holds a cold
(counter-0) block within one pass. Each rejected attempt still ages main by
one step, so the gate opens again as main cools, and hm_0's genuine reuse
still gets in. It raises the bar for entering main only under pressure, which
is the opposite direction from the loosened admission refuted in cycle 0005.

Refutation: if web_0 at 131072 does not beat 0.5699, promotion pressure on hot
main blocks is not what limits web_0 there. If hm_0 at either size drops by
more than web_0 gains, rejected probation hits were real reuse and the
admission gate is too strict.
