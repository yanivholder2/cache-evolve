# H03

Raising cycle 0006 v003's small-bucket probation floor from 64 to 80 slots, with the large-bucket quarter fraction left unchanged, raises hit-rate on web_0 at 16384 now that the ceiling-7 main ranks its smaller region better.

## Parent

cycle/0006/v003

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0006/v003. This is the single fine-grained depth test between 64 and 96
that the cycle 0006 continuation allows. Nothing else changes: `GCLOCK_MAX = 7`,
reset-to-0 on promotion, the sweep, and the prediction.

1. **Sizing.** Set `const PROBATION_FLOOR: usize = 80;` and change the floor's
   cap from half the bucket to five-eighths of it. In `probation_len`:
   `(max_size / 4).max(PROBATION_FLOOR.min(max_size * 5 / 8)).max(1)` for
   `max_size >= 4`, and `0` below that. Update the doc comments to match.

   | `max_size` | old `small_len` | new `small_len` |
   | --- | --- | --- |
   | 8 | 4 | 5 |
   | 16 | 8 | 10 |
   | 64 | 32 | 40 |
   | 128 | 64 | 80 |
   | 1024 | 256 | 256 (unchanged) |

   `small_len < max_size` still holds for every `max_size >= 4`. Check this
   at 4, 5, 6 and 7 in particular, where `max_size * 5 / 8` can be 2, 3 or 4,
   and the main region must stay non-empty.
2. **Tests** (in `clock_tests`):
   - Update `probation_sizing_table` to the new table, keeping the loop that
     asserts `1 <= s < size` for 4..=4096, and assert
     `bucket(128).small_len == 80`.
   - `never_hit_item_evicted_after_small_len_misses` and
     `probation_hit_item_survives_into_main` hard-code `small_len == 4` for
     `bucket(8)`, which is now 5. Rewrite them to derive the expected keys
     from `b.small_len`, or move them to a size whose value is easy to work
     out (for example `bucket(16)` with 10) and recompute the expected
     evictions.
   - `candidate_matches_sweep` must pass for all sizes.

Invariants: those of v003. Metadata and per-op cost are unchanged, apart from
a smaller main region (48 slots) in 128-slot buckets.

## Rationale (optional)

Cycle 0006 bracketed depth from parents that used ceiling 3: 64 helped and 96
lost hm_0 at the small size. The ceiling-7 winner changed main's ranking
quality, which may move the best point. A frequency-ranked main that tells hot
from warm blocks apart better should hold hm_0's hot set in fewer slots, while
web_0's late second touches at 16384 gain 16 more misses of probation
lifetime. This is a bounded, cheap test of whether the depth optimum moved,
and it changes only the small-bucket cells (1024-slot buckets stay at 256),
so it does not overlap H01 or H02.

Refutation: if web_0 at 16384 does not beat 0.4178, the depth lever is
finished, as cycle 0006 suggested. If hm_0 at 16384 drops below 0.4529 by more
than web_0 gains, ceiling 7 did not make main more space-efficient, and the
floor should stay at 64 permanently.
