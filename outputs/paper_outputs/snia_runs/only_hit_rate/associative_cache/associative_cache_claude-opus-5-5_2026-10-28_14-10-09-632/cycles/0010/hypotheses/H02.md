# H02

Turning the probation FIFO into a CLOCK-style ring raises hm_0 hit-rate at both 16384 and 131072 without lowering web_0 below cycle 0009 v001's values: a counter-0 slot whose recent bit is set (it was touched only inside the correlated window) gets one extra probation lap instead of being evicted.

## Parent

cycle/0009/v001

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0009/v001. Keep main-region behaviour exactly as it is: `sweep_visit`,
`steps`, `halving`, `scan_min_from`, reset-to-0 and recent-clear on promotion.
Keep `probation_len`, `CRP_DIV` and `get_from_position`/existing-key `put`.
A correlated hit still sets `recent` without bumping. Do not edit
`Item` or `src/shared/`.

1. **New helper `probation_pick(&self) -> (usize, bool)`.** It is pure and does
   not mutate. Starting at `sh = small_hand` (clamped to 0 if out of range),
   walk at most `small_len + 1` probation slots, wrapping within
   `[0, small_len)`:
   - `lfu_counter > 0` → return `(idx, true)`. Promote this slot.
   - `lfu_counter == 0 && !recent[idx]` → return `(idx, false)`. Evict this slot.
   - `lfu_counter == 0 && recent[idx]` → skip it. In the mutating path the
     recent bit is cleared at this point.
   The walk always ends within `small_len + 1` steps, because a skipped slot
   ends the walk on its next visit.
2. **`put`, split-active branch.** Replace the single-slot test at
   `small_hand` with a mutating walk that follows the same rules. It clears
   `recent` on each skipped slot and stops at the first slot that should be
   promoted or evicted. Call that slot `p`. Set `small_hand = (p + 1) % small_len`.
   The evict branch and the promote branch (main sweep, `promoted.lfu_counter
   = 0`, recent and the new item taking `p`) are otherwise unchanged.
3. **`eviction_candidate_index`.** In split-active mode, call
   `probation_pick()`. If the result is `(p, false)`, return `Some(p)`.
   Otherwise return `Some(self.scan_min_from(self.small_len, self.main_hand()))`.
   This matches `put`, because a skipped slot does not change the main region.
4. **Probation age.** `probation_age` stays position-based relative to
   `small_hand`. A slot that is skipped once is treated as old on its second
   lap, so a hit then is not correlated. This is intended: a second touch after
   more than a full lap is real, separated reuse.
5. **Doc comment.** Describe the one-lap retention rule.
6. **Tests.** `correlated_probation_hit_not_promoted` currently expects X
   to be evicted within 64 inserts. Change it so X survives the first lap
   (assert that it is still in probation after 64 inserts, with `recent` cleared)
   and is evicted within the next 64 inserts if it gets no further hits. Add
   `retained_burst_item_promoted_on_late_hit`: after X's first lap, a single
   hit bumps its counter to 1, and X then moves to main. Re-check
   `never_hit_item_evicted_after_small_len_misses` and
   `probation_hit_item_survives_into_main`. They involve no recent-only slots,
   so they should pass unchanged. `candidate_matches_sweep` (all
   sizes and modes) must still pass. This is the exactness check for step 3.

Invariants: `items.len() == recent.len() <= max_size`; at most one eviction per
miss; `small_hand < max(min(small_len, len), 1)`. Extra cost on the probation
path: at most `small_len + 1` slot checks per miss, and usually one.

## Rationale (optional)

Probation depth for all items is closed (cycles 0006–0007), and ghost
admission is retired (0003, 0005). Both work on items that probation never
retains. This lever is narrower. It gives extra probation residency only to items
that showed some reuse, too close together to be trusted. Cycle 0009
v002 showed that hm_0 has real short-gap reuse that the correlated window
catches, and in 128-slot buckets that reuse is evicted immediately. One extra lap
lets that reuse show up again outside the window. The promotion gate
itself does not change: only a non-correlated hit bumps the counter. web_0's
burst-only blocks should therefore still be evicted, one lap later.

Refutation: the claim fails if hm_0 at 16384 does not beat 0.4549 or hm_0
at 131072 does not beat 0.7388. If either web_0 cell drops below v001
(0.4183 / 0.5846), the extra lap is costing web_0 cold slots, and the rule
should be limited to small buckets.
