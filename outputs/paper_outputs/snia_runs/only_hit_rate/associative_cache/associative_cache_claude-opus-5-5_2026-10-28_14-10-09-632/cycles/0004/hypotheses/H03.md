# H03

Splitting each probation hit in v002 so the first hit moves the item only to the bottom of the protected region, with MRU reserved for items hit again there, raises hit-rate by keeping one-hit web_0 blocks from flushing hm_0's long-reuse blocks out of protected space.

## Parent

cycle/0002/v002

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0002/v002. Leave insertion exactly as it is: probation insert at
`len / INSERT_FRACTION_DIV` and every 32nd new item at the MRU tail. Change
only the hit path, which today always moves to MRU through
`eviction_policy.get_from_position`.

1. Add `const PROTECT_FRACTION_DIV: usize = 2;`. The protected-region entry
   point is `entry = len / PROTECT_FRACTION_DIV`, which is above the probation
   point `len / 4`.
2. Override `get_from_position(position)` (also used by `put` on an existing
   key):
   - Let `len = items.len()` and `entry = len / PROTECT_FRACTION_DIV`.
   - **`position < entry`** (still in the lower half, i.e. probation or
     ageing): `let it = items.remove(position); items.insert(entry - 1, it);`
     Use `entry - 1` because the removal shifted the upper half down by one.
     Return that index. The item lands just below the midpoint, above every
     probation item, and every block above it, including all MRU samples and
     re-hit blocks, keeps its rank.
   - **`position >= entry`**, an item hit while already in the upper half:
     delegate to the existing ClassicLRU `eviction_policy.get_from_position`
     (move to MRU) and return its index.
   - **Small buckets (`len < 4`):** delegate to the policy unchanged, so
     edge-case tests keep their LRU behaviour.
3. No new per-item or per-bucket state. Do not touch `Item`, `evict_item`,
   or the insertion path.

Invariants: `items.len()` unchanged by a hit; unique keys; the returned
reference is the hit item, so return the index it now occupies; at most one
eviction, and only on a full-bucket miss. Add tests in the bucket file's own
test module:
- A probation hit lands at `len/2 - 1`.
- A second hit moves the item to `len - 1`.

Measure per-op-time. The mid-vector move costs at most the same memmove as
the existing MRU move.

## Rationale (optional)

This is the "graded promotion on top of cold insertion" revisit that the
cross-cycle notes held back until cold insertion existed. Cycle 0001 v002
failed because new items still entered at MRU. Now they enter at `len/4`.
Cycle 0003 showed that hm_0 needs a large, stable protected region and
web_0 needs probation to drain cold blocks. In v002, every first re-hit
(including web_0's short, once-only re-references) jumps to MRU and pushes
every protected block down one rank. With this change a block needs two
hits to reach the top, so the top half is kept for blocks that have been
reused more than once. This approach doesn't touch the probation/protected split itself
(unlike the cycle 0003 floor) or the sample rate (unlike H01), so it tests a
third lever.

Expected result: web_0 improves at both sizes, and hm_0@131072 holds or
improves. Refutation: hm_0@16384 drops below 0.4558, meaning one-hit reuse
there needs full MRU protection.
