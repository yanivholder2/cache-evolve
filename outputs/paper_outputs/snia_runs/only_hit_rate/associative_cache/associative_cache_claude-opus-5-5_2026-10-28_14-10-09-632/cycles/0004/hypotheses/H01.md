# H01

Steering v002's MRU-sample rate with a per-bucket PSEL fed by per-item tags stored in `lfu_counter`, which reward only sampled items hit after they would have left probation and penalise only sampled items evicted unhit, raises hit-rate by recovering web_0 at 131072 while keeping v002's hm_0 gain at 16384.

## Parent

cycle/0002/v002

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0002/v002 (cold insertion at `len / INSERT_FRACTION_DIV`, every 32nd new
item pushed at the MRU tail).

The feedback state lives on each item, so it covers the item's whole lifetime
in the bucket. That fixes the sizing failure of cycle 0003 v001's 8-entry
ring. The ClassicLRU lineage never uses `Item::lfu_counter`, so the tag goes
there and `Item` keeps its size. The implementer must check that
ClassicLRU's `get_from_position` / `EvictionPolicy` path does not write
`lfu_counter`. If it does, save the tag before the policy call and restore it
afterwards.

1. **Tag encoding** (helpers `fn tag(stamp: u32, ins: usize) -> usize`,
   `fn is_sampled(c) -> bool`, `fn stamp(c) -> u32`, `fn probe_len(c) -> usize`):
   - Bit 0 is the `sampled` flag. It is set only on items that BIP sends to
     the MRU tail.
   - Bits 1..=16 hold `ins`, the probation depth the item *would* have had
     (`len / INSERT_FRACTION_DIV` at admission), capped at 0xFFFF.
   - Bits 17..=48 hold the bucket's `miss_count: u32` at admission.
   - Probation-inserted items get `lfu_counter = 0` (not sampled).
2. **New bucket fields:** `miss_count: u32` (incremented once per new-item
   admission, replacing or alongside `insert_count`) and `psel: u8`, which
   starts at `PSEL_MAX / 2` with `PSEL_MAX = 15`.
3. **Sample period from PSEL**, computed in `put` instead of the fixed
   `BIMODAL_PERIOD`:
   - `psel <= 3` → no MRU sampling (pure LIP).
   - `4..=7` → period 128.
   - `8..=11` → period 32 (v002's rate).
   - `12..=15` → period 16.

   Sample when `miss_count % period == 0`.
4. **Hit path** (`put` on an existing key, and `get_from_position`): if the
   item `is_sampled`, compute `age = miss_count.wrapping_sub(stamp)`.
   - If `age > probe_len`, the hit is one cold insertion would have lost, so
     `psel = min(psel + 1, PSEL_MAX)`.
   - Either way, clear the tag (`lfu_counter = 0`) so each sample yields at
     most one signal. Short-reuse hits are therefore neutral, not rewarded.
     This fixes the miscalibration of cycle 0003 v001.

   Then do the normal ClassicLRU move to MRU.
5. **Eviction:** in the miss path, after `evict_item()` returns
   `Some(victim)`, if `is_sampled(victim.lfu_counter)` then
   `psel = psel.saturating_sub(1)`, because the sample used protected space
   for nothing. Clear the tag on the returned evicted item
   (`lfu_counter = 0`) so callers see a clean item.
6. When the period is "none", every new item goes to the `ins` position as in
   v001. Keep the `ins == 0 → push` rule.

Invariants: `items.len() <= max_size`; unique keys; the returned reference
is the inserted or hit item; at most one eviction, and only on a full-bucket
miss; `psel <= PSEL_MAX`. Add unit tests in the bucket file's own `#[cfg(test)]`
module:
- A sampled item hit after more than `ins` misses raises `psel`.
- A sampled item evicted unhit lowers it.
- A sampled item hit early leaves `psel` unchanged and clears the tag.

Measure per-op-time. The change adds O(1) work per op and no scans.

## Rationale (optional)

Cycles 0002 and 0003 established that MRU sampling helps hm_0 at 16384 and
hurts web_0 at 131072, and that a fixed rate can't serve both. Cycle 0003
v001 tried feedback, but its tracker forgot samples before they died, and it
rewarded hits that probation would have caught anyway. Here each sample
carries its own tag until it is either credited or evicted, so the negative
signal is never lost in 1024-slot buckets. Only the marginal benefit of MRU
placement is credited. Expected result: web_0@131072 buckets drift to
`psel <= 3` (pure LIP, approaching cycle 0002 v001's 0.5623), and hm_0@16384
buckets stay at period 32 or 16, keeping 0.4558 or better.
