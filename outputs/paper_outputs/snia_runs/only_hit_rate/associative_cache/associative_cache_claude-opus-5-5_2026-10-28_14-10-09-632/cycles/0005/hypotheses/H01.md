# H01

Adding a main-sized ghost ring of probation-evicted key fingerprints to cycle 0004 v002, so that a returning ghost key enters probation pre-marked for promotion, raises hit-rate mainly on web_0 at 16384 by catching second touches that arrive later than `small_len` misses.

## Parent

cycle/0004/v002

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0004/v002 (GCLOCK main region `[small_len, len)` with `hand`, a probation
FIFO `[0, small_len)` with `small_hand`, `GCLOCK_MAX = 3`, and `lfu_counter`
used as the reference counter). `small_len` stays at `max_size / 4`.

1. **Ghost state.** Add `ghost: Vec<u32>` (fingerprints), `ghost_cap: usize`
   and `ghost_pos: usize` to the struct.
   - Set `ghost_cap = max_size - small_len` (the main-region size: 96 slots in
     128-slot buckets, 768 in 1024-slot buckets), or `0` when `small_len == 0`.
   - The ghost is sized to the main region on purpose. In cycle 0003 the ghost
     ring was undersized and lost the signal. S3-FIFO sizes its ghost to main.
   - Fingerprint: hash the key with `std::collections::hash_map::DefaultHasher`
     and take the low 32 bits. Map `0` to `1`, because `0` is reserved for
     "empty".
   - Pre-allocate the ghost lazily as `vec![0u32; ghost_cap]` on first use, so
     buckets that never fill pay nothing.
2. **Record.** In `put`, on the full-bucket path where the probation item at
   `p` has `lfu_counter == 0` and is evicted, write its fingerprint at
   `ghost[ghost_pos]` and set `ghost_pos = (ghost_pos + 1) % ghost_cap`. Do not
   record main-region evictions, or removals through `evict_item` / `remove_at`.
3. **Consult.** In `put`, on a miss for a new key and before placing the new
   item, linearly scan `ghost` for the key's fingerprint.
   - If found, set that ghost entry to `0` and give the new item
     `lfu_counter = 1` instead of `0`. It still enters the probation slot `p`,
     or is pushed during fill-up, exactly as in v002. Because its counter is
     non-zero, it will be promoted when `small_hand` next reaches it, unless
     it is hit first.
   - If not found, the behaviour is unchanged (`lfu_counter = 0`).
   - Do the lookup before the probation item at `p` is recorded, so a key
     cannot match its own eviction.
4. **Victim choice is unchanged.** On this miss the victim is still chosen
   from `items[small_hand]` and the main sweep, exactly as in v002. So
   `eviction_candidate_index` needs no change and stays exact, and
   `candidate_matches_sweep` must still pass.
5. **Tests** (in the file's own `clock_tests`):
   - A key evicted from probation unhit and then re-inserted while still in
     the ghost is promoted into main on the next `small_hand` pass, without a
     hit.
   - A key that has fallen out of the ghost (more than `ghost_cap` probation
     evictions later) is evicted from probation as before.
   - A ghost entry is cleared once it matches.

Invariants: `items.len() <= max_size`; at most one eviction per miss;
`lfu_counter <= GCLOCK_MAX`; both hands in bounds; no per-`Item` fields
added. Metadata cost is 4 bytes × `ghost_cap` per bucket. The per-op cost is
one linear ghost scan per miss (up to 768 u32 compares at the large size).
Report per-op-time.

## Rationale (optional)

v002's open gap is web_0 at 16384. There, the second touch of many blocks
arrives after the block has spent its 32 misses in probation and been thrown
away as one-touch. A ghost that covers a main region's worth of probation
evictions remembers them long enough. Marking the returning item with
counter 1 is a CLOCK-native form of S3-FIFO's "ghost hit → insert into
main". Victim selection on the miss is untouched, so the
predicted-candidate contract holds. Scan blocks never return, so their ghost
entries cost nothing, and large-bucket filtering on web_0 should be kept.

Refutation: if web_0 at 16384 does not beat v002's 0.4159 by at least 0.003,
ghost admission does not pay off even at main-sized coverage. Retire it.
