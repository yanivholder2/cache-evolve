# H02

Making v001's cold insertion bimodal, so that every 32nd new item in a bucket is inserted at the MRU tail and all others at `len/4`, raises hit-rate by letting part of each long-reuse-distance working set survive past the probation window.

## Parent

cycle/0001/v001

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
v001's version.

1. Add a field `insert_count: u32` to `AssociativeCacheBucket` and initialise
   it to 0 in `new`. This is per-bucket state, not per-item, so `Item` keeps
   its size. Add `const BIMODAL_PERIOD: u32 = 32;`. Keep
   `INSERT_FRACTION_DIV = 4`.
2. In the miss path of v001's `Bucket::put` override, after the optional
   `evict_item()`:
   - `self.insert_count = self.insert_count.wrapping_add(1);`
   - If `self.insert_count % BIMODAL_PERIOD == 0`, `push` the item at the MRU
     tail and return index `len - 1`. This is the BIP "occasional MRU insert".
   - Otherwise keep v001's behaviour: `ins = len / INSERT_FRACTION_DIV`, then
     `insert(ins, item)`, or `push` when `ins == 0`.
   Use a deterministic counter, not an RNG, so runs are reproducible and no
   new crate dependency is needed.
3. Leave the hit / update-existing path unchanged: move to MRU through
   `get_from_position`.

Invariants: `items.len() <= max_size`; no duplicate keys; the returned
reference points at the inserted item; an evicted item is returned only on a
full-bucket miss. Do not touch `Item`, the eviction policy, or any protected
file.

## Rationale (optional)

This is Qureshi et al.'s bimodal insertion (BIP) applied on top of the LIP
point that won cycle 0001. Pure cold insertion cannot keep any part of a
working set whose reuse distance is longer than the probation window. That is
the 16384 loss described in the v001 insight. Sending 1/32 of new items to
MRU gives a slowly changing sample of those blocks a full bucket lifetime, so
they can be hit and become protected. Scans still mostly drain through
probation. The mechanism is different from H01: H01 deepens probation for
every item, while this keeps probation as it is and sends a small sample of
items past it.
