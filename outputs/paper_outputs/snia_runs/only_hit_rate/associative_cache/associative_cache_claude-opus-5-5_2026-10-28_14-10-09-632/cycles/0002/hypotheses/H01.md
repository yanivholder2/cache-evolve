# H01

Giving every new item a probation window of at least 64 slots, by inserting at `max(len/4, min(len/2, 64))` instead of a flat `len/4`, raises hit-rate at cache size 16384 and keeps v001's gain at 131072.

## Parent

cycle/0001/v001

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, in v001's
`Bucket::put` override of `impl Bucket<K, V> for AssociativeCacheBucket<K, V>`.

- Replace `const INSERT_FRACTION_DIV: usize = 4;` with three constants:
  `INSERT_FRACTION_DIV: usize = 4`, `MIN_PROBATION_SLOTS: usize = 64`, and
  `MAX_PROBATION_FRACTION_DIV: usize = 2`.
- Add a private helper `fn insertion_index(len: usize) -> usize` that returns
  `max(len / INSERT_FRACTION_DIV, min(len / MAX_PROBATION_FRACTION_DIV, MIN_PROBATION_SLOTS))`.
  Concrete values after eviction:
  - 127-slot full bucket (size 16384): returns 63, so the probation depth
    doubles from about 32 to about 63.
  - 1023-slot full bucket (size 131072): returns `max(255, 64) = 255`, the
    same as v001.
  - Small or test-sized buckets, e.g. len 3: returns `max(0, min(1, 64)) = 1`.
    Keep v001's rule that `ins == 0` means `push` at the tail, so empty and
    one-item buckets behave as before.
- In the miss path, call `evict_item()` first when the bucket is full,
  exactly as v001 does. Then compute `ins = insertion_index(self.items.len())`
  and use `self.items.insert(ins, item)`, or `push` when `ins == 0`.
- Leave the update-existing / hit path unchanged: overwrite the value, then
  `get_from_position`, which is ClassicLRU's move to MRU.

Invariants: `items.len() <= max_size`; no duplicate keys; the returned
reference points at the inserted item; an evicted item is returned only on a
full-bucket miss. Do not change `Item`, the eviction policy, or the geometry.

## Rationale (optional)

The v001 insight puts the loss at 16384 on the ~32-slot probation window: a
real second reference often arrives after the item has already been evicted.
A floor on probation depth, measured in slots and not as a fraction, lets
small buckets keep that reuse. Large buckets keep the len/4 point, which is
where v001 got its biggest win. The experiment can be checked one cell at a
time: hit-rate should rise at 16384 on web_0 and hm_0, and 131072 should be
unchanged or within noise.
