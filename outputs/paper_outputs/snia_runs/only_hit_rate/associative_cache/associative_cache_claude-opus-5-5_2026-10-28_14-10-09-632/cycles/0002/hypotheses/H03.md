# H03

Replacing v003's 1-bit CLOCK reference flag with a GCLOCK saturating counter (hits increment `lfu_counter` up to 3, the sweep decrements it, new items start at 0) raises hit-rate by protecting frequently reused blocks from one-touch scan blocks.

## Parent

cycle/0001/v003

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
v003's in-place CLOCK version, which has the `hand: usize` field and uses
`Item::lfu_counter` as the reference bit.

1. Add `const GCLOCK_MAX: <type of lfu_counter> = 3;`.
2. `get_from_position(position)`: in place of `lfu_counter = 1`, set
   `lfu_counter = min(lfu_counter + 1, GCLOCK_MAX)`, using saturating
   arithmetic. Do not reorder; return `&self.items[position]`.
3. `put`, existing key: overwrite the value and apply the same saturating
   increment.
4. `put`, miss on a not-full bucket: `push` with `lfu_counter = 0`, as now.
5. `put`, miss on a full bucket: change the sweep to
   `while items[hand].lfu_counter > 0 { items[hand].lfu_counter -= 1; hand = (hand + 1) % len; }`.
   The loop always ends within `GCLOCK_MAX` rotations, because each pass
   decrements every counter. Then `std::mem::replace` the victim at `hand`
   with the new item (`lfu_counter = 0`), advance `hand`, and return
   `(&items[victim_idx], Some(evicted))`, as v003 already does.
6. `eviction_candidate_index`: without mutating anything, return the index
   with the minimum `lfu_counter`, scanning from `hand` and breaking ties by
   distance from `hand`. With counters this is the slot the decrementing sweep
   would reach first at 0. `evict_item` keeps v003's `remove_at` and `hand`
   fix-up logic, applied to that index.

Invariants: `items.len() <= max_size`; unique keys; `hand < max(len, 1)`;
`lfu_counter <= GCLOCK_MAX`; an eviction is returned only on a full-bucket
miss. `Item` keeps its size, because no new per-item field is added.

## Rationale (optional)

v003 showed that coarse recency keeps hit-rate (0.530 against the baseline's
0.527) and removes all memmoves. Cycle 0001 found that the winning lever is
ranking reused items above new ones. With a 1-bit flag, a block that is hit
once and a block that is hit many times look the same after one sweep. A
2-bit counter lets frequently reused blocks survive up to 3 more sweeps, while
new blocks (counter 0) are the first victims. That gives a frequency-aware,
scan-resistant ranking without v001's O(n) mid-vector insert. Per-op-time
should also be watched: if this matches v001 on hit-rate, it does so with no
element shifting.
