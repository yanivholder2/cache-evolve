# H01

Inserting newly admitted items at the bucket's 25% position instead of its MRU tail makes each bucket scan-resistant and raises MSR hit-rate.

## Parent

baseline

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`. Override the
`Bucket::put` default method in `impl Bucket<K, V> for AssociativeCacheBucket<K, V>`.

- **Update-existing path:** keep this the same as the trait default. Find the
  key with `get_position`, overwrite `value`, then call
  `self.get_from_position(position)`. This keeps the ClassicLRU behaviour of
  moving a hit item to the back (MRU).
- **Miss/insert path:** if the bucket is full, call `self.evict_item()` first.
  ClassicLRU still evicts index 0 (LRU end). Then, instead of `push`, insert
  the new item at `ins = self.items.len() / 4`, computed after the eviction,
  using `self.items.insert(ins, item)`. If `items.len() < 4` (`ins == 0`),
  insert at the back (`push`) so tiny or empty buckets behave as before.
  Return `(&self.items[ins_or_last], evicted)`.

This is an LRU-insertion-point (LIP/SLRU-like) scheme. A new block must be hit
again before it falls the last ~25% of the bucket to the LRU end. Hit items
jump to MRU and are protected. One-touch scan blocks, which are common in
`web_0`/`hm_0` block I/O, are evicted quickly and do not flush the reused
working set.

Invariants to preserve:
- `items.len() <= max_size`
- No duplicate keys
- The returned reference is the inserted item
- The evicted item is returned exactly when the bucket was full on a miss

Do not change `Item`, `EvictionPolicy`, geometry, or any protected file. Make
the fraction a `const INSERT_FRACTION_DIV: usize = 4;` so later cycles can tune
it.

## Rationale (optional)

Per-bucket capacity here is large: 16384/128 = 128 slots and 131072/128 = 1024
slots. That makes each bucket behave like a small global LRU, and MSR traces
are known to punish LRU with sequential scans. Get cost is unchanged; insert
cost stays O(n) memmove like the baseline's eviction `remove(0)`.
