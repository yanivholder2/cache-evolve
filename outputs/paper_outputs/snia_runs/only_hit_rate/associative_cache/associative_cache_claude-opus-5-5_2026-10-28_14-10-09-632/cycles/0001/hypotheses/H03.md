# H03

Replacing ClassicLRU's per-hit `remove`+`push` reordering with an in-place CLOCK (second-chance) scheme, where hits only set a reference bit and items never move, lowers get/put per-op-time.

## Parent

baseline

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`.

1. Add a field `hand: usize` to `AssociativeCacheBucket` and initialise it to
   0 in `new`. Use the existing `Item::lfu_counter` field as the reference bit
   (0 or 1), so `Item` stays the same size and the metadata-size dimension
   does not change.
2. Override `get_from_position(&mut self, position)` so that it sets
   `self.items[position].lfu_counter = 1` and returns
   `&self.items[position]`. It must not call into the policy and must not
   reorder the vector. Hit cost becomes the linear key scan plus one store,
   with no O(n) memmove.
3. Override `Bucket::put`:
   - **Existing key:** overwrite the value and set the reference bit, with no
     movement.
   - **Not full:** `push` the new item with `lfu_counter = 0`.
   - **Full:** run the CLOCK sweep. While `items[hand].lfu_counter == 1`,
     clear it and advance `hand = (hand + 1) % len`. The sweep finishes within
     at most one full rotation. Then replace the victim in place using
     `std::mem::replace(&mut self.items[hand], item)`, which gives the evicted
     item. Advance `hand` by one modulo `len`, and return
     `(&self.items[victim_idx], Some(evicted))`. Do not use `Vec::remove` or
     `insert`.
4. Override `eviction_candidate_index` so it returns the index the CLOCK sweep
   would pick, without mutating anything: scan from `hand` for the first item
   with bit 0, or return `hand` if every bit is 1. Also override `evict_item`
   so external callers, such as gate tests, see a consistent eviction: use
   `remove_at` on that index and fix up `hand` (decrement it if it was past
   the removed index, then clamp it to `len`).

Invariants:
- `items.len() <= max_size`
- Keys are unique
- `hand < max(len, 1)`
- An eviction is returned only on a full-bucket miss

## Rationale (optional)

The baseline get p50 is 55 ns and put p50 is 106 ns. On 128- and 1024-slot
buckets of 40-byte items, most of that time is the `Vec::remove` + `push`
memmove (up to ~40 KB) on every hit and on every eviction (`remove(0)`). CLOCK
removes all element shifting, and its hit-rate is usually within a point or
two of LRU, so this variant trades very little hit-rate for a large per-op-time
cut.
