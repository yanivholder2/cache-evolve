# H02

Widening the correlated-reference window in 128-slot buckets from 4 to an absolute 16 probation insertions (the same width that won at 1024 slots) raises hit-rate on web_0 at 16384, because it filters burst-only promotions there too.

## Parent

cycle/0008/v003

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
cycle/0008/v003. Keep the main region, sweep rule (recent bit, then halving),
`steps`, `scan_min_from`, `GCLOCK_MAX = 7`, `probation_len`, the probation
test and **reset-to-0 on promotion** exactly as they are. Only the width of
the correlated-reference window changes.

1. **Constants.** Keep `CRP_DIV = 16`. Add `const CRP_MIN_WINDOW: usize = 16;`
   and `const CRP_FLOOR_MIN_SMALL: usize = 64;`. The floor applies only when
   the probation ring has at least 64 slots, so tiny buckets keep their
   current behaviour.
2. **Cached window.** Add a field `crp_window: usize` to
   `AssociativeCacheBucket`. In `new`, compute
   `let w = small_len / CRP_DIV;` and then
   `crp_window = if small_len >= CRP_FLOOR_MIN_SMALL { w.max(CRP_MIN_WINDOW.min(small_len / 2)) } else { w };`.
   With the evaluated sizes this gives `small_len = 64` → 16 (was 4) and
   `small_len = 256` → 16 (unchanged). Buckets of size 8 or 16 (small_len 4
   or 8) get 0 as before.
3. **Filter.** In `is_correlated_probation_hit`, replace
   `self.small_len / CRP_DIV` with `self.crp_window`. Do not change
   `probation_age`, or the no-bump/recent-set behaviour in
   `get_from_position` and `put`'s existing-key branch.
4. **Doc comments.** Update the struct doc and the `CRP_DIV` comment to say
   the window is `max(small_len / 16, 16)` once probation has at least 64
   slots.
5. **Tests (`clock_tests`).**
   - Add `crp_window_sizing`. Assert that `bucket(8).crp_window == 0`,
     `bucket(16).crp_window == 0`, `bucket(128).crp_window == 16` and
     `bucket(1024).crp_window == 16`.
   - `late_probation_hit_promoted`: age 10 is now inside the 16-slot window.
     Change the setup to 20 intervening misses (loop `0..20`, then `20..64`),
     and assert `probation_age(px) == 20` and that X is promoted with
     counter 0.
   - Add `mid_window_hit_not_promoted`. In `bucket(128)`, insert X, run 12
     distinct misses (age 12 < 16), `get(X)`, and assert the counter is still
     0. Then run the remaining misses and assert X is evicted and never
     reaches main.
   - `correlated_probation_hit_not_promoted`, `candidate_matches_sweep` and
     the size ≤ 8 tests must pass unchanged.

Invariants: no new per-slot state, the hit path stays O(1), and
`eviction_candidate_index` stays exact because it reads only counters.
1024-slot buckets must be bit-identical to v003.

## Rationale (optional)

v003's insight shows the filter's effect scales with the window's absolute
width. At 16 slots it gave the lineage's largest single-cell gain (web_0 at
131072 rose from 0.5731 to 0.5846) and also nudged hm_0 up. At 4 slots, in
128-slot buckets, it caught almost none of a burst's later hits, and web_0 at
16384 was flat to slightly down (0.4178). Bursts are measured in requests to
a bucket, not in fractions of the ring, so the window should be an absolute
width. 16 slots is still only a quarter of the 64-slot probation ring, so
re-references at reuse distance 16–64 still promote.

Refutation: if web_0 at 16384 does not rise above 0.4185 (the best small-size
web_0 in cycle 0008), bursts are not what limits small-bucket web_0. If hm_0
at 16384 drops below 0.4525, short-gap reuse in small buckets is real reuse,
and the window should be narrowed (for example to 8) rather than dropped. The
131072 cells must equal v003's (0.5846 and 0.7388).
