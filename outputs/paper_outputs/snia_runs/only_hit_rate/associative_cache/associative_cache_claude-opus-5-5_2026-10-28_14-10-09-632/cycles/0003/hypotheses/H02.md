# H02

Adding a per-bucket ghost ring of recently evicted keys to v003's GCLOCK, so that a missed key found in the ghost ring is admitted with counter 1 instead of 0, raises hit-rate in the 16384 cells by protecting blocks whose reuse distance exceeds one hand rotation.

## Parent

cycle/0002/v003

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
v003's GCLOCK version. Keep `GCLOCK_MAX = 3`, `gclock_bump`, the hit path
(`get_from_position` and the update-existing branch), and the sweep loop.

1. Add per-bucket fields, initialised in `new`: `ghost: Vec<K>` with capacity
   `ghost_cap`, `ghost_next: usize = 0`, and
   `ghost_cap: usize = max(1, settings.bucket_size / GHOST_DIV)`, where
   `const GHOST_DIV: usize = 2`. That gives 64 ghost keys per 128-slot bucket
   and 512 per 1024-slot bucket. `ghost` is a ring: while
   `ghost.len() < ghost_cap`, `push`; after that, overwrite `ghost[ghost_next]`.
   Either way, advance `ghost_next = (ghost_next + 1) % ghost_cap`. Store only
   keys, not values or `Item`s.
2. Add a private helper `fn ghost_take(&mut self, key: &K) -> bool`. It scans
   `ghost` linearly. On a match it removes that key so it can't be credited
   twice: write a key that can't collide, or do a `swap_remove` and repair
   `ghost_next` so it stays `< ghost_cap` and `<= ghost.len()`. Return whether
   it matched. The scan only runs on misses, which already pay for a sweep.
3. Add a private helper `fn ghost_record(&mut self, key: K)` that implements
   the ring write from step 1.
4. In `put`, on any miss (both the not-full branch and the full branch),
   compute `let warm = self.ghost_take(&item.key);` before inserting. Set the
   new item's `lfu_counter = if warm { 1 } else { 0 }`. Everything else in the
   not-full branch stays the same.
5. Full branch: after the sweep chooses `victim_idx` and `std::mem::replace`
   yields `evicted`, call `ghost_record(evicted.key)`. Also call
   `ghost_record` on the key evicted in `evict_item()`.
6. `eviction_candidate_index` needs no change, because it already selects by
   minimum counter from `hand`. A warm item with counter 1 is handled
   correctly. The `candidate_matches_sweep` test must still pass.

Invariants: `items.len() <= max_size`; unique keys in `items`; a key in
`items` is never in `ghost`. This holds because `ghost_take` runs on every
admission, and `ghost_record` runs only with keys that have just been evicted.
Also: `lfu_counter <= GCLOCK_MAX`; `hand < max(len, 1)`;
`ghost.len() <= ghost_cap`. `Item` keeps its size. The added state is
per-bucket metadata only.

## Rationale (optional)

GCLOCK is the lineage whose advantage grows with bucket size. Its weak cells
are the 16384 ones (hm_0 0.4396, web_0 0.4161), where a one-touch admission at
counter 0 is evicted after a single short rotation. A block that comes back
soon after eviction has proven that it has reuse. Scan blocks almost never
come back within `len/2` evictions, so the ghost credit is scan-resistant by
construction, and it avoids v002's web_0 pollution problem. This is the
"cold-insertion analogue" asked for in the cycle 0002 insight. It ranks
proven-but-evicted blocks above brand-new ones without any element shifting.
Expected result: gains at 16384 on both traces, larger on hm_0, and 131072
flat or slightly up.
