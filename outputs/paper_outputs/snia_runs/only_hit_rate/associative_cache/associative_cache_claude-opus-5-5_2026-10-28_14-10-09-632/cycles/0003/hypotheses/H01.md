# H01

Replacing v002's fixed 1-in-32 MRU insertion with a per-bucket feedback counter, which raises the MRU-insert rate when MRU-sampled items get re-hit and lowers it when they are evicted untouched, raises hit-rate by keeping v002's hm_0 gain and removing its web_0 loss.

## Parent

cycle/0002/v002

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
v002's version. Keep `INSERT_FRACTION_DIV = 4` and the hit / update-existing
path (`get_from_position` → policy move to MRU).

1. Remove `const BIMODAL_PERIOD`. Add the constants
   `PSEL_MAX: u8 = 15`, `PSEL_INIT: u8 = 8`, `PSEL_THRESHOLD: u8 = 8`,
   `PERIOD_BIP: u32 = 16` (used while MRU sampling is paying off) and
   `PERIOD_LIP: u32 = 128` (used while it is not; it stays non-zero so the
   bucket can keep learning), and `SAMPLE_SLOTS: usize = 8`.
2. Add these per-bucket fields (initialised in `new`): `psel: u8 = PSEL_INIT`,
   `sampled: [Option<K>; SAMPLE_SLOTS] = [None; SAMPLE_SLOTS]` (K is `Copy`), and
   `sample_next: usize = 0` (ring write cursor). Keep `insert_count`. Add no
   per-item state, so `Item` keeps its size.
3. Add a private helper `fn take_sampled(&mut self, key: &K) -> bool`. It
   scans `sampled` linearly. On a match it sets that slot to `None` and returns
   true; otherwise it returns false.
4. Miss path in `put`:
   - Call `evict_item()` first when the bucket is full, as now. If an item was
     evicted and `take_sampled(&evicted.key)` is true, do
     `psel = psel.saturating_sub(1)`: an MRU-sampled item died without reuse.
   - `insert_count = insert_count.wrapping_add(1)`. Set
     `period = if psel >= PSEL_THRESHOLD { PERIOD_BIP } else { PERIOD_LIP }`.
   - If `insert_count % period == 0`, push the item at the MRU tail, write its
     key into `sampled[sample_next]` (overwriting the old slot), and advance
     `sample_next = (sample_next + 1) % SAMPLE_SLOTS`. Otherwise use v002's
     `len / INSERT_FRACTION_DIV` insert, or `push` when that is 0.
5. Hit paths: in `get_from_position`, before delegating to the policy, read
   `self.items[position].key`. If `take_sampled(&key)` is true, do
   `psel = min(psel + 1, PSEL_MAX)`: an MRU-sampled item was reused. Do the same
   in the update-existing branch of `put`. That branch already calls
   `get_from_position`, so do the check only once, inside `get_from_position`.

Invariants: `items.len() <= max_size`; unique keys; `psel <= PSEL_MAX`; the
returned reference points at the inserted item; an eviction is returned only
on a full-bucket miss. The behaviour stays deterministic, with no RNG and no
new crates. Don't touch `Item`, the eviction policy, or any protected file.

## Rationale (optional)

v002's insight shows a clean split. MRU-sampled items on hm_0 (at 16384) get
re-hit and pay off. On web_0 they are one-touch blocks that pollute the
protected region. This is the per-bucket analogue of DIP's PSEL: it scores
BIP directly by what happens to the items BIP chose. Buckets fed by
scan-like traffic will drift to `PERIOD_LIP`, close to v001 behaviour, which
was best on web_0. Buckets with long reuse distances will go to
`PERIOD_BIP`, which samples more aggressively than v002. The claim is
falsified if web_0 stays below cycle/0001/v001 or if hm_0 at 16384 falls
below v002's 0.4558.
