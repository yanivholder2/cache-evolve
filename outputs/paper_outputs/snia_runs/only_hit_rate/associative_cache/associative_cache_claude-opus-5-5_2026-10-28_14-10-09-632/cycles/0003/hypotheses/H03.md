# H03

Adding cycle 0002 v001's 64-slot absolute probation floor to v002's bimodal cold insertion raises hit-rate at size 16384 on both traces, because the two mechanisms recover different reuse: medium-distance reuse from the floor and long-distance reuse from MRU sampling.

## Parent

cycle/0002/v002

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`, starting from
v002's version. Keep `BIMODAL_PERIOD = 32`, the `insert_count` field, and the
hit / update-existing path unchanged.

1. Add `const MIN_PROBATION_SLOTS: usize = 64;` and
   `const MAX_PROBATION_FRACTION_DIV: usize = 2;`, and keep
   `INSERT_FRACTION_DIV = 4`.
2. Add a private free function `fn insertion_index(len: usize) -> usize` that
   returns
   `max(len / INSERT_FRACTION_DIV, min(len / MAX_PROBATION_FRACTION_DIV, MIN_PROBATION_SLOTS))`.
   For a 127-slot bucket after eviction it returns 63; for a 1023-slot bucket
   it returns 255, the same as v002; for len 3 it returns 1.
3. In the non-MRU branch of `put`'s miss path, replace
   `let ins = self.items.len() / INSERT_FRACTION_DIV;` with
   `let ins = insertion_index(self.items.len());`. Keep the rule that
   `ins == 0` means `push`. The `insert_count % BIMODAL_PERIOD == 0` MRU branch
   stays as it is.
4. Call `evict_item()` before computing `ins`, as now, so `len` is the
   post-eviction length.

Invariants: `items.len() <= max_size`; `ins <= items.len()`; no duplicate
keys; the returned reference points at the inserted item; an eviction is
returned only on a full-bucket miss. Do not touch `Item`, the eviction policy,
or any protected file.

## Rationale (optional)

Cycle 0002 asked directly whether the floor and occasional MRU insertion stack
or recover the same reuse. Each one beat its parent at 16384 independently:
v001 scored hm_0 0.4473 and web_0 0.4165, and v002 scored hm_0 0.4558 and
web_0 0.4137. The floor helped web_0 at 16384, where BIP did not. If the gains
are additive, hm_0 at 16384 should exceed 0.4558, web_0 at 16384 should
recover to about 0.416, and 131072 should match v002, since the floor is
inactive in 1024-slot buckets. If hm_0 does not exceed v002, the two
mechanisms overlap and the floor is redundant with sampling. This is a single
controlled change, so the result can be attributed cleanly. It is also
distinct from H01, which keeps v002's fixed insertion depth and adapts only
the sampling rate.
