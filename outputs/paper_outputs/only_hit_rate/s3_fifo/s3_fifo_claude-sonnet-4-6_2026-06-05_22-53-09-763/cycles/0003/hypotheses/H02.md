# H02

Lowering the small-to-main promotion threshold from `freq > 1` to `freq > 0` in v003's configuration raises hit rate by promoting once-accessed items directly to main, with v003's tighter ghost guard compensating for the wider admission gate.

## Parent

cycle/0002/v003

## Changes

In `src/s3_fifo/mod.rs`, inside `evict_small()`, change the promotion condition from:

```rust
if tail.freq > 1 {
```

to:

```rust
if tail.freq > 0 {
```

This is the only edit. All other v003 settings remain unchanged: `small_size = capacity / 10`, `ghost_size = (main_size / 2).max(1)`, the ghost overflow guard using `self.ghost_size`, and `MAX_FREQ = 3`. The `evict_main()` second-chance loop and the ghost-hit re-admission path in `put()` are untouched.

Under the new threshold, any small-queue item that has been accessed at least once (freq ≥ 1) is promoted to main on eviction; only completely cold items (freq = 0) are ghosted. The ghost queue therefore receives only items with zero accesses, sharpening the ghost signal: every future ghost hit corresponds to a key that was evicted cold but has now been re-requested, which is a stronger re-use signal than the current policy allows (which also ghosts freq=1 items).

## Rationale

This threshold was tried in cycle 0001 on the baseline configuration (large small queue, full-size ghost) and degraded performance because second-chance eviction could not shed the wave of lower-quality promotions fast enough. The conditions in v003 are materially different: (1) the small queue is only 10% of capacity, limiting the volume of newly promoted items per eviction cycle; (2) the ghost cap is halved, so ghost-hit promotions are already high-precision. The cycle 0002 insight explicitly flagged `freq > 0` as the secondary axis worth opening now that ghost precision is in place. The hypothesis is that the two guards together — a narrow small queue and a tight ghost window — absorb the wider admission without flooding main.
