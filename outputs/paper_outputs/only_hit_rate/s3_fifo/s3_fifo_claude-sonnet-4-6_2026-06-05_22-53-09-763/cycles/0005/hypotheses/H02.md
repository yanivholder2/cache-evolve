# H02

Replacing the move-to-front eviction reprieve in `evict_main()` with an in-place backward frequency-decrement scan will improve hit rate by preserving FIFO temporal order among main-queue survivors and preventing high-freq items from repeatedly jumping to the head of the queue.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, replace the entire body of `evict_main()`. The current implementation pops from the tail and pushes surviving items (freq > 0, decremented) back to the front, which repositions hot items away from eviction pressure. The new implementation decrements frequencies in-place and removes the first zero-freq item found scanning backward from the tail, preserving each item's FIFO position:

```rust
fn evict_main(&mut self) {
    for i in (0..self.main.len()).rev() {
        if self.main[i].freq == 0 {
            self.main.remove(i);
            return;
        } else {
            self.main[i].freq -= 1;
        }
    }
    // Every item had freq >= 1 and has been decremented by one pass;
    // at least one is now 0. Recurse once to find and remove it.
    self.evict_main();
}
```

`VecDeque::remove(i)` is available in std and is O(n); that is acceptable. All other logic is unchanged: `evict_small()` promotion threshold (`freq > 1`), `ghost_size`, `small_size`, `MAX_FREQ`, and the `get()` saturation logic all remain as in baseline.

## Rationale

The current FIFO-with-front-promotion scheme allows items with accumulated freq to cycle to the head indefinitely, which is effective but couples temporal recency and frequency into a single positional ordering. The CLOCK-style in-place scan decouples them: items are evicted in their original FIFO order among items at the same freq tier, letting temporal eviction pressure fall on the oldest cold items rather than creating a freq-sorted heap at the front. Whether this matches the workload's re-use structure better than the current scheme is an open empirical question.
