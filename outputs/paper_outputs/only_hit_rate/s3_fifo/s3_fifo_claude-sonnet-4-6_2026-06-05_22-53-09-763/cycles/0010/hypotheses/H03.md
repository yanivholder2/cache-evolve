# H03

Feeding the ghost queue from main-queue evictions rather than small-queue evictions will improve hit rate by using the ghost as a "recently-proven-resident" bypass signal instead of a "twice-seen cold-item" bypass signal.

## Parent

baseline

## Changes

The baseline ghost queue is populated in `evict_small()` — items rejected by the cold filter (freq <= 1 in small) are pushed to ghost. The hypothesis is that items which actually resided in main are more valuable to track for fast re-admission than items that merely appeared twice in the cold-admission queue.

**1. Stop pushing small-queue evictions to ghost.**

In `evict_small()`, remove the ghost-tracking branch for evicted cold items. The `else` arm becomes a plain no-op (item is discarded):

```rust
fn evict_small(&mut self) {
    if let Some(tail) = self.small.pop_back() {
        if tail.freq > 1 {
            if self.main.len() >= self.main_size {
                self.evict_main();
            }
            self.main.push_front(tail);
        }
        // cold items (freq <= 1) are simply dropped; ghost no longer
        // tracks small-queue rejections.
    }
}
```

**2. Push main-queue evictions to ghost.**

In `evict_main()`, after the `break` (the item whose freq <= 1 is truly evicted), record its key in the ghost queue using the same bounds logic:

```rust
fn evict_main(&mut self) {
    while let Some(mut tail) = self.main.pop_back() {
        if tail.freq > 1 {
            tail.freq -= 1;
            self.main.push_front(tail);
        } else {
            // Record the evicted key in ghost so a subsequent put() re-admits
            // it directly to main front, bypassing the cold filter.
            if self.ghost.len() >= self.ghost_size {
                self.ghost.pop_back();
            }
            self.ghost.push_front(tail.key);
            break;
        }
    }
}
```

**3. `put()` ghost-hit path is unchanged.**

Ghost hits still remove the key from ghost and admit the new entry directly to the front of main at freq=0. No change to that branch.

**4. Update the block-comment header** to document that ghost now tracks main-queue evictions rather than small-queue evictions, and update or add a test `ghost_hit_promotes_back_to_main` that exercises the new feeding path (put an item, promote it to main via eager-promotion, fill main until the item is evicted to ghost, then re-put it and assert it lands in main).

All other logic (MAX_FREQ = 3 from baseline, `evict_main()` threshold `freq > 1`, eager-promotion threshold `freq >= 2`, small_size = capacity/20 from the v001 lineage — or capacity/10 if deriving from baseline; since parent is baseline use baseline's `capacity / 10`) remains unchanged.

## Rationale

In the current design the ghost detects "we have seen this key at least twice since it first entered small — it might be worth admitting to main." Main-evicted items carry a stronger signal: they passed the cold filter, accumulated enough frequency for eager promotion, and survived at least one second-chance pass in main before reaching freq <= 1. Re-admitting them directly to main on next access is precisely the use case the ghost was designed for. Shifting the ghost feed to main evictions has not been explored in any prior cycle and targets a structurally distinct mechanism from the queue-sizing and MTF improvements in H01 and H02.
