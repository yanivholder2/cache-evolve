# H02

Reducing the small queue from capacity/20 (~5%) to capacity/28 (~3.6%) will continue the monotone hit-rate improvement by transferring more resident slots to main without degrading the cold-admission filter, since the true floor has not yet been located.

## Parent

cycle/0009/v001

## Changes

In `try_new()`, change the single denominator on line 59 of the v001 overlay from `20` to `28`:

```rust
// Before (v001):
(capacity / 20).max(1).min(capacity - 1)

// After:
(capacity / 28).max(1).min(capacity - 1)
```

At capacity 2048 this reduces small_size from 102 slots to 73 slots, transferring ~29 additional resident slots to main. `main_size` updates automatically as `capacity - small_size`, and `ghost_size = main_size / 2` grows in step.

No other changes: keep MAX_FREQ = 5, eager-promotion threshold at `freq >= 2`, `evict_main()` threshold at `freq > 1`, `evict_small()` logic, the MTF-free main `get()` path, and all existing tests. Update the block-comment header to record the new denominator and the step being probed (capacity/28).

## Rationale

The small-queue shrinkage benefit has held monotonically across eight prior cycles (25% → 10% → ~8% → ~7% → ~5%). Cycle 0009's winner established capacity/20; cross-cycle insights rank locating the true floor as the highest-priority empirical question. Moving to capacity/28 is a proportionally similar step (denominator ratio ≈ 1.4×) to prior successful reductions, making it the natural next probe without leaping so far as to risk a sharp filter-quality cliff in a single step.
