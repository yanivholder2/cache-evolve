# H02

Deepening the ghost queue while gating re-admission on ghost freshness — fresh ghost hits go straight to main, stale ones re-enter via small — will capture more long-gap reuse and raise hit-rate without crowding main.

cycle/0002/v001

## Changes

This targets the open question left by cycle 0001 (deeper ghost regressed
when re-admitted direct-to-main) and cycle 0002 (re-admitting every ghost
hit via small regressed): test the untried middle path — deeper ghost
history with a *freshness* gate.

In `src/s3_fifo/mod.rs`:

1. Decouple ghost capacity from `main_size`. Add a `ghost_size` field set
   in `try_new()` to `2 * main_size` (saturating, clamped `>= 1`), and use
   it for the `VecDeque::with_capacity(...)` of `ghost` and for the
   `if self.ghost.len() >= ...` cap in `evict_small()`. This lengthens
   the reuse-history window.
2. In `put()`, when the key is found in `ghost`, determine its position
   in the ghost `VecDeque` (front = most recently evicted). If it sits in
   the front half (position `< ghost.len() / 2`), treat it as "fresh" and
   keep the existing direct-to-main re-admission (evict main if full,
   `push_front` into `main`). If it sits in the back half ("stale"),
   remove it from ghost and instead admit it as a normal new entry into
   the `small` queue (running `evict_small()` first if small is full,
   then `push_front` into `small` with `freq = 0`).

Preserve: the ghost-key removal on hit, capacity bounds
(`small.len() + main.len() <= capacity`), and all existing eviction
logic. The claim is that the freshness gate recovers the long-gap reuse
that pure deepening lost while keeping stale, low-value ghost hits off the
contention-sensitive main queue.
