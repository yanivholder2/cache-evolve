# H02

Evicting weak small-evicted ghost records before strong main-evicted ones, within an unchanged ghost budget, raises hit-rate.

## Parent

cycle/0006/v002

## Changes

In the parent (`src/s3_fifo/mod.rs`) the ghost queue is `VecDeque<K>` and is
trimmed by dropping its tail (`self.ghost.pop_back()`) whenever it reaches
`main_size`, treating every ghost key — whether demoted from small (weak,
freq ≤ 1) or evicted from main (strong, earned promotion then cooled) —
identically.

Make the ghost queue source-aware without changing its total size:

1. Add a small struct, e.g. `struct GhostKey<K> { key: K, from_main: bool }`,
   and change the field to `ghost: VecDeque<GhostKey<K>>`.
2. In `evict_small`'s demotion branch, push with `from_main: false`. In
   `evict_main`'s drop branch, push with `from_main: true`. Keep both
   `push_front` at the head as today.
3. Replace the blind `pop_back()` trim used by both eviction paths with a
   helper `evict_ghost_one()` that, when the queue is full, first scans from
   the tail for the oldest `from_main: false` (weak) record and removes it;
   only if none exists does it fall back to dropping the tail. This evicts
   weak history first so strong main-evicted records persist longer.
4. Update the `in_ghost` lookup in `put` and the `retain` removal to compare
   against `ghost_key.key`.

Keep the partition ratio, move-to-front `get`, the `evict_main` rotation, and
the direct-to-main re-admission (still `Entry::new`, freq 0) unchanged. Only
the ghost *retention priority by source* changes; total ghost capacity stays
`main_size`.

## Rationale (optional)

The cross-cycle open question asks whether the ghost should be weighted by
source. This protects the proven-valuable main-evicted population's history
without enlarging the window (which separately risks leaking one-hit-wonders),
isolating retention-priority from raw depth.
