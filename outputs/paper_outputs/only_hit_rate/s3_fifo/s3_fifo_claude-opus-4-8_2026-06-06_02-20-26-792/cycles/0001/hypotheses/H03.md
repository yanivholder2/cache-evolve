# H03

Deepen the ghost queue to remember more recently-evicted keys (full capacity rather than main_size), increasing ghost-hit re-admissions and hit-rate.

## Parent

baseline

## Changes

In `src/s3_fifo/mod.rs`, add a `ghost_size: usize` field to the `S3Fifo`
struct. In `try_new()`, set `ghost_size = capacity` (i.e. roughly double the
current `main_size`) and use it for the ghost `VecDeque::with_capacity(...)`
allocation. Replace the two places that bound the ghost queue length against
`main_size` with `ghost_size`: the eviction trim in `evict_small()`
(`if self.ghost.len() >= self.main_size { self.ghost.pop_back(); }`) must
become `>= self.ghost_size`. The ghost queue stores only keys (not values),
so this does not affect resident-set size — the capacity-bound, value-
fidelity, and no-phantom invariants are all preserved because ghosted keys
are never returned by `get`. Do not change promotion thresholds or the
small/main partition sizing.

## Rationale (optional)

The baseline forgets an evicted key once `main_size` newer evictions occur.
On a long-tailed LIRS workload, a key reaccessed after a slightly longer gap
falls out of the ghost queue and is treated as cold, re-entering the slow
small queue instead of being re-admitted to main. A deeper ghost queue
lengthens the reuse-detection window, turning more of those reaccesses into
direct main re-admissions. This isolates the history-depth lever from the
admission (H01) and sizing (H02) strategies.
