# H02

Record main-queue eviction victims in the ghost queue (today they are silently dropped) so a previously-promoted, briefly-cold key re-admits directly to main on reaccess, raising hit-rate by exploiting a strong reuse signal the current code discards.

## Parent

cycle/0004/v003

## Changes

Target `evict_main()`. Currently when the scanned tail has `freq == 0` the loop
hits the `else { break; }` branch and the popped `tail` entry is dropped entirely —
main-evicted keys leave no ghost record, so only `evict_small`-evicted keys can
ever be re-admitted. Change the `else` branch so that, before breaking, the
victim's key is pushed into the ghost queue using the same capacity discipline as
`evict_small`: if `self.ghost.len() >= self.main_size` then `self.ghost.pop_back()`,
then `self.ghost.push_front(tail.key)`. Leave the rotation/second-chance logic
(`freq > 0` → decrement and `push_front`) untouched.

The existing `put()` in-ghost branch already routes any ghost hit direct-to-main,
so no change is needed there: a reaccess to a former main resident will now
re-enter main directly instead of starting cold in the small admission queue.

Rationale: a key that was promoted to main and then cooled to `freq == 0` is a
*stronger* reuse population than the one-hit-wonders that dominate small-queue
evictions — it earned promotion at least once. Prior cycles only ever deepened or
gated ghost history over the weak small-evicted population; ghosting the
main-evicted population is an untouched mechanism. Distinguish this from the failed
"deeper ghost" probes: ghost depth/window is unchanged here — only the *source*
population gains a record.

Invariants to preserve: keep the direct-to-main re-admission path and ghost
capacity bound (`main_size`); do not alter `evict_small` or the move-to-front main
hit path; main's resident count still drops by exactly one per `evict_main` victim.
