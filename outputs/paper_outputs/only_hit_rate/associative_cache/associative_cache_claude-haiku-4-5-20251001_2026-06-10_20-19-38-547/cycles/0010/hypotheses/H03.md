# H03

Implement frequency-weighted promotion scoring to prioritize cold-to-hot promotion of high-value items, improving hit-rate by focusing hot-tier space on recoveries showing strongest re-access patterns.

## Parent

baseline

## Changes

Modify the `AssociativeCache<K, V>` two-tier stash mechanism (20% hot / 5% cold, with promotion-on-hit) to use frequency-weighted promotion scoring when deciding which cold-tier items get priority access to the hot tier.

**Track access frequency in cold tier**: Add a `cold_access_count: usize` field to the `Item<K, V>` struct to track how many times an item is re-accessed while residing in cold stash. Initialize this field to 0 when an item enters cold stash (from bucket eviction), and increment it each time the same key is accessed while the item is in cold tier (during `get_and_update_item()` on a cold-stash hit).

**Promotion scoring**: When promoting a cold-tier item to hot tier, compute a `promotion_score` as follows:
```
promotion_score = cold_access_count / (1.0 + time_since_eviction_ms / 1000.0)
```
where `time_since_eviction_ms` is the elapsed time in milliseconds since the item was evicted to cold stash (tracked via the existing `timestamp` field updated at promotion time).

**Selective promotion on hot-tier capacity**: When the hot stash is at capacity and a cold-tier hit would promote an item to hot, instead of promoting the most-recently-accessed cold item (current promotion-on-hit), scan the cold stash for all items ready to promote (i.e., items that just showed a hit) and select the one with the **highest promotion_score**. This ensures high-frequency re-accessed items and items with recent eviction-to-hit latency are prioritized.

**Fallback**: If no items are currently being promoted (i.e., when the hot tier fills during normal cold-→hot transitions), evict the least-recently-accessed item from hot tier using the existing LRU mechanism, and promote the highest-scoring cold item if available.

**Interaction with FIFO insertion**: Items enter cold stash via FIFO from bucket evictions (unchanged). The frequency-weighted scoring applies only at promotion time, not at insertion.

Preserve the 20%/5% partition, the promotion-on-hit core mechanism, and all other two-tier stash semantics from the baseline. The change is scoped to the promotion prioritization logic—which cold-tier items get promoted first when hot tier has limited capacity.

This tests whether focusing hot-tier capacity on items showing the highest re-access frequency (weighted by recency) yields better hit-rate than promotion-on-first-hit, by ensuring that high-value recoveries are not crowded out by lower-value items when hot tier is constrained.
