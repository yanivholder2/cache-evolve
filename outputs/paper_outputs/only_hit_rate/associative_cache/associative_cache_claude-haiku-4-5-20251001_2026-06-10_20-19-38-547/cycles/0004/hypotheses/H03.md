# H03

Test whether geometry optimization (wider buckets) can achieve competitive hit rate with reduced stash overhead (15% instead of 25%), trading off recovery capacity for collision reduction.

## Parent

baseline

## Changes

Implement two coordinated changes in `src/shared/geometry.rs` and `src/associative_cache/mod.rs`. In geometry, overlay `BaselineGeometry::layout()` to prefer fewer, wider buckets (similar transformation as H01: reduce bucket count by ~0.67–0.75 factor, increase bucket width proportionally, maintaining total capacity). In the cache implementation, add a 15% stash (`total_capacity / 6.67`, minimum 1) with FIFO eviction and secondary lookup on primary bucket misses. The hypothesis expects that collision reduction from the geometry rebalancing will reduce the rate of evictions requiring recovery, allowing a smaller stash (15% vs. the proven 25%) to provide comparable hit-rate improvement. If this variant matches or exceeds 25%-stash baselines while using less stash capacity, it suggests the binding constraint has shifted from capacity to collision frequency, enabling more efficient cache design. If it underperforms, it confirms that raw stash capacity remains necessary despite geometry improvements.
