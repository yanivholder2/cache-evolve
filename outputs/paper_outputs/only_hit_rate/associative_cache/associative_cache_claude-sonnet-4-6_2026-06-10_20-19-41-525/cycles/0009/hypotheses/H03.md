# H03

Combining SLRU's two-queue structure with 4x-wider buckets, cold-first eviction within the probationary segment, and decay-by-2 warm-lock confined to the probationary segment raises hit rate over v003 by adding structural working-set protection on top of the single-queue mechanisms that are already proven.

baseline

## Changes

Implement two overlay files:

---

### 1. `src/shared/geometry.rs`

Identical to cycle/0008/v003's `geometry.rs`: factor-4 wide-bucket repartition
(`target_num_buckets = num_of_buckets / 4`, capacity-preserving fallback). For the
standard 128×16=2048 configuration this yields 32×64.

---

### 2. `src/associative_cache/associative_cache_bucket.rs`

Implement an SLRU bucket that merges v002's two-queue structure with v003's
cold-first eviction and decay-by-2 warm-lock. The struct must include a `prob_count:
usize` field (same as v002) in addition to `items`, `max_size`, and `eviction_policy`.

**Tier layout** (same as v002):
- `items[0..prob_count]` = probationary segment, index 0 = oldest.
- `items[prob_count..]` = protected segment, index `prob_count` = oldest.
- `prob_cap = max_size / 2`, `prot_cap = max_size - prob_cap` (50/50 split).

**`put()`** (same as v002):
- Existing key: update value in place, call `get_from_position(position)`, return.
- New key, bucket full: call `evict_item()` first.
- New key: insert at back of probationary via `self.items.insert(self.prob_count,
  item); self.prob_count += 1`.

**`get_from_position(position)`** (same structure as v002 but add counter cap):
- Increment `lfu_counter` with cap at 4:
  `self.items[position].lfu_counter = self.items[position].lfu_counter.saturating_add(1).min(4);`
- Probationary hit (`position < prob_count`): remove item, decrement `prob_count`.
  If protected is full (`items.len() - prob_count == prot_cap()`), demote oldest
  protected item (`items[prob_count]`) to probationary-front (index 0), increment
  `prob_count`. Push accessed item to back of `items` (protected-back).
- Protected hit (`position >= prob_count`): remove item, push to back of `items`
  (protected-back). Do not change `prob_count`.

**`evict_item()`** — this is the core change vs v002:
1. If `items` is empty, return `None`.
2. **Cold-first scan within probationary**: scan `items[0..prob_count]` for the first
   item with `lfu_counter == 0`. If found at index `i`, remove it (`self.items.remove(i)`),
   decrement `prob_count`, and return it.
3. **Warm-lock path — decay + evict oldest probationary**: if no cold probationary item
   was found and `prob_count > 0`:
   - Apply `saturating_sub(2)` decay to all probationary items ONLY:
     ```rust
     for item in self.items[0..self.prob_count].iter_mut() {
         item.lfu_counter = item.lfu_counter.saturating_sub(2);
     }
     ```
   - Then remove `self.items[0]` (oldest probationary item), decrement `prob_count`,
     and return it.
4. **Probationary empty fallback**: if `prob_count == 0`, remove `self.items[0]`
   (oldest protected item) without changing `prob_count`, and return it.

**Key invariants to preserve:**
- `prob_count` never exceeds `items.len()`.
- Protected items (`items[prob_count..]`) are never decayed in the warm-lock path.
- `saturating_sub` prevents underflow on any counter.
- Total capacity = `num_of_buckets * bucket_size` is conserved by geometry.

Do NOT add or modify `eviction_policy.rs` — the baseline version is sufficient since
the SLRU bucket manages counter increments directly in `get_from_position` and does not
delegate counter updates to the eviction policy trait object.

## Rationale

This variant tests whether the three proven mechanisms — SLRU tier separation, wide-bucket
geometry, and cold-first + decay eviction — are mutually reinforcing when combined.
v002 had SLRU without wide geometry and without cold-first/decay; v003 had cold-first +
decay + wide geometry without SLRU. The open question from the cross-cycle history is
whether cold-first eviction and mid-point insertion remain complementary inside SLRU.
This design answers that directly by replacing mid-point insertion with SLRU's explicit
probationary/protected boundary (which provides a stronger structural guarantee: one-hit
wonders cannot enter protected at all, regardless of insertion position) while retaining
cold-first + decay within the probationary segment. Confining decay to probationary
items only is critical: protected items have earned their status through promotion and
should not have their counters degraded by probationary warm-lock events.
