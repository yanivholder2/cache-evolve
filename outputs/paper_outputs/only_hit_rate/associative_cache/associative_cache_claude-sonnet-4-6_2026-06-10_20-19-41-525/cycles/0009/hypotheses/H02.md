# H02

Applying SLRU's two-queue tier separation on 4x-wider buckets raises hit rate by giving each probationary/protected split the same large item pool that underpins every single-queue winner since cycle 0002.

## Parent

cycle/0008/v002

## Changes

Add a `src/shared/geometry.rs` overlay alongside v002's existing
`src/associative_cache/associative_cache_bucket.rs`. The bucket implementation from
v002 is carried forward **completely unchanged**.

`geometry.rs` must implement the same factor-4 wide-bucket repartition used in
cycle/0008/v003 (and cycle/0007/v003, cycle/0004/v001, etc.):

```rust
pub struct BaselineGeometry { pub num_of_buckets: usize, pub bucket_size: usize }

impl BaselineGeometry {
    pub fn for_settings(settings: &AssociativeCacheSettings) -> Self {
        let total = settings.num_of_buckets * settings.bucket_size;
        let factor = 4usize;
        let target_num_buckets = (settings.num_of_buckets / factor).max(1);
        let (num_of_buckets, bucket_size) = if total % target_num_buckets == 0 {
            (target_num_buckets, total / target_num_buckets)
        } else {
            (settings.num_of_buckets, settings.bucket_size)
        };
        BaselineGeometry { num_of_buckets, bucket_size }
    }
}

impl BucketGeometry for BaselineGeometry {
    fn layout(&self, _total_capacity: usize) -> (usize, usize) {
        (self.num_of_buckets, self.bucket_size)
    }
}
```

For the standard 128×16=2048 configuration this produces 32 buckets of 64 slots each.
Each SLRU bucket then has `prob_cap = 32` (probationary) and `prot_cap = 32`
(protected) instead of the v002 baseline's 8/8 split.

Do NOT change `eviction_policy.rs` or `associative_cache_bucket.rs`.

**Invariant to preserve:** capacity conservation — `new_num_of_buckets *
new_bucket_size == settings.num_of_buckets * settings.bucket_size` for all valid
inputs.

## Rationale

v002's SLRU design ran on baseline narrow-bucket geometry (128×16) because it did not
include a `geometry.rs` overlay. Every single-queue winner since cycle 0002 has relied
on the 4x wide-bucket repartition (32×64) to give the per-bucket LRU a large enough
eviction pool. v002's 0.6887 vs v003's 0.7298 gap is largely attributable to this
geometry deficit rather than to the SLRU structure itself. This variant isolates the
geometry variable: if wide SLRU matches or exceeds v003, the structural tier separation
is a genuine improvement. If it still trails, the SLRU logic itself is the bottleneck
and further mechanism changes are needed.
