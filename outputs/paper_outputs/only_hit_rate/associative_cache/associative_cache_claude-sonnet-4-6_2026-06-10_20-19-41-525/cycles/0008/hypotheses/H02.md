# H02

An SLRU (Segmented LRU) two-queue design that physically partitions each bucket into a probationary segment and a protected segment improves hit-rate over baseline by explicitly preventing scan traffic from displacing confirmed-hot items.

## Parent

baseline

## Changes

Replace the body of `src/associative_cache/associative_cache_bucket.rs` with an SLRU
implementation. Add one field to `AssociativeCacheBucket`:

```rust
prob_count: usize,   // live count of probationary items in items[0..prob_count]
```

The `items` vector is logically divided at runtime: `items[0..prob_count]` holds
probationary items (LRU front at index 0 = oldest, new arrivals appended at index
`prob_count - 1`); `items[prob_count..]` holds protected items (LRU front at index
`prob_count` = oldest, most-recently-promoted at the back).

Fixed caps: `prob_cap = max_size / 2`, `prot_cap = max_size - prob_cap`.

**`put()` override** (new-item insertion):
- Existing-key update: update value in place, call `get_from_position`, return as now.
- New key, full: evict first (see below), then insert.
- Insert new item at index `prob_count` (back of probationary segment):
  `self.items.insert(self.prob_count, item); self.prob_count += 1;`
  This preserves `items[0]` as the oldest probationary item.

**`evict_item()` override**:
- If `prob_count > 0`: remove `items[0]` (oldest probationary), decrement `prob_count`, return it.
- Else (probationary empty): remove `items[0]` (oldest protected; `prob_count` is 0 so this is the oldest overall).

**`get_from_position()` override** (hit logic, position `p` in `items`):
- Increment `items[p].lfu_counter` (keep counter tracking for inspection; not used for eviction here).
- If `p < prob_count` (probationary hit):
  - Remove item from `items[p]`; `prob_count -= 1`.
  - Protected count after removal = `items.len() - prob_count`. If that equals `prot_cap` (protected full), demote the oldest protected item: remove `items[prob_count]` (now index `prob_count` after prior removal) and insert it at index 0 (front of probationary); `prob_count += 1`.
  - Push the accessed item to the back of `items` (newest protected).
- If `p >= prob_count` (protected hit):
  - Remove item from `items[p]`.
  - Push to back of `items` (LRU promotion within protected).
- Return reference to the item at its new position.

**No changes to `src/shared/geometry.rs` or `src/shared/eviction_policy.rs`**. The
`eviction_policy` field is still constructed but its methods are not called; the bucket
manages its own eviction entirely through the overrides above. The `lfu_counter` field
on items is incremented on hits (satisfying invariants) but is not read for eviction
decisions.

**Invariants to preserve**: total capacity (num_of_buckets × bucket_size) unchanged;
every item in `items` has a unique key; `get` returns the value for any key present;
`put` evicts before exceeding `max_size`.

## Rationale

All cycles through 0007 have operated within the single-queue associative bucket
model (cold-first, counters, decay). SLRU explicitly separates the two concerns that
the current design co-encodes in position and counter: recency (is this item a proven
member of the working set?) and eviction ordering (who goes first?). The open-question
section of the cross-cycle insights calls out this design family as the one structural
alternative that has never been tested. A win here would open a new evolutionary
branch; a loss would confirm that co-encoding position + counter is the right model
for workload-a.
