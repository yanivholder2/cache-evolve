# H01

Stacking LFU minimum-counter selection onto cycle/0004/v001's warm-lock decay path — replacing the positional `remove_at(0)` with a scan for the item with the lowest post-decay `lfu_counter` — will improve hit-rate over cycle/0004/v001 by evicting the least-valuable item after decay rather than the merely oldest one.

## Parent

cycle/0004/v001

## Changes

Modify `src/associative_cache/associative_cache_bucket.rs` only; all other overlay files
from cycle/0004/v001 (`eviction_policy.rs` with cold-first ClassicLRU, `geometry.rs`
with factor-4 wide-bucket layout) are preserved unchanged.

In the `evict_item` method, the decay branch (step 2, triggered when no cold candidate
exists) currently reads:

```rust
// Step 2: warm-lock — decrement all counters, then evict LRU front.
for item in self.items.iter_mut() {
    item.lfu_counter -= 1;
}
Some(self.remove_at(0))
```

Change the eviction target after the decay loop from `remove_at(0)` to a
minimum-counter scan:

```rust
// Step 2: warm-lock — decrement all counters.
for item in self.items.iter_mut() {
    item.lfu_counter -= 1;
}
// Evict the item with the lowest post-decay lfu_counter, breaking ties
// by lowest index (earliest in recency order = most LRU among equals).
let victim = self.items
    .iter()
    .enumerate()
    .min_by_key(|(_, item)| item.lfu_counter)
    .map(|(i, _)| i)
    .unwrap_or(0);
Some(self.remove_at(victim))
```

Step 1 (cold-first scan before decay) and the `put()` mid-point insertion path are
unchanged. The invariant that `evict_item` returns `Some` when items are non-empty is
preserved.

## Rationale

After the decay pass, items that had `lfu_counter == 1` are now cold (`lfu_counter == 0`)
and are the best eviction candidates — they held the least evidence of future reuse before
decay. Items at higher pre-decay values retain non-zero post-decay counts. The current
`remove_at(0)` ignores this information and blindly evicts the positionally oldest item,
which may be a high-counter hot item that happens to be at the LRU front. The LFU scan
over post-decay counters picks the truly least-valuable item. In the common subcase where
the minimum post-decay counter is 0 (i.e., at least one item was at exactly 1 before
decay), this also doubles as a second cold-first pass, so it strictly dominates `remove_at(0)`.
The cross-cycle insight explicitly flags the combination of decay (v001) and LFU fallback
(v002) as the highest-priority unprobed combination; this hypothesis stacks them in the
eviction path itself rather than in the policy's `eviction_candidate_index`.
