# H01

Replacing cold-first-scan + bulk-decay with a persistent CLOCK-hand eviction that grants each warm item a per-step decrement opportunity will improve hit-rate by distributing aging pressure proportionally across all warm items rather than evicting whichever cold item happens to appear first in index order.

## Parent

cycle/0005/v003

## Changes

Modify `src/associative_cache/associative_cache_bucket.rs` only; leave `src/shared/geometry.rs` and `src/shared/eviction_policy.rs` unchanged from cycle/0005/v003.

**1. Add a `clock_hand: usize` field to `AssociativeCacheBucket`:**

```rust
pub struct AssociativeCacheBucket<K, V> {
    items: Vec<Item<K, V>>,
    max_size: usize,
    eviction_policy: Box<dyn EvictionPolicy<K, V>>,
    clock_hand: usize,   // ← new field
}
```

Initialise it to `0` in `new()`.

**2. Replace `evict_item()` with CLOCK semantics (remove the cold-first scan and the bulk-decay pass entirely):**

```rust
fn evict_item(&mut self) -> Option<Item<K, V>> {
    if self.items.is_empty() {
        return None;
    }
    let n = self.items.len();
    // CLOCK sweep: at most n full rotations (cap==4 guarantees termination).
    for _ in 0..n * 5 {
        let hand = self.clock_hand % self.items.len();
        if self.items[hand].lfu_counter == 0 {
            // Found a cold item — evict it and advance hand past the gap.
            let evicted = self.items.remove(hand);
            self.clock_hand = if self.items.is_empty() { 0 } else { hand % self.items.len() };
            return Some(evicted);
        }
        // Give this item a second chance: decrement its counter and move on.
        self.items[hand].lfu_counter -= 1;
        self.clock_hand = (hand + 1) % self.items.len();
    }
    // Safety fallback (should not be reached with cap==4): evict hand position.
    let hand = self.clock_hand % self.items.len();
    let evicted = self.items.remove(hand);
    self.clock_hand = if self.items.is_empty() { 0 } else { hand % self.items.len() };
    Some(evicted)
}
```

**3. Update `put()` to maintain hand consistency after mid-point insertion:**

After inserting at `mid` (which shifts indices `>= mid` rightward by 1), adjust the hand:

```rust
fn put(&mut self, item: Item<K, V>) -> (&Item<K, V>, Option<Item<K, V>>) {
    if let Some(position) = self.get_position(&item.key) {
        self.items[position].value = item.value;
        let pushed_item = self.get_from_position(position);
        return (pushed_item, None);
    }
    let evicted_item = if self.is_full() { self.evict_item() } else { None };
    let mid = self.items.len() / 2;
    self.items.insert(mid, item);
    // Adjust hand: insertion at mid shifts all items at >= mid rightward.
    if mid <= self.clock_hand && self.clock_hand + 1 < self.items.len() {
        self.clock_hand += 1;
    }
    (&self.items[mid], evicted_item)
}
```

**Invariants preserved from v003:**
- Wide-bucket geometry (factor-4 repartition in `geometry.rs`): unchanged.
- Counter increment capped at 4 in `ClassicLRU::get_from_position` (`eviction_policy.rs`): unchanged.
- Mid-point insertion ordering: preserved in the updated `put()`.
- No unbounded counter accumulation: the cap ensures at most 4 CLOCK passes per item.

## Rationale

The cold-first scan always evicts the *first* cold item in index order, which under mid-point insertion tends to be an older insertion — a reasonable heuristic but one that ignores the relative warmth of adjacent items. Bulk decay then ages *all* items simultaneously when warm-lock occurs, compressing frequency differences to near-zero. CLOCK instead ages each item individually as the hand sweeps past, so items with genuinely higher access counts survive more passes before being evicted. This preserves inter-item frequency differentiation through the aging process and avoids the "counter compression" failure mode identified in cycle 0005.
