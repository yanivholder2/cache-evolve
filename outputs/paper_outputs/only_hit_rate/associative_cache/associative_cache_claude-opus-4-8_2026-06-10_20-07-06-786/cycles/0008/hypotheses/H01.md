# H01

Improving key-to-bucket distribution with a strong avalanche finalizer and bias-free reduction in `get_index` spreads the hot working set more evenly across buckets and raises hit-rate.

## Parent

cycle/0007/v002

## Changes

This is the one genuinely untested *trace-structure* axis the cross-cycle
insights call for: every prior cycle treated routing as a fixed cost and only
tuned bucket logic or width. The trace is collision-bound, so how evenly keys
land across buckets directly bounds achievable hit-rate. Attack the routing
quality itself, leaving the segmented bucket logic and the single-halving
geometry of the parent untouched.

Edit `src/shared/utils.rs` only:

1. In `hash` (or in `get_index` after calling `hash`), pass the raw
   `hasher.finish()` value through a splitmix64-style finalizer before it is
   reduced to a bucket index:
   ```
   let mut x = hasher.finish();
   x ^= x >> 30; x = x.wrapping_mul(0xbf58476d1ce4e5b9);
   x ^= x >> 27; x = x.wrapping_mul(0x94d049bb133111eb);
   x ^= x >> 31;
   ```
   `DefaultHasher` (SipHash) output can correlate in its low bits for the
   sequential/structured integer keys this trace uses; the finalizer adds
   avalanche so adjacent keys scatter.

2. Replace the low-bit-biased `hash % size` reduction in `get_index` with the
   bias-free multiplicative (Lemire) reduction:
   ```
   ((x as u128 * size as u128) >> 64) as usize
   ```
   which uses the *high* bits of the mixed value and avoids modulo bias when
   `size` is not a power of two.

Invariants to preserve: `get_index` must stay a pure, deterministic function of
`(key, size)` returning a value `< size` (the unit tests `get_index_within_bounds`,
`get_index_deterministic`, and `hash_differs_for_different_keys` still pass).
Because the P2 `slot_legality` gate computes the home bucket with the *same*
`get_index`, placement and the gate check stay automatically consistent — do not
change the signature or introduce per-key state.

## Rationale (optional)

This is capacity-neutral and the only legal structural lever (multi-home schemes
violate the single-home P2 gate). If the parent's hit-rate ceiling is set by
uneven bucket load rather than bucket policy, this is the change that moves it;
if `DefaultHasher` is already near-uniform here, it lands as a clean tie and
rules the routing axis out.
