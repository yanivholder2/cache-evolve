# H01

Applying a second capacity-conserving widening step (≈4× associativity over baseline) raises hit-rate by letting each collision set retain still more of its hot working set, testing whether the sweet spot lies beyond one halving.

## Parent

cycle/0006/v001

## Changes

Modify `BucketGeometry::layout` in `src/shared/geometry.rs` (the parent's
single-halving version) to apply the capacity-conserving widening step up to
**two** times instead of once. Concretely, run a loop that repeats `nb /= 2;
bs *= 2;` while `nb` is even and `nb / 2 >= 1` (i.e. stops before `num_of_buckets`
would drop below 1), capped at two iterations total. Each step preserves the
product exactly, so `nb * bs == self.num_of_buckets * self.bucket_size` always
holds and P4 `capacity_conservation` passes for arbitrary budgets (including odd
`nb`, where the loop simply stops or never starts and falls back to the
identity/one-step split). Leave the segmented bucket logic in
`associative_cache_bucket.rs` completely untouched — this is a pure routing
change.

The parent already confirmed one halving helps and is "near the associativity
sweet spot"; this variant deliberately overshoots by one step to locate the
turning point. If hit-rate rises further, the sweet spot is wider than one
halving; if it regresses, one halving is confirmed optimal and the routing-loss
boundary is pinned.

## Rationale

Geometry is the only axis to yield a hit-rate gain in several cycles, and the
central open question from cycle 0006 is whether one halving is exactly optimal
or merely the first step. A direct second-step probe answers it cheaply, citing
the proven winner as the base so the only variable is associativity depth.
