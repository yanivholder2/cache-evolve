# H03

Gating target-to-probing promotion on lfu_counter >= 2 in the target tier will raise hit-rate by reserving the probing bucket for doubly-confirmed-hot items and reducing probing churn caused by one-hit-in-target items earning the premium tier prematurely.

## Parent

cycle/0007/v001

## Changes

In `src/dash/segments/dash_segment.rs`, modify the target-bucket branch of `promotion_get()` to require `lfu_counter >= 2` before executing a target-to-probing promotion. The hottest item that fails the gate is handled by the existing intra-bucket path (`get_from_position`) instead, which increments its counter and moves it to MRU — so it accumulates the required accesses on subsequent hits.

Locate the block:

```rust
if let Some(item_idx) = core.buckets[target_idx].get_position(key) {
    let is_hottest = Some(item_idx) == core.buckets[target_idx].promotion_candidate_index();
    if is_hottest {
        debug!("promotion_get: key={key:?} found in target as hottest -> probing={probing_idx}");
        let data = core.buckets[target_idx].remove_at(item_idx);
        promote_to_probing(core, data, insert_pos);
        // ...
    } else {
        debug!("promotion_get: key={key:?} found in target item_idx={item_idx} (intra-promote)");
        return Some(core.buckets[target_idx].get_from_position(item_idx));
    }
}
```

Replace the `if is_hottest` condition with a compound check:

```rust
if let Some(item_idx) = core.buckets[target_idx].get_position(key) {
    let is_hottest = Some(item_idx) == core.buckets[target_idx].promotion_candidate_index();
    let counter = core.buckets[target_idx].get_items()[item_idx].lfu_counter;
    if is_hottest && counter >= 2 {
        debug!("promotion_get: key={key:?} found in target as hottest (counter={counter}) -> probing={probing_idx}");
        let data = core.buckets[target_idx].remove_at(item_idx);
        promote_to_probing(core, data, insert_pos);
        // ...
    } else {
        debug!("promotion_get: key={key:?} found in target item_idx={item_idx} (intra-promote)");
        return Some(core.buckets[target_idx].get_from_position(item_idx));
    }
}
```

The `get_items()` call is a borrow of the bucket slice and is safe before the `remove_at` on the promotion branch. `get_from_position` still handles the intra-bucket case (both non-hottest items and hottest items that fail the counter gate), incrementing `lfu_counter` via `ClassicLRUFreqProtect::get_from_position` and moving the item to MRU. Items will reach `counter >= 2` after two intra-bucket hits and then qualify for probing promotion on the third target access.

No changes to `eviction_policy.rs`, `geometry.rs`, `dash_bucket.rs`, or `item.rs`. All v001 mechanisms (ClassicLRUFreqProtect eviction, Back-insert stash→target, second-chance recovery, lfu_counter reset on demotion) are preserved untouched.

**Invariant to preserve**: Items removed via `remove_at` on the promotion branch still enter `promote_to_probing` with their current counter value (which may be 0, 1, or 2 — the `remove_at` call does not increment the counter). This is existing behaviour; the only change is the eligibility gate before the `remove_at`.
