# H02

Replace the ghost-set re-admission mechanism with an immediate second-chance insertion into the target tier for stash-evicted items, to improve hit-rate by keeping semi-warm items in cache rather than letting them leave and relying on a future re-insertion event.

## Parent

cycle/0004/v002

## Changes

Modify only `src/dash/segments/dash_segment.rs`. All other files (`geometry.rs`, etc.) are inherited from cycle/0004/v002 unchanged.

### Remove the ghost set entirely

- Remove the `ghost_keys: VecDeque<K>` field from `DashSegment<K, V>`.
- Remove `use std::collections::VecDeque;` from the imports.
- Remove the `GHOST_CAPACITY` constant.
- Update `try_new` / `new` to construct `Self { core }` (no `ghost_keys` field).

### Replace `put` logic

The overridden `put` keeps the normal stash admission path (`put_at(Slot::Stash, InsertPosition::Back, item)`) but replaces the ghost-set recording with a direct second-chance promotion for any evicted stash resident:

```rust
fn put(&mut self, item: Item<K, V>) {
    debug_assert!(
        !self.core.contains_key(&item.key),
        "put: key={:?} already present — caller must not re-insert a resident key",
        item.key
    );

    debug!("DashSegment.put: key={:?} -> stash", item.key);
    let evicted = self.core.put_at(Slot::Stash, InsertPosition::Back, item);

    if let Some(ev) = evicted {
        // Second-chance: rather than recording the evicted key in a ghost set
        // and waiting for a future re-insertion, immediately place the item in
        // its target bucket at the LRU end (Front). It competes from the
        // coldest position in the hot tier, where it will survive if accessed
        // before the next cascade eviction pushes it out.
        debug!(
            "DashSegment.put: stash evicted key={:?} -> second-chance target(Front)",
            ev.key
        );
        promote_to_target(&mut self.core, ev, InsertPosition::Front);
    }
}
```

### `get` is unchanged

Keep `promotion_get(&mut self.core, key, InsertPosition::Back)` exactly as in the parent. All promotion positions (stash→target at Back, target→probing at Back) are inherited unchanged.

### Update doc-comment

Update the struct-level doc comment to describe the second-chance mechanism instead of the ghost-set mechanism.

### Test adjustments

The `ghost_set_re_admission_bypasses_stash` test is specific to the ghost mechanism and should be replaced with a test verifying that a stash-evicted item appears in its target bucket (not in stash) immediately after the triggering `put`. Retain all other inherited tests unchanged.

## Rationale

Cycle 0005's insight and the cross-cycle summary both conclude that the ghost set delivers noise-level movement regardless of re-admission position. The mechanism's weakness is structural: it only fires if the evicted item is re-inserted within the ghost window, which requires an external workload event (a new `put` of the same key). For workload-a's stable hot set, that re-insertion may never come for semi-warm items that cycle through stash eviction.

The second-chance approach fires unconditionally: every stash-evicted item gets one cycle of life in its target bucket at the LRU end. Items genuinely about to be re-accessed survive (they hit before the next cascade pushes them out); items with no further reuse evict immediately without occupying a ghost-set slot. The cost is a potential target cascade on every stash overflow, but `demote_from_normal_bucket` already handles that path gracefully and the target LRU resident being displaced was itself the coldest item in target.
