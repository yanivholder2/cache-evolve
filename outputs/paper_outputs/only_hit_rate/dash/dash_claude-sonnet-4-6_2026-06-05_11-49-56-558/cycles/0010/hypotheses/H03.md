# H03

Applying the stash-exit counter credit to second-chance recovery items in `DashSegment::put()` will improve hit-rate by protecting overflow-evicted items from immediate re-eviction in the target tier, closing the same protection gap that was closed for stash-hit items in the parent.

## Parent

cycle/0009/v003

## Changes

In `src/dash/segments/dash_segment.rs`, modify the `put()` method's stash-overflow second-chance path.

Current code in `DashSegment::put()`:
```rust
if let Some(ev) = self.core.put_at(Slot::Stash, InsertPosition::Back, item) {
    debug!(
        "DashSegment.put: stash evicted key={:?} -> second-chance -> target(Front)",
        ev.key
    );
    promote_to_target(&mut self.core, ev, InsertPosition::Front);
}
```

Change to:
```rust
if let Some(mut ev) = self.core.put_at(Slot::Stash, InsertPosition::Back, item) {
    debug!(
        "DashSegment.put: stash evicted key={:?} -> second-chance -> target(Front)",
        ev.key
    );
    // Credit the second-chance item before target entry, mirroring the credit
    // applied to stash-hit items in promotion_get. The item arrives with
    // lfu_counter == 0 (reset on stash entry); without this credit it is
    // as eviction-vulnerable as a cold newcomer despite having been a recent
    // stash resident.
    ev.lfu_counter += 1;
    promote_to_target(&mut self.core, ev, InsertPosition::Front);
}
```

The binding changes from `Some(ev)` to `Some(mut ev)` to allow the `lfu_counter` mutation before passing ownership. No other changes: `promotion_get` retains its existing `data.lfu_counter += 1` credit, `demote_from_normal_bucket` retains its `item.lfu_counter = 0` reset before stash insertion, and all geometry and policy logic is identical to the parent.

## Rationale

The parent (v003) added `data.lfu_counter += 1` before `promote_to_target` in the stash-hit path of `promotion_get`, closing a protection gap: stash-hit items entered the target tier with `lfu_counter == 0`, indistinguishable from cold newcomers under `ClassicLRUFreqProtect`. v003's fix was confirmed to produce a genuine positive lift.

The same gap exists in the stash-overflow second-chance path. When stash overflows, the evicted item arrives at the target tier via `InsertPosition::Front` (LRU end) with `lfu_counter == 0`. Under `ClassicLRUFreqProtect.eviction_candidate_index`, this zero-count item is immediately the preferred eviction victim — it gets a second-chance insertion and can be evicted again before receiving a single access, if the target bucket is full or receives another cold insertion. The second-chance mechanism provides continued cache residency in principle, but without the counter credit the item enters the target tier maximally vulnerable.

The two paths — stash hit and stash overflow second-chance — are symmetric: both produce an item transitioning from stash to target with a zeroed counter. v003 closed the gap on the hit path; this hypothesis closes the analogous gap on the overflow path. The invariant that stash entries arrive at zero (so they don't protect stash slots from cold newcomers) is preserved, since the credit is applied after the item leaves the stash, not before it enters.
