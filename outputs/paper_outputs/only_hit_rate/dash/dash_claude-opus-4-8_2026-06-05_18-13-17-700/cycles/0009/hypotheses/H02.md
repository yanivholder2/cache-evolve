# H02

Fast-tracking re-requested keys that were recently dropped from the stash straight into the protected target tier raises hit-rate by distinguishing recurring keys from one-shot transients on re-admission.

## Parent

cycle/0007/v001

## Changes

Add a small bounded **ghost list** (keys only, no values) of stash victims that
were *dropped* — i.e. evicted from the cache entirely — to `DashSegment` in
`src/dash/segments/dash_segment.rs`, and use a ghost hit on the next admission
of that key as a reuse-distance signal that the key is recurring, not transient.

Concretely:

1. Add a field `ghost: VecDeque<K>` (plus a companion `HashSet<K>` for O(1) membership, or accept linear scan if the ring is tiny) to `DashSegment`, initialised empty in `try_new`. Bound its length to roughly the total stash capacity (`core.stash_size * bucket_size`); when full, pop the oldest key before pushing a new one. Keep keys only — never store values — so the ghost list adds no capacity and does not affect `capacity_conservation`.
2. In `stash_insert`, in the *drop* branch (the `else` where both alternate homes are unavailable and the victim is currently discarded), record `victim.key` into the ghost ring before dropping it. This is the only place a key truly leaves the cache.
3. In `put` (cold admission), before routing through `stash_insert`: if `item.key` is present in the ghost ring, treat it as a proven recurring key — remove it from the ghost ring and admit it via `promote_to_target(core, item, InsertPosition::Back, InsertPosition::Back)` (MRU landing in its target, skipping stash dwell), instead of `stash_insert`. A key not in the ghost ring keeps the existing cold path (stash, MRU landing) unchanged, so genuine first-touch cold keys still earn dwell time.

Invariants to preserve: this must remain at most one new resident seat per
`put` — `promote_to_target` already conserves occupancy by cascading exactly one
evicted item down the tier, so `single_eviction_per_put` holds. The ghost ring
holds only keys and is strictly bounded, so total cached *items* are unchanged.
Do not alter the get/promotion path; keep two-speed promotion, the touch
counter, and single-hop stash relocation exactly as in the parent.

## Rationale (optional)

Front-inserting *cold* keys regressed because first-touch keys need dwell time —
but a ghost hit means the key was admitted, dropped, and requested again, which
is precisely the LIRS-style short-reuse-distance signal of a non-transient key.
Promoting only those keys targets the recurring/transient boundary without
denying residency to genuinely cold keys.
