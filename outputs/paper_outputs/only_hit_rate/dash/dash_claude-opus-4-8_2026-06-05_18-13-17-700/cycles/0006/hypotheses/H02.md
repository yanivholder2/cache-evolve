# H02

Give a stash key evicted on overflow one relocation attempt into an alternate stash bucket before dropping it, extending cold-key dwell time without spending extra budget, to raise hit-rate.

## Parent

baseline

## Changes

Cycles 0004–0005 established that the stash's value is purely *dwell time*:
new keys must stay resident long enough to catch a second reference and prove
themselves. Removing or front-loading stash admission both regressed because
they cut that dwell time. This hypothesis lengthens dwell time along an
untouched axis — a second-chance relocation on overflow — instead of changing
admission position (closed) or stash capacity (saturated).

Work in `src/dash/segments/dash_segment.rs` (leave the contract-protected
files alone). The baseline admits cold keys via the segment's `put` path into
`core.stash_buckets[stash_idx]` and demotes warm keys to stash via
`core.put_at(Slot::Stash, ...)`. In both stash-insert sites, change the policy
so that when inserting into a stash bucket would evict a victim (i.e. the bucket
is full), the evicted victim is given exactly **one** relocation attempt into a
secondary stash bucket before being dropped:

- Compute the primary stash index as today via `get_index(&key, core.stash_size)`.
- Compute a secondary stash index with a second derivation, e.g.
  `alt_idx = get_index_with_salt(&key, core.stash_size)` (add a small helper that
  perturbs the hash, such as hashing `(key, 0x9E3779B9)`), distinct from the
  primary index whenever `core.stash_size >= 2`.
- When the primary stash bucket is full, attempt to place the *overflow victim*
  (the key the primary insert would evict — the LRU/promotion-candidate of that
  bucket) into the secondary bucket at its MRU end (`InsertPosition::Back`).
  Insert the incoming key into the primary bucket as before. If the secondary
  bucket is also full, the victim is dropped as it would be today (no infinite
  cascade — at most one relocation hop).

Preserve invariants: total stash capacity is unchanged (this only changes
*which* victim is dropped, never how many slots exist, so capacity conservation
still holds); when `core.stash_size < 2` fall back to today's behaviour exactly
(no secondary bucket exists); promotion, demotion-cascade, and target/probing
logic are untouched.

## Rationale (optional)

This is a cuckoo-style residency extension confined to the stash. It directly
strengthens the one stash property the cohort proved load-bearing (dwell time
for new keys) without re-running the two failed stash levers (removal,
front-insertion). It explores a genuinely new seam from a clean baseline so its
signal is unconfounded by the promotion-side winners.
