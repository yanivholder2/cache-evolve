# H01

Grafting v003's second-probing-home rescue onto the v002 ghost winner stacks two orthogonal warm-population seams to raise hit-rate above 0.719.

## Parent

cycle/0009/v002

## Changes

Port the probing-tier breadth rescue from `cycle/0009/v003` into this
variant's `promote_to_probing`. Today the v002 `promote_to_probing`
inserts into `probing_idx = (target_idx + 1) % segment_size` and hands any
`evicted` victim straight to `demote_from_normal_bucket`. Insert a rescue
hop between the `put_at(Slot::Probing, ...)` eviction and the demote call,
exactly as v003 does:

- Only when `segment_size >= 3`, compute `probing_alt = (target_idx + 2) %
  segment_size`, `victim_target = get_index(&evicted.key, segment_size)`,
  and `victim_probing = (victim_target + 1) % segment_size`.
- If `probing_alt != probing_idx && probing_alt == victim_probing &&
  !core.buckets[probing_alt].is_full()`, relocate `evicted` into
  `core.buckets[probing_alt]` at `InsertPosition::Back` and `return`
  (no demotion).
- Otherwise fall through to the existing `demote_from_normal_bucket`
  cascade unchanged.

Preserve every v002 invariant: the rescue hop must fire only on a
confirmed non-full alternate so it never itself evicts
(`single_eviction_per_put` holds), it must keep the threaded `&mut Ghost`
plumbing intact (the demote path still records true drops into the ghost
ring), and the ghost fast-track in `put` plus the two-speed promotion and
touch-counter logic stay exactly as they are. Only the probing-eviction
branch changes.

## Rationale (optional)

v002 (ghost gate on dropped-then-recurring keys) and v003 (breadth-of-homes
on warm probing victims) each netted a clean independent positive on
disjoint populations. The cross-cycle open question is whether they
compound or overlap once both ride the winner; this is the direct test.
