# H01

Shrinking 2Q's A1in admission queue to the incumbent's ~5% probationary share, giving the reuse list Am ~95% of capacity, lifts hit-rate toward the 95/5 SLRU incumbent.

## Parent

cycle/0009/v003

## Changes

This is the geometry half of the "race 2Q against the 95/5 incumbent"
thread. The 2Q parent uses the canonical `kin = capacity / 4` (A1in =
25% of capacity), which starves the main reuse list Am relative to the
incumbent's 95% protected tier. Change only the sizing in `try_new`:

- Set `kin = capacity / 20` (≈5% admission floor, mirroring the
  incumbent's `capacity - protected_cap` probationary budget). For
  `capacity == 2048` this is 102, matching the incumbent's ~103-slot
  floor.
- Leave `kout = capacity / 2` unchanged (ghost A1out target).
- Leave `evict_if_needed`, `evict_ghost_if_needed`, `get`, and `put`
  logic exactly as in the parent — only the two field initializers move.

Preserve all invariants: resident count `lens[AM] + lens[A1IN] <=
capacity`, ghost nodes carry `value == None`, and slot reuse via the
free list is unchanged. The hypothesis is confirmed if hit-rate rises
above the parent's 0.7103 and ideally clears the incumbent's 0.7313;
refuted if a tiny A1in chokes admission and hit-rate stalls or drops.

## Rationale (optional)

incumbent's capacity share, with the FIFO admission filter intact, close
the gap? Distinct from H02, which holds geometry fixed and changes the
