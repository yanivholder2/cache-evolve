# H02

Choosing the eviction victim by lowest access frequency within a bounded window of the LRU end, instead of strictly the LRU node, makes the cache scan-resistant and raises hit-rate.

## Parent

cycle/0001/v001

## Changes

Add a saturating `freq: u8` field to `Node`, initialized to 0 on allocation and
reset to 0 whenever a slot is reused for a brand-new key in `put`. Increment
`freq` (saturating) on every access in both `get` and `put`-on-existing-key,
for nodes in either segment.

Replace the victim choice in `put` (currently `prob_head`, falling back to
`prot_head`) with a bounded frequency-aware scan: starting from `prob_head` and
walking `next` toward the MRU end for at most `W` nodes (use `W = 8`), select
the node with the smallest `freq`; break ties toward the LRU-most candidate
(the earliest visited). If the probationary segment is empty, run the same
bounded scan from `prot_head` over the protected segment instead. Evict the
selected node and reuse its slot exactly as today (remove from `map`, `unlink`,
overwrite key/value, reset `freq` to 0, then `push_back_probationary`).

The newly put key is ALWAYS admitted into the probationary MRU end — never
rejected — so put-then-get visibility and the contract suite are preserved.

To stop counters from ossifying, add periodic aging: keep a `u64` access
counter on the cache, increment it on every access, and when it reaches
`capacity * 8`, right-shift (`>>= 1`) the `freq` of every resident node and
reset the access counter. Keep this O(capacity) sweep amortized and rare.

Preserve all invariants: `prob_len + prot_len == map.len()`, residency never
exceeds `capacity`, probationary-first segment preference for the victim search,
and in-place slot reuse. Keep promotion-on-first-hit and
`enforce_protected_budget` unchanged.

## Rationale (optional)

Cycle 0002's continuation names eviction-victim selection and scan resistance as
the orthogonal levers to try once the promotion signal is treated as fixed.
Strict LRU eviction discards a warm probationary key the instant a scan flood
pushes it to the head; a small frequency-weighted window protects keys with
demonstrated reuse without touching the protected tier or the capacity bound.
