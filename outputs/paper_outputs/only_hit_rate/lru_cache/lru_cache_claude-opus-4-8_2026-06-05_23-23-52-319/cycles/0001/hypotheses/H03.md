# H03

Add a per-node reference bit and evict via a CLOCK-style second-chance scan, so recently-accessed keys survive one eviction pass and raise hit-rate.

## Parent

baseline

## Changes

Introduce a frequency-aware eviction using reference bits (CLOCK /
second-chance), keeping the single arena and list but changing what
eviction does.

Implementation:
- Add a `referenced: bool` field to `Node`, initialised `false`.
- On `get` hit: set `referenced = true`. Do **not** unlink/re-push the
  node on a hit (this is the key mechanical difference from the
  baseline's promote-on-get) — recency is now approximated by the bit
  plus list order rather than by moving on every access.
- On `put`-after-miss at capacity, choose the victim with a bounded scan
  from `head`: if the head node's `referenced` bit is set, clear it,
  move that node to the tail (giving it a second chance), and advance to
  the new head; evict the first node whose bit is already clear. The
  scan visits at most `capacity` nodes and is guaranteed to find a
  victim (a full pass clears all bits), so it terminates and frees
  exactly one slot — P1 capacity bound holds.
- New entries are pushed at the tail with `referenced = false` and
  registered in the map; the reused slot's bit is reset on insertion.

Values are stored only for resident keys and the map mirrors residency,
so P2 value_fidelity and P3 no_phantom_items are preserved.

## Rationale (optional)

CLOCK approximates LFU-style protection with O(1) amortised cost and no
second list, making it a mechanism distinct from segmentation (H01) and
insertion-position bias (H02) while still targeting hit-rate.
