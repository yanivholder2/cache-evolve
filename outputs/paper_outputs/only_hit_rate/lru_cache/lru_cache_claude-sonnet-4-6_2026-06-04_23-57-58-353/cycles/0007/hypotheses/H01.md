# H01

Dynamically widening the protected segment when demotion pressure forces out warm entries will improve hit rate by better matching protected capacity to the hot working-set size on workload-a.

## Parent

cycle/0006/v001

## Changes

Add two fields to `LruCache`: `imbalance: i32` (init 0) and `op_count: u64` (init 0). Increment `op_count` on every `get()` call and every `put()` call for a new key (not re-puts).

**Signal collection** — in `demote_prot_head()`, after selecting the victim: if `victim.freq >= 2` (a warm entry is being forced out under pressure), do `self.imbalance -= 1`. In `put()` on a ghost hit (immediately after the ghost set check confirms a hit): do `self.imbalance += 1`.

**Adaptation step** — at the end of every `put()` for a new key, after `op_count` is incremented, compute `adapt_interval = (self.capacity / 8).max(1)`. When `self.op_count % adapt_interval == 0`, apply exactly one adaptation:
- If `imbalance < 0` and `prot_cap < capacity * 9 / 10`: `prot_cap += 1; prob_cap -= 1; ghost_cap = prob_cap`
- If `imbalance > 0` and `prob_cap > (capacity / 10).max(1)`: `prot_cap -= 1; prob_cap += 1; ghost_cap = prob_cap`
- Reset `imbalance = 0` in either branch (do nothing if neither condition applies)

All other logic — frequency counting, counter halving on demotion, MAX_FREQ cap, referenced-bit tie-breaker in `demote_prot_head()`, probationary min-freq scan of LRU half, ghost set membership tracking — is unchanged from the parent. The 80/20 split is the starting configuration.

**Invariants to preserve**: `prot_cap + prob_cap == capacity` at all times. `ghost_cap` must equal `prob_cap` after any adjustment to keep the ghost set sized to the probationary segment.

## Rationale

Two consecutive cohorts have produced neutral winners at the fixed 80/20 split, suggesting either the split is optimal or the adaptation signal is absent with a static ratio. The cross-cycle insight explicitly identifies adaptive segment-ratio balancing as an untested direction. Ghost hits on workload-a are rare, so `imbalance` is expected to drift negative when warm entries are demoted under pressure, causing `prot_cap` to grow until it accommodates the hot working set. The bounded clamp prevents over-correction.
