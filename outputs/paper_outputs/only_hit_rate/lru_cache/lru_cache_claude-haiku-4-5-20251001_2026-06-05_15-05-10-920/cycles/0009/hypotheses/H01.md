# H01

Apply per-access frequency decay proportional to elapsed operations since last access to improve cache responsiveness to gradual access pattern phase shifts without relying on fixed-interval periodic decay.

## Parent

cycle/0004/v003

## Changes

The parent variant uses periodic bulk frequency decay: every capacity × 16 operations, all node frequencies are multiplied by 0.75×. This approach assumes phase shifts occur at regular intervals, but real workloads may transition more gradually.

Replace the periodic decay mechanism with per-access decay:

1. Add a new field to the Node struct: `last_access_counter: u64` to track when each node was last accessed
2. Add to LruCache: `global_operation_counter: u64` to count total operations
3. Remove the `frequency_reset_counter` and `check_and_perform_frequency_reset()` periodic decay mechanism entirely
4. In the `get()` method, after incrementing node frequency, apply decay based on operation delta:
   ```rust
   let ops_since_access = self.global_operation_counter - self.nodes[idx].last_access_counter;
   let decay_factor = if ops_since_access > 64 { 
       (self.nodes[idx].freq as u16 * (128_u16.saturating_sub((ops_since_access / 64) as u16))) / 128 
   } else { 
       self.nodes[idx].freq as u16 
   } as u8;
   self.nodes[idx].freq = decay_factor;
   self.nodes[idx].last_access_counter = self.global_operation_counter;
   ```
5. In the `put()` method's new-key eviction logic, apply the same decay formula to candidate victims based on their last_access_counter when computing minimum frequency for eviction

This change makes frequency decay responsive to workload dynamics rather than clock-based intervals, potentially capturing phase shifts more efficiently.

## Rationale

Cycle 0008 confirmed the 0.75× coefficient is locked in and the capacity × 16 interval is robustly tuned. However, both findings assume *periodic* decay is the optimal triggering mechanism. The workload may contain gradual phase transitions that periodic boundaries miss, while per-access decay could adapt smoothly without introducing statistical tracking overhead. This tests whether the bottleneck is the decay *curve* (locked in) or the decay *timing model* (fixed interval vs. activity-responsive).
