# H03

Apply frequency decay only to items with frequency ≥ 4, leaving cold items (frequency < 4) untouched, to focus decay on truly hot items while preserving cold-item temporal structure and improve hit-rate.

## Parent

baseline

## Changes

In the `check_and_perform_frequency_reset()` function, modify the decay loop to apply selective decay:

Replace the current loop:

```rust
for node in &mut self.nodes {
    node.freq = (node.freq as u16 * 3 / 4) as u8;
}
```

with:

```rust
for node in &mut self.nodes {
    if node.freq >= 4 {
        node.freq = (node.freq as u16 * 3 / 4) as u8;
    }
}
```

This retains the 0.75× multiplicative decay coefficient and capacity × 16 reset interval, but applies decay selectively only to items whose frequency has reached 4 or higher. Cold items (frequency 0–3) retain their frequencies across decay cycles, preserving their historical access record while focusing decay overhead on the hot end of the frequency spectrum where forgetting matters most.

## Rationale (optional)

The cross-cycle insights explicitly identify "threshold-dependent or piecewise decay" as unexplored territory and note: "Could lower-cost alternatives—such as decaying only frequencies above a threshold, applying different rates to hot vs. cold items, or frequency-dependent decay coefficients—bypass the plateau without abandoning the baseline?" This hypothesis tests the simplest threshold-dependent variant: protecting cold items from decay while aging out hot frequencies. This reduces decay's impact on low-frequency items that may have genuine reuse value, while still forcing the cache to forget truly ancient hotspots. The threshold of 4 is chosen as a conservative cutoff representing items accessed at least 4 times.
