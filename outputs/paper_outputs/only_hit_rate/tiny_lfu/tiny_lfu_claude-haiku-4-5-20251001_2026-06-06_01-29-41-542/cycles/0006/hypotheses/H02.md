# H02

Incorporate item size into eviction victim-selection scoring to bias eviction toward smaller items, reducing the byte-cost of evictions while preserving frequency-age logic for correctness.

baseline

## Changes

Modify the victim-selection scoring logic in the `put()` method to incorporate item size. Within the victim-finding loop (lines 103-113 in the current evolved code), change the score calculation from `score = age / (frequency + 1)` to `score = (age / (frequency + 1)) * size_penalty`, where `size_penalty = 1.0 / (1.0 + normalize_size)` and `normalize_size = item_value.len() / average_cache_item_size`. Compute `average_cache_item_size` as the total bytes cached divided by number of items. This biases victim selection toward smaller items: small items get score multipliers < 1.0 (lower priority for eviction), while large items get multipliers > 1.0 (higher priority). The frequency-age signal determines correctness; size determines cost efficiency. Test whether this orthogonal signal improves overall cache performance by reducing eviction overhead.
