# H01

Add frequency-ranked victim sampling over the probationary segment to v003's SLRU so eviction drops the coldest probationary key instead of always the probationary LRU head, raising hit-rate.

## Parent

cycle/0004/v003

## Changes

In `put()`, the full-cache branch currently takes `self.prob_head` as the sole
victim. Replace that with a bounded forward scan of the probationary list:
start at `prob_head`, follow `next` (which stays within the probationary
segment, since v003 keeps probationary and protected as separate lists), and
visit up to `SAMPLE` nodes, tracking the one with the lowest
`sketch.estimate(key)` as the victim. Add a module constant `const SAMPLE:
usize = 5;`. Break ties toward the node nearest `prob_head` (most-LRU) by using
a strict `<` while scanning head→tail. Keep the admission gate exactly as-is
(`incoming_freq > victim_freq`, where `victim_freq` is now the sampled
minimum), and reuse the existing `unlink`/`push_back_prob`/map-update path on
the chosen victim index. Preserve all SLRU invariants: do not touch the
protected list during the scan, leave `protected_len`/`protected_cap`
bookkeeping unchanged, and ensure the victim is always a probationary node so a
full cache still always yields a victim.

## Rationale (optional)

v003 and v002 each proved SLRU and frequency-ranked victim sampling are
independently directionally-positive but were never combined; this tests
whether spending the sharp sketch on victim choice *within* the probationary
tier clears the noise floor that each lever hovered at alone.
