# H02

Introducing a very slow periodic count-halving (every `sketch_width * 8` operations) on the 8× wide sketch prevents count inflation on long traces and improves temporal relevance, raising hit rate above v001's 0.7435.

## Parent

cycle/0007/v001

## Changes

In the overlay `src/tiny_lfu/mod.rs`, modify `CountMinSketch` to add decay tracking and a periodic halving step.

**1. Add fields to `CountMinSketch`:**

```rust
struct CountMinSketch {
    width: usize,
    depth: usize,
    counts: Vec<Vec<u32>>,
    op_count: u64,
    decay_interval: u64,
}
```

**2. Update `CountMinSketch::new()` to initialise the new fields:**

```rust
fn new(width: usize) -> Self {
    let depth = SKETCH_DEPTH;
    let counts = vec![vec![0; width]; depth];
    let decay_interval = (width as u64) * 8;
    Self { width, depth, counts, op_count: 0, decay_interval }
}
```

`decay_interval` is set to `width * 8`. At capacity=2048 with SKETCH_WIDTH_FACTOR=8 the sketch width is 16384, giving a decay interval of 131 072 operations — roughly 64 full passes over the cache between halvings.

**3. Add a private `maybe_decay()` method to `CountMinSketch`:**

```rust
fn maybe_decay(&mut self) {
    self.op_count += 1;
    if self.op_count >= self.decay_interval {
        self.op_count = 0;
        for row in self.counts.iter_mut() {
            for cell in row.iter_mut() {
                *cell >>= 1;
            }
        }
    }
}
```

**4. Call `maybe_decay()` at the end of `CountMinSketch::increment()`:**

After the existing conservative-update loop that increments rows at the minimum, add a single call:

```rust
self.maybe_decay();
```

No changes to `estimate()`, `position()`, or any cache-level logic. The SLRU structure, k=4 victim scan, PROMO_THRESHOLD=8, was_protected bypass, conservative update semantics, 8× sketch width, and SKETCH_DEPTH=4 are all preserved from v001.

## Rationale

Prior sketch-aging experiments (cycles 0001 and 0002) regressed at aggressive to moderate cadences because halving too frequently stripped hot-item signal. The cycle-0007 insight explicitly flags whether the 8× width changes this dynamic as an open question: the narrower collision profile means counts are more accurate, and the higher per-item counts accumulated by truly hot items provide a larger buffer against decay. A `width * 8` interval is 8× slower than the canonical CMS halving recommendation (`width` increments), far outside the range that previously failed. Halving right-shifts all cells by 1, so items with counts well above the threshold retain their signal through multiple decay cycles while counts from one-time accesses quickly fall to zero, naturally sharpening the frequency ranking.
