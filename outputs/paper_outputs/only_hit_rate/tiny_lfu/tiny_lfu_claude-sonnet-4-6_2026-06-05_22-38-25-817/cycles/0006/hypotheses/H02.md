# H02

Replacing standard CountMinSketch increment semantics with conservative update — incrementing only the sketch rows that currently hold the minimum count for a key — reduces systematic overcounting and sharpens the frequency estimates used by both the k=4 victim scan and the PROMO_THRESHOLD gate, improving hit rate.

## Changes

Modify `CountMinSketch::increment()` to use conservative update semantics. No other functions or constants change.

Current implementation increments `self.counts[row][pos]` for every row unconditionally (subject to the `MAX_COUNT` cap).

New implementation:
1. Before the per-row loop, compute the current minimum estimate: `let current_min = self.estimate(key);`.
2. Inside the loop, only increment `self.counts[row][pos]` if `self.counts[row][pos] <= current_min` (i.e., this row is at the minimum; incrementing it will not push it above the true minimum). The `MAX_COUNT` guard remains unchanged.

The function signature, return type, and all callers remain the same. `estimate()` is unchanged.

Concretely, replace the body of `increment()` with:

```rust
fn increment<K: Hash>(&mut self, key: &K) {
    let current_min = self.estimate(key);
    for row in 0..self.depth {
        let pos = self.position(key, row as u64);
        let counter = &mut self.counts[row][pos];
        if *counter <= current_min && *counter < MAX_COUNT {
            *counter += 1;
        }
    }
}
```

## Rationale

Standard CMS increment blindly raises all rows, causing over-estimation whenever two keys collide in the same bucket. Conservative update lifts only the rows that are at the current minimum, tightening the estimate without requiring a wider sketch. This is a well-known improvement to CMS accuracy with no memory cost. Given that hit rate at the current optimum is determined by the fidelity of frequency discrimination in the k=4 scan and the PROMO_THRESHOLD gate, sharpening estimates without changing any other knob is a clean test of whether sketch noise is still a limiting factor.
