# H01

Doubling the per-bucket stash capacity from `bucket_size / 4` to `bucket_size / 2` will increase hit rate by retaining more medium-frequency items through cold-burst insertions before stash overflow discards them.

## Parent

cycle/0002/v001

## Changes

In `src/associative_cache/associative_cache_bucket.rs`, in `AssociativeCacheBucket::new()`, change the `stash_max_size` initialisation line from:

```rust
stash_max_size: (settings.bucket_size / 4).max(1),
```

to:

```rust
stash_max_size: (settings.bucket_size / 2).max(1),
```

No other changes. The `stash_push()`, `evict_to_stash()`, `get()`, and `put()` logic are all preserved exactly as in the parent; only the stash capacity bound changes. The invariant that primary items and stash items are disjoint is unaffected because it is enforced by the promotion-and-remove path, not by the size limit.

## Rationale

The cycle-insight open question asks whether `bucket_size / 4` is the right stash size. A small stash caps how many displaced items can survive a burst; if the hot set plus the burst together exceed `primary + stash` capacity the oldest stash entries are dropped by FIFO before they can be re-accessed. A larger stash extends the survival window at the cost of slightly more memory per bucket. This hypothesis isolates the capacity dimension from the eviction-within-stash dimension tested by H02.
