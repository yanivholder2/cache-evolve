# H03

Filtering zero-frequency items from entering the stash — discarding evicted items that have never been accessed rather than storing them — will raise hit rate by reserving all stash capacity for items with at least one demonstrated access.

## Parent

cycle/0003/v003

## Changes

In `associative_cache_bucket.rs`, modify `evict_to_stash()` to only call `stash_push` when the evicted item has `lfu_counter >= 1`. Items evicted with `lfu_counter == 0` are silently dropped rather than written into the stash.

Current code:
```rust
fn evict_to_stash(&mut self) {
    if self.items.is_empty() {
        return;
    }
    let idx = self.eviction_policy.eviction_candidate_index(&self.items);
    let evicted = self.items.remove(idx);
    self.stash_push(evicted);
}
```

Replace with:
```rust
fn evict_to_stash(&mut self) {
    if self.items.is_empty() {
        return;
    }
    let idx = self.eviction_policy.eviction_candidate_index(&self.items);
    let evicted = self.items.remove(idx);
    if evicted.lfu_counter >= 1 {
        self.stash_push(evicted);
    }
}
```

No other changes. The stash capacity, FIFO ordering, promotion credit (+2), and all other bucket logic remain exactly as in cycle/0003/v003.

## Rationale

The stash acts as a second-chance buffer. Items evicted from primary with `lfu_counter == 0` have never been accessed since insertion; they entered the bucket only to fill a slot and were displaced on the very next cold-burst arrival. Granting these items a stash slot consumes capacity that could hold an item with real reuse history. On a Zipfian-access workload like workload-a, a meaningful fraction of primary evictions are these pure cold-start items. Filtering them out ensures every stash slot is occupied by a candidate with at least one prior hit, making the second-chance promotion mechanism more precise.
