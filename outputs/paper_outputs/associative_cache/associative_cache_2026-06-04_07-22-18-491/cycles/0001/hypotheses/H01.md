# H01

Changing `ClassicLRU` eviction to select the least-frequently-used victim (with position-order tie-breaking) while retaining move-to-back on access improves hit rate by shielding hot items from displacement.

## Parent

baseline

## Changes

Edit `src/shared/eviction_policy.rs` — modify only the `ClassicLRU` impl; leave all other policy structs and `EvictionPolicyKind` untouched.

**`ClassicLRU::get_from_position`** — after removing the item and pushing it to the back (existing move-to-back), increment the counter on the newly placed item:

```rust
fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
    let item = items.remove(position);
    items.push(item);
    let back = items.len() - 1;
    items[back].lfu_counter += 1;
    back
}
```

**`ClassicLRU::eviction_candidate_index`** — replace the hard-coded `0` with a linear scan that picks the item with the smallest `lfu_counter`, breaking ties by vector index (smallest index = oldest, so ties resolve in LRU order):

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    items
        .iter()
        .enumerate()
        .min_by_key(|(i, item)| (item.lfu_counter, *i))
        .map(|(i, _)| i)
        .unwrap_or(0)
}
```

**`ClassicLRU::promotion_candidate_index`** — keep as `items.len() - 1` (most recently accessed item, now also the one with the highest accumulated counter after a hit).

No changes to `Item`, `AssociativeCacheBucket`, or any other file. The `lfu_counter` field is already present on every `Item` and initialised to `0`; this change begins writing it for the ClassicLRU policy.

## Rationale

The baseline ClassicLRU evicts purely by recency: the item that has not been accessed for the longest time. On LIRS traces with Zipfian skew (workload-a), a small fraction of items receives the vast majority of accesses. Pure LRU can evict these hot items when they are temporarily displaced in position by a burst of cold-item puts. Selecting the LFU candidate instead protects high-frequency items while the position-order tie-break ensures that among equally infrequent items the oldest one is still evicted first, preserving LRU behaviour for the cold working set.
