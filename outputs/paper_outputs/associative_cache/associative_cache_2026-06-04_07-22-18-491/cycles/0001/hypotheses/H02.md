# H02

Removing the `timestamp: Instant` field from `Item` shrinks `sizeof::<Item<u64,u64>>()` from 40 bytes to 24 bytes, improving the metadata-size fitness dimension by 40%.

## Parent

baseline

## Changes

Two files need coordinated edits. No other files should be touched.

### `src/shared/item.rs`

1. Remove `use std::time::Instant;` from the imports.
2. Remove the `pub timestamp: Instant` field from the `Item<K, V>` struct.
3. In `Item::new`, remove the `timestamp: Instant::now()` initialiser line.
4. In the `Display` impl, remove `timestamp: {:?}` from the format string and remove `self.timestamp` from the argument list.

The resulting `Item<u64, u64>` layout is: `key: u64` (8 bytes) + `value: u64` (8 bytes) + `lfu_counter: usize` (8 bytes) = 24 bytes, a 16-byte reduction.

### `src/shared/eviction_policy.rs`

`TimestampLRU` is the only policy that reads or writes `item.timestamp`; it must be patched so it compiles and still satisfies the `EvictionPolicy` contract.

1. Remove `use std::time::Instant;` from the imports (no longer needed).
2. **`TimestampLRU::get_from_position`** — replace the body `items[position].timestamp = Instant::now(); position` with a no-op that simply returns `position` unchanged:
   ```rust
   fn get_from_position(&self, _items: &mut Vec<Item<K, V>>, position: usize) -> usize {
       position
   }
   ```
3. **`TimestampLRU::eviction_candidate_index`** — replace the `min_by_key(timestamp)` scan with `0` (evict from the front, oldest by insertion order — equivalent to FIFO):
   ```rust
   fn eviction_candidate_index(&self, _items: &[Item<K, V>]) -> usize {
       0
   }
   ```
4. **`TimestampLRU::promotion_candidate_index`** — replace the `max_by_key(timestamp)` scan with `items.len() - 1`:
   ```rust
   fn promotion_candidate_index(&self, items: &[Item<K, V>]) -> usize {
       items.len() - 1
   }
   ```

`TimestampLRU`'s `name()` stays `"TimestampLRU"` and its ordinal index stays `1` so JNI round-trips remain valid. All other policy impls (`ClassicLRU`, `Lfu`, `Lifo`, `Fifo`, `Swap`) do not touch `timestamp` and need no changes.

## Rationale

Every `Item` in the baseline carries a 16-byte `Instant` timestamp that is read only by `TimestampLRU` — the policy not selected for evaluation. The baseline simulation runs with ClassicLRU (policy ordinal 0), which never consults `timestamp`, so the field is dead weight in every bucket slot. Removing it cuts per-item overhead by 40% and directly reduces the metadata-size fitness dimension summary from 40 to 24, without altering ClassicLRU hit-rate behaviour.
