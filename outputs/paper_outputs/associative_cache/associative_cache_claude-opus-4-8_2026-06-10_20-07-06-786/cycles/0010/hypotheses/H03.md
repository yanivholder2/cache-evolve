# H03

Evicting the *newest* unpromoted probationary item instead of the oldest (scan-resistant MRU probation eviction) raises hit-rate on the LIRS trace by freezing older near-promotion keys against scan/loop bursts.

## Changes

The established SLRU bucket (`src/associative_cache/associative_cache_bucket.rs`) admits new keys at the probationary front (index 0, the newest) and evicts the *oldest* probationary item — the boundary slot at `idx = len - protected_count - 1` returned by `eviction_candidate_index`. This is a FIFO probation: every newcomer gets a full lap before eviction.

Test the opposite probation discipline. Change only the probationary branch of `eviction_candidate_index` to return the newest unpromoted slot, index `0`, instead of `len - protected_count - 1`:

```rust
fn eviction_candidate_index(&self) -> Option<usize> {
    if self.items.is_empty() {
        None
    } else if self.protected_count == self.items.len() {
        Some(0)                      // all-protected: unchanged, protected LRU end
    } else {
        Some(0)                      // probationary: evict the NEWEST unpromoted item
    }
}
```

Index 0 is always probationary whenever `protected_count < len` (it sits in the prefix `[0, k)`), so the victim is unprotected and `protected_count` stays correct (`evict_item` only decrements on a protected victim, which this branch never selects). Keep admission at index 0, single-hit immortal promotion, the get-path MRU move, and the protected-suffix invariant exactly as in baseline. Note the dynamic: a fresh miss inserts at 0, and the next miss evicts whatever currently sits at 0 — so one-hit-wonders and scan/loop traffic churn through a single probationary slot while older probationary keys in `[1, k)` are shielded until they earn promotion.

This is a genuine behavioural change (not a cost rewrite): hit-rate will move. The thesis is that the LIRS workload's scan/loop segments are better resisted by discarding the most-recent unproven key first, protecting the keys closest to a promoting second hit.

## Rationale (optional)

The cross-cycle ledger credits FIFO probation but does not record a clean test of MRU/scan-resistant probation eviction; the open question explicitly asks whether any untested trace-structure axis remains. This is a one-line, invariant-safe probe of that axis with a defensible upside on a scan-heavy trace, and a clear negative result would further confirm the ceiling.
