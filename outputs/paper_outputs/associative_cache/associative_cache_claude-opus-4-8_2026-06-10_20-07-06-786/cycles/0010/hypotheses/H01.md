# H01

Stacking all three banked cost rewrites (u64 logical clock + rotate-left get + rotate-replace put) onto the winning geometry-halving variant holds hit-rate at 0.7284 while improving per-op-time and metadata-size, answering whether the rewrites compose observably.

## Parent

cycle/0009/v002

## Changes

v002 already carries the one capacity-conserving geometry halving (`src/shared/geometry.rs`), the `rotate_left`-based MRU promotion on the get path, the O(1) `eviction_candidate_index`, and the `protected_count` bookkeeping in `src/associative_cache/associative_cache_bucket.rs`. It still uses the unmodified `Instant` timestamp in `src/shared/item.rs` and a generic `evict_item()` + `items.insert(0, item)` admission in `put`.

Consolidate the other two banked rewrites into v002:

1. **Metadata (from cycle/0009/v001):** In `src/shared/item.rs`, replace the `Instant`-typed `Item.timestamp` with a process-global monotonic `AtomicU64` logical clock exposed via `next_timestamp()`, and have `TimestampLRU` read the u64 in its `min_by_key`/`max_by_key`. This shrinks `Item<u64,u64>` from 40 to 32 bytes. Preserve the exact total age order (smaller = older) so every victim/promotion choice stays identical; bump the counter at the same sites the old `Instant::now()` was read (item creation and the get-path refresh).

2. **Put path (from cycle/0009/v003):** In `put`, fold the boundary-eviction case (`protected_count < len`) into a prefix `self.items[..=idx].rotate_right(1)` (where `idx = len - protected_count - 1`) plus an in-place `std::mem::replace(&mut self.items[0], item)`, returning the replaced victim. Keep the all-protected case (`protected_count == len`) on the existing remove+insert fallback.

Preserve all invariants: the probationary-prefix/protected-suffix partition, `protected_count == len - k`, single-hit immortal promotion, FIFO probation eviction order, and byte-identical post-states. The expected result is an exact hit-rate tie (0.7284); the value is verifying the three independent cost rewrites stack without interaction and banking the combined cost profile in one variant.

## Rationale (optional)

The last four cycles flagged the open question of whether the stackable cost rewrites change anything observable once all adopted. This builds the single fully-consolidated variant that settles it, derived from the proven best-so-far so any hit-rate movement would be a genuine interaction signal rather than noise.
