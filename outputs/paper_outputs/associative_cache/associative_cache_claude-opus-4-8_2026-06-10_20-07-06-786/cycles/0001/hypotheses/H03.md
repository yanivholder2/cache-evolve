# H03

Admitting newly inserted keys into a probationary front slot, so they are evicted first unless re-hit, raises hit rate on scan-heavy access by protecting the established working set.

## Parent

baseline

## Changes

Overlay `src/associative_cache/associative_cache_bucket.rs` to change *where a
new key lands* inside its home bucket — a scan-resistance / second-chance
movement — while leaving the eviction-policy enum and all routing untouched.

Override the `Bucket::put` default for `AssociativeCacheBucket` as follows:

1. If the key already exists (`get_position` returns `Some`), behave exactly as
   the baseline: overwrite the value in place and apply the policy's
   `get_from_position` (promotion). Return `(&inserted, None)`.
2. If the key is new and the bucket is full, evict via the existing
   `evict_item()` path (front item under ClassicLRU), then `insert` the new
   item at index `0` (the eviction-candidate end) instead of pushing to the
   back. If the key is new and the bucket is not full, also insert at index `0`.
3. Return `(&inserted, evicted)` with the reference pointing at the newly
   inserted item at its actual index.

Because hits still promote toward the back via the unchanged
`get_from_position`, a fresh key sits at the front as "probationary" and is the
next victim until it earns a hit; one-hit-wonders and scan traffic are flushed
quickly while re-used keys migrate to safety. This is distinct from H02
(frequency-based victim choice) and H01 (geometry): it changes the *insertion
position*, not the victim rule or the bucket count.

Invariants to preserve: still evict exactly one item before inserting into a
full bucket (P1); inserted keys must remain findable by `get_position` (P3); no
cross-bucket relocation (P2). Keep this file's `#[cfg(test)]` module compiling
and passing.
