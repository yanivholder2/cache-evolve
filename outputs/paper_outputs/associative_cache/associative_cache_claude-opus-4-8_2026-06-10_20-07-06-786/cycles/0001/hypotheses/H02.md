# H02

Selecting the eviction victim by hit-frequency instead of pure insertion-recency raises hit rate by retaining proven-hot keys within each bucket.

## Parent

baseline

## Changes

Overlay `src/associative_cache/associative_cache_bucket.rs` to make the bucket
do recency+frequency-aware *intra-bucket* movement, without adding a new
`EvictionPolicyKind` variant (the enum and its JNI ordinal mapping stay
untouched).

Two overrides on the `Bucket` impl for `AssociativeCacheBucket`:

1. Override `get_from_position(&mut self, position)` so that, on every hit, it
   (a) increments `self.items[position].lfu_counter` by 1, then (b) moves that
   item to the back of `items` (same MRU promotion the baseline ClassicLRU
   path performs). Return a reference to its new index. This makes
   `lfu_counter` a live per-item hit count even though the configured policy is
   ClassicLRU, which otherwise never touches it.
2. Override `eviction_candidate_index(&self) -> Option<usize>` (the trait
   default delegates to the policy) so that, when the bucket is non-empty, it
   returns the index of the item with the **minimum `lfu_counter`**, breaking
   ties toward the **front** (oldest position). Return `None` on an empty
   bucket.

Net effect: a key that has earned hits resists eviction; among never-re-hit
keys the least-recently-inserted one goes first, preserving the baseline's
recency behaviour as the tie-break.

Invariants to preserve: keep `put`, `get`, and `get_position` semantics intact
so residents stay retrievable (P3); never exceed `max_size` (P1 — still evict
exactly one item before pushing into a full bucket); and never relocate an item
to another bucket (P2). Keep the existing `#[cfg(test)]` module in this file
compiling and passing.
