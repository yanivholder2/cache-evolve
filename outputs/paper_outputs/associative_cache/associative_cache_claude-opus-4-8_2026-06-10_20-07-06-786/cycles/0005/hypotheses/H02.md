# H02

Admit a key that was recently evicted from this bucket straight into the protected segment via a small in-bucket ghost ring, raising hit-rate on returning keys.

## Parent

cycle/0003/v002

## Changes

In the parent, every new key — including one that was a proven hot key evicted
one access ago — is re-admitted to the probationary front (`index 0`,
`lfu_counter == 0`) and must earn promotion all over again. On a collision-bound
trace, a recurring key repeatedly pays full probation. Add a bounded ghost
memory of recently-evicted keys so a returning key skips probation:

1. Add a field to `AssociativeCacheBucket`, e.g.
   `ghost_keys: std::collections::VecDeque<K>`, initialised empty in `new()`
   with a small fixed capacity (bound it to `settings.bucket_size` so metadata
   growth stays tiny — keys only, no values, no timestamps).

2. Record evictions: override the eviction path so that whenever `put` evicts an
   item (the `Some(evicted)` branch), push `evicted.key` onto `ghost_keys`,
   popping the front when length exceeds the capacity bound (FIFO ring).

3. Re-admission in `put`: when inserting a key that is *not* already resident,
   check `ghost_keys`. If the key is present there, admit it as already-proven —
   set `lfu_counter = 1` and insert it at the protected MRU back (`push`) rather
   than the probationary front, and remove it from `ghost_keys`. If absent,
   admit probationary at `index 0` exactly as the parent does.

Preserve `eviction_candidate_index` and the hit-path `get_from_position`
unchanged, and keep the existing FIFO-probation / promote-on-first-hit
semantics for never-before-seen keys. Keep the ghost ring strictly bounded so
the metadata footprint stays small.

## Rationale (optional)

This is an ARC/2Q/LIRS-style ghost reentry confined to the proven productive
surface (admission within the bucket). It strengthens protection for keys that
have already demonstrated value, which is the direction every hit-rate win in
this run has come from — distinct from H01, which discriminates *among* resident
protected keys rather than accelerating *re-entry*.
