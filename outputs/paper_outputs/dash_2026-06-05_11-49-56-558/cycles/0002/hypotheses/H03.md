# H03

Replacing pure LFU with an aging-LFU policy — where every bucket hit also decrements all non-accessed items' counters by one — will prevent stale early-access counts from permanently occupying slots and improve hit-rate over the baseline on workload-a.

## Parent

baseline

## Changes

Two files require changes.

**1. `src/shared/eviction_policy.rs`** — add a new `AgingLfu` struct and register it in `EvictionPolicyKind`.

Add the following struct declaration after the existing `Lfu` struct:

```rust
/// LFU with passive aging: each hit increments the accessed item's counter by 2
/// and saturating-decrements every other item's counter by 1. Net effect: +1 for
/// the hot item, −1 for all cold co-residents. Prevents early-popularity items
/// from holding slots after their access rate drops.
#[derive(Debug)]
pub struct AgingLfu;
```

Add the following trait implementation:

```rust
impl<K, V> EvictionPolicy<K, V> for AgingLfu
where
    K: Hash + Eq + Copy + Debug,
    V: Eq + Copy + Debug,
{
    fn name(&self) -> &'static str {
        "AgingLfu"
    }

    fn get_from_position(&self, items: &mut Vec<Item<K, V>>, position: usize) -> usize {
        for (i, item) in items.iter_mut().enumerate() {
            if i == position {
                item.lfu_counter = item.lfu_counter.saturating_add(2);
            } else {
                item.lfu_counter = item.lfu_counter.saturating_sub(1);
            }
        }
        position // no reordering; LFU is order-independent
    }

    fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
        items
            .iter()
            .enumerate()
            .min_by_key(|(_, item)| item.lfu_counter)
            .expect("eviction_candidate_index precondition: non-empty")
            .0
    }

    fn promotion_candidate_index(&self, items: &[Item<K, V>]) -> usize {
        items
            .iter()
            .enumerate()
            .max_by_key(|(_, item)| item.lfu_counter)
            .expect("promotion_candidate_index precondition: non-empty")
            .0
    }
}
```

Register `AgingLfu` in `EvictionPolicyKind` by making these targeted edits:

- Add `AgingLfu` as a new enum variant.
- Update `all()`: change the return type from `[Self; 6]` to `[Self; 7]`, add `AgingLfu` to both the `_exhaustive` match arm and the returned array.
- Update `name()`: add arm `EvictionPolicyKind::AgingLfu => "AgingLfu"`.
- Update `index()`: add arm `EvictionPolicyKind::AgingLfu => 6`.
- Update `all_names()`: change return type from `[&'static str; 6]` to `[&'static str; 7]`.
- Update `build()`: add arm `EvictionPolicyKind::AgingLfu => Box::new(AgingLfu)`.

**2. `src/dash/dash_bucket.rs`** — force `AgingLfu` in `new_bucket`, discarding the caller-supplied policy (same pattern v002 used for `Lfu`).

Add `use crate::shared::eviction_policy::EvictionPolicyKind;` to the imports at the top of the file.

Replace the body of `new_bucket`:

pub fn new_bucket<K, V>(
    max_size: usize,
    _eviction_policy: Box<dyn EvictionPolicy<K, V>>,

## Rationale

v002 showed pure LFU beats LRU on workload-a's frequency-skewed access pattern, but pure LFU has a known weakness: items that accumulate high counts early in the trace never vacate even after their access rate drops. Aging-LFU keeps the frequency signal while continuously discounting stale counts, making the hot set responsive to access-pattern shifts. This is a strictly different mechanism from v002 and is explored from baseline to isolate the policy effect independently of any topology change.
