# H02

Pushing the normal/stash split from 50/50 to 75/25 will further raise hit-rate on workload-a by expanding hot-tier capacity beyond what v003 tested.

## Parent

cycle/0001/v003

## Changes

In `src/shared/geometry.rs`, modify the `layout` method of `BaselineGeometry`. Replace the existing 50/50 computation:

```rust
let normal = (total_buckets / 2).max(2);
let stash = total_buckets - normal;
```

With a 75/25 computation:

```rust
let normal = (total_buckets * 3 / 4).max(2);
let stash = (total_buckets - normal).max(1);
```

For the production harness settings (32 total buckets: 8 normal + 24 stash in the baseline), this yields 24 normal + 8 stash, compared to v003's 16/16. The `.max(2)` clamp on `normal` preserves the invariant `num_of_normal_buckets >= 2` (required for probing) for all proptest-generated edge cases. The `.max(1)` clamp on `stash` ensures at least one stash slot exists; note that when `total_buckets` is small (e.g. 3) the formula produces `normal = max(2, 2) = 2`, `stash = max(1, 1) = 1`, which is valid.

No other file needs to change — `dash_segment.rs` and `eviction_policy.rs` are inherited from v003 unchanged.

## Rationale

The cycle-1 insight explicitly asked whether the normal/stash gain curve has a peak or break point beyond 16/16. v003 confirmed that 16/16 beats 8/24; this hypothesis probes the next meaningful checkpoint (24/8) to determine whether more hot-tier capacity is still beneficial or whether the working set is saturated at 16 normal buckets.
