# H02

A bounded ghost-key set that re-admits recently stash-evicted keys directly into their target bucket (bypassing stash re-entry) raises hit rate by cutting the promotion-ladder delay for items cycling at the stash eviction boundary.

## Parent

cycle/0003/v002

## Changes

Starting from v002's overlay (geometry.rs with 75/25 split preserved unchanged; dash_segment.rs with `InsertPosition::Back` stash-to-target promotion), modify only `dash_segment.rs` to add a ghost-set field to `DashSegment`, override `Segment::put` to perform ghost-set lookup, and track stash evictions.

### 1. Imports and constant

Add to the top of `dash_segment.rs`:

```rust
use std::collections::VecDeque;

const GHOST_CAPACITY: usize = 32; // bounded ghost set — ~4× a typical 8-slot stash
```

### 2. `DashSegment` struct: add `ghost_keys` field

```rust
pub struct DashSegment<K, V>
where
    K: Hash + Eq + Copy + Debug + 'static,
    V: Eq + Copy + Debug + 'static,
{
    core: SegmentCore<K, V>,
    ghost_keys: VecDeque<K>,   // ← add this field
}
```

### 3. `try_new` / `new`: initialise ghost set

In `try_new`, change the construction to:

```rust
Some(Self { core, ghost_keys: VecDeque::with_capacity(GHOST_CAPACITY) })
```

(The `new` constructor delegates to `try_new` unchanged.)

### 4. Override `Segment::put` in the `impl Segment<K, V> for DashSegment<K, V>` block

Add `fn put` to the impl (the trait has a default but we override it here):

```rust
fn put(&mut self, item: Item<K, V>) {
    debug_assert!(
        !self.core.contains_key(&item.key),
        "put: key={:?} already present — caller must not re-insert a resident key",
        item.key
    );

    // Ghost re-admission: if this key was recently evicted from stash, bypass
    // stash and insert directly into its target bucket at the LRU end (Front).
    if let Some(pos) = self.ghost_keys.iter().position(|k| *k == item.key) {
        self.ghost_keys.remove(pos);
        debug!("DashSegment.put: ghost re-admission key={:?} -> target(Front)", item.key);
        promote_to_target(&mut self.core, item, InsertPosition::Front);
        return;
    }

    // Normal path: new cold item enters stash.
    debug!("DashSegment.put: key={:?} -> stash", item.key);
    let evicted = self.core.put_at(Slot::Stash, InsertPosition::Back, item);

    // If stash evicted a resident, record its key in the ghost set so a future
    // re-insertion can skip the stash re-admission step.
    if let Some(ev) = evicted {
        debug!("DashSegment.put: stash evicted key={:?} -> ghost set", ev.key);
        if self.ghost_keys.len() >= GHOST_CAPACITY {
            self.ghost_keys.pop_front(); // evict oldest ghost entry
        }
        self.ghost_keys.push_back(ev.key);
    }
}
```

`promote_to_target` is the existing free function in the same file. No changes to it are needed. `fn get` retains `InsertPosition::Back` (from v002). The geometry.rs overlay from v002 (75/25 = 24/8 split) is included verbatim.

## Rationale

Items that are repeatedly evicted from stash and re-inserted (items at the stash eviction boundary) currently re-enter stash on every insertion, requiring a full stash-hit access to reach target before they can climb to probing. A ghost set records the keys of the most recently evicted stash items; when the same key re-arrives via `put`, it is promoted directly into its target bucket (LRU end, conservative), skipping stash entirely. The bounded VecDeque (capacity 32) caps memory overhead and naturally ages out stale ghost entries in FIFO order. Front insertion into target is chosen deliberately: the re-admitted item must still earn its way to MRU within the target bucket before qualifying for probing, preventing the ghost path from trivially inflating probing occupancy.
