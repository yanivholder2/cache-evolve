# H01

Requiring at least two hits while an item is the hottest resident in its target bucket before promoting it to probing reduces probing-slot pollution from single-access scans and raises hit rate on top of the 24/8 topology with MRU re-entry.

## Parent

cycle/0003/v002

## Changes

Starting from v002's overlay (geometry.rs with 75/25 split preserved unchanged; dash_segment.rs with `InsertPosition::Back` stash-to-target promotion), modify `dash_segment.rs` to add an access-count gate in `promotion_get` before the target→probing promotion step, and reset `lfu_counter` on each tier entry.

### 1. `promote_to_target`: reset `lfu_counter` on target entry

Change the function signature to accept `mut item` and zero the counter before inserting, so each target residency starts with a clean slate:

```rust
fn promote_to_target<K, V>(core: &mut SegmentCore<K, V>, mut item: Item<K, V>, insert_pos: InsertPosition)
where ...
{
    item.lfu_counter = 0;   // ← add this line
    let target_idx = get_index(&item.key, core.segment_size);
    let Some(evicted) = core.put_at(Slot::Target, insert_pos, item) else {
        return;
    };
    demote_from_normal_bucket(core, evicted, target_idx, insert_pos);
}
```

### 2. `promotion_get`: gate target→probing on `lfu_counter >= 2`

In the branch that handles "item found in target bucket as the hottest" (`is_hottest == true`), replace the unconditional removal+promote with a counter-check:

```rust
if is_hottest {
    // Increment the per-target-visit counter before making the promotion decision.
    core.buckets[target_idx].get_items_mut()[item_idx].lfu_counter =
        core.buckets[target_idx].get_items()[item_idx].lfu_counter.saturating_add(1);
    let hit_count = core.buckets[target_idx].get_items()[item_idx].lfu_counter;

    if hit_count >= 2 {
        debug!(
            "promotion_get: key={key:?} in target as hottest hit_count={hit_count} -> probing={probing_idx}"
        );
        let mut data = core.buckets[target_idx].remove_at(item_idx);
        data.lfu_counter = 0;   // reset counter before entering probing tier
        promote_to_probing(core, data, insert_pos);

        let Some(item_new_idx) = core.buckets[probing_idx].get_position(key) else {
            unreachable!("promotion_get: key not found after promote_to_probing")
        };
        return Some(&core.buckets[probing_idx].get_items()[item_new_idx]);
    } else {
        // Not yet eligible — advance position in-target (ClassicLRU: move to MRU) but do not promote.
        debug!(
            "promotion_get: key={key:?} in target as hottest hit_count={hit_count} -> intra-promote only"
        );
        return Some(core.buckets[target_idx].get_from_position(item_idx));
    }
}
```

All other logic in `promotion_get` (stash-hit path, non-hottest target path, probing-hit path) is unchanged. The `promote_to_probing` function signature is unchanged. The geometry.rs overlay from v002 (75/25 = 24/8 split) is included verbatim.

## Rationale

In v002, any item that reaches the MRU position in its target bucket (which can happen after a single stash-to-target promotion with Back-insert) immediately qualifies for probing on the next access. This means a one-time scan item can occupy a probing slot after just two total accesses. Requiring `lfu_counter >= 2` within the target tier (i.e., being the hottest item on two separate hits) adds a light second-chance filter: items must prove recurrent hotness before graduating to probing, while still using ClassicLRU's positional ordering for intra-bucket recency. The `lfu_counter` field in `Item` is already present and unused by ClassicLRU, so this adds zero struct overhead.
