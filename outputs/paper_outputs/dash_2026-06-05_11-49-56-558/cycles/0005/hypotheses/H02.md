# H02

Hard-coding demotion insertions to `Front` (LRU end) in `demote_from_normal_bucket` instead of inheriting `InsertPosition::Back` from the triggering promotion will improve hit-rate by ensuring freshly-demoted items start at the bottom of their destination tier's eviction queue rather than jumping to MRU and displacing established warm residents.

## Parent

cycle/0004/v002

## Changes

In `src/dash/segments/dash_segment.rs`, modify the body of `demote_from_normal_bucket` to use `InsertPosition::Front` for every `core.put_at` call inside the function, ignoring the `insert_pos` parameter that is passed in. Do not change the function signature or any call sites — only the internal call-site argument changes.

Current body:
```rust
fn demote_from_normal_bucket<K, V>(
    core: &mut SegmentCore<K, V>,
    item: Item<K, V>,
    source_idx: usize,
    insert_pos: InsertPosition,
) where ... {
    let true_target = get_index(&item.key, core.segment_size);
    if true_target == source_idx {
        core.put_at(Slot::Stash, insert_pos, item);          // ← change to Front
    } else {
        if let Some(cascade) = core.put_at(Slot::Target, insert_pos, item) {  // ← Front
            core.put_at(Slot::Stash, insert_pos, cascade);   // ← Front
        }
    }
}
```

Replace all three `insert_pos` arguments in `put_at` calls with `InsertPosition::Front`:

```rust
fn demote_from_normal_bucket<K, V>(
    core: &mut SegmentCore<K, V>,
    item: Item<K, V>,
    source_idx: usize,
    _insert_pos: InsertPosition,   // retained for signature compatibility, unused
) where ... {
    let true_target = get_index(&item.key, core.segment_size);
    if true_target == source_idx {
        core.put_at(Slot::Stash, InsertPosition::Front, item);
    } else {
        if let Some(cascade) = core.put_at(Slot::Target, InsertPosition::Front, item) {
            core.put_at(Slot::Stash, InsertPosition::Front, cascade);
        }
    }
}
```

All promotion paths (`promote_to_target`, `promote_to_probing`) are unchanged and continue to insert at `InsertPosition::Back` (MRU). Only the demotion path diverges. The ghost set logic and geometry are also unchanged from the parent.

## Rationale

In cycle/0004/v002 every `put_at` — both promotions and demotions — uses `InsertPosition::Back`. This means a demoted item from probing or target lands at MRU of its destination tier, competing immediately with the most recently-accessed residents. An item that just got displaced was less recently-accessed than the item that displaced it; placing it at LRU (Front) of its new tier gives it a fair position without letting it crowd out genuinely hot residents. This asymmetry — promotions at MRU, demotions at LRU — is standard in segmented-LRU designs and has not yet been tested in this cache.
