# H01

Pushing the normal/stash split from v002's 75/25 to 87.5/12.5 (28 normal / 4 stash) will continue the ascending hit-rate gain curve, or expose the breakpoint where stash under-capacity starts hurting cold-item re-entry.

## Parent

cycle/0002/v002

## Changes

Modify `src/shared/geometry.rs` — the `layout()` method inside `BaselineGeometry`. Change the fraction used to compute `normal` from `3/4` (v002's 75/25 split) to `7/8` (87.5/12.5):

```rust
let total_buckets =
    self.topology.num_of_normal_buckets + self.topology.num_of_stash_buckets;
let normal = (total_buckets * 7 / 8).max(2); // 87.5/12.5 split
let stash = (total_buckets - normal).max(1);  // >= 1 required for stash
DashGeometry {
    num_of_segments:       self.topology.num_of_segments,
    num_of_normal_buckets: normal,
    num_of_stash_buckets:  stash,
    bucket_size:           self.topology.bucket_size,
}
```

For the production 32-bucket setting this yields 28 normal / 4 stash, up from v002's 24/8. The edge-case guards (`.max(2)` on normal, `.max(1)` on stash) must be preserved so the validity invariant (`num_of_normal_buckets >= 2`, `num_of_stash_buckets >= 1`) holds under proptest's small settings.

No other file changes are required. `src/dash/segments/dash_segment.rs`, `src/shared/eviction_policy.rs`, `src/dash/dash_bucket.rs`, and `src/shared/item.rs` remain at their v002 state — the segment continues to use `InsertPosition::Front` and geometry is the sole change.

## Rationale

Both prior cycles showed monotonically increasing returns as the ratio shifted: 8/24 (baseline, 0.663) → 16/16 (cycle 1 winner, 0.697) → 24/8 (cycle 2 winner, 0.714). The cross-cycle insight flags the gain curve's peak location as the top open question. A 28/4 probe is the natural next step to determine whether the working set fits within 28 normal buckets or whether the 4-slot stash becomes a binding constraint that forces cold-re-entry evictions.
