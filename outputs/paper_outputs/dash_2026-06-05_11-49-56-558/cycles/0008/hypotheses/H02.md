# H02

Switching the stash-overflow second-chance promotion from LRU-end insertion (Front) to MRU-end insertion (Back) will raise hit-rate by giving second-chance items immediate hot-end position, consistent with the universal MRU-wins principle observed across all prior cycles.

## Parent

cycle/0007/v001

## Changes

In `src/dash/segments/dash_segment.rs`, change the `put()` method's second-chance `promote_to_target` call from `InsertPosition::Front` to `InsertPosition::Back`. This is the only diff from v001:

```rust
// current (v001):
promote_to_target(&mut self.core, ev, InsertPosition::Front);

// proposed:
promote_to_target(&mut self.core, ev, InsertPosition::Back);
```

The surrounding logic is unchanged: the stash insert still uses `InsertPosition::Back` for new cold items; the stash-evicted item `ev` is still unconditionally recovered (no condition added); `promote_to_target` still handles any resulting target overflow via `demote_from_normal_bucket` which resets `lfu_counter` to 0 before stash re-entry.

No changes to `eviction_policy.rs`, `geometry.rs`, `dash_bucket.rs`, or `item.rs`.

**Invariant to preserve**: The second-chance item still always enters the cache rather than being discarded; only its insertion position within the target bucket changes. Any cascade from target overflow continues to be handled by the existing `demote_from_normal_bucket` path unmodified.

**Rationale for plausibility**: Second-chance items are items displaced from stash by hash collision with a new cold arrival — they are not cold by choice, only by bad luck. Back/MRU insertion means one more target access promotes them to probing, rather than forcing them to wait through two target accesses from the LRU end. Cross-cycle evidence shows every other promotion path uses Back insertion; the second-chance path is the sole exception in v001.
