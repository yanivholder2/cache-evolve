# H02

Adding a key-only ghost cache that captures keys displaced from the stash by FIFO overflow and boosts their `lfu_counter` to 1 on re-insertion raises hit rate by extending effective eviction memory across three tiers — primary, stash, and ghost.

## Parent

cycle/0003/v003

## Changes

One file requires changes: `src/associative_cache/associative_cache_bucket.rs`, based
on the cycle/0003/v003 overlay (LFU + FIFO stash + +2 promotion credit). All existing
stash and promotion logic is preserved exactly; the ghost tier is strictly additive.

### Struct fields

Add two new fields to `AssociativeCacheBucket<K, V>`:

```rust
ghost: Vec<K>,
ghost_max_size: usize,
```

Initialize them in `new()`:

```rust
ghost: Vec::new(),
ghost_max_size: settings.bucket_size,   // same capacity as primary
```

`ghost_max_size` equals primary capacity. Because each ghost entry holds only a key
(~8 bytes) rather than a full item (~40 bytes), the ghost provides five times the
memory span of the primary tier at the equivalent byte cost.

### New private helper `ghost_push`

```rust
fn ghost_push(&mut self, key: K) {
    if self.ghost.len() >= self.ghost_max_size {
        self.ghost.remove(0);   // FIFO: drop oldest ghost key
    }
    self.ghost.push(key);
}
```

### Modified `stash_push`

When the stash FIFO displaces its oldest entry to make room for a new evictee, send
that entry's key into the ghost before dropping the item:

```rust
fn stash_push(&mut self, item: Item<K, V>) {
    if self.stash.len() >= self.stash_max_size {
        let displaced = self.stash.remove(0);
        self.ghost_push(displaced.key);   // key enters ghost on stash-FIFO displacement
    }
    self.stash.push(item);
}
```

The existing cycle/0003/v003 `stash_push` body is otherwise unchanged.

### Modified `put()` — Case 3 only (brand-new key)

After the primary-resident check (case 1) and the stash-hit promotion (case 2),
which are unchanged, add a ghost lookup before the final push:

```rust
// Case 3: brand-new key
if self.items.len() == self.max_size {
    self.evict_to_stash();
}
let mut new_item = item;
if let Some(ghost_pos) = self.ghost.iter().position(|k| *k == new_item.key) {
    self.ghost.remove(ghost_pos);
    new_item.lfu_counter = 1;   // mild head start: completed the primary→stash→ghost journey
}
self.items.push(new_item);
let back = self.items.len() - 1;
(&self.items[back], None)
```

The +1 initial counter is intentionally lower than the +2 stash promotion credit:
ghost items have aged out of the stash without being re-accessed, so they are less
certain re-use candidates than stash hits.

### No change to `get()`

The ghost holds keys only; it cannot serve values. A ghost miss remains a full miss
and `get()` is unchanged from cycle/0003/v003.

### Complexity

The ghost lookup in case 3 is O(ghost_max_size) = O(bucket_size), the same
asymptotic cost as the existing stash lookup already present in `put()`.

## Rationale

On a Zipfian workload the stash captures items evicted during cold bursts and returns
them to primary when the workload circles back. The ghost extends this memory one tier
further: keys that age out of the stash's FIFO cap without being accessed are retained
cheaply (key-only) so that when they re-appear as inserts the cache can distinguish
them from truly cold items. The +1 head start is deliberately small — enough to reduce
the probability of immediate re-eviction on the first insertion cycle but not large
enough to lock out newer, actively hot items.
