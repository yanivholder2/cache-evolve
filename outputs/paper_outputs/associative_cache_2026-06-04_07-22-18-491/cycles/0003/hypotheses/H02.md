# H02

Replacing the FIFO stash eviction policy with a drop-minimum-frequency selection will increase hit rate by retaining higher-frequency stash candidates, so that any given stash promotion is more productive than under the current oldest-first rule.

## Parent

cycle/0002/v001

## Changes

In `src/associative_cache/associative_cache_bucket.rs`, modify the `stash_push()` method. Currently, when the stash is at capacity, index 0 (the oldest entry) is unconditionally removed:

```rust
fn stash_push(&mut self, item: Item<K, V>) {
    if self.stash.len() >= self.stash_max_size {
        self.stash.remove(0);
    }
    self.stash.push(item);
}
```

Replace the `self.stash.remove(0)` line with a scan that finds and removes the stash entry whose `lfu_counter` is smallest (ties broken by position — earliest position wins, i.e. preserve youngest among ties):

```rust
fn stash_push(&mut self, item: Item<K, V>) {
    if self.stash.len() >= self.stash_max_size {
        let victim = self
            .stash
            .iter()
            .enumerate()
            .min_by_key(|(i, s)| (s.lfu_counter, *i))
            .map(|(i, _)| i)
            .unwrap_or(0);
        self.stash.remove(victim);
    }
    self.stash.push(item);
}
```

All other methods (`evict_to_stash`, `get`, `put`) remain identical to the parent. The stash size cap and the primary-eviction path are unchanged.

## Rationale

Under FIFO, an item with `lfu_counter = 0` inserted long ago blocks a higher-frequency item that was evicted later. Selecting the minimum-frequency victim ensures the stash population trends toward items that have actually been re-accessed, mirroring the same LFU principle that drives primary eviction in the parent variant. The scan cost is at most `stash_max_size` comparisons per insertion — at most 4–8 items for typical `bucket_size` values — which is the same order as the existing linear stash search in `get()` and `put()`.
