# H01

Partitioning each bucket into a protected and probationary region (SLRU-in-a-bucket) raises hit rate by shielding re-referenced items from one-shot scans.

## Parent

baseline

## Changes

Edit only `src/shared/item.rs` and `src/shared/eviction_policy.rs`. No new
`EvictionPolicyKind` variant is introduced — the new behaviour is delivered
by mutating the existing `ClassicLRU` policy's impl in place, so the
selection wiring already in the codebase keeps pointing at the same policy
name while picking up the new semantics.

1. **`src/shared/item.rs`** — add a new `pub protected: bool` field to
   `Item<K, V>`. Initialise it to `false` in `Item::new`. Keep the
   `Item::new(key, value)` two-argument signature and the `key`, `value`,
   `lfu_counter`, `timestamp` fields intact (manifest requirements). Leave
   `PartialEq` unchanged — equality still compares `key` + `value` only —
   so the in-file equality tests keep passing. Extend the `Display` impl to
   print `protected` alongside the existing fields. Update the in-file unit
   tests `new_initializes_fields` and `clone_produces_independent_copy` to
   also assert `protected == false` on a fresh item.

2. **`src/shared/eviction_policy.rs`** — rewrite only the
   `EvictionPolicy<K, V>` impl block for `ClassicLRU`. Keep its `name()`
   returning `"ClassicLRU"` so the existing selection wiring keeps choosing
   this policy:
   - `get_from_position(items, position)`: remove the item at `position`;
     set its `protected` field to `true`; push it onto the back; return
     `items.len() - 1`. Both first-time and repeat hits end up at the back
     and protected — promotion is monotonic, never demoted within a bucket.
   - `eviction_candidate_index(items)`: return the lowest index `i` where
     `items[i].protected == false`. If every item is protected, fall back
     to index `0` so eviction never stalls when the bucket fills with
     protected residents.
   - `promotion_candidate_index(items)`: return the highest index `i` where
     `items[i].protected == true`. If none are protected yet, fall back to
     `items.len() - 1` so segment-level "is_hottest → promote" logic still
     has a valid hottest slot.

   Update the in-file `ClassicLRU` unit tests
   (`classic_lru_evicts_least_recently_used`, `classic_lru_get_moves_to_back`,
   `classic_lru_eviction_chain`, `eviction_candidate_index_classic_lru`,
   `promotion_candidate_index_classic_lru_fifo_swap_is_last`) so they
   exercise the new "promote-to-protected on first hit, evict from
   probationary front" behaviour. Leave every other policy impl
   (`TimestampLRU`, `Lifo`, `Lfu`, `Fifo`, `Swap`), the `EvictionPolicyKind`
   enum, and all its methods byte-for-byte unchanged.

Invariants to preserve: `eviction_candidate_index` and
`promotion_candidate_index` return an in-bounds index for any non-empty
`items`; `get_from_position` leaves `items.len()` unchanged; the
`Item::new(key, value)` two-argument constructor remains; `key` and `value`
fields remain present.

## Rationale (optional)

The baseline runs ClassicLRU inside each bucket, so a single cold scan can
sweep hot items off the MRU end. Segmented-LRU partitioning is a cheap,
well-known fix that fits the existing trait surface and co-evolves `Item`
per the manifest's guidance that item layout co-evolves with the eviction
policy.
