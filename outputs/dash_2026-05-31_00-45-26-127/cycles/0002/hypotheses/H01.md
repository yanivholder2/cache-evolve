# H01

Split each Dash bucket into a protected and probationary segment via a per-item `protected` flag to raise hit-rate on lirs:multi1 by retaining re-referenced items past the front-pop victim.

## Parent

baseline

## Changes

Add a `pub protected: bool` field to `Item` in `src/shared/item.rs`, initialized to `false` in `Item::new`, and excluded from `PartialEq` (alongside `lfu_counter` and `timestamp`, which are already ignored).

In `src/shared/eviction_policy.rs`, modify only `ClassicLRU` — leave every other policy untouched:

1. `get_from_position`: keep the existing strict move-to-back (`items.remove(position)` + `items.push(item)`), but immediately before the `remove`, set `items[position].protected = true`. After the push, if the count of protected items exceeds `items.len() / 2`, scan items front-to-back and clear the `protected` flag on the first protected item found (demoting the oldest protected back to probationary). This cap guarantees `eviction_candidate_index` always has an unprotected candidate.
2. `eviction_candidate_index`: scan front-to-back; return the index of the first item whose `protected == false`. If somehow every item is protected (e.g. immediately after the cap demotion missed because of a transient state), fall back to returning `0`.
3. `promotion_candidate_index`: unchanged — keep returning `items.len() - 1`, so the segment-level promotion gating in `promotion_get` continues to trigger off the strict-MRU position.

Do not touch `src/dash/dash_bucket.rs`. Do not alter the `EvictionPolicy` trait signature. Preserve every existing test in `eviction_policy.rs` (the LFU/Lifo/Fifo tests should still pass; the ClassicLRU eviction tests may shift because re-referenced items are now skipped on the first front-pop — that is the intended behaviour change).

## Rationale (optional)

Cycle 1's H01 was dropped to a 529 overload before it ever ran, and the cycle-1 insight explicitly flagged the segmented-bucket idea plus per-item state as the most promising unexplored direction. A single boolean per item is the minimum-cost realisation of "protect once-referenced items from the next eviction round" — an LRU-K-flavoured second-chance that avoids the stale-counter problem v003 hit.
