# H02

Replace strict move-to-back in ClassicLRU with a CLOCK-style reference-bit sweep so per-op cost drops to O(1) on hits while cold-end eviction stays accurate on lirs:multi1.

## Parent

baseline

## Changes

Add a `pub ref_bit: bool` field to `Item` in `src/shared/item.rs`, initialized to `false` in `Item::new`, and excluded from `PartialEq`.

In `src/shared/eviction_policy.rs`, rewrite the `ClassicLRU` impl — leave every other policy untouched:

1. `get_from_position`: set `items[position].ref_bit = true` and return `position` unchanged. No `remove`, no `push`, no `swap`. This is a true O(1) hit path.
2. `eviction_candidate_index`: implement the classic two-pass clock sweep.
   - First pass: iterate front-to-back. If `items[i].ref_bit == true`, set it to `false` and continue. If `items[i].ref_bit == false`, return `i` immediately.
   - If the first pass exhausts the bucket (every item was referenced since the last eviction), every bit has now been cleared, so return `0`.
3. `promotion_candidate_index`: keep returning `items.len() - 1`. Because items no longer migrate on hit, the back position now reflects insertion recency rather than hit recency — that is intentional; the segment-level promotion gate in `promotion_get` will then promote based on "the most-recently-inserted item that was also just hit," which preserves the existing promotion cadence for cold-segment workloads without an in-bucket shuffle.

Do not change `DashBucket` or the `EvictionPolicy` trait. The existing `classic_lru_get_moves_to_back` and `classic_lru_eviction_chain` tests in `bucket.rs` will fail — these assert strict move-to-back semantics that this hypothesis is deliberately replacing; update or delete only those two assertions inside `eviction_policy.rs` / `dash_bucket.rs` if any equivalents live there, but do not weaken the cold-segment integration tests in `promotion_logic.rs`.

## Rationale (optional)

v002's bubble-back regressed because slow drift weakened the cold-end ordering — but the lesson is "drift is the wrong model," not "movement is necessary." CLOCK does the opposite of bubble-back: it pays no movement cost per hit, and lets eviction itself decide victims using a single round of reference-bit clearing. It is structurally distinct from v002 and v003, and is a well-known LRU approximation that wins on workloads with many one-shot references — which is where lirs:multi1 spends much of its mass.
