# H03

Shrink the Item layout to just key and value, dropping timestamp and lfu_counter, to cut metadata size while keeping ClassicLRU bucket-movement intact.

## Parent

baseline

## Changes

The metadata-size metric is `sizeof(Item<u64,u64>) = 40` bytes: key(8) + value(8) +
`lfu_counter: usize`(8) + `timestamp: Instant`(16). The baseline cold segment uses
`ClassicLRU`, whose `get_from_position` reorders the vec (remove+push) and whose
eviction/promotion candidates are positional (index `0` / `len-1`) — it reads
**neither** removed field. So the layout and the movement co-evolve: a slimmer Item
leaves hit-rate untouched.

Edits:

- `src/shared/item.rs`: remove the `timestamp: Instant` and `lfu_counter: usize`
  fields from `Item<K,V>`, leaving only `key` and `value`. Keep
  `Item::new(key, value)` constructible and keep the `key`/`value` fields present
  (item extension-point contract). Drop the now-unused `Instant` import and the
  `lfu_counter`/`timestamp` references in the `Display` impl and in baseline unit
  tests that assert on them.
- `src/shared/eviction_policy.rs`: the crate must still compile. `TimestampLRU`
  (reads `item.timestamp`) and `Lfu` (reads/writes `item.lfu_counter`) now reference
  removed fields — reimplement both bodies to positional behavior (`get_from_position`
  returns `position` unchanged, `eviction_candidate_index` returns `0`,
  `promotion_candidate_index` returns `items.len()-1`), i.e. FIFO-equivalent. Keep
  every `EvictionPolicyKind` variant, its `name()`, and its `index()` ordinal intact
  — do not renumber the enum or rename structs (JNI ordinals and `all()` depend on
  them).

Do **not** touch `promotion_logic.rs` or `promotion_cold_segment.rs`; the
bucket-movement path is unchanged. Invariants P1–P5 are layout-agnostic (they depend
on slot derivation and per-put eviction counting, not on item fields) and continue
to hold.

Expected: `Item<u64,u64>` drops from 40 to 16 bytes. Confirm via the
`evolve-metadata-size` binary and verify the hit-rate summary stays at ~0.94725.
