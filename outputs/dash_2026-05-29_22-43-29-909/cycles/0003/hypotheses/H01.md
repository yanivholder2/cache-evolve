# H01

Add a second-hit stash admission gate on top of v001's O(1) back-push promotion so single-touch scan keys never enter the hot tier, raising hit rate on the lirs:multi1 scan/loop trace while preserving v001's latency profile.

## Parent

cycle/0001/v001

## Changes

Start from `cycle/0001/v001`'s overlay and keep its `src/dash/dash_bucket.rs`
exactly as-is (the `put_at` that ignores `InsertPosition` and always `push`es to
`Back`, giving the O(1) promotion-insert and the current best hit-rate of
0.4842). This hypothesis adds one new overlaid file on top of it:
`src/dash/segments/promotion_logic.rs`.

Edit only the **stash-hit branch** of `promotion_get` — the
`if let Some(item_idx) = core.stash_buckets[stash_idx].get_position(key)` block
(today: `remove_at(item_idx)` then `promote_to_target(core, data, insert_pos)`
then relocate). Replace it with a one-more-chance admission gate:

1. Increment the stash resident's counter explicitly:
   `core.stash_buckets[stash_idx].get_items_mut()[item_idx].lfu_counter += 1;`
   Do this here because the eval path runs `ClassicLRU`, whose
   `get_from_position` never touches `lfu_counter`, so without this line the gate
   has no signal.
2. Read the updated counter. If it is `< 2` (first hit while resident in stash),
   do **not** promote: touch the item in place inside its stash bucket via
   `let item = core.stash_buckets[stash_idx].get_from_position(item_idx);` and
   `return Some(item);`, leaving the key resident in its own stash slot.
3. Only when the counter reaches `>= 2` do the existing promotion: `remove_at`,
   `promote_to_target(core, data, insert_pos)`, then the existing relocate-and-
   return with its `unreachable!` guard intact.

Leave the target-hit branch, the probing-hit branch, `promote_to_target`,
`promote_to_probing`, `demote_from_normal_bucket`, and both `unreachable!`
post-conditions unchanged. New keys still enter via the default `put` into stash
with `lfu_counter == 0`.

Invariants P1–P5 hold: a not-yet-admitted key stays resident in its slot-legal
stash bucket, and the gate adds no item and no extra eviction, so
single-eviction-per-put, slot legality, and capacity bounds are untouched. Keep
the crate compiling and update the in-crate `#[cfg(test)]` case
`stash_hit_inserts_at_front_of_target` in `promotion_cold_segment.rs` (and any
sibling that assumes a stash hit promotes on the first touch) to drive two stash
hits before asserting the promotion into target.

## Rationale (optional)

This finally realizes the cycle-2 H02 direction that produced no result (its
variant never emitted an overlay), and which the cross-cycle notes call the most
promising live refinement. It keeps the empirical hit-rate-and-latency leader
(cycle-1 v001) and repairs the exact mechanism that the insight says cost hits —
first-touch admission of scan keys into the MRU-protected tier — turning the
stash into a reuse filter the LIRS trace rewards.
