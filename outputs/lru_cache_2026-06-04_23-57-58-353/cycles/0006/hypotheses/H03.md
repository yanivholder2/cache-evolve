# H03

Weighting each entry's stored frequency by a logical-clock decay factor proportional to the time since its last access will raise hit rate by making the demotion and eviction scans prefer entries that were once warm but have since gone cold over entries that are still being accessed at low but recent frequency.

## Parent

cycle/0005/v002

## Changes

The current policy halves `freq` only on protected-to-probationary demotion, meaning entries in the protected segment accumulate frequency credit that never decays unless a demotion event occurs. This change adds a lightweight per-operation logical clock and uses it at victim-selection time to compute an effective frequency that ages passively between accesses — without modifying any stored counters.

**1. Add a logical-clock counter to `LruCache`**

In the `LruCache` struct, add one field:
```rust
op_count: u64,
```
Initialize to `0` in `try_new()`.

**2. Add a `last_access` timestamp to `Node<K, V>`**

In the `Node` struct, add:
```rust
last_access: u64,
```
Initialize to `0` in every `Node { ... }` construction site (both the `self.nodes.push(Node { ... })` fresh-allocation path and the `self.nodes[evict_idx].last_access = 0` reuse path in `put()`). The initial value of `0` is fine; the clock starts at `0` and advances from there.

**3. Advance the clock and record access time in `get()` and `put()`**

At the very start of `get()` (before any other logic), add:
```rust
self.op_count = self.op_count.wrapping_add(1);
```
After the segment-specific position update (both the `Protected` move-to-tail branch and the `Probationary` promotion branch), set:
```rust
self.nodes[idx].last_access = self.op_count;
```

At the very start of `put()` (before the re-put check), add:
```rust
self.op_count = self.op_count.wrapping_add(1);
```
When a new node is pushed into the arena (both the fresh-push path and the slot-reuse path), set `last_access = self.op_count` on the node immediately after overwriting its fields (e.g., `self.nodes[evict_idx].last_access = self.op_count;`).

**4. Define a decay constant**

At module scope, add:
```rust
const FREQ_HALF_LIFE: u64 = 512;
```
With `capacity = 2048`, this means an entry that goes unaccessed for 512 operations has its effective frequency halved; after 1024 ops of silence its effective frequency is quartered, and so on.

**5. Replace raw `freq` comparisons in `demote_prot_head()` and the probationary eviction scan with decayed effective-frequency comparisons**

Add a helper (or inline the computation at both sites):
```rust
fn effective_freq(&self, idx: usize) -> u32 {
    let age = self.op_count.wrapping_sub(self.nodes[idx].last_access);
    let shifts = (age / FREQ_HALF_LIFE).min(31) as u32;
    self.nodes[idx].freq >> shifts
}
```

In `demote_prot_head()`, replace `let freq = self.nodes[idx].freq;` with:
```rust
let freq = self.effective_freq(idx);
```

In the probationary eviction scan inside `put()`, replace `let freq = self.nodes[idx].freq;` with:
```rust
let freq = self.effective_freq(idx);
```

Do NOT change the stored `self.nodes[idx].freq` or `self.nodes[v].freq /= 2` logic — the stored counter is still incremented on hits and halved on demotion exactly as before. The decay computation is read-only at victim-selection time.

**Invariants to preserve**: `MAX_FREQ`, scan lengths (`prot_count / 4` and `prob_count / 2`), ghost-set logic, promotion paths, and all other code are unchanged. The `op_count` wrapping arithmetic is safe: `wrapping_sub` in `effective_freq` handles the u64 wraparound correctly, and with `min(31)` the shift amount is always in-range.

## Rationale

The cross-cycle insights note that adaptive or decay-weighted frequency counting is an unexplored direction. The current policy cannot distinguish an entry that was last accessed 2000 operations ago (effectively cold) from one accessed 10 operations ago (actively warm) if both carry the same stored `freq`. Adding passive decay makes the scan aware of recency without the cost of a full EMA update on every access — the decay is computed only when a victim must be chosen, keeping the hot path unchanged.
