# H01

Adding a per-node `referenced` bit that acts as a demotion tie-breaker in the protected segment — while still performing move-to-tail on every hit — will raise hit rate by shielding recently-accessed protected entries from demotion when an equal-frequency but unreferenced candidate exists in the scan window.

## Parent

cycle/0005/v002

## Changes

The cycle-3 second-chance variant failed because it suppressed `push_back_prot` when the `referenced` bit was set, stranding hot entries near the demotion head. This variant preserves recency ordering (move-to-tail always happens) and uses `referenced` only as a tie-breaker inside `demote_prot_head()`.

**1. Add `referenced: bool` to `Node<K, V>`**

In the `Node` struct definition, add:
```
referenced: bool,
```
Initialize it to `false` in every `Node { ... }` construction site (there are two: the `self.nodes.push(Node { ... })` path and the `self.nodes[evict_idx] = Node { ... }` reuse path in `put()`).

**2. Set `referenced = true` on protected hits in `get()`**

In the `Segment::Protected` arm of `get()`, after the existing `self.unlink_prot(idx); self.push_back_prot(idx);` calls, add:
```rust
self.nodes[idx].referenced = true;
```
Do NOT change the `push_back_prot` call — move-to-tail must still happen unconditionally.

For the `Segment::Probationary` arm, `referenced` stays `false` (it is not set during promotion; the new node in protected starts cold).

**3. Use `(freq, referenced_bit)` as the comparison key in `demote_prot_head()`**

Replace the current victim-selection comparison:
```rust
if freq < victim_freq {
    victim_freq = freq;
    victim_idx = Some(idx);
}
```
with a tuple comparison that treats an unreferenced node as strictly "colder" than a referenced node at the same frequency:
```rust
let r = if self.nodes[idx].referenced { 1u32 } else { 0u32 };
let score = (freq, r);
if score < victim_score {
    victim_score = score;
    victim_idx = Some(idx);
}
```
Initialize `victim_score` to `(u32::MAX, u32::MAX)` instead of `victim_freq = u32::MAX`.

**4. Clear `referenced` on demotion**

After `self.nodes[v].freq /= 2;` in `demote_prot_head()`, add:
```rust
self.nodes[v].referenced = false;
```
This ensures a demoted entry re-enters probationary without carrying its protected-era reference status.

**Invariants to preserve**: the existing `scan_len = (self.prot_count / 4).max(1)` stays unchanged; ghost-set logic, probationary eviction scan, and all other code paths are untouched.

## Rationale

The cycle-3 failure was caused by position-freeze, not by the reprieve concept itself. By keeping move-to-tail intact, the protected segment's recency ordering is preserved. The `referenced` bit then acts purely as a secondary eviction priority signal: among entries with the same frequency in the LRU quarter, prefer to evict the one that has not been touched since its last demotion-scan opportunity. This should provide a small shield for recently-active entries without disrupting the dominant frequency ordering.
