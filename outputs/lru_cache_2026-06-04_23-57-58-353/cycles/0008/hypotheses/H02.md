# H02

Widening probationary from 20% to 30% of capacity on the IRR baseline will improve hit rate by increasing the filter zone without hurting hot-entry retention, because IRR timestamp preservation lets genuinely warm entries win eviction contests in the larger probationary segment even without physical protection.

## Parent

cycle/0007/v003

## Changes

In `try_new()`, change the single line that computes `prot_cap`:

```
// before
let prot_cap = capacity * 4 / 5;   // 80% protected, 20% probationary

// after
let prot_cap = capacity * 7 / 10;  // 70% protected, 30% probationary
```

Update the accompanying log message to reflect the new ratio:

```
// before
log::info!("LruCache.try_new: capacity={capacity} prot_cap={prot_cap}");

// after
log::info!("LruCache.try_new: capacity={capacity} prot_cap={prot_cap} ratio=70/30");
```

No other changes. All IRR logic, scan fractions, op-clock update, and segment-transition code stay exactly as in the parent.

### Rationale

Cycle 2 tested a 70/30 split (protected=70%) on the *frequency* baseline and it regressed: with freq-based eviction, a smaller protected segment triggered excess demotion churn because entries had to accumulate frequency counts over time, and a shrunken protected segment evicted them before they could. Under IRR the dynamics are different: timestamps are preserved across demotion, so a previously hot entry (small IRR) retains its competitive advantage inside probationary without any manual counter adjustment. Cold newcomers still arrive with `IRR = u64::MAX` regardless of segment size. A 30% probationary zone therefore provides a larger cold-traffic filter — more one-hit wonders are absorbed and competed out before they reach protected — while genuinely warm entries self-protect through their IRR score. If the 80/20 split was calibrated for the older frequency signal and is now sub-optimal for IRR, this should produce a measurable gain. If the LIRS trace's hot working set is large enough to overflow a 70% protected segment, it will regress as in cycle 2.
