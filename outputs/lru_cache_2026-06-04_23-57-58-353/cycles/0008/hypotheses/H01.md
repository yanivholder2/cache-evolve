# H01

Reducing the probationary eviction scan from the LRU half to the LRU quarter on the IRR baseline will maintain hit rate while halving scan overhead, because IRR=MAX cold newcomers are concentrated at the LRU head and a narrower window is sufficient to identify the coldest victim.

## Parent

cycle/0007/v003

## Changes

In `evict_from_probationary()`, change the single line that computes the scan length:

```
// before
let scan_len = (self.prob_count / 2).max(1);

// after
let scan_len = (self.prob_count / 4).max(1);
```

Everything else in the function is unchanged: the scan still starts from `prob_head`, still picks the node with the highest IRR, and still calls `unlink_probationary` + `free_slots.push` on the selected victim.

Leave `demote_prot_head()`, all `irr()` logic, segment sizes, op-clock updates, and every other function untouched.

### Rationale

Under IRR eviction, cold newcomers (only one access ever recorded) carry `IRR = u64::MAX`, while demoted entries that were formerly hot carry small IRR values. Because IRR=MAX entries all look identical at the maximum end, the coldest victim is usually found within the first few slots of the LRU-ordered probationary list — no improvement is possible by looking further. Cycle 5 confirmed the half-scan is load-bearing on the *frequency* baseline (where cold and warm entries are interleaved throughout the list). With IRR the population is stratified differently: MAX-IRR entries cluster near the head, so a quarter-width scan should still reliably find a MAX-IRR victim on every eviction. If the scan fraction is genuinely too wide for IRR, this hypothesis confirms the narrower window is safe; if hit rate regresses, it reveals that IRR variation within the scan window is meaningful even for near-head entries.
