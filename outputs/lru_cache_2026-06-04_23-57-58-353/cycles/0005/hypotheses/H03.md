# H03

Requiring two distinct accesses in the probationary segment before promoting an entry to protected will reduce one-hit-wonder pollution of the working set and improve hit rate on the access-skewed workload.

## Parent

cycle/0004/v003

## Changes

In `get()`, modify the `Segment::Probationary` match arm. Currently it unconditionally promotes the entry to protected on any hit. Replace it with a two-stage check:

```rust
Segment::Probationary => {
    if self.nodes[idx].freq >= 2 {
        // Second (or later) access: promote to protected.
        self.unlink_prob(idx);
        self.prob_count -= 1;
        if self.ghost_set.remove(key) {
            self.ghost.retain(|k| k != key);
        }
        self.nodes[idx].segment = Segment::Protected;
        self.push_back_prot(idx);
        self.prot_count += 1;
        if self.prot_count > self.prot_cap {
            self.demote_prot_head();
        }
    } else {
        // First access (freq was 0, now 1): stay in probationary but refresh to MRU.
        self.unlink_prob(idx);
        self.push_back_prob(idx);
    }
}
```

Note: the freq increment at the top of `get()` (`saturating_add(1)`) happens before this branch, so `self.nodes[idx].freq` is already 1 on the first probationary hit and >= 2 on the second. The ghost-set defensive removal (currently executed unconditionally on every probationary hit) is moved inside the promotion branch only, since a non-promoting hit leaves the entry in probationary where ghost tracking is irrelevant.

All other logic (protected hits, probationary eviction scan in `put()`, demotion from protected, ghost admission on put) remains identical to v003.

## Rationale

v003 promotes any probationary entry on its very first access. On a scan-heavy or bursty workload this means items accessed exactly once — which the SLRU design was intended to filter — can still reach protected if they happen to be accessed a second time while still in probationary (e.g., a repeated scan of the same address range). A two-hit gate makes the admission criterion explicit: promotion requires demonstrated reuse, not merely presence at a lucky moment. The first access refreshes the entry to MRU of probationary (extending its survival window), and the second access triggers promotion. The cost is that genuinely hot items take one extra access before entering protected; the benefit is fewer transient items displacing the stable working set.
