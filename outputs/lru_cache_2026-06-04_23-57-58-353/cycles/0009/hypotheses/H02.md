# H02

Augmenting the IRR baseline with a coarse visit counter (clamped at 4, halved on demotion) and using it as the primary eviction key will improve hit rate by recovering the long-term warmth signal that pure IRR discards.

## Parent

cycle/0007/v003

## Changes

cycle/0007/v003 uses IRR as the sole eviction signal. The cycle 8 cross-cycle insight identified the core weakness: IRR is a two-point snapshot and cannot distinguish an entry accessed twice quickly *in the distant past* from one accessed twice quickly *just now*. A coarse visit count provides exactly the long-term signal that frequency halving gave cycle/0006/v001, but without unbounded accumulation.

### New constant

```rust
const MAX_VISITS: u8 = 4;
```

### New field on Node<K, V>

Add `visits: u8` initialized to `0` alongside the existing IRR timestamp fields.

### Changes to `get()`

After updating the IRR timestamps (`prev_access`, `last_access`, `op_clock`), increment visits capped at `MAX_VISITS`:

```rust
if self.nodes[idx].visits < MAX_VISITS {
    self.nodes[idx].visits += 1;
}
```

Apply this for hits in both segments (protected and probationary).

### Changes to `demote_prot_head()`

After the victim is selected and before it is unlinked from protected, halve its visit count to preserve a decaying warmth signal across the segment transition (mirroring counter halving in cycle/0006/v001):

```rust
self.nodes[victim_idx].visits >>= 1;
```

The IRR timestamps are already preserved across demotion (unchanged from parent).

### Changes to victim selection in both `evict_from_probationary()` and `demote_prot_head()`

Replace the single-key `max IRR` comparison with a two-key comparison: fewest visits first (coldest on long-term), then highest IRR as tie-breaker (coldest on short-term). This means the "victim" in both scan loops is selected as:

```rust
// cur_visits: u8, cur_irr: u64 for the current candidate
// victim_visits: u8, victim_irr: u64 initialized to (MAX_VISITS+1, 0u64)
if cur_visits < victim_visits
   || (cur_visits == victim_visits && cur_irr > victim_irr)
{
    victim_visits = cur_visits;
    victim_irr    = cur_irr;
    victim_idx    = Some(cur_node_idx);
}
```

Initialize `victim_visits = MAX_VISITS + 1` (or `u8::MAX`) and `victim_irr = 0` before the scan loop so the first candidate always replaces the initial sentinel.

### New entries

New entries in `put()` initialize `visits = 0`, which makes them primary eviction candidates when they compete against entries with any accumulated visits — correctly biasing eviction toward cold newcomers.

### Invariants preserved

All IRR timestamp mechanics (preservation across demotion, `op_clock` increment pattern), scan window fractions (LRU half in probationary, LRU quarter in protected), the 80/20 segment split, and the absence of a ghost set are unchanged from cycle/0007/v003.

## Rationale

The `visits` counter with halving-on-demotion mimics the frequency-halving mechanism that made cycle/0006/v001 effective, but at a coarser level (4 states vs. 8). An entry that accumulated 4 visits and is demoted arrives in probationary with 2 visits — enough to survive over cold newcomers at 0 visits — matching the intended behavior of cycle/0006/v001's frequency halving. The 2-bit ceiling prevents unbounded accumulation. IRR remains as the tie-breaker, preserving its sharpness when visit counts are equal.
