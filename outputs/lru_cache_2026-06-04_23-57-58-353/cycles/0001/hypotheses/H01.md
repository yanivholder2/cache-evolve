# H01

Replacing the single LRU list with a two-segment SLRU layout (probationary + protected) will raise hit rate by shielding frequently-reused entries from one-hit scan pollution.

## Parent

baseline

## Changes

Restructure `LruCache` in `src/lru_cache/mod.rs` to maintain two ordered sub-lists within the same arena and `HashMap`, with separate head/tail pointers for each segment:

**New fields on `LruCache`:**
- `prot_head: Option<usize>`, `prot_tail: Option<usize>` — protected segment (LRU end / MRU end)
- `prob_head: Option<usize>`, `prob_tail: Option<usize>` — probationary segment
- `prot_count: usize`, `prob_count: usize` — current occupancy of each segment
- `prot_cap: usize` — set to `(capacity * 4).div_ceil(5)` in `try_new` (80 % of total)

Remove the current unified `head`/`tail` fields.

**New field on `Node`:**
- `in_protected: bool` — true when the node lives in the protected segment

**`put` (new key):**
Insert the new node at the probationary MRU end (`prob_tail`). Set `in_protected = false`. Increment `prob_count`. If `prob_count > capacity - prot_cap`, evict `prob_head` (remove its key from the map, mark slot free with a sentinel or reuse it for the incoming entry as the baseline does).

**`get` (probationary hit):**
Unlink the node from the probationary list, decrement `prob_count`. Link it at the protected MRU end (`prot_tail`), set `in_protected = true`, increment `prot_count`. If `prot_count > prot_cap`, demote `prot_head`: unlink it from protected (decrement `prot_count`), link it at the probationary MRU end (increment `prob_count`), set `in_protected = false`. If `prob_count` now exceeds its cap, evict `prob_head` as above.

**`get` (protected hit):**
Unlink the node from its current position in the protected list and relink at `prot_tail` (standard MRU promotion within the segment). Counts do not change.

**`put` (existing key, either segment):**
Update value in place, then apply the same promotion logic as the corresponding `get` case above (probationary hit promotes; protected hit moves to protected MRU).

**`unlink` / `push_back`:**
Keep the existing `unlink` and `push_back` helpers but add `push_back_prob` and `push_back_prot` variants that update the correct head/tail pair. `unlink` remains segment-agnostic (it reads `prev`/`next` from the node, which are always correct).

**Invariants:**
Total resident keys = `prot_count + prob_count <= capacity` at all times, satisfying P1. Value writes happen before any structural move, preserving P2 and P3.
