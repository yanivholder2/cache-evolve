# H03

Scanning a window of 8 LRU-end candidates and evicting the one with the lowest saturating access-frequency counter will raise hit rate by preventing hot entries from being displaced during cold-start bursts.

## Parent

baseline

## Changes

Extend the existing LRU implementation in `src/lru_cache/mod.rs` with a per-node frequency counter and a small-window victim-selection pass at eviction time. All other logic (arena reuse, `unlink`, `push_back`, map management) is unchanged.

**Add to `Node<K, V>`:**
```rust
freq: u8,  // saturating counter, max value 3; 0 on construction
```

**`get` hit:**
After the existing `self.unlink(idx); self.push_back(idx);` calls, add:
```rust
self.nodes[idx].freq = self.nodes[idx].freq.saturating_add(1).min(3);
```

**`put` (existing key):**
After updating the value and promoting the node, apply the same saturating increment to `self.nodes[idx].freq`.

**`put` (new key):**
When constructing the new `Node`, set `freq: 0`.

**Eviction path in `put` (arena full):**
Replace the direct `let head_idx = self.head.expect(...)` victim selection with a window scan:

```rust
const WINDOW: usize = 8;
let mut victim = self.head.expect("non-empty list has a head");
let mut cursor = victim;
for _ in 1..WINDOW {
    match self.nodes[cursor].next {
        Some(next_idx) => {
            if self.nodes[next_idx].freq < self.nodes[victim].freq {
                victim = next_idx;
            }
            cursor = next_idx;
        }
        None => break,
    }
}
// victim is now the lowest-frequency node among the first WINDOW LRU-end entries
let evicted_key = self.nodes[victim].key.clone();
self.map.remove(&evicted_key);
self.unlink(victim);
self.nodes[victim].key = key.clone();
self.nodes[victim].value = value;
self.nodes[victim].freq = 0;
// then push_back(victim) and map.insert(key, victim) as before
```

When `capacity < WINDOW` the loop simply exhausts the list and picks the best available victim, so the logic is correct for any capacity including 1.

**Invariants:**
Exactly one slot is evicted per new-key insertion, so `map.len() <= capacity` (P1) is maintained. Values are written to the victim slot before it is re-linked and re-inserted into the map, so P2 and P3 are unaffected.
