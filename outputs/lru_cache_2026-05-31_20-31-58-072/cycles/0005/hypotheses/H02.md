# H02

Promotion strength scaled by ghost-ring position lifts hit-rate by giving fresh ghost-hits one extra sweep of Hot protection.

## Parent

cycle/0003/v001

## Changes

In `src/lru_cache/mod.rs`, change ghost-hit promotion in
`LruCache::put` so that the *position* of the matched ghost entry
controls how strongly the re-admitted key is promoted.

Concretely: today `ghost_remove(&key)` is called and the slot is
re-inserted as `SlotState::Hot` with `referenced: false`. Replace this
with a positional check:

1. Extend `ghost_remove` (or split into a new helper) to return the
   ring index of the matched entry, not just whether it was present.
2. Compute the entry's "freshness offset" against `ghost_head`:
   `offset = (ghost_head + ring_len - idx) % ring_len`. Smaller offset
   means the entry was written more recently.
3. If `offset < ring_len / 4` (freshest quarter), insert the re-admitted
   key with `SlotState::Hot` *and* `referenced: true` — it now survives
   one extra pass-2 ref-clear sweep before becoming eligible for
   eviction.
4. Otherwise (older three-quarters), keep the existing behaviour:
   `SlotState::Hot`, `referenced: false`.

Resident updates and brand-new non-ghost inserts are unchanged. Pass 1,
pass 2, fallback, and the ghost-ring write path are unchanged. Preserve
all invariants: `len <= capacity`, ghost ring length stays `capacity`,
ghost set and ghost ring stay in lockstep.

## Rationale (optional)

Cycle-3 v001's sweep-up to full-capacity ghost ring caught only a
sliver beyond a quarter-capacity, suggesting the re-reference
distribution has a thin tail. Encode that thinness as differentiated
promotion strength: a *fresh* ghost-hit is much more likely to be
re-referenced again soon, so it deserves stronger protection than a
stale one. The current uniform promotion treats both the same, leaving
fresh ghost-hits exposed to a pass-2 demotion they would otherwise
have survived.
