# H01

Bypass-on-first-sight admission gating prevents cold-scan keys from ever displacing resident slots, lifting hit-rate on lirs:multi1@512.

## Parent

cycle/0003/v001

## Changes

Modify `LruCache::put` in `src/lru_cache/mod.rs` to add a brand-new-key
admission gate **before** any eviction is triggered. Add a
`seen: Vec<bool>` first-seen sketch of length `capacity.saturating_mul(4).max(4)`,
indexed by `DefaultHasher` fold of the key (same shape as cycle-4 v001's
sketch). On every `get` and every `put`, mark `seen[fp] = true`.

Then, in `put`, when the cache is at capacity **and** the key is
brand-new (not resident, not in the ghost ring) **and** `seen[fp]` was
`false` *prior* to this put, treat the put as a no-op: do not call
`evict_one`, do not allocate a slot, do not touch `map`, do not push
anything to the ghost ring. Simply return after marking the sketch. The
key is admitted only on its second `put` (when `seen[fp]` is already
true), at which point the existing CLOCK-Pro-lite admission path runs
unchanged.

Ghost-promoted inserts (key present in `ghost_set`) bypass the gate
unconditionally — they have proved themselves once already. Resident
updates (key already in `map`) also bypass the gate unchanged.

Preserve invariants: `len <= capacity`, `map.len() == len`, every
`Some` slot's key is present in `map`, ghost ring contents disjoint
from resident keys.

## Rationale (optional)

Cycle-4 v001 used a first-seen sketch only as *post-admission* taint
ranking inside the eviction loop and tied at parity — the scan key was
still admitted and still evicted something. The cycle-3 cycle-insight
named "Cold-admission gating that filters scan inserts before they
pollute the ring" as the genuinely unpulled lever. This hypothesis
pulls it: brand-new unseen keys never touch the ring at all, so the
spared Cold slot stays Cold for as long as its own ref bit holds,
rather than for one extra sweep.
