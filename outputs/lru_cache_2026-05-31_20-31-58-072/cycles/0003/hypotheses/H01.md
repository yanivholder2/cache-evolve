# H01

Scaling the CLOCK-Pro-lite ghost ring from `capacity/4` up to full `capacity` raises hit rate on lirs:multi1 by capturing re-references at longer eviction-to-reference distances.

## Parent

cycle/0002/v002

## Changes

In `try_new()` (src/lru_cache/mod.rs), replace the ghost-ring sizing
expression

```
let ghost_len = (capacity / 4).max(1);
```

with

```
let ghost_len = capacity;
```

(and update the `HashSet::with_capacity(ghost_len)` line accordingly so
its hint matches the new ring length). Do not touch any other ghost
mechanics — `push_ghost`, `ghost_remove`, the ghost lookup in `put`, and
the Hot-vs-Cold ghost gating in `evict_at` all remain exactly as v002
has them. Keep the `was_cold` rule that only Cold evictions enter the
ghost. The fallback eviction in `evict_one()` still treats its victim
as Cold.

The hypothesis is that v002's ghost length (capacity/4 = 128 slots at
size 512) drops keys whose re-reference distance exceeds ~1/4 capacity,
and that lirs:multi1 has a fat enough re-reference tail past that
window that quadrupling the ring closes a meaningful chunk of misses
without re-introducing frequency bias.

## Rationale

The cycle-2 insight names ghost-ring sizing explicitly as the first
tuning knob on the champion. A pure sizing sweep is the cleanest
ablation to isolate whether v002's ghost is undersized vs. saturated;
it changes no policy code, only one constant, so the result is
attributable.
