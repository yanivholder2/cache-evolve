# H02

Replacing per-`get` list re-linking with a CLOCK second-chance reference bit cuts per-op time without materially hurting hit rate.

## Parent

baseline

## Changes

Rewrite `src/lru_cache/mod.rs` to back the cache with a fixed-size ring
buffer plus a per-slot reference bit, instead of a doubly-linked list.

State:

- `map: HashMap<K, usize>` — key to slot index (unchanged role).
- `slots: Vec<Option<Entry<K, V>>>` of length `capacity`, where
  `Entry { key: K, value: V, referenced: bool }`. Use `Option` so eviction
  can leave a hole that the hand fills on next insert.
- `hand: usize` — the CLOCK hand, advancing modulo `capacity`.
- `len: usize` — current resident count.

Behaviour:

- `get(&key)`: if `map.get(key)` returns `Some(idx)`, set
  `slots[idx].as_mut().unwrap().referenced = true` and return `Some(&value)`.
  No list operations, no pointer rewrites. On miss, return `None`.
- `put(key, value)`: if the key is already resident, update the value in
  place and set its `referenced` bit. Otherwise, if `len < capacity`, scan
  forward from `hand` for the first empty slot, install the entry there,
  set its bit to `false`, and increment `len`. If `len == capacity`, run
  the CLOCK eviction sweep: while `slots[hand].referenced` is `true`,
  clear the bit and advance `hand`; the first slot whose bit is already
  `false` is the victim — remove its key from the map, overwrite the slot
  with the new entry (bit = `false`), and advance `hand` past it.

Invariants P1/P2/P3 hold trivially: `len` is bounded by `capacity`, the slot
write places exactly the key/value pair the caller passed, and a never-put
key cannot appear in `map`. The JNI ABI in `lru_cache_jni.rs` is untouched.

## Rationale

The baseline pays for `unlink` + `push_back` on every `get` and every
`put` — four pointer rewrites per hit. CLOCK's per-`get` work is a single
bool store, and amortised per-`put` work is one hand advance over a small
constant number of slots. Hit rate is typically within a couple of
percentage points of LRU on most workloads, so this trades a small hit-rate
risk for a substantial per-op time win.
