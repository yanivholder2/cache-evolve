# H01

Splitting the linked list into a probationary and a protected segment, with promotion gated on a second hit, raises hit rate on scan-heavy traces relative to plain LRU.

## Parent

baseline

## Changes

Replace the single doubly-linked list in `src/lru_cache/mod.rs` with a
two-segment SLRU layout. Keep the same arena (`Vec<Node<K, V>>`) and the same
`HashMap<K, usize>`, but add a second pair of head/tail pointers and a
per-node `segment: u8` (or bool) tag, so every node belongs to either the
*probationary* segment or the *protected* segment.

Sizing: split `capacity` as `protected_capacity = capacity * 4 / 5` and
`probationary_capacity = capacity - protected_capacity`. Both segments share
the arena; only the per-segment list lengths are bounded.

Behaviour:

- `put` on a miss inserts the new node at the MRU end of the probationary
  segment. If the probationary segment is over capacity, evict from its LRU
  head (drop the key from the map and reuse the arena slot, mirroring the
  current eviction-by-slot-reuse pattern).
- `put` on an existing key updates the value in place and applies the same
  promotion rule as `get`.
- `get` on a probationary hit unlinks the node from the probationary list and
  pushes it to the MRU end of the protected list. If the protected segment is
  now over its capacity, demote its LRU head into the MRU end of the
  probationary segment (no key/value change, only segment-tag and list
  membership change).
- `get` on a protected hit just moves the node to its own segment's MRU end,
  exactly like the current LRU promotion.

Eviction is always taken from the probationary segment's LRU head, so the
total resident count stays `<= capacity` (P1) and never-put keys stay absent
(P3). Values are never copied to a different slot, preserving P2.

Update `push_back` / `unlink` to take an explicit segment selector, or
duplicate them per segment, so all four head/tail fields stay consistent.
The JNI ABI in `lru_cache_jni.rs` is untouched.

## Rationale

The baseline reports `hit_rate = 0.0` on lirs:multi1 at sizes 16 and 32,
which suggests pure recency cannot retain anything against the trace's
working set. Segmenting the list lets one-shot keys evict each other in the
probationary segment without disturbing the protected working set, which is
the classic SLRU win on scan-mixed workloads.
