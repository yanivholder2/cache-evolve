# H03

Packing arena links as `u32` with a sentinel for `None` shrinks per-entry metadata from 16 bytes of `Option<usize>` to 8 bytes of raw indices, lowering metadata size with no behavioural change.

## Parent

baseline

## Changes

Modify `src/lru_cache/mod.rs` to replace `Option<usize>` link fields with
`u32` and a sentinel.

Specifically:

- Define `const NIL: u32 = u32::MAX;` at module scope and a small inline
  helper pair `fn enc(opt: Option<usize>) -> u32` / `fn dec(raw: u32) ->
  Option<usize>` (or inline the encoding directly).
- Change `Node<K, V>`'s `prev: Option<usize>` and `next: Option<usize>` to
  `prev: u32` and `next: u32`. On a 64-bit target this drops the per-node
  link overhead from 32 bytes to 8 bytes.
- Change `head: Option<usize>` and `tail: Option<usize>` on `LruCache`
  similarly to `head: u32`, `tail: u32`.
- Rewrite `unlink` and `push_back` to operate on `u32` indices: read
  `prev`/`next` directly, compare against `NIL` instead of pattern-matching
  on `Option`, and write `NIL` where the current code writes `None`.
- In `try_new`, reject any `capacity` such that `capacity >= NIL as usize`
  with the same `log::error!` + `None` pattern used for `capacity == 0`, so
  no valid arena slot index collides with `NIL`.
- Leave the `HashMap<K, usize>` and the eviction-by-slot-reuse logic in
  `put` unchanged; only the link representation changes.

P1 (capacity bound), P2 (value fidelity), and P3 (no phantom items) all hold
because the change is a bit-for-bit representation swap of the linked-list
pointers — the order of operations and the set of resident keys are
identical to the baseline.

## Rationale

The fitness vector targets metadata size as a first-class dimension, and the
baseline's `Option<usize>` link encoding is the easiest large win: 16 bytes
of Node overhead per slot collapse to 4, scaling linearly with `capacity`.
The change is mechanical and preserves every observable LRU behaviour, so it
is a clean A/B against the baseline on the metadata-size axis.
