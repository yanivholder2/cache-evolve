# H02

Add CLOCK-Pro-lite cold/hot promotion plus a small ghost-test ring to v002 so re-referenced and recently-evicted keys are explicitly protected, raising hit-rate on the recency-skewed lirs:multi1 trace.

## Parent

cycle/0001/v002

## Changes

In `src/lru_cache/mod.rs`, extend the cache with a three-state per-slot
tag and a small ghost ring of recently-evicted cold keys.

Replace `referenced: bool` on `Entry<K, V>` with a `state: SlotState`
enum value: `Cold`, `Hot`, where each carries an effective reference
bit. Use a `#[repr(u8)]` enum or a packed pair `(state: SlotState,
referenced: bool)`; either is fine as long as the at-capacity sweep can
distinguish the four (state x referenced) cases.

Add a fixed-size ghost ring on `LruCache<K, V>`:

- `ghost: Vec<Option<K>>` of length `max(1, capacity / 4)`,
- `ghost_head: usize`,
- `ghost_set: HashSet<K>` mirroring the ring contents for O(1)
  membership.

Promotion / demotion rules in `get` and `put`:

- `get` hit on a `Cold` slot: promote the slot to `Hot`, set its
  reference bit, return the value. (This is the second-touch promotion
  v001 found scan-resistant.)
- `get` hit on a `Hot` slot: set its reference bit; do not change state.
- `put` for a brand-new key whose key is present in `ghost_set`: insert
  as `Hot` with reference bit false; remove the key from
  `ghost_set` and from its ghost ring slot. (Recently evicted, immediately
  re-referenced — treat as hot.)
- `put` for a brand-new key not in the ghost set: insert as `Cold` with
  reference bit false.

CLOCK sweep at capacity: prefer cold-unreferenced victims. Sweep the
hand at most twice:

- pass 1: only consider `Cold` slots — if reference bit set, clear it and
  advance; if clear, evict.
- pass 2 (only if pass 1 finds no victim, i.e. all cold slots had
  reference bits set when pass 1 entered): re-sweep all slots — `Hot`
  slots with reference bit set get cleared and demoted to `Cold`; the
  first `Hot` slot with reference bit already clear is evicted.

On any eviction of a `Cold` slot, push its key into the ghost ring
(overwriting the slot at `ghost_head`, removing the displaced key from
`ghost_set`, inserting the new key into `ghost_set`, advancing
`ghost_head`). Hot evictions do not enter the ghost ring.

Preserve the existing `LruCache<K, V>` API surface, the
`framework::Cache` impl, `try_new` / `new`, and the JNI ABI in
`lru_cache_jni.rs`. The two-pass sweep still terminates in
`O(capacity)` per `put` and the ghost ring uses bounded extra memory.

## Rationale

v002's gain came from CLOCK's structural simplicity, but its insight
flags strict-recency loss as the cap on hit-rate. CLOCK-Pro-lite layers
v001's second-touch promotion idea (which v001's qualitative insight
credited for scan resistance) and an evicted-key memory onto v002's
ring, attacking the only scored dimension while leaving v002's pointer-
free hot path intact for the common `get`-hit case.
