# H01

Replace v002's single reference bit with a saturating 2-bit aging counter (GCLOCK) so multi-touch keys outlive scan keys, lifting hit-rate above v002's strict-recency loss on lirs:multi1.

## Parent

cycle/0001/v002

## Changes

In `src/lru_cache/mod.rs`, modify the `Entry<K, V>` struct to replace
`referenced: bool` with `counter: u8` (logical range 0..=3, saturating).
Update the three reference-bit sites:

- `get`: increment `entry.counter` saturating at 3 (use
  `entry.counter = entry.counter.saturating_add(1).min(3)`).
- `put` for a key already in `self.map`: same saturating increment.
- `put` insertion of a brand-new entry (both the under-capacity branch and
  the post-eviction branch): initialize `counter = 1` rather than
  `referenced = false`. A starting count of 1 gives new keys one full
  sweep of protection so the first scan pass cannot evict them.

Rewrite the CLOCK sweep in the at-capacity branch so that, while sweeping
the hand:

- if `entry.counter > 0`, decrement it by 1 and advance the hand
  (continuing the loop);
- if `entry.counter == 0`, the slot is the victim — evict its key as
  today, write the new entry with `counter = 1`, advance the hand, and
  return.

Keep the existing termination guarantee: with a saturated counter of 3,
the sweep needs at most `3 * capacity + 1` iterations in the worst case
to find a victim, which is still bounded.

Preserve the public `LruCache<K, V>` type, the `framework::Cache` impl,
the `try_new` / `new` constructors, the `HashMap` + `Vec<Option<Entry>>`
+ `hand` + `len` + `capacity` field layout, and the JNI ABI in
`lru_cache_jni.rs`. No new allocations per op; only the per-slot field
widens from `bool` to `u8`.

## Rationale

v002's insight notes its weakness is "victims chosen by the hand-sweep
can be slightly fresher than the true LRU tail" — a binary reference bit
loses information after one sweep. Aging counters retain a graded
recency signal across sweeps, so multi-touch keys survive cold scans
that a single-bit CLOCK would have flushed, directly attacking the only
scored fitness dimension while keeping v002's per-op time profile.
