# H03

Implement a strict 80/20 SLRU on the baseline arena-list so the second-touch promotion effect v001 observed is actually measured at the baseline's capacity, settling whether SLRU beats pure LRU on lirs:multi1 at matched size.

## Parent

baseline

## Changes

In `src/lru_cache/mod.rs`, extend the baseline doubly-linked-list
arena to host two segments — probationary and protected — sharing the
same `nodes: Vec<Node<K, V>>` arena and the same `map: HashMap<K, usize>`.

Augment `Node<K, V>` with a `segment: u8` field (0 = probationary,
1 = protected). Replace the single `head` / `tail` pair on
`LruCache<K, V>` with two pairs:

- `prob_head` / `prob_tail` (probationary segment, head = LRU end),
- `prot_head` / `prot_tail` (protected segment, head = LRU end).

Add two derived size fields computed once in `try_new`:

- `prot_capacity = (capacity * 4) / 5`,
- `prob_capacity = capacity - prot_capacity`.

Both must be at least 1; if `capacity == 1`, fall back to a single
probationary slot with `prot_capacity = 0`. Maintain running counts
`prob_len` and `prot_len`.

Generalise the existing `unlink` and `push_back` helpers to take a
segment id and operate on the corresponding head/tail pair; do not
share linkage between segments.

Update `get`:

- On hit in probationary: unlink from probationary, push to protected
  tail, flip `segment` to 1, increment `prot_len`, decrement `prob_len`.
  If `prot_len > prot_capacity`, demote the protected head: unlink from
  protected, push to probationary tail, flip `segment` to 0, adjust the
  two length counters.
- On hit in protected: unlink and push to protected tail; counters
  unchanged.

Update `put` for a new key:

- Always insert at the probationary tail with `segment = 0`.
- If `prob_len == prob_capacity` (probationary full), evict the
  probationary head — reuse its arena slot for the new entry exactly the
  way the baseline reuses the LRU head slot today.
- If `prob_len < prob_capacity` but the arena is full overall, evict the
  probationary head anyway (eviction must always come from probationary,
  never protected).
- If the arena is not yet full, allocate a fresh arena slot via
  `self.nodes.push(...)` as today.

Update `put` for a key already in `self.map`: update its value in place,
then promote/keep it in the protected segment using the same logic as a
`get` hit on that segment.

Preserve the `framework::Cache` impl, the public `LruCache<K, V>` type,
`try_new` / `new`, and the JNI ABI in `lru_cache_jni.rs`. Arena slot
reuse (P1/P2/P3 invariants) is preserved because eviction still
overwrites the evictee's existing slot in `self.nodes` — no free list.

## Rationale

v001's insight explicitly flags that its hit-rate movement "does not by
itself prove a same-size delta over plain LRU" because the variant and
baseline were sampled at different cache sizes. Rebuilding SLRU on the
baseline path produces a clean, same-size comparison and, because the
fitness vector currently scores only hit-rate, lets the loop actually
select for SLRU's scan-resistance if it is real. The 80/20 split is the
canonical SLRU configuration; baking it in directly avoids parameter
sweeps until the basic effect is confirmed.
