# H01

Mark the first-seen sketch only on `put` (not on `get`) so the cold-admission gate's precondition survives long enough to actually drop scan keys, raising hit-rate on lirs:multi1@512.

## Parent

cycle/0005/v001

## Changes

The parent's `get` writes `self.seen[fp] = true` before `put` ever reads
it, which collapsed the H01 admission gate every cycle: under the
framework's `get_miss → put` pattern `was_seen` is always true by the
time `put` checks it. Fix the precondition without changing any other
behaviour:

1. In `get()` (cycle/0005/v001 `mod.rs` lines 120–134), **remove** the
   two lines
   ```rust
   let fp = self.fingerprint(key);
   self.seen[fp] = true;
   ```
   `get` must not touch `seen` at all — neither read nor write. Hits and
   misses still update slot state and the reference bit exactly as
   today.
2. In `put()` (lines 146–151), the order must be: first compute `fp`
   and capture `was_seen = self.seen[fp]`, then **immediately overwrite**
   `self.seen[fp] = true` (unchanged from parent). This guarantees a
   brand-new key's *first* `put` sees `was_seen == false` and is therefore
   eligible to be gated.
3. The gate condition itself at line 172 — `if self.len >= self.capacity
   && !from_ghost && !was_seen { return; }` — stays bit-for-bit
   identical. So do the sketch sizing
   (`capacity.saturating_mul(4).max(4)`), the `DefaultHasher`
   fingerprint, the ghost-ring path, the resident-update bypass, the
   two-pass CLOCK-Pro-lite sweep, and the four invariants
   (`len <= capacity`, `ghost.len() == capacity`, ghost-set/ring
   lockstep, single occupancy per key).

Net effect: a brand-new key's first put at full capacity is dropped
(sketch is marked, no slot taken, no eviction, ghost untouched);
its second put — or any put of a key whose fingerprint already
collided — passes through the unchanged CLOCK-Pro-lite admission
path. This is the only re-attempt of cold-admission gating the
cycle-5 cycle-insight authorised; if hit-rate still ties parity
after this fix, the lever is genuinely inert on this trace.

## Rationale (optional)

The cycle-5 cycle-insight explicitly named this as the one
single-trace lever still unpulled — the precondition collapse was a
mechanical bug, not a verdict on the gate. Worth exactly one slot to
distinguish "lever doesn't work" from "lever was never exercised."
