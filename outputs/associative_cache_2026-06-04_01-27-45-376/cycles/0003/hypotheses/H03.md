# H03

Require at least two untouched slots before cycle/0001/v003's filter fires; otherwise fall back to pure LRU-front eviction, treating a lone `lfu_counter == 0` slot as a fresh insert worth protecting and lifting hit-rate.

## Parent

cycle/0001/v003

## Changes

In `src/shared/eviction_policy.rs`, modify only `ClassicLRU`'s
`eviction_candidate_index`. First do a counting pass:
`let untouched = items.iter().filter(|it| it.lfu_counter == 0).count();`.
If `untouched >= 2`, repeat the parent's behaviour — return the
lowest-index slot whose `lfu_counter == 0`. If `untouched < 2` (zero
or exactly one untouched slot), return slot 0 unconditionally, the
pure LRU-front fallback. Leave `get_from_position` (move-to-back plus
`lfu_counter += 1`) and `promotion_candidate_index` exactly as in
cycle/0001/v003. Do not touch any other policy, the
`EvictionPolicyKind` enum, or the tests.

## Rationale

cycle/0002's post-mortem named "detectable proxy for the all-touched
regime" as an open question; the count of untouched slots is the
cheapest such proxy. When the bucket holds many untouched slots, it
is genuinely cold and the untouched-first filter pays off (this is
the regime where cycle/0001/v003 wins over baseline). When only one
untouched slot exists, it is almost always the freshly-inserted item
at the back — sacrificing it is the same failure mode that broke
cycle/0002/v003's short-promotion variant. Cardinality is orthogonal
to the positional axis H02 explores and the aging axis H01 explores.
