# H01

Decay every other slot's `lfu_counter` on each hit so the untouched-first eviction filter keeps firing in the previously hostile all-touched regime, lifting hit-rate above cycle/0001/v003.

## Parent

cycle/0001/v003

## Changes

In `src/shared/eviction_policy.rs`, modify the `ClassicLRU` impl of
`EvictionPolicy::get_from_position`. Before the existing
`items[position].lfu_counter += 1; let item = items.remove(position); items.push(item);`
sequence, walk every other index `i != position` and saturating-decrement
its `lfu_counter` by 1 (i.e. `if items[i].lfu_counter > 0 { items[i].lfu_counter -= 1; }`).
Apply the increment to the hit slot's counter *before* the
remove+push so the freshly hit item enters the back of the bucket with
a positive counter while the rest age. Keep
`eviction_candidate_index` exactly as in cycle/0001/v003: first pass
returns the lowest-index slot whose `lfu_counter == 0`, fallback
returns slot 0. Keep `promotion_candidate_index` returning
`items.len() - 1`. Leave every other policy (`TimestampLRU`, `Lifo`,
`Lfu`, `Fifo`, `Swap`), the `EvictionPolicyKind` enum, and all tests
untouched.

## Rationale

cycle/0002/v002's min-counter rank failed because lifetime counts
fight bucket-position recency in the all-touched regime. On-hit decay
turns `lfu_counter` from "lifetime hits" into "recent-relative
hits": slots that have been quiet for ~N hits decay back to 0, so
cycle/0001/v003's untouched-first scan keeps producing a clean
recency-aligned victim instead of falling back to slot 0. This is the
"aging step" called out in cycle 0002's open questions and the
cross-cycle insights.
