# H02

Replace per-hit move-to-back with a CLOCK-style reference bit so reads avoid the O(n) `Vec::remove`+`push` shift, cutting per-op time while approximating LRU hit rate.

## Parent

baseline

## Changes

In `src/shared/eviction_policy.rs`, rewrite
`impl<K, V> EvictionPolicy<K, V> for ClassicLRU` to behave as a CLOCK /
second-chance policy that never reorders the items vector on access:

1. `get_from_position(items, position)`: set
   `items[position].lfu_counter = 1` (used here as a single reference
   bit) and return `position` unchanged. No `remove`, no `push`, no
   swap — strictly O(1).
2. `eviction_candidate_index(items)`: scan from index 0 forward; if
   `items[i].lfu_counter > 0`, set it to `0` (clear the reference bit)
   and continue; the first index whose `lfu_counter` is already `0`
   becomes the victim. If the scan completes without finding a `0`
   (every slot was hot and got cleared this pass), return `0`. This is
   the classic CLOCK hand sweep, with the items vector itself serving
   as the circular buffer.
3. `promotion_candidate_index(items)`: scan from the back forward and
   return the first index with `lfu_counter > 0`; if none, return
   `items.len() - 1`. This keeps the trait's symmetry contract intact.

Do not modify `AssociativeCacheBucket`. The bucket-trait paths
(`put`, `is_full`, `evict_item`, `remove_at`) and the P1/P2/P3
invariants are unaffected because the items vector still grows only via
`push` (in `Bucket::put`) and shrinks only via `Vec::remove` (in
`remove_at`); access no longer mutates length or order at all. New
insertions land at the back with `lfu_counter = 0`, so a never-touched
item is the first victim — exactly the CLOCK contract.

## Rationale (optional)

ClassicLRU's hot path in `get_from_position` is `items.remove(position)`
(O(bucket_size)) plus `items.push`. For bucket_size = 16 that is a
~16-element shift on every cache hit. Replacing it with a single byte
write to a counter field already present on `Item` should dominate the
per-op-time dimension while keeping hit rate within a few percent of
LRU on Zipfian-shaped workloads.
