# H02

Replace v003's binary touched/untouched eviction filter with a single-pass min-`lfu_counter` victim selection (LRU-front tiebreak) to raise hit rate by giving every slot a smooth frequency-weighted protection level instead of a hard 0-vs-nonzero gate.

## Parent

cycle/0001/v003

## Changes

In `src/shared/eviction_policy.rs`, rewrite the `ClassicLRU`
`EvictionPolicy::eviction_candidate_index` implementation as a single
linear scan that selects, among all slots, the one with the minimum
`lfu_counter`. Break ties by lowest index (i.e., LRU front — the
slot closest to the eviction end of the recency order wins the tie).
Concretely:

```text
let mut best = 0;
for i in 1..items.len() {
    if items[i].lfu_counter < items[best].lfu_counter {
        best = i;
    }
}
return best;
```

The `items.iter().enumerate().min_by_key(...)` form returns the first
matching slot on ties, which already yields LRU-front tiebreak —
acceptable as long as the tiebreak behaviour is preserved.

Leave `get_from_position` untouched: it still does `remove` + `push`
and `lfu_counter += 1` on every hit. Leave `promotion_candidate_index`
returning `items.len() - 1`. Do not change the trait, the bucket, or
`Item`.

This generalises v003: when only one slot has `lfu_counter == 0` it
picks that slot (same as v003 pass 1); when several slots are
untouched it picks the LRU-most one of them (also same as v003,
since v003 returns the first `== 0` and the LRU front has the lowest
index); when every slot has been touched, instead of falling back to
slot 0 unconditionally it picks the slot with the *fewest* hits — a
strictly more informed choice that uses the counter v003 already
maintains.

## Rationale (optional)

v003 leaves performance on the table once every slot has been touched
at least once: it discards counter information and falls back to pure
LRU. Min-counter eviction with LRU tiebreak subsumes v003's behaviour
under the cohort's measured access pattern while giving the policy
something better than coin-flip-on-LRU-front when the all-touched
regime is reached. Distinct from H01 (3-tier piecewise filter) because
this is a continuous rank — every counter value matters, not just
`{0, 1, ≥2}`.
