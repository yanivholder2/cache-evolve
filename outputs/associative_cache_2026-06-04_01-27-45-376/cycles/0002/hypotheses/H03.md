Modulate `ClassicLRU` promotion velocity by hit count — first hit swaps the item one slot toward the back, subsequent hits do the full move-to-back — to raise hit rate by widening protection only for items that have proven repeatable interest, without v001's "no promotion on first hit" failure.

## Parent

baseline

## Changes

In `src/shared/eviction_policy.rs`, change the `ClassicLRU`
`EvictionPolicy::get_from_position` implementation so the magnitude of
the promotion depends on the slot's current `lfu_counter`:

1. Read `let prior = items[position].lfu_counter;`.
2. Increment `items[position].lfu_counter += 1;` (counter still
   advances on every hit, identical to baseline).
3. If `prior == 0` (first hit on this slot since insertion): perform
   a *single-step swap toward back* — if `position + 1 < items.len()`,
   `items.swap(position, position + 1)` and return `position + 1`;
   otherwise the slot is already at the back, return `position`.
4. If `prior >= 1` (slot has already been promoted at least once):
   do the existing baseline ClassicLRU behaviour —
   `let item = items.remove(position); items.push(item);`
   return `items.len() - 1`.

Leave `eviction_candidate_index` and `promotion_candidate_index`
exactly as in baseline (`0` and `items.len() - 1` respectively). Do
not modify the trait, `Item`, the bucket, or any other policy.

The first-hit slot is *not* withheld from promotion (that was v001's
failure mode) — it is promoted, just by a smaller distance — so a
genuinely hot newcomer still moves away from the eviction front on
its very first hit and survives. Sustained hot items reach the back
in O(hits) instead of O(1), but reach it nonetheless; one-shot
scanners only ever swap by one position and remain near the front,
which biases eviction toward churn under the existing baseline
front-eviction rule.

## Rationale (optional)

This attacks the cohort's "promotion-side gating regresses hit rate"
finding from a different angle than v001: instead of skipping
promotion entirely on first hit, it shortens the promotion's *reach*.
That preserves the "newly-touched item is protected from the very
next eviction" property the v001 failure analysis identified as
critical, while still giving repeatedly-hit items the full ClassicLRU
boost. Distinct from H01 and H02, which both touch eviction; this
hypothesis touches only the access path, so it can be composed with
v003-style eviction filters in a later cycle if it pays off.
