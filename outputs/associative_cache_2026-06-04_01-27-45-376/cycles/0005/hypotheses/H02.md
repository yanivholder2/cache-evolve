# H02

A per-bucket reference bitmask with mass-clear aging on the all-touched sweep gives v003's untouched-first filter a decay path that lifetime `lfu_counter` cannot, raising hit-rate while keeping per-item metadata flat.

## Parent

cycle/0004/v002

## Changes

Reuse the per-bucket state vehicle the parent already proved metadata-neutral (`Cell<u8>` lived on `AssociativeCacheBucket`, did not bloat `Item` or `AssociativeCache`), but repurpose it for time-based CLOCK aging rather than spatial fairness:

1. In `src/associative_cache/associative_cache_bucket.rs`, replace `victim_cursor: Cell<u8>` with `ref_bits: Cell<u16>` (one bit per slot; bucket_size ≤ 16 in the benchmark). Initialise to `0` in `new`.
2. Override `Bucket::get_from_position`: before delegating to `self.eviction_policy.get_from_position(&mut self.items, position)`, set bit `position` in `ref_bits`. After the delegation (which under ClassicLRU performs the move-to-back), mirror the same `remove+push` permutation on `ref_bits`: extract bit `position`, shift bits `position+1..len` down by one, and set the bit at the new `len-1` position to whatever was at the original `position` (i.e., `1`, since we just set it). Use plain `u16` operations — no allocation.
3. Override `Bucket::eviction_candidate_index`: if the policy is `ClassicLRU`, scan bits `0..items.len()` and return the first index whose `ref_bits` bit is `0`. If every bit is set, clear `ref_bits` to `0` AND return `0` (i.e., evict the LRU front but reset all protection so the next eviction sweep can again discriminate untouched-from-touched). For every other policy, delegate to `self.eviction_policy.eviction_candidate_index(&self.items)` exactly as the trait default does. Also remove the bit for the evicted slot when `evict_item` removes at the returned index — mirror `Vec::remove` on the bitmask by shifting bits above the index down by one.
4. Insertion via `put` (the trait default) pushes a new item at `len-1`; ensure the new slot's bit is `0` (untouched) — clear bit `len-1` immediately after `items.push`.

Critical distinction from the parent: cycle/0004/v002 used its cursor for *spatial* rotation across the existing untouched-slot set (CLOCK in space) and lost because it discarded the leftmost-as-age coupling. This change keeps v003's leftmost-first scan order untouched and uses the per-bucket state for *temporal* aging instead — mass-clear when no untouched slot exists, restoring the untouched-vs-touched signal on the next call. Distinction from `lfu_counter == 0`: the bit lives on the bucket and can be cleared en masse without touching `Item`, so the aging step has no per-hit cost and never interacts with downstream consumers of `lfu_counter`.

Leave `eviction_policy.rs` unchanged for non-ClassicLRU policies and leave the `ClassicLRU::eviction_candidate_index` trait impl as it currently appears in the parent overlay (it is bypassed by the bucket override for ClassicLRU).

## Rationale (optional)

The parent proved per-bucket state is the right vehicle (metadata-flat, reached the Pareto front despite a losing payload). The cross-cycle digest's open question — whether per-bucket state can carry a *different* signal than the rotation use that lost — points directly at this design: decouple "ever touched" from `lfu_counter`, then add the aging step the digest said any counter-based policy needs to compete.
