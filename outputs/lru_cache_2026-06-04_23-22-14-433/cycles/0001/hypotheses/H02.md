# H02

Replacing pure LRU with a segmented LRU (SLRU) — a probationary LRU segment for items accessed once and a protected LRU segment for items accessed more than once, where protected overflow demotes to probationary rather than directly evicting — will improve hit rate on lirs:multi1.trace.gz by preserving multi-hit items across bursts of cold traffic.

## Parent

baseline

## Changes

Rewrite `src/lru_cache/mod.rs`. All changes stay within `LruCache<K, V>` and `Node<K, V>`.

### How SLRU differs from 2Q (H01)

Both policies use two segments but differ in two ways that affect hit rate differently:
1. SLRU's probationary segment uses **LRU order** (a cold item that gets re-accessed moves to probationary MRU and delays its own eviction). 2Q's cold queue is FIFO (access order is ignored for cold items).
2. When the protected segment overflows, SLRU **demotes** the protected LRU item to probationary MRU instead of immediately evicting it. The item remains in cache; only the probationary tail is ever truly evicted.

### Node struct

Add one field:

```rust
protected: bool,  // false → in probationary; true → in protected
```

### LruCache struct

Replace `head`/`tail` with four list-boundary pointers and two counters:

```rust
prob_head: Option<usize>,  // LRU (eviction) end of probationary
prob_tail: Option<usize>,  // MRU end of probationary
prot_head: Option<usize>,  // LRU end of protected
prot_tail: Option<usize>,  // MRU end of protected
prob_len: usize,
prot_len: usize,
```

Add capacity split computed in `try_new`:
`prot_cap = (capacity * 4 / 5).max(1)` (≈80 %); `prob_cap = capacity - prot_cap`.

### `unlink`

Read `nodes[idx].protected` to decide which pair of list-head/tail pointers to patch, and decrement the matching counter.

### `push_back_prob(idx)` / `push_back_prot(idx)`

Two helpers that append to the respective MRU tail and increment the matching counter.

### `put` (new key)

All new keys enter probationary with `protected = false`.

Before inserting, if `prob_len + prot_len == capacity`:
- Unlink `prob_head` (the true LRU victim), remove its key from `map`, reuse its arena slot as `idx`.

Push the new node to probationary MRU via `push_back_prob(idx)` and register in `map`.

### `get` (hit)

After looking up `idx`, branch on `nodes[idx].protected`:

- **Probationary hit**: unlink from probationary. Promote to protected MRU:
  - If `prot_len == prot_cap`: demote `prot_head` to probationary first — unlink it from protected, set `nodes[prot_head_idx].protected = false`, push it to probationary MRU via `push_back_prob`. If this causes `prob_len > prob_cap`, evict the (new) `prob_head` from the cache (`map.remove`; that slot is not immediately reused here — it stays in the arena but is unlinked and will be reused on the next new-key insertion that needs a slot). Decrement `prob_len`.
  - Set `nodes[idx].protected = true`, call `push_back_prot(idx)`.
- **Protected hit**: unlink from protected, `push_back_prot(idx)` (LRU move-to-tail within protected).

### Slot reuse

Track one additional field `free_slot: Option<usize>` (an arena index whose key has been evicted but whose slot has not yet been reused). On every new-key `put`, if `free_slot.is_some()`, consume it; otherwise use `nodes.len()` as usual.

### Invariants to preserve

- `prob_len + prot_len == map.len()` at all times.
- `map.len() <= capacity` at all times.
- P1 capacity_bound, P2 value_fidelity, P3 no_phantom_items must all pass.
