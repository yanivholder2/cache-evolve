# H03

Adding a saturating per-entry frequency counter and evicting the minimum-frequency item among the first eight candidates from the LRU head — rather than always evicting the strict LRU head — will improve hit rate on lirs:multi1.trace.gz by preventing one-time-scan items from displacing high-frequency entries that happen to be LRU-positioned.

## Parent

baseline

## Changes

All changes are confined to `src/lru_cache/mod.rs`. The list structure, arena, and map are unchanged; only the eviction policy gains a frequency tiebreaker.

### Node struct

Add one field:

```rust
freq: u8,  // saturating access frequency counter; initialised to 1 on insertion
```

### LruCache struct

No structural changes. Optionally add a constant:

```rust
const EVICT_SCAN: usize = 8;
```

(or define it as a module-level constant).

### `put` (new key path)

When constructing a new `Node` or overwriting a reused slot, set `freq = 1`.

### `get`

After locating `idx` and before the `unlink`/`push_back` sequence, saturate-increment the counter:

```rust
self.nodes[idx].freq = self.nodes[idx].freq.saturating_add(1);
```

Then perform the existing `unlink(idx)` + `push_back(idx)` as before.

### `put` (eviction path — arena full)

Replace the unconditional `self.head.expect(…)` victim selection with a short linear scan:

```rust
let mut victim = self.head.expect("non-empty list has a head");
let mut cursor_opt = self.nodes[victim].next;
let mut steps = 1usize;
while steps < Self::EVICT_SCAN {
    let cursor = match cursor_opt {
        Some(c) => c,
        None => break,
    };
    if self.nodes[cursor].freq < self.nodes[victim].freq {
        victim = cursor;
    }
    cursor_opt = self.nodes[cursor].next;
    steps += 1;
}
```

Then use `victim` in place of `head_idx` for the rest of the existing eviction logic:
- `evicted_key = self.nodes[victim].key.clone()`
- `self.map.remove(&evicted_key)`
- `self.unlink(victim)`
- Reuse `victim` as the arena slot for the new key; set `self.nodes[victim].key = key.clone()`, `value`, `freq = 1`.
- `self.push_back(victim)` and `self.map.insert(key, victim)`.

The scan is bounded at `EVICT_SCAN = 8` iterations, keeping eviction O(1) in practice (constant at most 8 pointer dereferences). The list invariant is unchanged: `unlink` + `push_back` already handle any list position.

### Rationale for scan width

Eight candidates gives a good tradeoff: with capacity 512 the scan covers ~1.5 % of the cache, which is enough to rescue a frequently accessed item sitting near the LRU tail while staying well within O(1) amortised cost.

### Invariants to preserve

- `map.len() <= capacity` at all times (unchanged eviction trigger, only victim selection changes).
- P1 capacity_bound, P2 value_fidelity, P3 no_phantom_items must all pass.
- The `freq` field must never affect which keys are considered present or absent — only which resident key is chosen as the eviction victim.
