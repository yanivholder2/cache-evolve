# H03

Adding a small per-bucket stash that catches recently evicted items and re-promotes them on subsequent access improves hit rate by recovering short-term recency misses that the primary eviction policy would otherwise permanently lose.

baseline

## Changes

Edit only `src/associative_cache/associative_cache_bucket.rs`. No other file should be touched.

### Struct changes

Add two fields to `AssociativeCacheBucket`:

```rust

    K: Hash + Eq + Copy + Debug,
```

In `AssociativeCacheBucket::new`, initialise the two new fields. Set `stash_max_size` to `(settings.bucket_size / 4).max(1)` (one quarter of the primary bucket capacity, minimum one slot):

### `Bucket` trait overrides

The `Bucket` trait provides default implementations of `put` and `get`. Override both in the `impl<K,V> Bucket<K,V> for AssociativeCacheBucket<K,V>` block.

**`put` override** — four cases handled in order:

1. Key already exists in primary → update value in place and call `get_from_position` (existing behaviour, identical to the default).
2. Key exists in stash → remove from stash, update value, promote to primary (evicting primary victim to stash if primary is full), push to primary.
3. Key is new and primary is not full → push directly to primary (no stash involvement).
4. Key is new and primary is full → call `evict_item()` to get the primary victim, push victim to stash (dropping the oldest stash entry first if the stash is at capacity), then push the new item to primary.

```rust
fn put(&mut self, item: Item<K, V>) -> (&Item<K, V>, Option<Item<K, V>>) {
    // Case 1: update existing key in primary
    if let Some(position) = self.get_position(&item.key) {
        self.get_items_mut()[position].value = item.value;
        let pushed = self.get_from_position(position);
        return (pushed, None);
    }
    // Case 2: key is in stash — promote
    if let Some(stash_pos) = self.stash.iter().position(|i| i.key == item.key) {
        let mut stash_item = self.stash.remove(stash_pos);
        stash_item.value = item.value;
        if self.is_full() {
            if let Some(evicted) = self.evict_item() {
                self.stash_push(evicted);
            }
        }
        self.get_items_mut().push(stash_item);
        let pushed = self.get_items().last().expect("bucket invariant: just pushed");
        return (pushed, None);
    }
    // Cases 3 and 4: new key
    if self.is_full() {
        if let Some(evicted) = self.evict_item() {
            self.stash_push(evicted);
        }
    }
    self.get_items_mut().push(item);
    let pushed = self.get_items().last().expect("bucket invariant: just pushed");
    (pushed, None)
}
```

**`get` override** — check primary first, then stash:

```rust
fn get(&mut self, key: &K) -> Option<&Item<K, V>> {
    // Primary hit
    if let Some(position) = self.get_position(key) {
        return Some(self.get_from_position(position));
    }
    // Stash hit — promote to primary
    if let Some(stash_pos) = self.stash.iter().position(|i| &i.key == key) {
        let stash_item = self.stash.remove(stash_pos);
        if self.is_full() {
            if let Some(evicted) = self.evict_item() {
                self.stash_push(evicted);
            }
        }
        self.get_items_mut().push(stash_item);
        return self.get_items().last();
    }
    None
}
```

**`stash_push` helper** — add as a private method on `AssociativeCacheBucket` (outside the `Bucket` trait impl):

```rust
fn stash_push(&mut self, item: Item<K, V>) {
    if self.stash.len() >= self.stash_max_size {
        self.stash.remove(0); // drop oldest stash entry (FIFO overflow)
    }
    self.stash.push(item);
}
```

### Invariants preserved

- The primary `items` vector never exceeds `max_size`; the `is_full` / `evict_item` / `get_from_position` delegation is unchanged.
- The stash never exceeds `stash_max_size`; overflow drops the oldest entry rather than silently growing.
- A key can exist in at most one location: the primary hit check in `put` and `get` runs before the stash check, and stash entries are removed before being promoted to primary.

## Rationale

The baseline has no second-chance mechanism: once an item is evicted from its bucket it is gone. Short-lived working-set shifts (scan interference, burst traffic) cause items to be evicted and then immediately requested again, producing avoidable misses. A tiny stash per bucket acts as a recency buffer, catching those items before they leave the cache entirely. With `bucket_size = 16` the stash holds 4 items — small enough to not materially change eviction pressure on the primary.
