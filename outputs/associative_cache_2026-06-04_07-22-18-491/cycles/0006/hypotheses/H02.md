# H02

Reducing the probe zone capacity from one-half to one-quarter of primary capacity raises hit rate by freeing primary slots sooner for items with confirmed reuse, at the cost of a shorter filter window for cold inserts.

## Parent

cycle/0005/v003

## Changes

One overlay file requires a change.

### `src/associative_cache/associative_cache_bucket.rs`

In `new()`, change the `probe_max_size` initialisation from:

```rust
probe_max_size: (settings.bucket_size / 2).max(1),
```

to:

```rust
probe_max_size: (settings.bucket_size / 4).max(1),
```

No other changes. The probe FIFO eviction logic, the probe-hit promotion path (incrementing `lfu_counter` by 1, evicting from primary if full), the primary eviction logic, and all `Bucket` trait method signatures remain identical to cycle/0005/v003.

**Invariants to preserve**:
- `probe_max_size` must always be at least 1 (the `.max(1)` guard is preserved).
- `get_items()` continues to return only primary items.
- The probe-hit counter increment (`probe_item.lfu_counter += 1`) is unchanged.

## Rationale

cycle/0005/v003 fixed the probe cap at half of primary capacity without characterising the gain curve above or below that ratio. On a Zipfian workload the hot set is small and items are re-accessed quickly, so a shorter probe queue should still filter one-time-access items while releasing primary slots earlier for items that confirm reuse on the first or second access. A quarter-capacity probe matches the stash cap used by cycle/0003/v003, making a future comparison between the two mechanisms more symmetric. If performance degrades, it confirms that the half-capacity ratio is already at or past the optimum and the gain is not monotone in probe size.
