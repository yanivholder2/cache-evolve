# H03

Adding LFU-weighted eviction to the probe zone baseline — without a stash — raises hit rate by ensuring that the primary resident with the lowest confirmed access frequency is displaced first when a probe item is promoted.

## Parent

cycle/0005/v003

## Changes

One overlay file requires a change.

### `src/shared/eviction_policy.rs`

Override the file to make `ClassicLRU::eviction_candidate_index` use LFU-weighted selection instead of pure position order. Change:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    // baseline: first in vec is oldest / LRU candidate
    0
}
```

to:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    items
        .iter()
        .enumerate()
        .min_by_key(|(i, item)| (item.lfu_counter, *i))
        .map(|(i, _)| i)
        .unwrap_or(0)
}
```

This is the identical change made in cycle/0003/v003's `eviction_policy.rs`. The `get_from_position` method of `ClassicLRU` (which moves the accessed item to the back and increments `lfu_counter`) remains unchanged. All other policies (`TimestampLRU`, `Lifo`, `Lfu`, `Fifo`, `Swap`, `EvictionPolicyKind`) are copied from baseline without modification.

`src/associative_cache/associative_cache_bucket.rs` is inherited from cycle/0005/v003 without any change: the probe zone at half primary capacity, the probe-hit promotion path (`lfu_counter += 1`), and primary eviction via `self.eviction_policy.eviction_candidate_index` are all preserved. No stash is added.

**Invariants to preserve**:
- `probe_max_size` remains `(settings.bucket_size / 2).max(1)`.
- No stash fields are introduced; evicted primary items are discarded as in cycle/0005/v003.
- The `lfu_counter += 1` increment on probe-hit promotion is preserved; items enter primary already holding one frequency credit, which participates in the LFU selection on subsequent evictions.

## Rationale

cycle/0005/v003 uses ClassicLRU's default eviction order (position in the vec, i.e. insertion order) to choose which primary item to displace when a probe-zone item is promoted. Once the probe zone has filtered cold inserts, primary residents should all carry at least one access (they were promoted from probe), but their frequencies may still diverge substantially. Using LFU-weighted eviction ensures the least-accessed confirmed item is displaced first. This isolates the contribution of the eviction-discriminator improvement from the stash's second-chance mechanism, tested separately in H01. If LFU alone helps here, it can be combined with the stash; if it is neutral, the probe's admission filter already dominates and further eviction tuning offers no leverage.
