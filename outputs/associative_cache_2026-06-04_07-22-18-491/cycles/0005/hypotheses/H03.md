# H03

Routing all new key inserts through a small probationary buffer and promoting items to primary only upon a subsequent `get` hit prevents first-access-only items from displacing primary residents, raising hit rate on Zipfian workloads.

## Parent

baseline

## Changes

One file requires changes: `src/associative_cache/associative_cache_bucket.rs`, built
from the baseline bucket (ClassicLRU eviction, no stash). The `eviction_policy.rs` and
`item.rs` files are inherited from baseline without modification.

### Struct fields

Add two new fields to `AssociativeCacheBucket<K, V>`:

```rust
probe: Vec<Item<K, V>>,
probe_max_size: usize,
```

Initialize them in `new()`:

```rust
probe: Vec::new(),
probe_max_size: (settings.bucket_size / 2).max(1),
```

The probe zone holds at most half the primary capacity. New inserts enter probe rather
than primary; they graduate to primary only after a `get` hit confirms reuse.

### Overridden `get(&mut self, key: &K) -> Option<&Item<K, V>>`

```rust
fn get(&mut self, key: &K) -> Option<&Item<K, V>> {
    // Primary hit — unchanged behaviour
    if let Some(position) = self.get_position(key) {
        return Some(self.get_from_position(position));
    }
    // Probe hit — promote to primary on second access
    if let Some(probe_pos) = self.probe.iter().position(|i| &i.key == key) {
        let mut probe_item = self.probe.remove(probe_pos);
        probe_item.lfu_counter += 1;   // counts as the second observed access
        if self.items.len() == self.max_size {
            let evict_idx = self.eviction_policy.eviction_candidate_index(&self.items);
            self.items.remove(evict_idx);
        }
        self.items.push(probe_item);
        let back = self.items.len() - 1;
        return Some(&self.items[back]);
    }
    None
}
```

A probe hit serves the value (the full `Item` is stored in probe) and simultaneously
promotes the item to primary with `lfu_counter = 1`, giving it a non-zero frequency
head start before competing with established primary residents.

### Overridden `put(&mut self, item: Item<K, V>) -> (&Item<K, V>, Option<Item<K, V>>)`

Three cases, in priority order:

```rust
fn put(&mut self, item: Item<K, V>) -> (&Item<K, V>, Option<Item<K, V>>) {
    // Case 1: key already resident in primary — update in place
    if let Some(position) = self.get_position(&item.key) {
        self.get_items_mut()[position].value = item.value;
        let pushed = self.get_from_position(position);
        return (pushed, None);
    }
    // Case 2: key in probe — update value, no promotion (only get() promotes)
    if let Some(probe_pos) = self.probe.iter().position(|i| i.key == item.key) {
        self.probe[probe_pos].value = item.value;
        return (&self.probe[probe_pos], None);
    }
    // Case 3: brand-new key — insert into probe, FIFO-evict oldest probe entry if full
    if self.probe.len() >= self.probe_max_size {
        self.probe.remove(0);   // oldest probe item dropped; no stash in this variant
    }
    self.probe.push(item);
    let back = self.probe.len() - 1;
    (&self.probe[back], None)
}
```

`put()` on an existing probe key updates the value but does not promote; promotion is
deferred exclusively to `get()`. This keeps the probe as a strict admission gate:
only confirmed reuse (via `get`) earns primary entry.

### Invariants preserved

- `get_items()` returns only primary items; probe is an internal implementation
  detail never exposed through the `Bucket` trait methods.
- `evict_item()`, `eviction_candidate_index()`, and `remove_at()` operate on
  `self.items` only and are inherited from the baseline trait without change.
- `get_from_position()` is inherited from baseline and continues to delegate to
  `self.eviction_policy` for primary-resident items.
- Evictions from primary are permanent (the evicted item is dropped); there is no
  stash in this variant, keeping the structure minimal.

## Rationale

The stash mechanism (introduced in cycle 2) gives second chances to items after they
are evicted from primary. This hypothesis explores the complementary direction:
admission control before items reach primary. On a Zipfian workload most inserts are
for keys that will be accessed again (the distribution ensures temporal locality), so
the probe zone should fill with items that quickly earn their promotion via a `get`
hit. Items that never receive a second access age out of the probe FIFO without ever
consuming a primary slot, leaving primary exclusively for items with confirmed reuse.
Starting from baseline (rather than cycle/0003/v003) isolates the effect of
probationary admission from the stash-and-promotion mechanism; if this approach shows
a gain, a future cycle can combine both mechanisms.
