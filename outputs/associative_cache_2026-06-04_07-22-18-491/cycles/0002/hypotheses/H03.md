# H03

Replacing ClassicLRU's lexicographic (frequency, position) eviction criterion with a frequency-times-recency product score will raise hit rate by giving recency proportional weight alongside frequency rather than treating it as a pure tiebreaker.

## Parent

baseline

## Changes

Modify `src/shared/eviction_policy.rs` from the baseline. Only `ClassicLRU::eviction_candidate_index` changes; everything else — the struct definitions, other policy impls, `EvictionPolicyKind`, and all tests — is preserved.

Replace the current body:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    items
        .iter()
        .enumerate()
        .min_by_key(|(i, item)| (item.lfu_counter, *i))
        .map(|(i, _)| i)
        .unwrap_or(0)
}
```

with a product-score body:

```rust
fn eviction_candidate_index(&self, items: &[Item<K, V>]) -> usize {
    items
        .iter()
        .enumerate()
        .min_by_key(|(i, item)| item.lfu_counter.saturating_add(1) * (*i + 1))
        .map(|(i, _)| i)
        .unwrap_or(0)
}
```

Scoring rationale: in ClassicLRU, `get_from_position` moves the accessed item to the back of the vector, so `position` encodes recency — position 0 is the least recently used slot, position `len-1` is the most recently used. The product `(lfu_counter + 1) * (position + 1)` gives a low score (high eviction priority) to items that are both cold (low counter) and old (low position), and a high score (low eviction priority) to items that are both hot and recent. Critically, a newly inserted item at position `len-1` with `lfu_counter = 0` receives score `len`, which protects it proportionally to the bucket's occupancy — avoiding the failure mode where a brand-new item is immediately the weakest LFU candidate despite being brand new. A stale item with high historical frequency (high counter, low position) receives score `(lfu+1) * 1`, making it vulnerable once it stops being accessed even if its counter is large.

The `get_from_position` access discipline (move-to-back, increment `lfu_counter`) is unchanged from baseline ClassicLRU.
